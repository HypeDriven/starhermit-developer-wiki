Commencer

ÉtoileErmite est une plate-forme de distribution de jeux et de logiciels avec une couche sociale intégrée, exposée via REST et WebSockets. Cette page vous donne un aperçu du terrain : ce que fait la plate-forme, où elle écoute, comment fonctionnent l'authentification et la gestion des versions, et les deux manières dont votre propre jeu peut s'y intégrer.

Pour votre premier jeu par navigateur, télécharger et publier le démarrage rapide. Pour une autre architecture, choisir une intégration, puis vérifie informations d'identification, Conventions API, et disponibilité des fonctionnalités. Utiliser dépannage lorsqu'un appel échoue.

Ce que propose StarHermit

  • Utilisateurs & authentification — enregistrement par clé publique (pas de mot de passe) et connexion OAuth via les fournisseurs pour lesquels ce déploiement dispose d'informations d'identification ; voir Authentification.
  • Profils & présence — profils d'utilisateurs, avatars, paramètres de confidentialité, droits et battements de présence ; voir Profil.
  • Amis — demandes d'amis et état d'amitié ; voir Amis.
  • Chat textuel — conversations et messages; voir Chat.
  • Voix en temps réel — les salles vocales ; voir Voix.
  • Éditeurs — les comptes d'éditeurs qui possèdent des entrées de catalogue ; voir Éditeur.
  • Catalogue de logiciels — titres de logiciels avec versions et ressources téléchargeables ; voir Catalogue.
  • Droits — subventions par utilisateur de logiciels de catalogue (partie de Profil).
  • Réalisations & classements — les réalisations faisant autorité sur le serveur pour les jeux avec un backend de script ou de conteneur, ainsi que les réalisations revendiquées par le client pour les titres du catalogue ; voir Réalisations et Classements.
  • Relais par les pairs — répartition d'octets opaques liée à la correspondance avec autorisation de liste et limites de débit dérivées du taux de tick du jeu ; voir Relais.
  • Salles en temps réel — lobbies, matchmaking, joueurs et remplissages IA, et transport en temps réel pour des jeux rapides ; peut également accéder à une session scriptée liée à une salle pour une lecture faisant autorité sur le serveur ; voir Salles en temps réel.
  • Jeux faisant autorité - des jeux hébergés sur une plateforme dont les règles s'exécutent comme un JavaScript en bac à sable Scénario du jeu ou un Serveur de jeu de conteneur; les clients utilisent le partage API de jeux.

URL de base et ports

  • API REST publique : https://api.starhermit.com, sous api/v1/....
  • WebSockets publics : wss://api.starhermit.com/ws/v1/....
  • Les jeux publiés sur la plateforme sont servis à https://<slug>.starhermit.com avec /api et /ws disponible de même origine, les jeux hébergés sur la plateforme doivent donc utiliser des chemins relatifs.

Gestion des versions

Toutes les routes REST sont versionnées : api/v1/.... Les routes WebSocket vivent sous ws/v1/... et sont neutres en termes de version.

Méthodes recommandées pour participer à un jeu hébergé

Il est recommandé aux jeux hébergés sur StarHermit d'offrir deux options claires sur leur écran de démarrage :

  1. Connectez-vous avec un compte StarHermit existant - permet aux joueurs d'utiliser leur compte pour enregistrer leur progression et les fonctionnalités de plate-forme prises en charge, telles que les réalisations et les classements. Utilisez le flux de connexion aux jeux hébergés lorsqu'il n'y a pas de jeton de lancement valide ; les joueurs arrivant avec un jeton valide peuvent continuer directement.
  2. Jouez en solo sans vous connecter - propose une version solo autonome qui ne nécessite aucun compte et ne suit ni n'enregistre la progression. Gardez la progression en mémoire pour la session de jeu en cours, sans écrire de sauvegardes dans le cloud, de sauvegardes locales persistantes, de réalisations ou de scores de classement.

Étiquetez clairement la deuxième option, par exemple Jouez en solo (la progression n'est pas enregistrée), afin que les joueurs sachent à quoi s'attendre avant de commencer. Ce mode doit s'exécuter sans appels ou sockets d'API StarHermit authentifiés.

Modèle d'authentification (présentation)

  • Les jetons d'accès sont des JWT d'une durée de vie de 15 minutes ; les jetons d’actualisation tournent et durent 7 jours. Voir Authentification pour le format du jeton et les points de terminaison d’actualisation/déconnexion.
  • Envoyez le jeton d'accès en tant que Authorization: Bearer <token> en-tête sur chaque demande authentifiée. Pour /ws/** chemins uniquement, le titre est également accepté comme ?ticket= (un ticket de connexion unique de POST /api/v1/realtime/connection-tickets) ou comme ?access_token= (toujours pris en charge). Les navigateurs ne peuvent pas définir d'en-têtes sur les poignées de main WebSocket.
  • Les jeux utilisent également jetons de lancement à l'échelle du jeu - des JWT de courte durée créés par jeu qui clôturent l'appelant dans la surface API de ce jeu. Voir Authentification et Jeux.

Un jeu hébergé ouvert directement dans le navigateur peut offrir un Bouton de connexion. Starhermit gère la connexion ou la création de compte et renvoie un jeton de jeu directement dans le jeu.

Avant d'appeler des points de terminaison protégés ou d'ouvrir des sockets, un compte doit accepter les conditions actuelles. Utiliser GET /api/v1/me vérifier termsAcceptanceRequired, affichez le document de GET /api/v1/terms, et soumettez son hachage seulement après que l'utilisateur l'ait accepté. UN 403 avec error: "terms_acceptance_required" signifie que vous devez afficher le document actuel et proposer une réponse explicite Acceptez l’action. Les sessions de compte et les jetons de lancement de joueur peuvent soumettre leur acceptation ; les jetons de serveur ne le peuvent pas. L'actualisation d'un jeton n'enregistre pas l'acceptation.

Deux façons d'intégrer votre jeu

  1. Jeu hébergé sur plateforme. Vous publiez un jeu à partir d'un dépôt GitHub avec un starhermit.txt manifest - ou, s'il ne réside pas dans un référentiel, télécharger le dossier directement et ignorez complètement git. Il peut s'agir d'un navigateur uniquement, utilisez un bac à sable server.js, ou pointez vers une image de conteneur épinglée par résumé pour la logique du serveur. La plateforme sert le jeu à <slug>.starhermit.com avec /api et /ws proxy de même origine. Le chemin du script est démontré de bout en bout par l'implémentation de référence d'échecs à l'adresse https://github.com/HypeDriven/starhermit-chess. Voir Jeux GitHub, Scripts de jeu, Serveurs de jeux de conteneurs, et le Procédure pas à pas d'intégration.
  2. Client de jeu externe. Votre propre client appelle directement les API REST et WebSocket, en utilisant l'authentification JWT et, le cas échéant, les jetons de lancement de jeu. Les pages de référence API ci-dessous documentent la surface. Sur Unity, le SDK Unity implémente déjà cette surface en tant que clients C# typés - y compris les règles d'actualisation des jetons, de nouvelle tentative et de reconnexion de socket - pour les versions de bureau, mobiles, WebGL, console et serveur sans tête.

Les deux itinéraires vers un jeu hébergé sur une plateforme passent par un seul petit fichier : voir Le starhermit.txt manifeste pour son format, où il doit s'asseoir et pourquoi le le dossier que vous téléchargez doit être votre version distribuable plutôt que votre arborescence source.

Horloge du serveur — GET /api/v1/time

Délais que la plateforme vous remet (un récapitulatif de séance deadline, un script ctx.now) sont sur le du serveur horloge, donc un client effectuant un compte à rebours par rapport à sa propre horloge dérivera. Ceci le point de terminaison est volontairement anonyme – la synchronisation doit fonctionner avant la connexion – et est explicitement autorisé jetons de lancement à l'échelle du jeu, afin qu'un jeu hébergé puisse l'appeler tout en étant clôturé sur sa propre surface.

{
  "serverTime": 1785060842000,
  "serverTimeIso": "2026-07-25T09:14:02+00:00",
  "clientTime": 1785060841200,
  "skew": 800
}

clientTime (unix ms, facultatif) est renvoyé intact afin qu'une réponse puisse être adaptée à son demande ; skew est le naïf serverTime - clientTime pour les clients qui ne veulent pas faire l'aller-retour mathématiques. Pour une estimation réelle, faites-le à la manière NTP : réduisez de moitié l'aller-retour et calculez offset = serverTime + rtt/2 - now.

Comportement transversal

  • En-têtes de sécurité sont définis sur toutes les réponses.
  • Limitation du débit — les messages de chat sont limités à 10 par minute et par utilisateur ; d'autres points de terminaison peuvent renvoyer 429 comme documenté par page.
  • Erreurs sont toujours retournés comme {"error":"..."} avec codes d'état standard (400/401/403/404/409/422/429). Les pages individuelles notent uniquement les cas d’erreur spécifiques au point de terminaison.
