Le starhermit.txt Manifeste

starhermit.txt est un petit fichier en texte brut qui indique à StarHermit comment s'appelle votre jeu, comment lancez-le et quel type de serveur (le cas échéant) il exécute. C'est le seul fichier que la plateforme recherche dans tout ce que vous publiez.

Il appartient à la racine de ce que vous téléchargez — à la fois pour les fichiers clients d'un jeu et pour un fichier dédié serveur.

Vous n’êtes pas obligé de créer le fichier vous-même. Le client Windows et le tableau de bord Web montrer le manifeste comme champs modifiables : quel que soit votre build, il le préremplit, et tout ce qu'ils contiennent lorsque vous appuyez sur Télécharger est écrit dans le bundle en tant que manifeste. Donc une construction avec non starhermit.txt est toujours publiable, et un .tar - que vous ne pouvez pas modifier sur place - est comme modifiable sous forme de dossier. Envoyer le fichier dans votre build vaut toujours la peine : il voyage avec le artefact, donc les valeurs seront correctes la prochaine fois que quelqu'un le téléchargera.

La règle qui surprend les gens

Tout ce qui se trouve à côté du manifeste est téléchargé.

Le dossier que vous choisissez n'est pas un répertoire de projet dans lequel la plateforme fouille pour une build - le dossier contenu sont le jeu publié, copié tel quel. Chaque fichier et chaque sous-dossier adjacent à starhermit.txt, à n'importe quelle profondeur, monte et est servi aux joueurs.

Alors choisis ton sortie de build distribuable, pas votre arborescence source. Télécharger un répertoire de travail signifie expédier votre source, vos notes, vos actifs non minés et vos expériences à moitié terminées à chaque joueur, et en brûlant l'espace disque de votre jeu sur des fichiers que personne ne charge.

Une poignée de noms sont toujours ignorés, car ils ne font jamais partie d'un jeu publié : .git, node_modules, .DS_Store, Thumbs.db. Tout le reste est un jeu équitable, y compris README.md, .env des fichiers, *.psd sources et *.map fichiers. Si vous ne le remettez pas à un joueur, ne le laissez pas à côté du manifeste.

Où ça va

Un client de jeu

my-game-dist/
  starhermit.txt        <- belongs at this level
  index.html            <- your launch file
  game.js
  assets/
    sprites.png
    music.ogg

Prendre my-game-dist/. Le contenu devient le jeu, servi à https://<slug>.starhermit.com/, et index.html c'est ce qu'un joueur charge.

Ou choisissez-en un seul .tar exactement cette disposition — "Ajouter à partir de .tar" dans le client de bureau, le .tar champ dans le tableau de bord. Le client lit les entrées de l'archive, les réintègre dans le bundle pour vous, et préremplit les champs du manifeste à partir d'un starhermit.txt à l'intérieur. Utiliser --format=ustar:

tar --format=ustar -cf my-game.tar -C my-game-dist .

Les archives utilisant le nom long GNU ou les en-têtes étendus PAX sont refusées. Ces formats stockent le réel d'une entrée chemin dans un séparé bloc de métadonnées, donc les réhéberger signifie réécrire les métadonnées - et les obtenir subtilement faux publierait un jeu corrompu. Si votre build atteint les limites du chemin ustar (100 octets pour un nom, 155 pour son préfixe de répertoire), raccourcissez les noms de dossier les plus profonds ou téléchargez le dossier à la place.

Un serveur dédié

my-server-dist/
  starhermit.txt        <- belongs at this level
  image.tar            <- docker save output of your server image

Prendre my-server-dist/ — ou choisir image.tar tout seul, puisque le manifeste peut provenir du champs de la boîte de dialogue à la place. Contrairement au dossier client, une distribution serveur a exactement deux dossiers significatifs. fichiers : le manifeste et l'image du conteneur produite par

docker save my-server:latest > image.tar

Tout le reste dans un dossier de serveur est laissé de côté plutôt que téléchargé : la plateforme exécute votre conteneur, donc l'image contient déjà les fichiers de votre serveur. Garder le manifeste ici signifie de toute façon une version de serveur est auto-descriptive et peut être re-téléchargée d'elle-même.

Format

Lignes de key=value. Les lignes vides sont ignorées, # commence un commentaire et des espaces autour des touches et les valeurs sont tronquées. Les noms de clés ne sont pas sensibles à la casse, sauf que les chemins de dossier dans cache.<folder> sont sensibles à la casse ; les clés inconnues sont ignorées, donc une faute de frappe échoue silencieusement — vérifiez votre orthographe par rapport aux tableaux ci-dessous.

# My Game - browser-only
name=My Game
launch=index.html

Clés que chaque jeu peut définir

Clé Alias Signification
name — Le nom d’affichage que les joueurs voient. Obligatoire sauf si vous transmettez un nom d'affichage dans le formulaire de téléchargement.
launch launch_path, html Chemin d'accès à l'entrée .html, par rapport au manifeste. La valeur par défaut est index.html lorsqu'un fichier de ce nom se trouve à la racine.
cover cover_art, coverart Illustration sur la vignette de la bibliothèque du jeu. Un chemin relatif au fichier de lancement (cover.png, art/box.jpg) ou un absolu https:// URL. Facultatif : sans cela, la vignette affiche le favicon. Une mauvaise valeur est abandonnée plutôt que de refuser la partie.
description — Le texte de la page du magasin que les joueurs lisent sur votre jeu. Une ligne ; écrire \n pour un saut de ligne. Ou utiliser description.file pour le conserver dans un fichier. Voir Description et notes de version.
release_notes releasenotes Ce qui a changé dans cette version. Mêmes règles que description; release_notes.file pointe vers un fichier à la place.
owner username, user Flux de référentiel uniquement. Le propriétaire StarHermit ID utilisateur (UUID) depuis GET /api/v1/me, pas un nom d'utilisateur. Vous permet revendiquer une annonce ajoutée par quelqu'un d'autre en prouvant que vous contrôlez le référentiel. Ignoré lors d'un téléchargement – voir À qui appartient un jeu téléchargé.

Description et notes de version

Deux morceaux de texte facultatifs affichés à côté de votre jeu : un description (c'est quoi le jeu) et notes de version (ce qui a changé dans la version que vous publiez). Chacun peut être écrit dans le se manifester ou être conservé dans son propre dossier.

En ligne, pour un texte court. Le manifeste comporte une ligne par clé, alors écrivez \n partout où tu veux un saut de ligne (et \\ pour une barre oblique inverse littérale) :

name=Asteroid Garden
launch=index.html
description=Tend a garden on a drifting asteroid.\nPlant, water, and dodge the meteor showers.
release_notes=- New: night cycle\n- Fixed: seeds vanishing after a reload

A partir d'un fichier, pour toute période plus longue — c'est le formulaire à utiliser pour les vraies notes de version :

name=Asteroid Garden
launch=index.html
description.file=DESCRIPTION.md
release_notes.file=CHANGELOG.md

my-game-dist/
  starhermit.txt
  DESCRIPTION.md
  CHANGELOG.md
  index.html
Clé Alias Signification
description — Texte de description, en ligne.
description.file — Chemin vers un .md, .markdown ou .txt fichier contenant la description.
release_notes releasenotes Texte des notes de version, en ligne.
release_notes.file releasenotes.file Chemin vers un .md, .markdown ou .txt fichier contenant les notes de version.

Les règles :

  • Les chemins de fichiers sont relatifs à starhermit.txt (la racine du référentiel pour un jeu de référentiel), pas au fichier de lancement. Non .., pas de leader /, et seulement .md, .markdown ou .txt; tout autre chemin est ignoré plutôt que de refuser le jeu. Le fichier doit être à l'intérieur ce que vous publiez, c'est ainsi servi aux joueurs comme tous les autres fichiers à côté du manifeste. N'y mettez rien vous ne les montrerait pas.
  • Un fichier l'emporte sur la ligne en ligne. Déclarez les deux et le texte en ligne n'est qu'une solution de secours, utilisée lorsque le fichier est introuvable.
  • Le texte est relu à chaque fois que le manifeste est : chaque téléchargement ou push contenant un manifeste et chaque déploiement de référentiel (à partir du commit en cours de déploiement). Supprimez les deux lignes et le le texte est effacé. Un fichier déclaré mais manquant, sans solution de secours en ligne, laisse le texte le jeu avait déjà.
  • Pourquoi un fichier et non un texte multiligne dans le manifeste ? Une clé sur deux est lue ligne par ligne. Si un Un paragraphe des notes de version pourrait se trouver à l'intérieur du manifeste, une note qui disait owner=someone serait lu comme un owner= doubler.
  • Taille: une description est coupée à 4 000 caractères et les notes de version à 20 000. Un texte plus long est raccourci, pas refusé. Les fins de ligne sont normalisées et les lignes vierges de début et de fin sont coupées.
  • Formatage: le texte est stocké exactement tel qu'il est écrit. Markdown est un choix judicieux, mais que ce soit il est rendu ou affiché sous forme de texte brut, c'est au client de l'afficher.
  • Les notes de version remplacent et ne s'accumulent pas. Chaque publication contient les notes pour que construire. Garder votre historique complet dans votre propre journal des modifications et publiez la pièce dont les joueurs ont besoin.

Les clients lisent la description de la liste du jeu et les notes de version de GET /api/v1/github-games/{id}/release-notes.

Mise en cache des actifs du navigateur

Utiliser cache.<folder>=<seconds> définir Cache-Control: public, max-age=<seconds> sur statique hébergé fichiers. Les durées sont des nombres entiers 0–31536000 (un an):

cache..=0
cache.audio=31536000
cache.audio/live=0
cache.assets/textures=604800

Ici cache.. définit la valeur par défaut de l'ensemble du site à zéro (revalidation lors de la réutilisation), audio/ cache pendant un an, audio/live/ revalide, et assets/textures/ cache pendant une semaine. Utilisez des noms de fichiers hachés avec le contenu pour des atouts à long terme : le redéploiement n'invalide pas les copies déjà mises en cache dans les navigateurs des joueurs.

Les chemins sont sensibles à la casse, par rapport à la racine hébergée (racine du référentiel ou client/ répertoire) et faire correspondre des dossiers entiers, y compris les descendants. audio ne correspond pas audiobooks. Une barre oblique finale est facultative ; le dossier le plus spécifique l'emporte et le dernier doublon l'emporte. Utiliser . uniquement pour la racine par défaut ; chemins absolus, segments vides, ./.. segments, barres obliques inverses, %, ?, #, : et les caractères de contrôle sont refusés. Sans règle de correspondance, il n'y a pas de statique explicite Cache-Control en-tête. Les appels d'API, les WebSockets et les solutions de secours pour les actifs manquants diffusés en externe sont non affecté.

Autoriser un autre site Web à accéder à votre jeu hébergé

Pour un client navigateur sur une autre origine, déclarez jusqu'à cinq origines HTTP/HTTPS exactes :

cors.origins=https://example.com,https://play.example.org,http://localhost:5173

Par exemple, après avoir publié ce manifeste, une page de développement sur http://localhost:5173 peut récupérer un atout de votre jeu hébergé :

const response = await fetch('https://YOUR_GAME_UID.starhermit.com/assets/levels.json');
if (!response.ok) throw new Error(`Asset request failed: ${response.status}`);
const levels = await response.json();

Chaque origine est un schéma, un nom d'hôte exact et un port facultatif. Caractères génériques, domaines nus, informations d'identification, chemins (même un sentier /), les requêtes et les fragments sont refusés. Le schéma et le port doivent correspondre ; les sous-domaines ne sont pas implicitement inclus. Répété cors.origins lignes se combinent, avec au plus cinq entrées dans le manifeste (les doublons comptent également). Omettez la clé pour ne permettre aucune origine supplémentaire ; une valeur vide n'est pas valide.

Cela s'applique aux actifs statiques, aux ressources de secours manquantes et aux /api/ demandes sur l'hôte de votre jeu. Les origines autorisées reçoivent des en-têtes CORS accrédités ; Les contrôles en amont OPTIONS permettent GET, HEAD, POST, PUT, PATCH, DELETE et OPTIONS avec les en-têtes demandés. Authentification et autorisation API toujours appliquer. Cela ne configure pas CORS sur api.starhermit.com, modifier les règles d'origine WebSocket ou élargir les URL de retour autorisées par la connexion au jeu par navigateur. Un jeu fonctionnant sur sa propre origine hébergée n'a pas besoin déclaration CORS supplémentaire.

Cache de publication et paramètres CORS

Les deux stratégies sont publiées avec les fichiers clients. Les déploiements de référentiel lisent le commit épinglé. En paquets, racine starhermit.txt a la priorité sur client/starhermit.txt. Un téléchargement de fusion sans manifeste conserve les politiques existantes ; un manifeste fourni les remplace (omettre un paramètre l'efface). Un remplacement complet sans manifeste efface les deux politiques. Les paramètres non valides rejettent la publication avant de remplacer les fichiers actifs (422 pour les téléchargements ; un échec déploiement du référentiel). Voir mises à jour groupées.

Contrôles

Déclarez les actions du clavier utilisées par votre jeu, avec les touches par défaut que les joueurs peuvent relier :

control.left=KeyA+ArrowLeft | Move left
control.jump=Space+KeyW | Jump

control.<action>=<code>[+<code>...][ | <label>] : les identifiants d'action sont des lettres minuscules, des chiffres et _; les codes sont KeyboardEvent.code valeurs (KeyA, Space, ArrowLeft), jusqu'à 4 par action rejointe avec +; au maximum 32 actions, et aucune clé sur deux actions. Les lignes invalides sont ignorées silencieusement et un un jeu sans ligne valide n'a pas de contrôles - ses réponses API de contrôles 404 "This game declares no controls.". Ils prennent effet lorsque vous publiez une build les contenant. Voir Tutoriel : ajouter des contrôles à votre jeu.

Clés pour un jeu de moteur StarHermit

Un jeu joué par le Moteur StarHermit (un jeu de script) déclare le moteur avec lequel il tourne engine.* clés. Le moteur les lit avec name=, server= et le control.* lignes; le client StarHermit Windows joue à un jeu de manière native lorsqu'il trouve engine.version et engine.entry.

Clé Signification
engine.api La version majeure de l'API hôte pour laquelle le jeu est écrit (1).
engine.entry Le module que le moteur démarre, tel que src/main.ts.
engine.version L'exact libération du moteur le jeu continue, X.Y.Z; sa majeure est engine.api. La plateforme l'enregistre à chaque publication et sert les pages d'un jeu de script sous le moteur. Politique de sécurité du contenu.
engine.minor Facultatif : la version mineure de l'API hôte dont le jeu a besoin ; un moteur qui offre moins le refuse.
engine.capabilities Facultatif, séparés par des virgules : platform, voice, clipboard, storage.
engine.gamepad.<action> Commandes de manette de jeu par défaut pour une action control.* les lignes déclarent.
engine.limits.<name> Facultatif : diminue une des limites du moteur du jeu.

Clés pour un jeu avec logique serveur

Prendre un façon serveur. Déclarer les deux server= et container.image= est refusé.

Ceux-ci fonctionnent dans un dossier téléchargé ainsi qu'un référentiel. UN server= le script voyage à l'intérieur du dossier que vous téléchargez et sa source est lue directement à partir de l'archive, donc un jeu faisant autorité les règles n'ont besoin d'aucun référentiel. Si la déclaration ne peut être honorée — le script est manquant, pointe en dehors du dossier, ou demande un conteneur pour lequel vous n'êtes pas autorisé à exécuter - l'intégralité du téléchargement est refusé plutôt que de créer un jeu à moitié configuré.

Clé Signification
server (alias server_script) Chemin d'accès à un fichier JavaScript qui s'exécute en tant que serveur faisant autorité dans le bac à sable de StarHermit. Voir Scripts de jeu.
container.image A résumé épinglé image (name@sha256:<64 hex>) pour s'exécuter en tant que serveur. Les tags sont refusés. Voir Serveurs de jeux de conteneurs.
container.port Port sur lequel votre conteneur écoute.
container.memory_mb Mémoire demandée en MiB, limitée aux limites de l'opérateur.
container.cpu Limite de CPU pour le conteneur.
container.health Cheminez vers la plate-forme pour vérifier qu'elle est prête.
container.env.<NAME> Une variable d'environnement transmise à votre conteneur.

Commencer le matchmaking avant que chaque siège humain ne soit pourvu

Ces paramètres s'appliquent à un jeu faisant autorité utilisant le matchmaking StarHermit, avec soit un Serveur JavaScript ou conteneur :

matchmaking.max_wait_seconds=30
matchmaking.ai_players=2
Clé Signification
matchmaking.max_wait_seconds Entier 0–86400. Démarrez une correspondance sous-remplie lorsque le ticket sélectionné le plus ancien a attendu ce nombre de secondes. 0 démarre immédiatement. Omettre pour conserver le comportement par défaut de correspondance ou d'expiration humaine complète.
matchmaking.ai_players Entier 0–31, défaut 0. À la date limite, remplissez autant de sièges vacants avec l’IA ; laisser tous les autres sièges vacants vides. Nécessite matchmaking.max_wait_seconds.

La capacité de la file d'attente provient de celle d'un script game.queues; sans déclaration, c'est 1v1. Le conteneur actuel /describe le lecteur n'importe pas queues, donc le matchmaking de conteneurs utilise la forme implicite 1v1. Par exemple, dans une file d'attente de huit places déclarée par le script avec trois humains en attente, les paramètres ci-dessus commencent avec trois humains, deux joueurs IA et trois sièges vides. Un humain à part entière le match peut commencer avant la date limite et ne reçoit aucune IA. Définir l'IA sur 0 permet une correspondance uniquement humaine avec des sièges vides, y compris un seul humain si le jeu le permet.

La plateforme vérifie lors de la mise en file d'attente et lors des vérifications périodiques de mise en relation (par défaut tous les 5 secondes), ainsi, un démarrage peut suivre la date limite jusqu'à un intervalle de balayage sous charge normale. Compatibilité Elo et le sous-ensemble de file d'attente autorisé pour chaque ticket s'applique toujours. Les groupes restent ensemble au sein d’une seule équipe ; à la date limite, un groupe plus petit ou un joueur solo peut occuper une équipe plus grande, avec les sièges restants disponible pour l’IA ou laissé vide. Les billets ne sont pas regroupés en une seule équipe.

Votre serveur de jeu doit accepter les correspondances sous-remplies et implémenter le comportement de l'IA. Marques StarHermit les joueurs IA ; cela ne génère pas leurs mouvements. Une session rejetée annule les tickets sélectionnés. La disposition des sièges gelés est fournie comme ctx.matchmaking, et les sièges occupés apparaissent dans ctx.players; voir le contexte du serveur. Les sièges vides ne sont pas automatiquement rempli par des jointures tardives.

Les redéploiements et téléchargements de référentiel appliquent ces paramètres. Un manifeste fourni sans les clés réinitialisées eux ; un patch sans manifeste les préserve. Les valeurs invalides sont refusées (upload 422, ou un échec déploiement du référentiel). Ces paramètres n'affectent pas les jeux d'entraînement explicites ou les salles en temps réel. jointure/remplissage rapide.

Comment en créer un

  1. Ouvrez un éditeur de texte brut : Notepad, TextEdit, VS Code, n'importe quoi. Pas Word.
  2. Tapez les touches dont votre jeu a besoin, une par ligne (commencez par un exemple ci-dessous).
  3. Enregistrez-le sous starhermit.txt dans le dossier que vous allez télécharger, codé en UTF-8.

Sous Windows, le Bloc-notes "Documents texte" le type de sauvegarde ajoute .txt à tout ce que vous tapez, donc nommer le fichier starhermit.txt rendements starhermit.txt.txt. Soit choisir Tous les fichiers dans la boîte de dialogue d'enregistrement, ou activez l'explorateur de fichiers Extensions de nom de fichier visualisez-le et renommez-le ensuite. Un fichier nommé starhermit.txt.txt n'est pas trouvé et le téléchargement est refusé.

Le nom est exact : tout en minuscules, sans espaces. Starhermit.txt et starhermit.TXT travailler parce que le la recherche n'est pas sensible à la casse, mais starhermit.text, starhermit.cfg et manifest.txt ne pas.

Exemples

Jeu sur navigateur uniquement

name=Asteroid Garden
launch=index.html

Jeu avec pochette

name=Asteroid Garden
launch=index.html
cover=art/cover.png

Un chemin relatif est résolu par rapport au fichier de lancement (non .., pas de leader /, pas de chaîne de requête) et doit se terminer par .png, .jpg/.jpeg, .gif, .webp ou .svg. Une URL absolue doit être https:// — http:// est supprimé - et les octets sont reniflés, donc l'URL elle-même n'a besoin d'aucune extension d'image.

La ligne est relue à chaque déploiement, donc la changer change le couvercle et le retirer supprime le couverture. Une image définie à partir de Gérer → Couverture dans le tableau de bord web (ou par un opérateur StarHermit) le remplace : ce choix réside en dehors de la construction, donc un redéploiement ne l'annule jamais. Suppression du le téléchargement revient à nouveau à cette ligne.

Tuiles de bibliothèque

La pochette est une affiche : les deux bibliothèques redimensionnez-le pour remplir la tuile et recadrez-le au centre quoi qu'il arrive pas adapté. Les carreaux n'ont pas la même forme.

Surface Tuile Recadrer
Client Windows Portrait 96×128 (3:4) Remplit le portrait ; l'art au sens large perd ses côtés
Tableau de bord Web Carré Remplit le carré ; l'art plus grand perd le haut et le bas

Gardez le sujet dans le centre. Un portrait 3:4 dont le carré du milieu est la composition, ou un carré dont la bande centrale 3:4 est, survit aux deux récoltes. La boîte aux lettres n'est jamais appliquée - vide les marges que vous ajoutez autour de l’illustration sont coupées avec tout le reste.

Les couvertures SVG s'affichent sur la bibliothèque Web. Le client Windows n'a pas de décodeur SVG, donc cette tuile revient au favicon tandis que la vignette Web affiche toujours la couverture. Préférez PNG, JPEG ou WEBP quand vous le souhaitez la même tuile sur les deux.

Revendiquer une annonce que vous possédez – jeux de référentiel uniquement

Ensemble owner à l'ID utilisateur immuable StarHermit renvoyé comme id par GET /api/v1/me-pas le nom d'utilisateur ou pseudo du profil :

name=My Game
launch=index.html
owner=3fa85f64-5717-4562-b3fc-2c963f66afa6

À qui appartient un jeu téléchargé

Le compte qui le télécharge. Toujours, et il n'y a rien à configurer.

Un téléchargement n'a aucun référentiel derrière lui, donc personne ne peut prouver son contrôle : la plateforme enregistre le compte de téléchargement en tant que demandeur et laisse le champ du propriétaire GitHub vide, donc aucune revendication ne pourra jamais correspondre à la ligne. Un owner= La ligne dans une version téléchargée est ignorée et les clients le font ne pas offrir de champ pour cela - mettre un jeu au nom d'une autre personne lui attribuerait la responsabilité pour le contenu qu'ils n'ont pas publié, ce qu'un formulaire de téléchargement ne devrait pas pouvoir faire.

Remettre un jeu que vous possédez déjà à quelqu'un d'autre est une action distincte et délibérée à partir de son menu Gérer. après coup, pas une décision prise lors de son ajout.

Publier à partir d'un référentiel GitHub à la place

Si votre jeu vit dans un github.com référentiel, mettre starhermit.txt à la racine du référentiel et soumettez l'URL du dépôt - la plate-forme lit le manifeste directement à partir du dépôt et aucun téléchargement n'est effectué. impliqué. Tout ce qui précède s'applique sans changement, sauf que "tout ce qui est adjacent" signifie tout dans le référentiel, ce qui est une bonne raison de conserver la sortie et les sources de la build dans des dépôts séparés (ou d'utiliser le dossier de téléchargement pour votre sortie construite).

Voir Jeux GitHub pour le flux du référentiel, et Ajouter un jeu à partir d'un dossier local pour le téléchargement points de terminaison que les clients appellent.

Limites

Un jeu peut occuper 2 Go sur starhermit.com (l'allocation peut varier selon le déploiement), et c'est également le plafond pour un seul téléchargement de remplacement. UN ?mode=merge Le patch est délimité par l'arborescence résultante, donc un petit téléchargement qui ferait en sorte que le jeu en direct dépasse le l'indemnité est refusée. Profondément les chemins imbriqués sont refusés : le format d'archive limite un chemin à 100 caractères pour le nom du fichier plus 155 pour son préfixe de répertoire, raccourcissez donc les très longues chaînes de dossiers.

Dépannage

Ce que tu vois Pourquoi
Le client dit que votre build n'a pas de manifeste Non starhermit.txt à la racine de ce que vous avez choisi (une copie plus profonde à l'intérieur ne compte pas). Il s'agit d'une invite, pas d'un refus : remplissez les champs de la boîte de dialogue et une est rédigée pour vous.
Ton .tar est refusé car "en-têtes étendus" Le client emballeur qui héberge un seul .tar dans client/ refuse toujours les blocs de nom long GNU et PAX (la réécriture de ces blocs de métadonnées est la façon dont l'entrée suivante est nommée). git archive et tar -czf . sont acceptés par la plateforme elle-même. Recréer avec tar --format=ustar, ou téléchargez le dossier.
Vous avez modifié un champ mais l'ancienne valeur est active Le manifeste à l’intérieur de votre build est inchangé ; seul le paquet a reçu le nouveau. Mettez à jour le fichier dans votre build afin que le prochain téléchargement démarre à partir des bonnes valeurs.
"Un nom d'affichage est requis" Non name= ligne et aucun nom d'affichage saisi dans le formulaire.
"Un chemin de lancement est requis" Non launch= ligne et non index.html à la racine du dossier.
"Les fichiers du téléchargement ne contiennent pas le fichier de lancement" launch= nomme un fichier qui ne se trouve pas dans le dossier. Vérifiez l'orthographe et qu'elle est relative au manifeste et non absolue.
Votre jeu est publié mais il manque des fichiers Ces fichiers n'étaient pas adjacents au manifeste. Le téléchargement commence dans le dossier contenant starhermit.txt; rien au-dessus n’est inclus.
La vignette de la bibliothèque affiche le favicon, pas votre couverture cover= est manquant, n'est pas un chemin d'image utilisable/https:// URL, ou le fichier ne se trouve pas à côté du fichier de lancement. Les mauvaises valeurs sont supprimées silencieusement – ​​le jeu est toujours publié. SVG apparaît uniquement dans la bibliothèque Web ; la vignette Windows revient au favicon. Une image de Gérer → Couverture remplace le manifeste jusqu'à ce que vous le supprimiez ici.
Votre description ou vos notes de version n'apparaissent pas La clé est mal orthographiée (les clés inconnues sont ignorées), le *.file le chemin n'est pas un .md/.markdown/.txt fichier relatif à starhermit.txt, ou le fichier ne figurait pas dans ce que vous avez publié. Un fichier manquant conserve le texte précédent.
Vos notes de version affichent \n littéralement Seul le formulaire en ligne devient \n dans un saut de ligne. Texte lu d'un *.file est utilisé exactement tel qu’écrit.
container.image refusé Il n’est pas épinglé dans un résumé. Utiliser name@sha256:<64 hex>, pas une balise.
L'API des contrôles dit "Ce jeu ne déclare aucun contrôle." Non valide control.* ligne dans la version en direct. Vérifiez les lignes par rapport Contrôles et publier une nouvelle version - voir Tutoriel : ajouter des contrôles à votre jeu.
