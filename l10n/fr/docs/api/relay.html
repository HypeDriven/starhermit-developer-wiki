Relais

Le relais fournit une distribution d'octets opaque pour le netcode du jeu : une API REST (api/v1/relay) gère séances, et ws/v1/relay transmet textuellement les trames binaires entre les participants. Chaque relais est lié à exactement une correspondance existante : un séance de jeu ou un salle en temps réel-et utilise la liste de ce match pour l'autorisation.

Tous les points de terminaison REST nécessitent une authentification : un jeton d'utilisateur complet ou un jeton de lancement de jeu pour les relais lié aux propres sessions et salles de ce jeu : la liste affiche uniquement celles-ci, ainsi que toutes les autres réponses de relais 404 (ou 403 pour en créer un). Le relais d'un jeton de lancement prend l'identifiant de son propre jeu comme titleId — l'uid dans son game_scope réclamation — et tout autre titre est refusé 403, car le par titre le plafond de session compte pour lui. Les erreurs sont renvoyées sous forme {"error":"..."}: 403 lorsque l'appelant est pas dans le match lié ou le relais appartient à un autre jeu, 404 pour un relais inconnu, 409 pour un état qui refuse la demande (non liée, complète, fermée, déjà rejointe ou à la limite de session), et 503 lorsque le relais est éteint.

Points de terminaison REST

Base: https://api.starhermit.com/api/v1/relay.

Méthode Chemin Authentification Description
OBTENIR /?titleId= JWT Répertorier les sessions de relais actives pour ce titre dont la correspondance liée inclut l'appelant
POSTE / JWT Créer un relais lié à un match
OBTENIR /{sessionId} JWT Obtenez une session de relais — visible uniquement par les membres de son match lié (404 sinon)
POSTE /{sessionId}/join JWT Rejoignez le relais; l'appelant doit être dans sa correspondance liée
POSTE /{sessionId}/close JWT Fermer un relais (créateur uniquement)

Reliure de correspondance

L’adhésion au Relais n’est pas un lobby indépendant et ouvert. La liste des matchs est la source de vérité :

  • Un relais a soit gameSessionId ou realtimeRoomId, jamais les deux et jamais ni l'un ni l'autre.
  • Le créateur doit appartenir à cette session de jeu ou détenir un siège actif et non gauche dans ce temps réel chambre.
  • Chaque inscription ultérieure est vérifiée par rapport à la même liste.
  • L'ouverture du WebSocket nécessite à la fois une ligne de participant relais active et une adhésion actuelle au match lié. Quitter une salle en temps réel empêche donc une connexion relais ultérieure/de remplacement.
  • Liste par titleId renvoie uniquement les relais liés aux correspondances auxquelles l'appelant appartient ; ce n'est pas un répertoire de chaque match en direct pour ce titre.

Il s’agit d’un changement de forme de demande requis. Les anciennes lignes de relais non liées ne peuvent pas autoriser un socket ; créer un nouveau relais lié à la place.

Créer une séance

POST /api/v1/relay

Liez-vous à une session de jeu faisant autorité :

{
  "titleId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "maxParticipants": 8,
  "gameSessionId": "0f8fad5b-d9cb-469f-a165-70867728950e",
  "realtimeRoomId": null
}

Ou associez-vous à une salle en temps réel :

{
  "titleId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "maxParticipants": 8,
  "gameSessionId": null,
  "realtimeRoomId": "b1d2c3e4-5f60-4a71-8b92-c3d4e5f60718"
}

maxParticipants par défaut 8. Au maximum cinq sessions de relais actives peuvent exister par titre par par défaut. L'appel est rejeté si le nombre de liaisons n'est pas exactement un ou si l'appelant n'est pas dans le correspondance sélectionnée.

Le relais ne crée pas la session ou la salle de jeu. Créez/rejoignez ce match via le API de jeux ou API des salles en temps réel d'abord, puis transmettez son identifiant ici.

Forme de la séance

{
  "id": "d290f1ee-6c54-4b01-90e6-d701748f0851",
  "titleId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "creatorUserId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "gameSessionId": "0f8fad5b-d9cb-469f-a165-70867728950e",
  "realtimeRoomId": null,
  "isBound": true,
  "maxParticipants": 8,
  "currentParticipantCount": 1,
  "status": "Active",
  "createdAt": "2026-07-28T11:30:00Z",
  "closedAt": null,
  "participants": [
    {
      "id": "e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b",
      "sessionId": "d290f1ee-6c54-4b01-90e6-d701748f0851",
      "userId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
      "connectionId": null,
      "joinedAt": "2026-07-28T11:30:01Z",
      "leftAt": null,
      "status": "Connected"
    }
  ]
}

Exactement un ID de liaison n'est pas nul et isBound est donc true. Session status est "Active" ou "Closed"; closedAt, connectionId, et leftAt peut être absent ou nul.

Rejoindre et fermer

POST /api/v1/relay/{sessionId}/join renvoie la mise à jour RelaySession. Cette jointure REST est requise avant d'ouvrir le WebSocket. Un créneau relais gratuit ne suffit pas : l'appelant doit encore être membre de le match lié.

POST /api/v1/relay/{sessionId}/close retours 204 et est réservé aux créateurs.

WebSocket : ws/v1/relay

Connectez-vous à :

wss://api.starhermit.com/ws/v1/relay?sessionId=<relay-id>&titleId=<title-id>

Authentifiez-vous avec un Authorization: Bearer <token> en-tête, ?ticket=, ou ?access_token= paramètre de requête. La poignée de main revient 403 sauf si l'utilisateur a rejoint le relais et est toujours autorisé par son lié correspondre.

Le socket est en sortance d'octets opaque. Chaque trame binaire est transmise inchangée les unes aux autres participant connecté. Il n'y a pas de cadrage JSON et la plateforme n'interprète pas les données du jeu. La taille maximale des messages est de 4 Ko par défaut.

Limite de taux tenant compte du taux de ticks

Règle de suppression de connexion : si un client envoie des commandes/trames de relais plus rapidement que le débit autorisé, StarHermit ferme le relais WebSocket de ce client avec PolicyViolation. Il ne s'agit pas d'une file d'attente ou d'un suppression de trame au mieux : la connexion client est terminée et doit se reconnecter.

L'intervalle minimum de chaque expéditeur est dérivé de la vitesse à laquelle la correspondance liée est rythmée :

minimum interval ms = (1000 / max(pacingRateHz, 1)) × 0.90

La marge de 10 % permet une gigue de minuterie et de réseau ordinaire. Le tarif n'est jamais pris en dessous 1 Hz, donc la limite ne demande jamais plus de ~900 ms de silence entre deux images, même si le jeu est lent tiques. Exemples :

Taux effectif Intervalle minimum de l'expéditeur
20 Hz 45 ms
30 Hz 30 ms
60 Hz 15 ms
120 Hz 7,5 ms

Pour une session de jeu, le tarif provient de sa définition de jeu. Pour une salle en temps réel, la salle gameSlug est résolu en une définition de jeu. La priorité normale du taux effectif s’applique : remplacement de l'opérateur, puis le taux demandé par le jeu. À quoi sert la limite de relais pas suivre est un taux qui ne dit rien sur la fréquence à laquelle les joueurs se parlent : si aucune définition ne peut être résolu, si le jeu s'est désabonné du serveur coche avec 0, ou s'il n'a demandé aucun tarif et ainsi prend la lenteur par défaut de la plate-forme, la limite est plutôt dimensionnée à partir du taux global. Un jeu n'est jamais limité à un message toutes les quelques secondes car personne n'a écrit de numéro dans le code de son serveur. Tarifs sont délimités par le plafond de la plate-forme.

Un client doit rythmer les commandes selon cet intervalle ou plus lentement. Envoi de deux commandes/images plus rapprochées supérieur à l'intervalle minimum est traité comme une inondation : StarHermit abandonne la connexion de ce client en fermant son relais WebSocket avec PolicyViolation. Les expéditeurs sont limités indépendamment, donc un la violation du client ne déconnecte pas les autres joueurs.

Flux de clients recommandé

  1. Créez ou rejoignez la session de jeu réelle/la salle en temps réel.
  2. Demandez à un membre du match de créer un relais avec cet ID de match.
  3. Partagez l'ID de relais renvoyé uniquement via l'état authentifié du match ou les messages de liste.
  4. Les autres membres du match appellent POST /api/v1/relay/{relayId}/join.
  5. Chaque membre ouvre ws/v1/relay et adapte les images au taux de tick effectif du jeu ; envoi abandonne plus rapidement la connexion WebSocket de ce client.
  6. Le créateur ferme le relais à la fin du match.

N'utilisez pas les ID de relais comme secrets d'autorisation. La plateforme autorise contre la liste liée ; les identifiants identifient uniquement les ressources.

Positionnement

Utilisez le relais pour les jeux rapides qui nécessitent une diffusion par les pairs à faible surcharge. C'est volontairement bête transport : la liaison garantit qui peut participer, mais la plateforme n'analyse ni ne valide toujours charges utiles, élire un pair faisant autorité ou résoudre la tricherie.

Pour les règles et l'état appliqués par le serveur, utilisez le API de jeux avec un script en bac à sable ou back-end de conteneur. Les salles en temps réel fournissent des halls, des sièges, du jumelage et routage compatible avec l'hôte ; le relais peut désormais se lier à l'une de ces salles au lieu de dupliquer sa liste.

Confirmez la disponibilité du relais avant d'expédier une fonctionnalité qui en dépend.
