Chat

Le chat StarHermit couvre les messages directs, les salles de groupe et les conversations de session de jeu, via une API REST (api/v1/chat) plus un canal push WebSocket serveur-client (ws/v1/chat). Tous les points de terminaison REST nécessitent une authentification. Les corps d’erreur varient ; voir Conventions API.

Points de terminaison REST

Base: https://api.starhermit.com/api/v1/chat.

Méthode Chemin Authentification Description
POSTE /conversations JWT Créer une conversation (1 ami = direct, ≥2 = groupe)
CORRECTIF /conversations/{id} JWT Renommer une conversation (n'importe quel membre)
POSTE /conversations/{id}/invites JWT Inviter un utilisateur dans un groupe
OBTENIR /invites JWT Listez vos invitations à discuter en attente
POSTE /invites/{id}/accept JWT Accepter une invitation à discuter
POSTE /invites/{id}/decline JWT Refuser une invitation à discuter
OBTENIR /rooms/joinable JWT Répertoriez les salles ouvertes avec ≥1 ami à l'intérieur
POSTE /conversations/{id}/join JWT Rejoignez une salle ouverte (vous devez être ami avec un membre)
POSTE /conversations/{id}/participants JWT Ajouter des participants à une conversation
SUPPRIMER /conversations/{id}/participants/{userId} JWT Supprimer un participant (lui-même : n'importe quel membre ; autres : créateur de groupe uniquement)
POSTE /conversations/{id}/leave JWT Quitter une conversation
OBTENIR /conversations JWT Répertorier les conversations, y compris chaque nombre non lu
OBTENIR /conversations/{id} JWT Obtenez une conversation, y compris son nombre de non lus
OBTENIR /unread JWT Obtenez le nombre total de messages non lus
POSTE /conversations/{id}/read JWT Marquer une conversation comme lue
OBTENIR /conversations/{id}/messages?page=&pageSize= JWT Obtenir l'historique des messages paginés
POSTE /conversations/{id}/messages JWT Envoyer un message (taux limité)
METTRE /conversations/{conversationId}/messages/{messageId} JWT Modifier un message
SUPPRIMER /conversations/{conversationId}/messages/{messageId} JWT Supprimer un message (pierre tombale)

Créer une conversation

POST /conversations

{
  "participantIds": ["<guid>"],
  "name": "Friday night lobby",
  "friendUserId": "<guid>",
  "joinPolicy": "closed"
}

Tous les champs sont facultatifs. Un ami participant crée un direct conversation; deux ou plus créent un groupe. joinPolicy est "open" ou "closed" (défaut "closed"). Renvoie un ConversationDto.

Renommer une conversation

PATCH /conversations/{id} avec { "name": "New name" } → ConversationDto. Tout membre peut renommer ; une note système avec kind: "system_rename" est diffusé.

Invitations

POST /conversations/{id}/invites avec { "toUserId": "<guid>" } → ChatInviteDto. Les invitations sont le seul moyen d’accéder à une pièce fermée.

GET /invites → ChatInviteDto[]:

[
  {
    "id": "<guid>",
    "conversationId": "<guid>",
    "conversationName": "Friday night lobby",
    "fromUserId": "<guid>",
    "fromUsername": "alice",
    "toUserId": "<guid>",
    "status": "pending",
    "createdAt": "2026-07-22T07:00:00Z"
  }
]

POST /invites/{id}/accept et POST /invites/{id}/decline → ChatInviteDto.

Rejoindre des pièces

GET /rooms/joinable → JoinableRoomDto[] — des salles ouvertes dans lesquelles au moins un de vos amis se trouve à l'intérieur :

[
  {
    "id": "<guid>",
    "name": "Friday night lobby",
    "joinPolicy": "open",
    "createdAt": "2026-07-22T07:00:00Z",
    "participants": [{ "userId": "<guid>", "username": "alice" }]
  }
]

POST /conversations/{id}/join → ConversationDto. Rejoint une pièce ouverte; vous devez être ami avec un membre.

Participants

POST /conversations/{id}/participants avec { "participantIds": ["<guid>"] } → ConversationDto.

DELETE /conversations/{id}/participants/{userId} → 204. Tout membre peut se retirer ; en supprimer d’autres nécessite d’être le créateur du groupe.

POST /conversations/{id}/leave → 204.

Lire des conversations

GET /conversations → ConversationDto[].

GET /conversations/{id} → ConversationDto:

{
  "id": "<guid>",
  "type": "group",
  "name": "Friday night lobby",
  "createdByUserId": "<guid>",
  "joinPolicy": "closed",
  "createdAt": "2026-07-22T07:00:00Z",
  "participants": [{ "userId": "<guid>", "username": "alice" }],
  "otherParticipant": { "userId": "<guid>", "username": "bob" },
  "unreadCount": 3
}

type est l'un des direct, group, game. name, createdByUserId, et otherParticipant peut être absent. unreadCount compte les messages texte non lus envoyés par d'autres membres après l'horizon de lecture par conversation de l'appelant.

État non lu

GET /unread renvoie le nombre de non lus dans toutes les conversations de l'appelant :

{ "total": 7 }

POST /conversations/{id}/read fait avancer l'horizon de lecture de l'appelant pour cette conversation. Utilisez-le après avoir affiché la transcription actuelle. Le serveur émet un conversation_read événement à toutes les sockets appartenant à l'appelant, permettant à plusieurs clients connectés d'effacer leurs badges. Les messages nouveaux et supprimés peuvent modifier le total, les clients doivent donc mettre à jour à partir des événements WebSocket ou récupérer périodiquement /unread.

Messages

GET /conversations/{id}/messages?page=1&pageSize=50 → PagedMessagesDto:

{
  "conversationId": "<guid>",
  "page": 1,
  "pageSize": 50,
  "totalCount": 123,
  "items": []
}

POST /conversations/{id}/messages avec { "content": "hello" } → MessageDto. Débit limité à 10 messages/minute par utilisateur ; le dépasser revient 429.

PUT /conversations/{conversationId}/messages/{messageId} avec { "content": "edited" } → MessageDto.

DELETE /conversations/{conversationId}/messages/{messageId} → 204. La suppression est une pierre tombale : le message reste avec isDeleted: true.

MessageDto:

{
  "id": "<guid>",
  "conversationId": "<guid>",
  "senderId": "<guid>",
  "senderUsername": "alice",
  "content": "hello",
  "kind": "text",
  "metadata": { "key": "value" },
  "sentAt": "2026-07-22T07:00:00Z",
  "editedAt": null,
  "isDeleted": false
}

kind est "text" ou "system_rename"; content, metadata (a Dictionary<string,string>), et editedAt peut être absent/nul.

WebSocket : ws/v1/chat

Connectez-vous à wss://api.starhermit.com/ws/v1/chat avec un JWT via le Authorization en-tête, ?ticket=, ou ?access_token=.

C'est un serveur pur → canal push client: les frames client sont ignorées (uniquement Close est honoré). Chaque cadre est une enveloppe :

{ "type": "<event>", "payload": { } }
Événement type Charge utile
conversation_created ConversationDto
conversation_renamed ConversationDto
participants_added ConversationDto
participant_removed ConversationDto
chat_invite ChatInviteDto
chat_invite_responded ChatInviteDto
new_message MessageDto
message_updated MessageDto
message_deleted MessageDto
conversation_read Changement d'état de lecture pour l'utilisateur connecté ; récupérer les décomptes non lus
game_invite { "inviteId", "kind", "gameSlug", "gameName", "roomId", "from": { "userId", "username" }, "createdAt", "acceptPath", "declinePath", "inProgress", "sessionId" } - voir ci-dessous

game_invite : un événement pour les deux systèmes d'invitation

N'importe qui peut être invité à jouer de deux manières, et cet événement unique porte les deux : un client met en œuvre un toast, pas deux :

kind Délivré par L'accepter
"session" POST /games/{slug}/invites Crée une nouvelle session de jeu pour vous deux
"room" POST /realtime/rooms/{id}/invites Prend place dans une pièce dans laquelle l'invitant est déjà assis ; roomId est-ce que cette pièce

acceptPath et declinePath sont les points finaux qui répondent ce invitez - utilisez-les et la distinction n'a jamais d'importance. Répondre au point final de l'autre système est un 404: les deux conservent des identifiants d'invitation séparés.

inProgress est true lorsque vous acceptez de rejoindre une partie en cours de jeu – une invitation à une session qui nomme une session en cours ou une invitation à une salle démarrée qui permet de rejoindre une session en cours – et sessionId est la session de ce jeu. Utilisez-le pour dire "rejoignez leur jeu" au lieu de "jouer".

{
  "type": "game_invite",
  "payload": {
    "inviteId": "e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b",
    "kind": "room",
    "gameSlug": "poker",
    "gameName": "StarHermit Poker",
    "roomId": "b1d2c3e4-5f60-4a71-8b92-c3d4e5f60718",
    "from": { "userId": "9b2f8c1a-1111-4222-8333-444455556666", "username": "alice" },
    "createdAt": "2026-07-26T14:10:00Z",
    "acceptPath": "/api/v1/realtime/rooms/invites/e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b/accept",
    "declinePath": "/api/v1/realtime/rooms/invites/e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b/decline"
  }
}

roomId est null pour "session" invite. Un jeton de lancement à l'échelle du jeu ne peut pas ouvrir ce socket ni lire le nom de l'ensemble du compte. /me/game-invites boîte de réception. Sondage auprès des clients du jeu GET /api/v1/games/{slug}/invites pour les invitations à des sessions et GET /api/v1/realtime/rooms/invites pour leurs invitations à la salle de jeux. Les clients du compte peuvent lire les deux types GET /api/v1/me/game-invites.

Discutez au sein d'une session de jeu

Un jeton de lancement à l'échelle du jeu ne peut pas ouvrir ws/v1/chat - il est bloqué car le socket diffuse toutes les conversations d'un utilisateur. Jetons de lancement peut utiliser l'API REST de chat sur les conversations attachées à leurs propres sessions de jeu : le détail de la session renvoie un chatConversationId, la conversation est de type "game", ses participants sont les acteurs de la session et les règles d'amitié sont contournées.

Les clients de jeu chargent donc généralement l'historique via REST et interrogent les nouveaux messages au lieu d'utiliser le socket. Par exemple, le implémentation de référence d'échecs interroge toutes les 5 secondes :

GET /api/v1/chat/conversations/{chatConversationId}/messages?page=1&pageSize=50
Authorization: Bearer <launch-token>

POST /api/v1/chat/conversations/{chatConversationId}/messages
Authorization: Bearer <launch-token>
Content-Type: application/json

{ "content": "good game" }
