Catalogue de logiciels

Le catalogue de logiciels couvre la navigation et la revendication de titres, la création de listes, le téléchargement, les sauvegardes dans le cloud, la liste de souhaits et les évaluations. Les lectures sont anonymes ; les écritures nécessitent un JWT.

URL de base : https://api.starhermit.com. Tous les itinéraires sont sous /api/v1/....

Parcourir et revendiquer des titres

Méthode Chemin Authentification Description
OBTENIR /api/v1/software Anonyme Rechercher et paginer le catalogue
OBTENIR /api/v1/software/{id} Anonyme Obtenez un titre, ou 404
OBTENIR /api/v1/software/{id}/builds?page=&pageSize= Anonyme Liste paginée des builds pour un titre
POSTE /api/v1/software/{id}/claim JWT Réclamer soi-même un titre gratuit, accordant un droit
POSTE /api/v1/software/{id}/launch JWT Démarrer une session de lancement (nécessite un droit)

GET /api/v1/software accepte les paramètres de requête q (texte intégral), category, tag, publisherId, platform, releaseStatus, sort, page, et pageSize. Valide sort valeurs: name, name_desc, created, created_desc, updated, updated_desc. Il renvoie un PagedResult:

{
  "items": [
    {
      "id": "…",
      "name": "…",
      "description": "…",
      "publisherId": "…",
      "category": "…",
      "platform": "…",
      "releaseStatus": "…",
      "tags": ["…"],
      "priceCents": 0,
      "createdAt": "…",
      "updatedAt": "…"
    }
  ],
  "totalCount": 1,
  "page": 1,
  "pageSize": 20
}

GET /api/v1/software/{id}/builds renvoie un PagedResult de SoftwareBuild:

{
  "items": [
    {
      "id": "…",
      "titleId": "…",
      "version": "…",
      "releaseDate": "…",
      "releaseNotes": "…",
      "metadata": "…",
      "createdAt": "…",
      "updatedAt": "…"
    }
  ],
  "totalCount": 1,
  "page": 1,
  "pageSize": 20
}

POST /api/v1/software/{id}/claim fonctionne uniquement pour les titres gratuits (priceCents == 0); il accorde à l'appelant un droit et renvoie 204. Pour les titres payants, il renvoie 402 avec :

{"error": "purchasing is not available yet"}

POST /api/v1/software/{id}/launch nécessite un droit (403 sinon) et renvoie un LaunchSession:

{
  "launchId": "…",
  "startTime": "…"
}

Il enregistre une activité de lancement, qui est masquée si les paramètres de confidentialité de l'utilisateur le prévoient (voir profile.md). Terminez la séance avec POST /api/v1/activity/launches/{id}/end - voir activity.md. Les droits d'un utilisateur sont répertoriés via GET /api/v1/me/entitlements (voir profile.md).

Téléchargements

Méthode Chemin Authentification Description
POSTE /api/v1/software/{id}/download JWT Obtenez une URL de téléchargement signée (nécessite un droit)

Nécessite un droit (403 sinon). Retours :

{
  "downloadUrl": "…"
}

L'URL cible la première ressource téléchargeable de la dernière version. L'appel enregistre une activité de téléchargement. La distribution binaire du catalogue est actuellement un aperçu ; les URL renvoyées ne sont pas garanties en production téléchargements. Voir disponibilité des fonctionnalités avant de s’appuyer sur ce flux de publication.

Sauvegardes cloud

Un emplacement par jeu, la dernière écriture gagne. Tous les itinéraires nécessitent un JWT : un jeton d'utilisateur complet ou un jeton de jeu. jeton de lancement pour le propre emplacement de ce jeu (ci-dessous).

La limite de 10 Mo (10 485 760 octets) s'applique au sauvegarde décodée, pas la demande. PUT prend le sauvegarde codée en base64 en JSON, de sorte que le corps est environ un tiers plus grand que la sauvegarde – environ 14 Mo à le plafond - et l'API l'accepte.

Limite (par compte) Défaut Refus
Une sauvegarde, décodée 10 Mo 413 cloud_save_too_large
Jeux avec sauvegarde 200 409 cloud_save_slots_exhausted (une sauvegarde pour un nouveau jeu)
Tous les sauvegardes ensemble 1 Go 507 cloud_save_quota_exceeded, avec used
Téléchargements 30 par minute 429, avec Retry-After

Chaque refus nomme le numéro en vigueur comme limit. Le total est mesuré sur la durée du compte autre enregistre, de sorte qu'un emplacement peut toujours être écrasé par quelque chose de pas plus gros. Les opérateurs peuvent modifier n'importe lequel des ceux-ci pour un seul compte.

Méthode Chemin Authentification Description
OBTENIR /api/v1/me/cloud-saves/{gameKey}/info JWT Enregistrer les métadonnées : { exists, sizeBytes, updatedAt? }
OBTENIR /api/v1/me/cloud-saves/{gameKey} JWT application/zip octets, 404 si aucun
METTRE /api/v1/me/cloud-saves/{gameKey} JWT Téléchargez une sauvegarde (sauvegarde décodée ≤ 10 Mo, gameKey ≤ 300 caractères)

METTRE le corps :

{
  "dataBase64": "…"
}

Réponse PUT :

{
  "gameKey": "…",
  "sizeBytes": 0,
  "updatedAt": "…"
}

Sauvegarde depuis l'intérieur d'un jeu (jeton de lancement)

Un jeu exécuté avec son jeton de lancement peut lire et écrire la sauvegarde du joueur pendant ce jeu. Votre jeu s'enregistre partout où il est exécuté : un navigateur ou l'application de bureau StarHermit, qui s'exécute jeux hébergés également dans un navigateur – de sorte que la sauvegarde suit le joueur entre eux.

La clé est game:<gameId>, où <gameId> est l'identifiant de votre jeu - la même valeur que son slug, son <gameId>.starhermit.com l'adresse, et le game_scope revendication du jeton de lancement :

const key = `game:${gameScope}`;            // e.g. "game:3fa85f64-5717-4562-b3fc-2c963f66afa6"

// Load on startup — 404 means no save yet.
const res = await fetch(`/api/v1/me/cloud-saves/${key}`, { headers: { Authorization: `Bearer ${launchToken}` } });
if (res.status !== 404 && !res.ok) throw new Error(`Save load failed: ${res.status}`);
const save = res.status === 404 ? null : new Uint8Array(await res.arrayBuffer());
const etag = res.headers.get("ETag");
if (save && !etag) throw new Error("Save version unavailable; do not overwrite it.");
// Validate/decode your own save format before adopting it or enabling uploads.

// Save at checkpoints, not every frame.
const written = await fetch(`/api/v1/me/cloud-saves/${key}`, {
  method: "PUT",
  headers: {
    Authorization: `Bearer ${launchToken}`, "Content-Type": "application/json",
    ...(etag ? { "If-Match": etag } : { "If-None-Match": "*" }),
  },
  body: JSON.stringify({ dataBase64: base64(zipBytes) }), // Your ZIP encoder and bytes.
});
if (written.status === 412) throw new Error("Another device saved. Reload before writing again.");
if (!written.ok) throw new Error(`Save write failed: ${written.status}`);
const acknowledgement = await written.json(); // Retain acknowledgement.etag for your next write.
  • Seulement cette clé exacte. Toute autre clé : celle d'un autre jeu, celle d'un jeu en magasin ou une orthographe différente de la vôtre (majuscules, l'identifiant nu) - est 403 pour un jeton de lancement. Cela comprend github:<gameId>, l'emplacement séparé que l'application de bureau utilise lorsqu'un joueur synchronise un dossier de sauvegarde local pour votre jeu, donc cette synchronisation ne peut jamais écraser la sauvegarde écrite par votre jeu.
  • N'importe quel format. La plateforme n'ouvre jamais la sauvegarde ; stockez tout ce que votre jeu peut lire (c'est servi de application/zip indépendamment de). Jusqu'à 10 Mo.
  • Les écritures inconditionnelles sont les dernières victoires d'écriture, sans historique. Utiliser les écritures conditionnelles pour détecter deux onglets/appareils économisant en même temps. Chargez au démarrage et enregistrez aux points de contrôle au premier plan. Sortie de page les téléchargements s'effectuent au mieux et sont soumis à des limites de taille de navigateur ; voir la recette pour sauver en toute sécurité.
  • Chaque sauvegarde a une version. C'est ETag est en téléchargement, sur /info (aussi comme etag) et sur le PUT réponse. Renvoyez-le comme If-Match et l'écriture n'a lieu que si personne n'a sauvegardé depuis; sinon 412 {"error":"precondition_failed","etag":"<current>"} vous indique la version à charge. If-Match: * nécessite une sauvegarde existante ; If-None-Match: * n'écrit que lorsqu'il n'y en a pas. Sans en-tête PUT est inconditionnel : la dernière écriture l'emporte. UN GET avec If-None-Match: <etag> réponses 304 lorsque vous détenez déjà la sauvegarde la plus récente.
  • Un jeu sans liste hébergée (un jeu fourni par l'opérateur) n'a pas d'emplacement.

Les petites préférences qui changent fréquemment appartiennent à paramètres par joueur plutôt; ils sont également accessibles avec le jeton de lancement et prennent en charge les mises à jour partielles.

Liste de souhaits

Tous les itinéraires nécessitent un JWT.

Méthode Chemin Authentification Description
OBTENIR /api/v1/me/wishlist JWT { titleIds: guid[] }
METTRE /api/v1/me/wishlist/{titleId} JWT Ajouter à la liste de souhaits, 204 (idempotent)
SUPPRIMER /api/v1/me/wishlist/{titleId} JWT Supprimer de la liste de souhaits, 204

Notes

Tous les itinéraires nécessitent un JWT. La clé de jeu uniforme est un guide de catalogue, ou "provider:externalId" pour les jeux externes (voir external-libraries.md).

Méthode Chemin Authentification Description
METTRE /api/v1/me/ratings JWT Augmenter ma note pour un jeu
POSTE /api/v1/ratings/query JWT Résumés des évaluations par lots
OBTENIR /api/v1/ratings/reviews?key=&top= JWT Critiques d'un jeu (top par défaut 10)

METTRE le corps :

{
  "gameKey": "…",
  "stars": 4,
  "review": "…"
}

stars est compris entre 0 et 5 ; review est facultatif. La réponse est un RatingSummaryDto:

{
  "gameKey": "…",
  "average": 4.5,
  "count": 12,
  "myStars": 4
}

POST /api/v1/ratings/query corps et réponse :

{
  "keys": ["…", "…"]
}

retours RatingSummaryDto[]. GET /api/v1/ratings/reviews retours GameReviewDto[]:

[
  {
    "userId": "…",
    "username": "…",
    "stars": 4,
    "review": "…",
    "timestamp": "…"
  }
]
