Moteur

Où se procurer le moteur StarHermit, le runtime qui joue jeux de scénario. L'API de la plateforme est l'endroit idéal pour trouver les versions : elle répertorie chaque version, indique celles qui sont révoquées et donne les URL et les hachages des fichiers de chaque version. Les lectures sont anonymes.

URL de base : https://api.starhermit.com. Tous les itinéraires sont sous /api/v1/....

Méthode Chemin Authentification Description
OBTENIR /api/v1/engine/releases Anonyme Chaque version, la version la plus récente en premier, celles révoquées incluses
OBTENIR /api/v1/engine/releases/{version} Anonyme Une version par sa version exacte (X.Y.Z), ou 404 
{"releases": [{
  "version": "1.35.0", "api": {"major": 1, "minor": 35}, "revoked": false, "date": "2026-11-03T16:45:15Z",
  "web": {"base": "https://wiki.starhermit.com/engine/1.35.0/", "manifestIntegrity": "sha384-<SRI hash>"},
  "native": {"linux-x86_64": {
    "manifestUrl": "https://wiki.starhermit.com/engine/1.35.0/native/linux-x86_64/native.json",
    "manifestSha256": "<SHA-256 of native.json>"}}
}]}

GET /api/v1/engine/releases/{version} répond à un de ces objets sans le releases emballage. Les URL pointent vers wiki.starhermit.com pour les versions récentes et à engine.starhermit.com pour les plus âgés ; utilisez-les comme indiqué.

  • api est l'API hôte proposée par la version. Sa majeure est la majeure de la version et la engine.api un le jeu déclare ; son mineur augmente à mesure que des membres sont ajoutés (un jeu peut en nécessiter un avec engine.minor).
  • revoked: true est livré avec un revokedReason. Une version révoquée reste répertoriée afin que les clients puissent expliquer pourquoi ils le refusent.
  • web est null pour une version sans runtime Web. manifestIntegrity est le hachage SRI du web le temps d'exécution manifest.json, la valeur qu'une page de chargement épingle.
  • native a une entrée par plateforme (windows-x86_64, linux-x86_64, macos-x86_64, macos-aarch64), ou est {}. manifestSha256 est l'hexagone SHA-256 de cette plateforme native.json; vérifiez-le avant de faire confiance à la liste de fichiers à l'intérieur.

Les deux routes envoient Cache-Control: public, max-age=60 avec un ETag et réponds 304 à une correspondance If-None-Match. Si la plateforme n'a pas encore lu la liste des versions depuis son démarrage, elle répond 503 avec Retry-After.

Une version publiée ne change jamais : un correctif est la prochaine version. Le moteur tutoriel décrit la version la plus récente ; cette API dit laquelle c'est-à-dire.

Téléchargez le moteur

Les développeurs téléchargent le runtime natif d'une version pour écrire, vérifier, empaqueter et jouer à des jeux. Les joueurs font rien : le client StarHermit et la page d'un jeu récupèrent les pins de sortie du jeu.

  1. Demandez à l'API la version, la plus récente ou celle que votre jeu épingle :

    curl -s https://api.starhermit.com/api/v1/engine/releases/1.35.0

  2. Prenez celui de votre plateforme native.<platform>.manifestUrl, va chercher ça native.json et vérifiez son SHA-256 contre manifestSha256.

  3. native.json's downloads nomme le téléchargement du développeur avec son size et sha256. Les archives est assis à côté native.json: remplacer native.json à la fin de manifestUrl avec les archives nom. Téléchargez-le et vérifiez son SHA-256.

Les mêmes étapes qu'un script (nécessite curl, jq et sha256sum; sur l'utilisation de macOS shasum -a 256):

version=1.35.0 platform=linux-x86_64   # or windows-x86_64, macos-x86_64, macos-aarch64
release=$(curl -fsS "https://api.starhermit.com/api/v1/engine/releases/$version")
manifest_url=$(jq -r --arg p "$platform" '.native[$p].manifestUrl' <<<"$release")
manifest_sha=$(jq -r --arg p "$platform" '.native[$p].manifestSha256' <<<"$release")
curl -fsSO "$manifest_url"
echo "$manifest_sha  native.json" | sha256sum -c -
archive=$(jq -r '.downloads | keys[0]' native.json)
curl -fsSO "${manifest_url%native.json}$archive"
echo "$(jq -r --arg a "$archive" '.downloads[$a].sha256' native.json)  $archive" | sha256sum -c -

Dans PowerShell, Invoke-RestMethod lit le communiqué et Get-FileHash -Algorithm SHA256 donne le hachage à comparer. Le tutoriel couvre le déballage et la première manche.

Le outils de développement autonomes (publication automatisée et serveur de développement MCP) sont publiés séparément du runtime.

Intégrité

Une chaîne de hachage couvre chaque octet exécuté par un client :

  1. L'API donne le SHA-256 d'une version native.json.
  2. native.json donne le SHA-256 et la taille de chaque fichier, ainsi que son téléchargement par le développeur sous downloads.
  3. Le client StarHermit récupère uniquement les éléments d'une version qu'il ne détient pas déjà, les vérifie chacun, rassemble chaque fichier et le vérifie avant de mettre la version en place.

La page de chargement d'un jeu par navigateur épingle le moteur d'exécution Web starhermit.js et manifest.json avec l'ISR hachages, et le runtime vérifie tous les autres fichiers qu'il charge par rapport au manifeste.

L'environnement d'exécution Web

La page de chargement d'un jeu (index.html, écrit par starhermit package --web) charges starhermit.js et manifest.json depuis https://engine.starhermit.com/engine/X.Y.Z/, avec les mêmes hachages SRI que le URL sous web.base. Utiliser engine.starhermit.com dans n'importe quelle page de chargement que vous écrivez vous-même : il conserve chaque version, tandis que les URL sous web.base ne conserver que les versions récentes et une ancienne version disparaît d'eux. Les outils de la version 1.26.0 écrivent engine.starhermit.com par défaut (--loader-base URL ou STARHERMIT_WEB_LOADER_BASE le remplace). Pour un jeu hébergé packagé par des outils plus anciens, la plateforme réécrit les deux URL du moteur lorsque la version n'est plus sous web.base; reconditionner les jeux hébergés ailleurs. Une version révoquée n’est signifiée ni par l’une ni par l’autre origine.

Jeux de script sur la plateforme

Quand la racine d'un jeu starhermit.txt déclare engine.version, la plateforme le traite comme un jeu de script :

  • chaque publication enregistre la publication du code PIN des fichiers, comme hosting.engineVersion, et définit hosting.deployWarning (également dans la réponse d'un bundle push) lorsque cette version n'est pas répertoriée ou est révoqué. Un avertissement n'arrête jamais une publication.
  • chaque page du jeu hébergé est accompagnée d'une politique de sécurité du contenu qui n'admet que les scripts des deux origines du moteur (et du moteur propre blob: travailleurs), donc le seul code est un script la page du jeu peut fonctionner est le moteur officiel :
default-src 'self'; script-src https://wiki.starhermit.com https://engine.starhermit.com 'wasm-unsafe-eval' blob:; worker-src blob:;
connect-src 'self' https://wiki.starhermit.com https://engine.starhermit.com; img-src 'self' blob: data:; media-src 'self' blob:;
style-src 'self' 'unsafe-inline'; font-src 'self' https://wiki.starhermit.com https://engine.starhermit.com;
frame-ancestors https://dashboard.starhermit.com; base-uri 'self'; form-action 'none'

Une page d'un jeu de script sans version de navigateur (comme la page simple téléchargée par un jeu Windows uniquement) pour les navigateurs) ne nécessite aucun script et n'est pas affecté.

Révocations

Une version jugée dangereuse est révoquée. Le client StarHermit ne l'installe ni ne le démarre et indique au joueur, les commandes d'empaquetage refusent d'empaqueter un jeu pour lui, et la plateforme avertit les propriétaires de les jeux qui l'épinglent lors de leur publication. Une version révoquée est toujours suivie d'une version corrigée : ré-épinglez-y et publier (voir Passer à un moteur plus récent).
