Liens externes

Un jeu avec moteur StarHermit (API hôte 1.24) peut ouvrir une page Web, mais une seule que le personnel de StarHermit avoir approuvé votre jeu. Votre jeu ouvre un lien par identifiant et ne transmet jamais d'URL, il ne peut donc pas ajouter n'importe quoi contre un.

Déclarez vos liens

Dans starhermit.txt:

engine.minor=24
engine.link.discord=https://discord.gg/abc
engine.link.store=https://example.com/game
  • Vous pouvez déclarer jusqu'à 16 liens. Chaque identifiant comporte de 1 à 32 caractères a-z 0-9 - et ne peut apparaître qu'une seule fois.
  • N'importe lequel engine.link.* besoins clés engine.minor=24, donc les anciens runtimes refusent le jeu.
  • Vos scripts appellent openLink("discord"). Le runtime affiche sa propre confirmation, avec le lien hôte et URL complets, et ouvre la page uniquement si le joueur choisit Ouvrir.

Qu'est-ce qu'un lien peut être

Un lien doit être https, sans port, non user@, pas d'adresse IP et pas de nom local (localhost, .local, .internal). Son hôte doit être ASCII, avec des noms internationalisés écrits en punycode, et avoir au moins deux étiquettes. Il ne peut pas contenir de barres obliques inverses, d'espaces, de barres obliques codées (%2f, %5c) ou ./.. segments de chemin. La plateforme conserve la forme canonique : le schéma et l'hébergeur en minuscules, et / pour un chemin vide. Tout le reste est conservé exactement tel que vous l’avez écrit.

Un package avec un lien qui enfreint une règle est refusé lors de votre publication, avec 422 invalid_link: engine.link.<id> is not an allowed link (<rule>), avant que quoi que ce soit ne soit mis en ligne.

Revoir

Chaque nouveau lien démarre pending, et le runtime n'ouvre rien jusqu'à ce que le personnel l'approuve. Certains liens sont rejeté automatiquement : raccourcisseurs d'URL et services de redirection, dont la destination est quelqu'un d'autre contrôles et téléchargements directs de programmes et d'archives (.exe, .dmg, .apk, .zip et similaire). Paramètres de suivi tels que utm_* sont signalés pour le réviseur.

Une approbation appartient à votre jeu et à cette URL exacte. Une version ultérieure répertoriant la même URL, sous n'importe quelle pièce d'identité, la garde. La modification de l'URL nécessite un nouvel examen. Le personnel peut révoquer une approbation ou bloquer un hôte entier, à tout moment.

Consultez vos liens et leur statut sur GET /api/v1/me/github-games/{id}/links:

[ { "id": "discord", "url": "https://discord.gg/abc", "status": "approved", "autoReason": null, "note": null } ]

Les vérifications d'exécution GET /api/v1/games/{slug}/links/{id} à chaque ouverture, au lancement du joueur jeton. La réponse est { id, url, status }, où status est approved, pending, rejected ou revoked, ou 404 link_unknown pour un identifiant que votre manifeste déployé ne déclare pas.

Pendant que vous développez localement (--dev nativement, ou une page de bouclage dans le navigateur, sans lancement token), le runtime ouvre les liens déclarés derrière un avertissement indiquant qu'ils ne sont pas examinés.
