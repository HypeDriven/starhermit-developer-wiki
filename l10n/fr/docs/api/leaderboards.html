Classements

Définitions et entrées du classement. Les lectures sont anonymes ; la soumission d'une partition nécessite un JWT.

URL de base : https://api.starhermit.com. Tous les itinéraires sont sous /api/v1/....

Méthode Chemin Authentification Description
OBTENIR /api/v1/leaderboards Anonyme Liste des définitions (requête scope, region, titleId)
OBTENIR /api/v1/leaderboards/{id} Anonyme Obtenez une définition
OBTENIR /api/v1/leaderboards/{id}/entries?scope=&region=&friendsOnly=&page=&pageSize= Anonyme Entrées paginées ; friendsOnly=true nécessite une authentification
POSTE /api/v1/leaderboards/{id}/submit JWT Soumettre une note (tableaux du catalogue uniquement)
OBTENIR /api/v1/games/{slug}/leaderboards Porteur Les propres plateaux actifs de votre jeu (jeton de lancement accepté)
OBTENIR/POSTER /api/v1/me/github-games/{id}/leaderboards JWT (propriétaire du jeu) Lister/créer les plateaux de votre jeu
METTRE/SUPPRIMER /api/v1/me/github-games/{id}/leaderboards/{leaderboardId} JWT (propriétaire du jeu) Mettre à jour/supprimer un

Jeux faisant autorité et Elo

Chaque jeu faisant autorité a un classement elo ; son identifiant vient de GET /api/v1/games/{slug} → leaderboardId (voir games.md). Les partitions sont écrites UNIQUEMENT par la plateforme à partir du script eloUpdates ou le canal de contrôle des conteneurs - la soumission directe est refusée. Les clients du jeu lisent les entrées via le point de terminaison paginé standard ; par exemple, les demandes d'implémentation de référence d'échecs :

GET /api/v1/leaderboards/{leaderboardId}/entries?friendsOnly=true&page=1&pageSize=10

Les jetons de lancement à l'échelle du jeu peuvent lire le classement de leur propre jeu. Le classement côté éditeur CRUD réside dans publisher.md.

Réinitialiser la note d'un joueur

Le propriétaire du jeu peut remettre la note d'un joueur au niveau de départ. 1200 — pour un schtroumpf, un boosté compte, ou une note d'un bug corrompu :

DELETE /api/v1/me/github-games/{id}/players/{userId}/elo      → 200 { "userId": "…", "elo": 1200 }

Il réinitialise les paires de matchmaking, supprime la ligne du joueur du tableau elo (il renvoie avec leur prochaine correspondance notée) et définit un chiffre numérique de premier niveau elo dans le document du lecteur de votre script à 1200 — parce que votre script calcule la prochaine note à partir de son propre document, en réinitialisant uniquement le la copie de la plateforme serait annulée lors du prochain match. Tout le reste dans le document (victoires, historique) est laissé seul. Si votre script conserve sa note sous un autre nom, il est pas réécrit : garder c'est dans playerStates[id].elo pour obtenir des réinitialisations gratuitement. Un match déjà en cours peut encore signaler un note calculée avant la réinitialisation. 404 lorsque le jeu n'est pas le vôtre ou que le joueur n'a pas de note dans ça. La notation est également soumise aux règles élo.

Réinitialiser les horaires

N'importe quel classement – ​​le propre tableau d'un jeu ou celui d'un titre de catalogue – peut recommencer selon un calendrier :

resetSchedule Recommence
daily tous les jours à 00h00 UTC
weekly tous les lundis à 00h00 UTC
monthly le 1er de chaque mois à 00h00 UTC
omis, null ou "never" jamais

Toute autre valeur est une 400. Les rapports de définition currentPeriodStartedAt et nextResetAt (les deux null pour une carte qui ne se réinitialise jamais), afin qu'un client puisse montrer "se réinitialise dans 2 jours".

Une réinitialisation est appliquée lorsque la carte est lire : le point final des entrées affiche uniquement les scores soumis depuis la période en cours a commencé et les classements sont calculés au cours de la période. Rien n'est supprimé au limite, donc la réinitialisation prend effet à exactement 00h00 UTC. Cela signifie également que l'horaire peut être modifié à tout moment — cela modifie les entrées affichées et non celles conservées. Les périodes précédentes ne sont pas lisible via l'API.

Les propres classements de votre jeu

A côté de son plateau elo, un jeu avec un server= script ou container.image= le backend peut avoir ses propres classements – meilleur score, tour le plus rapide, plus de victoires – créés par le propriétaire du jeu. Vous n'avez pas besoin d'un compte éditeur : posséder le jeu fait de vous son éditeur.

Comme le tableau elo, seul le serveur de votre jeu leur écrit. Votre script revient scores: { "<key>": { "<userId>": score } } de n'importe quel crochet (voir Scripts de jeu – Classements), ou votre conteneur envoie un scores message de contrôle. POST /leaderboards/{id}/submit est refusé, donc un client modifié ne peut pas poster de score.

Créez-en un – POST /api/v1/me/github-games/{id}/leaderboards

{
  "key": "high-score",
  "name": "High score",
  "scoreType": "integer",
  "sortDirection": "desc",
  "minScore": 0,
  "maxScore": 1000000,
  "isActive": true
}

Retours 201 avec un LeaderboardDefinitionDto dont gameDefinitionId et key sont fixés.

Champ Signification
key Requis. Le nom que votre serveur soumet sous : 1 à 64 lettres, chiffres, ., _, -. Unique par jeu.
name Requis. Nom à afficher, 200 caractères maximum.
scoreType integer (défaut), decimal, ou time-ms (un nombre entier non négatif de millisecondes)
sortDirection desc (par défaut : plus c'est haut, mieux c'est) ou asc (plus bas est mieux, par exemple les temps au tour)
minScore / maxScore Limites facultatives ; un score en dehors d'eux est ignoré
isActive Défaut true. Un tableau inactif n'accepte aucun score et n'est pas répertorié pour les joueurs.
resetSchedule Facultatif: daily, weekly ou monthly - voir Réinitialiser les horaires. Par défaut : ne se réinitialise jamais.

key, scoreType et sortDirection ne peut pas changer après la création: votre serveur soumet par clé, et les partitions déjà stockées ont été choisies par les deux autres. Besoin d'un autre ? Créez un nouveau tableau. PUT .../leaderboards/{leaderboardId} accepte name, minScore, maxScore, isActive et resetSchedule (envoyer "never" pour arrêter la réinitialisation); DELETE enlève le tableau et ses entrées - ensemble isActive: false de le mettre à la retraite et de les conserver. Un jeu peut avoir au plus 2048 planches.

Comment les scores sont conservés

  • Une entrée par joueur : son meilleur. "Meilleur" suit le conseil d'administration sortDirection. Soumettre un un score pire ne change rien, alors faites un rapport après chaque match sans vérifier au préalable. Sur un tableau avec un planning de réinitialisation, c'est le mieux cette période: le premier score après une réinitialisation compte toujours, aussi bon que soit le score du joueur lors de la dernière période.
  • Seuls les joueurs de la session peuvent être marqués ; le siège AI et toute autre personne sont ignorés.
  • Un score qui enfreint les règles du jeu (hors de portée, fraction sur un integer conseil, un négatif time-ms) est ignoré, tout comme une clé sans carte active. Rien n'est renvoyé à votre serveur.

Montrez-les dans votre jeu

GET /api/v1/games/{slug}/leaderboards répertorie les plateaux actifs du jeu avec leur id et key, et fonctionne avec le jeton de lancement du jeu. Lire les entrées avec le point de terminaison paginé standard ci-dessus : GET /api/v1/leaderboards/{id}/entries — que le jeton de lancement peut également atteindre pour ces cartes.
