Éditeur

L'espace éditeur : gérez les organisations d'éditeurs et leurs membres, créez et téléchargez des titres et des builds de logiciels, et gérez les réalisations, les droits et les définitions de classement pour vos titres.

Publier un jeu plutôt qu'un titre de catalogue ? Vous n’avez besoin de rien de tout cela. Le propriétaire d'un jeu avec un backend de script ou de conteneur est son éditeur et gère ses classements et réalisations sous /api/v1/me/github-games/{id}/… - voir Tutoriel : classements et réalisations pour votre jeu.

URL de base : https://api.starhermit.com. Tous les itinéraires nécessitent un JWT ainsi que les revendications d'autorisation répertoriées. Rôles : PublisherMember, PublisherOwner. Les demandes d'autorisation sont attribuées via des rôles ; les jetons frappés portent les revendications d'autorisation.

Editeurs et membres

Préfixe de l'itinéraire : api/v1/publisher.

Méthode Chemin Authentification Description
POSTE /api/v1/publisher JWT (Permission-publisher.content.manage) Créer un éditeur ; le créateur devient membre avec un rôle "Owner" → 201
OBTENIR /api/v1/publisher JWT (Permission-publisher.content.manage) Liste des éditeurs → Publisher[]
POSTE /api/v1/publisher/{publisherId}/members JWT (Permission-publisher.members.manage) + rôle Owner Ajouter un membre → 204
SUPPRIMER /api/v1/publisher/{publisherId}/members/{memberUserId} JWT (Permission-publisher.members.manage) + rôle Owner Supprimer un membre → 204 (le propriétaire ne peut pas être supprimé)
OBTENIR /api/v1/publisher/{publisherId}/members/{memberUserId} JWT (Permission-publisher.members.manage) + adhésion à cet éditeur Devenir membre → PublisherMember

Qui peut changer d'adhésion

La revendication d'autorisation indique que vous pouvez gérer les membres éditeurs quelque part ; ça ne dit pas lequel éditeur. Les deux contrôles s’appliquent donc :

  • L'ajout et la suppression de membres sont Owner-seulement. L'adhésion confère une autorité de gestion de contenu sur chacun des titres de l'éditeur, donc un simple membre qui pourrait ajouter des membres pourrait accorder cela autorité à quiconque. Un non-propriétaire obtient 401.
  • La lecture d’une adhésion nécessite d’appartenir à cet éditeur. Un appelant à l'extérieur reçoit la même chose 404 en tant qu'utilisateur qui n'est pas membre, le point de terminaison ne révèle donc rien sur les éditeurs que vous n'êtes pas une partie de.

Créer un éditeur

POST /api/v1/publisher

{
  "name": "HypeDriven",
  "description": "..."
}

Le créateur devient membre avec rôle "Owner".

Ajouter un membre

POST /api/v1/publisher/{publisherId}/members

{ "userId": "<user id>" }

Titres et builds de logiciels

Méthode Chemin Authentification Description
POSTE /api/v1/publisher/software JWT (Permission-publisher.content.manage) Créer/mettre à jour un titre de logiciel (corps = métadonnées du titre ; adhésion à l'éditeur réel du titre obligatoire)
POSTE /api/v1/publisher/software/upload JWT (Permission-publisher.content.manage + Permission-publisher.binary.publish) Obtenir les URL de téléchargement pour un titre → UploadUrlInfo[]
POSTE /api/v1/publisher/software/build/finalize JWT (Permission-publisher.content.manage + Permission-publisher.binary.publish) Finaliser une build à partir des ressources téléchargées → 204
OBTENIR /api/v1/publisher/analytics/downloads?publisherId= JWT (Permission-publisher.content.manage) Nombre de téléchargements par titre
OBTENIR /api/v1/publisher/analytics/launches?publisherId= JWT (Permission-publisher.content.manage) Nombre de lancements par titre

La publication d'une version nécessite la subvention de publication binaire

Les deux points de terminaison de build nécessitent publisher.binary.publish au sommet de publisher.content.manage et l'adhésion à l'éditeur du titre. Sans cela, les deux répondent 403, tandis que tous les autres points de terminaison de cette page continuent de fonctionner - vous pouvez créer et modifier des titres, définir les réalisations et les classements, ainsi que les droits aux subventions ; vous ne pouvez tout simplement pas envoyer un exécutable.

La raison est ce qu'est une construction. Les ressources d'une build sont téléchargées par le client de bureau et exécutées sur le la machine du joueur avec les privilèges du joueur, en dehors de tout contrôle de Starhermit bac à sable - contrairement à un jeu par navigateur, qui s'exécute dans le navigateur. Ainsi, le droit d'en publier un est accordé par compte par un Administrateur de Starhermit (le BinaryPublisher rôle), non acquis par la création d’un éditeur. Non un autre rôle le porte. Demandez la subvention à un administrateur avant de créer un flux de téléchargement sur ces points de terminaison; il est également supprimé lorsqu'un compte d'éditeur est suspendu.

Les jeux par navigateur n'ont besoin de rien de tout cela : /api/v1/me/github-games soumissions, téléchargements de dossiers et bundle les push restent en libre-service pour tout compte connecté.

Créer ou mettre à jour un titre de catalogue

POST /api/v1/publisher/software accepte id (omettre pour un nouveau titre), publisherId, name, description, category, platform, releaseStatus, tags, et priceCents:

{
  "publisherId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "name": "Orbit League",
  "description": "A space racing game.",
  "category": "game",
  "platform": "windows",
  "releaseStatus": "released",
  "tags": ["racing"],
  "priceCents": 0
}

Le succès est 201 avec le titre. Seules les métadonnées du titre sont acceptées ; ne pas envoyer d'adhésion d'éditeur ou des objets d'actif ici. La création d'un éditeur revient 201 sans objet éditeur ; liste GET /api/v1/publisher pour obtenir son identifiant.

Obtenir les URL de téléchargement

POST /api/v1/publisher/software/upload

{ "titleId": "<title id>" }

Réponse - UploadUrlInfo[]:

[
  {
    "type": "executable",
    "uploadUrl": "...",
    "fieldKey": "..."
  }
]

type est l'un des "executable", "data", "metadata".

Finaliser une build

POST /api/v1/publisher/software/build/finalize → 204

{
  "titleId": "<title id>",
  "buildId": "<optional build id>",
  "version": "1.0.0",
  "releaseNotes": "...",
  "assets": [
    { "type": "executable", "checksum": "...", "fieldKey": "..." }
  ]
}

Le workflow de création de catalogue est actuellement en version préliminaire et ne fournit pas de livraison binaire de production. ou une garantie de vérification du contenu ou d'analyse des logiciels malveillants. Ne pas traiter une construction ou un actif accepté statut comme preuve qu’un exécutable est sûr. Voir disponibilité des fonctionnalités. La publication de jeux hébergés utilise le API de téléchargement de jeu.

Analytique

Les deux points de terminaison renvoient un identifiant de titre de mappage d'objet JSON à compter :

{ "<titleId>": 42 }

Réalisations

Itinéraire api/v1/publisher; toutes les voies de gestion des réalisations nécessitent Permission-publisher.content.manage.

Ces points de terminaison gèrent titre-catalogue réalisations uniquement. Ils exigent également que l'appelant soit un membre de l'éditeur propriétaire du titre, et ils échec fermé pour les réalisations qui appartiennent à un jeu faisant autorité — ceux-ci sont déclarés par le script du jeu ou le backend du conteneur et ne le sont pas géré par l'éditeur (voir Réalisations, Scripts de jeu, et Serveurs de jeux de conteneurs).

Méthode Chemin Authentification Description
POSTE /api/v1/publisher/titles/{titleId}/achievements JWT Créer une réalisation → AchievementDto
OBTENIR /api/v1/publisher/titles/{titleId}/achievements JWT Lister les réalisations d'un titre → AchievementDto[]
OBTENIR /api/v1/publisher/achievements/{id} JWT Obtenez un succès → AchievementDto
METTRE /api/v1/publisher/achievements/{id} JWT Mettre à jour (tous les champs nullables) → AchievementDto
SUPPRIMER /api/v1/publisher/achievements/{id} JWT Supprimer → 204

Créer une réalisation

POST /api/v1/publisher/titles/{titleId}/achievements

{
  "key": "first_win",
  "name": "First Win",
  "description": "Win your first game.",
  "icon": "...",
  "secret": false,
  "points": 10,
  "visibility": "...",
  "criteria": "..."
}

icon, visibility, et criteria sont facultatifs. Sur PUT, tous les champs sont nullables. Voir achievements.md pour la surface face au joueur.

Créer un classement

POST /api/v1/publisher/leaderboards/

{
  "name": "Global Elo",
  "scoreType": "...",
  "sortDirection": "...",
  "resetSchedule": "...",
  "minScore": 0,
  "maxScore": 4000,
  "scope": "...",
  "region": "...",
  "isActive": true,
  "softwareTitleId": "<optional title id>"
}

resetSchedule, minScore, maxScore, region, et softwareTitleId sont facultatifs. Sur PUT, tous les champs sont nullables. resetSchedule est daily, weekly, monthly ou never; tout le reste est un 400 - voir Réinitialiser les horaires. Voir leaderboards.md pour la surface face au joueur.

Publier un build : flux

  1. Détenir la subvention de publication binaire: les étapes 3 et 5 nécessitent publisher.binary.publish, lequel un Subventions d'administrateur Starhermit par compte. Voir La publication d'une version nécessite la subvention de publication binaire.
  2. Créer un éditeur: POST /api/v1/publisher avec { name, description }.
  3. Créer le titre: POST /api/v1/publisher/software avec les métadonnées du titre ci-dessous.
  4. Obtenir les URL de téléchargement: POST /api/v1/publisher/software/upload avec { titleId }.
  5. Télécharger des fichiers au retour uploadUrls.
  6. Finaliser la construction: POST /api/v1/publisher/software/build/finalize avec les ressources téléchargées' { type, checksum, fieldKey } entrées.
  7. Vérifier la disponibilité de la distribution: l'aperçu actuel du catalogue ne garantit pas les téléchargements de production vérifiés ni l'analyse des logiciels malveillants ; voir disponibilité.
  8. Les utilisateurs réclament et téléchargent le titre dans le catalogue — voir catalog.md.

Les corps d’erreur varient ; voir Conventions API.
