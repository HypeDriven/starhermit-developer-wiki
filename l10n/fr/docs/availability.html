Disponibilité et confiance des fonctionnalités

Utilisez les champs de réponse et de découverte du point de terminaison comme réponse pour le déploiement que vous ciblez. Un itinéraire publié ou un wrapper SDK ne garantit pas que tous les services facultatifs sont disponibles.

Les limites indiquées dans les pages de référence sont celles par défaut, sauf si une valeur spécifique au déploiement est explicitement indiquée. Utiliser les limites renvoyées et Retry-After. A 503 overloaded avec Retry-After: 300 signifie réessayer le conseil, ce n'est pas une promesse que le service sera disponible cinq minutes plus tard.

Routes de génération réservées

Le préfixe de génération du lecteur/serveur est /api/v1/games/{slug}/generation: découverte, citations, et Les itinéraires de création/lecture/suppression de tâches sont réservés. Les itinéraires compte/propriétaire et fournisseur public sont également réservé. Les appelants valides reçoivent actuellement 503 avec:

{ "error": "overloaded", "code": "overloaded", "retryAfterSeconds": 300 }

L'authentification et la portée du jeu s'appliquent toujours. Aucun résultat de génération, achat ou fournisseur utilisable la connexion est promise. Ces réserves sont répertoriées séparément dans le Contrat REST.

Qu’est-ce qui rend un résultat fiable ?

Modèle Garanties de la plateforme Ce que votre jeu doit valider
Salle acheminée par l'hôte Expéditeur authentifié, hôte attribué, sièges et routage Simulation et honnêteté de l’hôte ; les clients peuvent être modifiés
Prix ​​​​de scénario/conteneur Seul le backend du jeu écrit les scores et les réalisations du jeu ; les destinataires doivent être des participants Si le gameplay a réellement mérité le prix
Score solo signalé par le client avec limites Le serveur vérifie le type/plage numérique avant d'écrire Un numéro plausible ne constitue pas la preuve d'une course légitime
Réalisation revendiquée par le client Vérifications des comptes et des droits Condition de déverrouillage observée par le client ; un client modifié peut le réclamer
Sauvegarde ou paramètres dans le cloud Données limitées du joueur authentifié Validation des documents, règles du jeu et question de savoir si les progrès peuvent être fiables pour la compétition
Association d'identité externe L'identité a été associée au compte Vérifier les billets/propriété de la vitrine via la vitrine si nécessaire

Le fourni score-script.js accepte les valeurs signalées par le client dans les limites configurées. C'est utile pour les plateaux solo occasionnels, mais n'empêche pas les résultats inventés à portée. Pour la compétition jouer, simuler des règles faisant autorité ou vérifier une rediffusion d'entrées enregistrées avant d'attribuer des scores. Ne déduisez jamais les garanties anti-triche simplement d'une API refusant les soumissions directes de scores.

De même, un backend attaché uniquement aux récompenses ne peut pas vérifier le gameplay qu’il n’observe jamais. Définissez les preuves qu'il accepte, validez-les et expliquez clairement ce modèle de confiance aux joueurs lorsqu'il compte. Voir choisir une intégration.
