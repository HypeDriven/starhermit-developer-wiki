SDK Unity

Le SDK Starhermit Unity (HypeDriven/starhermit-unity-sdk) est un package Unity Package Manager avec des clients C# typés et asynchrones pour la plateforme. Il gère Requêtes HTTP, analyse JSON, actualisation des jetons et reconnexion WebSocket.
Emballer com.starhermit.sdk, version 0.1.0
Espace de noms Starhermit
Référence de l'API REST v1 et WebSocket v1
Fonctionnalités REST plus récentes Utiliser client.Raw et modèle RawJson lorsque cette version du SDK n'a pas de membre typé
Protocoles WebSocket tous les 6, une classe de connexion chacun
Licence MIT

Le SDK est un client et non une seconde implémentation de la plateforme. Autorisation, amitié, les droits, l'adhésion à la chambre, la validation des scores, les résultats des jeux et les budgets de stockage restent faisant autorité sur le serveur exactement comme documenté dans les pages ci-dessous — le SDK fait apparaître la réponse du serveur et ses limites publiées plutôt que de décider ou de mettre en cache les siennes.

Cette page est le guide d'intégration. La documentation complète du package se trouve dans le référentiel sous Packages/com.starhermit.sdk/Documentation~.

Exigences

  • Unity 2021.3 LTS ou version ultérieure, niveau de compatibilité API Norme .NET 2.1, C# 9.
  • Mono et IL2CPP, avec suppression gérée de Désactivé à Haut (le colis expédie son propre Runtime/link.xml).
  • Aucune réflexion, aucune génération de code dynamique, aucun plugin natif obligatoire.

Chaque module compile pour chaque cible de build. Lorsqu’une cible manque réellement de capacité – non microphone sur un serveur sans tête, pas d'en-têtes de prise de contact dans un navigateur - l'appel est lancé StarhermitFeatureUnavailableException avec une écurie Reason, au lieu d'échouer la construction ou désactiver les fonctionnalités non liées.

Installer

Gestionnaire de paquets → Ajouter un package à partir de l'URL git, ou une entrée dans Packages/manifest.json. Le paquet se trouve dans un sous-dossier du référentiel, l'URL doit donc path=:

{
  "dependencies": {
    "com.starhermit.sdk": "https://github.com/HypeDriven/starhermit-unity-sdk.git?path=/Packages/com.starhermit.sdk"
  }
}

Épinglez une version en ajoutant #<tag-or-commit>:

https://github.com/HypeDriven/starhermit-unity-sdk.git?path=/Packages/com.starhermit.sdk#v0.1.0

Unity débourse pour git, donc un dépôt privé n'est résolu que si le git de l'éditeur peut s'authentifier de manière non interactive - une clé SSH (git@github.com:HypeDriven/starhermit-unity-sdk.git?path=/Packages/com.starhermit.sdk) ou un assistant d'identification configuré. Un chemin local ou un registre étendu fonctionne de la même manière. L'importation modifie non paramètres du projet et n’effectue aucun accès au réseau.

Créer un client

using Starhermit;

var client = StarhermitClient.Create(new StarhermitOptions
{
    ApiBaseUri = new Uri("https://api.starhermit.com/api/v1/"),
    GameSlug   = "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
    TokenStore = myPlatformSecureStore,
    LogLevel   = StarhermitLogLevel.Warning
});

await client.InitializeAsync();               // loads a stored session, refreshes it if expired
var me = await client.Me.GetProfileAsync();

Create n'effectue aucune E/S. Rien ne touche le réseau jusqu'à ce que vous initialisiez, appeliez un service ou ouvriez un connexion. La base WebSocket est dérivée de ApiBaseUri (wss://<host>/ws/v1/) sauf si vous définissez WebSocketBaseUri toi-même.

StarhermitClient est IDisposable : la suppression annule les demandes en vol, ferme chaque connexion distribué, arrête les battements de cœur et libère l'audio. Il n'y a pas d'état mutable statique dans le package, donc deux clients peuvent fonctionner côte à côte dans des environnements différents et un client survit aux chargements de scène.

Un jeu publié sur la plateforme est servi à partir de https://<slug>.starhermit.com avec /api et /ws proxy de même origine (voir Jeux GitHub). Une version WebGL publiée qui way doit pointer vers sa propre origine afin que le navigateur effectue des appels de même origine :

ApiBaseUri = new Uri("https://83fd04b1-3cbe-4b09-a251-3733ad4b9d94.starhermit.com/api/v1/") // your game's uid

Pour un backend local, AllowInsecureTransport = true permis http/ws. Le client construction refuse un adresse non HTTPS sans elle, et la validation de build de l'éditeur échoue à une build de lecteur non-développeur cela l'a toujours réglé. Il ne désactive jamais la validation du certificat.

Connexion

Les trois types de titres de compétences décrits dans Authentification sont des types distincts dans des magasins dans le SDK ; aucun ne peut remplacer un autre.

OAuth — le SDK ouvre l'URL d'autorisation via un fichier injecté IStarhermitOAuthBrowser et complète l'échange :

var session = await client.Auth.SignInWithOAuthAsync("google");

Utiliser BuildAuthorizeUri(provider) plus CompleteOAuthAsync(...) au lieu de cela, lorsque votre plate-forme remet le redirigez-le via sa propre plomberie de lien profond ou de navigateur intégré.

Clé publique — le flux sans mot de passe pour les lecteurs embarqués, consoles et serveurs dédiés (voir Serveur dédié + intégration de lecteurs intégrés). Les types de clés pris en charge sont Ed25519, ECDSA-P256 et RSA-PSS; le SDK ne génère ni ne stocke jamais de clé privée, il appelle une clé injectée IStarhermitSigner:

var session = await client.Auth.SignInWithPublicKeyAsync(signer);   // or (), using Options.Signer

Détail du contrat à connaître. Le déploiement vérifie une signature de défi par rapport à la sienne PascalCase sérialisation du défi, alors que le JSON que vous recevez est camelCase — re-sérialisation la réponse ne serait jamais vérifiée. StarhermitChallenge.CanonicalPayload reproduit les octets exacts à signe, donc la signature roulée à la main doit faire de même.

Jeton de lancement du jeu — frappé par jeu et clôturé sur la surface de ce jeu :

var chess = client.Games.ForSlug("83fd04b1-3cbe-4b09-a251-3733ad4b9d94");
await chess.AcquireLaunchTokenAsync();
var fenced = chess.WithLaunchToken();     // subsequent calls authorise with the launch token

La création d'un jeton de lancement ne remplace jamais la session de compte. Les informations d'identification portées par une demande sont décidé par le pipeline de requêtes, et non par le service que vous avez appelé.

L'actualisation du jeton d'accès est coordonnée : un 401 achète au plus une actualisation et une relecture, et simultanément les appelants attendent la même actualisation plutôt que d'en démarrer plusieurs - avec un jeton d'actualisation rotatif, une seconde l'échange révoquerait la famille et déconnecterait le joueur. Un rejet définitif soulève SessionExpired une fois; un échec de transport laisse la session intacte.

Accepter les conditions actuelles

Vérifiez l'acceptation avant de démarrer des battements de cœur, des demandes de jeu ou des sockets. La version 0.1.0 a AcceptTermsAsync, mais la découverte de champs de profil et de termes plus récents utilise sa prise en charge brute JSON :

var profile = await client.Me.GetProfileAsync(ct);
var needsAcceptance = profile.RawJson["termsAcceptanceRequired"].AsBooleanOrDefault();
var terms = await client.Raw.SendForJsonAsync(new StarhermitRequest("GET", "terms"), ct);
var textToDisplay = terms["text"].AsStringOrNull();
var displayedHash = terms["hash"].AsStringOrNull();
// Display textToDisplay. Retain displayedHash for this displayed revision.
// Only in the user's Accept handler, using an account session:
// await client.Me.AcceptTermsAsync(displayedHash, ct);

N'utilisez pas d'exemple d'étiquette de révision telle que terms-2026-08 : seul le hachage actuel de l'API est accepté. Sur 409, récupérez et affichez le nouveau texte pour une autre acceptation. Sur 403 terms_acceptance_required, résolvez l'acceptation avant de réessayer ; les jetons de lancement des joueurs peuvent également soumettre leur acceptation via l'API après consentement explicite. Voir Profil pour le flux complet.

Une séance de bout en bout

Le cycle de vie de la procédure pas à pas d'intégration, en C# :

var chess = client.Games.ForSlug("83fd04b1-3cbe-4b09-a251-3733ad4b9d94");
await chess.AcquireLaunchTokenAsync();

var ticket = await chess.EnqueueMatchmakingAsync();
while (!ticket.IsMatched)
{
    await Task.Delay(TimeSpan.FromSeconds(2), ct);
    ticket = await chess.GetMatchmakingAsync(ct) ?? ticket;
}

using var game = client.CreateGameConnection(ticket.SessionId!.Value, "83fd04b1-3cbe-4b09-a251-3733ad4b9d94", useLaunchToken: true);
game.FrameReceived       += frame => ApplyServerState(frame);
game.AchievementUnlocked += unlock => ShowToast(unlock);
game.PresenceChanged     += (userId, online) => UpdateOpponentDot(userId, online);
game.ErrorReceived       += message => ShowError(message);

await game.ConnectAsync(ct);
await game.SendCommandAsync(writer =>
{
    writer.Write("type", "move");
    writer.Write("from", "e2");
    writer.Write("to",   "e4");
}, ct);

SendCommandAsync encapsule la charge utile comme {"type":"cmd","data":…}; SendRealtimeInputAsync est le chemin à débit limité pour une entrée continue. La connexion ne coche pas la logique du jeu, prédit l'autorité énoncer, fabriquer un résultat ou renvoyer une commande éventuellement non idempotente après un message ambigu. déconnecter - le serveur reste la seule autorité sur ce qui s'est passé.

Chaque connexion partage une machine à états : Disconnected, Connecting, Connected, Reconnecting, Closing, Faulted, avec StateChanged, Closed et Faulted événements, files d'attente sortantes délimitées avec contre-pression explicite et envois ordonnés. La reconnexion utilise un recul instable, réacquiert un courant jeton avant chaque tentative, et s’arrête définitivement lors d’une autorisation ou d’une clôture de police plutôt que martelant une porte, la plate-forme se ferma. On ne suppose jamais que l’adhésion a survécu à l’écart : chaque protocole récupère ou rejoint lors de la reconnexion.

Les informations d'identification montent sur le Authorization en-tête là où la plateforme le permet et ?access_token= sur /ws/** sinon, car un navigateur ne peut pas définir les en-têtes de prise de contact. Le jeton de requête est supprimé de chaque journal.

Async, threading et Unity

Chaque opération d'E/S renvoie Task et prend une traînée CancellationToken. Il n'y a pas async void méthodes et aucune méthode publique ne bloque le thread appelant.

Les événements et les rappels de progression sont publiés dans le contexte de synchronisation sur lequel le client a été créé. si vous le créez sur le thread principal de Unity, un gestionnaire peut toucher GameObjects directement. Un serveur sans tête peut sauter le saut avec options.CallbackDispatcher = ImmediateCallbackDispatcher.Instance. Les rappels sont ordonné par connexion, et un gestionnaire qui lance est signalé aux diagnostics sans arrêter le recevoir la boucle.

StarhermitLifecycle.Attach(client) relie les événements d'application d'Unity : le battement de cœur de présence s'arrête en suspension et envoie immédiatement lors de la reprise, et le client est disposé à quitter sans synchronisation travail en réseau.

Les modèles ne font jamais référence GameObject, MonoBehaviour ou une scène. StarhermitTextures convertit l'avatar et octets de pochette dans un Texture2D sur le thread principal — l'appelant est propriétaire du résultat et doit le détruire.

Erreurs, tentatives et pagination

Statut Exception
400 / 422 StarhermitBadRequestException, StarhermitValidationException (erreurs de champ saisies par nom de fil)
401 StarhermitAuthenticationException
402 StarhermitEntitlementException
403 StarhermitAuthorizationException
404 StarhermitNotFoundException
409 StarhermitConflictException
429 StarhermitRateLimitException (porte RetryAfter)
5xx StarhermitServerException

Chacun porte le statut, celui du serveur {"error":"..."} message, tout code lisible par machine, la demande pièce d'identité, Retry-After, des en-têtes expurgés et un corps expurgé avec une taille limitée. Une demande qui n'est jamais parvenue au L'API augmente StarhermitTransportException ou StarhermitTimeoutException — une panne de transport n'est jamais déguisé en réponse API. L'annulation apparaît toujours comme OperationCanceledException.

Les tentatives sont limitées, instables, honneur Retry-After jusqu'à un plafond, et sont limités aux échecs par seconde tentative a pu survivre : erreurs de connexion, délais d'attente, 408, 429 et transitoire 5xx. 403, 404, 409 et les échecs de validation ne sont jamais réessayés, et un POST est réessayé uniquement lorsqu'il accepte avec AsIdempotent. Un budget de nouvelles tentatives à l'échelle du processus empêche plusieurs clients de transformer une panne en tempête.

Retour de la liste des points de terminaison StarhermitPage<T> transportant les propres métadonnées de pagination du serveur, plus paresseux énumération qui récupère une page uniquement au fur et à mesure de sa consommation :

await foreach (var title in client.Software.EnumerateTitlesAsync(query, cancellationToken: ct)) { … }

Les téléchargements sont diffusés vers un IStarhermitFileStore via un fichier temporaire, vérifiez un SHA-256 fourni et sont promus de manière atomique ; OpenDownloadAsync rapports IsResumed seulement pour un vrai 206, parce que ajouter un fichier entier à un fichier partiel le corrompt tout en passant une vérification de longueur.

Stockage des informations d'identification

Le paquet n'expédie aucun magasin qui prétend être sécurisé. La valeur par défaut est en mémoire ; l'adhésion EncryptedFileTokenStore (AES-CBC avec HMAC-SHA256 sur une clé fournie par votre application) est documenté comme obscurcissement au repos, pas un porte-clés. Fil IStarhermitTokenStore au propre sécurisé de la plateforme stockage - Trousseau, Keystore, stockage utilisateur du SDK de la console. PlayerPrefs n'est jamais présenté comme sécurisé.

Les jetons, jetons d'actualisation, clés privées, secrets client et clés d'appel ne sont jamais sérialisés dans un ScriptableObject, une scène, Resources, un journal, un message d'exception, un événement de télémétrie ou un build artefact. StarhermitSettings ne contient que les valeurs par défaut non secrètes du projet : adresses, slug, niveau de journalisation, timeout et le drapeau de développement.

La rédaction est structurelle — par en-tête, paramètre de requête et nom de membre JSON, à chaque profondeur — donc un Les informations d'identification dont cette version du SDK n'a jamais entendu parler sont toujours supprimées des journaux, des exceptions et de la télémétrie. Les fragments d'URL sont entièrement supprimés. Aucune télémétrie n'est collectée par défaut ; un lavabo injecté reçoit nom de l'événement, identifiant de l'opération, durée, famille de statuts, nombre de tentatives, identifiant et résultat de la demande, jamais d'URL, corps ou contenu du joueur.

Quand la plateforme embarque du nouveau

Les modèles sont immuables et conservent le JSON à partir duquel ils ont été analysés, donc un champ ajouté au déploiement après cette version du SDK est toujours lisible et un point de terminaison que cette version ne tape pas est toujours appelable avec les mêmes informations d'identification, tentatives et rédaction qu'un appel tapé :

var value = profile.RawJson["shippedAfterThisSdk"].AsStringOrNull();

var json  = await client.Raw.SendForJsonAsync(
    new StarhermitRequest("GET", "some/new/route").WithQuery("page", 1), ct);

Les trames de socket sont distribuées sur leur discriminateur de type avec un repli de trame inconnue qui préserve le charge utile, les chaînes d'énumération inconnues sont conservées sous forme de chaînes plutôt que contraintes, et un niveau de confidentialité inconnu se lit comme le la plupart interprétation privée. Optional<T> distingue les valeurs nulles omises, explicites et valeur, ce dont un corps PATCH a besoin.

client.GetDiagnostics() renvoie les états de connexion, la profondeur de la file d'attente, le nombre de reconnexions, l'expiration du jeton, l'horloge fraîcheur, demandes en cours, tentatives effectuées et la dernière erreur expurgée - l'instantané à joindre à un rapport de bug.

Échantillons

Huit échantillons sont livrés avec le package et sont compilés dans CI, afin qu'ils ne puissent pas dériver de l'API qu'ils utilisent. démontrer : authentification et profil, amis et chat, jeu de matchmaking, temps réel et relais, voix, Services de catalogue, outil d'édition et serveur dédié.

Statut de vérification

La suite propre au SDK (144 tests hermétiques sous dotnet test, les mêmes fichiers exécutés que Unity EditMode tests) et un manifeste de couverture généré qui échoue à la construction lorsqu'une opération d'API n'a pas de mappage SDK exécuter à chaque changement ; cinq tests supplémentaires lisent un déploiement en direct lorsqu'ils sont pointés vers un déploiement et sont ignorés sinon. La matrice de l'éditeur et IL2CPP les builds de lecteurs pour Linux, Android et WebGL sont définis dans CI mais nécessitent une ferme de build sous licence, donc le le tableau de plate-forme ci-dessus indique le support prévu - traitez une cible comme qualifiée uniquement une fois que vous avez construit pour c'est vous-même.
