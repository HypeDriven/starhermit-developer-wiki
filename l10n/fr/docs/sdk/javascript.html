SDK JavaScript (jeux sur navigateur)

starhermit-sdk.js est un client à fichier unique et sans dépendance pour les jeux par navigateur publié sur StarHermit. Il lit le jeton de lancement, le maintient renouvelé et fournit des aides pour le commun API de jeton de lancement à l'échelle du jeu : identité, sauvegardes dans le cloud, paramètres et contrôles par joueur, invitations, matchmaking, sessions et socket de gameplay, réalisations, classements, replays, chat, salles vocales et en temps réel.
Déposer docs/sdk/starhermit-sdk.js — copiez-le dans votre jeu sans modification
Mondial window.StarHermit (aussi module.exports sous Node, pour les tests)
Dépendances aucun — il utilise celui du navigateur fetch, WebSocket et (pour lire les sauvegardes compressées) DecompressionStream
Référence de l'API REST v1 et WebSocket v1, surface de jeton de lancement uniquement

Le SDK est un client et non une seconde implémentation de la plateforme. Scores et succès débloqués sont écrits uniquement par le serveur du jeu (un résultat de script ou un message de contrôle de conteneur) - un client ne peut jamais les publier et le SDK ne fait que les lire. Tout le reste fait autorité sur le serveur exactement comme indiqué sur le Pages API.

Les assistants authentifiés n'effectuent aucune requête API sans jeton de lancement. Les lectures résolvent généralement à null, [], ou une carte vide ; les écritures peuvent résoudre null/false et les sauvegardes anti-rebond n'ont pas d'effet immédiat valeur de retour. Une prise reste déconnectée. Gardez la progression autonome en mémoire si le joueur a choisi jeu non suivi. Appel signOut() avant de passer du jeu de compte à ce mode afin que le renouvellement s'arrête.

Installer

Copiez le fichier à côté des autres scripts statiques de votre jeu (où que votre build les expédie) et chargez-le. avant votre propre code :

<script src="starhermit-sdk.js"></script>
<script>
  StarHermit.init();          // as early as possible: it reads and strips the token from the URL fragment
</script>

Appel init() une fois, avant qu'un routeur ne touche location.hash. Possibilités : init({ base, gameId, autoRefresh, launcherUrl }) — base points d'appels REST à une origine autorisée pendant le développement local (les jeux hébergés sur la plateforme utilisent la même origine). gameId, s'il est fourni, doit correspondre l'UUID hébergé pour la connexion ; les pages locales/externes ne sont pas des origines de retour de connexion au jeu valides. autoRefresh: false laisse le renouvellement des jetons à un jeu qui gère sa propre chaîne, et launcherUrl remplace où relaunch() envoie le joueur (par défaut https://dashboard.starhermit.com/).

Sauvegardes cloud

La machine à sous du jeu est game:<slug> (catalogue : sauvegarde depuis l'intérieur d'un jeu); le SDK construit le chemin, compresse la charge utile et gère le /info vérifier.

const remote = await StarHermit.loadJSON();          // null: empty slot, signed out — or a failed read
if (StarHermit.saveLoadFailed()) showSyncError();    // tell those apart when it matters
else if (remote && isNewer(remote, local)) adopt(remote);

StarHermit.saveJSON(state);                          // debounced (2 s) checkpoint upload
addEventListener('pagehide', () => StarHermit.flushSave(true));   // keepalive flush
StarHermit.on('saved', ok => setSyncIndicator(ok));

Chargez avant de sauvegarder. Comparez et adoptez la copie cloud avant toute écriture qui pourrait atteindre saveJSON - y compris les paramètres, les écritures de surnom ou de point de contrôle au démarrage - ou une copie locale obsolète peut écraser une sauvegarde plus récente effectuée sur un autre appareil. Conservez les premières sauvegardes jusqu'à ce que la charge de démarrage se stabilise.

Le SDK protège l'autre moitié de cette course : lorsqu'une lecture échoue (erreur réseau ou serveur, par exemple). par opposition à un emplacement vide), il définit saveLoadFailed(), émet saveerror, et refuse d'écrire jusqu'à ce que /info confirme que l'emplacement est vide ou plus tard loadSave() réussit. Une écriture refusée est résolue false et émet saved avec false.

Les écritures après un chargement sont conditionnelles. Le SDK mémorise la version (ETag) de le sauvegarder en dernier lit ou écrit et le renvoie, donc une écriture atterrit uniquement sur la sauvegarde sur laquelle elle était basée - ou, pour un emplacement c'était vide, seulement tant qu'il l'est encore. Lorsqu'un autre appareil est enregistré entre les deux, l'écriture est refusée (412) : le SDK émet saveconflict, ensembles saveConflicted(), et refuse d'écrire davantage jusqu'à ce qu'un loadSave() permet au jeu de fusionner ou d'adopter la nouvelle sauvegarde. Un jeu qui ne charge jamais écrit sans condition, comme auparavant.

StarHermit.on('saveconflict', async () => {
  const remote = await StarHermit.loadJSON();       // lifts the block
  StarHermit.saveJSON(merge(remote, local));        // conditional on the version just loaded
});

Niveau inférieur : loadSave() / writeSave(text) pour les cordes brutes, saveInfo() pour { exists, sizeBytes, updatedAt, etag }.

Rapports de crash et de bugs

Les joueurs peuvent signaler des problèmes depuis le jeu ; le propriétaire les trie à travers le API de rapports.

await StarHermit.reportBug('Score did not save', 'Finished level 3, score shows 0', {
  clientVersion: '1.4.2',
  attachments: [{ fileName: 'state.json', contentType: 'application/json', data: JSON.stringify(state) }],
});
StarHermit.captureCrashes({ clientVersion: '1.4.2' });   // opt-in: uncaught errors become crash reports
const mine = await StarHermit.myReports();               // [{ id, kind, status, title, ... }]

report(kind, title, description, opts) est la forme générale (reportBug et reportCrash réparer le genre). captureCrashes fichiers au plus un rapport par message distinct et trois par chargement de page, donc un Crash Loop ne peut pas utiliser l'allocation journalière du joueur (20 par partie par défaut). Demandez au joueur avant attacher quoi que ce soit de personnel.

Classements solo

Un client ne peut jamais publier de score (seul le serveur du jeu le peut). Un jeu solo nécessite donc un petit script de plateforme pour posséder ses tableaux. score-script.js en est un : copiez-le ensuite à votre jeu, déclarez-le dans starhermit.txt comme server=score-script.js, et modifier uniquement son BOARDS bloc, qui répertorie chaque tableau au fur et à mesure que vous créer le:

var BOARDS = {
  "high-score": { "name": "High score", "scoreType": "integer", "sortDirection": "desc", "minScore": 0, "maxScore": 1000000 }
};

Lorsqu'une course se termine, publiez-la et montrez la place du joueur :

const accepted = await StarHermit.submitScores({ 'high-score': total });   // [] when signed out or refused
if (accepted.includes('high-score')) {
  const board = await StarHermit.leaderboard('high-score', { pageSize: 100 });
  const me = board.items.find(e => e.userId === StarHermit.userId);
  showRank(me && me.rank);
}

submitScores ouvre une séance d'entraînement (POST .../sessions/ai), envoie {type:'result', scores} sur le socket de gameplay et résout les touches du tableau acceptées par le script ; il émet également scores avec cette liste. Le script laisse tomber un score qui n'est pas un nombre du type du tableau ou qui ne correspond pas à son nombre. minScore/maxScore, publie le reste via son scores revenir et mettre fin à la session. Le client rapporte toujours le résultat. Un score inventé à portée peut réussir ; ces planches conviennent aux loisirs jouer. Pour la compétition, validez le run dans le script ou le conteneur avant de l'attribuer. La reconnaissance répertorie les clés acceptées par le script ; ce n'est pas une preuve que chaque tableau était actif ou qu'un nouveau record personnel a été stocké. Voir confiance et disponibilité.

Reconnexion et jetons expirés

Un socket porte le jeton de lancement dans son URL, et une poignée de main avec un jeton expiré est refusée avant la mise à niveau - le navigateur ne signale que le code de fermeture 1006, exactement comme une coupure de réseau. Donc un échec la reconnexion peut être un échec d'authentification et réessayer la même URL ne pourra jamais être récupérée. Le renouvellement fonctionne uniquement pendant que le jeton actuel est valide et dans les 12 heures suivant le lancement initial ; après cela, seul le le lanceur peut créer un nouveau jeton.

connect() gère cela lui-même : avant chaque reconnexion, il renouvelle le jeton via POST /api/v1/games/{slug}/launch-token (sauf s'il a été renouvelé depuis l'ouverture du socket) et rouvre avec le nouveau. Une erreur de réseau ou de serveur lors du renouvellement recule et renouvelle à nouveau - cela n'a jamais été le cas. rouvre l'ancienne URL. Lorsque le renouvellement est refusé ou que le jeton a expiré, le SDK se déconnecte (auth avec reason: 'expired'), cesse de se reconnecter et appelle onAuthLost():

const conn = StarHermit.connect(sessionId, {
  onGame, onClose,
  onAuthLost: () => showReconnectPanel(),   // e.g. "Session expired — Back to StarHermit"
});
backButton.onclick = () => StarHermit.relaunch();

relaunch() renvoie le joueur pour un nouveau jeton de lancement : en se connectant à l'ouverture du jeu de cette façon (StarHermit.launchKind === 'sign-in'), sinon au lanceur. À l'intérieur du lanceur cadre de jeu, il navigue dans la fenêtre supérieure, ce que les navigateurs autorisent uniquement à partir d'un geste de l'utilisateur, alors appelez-le d'un clic; ça revient false lorsque la navigation a été refusée.

Un navigateur peut masquer les sessions terminées, les conditions, l'adhésion ou les échecs de construction. 1006. Avant un nouvelle tentative automatique, connect() vérifie l'état de la session via REST et, quand opts.build est fourni, le compare avec les informations du jeu. onUnavailable(error) reçoit un échec REST permanent ou s'est terminé séance ; onTermsRequired(body) demande l’acceptation explicite des conditions. Créez une nouvelle connexion après les résoudre. onClose(1008) signifie que la connexion a été remplacée ou a violé la politique ; ne fais pas rouvrez-le automatiquement.

Sockets votre jeu s'ouvre tout seul (realtime.socketUrl(roomId), voice.socketUrl(roomId)) besoin du même règle. Avant d'en rouvrir un, appelez renewForReconnect() et agir sur son résultat :

async function reopen() {
  const r = await StarHermit.renewForReconnect();
  if (r === 'renewed') ws = new WebSocket(StarHermit.realtime.socketUrl(roomId)); // fresh token in the URL
  else if (r === 'retry') setTimeout(reopen, backoff());                         // renewal itself failed
  else if (r === 'terms-required') showTermsPanel();                              // explicit acceptance
  else showReconnectPanel();                                                     // 'relaunch'
}

Les renouvellements simultanés partagent une demande. terms-required préserve le jeton du joueur et émet termsrequired; afficher getTerms() et appelle acceptTerms(displayed.hash) uniquement sur le joueur Acceptez l'action, puis réessayez. Les sockets gérés par votre jeu nécessitent également des vérifications REST pour les ressources terminées. et doit s'arrêter à la clôture de la politique. Voir dépannage.

Événements

StarHermit.on(type, fn) renvoie une fonction de désabonnement ; off(type, fn) fonctionne aussi.

Événement Charge utile
auth { signedIn, userId } lors de la connexion ; { signedIn: false, reason } à la déconnexion ou à l'expiration (reason: 'expired' lorsque le renouvellement est refusé — offre relaunch())
saved true / false après chaque nuage, écrivez
saveerror { op: 'load' } après une lecture ratée ; { op: 'write', blocked: true } pour une écriture refusée
achievement un déverrouillage poussé sur la prise gameplay
scores les clés du tableau acceptées par submitScores ([] quand rien n'a été posté)
saveconflict { etag } lorsqu'un autre appareil a modifié la sauvegarde ; recharger avant de fusionner/enregistrer
termsrequired Erreur de termes renvoyée par un renouvellement de jeton de lancement ; conserver le jeton et demander le consentement
