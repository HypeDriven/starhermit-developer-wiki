Outils de développement StarHermit

Créez des packages de script-jeu publiables, téléchargez-les sur StarHermit et donnez à votre assistant de codage une connexion MCP locale. Ces outils ne nécessitent aucun Installation de rouille ou vérification de la source du moteur. Le jeu peut avoir le sien créer des dépendances, telles que Node.js.

Téléchargez l'archive pour votre ordinateur à partir du tableau ci-dessous ou à partir de https://engine.starhermit.com/engine/tools/latest.json (il répertorie chacun l'adresse, la taille et le SHA-256 de l'archive), et comparez son SHA-256 avec le somme de contrôle à côté (<archive>.sha256). Décompressez-le et placez son répertoire sur PATH, ou utilisez le chemin complet de l'exécutable dans les commandes ci-dessous. Les téléchargements macOS sont fourni séparément pour Apple Silicon (macos-aarch64) et Intel (macos-x86_64). Ils ne sont pas certifiés par Apple et aucun téléchargement n'est possible. Authenticode ou ID de développeur signé. La version Apple Silicon est compilation croisée ; signaler des problèmes.

Vérifier et emballer un jeu

starhermit-tools --version
starhermit-tools check my-game
starhermit-tools package --web my-game --out upload --remote-out remote-objects

Le répertoire du jeu contient starhermit.txt et les fichiers dont le jeu a besoin. engine.version épingle une version de moteur publiée ; l'outil lit son manifeste à partir de engine.starhermit.com et écrit un chargeur et un fichier épinglés par hachage indice. --engine-version X.Y.Z sélectionne explicitement une version compatible. Fichiers déclarés par engine.remote.files sont écrits à remote-objects; quand engine.remote.urls=platform, la publication les télécharge en premier.

check valide le manifeste, les chemins d’accès aux packages et la structure des fichiers. C'est le cas pas exécuter de scripts. Testez le jeu Web packagé dans un navigateur avant publication. Les développeurs peuvent également télécharger le natif correspondant runtime à partir d'une version du moteur (Windows, Linux et du moteur 1.26.2 macOS 11 ou version ultérieure sur Intel et Apple Silicon) et utilisez starhermit check my-game pour un contrôle d'exécution sans tête. Le MacOS les environnements d'exécution sont signés ad hoc et non notariés, et ils n'ont pas encore été testé sur du vrai matériel Apple. Une archive tar téléchargée dans un navigateur est mis en quarantaine : exécuter xattr -d com.apple.quarantine starhermit ou permettez-le dans Paramètres système.

Publier

Utilisez votre propre clé de déploiement enregistrée, après l'intégration de la clé publique et les guides CI/CD dans le wiki du développeur. Ensemble STARHERMIT_PUBLIC_KEY et STARHERMIT_PRIVATE_KEY dans votre shell ou votre magasin secret CI. Alternativement, ensemble STARHERMIT_ACCESS_TOKEN à un jeton d'accès au compte. Ne les mettez pas valeurs dans le jeu, validez-les ou ajoutez-les à la configuration MCP.

starhermit-tools publish --game-id YOUR-GAME-ID --upload upload --remote-out remote-objects

Cela remplace les fichiers déployés du jeu. --mode merge corrige un existant téléchargez à la place. Pour créer un nouveau jeu, remplacez --game-id YOUR-GAME-ID avec --new. --socket sélectionne le WebSocket de téléchargement ; gros téléchargements, sélectionnez-le automatiquement. --display-name et --description remplacer le téléchargé le nom et la description du manifeste. L'éditeur signale l'URL hébergée et rédige un rapport de publication à côté du téléchargement.

Le compte doit posséder le jeu. Une erreur d'identification ou une limite refusée est un erreur ; ne contournez pas ce problème avec les informations d'identification de quelqu'un d'autre. À distance les objets déjà détenus par le jeu sont réutilisés ; téléchargements d'objets interrompus reprendre. Un nouveau jeu peut être créé avant l'échec d'un téléchargement d'objet ultérieur ; utilisez son identifiant de jeu signalé pour réessayer plutôt que d'en créer un autre.

STARHERMIT_API_BASE sélectionne un autre déploiement HTTPS. STARHERMIT_CA_FILE sélectionne un bundle de confiance PEM, par exemple un développement CA ; La vérification TLS est toujours activée. L'utilisation normale n'a besoin d'aucune variable.

Connectez un assistant de codage avec MCP

Ajoutez un serveur MCP stdio à la configuration de votre assistant, en utilisant l'absolu chemins appropriés à votre ordinateur :

{
  "mcpServers": {
    "starhermit": {
      "command": "/absolute/path/to/starhermit-tools",
      "args": ["mcp", "--package", "/absolute/path/to/my-game"]
    }
  }
}

Le serveur propose check_package, package_web, et package_native. Si le jeu dispose d'un script de build Node.js, ajoutez --build-script et son chemin absolu vers les arguments MCP pour exposer un build outil. Cela fonctionne ce script configuré ; il n'accepte pas les commandes arbitraires de MCP. package_web prend facultatif outDir, remoteOut, et engineVersion; les chemins de sortie relatifs sont relatifs au répertoire du jeu. Par défaut, il écrit starhermit-build/upload et starhermit-build/remote à côté du répertoire du jeu. package_native écrit l'index de fichier natif du jeu pour installation par un client StarHermit pris en charge, qui installe le moteur runtime pour la plateforme du joueur (macOS inclus, à partir du moteur 1.26.2). Aucun des deux outils ne publie quoi que ce soit.

Avec un runtime natif installé, ajoutez --runtime et son chemin exécutable absolu vers les arguments MCP pour activer run_checks. Cet outil exécute le code du jeu dans le runtime configuré. Publication est disponible uniquement sous forme de commande CLI explicite et n'est jamais un outil MCP.
