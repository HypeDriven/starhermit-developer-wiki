Tutoriel : classements et réalisations pour votre jeu

Si vous possédez un jeu sur StarHermit, vous en êtes l'éditeur. Tu peux le donner classements (score élevé, course la plus rapide, séquence la plus longue) et réalisations sans compte d'éditeur ni spécial autorisation. Il suffit de posséder le jeu.

Il y a une règle derrière tout sur cette page : vous les définissez, le serveur de votre jeu écrit eux. Le client d'un joueur ne peut jamais publier de score ni revendiquer un exploit pour ceux-ci, et votre serveur doit valider le gameplay qui les rapporte. Refuser les soumissions directes d'API à lui seul n'empêche pas un client modifié d'inventer des événements de jeu. C'est pourquoi le jeu a besoin d'un backend faisant autorité : un server= un script ou un container.image= dans starhermit.txt.

Ce tutoriel construit à la fois pour un petit jeu d'arcade, Collectionneur d'étoiles: une course se termine lorsque le joueur plante, et il a un total de points et une durée d'exécution.

Avant de commencer

Il vous faut :

  • Un jeu avec un backend serveur que vous possédez : celui que vous avez ajouté depuis votre propre référentiel, téléchargé sous forme de dossier, ou revendiqué. Un jeu sur navigateur uniquement répond 409 à chaque appel ci-dessous, avec un message expliquant pourquoi.
  • Un jeton d'accès utilisateur complet, pas le jeton de lancement d'un jeu. Les jetons de lancement sont clôturés au jeu surface du joueur et ne peut pas atteindre /me/....
  • L'identifiant de votre jeu (c'est aussi son <id>.starhermit.com adresse):
ACCESS_TOKEN='your-full-user-access-token'
API=https://api.starhermit.com

curl -s "$API/api/v1/me/github-games" -H "Authorization: Bearer $ACCESS_TOKEN" |
  jq '.[] | {id, displayName, gameSlug}'

GAME_ID='the-id-from-above'

gameSlug c'est ainsi que votre client appelle le jeu /api/v1/games/{slug}/.... Chaque jeu que vous avez ajouté ou téléchargé contient un jeu uniquement sur navigateur, il ne vous indique donc pas s'il existe un serveur : GET /api/v1/games/{slug} fait - il répond 404 jusqu'à ce que le jeu ait un backend.

1. Créez les classements

Star Collector obtient deux tableaux : le plus de points (le plus élevé est le mieux) et la course la plus rapide jusqu'à 100 points (le plus bas est le mieux). c'est mieux).

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/leaderboards" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "high-score", "name": "High score",
        "scoreType": "integer", "sortDirection": "desc",
        "minScore": 0, "maxScore": 1000000 }'

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/leaderboards" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "fastest-100", "name": "Fastest to 100",
        "scoreType": "time-ms", "sortDirection": "asc" }'

Chaque appel revient 201 et le conseil d'administration, y compris ses id et key. Votre serveur utilise le clé, alors choisissez-le avec soin. La clé, scoreType et sortDirection ne peut pas être modifié ultérieurement.

scoreType Accepte
integer nombres entiers
decimal n'importe quel numéro
time-ms millisecondes entières non négatives

Ensemble minScore/maxScore à ce que votre jeu peut réellement produire. Un score en dehors d'eux est abandonné, ce qui constitue une protection bon marché contre un bug dans la logique de votre propre serveur.

2. Créez les réalisations

Vous pouvez attribuer des succès à un jeu de deux manières, et vous pouvez utiliser les deux à la fois :

Déclaré dans le code Créé via l'API
Où game.achievements dans votre script, ou /describe dans votre conteneur POST /me/github-games/{id}/achievements
Modifié par publier une mise à jour un appel API, prenant effet immédiatement
Bon pour les réalisations autour desquelles votre code est construit en ajouter ou en reformuler sans version

Les deux types sont déverrouillés de la même manière, en renvoyant la clé par votre serveur. Ici, nous en créons deux à travers l'API :

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "century", "name": "Century",
        "description": "Collect 100 stars in one run.", "points": 10 }'

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "untouchable", "name": "Untouchable",
        "description": "Reach 500 points without losing a shield.",
        "points": 50, "secret": true }'

A secret le succès reste caché aux joueurs jusqu'à ce qu'ils l'aient déverrouillé.

Pour voir tout ce que le jeu propose, y compris les succès déclarés par votre code, répertoriez-les :

curl -s "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" | jq '.[] | {key, origin, unlocks}'

origin est declared pour les réalisations de votre code et owner pour les réalisations que vous avez créées ici. Vous pouvez modifier et supprimer uniquement owner ceux. UN declared on serait remis par ton prochain mise à jour, donc l'API refuse (409) et vous le modifiez dans le code à la place.

3. Publiez des scores et débloquez des réalisations à partir de votre script

Votre script rapporte les deux types de résultats dans sa valeur de retour. Il peut le faire à partir de n’importe quel hook : createSession, onPlayerMessage ou onTick.

  • scores: clé du tableau → identifiant du joueur → numéro.
  • achievements: identifiant du joueur → clés pour déverrouiller.
'use strict';

function endRun(ctx, s, playerId) {
  var run = s.runs[playerId];
  var scores = { "high-score": {} };
  scores["high-score"][playerId] = run.points;
  if (run.reached100At) {
    scores["fastest-100"] = {};
    scores["fastest-100"][playerId] = run.reached100At - run.startedAt;
  }

  var unlocked = [];
  if (run.stars >= 100) unlocked.push("century");
  if (run.points >= 500 && !run.lostShield) unlocked.push("untouchable");
  var achievements = {};
  achievements[playerId] = unlocked;

  run.over = true;
  return {
    ok: true,
    sessionState: s,
    scores: scores,
    achievements: achievements,
    broadcast: [{ to: [playerId], data: { type: "run-over", points: run.points } }]
  };
}

globalThis.game = {
  tickRateHz: 10,

  createSession(ctx) {
    var runs = {};
    ctx.players.forEach(function (p) {
      runs[p.id] = { points: 0, stars: 0, lostShield: false, startedAt: ctx.now,
                     reached100At: null, over: false };
    });
    return { ok: true, sessionState: { runs: runs } };
  },

  onPlayerMessage(ctx) {
    var s = ctx.sessionState;
    var from = ctx.message.from;
    var run = s.runs[from];
    var msg = ctx.message.data || {};
    if (!run || run.over) return { ok: false, error: "No run in progress" };

    // The client reports what happened; the script decides what it is worth.
    if (msg.type === "collect") {
      run.stars += 1;
      run.points += 5;
      if (run.points >= 100 && !run.reached100At) run.reached100At = ctx.now;
      return { ok: true, sessionState: s };
    }
    if (msg.type === "shield-lost") {
      run.lostShield = true;
      return { ok: true, sessionState: s };
    }
    if (msg.type === "crash") return endRun(ctx, s, from);
    return { ok: false, error: "Unknown command" };
  },

  onTick(ctx) { return { ok: true }; }
};

Les choses que tu fais pas il faut gérer :

  • Pires scores. Chaque joueur conserve son meilleur score sur chaque plateau, jugé par le score du plateau. sortDirection. Signalez chaque course et la plateforme garde le meilleur.
  • Répétez les déverrouillages. Déverrouiller quelque chose qu'un joueur possède déjà ne fait rien, alors rendez la clé chaque fois que la condition est remplie.
  • L'identité de quelqu'un d'autre. Scores et déverrouillages pour les personnes qui ne participent pas à la session, y compris l'IA siège, sont ignorés.

Les clés inconnues, les tableaux inactifs et les scores hors de portée sont supprimés silencieusement. Votre script ne reçoit aucun erreur pour eux, alors vérifiez vos cartes une fois, comme dans article 4.

Un vrai jeu devrait demander au serveur de déterminer les points et les temps à partir de son propre état d'autorité, et non confiance collect messages tels qu'ils sont. Cet exemple est court pour montrer le reporting. Scripts de jeu a le contrat de forme de retour complet.

3b. La même chose depuis un conteneur

Un jeu conteneur envoie les deux mêmes choses sur son contrôle WebSocket :

{ "type": "scores", "sessionId": "…",
  "scores": { "high-score": { "<userId>": 740 }, "fastest-100": { "<userId>": 41250 } } }

{ "type": "achievements", "sessionId": "…",
  "unlocks": { "<userId>": ["century"] } }

scores peut également être inclus dans toute enveloppe de réponse d’où votre conteneur revient /sessions. Le les mêmes règles s'appliquent : participants uniquement, meilleur score conservé, clés inconnues ignorées. Voir Serveurs de jeux de conteneurs.

4. Montrez-les dans votre jeu

Votre client lit tout avec le jeton de lancement qu'il détient déjà. Rien ici n'a besoin du jeton du propriétaire.

Trouvez les planches.

const boards = await api(`/api/v1/games/${slug}/leaderboards`);
// [{ id, key: "high-score", name: "High score", sortDirection: "desc", ... }, ...]
const high = boards.find(b => b.key === "high-score");

Seuls les tableaux actifs sont répertoriés.

Lisez un tableau.

const page = await api(`/api/v1/leaderboards/${high.id}/entries?page=1&pageSize=10`);
// { items: [{ rank, username, score, ... }], total, page, pageSize }
const friends = await api(`/api/v1/leaderboards/${high.id}/entries?friendsOnly=true&pageSize=10`);

Pour un time-ms tableau, formatez le score sous forme de temps : 41250 → 0:41.25.

Réalisations.

  • GET /api/v1/games/{slug}/achievements répertorie chaque réalisation avec le joueur unlocked État. Les secrets restent cachés jusqu'à ce qu'ils soient gagnés.
  • Le déverrouillage lui-même arrive en direct ws/v1/games comme {"type":"achievement","data":{key,name,description,points,...}}. Portez un toast quand c'est le cas. L'appel de liste au chargement détecte tout ce qui est déverrouillé alors que le socket était fermé.

Voir Réalisations pour le cadre.

5. Prenez soin d'eux

Renommez un tableau ou modifiez ses limites.

curl -s -X PUT "$API/api/v1/me/github-games/$GAME_ID/leaderboards/$BOARD_ID" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "name": "All-time high score", "maxScore": 2000000 }'

Les nouvelles limites s'appliquent uniquement aux nouveaux scores.

Retirez un tableau mais conservez ses scores. Envoyer { "isActive": false }. Le conseil cesse d'accepter marque et disparaît de la liste du jeu. Ses entrées peuvent toujours être lues par identifiant.

Réinitialisation selon un calendrier. Donner une planche "resetSchedule": "daily", "weekly" ou "monthly" (sur créer, ou plus tard avec PUT) et cela recommence à 00h00 UTC à chaque période - parfait pour un "ceci le meilleur de la semaine" embarquez à côté d’un de tous les temps. Rien à faire dans votre script : rapportez les scores comme d'habitude, et le premier score de chaque joueur d'une nouvelle période compte. Voir Réinitialiser les horaires.

Commencez une nouvelle saison à la main. Pour une saison ponctuelle plutôt qu'un planning, créez un nouveau tableau (high-score-s2), pointez votre script dessus et retirez l'ancien.

Supprimer un tableau. DELETE .../leaderboards/{id} supprime le tableau et toutes ses entrées, et ne peut pas être annulé.

Modifier une réalisation. PUT .../achievements/{achievementId} avec l'un de name, description, icon, secret et points. La clé ne change jamais.

Supprimer une réalisation. Cela ne fonctionne que pour celui que vous avez créé et que personne n'a encore déverrouillé. Les succès gagnés sont permanents.

Déplacez une réalisation dans le code. Déclarez la même clé dans game.achievements et publier. Le La déclaration reprend le succès existant et les joueurs qui le possèdent le conservent.

Réponse Signification
404 Le jeu ne vous appartient pas, ou le plateau ou le succès ne lui appartient pas
409 "… back-end du serveur…" Le jeu n'a pas server= ou container.image=
409 "a déjà…" La clé est prise, par un tableau ou par une réalisation déclarée ou créée
409 "déclaré par le serveur du jeu" Changez cette réussite dans votre code
409 "déjà débloqué" Les joueurs le détiennent, il ne peut donc pas être supprimé
400 Une clé avec d'autres caractères, un nom manquant ou minScore > maxScore

Limites : 2048 classements et 200 réalisations créées par jeu, plus jusqu'à 100 déclarées.

Liste de contrôle

  • [ ] Le jeu a un server= script ou container.image=, et gameSlug est placé dans GET /me/github-games.
  • [ ] Chaque carte a une clé stable et le droit scoreType et sortDirection (ils ne peuvent pas changer plus tard).
  • [ ] Le serveur renvoie scores et achievements (script) ou envoie les messages de contrôle (conteneur), élaborés à partir de l'état faisant autorité.
  • [ ] Le client trouve des planches avec GET /games/{slug}/leaderboards, ne code jamais en dur leurs identifiants et lit les entrées par identifiant.
  • [ ] Le client charge GET /games/{slug}/achievements et montre un toast sur le achievement cadre.
  • [ ] Les anciennes planches sont retirées avec isActive: false plutôt que supprimé, à moins que vous ne souhaitiez vraiment que les scores disparaissent.
