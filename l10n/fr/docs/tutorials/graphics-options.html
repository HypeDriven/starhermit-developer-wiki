Tutoriel : options graphiques avec qualité détectée automatiquement

Donnez à votre jeu par navigateur un Graphique menu qui sélectionne un niveau de qualité raisonnable pour la machine du joueur lors du premier lancement, leur permet de le remplacer et se souvient de leur choix sur tous les appareils via StarHermit.

Pour la section Audio correspondante, voir options audio avec une limite sonore détectée automatiquement. Pour une section Langue, voir localisez votre jeu et ajoutez des paramètres de langue.

graphics-options.js est un module ES unique, sans dépendances, qui s'occupe de la comptabilité :

  • Auto évalue le GPU sur un niveau matériel de 0 (un Samsung Galaxy S20 ou inférieur) à 20 (un RTX 5090), sélectionne l'un des quatre préréglages (Faible, Équilibré, Élevé, Ultra) à partir de ce niveau, mémoire, cœurs de processeur et le type d'appareil, et descend pour la session si les images restent lentes.
  • Les joueurs peuvent remplacer chaque effet (ombres, occlusion ambiante, floraison, anti-aliasing ou le vôtre), définissez une échelle de rendu de 50 à 200 %, choisissez un FPS maximum manuel au lieu d'un rafraîchissement automatique de l'affichage (la moitié du taux de rafraîchissement sur les téléphones et les tablettes) et activez la résolution adaptative et la lecture de la fréquence d'images.
  • Les paramètres sont enregistrés dans localStorage ils s'appliquent donc avant la première image, et au joueur paramètres par jeu alors ils suivent le joueur jusqu'à leur d'autres machines.
  • Il comprend un panneau d'options prêts à l'emploi construit à partir de la même table de qualité.

Il n'importe aucun moteur. Votre moteur de rendu écoute les modifications et applique les niveaux. Cette page le connecte à trois.js. D'autres moteurs utilisent les mêmes crochets (voir Autres moteurs).

1. Ajoutez les fichiers

Copie starhermit-sdk.js et graphics-options.js à côté des scripts de votre jeu, inchangés. Appel StarHermit.init() avant votre module s'exécute, donc le jeton de lancement a été lu au moment où le Graphics Store vérifie si un joueur est connecté :

<script src="starhermit-sdk.js"></script>
<script>StarHermit.init();</script>
<script type="module" src="main.js"></script>

Sans jeton de lancement (développement local, tout autre hébergeur), la boutique conserve tout localStorage et ne fait aucune demande.

2. Créez le magasin et le panel

import { createGraphics, mountGraphicsPanel } from './graphics-options.js';

const gfx = createGraphics({ storageKey: 'mygame.graphics' });
mountGraphicsPanel(document.getElementById('graphics-options'), gfx);

mountGraphicsPanel remplit l'élément avec les contrôles. Votre boîte de dialogue de paramètres fournit le cadre, le titre et le bouton Fermer. Chaque modification s'applique immédiatement et est enregistrée.

Comment Auto sélectionne un préréglage

Lors de la création, le magasin sonde une fois un contexte WebGL jetable (gfx.system), évalue le GPU signalé sur un niveau matériel de 0 à 20 (gfx.level), et mappe ce niveau à un préréglage (gfx.detected). Niveau 0 est un Samsung Galaxy S20 (Adreno 650 ou Mali-G77) ou quelque chose de plus faible ; le niveau 20 est un RTX 5090. Chaque Le niveau représente environ 23 % de débit graphique en plus que celui ci-dessous, donc le niveau 20 est d'environ 60 × le niveau 0 :

Pendant l'exécution du jeu, Auto surveille également les temps d'image. Si la résolution adaptative est déjà tombée à son niveau le plancher et les images restent en moyenne supérieures à 26 ms pour trois fenêtres supplémentaires de 90 images, Auto réduit d'un préréglage pour le reste de la séance. Choisir Auto dans le panneau à nouveau re-détecte. Un préréglage du lecteur cueilli à la main ne change jamais tout seul.

Fréquence d'images maximale

Fréquence d'images maximale par défaut Auto (taux de rafraîchissement): le navigateur programme le rendu avec le taux de rafraîchissement de l'écran. Sur un téléphone ou une tablette, la valeur par défaut est Auto (demi-taux de rafraîchissement) à la place, ce qui permet un rafraîchissement de l'affichage sur deux (30 FPS à 60 Hz, 60 FPS à 120 Hz) pour limiter la chaleur et l'épuisement de la batterie. Les navigateurs ne signalent pas le taux de rafraîchissement, donc le magasin le mesure à partir de l'espacement de rappels d'animation ; où ils arrivent en dessous de 50 Hz (par exemple, un navigateur les limitant dans un mode basse consommation), chaque rappel est rendu.

Choisir Coutume et entrez un entier de 1 à 1000 FPS pour remplacer l'une ou l'autre valeur par défaut ; sur un téléphone, entrez le taux de rafraîchissement de l’écran pour un rendu à plein débit. La limite s'applique immédiatement, est enregistrée localement et sur le même profil cloud que les autres paramètres graphiques, et survit aux préréglages de qualité changements. Retour à Auto pour supprimer la limite. Ce choix est indépendant du Auto préréglage de qualité.

Le moteur de rendu doit appeler gfx.shouldRender(now) dans sa boucle d'animation, comme indiqué ci-dessous. Une limite est un plafond, pas une fréquence d'images promise : le rendu ne peut toujours pas dépasser les rappels d'animation du navigateur ou les performances de la machine. Le réglage de 144 FPS sur un écran 60 Hz restitue donc toujours au maximum 60 FPS.

Pour un menu personnalisé, utilisez gfx.set({ maxFps: 45 }) et gfx.set({ maxFps: null }) pour restaurer Auto. Résolu gfx.settings.maxFps est 0 pour l'automobile, et gfx.settings.halfRefresh est true lorsque Auto est rythme à la moitié du taux de rafraîchissement. Les valeurs enregistrées non valides reviennent à Auto ; les nombres positifs sont arrondis et serré à 1-1000.

Où vivent les paramètres

Magasin Clé Pourquoi
localStorage <storageKey>.gpu.<GPU profile> Lire de manière synchrone, de sorte que la première image utilise déjà les paramètres de ce GPU
Paramètres par joueur graphics.gpu.<GPU profile> Suit le joueur vers une autre machine signalant le même GPU

Chaque GPU dispose d'un profil indépendant, couvrant tous les choix graphiques, y compris le FPS maximum. Par exemple, définissez Ultra et 90 FPS sur le GPU A, puis lancez sur le GPU B : B démarre avec le matériel détecté par défaut, sauf si vous avez précédemment enregistré les choix pour B. Le retour à A restaure Ultra et 90 FPS. Deux GPU détectés tous deux comme étant élevés ont toujours des profils distincts. Un changement dans la qualité détectée Le niveau sur le même GPU n’écarte pas ses choix enregistrés.

Le profil est un hachage stable de 16 caractères du nom du GPU signalé par le navigateur, normalisé pour la casse. et des espaces. storageKey et cloudKey fournir des préfixes ; gfx.storageKey, gfx.cloudSlot, et gfx.gpuProfile exposer les clés et le profil actifs. La détection du GPU se produit lors de la création du magasin ; créez un nouveau magasin au prochain lancement du jeu pour sélectionner le profil d'un autre GPU.

Si aucun nom de GPU n'est disponible, les choix s'appliquent à la session sans persistance locale ou cloud. Si le navigateur masque plusieurs GPU portant le même nom, ils partagent un profil car il ne peut pas le faire. les distinguer. Les anciens paramètres locaux non délimités et les paramètres cloud de classe d'appareil restent intacts. et ne sont pas importés, car ils n’identifient pas à quel GPU appartiennent les choix.

Chaque valeur est { "saved": {…}, "at": <ms timestamp> }. Les deux copies sont rapprochées de la même manière que le cloud enregistre:

  • Lire avant d'écrire. Au démarrage (et lorsqu'un autre joueur se connecte), le magasin lit GET /api/v1/games/{slug}/settings. La copie avec le plus récent at gagne. Si la copie cloud gagne, le le magasin l'adopte et licencie un change avec raison 'cloud'. Si la copie locale est plus récente, le magasin le pousse.
  • Un échec de lecture bloque l’écriture. La copie locale continue de fonctionner. Le prochain changement effectué par le joueur réessaye la lecture avant que quoi que ce soit ne soit écrit, afin qu'un périphérique obsolète ne puisse pas écraser un choix plus récent. Je ne pouvais pas voir.
  • Les changements sont poussés avec setSetting après 800 ms sans autre modification. Les renouvellements de jetons (qui lance également le SDK auth événement) ne déclenche pas une autre lecture.

3. Appliquez les paramètres à votre moteur de rendu

Quatre hooks connectent le magasin à un moteur de rendu three.js :

  • gfx.on('change', fn) pour les ombres et les effets.
  • Une chaîne de post-traitement reconstruite à partir des niveaux actuels.
  • gfx.frame(ms) et gfx.pixelRatio() dans la boucle de rendu, qui pilote la résolution adaptative.
  • gfx.shouldRender(now) avant de dessiner, ce qui applique la limite manuelle de FPS et le rythme de demi-rafraîchissement.

Créez le moteur de rendu avec antialias: false. MSAA provient alors de la cible de rendu de la post-chaîne, donc chaque niveau d'anticrénelage peut être commuté sans recréer le contexte WebGL.

import * as THREE from 'three';
import { EffectComposer } from 'three/addons/postprocessing/EffectComposer.js';
import { RenderPass } from 'three/addons/postprocessing/RenderPass.js';
import { GTAOPass } from 'three/addons/postprocessing/GTAOPass.js';
import { UnrealBloomPass } from 'three/addons/postprocessing/UnrealBloomPass.js';
import { OutputPass } from 'three/addons/postprocessing/OutputPass.js';
import { SMAAPass } from 'three/addons/postprocessing/SMAAPass.js';
import { ShaderPass } from 'three/addons/postprocessing/ShaderPass.js';
import { FXAAShader } from 'three/addons/shaders/FXAAShader.js';

// canvas, scene, camera and a shadow-casting DirectionalLight `sun` are your game's own.
const renderer = new THREE.WebGLRenderer({ canvas, antialias: false });
renderer.toneMapping = THREE.ACESFilmicToneMapping;

const SHADOW_MAP = { off: 0, low: 1024, medium: 2048, high: 4096 };
let composer = null;
let size = {};

gfx.on('change', (s) => {
  const mapSize = SHADOW_MAP[s.shadows];
  renderer.shadowMap.enabled = mapSize > 0;
  sun.castShadow = mapSize > 0;
  if (mapSize && sun.shadow.mapSize.x !== mapSize) {
    sun.shadow.mapSize.set(mapSize, mapSize);
    sun.shadow.map?.dispose();
    sun.shadow.map = null;
  }
  scene.traverse((o) => [].concat(o.material || []).forEach((m) => { m.needsUpdate = true; })); // shadow on/off recompiles
  size = {}; // resize and rebuild the post chain on the next frame
});

function buildPost(s, w, h, ratio) {
  composer?.dispose();
  composer = null;
  if (gfx.info.postFailed || (s.ao === 'off' && s.bloom === 'off' && s.antialias === 'off')) return;
  try {
    const pw = Math.round(w * ratio), ph = Math.round(h * ratio);
    const target = new THREE.WebGLRenderTarget(pw, ph, { type: THREE.HalfFloatType, samples: s.antialias === 'msaa' ? 4 : 0 });
    const c = new EffectComposer(renderer, target);
    c.setPixelRatio(ratio);
    c.setSize(w, h);
    c.addPass(new RenderPass(scene, camera));
    if (s.ao !== 'off') {
      const ao = new GTAOPass(scene, camera, pw, ph);
      ao.updateGtaoMaterial({ samples: s.ao === 'high' ? 16 : 8 });
      c.addPass(ao);
    }
    if (s.bloom === 'on') c.addPass(new UnrealBloomPass(new THREE.Vector2(w, h), 0.5, 0.4, 0.9));
    c.addPass(new OutputPass());
    if (s.antialias === 'smaa') c.addPass(new SMAAPass());
    if (s.antialias === 'fxaa') {
      const fxaa = new ShaderPass(FXAAShader);
      fxaa.material.uniforms.resolution.value.set(1 / pw, 1 / ph);
      c.addPass(fxaa);
    }
    composer = c;
  } catch {
    gfx.report({ postFailed: true }); // the panel shows a note; don't console.warn
  }
}

let last = performance.now();
renderer.setAnimationLoop((now) => {
  // Update your simulation here using its own elapsed time or fixed timestep.
  // Keep simulation/input independent of skipped render ticks.
  if (!gfx.shouldRender(now)) return;
  gfx.frame(now - last); // elapsed time between rendered frames, including the FPS limit
  last = now;
  const w = canvas.clientWidth, h = canvas.clientHeight, ratio = gfx.pixelRatio();
  if (w !== size.w || h !== size.h || ratio !== size.ratio) {
    size = { w, h, ratio };
    renderer.setPixelRatio(ratio);
    renderer.setSize(w, h, false);
    camera.aspect = w / h;
    camera.updateProjectionMatrix();
    buildPost(gfx.settings, w, h, ratio);
    gfx.report({ pixels: [Math.round(w * ratio), Math.round(h * ratio)] });
  }
  try {
    if (composer) composer.render();
    else renderer.render(scene, camera);
  } catch {
    composer = null;
    gfx.report({ postFailed: true });
  }
});

Remarques :

  • Le three/addons/ les fichiers doivent provenir du même version three.js comme three lui-même. Mélange les versions brisent la chaîne de publication. Le code ci-dessus cible les versions actuelles. Sur les plus âgés, SMAAPass prend (width, height).
  • Low désactive tous les effets de post-traitement, de sorte que le jeu s'affiche directement sur le canevas à un moment donné. rapport de pixels de l'appareil d'au plus 1. Cela maintient Low aussi bon marché que le jeu l'était avant tout cela.
  • gfx.pixelRatio() retours min(devicePixelRatio, preset cap) × preset scale × render scale × adaptive scale, serré à 0,25–3. Les plafonds sont 1 pour Low, 1,5 pour Balanced et 2 pour High et Ultra.
  • La résolution adaptative est en moyenne de 90 images. Au-dessus de 26 ms, l'échelle est réduite de 0,1 (jusqu'à 0,6). Ci-dessous 14 ms, l'échelle augmente de 0,05 (jusqu'à 1). Les images de plus de 1 s (onglets en pause ou en arrière-plan) sont ignoré, et une seule trame lente compte au maximum 250 ms pour l'adaptation, donc un accroc ne peut pas diminuer l'échelle. La lecture FPS utilise les temps réellement écoulés. Avec une limite manuelle ou une stimulation à demi-rafraîchissement, le seuil lent est d'au moins 115 % de l'image cible intervalle et le seuil rapide est d'au moins 85 %, donc une limite délibérée de 30 FPS ne diminue pas la qualité en soi. Pour des limites très basses, la coupure de pause et la coupure d'attelage correspondent à au moins deux intervalles cibles. Alimentation gfx.frame uniquement les images rendues ; conserver le dernier horodatage rendu lorsqu'une tick est ignorée.

Autres moteurs

Quel que soit le dessin de vos frames, l'intégration utilise les mêmes hooks :

Appel Utiliser
gfx.on('change', (settings, reason) => …) Appliquez des niveaux. S'exécute une fois immédiatement ('init'), puis sur 'settings', 'cloud' et 'auto'. Renvoie une fonction de désabonnement.
gfx.settings { preset, auto, scale, dprCap, adaptive, showFps, maxFps, halfRefresh, <category>: <tier> }; maxFps: 0 signifie un rafraîchissement automatique de l'affichage, réduit de moitié lorsque halfRefresh est true.
gfx.level Le niveau matériel détecté, 0 à 20, pour adapter vos propres budgets (nombre de particules, distance de tirage). Cela ne change pas lorsque Auto descend.
gfx.shouldRender(now) Chaque rappel d'animation, avec son horodatage en millisecondes. Ignorer le dessin s'il revient false. Gardez les mises à jour de simulation/entrée indépendantes.
gfx.frame(ms) Chaque image rendue, avec le temps écoulé depuis l'image rendue précédente. Retours true lorsque le rapport de pixels ou le préréglage automatique a changé.
gfx.pixelRatio() Le rapport à rendre à
gfx.report({ pixels, postFailed }) Indique au panneau la taille de sortie ou que les effets ne sont pas disponibles

Pour un jeu sur toile 2D, multipliez la taille du support de la toile par gfx.pixelRatio(), et cartographiez le vôtre effets (particules, lueur, couches de parallaxe) aux catégories comme décrit ci-dessous.

4. Adaptez-le à votre jeu

Vos propres effets. Passez un tableau de qualité qui répertorie uniquement ce que votre jeu dessine réellement. Chaque préréglage la ligne nécessite un niveau pour chaque catégorie, plus scale et dprCap:

import { createGraphics, CATEGORIES, TABLE } from './graphics-options.js';

const gfx = createGraphics({
  storageKey: 'mygame.graphics',
  categories: { ...CATEGORIES, particles: ['off', 'low', 'high'] },
  table: {
    low: { ...TABLE.low, particles: 'off' },
    balanced: { ...TABLE.balanced, particles: 'low' },
    high: { ...TABLE.high, particles: 'high' },
    ultra: { ...TABLE.ultra, particles: 'high' },
  },
});

Le panneau crée une sélection par catégorie, donc une nouvelle catégorie apparaît automatiquement. Nommez-le avec strings.categories.particles.

Vos propres préréglages. Une table dont les préréglages portent d'autres noms a également besoin levels: le plus bas de chaque preset niveau matériel. Sélectionne automatiquement le préréglage avec le niveau de départ le plus élevé égal ou inférieur gfx.level:

const gfx = createGraphics({
  table: { fast: { ...TABLE.low }, standard: { ...TABLE.balanced }, cinematic: { ...TABLE.ultra } },
  levels: { fast: 0, standard: 6, cinematic: 15 },
});

Traductions. Les chaînes anglaises du panneau sont exportées sous forme STRINGS. Passez le vôtre avec le même forme. Seules les clés que vous donnez sont remplacées :

mountGraphicsPanel(el, gfx, {
  strings: {
    quality: 'Qualität', auto: 'Automatisch ({tier})', fromPreset: 'Laut Voreinstellung ({tier})',
    renderScale: 'Renderskalierung', adaptive: 'Adaptive Auflösung', showFps: 'Bildrate anzeigen',
    maxFps: 'Maximale Bildrate', autoFps: 'Automatisch (Bildschirmfrequenz)',
    autoHalfFps: 'Automatisch (halbe Bildschirmfrequenz)', level: 'Stufe {level}',
    customFps: 'Benutzerdefiniert', fpsLimit: 'Maximale FPS (1–1000)',
    categories: { shadows: 'Schatten', ao: 'Umgebungsverdeckung', particles: 'Partikel' },
    tiers: { low: 'Niedrig', balanced: 'Ausgewogen', high: 'Hoch', off: 'Aus', on: 'An' },
  },
});

Stylisme. Le panel utilise les classes .gfx-panel, .gfx-row, .gfx-summary et .gfx-note. C'est les règles intégrées sont enveloppées dans :where(), donc toute règle de votre propre feuille de style les remplace. Les lignes sont au moins 44 px de hauteur pour le toucher. La lecture de la fréquence d'images (#gfx-fps) se trouve dans le coin inférieur gauche, à l'intérieur de la zone de sécurité et ne capture pas les clics.

Lire le résultat ailleurs. <html> porte data-gfx-preset (le préréglage actif) et data-gfx-auto (1 ou 0), que CSS et les tests peuvent activer.

5. Testez-le

  • Les navigateurs sans tête s'affichent avec un GPU logiciel, donc Auto se résout au niveau 0 (Faible) et les tests restent rapides.
  • Conduisez le vrai panneau. Chaque contrôle a un data-gfx attribut (preset, renderScale, adaptive, frameRate, maxFps, showFps, ou le nom de la catégorie) :
const preset = () => page.evaluate(() => document.documentElement.dataset.gfxPreset);
await page.locator('select[data-gfx=preset]').selectOption('high');
assert.equal(await preset(), 'high');
await page.reload();
assert.equal(await preset(), 'high'); // persisted
await page.locator('select[data-gfx=frameRate]').selectOption('custom');
await page.locator('input[data-gfx=maxFps]').fill('45');
await page.locator('input[data-gfx=maxFps]').press('Tab');
await page.reload();
assert.equal(await page.locator('input[data-gfx=maxFps]').inputValue(), '45');
await page.locator('select[data-gfx=frameRate]').selectOption('auto');
  • Les fonctions pures detectLevel(system), presetForLevel(level, levels), detectPreset(system), resolve(saved, detected, { mobile }) et withPreset(saved, preset) exécuté sous Node pour les tests unitaires. createGraphics({ sdk, storage, system }) accepte également les contrefaçons pour les trois ; passer un system avec un le téléphone gpu et mobile: true pour tester les paramètres par défaut du mobile.
  • node --test tests/graphics-options.test.mjs vérifie les niveaux de matériel, la validation et la persistance par GPU et restauration, stimulation des images sur différents taux de rafraîchissement d'affichage (y compris la stimulation de demi-rafraîchissement sur téléphones), la commutation en direct et la qualité adaptative avec une limite FPS.
