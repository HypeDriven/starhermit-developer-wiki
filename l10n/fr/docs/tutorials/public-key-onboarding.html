Tutoriel : Intégrer des lecteurs avec une clé publique

Un compte StarHermit n'a pas besoin de Google, GitHub ou de tout autre fournisseur de connexion. Son titre peut être une paire de clés que votre jeu génère sur l'appareil du joueur, plus une adresse e-mail du joueur confirme une fois. Après cela, votre jeu se connecte silencieusement à chaque lancement en signant un défi avec la clé. Le joueur ne saisit jamais de mot de passe et n'a jamais besoin de visiter une page StarHermit.

Ce tutoriel construit ce flux de bout en bout : générez la clé, enregistrez-la, attendez que le joueur confirmez, connectez-vous, conservez la session et gérez les deuxièmes appareils et les clés perdues.

Utilisez-le pour jeux natifs et autonomes, lanceurs, versions Steam/Epic/GOG et outils de bureau — tout ce qui s'exécute sur la machine du joueur et peut y conserver une clé privée.

Utilisez autre chose pour

  • Un jeu par navigateur hébergé sur StarHermit, qui reçoit déjà un jeton de lancement lorsqu'il est ouvert depuis le tableau de bord, ou peut afficher un Bouton de connexion.
  • Un pipeline CI, qui devrait inscrire une clé d'une session OAuth sans étape d'envoi de courrier électronique : Tutoriel : télécharger des builds à partir de CI/CD.
  • Un serveur de jeu dédié, qui possède son propre jeton de déploiement et ne peut pas créer ou agir en tant que joueurs : Tutoriel : publier un serveur dédié.

Ce que voit le joueur

  1. Votre jeu demande une adresse e-mail et leur consentement pour créer un compte StarHermit.
  2. Ils ouvrent l'e-mail de confirmation, cliquent sur le lien et appuient sur Confirmer sur la page qu'il ouvre.
  3. De retour dans votre jeu, ils sont connectés. Lors des lancements ultérieurs, rien n'est demandé du tout.

Une adresse e-mail est requise et le joueur doit la confirmer une fois. Il n'y a aucun moyen de créer un Compte StarHermit en silence à partir d'une seule identité Steam, Epic ou GOG.

Avant de commencer

Le code sur cette page est du JavaScript simple utilisant WebCrypto et fetch, donc il s'exécute dans un navigateur, dans Electron et dans le nœud 20 ou version ultérieure. Le js les blocs ci-dessous, dans l'ordre, forment un module ES — sauve-les ensemble comme starhermit-key-auth.js. Toute autre langue fonctionne de la même manière : l'étape 1 donne le formats d'octets et étape 3 les octets exacts à signer.

const API = 'https://api.starhermit.com';

const b64 = (bytes) => btoa(String.fromCharCode(...new Uint8Array(bytes)));

1. Créez la clé de l'appareil

Générer une paire de clés par installation, la première fois que votre jeu a besoin d'un compte. Le privé La clé ne quitte jamais l'appareil : ni vers vos serveurs, ni vers StarHermit.

keyType keyData (norme Base64) Signature (standard Base64)
Ed25519 - recommandé La clé publique brute de 32 octets La signature brute Ed25519 de 64 octets
ECDSA-P256 Le point public : 65 octets non compressés (04‖X‖Y) ou 33 octets compressés ECDSA avec SHA-256, ASN.1 codé DER
RSA-PSS SubjectPublicKeyInfo DER, module 2048-8192 bits, exposant ≤ 32 bits RSASSA-PSS, SHA-256, MGF1-SHA-256, sel de 32 octets

keyData comporte au maximum 2 000 caractères. Une clé appartient à un compte sur la plateforme.

Prendre Ed25519 sauf si votre plateforme ne peut pas le produire. Si vous utilisez ECDSA, notez que WebCrypto, Windows CNG et la plupart des magasins de clés matérielles renvoient la signature brute r‖s (64 octets). ÉtoileErmite attend DER, alors convertissez-le - le module ci-dessous le fait.

// One key per installation. The private key can sign but is never exported.
export async function createDeviceKey(keyType = 'Ed25519') {
  if (!['Ed25519', 'ECDSA-P256'].includes(keyType)) throw new Error('This helper supports Ed25519 or ECDSA-P256');
  const algorithm = keyType === 'Ed25519'
    ? { name: 'Ed25519' }
    : { name: 'ECDSA', namedCurve: 'P-256' };
  const pair = await crypto.subtle.generateKey(algorithm, false, ['sign', 'verify']);
  return {
    keyType: keyType === 'Ed25519' ? 'Ed25519' : 'ECDSA-P256',
    keyData: b64(await crypto.subtle.exportKey('raw', pair.publicKey)),
    privateKey: pair.privateKey,
  };
}

Stockez la clé privée là où le système d’exploitation la protège. Dans un navigateur ou un moteur de rendu Electron, un non extractible CryptoKey peut être conservé dans IndexedDB tel quel. Un jeu natif devrait utiliser le magasin de clés de plate-forme – Windows DPAPI ou CNG, trousseau macOS, libsecret sous Linux. Magasin keyType et keyData à côté; vous les envoyez à chaque demande.

2. Commencez l'inscription

Demandez l'adresse e-mail et le consentement du joueur, puis :

async function post(path, body) {
  const res = await fetch(API + path, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  });
  return { status: res.status, body: await res.json().catch(() => ({})) };
}

function fail(step, { status, body }) {
  return Object.assign(new Error(`${step}: ${body.error ?? status}`), { status, body });
}

export async function register(key, email) {
  const res = await post('/api/v1/auth/public-key/register',
    { email, keyType: key.keyType, keyData: key.keyData });
  if (res.status !== 202) throw fail('register', res);
  return res.body; // { registrationId, email, emailSent, deferralReason, message }
}

202 signifie que StarHermit a accepté l'enregistrement. Si emailSent est false, l'e-mail est mis en file d'attente et arrivera toujours; deferralReason dit pourquoi il a attendu. Rien n'est encore attaché à un compte.

Trois règles façonnent votre interface utilisateur :

  • Une inscription par adresse email et une par adresse IP, toutes les 24 heures. Une deuxième tentative est 429 avec Retry-After. Demandez au joueur de confirmer l'adresse avant de l'envoyer, car une faute de frappe leur coûte une journée. Envoyez la demande depuis l'appareil du joueur, jamais via votre propre serveur : chaque Le joueur partagerait l'adresse IP de votre serveur et son enregistrement quotidien unique.
  • Le lien expire après 4 heures. En cas d'expiration, le joueur peut se réinscrire une fois les 24 heures écoulées. sont debout.
  • 400 signifie que l'adresse e-mail ou le matériel clé a été rejeté ; error dit lequel.

3. Connectez-vous avec la clé

La connexion est un défi et une réponse. POST /api/v1/auth/public-key/challenge renvoie :

{
  "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
  "payload": {
    "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
    "fingerprint": "9c0b7a…",
    "issuer": "starhermit",
    "audience": "starhermit",
    "expiry": "2026-10-09T14:21:41.9264875+00:00",
    "nonce": "NmL+tgMum6HXU/pa3T9xjQ==",
    "clientTimestamp": "2026-10-09T14:16:41.9265739+00:00"
  },
  "expiresIn": 300
}

Ce que vous signez n'est pas le JSON que vous avez reçu. StarHermit vérifie la signature par elle-même sérialisation de payload:

  • JSON compact, pas d'espace ;
  • PascalCase noms des membres, exactement dans l'ordre ChallengeId, Fingerprint, Issuer, Audience, Expiry, Nonce, ClientTimestamp;
  • chaque valeur copiée exactement comme servi — ne pas analyser ni reformater les dates ;
  • chaque + dans le nonce écrit comme \u002B. Le + les dates restent telles quelles.

Pour le défi ci-dessus, les octets signés sont le codage UTF-8 de :

{"ChallengeId":"4fc4d72b-4c12-41ca-a500-dc13cccc3865","Fingerprint":"9c0b7a…","Issuer":"starhermit","Audience":"starhermit","Expiry":"2026-10-09T14:21:41.9264875+00:00","Nonce":"NmL\u002BtgMum6HXU/pa3T9xjQ==","ClientTimestamp":"2026-10-09T14:16:41.9265739+00:00"}

Si vous vous trompez, la réponse est 401 "Invalid signature.", qu'aucune nouvelle tentative ne corrigera.

const FIELDS = ['challengeId', 'fingerprint', 'issuer', 'audience', 'expiry', 'nonce', 'clientTimestamp'];

export function challengeSigningBytes(payload) {
  const members = FIELDS.map((field) => {
    let value = JSON.stringify(payload[field]);
    if (field === 'nonce') value = value.replaceAll('+', '\\u002B');
    return `"${field[0].toUpperCase()}${field.slice(1)}":${value}`;
  });
  return new TextEncoder().encode(`{${members.join(',')}}`);
}

export async function signChallenge(key, payload) {
  const data = challengeSigningBytes(payload);
  if (key.keyType === 'Ed25519')
    return b64(await crypto.subtle.sign({ name: 'Ed25519' }, key.privateKey, data));
  // WebCrypto returns an ECDSA signature as raw r||s; the server expects ASN.1 DER.
  const rs = new Uint8Array(
    await crypto.subtle.sign({ name: 'ECDSA', hash: 'SHA-256' }, key.privateKey, data));
  return b64(derEcdsaSignature(rs));
}

function derEcdsaSignature(rs) {
  const integer = (bytes) => {
    let i = 0;
    while (i < bytes.length - 1 && bytes[i] === 0) i++;
    const value = [...bytes.slice(i)];
    return value[0] & 0x80 ? [0x02, value.length + 1, 0, ...value] : [0x02, value.length, ...value];
  };
  const body = [...integer(rs.slice(0, 32)), ...integer(rs.slice(32))];
  return new Uint8Array([0x30, body.length, ...body]);
}

// Resolves to { userId, accessToken, refreshToken }, or null while the key is not attached to
// an account yet — the player has not confirmed, the link expired, or the key was revoked.
export async function signIn(key) {
  const { keyType, keyData } = key;
  const challenge = await post('/api/v1/auth/public-key/challenge', { keyType, keyData });
  if (challenge.status !== 200) throw fail('challenge', challenge);
  const signature = await signChallenge(key, challenge.body.payload);
  const done = await post('/api/v1/auth/public-key/complete',
    { challengeId: challenge.body.challengeId, signature, keyType, keyData });
  if (done.status === 200) return done.body;
  if (done.status === 401 && done.body.error === 'Public key not registered or revoked.') return null;
  throw fail('complete', done); // "Invalid signature." will never succeed: fix it, don't retry it
}

Un défi dure cinq minutes et est à usage unique, même en cas d'échec de la tentative, alors demandez-en un nouveau. pour chaque tentative. Défiez et partagez complètement une limite de 60 requêtes par minute par adresse IP.

4. Attendez que le joueur confirme

Le lien envoyé par e-mail ouvre une page StarHermit indiquant ce que fera la confirmation ; l'ouvrir change rien, donc un scanner de courrier prévisualisant le lien ne peut pas confirmer au nom du joueur. Quand le le joueur appuie Confirmer, StarHermit crée son compte, joint votre clé et marque l'adresse vérifié. Si un compte utilise déjà cette adresse, la page l'indique et la clé y est ajoutée au lieu de cela, donc un joueur qui possède déjà un compte StarHermit le conserve. Sur starhermit.com, ils atterrissent ensuite sur le tableau de bord StarHermit, déjà connecté.

Votre jeu ne reçoit jamais les jetons de cette page, et n'en a pas besoin. Le joueur peut confirmer sur un téléphone ou dans un autre navigateur. Une fois la clé attachée, votre jeu peut simplement se connecter avec ça. Alors montrez un "vérifie ta boîte de réception" écran et continuez d’essayer :

// Poll until the player confirms the emailed link. Two requests per attempt, so every 5 s stays
// well inside the 60-per-minute sign-in limit.
export async function waitUntilConfirmed(key, { intervalMs = 5000, signal } = {}) {
  for (;;) {
    signal?.throwIfAborted();
    const session = await signIn(key);
    if (session) return session;
    await new Promise((resolve) => setTimeout(resolve, intervalMs));
  }
}

Rassembler les étapes 1 à 4 :

import { createDeviceKey, register, signIn, waitUntilConfirmed } from './starhermit-key-auth.js';

const key = await loadStoredKey() ?? await saveKey(await createDeviceKey());
let session = await signIn(key);                // a returning player is signed in here
if (!session) {
  const email = await askForEmailAndConsent();
  await register(key, email);
  showCheckYourInbox(email);
  session = await waitUntilConfirmed(key, { signal: cancelButton.signal });
}

loadStoredKey, saveKey, askForEmailAndConsent et showCheckYourInbox êtes à vous d'écrire. Offrez un Annuler cela annule l'attente et arrête l'interrogation après quatre heures, lorsque le lien expire.

Continuez à interroger même si la page de confirmation de votre plateforme redirige vers votre site. Le joueur souvent ouvre l'e-mail sur un appareil différent de celui en attente, puis la redirection n'atteint nulle part près de votre écran d'attente ; l'interrogation est ce qui signe le périphérique en attente. Si la redirection arrive dans un deuxième onglet, connectez-vous avec un seul d'entre eux et révoquez la session supplémentaire, sinon le joueur se retrouve avec deux.

5. Gardez la session

complete renvoie un jeton d'accès de 15 minutes et un jeton d'actualisation qui dure sept jours et tourne. Envoyez le jeton d'accès en tant que Authorization: Bearer …, et actualisez-le avant son expiration :

// Resolves to the new pair, or null when the session is over — sign in with the key again.
export async function refresh(refreshToken) {
  const res = await post('/api/v1/auth/refresh', { refreshToken });
  return res.status === 200 ? res.body : null; // { accessToken, refreshToken }
}

Remplacer les deux des jetons à chaque fois. La présentation d'un jeton d'actualisation utilisé met fin à toute la session, alors faites assurez-vous que deux threads ou processus ne s’actualisent jamais en même temps. Quand refresh retours null, appel signIn — aucun e-mail n'est impliqué. La clé est le titre de compétences de longue durée ; les jetons n'en sont qu'un cache.

6. Terminez la configuration du compte

Termes. Un nouveau compte doit accepter les conditions actuelles de StarHermit avant de pouvoir utiliser autre chose. Appel GET /api/v1/me. Si termsAcceptanceRequired est true, affiche le texte de GET /api/v1/terms, et lorsque le joueur l'accepte, envoie son hachage à POST /api/v1/me/terms/accept. Vérifiez à nouveau lors des lancements ultérieurs, car les conditions sont révisées. Détails: Acceptation des conditions.

Nom. Le compte commence par un pk-… nom d'utilisateur. Laissez le joueur choisir un surnom :

PATCH /api/v1/me
Authorization: Bearer <access-token>
Content-Type: application/json

{ "nickname": "RookPilot" }

À partir de là, le compte est comme n’importe quel autre : amis, chat, matchmaking, sauvegardes dans le cloud, réalisations.

7. Seconds appareils, clés perdues et limites

Un deuxième appareil génère sa propre clé et l'enregistre avec la même adresse email. Quand le Le joueur confirme, la clé rejoint son compte existant plutôt que d'en créer un nouveau. Les 24 heures la limite par adresse s’applique ici également.

Un appareil perdu ou volé. POST /api/v1/auth/public-key/revoke-request avec { "email": "…" } envoie par courrier électronique un lien vers une page ; confirmant qu'il révoque chaque clé sur le compte et termine les sessions ces clés sont connectées. L'ouverture du lien seule ne change rien. La demande répond toujours 202 avec le même message, que le l'adresse a un compte. Le lien expire au bout de quatre heures et un compte peut demander une fois tous les 15 minutes. Ensuite, chaque appareil restant s'enregistre à nouveau (étape 2).

Ce qu’un compte clé uniquement ne peut pas faire. Quelques modifications protègent les informations d'identification du compte, elles nécessiter une session connectée via un fournisseur tel que Google ou GitHub :

Action Compte clé uniquement
Ajouter une clé ou révoquer d'autres appareils (POST /me/public-keys, DELETE /me/public-keys/{id} ou /all) 403 - inscrivez-vous via une inscription par e-mail ou utilisez une session authentifiée OAuth
Changer l'adresse e-mail du compte 403 oauth_session_required — pas possible tant qu'un fournisseur n'est pas lié
Révoquer la propre clé de cette installation DELETE /api/v1/me/public-keys/current, en utilisant sa session complète de compte à clé publique ; supprimer les informations d'identification locales après le succès

Pour gérer d'autres informations d'identification ou modifier l'e-mail, associez un fournisseur. Lorsqu'un compte clé uniquement en lie un, le lien est conservé jusqu'à ce que le joueur le confirme depuis son email. Après cela, la connexion d'un fournisseur peut faire tout ce qui précède. Voir authorize?link=true.
