Chargez et enregistrez votre progression en toute sécurité

Utilisez les sauvegardes dans le cloud pour la progression appartenant au client d'un joueur connecté. L'option solo non signée conserve la progression en mémoire et ne lit ni n'écrit les sauvegardes du compte. Les préférences appartiennent à paramètres du jeu, pas le document d'avancement.

Un jeton de lancement peut accéder exactement game:<gameId>, où gameId est-ce que c'est game_scope. La plateforme stocke les octets opaques, avec une sauvegarde par emplacement. Validez le format attendu par votre jeu. Voir Sauvegardes cloud pour les quotas et les en-têtes conditionnels.

Une petite recette JSON complète

Copie cloud-save-store.js dans votre construction. Cet exemple stocke les données brutes Octets JSON UTF-8 ; la plateforme leur sert avec application/zip mais ne nécessite pas de format ZIP. Utilisez un autre lecteur pour les sauvegardes ZIP, y compris le sauvegardes ZIP du SDK du navigateur. Ne changez pas de format sans un plan de migration pour les lecteurs existants.

import { CloudSaveStore } from './cloud-save-store.js';

const store = new CloudSaveStore({
  gameId: StarHermit.slug,
  token: () => StarHermit.token, // Always obtain the current renewed token.
});
const valid = value => value?.version === 1 && Number.isSafeInteger(value.points) && value.points >= 0;
let progress = { version: 1, points: 0 };
let saving = false;

async function startAccountGame() {
  // Keep gameplay/saving disabled until this resolves.
  const remote = await store.load(valid);
  progress = remote ?? { version: 1, points: 0 };
  render(progress);
}

async function saveCheckpoint() {
  if (saving) return; // Coalesce checkpoints; do not issue overlapping writes.
  saving = true;
  showSync('Saving…');
  try {
    await store.save(progress);
    showSync('Saved');
  } catch (error) {
    if (error.status === 412) {
      // Keep local progress in memory. Offer Reload cloud or an explicit merge.
      showConflict(() => startAccountGame());
    } else showSync('Save failed; retry after resolving the error');
  } finally {
    saving = false;
  }
}

render, showSync, et showConflict sont votre interface utilisateur. Attendre startAccountGame() avant d'activer jouer ou sauvegarder. En cas d'échec de chargement, conservez l'état local actuel du lecteur, affichez l'échec, et gardez les téléchargements bloqués. UN 404 est le cas de l'emplacement vide ; 401, 403, 5xx, JSON mal formé, ou une version de sauvegarde non prise en charge ne sont pas des emplacements vides.

La recette ne renouvelle pas les informations d'identification. Le SDK du navigateur renouvelle les jetons de lancement tant qu'ils restent valide. Résolvez les termes en attente ou réauthentifiez-vous via le flux d'entrée du jeu avant de réessayer une lecture.

Conditions et conflits

Ce qui a été chargé En-tête lors de la prochaine écriture Si un autre appareil écrit
Sauvegarde existante avec ETag If-Match: <etag> 412 precondition_failed
Aucune sauvegarde (404) If-None-Match: * 412 precondition_failed
Rien n'a été chargé avec succès Pas d'écriture Continuez à réessayer la lecture ou laissez le joueur rester en jeu non suivi

Utilisez la version du les données que vous avez chargées, pas une vérification ultérieure des métadonnées. Conserver le nouvel ETag renvoyé par chaque écriture réussie. UN 412 bloque les sauvegardes supplémentaires jusqu'à ce que le jeu charge la version actuelle et le joueur l'adopte ou le fusionne. Ne supprimez pas silencieusement la condition et n’écrasez pas un autre périphérique. L'API n'offre aucun historique de sauvegarde pour annuler cet écrasement.

Si deux appareils doivent mettre à jour indépendamment les compteurs ou l'inventaire, un seul document de dernière écriture l'emporte peut ne pas correspondre au jeu. Utilisez l’état faisant autorité sur le serveur et définissez plutôt des commandes de jeu validées.

Format de sauvegarde et migration

Incluez une version de format et validez les types, les plages et les champs obligatoires avant d'adopter la version à distance. progrès. Écrivez une migration pour les anciennes versions prises en charge. Conservez intacte une version inconnue plus récente ; ne le réinitialisez pas aux valeurs par défaut et ne téléchargez pas dessus. Les données cloud sont contrôlées par le client, alors ne les traitez jamais comme preuve d'un score compétitif ou d'un droit payé.

La limite de sauvegarde décodée par défaut est de 10 Mio. Base64 ajoute environ un tiers au corps de la requête. 413 cloud_save_too_large, 409 cloud_save_slots_exhausted, et 507 cloud_save_quota_exceeded sont différentes pannes de capacité ; inspecter code et limit. Honneur Retry-After sur 429.

Points de contrôle et sortie de page

Enregistrez à des points de contrôle significatifs et proposez une action de sauvegarde visible. Anti-rebond des changements rapides et sérialisation écrit pour que chacun utilise la dernière version reconnue. Conservez un indicateur sale jusqu'à ce qu'il soit reconnu. Une requête ayant échoué n’est pas une sauvegarde confirmée ; après une écriture ambiguë, rechargez avant une autre écriture.

Un téléchargement de sortie de page est la meilleure solution. Navigateur fetch(..., { keepalive: true }) partage un petit vol allocation corporelle, généralement 64 Ko ; une sauvegarde de 10 Mio ne peut pas s'appuyer sur elle. Un onglet peut se fermer avant toute demande se termine. Utilisez des sauvegardes de premier plan ordinaires pour plus de durabilité et ne qualifiez pas les progrès non reconnus de enregistré. Le démarrage rapide enregistre son petit document à chaque point de collecte.

Vérifiez dans votre jeu

  1. Commencez avec un emplacement vide ; collectez la progression, enregistrez, rechargez et confirmez son retour.
  2. Refuser les lectures avec une erreur réseau, 403, ou des données invalides ; confirmez qu'aucun téléchargement ne suit.
  3. Ouvrez deux onglets sur une version. Enregistrez en A, puis B : B doit faire apparaître un conflit et préserver son état local.
  4. Testez un format plus ancien/plus récent et un accusé de réception manquant sans écraser les données inconnues.
  5. Entrez en mode solo non suivi et vérifiez que le jeu ne fait aucune demande de sauvegarde dans le cloud.
