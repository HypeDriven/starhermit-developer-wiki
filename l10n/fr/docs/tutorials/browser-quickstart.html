Créez votre premier jeu par navigateur hébergé

Télécharger le collecteur d'étoiles, un petit jeu complet à deux entrées options : jeu de compte avec sauvegardes dans le cloud et jeu solo dont la progression est conservée uniquement en mémoire. Essayez une lecture non signée sur ce wiki ; la connexion au compte devient disponible après avoir publié votre propre copie sur StarHermit.

Vous avez besoin d'un compte StarHermit pour publier. Le jeu lui-même n'a besoin d'aucun serveur backend, ni de dépendance l'installation, l'étape de build ou l'organisation de l'éditeur.

1. Décompressez et jouez localement

Le ZIP contient index.html, app.js, style.css, starhermit.txt, et les deux fichiers d'aide. Servez le dossier extrait avec un serveur statique local, par exemple :

python3 -m http.server 8000 --directory star-collector

Ici star-collector est le dossier dans lequel vous avez extrait. Ouvrir http://localhost:8000 et choisissez Jouez en solo (la progression n'est pas enregistrée). Cliquez sur l'étoile. Retour au départ ou rechargement démarre une nouvelle exécution non suivie. Ce mode n'écrit ni la progression locale ni la progression du compte.

2. Publiez le dossier distribuable

Le manifeste se trouve déjà à la racine du dossier :

name=Star Collector Quickstart
launch=index.html
description=A small single-player game with account saves or untracked play.

Dans l'interface utilisateur de publication de jeux de StarHermit, ajoutez ce dossier en tant que nouveau jeu. L'intégralité du dossier sélectionné est le version publiée. Conservez uniquement les fichiers que vous avez l'intention de servir. L'équivalent API regroupe les fichiers sous client/ et envoie une archive gzip brute :

mkdir -p bundle/client
cp -R star-collector/. bundle/client/
cp star-collector/starhermit.txt bundle/starhermit.txt
# Write the archive outside bundle so it cannot include itself.
tar -C bundle -czf star-collector.tar.gz .

curl --fail-with-body -X POST https://api.starhermit.com/api/v1/me/github-games/upload \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H 'Content-Type: application/gzip' \
  --data-binary @star-collector.tar.gz

ACCESS_TOKEN est votre jeton de compte complet, après acceptation explicite des conditions actuelles. La réponse est game.id, game.gameSlug, et le sous-domaine hébergé identifie votre jeu. Ouvrez l'URL hébergée renvoyée. Pour les versions ultérieures, utilisez le nom de ce jeu point de terminaison du bundle plutôt que de créer une autre annonce. Voir Publication CI quand il est prêt.

3. Essayez les deux chemins d'entrée de compte

Lancement depuis StarHermit : le lanceur fournit #game_token=<jwt>. L'assistant le capture et le supprime de l'URL avant l'exécution du module de jeu. Choisir Continuez avec votre compte StarHermit.

Ouvrez directement l'URL hébergée : choisir Connectez-vous avec StarHermit. Le sélecteur de fournisseur permet au joueur, connectez-vous avec un compte existant ou créez-en un. On revient directement sur ce jeu avec un scope #access_token=<jwt>; aucun identifiant à l'échelle du compte n'est envoyé au jeu.

Le jeu charge la progression uniquement lorsque le joueur choisit de jouer avec un compte. Si les conditions actuelles doivent être acceptées, il affiche le document sous forme de texte et propose Accepter et continuer. L'acceptation envoie uniquement le hachage de la révision affichée. Une révision modifiée est réaffichée pour une autre décision explicite.

4. Vérifiez les progrès et les échecs

Collectez quelques étoiles en mode compte, attendez Enregistré, et rechargez. Le décompte revient après avoir choisi jeu de compte. Ouvrez un deuxième onglet sur le même décompte sauvegardé : sauvegardez dans l'un, puis collectez dans l'autre. Le le deuxième doit montrer un conflit et proposer Charger les dernières avancées du cloud au lieu de l'écraser.

Le document de sauvegarde est { version: 1, points: <non-negative integer> }. Le jeu se charge et valide avant d'écrire, utilise l'ETag chargé pour les mises à jour conditionnelles et bloque les écritures après un échec de lecture. Il enregistre à chaque collecte et étiquette les données enregistrées uniquement après accusé de réception. Voir la recette salvatrice pour les formats, la migration et les documents plus volumineux.

La sélection d'un jeu non suivi supprime le jeton de joueur du jeu et arrête le renouvellement de l'arrière-plan. Pas de nuage une sauvegarde, une réussite, un classement ou une écriture de progression locale se produisent. Choisir de jouer à nouveau en compte utilise connectez-vous pour obtenir un nouveau jeton.

5. Adaptez-le à votre jeu

Remplacez le bouton étoile et le schéma de progression par votre gameplay. Conserver les choix d'entrée, jeton capture, acceptation des termes explicites, règle de chargement avant sauvegarde, gestion des erreurs et état de sauvegarde. Déclarez les actions du clavier dans le manifeste et lisez le API de contrôle lorsque votre jeu a besoin de reliures. Mettez les préférences de volume et de graphiques dans paramètres.

Pour les résultats multijoueurs ou compétitifs validés, ajoutez un script ou un conteneur. Le compteur cloud de ce démarrage rapide correspond à une progression appartenant au client et non à une preuve d'un score légitime.

Déposer But
index.html, style.css Entrée, termes, gameplay et interface utilisateur de statut accessibles
app.js Modes de saisie, consentement explicite, validation de progression, points de contrôle, conflits
starhermit-sdk.js Capture du jeton de lancement, connexion hébergée, renouvellement du jeton
cloud-save-store.js Recette de chargement JSON brut/sauvegarde conditionnelle
starhermit.txt Métadonnées de publication publique
