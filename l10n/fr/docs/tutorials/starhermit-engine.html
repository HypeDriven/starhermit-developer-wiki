Tutoriel : créer un jeu avec le moteur StarHermit

Le Le moteur StarHermit est le moyen recommandé pour créer des jeux à publier sur StarHermit. Vous construisez le jeu une seule fois, et le même package est automatiquement jouable dans un navigateur et de manière native sur toutes les plates-formes prises en charge par le moteur. Le jeu natif offre des performances et des fonctionnalités supplémentaires. La disponibilité dépend de la version du moteur : 1.1.0 et versions ultérieures disposent d'un runtime Windows et d'un runtime Web. (1.0.0 était uniquement Windows), 1.8.1 et versions ultérieures également un environnement d'exécution Linux pour les développeurs, et 1.26.2 et versions ultérieures des environnements d'exécution macOS (Intel et Apple Silicon). Cette page décrit le moteur 1.27.0; ce que chaque version a changé est répertorié sous Versions du moteur.

Le moteur StarHermit fonctionne jeux de scénario: un jeu entier écrit en TypeScript (ou JavaScript) et joué par un exécutable de moteur prédéfini, le runtime StarHermit, sans compiler de code natif. Vous écrivez la logique du jeu en fonction des modules intégrés du moteur : une scène 3D, une entrée, un HUD, de l'audio, stockage et la plateforme StarHermit — et le runtime fait le reste : fenêtrage, rendu sur le GPU, son, menu d'options, connexion et jeu en ligne. Les joueurs ouvrent le jeu sur starhermit.com dans leur navigateur, où sa page charge le moteur que votre jeu demande à ce wiki, ou y jouez de manière native dans le Client Windows StarHermit, qui installe ce moteur.

1. Qu'est-ce qu'un jeu de scénario

Un jeu de script est un dossier (un emballer) avec un starhermit.txt à son root, vos modules TypeScript et vos ressources. Trois engine.* les lignes du manifeste en font un :

engine.api=1
engine.entry=src/main.ts
engine.version=1.27.0

engine.api est la version majeure de l'API hôte sur laquelle votre code est écrit, engine.entry le module, le runtime démarre et engine.version la version exacte du moteur sur lequel le jeu est construit et testé pour. Les versions sont publiées sur ce wiki sous Versions du moteur; le le jeu ne contient jamais le moteur lui-même, donc un téléchargement ne contient que vos propres fichiers.

Le runtime traite chaque jeu comme non fiable : votre code atteint la machine uniquement via l'API hôte (ses propres fichiers de package, son propre stockage, la plateforme pour son propre identifiant de jeu), jamais de fichiers, de processus, connexions réseau arbitraires ou les informations d'identification du joueur. En retour, un jeu ne peut pas planter le runtime ou accrochez la fenêtre : un appel qui dure trois secondes fait apparaître le propre "ne répond pas" écran, et une erreur non détectée termine le jeu sur un écran d'erreur à partir duquel le joueur peut redémarrer.

2. Obtenez le moteur

Pour la publication automatisée et un serveur MCP de développement de jeux de script, procurez-vous le outils de développement autonomes. Ils emballent également jeux Web sur macOS sans accès à Rust ou au référentiel privé ; playtest dans un navigateur là-bas. La lecture native Windows/Linux utilise le runtime ci-dessous.

Joueurs ne rien faire : dans un navigateur, la page du jeu charge la version des pins du jeu de ce wiki et le vérifie par rapport aux hachages que la page contient ; dans le client Windows StarHermit, Lire les téléchargements la version (une fois, partagée par chaque jeu qui l'épingle), vérifie chaque fichier par rapport à la version les hachages publiés et le démarrent.

Développeurs téléchargez le runtime d'une version depuis la zone moteur :

  • starhermit-1.27.0-windows-x86_64.zip (Windows 10 ou 11, 64 bits), 11,6 Mo.
  • starhermit-1.27.0-linux-x86_64.tar.gz (Linux 64 bits avec glibc 2.35 ou version ultérieure : Ubuntu 22.04, Debian 12 ou version ultérieure), 11,8 Mo.
  • starhermit-1.27.0-macos-x86_64.tar.gz (macOS 11 ou version ultérieure sur Intel), 10,8 Mo et starhermit-1.27.0-macos-aarch64.tar.gz (macOS 11 ou version ultérieure sur Apple Silicon), 9,5 Mo. Ceux-ci sont signés ad hoc et non notariés : le StarHermit Le client macOS les installe sans problème, mais une archive tar téléchargée dans un navigateur est mise en quarantaine et Gatekeeper le bloque (effacez-le avec xattr -dr com.apple.quarantine sur le dossier décompressé). Ils ont pas encore été testé sur du matériel Apple réel ou avec un GPU.

L'archive contient un dossier, starhermit-1.27.0-windows-x86_64, avec starhermit.exe, le release.json qui indique au runtime de quelle version il s'agit, la version web-manifest.json, LICENSE-engine et les avis des tiers. C'est le même moteur que le client installe, et il regroupe les jeux pour le runtime Web de la version sans réseau. Sa taille et SHA-256 sont répertoriés sous downloads dans la version native.json; à vérifiez votre copie dans PowerShell, comparez-la sha256 avec:

Get-FileHash .\starhermit-1.27.0-windows-x86_64.zip -Algorithm SHA256

Décompressez l'archive et ouvrez un terminal dans le dossier décompressé :

.\starhermit.exe --version

starhermit 1.27.0 (host API 1.29, launcher 1; engine release 1.27.0)

Sous Linux, décompressez l'archive et exécutez starhermit de son dossier (son native.json répertorie le SHA-256 de l'archive de la même manière façon; vérifie-le avec sha256sum):

tar -xzf starhermit-1.27.0-linux-x86_64.tar.gz
./starhermit-1.27.0-linux-x86_64/starhermit --version

--version, new, types, check et package besoin de rien de plus. Pour jouer à un jeu dans une fenêtre, le le runtime nécessite Wayland ou X11 avec les pilotes Vulkan ou OpenGL ES 3.0, et ALSA ou PulseAudio pour le son ; native.json's requires répertorie toutes les bibliothèques qu'il utilise. Les joueurs jouent toujours aux téléchargements natifs dans le Client Windows StarHermit ; le runtime Linux est destiné à l'écriture, à la vérification et à l'empaquetage de jeux.

Les commandes ci-dessous sont écrites comme starhermit; exécutez-les comme .\starhermit.exe (Windows) ou ./starhermit (Linux) à partir de ce dossier, ou ajoutez le dossier à votre PATH.

3. Créez le jeu

starhermit new star-catcher --title "Star Catcher"

Created Star Catcher in star-catcher: a script game pinned to engine 1.27.0
Play it: starhermit star-catcher
Check it: starhermit check star-catcher
For a native upload (the StarHermit client plays it): starhermit package --native star-catcher
For the web: starhermit package --web star-catcher --out <upload>

Le nouveau dossier contient un point de départ jouable : un cube qui saute lorsque vous appuyez sur Espace :

star-catcher/
  starhermit.txt             the manifest, pinned to the runtime's own release (engine.version=1.27.0)
  tsconfig.json              TypeScript settings for checking the game
  src/main.ts                the entry module
  .starhermit/starhermit.d.ts  the host API's declarations, for your editor and the type checker

.starhermit/ commence par un point, il ne fait donc jamais partie du package. starhermit types star-catcher réécrit les déclarations, par exemple après avoir migré vers une version plus récente exécution. Chaque module, membre, unité, limite et erreur de l'API hôte est documenté dans ce fichier.

Le runtime ne vérifie pas le type : il supprime les types de TypeScript lors du chargement de chaque module. Vérifiez-les vous-même avec TypeScript 5 ou version ultérieure ; avec Node.js installé, npx l'exécute sans installer tout ce qui se trouve dans le dossier du jeu :

cd star-catcher
npx --package typescript tsc -p .

Les fichiers de développement restent en dehors du package : les noms de points (tels que .starhermit/ et .git/), node_modules/, tsconfig.json, jsconfig.json, package.json, npm, fils et fichiers de verrouillage pnpm, cartes sources (*.js.map, *.ts.map et autres) et Thumbs.db/desktop.ini. Tout le reste dans le dossier fait partie du package. Pour en omettre davantage, ajoutez un .starhermitignore à la racine du jeu avec des règles de style gitignore (* et ? dans un nom, ** pour un nombre quelconque de dossiers, une fin / pour un dossier, ! pour conserver un fichier, une règle par défaut est laissée de côté ; la dernière règle de correspondance décide) :

notes/
levels/**/draft-*.json
!package.json

Un jeu qui lit ou importe un fichier oublié échoue avec une erreur nommant la règle, en cours de développement comme eh bien, alors starhermit check l'attrape avant de le télécharger.

4. Écrivez la première version

Remplacer le généré starhermit.txt avec le manifeste du jeu :

name=Star Catcher
description=Catch the falling stars before the time runs out.
launch=index.html
engine.api=1
engine.entry=src/main.ts
engine.version=1.27.0
engine.minor=15
engine.capabilities=platform,storage
control.left=KeyA+ArrowLeft | Move left
control.right=KeyD+ArrowRight | Move right
control.start=Space+Enter | Start a round
engine.gamepad.left=LeftStickLeft+DpadLeft
engine.gamepad.right=LeftStickRight+DpadRight
engine.gamepad.start=South
cache..=0

Le control.* Les lignes déclarent les actions du jeu avec leurs touches par défaut (les touches de la plateforme). contrôles format) et engine.gamepad.* leurs paramètres par défaut de manette de jeu. Les joueurs se relient dans le menu Options du runtime, le jeu lit donc actes, jamais de clés. Un jeu déclare jusqu'à 128 actions : la plateforme conserve les 32 premières avec le compte du joueur, et le runtime conserve les liaisons du reste dans les paramètres synchronisés du lecteur. engine.group.<action>=Heading démarre un groupe à cette action (jusqu'au groupe suivant), que l'écran de contrôle affiche sous le titre, par exemple engine.group.left=Movement (API hôte 1.6). engine.capabilities demande ce que le jeu utilise au-delà du dessin et de la saisie : platform pour le joueur connecté et en ligne fonctionnalités, storage pour les données conservées sur l'appareil et le compte du joueur. launch=index.html nomme le page qui joue au jeu dans les navigateurs, que le moteur écrit lorsque vous publier.

Puis remplacez src/main.ts:

// Star Catcher: catch the falling stars in the basket before the time runs out.
import { frame, onFixedUpdate, onRender, onStart, setFixedRate } from "starhermit:engine";
import {
  AmbientLight,
  BoxGeometry,
  Color,
  DirectionalLight,
  Mesh,
  MeshStandardMaterial,
  PerspectiveCamera,
  SphereGeometry,
  renderer,
  scene,
} from "starhermit:scene";
import { onAction, value } from "starhermit:input";
import { storage } from "starhermit:storage";
import { player } from "starhermit:platform";
import * as draw from "starhermit:draw";

// -- The scene ----------------------------------------------------------------
const camera = new PerspectiveCamera(50, 16 / 9, 0.1, 100);
camera.position.set(0, 4, 12);
camera.lookAt(0, 3, 0);
renderer.camera = camera;
scene.background = new Color(0x0b1020);

const sun = new DirectionalLight(0xfff4e0, 1.2);
sun.position.set(3, 8, 5);
scene.add(sun, sun.target, new AmbientLight(0x6070a0, 0.5));

const basket = new Mesh(new BoxGeometry(2, 0.4, 1), new MeshStandardMaterial({ color: 0x4fa3ff, roughness: 0.4 }));
scene.add(basket);

const starGeometry = new SphereGeometry(0.3, 16, 12);
const starMaterial = new MeshStandardMaterial({ color: 0xffd34d, emissive: 0xffb000, emissiveIntensity: 0.6 });
const stars = Array.from({ length: 3 }, () => {
  const mesh = new Mesh(starGeometry, starMaterial);
  scene.add(mesh);
  return { mesh, x: 0, y: 0, previousY: 0, speed: 0 };
});
type Star = (typeof stars)[number];

// -- The rules ----------------------------------------------------------------
const WIDTH = 6; // the basket moves between -WIDTH and WIDTH
const ROUND = 60; // seconds a round lasts
let basketX = 0;
let previousX = 0;
let score = 0;
let timeLeft = 0; // 0 between rounds
const saved = storage.getJson("best");
let best = typeof saved === "number" ? saved : 0;

function drop(star: Star): void {
  star.x = (Math.random() * 2 - 1) * WIDTH;
  star.y = star.previousY = 8 + Math.random() * 4;
  star.speed = 2 + Math.random() * 2 + score * 0.05;
}

onStart(() => {
  setFixedRate(60);
  for (const star of stars) drop(star);
});

onAction((event) => {
  if (event.action === "start" && event.pressed && timeLeft === 0) {
    score = 0;
    timeLeft = ROUND;
    for (const star of stars) drop(star);
  }
});

onFixedUpdate((step) => {
  previousX = basketX;
  for (const star of stars) star.previousY = star.y;
  if (timeLeft === 0) return;
  // An action's value is 0 to 1, so a stick steers gently and a key fully.
  const steer = value("right") - value("left");
  basketX = Math.max(-WIDTH, Math.min(WIDTH, basketX + steer * 9 * step));
  for (const star of stars) {
    star.y -= star.speed * step;
    if (star.y < 0.6 && star.y > 0 && Math.abs(star.x - basketX) < 1.2) {
      score += 1;
      drop(star);
    } else if (star.y < -1) {
      drop(star);
    }
  }
  timeLeft = Math.max(0, timeLeft - step);
  if (timeLeft === 0 && score > best) {
    best = score;
    storage.setJson("best", best);
  }
});

// -- Drawing ------------------------------------------------------------------
onRender((alpha) => {
  // Between two fixed steps: draw where things are at this moment.
  basket.position.set(previousX + (basketX - previousX) * alpha, 0.2, 0);
  for (const star of stars) {
    star.mesh.position.set(star.x, star.previousY + (star.y - star.previousY) * alpha, 0);
  }
  hud();
});

function hud(): void {
  const { width, height, scale } = frame();
  const size = 22 * scale;
  const name = player()?.displayName ?? "Guest";
  draw.text(`${name}   score ${score}   best ${best}`, 16 * scale, 16 * scale, { size, color: "#e8ecf4" });
  if (timeLeft > 0) {
    draw.text(`${Math.ceil(timeLeft)} s`, width - 16 * scale, 16 * scale, { size, color: "#ffd34d", align: "end" });
  } else {
    draw.rect(0, height / 2 - 40 * scale, width, 80 * scale, [0, 0, 0, 0.5]);
    draw.text("Press Space to play", width / 2, height / 2 - 12 * scale, { size, color: "#ffffff", align: "center" });
  }
}

Ce que fait chaque partie :

  • La scène. starhermit:scene suit three.js : une caméra, des lumières, des maillages constitués d'une géométrie et un matériau, scene.add. Les distances sont en mètres, les angles en radians et les couleurs sRGB.
  • Les règles. onFixedUpdate fonctionne au tarif fixe setFixedRate(60) demande, 60 fois par seconde quelle que soit la fréquence d'images, le jeu se déroule donc de la même manière sur chaque machine. value("right") est la valeur de l'action de 0 à 1, donc un manche de manette de jeu se dirige doucement et une touche se dirige complètement, et onAction entend chaque pression, ici pour commencer un tour.
  • Dessin. onRender s'exécute une fois par image avec alpha, à quelle distance se trouve le cadre entre les deux derniers marches fixes; positions tirées entre previous et les valeurs actuelles se déplacent en douceur à chaque actualisation taux. starhermit:draw dessine le HUD sur la scène en pixels de la fenêtre ; frame().scale convertit pixels logiques pour les écrans haute résolution.
  • La meilleure note reste sur l'appareil du joueur pendant starhermit:storage, tenu à l'écart pendant chaque joueur.

Alors jouez-y :

Appuyez sur Espace pour démarrer une partie et sur les touches fléchées (ou A et D, ou une manette de jeu) pour diriger. F1 toujours ouvre le propre menu du runtime : graphiques, audio, contrôles (rebinding), le compte et quitter. Votre le jeu ne peut pas parcourir ce menu ni le lire, et aucun jeu ne peut lier la F1.

Sa page Graphiques propose Auto et dix niveaux, de quantum (un téléphone) via atomic, molecular, cellular, terrestrial, planetary, stellar, galactic et cosmic à infinite (les ordinateurs de bureau les plus rapides). Auto en sélectionne un sur le GPU et un court test de référence en premier temps, ne démarre pas plus haut que stellar et se retire lorsque les images sont en retard. Votre jeu lit le niveau avec frame().level et ses budgets avec levelSettings() (API hôte 1.14, donc engine.minor=14); frame().quality donne toujours low, balanced, high ou ultra. Niveaux que l'appareil ne peut pas exécuter (depuis la plus grande taille de texture de son GPU ; les téléphones, tablettes et appareils de 4 Gio s'arrêtent à cellular) montrer handicapé avec la raison, et frame().levelCeiling donne le plus haut possible : un jeu qui tire le sien Le menu graphique désactive les niveaux supérieurs (ui.select les options prennent disabled et description).

Lors du développement, ajoutez --dev (starhermit star-catcher --dev) : le runtime imprime ensuite le fichier du jeu console sortie sous la même forme et signale les erreurs sur vos lignes TypeScript.

6. Plusieurs choses à la fois : starhermit:world

Nativement, le TypeScript de votre jeu s'exécute dans le propre interpréteur de script du moteur, qui conserve chaque jeu dans ses budgets temps et mémoire ; dans les navigateurs, il s'exécute dans le moteur JavaScript du navigateur, dans un travailleur, la page peut s'arrêter. Les décisions et quelques dizaines d'objets y coûtent peu, mais à l'unité le travail – déplacer des milliers de particules, une foule, un troupeau – signifierait des milliers d'étapes interprétées chaque image. Pour cela le moteur a starhermit:world:

  • tableaux conserver les données d'entité dans des colonnes saisies (nombres et vecteurs) dans la mémoire du jeu ;
  • graines sont des fonctions ordinaires d'une ligne que le runtime compile et exécute de manière native chaque ligne d'un tableau, sans entrer de script ;
  • le calendrier exécute les noyaux à chaque image, et reliures dessiner une table comme une seule InstancedMesh (ou piloter des nœuds de scène), composant chaque instance de manière native.

Votre script prend les décisions ; le moteur d'exécution effectue l'arithmétique par ligne. Ajoutez un ciel nocturne de 4 000 des étincelles scintillantes derrière le jeu alors que src/sky.ts:

// The night sky behind the game: 4,000 twinkling sparkles. Their data lives
// in a starhermit:world table, a kernel moves every one of them natively each
// frame, and an instance binding draws the table as one InstancedMesh, so the
// game's script runs no per-sparkle code at all.
import { InstancedMesh, MeshBasicMaterial, SphereGeometry, scene } from "starhermit:scene";
import { bind, kernel, schedule, table } from "starhermit:world";

const COUNT = 4_000;

// One row per sparkle: where it hangs, how it twinkles, and what the kernel
// writes each frame (its height and size).
const sky = table("sky", COUNT, {
  base: "vec3",
  phase: "f32",
  rate: "f32",
  y: "f32",
  size: "f32",
});
sky.spawn(COUNT);

// Filled once from script, through typed arrays over the table's memory.
const base = sky.column("base");
const phase = sky.column("phase");
const rate = sky.column("rate");
for (let i = 0; i < COUNT; i++) {
  base[i * 3] = (Math.random() * 2 - 1) * 40;
  base[i * 3 + 1] = Math.random() * 24 - 2;
  base[i * 3 + 2] = -10 - Math.random() * 30;
  phase[i] = Math.random() * Math.PI * 2;
  rate[i] = 0.5 + Math.random() * 2;
}

// An ordinary function of one row. The runtime compiles it and runs it over
// every live row without entering script.
const twinkle = kernel(sky, (r, u: { drift: number }, f) => {
  r.y = r.base.y + Math.sin(f.time * u.drift + r.phase) * 0.3;
  r.size = 0.04 + 0.04 * Math.abs(Math.sin(f.time * r.rate + r.phase));
});

const mesh = new InstancedMesh(new SphereGeometry(1, 6, 4), new MeshBasicMaterial({ color: 0xcfd8ff }), COUNT);
scene.add(mesh);

/** Starts the sky: the kernel runs after every onUpdate, and the binding
 * composes the mesh's instances from the columns after every onRender. */
export function startSky(): void {
  schedule.update(twinkle, { drift: 0.4 });
  bind.instances(mesh, sky, { position: ["base.x", "y", "base.z"], scale: "size" });
}

et démarrez-le à partir de src/main.ts: importez-le avec les autres importations, et appelez-le onStart:

import { startSky } from "./sky.js";

onStart(() => {
  setFixedRate(60);
  startSky();
  for (const star of stars) drop(star);
});

Les noms d'importation ./sky.js, convention de TypeScript pour un module écrit comme sky.ts; le temps d'exécution le résout de la même manière. Les noyaux acceptent un sous-ensemble du langage : les nombres et les booléens, l'arithmétique, Math, if, délimité for les boucles, les colonnes de la ligne et les uniformes que vous transmettez - et le temps d'exécution rejette toute autre chose avec un SyntaxError sur la ligne du noyau lors de sa compilation, plutôt que exécutez-le lentement. Les déclarations de starhermit:world décrire le sous-ensemble, les files d'attente d'événements qui les noyaux émettent vers, des tables avec un historique pour un mouvement fluide à étapes fixes et des liaisons de nœuds.

7. Joueurs, sauvegardes et jeu en ligne

Le joueur. player() depuis starhermit:platform est le joueur connecté, ou null pour un invité; Star Catcher affiche son nom dans son HUD. Lorsque le client StarHermit Windows démarre votre jeu, le joueur est connecté dès la première image, avec le compte du client : le client remet le exécute un jeton de lancement pour votre jeu sur une chaîne privée, le renouvelle pendant l'exécution du jeu et le le jeu ne le voit jamais (aucun appel hôte ne renvoie un jeton, une clé ou un cookie). Les joueurs ne se connectent jamais à l'intérieur d'un jeu; la connexion et la déconnexion se produisent dans le client.

Dans les navigateurs la plateforme ouvre la page du jeu avec un jeton de lancement de votre jeu, que le le moteur extrait l'adresse de la page avant que votre code ne s'exécute et se renouvelle dans les 12 heures de la plateforme limite; votre jeu ne voit que player(), exactement comme nativement. Un invité qui choisit Se connecter dans le La boîte de dialogue Compte du runtime accède à la propre page de connexion de StarHermit et revient connecté. Voice utilise le le microphone du navigateur après l'invite d'autorisation du navigateur.

Le développement s'exécute. Démarré depuis un terminal, un package ne peut pas revendiquer à lui seul une identité de plateforme, donc starhermit star-catcher joue en tant qu'invité. Une fois votre jeu publié, un lancement de développement le nomme :

starhermit star-catcher --game <your game's id>

et vous vous connectez via F1 → Compte…, la boîte de dialogue propre au runtime (une clé sur cet ordinateur et une confirmation par courrier électronique, comme dans intégration à clé publique). Stockage, paramètres, sauvegardes et jeu en ligne, puis suivez ce jeu et ce compte.

9. Passer à un moteur plus récent

Un jeu fonctionne exactement sur la version qu'il épingle : rien ne le met à niveau dans votre dos, et une version publiée la version ne change jamais. Pour passer à un jeu plus récent, téléchargez son runtime, exécutez votre jeu et ses vérifications dessus, puis réépinglez en changeant engine.version dans starhermit.txt, emballez à nouveau et publiez. Les clients des joueurs téléchargent le nouveau moteur une fois (uniquement ce qui a changé par rapport aux versions qu'ils ont déjà téléchargées). maintenez) et les fichiers modifiés de votre jeu.

La version majeure de la version est celle de l'API hôte : engine.api=1 les jeux se déplacent librement dans 1.x.x. Un jeu qui nécessite que les membres de l'API hôte soient ajoutés dans une version mineure peuvent le dire avec engine.minor=N; un plus âgé le runtime le refuse ensuite avec un message au lieu d'échouer plus tard.

Une version jugée dangereuse est révoqué: versions.json le marque avec le raison, le client refuse de l'installer ou de le démarrer (et explique au joueur pourquoi), et l'emballage les commandes le refusent à chaque fois qu'elles lisent versions.json. Une version révoquée est toujours suivie d'une version corrigée ; ré-épinglez-y et publiez-le.

10. Limites et licence

Nativement, le JavaScript du jeu s'exécute sur un interpréteur sans JIT, bien en dessous de la vitesse du navigateur ; voir Performances natives pour les jeux de script avant d'écrire du code lourd par image.

Le runtime maintient chaque jeu dans les limites des budgets, qu'un package peut réduire avec engine.limits.* mais ne jamais augmenter, sauf son budget image : engine.limits.image_mib (API hôte 1.9) augmente la valeur par défaut de 56 Mio à 512 Mio, dans gpu_mib. Le temps de script est mesuré nativement en instructions d'une machine de référence (carburant); les navigateurs n'ont pas de carburant mais pareil "ne répond pas" limites :

Phase Carburant "Ne répond pas" après
Évaluation du module (code de portée module de l'entrée et de ses importations) 60 s en tout ; il ne peut pas faire de pause 9 s, avec onStart
onStart et ses promesses d'emplois 256 ms par tranche (8 × fuel_ms) 9 s, avec évaluation du module
Un cadre : événements, timers, onFixedUpdate, onUpdate, onRender, promets des emplois 32 ms par appel (fuel_ms) 3 s pour tout le cadre
onSuspend, onResume 32 ms 3 s

Un appel qui consomme son carburant est mis en pause et non terminé : il continue sur les images suivantes pendant que le jeu n'apporte rien de nouveau. Une fois qu'une phase dépasse sa limite, le temps d'exécution "ne répond pas" l'écran permet au le joueur attend ou arrête le jeu (60 s pendant que le jeu a appelé) engine.setBusy, ou tant qu'il demande avec setBusy(label, { seconds }), jusqu'à 600 s, avec engine.minor=14; un appel dure le plus longtemps allocation qu'il a demandée, et une allocation plus courte compte à partir du prochain appel). Une erreur pour les noms d'heure la phase, le temps d'exécution et la limite, par exemple module evaluation of src/main.ts ran past its time budget (it ran 61234 ms; the limit is 60000 ms); la limite de l'évaluation du module est le temps sur l'horloge, les autres sont comptés dans les instructions de la machine de référence. Tranche long travail sur les images (fuelLeft() dit ce qui reste du carburant de cet appel), ou l'annoncer avec setBusy.

Les autres limites : un tas de script de 256 Mo et 1 024 call frames, 64 Mo de stockage, des canevas d'au plus 4 096 pixels par côté et 8 388 608 pixels (4 096 × 2 048), 128 actions, BigInts d'au plus 220 des morceaux, au maximum 512 Mio et 65 536 fichiers dans un package et, pour les téléchargements, les 50 Mio et 9 998 chemins de la plateforme (un jeu la plateforme permet plus de passes --max-upload-mib et --max-upload-paths à l'emballage commandes, ou --game-id lire ses limites). Les ressources volumineuses peuvent ne pas être téléchargées car fichiers distants: engine.remote.files= et engine.remote.urls= dans starhermit.txt nommer les fichiers que vos propres hôtes HTTPS servent (ou engine.remote.urls=platform: StarHermit les sert, et cargo starhermit publish les télécharge), les commandes d'empaquetage épinglent chacune par taille et SHA-256, et le runtime les récupère et les vérifie (files.fetch dans starhermit:engine; voir les déclarations de l'API hôte). Une grande scène peut repousser ses limites starhermit.txt (API hôte 1.14, donc engine.minor=14): engine.limits.mesh_mib (par défaut 124, jusqu'à 1 536), engine.limits.meshes (1 008, jusqu'à 4 096), engine.limits.instanced_meshes (1 024, jusqu'à 4 096) et, nativement, engine.limits.heap_mib (256, jusqu'à 1 024 ; les navigateurs ne limitent pas le tas). Les maillages et les images restent ensemble engine.limits.gpu_mib (2 Gio), et les limites élevées jusqu'à leurs plafonds sont destinées aux ordinateurs de bureau : un maillage complet Le budget prend également environ deux fois sa taille dans la mémoire principale, soit un tas complet environ 1,2 fois. engine.budgets() et game.limits signaler ce qui s'applique, et le RangeError pour un budget complet, nomme la clé qui le fait monter. Une trame envoie au maximum 96 Mio de nouveaux maillages et images au GPU ; quel jeu fait passé qui attend et passe en revue les images suivantes, premier entré, premier sorti, et les objets sont dessinés une fois que leur maillage et leurs images ont été créés. arrivé (engine.usage().waitingUploads et waitingUploadBytes lire 0 quand tout est envoyé, hôte API 1.15), un niveau peut donc être construit dans un seul cadre. Avec engine.minor=15 les tableaux typés compacts restent compact sur le GPU et dans le budget : se positionne comme un Int16Array, normales comme normalisées Int8Array, les couleurs comme normalisées Uint8Array et les UV en tant que valeur normalisée Uint16Array prendre 16 octets par le sommet où les flotteurs prennent 48 ; omettez l'index d'un maillage ombré à plat ; et une géométrie sans attributs dessinés avec setDrawRange(0, N) et un boundingSphere donne un crochet de sommet N sommets pour rien (herbe, particules). Différences natives et navigateur

Nativement votre code s'exécute dans l'interpréteur du moteur, dans les navigateurs dans le moteur JavaScript du navigateur (V8 dans Chrome et Edge). Les deux sont strictement ECMAScript 2022, BigInt inclus et starhermit check lance le jeu de manière native et relie ses modules au fur et à mesure que les navigateurs les obtiennent. Ce qui diffère encore :

  • Modules qui s'importent les uns les autres. Dans les navigateurs, une importation lue avant l'exécution de son module est undefined; check échoue lors d'une telle lecture dans le code de niveau supérieur d'un module (lisez-le dans une fonction à la place). export * from un module d'un tel cycle échoue check: nommez les exportations. UN let réexporté depuis un module d'un cycle est une copie dans les navigateurs, donc les affectations ultérieures ne sont pas visibles à travers lui : importez-le depuis son propre module.
  • Chargement. import() a besoin d'une chaîne littérale (check échoue sur un spécificateur calculé).
  • Code à partir de chaînes. eval échoue la charge de manière native ; new Function(...) jette un EvalError sur les deux.
  • Scripts classiques. Un fichier starhermit:script s'exécute comme un script classique (loadClassic, sandbox, authority, worker) sans un "use strict" La directive, en dehors des classes, suit le mode bâclé comme dans les navigateurs et sur la plateforme : attribuer un nom non déclaré crée un global (la lecture en jette encore) ; this dans un la fonction appelée sans un est globalThis et un primitif this est encadré ; delete name réponses true ou false; une fonction peut répéter un nom de paramètre (pas une flèche ou une méthode) ; arguments.callee est le fonction ; une mission échouée est ignorée et une mission refusée delete est false. Toujours strict nativement : héritage octal (010, "\07") et with échoue le chargement, une fonction déclarée dans un bloc n'est visible que dans ce bloquer, et arguments ne suit pas les écritures dans les paramètres (ni eux). Commencez ces fichiers avec "use strict" se comporter de la même manière partout.
  • Seuls les navigateurs intégrés ont: Proxy, WeakRef, FinalizationRegistry, Atomics, structuredClone, les assistants de l'itérateur, Array.fromAsync, le nouveau Set méthodes, le travailleur globales (self, crypto, atob, URL, WebAssembly, …) et certains de Intl (ListFormat, Segmenter, DisplayNames, Locale). check avertit de chaque utilisation avec son fichier et sa ligne ; typeof les tests sont bien.
  • Expressions régulières. Le v le drapeau et l'héritage RegExp.$1 les statistiques sont réservées au navigateur.
  • Dates. L'heure locale native est UTC (getTimezoneOffset() est 0); les navigateurs utilisent le temps du joueur zone. Formater les heures de l'horloge murale avec timeZone: "UTC" pour afficher la même chose sur les deux.
  • Limites. Nativement, une chaîne contient au maximum 228 − 16 unités de code, un tableau 226 éléments et un BigInt 220 bits (plus dans les navigateurs) ; un débordement de pile met plutôt fin nativement au jeu que de lancer un capturable RangeError. Math.random les séquences diffèrent.
  • Début audio. Dans les navigateurs, l'audio attend la première pression du lecteur : d'ici là context.state est "suspended" et currentTime reste immobile, alors c'est "running" et statechange les incendies. Nativement c'est "running" dès le début.
  • Paramètres par défaut du navigateur. Pendant que le jeu s'exécute, sa page conserve le menu contextuel du navigateur, le texte sélection, copier-coller, fichiers déposés et raccourcis tels que Ctrl+S, Ctrl+F, zoom et menu Alt de la barre du jeu, et une touche liée à votre jeu l'atteint également avec Ctrl, Alt ou Cmd. F11, F12, rechargez et les touches de tabulation du navigateur fonctionnent toujours, et les champs de texte restent collés.
  • Clôture. onQuit s'exécute une fois, après la frame en cours (et après onSuspend si la fenêtre ou l'onglet a été masqué en premier). Ce à quoi il écrit storage et settings est conservé, et son saves.save, la copie des paramètres du compte et les appels de sa plateforme s'éteignent à la fermeture du jeu (leurs réponses n'atteignent personne). Nativement, il en a une seconde et il en télécharge jusqu'à trois de plus ; dans navigateurs une page qui disparaît (un onglet fermé, un rechargement, un lien suivi) attend 0,2 s, pour les jeux avec le storage capacité ou un lecteur connecté, et envoie au maximum 16 requêtes avec 64 Ko de corps en tout : une sauvegarde plus importante est téléchargée lors de la prochaine session. Safari arrête le jeu avant que la page n'apprenne qu'il s'en va, donc là onQuit ne s'exécute pas sur un onglet fermé ou un lien suivi : conserve ce qui doit être enregistré en dernier lieu au fur et à mesure de ses modifications, ou dans onSuspend. Une page que le navigateur renvoie à partir de son cache arrière/suivant se charge à nouveau, et le jeu recommence avec ce qu’il a stocké.
  • Valeurs de l'API hôte. Aucune API hôte ne prend un BigInt, et JSON.stringify en refuse un (TypeError) : convertir avec Number(x) ou String(x) avant de le sauvegarder ou de le transmettre.
