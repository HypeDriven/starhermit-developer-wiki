Exemple de jeu : comment Football utilise le moteur StarHermit

StarHermite Football est un public, complet jeu de scénario. C'est du football 3D en temps réel pour 1 à 22 joueurs, avec des coéquipiers IA, un projecteur éclairé stade, lobbies en ligne, chat vocal et textuel, rediffusions, classement, réalisations et neuf langues. Cette page le démonte étape par étape pour montrer comment un vrai jeu utilise le moteur. Chacun Cette étape nomme les modules du moteur impliqués et renvoie à la source du jeu, où vous pouvez lire le code complet.

Cette procédure pas à pas est écrite pour le moteur 1.41.0, la dernière version. Chaque appel affiché est répertorié dans le référence de l'API du moteur. Lire le tutoriel moteur d'abord si vous n'avez pas encore construit de jeu de script.

Les liens sources pointent vers la validation 33bd9bd. À ce moment-là, le jeu épingle le moteur 1.39.0 avec engine.minor=39. Il n'utilise rien de plus récent, donc fonctionne inchangé sur 1.41.0 ; le déplacer est un changement d'une seule ligne vers engine.version (voir étape 12).

La forme du jeu

Chemin Rôle
starhermit.txt Le manifeste : nom, code PIN du moteur, script du serveur, contrôles, fonctionnalités
server.js La simulation de match unique : exécutée par la plateforme en tant que serveur faisant autorité et chargée par le client pour la pratique et la prédiction hors ligne
engine/src/main.ts Le module d'entrée : les rappels du cycle de vie et la machine à états des écrans
engine/src/match.ts, logic/ Flux de correspondance, netcode, interpolation et prédiction
engine/src/world/ Le stade, les footballeurs, le ballon et la foule dans la scène 3D
engine/src/screens/, hud.ts Menus (starhermit:ui) et le HUD en match (starhermit:draw)
engine/src/net.ts, platform.ts, chat.ts, voice.ts Tout ce qui parle à la plateforme StarHermit
engine/src/audio.ts, i18n.ts, quality.ts Niveaux sonores, langues et graphiques
assets/, sfx/ Les images, les tables de cordes et les extraits sonores

1. Le manifeste

starhermit.txt fait du dossier un jeu de script, et déclare également le script du serveur et les contrôles :

name=Football
launch=index.html
server=server.js
control.up=KeyW+ArrowUp | Run forward
control.shoot=Space+KeyJ | Shoot (hold) / tap to pass
control.tackle=KeyK | Slide tackle / pressure
engine.api=1
engine.entry=engine/src/main.ts
engine.version=1.39.0
engine.minor=39
engine.capabilities=platform,voice,clipboard,storage
engine.gamepad.shoot=West+RightTrigger
engine.gamepad.pass=South
  • launch=index.html est la page du chargeur qui starhermit package --web écrit. Il joue le jeu dans les navigateurs sur le runtime Web de la version épinglée.
  • server=server.js est le script de correspondance faisant autorité sur la plateforme (étape 6).
  • control.* et engine.gamepad.* les lignes définissent actes. Le runtime leur associe des touches et des pads, et les joueurs les relient dans le menu Options du runtime. Le jeu ne nomme jamais de clé de gameplay.
  • engine.capabilities demande la plateforme (rooms, sockets, classements, replays, chat), la voix, le presse-papiers (liens d'invitation) et le stockage (paramètres). Le runtime refuse les appels en dehors d’eux.

La liste complète des clés est dans le starhermit.txt manifeste.

2. Le module d'entrée et la boucle de trame

engine/src/main.ts configure le moteur de rendu au niveau du module, puis enregistre les quatre rappels du cycle de vie de starhermit:engine:

import { frame, onFixedUpdate, onRender, onStart, onUpdate, setFixedRate } from "starhermit:engine";
import { ACESFilmicToneMapping, PCFSoftShadowMap, PerspectiveCamera, renderer, scene } from "starhermit:scene";

const camera = new PerspectiveCamera(55, 16 / 9, 0.1, 800);
renderer.camera = camera;
renderer.shadowMap.enabled = true;
renderer.shadowMap.type = PCFSoftShadowMap;
renderer.toneMapping = ACESFilmicToneMapping;

onStart(() => {
  setFixedRate(60);
  loadLanguages(); // string tables (step 10)
  sim();           // evaluate server.js once (step 6)
  menuScene.start(); // an AI-vs-AI match behind the menu
  // … platform listeners, settings listeners, invite polling
});

onFixedUpdate((step) => {
  if (match) match.fixedStep(step);
  else if (!replay) menuScene.fixedStep(step);
});

onUpdate((delta) => {
  pollQuality();
  if (match) match.update(Math.min(delta, 0.1));
  // … replay viewer or menu backdrop
});

onRender(() => {
  const fr = frame();
  if (Math.abs(camera.aspect - fr.width / fr.height) > 1e-6) {
    camera.aspect = fr.width / fr.height;
    camera.updateProjectionMatrix();
  }
  hud.draw();
  // … chat, in-match menu or the menu screens
});

Le motif à copier :

  • La simulation s'exécute onFixedUpdate, à une fréquence fixe de 60 Hz.
  • La logique par image s'exécute dans onUpdate, avec delta plafonné pour qu'un cadre bloqué ne fasse pas les joueurs sautent.
  • Le dessin s'exécute onRender. Il n'y a qu'un seul rappel de chaque rappel, donc main.ts les fans vers le écran actuel : menu, lobby, match, replay ou résultat.

3. Le monde 3D : starhermit:scene

Le stade, les footballeurs, le ballon et les officiels sont des objets ordinaires de style three.js provenant de starhermit:scene: Mesh, Group, MeshStandardMaterial, CylinderGeometry, Sprite, CanvasTexture et ainsi de suite. Le code porté depuis three.js fonctionne principalement inchangé. Quelques détails à lire :

  • world/stadium.ts construit le terrain, les tribunes, les projecteurs et le brouillard. Il définit les post-effets (renderer.bloom, renderer.grade, renderer.antialias) et des ombres pour chaque niveau graphique.
  • world/environment.ts réalise une carte de l'environnement avec PMREMGenerator d'un DataTexture.
  • world/crest.ts et world/nametags.ts dessinez les écussons des équipes et les surnoms flottants sur un starhermit:canvas OffscreenCanvas, puis utilisez-les comme CanvasTexturesable Sprites.

4. Des milliers de pièces mobiles : starhermit:world

Animer 22 footballeurs joint par joint, ainsi que des milliers de spectateurs, serait trop lent car script par objet sur l'interpréteur natif. Le football évolue starhermit:world tableaux (lignes de colonnes tapées) et graines (fonctions que le runtime s'exécute sur chaque ligne de manière native) :

import { kernel, schedule, table } from "starhermit:world";

const crowd = table("crowd", CROWD_ROWS, {
  bx: "f32", by: "f32", bz: "f32", ph: "f32", fr: "f32", av: "f32",
  q: "quat", s: "f32", sy: "f32", x: "f32", y: "f32", z: "f32",
});
const sway = kernel(crowd, (r, u: { t: number; amp: number; spd: number; sway: number; shake: number }) => {
  const j = Math.sin(u.t * u.spd * r.fr + r.ph);
  r.y = r.by + (j > 0 ? j * j : 0) * u.amp * r.av;
  // …
});
// An eighth of the crowd each frame: the work is sliced across frames.
const swayRun = schedule.update(sway, { t: 0, amp: 0, spd: 0, sway: 0, shake: 0 }, { slices: 8 });

Le footballeur s'installe world/rig.ts utilisez la même approche. UN rigs la table contient l'état d'animation de chaque footballeur. UN joints tableau, avec un ref:rigs colonne, contient 15 joints par plate-forme, et reliures en chasser les nœuds de scène. Deux noyaux programmés après onUpdate calcule les poses et le runtime écrit le nœud se transforme. Le travail de script par footballeur représente environ une douzaine de chiffres par image.

5. Saisie : actions, toucher et manettes de jeu

engine/src/input.ts lit les actions du manifeste à travers starhermit:input:

  • value(action) renvoie jusqu'où une action est maintenue (le mouvement est value("up") - value("down")). onAction fournit des bords de presse et de libération.
  • Utilisations du look souris requestPointerLock, onPointerDelta et onPointerLockChange. La caméra le stick droit vient de gamepads(), et vibrate donne un court tick haptique.
  • Sur les écrans tactiles (primaryPointer() est grossier), setTouchControls montre un joystick et Boutons SHOOT/PASS/TACKLE dessinés par le runtime. Les boutons sont liés aux mêmes actions :
setTouchControls([
  { kind: "stick", up: "up", down: "down", left: "left", right: "right", anchor: "bottom-left", offset: [90, 90], radius: 66 },
  { kind: "button", action: "shoot", label: T("SHOOT").slice(0, 16), anchor: "bottom-right", offset: [66, 66], radius: 46 },
  // … PASS and TACKLE
]);

screens/controls.ts répertorie le courant bindings() et appelle requestRebind. Le runtime capture ensuite la nouvelle clé ou bouton.

6. Une simulation pour le client et le serveur : starhermit:script

server.js est un script classique simple sans importation, Date ou Math.random, comme bac à sable de la plateforme nécessite. Il définit deux globales :

  • globalThis.game détient les points d'entrée de la plate-forme (createSession, onPlayerMessage, onTick) et déclarations statiques lues au moment de la publication :

    globalThis.game = {
  tickRateHz: 30,
  replays: true,
  achievements: [
    { key: 'debut', name: 'Debut', description: 'Finish your first match.', points: 10 },
    { key: 'hat-trick', name: 'Hat-Trick', description: 'Score three goals in one match.', points: 50 },
    // …
  ],
  createSession: function (ctx) { /* seats, AI, seed from ctx.random */ },
  // …
};

  • globalThis.FootballSim détient la même simulation (createMatch, stepMatch, l'IA) pour le cliente.

Le client charge le même fichier dans son propre domaine avec loadClassic depuis starhermit:script (engine/src/sim.ts):

import { loadClassic } from "starhermit:script";

loadClassic("server.js");
const S = (globalThis as unknown as { FootballSim?: FootballSimApi }).FootballSim;

Étapes de pratique hors ligne FootballSim localement à 60 Hz avec AI dans un siège sur deux. En ligne, le la plate-forme fonctionne server.js avec autorité à 30 Hz. Le jeu ne conserve jamais deux copies de son règles.

7. Matchs en ligne : salles et emplacements de jeu

Les lobbys utilisent les salles de la plateforme à travers starhermit:platform (screens/lobby.ts):

import * as P from "starhermit:platform";

// Quick play: join any open room, or open one.
let room = await P.rooms.quickJoin();
if (!room) {
  room = await P.rooms.create({ teamCount: 2, seatsPerTeam: teamSize, backfillAfterSeconds: 30, metadata: { game: "football" } });
  room = await P.rooms.open(room.id);
}

// Ranked solo vs AI: every other seat is an AI player, so starting begins the match at once.
room = await P.rooms.create({ teamCount: 2, seatsPerTeam: teamSize, backfillAfterSeconds: 30, aiPlayers: 2 * teamSize - 1, metadata: { game: "football" } });
room = await P.rooms.start(room.id);

Les amis, les invitations et les changements de siège passent P.friends.list, P.rooms.invite, P.rooms.acceptInvite et P.rooms.seat. P.rooms.mine permet à un joueur de rejoindre un match qu'il a quitté.

Une fois le match commencé, engine/src/net.ts ouvre la prise de jeu avec P.connectGame(sessionId):

  • Il envoie des entrées à 30 Hz avec sendInput.
  • Il demande un instantané complet avec sendCommand({ type: "sync" }) à chaque ouverture et sur resumed.
  • Il écoute game (instantanés et événements), achievement et stopped. stopped rapporte pourquoi le socket s'est arrêté : déconnecté, conditions mises à jour ou la correspondance a disparu.

Le runtime conserve les informations d'identification du joueur et se reconnecte tout seul, le jeu ne gère donc aucun jeton. et n'a pas de boucle de nouvelle tentative.

logic/interp.ts lisse les instantanés du serveur avec une interpolation adaptative. logic/predict.ts prédit le mouvement du footballeur local et le corrige à chaque instantané. La prédiction affecte seulement ce qui est dessiné ; le serveur reste faisant autorité.

8. Le reste de la plateforme

Fonctionnalité Appels Source

Classement P.leaderboards.list, P.leaderboards.entries (planche déclarée dans leaderboards.json) screens/leaderboard.ts
Réalisations Déclaré dans server.js, décerné à temps plein, répertorié avec P.achievements.list screens/achievements.ts
Rediffusions game.replays: true dans server.js; P.replays.list, P.replays.get screens/replays.ts, replayView.ts
Chat textuel P.sessions.get (la conversation du match), P.chat.messages, P.chat.subscribe, P.chat.post chat.ts

Rapports de bogues P.reportBug screens/settings.ts

Chaque appel peut être rejeté avec un PlatformError. Le football considère les fonctionnalités en ligne comme du meilleur effort : l'échec montre "en ligne indisponible" ou retombe dans le silence et ne termine jamais la partie. Déconnecté, le jeu propose toujours une pratique hors ligne.

9. Menus et HUD : starhermit:ui, starhermit:draw, starhermit:canvas

  • Menus (screens/*.ts, le menu de match et les boîtes de dialogue dans main.ts) utiliser starhermit:ui, l'interface utilisateur en mode immédiat du moteur. Les widgets sont appelés tous les cadre de onRender, et ui.setTheme leur donne les couleurs du jeu. Les propres options du runtime le menu s'ouvre avec openMenu.
  • Le HUD ( hud.ts) dessine le tableau d'affichage, l'horloge et les marqueurs avec starhermit:draw: draw.roundRect, draw.text et draw.image (une toile de crête), en ordre d'appel sur la scène.
  • Images sont chargés de createImageBitmap depuis starhermit:canvas, par exemple l'art clé du menu.

10. Paramètres et langues : starhermit:storage, cordes

  • Les paramètres par joueur (muet, voix, langue, remplacements graphiques) sont disponibles dans settings depuis starhermit:storage. Ils sont conservés sur l'appareil et dans le compte. settings.onChange applique une modification effectuée sur un autre appareil.
  • i18n.ts charges assets/strings.json dans le moteur strings tableaux (strings.load, strings.t, strings.setLanguage). Il choisit la langue parmi le choix enregistré, puis celle du joueur Langue StarHermit, puis celle de l'appareil (preferences). l10n/font.ts charge les polices de script avec FontFace pour les langues qui en ont besoin.

11. Niveaux sonores et graphiques

  • audio.ts construit un graphique Web Audio avec starhermit:audio:
    • Les clips créés sont répertoriés dans sfx/manifest.json (lire avec files.readJson).
    • Un synthétiseur couvre n'importe quel événement sans clip, ainsi que la réverbération de la foule et du stade.
    • Les nœuds de courte durée sont libérés dès leur fin, car le graphe hôte est limité.
  • quality.ts suit le niveau graphique du joueur (frame().level, levelSettings). Ombres, floraison et l'anticrénelage suit ce niveau. Le contenu propre du jeu (détail du pitch, densité de la foule, particules) a des remplacements par joueur en haut.

12. Packager, tester et publier

  • Vérification de type avec tsc -p engine. engine/tsconfig.json inclut la version starhermit.d.ts et des ensembles "lib": ["ES2022"], "types": [] et "allowImportingTsExtensions": true.
  • Test. npm test court server.js tests de régression. engine/tests/run.sh exécute la logique tests (interpolation, prédiction, pose, lobby) sous Node. starhermit <folder> --check valide le package et lit 120 images sans tête.
  • Emballer. starhermit package --web . réécrit index.html et starhermit-files.json, qui s'engagent à chaque changement.
  • Publier. Le jeu est ajouté sur StarHermit à partir de l'URL de son référentiel. La plateforme lit starhermit.txt, court server.js comme script de match et crée le classement à partir de leaderboards.json.

Pour déplacer Football, ou votre propre jeu, vers le moteur 1.41.0 :

  1. Téléchargez le runtime 1.41.0.
  2. Ensemble engine.version=1.41.0.
  3. Exécutez les vérifications et emballez à nouveau.

Augmenter engine.minor à 41 uniquement lorsque vous souhaitez héberger l'API 1.41 nouvelles fonctionnalités.
