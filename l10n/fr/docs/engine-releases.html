Sorties du moteur StarHermit

Le moteur StarHermit - le moteur d'exécution qui joue jeux de scénario - est publié sur ce wiki sous forme de versions versionnées et immuables sous wiki.starhermit.com/engine/. Les jeux épinglent une version exactement avec engine.version dans leur starhermit.txt; la page d'un jeu charge le runtime Web de la version à partir de ici dans le navigateur, le client StarHermit Windows installe le runtime natif de la version et joue le jeu dessus, et les développeurs téléchargent le runtime d'une version à partir d'ici pour construire avec.

Versions

Une libération est X.Y.Z. X est le version majeure de l'API hôte, le engine.api un jeu déclare, donc chaque version 1.x.x est exécutée engine.api=1 jeux; la version enregistre également la version mineure de l'API hôte, qui grandit à mesure que des membres sont ajoutés (un jeu peut en nécessiter un avec engine.minor). Une version publiée ne change jamais : un correctif est la prochaine version.

Libérer API hôte Durées d'exécution Téléchargement pour les développeurs
1.3.0 1.7 Internet ; Windows (x86-64) starhermit-1.3.0-windows-x86_64.zip
1.2.0 1.6 Internet ; Windows (x86-64) starhermit-1.2.0-windows-x86_64.zip
1.1.0 1.4 Internet ; Windows (x86-64) starhermit-1.1.0-windows-x86_64.zip
1.0.0 1.4 Windows (x86-64) ; pas d'exécution Web starhermit-1.0.0-windows-x86_64.zip

versions.json est la liste faisant autorité, la plus récente en premier, et le moteur la propre page de la zone répertorie la même chose.

La documentation décrit toujours la version la plus récente. Les pages ici peuvent être mises en cache jusqu'à dix minutes après la publication d'un communiqué ; versions.json dit quelle version est le plus récent.

Notes de version

1.3.0

API hôte 1.7. Les jeux épinglés sur une version antérieure continuent de fonctionner dessus ; réépinglez pour les utiliser.

  • Des scripts plus rapides et plus simples : l'interpréteur natif conserve les valeurs dans un mot machine et met en cache la propriété recherches, et x | 0, x >>> 0 et les décalages par constantes s'exécutent comme des instructions uniques. Utilisation de jeux riches en objets environ la moitié du tas et la génération de cartes est environ 1,2 à 1,3 fois plus rapide. Un jeu dépassant sa limite de tas est collecté et ses tables rétrécirent avant qu'il ne soit terminé ; STARHERMIT_HEAP_CENSUS=<seconds> avec --dev imprime ce que le le tas tient.
  • Fichiers distants (API hôte 1.7) : engine.remote.files=, engine.remote.urls= et engine.remote.redirects= marquer les fichiers servis par les propres hôtes HTTPS du jeu. Les commandes d'emballage les laissent de côté du téléchargement et épinglez chacun par taille et SHA-256 dans starhermit-remote.json (--remote-out DIR écrit leur objets par hachage). Le runtime les récupère, les vérifie et les met en cache ; files.fetch(paths, onProgress) les rend prêt, files.status(path) indique où se trouve un fichier et les chargeurs récupèrent ce qu'ils chargent.
  • Limites de téléchargement: --max-upload-mib et --max-upload-paths (ou STARHERMIT_MAX_UPLOAD_MIB / _PATHS) dépasser les limites élevées d'un jeu, et avec --game-id les outils lisent les limites signalées par la plateforme.
  • glTF: Mailles Draco-comprimées (KHR_draco_mesh_compression) et KHR_mesh_quantization charger à travers GLTFLoader.
  • Géométrie et matériaux (API hôte 1.7) : BufferAttribute.onUpload supprime les tableaux d'une géométrie du tas une fois qu'ils atteignent le GPU ; compact Int8, Uint8 et Int16 attributs ; quatre vec4 personnalisés par instance (setCustomAt(i, v, slot)); mélange prémultiplié et multiplié ; abattage par boundingSphere et frustumCulled = false. Les couleurs de sommet en dehors de 0 à 1 ne déposent plus un maillage silencieusement.
  • Web: l'effacement de démarrage de la page n'émet plus de tirage vide, donc WebGPU arrête d'avertir d'un sommet zéro compter.

1.2.0

API hôte 1.6. Les jeux épinglés sur 1.1.0 continuent de fonctionner sur 1.1.0 ; réépinglez pour les utiliser.

  • GrosInt nativement, comme dans les navigateurs : 1n << 64n et le reste de ES2022 BigInt (BigInt.asIntN, asUintN, BigInt64Array, BigUint64Array, accesseurs BigInt de DataView). Un BigInt contient au maximum 220 bits de manière native. API hôtes et JSON.stringify refuser les BigInts (TypeError).
  • Modules dans les navigateurs: un module qui importe une liaison et l'exporte à nouveau se charge désormais lorsque le deux modules s'importent (il a échoué avec "L'exportation '…' n'est pas définie dans le module"), tout comme export { x } from et import() dans un tel cycle.
  • starhermit check relie les modules au fur et à mesure que les navigateurs les obtiennent et échoue, avec un fichier et une ligne, où un le navigateur ne chargeait pas le jeu ; met en garde contre les éléments intégrés que seuls les navigateurs possèdent ; imprime le jeu console sortir (--quiet le cache); et échoue à un jeu qui ferait apparaître le "ne répond pas" écran.
  • Budgets-temps: l'évaluation du module a 60 s de carburant (c'était 2 s), TypedArray set et fill ne coûte que ce qu'ils écrivent, et une erreur de temps nomme la phase, la durée de son exécution et la limite. Les budgets par phase sont dans le tutoriel.
  • Jusqu'à 128 actions reconductibles (la plateforme conserve les 32 premiers avec le compte, le runtime garde le reste dans les paramètres synchronisés du lecteur), et engine.group.<action>=Heading les regroupe sur le écran de contrôle.
  • Les packages omettent les fichiers de développement (node_modules/, tsconfig.json, package.json, verrouiller fichiers, mappages sources, …) et quel que soit .starhermitignore listes. package --web --out DIR écrit un téléchargement sans eux ; un index rédigé sur place les répertorie sous "excluded".
  • La page: un fichier modifié après l'empaquetage est nommé sur l'écran d'erreur avec sa liste et taille réelle et SHA-256 ; le chargeur nomme l'icône du jeu (non /favicon.ico demande); un navigateur sans WebGPU ou WebGL 2, on obtient un message clair.
  • Matériaux personnalisés (API hôte 1.6) : jeu WGSL vertex et surface hooks sur les standards, physiques, Lambert et des matériaux de base et un ShaderMaterial, vérifié et mis en bac à sable par le moteur ; un crochet de surface additif MeshBasicMaterial donne de l'éclat.
  • Scènes et outils (API hôte 1.5) : GLTFLoader dans starhermit:scene, engine.setBusy(label) pour un travail long qui ne peut pas être découpé, le script s'accumule engine.stats(), et un profileur d'échantillonnage (STARHERMIT_SAMPLE avec --dev).
  • Des scripts plus rapides : boucles de tableau typé 25 à 30 % plus rapides et Math intégrés calculés en ligne.

1.1.0

Le moteur d'exécution Web : les jeux sont joués dans les navigateurs à partir des fichiers du moteur de ce wiki, épinglés par SRI, avec des informations en ligne. lecture, voix et polices Liberation et DejaVu groupées ; starhermit package --web écrit un dossier pour les navigateurs et le client.

1.0.0

La première version : le runtime Windows (x86-64), sans runtime Web.

La zone moteur

engine/
  versions.json            every release: host API, date, runtimes, revocation
  X.Y.Z/
    native/windows-x86_64/
      native.json          the Windows runtime's files, each with its size, SHA-256 and chunks
      starhermit-X.Y.Z-windows-x86_64.zip
                           the developer download: the same files as one archive
    manifest.json          the web runtime's files, each with its size and sha384
    starhermit.js          the module a game's loader page loads
    starhermit.wasm, *.js  the runtime, its audio mixer and worklets
    starhermit.d.ts        the host API's declarations
    fonts/, licenses/      the runtime's fonts and every licence notice
                           (all of the web runtime only in a release that has one)
  chunks/ab/<sha256>.z     pieces of the native files, shared by every release
  patches/ab/<sha256>.p    binary patches from earlier releases' files

Chaque fichier est publié tel quel (aucun nom de fichier ne commence par _ ou .), et GitHub Pages le sert avec Access-Control-Allow-Origin: *.

versions.json

{
  "format": 2,
  "versions": [
    {
      "api": {"major": 1, "minor": 4},
      "date": "2026-10-20T13:55:50Z",
      "native": {
        "windows-x86_64": {"manifest": "1.1.0/native/windows-x86_64/native.json", "sha256": "<SHA-256 of native.json>"}
      },
      "revoked": false,
      "version": "1.1.0",
      "web": {"manifest": "sha384-<SRI hash of manifest.json>"}
    }
  ]
}

web est {"manifest": "sha384-…"}, le hachage SRI du site Web de la version manifest.json, ou null pour une version sans runtime Web. native épingle chaque plate-forme native.json par son SHA-256. Un la version a été retirée parce qu'elle n'est pas sûre, dit "revoked": true avec un "revokedReason"; c'est le seul le changement qu'une entrée publiée prend jamais.

native.json

native.json répertorie les fichiers du dossier du moteur qu'un client installe - starhermit.exe, release.json (la version de la release, l'API hôte et le launcher protocole dont son runtime parle), LICENSE-engine et les avis des tiers - chacun avec son size, sha256 et chunks. Un morceau est une partie d'un fichier, stocké sous forme compressée avec zlib chunks/<first two hex digits>/<sha256>.z et nommé par le SHA-256 de ses octets non compressés ; les limites des morceaux suivent le contenu, donc un stretch conserve son morceau d'une version à l'autre. Là où il est plus petit, un fichier répertorie également patches à partir du même fichier des versions antérieures ("from": le SHA-256 du fichier précédent). downloads répertorie le téléchargement du développeur avec son size et sha256; les clients ne l'installent jamais. Dans une version avec un environnement d'exécution Web, le dossier natif contient également web-manifest.json, le site web de la version manifeste, de sorte que le développeur télécharge des packages de jeux pour le Web sans réseau.

L'environnement d'exécution Web

Le runtime Web d'une version est constitué des fichiers à côté de son manifest.json, qui répertorie chacun avec son size et sha384 et enregistre la version de la version, l'API hôte et la build. La page de chargement d'un jeu (index.html, écrit par starhermit package --web) n'a pas de script propre : il se charge starhermit.js et manifest.json depuis https://wiki.starhermit.com/engine/X.Y.Z/ avec les hachages SRI, et le moteur récupère tous les autres fichiers dont il a besoin (starhermit.wasm, les worklets audio, les polices) et le vérifie contre le manifeste. La page exécute uniquement le moteur : entrée, menus d'exécution, audio, stockage, session de plate-forme et voix - et le TypeScript du jeu s'exécute dans un travailleur qu'il démarre et peut arrêter.

Le runtime Web regroupe ses propres polices, Liberation 2.1.5 (SIL Open Font License 1.1) et DejaVu Sans 2.37 (licences Bitstream Vera et Arev) ; leurs avis sont dans licenses/ avec les autres.

Intégrité

Une chaîne de hachage couvre chaque octet exécuté par un client :

  1. versions.json (ou l'API de la plateforme ci-dessous) donne le SHA-256 d'une version native.json.
  2. native.json donne le SHA-256 de chaque fichier et celui de chaque morceau.
  3. Le client récupère uniquement les morceaux qu'il ne détient pas déjà, vérifie la taille stockée de chacun, taille gonflée et SHA-256, rassemble chaque fichier, vérifie le SHA-256 du fichier et se déplace ensuite seulement la libération en place. Un correctif est vérifié par rapport à son propre SHA-256 et le fichier corrigé par rapport à celui du fichier ; tout échec retombe sur les morceaux.

Le téléchargement développeur est couvert par la même chaîne jusqu'à son entrée dans downloads. Un navigateur la page de chargement du jeu épingle le moteur d'exécution Web starhermit.js et manifest.json avec des hachages SRI, et le moteur d'exécution vérifie tous les autres fichiers qu'il charge par rapport au manifeste.

Le moteur publie l'API

La plateforme sert la même liste, avec chaque URL sur ce wiki, donc les clients demandent à l'API quel moteur pour récupérer :

GET /api/v1/engine/releases → chaque version, la plus récente en premier :

{"releases": [{
  "version": "1.1.0", "api": {"major": 1, "minor": 4}, "revoked": false, "date": "2026-10-20T13:55:50Z",
  "web": {"base": "https://wiki.starhermit.com/engine/1.1.0/", "manifestIntegrity": "sha384-<SRI hash>"},
  "native": {"windows-x86_64": {
    "manifestUrl": "https://wiki.starhermit.com/engine/1.1.0/native/windows-x86_64/native.json",
    "manifestSha256": "<SHA-256 of native.json>"}}
}]}

GET /api/v1/engine/releases/{version} → une version, ou 404 quand il n'est pas répertorié. Les deux sont anonyme et pouvant être mis en cache (Cache-Control: public, max-age=60 avec un ETag). Une version révoquée porte revokedReason; web est null pour une version sans runtime Web. Alors que la plateforme n'a jamais lu la liste (le wiki inaccessible depuis son lancement) ils répondent 503 avec Retry-After.

Jeux de script sur la plateforme

Quand la racine d'un jeu starhermit.txt déclare engine.version, la plateforme le traite comme un script jeu :

  • chaque publication enregistre la publication du code PIN des fichiers, comme hosting.engineVersion, et définit hosting.deployWarning (également dans la réponse d'un bundle push) lorsque cette version n'est pas répertoriée ou est révoqué. Un avertissement n'arrête jamais une publication.
  • chaque page du jeu hébergé est accompagnée d'une politique de sécurité du contenu qui n'admet que les scripts de ce wiki (et du propre moteur blob: travailleurs), donc le seul code qu'une page de jeu de script peut run est le moteur officiel :
default-src 'self'; script-src https://wiki.starhermit.com 'wasm-unsafe-eval' blob:; worker-src blob:;
connect-src 'self' https://wiki.starhermit.com; img-src 'self' blob: data:; media-src 'self' blob:;
style-src 'self' 'unsafe-inline'; font-src 'self' https://wiki.starhermit.com;
frame-ancestors https://dashboard.starhermit.com; base-uri 'self'; form-action 'none'

Une page d'un jeu de script sans version de navigateur (comme la page simple téléchargée par un jeu Windows uniquement) pour les navigateurs) ne nécessite aucun script et n'est pas affecté.

Révocations

Une version révoquée reste répertoriée afin que les clients puissent expliquer pourquoi ils la refusent : le client StarHermit le fait. ne pas l'installer ou le démarrer et indique au joueur que les commandes d'empaquetage refusent d'empaqueter un jeu pour celui-ci quand ils lisent versions.json, et la plateforme prévient les propriétaires de jeux qui l'épinglent lorsqu'ils publier. Réépinglez la version qui la remplace et publiez à nouveau (voir Passer à un moteur plus récent).
