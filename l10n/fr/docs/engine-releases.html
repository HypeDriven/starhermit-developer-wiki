Sorties du moteur StarHermit

Le moteur StarHermit - le moteur d'exécution qui joue jeux de scénario - est publié sur ce wiki sous forme de versions versionnées et immuables sous wiki.starhermit.com/engine/. Les jeux épinglent une version exactement avec engine.version dans leur starhermit.txt; la page d'un jeu charge le runtime Web de la version à partir de ici dans le navigateur, le client StarHermit Windows installe le runtime natif de la version et joue le jeu dessus, et les développeurs téléchargent le runtime d'une version à partir d'ici pour construire avec.

Outils de développement

Le outils de développement autonomes fournir automatisé édition et développement de jeux de script MCP sur macOS (Apple Silicon et Intel), Linux et Windows. Aucune installation Rust ni accès au référentiel privé n'est nécessaire. Les versions d'outils sont indépendantes du runtime du jeu et des broches du jeu.

Versions

Une libération est X.Y.Z. X est le version majeure de l'API hôte, le engine.api un jeu déclare, donc chaque version 1.x.x est exécutée engine.api=1 jeux; la version enregistre également la version mineure de l'API hôte, qui grandit à mesure que des membres sont ajoutés (un jeu peut en nécessiter un avec engine.minor). Une version publiée ne change jamais : un correctif est la prochaine version.

Notes de version

1.12.0

API hôte 1.15, comme 1.11.0 : code PIN engine.version=1.12.0; rien de nouveau à déclarer, et chaque changement s'applique à chaque jeu.

  • Scripts plus rapides en mode natif sur code réseau branché et appels : conditions avec &&, || et ! sauter sur chacun opérande, plusieurs séquences d'instructions s'exécutent comme une seule (x + y * w, table[i]), et les appels de fonctions simples ignorent le chemin d'appel général de l'interprète. Un passage en hauteur de 1024×768 prend 1,04 s au lieu de 1,37 s ; exécutions de code contenant beaucoup d'objets à peu près comme avant. Les résultats sont les mêmes.
  • Le carburant achète plus de travail: une instruction fusionnée compte pour une, donc le code branché dépense environ 29 % d'unités en moins ; le le taux est inchangé.
  • Messages de socket perdus (natifs): une prise plateforme (les salles, les prises jeu et temps réel, le relais voix) pourrait supprimer un message arrivé lorsque le runtime vérifiait un socket inactif, le plus souvent le premier lors de son ouverture ; cargo starhermit publish --socket puis parfois j'attendais trois minutes.
  • Scripts classiques (loadClassic, sandbox, authority, worker) sans "use strict" ignorer un échec devoir et réponse false pour un refus delete nativement, comme dans les navigateurs, au lieu de lancer.
  • Capture vocale Linux: abandonner une connexion PulseAudio lente n'attend plus jusqu'à 8 s pour son démontage.

1.11.0

API hôte 1.15 : code PIN engine.version=1.11.0; déclarer engine.minor=15 pour les formats de sommets compacts et le nouveaux champs d'utilisation. Tout le reste s'applique à chaque jeu.

  • Les gros cadres n'échouent plus : les maillages et les images qu'une image fait au-delà de 96 Mio attendent et passent sur les images suivantes, premier entré, premier sorti, au lieu de lancer ; les objets se dessinent une fois leur maillage et leurs images arrivées. Chargement du code que les téléchargements par étapes à travers les images peuvent avoir lieu. engine.usage().waitingUploads et waitingUploadBytes (1.15) lire 0 une fois que tout est envoyé.
  • Sommets compacts (1.15) : les positions Int16, les normales Int8 normalisées, les couleurs Uint8 et les UV Uint16 restent compacts sur le GPU et dans le budget de maillage (16 octets par sommet où les flottants en prennent 48) ; la géométrie non indexée dessine sans une liste d'index ; une géométrie sans attributs dessinée avec setDrawRange(0, N) et un boundingSphere donne un crochet de sommet N sommets sans coût de maillage.
  • Aucun problème dû à la perte de ressources: le runtime ne collecte plus les déchets à partir de zéro toutes les 512 scènes ressources (environ 100 ms sur un tas de 240 Mio) ; il libère les ressources abandonnées en étapes courtes, et une création a le budget refuserait d'abord de les récupérer.
  • Scripts plus rapides en mode natif: le code numérique s'exécute environ 1,8 fois plus vite dans l'interpréteur du moteur. Module le budget de l'évaluation est désormais de 60 s par horloge, et le découvert d'un appel occupé à l'intérieur d'un rappel est un temps.
  • Direct3D 12 partage les blocs tampons entre les petits maillages et les tampons d'instance, comme le fait Vulkan (4 096 petits les maillages occupent 1 Mio de mémoire vidéo au lieu de 16 à 256 Mio).
  • Son Linux: une recherche lente de PulseAudio ne retarde plus le repli ALSA au-delà de 2 s.

1.10.0

API hôte 1.14 : code PIN engine.version=1.10.0 et déclarer engine.minor=14 utiliser ce qui est nouveau; jeux sur les anciens les mineurs gardent leur comportement.

  • Dix niveaux graphiques: Options › Les graphiques offrent Auto et quantum, atomic, molecular, cellular, terrestrial, planetary, stellar, galactic, cosmic et infinite, téléphonez au bureau le plus rapide. Automatique en détecte un (GPU, mémoire, un court benchmark), démarre au maximum à stellar et descend sous la charge. Lisez-le avec frame().level, levelIndex et graphics, et les budgets du niveau avec levelSettings(); frame().quality donne toujours les quatre niveaux. Charges faibles, équilibrées, élevées et ultra enregistrées par les joueurs sous forme quantique, moléculaire, terrestre et galactique. Avec engine.minor=14 le niveau limite la taille des cartes d'ombre et les échantillons MSAA.
  • Ce qu'un appareil ne peut pas exécuter est désactivé, pour la raison: niveaux au-dessus de son plafond (frame().levelCeiling), VSync dans les navigateurs, échelle de rendu là où un jeu de script dessine à la taille de la fenêtre, plein écran exclusif sans un commutateur de mode vidéo, des limites d'image au-dessus de l'écran. ui.select les options prennent disabled et description pour vos propres menus. Un choix enregistré sur un appareil plus puissant y est conservé et réutilisé.
  • Musique diffusée: audio.stream(path, options) lit Ogg Opus ou Vorbis pendant qu'il décode, sans clip, à partir de fichiers de package ou de fichiers distants qui sont lus pendant leur téléchargement (chaque élément de 256 Ko vérifié) et restent mis en cache pour une lecture hors ligne. Au maximum 4 à la fois. Reconditionnez un jeu avec des fichiers Ogg distants afin que son index répertorie les morceaux.
  • Des scènes plus grandes: augmenter engine.limits.mesh_mib (124 Mio debout, jusqu'à 1 536), engine.limits.meshes (1 008, jusqu'à 4 096), engine.limits.instanced_meshes (1 024, jusqu'à 4 096) et, nativement, engine.limits.heap_mib (256, jusqu'à 1 024), dans gpu_mib. Les maillages de moins de 65 536 sommets sont téléchargés en 16 bits indices et compter sur ce qu'ils téléchargent. Le collecteur fonctionne désormais par étapes courtes (le pire la pause est passée d'environ 110 à 20 ms), et un appareil qui ne peut pas donner de mémoire met fin au jeu comme étant hors script mémoire plutôt que de planter.
  • Chargement plus long: setBusy(label, { seconds }) demande jusqu'à 600 s avant que l'écran ne réponde ; un l'appel conserve l'allocation la plus longue qu'il a demandée, et une allocation plus courte compte à partir de l'appel suivant.
  • Quoi onQuit les sauvegardes s'éteignent: c'est saves.save, les paramètres du compte et les écritures des appels de plateforme sont envoyé à la fermeture du jeu, nativement et dans les navigateurs (où la page envoie au maximum 16 requêtes et 64 Ko avec keepalive; une sauvegarde plus grande télécharge la prochaine session).

Le runtime Windows est construit à partir du moteur a5ba81ec, le même code que le commit de la version (7e778bf3) mais pour diagnostics : l'analyse d'apprentissage automatique de Microsoft Defender a signalé les versions de la validation de version comme Trojan:Win32/Bearfoos.B!ml, un faux positif. C'est --version lit starhermit 1.9.1 (host API 1.14, …; engine release 1.10.0).

1.9.1

API hôte 1.13, comme 1.9.0 : ré-épingler sur 1.9.1 (engine.version=1.9.1) pour les obtenir.

  • Les shaders personnalisés sont vérifiés au fur et à mesure que les navigateurs les vérifient: le WGSL d'un matériau est désormais soumis aux règles WebGPU applique, nativement et dans starhermit check, avec la partie, la ligne et la colonne. Cela couvre un nom déclaré deux fois dans une portée, une valeur masquant un élément intégré, elle est ensuite utilisée comme (let min = …; min(a, b)), mots réservés comme noms (target, filter, set, type, self, common, active, …, noms des uniformes et des textures aussi), une valeur intégrée laissée inutilisée, break ou continue en dehors d'une boucle et des expressions constantes qui déborder ou diviser par zéro. Un tel code permettait de dessiner nativement et rien dans les navigateurs. Si check refuse maintenant votre matériel, renommez ou corrigez le nom du message. Mathématiques entières constantes à l'intérieur des calculs d'expressions flottantes comme WGSL le fait partout (1 / 2 * 0.5 est 0).
  • Shaders refusés signalés dans les navigateurs: un matériau ou renderer.post programmer le WebGPU du navigateur refuse est enregistré une fois dans le journal du jeu avec le message de WebGPU sur votre ligne, et shaderError le rapporte.
  • Firefox et Safari: les lignes de console et les écrans d'erreur portent leur fichier, ligne et colonne ; à court de la mémoire termine le jeu avec "manque de mémoire de script"; les sons chargés en rafale sont jouables immédiatement dans Firefox ; et la première tonalité du premier oscillateur d'un jeu démarre à l'heure dans chaque navigateur.
  • Cache avant/arrière: une page que le navigateur renvoie se charge à nouveau, et le jeu recommence avec ce qu'il stocké (il montrait que le jeu était arrêté).
  • Connu dans Safari: onQuit ne s'exécute pas lorsque la page se ferme ou navigue. Conservez ce qui doit être enregistré en dernier sous ça change, ou dans onSuspend. Connu dans Firefox : un jeu qui prend toute la mémoire permise par le navigateur peut geler l'onglet.
  • Outillage: starhermit new écrit engine.minor=13 pour un jeu épinglé sur la propre version du runtime, donc nouveau les jeux obtiennent le comportement de l'interface utilisateur de la version 1.9. Téléchargements natifs (fichiers distants, cargo starhermit publish) réutiliser HTTPS connexions, environ 3,5 fois plus rapides pour de nombreux fichiers.
  • Jeux de rouille: l'interface utilisateur manipule un doigt comme le font les jeux de script (ui::PointerInput).

1.9.0

API hôte 1.13. Les jeux épinglés sur une version antérieure continuent de fonctionner dessus. Ré-épingler sur 1.9.0 (engine.version=1.9.0) pour les correctifs du cycle de vie ; ajouter engine.minor=13 pour le nouveau comportement de l'interface utilisateur.

  • Contenu de l'interface utilisateur pivoté (engine.minor=13) : un style rotate transforme tout ce que sa boîte dessine, comme un CSS la transformation fait : le texte avec ses ombres, ses lueurs, ses traits et ses remplissages dégradés, ses images, ses neuf tranches, sa décoration images et ombres floues, avec des bords lisses. La mise en page, les tests de réussite et la concentration restent là où se trouve la boîte. Un propre au widget dessiné par le jeu draw reste debout. Les jeux déclarant un mineur plus âgé, ou aucun, conservent le texte, les images et des ombres floues debout.
  • Doigts dans l'interface utilisateur du jeu (engine.minor=13): hovered et hoverWithin ne correspond jamais à un doigt, et pressed ne correspond que lorsque le doigt est posé sur le widget, donc rien ne reste allumé après une pression. Les robinets obtiennent des cibles de taille tactile et un glissement dans une zone de défilement la font défiler. La souris et le stylet restent inchangés.
  • onSuspend et onResume dans les navigateurs: un onglet caché ou un navigateur réduit suspend désormais le jeu en tant que la fenêtre réduite le fait nativement ; onSuspend s'exécute après la trame en cours et ce qu'il écrit dans le stockage est conservé, et onResume s'exécute avant l'image suivante lorsque la page s'affiche.
  • onQuit: il n'a pour la plupart jamais fonctionné, nativement ou dans les navigateurs, car une fenêtre ou une page qui se ferme trouve généralement un cadre en cours. Il s'exécute désormais une fois, après cette image (après onSuspend si le jeu était masqué en premier), et ses écritures de stockage sont conservées. Nativement, il en a une seconde ; dans les navigateurs, une page qui disparaît attend 0,2 s pour les jeux avec le storage capacité. Sauvegardes dans le cloud, copie des paramètres du compte et appels de plateforme effectués dans onQuit ne sortez toujours pas: enregistrez pendant les images.
  • Correctifs: la première image d'une fenêtre réduite après son retour ne prend plus un long pas de temps.

1.8.1

API hôte 1.12, comme 1.8.0 : ré-épingler sur 1.8.1 (engine.version=1.8.1) pour les obtenir ; aucune modification de code n’est nécessaire.

  • Sons courts dans les navigateurs: sons sur le graphe de synthèse (starhermit:audio's context) qui a commencé à context.currentTime et durait moins de quelques secondes n'étaient jamais entendues dans les navigateurs : les commandes du graphique arrivé au mixeur avec quelques secondes de retard. Ils arrivent maintenant immédiatement, et currentTime est l'heure du mixeur sur les deux les environnements d'exécution, également juste après le retour d'un onglet masqué ou d'une fenêtre réduite. Si votre jeu est silencieux ou rate court effets dans les navigateurs sur 1.8.0 ou version antérieure, ré-épinglez sur 1.8.1.
  • Exécution Linux: un téléchargement développeur, starhermit-1.8.1-linux-x86_64.tar.gz, pour Linux 64 bits avec glibc 2.35 ou plus récent. C'est native.json énumère ce dont il a besoin. Les téléchargements natifs sont toujours lus par le client Windows.
  • Paramètres par défaut du navigateur: pendant qu'un jeu s'exécute, sa page conserve le menu contextuel, la sélection, la copie et le coller, déposer des fichiers, faire un défilement automatique avec le clic central, les boutons Précédent et Suivant de la souris et les raccourcis tels que Ctrl+S, Ctrl+F, Ctrl+P, zoom, F1, F3 et Alt du jeu, et les touches liées au jeu l'atteignent avec Ctrl, Alt ou Cmd aussi. F11, F12, recharger et les touches de tabulation du navigateur fonctionnent toujours. Une page intégrant un jeu dans un document plus grand peut conserver le comportement du navigateur avec browserDefaults: "page".
  • Mémoire insuffisante dans les navigateurs: un jeu qui utilise la mémoire du navigateur se termine par "le jeu n'avait plus de script mémoire" au lieu de casser la page.
  • Correctifs: indigène http:// les requêtes essaient chaque adresse à laquelle un nom est résolu (localhost sous Windows); le Téléchargements Windows starhermit.exe conserve son bit exécutable lorsqu'il est décompressé sous Linux ou WSL.

1.8.0

API hôte 1.12. Les jeux épinglés sur une version antérieure continuent de fonctionner dessus ; réépingler (avec engine.minor=12 pour le nouveaux membres) pour les utiliser.

  • Styles pour l'interface utilisateur du jeu: s'inscrire regarde une fois avec ui.setStyles par type et classe de widget, avec ui.setTokens valeurs et classes de nom par widget avec ui.style(...). Dégradé, image et neuf tranches remplissages, bordures par côté, coins arrondis ou coupés, ombres et lueurs, décorations, flou d'arrière-plan et texte avec espacement des lettres, ombres, contours et remplissages dégradés. Blocs d'état (survol, pressé, focus-visible, coché, sélectionné, désactivé, premier, dernier, impair, pair, entrée, sortie) et inside les règles fonctionnent comme en CSS, et parts curseurs de style, cases à cocher, sélections, onglets, compteurs et boîtes de dialogue. Les tailles sont en bordure de boîte.
  • Mouvement: transitions entre regards, animations d'images clés avec enfants décalés, entrée et sortie animations, mise à l'échelle et rotation. Le mouvement réduit les rend instantanés ou immobiles.
  • Mise en page et widgets: grilles avec lignes lignées et rayées, piles, placement ancré, justify et espaceurs, étirement, remplissage et croissance, marges ; des boutons construits à partir du contenu, ui.widget pour les widgets dessinés par main qui garde la concentration, la navigation et les lecteurs d'écran, les info-bulles, les compteurs, les groupes radio, les commutateurs et ui.document.
  • Depuis CSS: ui.stylesFromCss et le starhermit css FILE commande convertir le style d'une version de navigateur feuille en styles, animations, jetons et mises en page, répertoriant ce qui n'a pas de style.
  • Curseurs: input.setCursor définit le pointeur par le nom du curseur CSS, ou vers la propre image du jeu jusqu'à 64x64.
  • La taille de l'interface du lecteur, la taille du texte, le contraste élevé et la réduction du mouvement s'appliquent toujours aux styles.
  • Correctifs: une Texture utilisée uniquement dans un style est conservée dans les navigateurs (son remplissage n'a rien dessiné) ; polices ajoutées avec canvas.fonts dessinez dans chaque image ; engine.preferences() est d'accord avec ui.preferences() chaque image ; renderer.capture() prend jusqu'à 4 captures à la fois et s'installe toujours ; le curseur clique et glisse pour atterrir étapes, et les curseurs et le pied de page du menu Options se comportent dans les grandes tailles et sur les pages lentes.

1.7.0

API hôte 1.11. Les jeux épinglés sur une version antérieure continuent de fonctionner dessus ; réépingler (avec engine.minor=11 pour le nouveaux membres) pour les utiliser.

  • Qualité de l'espace d'affichage: renderer.grade.space = "display" évalue la couleur affichée à l'écran, par canal après le mappage des tons, comme le fait la qualité du canevas d'une version Web : saturation, contraste autour de l'affichage 0,5, ombre et mettre en évidence les teintes, un night (désaturer et une teinte clair de lune qui épargne les pixels chauds et lumineux, avec spareSaturation et brightScale), un moment fort lift, et flashSpace: "display" pour un flash la nuit ne teint pas. Cela ne coûte rien de plus, quel que soit le niveau de qualité. La valeur par défaut "linear" la note est inchangée.
  • Petites cibles de rendu: RGFormat et RedFormat avec UnsignedByteType (RG8, R8) à 2 et 1 octets a pixel, chaque équation de mélange est limitée à 0–1.
  • L'interface utilisateur du jeu suit les paramètres du joueur, comme documenté : taille de l'interface, taille du texte, contraste élevé (sur setTheme, une étiquette color et un conteneur background) et une réduction des mouvements. ui.preferences() dit à quoi s'applique ce cadre et ui.measureText() mesure le texte au fur et à mesure que l'interface utilisateur le présente. Un jeu qui dimensionne son UI À la main devrait le vérifier à des tailles plus grandes.
  • Grand texte: un cadre dont le texte dépasse l'atlas de glyphes l'agrandit désormais (à 1024, puis 2048 px) au lieu de ne dessiner aucun texte de ce cadre.
  • Audio dans les navigateurs: context.state est "suspended" jusqu'à ce que la première pression du lecteur démarre l'audio, puis "running", avec statechange et resume() résoudre. UN setValueAtTime ou setTargetAtTime en remplace un en même temps juste avant, donc la mise à jour d'un paramètre à chaque image n'atteint plus la limite d'événement tout en l'horloge s'arrête.
  • Fenêtres: le runtime contient des informations de version et l'icône StarHermit, donc le Gestionnaire des tâches répertorie un jeu sous "ÉtoileErmite" (pas un mauvais nom avec une icône vide).

1.6.0

API hôte 1.10. Les jeux épinglés sur une version antérieure continuent de fonctionner dessus ; réépingler (avec engine.minor=10 pour le nouveaux membres) pour les utiliser.

  • Interface utilisateur plus rapide: les étiquettes inchangées conservent leur disposition dans les cadres, et les rectangles des widgets atteignent les scripts sans JSON. Une trame lourde d'interface utilisateur d'environ 800 widgets est passée d'environ 4 ms à 0,7 ms dans les navigateurs et d'environ 3 ms à 0,75 ms en mode natif, avec une sortie au pixel identique.
  • Un tas de scripts plus léger: les tables de l'interprète natif redonnent de la mémoire après une rafale de déchets (au bout de 8 collections pour la plupart vides d'affilée, jusqu'à doubler leur utilisation) ; au cours d'une grande bataille, les sommets du tas sont tombés d'environ 205 Mio à moins de 185 Mio.
  • Matériels : uniformes jusqu'à 16 Ko par matériau, et textureLoad(tex, coords, 0) pour des lectures exactes du texel (fixé dans la texture à chaque exécution).
  • Cibles de rendu et mélange: cibles demi-flotteurs à deux et à un canal (RGFormat, RedFormat avec HalfFloatType) à la moitié ou au quart de la mémoire du RGBA16F ; CustomBlending avec des équations et des facteurs de mélange (soustraction inverse, min, max) et SubtractiveBlending; renderer.render dans une cible utilise des matériaux tels qu'ils sont à l'appel.
  • Mémoire de textures : les pixels d'une DataTexture peuvent quitter le tas de script une fois téléchargés (image.data = null, ou dans onUpdate); il continue de dessiner et survit à la perte de périphérique ou de contexte.
  • Utilisation de la scène: engine.usage() et engine.budgets() compter les nœuds, les objets, les instances, les maillages instanciés, sprites, matériaux, programmes et lumières contre leurs limites.

1.5.1

API hôte 1.9, correctifs uniquement : réépinglez à partir de la version 1.5.0 sans autre modification.

  • Copier des œuvres: clipboard.writeText place le texte dans le presse-papiers du système de manière native (Windows, X11, Wayland) et dans les navigateurs ; il a déjà passé ses contrôles mais le texte n'est jamais arrivé.
  • Coller nativement: Ctrl+V, Maj+Inser ou la touche Coller colle dans un champ de texte ciblé. Uniquement le temps d'exécution lit le presse-papier, sur le geste du joueur ; le jeu considère le texte collé comme une saisie.

1.0.0

La première version : le runtime Windows (x86-64), sans runtime Web.

La zone moteur

engine/
  versions.json            every release: host API, date, runtimes, revocation
  X.Y.Z/
    native/windows-x86_64/
      native.json          the Windows runtime's files, each with its size, SHA-256 and chunks
      starhermit-X.Y.Z-windows-x86_64.zip
                           the developer download: the same files as one archive
    manifest.json          the web runtime's files, each with its size and sha384
    starhermit.js          the module a game's loader page loads
    starhermit.wasm, *.js  the runtime, its audio mixer and worklets
    starhermit.d.ts        the host API's declarations
    fonts/, licenses/      the runtime's fonts and every licence notice
                           (all of the web runtime only in a release that has one)
  chunks/ab/<sha256>.z     pieces of the native files, shared by every release
  patches/ab/<sha256>.p    binary patches from earlier releases' files

Chaque fichier est publié tel quel (aucun nom de fichier ne commence par _ ou .), et GitHub Pages le sert avec Access-Control-Allow-Origin: *.

versions.json

{
  "format": 2,
  "versions": [
    {
      "api": {"major": 1, "minor": 4},
      "date": "2026-10-20T13:55:50Z",
      "native": {
        "windows-x86_64": {"manifest": "1.1.0/native/windows-x86_64/native.json", "sha256": "<SHA-256 of native.json>"}
      },
      "revoked": false,
      "version": "1.1.0",
      "web": {"manifest": "sha384-<SRI hash of manifest.json>"}
    }
  ]
}

web est {"manifest": "sha384-…"}, le hachage SRI du site Web de la version manifest.json, ou null pour une version sans runtime Web. native épingle chaque plate-forme native.json par son SHA-256. Un la version a été retirée parce qu'elle n'est pas sûre, dit "revoked": true avec un "revokedReason"; c'est le seul le changement qu'une entrée publiée prend jamais.

native.json

native.json répertorie les fichiers du dossier du moteur qu'un client installe - starhermit.exe, release.json (la version de la release, l'API hôte et le launcher protocole dont son runtime parle), LICENSE-engine et les avis des tiers - chacun avec son size, sha256 et chunks. Un morceau est une partie d'un fichier, stocké sous forme compressée avec zlib chunks/<first two hex digits>/<sha256>.z et nommé par le SHA-256 de ses octets non compressés ; les limites des morceaux suivent le contenu, donc un stretch conserve son morceau d'une version à l'autre. Là où il est plus petit, un fichier répertorie également patches à partir du même fichier des versions antérieures ("from": le SHA-256 du fichier précédent). downloads répertorie le téléchargement du développeur avec son size et sha256; les clients ne l'installent jamais. Dans une version avec un environnement d'exécution Web, le dossier natif contient également web-manifest.json, le site web de la version manifeste, de sorte que le développeur télécharge des packages de jeux pour le Web sans réseau.

L'environnement d'exécution Web

Le runtime Web d'une version est constitué des fichiers à côté de son manifest.json, qui répertorie chacun avec son size et sha384 et enregistre la version de la version, l'API hôte et la build. La page de chargement d'un jeu (index.html, écrit par starhermit package --web) n'a pas de script propre : il se charge starhermit.js et manifest.json depuis https://wiki.starhermit.com/engine/X.Y.Z/ avec les hachages SRI, et le moteur récupère tous les autres fichiers dont il a besoin (starhermit.wasm, les worklets audio, les polices) et le vérifie contre le manifeste. La page exécute uniquement le moteur : entrée, menus d'exécution, audio, stockage, session de plate-forme et voix - et le TypeScript du jeu s'exécute dans un travailleur qu'il démarre et peut arrêter.

Le runtime Web regroupe ses propres polices, Liberation 2.1.5 (SIL Open Font License 1.1) et DejaVu Sans 2.37 (licences Bitstream Vera et Arev) ; leurs avis sont dans licenses/ avec les autres.

Intégrité

Une chaîne de hachage couvre chaque octet exécuté par un client :

  1. versions.json (ou l'API de la plateforme ci-dessous) donne le SHA-256 d'une version native.json.
  2. native.json donne le SHA-256 de chaque fichier et celui de chaque morceau.
  3. Le client récupère uniquement les morceaux qu'il ne détient pas déjà, vérifie la taille stockée de chacun, taille gonflée et SHA-256, rassemble chaque fichier, vérifie le SHA-256 du fichier et se déplace ensuite seulement la libération en place. Un correctif est vérifié par rapport à son propre SHA-256 et le fichier corrigé par rapport à celui du fichier ; tout échec retombe sur les morceaux.

Le téléchargement développeur est couvert par la même chaîne jusqu'à son entrée dans downloads. Un navigateur la page de chargement du jeu épingle le moteur d'exécution Web starhermit.js et manifest.json avec des hachages SRI, et le moteur d'exécution vérifie tous les autres fichiers qu'il charge par rapport au manifeste.

Le moteur publie l'API

La plateforme sert la même liste, avec chaque URL sur ce wiki, donc les clients demandent à l'API quel moteur pour récupérer :

GET /api/v1/engine/releases → chaque version, la plus récente en premier :

{"releases": [{
  "version": "1.1.0", "api": {"major": 1, "minor": 4}, "revoked": false, "date": "2026-10-20T13:55:50Z",
  "web": {"base": "https://wiki.starhermit.com/engine/1.1.0/", "manifestIntegrity": "sha384-<SRI hash>"},
  "native": {"windows-x86_64": {
    "manifestUrl": "https://wiki.starhermit.com/engine/1.1.0/native/windows-x86_64/native.json",
    "manifestSha256": "<SHA-256 of native.json>"}}
}]}

GET /api/v1/engine/releases/{version} → une version, ou 404 quand il n'est pas répertorié. Les deux sont anonyme et pouvant être mis en cache (Cache-Control: public, max-age=60 avec un ETag). Une version révoquée porte revokedReason; web est null pour une version sans runtime Web. Alors que la plateforme n'a jamais lu la liste (le wiki inaccessible depuis son lancement) ils répondent 503 avec Retry-After.

Jeux de script sur la plateforme

Quand la racine d'un jeu starhermit.txt déclare engine.version, la plateforme le traite comme un script jeu :

  • chaque publication enregistre la publication du code PIN des fichiers, comme hosting.engineVersion, et définit hosting.deployWarning (également dans la réponse d'un bundle push) lorsque cette version n'est pas répertoriée ou est révoqué. Un avertissement n'arrête jamais une publication.
  • chaque page du jeu hébergé est accompagnée d'une politique de sécurité du contenu qui n'admet que les scripts de ce wiki (et du propre moteur blob: travailleurs), donc le seul code qu'une page de jeu de script peut run est le moteur officiel :
default-src 'self'; script-src https://wiki.starhermit.com 'wasm-unsafe-eval' blob:; worker-src blob:;
connect-src 'self' https://wiki.starhermit.com; img-src 'self' blob: data:; media-src 'self' blob:;
style-src 'self' 'unsafe-inline'; font-src 'self' https://wiki.starhermit.com;
frame-ancestors https://dashboard.starhermit.com; base-uri 'self'; form-action 'none'

Une page d'un jeu de script sans version de navigateur (comme la page simple téléchargée par un jeu Windows uniquement) pour les navigateurs) ne nécessite aucun script et n'est pas affecté.

Révocations

Une version révoquée reste répertoriée afin que les clients puissent expliquer pourquoi ils la refusent : le client StarHermit le fait. ne pas l'installer ou le démarrer et indique au joueur que les commandes d'empaquetage refusent d'empaqueter un jeu pour celui-ci quand ils lisent versions.json, et la plateforme prévient les propriétaires de jeux qui l'épinglent lorsqu'ils publier. Réépinglez la version qui la remplace et publiez à nouveau (voir Passer à un moteur plus récent).
