Performa asli untuk permainan skrip

Game mesin StarHermit menjalankan paket yang sama di browser dan secara asli. Keduanya menjalankan kode Anda dengan sangat baik berbeda, jadi pilihlah di mana pekerjaan berat dilakukan sebelum Anda mem-porting atau menulisnya. Halaman ini mencakup skrip kecepatan, WebAssembly, adegan yang terikat GPU, pekerja dan pengukuran. Angka adalah pengukuran mesin dari Oktober 2026, pada mesin 1.26.1.

Bagaimana kode Anda berjalan

Di browser Secara asli
JavaScript Permainan V8 browser, kecepatan penuh Penerjemah mesin sendiri, tanpa JIT (sesuai desain, untuk keamanan)
WebAssembly, ranah utama WebAssembly browser Kode asli yang dikompilasi platform dari mesin 1.26.1 (detail); jika tidak, juru bahasa mesin (host API 1.25 dan yang lebih baru)
WebPerakitan di starhermit:script pekerja Penerjemah mesin, untuk hasil yang sedikit persis Kode asli yang dikompilasi platform, seperti di ranah utama
  • Secara asli, permainan sebenarnya adalah tentang JavaScript 15–25× lebih lambat dari V8. Tolok ukur mikro dapat memberi saran sekitar 8×. Jangan bergantung pada mereka.
  • WebAssembly asli yang telah dikompilasi oleh platform dijalankan kira-kira kecepatan V8: sekitar 7× lebih cepat daripada penerjemah pada patokan simulasi mesin, sekitar 1,4× waktu V8. Ditafsirkan WebAssembly sekitar 8–18× lebih lambat dari V8.
  • starhermit check menjalankan JavaScript persis seperti permainan berjendela. Tolok ukur dengan a --release pembuatan mesin saja.

WebAssembly yang dikompilasi

Dari mesin 1.26.1, saat Anda menerbitkan game yang berisi .wasm modul, platform mengkompilasi masing-masing modul modul sebelumnya dalam build sandbox dan menandatangani hasilnya. Runtime asli mengunduhnya, memverifikasi tanda tangan, menyimpannya dalam cache, dan menjalankannya sebagai kode asli. Anda tidak perlu mengubah permainan; publikasikan saja.

  • Di mana: Windows x86-64, Linux x86-64 dan Intel macOS, pada CPU x86-64-v2 atau lebih baru (SSE4.2 dan POPCNT). Apple Silicon Mac dan CPU lama masih melakukan interpretasi, begitu pula modul-modulnya menggunakan SIMD.
  • Kapan: sebuah instance yang dibuat sebelum kode yang dikompilasi diunduh terus ditafsirkan. Nanti instance dijalankan dikompilasi, termasuk peluncuran berikutnya, yang memuatnya dari cache disk.
  • Hasil yang sama: kode yang dikompilasi cocok dengan penerjemah sedikit demi sedikit, termasuk bahan bakar dan jebakan.
  • Periksa dan nonaktifkan: dengan --dev, log menunjukkan untuk setiap modul apakah modul dijalankan dikompilasi atau ditafsirkan, dan alasannya. STARHERMIT_WASM_AOT=0 mematikan kompilasi.
  • Browser tidak berubah: ranah utama menggunakan WebAssembly browser, dan pekerja menggunakan penerjemah mesin.

Pekerjaan per frame yang berat

Simulasi, penyambungan, pencarian jalan, dan pembangunan entitas adalah titik-titik panas yang biasa terjadi.

  1. Tulis kode panas dalam Rust atau bahasa WASM lainnya dan menjalankannya sebagai WebAssembly, idealnya di a starhermit:script pekerja. Setelah game diterbitkan, game tersebut berjalan secara native dengan kecepatan mendekati V8, sementara JavaScript biasa tetap sekitar 15–25× lebih lambat.
  2. Pilih jalur dengan runtime() dari starhermit:engine (host API 1.26). "web" berarti V8, jadi JavaScript baik-baik saja di sana. "native" berarti Anda sebaiknya memilih jalur WASM. Pekerja selalu mengambil jalur asli dan tidak dapat mengimpor starhermit:engine.
  3. Pertahankan JavaScript biasa untuk logika game, UI, dan orkestrasi. Sebarkan pekerjaan berat yang jarang terjadi ke seluruh frame.
  4. Jangan kompilasi JavaScript atau TypeScript ke WebAssembly untuk kecepatan. Hasilnya masih membutuhkan a Model objek JavaScript, jadi tidak menghasilkan apa-apa.

Bagi banyak entitas serupa, starhermit:world kernel berjalan secara asli juga.

Adegan yang terikat GPU

Biasanya, GPU biasanya menjadi batasnya hanya setelah waktu skrip terkendali.

  • Menggunakan InstancedMesh.setLevels([...]) dengan level poli rendah dan jarak imbang, dan tiga LOD (host API 1.26).
  • Berbelok castShadow off untuk alat peraga kecil atau jauh.
  • Batasi bayangan kaskade dengan shadow.cascades = { count, maxDistance }, ekstensi mesin.
  • Mengatur STARHERMIT_GPU_PASS_TIMES=1 untuk mencetak waktu GPU untuk setiap lintasan.

Pekerja

  • Sebelum menghosting API 1.27, simpan referensi ke setiap pekerja yang Anda gunakan, karena pengumpulan sampah mengakhirinya. Dari 1.27, seorang pekerja dengan pendengar hidup sampai terminate().
  • Pekerja dapat membaca file paket (files) dari host API 1.26.
  • Pekerja dapat mengirim pesan biner dan pesan yang dapat ditransfer dari host API 1.25.

Ukur

  • Bandingkan asli dan web menggunakan build yang sama.
  • Statistik frame mesin melaporkan waktu skrip secara terpisah dari waktu frame. Nomor bangku skrip adalah cocok untuk dikutip.
