API Permainan

Subsistem game adalah inti dari StarHermit: game multipemain otoritatif server yang aturannya dijalankan dalam file JavaScript kotak pasir atau wadah yang disediakan pengembang. Kedua runtime berbagi REST API yang dapat diakses oleh pemain (api/v1/games/{slug}) dan gameplay WebSocket (ws/v1/games). Untuk pembuatan server, lihat Skrip Permainan atau Server Game yang dihosting oleh kontainer. Untuk contoh runtime skrip yang lengkap, lihat Panduan Catur Dan HypeDriven/catur pertapa bintang.

URL Dasar: https://api.starhermit.com.

Titik akhir pemain memerlukan autentikasi dan berfungsi dengan token pengguna penuh dan peluncuran dalam lingkup game token. Keduanya /server/... titik akhir hanya untuk container: rekonsiliasi sesi menggunakan metode sempit token pembawa server, sedangkan pembaruan token menggunakan kunci penyegaran penerapan.

Apa {slug} adalah

Siput sebuah game adalah miliknya uid — nilai yang sama dengan miliknya <uid>.starhermit.com alamat, mis. 83fd04b1-3cbe-4b09-a251-3733ad4b9d94. Itu berasal dari id game yang tidak dapat diubah dan tidak ada apa-apa dapat mengaturnya: bukan starhermit.txt, bukan nama repo, bukan operator. Nama yang bisa digunakan oleh pengembang pilih akan menjadi sesuatu yang bisa diperebutkan oleh dua game, dan akan membutuhkan platform untuk menengahi siapa mengerti; suatu cairan tidak dapat bertabrakan atau diminta.

Siput bukanlah backend server. Setiap game ditambahkan dari folder lokal, dan setiap game repositori pemilik terverifikasi menambahkan, memilikinya — dengan atau tanpa server= atau container.image= — karena memang demikian alamat permukaan yang menghadap pemain dalam game: meluncurkan token, kontrol, pengaturan, dia slot penyimpanan cloud Dan kamar. SEBUAH Game khusus browser membutuhkannya sama seperti game lainnya. Satu-satunya game tanpa siput adalah repositori kiriman yang pemiliknya tidak terverifikasi (gameSlug adalah null di dalam GET /api/v1/me/github-games).

Titik akhir tentang server game — info game, pencapaian, sesi, perjodohan, undangan, memutar ulang — membutuhkan backend. GET /api/v1/games/{slug} jawaban 404 untuk game yang ada slug dan no backend, yang merupakan cara untuk membedakan keduanya.

Jangan melakukan hard-code. Bacalah dari token peluncuran game_scope klaim, atau — untuk a game browser yang dihosting platform — dari location.hostname, karena subdomainnya adalah uid.

Informasi permainan

GET /api/v1/games/{slug}

Mengembalikan definisi game ditambah statistik pemanggil untuk game tersebut. 404 jika tidak ada permainan seperti itu, atau jika game tersebut hanya untuk browser (memiliki slug tetapi tidak ada server backend).

{
  "slug": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "name": "Chess",
  "enabled": true,
  "leaderboardId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "maxConcurrentSessionsPerPlayer": 20,
  "replaysEnabled": true,
  "buildId": "s12",
  "me": {
    "userId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
    "elo": 1200,
    "wins": 4,
    "losses": 2,
    "draws": 1,
    "activeSessionCount": 2
  }
}
  • leaderboardId adalah opsional.
  • me.elo defaultnya adalah 1200; wins/losses/draws dibaca dari dokumen per pemain yang dimiliki waktu proses server.
  • replaysEnabled menyatakan apakah sesi permainan yang telah selesai disimpan — bacalah daripada berasumsi, dan sembunyikan UI replay Anda saat itu false. Melihat Pemutaran ulang.
  • buildId memberi nama logika server yang saat ini melayani permainan (s + versi skrip, atau c + awalan intisari gambar). Kirim kembali sebagai ws/v1/games?build=… jadi klien basi ditolak 409 {"error":"build_mismatch"} sebelum bertindak pada ladang yang dipindahkan. Menghilangkan build terhubung seperti sebelumnya.

Luncurkan token

POST /api/v1/games/{slug}/launch-token

Mencetak JWT lingkup permainan (masa pakai default 60 menit). game_scope={slug} dan tidak ada klaim izin. Token yang tercakup dapat mencetak ulang token untuk permainannya sendiri — ini adalah pola penyegaran klien — tetapi pembaruan dibatasi oleh launch_chain (defaultnya 12 jam dari sesi pengguna asli). Melewati batas atas pembaharuan itu 403. Klien harus menyegarkan sebelum token habis masa berlakunya; klien referensi catur, misalnya, menyegarkan setiap 45 menit. Perpanjang juga sebelum menyambungkan kembali soket — lihat Permainan WebSocket.

{
  "token": "eyJhbGciOi...",
  "expiresInSeconds": 3600
}

Prestasi

GET /api/v1/games/{slug}/achievements

Setiap pencapaian yang dinyatakan oleh backend resmi game, dengan status tidak terkunci pemanggil. Rahasia pencapaian tetap tersembunyi sampai penelepon membukanya. Menerima JWT pengguna penuh atau cakupan game token peluncuran. 404 ketika siput tidak memiliki definisi permainan yang resmi.

[
  {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "secret": false,
    "points": 10,
    "unlocked": true,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
]

Prestasi permainan adalah server-otoritatif: hanya skrip atau wadah game yang memberikannya, dan diklaim klien POST /api/v1/me/achievements/unlock titik akhir menolaknya. Buka kunci secara langsung tiba di soket gameplay sebagai {"type":"achievement"} bingkai. Kontrak penuh sudah masuk Prestasi, Skrip Permainan, Dan Server Game Kontainer.

GET /api/v1/games/{slug}/linked-achievements/{otherSlug}

Milik si penelepon membuka kuncinya lain game, sehingga game ini dapat membuka fitur berdasarkan game tersebut. Bekerja dengan token peluncuran game ini. Melihat Prestasi — Prestasi dari game lain.

Ikatan kontrol per pemain

Game dapat mendeklarasikan kontrol browser desktop dengan control.* entri di starhermit.txt. Kontrol API menyimpan a penggantian terpisah untuk setiap pengguna dan game. JWT pengguna penuh dan token peluncuran cakupan game adalah diterima; token peluncuran game_scope harus cocok {slug}.

GET /api/v1/games/{slug}/controls

Mengembalikan pengikatan efektif dalam urutan nyata. codes berisi penggantian pengguna kapan satu ada, sebaliknya defaultCodes. Kembali 404 "This game declares no controls." kapan bangunan hidup starhermit.txt tidak memiliki valid control.* line — deklarasikan dan publikasikan build; melihat Tutorial: tambahkan kontrol ke game Anda.

{
  "actions": [
    {
      "action": "up",
      "label": "Run forward",
      "defaultCodes": ["KeyW", "ArrowUp"],
      "codes": ["KeyW", "ArrowUp"]
    },
    {
      "action": "shoot",
      "label": "Shoot",
      "defaultCodes": ["Space"],
      "codes": ["KeyJ"]
    }
  ]
}

PUT /api/v1/games/{slug}/controls

Menggantikan penggantian pemanggil. Itu bindings objek mungkin berisi subset dari yang dideklarasikan tindakan; tindakan yang dihilangkan terus menggunakan defaultnya.

{
  "bindings": {
    "up": ["KeyW", "ArrowUp"],
    "shoot": ["KeyJ"]
  }
}

Setiap tindakan harus diumumkan oleh permainan. Setiap tindakan harus memiliki 1–4 valid KeyboardEvent.code nilai, dan tidak ada kode yang dapat ditetapkan ke dua tindakan sebagai hasilnya peta yang efektif. Tindakan, kode, atau konflik yang tidak valid muncul kembali 400.

DELETE /api/v1/games/{slug}/controls

Menghapus semua penggantian pemanggil dan memulihkan default manifes. Kembali 204. Penulisan token peluncuran memang disengaja, sehingga game yang dihosting mungkin menyediakan layar rebindingnya sendiri.

Pengaturan permainan per pemain

Tempat permainan Anda disimpan pilihannya sendiri untuk pemain — volume master, detail grafis, subtitle ukuran, kamera pilihan, pemuatan terakhir yang dipilih — sehingga mereka mengikuti pemain tersebut ke mesin mana pun yang mereka masuki dari. Penyimpanan kunci/nilai yang mencakup satu pemain dan satu game.

Tidak ada yang mendeklarasikan skema. Platform menyimpan kunci dan nilai-nilai Anda dan tidak pernah membacanya, jadi Anda menambahkan opsi dengan menuliskannya: tidak ada entri manifes, tidak ada penerapan ulang, tidak ada rilis platform. Itu juga berarti platform tidak dapat memvalidasinya untuk Anda — kesalahan ketik pada nama kunci adalah pengaturan baru, bukan pengaturan baru kesalahan.

Seperti API kontrol, token peluncuran cakupan game diterima (itu game_scope harus cocok {slug}), jadi layar opsi dalam game hanya berfungsi dengan token yang sudah dimiliki game tersebut. Berbeda dengan kontrol, tidak diperlukan deklarasi manifes: setiap game memiliki penyimpanan pengaturan sejak saat itu ada, termasuk game khusus browser tanpa logika server sama sekali.

Pilih toko yang tepat — penyimpanan awan tahan kemajuan (satu arsip buram per judul, 10 MB, juga dapat dijangkau dengan token peluncuran), dan status pemutar skrip atau container backend adalah otoritatif server dan tidak dapat ditulis dari a klien. Pengaturan adalah preferensi kecil milik klien di antaranya.

GET /api/v1/games/{slug}/settings

Semua yang disimpan penelepon untuk game ini. settings kosong untuk pemain yang belum pernah menyimpan apa pun - itu adalah a 200, tidak a 404. Kunci kembali diurutkan.

{
  "slug": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "settings": {
    "audio.master": 0.8,
    "graphics.detail": "ultra",
    "graphics.options": { "shadows": true, "msaa": 4 }
  },
  "count": 3,
  "bytes": 118,
  "updatedAt": "2026-08-07T15:04:11Z",
  "limits": { "maxKeys": 200, "maxKeyLength": 128, "maxTotalBytes": 2097152, "maxAccountBytes": 67108864 }
}

bytes adalah perbandingan dengan pengaturan pemain ini saat ini limits.maxTotalBytes. Baca batasan daripada mengkodekannya secara keras: tunjangan adalah pengaturan operator, dan permainan dapat diberikan miliknya sendiri. maxKeys (200 secara default) juga dapat diatur per game, dan maxAccountBytes batas satu pengaturan akun di setiap game (64 MB secara default).

PUT /api/v1/games/{slug}/settings

Menggantikan seluruh peta. Kunci yang dihilangkan oleh isi akan dihapus — kirim semuanya, atau gunakan PATCH.

{ "settings": { "audio.master": 0.8, "graphics.detail": "ultra" } }

Sebuah kosong settings objek menghapus pengaturan game untuk pemanggil. Mengembalikan bentuk yang sama seperti GET.

PATCH /api/v1/games/{slug}/settings

Menggabungkan ke dalam apa yang disimpan, meninggalkan kunci yang tidak disebutkan sendirian. A null nilai menghapus itu kunci. Ini menggabungkan kunci pengaturan tingkat atas; nilai objek menggantikan seluruh nilai pada kuncinya, termasuk properti bersarangnya. Inilah yang layar opsi harus digunakan — ini dapat menyimpan satu penggeser yang dipindahkan tanpa membaca terlebih dahulu dan menulis ulang segalanya.

{ "settings": { "audio.music": 0.25, "graphics.options": null } }

GET / PUT / DELETE /api/v1/games/{slug}/settings/{key}

Satu pengaturan pada satu waktu. GET kembali { "key", "value", "updatedAt" }, atau 404 jika penelepon punya tidak pernah menyimpannya. PUT dibutuhkan { "value": <any JSON> } dan menyimpan nilainya kata demi kata — termasuk sebuah eksplisit null, yang di sini adalah nilai seperti nilai lainnya, bukan penghapusan. DELETE kembali 204, dan menghapus sesuatu yang tidak ada adalah kegagalan, bukan kesalahan.

curl -X PUT "https://api.starhermit.com/api/v1/games/$SLUG/settings/audio.master" \
  -H "Authorization: Bearer $LAUNCH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"value": 0.35}'

Aturan

Aturan Nilai
Menetapkan nama 1–128 karakter dari A-Z a-z 0-9 . _ - : — namespace secara bebas (audio.master, graphics:shadows)
Nilai-nilai JSON apa pun: nomor, string, boolean, array, objek, null
Pengaturan per pemain, per game 200
Byte per pemain, per game 2 MB secara default — operator dapat menaikkan atau menurunkannya, dan dapat memberikan tunjangan berbeda pada satu permainan

Satu pengaturan dapat menggunakan seluruh tunjangan byte; tidak ada batasan per nilai yang lebih kecil dan terpisah.

Status Arti
400 Nama pengaturan yang buruk, atau isi yang tidak {"settings": {...}} / {"value": ...}
404 Tidak ada jawaban game untuk slug itu, atau (single-key GET) tidak ada yang disimpan di bawah kunci itu
413 Melebihi tunjangan — terlalu banyak pengaturan, atau terlalu banyak byte. Pesan tersebut menyatakan batasnya

Kumpulan yang berisi satu kunci buruk tidak akan menulis satu pun kunci bagus. Pengaturannya per pemain dan per permainan: tidak ada kebocoran antara dua pemain, atau antara dua permainan pemain yang sama. Mereka bertahan hidup a game dinonaktifkan atau dihapus dari daftar, karena itu adalah data pemain, bukan data game.

Sesi

GET /api/v1/games/{slug}/sessions/mine

Sesi aktif penelepon untuk game ini. myTurn Dan deadline diurai dari status skrip summary objek (lihat Skrip Permainan). pausedAt diatur sementara a gigih sesi dijeda tanpa ada orang di dalamnya, dan null jika tidak.

Sesi terikat ruangan sudah termasuk. A ruang waktu nyataSesi terikat mencantumkan setiap manusia yang duduk saat ruangan dimulai, sehingga muncul di sini untuk masing-masing manusia saat ruangan tersebut dimulai active. Kursi AI tidak ada players. Meninggalkan ruangan, atau menutup ruangan, tidak menghapus siapa pun dari sesi, sehingga tetap berada dalam daftar ini sampai sesi itu sendiri berakhir — kecuali dalam keadaan bergabung dalam proses ruangan, di mana pemain yang keluar memberikan tempat duduknya dan dikeluarkan dari sesi, dan pemain baru yang diterima di tengah pertandingan ditambahkan ke dalamnya. Tidak ada id ruangan dalam respons: gunakan GET /api/v1/realtime/rooms/joined untuk kamar penelepon, dan cocokkan kamar mereka gameSessionId melawan sessionId.

Pemulihan dan kepergian yang jelas

GET /api/v1/games/{slug}/sessions/{sessionId}/recovery mengembalikan snapshot yang efektif, memulihkan, nilai retensi dan transportasi. Peserta dan pemilik permainan boleh membacanya. Satuan waktu dan semuanya bidang respons dijelaskan dalam Siklus hidup sesi dan pemulihan.

POST /api/v1/games/{slug}/sessions/{sessionId}/leave melepaskan keanggotaannya di dunia yang persisten tanpa ruang waktu nyata. Ia tidak membutuhkan tubuh dan kembali 204; kepergian manusia terakhir mengakhiri dunia. 403 berarti bukan anggota, 404 berarti tidak ada sesi, 410 berarti berakhir, dan 409 berarti tidak persisten sesi atau sesi terikat ruangan. Untuk sesi terikat ruangan, gunakan ruangan itu /leave titik akhir. Penutupan soket saja yang mempertahankan keanggotaan. Melihat memutuskan hubungan dan pergi.

POST /api/v1/games/{slug}/sessions/ai

Membuat sesi latihan terhadap kursi AI platform: id pengguna tetap 00000000-0000-4000-8000-00000000a1a1, nama belakang "Rumah". Backend resmi game ini memainkan AI — tidak ada layanan bot eksternal.

{ "sessionId": "0f8fad5b-d9cb-469f-a165-70867728950e" }

Penjaruman

Sebuah skrip mendeklarasikan bentuk kecocokan yang diterimanya game.queues. Sebuah permainan tanpa diterima deklarasi memiliki satu implisit default antrian (dua tim satu). Wadah saat ini /describe pembaca melakukannya bukan impor queues, jadi game container menggunakan bentuk implisit 1v1 itu. Klien yang tidak menyebutkan nama antrian akan mendapatkan permainannya terlebih dahulu.

Hingga delapan antrian skrip dipertahankan. Kunci dipangkas, huruf kecil, tidak kosong dan paling banyak 32 karakter; kunci duplikat simpan yang pertama. teams dijepit ke 2–8 dan teamSize sampai 1–16; bentuk yang melebihi 32 total pemain dibuang. Deklarasi yang tidak valid dapat kembali menjadi implisit 1v1, jadi verifikasi bentuk yang efektif dengan GET /queues setelah diterbitkan.

GET /api/v1/games/{slug}/queues

[
  { "key": "duos", "teams": 2, "teamSize": 2, "players": 4 }
]

POST /api/v1/games/{slug}/matchmaking

Mengantrekan penelepon untuk pasangan elo terdekat. Dapat diulang ?queues= nama kunci kueri a bagian dari bentuk-bentuk itu (misalnya 1v1 dan 2v2, bukan 3v3). Pencocokan hanya mengisi tiket dengan bentuk yang diperbolehkan. Misalnya:

POST /api/v1/games/{slug}/matchmaking?queues=solo&queues=duos
Authorization: Bearer <token>

Gunakan kunci yang dikembalikan oleh GET /queues. ?queue=solo memilih satu bentuk; jika keduanya queue Dan queues disediakan, kuncinya digabungkan dan dihapus duplikatnya tanpa membedakan huruf besar-kecil. Kunci yang tidak diketahui adalah 404; daftar kosong setelah validasi 400. Kembali 409 jika penelepon sudah mengantri atau pada batas sesi bersamaan.

Pencarian dimulai di pita elo sempit dan melebar saat tiket menunggu (default 100, +10/s). Status: queued, matched, cancelled, expired (menunggu melewati batas, default 300 detik, tanpa menemukan siapa pun — tawarkan permainan latihan daripada berputar). Pesta adalah a ruang waktu nyata: POST /api/v1/realtime/rooms/{id}/matchmake (tuan rumah, lobi) memasukkan seluruh daftar sebagai satu tim.

{
  "ticketId": "b3b7c8d2-5c1e-4f3a-9e2d-1a2b3c4d5e6f",
  "status": "queued",
  "sessionId": null,
  "waitedSeconds": 12,
  "searchEloBand": 220,
  "maxWaitSeconds": 300
}

Game dapat ikut serta batas waktu dimulai pada starhermit.txt: matchmaking.max_wait_seconds memulai pertandingan yang kurang terisi setelah menunggu, dan matchmaking.ai_players membatasi berapa banyak kursi kosong yang menjadi AI. Kursi lainnya tetap kosong. Manusia seutuhnya pertandingan dimulai lebih awal. maxWaitSeconds melaporkan pengaturan game itu; tiket ini tetap ada queued hingga perjodohan dimulai, alih-alih berakhir pada batas tunggu global.

GET /api/v1/games/{slug}/matchmaking

Mengembalikan tiket terbaru penelepon, atau 404. A matched tiket dilaporkan hanya sementara itu sesi masih active. Setelah pertandingan berakhir inilah 404 jadi lobi menawarkan pertandingan baru alih-alih menunjuk pada id sesi yang mati.

Undangan

POST /api/v1/games/{slug}/invites

Badan permintaan:

{ "toUserId": "9b2f8c1a-1111-4222-8333-444455556666" }

Targetnya haruslah teman (403 jika tidak — lihat Teman-teman); 409 pada undangan duplikat atau saat salah satu pemain berada pada batas sesi. Yang diundang juga menerima a game_invite peristiwa mendorong soket obrolan mereka, dengan kind: "session".

Mengundang teman ke dalam permainan yang sedang berlangsung

Tambahkan sesi tempat Anda bermain:

{ "toUserId": "9b2f8c1a-1111-4222-8333-444455556666", "sessionId": "3f0c…" }

Menerima kalau begitu akui teman itu pada sesi lari itu alih-alih memulai yang baru — mereka menjadi pemain dalam segala hal (soket, ctx.players, memulihkan, menghubungkan kembali). Game Anda memutuskan apakah akan memerlukannya: platform meminta skrip game.onMembershipChange(ctx) atau wadah POST /sessions/{id}/members, dan permainan yang tidak menolak setiap bergabung. Aturan:

  • Sesi tersebut harus merupakan sesi aktif dari game ini Anda bermain di (403 jika tidak, 410 jika sudah berakhir), temanmu pasti belum ada di dalamnya (409), dan tidak boleh termasuk dalam ruang real-time (409 — mengundang melalui ruangan, yang tempat duduknya adalah roster).
  • Responsnya membawa targetSessionId; sessionId tetap null sampai undangannya diterima.
  • Saat menerima semuanya diperiksa lagi. Jika permainan menolak (penuh, tertutup…) penerimaannya adalah a 409 dan undangannya tetap tertunda. Jika pertandingan telah berakhir undangannya adalah dibatalkan dan menerima jawaban 410 — itu tidak pernah berubah menjadi permainan baru.
  • Hanya batasan sesi serentak milik orang yang diundang yang berlaku. Anda dapat menyimpan satu undangan tertunda per teman per tujuan, sehingga undangan ke pertandingan Anda dan undangan ke permainan baru dapat dilakukan secara bersamaan.

Platform yang dibangun sebelum fitur ini diabaikan sessionId dan memulai sesi baru saat menerima; targetSessionId dalam tanggapannya memberi tahu Anda mana yang Anda dapatkan.

Undangan mana yang harus Anda kirimkan? Menerima undangan polos (no sessionId) membuat sesi baru untuk kedua pemain tersebut. Jika pengundang sudah duduk di a ruang waktu nyata (lobi dengan tempat duduk), undang mereka ke ruangan itu — POST /api/v1/realtime/rooms/{id}/invites — jadi pilihlah tempat duduk mereka di meja tempat Anda berada. Keduanya memberi tahu orang yang diundang dengan cara yang sama, jadi jangan pernah mengirimkan keduanya untuk satu undangan: itu akan memberi tahu dua kali.

Bagikan tautan (undangan melalui URL)

Alur undangan di atas mengharuskan kedua pemain sudah berteman. Untuk mengundang seseorang yang ada belum ada di platform (atau belum menjadi teman), sebuah permainan dapat membagikan a berbagi tautan — URL ke dasbor web yang mengotomatiskan keseluruhan orientasi:

https://dashboard.starhermit.com/game-invite/<userId>/<gameSlug>
  • <userId> — ID pengguna pemain yang berbagi. Klien game sudah memilikinya: itu adalah sub klaim token peluncurannya (implementasi referensi catur memaparkannya sebagai Net.userId).
  • <gameSlug> — siput permainan (game_scope mengeklaim). Game tanpa skrip resmi atau backend container menggunakan id game GitHub (GUID) sebagai gantinya; dasbor menerima keduanya.
  • String kueri opsional — milik Anda. Apapun setelahnya ? diteruskan ke game Anda tanpa perubahan: …/game-invite/<userId>/<gameSlug>?room=K7MP2X&map=arena membuka permainan Anda di https://<game-id>.starhermit.com/…?room=K7MP2X&map=arena. Gunakan untuk menjatuhkan penerima secara langsung ke dalam ruangan, tingkat atau lobi. Itu bertahan saat penerima masuk, dan ditambahkan ke Anda URL game daripada mengganti apa pun di sana. Token peluncuran masih tiba di #game_token= pecahan, sehingga keduanya tidak pernah bertabrakan. Kodekan URL nilai yang Anda masukkan ke dalamnya.

Saat penerima membuka tautan, dasbor (bukan game) yang melakukan bagian undangan teman otomatis — tidak ada titik akhir backend baru yang terlibat, ini menyusun API yang sudah ada:

  1. Masukkan mereka (OAuth melalui penyedia langsung), atau gunakan kembali sesi yang ada. Niat penautan bertahan selama proses masuk pulang pergi.
  2. Menampilkan dialog persetujuan yang memberi nama pembagi dan gamenya teman yang berbagi: ia menerima permintaan pertemanan yang tertunda dari si pembagi jika ada, jika tidak, ia akan mengirimkannya (POST /api/v1/me/friend-requests).
  3. Meminta mereka untuk memilih nama panggilan jika akun mereka tidak memiliki nama panggilan profil (permainan menampilkan nama panggilan profil — lihat Profil).
  4. Meluncurkan game (platform yang dihosting https://<game-id>.starhermit.com salin, dengan token peluncuran di #game_token= fragmen seperti biasa).
  5. Mengirim mainkan undangan kembali ke pembagi dengan POST /api/v1/games/{slug}/invites — jadi tautan berbagi berakhir seperti undangan permainan biasa yang diterima oleh pembagi (sulang di dasbor, balon desktop, atau daftar undangan permainan itu sendiri). Jika permintaan pertemanan masih tertunda, dasbor mengantri undangan bermain dan mengirimkannya secara otomatis setelah pembagi menerimanya.

Artinya bagi klien game Anda:

  • Menawarkan tautan memerlukan satu baris pembuatan string — letakkan a "Bagikan tautan undangan" tombol di sebelah UI undang teman Anda dan salin URL ke papan klip. Melihat shareInviteLink() di implementasi referensi catur.
  • Tidak diperlukan penanganan khusus pada pihak penerima. Undangan penerima datang melalui alur undangan normal: undangan Anda GET .../invites polling menunjukkan kepada orang yang membagikan undangan masuk, menerimanya membuat sesi, dan penerima melihat sesi tersebut muncul GET .../sessions/mine (tunjukkan undangan keluar yang tertunda sehingga penantiannya terlihat — milik klien catur "diundang - menunggu" kartu).
  • Dasbor juga menggunakan URL ini sendiri: panel detail setiap game yang dihosting yang dapat dimainkan memiliki a Salin tautan undangan tombol, dan klien Windows menawarkan hal yang sama dari menu konteks permainan.

Pemutaran ulang

Pemutaran ulang adalah dokumen status akhir sesi yang telah selesai, disimpan oleh platform dan disajikan kembali ke pemain yang ada di dalamnya. Pemutaran ulang adalah fitur keikutsertaan dalam sebuah game, tidak aktif kecuali jika game tersebut memintanya mereka, karena tayangan ulang adalah penyimpanan yang disimpan platform selama rekor pertandingan ada.

Mintalah mereka di kode server Anda — replays: true di game objek untuk a naskah, "replays": true dari /describe untuk a server kontainer — dan publikasikan pembaruan untuk menerapkannya. Sebuah platform operator juga dapat menjawab permainan tertentu, jadi perlakukanlah replaysEnabled bidang GET /api/v1/games/{slug} sebagai jawabannya daripada menganggap pernyataan Anda adalah kata terakhir.

Kedua titik akhir di bawah kembali 404 untuk game yang pemutaran ulangnya tidak aktif, dan tidak ada yang disembunyikan darinya sesi permainan yang telah selesai — jadi klien yang menawarkan layar pemutaran ulang harus membacanya replaysEnabled Pertama.

Model sesi

  • Sidang status adalah "active" atau "finished".
  • Setiap sesi mendapat percakapan obrolan per sesi (ketik "game") agar lawan bisa ngobrol dan melakukan panggilan suara tanpa menjadi teman (melihat Mengobrol Dan Suara).
  • Batas sesi serentak per pemain ditetapkan secara default 20.
  • Sebuah permainan yang menyatakan persistent membuat sesi kosong dijeda bukannya mengakhirinya; menghubungkan ke satu melanjutkannya. Sesi yang dijeda diperhitungkan dalam batas tersebut. Lihat tutorial sesi persisten.
  • Sesi aktif yang tidak dimainkan oleh siapa pun adalah pensiun (status finished, ditinggalkan): 5 menit setelah yang terakhir ws/v1/games soket ditutup tanpa ada yang bergabung kembali, atau setelah 24 jam tanpa tindakan pemain. Sesi persisten malah dijeda. Hal ini juga berlaku untuk sesi di dalam ruangan; menutup kamar mereka tidak mengakhiri mereka.
  • Status tiket perjodohan: queued | matched | cancelled | expired.
  • Status undangan: pending | accepted | declined | cancelled.
  • Sesi dibuat melalui perjodohan, penerimaan undangan, titik akhir AI, atau permulaan ruang waktu nyata (sesi terikat ruangan — lihat Ruangan Waktu Nyata) — tidak ada "membuat lobi" titik akhir.
  • Pembaruan Elo berasal dari skrip resmi (eloUpdates) atau saluran kontrol penampung, mengatur peringkat yang digunakan untuk perjodohan dan dipublikasikan ke papan peringkat game (jenis skor elo). Klien tidak pernah bisa mengirimkan skor ke papan peringkat game secara langsung (melihat Papan peringkat).

Permainan WebSocket

ws/v1/games?sessionId={guid} (rute versi netral). Otentikasi dengan Authorization tajuk, ?ticket=, atau ?access_token=. Hanya peserta (403); saat terhubung dengan token peluncuran, itu game_scope harus cocok dengan permainan sesi. Sesi yang selesai adalah 410 {"error":"session_not_active"}. Opsional ?build= adalah buildId dari GET /games/{slug} — ketidakcocokan adalah 409 {"error":"build_mismatch"}.

  • Hanya bingkai teks, maks 16 KB per bingkai.
  • Sambungan yang lebih baru menggantikan sambungan lama: sambungan sebelumnya ditutup dengan PolicyViolation.
  • Menghubungkan ke jeda gigih sesi melanjutkannya sebelum perintah pertama Anda. Jika tidak dapat dilanjutkan (biasanya container masih dimulai), Anda mendapatkan file error bingkai dan soket ditutup dengan kode 1001; sesi tetap dijeda — sambungkan kembali dengan backoff.
  • Perpanjang token sebelum menyambung kembali. Token yang kadaluarsa ditolak 401 sebelum pemutakhiran, yang dilaporkan browser hanya sebagai kode dekat 1006 — tidak dapat dibedakan dengan terputusnya jaringan — sehingga kegagalan penyambungan kembali mungkin merupakan kegagalan autentikasi, dan membuka kembali hal yang sama ?access_token= URL tidak akan pernah dapat dipulihkan. Perbarui melalui POST /api/v1/games/{slug}/launch-token dan terhubung kembali dengan token baru. Pembaruan hanya berfungsi ketika token saat ini valid dan dalam waktu 12 jam (default) sejak peluncuran awal; setelah ditolak (401/403), berhenti menyambungkan kembali dan mengirim pemain kembali ke peluncur untuk mendapatkan token peluncuran baru.

Klien → server

Itu cmd amplop adalah kontrak platform; isi dari data ditentukan oleh backend otoritatif masing-masing game. Misalnya, implementasi referensi catur mengirimkan gerakan seperti ini:

{ "type": "cmd", "data": { "type": "move", "from": "e2", "to": "e4" } }

Untuk waktu proses skrip, perintah yang tahan lama dijalankan onPlayerMessage; ditandai secara eksplisit { "type": "input", "realtime": true, ... } data menggunakan kemenangan terbaru yang digabungkan ke kemenangan berikutnya onTick. Untuk runtime container, platform meneruskan perintah yang diautentikasi melalui aliran binernya dan container memiliki loop simulasinya. Dalam kedua kasus tersebut, platform menyediakan identitas pengirim tepercaya dan klien tidak pernah dapat menyampaikan status secara langsung. Server → klien

{ "type": "game", "data": { "...": "server-authorized message addressed to you" } }
{ "type": "error", "error": "Illegal move" }
{ "type": "presence", "userId": "9b2f8c1a-1111-4222-8333-444455556666", "online": true }
{ "type": "membership", "sessionId": "0f8fad5b-d9cb-469f-a165-70867728950e", "change": "joined", "userId": "9b2f8c1a-1111-4222-8333-444455556666", "name": "carol", "team": 0, "slot": 1 }
{ "type": "achievement", "data": { "key": "first-win", "name": "First Win", "description": "Win a match.", "icon": null, "points": 10, "unlockedAt": "2026-07-25T09:14:02Z" } }
{ "type": "resumed", "sessionId": "0f8fad5b-d9cb-469f-a165-70867728950e", "lostMs": 750 }
{ "type": "abandoned", "sessionId": "0f8fad5b-d9cb-469f-a165-70867728950e", "reason": "server_failure" }
  • game — pesan resmi server yang ditujukan kepada Anda.
  • error — kesalahan dari platform atau dari perintah terakhir Anda.
  • presence — disiarkan ke peserta lain ketika seseorang bergabung atau keluar.
  • membership — seseorang menjadi pemain di sesi ini di tengah pertandingan (joined) atau menyerahkan tempat duduknya (left); dikirim ke setiap peserta yang terhubung. Melihat Server Game Kontainer — anggota.
  • achievement — sebuah pencapaian yang baru saja diberikan oleh skrip game Anda, dikirim ke pemain yang menghasilkan saja. Jenis bingkai terpisah dengan sengaja: ini adalah kebenaran platform, bukan data game yang dikirimkan skrip. Dipancarkan dari jalur pembaruan tahan lama kedua runtime. Melihat Prestasi.
  • resumed — sesi berpindah tangan (pemulihan kontainer, atau proses Api lainnya mengambil alih sewa kepemilikan). Buang prediksi lokal; lostMs adalah kesenjangan sejak penulisan tahan lama terakhir. Lampiran pertama setelah handoff diumumkan satu kali per pemain.
  • abandoned — platform mengakhiri sesi tanpa pemenang atau pembaruan elo. Alasan: players_left, idle_no_players, superseded (pemain meminta permainan baru dengan judul ini), server_failure, restore_failed, operator_ended (pemilik game mengakhirinya), retention_expired (retensi pemulihan dunia yang dijeda telah berlalu). Disimpan sebagai { "kind": "abandoned", "reason": "…" }. A gigih sesi permainan tidak pernah berakhir hanya karena pemutusan hubungan atau tidak ada aktivitas — mereka malah berhenti sejenak. Manusia terakhir secara eksplisit pergi dunia yang berdiri sendiri masih bisa mengakhirinya players_left; kedaluwarsa pemulihan yang dikonfigurasi dapat mengakhirinya sebagai retention_expired.

Masukan waktu nyata diambil sampelnya, bukan diantri: platform menyimpan masukan dan tangan terbaru setiap pemain batch ke skrip Anda berikutnya onTick di dalam ctx.inputs. Mengirim lebih cepat dari game Anda tingkat centang tidak menghasilkan apa-apa, karena masukan antara dua tanda centang digabungkan satu. Kirim sesuai detak Anda, atau saat input berubah.

Perintah yang tahan lama untuk skrip diproses secara berurutan dan dibatasi secara terpisah dari waktu nyata masukan. Kirim tindakan terpisah ketika itu terjadi; mengirim gerakan terus menerus melalui waktu nyata yang ditandai jalur masukan. Batas perintah dapat bervariasi menurut game. Pemanggilan skrip juga dibatasi oleh game anggaran. Bingkai kesalahan WebSocket membawa pesan, bukan status HTTP. Skrip Anda harus menolak perintah yang tidak masuk akal, seperti gerakan tidak bergiliran.

Untuk a wadah game, perintah diteruskan ke container Anda saat perintah tersebut tiba, tanpa platform batas tarif pada mereka. Server Anda menerapkannya sendiri. Pembatasan laju input waktu nyata berlaku untuk skrip permainan saja.

Elo per pertandingan

Platformnya melakukannya bukan membatasi seberapa jauh peringkat dapat bergerak dalam satu pertandingan. eloUpdates (naskah) dan elo pesan kontrol (wadah) dibawa masing-masing pemain peringkat absolut baru, bukan perubahan, dan platform menerapkannya saat dikirim. Apa yang ditegakkannya:

  • Hanya pemain dalam sesi ini diperbarui. Id orang lain, dan kursi AI, dihilangkan.
  • Pembaruan diterapkan setiap kali server Anda mengembalikannya. Sesi itu platform berakhir (abandoned: pemain tersisa, menganggur, digantikan, kegagalan server, diakhiri oleh pemilik) diterbitkan TIDAK kamu berubah.
  • Peringkat tersebut ditulis ke kolom perjodohan berpasangan, dan ke papan elo permainan sebagai satu entri per pemain (peringkat terbaru mereka).
  • Pemilik game bisa mengatur ulang peringkat satu pemain sampai 1200.

Jadi ukuran ayunan adalah keputusan permainan Anda. Gunakan faktor K standar dan jepit kode Anda. Itu implementasi referensi catur menggunakan K = 32, jadi satu permainan bergerak a peringkat paling banyak 32 poin:

function eloAfter(mine, theirs, score /* 1 win, 0.5 draw, 0 loss */, K = 32) {
  const expected = 1 / (1 + Math.pow(10, (theirs - mine) / 400));
  const next = mine + K * (score - expected);
  return Math.round(Math.max(100, next));      // your floor, if you want one
}

Diagnostik pemilik dan webhook

Khusus pemilik. Token peluncuran dalam lingkup game tidak dapat mencapai hal ini.

GET /api/v1/games/{slug}/diagnostics

Cuplikan sesi langsung (koneksi aktif, selesai, langsung), pengukuran skrip terhadap CPU / anggaran memori/pernyataan, antrian perjodohan (penantian terlama dan seberapa jauh pelebarannya), dan kesehatan titik akhir webhook.

Webhook

GET/POST/DELETE /api/v1/games/{slug}/webhooks Dan POST .../{id}/resume. Hingga 5 titik akhir per permainan. Acara: session.created, session.finished (menghilangkan events untuk berlangganan keduanya). Itu rahasia penandatanganan dikembalikan sekali, saat membuat.

Platform POST JSON dengan:

  • X-Starhermit-Signature: t=<unix>,v1=<hmac-sha256> lebih "<t>.<body>"
  • X-Starhermit-Event-Id — peristiwa (kunci idempotensi; berulang di seluruh percobaan ulang)
  • X-Starhermit-Delivery — upaya ini

URL harus https dan tidak boleh ditetapkan ke rentang pribadi/loopback/CGNAT (dicentang di pendaftaran dan lagi sebelum setiap pengiriman). Pengalihan tidak diikuti. Titik akhir yang gagal mundur dan dinonaktifkan setelah kegagalan berturut-turut; resume membersihkan pemutus.

Waktu proses

Untuk game JavaScript, platformnya berjalan onTick menyapu pada tingkat yang dijepit yang diminta melalui game.tickRateHz; 0 menonaktifkan centang, dan permainan yang tidak meminta apa pun dicentang 0,25Hz — nyatakan tarif jika gameplay Anda bergantung pada centang. Sebuah container menggerakkan loop simulasinya sendiri dan menyatakan tarif yang diminta melalui /describe; platform menggunakan tarif tersebut untuk penjadwalan dan kebijakan snapshot, bukan untuk menghentikan permainan. Siklus hidup sebuah game

  1. Buat token peluncuran — POST /api/v1/games/{slug}/launch-token. Klien harus menyegarkannya sebelum masa berlakunya habis (klien referensi catur menyegarkan setiap 45 menit).
  2. Ambil status permainan — GET /api/v1/games/{slug} untuk info + statistik Anda; GET .../sessions/mine untuk permainan yang sedang berlangsung; GET .../invites Dan GET /api/v1/realtime/rooms/invites untuk undangan yang tertunda; GET .../replays/mine untuk sejarah kapan replaysEnabled; GET .../achievements untuk layar pencapaian.
  3. Temukan lawan, salah satu dari tiga cara:
    • Penjaruman: POST .../matchmaking, lalu jajak pendapat GET .../matchmaking setiap 3 detik sampai status adalah matched (responnya membawa sessionId). DELETE .../matchmaking untuk membatalkan.
    • Alur undangan: memilih teman dari GET /api/v1/me/friends (melihat Teman-teman), POST .../invites dengan { "toUserId": "..." }; panggilan orang yang diundang POST .../invites/{inviteId}/accept, yang membuat sesi. (Jika permainan Anda menempatkan pemain di a ruang waktu nyata pertama, undang mereka ke ruangan — pemberitahuan yang sama, tetapi menerima menempatkan mereka di meja yang sudah Anda ikuti.)
    • Latihan AI: POST .../sessions/ai.
  4. Muat sesi — GET .../sessions/{sessionId}.
  5. Hubungkan WebSocket — ws/v1/games?sessionId={guid} dengan token peluncuran, lalu kirimkan perintah sinkronisasi awal apa pun yang ditentukan oleh backend game — implementasi referensi catur, misalnya, mengirimkan {"type":"cmd","data":{"type":"sync"}}.
  6. Bermain - menukarkan cmd/game frame seperti yang ditentukan oleh backend, permukaan achievement bingkai, dan pegangan resumed dengan membuang prediksi dan meminta keadaan penuh.
  7. Hasil — backend otoritatif mengakhiri permainan; platform menerbitkan pembaruan elo ke papan peringkat dan, untuk game dengan memutar ulang, mengarsipkan keadaan akhir.
  8. Memutar ulang — GET .../replays/{sessionId} untuk keadaan akhir penuh.

Contoh: bentuk perintah catur

Bentuk muatan berikut ini contohnya: cara catur implementasi referensi mengisi data. Mereka ditentukan oleh naskah catur, bukan oleh platformnya — setiap game mendefinisikan kumpulan perintahnya sendiri dan menyiarkan muatan di backend otoritatifnya. Amplop perintah klien adalah cmd; termasuk amplop server umum game, error, presence, Dan achievement, dengan resumed/abandoned tambahan digunakan untuk pemulihan kontainer.
