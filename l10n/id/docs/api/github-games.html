Permainan GitHub

Publikasikan game dari repositori GitHub ke Pertapa Bintang, atau daftarkan game web yang sudah dihosting. Untuk permainan repositori, platform membaca starhermit.txt, mengkloning repo, dan menyajikannya di <slug>.starhermit.com. Karena /api Dan /ws diproksi dengan asal yang sama dari subdomain tersebut, yang dibutuhkan oleh game yang dihosting platform tidak ada konfigurasi berbasis CORS atau API. Komit yang disematkan mengontrol versi repositori mana yang aktif. Itu implementasi referensi catur diterbitkan dengan cara ini dan berfungsi sebagai contoh referensi model.

URL Dasar: https://api.starhermit.com. Semua rute berada di bawah api/v1/... dan memerlukan JWT kecuali disebutkan.

File klien yang dihosting dapat dideklarasikan masa pakai cache folder Dan asal CORS tambahan di dalam starhermit.txt. Kebijakan tersebut dipublikasikan dengan file klien; penggabungan bebas manifes tetap dipertahankan pengaturan yang ada, sementara manifes yang disediakan menggantikannya.

Manifesnya: starhermit.txt

Tempat starhermit.txt di root repo. Format: key=value garis, # memulai komentar.

name=Your Game
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html        # repo-relative HTML entry
cover=art/cover.png      # optional cover art for the library tile; or an https:// URL
description=One-line pitch\nSecond line   # optional; or description.file=DESCRIPTION.md
release_notes.file=CHANGELOG.md          # optional; or release_notes=inline text
owner=<starhermit user id>  # UUID from GET /api/v1/me; do not use username/nickname
# Choose at most one authoritative backend, or omit both for a browser-only game:
server=server.js         # sandboxed JavaScript; see game-scripts.md
# container.image=ghcr.io/owner/game@sha256:<64 lowercase hex>; see container-games.md

control.up=KeyW+ArrowUp | Move forward
control.shoot=Space | Shoot
  • Tidak ada slug kunci: platform menetapkan uid dan menggunakannya sebagai subdomain (<uid>.starhermit.com) dan namespace API game (/api/v1/games/<uid>/…).
  • cover (alias cover_art, coverart) adalah karya seni yang ditampilkan di ubin perpustakaan game: jalur yang berhubungan dengan file peluncuran, atau jalur absolut https:// URL. Opsional — tanpa ubin, ubin akan menampilkan favicon situs Anda. Baca ulang setiap penerapan, jadi mengubah baris akan mengubah sampulnya. Melihat Seni sampul untuk tanaman ubin.
  • description / release_notes (atau description.file / release_notes.file, nama yang mana a .md/.markdown/.txt file relatif terhadap manifes) adalah teks opsional untuk game Anda. Mereka dibaca ulang pada setiap penerapan cover. Melihat Deskripsi dan catatan rilis.
  • server mendeklarasikan backend JavaScript yang di-sandbox; melihat game-scripts.md.
  • container.image mendeklarasikan backend kontainer; melihat container-games.md. Itu harus disematkan intisari, dihosting di namespace pemilik GitHub yang terverifikasi pada registri yang diizinkan, dan dapat disertai dengan container.port, container.health, container.memory_mb, container.cpu, dan bukan rahasia container.env.* nilai-nilai.
  • Kedua kunci backend bersifat opsional untuk permainan browser murni, namun keduanya saling eksklusif satu sama lain.

Pengikatan kontrol default

Sebuah game dapat mendeklarasikan nol atau lebih tindakan browser desktop:

control.<action>=<code>[+<code>...][ | <label>]
  • Tindakannya menggunakan huruf kecil [a-z0-9_]{1,32} pengidentifikasi dan mempertahankan urutan nyata.
  • Kode adalah KeyboardEvent.code nilai-nilai; + memisahkan kunci alternatif untuk satu tindakan.
  • Label opsional ditampilkan di UI pemetaan ulang kontrol dan defaultnya adalah id tindakan.
  • Sebuah manifes dapat mendeklarasikan hingga 32 tindakan dan 4 kode per tindakan. Kode tidak dapat digunakan oleh dua tindakan. Garis kontrol yang tidak valid diabaikan.
  • Game dengan no control.* deklarasi tidak memiliki kontrol API/UI (404 "This game declares no controls."). Deklarasi dibaca ulang dari setiap build yang diterbitkan — setiap penerapan, unggahan folder dan mengganti bundle push. Langkah demi langkah: Tutorial: tambahkan kontrol ke game Anda.

Pemain dapat mengganti default ini per game melalui Game mengontrol API.

Daftarkan permainan

POST /api/v1/me/github-games

{
  "repoUrl": "https://github.com/HypeDriven/starhermit-chess",
  "displayName": "StarHermit Chess",
  "launchPath": "index.html"
}

Terlepas dari nama historisnya, repoUrl menerima tiga sumber peluncuran:

  1. A github.com/<owner>/<repo> gudang. Backend membaca manifesnya dan dapat menyebarkannya ke hosting StarHermit.
  2. URL Halaman GitHub yang sudah dihosting seperti https://owner.github.io/game/. Gudang identitas disimpulkan dari URL; URL itu sendiri diluncurkan, tanpa kloning atau pemasangan.
  3. Publik lainnya http:// atau https:// URL permainan web yang dihosting. Ini diluncurkan secara langsung dan tidak berpartisipasi dalam klaim kepemilikan GitHub.
  • displayName Dan launchPath adalah fallback opsional. Mereka berguna untuk repo pihak ketiga tanpa metadata manifes tepercaya; URL yang dihosting langsung adalah lokasi peluncurannya.
  • Untuk pemilik repositori terverifikasi, platform akan memvalidasi starhermit.txt.
  • Sebuah opsional server= naskah atau container.image= penyediaan backend permainan yang berwibawa; melihat game-scripts.md Dan container-games.md. Hosting kontainer terbuka untuk semua pengguna yang masuk di starhermit.com; penerapan yang dihosting sendiri dapat membatasinya ke daftar yang diizinkan operator.
  • Backend server yang dinyatakan memerlukan pemilik yang terbukti. Mengirimkan repo yang menyatakan server= atau container.image= tanpa login GitHub atau owner= buktinya adalah 403 (menyebutkan kedua bukti), bukan daftar khusus browser yang berpura-pura memiliki backend.
  • Batasan: 100 game per pengguna (dapat diganti oleh operator per akun). Mendaftarkan pengembalian duplikat 409.

Status pendaftaran/penempatan meliputi: InvalidUrl, LimitReached, Duplicate, MissingManualMetadata, MissingStarhermitTxt, InvalidLaunchPath, InvalidServerScriptPath, InvalidContainerImage, ServerProvisionConflict, RemovedByOwner.

Kesalahan menggunakan bentuk standar:

{ "error": "..." }

Tambahkan game dari folder lokal

POST /api/v1/me/github-games/upload → 201

Mitra untuk mendaftarkan URL: tidak ada repositori, dan tidak ada yang dikloning. Foldernya bepergian sebagai satu kesatuan .tar.gz pada badan permintaan dan platform menghosting isinya. Arsip yang sama format sebagai mendorong bungkusan, jadi kemasan yang sama bisa digunakan untuk keduanya.

Game yang dibuat memiliki a gameSlug dari awal, baik mendeklarasikan server atau tidak, jadi a unggahan khusus browser dapat digunakan kontrol, pengaturan per pemain, dia slot penyimpanan cloud, ruangan waktu nyata dan meluncurkan token seperti game lainnya.

client/           the game's files, published as-is
starhermit.txt    name= and launch= instead of the query parameters

Manifes bersifat opsional titik akhir ini — parameter kueri dapat memberikan nilai yang sama — dan klien StarHermit selalu mengirimkannya, dibuat dari bidang manifesnya. Pengiriman file di dalamnya build Anda masih layak dilakukan: build tersebut membuat build mendeskripsikan dirinya sendiri dan mengisi kolom tersebut terlebih dahulu, jadi begitulah dapat diunggah ulang tanpa mengingat nilai mana yang diperlukan. Melihat Itu starhermit.txt tampak untuk formatnya, dan perhatikan itu semuanya berdekatan dengan manifes diunggah — unggah bangunan yang dapat didistribusikan, bukan pohon sumber.

Kirim byte secara langsung — bukan data formulir multi-bagian — dengan Content-Type: application/gzip:

tar -czf game.tar.gz client/ starhermit.txt

curl -X POST "https://api.starhermit.com/api/v1/me/github-games/upload?displayName=My%20Game" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/gzip" \
  --data-binary @game.tar.gz

{
  "game": { "id": "...", "displayName": "My Game", "launchPath": "index.html", "hosting": { "hostingEnabled": true } },
  "bytesReceived": 4194304
}

Metadata diselesaikan dalam urutan ini, sehingga sebagian besar folder tidak memerlukan parameter kueri sama sekali:

  1. ?displayName= / ?launchPath= atas permintaan.
  2. name= / launch= di sebuah starhermit.txt di root arsip.
  3. index.html di akar client/ — digunakan sebagai jalur peluncuran ketika tidak ada nama lain yang menyebutkannya.

Catatan khusus untuk rute ini:

  • Permainan ini disiarkan langsung segera setelah panggilan kembali. Tidak ada hosting atau penerapan terpisah langkah: deployStatus adalah live Dan deployedCommitSha adalah null, karena tidak ada komitmen.
  • File tidak dapat dibuat ulang, sehingga platform tidak pernah memindahkannya dari mana pun. Sebuah permainan menambahkan cara ini membawa contentSource: upload dan mempertahankan versi yang diunggah hingga Anda memublikasikannya satu lagi. Dorong bangunan baru dengan titik akhir bundel atau unggah folder itu lagi.
  • Tidak ada repositori berarti tidak ada klaim. ownerLogin kosong, jadi tidak ada login GitHub yang bisa menandinginya; repoUrl membawa sintetis upload:<id> nilai daripada URL.
  • A server/image.tar ditolak di sini (422). Gambar server memerlukan permainan yang tersedia lampirkan, yang tidak ada sampai game tersebut ada — buat gamenya terlebih dahulu, lalu dorong gambarnya untuk /{id}/bundle.
  • Jalur peluncuran yang memberi nama file yang tidak terdapat dalam arsip ditolak (422) saat unggahan sedang berlangsung masih dalam tahap, daripada menjadi 404 untuk setiap pemain.

Batasannya sama dengan dorongan lainnya: lihat Batas unggahan.

Folder yang diunggah dapat membawa backend servernya sendiri

Jika arsipnya starhermit.txt mendeklarasikan logika server, unggahan menyediakannya juga — hal yang sama dilakukan oleh aliran repositori, tanpa repositori. Pilih satu gaya; menyatakan keduanya ditolak.

Pernyataan Apa yang terjadi
server=path/to/server.js Bagian belakang skrip. File tersebut berpindah di dalam folder yang Anda unggah, jadi sumbernya dibaca langsung dari arsip — tidak ada yang bisa diambil. Melihat game-scripts.md.
container.image=name@sha256:… Backend kontainer, disematkan seperti biasa. Melihat container-games.md. Gambar itu sendiri kemudian didorong ke /{id}/bundle.

Penolakan di sini menggagalkan keseluruhan pembuatan — tidak ada baris permainan setengah jadi yang bertahan:

  • server= memberi nama file yang tidak terdapat dalam arsip.
  • server= menunjuk ke luar file klien (../).
  • Mendeklarasikan keduanya server= Dan container.image=.
  • Meminta kontainer yang kontainernya dinonaktifkan, atau dari pemilik yang tidak menyetujuinya.

Seni sampul

Gambar yang ditampilkan pada ubin game Anda di perpustakaan. Aturlah dengan cara apa pun — apa pun yang Anda gunakan, itu anonim GET /api/v1/github-games/{id}/cover itulah yang menyajikannya:

  • Di bangunan Anda — a cover= masuk starhermit.txt, memberi nama gambar yang berhubungan dengan peluncurannya file atau mutlak https:// URL. Baca ulang setiap penerapan, sehingga repositori Anda tetap menjadi sumber kebenaran.
  • Diunggah — PUT /api/v1/me/github-games/{id}/cover dengan gambar yang dikodekan base64. Ini adalah apa dasbor webnya Kelola → Seni sampul lakukan, dan apa yang dapat dilakukan operator StarHermit untuk Anda.
PUT /api/v1/me/github-games/{id}/cover
Authorization: Bearer <token>
Content-Type: application/json

{ "imageBase64": "iVBORw0KGgoAAAANSUhEUg..." }

Sebuah unggahan menimpa manifesnya, dengan sengaja: penerapan yang membaca ulang starhermit.txt harus jangan pernah membatalkan karya seni yang dipilih seseorang dengan tangan. DELETE /api/v1/me/github-games/{id}/cover adalah jalan kembali - itu menghapus unggahan dan manifesnya cover= berlaku lagi.

PNG, JPEG, GIF, WEBP, BMP atau SVG, hingga 4 MB. Tipenya diendus dari byte, jadi a Content-Type Anda tegaskan tidak diperlukan atau dipercaya, dan byte yang bukan merupakan gambar yang dapat didekodekan ditolak dengan 400. Seorang kerabat cover= jalan harus berakhir di .png, .jpg/.jpeg, .gif, .webp atau .svg (TIDAK .., tidak memimpin /); nilai yang tidak dapat digunakan dihilangkan daripada gagal permainan.

Seni sampul adalah seni poster: kedua perpustakaan skalakan untuk mengisi ubin dan tanaman tengah apa pun fungsinya tidak cocok. Bentuk ubinnya tidak sama.

Permukaan Ubin Tanaman
klien Windows Potret 96×128 (3:4) Mengisi potret; seni yang lebih luas kehilangan sisinya
Dasbor web Persegi Mengisi kotak; seni yang lebih tinggi kehilangan bagian atas dan bawah

Pertahankan subjek di tengah sehingga kedua potongan terlihat tepat. Sampul SVG ditampilkan di perpustakaan web; itu Klien Windows tidak dapat memecahkan kode SVG, sehingga ubin malah menampilkan favicon. Sebuah permainan tanpa penutup semua kembali ke faviconnya (GET /api/v1/github-games/{id}/icon). Ikon diselesaikan dari URL yang Anda kirimkan dan, saat platform menghosting game tersebut, dari salinan yang disajikan <uid>.starhermit.com — jadi bundel yang diunggah dengan favicon di filenya masih mendapat ikon.

Angka penonton untuk game Anda

GET /api/v1/me/github-games/{id}/stats → GameStatsDto

Berapa banyak orang yang memainkan permainan kamu menambahkan. Terbatas untuk pemilik game — siapa pun bisa 404, jawaban yang sama seperti permainan yang tidak ada.

{
  "totalPlayers": 42,
  "playingNow": 3,
  "totalSessions": 130,
  "totalPlaytimeMinutes": 8140,
  "lastPlayedAt": "2026-07-29T08:45:24Z",
  "livenessWindowHours": 4
}
  • Hanya agregat. Anda mempelajari jumlah audiens Anda, bukan siapa saja yang ada di dalamnya.
  • totalPlayers penting orang yang berbeda, bukan sesi — seseorang yang bermain enam kali adalah satu pemain.
  • playingNow menghitung pemain berbeda yang sesinya belum berakhir Dan dimulai di dalam livenessWindowHours. Jendela itu penting: klien yang mogok atau kehilangan jaringannya tidak pernah mengirim sesi berakhir, dan tanpanya, baris-baris tersebut akan terbaca karena orang-orang masih bermain tanpa batas waktu.
  • totalPlaytimeMinutes penting sesi yang diselesaikan saja, mencocokkan angka waktu bermain per pengguna di activity.md. Sesi dalam penerbangan belum memberikan kontribusi apa pun.
  • lastPlayedAt adalah null untuk permainan yang belum pernah dimainkan siapa pun.

Angka-angka tersebut berasal dari buku besar peluncuran yang sama yang ditulis setiap klien (lihat activity.md), jadi a game yang pemainnya tidak pernah melaporkan peluncurannya akan dibaca sebagai nol.

Klaim kepemilikan

POST /api/v1/me/github-games/{id}/claim → GitHubGameDto

Ambil alih listingan yang ada saat Anda mengontrol repositorinya. Buktikan kepemilikan dengan menghubungkan login GitHub pribadi yang cocok dengan pemilik repositori, atau dengan melakukan owner=<your StarHermit user ID> ke repositori starhermit.txt. owner seharusnya menjadi UUID yang tidak dapat diubah dikembalikan sebagai id oleh GET /api/v1/me, bukan nama pengguna atau nama panggilan. Manifes metode mendukung repositori milik organisasi, yang tidak disimpulkan dari organisasi GitHub pribadi keanggotaan.

Jika berhasil, listingan yang ada akan menyimpan ID/riwayatnya, dikelola oleh penggugat, dan diperbarui metadata dan deklarasi backend yang dikontrol repositori, dan mengantri hosting jika tersedia. Itu pengirim sebelumnya kehilangan akses pengelolaan cakupan pemilik. Mengklaim listingan yang sudah Anda kelola menyinkronkannya kembali daripada mengembalikan konflik.

Penyimpanan metadata identitas GitHub {"login":"…"}; tautkan akun GitHub Anda melalui alur OAuth (lihat auth.md). Periksa status tautan dengan GET /api/v1/me/github → { linked, login }. Lihat tutorial klaim langkah demi langkah untuk penemuan, keduanya bukti metode, validasi, pengambilalihan, dan pemecahan masalah.

Mentransfer kepemilikan

Perpindahan adalah a penawaran tertunda yang diterima penerima, bukan langkah langsung — sebuah permainan (dan itu byte yang dihosting, yang dihitung terhadap penerima) tidak dapat dimasukkan ke akun lain tanpa byte tersebut katakan-begitu.

POST /api/v1/me/github-games/{id}/transfer (pemilik) mencatat penawaran dan pengembalian a GameTransferOfferDto; permainan tetap menjadi milik Anda sampai diterima.

{ "toUserId": "<user id>" }

// GameTransferOfferDto
{
  "id": "<offer id>",
  "gameId": "<game id>",
  "gameTitle": "StarHermit Chess",
  "fromUserId": "<guid>", "fromUsername": "alice",
  "toUserId": "<guid>",   "toUsername": "bob",
  "status": "pending",
  "createdAt": "2026-10-17T16:00:00Z"
}
  • Penerima melihatnya di bawah GET /transfers/incoming dan menerima dengan POST /transfers/{offerId}/accept. Penerimaan menggerakkan permainan Sekarang, diperiksa pada saat itu terhadap jumlah permainan dan tunjangan hosting milik penerima — sehingga penawaran tetap dapat dibuat gagal mendarat jika penerima berada pada batasnya. Mungkin saja sebaliknya POST /transfers/{offerId}/decline.
  • Penawar melihat penawaran mereka yang tertunda di bawah GET /transfers/outgoing dan dapat menariknya dengan POST /transfers/{offerId}/cancel.
  • Semuanya diperiksa ulang saat diterima: permainan dipindahkan, dihapus, atau ditunjuk kembali sejak tawaran dijawab GameUnavailable, dan menawarkan permainan yang sama lagi menggantikan tawaran yang masih menunggu keputusan, jadi dua penawaran langsung ditayangkan tawaran satu permainan tidak bisa keduanya diterima.

Dorong bundel game

POST /api/v1/me/github-games/{id}/bundle menerbitkan keluaran yang dibuat tanpa meminta StarHermit mengkloningnya lagi. Penelepon harus memiliki game yang terdaftar. Kirim .tar.gz byte secara langsung—tidak data formulir multi bagian—dengan Content-Type: application/gzip:

client/            optional static client files; must include the registered launch file
server/image.tar   optional output from `docker save`
starhermit.txt     optional manifest copy for bundle portability
remove.txt         merge only: client-relative paths to delete, one per line

Setidaknya client/ atau server/image.tar harus ada (penggabungan juga mungkin saja remove.txt). File klien ditukar secara atom. SEBUAH gambar server dimuat, intisari disematkan oleh platform, dan mengantrikan penerapan kontainer restart pada gambar itu. Gambar yang diunggah lebih diutamakan daripada referensi registri manifes, dan lebih dari a server= garis; sebuah manifes yang menyatakan keduanya server= Dan container.image= ditolak sebelum apa pun dimuat. Apa pun yang ada di arsip akan diabaikan.

Mengunggah gambar itu sendiri merupakan deklarasi. Jika game belum memiliki backend server — an folder yang diunggah yang menyatakan tidak ada — mendorong server/image.tar ketentuan satu dari intisari saja dimuat, di bawah gameSlug permainan sudah ada. Anda tidak perlu memberi nama pada gambar yang diberi pin intisari di a manifes pertama, yang berbentuk lingkaran: definisi harus ada sebelum dapat menerima gambar, dan gambar adalah satu-satunya hal yang dapat menggambarkannya.

Pendorongan ulang akan menerapkan kenop kontainer yang dinyatakan manifesnya, dan hanya itu saja. Termasuk starhermit.txt dalam bundel dengan yang diubah container.port, container.health, container.memory_mb atau container.cpu dan penerapan mengambilnya saat restart; tinggalkan kenop dan itu menyimpan apa pun yang Anda atur terakhir kali. Hilangkan seluruh manifes dan jangan tinggalkan apa pun tentang penerapannya berubah kecuali gambar.

Seikat milik siapa starhermit.txt membawa sesuatu yang dapat digunakan name= Juga mengganti nama daftar permainan untuk itu - pembaruan nama tampilan berjalan seiring dengan dorongan. Meninggalkan name= keluar (atau hilangkan manifes) untuk disimpan nama saat ini.

Klien StarHermit membuat bundel ini untuk Anda, dari sebuah folder atau satu .tar:

  • File klien — folder distribusi permainan, atau a .tar itu. Sebuah folder dikemas di bawah client/; a .tarEntrinya ditempatkan kembali di sana (arsip sudah ada di bawah client/ tersisa sendirian). hanya ustar — Arsip nama panjang GNU dan PAX ditolak, karena berarti menyimpannya kembali menulis ulang blok metadata yang memberi nama entri berikut.
  • Server khusus — folder distribusi server, atau docker save .tar dengan sendirinya. Dari folder hanya manifes dan image.tar diunggah: gambar sudah berisi milik Anda file milik server sendiri, jadi mengemas sisanya akan mengirimkan gigabyte untuk dibuang oleh platform.

Dalam kedua kasus tersebut starhermit.txt dapat diedit dalam dialog. Apapun itu build yang dipilih membawa mengisi kolom terlebih dahulu, dan apa pun yang disimpannya ditulis di root bundel - jadi sebuah build tanpa manifes dapat dipublikasikan, dan build yang dikirimkan sebagai a .tar masih bisa mendapatkan manifesnya diperbarui.

Pembaruan sebagian: ?mode=merge

Dorongan adalah a mengganti kecuali Anda bertanya sebaliknya: arsip adalah keseluruhan permainan, dan apa pun yang tidak ada di dalamnya itu hilang. ?mode=merge (HTTP dan soket unggahan sama) menjadikannya a tambalan dari klien langsung files — jawaban untuk mengunggah ulang gigabyte aset yang tidak diubah untuk perbaikan satu file.

printf '%s\n' '# one client-relative path per line; a directory removes everything under it' \
    'assets/old-music.ogg' 'levels/cut/' > remove.txt
tar czf patch.tar.gz client/index.html client/js/app.js remove.txt

curl -X POST "https://api.starhermit.com/api/v1/me/github-games/$GAME_ID/bundle?mode=merge" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/gzip" \
  --data-binary @patch.tar.gz

Dengan mode=merge:

  • file di bawah client/ ditambahkan atau ditimpa
  • jalur di root remove.txt (# komentar; suatu direktori menghapus seluruh subpohonnya) dihapus
  • setiap file langsung lainnya tetap sama seperti aslinya

Pohon yang digabungkan dipentaskan sebagai salinan dan ditukar secara atom — pemain melihat game lama atau game tersebut yang benar-benar baru, belum pernah dicampur. Hasilnya dibatasi oleh pertandingan tunjangan, bukan uploadnya, jadi sebuah game tidak bisa berkembang melewati batasnya satu patch kecil dalam satu waktu. Penggabungan hanya tentang file klien; A server/image.tar dimuat persis seperti pada penggantian. Sebuah tambalan yang membawa no starhermit.txt daun sampul seni seperti itu.

Penggabungan ditolak (409/422, tidak ada yang berubah) saat game belum dipublikasikan, kapan akan menghapus file peluncuran, atau kapan remove.txt poin di luar permainan. A remove.txt di a penggantian biasa juga ditolak (422), karena itu hanya bisa berarti sesuatu yang tidak Anda maksudkan berniat. mode harus replace (standar) atau merge; hal lainnya adalah 400.

Parameter yang sama berfungsi pada soket: ws/v1/game-upload?gameId=…&mode=merge. Itu ready bingkai menggemakannya sebagai "apply":"merge".

Titik akhir memperbarui game terdaftar yang sudah ada; itu tidak pernah membuat rekor permainan — untuk itu, lihat menambahkan game dari folder lokal. Dia Bisa penyediaan permainan backend server, sebagai efek samping memuat gambar server ke dalam game yang tidak ada. Lihat tutorial penerbitan server khusus.

Unggah dari CI/CD

Jangan menyimpan token OAuth interaktif dalam rahasia repositori. Masuk melalui OAuth sekali dan gunakan sesi itu untuk menambahkan kunci penerapan yang diberi label terpisah POST /api/v1/me/public-keys. CI pekerjaan kemudian dapat menandatangani /auth/public-key/challenge, tukarkan di /auth/public-key/complete, dan gunakan token akses 15 menit yang dikembalikan pada titik akhir bundel ini.

Kunci penerapan bertindak sebagai akun pemiliknya, sehingga akun tersebut harus memiliki game target. Itu tidak bisa tambahkan kunci lain atau cabut kunci lainnya. Ia dapat mencabut dirinya sendiri melalui /me/public-keys/current; mengelola pendaftaran dan kunci lain dari sesi yang diautentikasi OAuth. Gunakan satu kunci per lingkungan sehingga satu alur kerja dapat dinonaktifkan tanpa menghentikan alur kerja lainnya. Arsip selesai secara kasar 100 MB harus menggunakan transport WebSocket dibawah ini.

Melihat Unggah build dari CI/CD dengan kunci publik terdaftar OAuth untuk pembuatan kunci, penyiapan rahasia GitHub, skrip penandatanganan/pengunggah tantangan lengkap, statis dan tata letak bundel kontainer, dan alur kerja Tindakan GitHub.

Unggah melalui WebSocket

GET /ws/v1/game-upload (meningkatkan) - gunakan ini untuk apa pun yang berukuran lebih dari 100 MB.

CDN di depan API menolak isi permintaan HTTP secara kasar 100 MB dengan a 413 itu sendiri. Penolakan itu tidak pernah sampai ke platform, jadi tidak ada gunanya limitBytes dan muncul di no log Anda dapat membaca - a 413 dengan tidak limitBytes bidangnya adalah CDN, bukan tunjangan permainan Anda, yaitu dua lipat lebih besar. Benar-benar realistis docker save akan memukulnya.

Bingkai yang dikirim setelah pemutakhiran WebSocket bukan merupakan isi permintaan, jadi batas atas tidak berlaku. Hanya transportasinya yang berbeda. Bingkai biner digabungkan menjadi byte yang sama dengan rute HTTP membaca, melalui jalur yang sama, dan setiap penolakan, izin, dan badan keberhasilan adalah HTTP rute akan dihasilkan - sehingga klien dapat berbagi satu jalur kode di keduanya.

wss://api.starhermit.com/ws/v1/game-upload?gameId=$GAME_ID&access_token=$TOKEN
wss://api.starhermit.com/ws/v1/game-upload?gameId=$GAME_ID&mode=merge&access_token=$TOKEN
wss://api.starhermit.com/ws/v1/game-upload?displayName=My%20Game&launchPath=index.html&access_token=$TOKEN

Lulus gameId untuk mendorong ke game yang Anda miliki (the /{id}/bundle rute); hilangkan dan lewati displayName/launchPath untuk membuatnya dari folder (the /upload rute). Tokennya masuk ke dalam string kueri karena browser tidak dapat menyetel Authorization header pada jabat tangan WebSocket; itu diperiksa sekali, saat jabat tangan, sehingga unggahan yang umur token aksesnya lebih lama tetap selesai.

Arah Bingkai Arti
pelayan → {"type":"ready","mode":"bundle","apply":"replace","limitBytes":N,"heartbeatSeconds":15} Tunjangan diselesaikan dan ruang kosong diperiksa. Mulai mengirim. mode adalah bundle atau create. apply adalah merge ketika Anda meminta pembaruan sebagian.
→ pelayan biner Arsipkan byte, dipotong sesuka Anda — server tidak pernah menyusun ulang pesan, jadi 256 KB–1 MB adalah ukuran default yang bagus. Jika digabungkan, bingkai Anda harus persis seperti itu .tar.gz.
pelayan → {"type":"ack","bytesReceived":N} Kemajuan penerimaan, kira-kira setiap 8 MB. Dorong bilah kemajuan Anda dari ini.
→ pelayan {"type":"complete"} Arsip telah dikirim secara lengkap.
→ pelayan {"type":"abort"} Menyerah. Dijawab dengan status: 499; tidak ada yang dipublikasikan.
pelayan → {"type":"progress","phase":"publishing","bytesReceived":N} Detak jantung setiap 15 detik saat unggahan mendarat. Abaikan mereka, tapi harapkan mereka.
pelayan → {"type":"result","status":200,...} Kesuksesan. Objek lainnya adalah isi respons HTTP kata demi kata (status adalah 201 untuk membuat).
pelayan → {"type":"error","status":413,"error":"...","limitBytes":N} Penolakan. status dan isi adalah apa yang akan dijawab oleh rute HTTP.

Tidak ada yang dipublikasikan sampai {"type":"complete"} tiba. Ini adalah satu-satunya perilaku tanpa HTTP setara, dan ini disengaja: penanda akhir arsip tetap hidup di dalam byte tar, jadi platform selesai membaca arsip yang tampak lengkap tanpa koneksi berakhir. Sebuah soket yang hilang begitu saja setelah byte terakhir akan diterbitkan persis seperti yang selesai - diam-diam mengganti permainan langsung dengan dorongan yang ditinggalkan. Menutup soket tanpa mengunggah bingkai tidak ada apa-apa.

Publikasi setelah byte terakhir Anda dapat memakan waktu, terutama untuk gambar server. Mengharapkan progress detak jantung saat itu selesai; jangan menganggap interval tenang sebagai kegagalan pengunggahan.

Batas unggahan

Semua rute unggahan — baik titik akhir HTTP maupun WebSocket — memiliki aturan yang sama.

Membatasi Nilai
Tunjangan disk per game 2 GB di starhermit.com (tunjangan dapat bervariasi berdasarkan game/penerapan)
File yang dihosting per akun 20 GB di semua permainan akun (dapat disesuaikan oleh operator per akun)
Penyebaran repositori 50 MB arsip
starhermit.txt / remove.txt 256 KB setiap; remove.txt mencantumkan paling banyak 10.000 jalur (422)
Pelaksanaan terapan saat streaming, jadi dorongan yang terlalu besar akan terhenti di tengah penerbangan

Upload atau push dipotong sesuai sisa kuota hosting akun (413 dengan limitBytes), dan penerapan repositori yang akan meneruskannya gagal dengan alasan menyebutkan tunjangan. Per-push dan per-game adalah nomor yang sama pada pergantian. Penggabungan dibatasi oleh dihasilkan ukuran permainan, jadi tambalan kecil yang akan membuat pohon hidup melebihi yang diijinkan akan ditolak.

Status Arti
400 mode bukan keduanya replace juga bukan merge.
409 Penggabungan terhadap game yang belum memiliki file yang dipublikasikan.
413 Atas tunjangan. Tubuh membawa { "error", "limitBytes" }. A 413 tanpa limitBytes adalah batas badan CDN ~100 MB, bukan ini — gunakan soket unggah.
422 Arsip rusak, atau konten tidak dapat digunakan (file peluncuran tidak ada, no client/, a server/image.tar pada rute pembuatan, penggabungan yang akan menghapus file peluncuran, remove.txt pada penggantian). Juga sebuah terpotong arsip — akibat biasa dari koneksi terputus di tengah pengunggahan.
507 Server tidak memiliki ruang saat ini. Ditolak sebelum tubuh dibaca ketika kapasitas publikasi tidak tersedia; coba lagi nanti.

Arsip tidak boleh lepas dari akarnya atau berisi tautan, dan hanya file dan direktori biasa saja yang lolos diekstraksi — symlink, hard link, dan node perangkat ditolak. git archive Header global PAX, ./-nama awalan dari tar -czf game.tgz ., dan nama file yang hanya berisi .. (sprite..png) diterima. A .. segmen jalur masih ditolak.

Batas tarif

Kirim, klaim, ubah URL, hosting, dan penerapan semuanya mencapai GitHub pada satu token platform bersama-sama mereka dibatasi hingga 10 permintaan per menit per akun (429, dengan Retry-After). Sebuah operator dapat menaikkannya untuk satu akun.

Aktifkan hosting

PUT /api/v1/me/github-games/{id}/hosting → GameHostingView ("Disebarkan ke pertapa bintang")

{ "enabled": true }

Sematkan penerapan

PUT /api/v1/me/github-games/{id}/deployment → GameHostingView

{ "commit": "<sha or branch>" }

commit adalah opsional. Menyematkan sha/cabang akan mengantri pemindahan; pemilihan GET /api/v1/me/github-games/{id}/deployment untuk status.

Ini ditolak untuk permainan yang tidak menyebutkan nama repositori (bundel yang diunggah): menyematkan komit adalah apa memindahkan game ke repositorinya, dan game yang dibuat bundel tidak memilikinya. Menyebarkan ulang game yang diunggah memverifikasi file masih dalam volume daripada mengambil github.com.

Pindahkan game ke URL baru

PUT /api/v1/me/github-games/{id}/url

{ "repoUrl": "https://github.com/you/new-repo", "displayName": "optional for a hosted URL" }

Baris tersebut bertahan — uid, <uid>.starhermit.com, waktu bermain, peringkat — dan diterapkan ulang dari tujuan. Tujuan github harus merupakan tujuan yang dapat dibuktikan oleh penelepon bahwa mereka dapat mengontrolnya (403 jika tidak), dan itu starhermit.txt tidak boleh menyebutkan nama a berbeda owner= (403). Sebuah skrip atau wadah backend dinonaktifkan kecuali tujuan menyatakannya.

Sesi langsung (pemilik)

GET /api/v1/me/github-games/{id}/sessions mencantumkan sesi aktif server game. DELETE .../sessions/{sessionId} mengakhiri satu melalui jalur pengabaian platform (tidak ada pemenang, tidak ya, alasan operator_ended). Itu mengembalikan kapasitas kursi yang diadakan sesi yang macet.

Publikasikan game Anda sendiri: panduan

Ada dua rute masuk. Jika game Anda berada di repositori git, ikuti langkah-langkah bernomor di bawah. Jika itu hanya sebuah folder di mesin Anda, satu panggilan akan menyelesaikan semuanya: tambahkan game dari folder lokal mendaftarkan permainan, menerbitkan file, dan membiarkannya tetap aktif — tidak ada pengalih hosting dan tidak ada pin komit, karena tidak ada repositori untuk itu jalur.

  1. Pilih sumber: mendorong repo yang berisi starhermit.txt di root (opsional mendeklarasikan a server.js skrip atau gambar kontainer), atau siapkan URL publik dari game browser yang sudah dihosting.
  2. Tautkan identitas GitHub Anda melalui aliran OAuth (lihat auth.md); verifikasi dengan GET /api/v1/me/github.
  3. Daftarkan permainannya: POST /api/v1/me/github-games dengan repositori atau URL game yang dihosting repoUrl.
  4. Hanya permainan repositori — aktifkan hosting: PUT /api/v1/me/github-games/{id}/hosting dengan { "enabled": true }.
  5. Hanya permainan repositori — sematkan komit: PUT /api/v1/me/github-games/{id}/deployment dengan { "commit": "<sha>" }. Komit yang disematkan mengontrol versi langsung.
  6. Pemain meluncurkan permainan: permainan repositori yang diterapkan disajikan di <slug>.starhermit.com; permainan yang dihosting langsung membuka URL yang dikirimkannya. Setiap pertandingan dengan a gameSlug — backend atau tidak — menerima token peluncuran dari POST /api/v1/games/<slug>/launch-token di fragmen URL (opsional dengan &session_id=<guid> untuk mengundang tautan dalam).

Untuk kontrak sisi klien selengkapnya — cara game membaca token peluncuran dan berkomunikasi dengan API — lihat panduan catur implementasi referensi.
