Penerbit

Permukaan penerbit: kelola organisasi dan anggota penerbit, buat dan unggah judul dan build perangkat lunak, serta kelola pencapaian, hak, dan definisi papan peringkat untuk judul Anda.

Menerbitkan game, bukan judul katalog? Anda tidak membutuhkan semua ini. Pemilik a game dengan skrip atau backend kontainer adalah penerbitnya dan mengelola papan peringkatnya dan prestasi di bawah /api/v1/me/github-games/{id}/… - melihat Tutorial: papan peringkat dan pencapaian untuk game Anda.

URL Dasar: https://api.starhermit.com. Semua rute memerlukan JWT ditambah klaim izin yang tercantum. Peran: PublisherMember, PublisherOwner. Klaim izin diberikan melalui peran; token yang dicetak membawa klaim izin.

Penerbit dan anggota

Awalan rute: api/v1/publisher.

Metode Jalur Penulis Keterangan
POS /api/v1/publisher JWT (Permission-publisher.content.manage) Buat penerbit; pencipta menjadi anggota dengan peran "Owner" → 201
MENDAPATKAN /api/v1/publisher JWT (Permission-publisher.content.manage) Daftar penerbit → Publisher[]
POS /api/v1/publisher/{publisherId}/members JWT (Permission-publisher.members.manage) + peran Owner Tambahkan anggota → 204
MENGHAPUS /api/v1/publisher/{publisherId}/members/{memberUserId} JWT (Permission-publisher.members.manage) + peran Owner Hapus anggota → 204 (pemilik tidak dapat dihapus)
MENDAPATKAN /api/v1/publisher/{publisherId}/members/{memberUserId} JWT (Permission-publisher.members.manage) + keanggotaan penerbit itu Dapatkan anggota → PublisherMember

Siapa yang dapat mengubah keanggotaan

Klaim izin menyatakan Anda dapat mengelola anggota penerbit di suatu tempat; tidak disebutkan yang penerbit. Oleh karena itu, kedua pemeriksaan tersebut berlaku:

  • Menambah dan menghapus anggota adalah Owner-hanya. Keanggotaan membawa otoritas pengelolaan konten setiap gelar penerbit, jadi anggota biasa yang dapat menambahkan anggota dapat mengabulkannya wewenang kepada siapa pun. Yang bukan pemilik mendapat 401.
  • Membaca keanggotaan memerlukan kepemilikan penerbit itu. Seorang penelepon di luar mendapat hal yang sama 404 sebagai pengguna yang bukan anggota, sehingga titik akhir tidak mengungkapkan apa pun tentang penerbit yang bukan Anda bagian dari.

Buat penerbit

POST /api/v1/publisher

{
  "name": "HypeDriven",
  "description": "..."
}

Pencipta menjadi anggota yang mempunyai peran "Owner".

Tambahkan anggota

POST /api/v1/publisher/{publisherId}/members

{ "userId": "<user id>" }

Judul dan build perangkat lunak

Metode Jalur Penulis Keterangan
POS /api/v1/publisher/software JWT (Permission-publisher.content.manage) Membuat/memperbarui judul perangkat lunak (isi = metadata judul; keanggotaan dalam penerbit sebenarnya dari judul tersebut diberlakukan)
POS /api/v1/publisher/software/upload JWT (Permission-publisher.content.manage + Permission-publisher.binary.publish) Dapatkan URL unggahan untuk sebuah judul → UploadUrlInfo[]
POS /api/v1/publisher/software/build/finalize JWT (Permission-publisher.content.manage + Permission-publisher.binary.publish) Selesaikan pembangunan dari aset yang diunggah → 204
MENDAPATKAN /api/v1/publisher/analytics/downloads?publisherId= JWT (Permission-publisher.content.manage) Jumlah unduhan per judul
MENDAPATKAN /api/v1/publisher/analytics/launches?publisherId= JWT (Permission-publisher.content.manage) Jumlah peluncuran per judul

Menerbitkan build memerlukan hibah penerbitan biner

Kedua titik akhir build memerlukan publisher.binary.publish di atas publisher.content.manage dan keanggotaan penerbit judul. Tanpa itu keduanya menjawab 403, sementara setiap titik akhir lainnya di halaman ini tetap berfungsi — Anda dapat membuat dan mengedit judul, menentukannya prestasi dan papan peringkat, dan memberikan hak; Anda tidak bisa mengirimkan file yang dapat dieksekusi.

Alasannya adalah apa itu build. Aset build diunduh oleh klien desktop dan dijalankan di mesin pemain dengan hak istimewa pemain, di luar kontrol Starhermit kotak pasir apa pun — tidak seperti a permainan browser, yang berjalan di browser. Jadi hak untuk mempublikasikan satu diberikan per akun oleh a Administrator Starhermit (the BinaryPublisher peran), tidak diperoleh dengan membuat penerbit. Tidak peran lain membawanya. Mintalah izin kepada administrator sebelum membuat alur pengunggahan titik akhir ini; itu juga dihapus ketika akun penerbit ditangguhkan.

Game browser tidak memerlukan semua ini: /api/v1/me/github-games pengiriman, unggahan folder, dan bundel mendorong tetap melayani mandiri untuk akun apa pun yang masuk.

Membuat atau memperbarui judul katalog

POST /api/v1/publisher/software menerima id (hilangkan untuk judul baru), publisherId, name, description, category, platform, releaseStatus, tags, Dan priceCents:

{
  "publisherId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "name": "Orbit League",
  "description": "A space racing game.",
  "category": "game",
  "platform": "windows",
  "releaseStatus": "released",
  "tags": ["racing"],
  "priceCents": 0
}

Sukses adalah 201 dengan judul. Hanya metadata judul yang diterima; jangan kirim keanggotaan penerbit atau objek aset di sini. Membuat penerbit kembali 201 tanpa objek penerbit; daftar GET /api/v1/publisher untuk mendapatkan ID-nya.

Dapatkan URL unggahan

POST /api/v1/publisher/software/upload

{ "titleId": "<title id>" }

Tanggapan - UploadUrlInfo[]:

[
  {
    "type": "executable",
    "uploadUrl": "...",
    "fieldKey": "..."
  }
]

type adalah salah satu dari "executable", "data", "metadata".

Selesaikan pembangunan

POST /api/v1/publisher/software/build/finalize → 204

{
  "titleId": "<title id>",
  "buildId": "<optional build id>",
  "version": "1.0.0",
  "releaseNotes": "...",
  "assets": [
    { "type": "executable", "checksum": "...", "fieldKey": "..." }
  ]
}

Alur kerja pembuatan katalog saat ini berupa pratinjau dan tidak menyediakan pengiriman biner produksi atau jaminan verifikasi konten atau pemindaian malware. Jangan perlakukan bangunan atau aset yang diterima status sebagai bukti bahwa suatu executable aman. Melihat ketersediaan fitur. Penerbitan game yang dihosting menggunakan API pengunggahan game.

Analisis

Kedua titik akhir mengembalikan id judul pemetaan objek JSON untuk dihitung:

{ "<titleId>": 42 }

Prestasi

Rute api/v1/publisher; semua rute manajemen pencapaian membutuhkan Permission-publisher.content.manage.

Titik akhir ini dikelola judul katalog prestasi saja. Mereka juga mengharuskan penelepon menjadi a anggota penerbit yang memiliki judul tersebut, dan mereka gagal ditutup untuk pencapaian yang dimilikinya permainan yang berwibawa — hal tersebut dideklarasikan oleh skrip game atau backend container, namun tidak dikelola penerbit (lihat Prestasi, Skrip Permainan, Dan Server Game Kontainer).

Metode Jalur Penulis Keterangan
POS /api/v1/publisher/titles/{titleId}/achievements JWT Ciptakan prestasi → AchievementDto
MENDAPATKAN /api/v1/publisher/titles/{titleId}/achievements JWT Buat daftar pencapaian sebuah judul → AchievementDto[]
MENDAPATKAN /api/v1/publisher/achievements/{id} JWT Dapatkan satu prestasi → AchievementDto
MELETAKKAN /api/v1/publisher/achievements/{id} JWT Perbarui (semua bidang dapat dibatalkan) → AchievementDto
MENGHAPUS /api/v1/publisher/achievements/{id} JWT Hapus → 204

Ciptakan sebuah prestasi

POST /api/v1/publisher/titles/{titleId}/achievements

{
  "key": "first_win",
  "name": "First Win",
  "description": "Win your first game.",
  "icon": "...",
  "secret": false,
  "points": 10,
  "visibility": "...",
  "criteria": "..."
}

icon, visibility, Dan criteria bersifat opsional. Pada PUT, semua bidang dapat dibatalkan. Melihat achievements.md untuk permukaan yang menghadap pemain.

Hak

Rute api/v1/publisher/entitlements; yang dibutuhkan kedua rute Permission-publisher.content.manage.

Metode Jalur Penulis Keterangan
POS /api/v1/publisher/entitlements/grant JWT Berikan judul kepada pengguna → 204
POS /api/v1/publisher/entitlements/revoke JWT Cabut judul dari pengguna → 204

Tubuh untuk keduanya:

{
  "userId": "<user id>",
  "softwareTitleId": "<title id>"
}

Papan peringkat

Rute api/v1/publisher/leaderboards; semua rute membutuhkan Permission-publisher.content.manage.

Metode Jalur Penulis Keterangan
POS /api/v1/publisher/leaderboards/ JWT Buat definisi papan peringkat → LeaderboardDefinitionDto
MENDAPATKAN /api/v1/publisher/leaderboards/{id} JWT Dapatkan definisi → LeaderboardDefinitionDto
MELETAKKAN /api/v1/publisher/leaderboards/{id} JWT Perbarui (semua bidang dapat dibatalkan) → LeaderboardDefinitionDto
MENGHAPUS /api/v1/publisher/leaderboards/{id} JWT Hapus → 204

Buat papan peringkat

POST /api/v1/publisher/leaderboards/

{
  "name": "Global Elo",
  "scoreType": "...",
  "sortDirection": "...",
  "resetSchedule": "...",
  "minScore": 0,
  "maxScore": 4000,
  "scope": "...",
  "region": "...",
  "isActive": true,
  "softwareTitleId": "<optional title id>"
}

resetSchedule, minScore, maxScore, region, Dan softwareTitleId bersifat opsional. Pada PUT, semua bidang dapat dibatalkan. resetSchedule adalah daily, weekly, monthly atau never; hal lain adalah a 400 - melihat Atur ulang jadwal. Melihat leaderboards.md untuk permukaan yang menghadap pemain.

Publikasikan build: flow

  1. Pegang hibah penerbitan biner: langkah 3 dan 5 diperlukan publisher.binary.publish, yang a Hibah administrator Starhermit per akun. Melihat Menerbitkan build memerlukan hibah penerbitan biner.
  2. Buat penerbit: POST /api/v1/publisher dengan { name, description }.
  3. Buat judulnya: POST /api/v1/publisher/software dengan metadata judul di bawah.
  4. Dapatkan URL unggahan: POST /api/v1/publisher/software/upload dengan { titleId }.
  5. Unggah file kepada yang kembali uploadUrls.
  6. Selesaikan pembangunan: POST /api/v1/publisher/software/build/finalize dengan aset yang diunggah' { type, checksum, fieldKey } entri.
  7. Periksa ketersediaan distribusi: pratinjau katalog saat ini tidak menjamin pengunduhan produksi terverifikasi atau pemindaian malware; melihat tersedianya.
  8. Pengguna mengklaim dan mengunduh judul melalui katalog — lihat catalog.md.

Badan kesalahan bervariasi; melihat konvensi API.
