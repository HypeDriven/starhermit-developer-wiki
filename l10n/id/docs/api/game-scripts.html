Skrip Permainan

Permainan resmi StarHermit dapat didefinisikan dengan a file JavaScript tunggal dieksekusi di sisi server dalam kotak pasir Jint mesin. Skrip adalah satu-satunya otoritas dalam aturan permainan itu: skrip memvalidasi setiap perintah pemain, mengubah status, memutuskan apa yang mungkin dilihat setiap klien, menghitung Elo, dan mengakhiri permainan. Klien tidak memiliki otoritas. Halaman ini mendokumentasikan runtime JavaScript; permainan yang membutuhkan bahasa lain mungkin mengimplementasikannya Server Permainan Kontainer protokol. Keduanya menggunakan tampilan pemain yang sama API Permainan. Contoh yang berhasil adalah catur - implementasi referensi di HypeDriven/catur pertapa bintang.

Model eksekusi

  • Satu file JS per game, dieksekusi dalam a mesin Jint kotak pasir baru per pemanggilan. Tidak ada yang tersisa di memori di antara panggilan — semua status ada di dokumen yang Anda kembalikan.
  • Tidak ada lingkungan sekitar Date atau Math.random. Waktu dan keacakan diberikan sebagai: ctx.now (ms zaman) dan ctx.random (melayang masuk [0, 1)).
  • Platform memanggil skrip saat pemain mengirimkan perintah tahan lama, saat sesi dibuat, dan secara berkala onTick menyapu (lihat API Game — Waktu proses). Waktu nyata {type:"input", realtime:true} frame adalah pengecualian: frame tersebut di-buffer pada kemenangan terbaru dan dikirim sebagai batch ke tick berikutnya.

Titik masuk

Paparkan penangannya globalThis.game. Enam opsional statis deklarasi yang ada di samping mereka: tickRateHz menanyakan platform seberapa sering harus dipanggil onTick — nyatakan jika game Anda bergantung pada centang, karena permainan yang mengatakan tidak ada yang dicentang setiap empat detik sekali (lihat Tingkat centang), achievements mencatat pencapaian permainan (lihat Prestasi), replays meminta platform untuk menyimpan sesi Anda yang telah selesai (lihat Pemutaran ulang), persistent jeda sesi alih-alih mengakhirinya ketika semua orang pergi (lihat Sesi yang persisten), linkedAchievements sebutkan game lain yang pembukaan kuncinya Anda terima ctx.linkedAchievements (melihat Prestasi dari game lain), Dan queues menyatakan bentuk perjodohan menerima (lihat Permainan — Menjodohkan). Sebuah permainan yang menyatakan tidak ada antrian yang memiliki 1v1 implisit:

globalThis.game = {
  tickRateHz: 0, // turn-based: opt out of periodic ticks
  replays: true, // keep finished sessions as replays
  queues: [{ key: "duos", teams: 2, teamSize: 2 }],
  achievements: [
    { key: "first-win", name: "First Win", description: "Win a match.", points: 10 }
  ],
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

Deklarasi dibaca dengan mengevaluasi skrip Anda saat game diterbitkan atau diperbarui, tidak pada setiap pemanggilan — jadi nilai tersebut harus berupa nilai statis di game obyek. Publikasikan pembaruan untuk menerapkan perubahan.

  • createSession(ctx) — dipanggil ketika sesi dibuat (perjodohan, penerimaan undangan, latihan AI, atau ruang waktu nyata dimulai — lihat Sesi terikat ruangan).
  • onPlayerMessage(ctx) — meminta perintah klien tahan lama yang diterima melalui gameplay WebSocket. Masukan ditandai secara eksplisit realtime:true melewati titik masuk ini.
  • onMembershipChange(ctx) - opsional. Dipanggil ketika pemain bergabung atau meninggalkan sesi lari (a ruang bergabung dalam proses, atau sebuah mengundang ke permainan yang sedang berlangsung). ctx.players sudah mencerminkan perubahan, dan ctx.membership adalah { change: "joined" | "left", userId, name, team, slot }. Kembali { ok: false } untuk menolak bergabung; skrip tanpa pengait ini menolak setiap penggabungan. Cuti bersifat final, apa pun pengembaliannya. Pencapaian dan skor dapat menentukan hasil; A sessionState diabaikan.
  • onTick(ctx) — dipanggil oleh layanan pengatur waktu platform pada tingkat tick efektif; input realtime terbaru tersedia di ctx.inputs. Game yang diselesaikan hingga 0 Hz tidak menerima panggilan berkala, namun fungsinya harus tetap ada untuk memenuhi kontrak skrip.

Objek konteks

ctx = {
  now: 1721473200000,              // ms epoch, from the host clock
  random: 0.7231,                  // float in [0, 1), from the host RNG
  sessionId: "0f8fad5b-...",       // current session id
  pausedMs: 0,                     // persistent games only: total ms this session has spent paused
  players: [                       // session participants
    { id: "7c9e6679-...", name: "alice" },
    { id: "00000000-0000-4000-8000-00000000a1a1", name: "The House", ai: true }
  ],
  sessionState: { /* ... */ },     // this script's session document, or null
  playerStates: {                  // per-player documents (elo, history), or null
    "7c9e6679-...": { elo: 1200, wins: 4, losses: 2, draws: 1, /* ... */ }
  },
  message: {                       // onPlayerMessage only
    from: "7c9e6679-...",          // the authenticated user id — trusted
    data: { type: "move", from: "e2", to: "e4" }  // client payload — untrusted (example: a chess move)
  },
  inputs: [                        // onTick only; omitted when none are pending
    { from: "7c9e6679-...",        // authenticated sender id — trusted
      data: { type: "input", seq: 42, mx: 0.7, mz: -0.2 } }
  ]
}
  • Kursi AI (jika ada) ditandai dengan ai: true pada entri pemainnya.
  • Sebuah permainan yang menyatakan linkedAchievements juga mendapat ctx.linkedAchievements: { <playerId>: { <otherSlug>: [unlocked keys] } }, baca ulang setiap doa. Melihat Prestasi dari game lain.
  • Sesi terikat ruang (dimulai dari ruang waktu nyata) mendapatkan dua bidang ctx tambahan, ctx.room Dan ctx.presence, pada setiap doa — lihat Sesi terikat ruangan.
  • Jangan percaya apa pun dari ctx.message.data atau ctx.inputs[].data. Identitas tepercaya adalah yang sesuai from, yang dilampirkan server dari koneksi yang diautentikasi — klien tidak akan pernah dapat menyediakan atau memalsukannya.
  • Masukan ikut serta dalam pengelompokan dengan {type:"input", realtime:true, ...}. Tidak ditandai input perintah tetap tahan lama onPlayerMessage memerlukan kompatibilitas ke belakang. Input waktu nyata menggunakan satu slot tertunda per pengirim: pergerakan adalah kemenangan terbaru, sementara pass, shoot, Dan tackle tepi tindakan digabungkan sehingga sampel gerakan berikut tidak dapat menghapusnya sebelum centang berikutnya. Skrip harus menjepit dan memvalidasi setiap nilai saat menggunakan batch.

Tingkat centang

Platformnya berjalan onTick menyapu per sesi aktif pada tingkat yang dapat dikonfigurasi. Skrip Anda menanyakan tarif yang diinginkan dengan mendeklarasikan statis tickRateHz pada objek permainan, di samping titik masuk:

globalThis.game = {
  tickRateHz: 15,          // ask the platform to tick this game 15x/second
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};
  • Deklarasi dibacakan saat game Anda diterbitkan atau diperbarui, tidak pada setiap centang. Publikasikan pembaruan setelah mengubahnya.
  • Sebuah permainan yang menyatakan tidak ada rate dicentang pada 0,25 Hz — setiap empat detik sekali. Itu cukup memutuskan jam pergerakan atau batas waktu dan hampir tidak membebani platform, tetapi ini terlalu lambat untuk apa pun yang bergantung pada gameplay Anda. Jika onTick menggerakkan permainan Anda, nyatakan tarif yang Anda perlukan.
  • Permintaan dibatasi hingga maksimum platform (30Hz secara default), sehingga game dapat meminta lebih sedikit melebihi yang dimungkinkan oleh platform, namun tidak lebih dari itu. Mintalah 0 untuk menonaktifkan centang sepenuhnya untuk sebuah game yang hanya bereaksi terhadap perintah pemain.
  • Tarif mungkin pecahan: 0.5 adalah tanda centang setiap dua detik. Angka bukan nol terkecil adalah 0.01 Hz — angka positif yang lebih kecil dimunculkan daripada dibaca sebagai pilihan untuk tidak ikut serta, karena a pecahan kecil adalah permainan yang lambat. Berdetak tidak aktif hanya untuk 0 atau tingkat negatif. Hilang atau deklarasi yang tidak dapat digunakan (string, null, NaN) mengambil default 0,25 Hz.
  • Operator dapat mengganti tarif untuk permainan tertentu, ke arah mana pun.
  • Input waktu nyata adalah hasil terbaru di antara tick, sementara tepi tindakan terpisah tetap teratur. Penerima yang lambat mungkin melewatkan snapshot yang sudah usang tetapi tidak dapat menunda simulasi atau penerima lainnya.

Pemutaran ulang

Saat sesi selesai, platform dapat melanjutkan sesi finalnya sessionState sebagai memutar ulang — itu dokumen dilayani oleh GET /api/v1/games/{slug}/replays/{sessionId} (melihat API Game — Pemutaran ulang). Tayangan ulang disimpan selama rekor pertandingan adalah, jadi permainan Anda hanya mendapat satu jika diminta:

globalThis.game = {
  replays: true,           // keep finished sessions as replays
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};
  • Deklarasinya harus literal true atau false — apa pun yang lain dibaca sebagai tidak ada deklarasi, dan permainan yang menyatakan tidak ada yang tidak dapat diputar ulang.
  • Itu dibaca saat game Anda diterbitkan atau diperbarui. Publikasikan pembaruan setelah mengubahnya.
  • Operator platform dapat menjawab permainan tertentu, jadi deklarasinya adalah permintaan bukan jaminan. GET /api/v1/games/{slug} melaporkan jawabannya sebagai replaysEnabled — cabangkan UI replay Anda pada hal itu, bukan pada apa yang diminta skrip Anda.
  • Tidak ada hal lain yang berubah jika pemutaran ulang dinonaktifkan: status sesi Anda masih disimpan dan diteruskan kembali setiap doa sebagai ctx.sessionState, dan ini masih merupakan titik pemulihan kerusakan. Permainan yang luar biasa tanpa pemutaran ulang tidak mendapatkan salinan yang bertahan lebih lama dari sesi tersebut, jadi jawaban titik akhir pemutaran ulangnya 404.
  • Rancang finalnya sessionState agar layak untuk diputar ulang — log pergerakan, atau apa pun yang dibutuhkan klien Anda untuk merekonstruksi pertandingan. Implementasi referensi catur terus berlanjut state.game.moves dan melangkah itu melalui modul aturan yang sama yang dijalankan platform.

Sesi yang persisten

Sebuah permainan yang menyatakan persistent: true mempertahankan sesinya ketika setiap pemain pergi. Sekitar 15 detik setelah pemutusan sesi terakhir dijeda - TIDAK onTick panggilan — dan yang pertama pemain untuk menyambung kembali melanjutkannya. Memutuskan sambungan atau tidak aktif akan menjeda sesi alih-alih mengabaikannya. Hasil permainan, pemilik tindakan, cuti anggota akhir yang eksplisit, kedaluwarsa retensi yang dikonfigurasi, atau kegagalan pemulihan terminal dapat terjadi masih mengakhirinya. Melihat Siklus hidup sesi.

globalThis.game = {
  persistent: true,        // pause empty sessions instead of ending them
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};
  • Harus literal true atau false. Itu dibaca saat game Anda diterbitkan atau diperbarui.
  • ctx.now tetap menjadi jam dinding. Sesi persisten juga didapat ctx.pausedMs, total waktu yang dihabiskan berhenti, jadi ctx.now - ctx.pausedMs adalah jam yang berhenti sementara tidak ada orang di sana.
  • Sesi yang dijeda dihitung berdasarkan batas sesi per pemain, jadi berikan perintah kepada pemain untuk mengakhiri a dunia dengan a result.

Lihat tutorial sesi persisten untuk contoh yang berhasil dan aliran klien.

Tata letak kursi perjodohan

Sesi matchmade baru diterima ctx.matchmaking pada setiap doa (buat, perintah dan centang). Ini mempertahankan bentuk antrean dan tempat duduk bahkan jika game di-deploy ulang nanti:

ctx.matchmaking = {
  queue: "ffa", teams: 4, teamSize: 1,
  seats: [
    { id: "human-uuid", name: "Alice", team: 0, slot: 0, ai: false },
    { id: "synthetic-ai-uuid", name: "AI 2-1", team: 1, slot: 0, ai: true },
    { id: null, name: null, team: 2, slot: 0, ai: false },
    { id: null, name: null, team: 3, slot: 0, ai: false }
  ]
};

ctx.players hanya berisi kursi yang terisi, dengan team Dan ai:true untuk AI. Indeks tim/slot adalah berbasis nol. ID AI stabil dalam sesi ini dan bukan ID akun StarHermit. Hanya manusia memiliki keanggotaan sesi/obrolan dan dapat menerima status pemain akun, peringkat, atau penulisan pencapaian. Pertahankan status AI sessionState. Salin bidang daftar mana pun yang dibutuhkan klien ke dalam status game Anda atau siaran. Sesi lama dan sesi non-perjodohan dapat dihilangkan ctx.matchmaking.

Nyatakan tenggat waktu mulai dan jumlah AI maksimum starhermit.txt. Dengan hitungan AI 0, kursi kosong tetap kosong. Konteks yang sama dikirimkan ke server kontainer.

Sesi terikat ruangan

Sesi bisa saja terikat pada ruang waktu nyata: ketika a ruang waktu nyata untuk permainan dengan a server= skrip dimulai, platform membuat satu sesi N-pemain untuk ruangan itu manusia peserta (kursi AI hanya ada di daftar yang menghadap skrip). Beginilah cara permainan waktu nyata yang otoritatif di server (misalnya sepak bola) dijalankan: ruangan menyediakan lobi/perjodohan, skrip menjalankan pertandingan. Melihat Ruang Realtime — jembatan untuk siklus hidup sisi ruangan.

Setiap pemanggilan (createSession, onPlayerMessage, onTick) dari sesi terikat ruangan menerima dua bidang ctx tambahan:

ctx.room = {
  roomId: "0f8fad5b-...",
  metadata: { /* ... */ },        // the room's opaque config.metadata blob
  roster: [                       // frozen match roster, humans AND AI seats,
    { userId: "7c9e6679-...",     //   ordered by team then slot
      name: "alice", team: 0, slot: 0, ai: false },
    { userId: null,               // AI seat — never a session player
      name: "Rafa Vento", team: 0, slot: 1, ai: true }
  ]
};
ctx.presence = {                  // every user who is or was a human participant
  "7c9e6679-...": { online: true, left: false }
};
  • presence.online — pengguna memiliki soket langsung di salah satu registri koneksi (ruang waktu nyata atau ws/v1/games).
  • presence.left — pengguna tidak lagi memegang kursi aktif: mereka secara eksplisit keluar dan kursi mereka diubah menjadi peserta AI. left bersifat permanen; online mungkin mengepak. Skrip ini diharapkan dapat mendorong logika pengambilalihan/penggabungan kembali AI dari tanda-tanda ini.
  • Daftar tersebut dibaca ulang pada setiap pemanggilan, sehingga konversi kursi (manusia → AI) muncul saat terjadi.

Saat skrip terikat ruangan kembali result, platform menyelesaikan sesi, menyimpan hasilnya di ruangan, dan menutup ruangan — tidak ada hasil yang dikirimkan host yang terlibat.

Hal sebaliknya tidak benar: penutupan ruangan tidak menyelesaikan sesinya. Jika ruangan ditutup terlebih dahulu (misalnya karena orang terakhirnya meninggalkan ruangan tanpa proses bergabung — bukan hanya karena tuan rumah offline, yang hanya memindahkan peran tuan rumah saat sesi aktif), sesi tetap berjalan, ctx.room.roster menjadi kosong dan setiap manusia menunjukkan left: true. Kembali result lalu jika pertandingan harus diakhiri dengan room. Melihat Ruang Waktu Nyata — aturan tuan rumah berdurasi 60 detik dan sesi terikat ruangan.

Kembalikan bentuk

Setiap titik masuk mengembalikan bentuk yang sama (semua bidang opsional kecuali ok):

return {
  ok: true,                        // false on failure
  error: "Illegal move",           // goes only to the sender (as a WS "error" frame)
  sessionState: { /* ... */ },     // REPLACES the stored session document
  playerStates: {                  // REPLACES stored per-player documents
    "7c9e6679-...": { elo: 1216, /* ... */ }
  },
  broadcast: [                     // only these messages ever reach clients
    { to: "all", data: { type: "moved", /* ... */ } },
    { to: ["9b2f8c1a-..."], data: { type: "state", /* ... */ } }
  ],
  eloUpdates: {                    // published to the game's leaderboard by the host
    "7c9e6679-...": 1216,
    "9b2f8c1a-...": 1184
  },
  achievements: {                  // server-authoritative unlocks, by player id
    "7c9e6679-...": ["first-win", "flawless"]
  },
  scores: {                        // to your game's own leaderboards, by board key
    "high-score": { "7c9e6679-...": 4200 }
  },
  result: { kind: "white-win", reason: "checkmate" }  // ends the session (example: a chess result)
};

Aturan utama:

  • sessionState dan setiap entri playerStates mengganti dokumen yang disimpan — selalu mengembalikan dokumen lengkap, tidak pernah berbeda.
  • Hanya pesan yang terdaftar di broadcast dikirimkan ke klien, masing-masing ditujukan ke id pemain eksplisit atau "all". Tidak ada lagi yang bocor.
  • eloUpdates adalah satu-satunya cara peringkat berubah. Nilai adalah milik masing-masing pemain peringkat absolut baru, diterapkan saat dikirim — platform tidak membatasi perubahan per pertandingan, jadi jepit sendiri (lihat Elo per pertandingan). Tuan rumah menggunakannya untuk perjodohan dan mempublikasikannya ke papan peringkat permainan; klien tidak pernah dapat mengirimkan skor secara langsung (lihat Papan peringkat). Pertahankan peringkatnya playerStates[id].elo jadi milik pemiliknya pengaturan ulang peringkat mencapai salinan Anda juga.
  • achievements adalah satu-satunya cara pencapaian diberikan. Kunci diselesaikan berdasarkan pencapaian game — diumumkan, atau dibuat oleh pemiliknya — dan disimpan oleh platform; melihat Prestasi.
  • scores adalah satu-satunya cara papan peringkat game Anda berubah — lihat Papan peringkat.
  • Akhiri permainan melalui result. Tuan rumah kemudian menyelesaikan sesi tersebut, dan memulai permainan dengan memutar ulang mengarsipkan final sessionState sebagai tayangan ulang (disajikan oleh GET .../replays/{sessionId} - melihat API Permainan).

Prestasi

Skrip Anda adalah hanya hal yang dapat membuka pencapaian game Anda. Tidak ada klien titik akhir bagi mereka: POST /api/v1/me/achievements/unlock langsung menolak pencapaian dalam lingkup game, dan titik akhir CRUD penerbit menolak untuk menyentuhnya. Pemilik game dapat menambahkan prestasi di sampingnya yang dinyatakan melalui /me/github-games/{id}/achievements; skrip Anda membukanya dengan kunci dengan cara yang persis sama. Hal ini menjadikan prestasi sebagai server- berwibawa seperti permainan lainnya, dan itulah mekanismenya setiap permainan dengan a server= naskah harus digunakan — termasuk yang alur permainannya berjalan di tempat lain (lihat game mana yang bisa menggunakan ini).

Menyatakan

Sebuah statis achievements susunan di game obyek. Hanya key diperlukan:

globalThis.game = {
  achievements: [
    { key: "first-win", name: "First Win", description: "Win a match.", points: 10 },
    { key: "flawless",  name: "Flawless",  description: "Win without conceding.",
      points: 50, secret: true, icon: "https://cdn.example/flawless.png" }
  ],
  // ...entry points
};
Bidang Jenis Catatan
key rangkaian Diperlukan. Id stabil, ≤ 128 karakter, unik di dalam game. Duplikat setelah yang pertama diabaikan.
name rangkaian Defaultnya adalah key.
description rangkaian Defaultnya adalah "".
icon rangkaian URL opsional.
secret boolean Tersembunyi dari pemain sampai mereka membukanya. Defaultnya adalah false.
points nomor Dijepit ke 0–10000. Defaultnya adalah 0.

Array diterapkan saat game diterbitkan atau diperbarui:

  • Definisi dicocokkan dengan key — mengedit nama, ikon, titik, atau bendera rahasia akan memperbarui definisi yang ada, dan setiap orang yang telah mendapatkannya akan menyimpannya.
  • Kunci yang Anda berhenti deklarasikan akan dihapus hanya ketika tidak ada yang membukanya. Sejarah yang diperoleh tidak pernah dimusnahkan, sehingga pencapaian yang dihentikan tetap dapat dilihat oleh pemain yang memegangnya.
  • Paling banyak 100 pencapaian per game; tambahan di luar itu dihilangkan.
  • Deklarasinya adalah upaya terbaik: entri yang salah format dilewati. Selalu konfirmasikan definisi yang dipublikasikan dengan GET /api/v1/games/{slug}/achievements setelah memperbarui permainan.

Membuka kunci

Kembalikan sebuah achievements peta dari setiap titik masuk - createSession, onPlayerMessage, atau onTick:

onTick(ctx) {
  const state = JSON.parse(JSON.stringify(ctx.sessionState));
  const unlocks = {};
  for (const p of ctx.players) {
    if (!p.ai && state.scores[p.id] >= 10) unlocks[p.id] = ["ten-points"];
  }
  return { ok: true, sessionState: state, achievements: unlocks };
}
  • Buka kuncinya adalah idempoten — menegaskan kembali kunci yang sudah dipegang pemain adalah sebuah larangan, sehingga skrip dapat dengan aman memberikan penghargaan dari kondisi yang dievaluasi ulang pada setiap centang alih-alih melacak "sudah diberikan penghargaan" di negara bagiannya sendiri.
  • Kunci yang tidak diketahui (tidak dideklarasikan atau dibuat oleh pemilik game), pengguna yang bukan peserta sesi ini, dan kursi AI akan diabaikan secara diam-diam.
  • Paling banyak 32 kunci diterima per pemain per pemanggilan; kunci selanjutnya dalam larik yang sama akan dibuang.
  • Baris dipertahankan dengan sisa penulisan doa, sehingga pembukaan kunci tidak dapat bertahan jika doa gagal.

Pengiriman

Setiap pembukaan kunci yang baru diberikan akan diteruskan ke pemain yang memperoleh penghasilan ws/v1/games sebagai bingkai yang berbeda - itu adalah kebenaran platform, bukan salah satu milik Anda broadcast pesan:

{ "type": "achievement",
  "data": { "key": "first-win", "name": "First Win", "description": "Win a match.",
            "icon": null, "points": 10, "unlockedAt": "2026-07-25T09:14:02Z" } }

Buka kunci diberikan dari createSession mendarat sebelum ada soket, jadi mereka tiba tanpa bingkai — klien harus membaca GET /api/v1/games/{slug}/achievements pada beban dan perlakukan bingkai sebagai jalur pembaruan langsung. Permukaan penuh masuk Prestasi.

Papan peringkat

Selain papan elo, game Anda dapat memiliki papan peringkat yang dibuat oleh pemiliknya POST /api/v1/me/github-games/{id}/leaderboards, masing-masing dengan a key. Posting ke mereka dengan kembali scores dari titik masuk mana pun — kunci papan → id pemain → nomor:

onPlayerMessage(ctx) {
  var s = ctx.sessionState;
  if (ctx.message.data.type === "finish-run") {
    var scores = { "high-score": {}, "fastest-run": {} };
    scores["high-score"][ctx.message.from] = s.points[ctx.message.from];
    scores["fastest-run"][ctx.message.from] = ctx.now - s.startedAt;   // a time-ms board
    return { ok: true, sessionState: s, scores: scores };
  }
  /* ... */
}
  • Setiap pemain menyimpannya terbaik skor di setiap papan, berdasarkan arah pengurutan papan, jadi laporkan setiap hasil — hasil yang lebih buruk diabaikan begitu saja.
  • Hanya peserta sesi yang dihitung. Kunci tidak diketahui atau tidak aktif, dan skor di luar aturan dewan, dijatuhkan secara diam-diam. Paling banyak 16 papan per pengembalian.
  • Berbeda dengan eloUpdates, tidak ada yang dipublikasikan ke playerStates — simpan salinanmu sendiri playerStates jika permainan perlu membaca kembali yang terbaik pribadi.

Di mana skrip Anda berjalan

Skrip yang berulang tanpa batas, menghabiskan memorinya, atau melebihi anggaran waktunya akan gagal doa. Hasil yang gagal tidak diterapkan. Perintah atau centang melaporkan salah satu dari:

  • Game script error: the script crashed its runtime (for example, by recursing without limit).
  • Game script error: the script exceeded its memory budget.
  • Game script error: the script exceeded its time budget.

Bagian server game Anda

  • Waktu skrip. Semua sesi game berbagi anggaran waktu skrip, sebesar 2000 ms per detik default, dibebankan dengan apa yang sebenarnya dilakukan oleh setiap pemanggilan. Permainan atas bagiannya malah ditolak daripada antri: tanda centang dilewati, perintah dijawab dengan "Game ini menggunakan lebih dari bagiannya dari server saat ini; coba lagi sebentar lagi.", dan membuat sesi kembali 429.
  • Perintah. Setiap pemain dapat mengirimkan 20 perintah tahan lama per detik per sesi (dengan ledakan singkat tunjangan); lebih dari itu sebuah perintah dijawab dengan an error bingkai, "Terlalu banyak perintah; lambat turun." Bingkai tidak menyertakan status HTTP. Masukan waktu nyata dibatasi secara terpisah.
  • Hasil. Hasil akhir sesi mungkin paling banyak 64 KB; yang lebih besar ditolak 422.
  • Ukuran skrip. A server= skrip mungkin paling banyak 2 MB; yang lebih besar ditolak 422 sebelumnya itu disimpan atau diurai.

Operator dapat menaikkan atau menurunkan masing-masingnya untuk satu permainan.

Anggaran

Skrip dijalankan berdasarkan anggaran sumber daya berikut:

  • ~250 ms CPU per pemanggilan
  • Memori 32 MB
  • Batas pernyataan per pemanggilan
  • Anggaran byte negara bagian per pemain — semua dokumen negara bagian harus tetap dapat diserialkan dan berukuran kecil
  • Nilai bersarang paling banyak pada kedalaman 64 tingkat ketika menjadi teks. Apa pun yang dikembalikan oleh titik masuk, semuanya deklarasi, JSON.stringify, Dan Array.prototype.join/toString/toLocaleString menolak a nilai yang lebih dalam dengan a RangeError (yang dikembalikan gagal dalam pemanggilan: "bersarang lebih dari 64 level dalam"). JSON.parse sudah berhenti di 64, jadi nilai yang lebih dalam tidak akan pernah bisa bolak-balik. flat meratakan hingga 64 level dan melempar jika array bersarang lebih dalam — termasuk array yang berisi itu sendiri.
  • Satu panggilan tidak dapat mengalokasikan lebih dari anggaran memori. repeat, padStart/padEnd, concat Dan replace/replaceAll melemparkan RangeError: Invalid string length ketika hasilnya bisa melebihi setengahnya anggaran dalam karakter (16M pada default 32 MB; penggantian regex dibatasi seolah-olah setiap posisi cocok, yang hanya mempengaruhi string sekitar satu juta karakter atau lebih). ArrayBuffer dan mengetikkan lemparan array RangeError melewati anggaran dalam byte, dan melewati array elemen anggaran/8 ditolak. Anggarannya juga diperiksa setelah hook Anda kembali, jadi an pernyataan akhir yang melebihi anggaran gagal dalam pemanggilan alih-alih berhasil.

Skrip referensi catur sengaja membuat dokumennya tetap kecil — sebagai contoh agar tetap sesuai anggaran, dokumen per pemainnya adalah

{
  elo: 1200,
  wins: 0, losses: 0, draws: 0,
  lastColorVs: "9b2f8c1a-...",        // for color alternation on rematch
  lastColorOrder: "w",
  recentGames: [ /* up to 30 summaries */ ]
}

Batas sesi bersamaan adalah 20 per pemain secara default.

sessionState.summary = {

deadline adalah stempel waktu Unix bilangan bulat milidetik, atau dihilangkan ketika tidak ada tenggat waktu. String tanggal ISO tidak dikenali. turnPlayerId adalah pemain UUID.

Penyebaran

Deklarasikan skrip di repositori game Anda starhermit.txt tampak:

server=server.js

Alur penerbitan melalui integrasi GitHub — lihat Permainan GitHub. Platform mengeksekusi skrip sesuai anggaran yang terdokumentasi. Jangan digabungkan server= dengan container.image=; gunakan waktu proses kontainer sebagai gantinya saat mengirimkan gambar.

Praktik terbaik

  • Validasi setiap perintah. Merawat ctx.message.data sebagai bermusuhan: periksa jenis, rentang, urutan giliran, dan status permainan sebelum menyentuh status.
  • Pertahankan pemanggilan dengan cepat dan nyatakan dalam jumlah kecil. Anda memiliki ~250 ms dan anggaran byte per dokumen pemain; naskah referensi catur, misalnya caps recentGames pada 30 entri karena alasan ini.
  • Menggunakan ctx.now / ctx.random hanya. TIDAK Date, TIDAK Math.random — tuan rumah memiliki jam dan dadu.
  • Desain broadcast pesan sebagai satu-satunya kontrak klien. Klien harus dapat merender keseluruhan game dari skrip yang dikirimkan; apa pun yang tidak disiarkan tidak ada bagi mereka.
  • Satu file, dua permukaan. File yang sama dapat berfungsi ganda sebagai aturan sisi klien melalui ekspor terpisah: implementasi referensi catur, misalnya, diekspos globalThis.chessRules untuk browser (pindahkan pratinjau, petunjuk validasi) dan globalThis.game untuk tuan rumah. Satu sumber kebenaran, tidak ada otoritas pada klien.
  • Selalu akhiri permainan melalui result jadi platform menerbitkan pembaruan Elo dan mengarsipkan tayangan ulangnya saat game Anda memilikinya memutar ulang.

Lihat Panduan Catur untuk tur baris demi baris, dan Anjuran AI untuk bantuan membuat skrip Anda sendiri.

Dibagikan konvensi API menjelaskan penguraian respons, stempel waktu, penomoran halaman, dan percobaan ulang.
