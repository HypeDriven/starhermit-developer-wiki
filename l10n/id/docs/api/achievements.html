Prestasi

Sebuah prestasi adalah milik tepatnya satu pemilik, dan pemilik memutuskan siapa yang diizinkan membukanya:

Pemilik Dinyatakan oleh Tidak terkunci oleh Gunakan untuk
Sebuah permainan yang berwibawa game.achievements dalam naskah, atau achievements dari sebuah wadah /describe — atau oleh pemilik game melalui /me/github-games/{id}/achievements Hanya waktu proses server game — otoritatif server Permainan dengan a server= naskah atau container.image= bagian belakang
Judul katalog (SoftwareTitle) Penerbit, melalui API penerbit Klien pemain, melalui POST /api/v1/me/achievements/unlock (hak diperlukan) Judul terdistribusi yang kliennya adalah satu-satunya yang mengetahui bahwa pemain memperoleh sesuatu

Keduanya saling eksklusif dan platform menerapkan pemisahan tersebut:

  • POST /api/v1/me/achievements/unlock menolak pencapaian dalam lingkup permainan — klien tidak akan pernah bisa mengklaimnya.
  • Titik akhir CRUD penerbit juga menolaknya. Anda tidak memerlukan penerbit untuk game yang Anda miliki: as pemiliknya kamu adalah penerbitnya, dan Anda mengelola pencapaiannya melalui titik akhir pemilik alih-alih.

URL Dasar: https://api.starhermit.com. Semua rute berada di bawah /api/v1/....

Metode Jalur Penulis Keterangan
MENDAPATKAN /api/v1/games/{slug}/achievements Pembawa Prestasi game resmi + status tidak terkunci penelepon
MENDAPATKAN /api/v1/me/github-games/{id}/achievements JWT (pemilik permainan) Setiap pencapaian permainan Anda, dengan pencapaiannya origin dan membuka kunci hitungan
POS /api/v1/me/github-games/{id}/achievements JWT (pemilik permainan) Ciptakan pencapaian untuk game Anda → 201
MELETAKKAN /api/v1/me/github-games/{id}/achievements/{achievementId} JWT (pemilik permainan) Perbarui yang Anda buat
MENGHAPUS /api/v1/me/github-games/{id}/achievements/{achievementId} JWT (pemilik permainan) Hapus yang Anda buat dan tidak ada yang membuka kuncinya → 204
MENDAPATKAN /api/v1/software/{titleId}/achievements Anonim Definisi pencapaian judul katalog
MENDAPATKAN /api/v1/me/achievements?titleId= JWT Pembuka kunci penelepon (semua pemilik, atau satu judul)
POS /api/v1/me/achievements/unlock JWT Buka kunci yang diklaim klien — judul katalog saja

Baca kesalahan secara defensif seperti yang dijelaskan dalam konvensi API. POST /me/achievements/unlock mengembalikannya 400 alasan sebagai teks biasa.

Prestasi game resmi server

Inilah mekanismenya setiap game harus digunakan jika memiliki skrip atau backend container. Itu runtime server adalah satu-satunya penulis. Itu harus memvalidasi bahwa pemain mendapatkan setiap pembukaan kunci; menolak pengiriman API langsung saja tidak memvalidasi kejadian yang dilaporkan oleh klien yang dimodifikasi.

1. Deklarasikannya dalam skrip Anda

Tambahkan statis achievements susunan ke game objek — lihat Skrip Game — Prestasi untuk kontrak penuh:

globalThis.game = {
  achievements: [
    { key: "first-win",  name: "First Win",  description: "Win a match.", points: 10 },
    { key: "flawless",   name: "Flawless",   description: "Win without conceding.",
      points: 50, secret: true, icon: "https://cdn.example/flawless.png" }
  ],
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

Deklarasi dibacakan saat game diterbitkan atau diperbarui dari repositorinya. Publikasikan pembaruan untuk menerapkan perubahan.

2. Buka kuncinya dari hook siklus hidup apa pun

Kembalikan sebuah achievements peta — id pengguna → susunan kunci — dari createSession, onPlayerMessage, atau onTick:

return {
  ok: true,
  sessionState: state,
  achievements: { [winnerId]: ["first-win", "flawless"] },
  result: { kind: "win", winner: winnerId }
};

Buka kuncinya adalah idempoten — mengembalikan kunci yang sudah dipegang pemain adalah hal yang dilarang, jadi skrip mungkin saja melakukannya tegaskan kembali pencapaian pada setiap centang tanpa mengkhawatirkan duplikat.

3. Pemain diberitahu melalui soket gameplay

Setiap pembukaan kunci yang baru diberikan hanya diberikan kepada pemain yang memperoleh penghasilan saja ws/v1/games, sebagai bingkainya sendiri type (platform kebenaran, bukan skrip-relay game pesan):

{
  "type": "achievement",
  "data": {
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "points": 10,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
}

Buka kunci diberikan dari createSession disimpan sebelum ada yang memiliki soket, jadi mereka datang bersama tanpa bingkai — membacanya dari titik akhir daftar yang dimuat.

Backend kontainer

Sebuah wadah mendeklarasikan bidang pencapaian yang sama GET /describe, lalu mengirimkan achievements pesan pada kontrolnya WebSocket. Platform menerapkan kunci yang sama, peserta, idempotensi, dan aturan penyampaian. Melihat Server Game Kontainer.

GET /api/v1/games/{slug}/achievements

Setiap pencapaian yang diumumkan game, dengan status tidak terkunci pemanggil. 404 jika siput tidak memiliki definisi game yang otoritatif (game tanpa skrip atau backend container tidak memiliki game milik prestasi — lihat Game mana yang bisa menggunakan ini). Prestasi rahasia disembunyikan sampai penelepon membuka kuncinya. Diurutkan berdasarkan kreasi, lalu kunci.

[
  {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "secret": false,
    "points": 10,
    "unlocked": true,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
]

Bekerja dengan JWT pengguna penuh atau token peluncuran cakupan game.

Game mana yang bisa menggunakan ini

Mekanisme ini tersedia untuk game yang mendeklarasikan a server= naskah atau a container.image= bagian belakang masuk starhermit.txt. Itu runtime server membuat pembukaan kunci menjadi otoritatif. Kasus penggunaan yang didukung skrip meliputi:

  • Game platform bernaskah — membuka kunci dari onPlayerMessage / onTick saat pertandingan berlangsung.
  • Game waktu nyata yang terikat ruangan — a ruang waktu nyata untuk a permainan dengan a server= skrip membuat sesi terikat saat dimulai, dan setiap kaitannya sesi dapat memberikan pencapaian.
  • Permainan pemain tunggal dan latihan — sesi melawan kursi AI (POST /api/v1/games/{slug}/sessions/ai) menjalankan skrip yang sama dan jalur buka kunci yang sama.
  • Game real-time yang diarahkan ke host — permainan yang alur permainannya melebihi saluran biner ruang waktu nyata masih dapat mengirimkan skrip server murni sebagai otoritas pencapaiannya: ruang awal membuat sesi terikat, dan skrip penghargaan dari createSession / onTick / tahan lama cmd pesan yang dikirim ws/v1/games sementara itu jalur cepat terus mengalir ws/v1/realtime.

Sesi yang didukung container juga dapat mendeklarasikan dan memberikan pencapaian melalui protokolnya. Sebuah permainan dengan tidak ada backend otoritatif (permainan browser murni, atau yang hanya dibuat di atas estafet rekan) tidak memiliki jalur buka kunci resmi server. Pembukaan kunci yang diklaim klien hanya tersedia untuk judul yang didistribusikan katalog, di bawah.

Batasan dan aturan

Aturan Nilai
Prestasi yang diumumkan per game 100 (ekstra diabaikan)
Panjang kunci pencapaian 128 karakter
Buka kunci kunci yang diterima per pemain, per doa 32
points dijepit ke 0–10000; defaultnya adalah 0
name default ke key ketika dihilangkan
  • Entri deklarasi yang formatnya salah adalah dilewati. Skrip yang gagal mengevaluasi menghasilkan hasil yang kosong daftar; deklarasi kontainer dibaca setelah melewati pemeriksaan kesehatan. Verifikasi dengan GET /api/v1/games/{slug}/achievements setelah penerapan.
  • Definisi dikecewakan oleh key. Kunci yang berhenti dideklarasikan oleh backend Anda telah dihapus hanya jika tidak ada yang punya membukanya — sejarah yang diperoleh tidak pernah hancur. Prestasi yang dibuat pemilik melalui API tidak pernah tersentuh oleh hal ini: hanya mereka yang dinyatakan yang direkonsiliasi.
  • Pembukaan kunci untuk pengguna yang bukan peserta sesi, dan untuk kursi AI, diabaikan.

Prestasi dari game lain

Sebuah game dapat membuka fitur berdasarkan apa yang dibuka pemainnya lain permainan: penghormatan sekuel yang asli, atau game dalam seri berbagi kosmetik. Ada dua cara untuk membacanya.

Dari server Anda: ctx.linkedAchievements (tepercaya)

Beri nama permainan lain dalam skrip Anda, di samping deklarasi Anda yang lain:

globalThis.game = {
  linkedAchievements: ["83fd04b1-3cbe-4b09-a251-3733ad4b9d94"], // other games' slugs (uids)
  // ...
};

Sebuah wadah mengembalikan hal yang sama linkedAchievements susunan dari GET /describe. Setiap skrip ctx doa kemudian membawa kunci terbuka setiap pemain manusia dalam game tersebut:

ctx.linkedAchievements = {
  "7c9e6679-...": {                                   // player id
    "83fd04b1-3cbe-4b09-a251-3733ad4b9d94": ["first-win", "checkmate-10"]
  }
};
  • Ini dibaca ulang setiap doa, jadi pembukaan kunci yang diperoleh di game lain di tengah pertandingan akan terlihat yang berikutnya. Sebuah wadah menerimanya di ctx POST /sessions, yaitu, pada saat membuat dan pada memulihkan.
  • Paling banyak 8 pertandingan; entri yang bukan string yang tidak kosong, duplikat, dan slug lebih dari 100 karakter dijatuhkan. Seperti deklarasi lainnya, deklarasi ini dibacakan saat game diterbitkan atau diperbarui.
  • Sebuah permainan yang menyatakan tidak ada yang mendapat tidak linkedAchievements lapangan dan tidak membayar apa pun.
  • Gunakan rute ini untuk apa pun yang harus diterapkan oleh platform, seperti membuka kunci gameplay atau memberikan izin pencapaian Anda sendiri.

Dari klien Anda: GET /api/v1/games/{slug}/linked-achievements/{otherSlug}

Milik si penelepon membuka kuncinya otherSlug. Tidak memerlukan deklarasi, jadi game khusus browser tanpa server dapat menggunakannya, dan berfungsi dengan token peluncuran {slug}: titik akhir game lain itu sendiri tetap dipagari dari token itu.

{
  "game": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "hidden": false,
  "unlocked": [
    { "key": "first-win", "unlockedAt": "2026-07-25T09:14:02Z" }
  ]
}

Seorang klien bisa berbohong tentang apa yang diterimanya, jadi perlakukan ini sebagai petunjuk untuk UI dan kosmetik, bukan sebagai bukti.

Apa yang diungkapkan

  • Hanya buka kunci status game yang Anda beri nama: kunci dan waktu buka kunci, tidak pernah nama, deskripsi atau daftar permainan lain yang pernah dimainkan pemain. Sebuah pencapaian rahasia yang telah dibuka oleh pemain adalah termasuk.
  • Siput yang tidak cocok dengan jawaban game seperti game tanpa ada yang terbuka.
  • Privasi dihormati. Seorang pemain yang pencapaiannya bersifat privasi Private adalah tersembunyi: tidak hadir dari ctx.linkedAchievements, Dan "hidden": true dengan daftar kosong dari titik akhir. Tersembunyi tidak sama dengan "tidak memilikinya", jadi jangan perlakukan seperti itu. FriendsOnly (default) diungkapkan, karena pembaca bertindak untuk pemain.

Prestasi yang diciptakan oleh pemilik game

Mendeklarasikan pencapaian dalam kode bukanlah satu-satunya cara untuk memberikan kesan pada game Anda. Jika Anda memiliki game dengan a server= naskah atau container.image= backend, Anda juga dapat membuat pencapaian melalui API — cara yang dilakukan penerbit untuk judul katalog, tanpa memerlukan akun atau izin penerbit. Kepemilikan game adalah keseluruhan dari hibah. Gunakan ini ketika seorang desainer ingin menambahkan atau menulis ulang pencapaian tanpa perubahan kode, atau ketika backend Anda memberikan kunci, hal itu tidak dideklarasikan.

Hanya server game Anda yang dapat membuka kuncinya, persis seperti yang dideklarasikan: skrip Anda mengembalikan kuncinya di achievements, atau penampung Anda mengirimkannya ke saluran kontrol. Tidak ada perubahan pada membuka kunci sisi — kunci diselesaikan semua pencapaian game, diumumkan dan dibuat.

{id} dari mana id gamemu berasal? GET /api/v1/me/github-games.

POST /api/v1/me/github-games/{id}/achievements

{
  "key": "speedrunner",
  "name": "Speedrunner",
  "description": "Finish a level in under a minute.",
  "icon": "https://cdn.example/speedrunner.png",
  "secret": false,
  "points": 25

key, name Dan description diperlukan. Kembali 201:

{
  "id": "…",
  "key": "speedrunner",
  "name": "Speedrunner",
  "description": "Finish a level in under a minute.",
  "icon": "https://cdn.example/speedrunner.png",
  "secret": false,
  "points": 25,
  "origin": "owner",
  "unlocks": 0,
  "createdAt": "…",
  "updatedAt": "…"
}

GET di jalur yang sama mencantumkan setiap pencapaian game dalam bentuk ini: origin adalah declared untuk yang dinyatakan oleh skrip atau wadah Anda dan owner untuk yang dibuat di sini, dan unlocks menghitung berapa banyak pemain yang memegang masing-masing pemain.

PUT .../achievements/{achievementId} mengambil salah satu dari name, description, icon, secret Dan points; itu key tidak bisa berubah. DELETE menghapusnya.

Aturan

Aturan Nilai
Kunci 1–128 karakter: huruf, angka, ., _, -, dimulai dengan huruf atau angka
name / description diperlukan; paling banyak 200/2000 karakter
points 0–10.000; defaultnya adalah 0
Prestasi yang dibuat pemilik per game 200 (selain yang dinyatakan hingga 100)
  • Pencapaian yang dinyatakan tetap menjadi milik kode Anda. Membuat kunci yang sudah dimiliki permainan 409, dan begitu juga mengedit atau menghapus a declared satu — pembaruan berikutnya akan mengembalikannya sebagai kode Anda menyatakannya. Ubah di skrip Anda atau /describe alih-alih.
  • Jika kode Anda nanti mendeklarasikan kunci yang Anda buat di sini, deklarasi tersebut mengambil pencapaian itu berakhir (origin menjadi declared). Pemain yang mendapatkannya menyimpannya.
  • Prestasi yang telah dibuka seseorang tidak dapat dihapus (409).
  • 404 berarti game tersebut bukan milik Anda; 409 di salah satu rute ini dengan pesan tentang server backend berarti game tersebut tidak memilikinya — game khusus browser tidak memiliki apa pun yang dapat membuka kuncinya prestasi.

Prestasi judul katalog

Untuk perangkat lunak yang didistribusikan melalui katalog, di mana klien adalah satu-satunya yang mengamati kondisi terbuka. Definisi dibaca secara anonim; membuka kunci membutuhkan JWT dan tidak dicabut hak atas gelar tersebut.

GET /api/v1/software/{titleId}/achievements

AchievementDto[]. Prestasi rahasia disembunyikan kecuali dibuka oleh penelepon (dan mereka criteria ditahan sampai saat itu). Prestasi dalam lingkup permainan tidak pernah muncul di sini.

[
  {
    "id": "…",
    "key": "…",
    "name": "…",
    "description": "…",
    "icon": "…",
    "secret": false,
    "points": 10,
    "visibility": "…",
    "criteria": "…"
  }
]

POST /api/v1/me/achievements/unlock

{ "achievementDefinitionId": "…" }

Kembali 204. Kembali 400 ketika pencapaiannya tidak ada, ketika penelepon tidak mempunyai hak untuk judulnya (lihat catalog.md), atau kapan pencapaiannya lingkup permainan — itu adalah hanya diberikan oleh skrip resmi atau backend container game. Membuka kembali sesuatu yang sudah ditahan akan kembali 204.

Manajemen sisi penerbit — menentukan, memperbarui, dan menghapus pencapaian judul — ada publisher.md.

GET /api/v1/me/achievements

Penelepon membuka kunci sebagai UserAchievementDto[]. Dengan tidak titleId ini mengembalikan setiap pembukaan kunci pegangan pengguna, baik dalam cakupan game maupun dalam cakupan judul; lulus ?titleId= untuk mempersempitnya menjadi satu judul katalog.

[
  {
    "id": "…",
    "achievementDefinitionId": "…",
    "key": "…",
    "name": "…",
    "description": "…",
    "icon": "…",
    "points": 10,
    "unlockedAt": "…"
  }
]

Untuk layar pencapaian permainan sendiri lebih disukai GET /api/v1/games/{slug}/achievements, yang juga mengembalikan definisi yang dimiliki pemain bukan belum terkunci.

Dibagikan konvensi API menjelaskan penguraian respons, stempel waktu, penomoran halaman, dan percobaan ulang.
