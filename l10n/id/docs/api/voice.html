Suara

Suara StarHermit menyediakan ruang suara per percakapan melalui REST API (api/v1/voice) ditambah WebSocket biner/teks campuran (ws/v1/voice) untuk sinyal audio dan WebRTC. Semua titik akhir REST memerlukan autentikasi. Ketersediaan suara mungkin berbeda. Badan kesalahan bervariasi; melihat konvensi API.

Kamar berlabuh ke a percakapan obrolan; keanggotaan dalam percakapan adalah gerbang segalanya, jadi aturan pertemanan obrolan juga mengatur suara (percakapan sesi permainan mengabaikan persahabatan). Batasan: 3 ruang aktif per percakapan, maksimal 10 peserta per ruang, codec "opus".

titik akhir REST

Basis: https://api.starhermit.com/api/v1/voice.

Metode Jalur Penulis Keterangan
POS /rooms JWT Buat ruang suara untuk percakapan
MENDAPATKAN /rooms?conversationId= JWT Buat daftar ruangan untuk percakapan
MENDAPATKAN /rooms/{roomId} JWT Dapatkan kamar
POS /rooms/{roomId}/join JWT Bergabunglah dengan ruangan (wajib sebelum WS)
POS /rooms/{roomId}/leave JWT Tinggalkan ruangan
POS /rooms/{roomId}/mute JWT Atur status bisu Anda sendiri
POS /rooms/{roomId}/participants/{userId}/server-mute JWT (pencipta) Host mute yang tidak dapat diangkat oleh peserta
POS /rooms/{roomId}/close JWT Menutup ruangan (khusus kreator)

Buat sebuah ruangan

POST /rooms

{ "conversationId": "<guid>", "maxParticipants": 10 }

Pengembalian a VoiceRoomDto.

Bentuk ruangan

GET /rooms?conversationId=<guid> → VoiceRoomDto[]; GET /rooms/{roomId} → VoiceRoomDto:

{
  "id": "<guid>",
  "conversationId": "<guid>",
  "creatorUserId": "<guid>",
  "codec": "opus",
  "status": "Active",
  "maxParticipants": 10,
  "createdAt": "2026-07-22T07:00:00Z",
  "participants": [
    {
      "userId": "<guid>",
      "username": "alice",
      "isMuted": false,
      "isConnected": true,
      "joinedAt": "2026-07-22T07:01:00Z"
    }
  ]
}

Bergabunglah, keluar, bisu, tutup

POST /rooms/{roomId}/join → VoiceRoomDto. Gabungan REST ini adalah diperlukan sebelum membuka WebSocket; menghubungkan tanpa itu kembali 403. Bergabung kembali akan menghapus milik peserta memiliki bisu (isMuted); milik tuan rumah isServerMuted selamat meninggalkan dan menyambung kembali.

POST /rooms/{roomId}/leave → 204.

POST /rooms/{roomId}/mute dengan { "muted": true } → 204. Ini adalah bisu yang dilakukan peserta dan tidak dapat menghapus bisu host.

POST /rooms/{roomId}/participants/{userId}/server-mute dengan { "muted": true } → 204 (khusus pencipta). Audio akan hilang jika salah satu mode bisu disetel.

POST /rooms/{roomId}/close → 204 (khusus pencipta).

Nyatakan bisu Anda saat terhubung daripada mewarisi apa pun yang diingat baris tersebut.

Soket Web: ws/v1/voice

Hubungkan ke wss://api.starhermit.com/ws/v1/voice?roomId=<guid> dengan JWT melalui Authorization tajuk, ?ticket=, atau ?access_token=. REST sebelumnya join diperlukan.

Protokolnya beragam:

Bingkai biner — audio

Bingkai biner membawa audio (misalnya Opus). Server menyampaikan setiap frame ke peserta lain sebagai:

[16-byte senderUserId][audio…]

Server mengawali diautentikasi id pengirim dan tidak pernah mempercayai pengirim yang disediakan klien. Audio dari pengguna yang dibisukan akan dihilangkan. Batasan: 100 paket/detik per pengguna, bingkai maksimal 4000 byte.

Bingkai teks — klien → kontrol server

{ "type": "mute", "muted": true }

{ "type": "speaking", "speaking": true }

{ "type": "rtc", "to": "<guid>", "payload": { } }

{ "type": "deafen", "deafened": true }

rtc muatan adalah sinyal WebRTC buram, diteruskan ke peserta yang dituju. deafen menekan audio biner yang masuk untuk soket ini; itu tidak otomatis dimatikan audio keluar atau koneksi rekan terpisah. Terapkan secara lokal ketika pemain memilih Deafen.

Bentuk peserta REST menampilkan bisunya sendiri, bukan bisu host. Daftar suara awal dan acara bergabung termasuk serverMuted; tidak ada acara push perubahan bisu host yang terpisah. Jika game Anda menggunakan P2P audio, sinyal dan penegakannya harus menjadi bagian dari integrasi media Anda sendiri.

Ketika soket suara terakhir terputus, keanggotaan ruang suara berakhir. Hubungi REST join lagi sebelumnya menyambungkan kembali dan memulihkan bisu yang diinginkan sebelum mengirim audio.

Server → acara klien

Amplop: { "event": "<name>", "data": { } }.

Peristiwa data
voice.roster { "roomId", "participants": [{ "userId", "muted", "serverMuted" }] } — dikirim ke pendatang baru
voice.participant_joined { "roomId", "userId", "muted", "serverMuted" }
voice.participant_left { "roomId", "userId" }

Contoh pola integrasi (dari implementasi referensi catur)

Suara diikutsertakan per sesi permainan. Klien yang khas enable() mengalir:

  1. GET /api/v1/voice/rooms?conversationId=<chatConversationId> untuk menemukan ruangan yang ada, lain-lain POST /api/v1/voice/rooms untuk membuatnya.
  2. POST /api/v1/voice/rooms/{roomId}/join.
  3. Membuka ws/v1/voice?roomId=<guid>.

Di implementasi referensi catur, audio dijalankan melalui WebRTC P2P dengan negosiasi sempurna; sinyal dipertukarkan melalui rtc pesan kontrol ({ "sdp": … } / { "ice": … } payloads), dengan jalur biner Opus yang dikirimkan ke server sebagai cadangan.

Token peluncuran dalam lingkup game mungkin gunakan suara REST dan WebSocket untuk ruangan yang terhubung dengan sesi permainannya sendiri.

Lihat juga

  • Pilihan audio — kontrol volume dasar, mikrofon, dan push-to-talk, dengan batas pemutaran yang terdeteksi secara otomatis
  • Mengobrol — ruangan yang menjadi tempat percakapan; sesi permainan terungkap chatConversationId
  • Pertandingan — sesi permainan dan token peluncuran
  • Menyampaikan — penyebaran byte untuk netcode game

Melihat kompatibilitas kredensial Dan kontrak yang dapat dibaca mesin.
