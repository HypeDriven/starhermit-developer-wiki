Profil

API profil mencakup akun milik pengguna yang diautentikasi (/api/v1/me/...), pencarian publik pengguna lain, kunci publik, identitas tertaut, pengaturan privasi, hak, dan detak jantung kehadiran. Rute akun memerlukan otorisasi; dokumen persyaratan saat ini bersifat publik.

Badan kesalahan bervariasi; melihat konvensi API.

PATCH /api/v1/me

Semua bidang opsional. Batasan: username 1–32 karakter; nickname ≤64 karakter (banyak akun tidak punya); metadata ≤4096 karakter. Nama pengguna dan nama panggilan berbagi satu namespace yang tidak peka huruf besar-kecil: 409 ketika akun lain menggunakan nama tersebut sebagai nama pengguna atau nama panggilannya, mengabaikan kasus. Nama panggilan dinormalisasi NFKC, dan karakter kontrol atau tak terlihat dinormalisasi 400. Berubah email tambahan memerlukan sebuah Sesi yang diautentikasi OAuth karena email akun dapat menyetujui tautan kredensial; kunci publik atau sesi verifikasi email didapat 403 untuk bidang itu tetapi mungkin masih memperbarui yang lain. Mengembalikan 204 aktif sukses, 409 konflik (nama pengguna atau nama panggilan sudah dipakai).

{
  "username": "newname",
  "email": "new@example.com",
  "metadata": "{}",
  "nickname": "New Nick"
}

Persyaratan penerimaan

Sebelum menggunakan titik akhir REST yang dilindungi atau membuka WebSockets, akun harus menerima saat ini istilah StarHermit. Hal ini berlaku untuk token akun dan token peluncuran pemain, termasuk akun itu menerima revisi yang lebih lama. Ini tidak berlaku untuk sumber daya anonim/masuk atau server kontainer token penerapannya sendiri. GET /api/v1/me dan titik akhir penerimaan tetap tersedia seperti biasanya izin akun sementara penerimaan tertunda.

GET /api/v1/me termasuk currentTermsHash Dan termsAcceptanceRequired. Yang disimpan termsAcceptedHash Dan termsAcceptedAt adalah nol sebelum penerimaan pertama. Hash yang ditampilkan di contoh profil di atas disingkat; selalu gunakan hash lengkap yang dikembalikan oleh API.

GET /api/v1/terms

Anonim; juga dapat dibaca dengan token peluncuran pemain. Kembali 200 dengan Cache-Control: no-store:

{ "hash": "<current-64-character-lowercase-sha256>", "text": "<complete terms text>" }

Memberikan text sebagai teks biasa. hash adalah SHA-256 dari byte dokumen UTF-8 yang tepat; gunakan yang dikembalikan nilai daripada hashing teks tampilan yang diformat ulang.

POST /api/v1/me/terms/accept

Setelah pengguna membaca dan secara eksplisit menerima revisi yang ditampilkan, kirimkan hashnya:

POST /api/v1/me/terms/accept
Authorization: Bearer <account-access-token>
Content-Type: application/json

{ "hash": "<hash-returned-with-the-displayed-text>" }

Kembali 200 dengan { "termsAcceptedHash", "termsAcceptedAt" }. Sesi akun OAuth dan kunci publik dan token peluncuran lingkup permainan pemain dapat menerima. Token server kontainer tidak dapat bertindak untuk pemain. Penerimaan disimpan di akun dan berlaku pada permintaan selanjutnya dengan token yang sama masih valid; menyegarkan token tidak diperlukan.

Hash yang hilang/kosong atau yang panjangnya lebih dari 64 karakter akan dikembalikan 400. Sebuah hash yang tidak persis seperti itu cocok dengan pengembalian revisi saat ini 409:

{
  "error": "terms_version_mismatch",
  "termsHash": "<current-hash>",
  "termsUrl": "/api/v1/terms"
}

Ambil dan tampilkan dokumen baru dan minta penerimaannya lagi; jangan diam-diam menerima penggantinya revisi. Permintaan dilindungi lainnya dengan pengembalian penerimaan yang tertunda 403:

{
  "error": "terms_acceptance_required",
  "message": "Accept the latest terms of service before using the API.",
  "termsHash": "<current-hash>",
  "termsUrl": "/api/v1/terms",
  "acceptUrl": "/api/v1/me/terms/accept"
}

Game yang dihosting dapat menampilkan persyaratan dan mengirimkan hash yang ditampilkan dengan token peluncuran pemainnya ketika pemain menekan Terima, lalu coba lagi. Itu juga dapat mengirim pemain ke UI akun mereka. Proses masuk berulang atau penyegaran token tidak memperbaiki penerimaan yang tertunda. Pemutakhiran WebSocket ditolak dengan HTTP 403 sebelum dibuka; browser mungkin menyembunyikan isi respons, jadi tangani penerimaan melalui REST sebelum menghubungkan.

Contoh untuk akun atau klien game (panggilan acceptDisplayedTerms hanya dari tindakan Terima pengguna):

const api = 'https://api.starhermit.com';
async function loadTerms() {
  const response = await fetch(`${api}/api/v1/terms`);
  if (!response.ok) throw new Error(`Terms fetch failed: ${response.status}`);
  return response.json(); // Display text, retain this document's hash.
}
async function acceptDisplayedTerms(accountToken, displayedTerms) {
  const response = await fetch(`${api}/api/v1/me/terms/accept`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${accountToken}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ hash: displayedTerms.hash })
  });
  if (response.status === 409) {
    throw new Error('Terms changed. Reload and display them for a new acceptance.');
  }
  if (!response.ok) throw new Error(`Acceptance failed: ${response.status}`);
  return response.json();
}

Avatar

PUT /api/v1/me/avatar menerima gambar PNG, persegi, ≤512×512 piksel, ≤1 MB:

{ "imageBase64": "iVBORw0KGgoAAAANSUhEUg..." }

Mengembalikan 204. GET /api/v1/me/avatar mengembalikan avatar Anda sebagai image/png byte.

Pengguna lain

  • GET /api/v1/users/{id}/avatar — Avatar PNG untuk pengguna mana pun.
  • GET /api/v1/users/{id}/profile:

Kunci publik

Kunci terdaftar adalah kredensial API: pemegangnya dapat melengkapi aliran tantangan kunci publik dan menerima akses/token penyegaran biasa berpasangan. Hal ini membuat kunci berlabel terpisah cocok untuk klien desktop atau jalur penerapan.

Menambahkan kunci atau mencabut kunci lain memerlukan sesi yang diautentikasi OAuth. Kunci publik sesi hanya dapat mencabut kuncinya sendiri DELETE /api/v1/me/public-keys/current. Itu tidak bisa mendaftarkan penggantian atau mencabut perangkat lain. Daftar tetap tersedia untuk setiap sesi akun penuh; peluncuran game dan token server tidak dapat mengelola kunci akun.

GET /api/v1/me/public-keys

Daftar ini mencakup baris yang dicabut sebagai jejak audit:

[
  {
    "id": "9b2f5c74-1d2e-4a6b-8c0d-1e2f3a4b5c6d",
    "keyType": "Ed25519",
    "keyData": "<base64-raw-32-byte-public-key>",
    "label": "orbit-league-production",
    "fingerprint": "4d9f3c...",
    "createdAt": "2026-07-01T12:00:00Z",
    "lastUsedAt": "2026-07-30T09:00:00Z",
    "isRevoked": false,
    "revokedAt": null,
    "metadata": null
  }
]

POST /api/v1/me/public-keys

Memerlukan sesi yang diautentikasi OAuth dan segera melampirkan kuncinya; tidak seperti anonim pendaftaran, tidak diperlukan perjalanan pulang pergi email.

{
  "keyType": "Ed25519",
  "keyData": "<base64-raw-32-byte-public-key>",
  "label": "orbit-league-production"
}

label bersifat opsional (maksimum 128 karakter). Jenis kunci yang diterima adalah Ed25519, ECDSA-P256, Dan RSA-PSS; materi harus berupa Base64 standar: kunci publik 32-byte mentah untuk Ed25519, P-256 yang dikodekan titik kurva untuk ECDSA, atau SPKI publik untuk RSA. Kunci RSA harus berukuran 2048–8192 bit. Platformnya mengkanonikalisasi materi yang valid dan membatasi akun hingga 20 kunci aktif secara default. fingerprint adalah intisari hex SHA-256 huruf kecil dari kanonik keyType:keyData rangkaian.

Kembali 201 dengan kunci yang dibuat. Pengembalian materi tidak valid 400; kunci yang sudah aktif atau penuh daftar kunci kembali 409 (yang terakhir termasuk limit). Materi kunci aktif bersifat unik di seluruh platform.

DELETE /api/v1/me/public-keys/{keyId}

Memerlukan sesi yang diautentikasi OAuth. Pencabutan bersifat idempoten dan mengakhiri sesi penyegaran yang dibuat dengan kunci; token akses yang menamainya ditolak pada permintaan berikutnya. Pengembalian:

{ "revoked": [{ "id": "...", "isRevoked": true }], "sessionsEnded": 1 }

Kunci yang tidak diketahui pada akun ini kembali 404.

DELETE /api/v1/me/public-keys/all

Operasi respons kompromi: mencabut setiap kunci aktif dan mengakhiri semua sesi yang diautentikasi. Ini memiliki eksplisit /all jalur sehingga ID kunci yang tidak sengaja kosong tidak dapat menjadi pencabutan massal. Mengembalikan hal yang sama { revoked, sessionsEnded } membentuk.

DELETE /api/v1/me/public-keys/current

Sesi akun lengkap yang diautentikasi dengan kunci publik dapat mencabut kunci yang digunakan untuk sesi tersebut, tanpa menyebutkan ID kunci. Gunakan ini untuk Lupakan perangkat ini. Ini mengembalikan hal yang sama { revoked, sessionsEnded } membentuk dan membatalkan sesi menggunakan kunci itu. Buang token yang disimpan dan kunci pribadi lokal setelah sukses. Sesi tanpa kunci publik kembali 409 dengan code: "no_public_key_session"; token peluncuran game ditolak.

Untuk contoh penerapan mesin yang lengkap, lihat Unggah build dari CI/CD dengan kunci publik terdaftar OAuth.

POST /api/v1/me/identities

{
  "provider": "epic",
  "providerUserId": "your-epic-account-id",
  "metadata": null
}

Nama penyedia yang dikenal platform sebagai OAuth (google, github, discord, twitch, gitlab, linkedin, bitbucket, ditambah nama yang dipesan microsoft, facebook, twitter, x, apple, steam) adalah ditolak di sini apakah penyedia tersebut dikonfigurasi atau tidak — identitas tersebut hanya dapat ditautkan melalui proses masuk yang sebenarnya. Gunakan nama yang tidak dicadangkan (epic, gog, id etalase khusus). Melihat Otentikasi.

DELETE /api/v1/me/identities/{identityId}

Menghapus identitas yang dikelola OAuth memerlukan sesi yang diautentikasi OAuth, sehingga kunci publik dicuri tidak dapat menghapus rute pemilik kembali ke akun. Mengembalikan 204.

Pengaturan privasi

GET /api/v1/me/privacy mengembalikan milikmu PrivacySettings; PUT /api/v1/me/privacy menggantikannya (mengembalikan 204):

{
  "onlineStatus": 1,
  "currentlyPlaying": 1,
  "recentLaunchActivity": 0,
  "hoursPlayed": 0,
  "recentDownloads": 0,
  "achievements": 2,
  "friendDiscoverability": 1,
  "profileVisibility": 2
}

Masing-masing bidang adalah a PrivacyLevel enum: 0 = Pribadi, 1 = Hanya Teman, 2 = Publik.

Kehadiran detak jantung

POST /api/v1/me/heartbeat

Mengembalikan 204. Menulis LastSeenAt sisi server, dibatasi — ini adalah sinyal kehadiran yang digunakan oleh teman dan obrolan.

Token peluncuran dalam lingkup game

Dari titik akhir di halaman ini, token peluncuran cakupan game hanya dapat memanggil:

  • GET /api/v1/users/{id}/avatar
  • GET /api/v1/users/{id}/profile
  • GET /api/v1/me/friends (melihat Teman-teman)
  • GET /api/v1/terms
  • POST /api/v1/me/terms/accept
  • POST /api/v1/me/heartbeat

Segala sesuatu yang lain mengembalikan 403 di bawah pagar lingkup permainan yang dijelaskan dalam Otentikasi.

Konvensi nama tampilan

UI game biasanya ditampilkan nama panggilan daripada nama pengguna saat merender lawan, kembali ke sesuatu seperti "Player " + id.slice(0,8) ketika tidak ada nama panggilan yang disetel. Implementasi referensi catur mengikuti konvensi ini; klien game lain harus melakukan hal yang sama.

Melihat kompatibilitas kredensial Dan kontrak yang dapat dibaca mesin.
