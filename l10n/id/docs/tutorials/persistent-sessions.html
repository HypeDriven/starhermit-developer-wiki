Tutorial: sesi persisten — permainan yang dijeda saat semua orang keluar

Biasanya platform mengakhiri pertandingan yang tidak dimainkan oleh siapa pun: setelah setiap pemain terputus dan tidak ada seorang pun telah kembali dalam waktu lima menit, sesi berakhir sebagai abandoned dengan alasan players_left (melihat API Game — Gameplay WebSocket). Itu tepat untuk catur permainan atau balapan, dan salah untuk sebuah peternakan, pembangun kota, penjara bawah tanah bersama, atau dunia mana pun yang menjadi tempat sekelompok orang pemain kembali ke beberapa hari.

Sebuah permainan bisa diminta sesi yang persisten alih-alih. Sesi persisten dijeda ketika pemutarnya terputus:

  1. Pemain terakhir pergi.
  2. Setelah sekitar 15 detik tanpa ada yang terhubung, platform jeda sesi. Tidak ada yang berjalan: permainan skrip mendapat no onTick panggilan, dan sesi permainan kontainer dihapus dari wadah.
  3. Sesi ini tetap dijeda sesuai kebijakan retensi pemulihannya. Membaca /sessions/{id}/recovery untuk kadaluwarsa apa pun daripada berasumsi itu disimpan selamanya.
  4. Pemain pertama yang terhubung ws/v1/games melanjutkan itu, sebelum perintah pertama mereka adalah ditangani. Permainan berlanjut dari tempat berhentinya.

Halaman ini menunjukkan cara menyalakannya, cara menjaga agar jam game Anda tidak melompati jeda, dan apa yang perlu dilakukan klien Anda.

1. Ikut serta

Kegigihan adalah deklarasi per game, baca saat game Anda dipublikasikan atau diperbarui — publikasikan perbarui setelah mengubahnya. Itu harus secara literal true atau false; hal lain dianggap tidak deklarasi, dan permainan yang menyatakan tidak ada yang berperilaku seperti sebelumnya.

Permainan skrip — statis persistent di game objek (lihat Skrip Permainan):

globalThis.game = {
  persistent: true,
  tickRateHz: 1,
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

Permainan kontainer — persistent di dalam kamu GET /describe jawabannya (lihat Server Game Kontainer):

{ "protocol": 1, "tickRateHz": 20, "maxSessions": 48, "persistent": true }

Tidak ada yang berubah tentang cara sesi dibuat: perjodohan, undangan, titik akhir AI, dan waktu nyata semua ruangan menghasilkan sesi persisten untuk permainan persisten.

2. Pertahankan waktu permainan saat dijeda

Platform tidak menulis ulang ctx.now — jam ini tetap menjadi jam dinding asli, kapan pun Anda mau tampilkan pemain (tenggat waktu, a "panen siap pukul") tetap memaknai apa yang dikatakannya. Sebaliknya, gigih sesi mendapatkan satu bidang konteks tambahan:

ctx.pausedMs   // total milliseconds this session has spent paused, so far

Itu hanya tumbuh, dan hanya pada sesi yang terus-menerus (permainan lain tidak pernah terlihat). Kurangi dan Anda memiliki jam permainan itu berhenti ketika tidak ada orang di sana:

function gameTime(ctx) {
  return ctx.now - (ctx.pausedMs || 0);
}

globalThis.game = {
  persistent: true,
  tickRateHz: 1,

  createSession(ctx) {
    return { ok: true, sessionState: { lastTick: gameTime(ctx), crops: [] } };
  },

  onTick(ctx) {
    var state = ctx.sessionState;
    var t = gameTime(ctx);
    var dt = t - state.lastTick;      // never includes the time the world was paused
    state.crops.forEach(function (crop) { crop.growth += dt; });
    state.lastTick = t;
    return { ok: true, sessionState: state };
  },

  onPlayerMessage(ctx) { /* ... */ }
};

Simpan stempel waktu Anda sendiri di waktu permainan (gameTime(ctx)), tidak masuk ctx.now, dan bandingkan saja melawan waktu pertandingan. Jika kamu ingin dunia untuk bergerak maju tanpa ada yang melihat — tanaman yang tumbuh semalaman - gunakan ctx.now sebagai gantinya dan ikuti langkah pertama setelah resume. Apa pun itu, itu milikmu pilihan; platform hanya melaporkan apa yang terjadi.

Dua detail waktunya:

  • Selama ~15 detik antara pemain terakhir keluar dan jeda, sesi terhenti berdetak secara normal. Pemain yang koneksinya terputus dan langsung kembali tidak menyebabkan jeda.
  • Setelah resume, berikutnya onTick datang satu interval centang kemudian. Waktu yang dijeda tidak diputar ulang sebagai tumpukan kutu yang terlewat.

Sebuah wadah menerima pausedMs di tempat yang sama: di POST /sessions tubuh itu dikirim kapan sesi dipulihkan setelah jeda.

3. Klien Anda

Sesi yang dijeda masih merupakan sesi aktif, jadi alur klien adalah yang sudah Anda miliki:

  • Buat daftar dunia untuk bergabung kembali dengan GET /api/v1/games/{slug}/sessions/mine. Setiap entri memiliki pausedAt stempel waktu saat dijeda dan null sementara seseorang ada di dalamnya, sehingga Anda dapat menunjukkannya "dijeda sejak…" atau "2 teman bermain sekarang" (melihat API Game — Sesi).
  • Bergabunglah kembali dengan membuka ws/v1/games?sessionId=… persis seperti sebelumnya. Resume terjadi selama menghubungkan. Tidak ada yang istimewa "dilanjutkan" bingkai untuk itu — permainan hanya berjalan saat Anda pertama kali perintah tiba — jadi minta atau tunggu pesan status lengkap normal game Anda, seperti yang biasa Anda lakukan ada sambungan ulang.
  • Tangani resume yang gagal. Jika platform tidak dapat melanjutkan sesi — kemungkinan besar sebuah container permainan yang servernya masih dimulai — Anda terima {"type":"error","error":"…"} dan soketnya ditutup dengan kode 1001. Sesi tetap dijeda dan tidak ada yang hilang. Hubungkan kembali setelah beberapa saat mundur (beberapa detik, bertambah), dan tampilkan "memulai dunia…" daripada sebuah kesalahan.
  • presence frame berfungsi seperti biasa, sehingga pemain lain dapat melihat siapa yang ada di dunia saat ini.

4. Mengakhiri sesi yang persisten

Sesi persisten berakhir ketika:

  • laporan permainan Anda a result (nilai pengembalian skrip atau pesan kontrol kontainer), atau
  • pemilik game mengakhirinya (DELETE /api/v1/me/github-games/{id}/sessions/{sessionId}),
  • anggota terakhir secara eksplisit meninggalkan dunia tanpa ruangan /sessions/{id}/leave, atau
  • data pemulihannya yang dijeda akan habis masa berlakunya berdasarkan kebijakan penyimpanan penerapan.

Memutuskan hubungan akan membuat keanggotaan tetap utuh; secara eksplisit meninggalkan menyerah keanggotaan. Melihat Siklus hidup sesi dan pemulihan untuk kedua aliran.

Meminta permainan baru bisa bukan menghentikan sesi pemain yang dijeda, dan sesi yang dijeda tetap dihitung terhadap batas sesi bersamaan per pemain (20 secara default). Beri pemain cara untuk menyelesaikan atau meninggalkan dunia - sebuah "meninggalkan dunia" perintahkan jawaban skrip Anda dengan a result, Misalnya. Jika tidak, pemain yang telah memenuhi batasnya tidak dapat memulai sesuatu yang baru.

onPlayerMessage(ctx) {
  var msg = ctx.message.data;
  if (msg.type === "close-world" && ctx.message.from === ctx.sessionState.ownerId) {
    return { ok: true, sessionState: ctx.sessionState, result: { kind: "closed" } };
  }
  /* ... */
}

5. Permainan kontainer: parkir

Untuk permainan kontainer jeda adalah a taman:

  1. Platform meminta cuplikan akhir (GET /sessions/{id}/snapshot) dan menyimpannya dengan tahan lama.
  2. Ini meruntuhkan sesi (DELETE /sessions/{id}). Wadah Anda berhenti mensimulasikannya, dan jika tidak ada sesi lain yang penerapannya dapat dihentikan setelah periode tidak aktif.
  3. Pada penggabungan berikutnya, ia membuat ulang sesi dengan POST /sessions, membawa yang disimpan snapshot dan yang diperbarui pausedMs — permintaan yang sama seperti pemulihan kerusakan — membangunkan penerapan yang terhenti terlebih dahulu jika diperlukan.

Jadi cuplikan yang Anda kembalikan harus cukup untuk membangun kembali seluruh dunia, bukan hanya untuk melanjutkan beberapa hal detik permainan. Jika snapshot terakhir gagal, sesi diparkir dari periodik terakhirnya pos pemeriksaan. Berbeda dengan kerusakan, parkir dan restorasi tidak diperhitungkan dalam anggaran mulai ulang Anda, dan pemain mendapat no resumed bingkai: tidak ada seorang pun di sana untuk melihat keadaan mundur.

Daftar periksa

  • [ ] persistent: true dideklarasikan (skrip) atau dikembalikan dari /describe (wadah), dan pembaruan diterbitkan.
  • [ ] Pengatur waktu permainan digunakan ctx.now - ctx.pausedMs, atau sengaja digunakan ctx.now dan mengejar ketinggalan.
  • [ ] Daftar klien sessions/mine, menunjukkan pausedAt, dan bergabung kembali ws/v1/games.
  • [ ] Klien mencoba kembali dengan backoff setelah an error diikuti dengan kode tutup 1001 saat terhubung.
  • [ ] Pemain mempunyai cara untuk mengakhiri dunia, sehingga mereka tidak pernah terjebak pada batas sesi.
  • [ ] Snapshot (Container) membangun kembali seluruh dunia.
