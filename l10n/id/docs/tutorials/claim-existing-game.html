Klaim Game yang Ditambahkan Orang Lain

Jika seseorang telah menambahkan game GitHub publik Anda ke StarHermit, Anda tidak perlu membuat daftar kedua. Klaim listingan yang ada untuk menjadi pemilik terverifikasi dan kelola metadatanya, hosting, penerapan, backend server, dan transfer di masa mendatang.

Klaim dilindungi oleh kontrol repositori. Mengetahui ID game atau URL repositori saja tidak cukup. Anda harus membuktikan kendali dengan salah satu dari dua cara berikut:

  1. Tautkan akun GitHub pribadi yang memiliki repositori; atau
  2. Komit ID pengguna StarHermit Anda yang tidak dapat diubah sebagai owner= di repositori starhermit.txt.

Metode kedua sangat berguna untuk repositori milik organisasi, karena saat ini Pemeriksaan login GitHub cocok dengan pemilik repositori pribadi dan tidak menyimpulkan keanggotaan organisasi.

Apa yang diklaim berubah

Klaim yang berhasil:

  • menyimpan ID game/daftar yang ada dan akumulasi riwayatnya;
  • mengubah pengguna StarHermit yang mengelola listingan menjadi Anda;
  • menandai daftar sebagai isVerifiedOwner: true;
  • menyegarkan metadata dan kontrol tepercaya dari starhermit.txt jika memungkinkan;
  • menyediakan atau menyegarkan backend skrip/wadah yang dideklarasikan;
  • mengaktifkan hosting platform jika tersedia dan mengantri penerapan sebagai pending;
  • menghapus akses pengelolaan dari orang yang pertama kali mengirimkan listingan tersebut.

Mengklaim tidak memberikan akses kepada pengirim sebelumnya ke akun GitHub Anda, dan tidak digabungkan Akun pengguna StarHermit. Ini mentransfer pengelolaan daftar spesifik itu.

Sebelum Anda mulai

Anda membutuhkan:

  • Akun StarHermit dan token akses pengguna penuh—bukan token peluncuran dalam lingkup game.
  • Akses tulis ke repositori jika menggunakan owner= metode bukti.
  • ID daftar StarHermit yang ada.
  • Untuk game repositori yang dikloning, valid starhermit.txt di root repositori.

Hanya github.com/<owner>/<repo> repositori dan situs Halaman GitHub mereka berpartisipasi dalam klaim ini mengalir. URL yang dihosting secara sewenang-wenang tidak memiliki kepemilikan repositori GitHub untuk membuktikannya dan tidak dapat diklaim cara.

Contoh penggunaan di bawah ini:

API=https://api.starhermit.com
ACCESS_TOKEN='your-full-user-access-token'
OWNER='your-github-login'
REPO='your-game-repository'

Akses token berlangsung 15 menit. Segarkan milik Anda sebelum memulai jika sudah hampir habis masa berlakunya.

Langkah 1: temukan daftar yang ada

Daftar permainan yang dibagikan:

curl -sS "$API/api/v1/github-games" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

Setiap item menyertakan daftar yang tidak dapat diubah id, dinormalisasi repoUrl, ownerLogin, repoName, itu pengirim saat ini, dan status kepemilikan:

{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "repoUrl": "https://github.com/octocat/orbit-league",
  "ownerLogin": "octocat",
  "repoName": "orbit-league",
  "displayName": "Orbit League",
  "isVerifiedOwner": false,
  "submittedByUserId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "submittedByUsername": "someone-else"
}

Cocokkan keduanya ownerLogin Dan repoName; jangan memilih game hanya karena nama tampilannya serupa. Dengan jq:

GAME_ID=$(
  curl -sS "$API/api/v1/github-games" \
    -H "Authorization: Bearer $ACCESS_TOKEN" |
  jq -r --arg owner "$OWNER" --arg repo "$REPO" \
    '.[] | select((.ownerLogin | ascii_downcase) == ($owner | ascii_downcase)
               and (.repoName | ascii_downcase) == ($repo | ascii_downcase)) | .id' |
  head -n1
)

printf 'Listing ID: %s\n' "$GAME_ID"

Hentikan jika hasilnya kosong. Jangan panggil klaim dengan ID yang disalin dari listingan yang tidak terkait.

Langkah 2: pilih cara membuktikan kepemilikan

Opsi A: tautkan akun GitHub pemilik repositori

Gunakan ini ketika repositori dimiliki langsung oleh login GitHub pribadi Anda.

Dari alur akun/pengaturan StarHermit, mulai GitHub OAuth link mode saat masuk ke Akun StarHermit yang seharusnya mengelola permainan. Menautkan berbeda dengan membuat a akun StarHermit kedua dengan login GitHub.

Alur API dimulai pada:

GET /api/v1/auth/oauth/github/authorize?link=true

Ini digerakkan oleh browser dan menggunakan cookie negara yang berumur pendek. Penautan memerlukan StarHermit terbaru otentikasi. Selesaikan otorisasi GitHub di sesi browser yang sama yang memulainya.

Verifikasi hasilnya:

curl -sS "$API/api/v1/me/github" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

Mengharapkan:

{ "linked": true, "login": "octocat" }

Login yang dikembalikan harus cocok dengan listingan yang ada ownerLogin, tidak peka huruf besar-kecil. Pribadi Login GitHub tidak membuktikan keanggotaan organisasi yang memiliki repositori. Untuk sebuah repositori milik organisasi, gunakan Opsi B.

Opsi B: tambahkan owner= ke starhermit.txt

Hal ini membuktikan kontrol karena hanya seseorang yang mampu mempublikasikan konten repositori yang dapat menambah nilai. Mengatur owner ke ID pengguna StarHermit (UUID) Anda yang tidak dapat diubah, bukan nama pengguna atau nama panggilan Anda.

Dapatkan ID Anda:

STARHERMIT_USER_ID=$(
  curl -sS "$API/api/v1/me" \
    -H "Authorization: Bearer $ACCESS_TOKEN" |
  jq -r '.id'
)

Di root repositori, buat atau perbarui starhermit.txt:

name=Orbit League
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html
owner=3fa85f64-5717-4562-b3fc-2c963f66afa6

Ganti pemilik contoh dengan STARHERMIT_USER_ID. Jangan masukkan nama pengguna atau nama panggilan Anda di sini; hal tersebut dapat berubah, sedangkan ID pengguna adalah pengidentifikasi kepemilikan yang stabil.

Untuk game resmi, pertahankan satu deklarasi backend:

# JavaScript runtime:
server=server.js

# OR container runtime, never both:
# container.image=ghcr.io/your-org/orbit-server@sha256:<64-lowercase-hex>

Komit dan dorong manifes ke repositori/versi yang dapat dibaca StarHermit:

git add starhermit.txt
git commit -m "Declare StarHermit game ownership"
git push

Sebelum mengklaim, buka repositori mentahnya starhermit.txt URL di browser yang tidak diautentikasi dan konfirmasikan nilai baru dapat dibaca publik. Mengklaim membaca repositori pada waktu permintaan; sebuah perubahan lokal yang tidak didorong tidak dapat membuktikan apa pun.

Langkah 3: validasi manifes

Untuk game repositori kloning normal, klaim memerlukan:

  • starhermit.txt di root repositori;
  • tidak kosong name=;
  • launch= menunjuk ke relatif repositori .html atau .htm mengajukan;
  • opsional yang valid server= jalan berakhir di .js/.mjs, atau valid container.image= pernyataan;
  • jangan pernah kedua runtime server sekaligus.

Daftar Halaman GitHub mempertahankan URL yang dihostingnya sebagai target peluncuran dan tidak memerlukan manifes ketika kepemilikan GitHub pribadi terbukti, meskipun nama manifes yang valid masih dapat memperbaruinya nama tampilan.

Jika game mendeklarasikan sebuah container, image-nya harus memenuhi registri, namespace pemilik, dan intisari aturan di Server Game yang dihosting oleh kontainer. Container hosting juga bisa dibatasi oleh operator platform.

Langkah 4: klaim daftarnya

Permintaan klaim tidak memiliki badan:

curl -sS -X POST \
  "$API/api/v1/me/github-games/$GAME_ID/claim" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

Sukses 200 mengembalikan game yang diperbarui:

{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "repoUrl": "https://github.com/octocat/orbit-league",
  "ownerLogin": "octocat",
  "repoName": "orbit-league",
  "displayName": "Orbit League",
  "launchPath": "index.html",
  "gameSlug": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "isVerifiedOwner": true,
  "metadataSource": "starhermit.txt",
  "hosting": {
    "hostingEnabled": true,
    "deployStatus": "pending"
  }
}

ID harus sama dengan yang ditemukan pada Langkah 1. Jangan membuat listing baru setelah klaim berhasil.

Mengklaim listingan yang sudah Anda kelola diperbolehkan dengan sengaja. Ia membaca ulang manifesnya, menyediakan kembali backend, dan mengantri ulang hosting, sehingga panggilan yang sama dapat digunakan untuk menyinkronkan ulang game yang dikelola pemilik setelah perubahan repositori.

Langkah 5: verifikasi pengambilalihan dan penerapan

Konfirmasikan bahwa game tersebut sekarang muncul di daftar terkelola Anda:

curl -sS "$API/api/v1/me/github-games" \
  -H "Authorization: Bearer $ACCESS_TOKEN" |
jq --arg id "$GAME_ID" '.[] | select(.id == $id)'

Periksa status penerapan:

curl -sS \
  "$API/api/v1/me/github-games/$GAME_ID/deployment" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

Klaim biasanya mengantri penerapan, jadi pending segera setelah klaim normal. Jajak pendapat dengan mundur hingga mencapai status hidup/sukses lingkungan atau terpapar deployError.

Setelah pengambilalihan, titik akhir pengelolaan yang tersedia untuk Anda meliputi:

PUT    /api/v1/me/github-games/{id}/deployment  pin a commit/branch and redeploy
POST   /api/v1/me/github-games/{id}/bundle      upload built client/container output
PUT    /api/v1/me/github-games/{id}/hosting     requeue hosting where supported
POST   /api/v1/me/github-games/{id}/transfer    transfer management deliberately
DELETE /api/v1/me/github-games/{id}             remove the game

Pengirim asli tidak lagi melihat daftar ini di bawah GET /api/v1/me/github-games dan tidak bisa gunakan titik akhir pengelolaan cakupan pemilik ini untuk itu.

Pemecahan masalah

403: tautkan pemilik repositori atau tambahkan owner=

Login GitHub yang tertaut tidak cocok ownerLogin, atau manifes owner tidak sama persis ID pengguna StarHermit Anda.

  • Memeriksa GET /api/v1/me/github.
  • Periksa persisnya ownerLogin dikembalikan oleh daftar publik.
  • Untuk repositori organisasi, gunakan owner=<your StarHermit user ID> di repo.
  • Konfirmasikan bahwa Anda mengirimkan manifes dan URL mentahnya dapat dibaca oleh publik.

404: tidak ada permainan bersama dengan ID itu

ID salah, atau listingan telah dihapus. Ulangi Langkah 1. Listing yang dihapus tidak dapat diklaim.

400: hilang atau tidak valid starhermit.txt

Untuk repositori yang dikloning, pastikan manifes root valid name dan HTML launch nilai-nilai. Juga memvalidasi deklarasi skrip/wadah opsional. Klaim tersebut awalnya tidak mempercayai metadata dimasukkan oleh bukan pemilik; itu menggantikannya dengan metadata yang dikontrol repositori.

Klaim gagal di sekitar slug/backend

Skrip mungkin tidak valid atau hosting kontainer mungkin tidak tersedia. Periksa kesalahan yang dikembalikan dan deklarasi backend, lalu panggil klaim lagi. Platform menetapkan UUID game sebagai slugnya; tidak ada siput nyata untuk dipilih atau diselesaikan.

GitHub telah ditautkan tetapi akun StarHermit yang salah memiliki tautan tersebut

Masuk ke akun StarHermit yang dimaksud dan lengkapi OAuth link mengalir ke sana. Jangan mengklaim dari akun StarHermit kedua sementara dan kemudian mengandalkan penggabungan akun; permainan transfer API manajemen, bukan identitas pengguna.

Catatan keamanan

  • Jangan pernah menerima tautan klaim atau ID daftar sebagai bukti kepemilikan repositori.
  • Jangan masukkan token akses GitHub, kredensial kontainer, atau rahasia lainnya starhermit.txt.
  • Selalu gunakan ID pengguna StarHermit yang tidak dapat diubah owner=; jangan gunakan nama pengguna atau nama panggilan.
  • Tinjau URL listingan dan repositori yang ada sebelum mengklaim; nama tampilan tidak unik.
  • Jika nanti Anda mentransfer permainan, penerima menjadi pengelola tetapi status pemilik terverifikasi menjadi pengelola mengatur ulang. Mereka harus menjalankan sendiri aliran klaim jika mereka mengontrol repositori.
