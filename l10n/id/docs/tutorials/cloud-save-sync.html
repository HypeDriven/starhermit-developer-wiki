Muat dan simpan kemajuan dengan aman

Gunakan penyimpanan cloud untuk kemajuan milik klien pemain yang masuk. Opsi pemain tunggal yang tidak ditandatangani menyimpan kemajuan dalam memori dan tidak membaca atau menulis simpanan akun. Preferensi termasuk dalam pengaturan permainan, bukan dokumen kemajuan.

Token peluncuran dapat mengakses dengan tepat game:<gameId>, Di mana gameId adalah itu game_scope. Platformnya menyimpan byte buram, dengan satu simpanan per slot. Validasi format yang diharapkan game Anda. Melihat Simpanan cloud untuk kuota dan header bersyarat.

Resep kecil JSON lengkap

Menyalin cloud-save-store.js ke dalam bangunan Anda. Contoh ini menyimpan mentah byte UTF-8 JSON; platform melayani mereka application/zip tetapi tidak memerlukan format ZIP. Gunakan pembaca yang berbeda untuk menyimpan ZIP, termasuk penyimpanan ZIP SDK browser. Jangan mengubah format tanpa rencana migrasi untuk pemain yang sudah ada.

import { CloudSaveStore } from './cloud-save-store.js';

const store = new CloudSaveStore({
  gameId: StarHermit.slug,
  token: () => StarHermit.token, // Always obtain the current renewed token.
});
const valid = value => value?.version === 1 && Number.isSafeInteger(value.points) && value.points >= 0;
let progress = { version: 1, points: 0 };
let saving = false;

async function startAccountGame() {
  // Keep gameplay/saving disabled until this resolves.
  const remote = await store.load(valid);
  progress = remote ?? { version: 1, points: 0 };
  render(progress);
}

async function saveCheckpoint() {
  if (saving) return; // Coalesce checkpoints; do not issue overlapping writes.
  saving = true;
  showSync('Saving…');
  try {
    await store.save(progress);
    showSync('Saved');
  } catch (error) {
    if (error.status === 412) {
      // Keep local progress in memory. Offer Reload cloud or an explicit merge.
      showConflict(() => startAccountGame());
    } else showSync('Save failed; retry after resolving the error');
  } finally {
    saving = false;
  }
}

render, showSync, Dan showConflict adalah UI Anda. Menunggu startAccountGame() sebelum mengaktifkan bermain atau menyimpan. Saat beban gagal, pertahankan status lokal pemutar saat ini, tampilkan kegagalan, dan tetap memblokir unggahan. A 404 adalah kotak dengan slot kosong; 401, 403, 5xx, format JSON salah, atau versi penyimpanan yang tidak didukung bukanlah slot kosong.

Resepnya tidak memperbarui kredensial. SDK browser memperbarui token peluncuran selagi masih ada sah. Selesaikan persyaratan yang tertunda atau autentikasi ulang alur entri game sebelum mencoba membaca lagi.

Kondisi dan konflik

Apa yang dimuat Header pada tulisan berikutnya Jika perangkat lain menulis
Penyimpanan yang ada dengan ETag If-Match: <etag> 412 precondition_failed
Tidak ada penyimpanan (404) If-None-Match: * 412 precondition_failed
Tidak ada yang berhasil dimuat Tidak ada tulisan Terus ulangi pembacaan atau biarkan pemain tetap bermain tanpa terlacak

Gunakan versi dari data yang Anda muat, bukan pemeriksaan metadata nanti. Simpan ETag baru yang dikembalikan oleh setiap penulisan yang berhasil. A 412 memblokir penyimpanan lebih lanjut hingga game memuat versi saat ini dan pemain mengadopsi atau menggabungkannya. Jangan diam-diam menghapus kondisi tersebut dan menimpa perangkat lain. API tidak menawarkan riwayat penyimpanan untuk membatalkan penimpaan tersebut.

Jika dua perangkat harus memperbarui penghitung atau inventaris secara independen, satu dokumen yang ditulis terakhir akan menang mungkin tidak cocok dengan permainannya. Gunakan status otoritatif server dan tentukan perintah game yang divalidasi.

Simpan format dan migrasi

Sertakan versi format dan validasi jenis, rentang, dan bidang wajib sebelum mengadopsi jarak jauh kemajuan. Tulis migrasi untuk versi lama yang didukung. Pertahankan versi baru yang tidak diketahui tetap utuh; jangan setel ulang ke default dan unggah di atasnya. Data cloud dikontrol oleh klien, jadi jangan pernah memperlakukannya sebagai bukti skor kompetitif atau hak berbayar.

Batas penyimpanan dekode default adalah 10 MiB. Base64 menambahkan sekitar sepertiga ke badan permintaan. 413 cloud_save_too_large, 409 cloud_save_slots_exhausted, Dan 507 cloud_save_quota_exceeded adalah kegagalan kapasitas yang berbeda; memeriksa code Dan limit. Menghormati Retry-After pada 429.

Pos pemeriksaan dan halaman keluar

Simpan di pos pemeriksaan yang bermakna dan tawarkan tindakan Simpan yang terlihat. Hapus perubahan cepat dan buat serial menulis sehingga masing-masing menggunakan versi terakhir yang diakui. Simpan indikator kotor sampai diketahui. Permintaan yang gagal bukan merupakan penyimpanan yang dikonfirmasi; setelah penulisan yang ambigu, muat ulang sebelum penulisan lainnya.

Unggahan keluar halaman adalah upaya terbaik. Peramban fetch(..., { keepalive: true }) berbagi penerbangan kecil tunjangan badan, umumnya 64 KiB; penghematan 10 MiB tidak dapat mengandalkannya. Tab mungkin ditutup sebelum permintaan apa pun selesai. Gunakan penyimpanan latar depan biasa untuk ketahanan, dan jangan beri label kemajuan yang tidak diakui sebagai disimpan. Mulai cepat menyimpan dokumen kecilnya di setiap pengumpulan titik.

Verifikasi di game Anda

  1. Mulailah dengan slot kosong; kumpulkan kemajuan, simpan, muat ulang, dan konfirmasikan pengembaliannya.
  2. Menolak membaca dengan kesalahan jaringan, 403, atau data tidak valid; konfirmasi tidak ada unggahan berikut.
  3. Buka dua tab pada satu versi. Kecuali di A, maka B: B harus memunculkan konflik dan mempertahankan keadaan lokalnya.
  4. Uji format lama/baru dan pengakuan yang hilang tanpa menimpa data yang tidak dikenal.
  5. Masuk ke mode pemain tunggal yang tidak terlacak dan verifikasi bahwa pemutaran tidak membuat permintaan penyimpanan cloud.

Melihat mulai cepat yang dapat dijalankan, konvensi API, Dan pemecahan masalah.
