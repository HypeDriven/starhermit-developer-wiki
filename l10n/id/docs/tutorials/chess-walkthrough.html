Panduan integrasi: membuat game di StarHermit

Halaman ini menjelaskan siklus hidup penuh pengintegrasian game dengan StarHermit, langkah demi langkah — publikasikan, luncurkan, menu, perjodohan, mainkan, obrolan, suara, peringkat, putar ulang. Semua yang ditampilkan berlaku untuk setiap game: game Anda menggantikan slugnya sendiri, perintahnya sendiri, dan skrip aturannya sendiri.

Contoh yang berjalan adalah implementasi referensi catur sumber terbuka, catur pertapa bintang: permainan catur korespondensi (24 jam per gerakan, diberi peringkat elo) yang dibuat sebagai permainan browser statis tanpa build dalam vanilla HTML/JS/CSS. Untuk setiap langkah, panduan ini menunjukkan panggilan persis yang dilakukan klien game dan file dalam repo referensi yang melakukan panggilan tersebut. Di mana pun nilai khusus catur muncul — UUID permainan referensi, perintah gerakan, pengkodean papan, dan sebagainya "hal" AI, batas waktu perpindahan 24 jam — itu adalah contoh nilai yang ditentukan oleh game Anda sendiri dalam skripnya sendiri.

Bacalah di samping halaman referensi API yang ditautkannya. Daftar periksa di bagian akhir merangkum semuanya menjadi apa yang perlu ditiru oleh game Anda sendiri.

1. Anatomi game yang dihosting platform

Game platform bernaskah adalah situs statis biasa ditambah satu file aturan. Implementasi referensi catur, misalnya, tidak memiliki bundler, tidak memiliki kerangka kerja, tidak ada langkah pembuatan:

Mengajukan Peran
index.html Seluruh halaman: papan, menu, obrolan, dan UI suara
app.js Bootstrap aplikasi, menu utama, perjodohan, undangan, pemutaran ulang, profil
net.js Lapisan HTTP: jalur permainan tercakup, token peluncuran, penyegaran token
game.js Pengontrol dalam game: gameplay WebSocket, obrolan, suara
ui.js Rendering papan dan menu
style.css Gaya
server.js Aturannya — lihat di bawah
starhermit.txt Publikasikan manifes

Dalam implementasi referensi, server.js patut mendapat perhatian khusus. Dia keduanya hal-hal sekaligus:

  • Itu skrip otoritatif server platform mengeksekusi (melalui host Jint-nya) dengan mengekspos globalThis.game. Setiap gerakan divalidasi di sini, di server, sesuai kontrak game-scripts.md.
  • milik klien mesin aturan bersama, diekspos sebagai globalThis.chessRules, yang digunakan browser untuk rendering papan, memindahkan pratinjau, dan memutar ulang pemutaran.

Satu file, satu sumber kebenaran, nol aturan otoritas pada klien. Klien game yang mengikuti pola ini tidak pernah memutuskan apakah suatu perpindahan sah atau tidak — ia akan menampilkan apa yang disiarkan oleh server. Ini adalah satu-satunya ide arsitektur terpenting dalam permainan platform bernaskah, dan implementasi referensi menunjukkannya.

2. Publikasikan game Anda

Penerbitan game apa pun dimulai dengan starhermit.txt bermanifestasi di root repo. Ini menyatakan permainan itu name, launch titik masuk, owner, Dan server naskah. Opsional cover= adalah karya seni di ubin perpustakaan — lihat Itu starhermit.txt tampak. Manifes implementasi referensi, misalnya:

name=StarHermit Chess
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html
owner=3fa85f64-5717-4562-b3fc-2c963f66afa6  # StarHermit user ID, not username/nickname
server=server.js

Gunakan yang tidak dapat diubah id dari GET /api/v1/me untuk owner; nama pengguna dan nama panggilan ditampilkan nilai-nilai dan tidak boleh digunakan sebagai pengidentifikasi kepemilikan nyata.

Platform mengkloning repo, menyajikan file statis di <slug>.starhermit.com — slug adalah cairan yang diberikan platform untuk game tersebut, bukan nama yang Anda pilih; permainan referensinya adalah 83fd04b1-3cbe-4b09-a251-3733ad4b9d94, jadi dapat dimainkan secara langsung 83fd04b1-3cbe-4b09-a251-3733ad4b9d94.starhermit.com — dan proxy /api Dan /ws ke bagian belakang asal yang sama. Satu keputusan tersebut menghapus seluruh kategori pekerjaan: tanpa CORS, tanpa konfigurasi berbasis API, tanpa deteksi lingkungan — klien game hanya menggunakan jalur relatif.

Aliran penuh: github-games.md Dan publisher.md.

3. Peluncuran dan otentikasi

Alur referensi catur menerima kredensial dari peluncur platform:

  1. Peluncur memanggil POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/launch-token (ditunjukkan dengan UUID game referensi; gantikan milik Anda sendiri) dengan JWT platform lengkap pengguna.
  2. Itu akan kembali berumur pendek, lingkup permainan token:
{ "token": "<jwt>", "expiresInSeconds": 3600 }
  1. Ini membuka permainan di index.html#game_token=<jwt>, opsional dengan &session_id=<guid> ditambahkan untuk tautan dalam undangan.

Dalam implementasi referensi, klien membaca hash sekali, lalu kupas dengan history.replaceState jadi token tidak pernah tertinggal di bilah URL atau riwayat (app.js, App.init). Ini menerjemahkan payload JWT untuk dua klaim:

  • sub — id pengguna
  • game_scope — siput permainan

Klaim kedua itu penting: klien game tidak boleh melakukan hard-code pada slugnya. Implementasi referensi membangun setiap URL API sebagai /api/v1/games/<slug> ditambah akhiran (net.js, Net.gamePath), jadi kode yang sama berfungsi untuk game apa pun, slug apa pun, penerapan apa pun.

Menyegarkan. Token yang dicakup diizinkan untuk melakukan panggilan ulang launch-token untuk permainannya sendiri, sehingga klien biasanya menyegarkan secara berkala — implementasi referensi menyegarkan setiap 45 menit (net.js, Net.startRefresh), dengan nyaman dalam masa hidup 60 menit.

Sebuah permainan yang dibuka secara langsung malah bisa menawarkan masuk browser, yang kembali #access_token daripada peluncurnya #game_token. Tangani kedua jalur masuk jika kamu mendukung keduanya. Perpanjang menggunakan masa pakai yang dikembalikan dan patuhi rantai perpanjangan 12 jam default langit-langit. A 403 terms_acceptance_required mengharuskan pemain untuk melakukannya terima melalui akun mereka; atau tampilkan persyaratan dalam game dan terima dengan token peluncuran pemain. Masuk lagi tidak penerimaan rekaman.

Referensi autentikasi: auth.md, games.md.

4. Memuat menu utama

Menu permainan biasanya dibuka dengan sejumlah kecil GET melawan slugnya sendiri. Dalam implementasi referensi ini adalah refreshMenu di dalam app.js:

Info permainan + statistik saya:

GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94

{
  "slug": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "name": "StarHermit Chess",
  "enabled": true,
  "leaderboardId": "<guid>",
  "maxConcurrentSessionsPerPlayer": 20,
  "me": {
    "userId": "<guid>",
    "elo": 1420,
    "wins": 31,
    "losses": 18,
    "draws": 4,
    "activeSessionCount": 3
  }
}

Itu me blok adalah seluruh kartu pemain — elo, rekaman, dan berapa banyak sesi bersamaan yang diizinkan yang digunakan (20 dalam contoh catur).

Sesi saya:

GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/sessions/mine

[
  {
    "sessionId": "<guid>",
    "status": "active",

]

myTurn Dan deadline Inilah yang membuat daftar sesi permainan korespondensi berguna — pemain melihat sekilas permainan mana yang menunggunya dan kapan setiap gerakan harus dilakukan.

Papan peringkat teman:

GET /api/v1/leaderboards/{leaderboardId}/entries?friendsOnly=true&page=1&pageSize=10

menggunakan leaderboardId dari respons info game.

Referensi: games.md, leaderboards.md.

5. Mengajak pemain mengikuti suatu sesi — ada tiga cara

Panduan ini menggunakan perjodohan, penerimaan undangan, dan latihan AI untuk membuat sesi. Permainan yang memerlukan lobi dapat digunakan ruangan waktu nyata, yang alur awalnya juga dapat membuat sesi otoritatif yang terikat.

A. Penjaruman

Dalam implementasi referensi, App.startMatchmaking di dalam app.js:

POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/matchmaking

Responsnya berupa tiket:

{ "ticketId": "<guid>", "status": "queued" }

atau pertandingan langsung:

{ "status": "matched", "sessionId": "<guid>" }

Saat mengantri, klien melakukan polling pada titik akhir pencocokan — jajak pendapat implementasi referensi GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/matchmaking setiap 3 detik, dan DELETE /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/matchmaking membatalkan tiketnya. Klien referensi juga memastikan pemain tidak pernah terjebak menatap pemintal: setelah 30 detik tak tertandingi, a "Bermain melawan hal" tombol muncul ("hal" adalah lawan AI bawaan dari contoh catur — lihat §12), dan POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/sessions/ai kembali { "sessionId" }.

B. Undangan teman

Dalam implementasi referensi, App.inviteFriend di dalam app.js. Daftar teman pertama — titik akhir ini secara eksplisit diizinkan untuk token dalam cakupan game:

GET /api/v1/me/friends

Kemudian kirimkan undangannya:

POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/invites
{ "toUserId": "<guid>" }

Penerima menerima (atau menolak) dari kliennya sendiri:

POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/invites/{id}/accept   → { "sessionId": "<guid>" }
POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/invites/{id}/decline  → 204

Menerima itulah yang menciptakan sesi. Itu &session_id= launch-hash deep-link (§3) langsung memasukkan pemain yang diundang ke dalamnya.

Undangan pertemanan hanya menjangkau orang-orang yang sudah berteman. Untuk menarik seseorang yang tidak (atau tidak berada di platform sama sekali), implementasi referensi juga menawarkan a Bagikan tautan undangan tombol (App.shareInviteLink): satu baris bangunan string yang disalin

https://dashboard.starhermit.com/game-invite/<Net.userId>/<slug>

ke papan klip. Dasbor web menangani semua yang dibutuhkan penerima — login, permintaan pertemanan, nama panggilan, meluncurkan game — lalu mengirimkan undangan bermain kembali ke pembagi, sehingga masuk ke daftar undangan yang sama. Melihat Bagikan tautan untuk kontrak penuh.

C. Aturannya

Sesi dibuat dengan perjodohan, penerimaan undangan, sessions/ai, atau memulai ruang waktu nyata dengan ujung belakang server. Untuk lobi dengan kursi, gunakan API ruangan waktu nyata.

6. Memainkan gameplay WebSocket

Putaran pemutarannya sama untuk setiap game yang diberi skrip: ambil sesi, buka soket, render siaran, kirim perintah. Dalam implementasi referensi, ini ada di dalamnya game.js, GameController.

Ambil sesi:

GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/sessions/{sessionId}

{
  "sessionId": "<guid>",
  "status": "active",
  "players": [ /* ... */ ],
  "createdAt": "…",
  "finishedAt": null,
  "chatConversationId": "<guid>",
  "result": null
}

Catatan chatConversationId — Anda memerlukannya untuk obrolan (§7) dan suara (§8).

Hubungkan soket gameplay:

ws(s)://<host>/ws/v1/games?sessionId=<id>&access_token=<token>

Pada open, klien segera mengirimkan perintah sinkronisasi:

{ "type": "cmd", "data": { "type": "sync" } }

Pada setiap pemutusan sambungan, ia akan tersambung kembali dengan backoff eksponensial dari 1 detik hingga batas atas 30 detik, dan mengirim ulang sinkronisasi pada setiap pembukaan. Perintah sinkronisasi membuat koneksi ulang menjadi tanpa status dan idempoten: apa pun yang dilewatkan klien, server akan menyiarkan ulang.

Amplop. Setiap frame adalah amplop JSON tipis:

  • Klien → server: {"type":"cmd","data":<command>}
  • Server → klien: {"type":"game","data":…}, {"type":"error","error":…}, {"type":"presence","userId","online"}

Perintah permainan ditentukan oleh skrip aturan Anda sendiri. Perintah contoh catur, misalnya (the data muatan a cmd bingkai):

{ "type": "sync" }
{ "type": "move", "from": "e2", "to": "e4", "promo": "q" }
{ "type": "resign" }
{ "type": "offer-draw" }
{ "type": "accept-draw" }
{ "type": "decline-draw" }

Dalam contoh catur, promo hanya hadir pada gerakan promosi.

Siaran juga ditentukan oleh skrip. Siaran contoh catur (the data muatan a game bingkai):

  • state — cuplikan lengkapnya:
{
  "type": "state",
  "white": "<userId>",
  "black": "<userId>",
  "ratings": { "white": 1420, "black": 1388 },
  "board": "RNBQKBNRPPPPPPPP................................pppppppprnbqkbnr",
  "turn": "w",
  "moves": [ { "from": "e2", "to": "e4", "promo": null, "san": "e4", "at": "…" } ],
  "status": "active",
  "result": null,
  "deadline": 1784642591000,
  "drawOfferBy": null,
  "ai": false,
  "aiName": null
}

Itu board adalah string 64 karakter, index = rank * 8 + file dengan a1 = 0, menggunakan PNBRQK untuk putih, pnbrqk untuk hitam, . untuk kotak kosong — pengkodean khusus catur; game Anda menentukan bentuk statusnya sendiri.

  • moved – satu gerakan diterapkan.
  • draw-offered / draw-declined.
  • game-over — { "result": { "kind", "reason", "at" }, "view" }, Di mana reason nilai ditentukan oleh skrip; contoh catur yang digunakan checkmate, stalemate, threefold-repetition, fifty-move-rule, insufficient-material, resignation, agreement, timeout, timeout-no-moves.

Identitas tidak pernah diambil dari muatan. Klien mengirimkan perintah tanpa id pengguna, dan skrip tidak pernah mempercayai perintah langsung — platform meneruskan pengirim yang diautentikasi ke skrip. Tidak ada yang perlu dipalsukan.

Melihat game-scripts.md untuk kontrak naskah di balik semua ini.

7. Obrolan dalam game

Setiap sesi membawa a chatConversationId (§6) yang dapat digunakan klien game untuk obrolan dalam game. Dalam implementasi referensi, initChat di dalam game.js menggunakannya seperti ini:

GET  /api/v1/chat/conversations/{id}/messages?page=1&pageSize=50
POST /api/v1/chat/conversations/{id}/messages
     { "content": "good luck!" }

Soket obrolan waktu nyata ws/v1/chat adalah diblokir untuk token cakupan game. Klien referensi mencobanya sekali, ditolak, dan kembali melakukan polling pada titik akhir REST setiap 5 detik — rencanakan untuk melakukan polling dari awal di game Anda sendiri.

Obrolan berfungsi meskipun kedua pemain mungkin bukan teman: percakapan sesi (ketik "game") dibuat dengan kedua pemain sebagai peserta, jadi aturan izin obrolan biasa sudah dipenuhi.

Referensi: chat.md.

8. Suara

Suara bersifat opt-in, dan klien game biasanya menyimpannya mati secara default. Implementasi referensi menanganinya game.js, VoiceController. Saat pemain mengaktifkannya:

  1. Temukan atau buat ruangan yang terikat dengan percakapan sesi:
GET  /api/v1/voice/rooms?conversationId=<chatConversationId>
POST /api/v1/voice/rooms
     { "conversationId": "<chatConversationId>" }
  1. Bergabunglah:
POST /api/v1/voice/rooms/{roomId}/join
  1. Hubungkan soket suara:
ws(s)://<host>/ws/v1/voice?roomId=<id>&access_token=<token>

Media adalah WebRTC peer-to-peer dengan negosiasi sempurna; soket hanya membawa sinyal dan kontrol:

  • Sinyal: {"type":"rtc","to":<userId>,"payload":{"sdp":…}} atau {"type":"rtc","to":<userId>,"payload":{"ice":…}}
  • Kontrol: {"type":"mute","muted":…}, {"type":"speaking","speaking":…}
  • Acara server: voice.roster, voice.participant_joined, voice.participant_left, voice.mute_changed, voice.speaking, voice.rtc

Jika P2P gagal, cadangannya adalah frame biner opus yang dikirimkan ke server: id pengirim 16 byte diikuti dengan payload audio.

Suara adalah dinonaktifkan di game AI — klien referensi memeriksa view.ai dari siaran negara dan tidak pernah menawarkan sakelar.

Referensi: voice.md.

9. Peringkat dan papan peringkat

Klien game tidak pernah mengirimkan skor. Saat pertandingan berakhir, naskah kembali eloUpdates dan itu platform mempublikasikannya ke papan peringkat game. Klien tidak pernah bisa menulis entri papan peringkat secara langsung; server juga harus memvalidasi gameplay di balik pembaruan peringkatnya.

Oleh karena itu, sisi klien sepele: baca entri (§4) dan render, seperti yang dilakukan implementasi referensi. Melihat leaderboards.md.

10. Memutar ulang

Sebuah permainan yang menyatakan replays: true dalam skripnya setiap sesi yang telah selesai disimpan oleh platform; klien cukup mengambil dan merendernya. Memeriksa replaysEnabled pada GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94 sebelum menawarkan layar — operator dapat menjawab permainan dengan cara apa pun, dan titik akhir di bawah akan kembali 404 saat tayangan ulang dimatikan. Dalam implementasi referensi, pengambilannya adalah App.loadReplays / App.openReplay di dalam app.js:

GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/replays/mine?limit=10
GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/replays/{sessionId}

Payload replay (ditunjukkan dengan bentuk hasil contoh catur):

{
  "sessionId": "<guid>",
  "players": [ /* ... */ ],
  "finishedAt": "…",
  "result": {
    "kind": "win",
    "reason": "checkmate",
    "at": "…",
    "white": "<userId>",
    "black": "<userId>",
    "moveCount": 41,
    "eloBefore": { "white": 1420, "black": 1388 },
    "eloAfter": { "white": 1436, "black": 1372 }
  },
  "state": { "game": { "moves": [ /* ... */ ] } }
}

Langkah pemirsa state.game.moves melalui yang dibagikan chessRules mesin secara lokal — sama server.js file aturan, berjalan di browser — jadi pemutaran ulang tidak memerlukan server bolak-balik; pertahankan versi aturan yang digunakan untuk pencocokan yang diarsipkan saat aturan berubah. Ini adalah hasil kedua dari desain satu file-dua peran dari §1, sebuah pola yang dapat diadopsi oleh game mana pun dengan file aturannya sendiri.

11. Profil pemain

Klien game menyelesaikan pemain lain melalui titik akhir profil publik. Dalam implementasi referensi, App.profileFor di dalam app.js:

GET /api/v1/users/{id}/profile  → { "id": "…", "username": "…", "nickname": "…" }
GET /api/v1/users/{id}/avatar   → image/png, or 404

Dua aturan UI yang diikuti klien referensi:

  • Memberikan nama panggilan, tidak pernah nama pengguna.
  • Jatuh kembali ke "Player " + id.slice(0, 8) ketika profil tidak ada atau nama panggilan kosong.

Referensi: profile.md.

12. AI melatih lawan

POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/sessions/ai (ditunjukkan dengan contoh slug) membuat sesi di mana platform menandai satu kursi ai: true di dalam createSession. Skrip itu sendiri yang berperan — perilaku AI adalah sesuatu yang ditentukan oleh skrip Anda sendiri. Dalam contoh catur, kursinya dimainkan oleh "hal", mesin penangkap material rakus yang membalas dalam pemanggilan yang sama yang memproses gerakan manusia.

Skrip permainan memutuskan apakah latihan akan mengubah peringkat pemain manusia. Kursi AI tidak bisa menerima status pemain akun, peringkat, atau pencapaian menulis. Simpan semua statistik AI dalam status sesi.

13. Apa yang TIDAK digunakan oleh game referensi

Implementasi referensi catur tidak menyentuh satupun dari hal-hal tersebut, namun semuanya tersedia untuk permainan yang memerlukannya:

  • Prestasi — permainan apa pun dengan a server= skrip dapat mendeklarasikannya (game.achievements) dan memberi mereka server-otoritatif dari hook siklus hidup apa pun; catur tidak. Judul katalog memiliki jalur terpisah yang diklaim klien: achievements.md, game-scripts.md.
  • Katalog / hak — untuk game yang didistribusikan dan dijual melalui katalog: catalog.md.
  • Menyampaikan — saluran relai frekuensi tinggi untuk permainan real-time yang bergerak cepat dengan skrip per-perintah yang berjalan bolak-balik terlalu lambat: relay.md.
  • Perpustakaan eksternal — menghubungkan perpustakaan game Steam, Epic, atau GOG: external-libraries.md.

Contoh catur, permainan papan berbasis giliran, tidak memerlukan satupun dari itu. Jika game Anda bersifat real-time, terdistribusi dalam katalog, atau memerlukan muatan biner, halaman-halaman tersebut adalah tempat untuk mencarinya selanjutnya.

14. Daftar periksa integrasi

  • [ ] Tambahkan a starhermit.txt tampak (name, launch, owner, server; opsional cover= untuk ubin perpustakaan).
  • [ ] Membaca #game_token dari hash URL satu kali, lalu hapus dengan history.replaceState.
  • [ ] Dekode JWT untuk sub (id pengguna) dan game_scope (siput) — jangan pernah melakukan hard-code pada slug Anda.
  • [ ] Bangun semua jalur API sebagai URL relatif asal yang sama: /api/v1/games/<slug> + akhiran.
