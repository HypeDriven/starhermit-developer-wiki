Publikasikan Server Game Khusus dan Pemain Onboard Dalam Game

Tutorial ini menunjukkan cara:

  1. Publikasikan atau perbarui wadah server game khusus dengan API unggahan bundel StarHermit.
  2. Terus perbarui token server StarHermit kontainer yang sudah berjalan lama.
  3. Pemain onboard dari Steam, Epic, GOG, atau build mandiri tanpa mengirimkannya melalui Penyedia OAuth atau mengharuskan mereka mengunjungi dasbor StarHermit.
  4. Berikan para pemain tersebut akses ke sesi StarHermit, perjodohan, papan peringkat, pencapaian, sesi obrolan, suara, teman, kehadiran, dan pemutaran ulang.

API yang dihadapi pemain tetap sama, baik yang dapat dieksekusi berasal dari Steam, Epic, GOG, atau milik Anda sendiri peluncur, atau https://<slug>.starhermit.com.

Batasan penting: tertanam tidak diam

StarHermit saat ini tidak mengekspos hak istimewa "membuat pemain sewenang-wenang" titik akhir ke sebuah permainan server. Sebuah wadah STARHERMIT_SERVER_TOKEN sengaja tidak memiliki identitas pemain dan tidak dapat mencetak akun pemain atau meniru pemain.

Pendaftaran kunci publik juga memerlukan email yang valid dan tautan verifikasi satu kali. Karena itu:

  • Anda Bisa pertahankan pendaftaran di dalam UI bermerek game Anda dan hindari Google/GitHub OAuth dan Dasbor StarHermit.
  • Anda tidak bisa diam-diam buat akun StarHermit hanya dari ID Steam, ID akun Epic, atau GOG tanda pengenal. Pemain harus menyetujui, memberikan email, dan mengonfirmasinya sekali.
  • Hasilkan dan simpan kunci pribadi setiap pemain di perangkat mereka. Jangan membuat kunci setiap pemain di server khusus Anda, unggah kunci pribadi, atau simpan database kunci kustodian kecuali Anda melakukannya sengaja mengambil tanggung jawab atas semua akun tersebut.

Untuk game asli, pengalaman paling lancar yang didukung adalah: panel akun dalam game menghasilkan kunci, meminta email dan persetujuan, menunggu sementara pemain mengonfirmasi tautan di kotak masuknya, lalu masuk dengan kunci dan menyimpan token penyegaran di brankas kredensial OS. Pemain tidak perlu melakukannya navigasikan situs StarHermit. Pemain yang tidak dapat memberikan dan memverifikasi email tidak dapat menyelesaikan alur ini dengan API saat ini.

Batasan arsitektur dan kepercayaan

Steam/Epic/GOG/native client
  ├─ owns the player's private key
  ├─ performs public-key registration/login
  ├─ holds player access + rotating refresh token
  ├─ optionally links the external platform identity
  └─ uses a game-scoped launch token for game/social APIs
                  │
                  │ REST + ws/v1/games
                  ▼
StarHermit API ───────── authenticated command ────────► your container
  ├─ creates sessions and matchmaking                     ├─ owns simulation
  ├─ stamps the trusted StarHermit user id                 ├─ never trusts payload identity
  ├─ persists snapshots/results/elo/achievements           └─ uses narrow server token only
  └─ supplies session chat, voice, friends, and replays

Klien game membuktikan siapa pemainnya. StarHermit memberi stempel identitas itu ke lalu lintas yang dikirim ke wadah. Penampung tidak pernah menerima ID Steam atau ID pengguna yang diberikan di dalam JSON gameplay sebagai bukti identitas.

Prasyarat

Anda membutuhkan:

  • Akun pengembang StarHermit dan token akses penuh.
  • Game terdaftar yang Anda miliki, dengan a gameSlug dan backend otoritatif. Titik akhir bundel memperbarui game yang ada; itu tidak membuat rekor permainan atau menyimpan siput.
  • Hosting kontainer diaktifkan untuk akun Anda.
  • Docker atau alat lain yang mampu menghasilkan Docker yang kompatibel docker save arsip.
  • Sebuah wadah implementasi protokol permainan v1.

Untuk pendaftaran layanan mandiri awal, gunakan repositori GitHub terverifikasi dengan starhermit.txt dan sebuah sah container.image deklarasi seperti yang dijelaskan dalam Permainan GitHub. Sekali game ada, bundel push dapat mempublikasikan build klien dan server nanti secara langsung.

Bagian 1: menerapkan kontrak kontainer

Proses Anda harus terus didengarkan PORT dan menerapkan:

Titik akhir Tanggung jawab
GET /health Kembali 200 hanya ketika sesi dapat diterima
GET /describe Deklarasikan protokol 1, tingkat/kapasitas tick yang diminta, dan pencapaian
POST /sessions Buat sesi atau pulihkan sesi dari snapshot
GET /sessions/{id}/snapshot Kembalikan titik pemulihan yang lengkap dan tahan lama
DELETE /sessions/{id} Lepaskan sesinya
WS /stream Terima perintah pemain yang diautentikasi dan keluarkan muatan game
WS /control Cuplikan dorong, pencapaian, Elo, hasil, dan tekanan balik

Mengesahkan X-Starhermit-Invoke-Key pada setiap permintaan HTTP dan pemutakhiran WebSocket STARHERMIT_INVOKE_KEY. Ini mengautentikasi StarHermit ke proses Anda.

Deklarasi minimal adalah:

{
  "protocol": 1,
  "tickRateHz": 20,
  "maxSessions": 48,
  "replays": true,
  "achievements": [
    {
      "key": "first-win",
      "name": "First Win",
      "description": "Win a match.",
      "points": 10
    }
  ]
}

replays meminta platform untuk menjaga status terakhir setiap sesi yang selesai, yaitu apa GET /api/v1/games/{slug}/replays/{sessionId} melayani. Deklarasikan hanya jika game Anda ingin diputar ulang; tanpanya tidak ada yang disimpan setelah pertandingan berakhir. Melihat Server Game Kontainer — GET /describe.

Bingkai aliran gameplay menggunakan:

[1 byte type][16 byte sessionId][16 byte userId][payload...]

Jenis 1 adalah perintah masuk; ID penggunanya dicap dari pemutar StarHermit yang diautentikasi. Jenis 2 adalah payload JSON keluar yang ditujukan kepada pemain tersebut, atau kepada semua orang saat ID penggunanya semua nol.

Efek yang tahan lama hilang /control:

{ "type": "snapshot", "sessionId": "...", "state": { "round": 4 } }
{ "type": "achievements", "sessionId": "...", "unlocks": { "<userId>": ["first-win"] } }
{ "type": "elo", "sessionId": "...", "updates": { "<userId>": 1248 } }
{ "type": "result", "sessionId": "...", "result": { "kind": "win", "winner": "<userId>" } }

StarHermit memfilter pembaruan ini ke peserta sesi dan kunci pencapaian yang dinyatakan. Hasilnya adalah terminal. Melihat Server Game yang dihosting oleh kontainer untuk protokol lengkap, snapshot, isolasi, dan kontrak pemulihan.

Bagian 2: daftarkan gamenya sekali

Letakkan manifes di repositori terverifikasi yang digunakan untuk pendaftaran awal:

name=Orbit League
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html
owner=3fa85f64-5717-4562-b3fc-2c963f66afa6  # your user ID from GET /api/v1/me, not username

container.image=ghcr.io/your-github-login/orbit-server@sha256:<64-lowercase-hex>
container.port=8080
container.health=/health
container.memory_mb=1024
container.cpu=1.0

Mengatur owner kepada yang abadi id dikembalikan oleh GET /api/v1/me. Jangan gunakan nama pengguna akun atau nama panggilan; itu adalah nilai tampilan dan dapat berubah.

Daftarkan:

API=https://api.starhermit.com
ACCESS_TOKEN='developer-access-token'

curl -sS -X POST "$API/api/v1/me/github-games" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "repoUrl":"https://github.com/your-github-login/orbit-league"
  }'

Simpan yang dikembalikan id sebagai GAME_ID Dan gameSlug sebagai GAME_SLUG, lalu konfirmasikan bahwa backend ada: GET $API/api/v1/games/$GAME_SLUG jawaban 200 setelah itu terjadi. Sebuah hadiah gameSlug sendirian tidak buktikan — setiap game terverifikasi memiliki satu, hanya browser yang disertakan. Pendaftaran yang menyatakan a wadah tanpa membuktikan bahwa Anda pemilik repositori ditolak 403, dan pendaftaran awal mungkin juga gagal ketika hosting kontainer tidak tersedia atau dibatasi.

Gambar yang didukung registri dalam manifes sudah cukup untuk menyebarkan versi pertama. Bagian selanjutnya mencakup jalur unggahan langsung, berguna untuk CI dan untuk build yang tidak Anda inginkan platform untuk mengkloning atau menarik lagi.

Bagian 3: menerbitkan bundel klien dan server khusus

Bangun arsip

Uploadnya adalah satu arsip tar terkompresi gzip dengan tata letak ini:

client/            optional static web client, including the registered launch file
server/image.tar   optional `docker save` output
starhermit.txt     the manifest

Setidaknya client/ atau server/image.tar harus hadir.

Jika Anda mempublikasikan melalui dasbor web StarHermit atau klien Windows daripada curl, Anda tidak melakukannya buat arsip ini dengan tangan. Pilih salah satu a folder distribusi server (memegang starhermit.txt Dan image.tar) atau itu image.tar dengan sendirinya, dan klien mengemas tata letak di atas. Itu starhermit.txt nilai — nama tampilan dan container.* tombol-tombol — adalah bidang dalam dialog, diisi sebelumnya dari manifes folder jika ada, jadi kosong image.tar menerbitkannya juga.

rm -rf bundle game-bundle.tar.gz
mkdir -p bundle/client bundle/server

# Optional hosted web client.
cp -R dist/. bundle/client/

# Dedicated server image.
docker build -t orbit-server:release -f Dockerfile.server .
docker save orbit-server:release -o bundle/server/image.tar

# Keeps the artifact self-describing, and is what the dashboard/desktop clients require.
cp starhermit.txt bundle/starhermit.txt

tar -C bundle -czf game-bundle.tar.gz .

Gambar harus bekerja dengan sistem file root read-only, pengguna non-root yang dipaksakan, tidak ada kemampuan, tidak volume, tidak ada internet, dan hanya sedikit yang dapat ditulisi /tmp. Ketergantungan vendor ke dalam gambar.

Unggah itu

POST /api/v1/me/github-games/{id}/bundle mengambil arsip sebagai badan permintaan mentah, bukan sebagai a bentuk multi bagian:

curl -sS -X POST "$API/api/v1/me/github-games/$GAME_ID/bundle" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/gzip" \
  --data-binary @game-bundle.tar.gz

Paket berukuran lebih dari 100 MB tidak akan melewati rute ini. CDN di depan API menolak badan permintaan besar dengan a 413 miliknya sendiri — platform yang tidak pernah dilihatnya, sehingga dibawanya tidak limitBytes dan muncul di tidak ada log yang dapat Anda baca. A docker save dari jangkauan gambar server nyata sebesar itu dengan mudah. Jika Anda melihat a 413 dengan tidak limitBytes, itu ini dan bukan permainanmu tunjangan, yaitu gigabyte.

Kirim arsip yang sama ws/v1/game-upload sebagai gantinya — bingkai setelah a Pemutakhiran WebSocket bukan merupakan isi permintaan, jadi batasannya tidak berlaku. Tata letak arsip sama, sama tunjangan, jawaban JSON yang sama; satu-satunya tambahan adalah Anda harus mengirim {"type":"complete"} kapan byte terakhir keluar, karena tidak ada yang dipublikasikan sampai Anda melakukannya.

Contoh tanggapan:

{
  "clientPublished": true,
  "serverImageLoaded": true,
  "imageDigest": "sha256:4e7d...",
  "bytesReceived": 318767104
}

Platformnya:

  • menukar secara atom client/, sehingga pengguna tidak melihat bangunan yang diunggah sebagian;
  • banyak server/image.tar, menghitung intisari yang tidak dapat diubah, dan menyematkan ulang penerapan;
  • mengantri container lama untuk digantikan dengan gambar yang diunggah;
  • memulihkan sesi aktif yang memenuhi syarat dari snapshot yang ada.

Anda hanya dapat mengunggah gambar klien atau gambar server saja. Penggunaan patch khusus klien ?mode=merge pada titik akhir yang sama (lihat pembaruan parsial); gambar yang digabungkan tetap ada dimuat utuh. Tunjangan disk suatu game adalah 2 GB di starhermit.com (dapat disesuaikan oleh operator) dan bisa disetel per game; karena push menggantikan konten game, bukan menambahkannya, itulah keduanya dorongan terbesar dan disk terbanyak yang dapat ditempati oleh game. 413 termasuk limitBytes; tidak valid arsip atau gambar dikembalikan 422; Dan 507 berarti server tidak memiliki ruang saat ini — sudah dicentang sebelum tubuh Anda dibaca, jadi unggahan yang gagal akan ditolak daripada setengah-setengah. Jangan memasang symlink, tautan keras, penjelajahan jalur, atau file di luar tata letak yang terdokumentasi dalam arsip.

Pengunggahan yang berhasil bukan berarti proses baru telah lolos pemeriksaan kesehatan. Jajak pendapat yang ada GET /api/v1/me/github-games/{id}/deployment melihat dan menguji sesi nyata sebelum mempromosikan membangun. Menyematkan penerapan repositori kemudian secara eksplisit akan mengalihkan penerapan kembali ke konten repositori.

Mengganti game yang sudah ada dari server= ke sebuah wadah

Didukung, dan mempertahankan permainan: id yang sama, siput, <uid>.starhermit.com alamat, pemain, papan peringkat dan prestasi. Tidak ada langkah pendaftaran terpisah.

  1. Mengganti server=... dengan Anda container.* memblokir masuk starhermit.txt. Keduanya saling menguntungkan eksklusif; sebuah manifes yang menyatakan keduanya ditolak.
  2. Dorong satu bungkusan yang dibawanya client/ (dengan manifes itu) Dan server/image.tar, lebih ws/v1/game-upload jika ukurannya besar.
  3. Gambar yang Anda unggah adalah gambar yang berjalan. A container.image= baris dalam manifes yang sama adalah baik untuk disimpan, tetapi intisari yang diunggah menang atasnya.
  4. Pemilihan GET /api/v1/me/github-games/{id}/deployment sampai terbaca running, lalu mulai yang sebenarnya ruangan atau korek api.

Bagian 4: memperbarui token platform penampung

Saat startup, kontainer menerima:

STARHERMIT_API_BASE
STARHERMIT_GAME_SLUG
STARHERMIT_SERVER_TOKEN
STARHERMIT_SERVER_TOKEN_EXPIRES_IN
STARHERMIT_REFRESH_KEY
STARHERMIT_INVOKE_KEY

STARHERMIT_SERVER_TOKEN sempit: ini mewakili server game, bukan pemain. Masa berlakunya habis setelahnya 24 jam secara default. Jadwalkan pembaruan sekitar setengahnya STARHERMIT_SERVER_TOKEN_EXPIRES_IN:

POST {STARHERMIT_API_BASE}/api/v1/games/{STARHERMIT_GAME_SLUG}/server/token
X-Starhermit-Refresh-Key: {STARHERMIT_REFRESH_KEY}

{ "token": "eyJhbGciOi...", "expiresInSeconds": 86400 }

Tidak diperlukan token pembawa untuk titik akhir ini. Itu memungkinkan pemulihan bahkan jika token lama memilikinya sudah kadaluwarsa. Ganti token dalam memori secara atom dan jadwalkan pembaruan berikutnya dari yang baru expiresInSeconds.

Pisahkan kedua rahasia penerapan:

  • STARHERMIT_INVOKE_KEY mengautentikasi permintaan StarHermit ke kontainer Anda.
  • STARHERMIT_REFRESH_KEY mengautentikasi wadah Anda saat memperbarui token StarHermitnya.

Keduanya berputar pada setiap kontainer dimulai ulang. Jangan pernah mencatatnya, kembalikan /describe, masukkan ke dalam a snapshot, atau mengirimkannya ke pemain.

Bagian 5: bergabung dengan pemain non-StarHermit tanpa OAuth

Jalankan alur ini di game atau peluncur asli, bukan di wadah khusus. Panduan lengkapnya, dengan kode klien yang diuji, adalah Tutorial: pemain onboard dengan kunci publik; pendeknya:

  1. Hasilkan kunci per instalasi pada peluncuran pertama (disarankan Ed25519) dan simpan kunci pribadinya di penyimpanan kredensial OS. Jangan pernah mengunggahnya, dan jangan pernah membuat kunci pemain di server Anda.
  2. Minta persetujuan dan alamat email, Kemudian POST /api/v1/auth/public-key/register dengan { email, keyType, keyData } dari perangkat pemutar. Ini dibatasi menjadi satu pendaftaran per alamat dan per IP setiap 24 jam (429 dengan Retry-After), jadi jangan pernah mem-proxy-nya melalui file Anda server — setiap pemain akan membagikan IP-nya.
  3. Tunggu hingga pemain mengonfirmasi. Tautan yang dikirim melalui email membuka halaman yang tidak mengubah apa pun hingga saat ini pemain menekan Konfirmasi, yang membuat akun dan melampirkan kuncinya; di starhermit.com mereka kemudian mendarat di dasbor StarHermit, jadi game Anda tidak menerima token tersebut. Sebaliknya itu masuk dengan kunci sampai berhasil: challenge, tandatangani StarHermit byte tantangan yang tepat, complete. Sampai pemain mengonfirmasi, complete jawaban 401 "Public key not registered or revoked.".
  4. Pertahankan sesinya dengan POST /api/v1/auth/refresh, dan masuk lagi dengan kunci tersebut kapan saja penyegaran gagal. Terima persyaratan saat ini kapan GET /api/v1/me laporan termsAcceptanceRequired (sesi akun dan token peluncuran pemain dapat — lihat penerimaan syarat). Token penerapan kontainer Anda adalah dikecualikan dari ketentuan; pengecualian itu tidak berlaku untuk para pemainnya.

Lebih banyak perangkat. Setiap instalasi mendaftarkan kuncinya sendiri dengan alamat email pemain yang sama, dan kuncinya bergabung dengan akun yang ada. POST /api/v1/me/public-keys bukanlah pilihan bagi para pemain berikut: itu memerlukan sesi yang masuk melalui penyedia OAuth.

5. Tambahkan nama pemain dan identitas eksternal

Akun yang dihasilkan dimulai dengan a pk-... nama belakang. Biarkan pemain memilih nama panggilan:

PATCH /api/v1/me
Authorization: Bearer <access-token>
Content-Type: application/json

{ "nickname": "RookPilot" }

Anda dapat mengaitkan akun dengan platform tempat eksekusi dijalankan:

POST /api/v1/me/identities
Authorization: Bearer <access-token>
Content-Type: application/json

{
  "provider": "epic",
  "providerUserId": "epic-account-id",
  "metadata": "{\"displayName\":\"RookPilot\"}"
}

Gunakan a tidak dicadangkan nama penyedia (epic, gog, atau id etalase Anda sendiri). Melakukan bukan menggunakan steam, google, github, atau nama lain apa pun yang diperlakukan oleh platform sebagai penyedia OAuth — yaitu ditolak meskipun penyedia tersebut tidak dikonfigurasi. Dapatkan ID eksternal dari platform itu SDK/sesi yang diautentikasi, bukan dari masukan pemain yang dapat diedit. Titik akhir ini mengaitkan identitas dengan akun StarHermit; itu bukan bukti kepemilikan etalase dan tidak boleh diganti verifikasi tiket platform itu sendiri untuk pembelian atau pelarangan.

API perpustakaan eksternal terpisah bersifat opsional dan saat ini menggunakan sinkronisasi demo sebagai penyedia integrasi telah diselesaikan; itu tidak diperlukan untuk bermain di server khusus.

Bagian 6: masuk ke dalam game dan gunakan layanan StarHermit

Mengganti {slug} dalam contoh HTTP di bawah ini dengan GAME_SLUG, UUID game yang Anda peroleh pendaftaran. Nama repositori orbit-league adalah nama tampilan/sumber, bukan siput API.

Buat token game dengan hak istimewa paling rendah

Gunakan token akses penuh satu kali untuk membuat token yang dipagari ke game Anda:

POST /api/v1/games/{slug}/launch-token
Authorization: Bearer <access-token>

{ "token": "eyJhbGciOi...", "expiresInSeconds": 3600 }

Gunakan token peluncuran ini untuk gameplay dan API sosial sesi yang diizinkan. Segarkan sebelum kadaluwarsa. Jauhkan token akun lengkap dari kode permainan jika memungkinkan.

Penjaruman

POST /api/v1/games/{slug}/matchmaking
Authorization: Bearer <game-token>

Pemilihan GET /api/v1/games/{slug}/matchmaking sampai status adalah matched, lalu sambungkan:

wss://api.starhermit.com/ws/v1/games?sessionId=<sessionId>&access_token=<game-token>

Pesan klien tetap berupa JSON:

{ "type": "cmd", "data": { "type": "input", "throttle": 0.8 } }

StarHermit mengonversi perintah ke aliran kontainer dan memberi stempel pada StarHermit yang diautentikasi ID pengguna. Penampung Anda mengembalikan muatan game resmi melalui bingkai aliran tipe-2.

Papan peringkat dan prestasi

Setiap game resmi menerima papan peringkat Elo. Kontainer Anda mengirimkan perubahan Elo dan mendeklarasikannya pencapaian terbuka /control; klien hanya membaca status platform yang dihasilkan:

GET /api/v1/games/{slug}/achievements
GET /api/v1/leaderboards/{leaderboardId}/entries

Klien Steam/Epic/GOG yang dimodifikasi tidak dapat secara langsung mengirimkan skor papan peringkat game atau mengklaim a prestasi yang dimiliki permainan.

Sesi obrolan dan suara

GET /api/v1/games/{slug}/sessions/{sessionId} kembali chatConversationId. Sesi percakapan memungkinkan peserta untuk mengobrol dan menggunakan suara meskipun mereka bukan teman.

Aliran suara yang khas:

  1. GET /api/v1/voice/rooms?conversationId=<chatConversationId>.
  2. Jika diperlukan, POST /api/v1/voice/rooms dengan ID percakapan.
  3. POST /api/v1/voice/rooms/{roomId}/join.
  4. Menghubungkan wss://api.starhermit.com/ws/v1/voice?roomId=<roomId>&access_token=<game-token>.

Akun yang sama juga memungkinkan teman, kehadiran, undangan permainan, pemutaran ulang, dan identitas profil semua etalase dibangun. Simpan satu kunci/akun StarHermit per manusia daripada membuat akun baru untuk setiap pertandingan atau setiap peluncuran etalase.

Daftar periksa produksi

Penerbitan

  • [ ] Game milik yang ada memiliki nilai bukan nol gameSlug.
  • [ ] Penampung menolak kunci pemanggilan yang salah atau hilang.
  • [ ] Kunci pemanggilan, kunci penyegaran, dan token server dibaca dari lingkungan saat proses dimulai, tidak pernah dimasukkan ke dalam gambar atau di-cache pada disk (ketiganya diputar pada setiap permulaan penampung).
  • [ ] /health tidak kembali 200 sebelum negara dapat diterima.
  • [ ] Bundel menggunakan mentah application/gzip, bukan pengkodean multi-bagian.
  • [ ] Gambar berfungsi hanya-baca, non-root, offline, dan tanpa volume.
  • [ ] Status penerapan dan sesi perjodohan sebenarnya diuji setelah diunggah.
  • [ ] Penyegaran token server berjalan sebelum separuh masa pakainya dan menukar token secara atom.
  • [ ] Rahasia penerapan tidak dicatat atau disimpan dalam snapshot.

Orientasi pemain

  • [ ] Pasangan kunci dihasilkan pada perangkat pemutar dan kunci pribadi menggunakan penyimpanan aman.
  • [ ] Pembuatan akun diungkapkan dan disetujui.
  • [ ] Verifikasi email selesai satu kali; 429 Retry-After dihormati.
  • [ ] Pendaftaran dan token pemain tidak melewati server khusus.
