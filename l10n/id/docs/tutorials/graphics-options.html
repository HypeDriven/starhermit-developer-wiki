Tutorial: pilihan grafis dengan kualitas terdeteksi otomatis

Berikan permainan browser Anda a Grafik menu yang memilih tingkat kualitas yang masuk akal untuk mesin pemain pada peluncuran pertama, biarkan mereka menggantinya, dan mengingat pilihan mereka di seluruh perangkat melalui StarHermit.

Untuk bagian Audio terkait, lihat opsi audio dengan batas suara yang terdeteksi secara otomatis.

graphics-options.js adalah modul ES tunggal, tanpa ketergantungan, itu menangani pembukuan:

  • Mobil memilih salah satu dari empat preset (Rendah, Seimbang, Tinggi, Ultra) dari GPU, memori, inti CPU, dan jenis perangkat, dan mundur untuk sesi tersebut jika frame tetap lambat.
  • Pemain dapat mengganti setiap efek (bayangan, oklusi sekitar, mekar, anti-aliasing, atau milik Anda sendiri), atur skala render 50–200%, pilih FPS maksimum manual daripada penyegaran tampilan otomatis, dan mengaktifkan resolusi adaptif dan pembacaan kecepatan bingkai.
  • Pengaturan disimpan ke localStorage jadi mereka berlaku sebelum frame pertama, dan ke frame pemain pengaturan per game jadi mereka mengikuti pemain itu ke mereka mesin lainnya.
  • Ini mencakup panel opsi siap pakai yang dibuat dari tabel kualitas yang sama.

Itu tidak mengimpor mesin. Perender Anda mendengarkan perubahan dan menerapkan tingkatannya. Halaman ini menghubungkannya tiga.js. Mesin lain menggunakan kait yang sama (lihat Mesin lainnya).

1. Tambahkan file

Menyalin starhermit-sdk.js Dan graphics-options.js di samping skrip game Anda, tidak berubah. Panggilan StarHermit.init() sebelum modul Anda berjalan, sehingga token peluncuran telah dibaca pada saat itu toko grafis memeriksa apakah pemain sudah masuk:

<script src="starhermit-sdk.js"></script>
<script>StarHermit.init();</script>
<script type="module" src="main.js"></script>

Tanpa token peluncuran (pengembangan lokal, host lainnya), toko menyimpan semuanya localStorage dan tidak membuat permintaan.

2. Buat toko dan panel

import { createGraphics, mountGraphicsPanel } from './graphics-options.js';

const gfx = createGraphics({ storageKey: 'mygame.graphics' });
mountGraphicsPanel(document.getElementById('graphics-options'), gfx);

mountGraphicsPanel mengisi elemen dengan kontrol. Dialog pengaturan Anda menyediakan bingkai, itu judul dan tombol Tutup. Setiap perubahan berlaku segera dan disimpan.

Bagaimana Otomatis memilih preset

Saat pembuatan, toko menyelidiki konteks WebGL sekali pakai (gfx.system) dan memetakannya ke preset (gfx.detected):

Sinyal Prasetel
Tanpa WebGL, atau penyaji perangkat lunak (SwiftShader, llvmpipe, Microsoft Basic Render) Rendah
Tidak ada WebGL2, 2 inti CPU atau kurang, atau memori 2 GB atau kurang Rendah
GPU diskrit (NVIDIA, AMD Radeon RX/Pro, Apple M-series) Tinggi
Yang lainnya (Intel/AMD terintegrasi, GPU seluler, Safari bertopeng "GPU Apple") Seimbang
Ponsel atau tablet (penunjuk kasar), atau memori 4 GB atau kurang paling banyak Seimbang

Otomatis tidak pernah memilih Ultra; pemain memilih ikut serta. Nama GPU berasal dari RENDERER, dan itu WEBGL_debug_renderer_info ekstensi hanya diminta jika Chromium menutupi namanya. Firefox mencatat a peringatan konsol ketika ekstensi itu diminta, dan sudah melaporkan nama aslinya.

Saat permainan berjalan, Otomatis juga melihat waktu frame. Jika resolusi adaptif sudah turun ke levelnya lantai dan bingkai masih rata-rata di atas 26 ms untuk tiga jendela 90 bingkai lagi, Otomatis menurunkan satu preset untuk sisa sesi. Memilih Mobil di panel lagi mendeteksi ulang. Prasetel pemutar dipetik dengan tangan tidak pernah berubah dengan sendirinya.

Kecepatan bingkai maksimum

Kecepatan bingkai maksimum defaultnya adalah Otomatis (kecepatan penyegaran): browser menjadwalkan rendering dengan kecepatan refresh layar. Memilih Kebiasaan dan masukkan bilangan bulat dari 1 hingga 1000FPS untuk menimpanya. Batasan tersebut langsung berlaku, disimpan secara lokal dan ke profil cloud yang sama dengan pengaturan grafis lainnya, dan bertahan dari perubahan preset kualitas. Kembali ke Mobil untuk menghapus batas. Pilihan ini tidak bergantung pada Mobil kualitas yang telah ditetapkan.

Penyaji harus menelepon gfx.shouldRender(now) dalam loop animasinya, seperti yang ditunjukkan di bawah ini. Batas adalah a batas atas, bukan kecepatan bingkai yang dijanjikan: rendering masih tidak dapat melebihi panggilan balik animasi browser atau kinerja mesin. Oleh karena itu, menyetel 144 FPS pada tampilan 60 Hz masih menghasilkan maksimal 60 FPS.

Untuk menu khusus, gunakan gfx.set({ maxFps: 45 }) Dan gfx.set({ maxFps: null }) untuk memulihkan Otomatis. Terselesaikan gfx.settings.maxFps adalah 0 untuk Otomatis. Nilai tersimpan yang tidak valid akan dikembalikan ke Otomatis; positif angka dibulatkan dan dijepit menjadi 1–1000.

Di mana pengaturannya berada

Toko Kunci Mengapa
localStorage <storageKey>.gpu.<GPU profile> Dibaca secara sinkron, sehingga frame pertama sudah menggunakan pengaturan GPU ini
Pengaturan per pemain graphics.gpu.<GPU profile> Mengikuti pemain ke komputer lain yang melaporkan GPU yang sama

Setiap GPU mendapat profil independen, mencakup setiap pilihan grafis termasuk FPS maksimum. Misalnya, atur Ultra dan 90 FPS pada GPU A, lalu peluncuran pada GPU B: B dimulai dengan terdeteksi perangkat keras default kecuali Anda sebelumnya menyimpan pilihan untuk B. Kembali ke A memulihkan Ultra dan 90 FPS. Dua GPU yang sama-sama terdeteksi High masih memiliki profil terpisah. Perubahan pada kualitas yang terdeteksi tingkat pada GPU yang sama tidak membuang pilihan tersimpannya.

Profil tersebut adalah hash 16 karakter stabil dari nama GPU yang dilaporkan browser, yang dinormalisasi untuk kasus tertentu dan spasi. storageKey Dan cloudKey awalan pasokan; gfx.storageKey, gfx.cloudSlot, Dan gfx.gpuProfile mengekspos kunci dan profil aktif. Deteksi GPU terjadi saat penyimpanan dibuat; buat toko baru pada peluncuran game berikutnya untuk memilih profil GPU lain.

Jika tidak ada nama GPU yang tersedia, pilihan berlaku untuk sesi tanpa persistensi lokal atau cloud. Jika browser menutupi beberapa GPU dengan nama yang sama, mereka akan berbagi profil karena tidak bisa membedakannya. Pengaturan lokal lama yang tidak tercakup dan pengaturan cloud kelas perangkat tidak tersentuh dan tidak diimpor, karena tidak mengidentifikasi GPU mana yang menjadi pilihannya.

Setiap nilai adalah { "saved": {…}, "at": <ms timestamp> }. Kedua salinan tersebut direkonsiliasi dengan cara yang sama penyimpanan awan:

  • Baca sebelum menulis. Saat permulaan (dan ketika pemain lain masuk), toko membaca GET /api/v1/games/{slug}/settings. Salinan dengan yang lebih baru at menang. Jika salinan cloud menang, toko mengadopsinya dan menembakkan a change dengan alasan 'cloud'. Jika salinan lokal lebih baru, toko mendorongnya.
  • Blok baca yang gagal menulis. Salinan lokal tetap berfungsi. Perubahan selanjutnya yang dilakukan pemain mencoba ulang pembacaan sebelum sesuatu ditulis, sehingga perangkat yang sudah usang tidak dapat menimpa pilihan yang lebih baru tidak bisa melihat.
  • Perubahan didorong dengan setSetting setelah 800 ms tanpa perubahan lebih lanjut. Pembaruan token (yang juga jalankan SDK auth acara) tidak memicu pembacaan lainnya.

3. Terapkan pengaturan ke penyaji Anda

Empat kait menghubungkan toko ke penyaji three.js:

  • gfx.on('change', fn) untuk bayangan dan efek matikan.
  • Rantai pasca-pemrosesan dibangun kembali dari tingkatan saat ini.
  • gfx.frame(ms) Dan gfx.pixelRatio() di loop render, yang mendorong resolusi adaptif.
  • gfx.shouldRender(now) sebelum menggambar, yang menerapkan batas FPS manual.

Buat penyaji dengan antialias: false. MSAA kemudian berasal dari target render rantai pos, jadi setiap tingkat anti-aliasing dapat dialihkan tanpa membuat ulang konteks WebGL.

import * as THREE from 'three';
import { EffectComposer } from 'three/addons/postprocessing/EffectComposer.js';
import { RenderPass } from 'three/addons/postprocessing/RenderPass.js';
import { GTAOPass } from 'three/addons/postprocessing/GTAOPass.js';
import { UnrealBloomPass } from 'three/addons/postprocessing/UnrealBloomPass.js';
import { OutputPass } from 'three/addons/postprocessing/OutputPass.js';
import { SMAAPass } from 'three/addons/postprocessing/SMAAPass.js';
import { ShaderPass } from 'three/addons/postprocessing/ShaderPass.js';
import { FXAAShader } from 'three/addons/shaders/FXAAShader.js';

// canvas, scene, camera and a shadow-casting DirectionalLight `sun` are your game's own.
const renderer = new THREE.WebGLRenderer({ canvas, antialias: false });
renderer.toneMapping = THREE.ACESFilmicToneMapping;

const SHADOW_MAP = { off: 0, low: 1024, medium: 2048, high: 4096 };
let composer = null;
let size = {};

gfx.on('change', (s) => {
  const mapSize = SHADOW_MAP[s.shadows];
  renderer.shadowMap.enabled = mapSize > 0;
  sun.castShadow = mapSize > 0;
  if (mapSize && sun.shadow.mapSize.x !== mapSize) {
    sun.shadow.mapSize.set(mapSize, mapSize);
    sun.shadow.map?.dispose();
    sun.shadow.map = null;
  }
  scene.traverse((o) => [].concat(o.material || []).forEach((m) => { m.needsUpdate = true; })); // shadow on/off recompiles
  size = {}; // resize and rebuild the post chain on the next frame
});

function buildPost(s, w, h, ratio) {
  composer?.dispose();
  composer = null;
  if (gfx.info.postFailed || (s.ao === 'off' && s.bloom === 'off' && s.antialias === 'off')) return;
  try {
    const pw = Math.round(w * ratio), ph = Math.round(h * ratio);
    const target = new THREE.WebGLRenderTarget(pw, ph, { type: THREE.HalfFloatType, samples: s.antialias === 'msaa' ? 4 : 0 });
    const c = new EffectComposer(renderer, target);
    c.setPixelRatio(ratio);
    c.setSize(w, h);
    c.addPass(new RenderPass(scene, camera));
    if (s.ao !== 'off') {
      const ao = new GTAOPass(scene, camera, pw, ph);
      ao.updateGtaoMaterial({ samples: s.ao === 'high' ? 16 : 8 });
      c.addPass(ao);
    }
    if (s.bloom === 'on') c.addPass(new UnrealBloomPass(new THREE.Vector2(w, h), 0.5, 0.4, 0.9));
    c.addPass(new OutputPass());
    if (s.antialias === 'smaa') c.addPass(new SMAAPass());
    if (s.antialias === 'fxaa') {
      const fxaa = new ShaderPass(FXAAShader);
      fxaa.material.uniforms.resolution.value.set(1 / pw, 1 / ph);
      c.addPass(fxaa);
    }
    composer = c;
  } catch {
    gfx.report({ postFailed: true }); // the panel shows a note; don't console.warn
  }
}

let last = performance.now();
renderer.setAnimationLoop((now) => {
  // Update your simulation here using its own elapsed time or fixed timestep.
  // Keep simulation/input independent of skipped render ticks.
  if (!gfx.shouldRender(now)) return;
  gfx.frame(now - last); // elapsed time between rendered frames, including the FPS limit
  last = now;
  const w = canvas.clientWidth, h = canvas.clientHeight, ratio = gfx.pixelRatio();
  if (w !== size.w || h !== size.h || ratio !== size.ratio) {
    size = { w, h, ratio };
    renderer.setPixelRatio(ratio);
    renderer.setSize(w, h, false);
    camera.aspect = w / h;
    camera.updateProjectionMatrix();
    buildPost(gfx.settings, w, h, ratio);
    gfx.report({ pixels: [Math.round(w * ratio), Math.round(h * ratio)] });
  }
  try {
    if (composer) composer.render();
    else renderer.render(scene, camera);
  } catch {
    composer = null;
    gfx.report({ postFailed: true });
  }
});

Catatan:

  • Itu three/addons/ file harus berasal dari rilis three.js yang sama sebagai three diri. Pencampuran rilis memutus rantai pos. Kode di atas menargetkan rilis saat ini. Pada yang lebih tua, SMAAPass dibutuhkan (width, height).
  • Rendah mematikan setiap efek pasca-pemrosesan, sehingga game dirender langsung ke kanvas pada a rasio piksel perangkat paling banyak 1. Itu membuat Low semurah game sebelum semua ini.
  • gfx.pixelRatio() kembali min(devicePixelRatio, preset cap) × preset scale × render scale × adaptive scale, dijepit ke 0,25–3. Batasnya adalah 1 untuk Rendah, 1,5 untuk Seimbang, dan 2 untuk Tinggi dan Sangat.
  • Resolusi adaptif rata-rata 90 frame. Di atas 26 ms, skalanya diturunkan sebesar 0,1 (turun menjadi 0,6). Di bawah 14 ms itu menaikkan skala sebesar 0,05 (hingga 1). Bingkai yang berdurasi lebih dari 1 detik (tab dijeda atau di latar belakang). diabaikan, dan satu frame lambat dihitung paling lama 250 ms untuk adaptasi sehingga satu halangan tidak dapat diturunkan skala. Pembacaan FPS menggunakan waktu yang sebenarnya telah berlalu. Dengan batasan manual, ambang batas lambat minimal 115% dari interval frame target dan ambang batas cepat setidaknya 85%, jadi batas 30 FPS yang disengaja tidak akan menurunkan kualitas dengan sendirinya. Untuk batas yang sangat rendah, batas jeda dan batas halangan setidaknya merupakan dua interval target. Memberi makan gfx.frame hanya bingkai yang dirender; pertahankan stempel waktu terakhir yang diberikan saat tanda centang dilewati.

Mesin lainnya

Apa pun yang menarik bingkai Anda, integrasinya menggunakan kaitan yang sama:

Panggilan Menggunakan
gfx.on('change', (settings, reason) => …) Terapkan tingkatan. Berjalan sekali dengan segera ('init'), lalu aktif 'settings', 'cloud' Dan 'auto'. Mengembalikan fungsi berhenti berlangganan.
gfx.settings { preset, auto, scale, dprCap, adaptive, showFps, maxFps, <category>: <tier> }; maxFps: 0 berarti penyegaran tampilan otomatis.
gfx.shouldRender(now) Setiap panggilan balik animasi, dengan stempel waktunya dalam milidetik. Lewati menggambar jika kembali false. Jaga agar pembaruan simulasi/input tetap independen.
gfx.frame(ms) Setiap frame yang dirender, dengan waktu sejak frame yang dirender sebelumnya. Kembali true ketika rasio piksel atau preset Otomatis berubah.
gfx.pixelRatio() Rasio untuk dirender pada
gfx.report({ pixels, postFailed }) Memberi tahu panel ukuran keluaran, atau bahwa efek tidak tersedia

Untuk permainan kanvas 2D, kalikan ukuran alas kanvas dengan gfx.pixelRatio(), dan petakan milik Anda sendiri efek (partikel, cahaya, lapisan paralaks) ke kategori seperti dijelaskan di bawah.

4. Sesuaikan dengan permainan Anda

Efek Anda sendiri. Lewati tabel berkualitas yang hanya mencantumkan apa yang sebenarnya digambar oleh permainan Anda. Setiap preset baris membutuhkan tingkatan untuk setiap kategori, plus scale Dan dprCap:

import { createGraphics, CATEGORIES, TABLE } from './graphics-options.js';

const gfx = createGraphics({
  storageKey: 'mygame.graphics',
  categories: { ...CATEGORIES, particles: ['off', 'low', 'high'] },
  table: {
    low: { ...TABLE.low, particles: 'off' },
    balanced: { ...TABLE.balanced, particles: 'low' },
    high: { ...TABLE.high, particles: 'high' },
    ultra: { ...TABLE.ultra, particles: 'high' },
  },
});

Panel membuat satu pilihan per kategori, sehingga kategori baru muncul secara otomatis. Beri nama dengan strings.categories.particles.

Terjemahan. String bahasa Inggris panel diekspor sebagai STRINGS. Berikan milik Anda sendiri dengan hal yang sama bentuk. Hanya kunci yang Anda berikan yang diganti:

mountGraphicsPanel(el, gfx, {
  strings: {
    quality: 'Qualität', auto: 'Automatisch ({tier})', fromPreset: 'Laut Voreinstellung ({tier})',
    renderScale: 'Renderskalierung', adaptive: 'Adaptive Auflösung', showFps: 'Bildrate anzeigen',
    maxFps: 'Maximale Bildrate', autoFps: 'Automatisch (Bildschirmfrequenz)',
    customFps: 'Benutzerdefiniert', fpsLimit: 'Maximale FPS (1–1000)',
    categories: { shadows: 'Schatten', ao: 'Umgebungsverdeckung', particles: 'Partikel' },
    tiers: { low: 'Niedrig', balanced: 'Ausgewogen', high: 'Hoch', off: 'Aus', on: 'An' },
  },
});

Penataan gaya. Panel menggunakan kelas .gfx-panel, .gfx-row, .gfx-summary Dan .gfx-note. Ini aturan bawaan disertakan :where(), jadi aturan apa pun di stylesheet Anda akan menimpanya. Baris adalah setidaknya tinggi 44 px untuk disentuh. Pembacaan kecepatan bingkai (#gfx-fps) berada di pojok kiri bawah, di dalam area aman, dan tidak menangkap klik.

Membaca hasilnya di tempat lain. <html> membawa data-gfx-preset (preset aktif) dan data-gfx-auto (1 atau 0), yang dapat dimatikan oleh CSS dan pengujian.

5. Ujilah

  • Browser tanpa kepala dirender dengan GPU perangkat lunak, jadi Otomatis memutuskannya Rendah dan tes tetap cepat.
  • Kendarai panel sebenarnya. Setiap kendali mempunyai a data-gfx atribut (preset, renderScale, adaptive, frameRate, maxFps, showFps, atau nama kategori):
const preset = () => page.evaluate(() => document.documentElement.dataset.gfxPreset);
await page.locator('select[data-gfx=preset]').selectOption('high');
assert.equal(await preset(), 'high');
await page.reload();
assert.equal(await preset(), 'high'); // persisted
await page.locator('select[data-gfx=frameRate]').selectOption('custom');
await page.locator('input[data-gfx=maxFps]').fill('45');
await page.locator('input[data-gfx=maxFps]').press('Tab');
await page.reload();
assert.equal(await page.locator('input[data-gfx=maxFps]').inputValue(), '45');
await page.locator('select[data-gfx=frameRate]').selectOption('auto');
  • Fungsi murni detectPreset(system), resolve(saved, detected) Dan withPreset(saved, preset) dijalankan di bawah Node untuk pengujian unit. createGraphics({ sdk, storage, system }) juga menerima yang palsu untuk semua tiga.
  • node --test tests/graphics-options.test.mjs memverifikasi validasi, persistensi dan restorasi per GPU, kecepatan bingkai pada kecepatan refresh tampilan yang berbeda, peralihan langsung, dan kualitas adaptif dengan batas FPS.
