Tutorial: Pemain Onboard dengan Kunci Publik

Akun StarHermit tidak memerlukan Google, GitHub, atau penyedia masuk lainnya. Kredensialnya bisa berupa pasangan kunci yang dihasilkan game Anda di perangkat pemain, ditambah alamat email pemain mengkonfirmasi sekali. Setelah itu, game Anda masuk secara diam-diam pada setiap peluncuran dengan menandatangani tantangan kuncinya. Pemain tidak pernah mengetikkan kata sandi dan tidak perlu mengunjungi halaman StarHermit.

Tutorial ini membangun alur tersebut dari ujung ke ujung: buat kunci, daftarkan, tunggu hingga pemain melakukannya konfirmasi, masuk, pertahankan sesi, dan tangani perangkat kedua dan kunci yang hilang.

Gunakan ini untuk game asli dan mandiri, peluncur, versi Steam/Epic/GOG, dan alat desktop — apa pun yang berjalan di mesin pemain dan dapat menyimpan kunci pribadi di sana.

Gunakan sesuatu yang lain untuk

  • Game browser yang dihosting di StarHermit, yang sudah menerima token peluncuran saat dibuka dashboard, atau dapat menunjukkan a Tombol masuk.
  • Saluran pipa CI, yang seharusnya mendaftarkan kunci dari sesi OAuth tanpa langkah email: Tutorial: mengunggah build dari CI/CD.
  • Server permainan khusus, yang memiliki token penerapannya sendiri dan tidak dapat membuat atau bertindak sebagai pemain: Tutorial: mempublikasikan server khusus.

Apa yang dilihat pemain

  1. Game Anda meminta alamat email dan persetujuan mereka untuk membuat akun StarHermit.
  2. Mereka membuka email konfirmasi, mengklik link, dan menekan Mengonfirmasi di halaman yang terbuka.
  3. Kembali ke permainan Anda, mereka sudah masuk. Pada peluncuran selanjutnya tidak ada yang ditanyakan sama sekali.

Alamat email diperlukan, dan pemain harus mengonfirmasinya satu kali. Tidak ada cara untuk membuat a Akun StarHermit diam-diam dari identitas Steam, Epic, atau GOG saja.

Sebelum Anda mulai

Kode pada halaman ini adalah JavaScript biasa menggunakan WebCrypto dan fetch, jadi dijalankan di browser, di Elektron dan di Node 20 atau lebih baru. Itu js blok di bawahnya, secara berurutan, membentuk satu modul ES — selamatkan mereka bersama sebagai starhermit-key-auth.js. Bahasa lain bekerja dengan cara yang sama: langkah 1 memberikan hal yang persis sama format byte, dan langkah 3 byte yang tepat untuk ditandatangani.

const API = 'https://api.starhermit.com';

const b64 = (bytes) => btoa(String.fromCharCode(...new Uint8Array(bytes)));

1. Buat kunci perangkat

Menghasilkan satu pasangan kunci per instalasi, pertama kali game Anda memerlukan akun. Pribadi kunci tidak pernah meninggalkan perangkat: tidak ke server Anda, tidak ke StarHermit.

keyType keyData (standar Base64) Tanda tangan (standar Base64)
Ed25519 - direkomendasikan Kunci publik mentah 32 byte Tanda tangan Ed25519 64-byte mentah
ECDSA-P256 Poin publik: 65-byte tidak terkompresi (04‖X‖Y) atau terkompresi 33-byte ECDSA dengan SHA-256, ASN.1 berkode DER
RSA-PSS SubjectPublicKeyInfo DER, modulus 2048–8192-bit, eksponen ≤ 32 bit RSASSA-PSS, SHA-256, MGF1-SHA-256, garam 32-byte

keyData maksimal 2.000 karakter. Satu kunci dimiliki oleh satu akun di seluruh platform.

Memilih Ed25519 kecuali platform Anda tidak dapat memproduksinya. Jika Anda menggunakan ECDSA, perhatikan bahwa WebCrypto, Windows CNG dan sebagian besar keystore perangkat keras mengembalikan tanda tangan sebagai mentah r‖s (64 byte). Pertapa Bintang mengharapkan DER, jadi konversikan — modul di bawah ini dapat melakukannya.

// One key per installation. The private key can sign but is never exported.
export async function createDeviceKey(keyType = 'Ed25519') {
  if (!['Ed25519', 'ECDSA-P256'].includes(keyType)) throw new Error('This helper supports Ed25519 or ECDSA-P256');
  const algorithm = keyType === 'Ed25519'
    ? { name: 'Ed25519' }
    : { name: 'ECDSA', namedCurve: 'P-256' };
  const pair = await crypto.subtle.generateKey(algorithm, false, ['sign', 'verify']);
  return {
    keyType: keyType === 'Ed25519' ? 'Ed25519' : 'ECDSA-P256',
    keyData: b64(await crypto.subtle.exportKey('raw', pair.publicKey)),
    privateKey: pair.privateKey,
  };
}

Simpan kunci pribadi di tempat yang dilindungi sistem operasi. Di browser atau penyaji Electron, yang tidak dapat diekstraksi CryptoKey dapat disimpan di IndexedDB apa adanya. Game asli harus menggunakan keystore platform — Windows DPAPI atau CNG, MacOS Keychain, libsecret di Linux. Toko keyType Dan keyData di sebelahnya; Anda mengirimkannya dengan setiap permintaan.

2. Mulai registrasi

Minta alamat email pemain dan persetujuannya, lalu:

async function post(path, body) {
  const res = await fetch(API + path, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  });
  return { status: res.status, body: await res.json().catch(() => ({})) };
}

function fail(step, { status, body }) {
  return Object.assign(new Error(`${step}: ${body.error ?? status}`), { status, body });
}

export async function register(key, email) {
  const res = await post('/api/v1/auth/public-key/register',
    { email, keyType: key.keyType, keyData: key.keyData });
  if (res.status !== 202) throw fail('register', res);
  return res.body; // { registrationId, email, emailSent, deferralReason, message }
}

202 berarti StarHermit menerima pendaftarannya. Jika emailSent adalah false, email dalam antrian dan akan tetap tiba; deferralReason mengatakan mengapa ia menunggu. Belum ada yang dilampirkan ke akun mana pun.

Tiga aturan membentuk UI Anda:

  • Satu pendaftaran per alamat email, dan satu pendaftaran per alamat IP, setiap 24 jam. Upaya kedua adalah 429 dengan Retry-After. Minta pemain mengkonfirmasi alamat sebelum Anda mengirimkannya, karena salah ketik biayanya sehari. Kirim permintaan dari perangkat pemain, jangan pernah melalui server Anda sendiri: setiap pemain akan membagikan IP server Anda dan registrasi harian tunggalnya.
  • Tautan kedaluwarsa setelah 4 jam. Jika lewat dari itu, pemain dapat mendaftar kembali 1 kali dalam 24 jam sudah bangun.
  • 400 berarti alamat email atau materi kunci ditolak; error mengatakan yang mana.

3. Masuk dengan kuncinya

Masuk adalah sebuah tantangan dan respons. POST /api/v1/auth/public-key/challenge kembali:

{
  "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
  "payload": {
    "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
    "fingerprint": "9c0b7a…",
    "issuer": "starhermit",
    "audience": "starhermit",
    "expiry": "2026-10-09T14:21:41.9264875+00:00",
    "nonce": "NmL+tgMum6HXU/pa3T9xjQ==",
    "clientTimestamp": "2026-10-09T14:16:41.9265739+00:00"
  },
  "expiresIn": 300
}

Apa yang Anda tandatangani bukanlah JSON yang Anda terima. StarHermit memverifikasi tanda tangannya sendiri serialisasi dari payload:

  • JSON kompak, tanpa spasi;
  • Kasus Pascal nama anggota, sesuai urutannya ChallengeId, Fingerprint, Issuer, Audience, Expiry, Nonce, ClientTimestamp;
  • setiap nilai disalin persis seperti yang disajikan — jangan menguraikan dan memformat ulang tanggal;
  • setiap + di nonce ditulis sebagai \u002B. Itu + di tanggalnya tetap apa adanya.

Untuk tantangan di atas, byte yang ditandatangani adalah pengkodean UTF-8 dari:

{"ChallengeId":"4fc4d72b-4c12-41ca-a500-dc13cccc3865","Fingerprint":"9c0b7a…","Issuer":"starhermit","Audience":"starhermit","Expiry":"2026-10-09T14:21:41.9264875+00:00","Nonce":"NmL\u002BtgMum6HXU/pa3T9xjQ==","ClientTimestamp":"2026-10-09T14:16:41.9265739+00:00"}

Jika ada yang salah dan jawabannya adalah 401 "Invalid signature.", yang tidak akan diperbaiki jika dicoba lagi.

const FIELDS = ['challengeId', 'fingerprint', 'issuer', 'audience', 'expiry', 'nonce', 'clientTimestamp'];

export function challengeSigningBytes(payload) {
  const members = FIELDS.map((field) => {
    let value = JSON.stringify(payload[field]);
    if (field === 'nonce') value = value.replaceAll('+', '\\u002B');
    return `"${field[0].toUpperCase()}${field.slice(1)}":${value}`;
  });
  return new TextEncoder().encode(`{${members.join(',')}}`);
}

export async function signChallenge(key, payload) {
  const data = challengeSigningBytes(payload);
  if (key.keyType === 'Ed25519')
    return b64(await crypto.subtle.sign({ name: 'Ed25519' }, key.privateKey, data));
  // WebCrypto returns an ECDSA signature as raw r||s; the server expects ASN.1 DER.
  const rs = new Uint8Array(
    await crypto.subtle.sign({ name: 'ECDSA', hash: 'SHA-256' }, key.privateKey, data));
  return b64(derEcdsaSignature(rs));
}

function derEcdsaSignature(rs) {
  const integer = (bytes) => {
    let i = 0;
    while (i < bytes.length - 1 && bytes[i] === 0) i++;
    const value = [...bytes.slice(i)];
    return value[0] & 0x80 ? [0x02, value.length + 1, 0, ...value] : [0x02, value.length, ...value];
  };
  const body = [...integer(rs.slice(0, 32)), ...integer(rs.slice(32))];
  return new Uint8Array([0x30, body.length, ...body]);
}

// Resolves to { userId, accessToken, refreshToken }, or null while the key is not attached to
// an account yet — the player has not confirmed, the link expired, or the key was revoked.
export async function signIn(key) {
  const { keyType, keyData } = key;
  const challenge = await post('/api/v1/auth/public-key/challenge', { keyType, keyData });
  if (challenge.status !== 200) throw fail('challenge', challenge);
  const signature = await signChallenge(key, challenge.body.payload);
  const done = await post('/api/v1/auth/public-key/complete',
    { challengeId: challenge.body.challengeId, signature, keyType, keyData });
  if (done.status === 200) return done.body;
  if (done.status === 401 && done.body.error === 'Public key not registered or revoked.') return null;
  throw fail('complete', done); // "Invalid signature." will never succeed: fix it, don't retry it
}

Tantangan berlangsung selama lima menit dan hanya sekali pakai, meskipun upayanya gagal, jadi mintalah tantangan baru untuk setiap upaya. Tantang dan selesaikan batas berbagi 60 permintaan per menit per alamat IP.

4. Tunggu hingga pemain mengonfirmasi

Tautan yang dikirim melalui email membuka halaman StarHermit yang menyatakan apa yang akan dilakukan konfirmasi; membukanya berubah tidak ada apa-apa, jadi pemindai email yang mempratinjau tautan tidak dapat mengonfirmasi atas nama pemain. Ketika pemain menekan Mengonfirmasi, StarHermit membuat akun mereka, melampirkan kunci Anda dan menandai alamatnya diverifikasi. Jika akun sudah menggunakan alamat itu, halaman akan menyatakan demikian dan kunci akan ditambahkan ke dalamnya sebagai gantinya, jadi pemain yang sudah memiliki akun StarHermit menyimpannya. Di starhermit.com mereka kemudian mendarat di dashboard StarHermit, sudah masuk.

Game Anda tidak pernah menerima token dari halaman itu, dan tidak membutuhkannya. Pemain mungkin konfirmasi di ponsel atau di browser lain. Setelah kunci terpasang, game Anda cukup masuk dengan itu. Jadi tunjukkan a "periksa kotak masuk Anda" layar dan terus mencoba:

// Poll until the player confirms the emailed link. Two requests per attempt, so every 5 s stays
// well inside the 60-per-minute sign-in limit.
export async function waitUntilConfirmed(key, { intervalMs = 5000, signal } = {}) {
  for (;;) {
    signal?.throwIfAborted();
    const session = await signIn(key);
    if (session) return session;
    await new Promise((resolve) => setTimeout(resolve, intervalMs));
  }
}

Menggabungkan langkah 1 hingga 4:

import { createDeviceKey, register, signIn, waitUntilConfirmed } from './starhermit-key-auth.js';

const key = await loadStoredKey() ?? await saveKey(await createDeviceKey());
let session = await signIn(key);                // a returning player is signed in here
if (!session) {
  const email = await askForEmailAndConsent();
  await register(key, email);
  showCheckYourInbox(email);
  session = await waitUntilConfirmed(key, { signal: cancelButton.signal });
}

loadStoredKey, saveKey, askForEmailAndConsent Dan showCheckYourInbox adalah milikmu untuk ditulis. Tawaran a Membatalkan yang membatalkan penantian, dan menghentikan pemungutan suara setelah empat jam, ketika tautannya kedaluwarsa.

Tetap lakukan polling meskipun halaman konfirmasi platform Anda dialihkan kembali ke situs Anda. Pemain sering membuka email di perangkat yang berbeda dari perangkat yang menunggu, lalu pengalihan tidak mengarah ke mana pun dekat layar tunggu Anda; polling inilah yang menandatangani perangkat yang menunggu. Jika pengalihan tiba di tab kedua, masuk hanya dengan salah satu dari mereka dan cabut sesi tambahan, atau pemain akan berakhir dengan dua.

5. Pertahankan sesinya

complete mengembalikan token akses 15 menit dan token penyegaran yang bertahan tujuh hari dan berputar. Kirim token akses sebagai Authorization: Bearer …, dan segarkan sebelum masa berlakunya habis:

// Resolves to the new pair, or null when the session is over — sign in with the key again.
export async function refresh(refreshToken) {
  const res = await post('/api/v1/auth/refresh', { refreshToken });
  return res.status === 200 ? res.body : null; // { accessToken, refreshToken }
}

Mengganti keduanya token setiap saat. Menyajikan token penyegaran bekas mengakhiri seluruh sesi, jadi buatlah tentu saja dua utas atau proses tidak pernah disegarkan sekaligus. Kapan refresh kembali null, panggilan signIn — tidak ada email yang terlibat. Kuncinya adalah kredensial yang berumur panjang; token hanyalah cache saja.

6. Selesaikan pengaturan akun

Ketentuan. Akun baru harus menerima persyaratan StarHermit saat ini sebelum dapat menggunakan yang lain. Panggilan GET /api/v1/me. Jika termsAcceptanceRequired adalah true, tampilkan teks dari GET /api/v1/terms, dan ketika pemain menerimanya, kirimkan hashnya ke POST /api/v1/me/terms/accept. Periksa lagi pada peluncuran selanjutnya, karena persyaratannya telah direvisi. Detail: Persyaratan penerimaan.

Nama. Akun dimulai dengan a pk-… nama belakang. Biarkan pemain memilih nama panggilan:

PATCH /api/v1/me
Authorization: Bearer <access-token>
Content-Type: application/json

{ "nickname": "RookPilot" }

Dari sini akunnya seperti akun lainnya: teman, obrolan, perjodohan, penyimpanan cloud, pencapaian.

7. Perangkat kedua, kunci yang hilang, dan batasannya

Perangkat kedua menghasilkan kuncinya sendiri dan mendaftarkannya alamat email yang sama. Ketika pemain mengonfirmasi, kuncinya bergabung dengan akun mereka yang sudah ada daripada membuat akun baru. 24 jam batas per alamat juga berlaku di sini.

Perangkat yang hilang atau dicuri. POST /api/v1/auth/public-key/revoke-request dengan { "email": "…" } mengirimkan tautan ke halaman melalui email; mengkonfirmasi ada pencabutan setiap kunci akun dan akhiri sesi kunci-kunci itu masuk. Membuka tautan saja tidak mengubah apa pun. Permintaan itu selalu dijawab 202 dengan pesan yang sama, baik itu atau tidak alamat memiliki akun. Tautan akan kedaluwarsa setelah empat jam, dan akun dapat meminta setiap 15 jam sekali menit. Setelah itu, setiap perangkat yang tersisa mendaftar lagi (langkah 2).

Apa yang tidak dapat dilakukan oleh akun khusus kunci. Beberapa perubahan melindungi kredensial akun, demikian juga memerlukan sesi yang masuk melalui penyedia seperti Google atau GitHub:

Tindakan Akun khusus kunci
Tambahkan kunci atau cabut perangkat lain (POST /me/public-keys, DELETE /me/public-keys/{id} atau /all) 403 — mendaftar melalui pendaftaran email, atau menggunakan sesi yang diautentikasi OAuth
Ubah alamat email akun 403 oauth_session_required — tidak mungkin dilakukan sampai penyedia terhubung
Cabut kunci instalasi ini sendiri DELETE /api/v1/me/public-keys/current, menggunakan sesi akun kunci publik lengkapnya; buang kredensial lokal setelah sukses

Untuk mengelola kredensial lain atau mengubah email, tautkan penyedia. Ketika akun khusus kunci menautkan satu akun, tautan tersebut akan ditahan sampai pemain mengonfirmasinya dari email mereka. Setelah itu, login penyedia dapat melakukan semua hal di atas. Melihat authorize?link=true.
