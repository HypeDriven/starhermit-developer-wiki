Tutorial: membuat game dengan mesin StarHermit

Itu Mesin StarHermit adalah cara yang disarankan untuk membuat game untuk dipublikasikan di StarHermit. Anda membuat game satu kali, dan paket yang sama secara otomatis dapat dimainkan di browser dan secara asli di semua platform yang didukung oleh mesin. Permainan asli menawarkan kinerja dan fitur tambahan. Ketersediaan bergantung pada rilis mesin: 1.1.0 dan yang lebih baru memiliki runtime Windows dan runtime web (1.0.0 hanya untuk Windows), 1.8.1 dan yang lebih baru juga merupakan runtime Linux untuk pengembang, dan 1.26.2 dan runtime macOS yang lebih baru (Intel dan Apple Silicon). Halaman ini menjelaskan mesin 1.28.0; apa yang diubah setiap rilis dicantumkan di bawah Rilis engine.

Mesin StarHermit bekerja permainan skrip: keseluruhan permainan yang ditulis dalam TypeScript (atau JavaScript) dan dimainkan oleh satu mesin bawaan yang dapat dieksekusi, runtime StarHermit, tanpa mengkompilasi kode asli apa pun. Anda menulis logika permainan berdasarkan modul bawaan mesin — adegan 3D, masukan, HUD, audio, penyimpanan dan platform StarHermit — dan runtime melakukan sisanya: windowing, rendering pada GPU, suara, menu opsi, masuk dan bermain online. Pemain membuka permainan di starhermit.com di browser mereka, tempat halamannya memuat mesin yang diminta permainan Anda dari wiki ini, atau memainkannya secara asli di Klien Windows StarHermit, yang memasang mesin itu.

Tutorial ini dibuat Penangkap Bintang, permainan kecil di mana Anda mengarahkan keranjang untuk menangkap jatuh bintang, dan membawanya dari folder kosong ke game yang diterbitkan:

1. Apa itu permainan skrip

Permainan skrip adalah folder (a kemasan) dengan a starhermit.txt di itu root, modul TypeScript Anda, dan aset Anda. Tiga engine.* baris dalam manifes menjadikannya satu:

engine.api=1
engine.entry=src/main.ts
engine.version=1.28.0

engine.api adalah versi utama dari API host yang digunakan untuk menulis kode Anda, engine.entry itu modul runtime dimulai, dan engine.version rilis mesin yang tepat untuk game tersebut dan diuji untuk. Rilis dipublikasikan di wiki ini di bawah Rilis engine; itu game tidak pernah berisi mesin itu sendiri, jadi unggahan hanya menampung file Anda sendiri.

Runtime memperlakukan setiap game sebagai tidak tepercaya: kode Anda hanya mencapai mesin melalui API host (file paketnya sendiri, penyimpanannya sendiri, platform untuk id gamenya sendiri), tidak pernah file, proses, koneksi jaringan sewenang-wenang atau kredensial pemain. Sebagai imbalannya, game tidak dapat menghentikan runtime atau gantung jendela: panggilan yang berjalan selama tiga detik menampilkan runtime-nya sendiri "tidak merespons" layar, dan kesalahan yang tidak tertangkap mengakhiri permainan pada layar kesalahan tempat pemain dapat memulai ulang.

2. Dapatkan mesinnya

Untuk penerbitan otomatis dan server MCP pengembangan permainan skrip, dapatkan alat pengembang mandiri. Mereka juga mengemas game web di macOS tanpa Rust atau akses repositori pribadi; tes bermain di a peramban di sana. Pemutaran asli Windows/Linux menggunakan runtime di bawah ini.

Pemain tidak melakukan apa pun: di browser, halaman game memuat rilis pin game dari wiki ini dan memeriksanya terhadap hash yang dibawa halaman tersebut; di klien Windows StarHermit, Mainkan unduhan rilis (sekali, dibagikan oleh setiap game yang menyematkannya), memeriksa setiap file terhadap rilisnya menerbitkan hash dan memulainya.

Pengembang unduh runtime rilis dari area mesin:

  • starhermit-1.28.0-windows-x86_64.zip (Windows 10 atau 11, 64-bit), 11,7 MB.
  • starhermit-1.28.0-linux-x86_64.tar.gz (Linux 64-bit dengan glibc 2.35 atau lebih baru: Ubuntu 22.04, Debian 12 atau lebih baru), 11,8 MB.
  • starhermit-1.28.0-macos-x86_64.tar.gz (macOS 11 atau lebih baru di Intel), 10,8 MB, dan starhermit-1.28.0-macos-aarch64.tar.gz (macOS 11 atau lebih baru di Apple Silicon), 9,5 MB. Ini ditandatangani secara ad hoc dan tidak dinotariskan: StarHermit Klien macOS menginstalnya tanpa masalah, tetapi tarball yang diunduh di browser dikarantina dan Penjaga gerbang memblokirnya (bersihkan dengan xattr -dr com.apple.quarantine pada folder yang belum dibongkar). Mereka punya belum diuji pada perangkat keras Apple asli atau dengan GPU.

Arsip menampung satu folder, starhermit-1.28.0-windows-x86_64, dengan starhermit.exe, itu release.json yang memberi tahu runtime rilis mana itu, rilisnya web-manifest.json, LICENSE-engine dan pemberitahuan pihak ketiga. Ini adalah mesin yang sama yang diinstal klien, dan itu mengemas game untuk runtime web rilis tanpa jaringan. Ukurannya dan SHA-256 tercantum di bawah downloads dalam rilis native.json; untuk periksa salinan Anda di PowerShell, bandingkan itu sha256 dengan:

Get-FileHash .\starhermit-1.28.0-windows-x86_64.zip -Algorithm SHA256

Buka paket arsip dan buka terminal di folder yang belum dibongkar:

.\starhermit.exe --version

starhermit 1.28.0 (host API 1.30, launcher 1; engine release 1.28.0)

Di Linux, buka paket arsip dan jalankan starhermit dari foldernya (itu native.json mencantumkan SHA-256 arsip yang sama cara; periksa dengan sha256sum):

tar -xzf starhermit-1.28.0-linux-x86_64.tar.gz
./starhermit-1.28.0-linux-x86_64/starhermit --version

--version, new, types, check Dan package tidak memerlukan apa-apa lagi. Untuk memainkan permainan di jendela runtime memerlukan Wayland atau X11 dengan driver Vulkan atau OpenGL ES 3.0, dan ALSA atau PulseAudio untuk suara; native.json's requires mencantumkan setiap perpustakaan yang digunakannya. Pemain masih memutar unggahan asli di Klien Windows StarHermit; runtime Linux adalah untuk menulis, memeriksa, dan mengemas game.

Perintah di bawah ini ditulis sebagai starhermit; jalankan sebagai .\starhermit.exe (jendela) atau ./starhermit (Linux) dari folder itu, atau tambahkan folder tersebut ke folder Anda PATH.

3. Buat permainannya

starhermit new star-catcher --title "Star Catcher"

Created Star Catcher in star-catcher: a script game pinned to engine 1.28.0
Play it: starhermit star-catcher
Check it: starhermit check star-catcher
For a native upload (the StarHermit client plays it): starhermit package --native star-catcher
For the web: starhermit package --web star-catcher --out <upload>

Folder baru ini berisi titik awal yang dapat dimainkan — sebuah kubus yang melompat ketika Anda menekan Spasi:

star-catcher/
  starhermit.txt             the manifest, pinned to the runtime's own release (engine.version=1.28.0)
  tsconfig.json              TypeScript settings for checking the game
  src/main.ts                the entry module
  .starhermit/starhermit.d.ts  the host API's declarations, for your editor and the type checker

.starhermit/ dimulai dengan sebuah titik, jadi itu tidak pernah menjadi bagian dari paket. starhermit types star-catcher tulis deklarasinya lagi, misalnya setelah Anda pindah ke yang lebih baru waktu proses. Setiap modul, anggota, unit, batasan, dan kesalahan API host didokumentasikan dalam file itu.

Runtime tidak memeriksa tipe: ia menghapus tipe TypeScript saat memuat setiap modul. Periksa mereka diri Anda sendiri dengan TypeScript 5 atau lebih baru; dengan Node.js terinstal, npx menjalankannya tanpa menginstal apa pun di folder game:

cd star-catcher
npx --package typescript tsc -p .

File pengembangan tidak disertakan dalam paket: nama titik (seperti .starhermit/ Dan .git/), node_modules/, tsconfig.json, jsconfig.json, package.json, file kunci npm, benang dan pnpm, peta sumber (*.js.map, *.ts.map dan sejenisnya) dan Thumbs.db/desktop.ini. Segala sesuatu yang lain masuk folder tersebut adalah bagian dari paket. Untuk menghilangkan lebih banyak, tambahkan a .starhermitignore di root permainan dengan aturan gaya gitignore (* Dan ? dalam sebuah nama, ** untuk sejumlah folder, sebuah tambahan / untuk folder, ! untuk menyimpan file, aturan default tidak disertakan; aturan pencocokan terakhir memutuskan):

notes/
levels/**/draft-*.json
!package.json

Game yang membaca atau mengimpor file yang ditinggalkan gagal dengan kesalahan penamaan aturan, dalam pengembangan sebagai baiklah, jadi starhermit check menangkapnya sebelum Anda mengunggah.

4. Tulis versi pertama

Ganti yang dihasilkan starhermit.txt dengan manifes permainan:

name=Star Catcher
description=Catch the falling stars before the time runs out.
launch=index.html
engine.api=1
engine.entry=src/main.ts
engine.version=1.28.0
engine.minor=15
engine.capabilities=platform,storage
control.left=KeyA+ArrowLeft | Move left
control.right=KeyD+ArrowRight | Move right
control.start=Space+Enter | Start a round
engine.gamepad.left=LeftStickLeft+DpadLeft
engine.gamepad.right=LeftStickRight+DpadRight
engine.gamepad.start=South
cache..=0

Itu control.* baris mendeklarasikan tindakan game dengan kunci defaultnya (kunci platform kontrol format) dan engine.gamepad.* default gamepad mereka. Pemain melakukan rebind mereka di menu Opsi runtime, sehingga permainan terbaca tindakan, tidak pernah kunci. Sebuah permainan diumumkan hingga 128 tindakan: platform menyimpan 32 tindakan pertama dengan akun pemain, dan runtime menyimpannya pengikatan sisanya dalam pengaturan pemutar yang disinkronkan. engine.group.<action>=Heading memulai sebuah grup pada tindakan itu (hingga grup berikutnya), yang ditampilkan layar kontrol di bawah judul, misalnya engine.group.left=Movement (host API 1.6). engine.capabilities menanyakan apa yang digunakan game selain menggambar dan memasukkan: platform untuk pemain yang masuk dan online fitur, storage untuk data yang disimpan di perangkat dan akun pemain. launch=index.html nama itu halaman yang memainkan permainan di browser, yang ditulis oleh mesin saat Anda menerbitkan.

Lalu ganti src/main.ts:

// Star Catcher: catch the falling stars in the basket before the time runs out.
import { frame, onFixedUpdate, onRender, onStart, setFixedRate } from "starhermit:engine";
import {
  AmbientLight,
  BoxGeometry,
  Color,
  DirectionalLight,
  Mesh,
  MeshStandardMaterial,
  PerspectiveCamera,
  SphereGeometry,
  renderer,
  scene,
} from "starhermit:scene";
import { onAction, value } from "starhermit:input";
import { storage } from "starhermit:storage";
import { player } from "starhermit:platform";
import * as draw from "starhermit:draw";

// -- The scene ----------------------------------------------------------------
const camera = new PerspectiveCamera(50, 16 / 9, 0.1, 100);
camera.position.set(0, 4, 12);
camera.lookAt(0, 3, 0);
renderer.camera = camera;
scene.background = new Color(0x0b1020);

const sun = new DirectionalLight(0xfff4e0, 1.2);
sun.position.set(3, 8, 5);
scene.add(sun, sun.target, new AmbientLight(0x6070a0, 0.5));

const basket = new Mesh(new BoxGeometry(2, 0.4, 1), new MeshStandardMaterial({ color: 0x4fa3ff, roughness: 0.4 }));
scene.add(basket);

const starGeometry = new SphereGeometry(0.3, 16, 12);
const starMaterial = new MeshStandardMaterial({ color: 0xffd34d, emissive: 0xffb000, emissiveIntensity: 0.6 });
const stars = Array.from({ length: 3 }, () => {
  const mesh = new Mesh(starGeometry, starMaterial);
  scene.add(mesh);
  return { mesh, x: 0, y: 0, previousY: 0, speed: 0 };
});
type Star = (typeof stars)[number];

// -- The rules ----------------------------------------------------------------
const WIDTH = 6; // the basket moves between -WIDTH and WIDTH
const ROUND = 60; // seconds a round lasts
let basketX = 0;
let previousX = 0;
let score = 0;
let timeLeft = 0; // 0 between rounds
const saved = storage.getJson("best");
let best = typeof saved === "number" ? saved : 0;

function drop(star: Star): void {
  star.x = (Math.random() * 2 - 1) * WIDTH;
  star.y = star.previousY = 8 + Math.random() * 4;
  star.speed = 2 + Math.random() * 2 + score * 0.05;
}

onStart(() => {
  setFixedRate(60);
  for (const star of stars) drop(star);
});

onAction((event) => {
  if (event.action === "start" && event.pressed && timeLeft === 0) {
    score = 0;
    timeLeft = ROUND;
    for (const star of stars) drop(star);
  }
});

onFixedUpdate((step) => {
  previousX = basketX;
  for (const star of stars) star.previousY = star.y;
  if (timeLeft === 0) return;
  // An action's value is 0 to 1, so a stick steers gently and a key fully.
  const steer = value("right") - value("left");
  basketX = Math.max(-WIDTH, Math.min(WIDTH, basketX + steer * 9 * step));
  for (const star of stars) {
    star.y -= star.speed * step;
    if (star.y < 0.6 && star.y > 0 && Math.abs(star.x - basketX) < 1.2) {
      score += 1;
      drop(star);
    } else if (star.y < -1) {
      drop(star);
    }
  }
  timeLeft = Math.max(0, timeLeft - step);
  if (timeLeft === 0 && score > best) {
    best = score;
    storage.setJson("best", best);
  }
});

// -- Drawing ------------------------------------------------------------------
onRender((alpha) => {
  // Between two fixed steps: draw where things are at this moment.
  basket.position.set(previousX + (basketX - previousX) * alpha, 0.2, 0);
  for (const star of stars) {
    star.mesh.position.set(star.x, star.previousY + (star.y - star.previousY) * alpha, 0);
  }
  hud();
});

function hud(): void {
  const { width, height, scale } = frame();
  const size = 22 * scale;
  const name = player()?.displayName ?? "Guest";
  draw.text(`${name}   score ${score}   best ${best}`, 16 * scale, 16 * scale, { size, color: "#e8ecf4" });
  if (timeLeft > 0) {
    draw.text(`${Math.ceil(timeLeft)} s`, width - 16 * scale, 16 * scale, { size, color: "#ffd34d", align: "end" });
  } else {
    draw.rect(0, height / 2 - 40 * scale, width, 80 * scale, [0, 0, 0, 0.5]);
    draw.text("Press Space to play", width / 2, height / 2 - 12 * scale, { size, color: "#ffffff", align: "center" });
  }
}

Apa yang dilakukan setiap bagian:

  • Adegan itu. starhermit:scene mengikuti three.js: kamera, lampu, jerat yang terbuat dari geometri dan sebuah bahan, scene.add. Jarak adalah meter, sudut radian, dan warna sRGB.
  • Aturannya. onFixedUpdate berjalan pada tingkat bunga tetap setFixedRate(60) meminta, 60 kali a kedua, berapa pun kecepatan bingkainya, sehingga permainan dimainkan sama di setiap mesin. value("right") adalah nilai aksinya dari 0 hingga 1, jadi stik gamepad akan bergerak dengan lembut dan kunci akan bergerak sepenuhnya, dan onAction mendengar setiap tekanan, di sini untuk memulai putaran.
  • Menggambar. onRender berjalan sekali per frame dengan alpha, seberapa jauh jarak frame antara dua frame terakhir langkah-langkah tetap; posisi yang ditarik di antaranya previous dan nilai saat ini bergerak dengan lancar pada penyegaran apa pun menilai. starhermit:draw menggambar HUD di atas pemandangan dalam piksel jendela; frame().scale mengkonversi piksel logis untuk tampilan DPI tinggi.
  • Skor terbaik tetap berada di perangkat pemain starhermit:storage, dipisah untuk setiap pemain.

5. Jalankan secara asli

starhermit check star-catcher

package=Directory files=3 bytes=6378 name="Star Catcher" api=1 entry=src/main.ts capabilities=platform,storage actions=left,right,start
left out: tsconfig.json (default rule tsconfig.json)
web=linked modules=2
runnable=true engine="TypeScript" frames=120 probes=0
PASS package src/main.ts: valid; 120 frames headless

check memvalidasi paket (manifest, jalur, ukuran) dan memutar 120 frame tanpa jendela, jadi a kesalahan sintaksis, impor yang tidak diketahui atau pengecualian saat start-up ditampilkan di sini dengan file, baris, dan kolomnya. Ini mencetak permainannya console keluaran seiring berjalannya ([game] log src/main.ts:12:5: text, paling banyak 1.000 garis; --quiet menyembunyikannya), gagal dalam permainan yang akan memunculkan "tidak merespons" layar, dan tautan modul Anda seperti cara browser memuatnya, jadi game yang tidak dapat dimuat di browser juga gagal di sini (lihat Perbedaan asli dan browser). Kemudian mainkan:

starhermit star-catcher

Tekan Spasi untuk memulai putaran dan tombol panah (atau A dan D, atau gamepad) untuk mengarahkan. F1 selalu membuka menu runtime sendiri: grafik, audio, kontrol (rebinding), akun, dan keluar. Anda game tidak dapat menggambar atau membacanya, dan tidak ada game yang dapat mengikat F1.

Halaman Grafiknya menawarkan Otomatis dan sepuluh level, dari quantum (telepon) melalui atomic, molecular, cellular, terrestrial, planetary, stellar, galactic Dan cosmic ke infinite (desktop tercepat). Otomatis memilih satu dari GPU dan benchmark singkat yang pertama waktu, dimulai tidak lebih tinggi dari stellar dan mundur ketika frame terlambat. Game Anda membaca levelnya dengan frame().level dan anggarannya dengan levelSettings() (host API 1.14, jadi engine.minor=14); frame().quality masih memberi low, balanced, high atau ultra. Level yang tidak dapat dijalankan oleh perangkat (dari ukuran tekstur GPU terbesarnya; ponsel, tablet, dan perangkat 4 GiB berhenti di cellular) pertunjukan dinonaktifkan dengan alasannya, dan frame().levelCeiling memberikan yang tertinggi yang bisa: permainan menggambarnya sendiri menu grafis menonaktifkan level di atasnya (ui.select pilihan yang diambil disabled Dan description).

Sambil berkembang, tambahkan --dev (starhermit star-catcher --dev): runtime kemudian mencetak game tersebut console keluaran dalam bentuk yang sama dan menunjukkan kesalahan pada baris TypeScript Anda.

6. Banyak hal sekaligus: starhermit:world

Secara alami, TypeScript game Anda berjalan di penerjemah skrip mesin itu sendiri, yang menyimpan setiap game sesuai anggaran waktu dan ingatannya; di browser ini berjalan di mesin JavaScript browser, di a pekerja halaman bisa berhenti. Keputusan dan beberapa lusin objek memerlukan biaya yang kecil, namun per-entitas pekerjaan - memindahkan ribuan partikel, kerumunan, kawanan - berarti ribuan langkah yang ditafsirkan setiap bingkai. Untuk itu mesinnya punya starhermit:world:

  • tabel menyimpan data entitas dalam kolom yang diketik (angka dan vektor) di memori permainan;
  • kernel adalah fungsi biasa dari satu baris yang dikompilasi dan dijalankan secara asli oleh runtime setiap baris tabel, tanpa memasukkan skrip;
  • itu jadwal menjalankan kernel setiap frame, dan ikatan menggambar meja menjadi satu InstancedMesh (atau menggerakkan node adegan), menyusun setiap instance secara asli.

Skrip Anda membuat keputusan; runtime melakukan aritmatika per baris. Tambahkan langit malam 4.000 berkilauan berkilau di belakang permainan sebagai src/sky.ts:

// The night sky behind the game: 4,000 twinkling sparkles. Their data lives
// in a starhermit:world table, a kernel moves every one of them natively each
// frame, and an instance binding draws the table as one InstancedMesh, so the
// game's script runs no per-sparkle code at all.
import { InstancedMesh, MeshBasicMaterial, SphereGeometry, scene } from "starhermit:scene";
import { bind, kernel, schedule, table } from "starhermit:world";

const COUNT = 4_000;

// One row per sparkle: where it hangs, how it twinkles, and what the kernel
// writes each frame (its height and size).
const sky = table("sky", COUNT, {
  base: "vec3",
  phase: "f32",
  rate: "f32",
  y: "f32",
  size: "f32",
});
sky.spawn(COUNT);

// Filled once from script, through typed arrays over the table's memory.
const base = sky.column("base");
const phase = sky.column("phase");
const rate = sky.column("rate");
for (let i = 0; i < COUNT; i++) {
  base[i * 3] = (Math.random() * 2 - 1) * 40;
  base[i * 3 + 1] = Math.random() * 24 - 2;
  base[i * 3 + 2] = -10 - Math.random() * 30;
  phase[i] = Math.random() * Math.PI * 2;
  rate[i] = 0.5 + Math.random() * 2;
}

// An ordinary function of one row. The runtime compiles it and runs it over
// every live row without entering script.
const twinkle = kernel(sky, (r, u: { drift: number }, f) => {
  r.y = r.base.y + Math.sin(f.time * u.drift + r.phase) * 0.3;
  r.size = 0.04 + 0.04 * Math.abs(Math.sin(f.time * r.rate + r.phase));
});

const mesh = new InstancedMesh(new SphereGeometry(1, 6, 4), new MeshBasicMaterial({ color: 0xcfd8ff }), COUNT);
scene.add(mesh);

/** Starts the sky: the kernel runs after every onUpdate, and the binding
 * composes the mesh's instances from the columns after every onRender. */
export function startSky(): void {
  schedule.update(twinkle, { drift: 0.4 });
  bind.instances(mesh, sky, { position: ["base.x", "y", "base.z"], scale: "size" });
}

dan memulainya dari src/main.ts: mengimpornya dengan impor lainnya, dan memanggilnya onStart:

import { startSky } from "./sky.js";

onStart(() => {
  setFixedRate(60);
  startSky();
  for (const star of stars) drop(star);
});

Nama-nama impor ./sky.js, konvensi TypeScript untuk modul yang ditulis sebagai sky.ts; waktu proses menyelesaikannya dengan cara yang sama. Kernel menerima subset dari bahasa — angka dan boolean, aritmatika, Math, if, dibatasi for loop, kolom baris dan seragam yang Anda lewati — dan runtime menolak apa pun dengan a SyntaxError di baris kernel saat mengkompilasinya, bukan menjalankannya perlahan. Deklarasi dari starhermit:world jelaskan subset, antrian acara itu kernel memancarkan, tabel dengan riwayat untuk gerakan langkah tetap yang mulus, dan pengikatan simpul.

7. Pemain, simpanan dan permainan online

Pemain. player() dari starhermit:platform adalah pemain yang masuk, atau null untuk a tamu; Star Catcher menunjukkan nama mereka di HUD-nya. Saat klien Windows StarHermit memulai permainan Anda, pemain masuk dari frame pertama, dengan akun klien: klien menyerahkan runtime token peluncuran untuk game Anda melalui saluran pribadi, memperbaruinya saat game berjalan, dan game tidak pernah melihatnya (tidak ada panggilan host yang mengembalikan token, kunci, atau cookie). Pemain tidak pernah masuk ke dalam a permainan; masuk dan keluar terjadi di klien.

Di browser platform membuka halaman game dengan token peluncuran untuk game Anda, yang mana mesin mengambil alamat halaman sebelum kode Anda dijalankan dan diperbarui dalam 12 jam platform membatasi; permainan Anda hanya melihat player(), persis seperti aslinya. Seorang tamu yang memilih Masuk di Dialog Akun runtime membuka halaman masuk StarHermit dan kembali masuk. Suara menggunakan mikrofon browser setelah permintaan izin browser itu sendiri.

Pembangunan berjalan. Dimulai dari terminal, sebuah paket tidak dapat mengklaim identitas platform dengan sendirinya, jadi starhermit star-catcher bermain sebagai tamu. Setelah game Anda diterbitkan, pengembangan diluncurkan beri nama:

dan Anda masuk melalui F1 → Akun…, dialog runtime itu sendiri (kunci di komputer ini dan satu konfirmasi melalui email, seperti pada orientasi kunci publik). Penyimpanan, pengaturan, simpan dan mainkan online lalu ikuti game dan akun itu.

Simpan dan pengaturan. starhermit:storage memiliki tiga toko, semuanya bersifat pribadi untuk game Anda: storage (data kunci/nilai pada perangkat, seperti yang digunakan Star Catcher), settings (opsi permainan, disimpan di akun pemain di bawah platform pengaturan per pemain), Dan saves (yang penyimpanan game, di perangkat, dan di pemain slot penyimpanan awan dengan konflik penanganan).

Bermain daring. Semua yang ditawarkan platform game ada di dalamnya starhermit:platform untuk permainanmu id sendiri: teman dan kehadiran, undangan, ruangan waktu nyata, perjodohan, itu soket permainan (connectGame), papan peringkat, pencapaian, tayangan ulang, obrolan, dan suara. Untuk multipemain otoritatif server, deklarasikan a naskah permainan:

server=server.js

Platform menjalankannya sebagai otoritas untuk sesi game Anda; starhermit:script's authority("server.js", …) menjalankan file yang sama pada pekerja lokal untuk latihan offline, persis seperti itu platform melakukannya, jadi permainan offline dan online berbagi satu jalur kode. Skor papan peringkat, prestasi dan hasil pertandingan hanya ditulis oleh skrip server, tidak pernah ditulis oleh game itu sendiri; membuat papan seperti yang dijelaskan dalam papan peringkat dan prestasi.

Berasal dari build JavaScript SDK

Sebuah game yang sudah berjalan di StarHermit sebagai browser yang dibuat menggunakan JavaScript SDK menjaga pemainnya tetap terhubung. kemajuan saat berpindah ke mesin (host API 1.8, jadi tambahkan engine.minor=8). Mesin menunjukkan awan simpan tidak ditulis sebagai luar negeri: saves.state() adalah "foreign", saves.foreign() memberikan slot bytes persis seperti yang disimpan (dan itu text padahal itu teks), dan tidak ada yang diunggah sampai game mengubahnya dan menyimpannya replaceForeign, yang hanya menggantikan versi yang ditampilkan. Itu tombol pengaturan game yang lebih lama (di luar game.) dibaca seluruhnya settings.legacyKeys() Dan settings.legacy(key), dan dihapus dengan settings.removeLegacy(key) sekali bermigrasi. decompress Dan compress (gzip, zlib atau DEFLATE mentah) memberikan byte yang sama secara asli dan di browser:

import { saves, settings } from "starhermit:storage";
import { decompress } from "starhermit:engine";

saves.onStatus((_, state) => {
  if (state !== "foreign") return;
  const old = saves.foreign()!;
  // For example, a save written as gzip-compressed JSON:
  const text = new TextDecoder().decode(decompress(old.bytes, "gzip"));
  saves.save(convert(JSON.parse(text)), { schema: 1, replaceForeign: true });
});
settings.onLegacy(() => {
  for (const key of settings.legacyKeys() ?? []) importOldSetting(key, settings.legacy(key));
});

Jika build browser mendaftarkan pekerja layanan yang melayani dari cache terlebih dahulu, maka akan kembali pemain terus mendapatkan versi lama yang di-cache hingga pekerja tersebut hilang. Kirimkan penggantinya ke jalur yang sama (misalnya sw.js) di unggahan mesin. Ini mengambil alih sekaligus, membersihkan cache lama, membatalkan pendaftarannya sendiri dan memuat ulang halamannya ke pemuat mesin. navigate() hanya berfungsi setelahnya clients.claim():

self.addEventListener("install", () => self.skipWaiting());
self.addEventListener("activate", (event) => event.waitUntil((async () => {
  await self.clients.claim();
  for (const key of await caches.keys()) await caches.delete(key);
  await self.registration.unregister();
  for (const client of await self.clients.matchAll({ type: "window" })) client.navigate(client.url);

9. Pindah ke mesin yang lebih baru

Sebuah game berjalan persis pada rilis yang disematkannya: tidak ada yang mengupgradenya di belakang Anda, dan diterbitkan rilis tidak pernah berubah. Untuk pindah ke yang lebih baru, unduh runtime-nya, jalankan game Anda dan periksa di atasnya, lalu sematkan ulang dengan cara menggantinya engine.version di dalam starhermit.txt, kemas lagi dan publikasikan. Klien pemain mengunduh mesin baru satu kali (hanya yang berubah dari rilis yang sudah mereka rilis tahan) dan file game Anda diubah.

Versi utama rilis ini adalah API host: engine.api=1 game bergerak bebas dalam 1.x.x. Sebuah permainan yang memerlukan anggota API host yang ditambahkan dalam versi minor dapat mengatakannya engine.minor=N; seorang yang lebih tua runtime kemudian menolaknya dengan pesan alih-alih gagal nanti.

Rilisan yang ditemukan tidak aman adalah dicabut: versions.json menandainya dengan alasannya, klien menolak untuk menginstal atau memulainya (dan memberi tahu pemain alasannya), dan kemasannya perintah menolaknya setiap kali mereka membaca version.json. Pelepasan yang dicabut selalu diikuti dengan pelepasan yang tetap; sematkan ulang ke sana dan publikasikan.

10. Batasan dan izin

Secara alami, JavaScript game berjalan pada penerjemah tanpa JIT, jauh di bawah kecepatan browser; melihat Performa asli untuk permainan skrip sebelum menulis kode per-frame yang berat.

Runtime menjaga setiap game sesuai anggaran, yang mungkin akan menurunkan anggaran paket engine.limits.* tapi tidak pernah menaikkan, kecuali anggaran gambarnya: engine.limits.image_mib (host API 1.9) menaikkan default 56 MiB hingga 512 MiB, dalam gpu_mib. Waktu skrip diukur secara asli dalam instruksi mesin referensi (bahan bakar); browser tidak punya bahan bakar tapi sama saja "tidak merespons" batas:

Fase Bahan bakar "Tidak merespons" setelah
Evaluasi modul (kode cakupan modul dari entri dan impornya) semuanya 60 detik; itu tidak bisa berhenti 9 detik, bersama dengan onStart
onStart dan pekerjaan yang dijanjikannya 256 ms sepotong (8 × fuel_ms) 9 detik, bersama dengan evaluasi modul
Bingkai: peristiwa, pengatur waktu, onFixedUpdate, onUpdate, onRender, menjanjikan pekerjaan 32 ms per panggilan (fuel_ms) 3 detik untuk seluruh bingkai
onSuspend, onResume 32 ms 3 s

Panggilan yang menghabiskan bahan bakarnya dijeda, bukan diakhiri: panggilan berlanjut pada frame berikutnya saat permainan berlangsung tidak menarik sesuatu yang baru. Setelah suatu fase melewati batasnya, runtime-nya "tidak merespons" layar memungkinkan pemain menunggu atau menghentikan permainan (60 detik saat permainan selesai engine.setBusy, atau selama diminta dengan setBusy(label, { seconds }), hingga 600 detik, dengan engine.minor=14; panggilan berlangsung paling lama tunjangan yang dimintanya, dan yang lebih pendek dihitung pada panggilan berikutnya). Kesalahan untuk nama waktu fase, waktu berjalan dan batasnya, misalnya module evaluation of src/main.ts ran past its time budget (it ran 61234 ms; the limit is 60000 ms); batas evaluasi modul adalah waktu pada jam, yang lainnya dihitung dalam instruksi mesin referensi. Irisan kerja panjang melintasi frame (fuelLeft() mengatakan apa yang tersisa dari bahan bakar panggilan ini), atau umumkan dengan setBusy.

Batasan lainnya: tumpukan skrip 256 MiB dan 1.024 frame panggilan, penyimpanan 64 MiB, kanvas paling banyak 4.096 piksel satu sisi dan 8.388.608 piksel (4096 × 2048), 128 tindakan, BigInt paling banyak 220 bit, paling banyak 512 MiB dan 65.536 file dalam satu paket dan, untuk unggahan, 50 MiB dan 9.998 jalur platform (permainan yang platformnya memungkinkan lebih banyak operan --max-upload-mib Dan --max-upload-paths ke kemasannya perintah, atau --game-id untuk membaca batasnya). Aset yang besar dapat terhindar dari upload sebagai file jarak jauh: engine.remote.files= Dan engine.remote.urls= di dalam starhermit.txt beri nama file yang dilayani oleh host HTTPS Anda sendiri (atau engine.remote.urls=platform: StarHermit melayani mereka, dan cargo starhermit publish mengunggahnya), perintah pengemasan menyematkan masing-masing berdasarkan ukuran dan SHA-256, dan waktu proses mengambil dan memeriksanya (files.fetch di dalam starhermit:engine; lihat deklarasi host API). Adegan besar dapat meningkatkan batasnya starhermit.txt (host API 1.14, jadi engine.minor=14): engine.limits.mesh_mib (default 124, hingga 1.536), engine.limits.meshes (1.008, hingga 4.096), engine.limits.instanced_meshes (1.024, hingga 4.096) dan, secara asli, engine.limits.heap_mib (256, hingga 1.024; browser tidak membatasi heap). Jerat dan gambar bersama-sama tetap berada di dalam engine.limits.gpu_mib (2 GiB), dan batasan yang dinaikkan ke batas atas adalah untuk desktop: mesh penuh anggaran juga memakan waktu sekitar dua kali ukurannya di memori utama, tumpukan penuh sekitar 1,2 kali. engine.budgets() Dan game.limits melaporkan apa yang berlaku, dan RangeError untuk anggaran penuh sebutkan kunci yang memunculkannya. Sebuah bingkai mengirimkan paling banyak 96 MiB mesh dan gambar baru ke GPU; betapa sebuah permainan melewati masa lalu yang menunggu dan melanjutkan ke bingkai berikutnya, masuk pertama, keluar pertama, dan objek digambar setelah jaring dan gambarnya ada tiba (engine.usage().waitingUploads Dan waitingUploadBytes terbaca 0 ketika semuanya terkirim, tuan rumah API 1.15), sehingga level dapat dibangun dalam satu frame. Dengan engine.minor=15 array yang diketik kompak tetap ada kompak pada GPU dan anggaran: posisi sebagai Int16Array, normal sebagai yang dinormalisasi Int8Array, warna sebagai dinormalisasi Uint8Array dan UV sebagai dinormalisasi Uint16Array ambil 16 byte a titik puncak dimana pelampung mengambil 48; tinggalkan indeks jaring berbayang datar; dan geometri dengan no atribut yang digambar dengan setDrawRange(0, N) dan sebuah boundingSphere memberikan kait simpul N simpul untuk tidak ada (rumput, partikel). Pegangan yang dijatuhkan game melepaskan sumber dayanya saat kolektor menemukannya mati, beberapa frame kemudian, dan sebuah kreasi yang anggarannya akan ditolak terlebih dahulu, mengambil kembali yang dijatuhkan; dispose() apa yang Anda hilangkan ketika anggaran terbatas. Untuk musik yang panjang, audio.stream(path) memutar file Ogg Opus atau Ogg Vorbis saat diterjemahkan, tanpa memuatnya sebagai klip (host API 1.14, jadi engine.minor=14; paling banyak 4 aliran sekaligus). Ogg yang terpencil file diputar saat diunduh, setiap bagian 256 KiB diperiksa saat tiba, dan tetap disimpan dalam cache di perangkat untuk diputar nanti, offline juga; mengemas ulang game sehingga indeks jarak jauhnya mencantumkan bagian-bagiannya. Melewati batas di mana suatu operasi bisa gagal (alokasi, panggilan host) menimbulkan a RangeError; kehabisan heap atau kedalaman panggilan mengakhiri permainan di layar kesalahan. Deklarasi API host daftar setiap batas.

Perbedaan asli dan browser

Secara alami, kode Anda berjalan di juru bahasa mesin, di browser di mesin JavaScript browser (V8 di Chrome dan Edge). Keduanya merupakan ECMAScript 2022 yang ketat, termasuk BigInt, dan starhermit check menjalankan game secara asli Dan menghubungkan modul-modulnya saat browser mendapatkannya. Yang masih berbeda:

  • Modul yang saling mengimpor. Di browser, pembacaan impor sebelum modulnya dijalankan adalah undefined; check gagal pada pembacaan seperti itu dalam kode tingkat atas modul (baca di dalam suatu fungsi sebagai gantinya). export * from modul siklus seperti itu gagal check: sebutkan ekspornya. A let diekspor lagi dari modul siklus adalah salinan di browser, sehingga tugas selanjutnya tidak terlihat melaluinya: impor dari modulnya sendiri.
  • Memuat. import() membutuhkan string literal (check gagal pada penentu yang dihitung).
  • Kode dari string. eval gagal memuat secara asli; new Function(...) melempar sebuah EvalError pada keduanya.
  • Skrip klasik. Sebuah berkas starhermit:script dijalankan sebagai skrip klasik (loadClassic, sandbox, authority, worker) tanpa a "use strict" direktif, di luar kelas, mengikuti mode ceroboh seperti di browser dan pada platform: menetapkan nama yang tidak dideklarasikan akan menciptakan global (membacanya masih melempar); this di a fungsi dipanggil tanpa ada is globalThis dan primitif this adalah kotak; delete name jawaban true atau false; suatu fungsi dapat mengulangi nama parameter (bukan panah atau metode); arguments.callee adalah fungsi; tugas yang gagal diabaikan dan ditolak delete adalah false. Masih ketat secara asli: warisan oktal (010, "\07") Dan with gagal memuat, fungsi yang dideklarasikan dalam sebuah blok hanya terlihat di dalamnya blok, dan arguments tidak mengikuti penulisan ke parameter (juga tidak ke sana). Mulailah file tersebut dengan "use strict" untuk berperilaku sama di mana pun.
  • Hanya browser bawaan yang memilikinya: Proxy, WeakRef, FinalizationRegistry, Atomics, structuredClone, pembantu iterator, Array.fromAsync, yang baru Set metode, pekerja global (self, crypto, atob, URL, WebAssembly, …) dan beberapa di antaranya Intl (ListFormat, Segmenter, DisplayNames, Locale). check memperingatkan setiap penggunaan dengan file dan barisnya; typeof tes baik-baik saja.
  • Ekspresi reguler. Itu v bendera dan warisannya RegExp.$1 statika hanya untuk browser.
  • Tanggal. Waktu setempat aslinya adalah UTC (getTimezoneOffset() adalah 0); browser menggunakan waktu pemain zona. Format waktu jam dinding dengan timeZone: "UTC" untuk menunjukkan hal yang sama pada keduanya.
  • Batasan. Secara asli, sebuah string menampung paling banyak 228 − 16 unit kode, larik 226 elemen dan BigInt 220 bit (lebih banyak di browser); tumpukan overflow secara asli mengakhiri permainan daripada melempar tangkapan RangeError. Math.random urutannya berbeda.
  • Awal audio. Di browser, audio menunggu penekanan pertama pemutar: sampai saat itu context.state adalah "suspended" Dan currentTime diam, maka itu dia "running" Dan statechange kebakaran. Secara alami memang demikian "running" dari awal.
  • Default peramban. Saat permainan berjalan, halamannya menyimpan menu klik kanan browser, berupa teks seleksi, salin dan tempel, letakkan file dan pintasan seperti Ctrl+S, Ctrl+F, zoom dan menu Alt bar dari game, dan kunci yang diikat game Anda mencapainya dengan Ctrl, Alt, atau Cmd juga. F11, F12, muat ulang dan tombol tab browser masih berfungsi, dan kolom teks tetap ditempel.
  • Penutupan. onQuit berjalan sekali, setelah frame sedang berlangsung (dan setelahnya onSuspend jika jendela atau tab disembunyikan terlebih dahulu). Untuk apa tulisannya storage Dan settings disimpan, dan itu saves.save, salinan pengaturan akun dan panggilan platformnya akan keluar saat game ditutup (jawaban mereka tidak sampai kepada siapa pun). Biasanya ia memiliki satu detik, dan unggahannya mencapai tiga detik lagi; di browser halaman akan hilang (tab tertutup, muat ulang, tautan diikuti) menunggu 0,2 detik, untuk game dengan itu storage kemampuan atau pemain yang masuk, dan mengirimkan paling banyak 16 permintaan dengan 64 KiB badan secara keseluruhan: simpanan yang lebih besar diunggah di sesi berikutnya. Safari menghentikan permainan sebelum halaman mendengar bahwa permainan itu hilang, jadi begitulah onQuit tidak berjalan pada tab tertutup atau tautan yang diikuti: simpan apa yang terakhir disimpan saat berubah, atau di onSuspend.
