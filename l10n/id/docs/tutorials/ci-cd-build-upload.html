Upload Build dari CI/CD dengan Kunci Publik yang terdaftar di OAuth

Tutorial ini memberikan kredensial StarHermitnya sendiri pada pipeline penerapan tanpa menyimpan Google Anda atau token GitHub OAuth di CI. Penyiapan satu kali bersifat interaktif:

  1. Masuk melalui OAuth dan terima persyaratan StarHermit saat ini.
  2. Tambahkan kunci publik khusus ke akun StarHermit Anda.
  3. Letakkan hanya bagian pribadi kunci itu di penyimpanan rahasia CI.

Setiap proses pipeline kemudian menandatangani tantangan StarHermit yang berumur pendek, dan biasanya menerima waktu 15 menit token akses, dan unggah versi baru. Kunci saluran bertindak sebagai akun Anda dan hanya dapat diperbarui game yang dimiliki akun.

Mengapa menggunakan kunci penerapan terpisah?

Jangan simpan akses OAuth atau segarkan token di CI. Kunci publik StarHermit adalah mesin yang lebih baik kredensial karena dapat diberi label, diaudit, dan dicabut secara independen. Sesi diautentikasi dengan kunci itu tidak dapat menambahkan kunci atau mencabut kunci lainnya; operasi tersebut memerlukan autentikasi OAuth sesi. Ia dapat mencabut dirinya sendiri melalui /api/v1/me/public-keys/current. Jika rahasia CI bocor, masuk dengan Google atau GitHub dan cabut kunci penerapan. Pencabutan juga mengakhiri sesi penyegaran yang dibuat oleh kunci tersebut dan membuat token akses yang ada gagal pada permintaan API berikutnya.

Gunakan satu kunci per repositori/lingkungan, misalnya orbit-league-production, daripada berbagi satu kunci pribadi di antara setiap alur kerja.

Prasyarat

  • Akun StarHermit masuk melalui Google atau GitHub OAuth.
  • Game yang sudah ada yang dimiliki oleh akun itu. Simpan itu id sebagai GAME_ID; pembaruan titik akhir bundel a permainan tetapi tidak membuatnya.
  • Build klien yang dapat didistribusikan dan/atau kompatibel dengan Docker docker save gambar. Melihat Permainan GitHub untuk tata letak arsip.
  • Python 3 untuk perintah pengaturan dan contoh alur kerja; curl Dan jq untuk contoh pendaftaran.

Saluran pipa dapat berhasil masuk dan tetap menerima 403 terms_acceptance_required kapan itu mengunggah atau membuka soket unggah. Mintalah pemilik akun meninjau dan menerima persyaratan saat ini secara interaktif, lalu jalankan kembali pekerjaan tersebut. Hal ini dapat terulang kembali ketika ketentuan berubah; tidak secara otomatis menerima ketentuan dari CI.

Pengaturan satu kali

1. Hasilkan kunci penerapan secara lokal

Contohnya menggunakan Ed25519. Jalankan ini di stasiun kerja tepercaya, bukan di pekerjaan CI:

python -m pip install cryptography
python - <<'PY'
import base64
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
from cryptography.hazmat.primitives.serialization import Encoding, NoEncryption, PrivateFormat, PublicFormat

key = Ed25519PrivateKey.generate()
private = key.private_bytes(Encoding.Raw, PrivateFormat.Raw, NoEncryption())
public = key.public_key().public_bytes(Encoding.Raw, PublicFormat.Raw)
print("STARHERMIT_PRIVATE_KEY=" + base64.b64encode(private).decode())
print("STARHERMIT_PUBLIC_KEY=" + base64.b64encode(public).decode())
PY

Nilai pribadinya adalah benih 32-byte dan ditampilkan satu kali di terminal lokal tepercaya ini. Jangan pernah berkomitmen itu, cetak di log CI, masukkan ke dalam artefak, atau kirimkan ke StarHermit. Jaga nilai publik langkah selanjutnya dan untuk variabel alur kerja.

2. Masuk dengan OAuth dan tambahkan kunci publik

Buka salah satu URL berikut di browser:

https://api.starhermit.com/api/v1/auth/oauth/github/authorize
https://api.starhermit.com/api/v1/auth/oauth/google/authorize

Setelah panggilan balik, segera gunakan token akses terautentikasi OAuth yang dikembalikan. Taruh di lokal variabel lingkungan daripada dalam riwayat shell:

read -rsp 'OAuth access token: ' OAUTH_ACCESS_TOKEN; echo
read -rp  'Public key: ' STARHERMIT_PUBLIC_KEY

curl -sS -X POST https://api.starhermit.com/api/v1/me/public-keys \
  -H "Authorization: Bearer $OAUTH_ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  --data "$(jq -n \
    --arg keyData "$STARHERMIT_PUBLIC_KEY" \
    --arg label 'orbit-league-production' \
    '{keyType:"Ed25519", keyData:$keyData, label:$label}')"

Panggilan itu kembali 201 dan catatan kuncinya. A 403 berarti token ini tidak berasal dari OAuth sesi (verifikasi email, kunci publik, atau token peluncuran game saja tidak cukup). A 409 berarti kunci sudah aktif atau akun telah mencapai batas kunci aktifnya.

Periksa hasilnya dengan GET /api/v1/me/public-keys. Daftar tersebut mencakup label, sidik jari, penggunaan terakhir kali, dan kunci yang dicabut, jadi ini juga merupakan jejak audit kredensial.

3. Konfigurasikan repositori

Di GitHub, tambahkan:

  • Rahasia tindakan STARHERMIT_PRIVATE_KEY: benih pribadi Base64.
  • Variabel tindakan STARHERMIT_PUBLIC_KEY: kunci publik mentah Base64.
  • Variabel tindakan STARHERMIT_GAME_ID: ID game yang dimiliki.

Lindungi produksi dengan Lingkungan GitHub jika diperlukan persetujuan. Nilai yang setara bisa saja disimpan dalam variabel yang dilindungi GitLab, Azure Key Vault, atau penyimpanan rahasia CI lainnya.

Tambahkan pembantu autentikasi/unggah

Lakukan hal berikut sebagai ci/starhermit_upload.py. Ini merekonstruksi tantangan persis JSON itu StarHermit menandatangani secara internal, mengautentikasi dengan Ed25519, dan memilih HTTP untuk arsip kecil atau unggah WebSocket untuk arsip lebih dari 90 MB. WebSocket menghindari badan HTTP CDN yang berukuran sekitar 100 MB batas.

#!/usr/bin/env python3
import argparse, asyncio, base64, json, os
from pathlib import Path
from urllib.parse import quote, urlparse, urlunparse

import requests
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey


def authenticate(api, public_key, private_key):
    challenge = requests.post(
        f"{api}/api/v1/auth/public-key/challenge",
        json={"keyType": "Ed25519", "keyData": public_key}, timeout=30)
    challenge.raise_for_status()
    body = challenge.json()
    p = body["payload"]

    # Public JSON is camelCase; the server verifies its ChallengePayload serialization, whose
    # property names and order are the PascalCase sequence below.
    payload = {
        "ChallengeId": p["challengeId"],
        "Fingerprint": p["fingerprint"],
        "Issuer": p["issuer"],
        "Audience": p["audience"],
        "Expiry": p["expiry"],
        "Nonce": p["nonce"],
        "ClientTimestamp": p["clientTimestamp"],
    }
    # System.Text.Json escapes '+' in string fields (the Base64 nonce) as \u002B.
    # DateTimeOffset fields keep literal '+' in their offsets: do not replace globally.
    fields = []
    for name, value in payload.items():
        encoded = json.dumps(value)
        if name == "Nonce":
            encoded = encoded.replace("+", r"\u002B")
        fields.append(json.dumps(name) + ":" + encoded)
    signed_payload = ("{" + ",".join(fields) + "}").encode("utf-8")

    seed = base64.b64decode(private_key, validate=True)
    signature = Ed25519PrivateKey.from_private_bytes(seed).sign(signed_payload)
    complete = requests.post(
        f"{api}/api/v1/auth/public-key/complete",
        json={"challengeId": body["challengeId"],
              "signature": base64.b64encode(signature).decode(),
              "keyType": "Ed25519", "keyData": public_key}, timeout=30)
    complete.raise_for_status()
    return complete.json()["accessToken"]


def upload_http(api, game_id, token, archive, mode):
    with archive.open("rb") as stream:
        response = requests.post(
            f"{api}/api/v1/me/github-games/{game_id}/bundle",
            params={"mode": mode} if mode != "replace" else None,
            headers={"Authorization": f"Bearer {token}",
                     "Content-Type": "application/gzip"},
            data=stream, timeout=1800)
    response.raise_for_status()
    print(json.dumps(response.json()))


async def upload_websocket(api, game_id, token, archive, mode):
    import websockets
    parsed = urlparse(api)
    query = f"gameId={quote(game_id)}&access_token={quote(token)}"
    if mode != "replace":
        query += f"&mode={quote(mode)}"
    uri = urlunparse(("wss" if parsed.scheme == "https" else "ws", parsed.netloc,
                      "/ws/v1/game-upload", "", query, ""))
    async with websockets.connect(uri, max_size=None, ping_interval=20) as ws:
        ready = json.loads(await ws.recv())
        if ready.get("type") != "ready":
            raise RuntimeError(ready)
        with archive.open("rb") as stream:
            while chunk := stream.read(512 * 1024):
                await ws.send(chunk)
        await ws.send(json.dumps({"type": "complete"}))
        while True:
            message = json.loads(await ws.recv())
            if message.get("type") == "result":
                print(json.dumps(message))
                return
            if message.get("type") == "error":
                raise RuntimeError(message)


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("archive", type=Path)
    parser.add_argument("--api", default="https://api.starhermit.com")
    parser.add_argument("--mode", choices=("replace", "merge"), default="replace",
                        help="replace the live client files (default) or patch them")
    args = parser.parse_args()
    game_id = os.environ["STARHERMIT_GAME_ID"]
    token = authenticate(args.api.rstrip("/"), os.environ["STARHERMIT_PUBLIC_KEY"],
                         os.environ["STARHERMIT_PRIVATE_KEY"])
    if args.archive.stat().st_size < 90 * 1024 * 1024:
        upload_http(args.api.rstrip("/"), game_id, token, args.archive, args.mode)
    else:
        asyncio.run(upload_websocket(args.api.rstrip("/"), game_id, token, args.archive, args.mode))


if __name__ == "__main__":
    main()

Perlakukan pintu keluar yang bukan nol sebagai penerapan yang gagal. Jangan mencatat token akses atau melengkapi isi permintaan. Token akses berlaku selama 15 menit, jadi autentikasi segera sebelum mengunggah; WebSocket memeriksanya selama jabat tangan dan mungkin selesai setelah token kedaluwarsa.

Contoh Tindakan GitHub

Contoh ini menerbitkan konten dist/ pada setiap dorongan ke main:

{% mentah %}

name: Deploy to StarHermit
on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'

      - name: Build
        run: |
          npm ci
          npm run build

      - name: Package StarHermit bundle
        run: |
          mkdir -p bundle/client
          cp -R dist/. bundle/client/
          cp starhermit.txt bundle/starhermit.txt
          tar -C bundle -czf game-bundle.tar.gz .

      - name: Install uploader dependencies
        run: python -m pip install 'cryptography>=42,<45' 'requests>=2.31,<3' 'websockets>=12,<13'

      - name: Upload build
        env:
          STARHERMIT_PRIVATE_KEY: ${{ secrets.STARHERMIT_PRIVATE_KEY }}
          STARHERMIT_PUBLIC_KEY: ${{ vars.STARHERMIT_PUBLIC_KEY }}
          STARHERMIT_GAME_ID: ${{ vars.STARHERMIT_GAME_ID }}
        run: python ci/starhermit_upload.py game-bundle.tar.gz

{% menggambar %}

Untuk server khusus, tambahkan docker build, simpan gambar ke bundle/server/image.tar, dan pertahankan starhermit.txt di akar bundel:

docker build -t my-game-server:${GITHUB_SHA} -f Dockerfile.server .
mkdir -p bundle/server
docker save my-game-server:${GITHUB_SHA} -o bundle/server/image.tar
tar -C bundle -czf game-bundle.tar.gz .

Pengunggahan bundel yang berhasil berarti StarHermit menerima dan menerbitkan bundel secara atom; memang demikian bukan berarti kontainer baru telah lolos pemeriksaan kesehatan. Pemilihan GET /api/v1/me/github-games/{id}/deployment dengan token yang baru diautentikasi dan menjalankan a tes asap sebelum mempromosikan rilis.

Rotasi dan respons insiden

  1. Masuk melalui OAuth dan terima persyaratan StarHermit saat ini.
  2. Tambahkan kunci yang baru dibuat dan diberi label jelas.
  3. Ganti rahasia dan variabel CI, lalu jalankan penerapan.
  4. Cabut kunci lama dengan DELETE /api/v1/me/public-keys/{keyId}.

Untuk dugaan kompromi luas, DELETE /api/v1/me/public-keys/all mencabut setiap kunci aktif. Kedua operasi penghapusan memerlukan sesi yang diautentikasi OAuth. Sebuah pipeline diautentikasi dengan miliknya sendiri kunci tidak dapat mencabut kunci lain, menambahkan pengganti, mengubah email akun, atau menghapus identitas OAuth. Ia dapat mencabut dirinya sendiri dengan DELETE /api/v1/me/public-keys/current; buang token yang disimpannya setelahnya.
