Tutorial: membangun pembalap kart multipemain

Tutorial ini membangun lapisan multipemain dari pembalap kart arcade — hingga delapan kart, pribadi lobi dengan teman, bergabung cepat dengan orang asing, driver CPU mengisi slot jaringan yang kosong, hitung mundur, putaran, urutan penyelesaian, dan pencapaian — di StarHermit API. Ini mencakup kontrak netcode dan platform memanggil; mesin, track art, dan model penanganan Anda adalah milik Anda sendiri.

Segala sesuatu yang khusus untuk game di sini — itu grand-prix antrian, tata letak bingkai biner, tombol item, konstanta fisika — adalah nilai contoh. Hanya titik akhir, selubung bingkai, dan batasnya saja perilaku platform, dan masing-masing tertaut ke halaman referensinya.

1. Pilih arsitektur

Pembalap adalah bentuk permainan yang paling sulit untuk anggaran server tick: kart bergerak cepat, bertabrakan, dan pemain merasakan steering lag 50 ms. StarHermit memberi Anda dua cara untuk menjalankannya, keduanya dimulai dari a ruang waktu nyata:

A. Dirutekan host B. Skrip otoritatif server
Siapa yang melakukan simulasi Klien host ruangan, apa pun yang disukainya (60 Hz+) Milikmu server= naskah, paling banyak 30Hz
Mengangkut Bingkai biner aktif ws/v1/realtime JSON cmd/game bingkai aktif ws/v1/games
Curang Tuan rumah dapat dipercaya Klien tidak memiliki otoritas
Elo, pencapaian naskah Tidak (host memposting hasil yang dijepit) Ya - eloUpdates, achievements, memutar ulang
Terbaik untuk Balapan santai dengan teman, fisika fidelitas penuh Balapan berperingkat dengan fisika arcade sederhana

Mulailah dengan A kecuali jika Anda membutuhkan permainan peringkat; bagian 7 menunjukkan untuk apa perubahan itu B. A server kontainer juga bisa menjalankan delapan kart terikat ruangan ras dan simulasikan pada 60 Hz secara resmi. Pencocokan API Game langsungnya saat ini menggunakan 1v1 implisit antrian, jadi gunakan ruang waktu nyata untuk jaringan yang lebih besar. Platform tidak melangkahi putaran penampung.

2. Manifes

Publikasikan folder build yang dapat didistribusikan dengan ini starhermit.txt pada akarnya (lihat manifes). Itu control.* garis memberi pemain UI yang mengikat kembali dan milik Anda klien a mengontrol API untuk membaca binding dari:

name=Turbo Hermits
launch=index.html
cover=art/cover.png
control.accelerate=KeyW+ArrowUp | Accelerate
control.brake=KeyS+ArrowDown | Brake / reverse
control.left=KeyA+ArrowLeft | Steer left
control.right=KeyD+ArrowRight | Steer right
control.drift=ShiftLeft+ShiftRight | Drift
control.item=Space | Use item

Jalur A punya TIDAK server= garis. Jika game mengirimkan skrip, memulai ruangan akan membuat sesi terikat dan hanya naskah yang dapat mengakhiri pertandingan — milik tuan rumah POST .../result berhenti menjadi cara balapan berakhir (bagian 7).

3. Masuk dan baca dasar-dasarnya

Game yang dihosting platform dibuka dengan #game_token=<jwt> di URL — baca sekali, hapus dengan history.replaceState, dan segarkan sebelum masa berlakunya habis 60 menit (detailnya ada di panduan catur Dan autentik). Siput Anda adalah tokennya game_scope klaim (atau location.hostnameitu label pertama); jangan pernah melakukan hard-code.

Saat dimuat, ambil apa yang dibutuhkan menu:

GET /api/v1/games/{slug}/controls     # effective key bindings (manifest defaults + overrides)
GET /api/v1/games/{slug}/settings     # camera, volume, last chosen kart — your own keys
GET /api/v1/realtime/rooms/mine       # 200 → the player is still in a race; rejoin it

Simpan pilihan menu dengan PATCH /api/v1/games/{slug}/settings ({"settings":{"kart":"hermit-crab"}}). Pengaturan mengikuti pemain melintasi mesin dan tidak memerlukan deklarasi.

4. Lobi

Sebuah grand prix gratis untuk semua, jadi ruangan tersebut memiliki satu tim yang terdiri dari delapan kursi. Lintasan, jumlah putaran dan mesin kelas menjadi buram metadata:

POST /api/v1/realtime/rooms
Authorization: Bearer <launch token>

{ "teamCount": 1, "seatsPerTeam": 8, "backfillAfterSeconds": 45,
  "aiPlayers": 0, "name": "Friday cup", "isVisible": true,
  "metadata": { "track": "coral-loop", "laps": 3, "cc": 150 } }

Dengan token peluncuran, permainan ruangan berasal dari token, jadi gameSlug dapat dihilangkan. Pencipta adalah tuan rumah di kursi (0, 0). Dari sini lobi adalah aliran ruangan biasa:

  • Teman-teman — POST /rooms/{id}/invites dengan {"toUserId": ...}. Platform ini memberi tahu mereka; menerima kursi mereka. Tunjukkan enam karakter joinCode jadi teman-teman juga bisa mengetiknya POST /rooms/join-by-code.
  • Orang asing — tuan rumah menelepon POST /rooms/{id}/open. Pemain tanpa panggilan kamar POST /rooms/quick-join dengan {"seats": 1} dan, seterusnya 404, buat dan buka sendiri.
  • Lacak suara / tuan rumah berubah pikiran — PATCH /rooms/{id} dengan yang baru metadata dan ruangan itu revision sebagai expectedRevision.
  • Solo melawan CPU — buat dengan "aiPlayers": 7, Kemudian POST /rooms/{id}/start.

Ruang terbuka dimulai dengan sendirinya ketika kedelapan kursi terisi atau backfillAfterSeconds lolos; tuan rumah juga bisa POST /rooms/{id}/start. Setiap kursi yang masih kosong menjadi peserta AI — itu milik Anda driver CPU.

5. Soket balapan (diarahkan ke host)

Menghubungkan

Setiap peserta membuka soket realtime dengan tiket sekali pakai:

const { ticket } = await api.post("/api/v1/realtime/connection-tickets"); // { ticket, expiresIn }
const ws = new WebSocket(
  `wss://api.starhermit.com/ws/v1/realtime?roomId=${roomId}&ticket=${encodeURIComponent(ticket)}`);
ws.binaryType = "arraybuffer";

Bingkai teks adalah dorongan JSON dan bingkai kontrol; frame biner adalah gameplay. Itu roster dorongan adalah grid Anda: setelah start dibekukan, termasuk kursi AI. Dengan satu tim, slot grid kart adalah miliknya milik peserta slot.

ws.onmessage = (e) => {
  if (typeof e.data === "string") return onControl(JSON.parse(e.data)); // roster, presence, event, ready, chat, result
  const bytes = new Uint8Array(e.data);
  const sender = guidFromDotNet(bytes.subarray(0, 16)); // server-stamped, trustworthy
  onGameplay(sender, new DataView(e.data, 16));          // your payload starts at byte 16
};

// The server prefixes the sender's participant id in .NET GUID byte order:
// the first three groups are little-endian.
function guidFromDotNet(b) {
  const h = (i) => b[i].toString(16).padStart(2, "0");
  return `${h(3)}${h(2)}${h(1)}${h(0)}-${h(5)}${h(4)}-${h(7)}${h(6)}-` +
         `${h(8)}${h(9)}-${h(10)}${h(11)}${h(12)}${h(13)}${h(14)}${h(15)}`;
}

Jangan pernah memasukkan id pemain ke dalam payload Anda sendiri dan percayalah — awalan 16-byte adalah satu-satunya identitas yang dijamin oleh server.

Perutean dan anggaran

Platform ini menerapkan bentuk permainan yang diarahkan oleh host:

  • A milik tamu jangkauan frame biner hanya tuan rumah — itulah saluran masukan.
  • Itu milik tuan rumah jangkauan frame biner setiap tamu — itulah saluran snapshot.
  • Setiap frame paling banyak 8 KB; setiap koneksi dapat mengirim 30 pesan/detik (2× meledak untuk satu kedua). Menutup soket dengan PolicyViolation.

Jadi host melakukan simulasi pada kecepatan berapa pun yang dirasa tepat (umumnya 60 Hz) tetapi mengirimkan snapshot di 20 Hz, dan tamu mengirimkan masukan pada 20 Hz. Itu menyisakan ruang kepala untuk bingkai kontrol sesekali.

Tata letak bingkai (contoh)

Input, tamu → host, 7 byte:

Mengimbangi Jenis Bidang
0 u8 1 = masukan
1 u16 seq — bertambah setiap pengiriman
3 i8 mengarahkan, −127…127
4 u8 throttle, 0…255
5 u8 bit: 0 rem, 1 drift
6 u8 itemPresses — penghitung, bukan bendera

itemPresses adalah hitungan penekanan tombol item. Pada 20 Hz, pers yang lebih pendek dari 50 ms akan melakukannya jika tidak, jatuh di antara sampel; dengan penghitung, tuan rumah menembakkan satu item per kenaikan, namun mesin press mendarat.

Snapshot, host → tamu, 4 + 22 byte per kart (176 byte untuk grid penuh):

Mengimbangi Jenis Bidang
0 u8 2 = cuplikan
1 u16 kutu tuan rumah
3 u8 jumlah kart
per kart u8, f32 ×4, u8, u16, u8, u8 slot, x, z, pos, kecepatan, putaran, pos pemeriksaan, item, bendera

Para tamu membuat kart lainnya ~100 ms di masa lalu, menginterpolasi antara dua snapshot itu tandai waktu itu, dan prediksi kart mereka sendiri secara lokal dari masukan mereka, menuju ke tuan rumah posisi ketika mereka tidak setuju. Sertakan masukan terakhir seq tuan rumah menerapkan per kart masuk flags atau sebuah bidang tambahan jika Anda ingin rekonsiliasi yang tepat.

Hitung mundur, acara balapan, selesai

Bingkai kontrol adalah JSON, maksimal 4 KB, dan stempel server from dengan id peserta pengirim:

  • Para tamu mengirim {"type":"ready"} setelah trek dimuat.
  • Tuan rumah menunggu setiap manusia yang terhubung siap (atau batas waktu), lalu mengirimkan {"type":"event","kind":"countdown","goInMs":3000}. Para tamu memulai hitungan mundur lokal mereka tanda terima — tidak diperlukan sinkronisasi jam pada presisi ini.
  • Ketukan balapan lainnya juga demikian event bingkai: {"kind":"lap","slot":3,"lap":2}, {"kind":"finished","slot":3,"place":1,"timeMs":94210}.
  • chat tersedia untuk semua orang, namun tamu dibatasi hingga 10 frame kontrol per menit — cukup banyak ready dan beberapa "gg"s, bukan untuk gameplay.

Ketika manusia terakhir melewati garis (atau penghitung waktu setelah pemenang habis), tuan rumah menyerahkan Hasilnya, yang menutup ruangan dan mendorong {"type":"result"} kepada semua orang:

POST /api/v1/realtime/rooms/{id}/result

{ "teamScores": [0],
  "metadata": { "track": "coral-loop",
                "order": [ { "slot": 3, "timeMs": 94210 }, { "slot": 0, "timeMs": 95002 } ],
                "bestLapMs": 30112 } }

teamScores membutuhkan tepat satu entri per tim (dijepit 0–50), yang tidak berguna dalam a gratis untuk semua; urutan akhir tetap ada metadata. Perlombaan tim adalah ruangan yang sama dengan teamCount: 2 dan poin masing-masing tim teamScores.

Driver CPU, lulusan dan perubahan host

  • Kursi AI dapat Anda kendalikan. Platform memesan tempat duduk dan memberi nama pengemudi; milik tuan rumah simulasi mengarahkannya (garis balap melalui pos pemeriksaan, dengan beberapa karet gelang).
  • Seorang tamu yang meninggalkan pertengahan balapan (POST /rooms/{id}/leave) menyimpan kart mereka di grid: daftar pemain push menunjukkan peserta yang sama id Sekarang isAi: true, dan CPU host mengambil alih kart tersebut.
  • Seorang tamu yang turun masih di dalam kamar; pertahankan kart mereka tetap meluncur dan biarkan mereka terhubung kembali — soket terbaru menggantikan soket lama.
  • Jika tuan rumah pergi, peran tuan rumah diberikan kepada manusia yang tersisa paling lama bergabung dan roster push menunjukkan yang baru isHost. Setiap tamu sudah memegang snapshot lengkap terbaru, jadi baru host melanjutkan simulasi darinya dan mulai mengirimkan snapshot; masukan tamu sekarang diarahkan ke mereka. Migrasi host adalah tugas kode Anda — platform hanya memindahkan perannya.
  • Kalau hostnya putus saja, ruangan ditutup setelah 60 detik tanpa soket host.

6. Sekitar perlombaan

  • Suara dan obrolan. Setiap tamu sudah bisa chat pada soket waktu nyata; untuk suara, lihat Suara.
  • Pertandingan ulang. Ruangan ditutup setelah hasilnya. Mintalah tuan rumah membuat ruangan baru dan mengundang manusia dari daftar sebelumnya, atau kirim semua orang kembali untuk bergabung dengan cepat.
  • Papan peringkat waktu putaran. Papan peringkat platform game adalah papan elo-nya, yang hanya ditulis oleh server waktu proses. Papan peringkat yang ditentukan penerbit menerima POST /api/v1/leaderboards/{id}/submit, tapi itu skor diklaim oleh klien — baik untuk uji waktu persahabatan, bukan untuk apa pun yang berhadiah.

7. Varian B: balap otoritatif server

Untuk permainan berperingkat, pindahkan simulasi ke dalam skrip. Lobi tidak berubah; tambahkan skrip dan pengaturan pencocokan ke manifes:

server=server.js
matchmaking.max_wait_seconds=20
matchmaking.ai_players=7

Sekarang ada dua hal yang menciptakan perlombaan: memulai sebuah ruangan menciptakan sesi terikat ruangan untuk manusianya, dan penjaruman (POST /api/v1/games/{slug}/matchmaking?queue=grand-prix) menciptakan satu ketika delapan pemain ditemukan — atau, dengan pengaturan di atas, setelah 20 detik dengan CPU hingga tujuh kosong kursi. Lobi teman bisa mengantri bersama POST /realtime/rooms/{id}/matchmake.

Apa pun pilihannya, klien mengambil alih sessionId (kamar itu gameSessionId, atau tiket yang cocok) dan mainkan ws/v1/games?sessionId=…. Soket waktu nyata, jika ada, disimpan hanya untuk daftar nama.

Naskahnya

Seluruh simulasi berjalan onTick pada langit-langit 30 Hz. Setiap doa adalah kotak pasir baru yang mendapat sessionState masuk dan mengembalikannya, jadi pertahankan statusnya tetap kecil — statusnya diserialkan setiap kali centang.

const TRACK = { laps: 3, radius: 14,
  checkpoints: [[0, 0], [120, 0], [160, 60], [120, 120], [0, 120], [-40, 60]] };

globalThis.game = {
  tickRateHz: 30,
  replays: true,
  queues: [{ key: "grand-prix", teams: 8, teamSize: 1 }],
  achievements: [
    { key: "chequered-flag", name: "Chequered Flag", description: "Win a race.", points: 10 }
  ],

  createSession(ctx) {
    const karts = racers(ctx).map((r, i) => ({
      id: r.id, name: r.name, ai: r.ai, x: -8 * (i % 2), z: -6 * i, heading: 0, speed: 0,
      cp: 1, lap: 0, boost: 0, boosts: 1, input: {}, ack: 0, finishedAt: null
    }));
    return { ok: true, sessionState: { t: ctx.now, goAt: ctx.now + 4000, karts, order: [] } };
  },

  onPlayerMessage(ctx) {                       // durable commands: discrete actions
    const s = copy(ctx.sessionState);
    const k = s.karts.find((k) => k.id === ctx.message.from);
    if (ctx.message.data?.type === "use-item" && k && k.boosts > 0 && ctx.now >= s.goAt) {
      k.boosts--; k.boost = 1.2;
    }
    return { ok: true, sessionState: s };
  },

  onTick(ctx) {
    const s = copy(ctx.sessionState);
    const dt = Math.min(Math.max((ctx.now - s.t) / 1000, 0), 0.1);
    s.t = ctx.now;
    for (const i of ctx.inputs || []) {        // latest realtime input per player since last tick
      const k = s.karts.find((k) => k.id === i.from);
      if (k) { k.input = i.data; k.ack = Math.max(k.ack, Math.floor(+i.data.seq) || 0); }
    }
    if (ctx.now >= s.goAt) {
      for (const k of s.karts) {
        if (k.finishedAt) continue;
        move(k, k.ai ? aiInput(k) : k.input, dt);   // pure motion — shared with the client
        progress(k, s, ctx);                        // checkpoints, laps, finish — server only
      }
    }
    const snap = s.karts.map((k) =>
      [k.id, r2(k.x), r2(k.z), r3(k.heading), r2(k.speed), r2(k.boost), k.lap, k.cp, k.ack]);
    const out = { ok: true, sessionState: s,
      broadcast: [{ to: "all", data: { type: "snap", t: s.t, goAt: s.goAt, karts: snap } }] };
    if (raceOver(s, ctx)) Object.assign(out, finish(s, ctx));
    return out;
  }
};

Pembantunya adalah kode permainan biasa. Bagian-bagian yang menjadi perhatian platform:

  • racers(ctx) membaca grid dari awal sesi mana pun: ctx.room.roster untuk a ruangan (kursi AI punya userId: null, jadi beri mereka id suka ai-0-5), ctx.matchmaking.seats untuk a balapan matchmade (melewati kursi dengan id: null), kalau tidak ctx.players.
  • move(k, input, dt) harus jepit setiap nilai masukan — steer ke −1…1, throttle hingga 0…1 — karena ctx.inputs[].data adalah apa pun yang dikirim klien. Hanya from dipercaya. Jaga agar tetap murni— tidak ctx, tidak ada status sesi — sehingga klien dapat menjalankannya juga (lihat prediksi sisi klien).
  • Keacakan dan waktu berasal dari ctx.random Dan ctx.now; tidak ada Date atau Math.random.
  • finish(s, ctx) kembali result (yang mengakhiri sesi dan, untuk sebuah ruangan, menutupnya), achievements untuk pemenang jika manusia, dan eloUpdates untuk pembalap manusia — misalnya berpasangan elo melintasi urutan akhir, membaca dari dan menulis kembali ke ctx.playerStates. Kursi AI tidak bisa menerima status pemain, peringkat, atau pencapaian.
  • raceOver juga harus mengakhiri perlombaan yang tidak dapat diselesaikan oleh siapa pun - setiap manusia mengikuti perlombaan tersebut ctx.presence (ruangan), atau batas waktu yang sulit.
  • Pemutaran ulang simpan saja terakhir sessionState. Pertahankan tabel waktu putaran dan penyelesaian akhir yang ringkas pesan di dalamnya, bukan log posisi per centang.

Klien

Kirim kemudi sebagai masukan waktu nyata setiap centang dan tindakan terpisah sebagai perintah tahan lama:

// ~30 Hz: latest-wins, batched into the next onTick
send({ type: "cmd", data: { type: "input", realtime: true, seq: ++seq,
                            steer, throttle, brake, drift } });

// on key press: a durable command, runs onPlayerMessage immediately
send({ type: "cmd", data: { type: "use-item" } });

Barang harus melalui perintah yang tahan lama. Input waktu nyata adalah kemenangan terbaru antara tick, dan platform hanya mempertahankan bidang sekali pakai pass, tackle Dan shoot ketika sampel yang lebih baru menggantikan yang lama — tombol lain apa pun dalam input waktu nyata dapat ditimpa sebelum dicentang melihatnya.

achievement bingkai tiba pada soket yang sama; membaca GET /api/v1/games/{slug}/achievements pada memuat apa pun yang diberikan sebelum dibuka.

Prediksi sisi klien

Hanya menampilkan apa yang dikirimkan server membuat kart terasa seperti dikemudikan melalui lumpur. Kemudi perubahan harus mencapai server, tunggu centang berikutnya (hingga 33 ms pada 30 Hz), dan kembali lagi dalam a snap — pada ping 80 ms yang berarti lebih dari 100 ms sebelum kart berbelok. Prediksi menyembunyikan itu: klien bergerak kartnya sendiri segera dan perlakukan masing-masing snap sebagai koreksi, bukan seperti gambar.

Bagikan kode gerak

Pisahkan simulasi seperti yang dilakukan skrip di atas: murni move(k, input, dt) untuk penanganan, dan khusus server progress untuk pos pemeriksaan, putaran dan finishing. Paparkan kode gerak dari server.js sebagai global kedua - pola yang digunakan catur globalThis.chessRules — dan memuat file yang sama peramban:

// server.js — shared by the platform's sandbox and the browser
function move(k, input, dt) { /* clamp input, integrate speed, heading, x, z, boost */ }
globalThis.kartPhysics = { move, TRACK };
globalThis.game = { /* ... as above ... */ };

<script src="server.js"></script>  <!-- defines kartPhysics; the client never calls game.* -->

Klien memperkirakan gerak saja. Lap, posisi, item, dan urutan finish tetap menjadi milik server panggilan. Jangan berharap hasil yang sedikit sama: kotak pasir dan browser mungkin tidak setuju pada bagian terakhir Math.sin/Math.cos, dan posisi di snap berbentuk bulat. Rekonsiliasi menyerap penyimpangan tersebut.

Ikuti ritme server

Server tidak menjalankan satu langkah per input. Setiap centang itu menerapkan terbaru masukan yang dipegangnya kart itu, terus menggunakannya hingga kart yang lebih baru tiba, dan terintegrasi secara real time sejak itu centang sebelumnya. Jadi cerminkan bentuk itu daripada melangkah pada kecepatan bingkai tampilan:

const pending = [];                              // inputs the server hasn't acknowledged yet
let seq = 0, predicted, previous;               // { x, z, heading, speed, boost }, seeded from the first snap
let error = { x: 0, z: 0, heading: 0 };          // visual offset, decays in render()

setInterval(() => {                              // 30 Hz, the script's tickRateHz
  if (!predicted || serverNow() < goAt) return;  // the server ignores movement before goAt
  const input = { steer: readSteer(), throttle: readThrottle(), brake: held("brake"), drift: held("drift") };
  const entry = { seq: ++seq, input, dt: 1 / 30 };
  send({ type: "cmd", data: { type: "input", realtime: true, seq: entry.seq, ...input } });
  pending.push(entry);
  previous = { ...predicted };
  kartPhysics.move(predicted, input, entry.dt);  // the kart responds now, not a round trip later
}, 1000 / 30);

Mengirim lebih cepat dari laju tick akan terbuang sia-sia — hanya input terbaru per tick yang digunakan — dan platform menurunkan input waktu nyata di atas batas per koneksinya.

Berdamailah dalam segala hal snap

Naskahnya bergema ack, paling atas seq itu telah diterapkan untuk setiap kart. Pada masing-masing snap, mundurkan milikmu kart ke status server dan memutar ulang apa yang belum dilihat server:

function onSnap(snap) {
  const [, x, z, heading, speed, boost, lap, cp, ack] = snap.karts.find((k) => k[0] === myId);
  while (pending.length && pending[0].seq <= ack) pending.shift();   // applied or superseded

  const corrected = { x, z, heading, speed, boost };
  for (const p of pending) kartPhysics.move(corrected, p.input, p.dt);

  if (!predicted) { predicted = corrected; previous = { ...corrected }; return; } // first snap
  error.x += predicted.x - corrected.x;          // what the player would see jump
  error.z += predicted.z - corrected.z;
  error.heading += predicted.heading - corrected.heading;
  if (Math.hypot(error.x, error.z) > 3) error = { x: 0, z: 0, heading: 0 }; // wall hit, bump: snap
  predicted = corrected;
  hud.lap = lap; hud.checkpoint = cp;            // progress is never predicted
}

Membuang semuanya ack benar meskipun kemenangan terbaru melewatkan beberapa input: a dilewati input digantikan sebelum server dicentang, jadi itu juga tidak mempengaruhi kart server.

Koreksi halus, render pada kecepatan bingkai

Koreksi kecil seharusnya tidak terlihat. Gambarlah kart pada posisi yang diprediksi ditambah dengan pembusukan kesalahan offset, dan interpolasi antara dua langkah prediksi 30 Hz terakhir sehingga tampilan 60 atau 144 Hz bergerak dengan lancar:

function render(frameDt) {
  const decay = Math.exp(-frameDt / 0.1);        // ~100 ms to absorb a correction
  error.x *= decay; error.z *= decay; error.heading *= decay;
  const a = sinceLastStep() * 30;                // 0…1 between prediction steps
  drawKart(lerp(previous.x, predicted.x, a) + error.x,
           lerp(previous.z, predicted.z, a) + error.z,
           lerpAngle(previous.heading, predicted.heading, a) + error.heading);
}

Sesuaikan ambang batas jepret daripada peluruhan: koreksi yang lebih besar dari panjang kart adalah hal yang nyata peristiwa (benjolan yang tidak Anda prediksi) dan terbaca lebih baik dalam sekejap daripada slide lambat.

Ketahui apa yang tidak perlu diprediksi

  • kart lainnya. Mereka diambil ~100 ms di masa lalu (buffer snaps dan interpolasi antara dua braket itu serverNow() - 100), jadi tumbukan yang diprediksikan terhadap mereka adalah tumbukan dengan dimana mereka adalah. Prediksi dinding dan lintasan — tidak bergerak — dan biarkan server menyelesaikannya gundukan kart-ke-kart. Koreksi terjadi dalam perjalanan bolak-balik. Jika buffer mengering, ekstrapolasi dari kecepatan dan menuju hingga ~100 ms, lalu tahan.
  • Barang. use-item adalah perintah yang tahan lama, sehingga dapat dijalankan onPlayerMessage segera setelah itu tiba - tidak ada centang tunggu. Mainkan nyala api dan suara saat tombol ditekan; biarkan kecepatannya melewatinya rekonsiliasi, sejak itu boost ada di snap. Jika server menolak (tidak ada biaya tersisa), selanjutnya snap menggulungnya kembali.
  • Negara ras. Jumlah putaran, posisi, dan finis berasal snap dan siaran skrip Anda saja.

Perkirakan jam server

snap.t Dan goAt adalah waktu server (ctx.now). Pertahankan offset dari celah terkecil yang diamati, yaitu menyaring pengiriman yang lambat:

let offset = Infinity;
function noteSnap(snap) { offset = Math.min(offset, performance.now() - snap.t); }
const serverNow = () => performance.now() - offset;

Mulai hitung mundur dari goAt, dan prediksi gerbang di atasnya seperti yang dilakukan loop di atas. Sebuah kart yang bergerak sebelumnya goAt secara lokal akan diikat kembali ke jaringan listrik terlebih dahulu snap setelah permulaan.

Untuk menyempurnakan semua ini, tambahkan latensi buatan dalam pengembangan (delay send Dan onSnap sebesar 100–200 ms) dan mencatat ukuran setiap koreksi — rata-rata koreksi besar yang stabil move telah melayang dari salinan server, atau kolom input dijepit secara berbeda di setiap sisi.
