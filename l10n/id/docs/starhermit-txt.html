Itu starhermit.txt Tampak

starhermit.txt adalah file teks biasa kecil yang memberi tahu StarHermit apa nama game Anda, bagaimana caranya meluncurkannya, dan jenis server apa (jika ada) yang dijalankannya. Ini adalah satu-satunya file yang dicari platform semua yang Anda publikasikan.

Itu milik akar dari apa yang Anda unggah — baik untuk file klien game maupun untuk file khusus server.

Anda tidak harus membuat sendiri file tersebut. Klien Windows dan dasbor web keduanya tampilkan manifes sebagai bidang yang dapat diedit: apa pun yang sudah dibawa oleh bangunan Anda, isi terlebih dahulu, dan apa pun yang disimpannya saat Anda menekan Unggah ditulis ke dalam bundel sebagai manifes. Jadi membangun dengan tidak starhermit.txt masih dapat diterbitkan, dan a .tar — yang tidak dapat Anda edit di tempatnya — adalah sebagai dapat diedit sebagai folder. Mengirimkan file di dalam build Anda masih layak dilakukan: file tersebut dikirimkan bersama artefak, sehingga nilainya tepat pada saat orang lain mengunggahnya.

Aturan yang mengejutkan orang

Segala sesuatu yang ada di sebelah manifes akan diunggah.

Folder yang Anda pilih bukanlah direktori proyek yang digali oleh platform untuk pembangunan — folder tersebut isinya adalah game yang diterbitkan, disalin apa adanya. Setiap file dan setiap subfolder yang berdekatan starhermit.txt, pada kedalaman berapa pun, naik dan disajikan kepada pemain.

Jadi pilihlah milikmu keluaran build yang dapat didistribusikan, bukan pohon sumber Anda. Mengunggah direktori kerja berarti mengirimkan sumber Anda, catatan Anda, aset Anda yang belum diminimalkan, dan eksperimen setengah jadi Anda ke sana setiap pemain, dan membakar ruang disk game Anda pada file yang tidak dimuat oleh siapa pun.

Beberapa nama selalu dilewati, karena nama tersebut tidak pernah menjadi bagian dari game yang diterbitkan: .git, node_modules, .DS_Store, Thumbs.db. Segala sesuatu yang lain adalah permainan yang adil - termasuk README.md, .env file, *.psd sumber dan *.map file. Jika Anda tidak mau menyerahkannya kepada pemain, jangan tinggalkan di sebelah manifes.

Ke mana perginya

Klien permainan

my-game-dist/
  starhermit.txt        <- belongs at this level
  index.html            <- your launch file
  game.js
  assets/
    sprites.png
    music.ogg

Memilih my-game-dist/. Isinya menjadi permainan, disajikan di https://<slug>.starhermit.com/, Dan index.html adalah apa yang dimuat pemain.

Atau pilih satu .tar tata letak yang persis seperti itu — "Tambahkan dari .tar" di klien desktop, itu .tar bidang di dasbor. Klien membaca entri arsip, memasukkannya kembali ke dalam bundel untuk Anda, dan mengisi kolom manifes dari a starhermit.txt di dalamnya. Menggunakan --format=ustar:

tar --format=ustar -cf my-game.tar -C my-game-dist .

Arsip yang menggunakan nama panjang GNU atau header PAX yang diperluas ditolak. Format tersebut menyimpan entri yang asli jalan di a memisahkan blok metadata, jadi menempatkannya kembali berarti menulis ulang metadata — dan mendapatkannya salah secara halus akan menerbitkan game yang korup. Jika build Anda mencapai batas jalur usstar (100 byte untuk a nama, 155 untuk awalan direktorinya), persingkat nama folder terdalam atau unggah foldernya.

Server khusus

my-server-dist/
  starhermit.txt        <- belongs at this level
  image.tar            <- docker save output of your server image

Memilih my-server-dist/ — atau pilih image.tar dengan sendirinya, karena manifesnya bisa berasal dari bidang dialog sebagai gantinya. Berbeda dengan folder klien, distribusi server memiliki dua arti file: manifes, dan gambar container yang dihasilkan oleh

docker save my-server:latest > image.tar

Apa pun yang ada di folder server akan tertinggal dan tidak diunggah — platform akan menjalankannya container, jadi gambar tersebut sudah berisi file server Anda. Tetap menyimpan manifes di sini berarti pembangunan server menggambarkan dirinya sendiri dan dapat diunggah ulang sendiri.

Format

Garis dari key=value. Baris kosong diabaikan, # memulai komentar, dan spasi di sekitar tombol dan nilai dipangkas. Nama kunci tidak membedakan huruf besar dan kecil, kecuali jalur folder di dalamnya cache.<folder> peka huruf besar-kecil; kunci yang tidak diketahui diabaikan, sehingga kesalahan ketik gagal secara diam-diam — periksa ejaan Anda berdasarkan tabel di bawah.

# My Game - browser-only
name=My Game
launch=index.html

Kunci yang dapat diatur oleh setiap permainan

Kunci Alias Arti
name — Nama tampilan yang dilihat pemain. Diperlukan kecuali Anda memberikan nama tampilan di formulir unggahan.
launch launch_path, html Jalan menuju entri .html, relatif terhadap manifes. Defaultnya adalah index.html ketika file dengan nama itu berada di root.
cover cover_art, coverart Karya seni di ubin perpustakaan game. Jalur relatif terhadap file peluncuran (cover.png, art/box.jpg) atau mutlak https:// URL. Opsional — tanpa ubin, ubin akan menampilkan favicon. Nilai yang buruk dihilangkan daripada menolak permainan.
description — Teks halaman toko yang dibaca pemain tentang game Anda. Satu baris; menulis \n untuk jeda baris. Atau gunakan description.file untuk menyimpannya dalam file. Melihat Deskripsi dan catatan rilis.
release_notes releasenotes Apa yang berubah dalam build ini. Aturan yang sama seperti description; release_notes.file menunjuk ke file sebagai gantinya.
owner username, user Aliran repositori saja. Pemilik StarHermit ID pengguna (UUID) dari GET /api/v1/me, bukan nama pengguna. Memungkinkan Anda mengklaim daftar yang ditambahkan orang lain dengan membuktikan bahwa Anda mengontrol repositori. Diabaikan pada unggahan — lihat Siapa pemilik game yang diunggah.

Deskripsi dan catatan rilis

Dua potongan teks opsional ditampilkan di samping permainan Anda: a keterangan (apa permainannya) dan catatan rilis (apa yang berubah pada build yang Anda terbitkan). Masing-masing dapat ditulis dalam memanifestasikan dirinya atau disimpan dalam filenya sendiri.

sebaris, untuk teks pendek. Manifesnya adalah satu baris per kunci, jadi tulislah \n dimanapun kamu mau a jeda baris (dan \\ untuk garis miring terbalik literal):

name=Asteroid Garden
launch=index.html
description=Tend a garden on a drifting asteroid.\nPlant, water, and dodge the meteor showers.
release_notes=- New: night cycle\n- Fixed: seeds vanishing after a reload

Dari sebuah file, untuk waktu yang lebih lama — ini adalah formulir yang digunakan untuk catatan rilis sebenarnya:

name=Asteroid Garden
launch=index.html
description.file=DESCRIPTION.md
release_notes.file=CHANGELOG.md

my-game-dist/
  starhermit.txt
  DESCRIPTION.md
  CHANGELOG.md
  index.html
Kunci Alias Arti
description — Teks deskripsi, sebaris.
description.file — Jalan menuju a .md, .markdown atau .txt file yang menyimpan deskripsi.
release_notes releasenotes Teks catatan rilis, sebaris.
release_notes.file releasenotes.file Jalan menuju a .md, .markdown atau .txt file yang memegang catatan rilis.

Aturannya:

  • Jalur file bersifat relatif starhermit.txt (root repositori untuk game repositori), bukan ke file peluncuran. TIDAK .., tidak memimpin /, dan hanya .md, .markdown atau .txt; jalur lainnya diabaikan daripada menolak permainan. Filenya harus di dalam apa yang Anda terbitkan, memang begitu disajikan kepada pemain seperti file lain di samping manifes. Jangan memasukkan apa pun ke dalamnya, kamu tidak akan menunjukkannya kepada mereka.
  • Sebuah file menang atas baris sebaris. Deklarasikan keduanya dan teks sebaris hanya merupakan cadangan, digunakan ketika file tidak dapat ditemukan.
  • Teks dibaca ulang setiap kali manifesnya: setiap upload atau push yang membawa a manifes, dan setiap penerapan repositori (dari komit yang diterapkan). Hapus kedua baris dan teks dihapus. File yang dideklarasikan tetapi hilang, tanpa fallback sebaris, akan meninggalkan teks permainan sudah dimiliki.
  • Mengapa berupa file dan bukan teks multi-baris dalam manifes? Setiap kunci lainnya dibaca baris demi baris. Jika sebuah paragraf catatan rilis bisa berada di dalam manifes, sebuah catatan yang kebetulan tertulis owner=someone akan dibaca sebagai owner= garis.
  • Ukuran: deskripsi dipotong menjadi 4.000 karakter dan catatan rilis menjadi 20.000. Teks yang lebih panjang adalah dipersingkat, bukan ditolak. Akhiran garis dinormalisasi dan garis kosong depan dan belakang dipangkas.
  • Pemformatan: teks disimpan persis seperti yang tertulis. Penurunan harga adalah pilihan yang masuk akal, tapi apakah itu dirender atau ditampilkan sebagai teks biasa terserah klien untuk menampilkannya.
  • Catatan rilis diganti, bukan diakumulasi. Setiap terbitan membawa catatan untuk itu membangun. Simpan riwayat lengkap Anda di log perubahan Anda sendiri dan publikasikan bagian yang dibutuhkan pemain.

Klien membaca deskripsi dari daftar game dan catatan rilis dari GET /api/v1/github-games/{id}/release-notes.

Cache aset browser

Menggunakan cache.<folder>=<seconds> untuk mengatur Cache-Control: public, max-age=<seconds> pada host statis file. Durasi adalah bilangan bulat 0–31536000 (setahun):

cache..=0
cache.audio=31536000
cache.audio/live=0
cache.assets/textures=604800

Di Sini cache.. menyetel default seluruh situs ke nol (validasi ulang saat digunakan kembali), audio/ cache selama setahun, audio/live/ memvalidasi ulang, dan assets/textures/ cache selama seminggu. Gunakan nama file dengan hash konten untuk aset berumur panjang: penerapan ulang tidak membuat salinan yang sudah disimpan dalam cache di browser pemain menjadi tidak valid.

Jalur peka huruf besar-kecil, relatif terhadap root yang dihosting (root repositori atau milik bundel client/ direktori), dan cocokkan seluruh folder termasuk turunannya. audio tidak cocok audiobooks. Garis miring tambahan bersifat opsional; folder yang paling spesifik menang, dan duplikat terakhir menang. Menggunakan . hanya untuk root default; jalur absolut, segmen kosong, ./.. segmen, garis miring terbalik, %, ?, #, : dan karakter kontrol ditolak. Tanpa aturan yang cocok, tidak ada keadaan statis yang eksplisit Cache-Control tajuk. Panggilan API, WebSockets, dan fallback aset hilang yang dialirkan secara eksternal tidak terpengaruh.

Mengizinkan situs web lain mengakses game yang Anda host

Untuk klien browser di asal lain, deklarasikan hingga lima asal HTTP/HTTPS yang tepat:

cors.origins=https://example.com,https://play.example.org,http://localhost:5173

Misalnya, setelah menerbitkan manifes ini, halaman pengembangan aktif http://localhost:5173 bisa mengambil aset dari game yang Anda host:

const response = await fetch('https://YOUR_GAME_UID.starhermit.com/assets/levels.json');
if (!response.ok) throw new Error(`Asset request failed: ${response.status}`);
const levels = await response.json();

Setiap asal adalah skema, nama host yang tepat, dan port opsional. Wildcard, domain kosong, kredensial, jalur (bahkan trailing /), pertanyaan dan fragmen ditolak. Skema dan port harus cocok; subdomain tidak disertakan secara implisit. Ulang cors.origins garis digabungkan, dengan paling banyak lima entri di seluruh manifes (duplikat juga dihitung). Hilangkan kunci untuk tidak mengizinkan asal tambahan; nilai kosong tidak valid.

Hal ini berlaku untuk aset statis, cadangan aset yang hilang, dan /api/ permintaan aktif tuan rumah permainan Anda. Asal yang diizinkan menerima header CORS yang diberi kredensial; OPTIONS preflight mengizinkan GET, HEAD, POST, PUT, PATCH, DELETE dan OPTIONS dengan header yang diminta. Otentikasi dan otorisasi API masih terapkan. Ini tidak mengkonfigurasi CORS aktif api.starhermit.com, mengubah aturan asal WebSocket, atau memperluas URL kembali yang diizinkan oleh login game browser. Game yang berjalan di host asal sendiri tidak memerlukan deklarasi CORS tambahan.

Menerbitkan cache dan pengaturan CORS

Kedua kebijakan dipublikasikan dengan file klien. Penerapan repositori membaca komit yang disematkan. Dalam bundel, root starhermit.txt diutamakan client/starhermit.txt. Unggahan gabungan tanpa manifes mempertahankan kebijakan yang ada; manifes yang disediakan menggantikannya (menghilangkan pengaturan akan menghapusnya). Penggantian penuh tanpa manifes menghapus kedua kebijakan tersebut. Pengaturan tidak valid menolak publikasi sebelum mengganti file langsung (422 untuk unggahan; sebuah gagal penyebaran repositori). Melihat pembaruan bundel.

Kontrol

Deklarasikan tindakan keyboard yang digunakan game Anda, dengan tombol default yang dapat diubah oleh pemain:

control.left=KeyA+ArrowLeft | Move left
control.jump=Space+KeyW | Jump

control.<action>=<code>[+<code>...][ | <label>]: ID tindakan adalah huruf kecil, angka dan _; kode adalah KeyboardEvent.code nilai (KeyA, Space, ArrowLeft), hingga 4 per tindakan yang digabungkan dengan +; paling banyak 32 tindakan, dan tidak ada kunci pada dua tindakan. Baris yang tidak valid dilewati secara diam-diam, dan a permainan tanpa garis yang valid tidak memiliki kontrol - kontrolnya adalah jawaban API 404 "This game declares no controls.". Aturan ini berlaku saat Anda memublikasikan build yang memuatnya. Melihat Tutorial: tambahkan kontrol ke game Anda.

Kunci untuk permainan mesin StarHermit

Sebuah permainan yang dimainkan oleh mesin StarHermit (permainan skrip) mendeklarasikan mesin yang dijalankannya engine.* kunci. Mesin membacanya bersama-sama name=, server= dan itu control.* garis; klien Windows StarHermit memainkan permainan secara asli ketika ditemukan engine.version Dan engine.entry, dan browser memutarnya dari halaman pemuat starhermit package --web menulis.

Kunci Arti
engine.api Versi utama API host tempat game ini ditulis (1).
engine.entry Modul mesin mulai, seperti src/main.ts.
engine.version Tepatnya pelepasan mesin permainan terus berjalan, X.Y.Z; utamanya adalah engine.api. Platform mencatatnya di setiap publikasi dan menyajikan halaman skrip permainan di bawah mesin Kebijakan-Keamanan-Konten.
engine.minor Opsional: versi minor API host yang dibutuhkan game; mesin yang menawarkan lebih sedikit menolaknya.
engine.capabilities Opsional, dipisahkan koma: platform, voice, clipboard, storage.
engine.gamepad.<action> Kontrol gamepad default untuk suatu tindakan control.* garis menyatakan.
engine.limits.<name> Opsional: menurunkan salah satu batas mesin untuk game tersebut.

Kunci untuk game dengan logika server

Memilih satu gaya server. Mendeklarasikan keduanya server= Dan container.image= ditolak.

Ini bekerja di sebuah folder yang diunggah serta tempat penyimpanan. A server= skrip berjalan di dalam folder yang Anda unggah dan sumbernya dibaca langsung dari arsip, sehingga merupakan permainan yang berwibawa aturan tidak memerlukan repositori sama sekali. Jika deklarasi tidak dapat dipenuhi — naskahnya hilang, menunjuk ke luar folder, atau meminta penampung yang tidak Anda izinkan untuk dijalankan — keseluruhan unggahannya menolak daripada membuat game setengah terkonfigurasi.

Kunci Arti
server (alias server_script) Jalur ke file JavaScript yang dijalankan sebagai server resmi di kotak pasir StarHermit. Melihat Skrip Permainan.
container.image A intisari-disematkan gambar (name@sha256:<64 hex>) untuk dijalankan sebagai server. Tag ditolak. Melihat Server Game Kontainer.
container.port Port yang didengarkan oleh container Anda.
container.memory_mb Memori yang diminta dalam MiB, dibatasi hingga batas operator.
container.cpu Batas CPU untuk kontainer.
container.health Jalur platform menyelidiki kesiapan.
container.env.<NAME> Variabel lingkungan diteruskan ke penampung Anda.

Memulai perjodohan sebelum setiap kursi manusia terisi

Pengaturan ini berlaku untuk game resmi yang menggunakan perjodohan StarHermit, dengan a JavaScript atau server kontainer:

matchmaking.max_wait_seconds=30
matchmaking.ai_players=2
Kunci Arti
matchmaking.max_wait_seconds Bilangan bulat 0–86400. Mulai pertandingan yang kurang terisi ketika tiket tertua yang dipilih telah menunggu beberapa detik. 0 segera dimulai. Hilangkan untuk mempertahankan perilaku default full-human-match-or-expire.
matchmaking.ai_players Bilangan bulat 0–31, bawaan 0. Pada tenggat waktu, isi kursi kosong sebanyak ini dengan AI; biarkan kursi kosong selanjutnya tetap kosong. Memerlukan matchmaking.max_wait_seconds.

Kapasitas antrian berasal dari skrip game.queues; tanpa deklarasi itu adalah 1v1. Wadah saat ini /describe pembaca tidak mengimpor queues, jadi penjodohan kontainer digunakan bentuk 1v1 implisit. Misalnya, dalam antrian delapan kursi yang dinyatakan dalam skrip dengan tiga orang menunggu, setting di atas dimulai dengan tiga manusia, dua pemain AI dan tiga kursi kosong. Manusia seutuhnya pertandingan dapat dimulai sebelum batas waktu dan tidak mendapat AI. Menyetel AI ke 0 memungkinkan kecocokan khusus manusia dengan kursi kosong, termasuk satu manusia jika game mendukungnya.

Platform memeriksa enqueue dan selama pemeriksaan perjodohan berkala (default setiap 5 detik), jadi permulaan dapat mengikuti batas waktu hingga interval sapuan pada beban normal. Kompatibilitas Elo dan subset antrean yang diizinkan untuk setiap tiket masih berlaku. Para pihak tetap bersama dalam satu tim; di batas waktu partai yang lebih kecil atau pemain solo dapat menempati tim yang lebih besar, dengan sisa kursi tersedia untuk AI atau dibiarkan kosong. Tiket tidak digabungkan menjadi satu tim.

Server game Anda harus menerima kecocokan yang kurang terisi dan menerapkan perilaku AI. tanda StarHermit para pemain AI; itu tidak menghasilkan gerakan mereka. Sesi yang ditolak membatalkan tiket yang dipilih. Tata letak kursi beku disediakan sebagai ctx.matchmaking, dan kursi yang ditempati muncul ctx.players; melihat konteks server. Kursi kosong tidak otomatis diisi oleh bergabung terlambat.

Penyebaran ulang dan pengunggahan repositori menerapkan pengaturan ini. Manifes yang disediakan tanpa kunci akan direset mereka; sebuah patch tanpa manifes akan mempertahankannya. Nilai yang tidak valid ditolak (upload 422, atau gagal penyebaran repositori). Pengaturan ini tidak mempengaruhi permainan latihan eksplisit atau ruang waktu nyata gabung cepat/isi ulang.

Cara membuatnya

  1. Buka editor teks biasa — Notepad, TextEdit, VS Code, apa saja. Bukan Kata.
  2. Ketikkan kunci yang dibutuhkan game Anda, satu kunci per baris (mulai dari contoh di bawah).
  3. Simpan sebagai starhermit.txt di folder yang akan Anda unggah, dikodekan sebagai UTF-8.

Di Windows, Notepad "Dokumen Teks" jenis penyimpanan ditambahkan .txt untuk apa pun yang Anda ketik, jadi beri nama mengajukan starhermit.txt hasil starhermit.txt.txt. Pilihlah Semua File dalam dialog simpan, atau nyalakan File Explorer Ekstensi nama file lihat dan ganti namanya setelahnya. Sebuah file bernama starhermit.txt.txt tidak ditemukan dan pengunggahan ditolak.

Namanya persis: semua huruf kecil, tanpa spasi. Starhermit.txt Dan starhermit.TXT bekerja karena pencarian tidak peka huruf besar-kecil, tapi starhermit.text, starhermit.cfg Dan manifest.txt tidak.

Contoh

Game khusus browser

name=Asteroid Garden
launch=index.html

Game dengan seni sampul

name=Asteroid Garden
launch=index.html
cover=art/cover.png

Jalur relatif diselesaikan terhadap file peluncuran (no .., tidak memimpin /, tidak ada string kueri) dan harus diakhiri dengan .png, .jpg/.jpeg, .gif, .webp atau .svg. URL absolut harus berupa https:// — http:// dijatuhkan — dan byte-bytenya diendus, sehingga URL itu sendiri tidak memerlukan ekstensi gambar.

Baris tersebut dibaca ulang pada setiap penerapan, jadi mengubahnya akan mengubah sampulnya dan menghapusnya akan menghapusnya penutup. Kumpulan gambar dari Kelola → Seni sampul di dasbor web (atau oleh operator StarHermit) menimpanya: pilihan itu berada di luar pembangunan, jadi penerapan ulang tidak akan membatalkannya. Menghapus upload jatuh kembali ke baris ini lagi.

Ubin perpustakaan

Seni sampul adalah seni poster: kedua perpustakaan skalakan untuk mengisi ubin dan tanaman tengah apa pun fungsinya tidak cocok. Bentuk ubinnya tidak sama.

Permukaan Ubin Tanaman
klien Windows Potret 96×128 (3:4) Mengisi potret; seni yang lebih luas kehilangan sisinya
Dasbor web Persegi Mengisi kotak; seni yang lebih tinggi kehilangan bagian atas dan bawah

Pertahankan subjek di dalam tengah. Potret 3:4 yang kotak tengahnya merupakan komposisi, atau a persegi yang garis tengahnya 3:4, bertahan dari kedua tanaman. Kotak surat tidak pernah diterapkan — kosong margin yang Anda tambahkan di sekitar karya seni akan terpotong bersama yang lainnya.

Sampul SVG ditampilkan di perpustakaan web. Klien Windows tidak memiliki decoder SVG, sehingga ubin mundur ke favicon saat ubin web masih menampilkan sampulnya. Pilih PNG, JPEG, atau WEBP bila Anda mau ubin yang sama pada keduanya.

Mengklaim listingan yang Anda miliki — hanya game repositori

Mengatur owner ke ID pengguna StarHermit yang tidak dapat diubah dikembalikan sebagai id oleh GET /api/v1/me—bukan itu nama pengguna atau nama panggilan profil:

name=My Game
launch=index.html
owner=3fa85f64-5717-4562-b3fc-2c963f66afa6

Siapa pemilik game yang diunggah

Akun yang mengunggahnya. Selalu, dan tidak ada yang perlu dikonfigurasi.

Sebuah unggahan tidak memiliki tempat penyimpanan di baliknya, jadi tidak ada yang dapat membuktikan kendalinya kepada siapa pun: the platform mencatat akun pengunggahan sebagai pengirim dan membiarkan bidang pemilik GitHub kosong tidak ada klaim yang dapat menandingi baris tersebut. Sebuah owner= baris dalam build yang diunggah diabaikan, dan klien mengabaikannya tidak menawarkan bidang untuk itu — menempatkan permainan atas nama orang lain akan memberikan mereka tanggung jawab untuk konten yang tidak mereka terbitkan, yang seharusnya tidak dapat dilakukan oleh formulir unggah.

Menyerahkan game yang sudah Anda miliki kepada orang lain merupakan tindakan terpisah dan disengaja dari menu Kelola game tersebut setelah faktanya, bukan keputusan yang dibuat sambil menambahkannya.

Menerbitkan dari repositori GitHub sebagai gantinya

Jika game Anda berada di a github.com repositori, letakkan starhermit.txt di akar repositori dan kirimkan URL repo — platform membaca manifes langsung dari repo dan tidak ada unggahan terlibat. Semua hal di atas berlaku tidak berubah, kecuali itu "semuanya berdekatan" berarti semuanya masuk repositori, yang merupakan alasan bagus untuk menyimpan output dan sumber build di repo terpisah (atau untuk menggunakan unggahan folder untuk keluaran bawaan Anda).

Melihat Permainan GitHub untuk aliran repositori, dan Tambahkan game dari folder lokal untuk unggahan titik akhir yang dihubungi klien.

Batasan

Satu permainan mungkin menempati 2 GB di starhermit.com (tunjangan dapat bervariasi berdasarkan penerapan), dan itu saja juga batas atas pada satu unggahan pengganti. A ?mode=merge patch dibatasi oleh pohon yang dihasilkan, jadi unggahan kecil yang akan membuat permainan langsung melebihi tunjangan ditolak. Secara mendalam jalur bersarang ditolak: format arsip membatasi jalur pada 100 karakter untuk nama file ditambah 155 untuk awalan direktorinya, jadi persingkat rantai folder yang sangat panjang.
