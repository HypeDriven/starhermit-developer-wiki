الإنجازات

الإنجاز ينتمي إلى بالضبط مالك واحد، ويقرر المالك من يُسمح له بفتحه:

مالك أعلن بواسطة مقفلة بواسطة استخدامه ل
لعبة موثوقة game.achievements في البرنامج النصي، أو achievements من حاوية /describe — أو من قبل مالك اللعبة خلال /me/github-games/{id}/achievements وقت تشغيل خادم اللعبة فقط — خادم موثوق ألعاب مع أ server= البرنامج النصي أو container.image= الخلفية
عنوان الكتالوج (SoftwareTitle) ناشر، عبر واجهة برمجة تطبيقات الناشر عميل اللاعب عبر POST /api/v1/me/achievements/unlock (الاستحقاق مطلوب) العناوين الموزعة التي يكون عميلها هو الشيء الوحيد الذي يعرف أن اللاعب حصل على شيء ما

الاثنان متنافيان والمنصة تفرض الانقسام:

  • POST /api/v1/me/achievements/unlock يرفض الإنجازات على مستوى اللعبة - لا يمكن للعميل المطالبة بواحدة على الإطلاق.
  • نقاط النهاية CRUD للناشر ترفضها أيضًا. لا تحتاج إلى ناشر للعبة التي تمتلكها: مثل صاحبها أنت نكون ناشرها، ويمكنك إدارة إنجازاتها من خلال نقاط نهاية المالك بدلاً من.

عنوان URL الأساسي: https://api.starhermit.com. جميع الطرق تحت /api/v1/....

طريقة طريق مصادقة وصف
يحصل /api/v1/games/{slug}/achievements حامل إنجازات اللعبة الموثوقة + حالة فتح المتصل
يحصل /api/v1/me/github-games/{id}/achievements JWT (مالك اللعبة) كل إنجاز لعبتك به origin وفتح العد
بريد /api/v1/me/github-games/{id}/achievements JWT (مالك اللعبة) أنشئ إنجازًا للعبتك → 201
يضع /api/v1/me/github-games/{id}/achievements/{achievementId} JWT (مالك اللعبة) قم بتحديث واحد قمت بإنشائه
يمسح /api/v1/me/github-games/{id}/achievements/{achievementId} JWT (مالك اللعبة) احذف واحدة قمت بإنشائها ولم يفتحها أحد → 204
يحصل /api/v1/software/{titleId}/achievements مجهول تعريفات إنجاز عنوان الكتالوج
يحصل /api/v1/me/achievements?titleId= JWT فتح المتصل (جميع المالكين، أو لقب واحد)
بريد /api/v1/me/achievements/unlock JWT إلغاء القفل الذي يطالب به العميل — عناوين الكتالوج فقط

قراءة الأخطاء بشكل دفاعي كما هو موضح في اتفاقيات API. POST /me/achievements/unlock يعود لها 400 السبب كنص عادي.

إنجازات اللعبة ذات سلطة الخادم

هذه هي الآلية أي يجب استخدام اللعبة عندما تحتوي على برنامج نصي أو واجهة خلفية للحاوية. ال وقت تشغيل الخادم هو الكاتب الوحيد. يجب التحقق من حصول اللاعب على كل عملية فتح؛ رفض لا تؤدي عمليات إرسال واجهة برمجة التطبيقات المباشرة وحدها إلى التحقق من صحة الأحداث التي أبلغ عنها العميل المعدل.

1. أعلن عنها في البرنامج النصي الخاص بك

أضف ثابتًا achievements مصفوفة الى game كائن - انظر مخطوطات اللعبة - الإنجازات للعقد الكامل:

globalThis.game = {
  achievements: [
    { key: "first-win",  name: "First Win",  description: "Win a match.", points: 10 },
    { key: "flawless",   name: "Flawless",   description: "Win without conceding.",
      points: 50, secret: true, icon: "https://cdn.example/flawless.png" }
  ],
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

تمت قراءة الإعلان عندما يتم نشر اللعبة أو تحديثها من مستودعها. نشر تحديث لتطبيق التغيير.

2. قم بإلغاء قفلها من أي خطاف في دورة الحياة

العودة ان achievements الخريطة - معرف المستخدم → مجموعة المفاتيح - من createSession, onPlayerMessage، أو onTick:

return {
  ok: true,
  sessionState: state,
  achievements: { [winnerId]: ["first-win", "flawless"] },
  result: { kind: "win", winner: winnerId }
};

يفتح عاجز - إن إعادة المفتاح الذي يحمله اللاعب بالفعل هو أمر محظور، لذلك قد يكون ذلك ممكنًا أعد تأكيد الإنجاز عند كل علامة دون القلق بشأن التكرارات.

3. يتم إخطار اللاعب عبر مقبس اللعب

يتم دفع كل فتح تم منحه حديثًا إلى اللاعب الفائز فقط ws/v1/games، كإطار خاص بها اكتب (حقيقة النظام الأساسي، وليس نصًا تم ترحيله game رسالة):

{
  "type": "achievement",
  "data": {
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "points": 10,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
}

يفتح الممنوحة من createSession تستمر قبل أن يكون لدى أي شخص مأخذ توصيل، حتى يصلوا معه بدون إطار - اقرأها من نقطة نهاية القائمة عند التحميل.

الواجهات الخلفية للحاويات

تعلن الحاوية عن نفس حقول الإنجاز الموجودة في GET /describe، ثم يرسل achievements رسالة على سيطرتها WebSocket. تطبق المنصة نفس المفتاح، المشارك، العجز الجنسي، وقواعد التسليم. يرى خوادم ألعاب الحاويات.

GET /api/v1/games/{slug}/achievements

كل إنجاز تعلنه اللعبة، مع حالة فتح المتصل. 404 إذا كان سبيكة لا يوجد لديه تعريف اللعبة الرسمي (اللعبة التي لا تحتوي على برنامج نصي أو واجهة خلفية للحاوية ليست مملوكة للعبة الإنجازات – انظر ما هي الألعاب التي يمكنها استخدام هذا؟). يتم إخفاء الإنجازات السرية حتى المتصل يفتح لهم. مرتبة حسب الخلق، ثم المفتاح.

[
  {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "secret": false,
    "points": 10,
    "unlocked": true,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
]

يعمل مع مستخدم JWT كامل أو رمز إطلاق على نطاق اللعبة.

ما هي الألعاب التي يمكنها استخدام هذا؟

الآلية متاحة للعبة التي تعلن إما أ server= السيناريو أو أ container.image= الخلفية في starhermit.txt. ال وقت تشغيل الخادم يجعل عملية إلغاء القفل موثوقة. تتضمن حالات الاستخدام المدعومة بالبرنامج النصي ما يلي:

  • ألعاب المنصات المكتوبة — فتح من onPlayerMessage / onTick كما تلعب المباراة.
  • ألعاب الوقت الحقيقي المرتبطة بالغرفة — a غرفة الوقت الحقيقي ل لعبة مع server= يقوم البرنامج النصي بإنشاء جلسة ملزمة عندما تبدأ، وكل ربط من ذلك يمكن للجلسة منح الإنجازات.
  • ألعاب فردية وممارسة - جلسة ضد مقعد الذكاء الاصطناعي (POST /api/v1/games/{slug}/sessions/ai) يقوم بتشغيل نفس البرنامج النصي ونفس مسار إلغاء القفل.
  • ألعاب الوقت الحقيقي التي يوجهها المضيف - لعبة تمتد طريقة لعبها على قناة ثنائية للغرفة في الوقت الحقيقي لا يزال بإمكانه شحن البرنامج النصي للخادم مجرد سلطة الإنجاز الخاصة بها: بداية الغرفة تخلق الجلسة المقيدة والنص الجوائز من createSession / onTick / دائم cmd الرسائل المرسلة ws/v1/games بينما المسار السريع يستمر في التدفق ws/v1/realtime.

يمكن للجلسات المدعومة بالحاويات أيضًا الإعلان عن الإنجازات ومنحها من خلال البروتوكول الخاص بها. لعبة مع لا يوجد خلفية موثوقة (لعبة متصفح خالصة، أو لعبة مبنية فقط على تتابع الأقران) لا يوجد لديه مسار إلغاء قفل معتمد للخادم. فتح القفل الذي يطالب به العميل متاح فقط لـ العناوين الموزعة في الكتالوج، أدناه.

الحدود والقواعد

قاعدة قيمة
الإنجازات المعلنة لكل لعبة 100 (تم تجاهل الإضافات)
طول مفتاح الإنجاز 128 حرفا
يتم قبول فتح المفاتيح لكل لاعب، لكل استدعاء 32
points فرضت على 0-10000؛ الإعدادات الافتراضية إلى 0
name الافتراضيات ل key عندما تم حذفها
  • إدخال إعلان تالف هو تم تخطيه. البرنامج النصي الذي يفشل في التقييم ينتج عنه ملف فارغ قائمة؛ تتم قراءة بيان الحاوية بعد اجتيازها للفحوصات الصحية. التحقق مع GET /api/v1/games/{slug}/achievements بعد النشر.
  • التعاريف التي كتبها key. يتم حذف المفتاح الذي توقفت الواجهة الخلفية عن الإعلان عنه فقط إذا لم يكن لدى أحد فتحه - التاريخ المكتسب لا يتم تدميره أبدًا. الإنجازات التي أنشأها المالك من خلال واجهة برمجة التطبيقات لا يتم التطرق إلى هذا أبدًا: يتم التوفيق بين المعلنين فقط.
  • يتم تجاهل عمليات إلغاء القفل للمستخدمين الذين ليسوا مشاركين في الجلسة، ولمقعد الذكاء الاصطناعي.

الإنجازات من الألعاب الأخرى

يمكن للعبة أن تفتح ميزات بناءً على ما فتحه اللاعب آخر اللعبة: تكريم تتمة النسخة الأصلية، أو الألعاب في سلسلة تشارك مستحضرات التجميل. هناك طريقتان لقراءتها.

من الخادم الخاص بك: ctx.linkedAchievements (موثوق)

قم بتسمية الألعاب الأخرى في البرنامج النصي الخاص بك، بجانب إعلاناتك الأخرى:

globalThis.game = {
  linkedAchievements: ["83fd04b1-3cbe-4b09-a251-3733ad4b9d94"], // other games' slugs (uids)
  // ...
};

حاوية ترجع نفس الشيء linkedAchievements مصفوفة من GET /describe. كل السيناريو يحمل ctx الخاص بالاستدعاء المفاتيح غير المؤمنة لكل لاعب بشري في تلك الألعاب:

ctx.linkedAchievements = {
  "7c9e6679-...": {                                   // player id
    "83fd04b1-3cbe-4b09-a251-3733ad4b9d94": ["first-win", "checkmate-10"]
  }
};
  • يتم إعادة القراءة عليه كل دعوة، لذلك يتم عرض عملية إلغاء القفل التي تم الحصول عليها في اللعبة الأخرى في منتصف المباراة التالي. تستقبلها الحاوية في ctx of POST /sessions، أي عند الإنشاء وفي استعادة.
  • على الأكثر 8 ألعاب؛ الإدخالات التي ليست عبارة عن سلاسل غير فارغة أو مكررة أو ارتباطات ثابتة تزيد عن 100 يتم إسقاط الشخصيات. مثل الإعلانات الأخرى يتم قراءتها عند نشر اللعبة أو محدث.
  • اللعبة التي تعلن لا شيء تحصل على لا linkedAchievements الميدان ولا يدفع شيئا.
  • استخدم هذا المسار لأي شيء يجب على النظام الأساسي فرضه، مثل فتح طريقة اللعب أو منح فرصة الإنجاز الخاص بك.

من عميلك: GET /api/v1/games/{slug}/linked-achievements/{otherSlug}

يتم فتح قفل المتصل الخاص به otherSlug. إنها لا تحتاج إلى إعلان، لذا فهي لعبة للمتصفح فقط بدون أي إعلان يمكن للخادم استخدامه، ويعمل مع رمز الإطلاق المميز {slug}: نقاط النهاية الخاصة باللعبة الأخرى البقاء مسيجة من هذا الرمز.

{
  "game": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "hidden": false,
  "unlocked": [
    { "key": "first-win", "unlockedAt": "2026-07-25T09:14:02Z" }
  ]
}

يمكن للعميل أن يكذب بشأن ما تلقاه، لذا تعامل مع هذا باعتباره تلميحًا لواجهة المستخدم ومستحضرات التجميل، وليس كدليل.

ما تم الكشف عنه

  • فتح حالة اللعبة التي قمت بتسميتها فقط: المفاتيح وأوقات فتح القفل، وليس الأسماء أو الأوصاف أو قائمة الألعاب الأخرى التي لعبها اللاعب. الإنجاز السري الذي فتحه اللاعب هو متضمنة.
  • سبيكة لا تتطابق مع أي لعبة تجيب مثل لعبة لا يوجد بها أي شيء مفتوح.
  • يتم احترام الخصوصية. لاعب خصوصية إنجازاته Private يكون مختفي: غائب من ctx.linkedAchievements، و "hidden": true مع قائمة فارغة من نقطة النهاية. مخفي ليست هي نفسها "ليس لديه أي شيء"، فلا تعامله على هذا النحو. FriendsOnly تم الكشف عن (الافتراضي) ، لأن القارئ يتصرف نيابة عن اللاعب.

الإنجازات التي أنشأها مالك اللعبة

إن الإعلان عن الإنجازات في الكود ليس الطريقة الوحيدة لمنح لعبتك بعضًا من المتعة. إذا كنت تمتلك لعبة مع server= البرنامج النصي أو container.image= الواجهة الخلفية، يمكنك أيضًا إنشاء إنجازات لها من خلال واجهة برمجة التطبيقات (API) - الطريقة التي يتبعها الناشر للحصول على عنوان الكتالوج، دون الحاجة إلى حساب ناشر أو إذن. امتلاك اللعبة هو كامل المنحة. استخدم هذا عندما يريد المصمم إضافة أو إعادة صياغة الإنجازات دون تغيير التعليمات البرمجية، أو عندما تمنح الواجهة الخلفية لديك المفاتيح، فإنها لا تعلن عنها.

يمكن لخادم لعبتك فقط فتحها، تمامًا مثل تلك المعلنة: يقوم البرنامج النصي الخاص بك بإرجاع المفتاح في achievementsأو ترسله الحاوية الخاصة بك إلى قناة التحكم. لا شيء يتغير على فتح الجانب — يتم حل المفاتيح ضد الجميع من إنجازات اللعبة المعلنة والمبتكرة.

{id} هو معرف اللعبة الخاصة بك من GET /api/v1/me/github-games.

POST /api/v1/me/github-games/{id}/achievements

{
  "key": "speedrunner",
  "name": "Speedrunner",
  "description": "Finish a level in under a minute.",
  "icon": "https://cdn.example/speedrunner.png",
  "secret": false,
  "points": 25
}

key, name و description مطلوبة. المرتجعات 201:

{
  "id": "…",
  "key": "speedrunner",
  "name": "Speedrunner",
  "description": "Finish a level in under a minute.",
  "icon": "https://cdn.example/speedrunner.png",
  "secret": false,
  "points": 25,
  "origin": "owner",
  "unlocks": 0,
  "createdAt": "…",
  "updatedAt": "…"
}

GET على نفس المسار يسرد كل إنجازات اللعبة بهذا الشكل: origin يكون declared لتلك التي يعلن عنها البرنامج النصي أو الحاوية الخاصة بك و owner لتلك التي تم إنشاؤها هنا، و unlocks يحسب عدد اللاعبين الذين يحملون كل واحد.

PUT .../achievements/{achievementId} يأخذ أي من name, description, icon, secret و points; ال key لا يمكن أن تتغير. DELETE يزيله.

قواعد

قاعدة قيمة
مفتاح 1-128 حرفًا: الحروف والأرقام ., _, -، بدءًا بحرف أو رقم
name / description مطلوب؛ بحد أقصى 200/2000 حرفًا
points 0-10000؛ الإعدادات الافتراضية إلى 0
الإنجازات التي أنشأها المالك لكل لعبة 200 (بجانب ما يصل إلى 100 المعلن عنها)
  • الإنجاز المعلن يبقى رمزك. إن إنشاء مفتاح للعبة له عوائد بالفعل 409, وكذلك تحرير أو حذف ملف declared واحد - التحديث التالي سيعيده كرمز خاص بك يعلن ذلك. قم بتغييره في البرنامج النصي الخاص بك أو /describe بدلاً من.
  • إذا أعلن الكود الخاص بك لاحقًا عن المفتاح الذي قمت بإنشائه هنا، يأخذ الإعلان هذا الإنجاز أكثر من (origin يصبح declared). اللاعبون الذين حصلوا عليها يحتفظون بها.
  • لا يمكن حذف الإنجاز الذي فتحه شخص ما (409).
  • 404 يعني أن اللعبة ليست لك؛ 409 على أي من هذه الطرق مع رسالة حول الخادم الواجهة الخلفية تعني أن اللعبة لا تحتوي على أي شيء - فاللعبة المخصصة للمتصفح فقط لا تحتوي على أي شيء يمكنه فتح قفل الإنجاز.

خطوة بخطوة: البرنامج التعليمي: المتصدرين والإنجازات التي حققتها لعبتك.

يفتح المتصل كما UserAchievementDto[]. مع لا titleId يؤدي هذا إلى إرجاع كل فتح للملف حيازة المستخدم، على نطاق اللعبة وعلى نطاق العنوان على حدٍ سواء; يمر ?titleId= لتضييق نطاقه إلى عنوان كتالوج واحد.

تفضل شاشة الإنجاز الخاصة باللعبة GET /api/v1/games/{slug}/achievements، والتي أيضا إرجاع التعريفات التي يمتلكها اللاعب لا بعد مقفلة.

مشترك اتفاقيات API وصف تحليل الاستجابة، والطوابع الزمنية، وترقيم الصفحات، وإعادة المحاولة.
