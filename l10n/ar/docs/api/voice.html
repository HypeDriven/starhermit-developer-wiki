صوت

يوفر صوت StarHermit غرفًا صوتية لكل محادثة عبر REST API (api/v1/voice) بالإضافة إلى WebSocket الثنائي/النص المختلط (ws/v1/voice) لإشارات الصوت وWebRTC. تتطلب جميع نقاط نهاية REST المصادقة. قد يختلف توفر الصوت. تختلف أجسام الخطأ؛ يرى اتفاقيات API.

ترتكز الغرف على أ محادثة الدردشة; العضوية في المحادثة بوابة لكل شيء، لذا فإن قواعد الصداقة في الدردشة تحكم الصوت أيضًا (محادثات جلسة اللعبة تتجاوز الصداقة). الحدود: 3 غرف نشطة لكل محادثة، بحد أقصى 10 مشاركين لكل غرفة، برنامج ترميز "opus".

نقاط النهاية REST

قاعدة: https://api.starhermit.com/api/v1/voice.

طريقة طريق مصادقة وصف
بريد /rooms JWT إنشاء غرفة صوتية للمحادثة
يحصل /rooms?conversationId= JWT قائمة الغرف للمحادثة
يحصل /rooms/{roomId} JWT احصل على غرفة
بريد /rooms/{roomId}/join JWT الانضمام إلى غرفة (مطلوب قبل WS)
بريد /rooms/{roomId}/leave JWT اترك غرفة
بريد /rooms/{roomId}/mute JWT قم بتعيين حالة كتم الصوت الخاصة بك
بريد /rooms/{roomId}/participants/{userId}/server-mute جي دبليو تي (منشئ) كتم صوت المضيف لا يمكن للمشارك رفعه
بريد /rooms/{roomId}/close JWT إغلاق غرفة (منشئ المحتوى فقط)

قم بإنشاء غرفة

POST /rooms

{ "conversationId": "<guid>", "maxParticipants": 10 }

يعود أ VoiceRoomDto.

شكل الغرفة

GET /rooms?conversationId=<guid> → VoiceRoomDto[]; GET /rooms/{roomId} → VoiceRoomDto:

{
  "id": "<guid>",
  "conversationId": "<guid>",
  "creatorUserId": "<guid>",
  "codec": "opus",
  "status": "Active",
  "maxParticipants": 10,
  "createdAt": "2026-07-22T07:00:00Z",
  "participants": [
    {
      "userId": "<guid>",
      "username": "alice",
      "isMuted": false,
      "isConnected": true,
      "joinedAt": "2026-07-22T07:01:00Z"
    }
  ]
}

انضم، غادر، كتم الصوت، أغلق

POST /rooms/{roomId}/join → VoiceRoomDto. هذا الانضمام REST هو مطلوب قبل فتح WebSocket؛ الاتصال بدون إرجاعه 403. تؤدي إعادة الانضمام إلى مسح بيانات المشارك ملك صامت (isMuted); مضيف isServerMuted ينجو من الإجازة وإعادة الاتصال.

POST /rooms/{roomId}/leave → 204.

POST /rooms/{roomId}/mute مع { "muted": true } → 204. هذا هو كتم الصوت الخاص بالمشارك ولا يمكنه مسح كتم صوت المضيف.

POST /rooms/{roomId}/participants/{userId}/server-mute مع { "muted": true } → 204 (المبدع فقط). يتم إسقاط الصوت في حالة ضبط أي من كتم الصوت.

POST /rooms/{roomId}/close → 204 (المبدع فقط).

اذكر كتم صوتك عند الاتصال بدلاً من وراثة ما يتذكره الصف.

مقبس ويب: ws/v1/voice

الاتصال ب wss://api.starhermit.com/ws/v1/voice?roomId=<guid> مع JWT عبر Authorization رأس, ?ticket=، أو ?access_token=. راحة سابقة join مطلوب.

البروتوكول مختلط:

الإطارات الثنائية – الصوت

الإطارات الثنائية تحمل الصوت (مثل Opus). يقوم الخادم بترحيل كل إطار إلى المشاركين الآخرين على النحو التالي:

[16-byte senderUserId][audio…]

يبدأ الخادم بـ مصادق عليه معرف المرسل ولا يثق مطلقًا في المرسل الذي يقدمه العميل. يتم إسقاط الصوت من المستخدمين الذين تم كتم صوتهم. الحدود: 100 حزمة/الثانية لكل مستخدم، الحد الأقصى للإطار 4000 بايت.

إطارات النص - التحكم في العميل → الخادم

{ "type": "mute", "muted": true }

{ "type": "speaking", "speaking": true }

{ "type": "rtc", "to": "<guid>", "payload": { } }

{ "type": "deafen", "deafened": true }

rtc الحمولات عبارة عن إشارات WebRTC غير شفافة، ويتم توجيهها إلى المشارك الموجه إليه. deafen يمنع الصوت الثنائي المُرحَّل الوارد لهذا المقبس؛ لا يتم كتم الصوت تلقائيًا الصوت الصادر أو اتصال نظير منفصل. قم بتطبيقها محليًا عندما يختار اللاعب الصم.

يعرض شكل مشارك REST كتم صوته، وليس كتم صوت المضيف. القائمة الصوتية الأولية والانضمام إلى الأحداث تشمل serverMuted; لا يوجد حدث دفع منفصل لتغيير كتم صوت المضيف. إذا كانت لعبتك تستخدم P2P الصوت، يجب أن تكون إشارات كتم صوت المضيف وتنفيذها جزءًا من تكامل الوسائط الخاصة بك.

عندما ينقطع آخر مقبس صوت، تنتهي عضوية غرفة الصوت. اتصل بالراحه join مرة أخرى من قبل إعادة الاتصال واستعادة كتم الصوت المقصود قبل إرسال الصوت.

الخادم → أحداث العميل

ظرف: { "event": "<name>", "data": { } }.

حدث data
voice.roster { "roomId", "participants": [{ "userId", "muted", "serverMuted" }] } - أرسلت إلى الوافد الجديد
voice.participant_joined { "roomId", "userId", "muted", "serverMuted" }
voice.participant_left { "roomId", "userId" }
voice.mute_changed { "roomId", "userId", "muted" }
voice.deafened `{ "معرف الغرفة", "معرف المستخدم", "يصم الآذان" }
voice.speaking { "roomId", "userId", "speaking" }
voice.rtc { "roomId", "from", "payload" }

نموذج لنمط التكامل (من التنفيذ المرجعي للشطرنج)

يتم الاشتراك في الصوت لكل جلسة لعبة. عميل نموذجي enable() تدفق:

  1. GET /api/v1/voice/rooms?conversationId=<chatConversationId> للعثور على غرفة موجودة، وإلا POST /api/v1/voice/rooms لإنشاء واحدة.
  2. POST /api/v1/voice/rooms/{roomId}/join.
  3. يفتح ws/v1/voice?roomId=<guid>.

في تنفيذ مرجع الشطرنج، يتم تشغيل الصوت عبر WebRTC P2P مع التفاوض المثالي؛ يتم تبادل الإشارات من خلال rtc رسائل التحكم ({ "sdp": … } / { "ice": … } الحمولات)، مع مسار Opus الثنائي الذي يتم ترحيله بواسطة الخادم باعتباره البديل.

رموز الإطلاق على مستوى اللعبة يمكن استخدم Voice REST وWebSocket للغرف الملحقة بجلسات اللعب الخاصة بهم.

انظر أيضا

  • خيارات الصوت - مستوى الصوت الأساسي والميكروفون وعناصر التحكم بالضغط والتحدث، مع غطاء التشغيل الذي تم اكتشافه تلقائيًا
  • محادثة - الغرف مرساة للمحادثات؛ فضح جلسات اللعبة chatConversationId
  • ألعاب - جلسات اللعبة وإطلاق الرموز
  • تتابع - بايت مروحي لرمز الشبكة الخاص باللعبة

يرى التوافق الاعتماد و العقود المقروءة آليا.
