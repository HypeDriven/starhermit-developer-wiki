اتفاقيات API

يستخدم REST https://api.starhermit.com/api/v1/...; استخدام المقابس wss://api.starhermit.com/ws/v1/.... يمكن الاتصال بالألعاب المستضافة /api/v1/... و /ws/v1/... على أصلهم. يستخدم العملاء الأصليون أصل واجهة برمجة التطبيقات العامة. تحتاج صفحة التطوير على أصل آخر إلى أصل CORS مسموح به في اللعبة المضيف؛ إن تعيين عنوان URL الأساسي لـ SDK وحده لا يسمح بهذا الأصل.

الطلبات والردود

أرسل JSON مع Content-Type: application/json، باستثناء تحميلات حزمة gzip الأولية. أسماء أعضاء JSON هي حالة الجمل. إرسال بيانات اعتماد حاملها في REST Authorization header.

إجابة كيفية قراءتها
200 / 201 JSON تحليل الكائن أو الصفيف الموثق؛ تحمل حقول إضافية
204 النجاح بلا جسد؛ لا تتصل response.json()
302 إعادة توجيه تسجيل الدخول/تأكيد المتصفح؛ التنقل بدلاً من جلب صفحات OAuth
304 القراءة الشرطية دون تغيير؛ الاحتفاظ بالبيانات التي تمتلكها بالفعل
الصورة، المرفق، الحفظ السحابي قراءة البايتات باستخدام نوع محتوى الاستجابة وعقد نقطة النهاية
خطأ اقرأ الحالة أولاً، ثم قم بتحليل الجسم بشكل دفاعي

نموذج الخطأ الشائع هو { "error": "...", "code": "..." }، مع الحقول الاختيارية اعتمادًا على نقطة النهاية. error غالبا ما تكون قابلة للقراءة من قبل الإنسان؛ code هو تمييز مستقر حيثما تقدم. تضع المصطلحات وبعض نقاط النهاية الأخرى أداة تمييز مباشرة error. تعود بعض نقاط النهاية بشكل عادي نص أو نص فارغ أو كائن تفاصيل مشكلة التحقق من الصحة title, status و errors. يجب ألا يفترض العملاء أن كل استجابة غير ناجحة هي JSON أو تحتوي على نفس الحقول.

export async function readResponse(response) {
  if (response.status === 204 || response.status === 304) return null;
  const text = await response.text();
  let body;
  try { body = text ? JSON.parse(text) : null; } catch { body = text || null; }
  if (!response.ok) {
    const message = (body && typeof body === 'object' && (body.error || body.message || body.title))
      || (typeof body === 'string' && body) || response.statusText;
    throw Object.assign(new Error(message), {
      status: response.status, code: body?.code, body,
      retryAfter: response.headers.get('Retry-After'),
    });
  }
  return body;
}

الوقت والأحجام والقيم الخالية

  • createdAt, updatedAt, finishedAtوالطوابع الزمنية للحساب/الموارد المماثلة هي سلاسل ISO 8601 مع إزاحة. علاج غائب أو null القيم الاختيارية غير متوفرة.
  • ctx.now, summary.deadline، قائمة الجلسة deadline، و /time.serverTime هي عدد صحيح يونكس ميلي ثانية. تحويل مع new Date(value)، لا Date.parse(value).
  • القيم الحدية بالبايت هي بايت، وليست أحرف Base64. تحميل Base64 JSON أكبر من حجمه محتويات فك التشفير. استخدم الحد الفعال الذي أبلغت عنه نقطة النهاية عندما يكون متاحًا.
  • الإغفال، nullوالكائن الفارغ ليس متكافئًا عالميًا. إعدادات PATCH يزيل أ مفتاح اسمه مع null; إعدادات مفتاح واحد PUT مخازن null كقيمة. مجموعة PUT يستبدل الخريطة بأكملها. اقرأ قواعد التحديث الخاصة بكل نقطة نهاية.
  • يتم دمج تصحيح الإعدادات مفاتيح المستوى الأعلى. تحل قيمة الكائن المتوفرة محل قيمة هذا المفتاح؛ ولا يقوم بدمج الخصائص المتداخلة بشكل متكرر.

ترقيم الصفحات

الترحيل يعتمد على مكان واحد page/pageSize يتم دعمها. تختلف واجهات برمجة التطبيقات المختلفة عن عمد مظاريف الاستجابة؛ لا تقم بإعادة استخدام المحلل اللغوي الذي يفترض اسم حقل عدد واحد.

منطقة شكل الجمع الافتراضي / الحد الأقصى لحجم الصفحة
عناوين البرامج وبنياتها { items, totalCount, page, pageSize } 20 / 100
رسائل الدردشة { conversationId, items, totalCount, page, pageSize } 50 / 100
إدخالات المتصدرين { items, total, page, pageSize } 20 / 100
البرامج الخارجية { items, total, page, pageSize } 20؛ طلب حجم صفحة إيجابي صغير
التقارير وسجلات أعطال الحاويات وقوائم الإشراف { items, total, page, pageSize } 20 / 100
الجلسات والأصدقاء وقوائم الألعاب والإنجازات المصفوفات الحدود القصوى الخاصة بنقطة النهاية؛ لا يوجد مؤشر عام للصفحة التالية
تغذية سحب الاعتدال على أساس المؤشر احتفظ بالمؤشر الذي تم إرجاعه؛ التعافي من 410 كما هو موثق

تعكس البيانات التعريفية لصفحات الاستجابة الصفحة المقدمة حيثما كان ذلك متاحًا. الصفحات المرجعية و العقود المقروءة آليا وصف معلمات الاستعلام الخاصة بنقطة النهاية.

إعادة المحاولة والتزامن

الموقف فعل
تم رفض رمز الوصول إلى الحساب باستخدام 401 التحديث مرة واحدة، باستخدام طلب تحديث مشترك واحد؛ ثم قم بتسجيل الدخول إذا تم الرفض
انتهت صلاحية رمز الإطلاق الحصول على رمز مميز جديد من خلال تسجيل الدخول/المشغل؛ الرموز منتهية الصلاحية لا يمكنها تجديد نفسها
403 terms_acceptance_required قم بعرض الشروط الحالية وقبولها بشكل صريح، ثم أعد المحاولة
آخر 403 حل النطاق أو العضوية أو الأذونات أو حالة الحساب؛ لا تقم بالتحديث في حلقة
409 حل تعارض التكرار/الحالة/المراجعة؛ أعد القراءة قبل تغيير المورد
الحفظ السحابي 412 قم بتحميل الإصدار الأحدث ودع اللعبة تندمج أو تعتمده
429 أو مؤقتة 503 شرف Retry-Afterوأضف الارتعاش وإعادة المحاولة المقيدة
فشل الشبكة أثناء الكتابة قد تكون النتيجة غير معروفة. فحص حالة المورد قبل تكرار الإجراء

Retry-After يمكن أن يكون ثواني أو تاريخ HTTP. لا تخترع رأسًا غير فعال: واجهة برمجة التطبيقات (API) لا تفعل ذلك وعد بآلية مفتاح العجز العام. يمكن إعادة محاولة إنشاء الجلسة أو إنشاء دعوة مورد آخر أو يتعارض مع الأول. تفضل القراءات والعمليات العاطلة صراحةً إعادة المحاولة التلقائية. تحديث التناوب، والتحميلات الكاملة، والموافقة على الشروط، ونتائج اللعبة النهائية لكل منها لديهم قواعدهم الخاصة.

من أجل عمليات الكتابة للمقارنة والمبادلة، استخدم ETags للحفظ السحابي، الغرفة expectedRevision، أو مراجعات الاعتدال حيث يدعم. الكتابة الناجحة لا تعني بالضرورة نشر حاوية مكتملة؛ التحقق منها الحالة قبل إرسال اللاعبين إلى بناء جديد. يرى استكشاف الأخطاء وإصلاحها.
