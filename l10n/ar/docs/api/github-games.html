ألعاب جيثب

انشر لعبة من مستودع GitHub على ستارهيرميت، أو قم بتسجيل لعبة ويب مستضافة بالفعل. بالنسبة لألعاب المستودع، يقرأ النظام الأساسي starhermit.txt، يستنسخ الريبو، ويقدمه في <slug>.starhermit.com. لأن /api و /ws يتم إنشاء وكيل من نفس الأصل من هذا النطاق الفرعي، وهو ما تحتاجه اللعبة المستضافة على النظام الأساسي لا يوجد تكوين CORS أو قاعدة API. يتحكم الالتزام المثبت في إصدار المستودع المباشر. ال تنفيذ مرجع الشطرنج يتم نشره بهذه الطريقة ويعمل كمثال مرجعي للنموذج.

عنوان URL الأساسي: https://api.starhermit.com. جميع الطرق تحت api/v1/... وتتطلب JWT ما لم تتم الإشارة إليه.

يمكن أن تعلن ملفات العميل المستضافة عمر ذاكرة التخزين المؤقت للمجلد و أصول CORS الإضافية في starhermit.txt. يتم نشر هذه السياسات مع ملفات العميل؛ يحتفظ بالدمج الخالي من البيان الإعدادات الحالية، في حين يحل البيان المرفق محلها.

البيان: starhermit.txt

مكان starhermit.txt في جذر الريبو. شكل: key=value خطوط, # يبدأ التعليق.

name=Your Game
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html        # repo-relative HTML entry
cover=art/cover.png      # optional cover art for the library tile; or an https:// URL
description=One-line pitch\nSecond line   # optional; or description.file=DESCRIPTION.md
release_notes.file=CHANGELOG.md          # optional; or release_notes=inline text
owner=<starhermit user id>  # UUID from GET /api/v1/me; do not use username/nickname
# Choose at most one authoritative backend, or omit both for a browser-only game:
server=server.js         # sandboxed JavaScript; see game-scripts.md
# container.image=ghcr.io/owner/game@sha256:<64 lowercase hex>; see container-games.md

control.up=KeyW+ArrowUp | Move forward
control.shoot=Space | Shoot
  • لا يوجد slug المفتاح: يقوم النظام الأساسي بتعيين معرف مستخدم ويستخدمه كمجال فرعي (<uid>.starhermit.com) ومساحة اسم API للعبة (/api/v1/games/<uid>/…).
  • cover (الأسماء المستعارة cover_art, coverart) هو العمل الفني الذي يظهر على لوحة مكتبة اللعبة: مسار متعلق بملف التشغيل، أو مطلق https:// عنوان URL. اختياري — بدون واحد، يعرض المربع الرمز المفضل لموقعك. أعد القراءة عند كل نشر، لذا فإن تغيير السطر يغير الغلاف. يرى فن الغلاف لمحاصيل البلاط.
  • description / release_notes (أو description.file / release_notes.file، الذي اسمه أ .md/.markdown/.txt الملف المتعلق بالبيان) عبارة عن نص اختياري للعبتك. تتم إعادة قراءتها عند كل عملية نشر مثل cover. يرى الوصف وملاحظات الإصدار.
  • server يعلن عن واجهة JavaScript الخلفية ذات وضع الحماية؛ يرى game-scripts.md.
  • container.image يعلن عن الواجهة الخلفية للحاوية؛ يرى container-games.md. يجب أن يتم تثبيته بشكل ملخص، واستضافته في مساحة اسم مالك GitHub الذي تم التحقق منه في سجل مدرج في القائمة المسموح بها، وقد يكون مصحوبًا container.port, container.health, container.memory_mb, container.cpu، وغير سرية container.env.* قيم.
  • يعد كلا المفتاحين الخلفيين اختياريين للعبة متصفح خالصة، لكنهما متنافيان مع بعضهما البعض.

روابط التحكم الافتراضية

قد تعلن اللعبة عن صفر أو أكثر من إجراءات متصفح سطح المكتب:

control.<action>=<code>[+<code>...][ | <label>]
  • الإجراءات صغيرة [a-z0-9_]{1,32} المعرفات والاحتفاظ بالأمر الواضح.
  • الرموز هي KeyboardEvent.code قيم؛ + يفصل المفاتيح البديلة لإجراء واحد.
  • يتم عرض التسمية الاختيارية في واجهات المستخدم لإعادة تعيين التحكم والإعدادات الافتراضية لمعرف الإجراء.
  • قد يعلن البيان عن ما يصل إلى 32 إجراء و4 رموز لكل إجراء. لا يمكن استخدام الرمز من قبل عملين. يتم تجاهل خطوط التحكم غير الصالحة.
  • ألعاب بدون control.* الإعلانات ليس لها ضوابط API/UI (404 "This game declares no controls."). تتم إعادة قراءة الإعلانات من كل إصدار منشور — كل نشر، وتحميل مجلد واستبدال دفع الحزمة. خطوة بخطوة: البرنامج التعليمي: إضافة عناصر التحكم إلى لعبتك.

يمكن للاعبين تجاوز هذه الإعدادات الافتراضية في كل لعبة من خلال واجهة برمجة تطبيقات التحكم في الألعاب.

يحصل /api/v1/me/github JWT حالة رابط هوية GitHub → { linked, login }

سجل لعبة

POST /api/v1/me/github-games

{
  "repoUrl": "https://github.com/HypeDriven/starhermit-chess",
  "displayName": "StarHermit Chess",
  "launchPath": "index.html"
}

رغم اسمها التاريخي repoUrl يقبل ثلاثة مصادر إطلاق:

  1. A github.com/<owner>/<repo> مستودع. تقرأ الواجهة الخلفية بيانها ويمكنها نشره لاستضافة StarHermit.
  2. عنوان URL لصفحات GitHub مستضاف بالفعل، مثل https://owner.github.io/game/. مستودع يتم استنتاج الهوية من عنوان URL؛ يتم تشغيل عنوان URL نفسه، بدون استنساخ أو تثبيت.
  3. أي عامة أخرى http:// أو https:// عنوان URL للعبة الويب المستضافة. يتم إطلاقه مباشرة و لا يشارك في المطالبة بملكية GitHub.
  • displayName و launchPath هي احتياطيات اختيارية. إنها مفيدة لمستودعات الطرف الثالث بدون بيانات وصفية موثوقة للبيان؛ عنوان URL المستضاف المباشر هو في حد ذاته موقع الإطلاق.
  • بالنسبة لأصحاب المستودعات الذين تم التحقق منهم، تقوم المنصة بالتحقق من صحتها starhermit.txt.
  • اختياري server= البرنامج النصي أو container.image= توفر الواجهة الخلفية لعبة موثوقة؛ يرى game-scripts.md و container-games.md. استضافة الحاوية مفتوحة لأي مستخدم مسجل الدخول على starhermit.com؛ يمكن أن يؤدي النشر المستضاف ذاتيًا إلى تقييده بالقائمة المسموح بها للمشغل.
  • تحتاج الواجهة الخلفية للخادم المعلنة إلى مالك مثبت. تقديم الريبو الذي يعلن server= أو container.image= بدون تسجيل الدخول إلى GitHub أو owner= الدليل هو 403 (تسمية كلا الدليلين)، وليست قائمة للمتصفح فقط تتظاهر بوجود واجهة خلفية.
  • الحدود: 100 لعبة لكل مستخدم (يمكن تجاوزها بواسطة المشغل لكل حساب). تسجيل عوائد مكررة 409.

تتضمن حالات التسجيل/النشر ما يلي: InvalidUrl, LimitReached, Duplicate, MissingManualMetadata, MissingStarhermitTxt, InvalidLaunchPath, InvalidServerScriptPath, InvalidContainerImage, ServerProvisionConflict, RemovedByOwner.

أخطاء تستخدم الشكل القياسي:

{ "error": "..." }

أضف لعبة من مجلد محلي

POST /api/v1/me/github-games/upload → 201

النظير لتسجيل عنوان URL: لا يوجد مستودع، ولا يتم استنساخ أي شيء. المجلد يسافر كواحد .tar.gz على نص الطلب وتستضيف المنصة ما تحتوي عليه. نفس الأرشيف تنسيق كما دفع حزمة، وبالتالي فإن نفس العبوة تعمل لكليهما.

اللعبة التي تم إنشاؤها لديها gameSlug من البداية، سواء أعلن عن خادم أم لا، لذلك أ يمكن استخدام التحميل في المتصفح فقط الضوابط, إعدادات لكل لاعب، إنه فتحة الحفظ السحابي, غرف الوقت الحقيقي وإطلاق الرموز مثل أي لعبة أخرى.

client/           the game's files, published as-is
starhermit.txt    name= and launch= instead of the query parameters

البيان اختياري ل نقطة النهاية هذه - يمكن لمعلمات الاستعلام توفير نفس القيم - و يرسل عملاء StarHermit دائمًا واحدًا، مبنيًا على حقول البيان الخاصة بهم. شحن الملف بالداخل لا يزال البناء الخاص بك يستحق القيام به: فهو يجعل البناء يصف نفسه بنفسه ويملأ هذه الحقول مسبقًا، لذلك يمكن إعادة تحميلها دون تذكر القيم التي تحتاجها. يرى ال starhermit.txt يظهر للتنسيق، ولاحظ ذلك كل شيء تم تحميل الملف المجاور للبيان - تحميل بناء قابل للتوزيع، وليس شجرة مصدر.

أرسل البايتات مباشرة - وليس بيانات النموذج متعدد الأجزاء - باستخدام Content-Type: application/gzip:

tar -czf game.tar.gz client/ starhermit.txt

curl -X POST "https://api.starhermit.com/api/v1/me/github-games/upload?displayName=My%20Game" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/gzip" \
  --data-binary @game.tar.gz

{
  "game": { "id": "...", "displayName": "My Game", "launchPath": "index.html", "hosting": { "hostingEnabled": true } },
  "bytesReceived": 4194304
}

يتم حل البيانات التعريفية بهذا الترتيب، لذلك لا تحتاج معظم المجلدات إلى معلمات استعلام على الإطلاق:

  1. ?displayName= / ?launchPath= على الطلب.
  2. name= / launch= في أ starhermit.txt في جذر الأرشيف.
  3. index.html في جذر client/ - يستخدم كمسار الإطلاق عندما لا يوجد أي اسم آخر.

ملاحظات خاصة بهذا المسار:

  • اللعبة مباشرة بمجرد عودة المكالمة. لا يوجد استضافة أو نشر منفصل خطوة: deployStatus يكون live و deployedCommitSha يكون null، لأنه لا يوجد التزام.
  • لا يمكن إعادة إنشاء الملفات، لذلك لا يقوم النظام الأساسي بإعادة نشرها من أي مكان أبدًا. لعبة وأضاف بهذه الطريقة يحمل contentSource: upload ويحتفظ ببنيته التي تم تحميلها حتى تقوم بالنشر واحد آخر. ادفع بناءًا جديدًا باستخدام نقطة نهاية الحزمة أو قم بتحميل المجلد مرة أخرى.
  • عدم وجود مستودع يعني عدم المطالبة. ownerLogin فارغ، لذا لا يمكن لأي تسجيل دخول إلى GitHub مطابقته على الإطلاق؛ repoUrl يحمل الاصطناعية upload:<id> القيمة بدلاً من عنوان URL.
  • A server/image.tar مرفوض هنا (422). تحتاج صورة الخادم إلى لعبة متوفرة قم بإرفاقه، وهو غير موجود حتى يتم إنشاء اللعبة - أنشئ اللعبة أولاً، ثم ادفع الصورة ل /{id}/bundle.
  • تم رفض مسار التشغيل الذي يسمي ملفًا لا يحتوي عليه الأرشيف (422) أثناء التحميل لا يزال في مرحلة التدريج، بدلاً من أن يصبح 404 لكل لاعب.

الحدود هي نفس أي دفعة أخرى: انظر حدود التحميل.

يمكن للمجلد الذي تم تحميله إحضار الواجهة الخلفية للخادم الخاص به

إذا كان الأرشيف starhermit.txt يعلن منطق الخادم، التحميل يوفرها أيضًا - وهو نفس الشيء الذي يفعله تدفق المستودع، بدون مستودع. اختر واحدة الاسلوب؛ تم رفض إعلان كلاهما.

تصريح ماذا يحدث
server=path/to/server.js الخلفية البرنامج النصي. يسافر الملف داخل المجلد الذي قمت بتحميله، لذلك تتم قراءة مصدره مباشرة من الأرشيف - ولا يوجد شيء لجلبه. يرى game-scripts.md.
container.image=name@sha256:… واجهة خلفية للحاوية، مثبتة على الملخص كما هو الحال دائمًا. يرى container-games.md. يتم دفع الصورة نفسها بعد ذلك إلى /{id}/bundle.

تؤدي حالات الرفض هنا إلى فشل عملية الإنشاء بأكملها - ولا ينجو أي صف لعبة نصف مكتمل من صف واحد:

  • server= تسمية ملف لا يحتوي عليه الأرشيف.
  • server= لافتا خارج ملفات العميل (../).
  • التصريح بكلا الأمرين server= و container.image=.
  • طلب حاوية معطلة للحاويات، أو من مالك غير معتمد لها.

فن الغلاف

الصورة المعروضة على بلاط لعبتك في المكتبة. اضبطه في كلتا الحالتين — أيًا كان ما تستخدمه، فإن مجهول GET /api/v1/github-games/{id}/cover هو ما يخدم ذلك:

  • في بنيتك — a cover= خط في starhermit.txt، تسمية صورة نسبة إلى الإطلاق ملف أو مطلق https:// عنوان URL. أعد القراءة عند كل عملية نشر، حتى يظل مستودعك هو مصدر الحقيقة.
  • تم الرفع — PUT /api/v1/me/github-games/{id}/cover مع الصورة المشفرة Base64. هذا هو ما هي لوحة القيادة على شبكة الإنترنت إدارة → صورة الغلاف ما يفعله، وما يمكن لمشغل StarHermit أن يفعله لك.
PUT /api/v1/me/github-games/{id}/cover
Authorization: Bearer <token>
Content-Type: application/json

{ "imageBase64": "iVBORw0KGgoAAAANSUhEUg..." }

تحميل يتجاوز البيان عمدا: نشر يعيد القراءة starhermit.txt يجب لا تتراجع أبدًا عن الفن الذي اختاره شخص ما يدويًا. DELETE /api/v1/me/github-games/{id}/cover هو طريق العودة — فإنه يسقط التحميل والبيان cover= ينطبق مرة أخرى.

PNG أو JPEG أو GIF أو WEBP أو BMP أو SVG، حتى 4 ميجا بايت. يتم استنشاق النوع من البايتات، لذلك أ Content-Type أنت تؤكد ليست هناك حاجة ولا يعتقد، والبايتات التي ليست صورة قابلة للفك يتم رفض مع 400. قريب cover= يجب أن ينتهي المسار في .png, .jpg/.jpeg, .gif, .webp أو .svg (لا ..، لا الرائدة /); يتم إسقاط قيمة غير قابلة للاستخدام بدلاً من فشل لعبة.

فن الغلاف هو فن الملصق: كلتا المكتبتين قم بقياسه لملء البلاط والمحصول المركزي مهما كان ما يفعله غير مناسب. البلاط ليس بنفس الشكل.

ادفع حزمة اللعبة

POST /api/v1/me/github-games/{id}/bundle ينشر مخرجات مبنية دون أن يطلب من StarHermit ذلك استنساخه مرة أخرى. يجب أن يمتلك المتصل اللعبة المسجلة. أرسل .tar.gz بايت مباشرة - لا بيانات النموذج متعددة الأجزاء - مع Content-Type: application/gzip:

client/            optional static client files; must include the registered launch file
server/image.tar   optional output from `docker save`
starhermit.txt     optional manifest copy for bundle portability
remove.txt         merge only: client-relative paths to delete, one per line

على الأقل client/ أو server/image.tar يجب أن يكون موجودًا (قد يكون الدمج أيضًا فقط remove.txt). يتم تبديل ملفات العميل تلقائيًا. أ يتم تحميل صورة الخادم، وتثبيتها بواسطة النظام الأساسي، ووضعها في قائمة انتظار نشر الحاوية إعادة التشغيل على تلك الصورة. الصورة التي تم تحميلها لها الأسبقية على مرجع التسجيل الخاص بالبيان، وأكثر من أ server= خط؛ بيان يعلن كلاهما server= و container.image= تم رفضه قبل أن يتم تحميل أي شيء. يتم تجاهل أي شيء آخر في الأرشيف.

إن تحميل الصورة هو في حد ذاته إعلان. إذا لم يكن للعبة واجهة خلفية للخادم حتى الآن — المجلد الذي تم تحميله والذي أعلن أنه لا شيء - يدفع server/image.tar أحكام واحدة من الملخص فقط محملة، تحت gameSlug اللعبة لديها بالفعل. ليس عليك تسمية صورة مثبتة بالملخص في ملف واضح أولاً، والذي كان دائريًا: يجب أن يكون التعريف موجودًا قبل أن يتمكن من تلقي صورة، وكانت الصورة هي الشيء الوحيد الذي يمكن أن يصفه.

تطبق عملية إعادة الدفع على مقابض الحاوية التي يعلن عنها بيانها، وتلك فقط. يشمل starhermit.txt في الحزمة مع تغيير container.port, container.health, container.memory_mb أو container.cpu ويلتقطه النشر عند إعادة التشغيل؛ اترك المقبض و فهو يحتفظ بكل ما قمت بتعيينه في المرة الأخيرة. احذف البيان بالكامل ولا شيء يتعلق بالنشر التغييرات باستثناء الصورة.

يقوم عملاء StarHermit ببناء هذه الحزمة لك، من مجلد أو واحدة .tar:

  • ملفات العميل - مجلد توزيع اللعبة، أو .tar منه. مجلد معبأة تحت client/; a .tarتتم إعادة إدخالات 's إلى هناك (أرشيف موجود بالفعل ضمن client/ بقي وحده). usstar فقط - يتم رفض أرشيفات GNU ذات الأسماء الطويلة وPAX، لأن إعادة توجيهها تعني إعادة كتابة كتل البيانات الوصفية التي تسمي الإدخال التالي.
  • خادم مخصص — مجلد توزيع الخادم، أو docker save .tar من تلقاء نفسها. من مجلد فقط البيان و image.tar تم تحميلها: الصورة تحتوي بالفعل على الخاص بك ملفات الخادم الخاصة، لذا فإن تعبئة الباقي سترسل غيغابايت إلى النظام الأساسي لتجاهلها.

وفي كلتا الحالتين starhermit.txt قابل للتحرير في مربع الحوار. مهما كان تحمل البنية المختارة ملء الحقول مسبقًا، وكل ما تحتويه مكتوب في جذر الحزمة - لذا البناء بدون بيان قابل للنشر، والذي يتم شحنه كملف .tar لا يزال من الممكن أن يكون له بيانه محدث.

docker save my-game-server:release -o image.tar
mkdir -p bundle/server
mv image.tar bundle/server/image.tar
cp starhermit.txt bundle/
tar -C bundle -czf game-bundle.tar.gz .

curl -X POST "https://api.starhermit.com/api/v1/me/github-games/$GAME_ID/bundle" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/gzip" \
  --data-binary @game-bundle.tar.gz

التحديثات الجزئية: ?mode=merge

الدفعة هي أ يستبدل إلا إذا طلبت خلاف ذلك: الأرشيف هو اللعبة بأكملها، وأي شيء ليس موجودًا فيها لقد ذهب. ?mode=merge (HTTP ومقبس التحميل على حد سواء) يجعله رقعة من العميل الحي الملفات - الحل لإعادة تحميل غيغابايت من الأصول التي لم تتغير لإصلاح ملف واحد.

printf '%s\n' '# one client-relative path per line; a directory removes everything under it' \
    'assets/old-music.ogg' 'levels/cut/' > remove.txt
tar czf patch.tar.gz client/index.html client/js/app.js remove.txt

curl -X POST "https://api.starhermit.com/api/v1/me/github-games/$GAME_ID/bundle?mode=merge" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/gzip" \
  --data-binary @patch.tar.gz

مع mode=merge:

  • الملفات تحت client/ تتم إضافتها أو الكتابة فوقها
  • المسارات في الجذر remove.txt (# تعليقات؛ يتم حذف الدليل الذي يزيل الشجرة الفرعية بالكامل).
  • يبقى كل ملف مباشر آخر كما هو تمامًا

يتم تنظيم الشجرة المدمجة كنسخة ويتم تبديلها ذريًا - يرى اللاعبون اللعبة القديمة أو اللعبة القديمة جديدة تمامًا، لا تخلط أبدًا. ويحدها النتيجة ألعاب بدل، وليس للتحميل، لذلك لا يمكن للعبة أن تتجاوز حدودها برقعة صغيرة واحدة في كل مرة. يتم الدمج فقط حول ملفات العميل؛ أ server/image.tar يتم تحميله تمامًا كما في الاستبدال. رقعة تحمل رقم starhermit.txt أوراق غلاف الفن كما كان.

تم رفض الدمج (409/422، لا شيء يتغير) عندما لا يتم نشر أي شيء في اللعبة بعد، عندما من شأنه إزالة ملف الإطلاق، أو متى remove.txt نقاط خارج اللعبة. أ remove.txt في أ تم أيضًا رفض الاستبدال العادي (422)، لأنه لا يمكن أن يعني إلا شيئًا لم تفعله تنوي. mode يجب أن يكون replace (الافتراضي) أو merge; أي شيء آخر هو 400.

نفس المعلمة تعمل على المقبس: ws/v1/game-upload?gameId=…&mode=merge. ال ready إطار يرددها كما "apply":"merge".

تقوم نقطة النهاية بتحديث لعبة مسجلة موجودة؛ فهو لا يقوم أبدًا بإنشاء سجل اللعبة - لذلك، انظر إضافة لعبة من مجلد محلي. هو - هي يستطيع توفير اللعبة الواجهة الخلفية للخادم، كأثر جانبي لتحميل صورة الخادم في لعبة لا تحتوي على أي صورة. انظر البرنامج التعليمي للنشر على خادم مخصص.

تحميل من CI/CD

لا تحتفظ برمز OAuth التفاعلي في سر المستودع. قم بتسجيل الدخول من خلال OAuth مرة واحدة واستخدمه تلك الجلسة لإضافة مفتاح نشر مُسمى بشكل منفصل POST /api/v1/me/public-keys. سي.آي يمكن بعد ذلك التوقيع على الوظيفة /auth/public-key/challenge، قم باستبدالها على /auth/public-key/complete، واستخدام رمز الوصول الذي تم إرجاعه لمدة 15 دقيقة على نقطة نهاية الحزمة هذه.

يعمل مفتاح النشر كحساب مالك، لذا يجب أن يمتلك هذا الحساب اللعبة المستهدفة. لا يمكن ذلك إضافة مفتاح آخر أو إلغاء المفاتيح الأخرى. يمكنها إلغاء نفسها من خلال /me/public-keys/current; إدارة التسجيل والمفاتيح الأخرى من جلسة مصادقة OAuth. استخدم مفتاحًا واحدًا لكل البيئة بحيث يمكن تعطيل سير عمل واحد دون إيقاف سير العمل الآخر. المحفوظات أكثر من تقريبا يجب أن يستخدم 100 ميجابايت وسيلة النقل WebSocket أدناه.

يرى يتم إنشاء التحميل من CI/CD باستخدام مفتاح عام مسجل في OAuth لإنشاء المفاتيح، والإعداد السري لـ GitHub، والبرنامج النصي الكامل لتوقيع التحدي/التحميل، والبرنامج الثابت و تخطيطات حزمة الحاوية وسير عمل GitHub Actions.

التحميل عبر WebSocket

GET /ws/v1/game-upload (يرقي) - استخدم هذا لأي شيء يزيد حجمه عن 100 ميجابايت.

يرفض CDN الموجود أمام واجهة برمجة التطبيقات (API) نص طلب HTTP بشكل تقريبي 100 ميجا بايت مع أ 413 منها الخاصة. هذا الرفض لا يصل أبدًا إلى المنصة، لذا فهو لا يحمل أي معنى limitBytes ويظهر في أي سجل لك يستطيع القراءة - أ 413 مع لا limitBytes الحقل هو CDN، وليس بدل لعبتك، وهو اثنان أوامر من حجم أكبر. أي واقعية docker save سوف يضربها.

الإطارات المرسلة بعد ترقية WebSocket ليست نص طلب، لذا لا ينطبق الحد الأقصى. فقط النقل يختلف تتسلسل الإطارات الثنائية في البايتات بالضبط التي توجهها HTTP اقرأ، وانتقل عبر نفس المسار، وكل نص رفض وبدل ونجاح هو HTTP كان من الممكن أن يتم إنتاج المسار - بحيث يمكن للعميل مشاركة مسار رمز واحد عبر كليهما.

wss://api.starhermit.com/ws/v1/game-upload?gameId=$GAME_ID&access_token=$TOKEN
wss://api.starhermit.com/ws/v1/game-upload?gameId=$GAME_ID&mode=merge&access_token=$TOKEN
wss://api.starhermit.com/ws/v1/game-upload?displayName=My%20Game&launchPath=index.html&access_token=$TOKEN

يمر gameId للدفع إلى لعبة تمتلكها ( /{id}/bundle طريق)؛ حذفها وتمرير displayName/launchPath لإنشاء واحد من مجلد ( /upload طريق). يذهب الرمز المميز إلى سلسلة استعلام لأن المتصفح لا يمكنه تعيين Authorization رأس على مصافحة WebSocket؛ إنه كذلك تم تحديده مرة واحدة، عند المصافحة، وبالتالي فإن التحميل الذي يتجاوز عمر رمز الوصول الخاص به لا يزال ينتهي.

اتجاه إطار معنى
الخادم → {"type":"ready","mode":"bundle","apply":"replace","limitBytes":N,"heartbeatSeconds":15} تمت تسوية البدل وفحص المساحة الحرة. ابدأ في الإرسال. mode يكون bundle أو create. apply يكون merge عندما طلبت التحديث الجزئي.
→ الخادم ثنائي وحدات بايت للأرشفة، مقسمة كيفما تشاء - لا يقوم الخادم أبدًا بإعادة تجميع الرسائل، لذا فإن 256 كيلو بايت - 1 ميجا بايت هو الإعداد الافتراضي الجيد. متسلسلة، يجب أن تكون الإطارات الخاصة بك هي نفسها تمامًا .tar.gz.
الخادم → {"type":"ack","bytesReceived":N} تقدم الاستلام، تقريبًا كل 8 ميجابايت. قم بقيادة شريط التقدم الخاص بك من هذا.
→ الخادم {"type":"complete"} تم إرسال الأرشيف كاملا.
→ الخادم {"type":"abort"} يستسلم. أجاب مع status: 499; لم يتم نشر أي شيء.
الخادم → {"type":"progress","phase":"publishing","bytesReceived":N} نبضات القلب كل 15 ثانية أثناء وصول التحميل. تجاهلهم، ولكن توقعهم.
الخادم → {"type":"result","status":200,...} نجاح. باقي الكائن هو نص استجابة HTTP حرفيًا (status يكون 201 من أجل خلق).
الخادم → {"type":"error","status":413,"error":"...","limitBytes":N} رفض. status والنص هو ما سيجيب عليه مسار HTTP.

لا يتم نشر أي شيء حتى {"type":"complete"} يصل. هذا هو السلوك الوحيد الذي لا يحتوي على HTTP مكافئ، وهو متعمد: علامة نهاية الأرشيف موجودة داخل بايت القطران، لذلك تنتهي المنصة من قراءة أرشيف كامل المظهر دون انتهاء الاتصال على الإطلاق. مقبس الذي سقط ببساطة بعد البايت الأخير كان سيتم نشره تمامًا مثل البايت الذي انتهى - استبدال اللعبة المباشرة بصمت بدفعة مهجورة. إغلاق المقبس دون تحميلات الإطار لا شيء.

قد يستغرق النشر بعد البايت الأخير بعض الوقت، خاصة بالنسبة لصورة الخادم. يتوقع progress دقات القلب بينما تنتهي؛ لا تعامل الفاصل الزمني الهادئ على أنه فشل في التحميل.

يتم قطع التحميل أو الدفع عند ما تبقى من بدل استضافة الحساب (413 مع limitBytes)، ويفشل نشر المستودع الذي من شأنه اجتيازه بسبب تسمية البدل. لكل دفعة ولكل لعبة نفس الرقم عند الاستبدال. الدمج يحده الناتجة حجم اللعبة، لذلك يتم رفض التصحيح الصغير الذي من شأنه أن يجعل الشجرة الحية تتجاوز الحد المسموح به.

حالة معنى
400 mode ليس كذلك replace ولا merge.
409 دمج ضد لعبة لا تحتوي على ملفات منشورة حتى الآن.
413 فوق البدل. يحمل الجسم { "error", "limitBytes" }. A 413 بدون limitBytes هو الحد الأقصى لهيكل CDN الذي يصل إلى 100 ميجابايت تقريبًا، وليس هذا — استخدم مقبس التحميل.
422 أرشيف تالف، أو محتويات غير قابلة للاستخدام (ملف التشغيل مفقود، رقم client/, a server/image.tar على مسار الإنشاء، عملية دمج قد تؤدي إلى حذف ملف التشغيل، remove.txt على الاستبدال). أيضا أ مبتورة الأرشيف - النتيجة العادية لانقطاع الاتصال أثناء التحميل.
507 الخادم ليس لديه مساحة الآن. رفض قبل قراءة الجسم عندما تكون القدرة على النشر غير متوفرة؛ أعد المحاولة لاحقًا.

لا يجوز للأرشيفات الهروب من جذرها أو تحتوي على روابط، ولا يمكن ذلك إلا للملفات والأدلة العادية المستخرج - يتم رفض الارتباطات الرمزية والروابط الثابتة وعقد الجهاز. git archive رؤوس PAX العالمية، ./-الأسماء السابقة من tar -czf game.tgz .وأسماء الملفات التي تحتوي فقط على .. (sprite..png) مقبولة. أ .. لا يزال يتم رفض جزء المسار.

حد المعدل

الإرسال والمطالبة وتغيير عنوان URL والاستضافة والنشر كلها تصل إلى GitHub على رمز واحد للنظام الأساسي، لذلك فهي تقتصر معًا على 10 طلبات في الدقيقة لكل حساب (429، مع Retry-After). ان يمكن للمشغل رفعه لحساب واحد.

تمكين الاستضافة

PUT /api/v1/me/github-games/{id}/hosting → GameHostingView ("نشر في starhermit")

{ "enabled": true }

تثبيت النشر

PUT /api/v1/me/github-games/{id}/deployment → GameHostingView

{ "commit": "<sha or branch>" }

commit هو اختياري. يؤدي تثبيت فرع/فرع إلى إعادة النشر في قائمة الانتظار؛ استطلاع GET /api/v1/me/github-games/{id}/deployment للحالة.

يتم رفض هذا بالنسبة للعبة التي لا تحتوي على مستودع (حزمة تم تحميلها): تثبيت الالتزام هو ما ينقل اللعبة إلى مستودعها، ولا تحتوي اللعبة التي تم إنشاؤها في الحزمة على أي منها. إعادة نشر لعبة تم تحميلها يتحقق من الملفات التي لا تزال موجودة على وحدة التخزين بدلاً من جلب github.com.

انقل لعبة إلى عنوان URL جديد

PUT /api/v1/me/github-games/{id}/url

{ "repoUrl": "https://github.com/you/new-repo", "displayName": "optional for a hosted URL" }

يبقى الصف على قيد الحياة — uid، <uid>.starhermit.com، وقت اللعب، التقييمات - ويتم إعادة نشرها من الوجهة. يجب أن تكون وجهة github هي الوجهة التي يمكن للمتصل إثبات سيطرته عليها (403 خلاف ذلك)، ولها starhermit.txt لا يجب تسمية أ مختلف owner= (403). مكتوبة أو حاوية يتم تعطيل الواجهة الخلفية ما لم تعلن الوجهة عن واحدة.

الجلسات المباشرة (المالك)

GET /api/v1/me/github-games/{id}/sessions يسرد الجلسات النشطة لخادم اللعبة. DELETE .../sessions/{sessionId} ينتهي بواحد من خلال مسار التخلي عن المنصة (لا يوجد فائز، لا إلو، السبب operator_ended). يؤدي ذلك إلى إرجاع مقعد السعة الذي كانت الجلسة المتوقفة تعقده.

المتصدرين والإنجازات (المالك)

مالك اللعبة هو ناشرها: يمكنك إنشاءها المتصدرين و الإنجازات لذلك تحت /me/github-games/{id}/leaderboards و /achievements بدون حساب الناشر. فقط يكتب لهم خادم لعبتك، لذا تحتاج اللعبة إلى ملف server= البرنامج النصي أو container.image= الواجهة الخلفية - تحصل على لعبة للمتصفح فقط 409. يرى المتصدرين, الإنجازات و درس تعليمي.

// GitHubGameDto
{
  "id": "...",

  "repoName": "...",
  "displayName": "...",
  "launchPath": "index.html",

  "coverArtUpdatedAt": "...",

  "releaseNotesUpdatedAt": "..."
}
  • serverScriptPath موجود فقط لواجهة JavaScript الخلفية. لا يعرض DTO الحالي مرجع صورة الحاوية.
  • gameSlug موجود لكل لعبة تمت إضافتها من مجلد محلي وكل لعبة أضافها مالك معتمد، مع أو بدون الواجهة الخلفية للخادم - يتناول عناصر التحكم في اللعبة والإعدادات وفتحة الحفظ السحابي والغرف ورموز الإطلاق. إنها null فقط لتقديم المستودع الذي لم يثبت صاحبه. لا يخبرك ما إذا كانت اللعبة لها واجهة خلفية أم لا؛ serverRuntime يفعل.
  • serverRuntime يوضح ما إذا كانت اللعبة تحتوي على واجهة خلفية للخادم: "script", "container"، أو null للعبة للمتصفح فقط. يتفق مع GET /api/v1/games/{gameSlug}، الذي يجيب 404 بالضبط عندما يكون null.
  • بالنسبة للعبة تمت إضافتها من مجلد محلي، repoUrl هو مادة اصطناعية upload:<id> علامة و ownerLogin/repoName فارغة - لا يوجد مستودع للاسم، والمالك الفارغ هو ما يجعل القائمة غير قابلة للمطالبة بها.
  • coverArtSource يكون "upload", "manifest" أو null، و coverArtUpdatedAt هو آخر مرة تم فيها تغيير هذا الغطاء - استخدمه للتخزين المؤقت /cover عنوان URL. أي شيء غير فارغ يعني أن اللعبة تحتوي على غلاف فني لجلبه؛ null يعني الرجوع إلى /icon. المصدران غير متساويين: التحميل يفوز دائمًا، وهو الوحيد DELETE /cover يمكن إزالة.
  • description هو وصف البيان، أو null. releaseNotesUpdatedAt عندما تكون ملاحظات الإصدار الأخيرة تم تغيير النص (null عندما لا تحتوي اللعبة على شيء). إن إعادة نشر الملاحظات المتطابقة لا يؤدي إلى تحريكها، لذا فمن الآمن قيادة أ "ما هو الجديد" الشارة: تذكر القيمة التي شاهدها اللاعب آخر مرة وقارنها. الملاحظات نفسها ليست في القائمة؛ يرى الوصف وملاحظات الإصدار.
  • SharedGitHubGameDto يمتد GitHubGameDto مع submittedByUserId و submittedByUsername.

انشر لعبتك الخاصة: الإرشادات التفصيلية

هناك طريقان للدخول. إذا كانت لعبتك موجودة في مستودع git، فاتبع الخطوات المرقمة أدناه. إذا كان مجرد مجلد على جهازك، فستقوم مكالمة واحدة بكل ذلك: إضافة لعبة من مجلد محلي يسجل اللعبة وينشر الملفات، ويتركها مباشرة - لا يوجد تبديل للاستضافة ولا دبوس التزام، لأنه لا يوجد مستودع لها المسار.

  1. اختر مصدرًا: دفع الريبو الذي يحتوي على starhermit.txt في الجذر (الإعلان اختياريًا عن a server.js البرنامج النصي أو صورة الحاوية)، أو قم بإعداد عنوان URL العام للعبة متصفح مستضافة بالفعل.
  2. اربط هوية GitHub الخاصة بك عبر تدفق OAuth (انظر auth.md); تحقق مع GET /api/v1/me/github.
  3. سجل اللعبة: POST /api/v1/me/github-games مع المستودع أو عنوان URL للعبة المستضافة في repoUrl.
  4. ألعاب المستودع فقط — تمكين الاستضافة: PUT /api/v1/me/github-games/{id}/hosting مع { "enabled": true }.
  5. ألعاب المستودع فقط - قم بتثبيت الالتزام: PUT /api/v1/me/github-games/{id}/deployment مع { "commit": "<sha>" }. يتحكم الالتزام المثبت في النسخة المباشرة.
  6. يبدأ اللاعبون اللعبة: يتم تقديم لعبة المستودع المنشورة في <slug>.starhermit.com; تفتح اللعبة المستضافة المباشرة عنوان URL المقدم الخاص بها. كل مباراة مع gameSlug — الخلفية أم لا — يتلقى رمز الإطلاق من POST /api/v1/games/<slug>/launch-token في جزء عنوان URL (اختياريًا مع &session_id=<guid> لدعوة الروابط العميقة).

للحصول على العقد الكامل من جانب العميل - كيف تقرأ اللعبة رمز الإطلاق المميز وتتحدث إلى واجهة برمجة التطبيقات (API) - راجع تجول الشطرنج من التنفيذ المرجعي
