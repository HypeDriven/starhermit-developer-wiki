عقود REST وWebSocket

هذه العقود القابلة للتنزيل تكمل الصفحات المرجعية. استخدامها لتفقد العمليات، التحقق من صحة الحمولات النموذجية، أو استيراد طلبات REST إلى عميل متوافق مع OpenAPI.

ملف التغطية
عقد OpenAPI REST أساليب REST العامة والمسارات والمعلمات ونماذج طلب JSON واستجابات النجاح وعائلات الاعتماد؛ تم وضع علامة على عمليات التوليد المحجوزة على أنها غير متوفرة
مخططات WebSocket JSON إطارات النص المعروفة حسب البروتوكول والاتجاه؛ تظل بيانات اللعب/الإشارات المملوكة للتطبيق مفتوحة
تخطيطات ثنائية بادئة المرسل في الوقت الفعلي، وبادئة الصوت، والترحيل غير المؤطر، ورأس دفق الحاوية، وأجزاء التحميل

عقود الراحة

يستخدم ملف REST واجهة برمجة التطبيقات المفتوحة 3.0.3 وأصل API العام. ترتبط كل عملية بالصفحة المرجعية الخاصة بها، الذي يحمل التفويض الكامل والتحقق والحدود وقواعد الخطأ. x-credentials يحدد عائلات الاعتماد المقبولة؛ ولا يحل محل شيكات الملكية أو العضوية. x-required-policies يصف الأذونات المسماة حيث تطبقها واجهة برمجة التطبيقات (API).

قد تتضمن الإجابات حقولًا إضافية. JSON الخاصة باللعبة، والبيانات الوصفية، والتشخيصات، والتحميل تستخدم النتائج أشكالًا مفتوحة حيث تحدد اللعبة أو مرجع نقطة النهاية محتوياتها. النجاح المخططات ليست وعدًا بأن كل متصل مرخص له. يمكن أن تكون أخطاء نقطة النهاية JSON أو نصًا عاديًا أو الاستجابات الفارغة، أو تفاصيل مشكلة التحقق من الصحة؛ يستخدم تحليل الاستجابة الدفاعية.

لا تعامل عمليات التوليد المحجوزة كخدمة عاملة. يصف عقدهم الحالي 503 overloaded الاستجابة، وليس حقول الطلب المستقبلية أو سلوك الإنشاء.

عقود WebSocket

اختر أ $defs مخطط لبروتوكول المقبس الخاص بك واتجاهه. على سبيل المثال، التحقق من صحة العميل إطار الحركة ضد GameRealtimeInput، بدلاً من المتانة العامة GameCommand:

{ "type": "cmd", "data": { "type": "input", "realtime": true, "seq": 1, "x": 0.5 } }

realtime ينتمي داخل data. حقول اللعب بعد ذلك هي عقد لعبتك. استخدم أ مخطط JSON 2020-12 أداة التحقق من الصحة مع مستند المخطط الكامل حتى يتم حل المراجع المحلية. تحتوي الوثيقة الجذرية على تعريفات؛ مطلوب تحديد تعريف للتحقق من صحة الإطار.

يجب أن تصل أنواع الإطارات المستقبلية إلى معالج الإطار غير المعروف لعميلك بدلاً من تعطل عملية الاستلام حلقة. لا يتحقق التحقق من صحة شكل JSON من صحة قواعد اللعبة أو يأذن بالعضوية أو يفرض المعدل حدود. تحدد الصفحات المرجعية قيود الدور والحجم/المعدل.

ترتيب بايت GUID

تعتبر مجموعات UUID الثلاثة الأولى ذات نهاية صغيرة في رأس بايت .NET GUID. على سبيل المثال:

UUID:  00112233-4455-6677-8899-aabbccddeeff
Bytes: 33 22 11 00 55 44 77 66 88 99 aa bb cc dd ee ff

وحدة فك ترميز المتصفح للبادئة ذات 16 بايت:

function guidFromDotNet(bytes) {
  if (bytes.length !== 16) throw new Error('Expected a 16-byte GUID');
  const hex = i => bytes[i].toString(16).padStart(2, '0');
  return `${hex(3)}${hex(2)}${hex(1)}${hex(0)}-${hex(5)}${hex(4)}-${hex(7)}${hex(6)}-` +
    `${hex(8)}${hex(9)}-${hex(10)}${hex(11)}${hex(12)}${hex(13)}${hex(14)}${hex(15)}`;
}

تحديد البادئات في الوقت الحقيقي مشاركون، بينما تحدد البادئات الصوتية المستخدمين. حاوية يحتوي الدفق على نوع بايت واحد متبوعًا بمعرفات UUID للجلسة/المستخدم، لذلك يبدأ JSON الخاص به بالبايت 33. ال لا يضيف التتابع أي بادئة. قراءة كل مأخذ توصيل بنفس التخطيط الثنائي يفسد الحمولات والهوية.

يرى أوراق الاعتماد والمعرفات, دورة حياة الجلسة، و استكشاف أخطاء WebSocket وإصلاحها.
