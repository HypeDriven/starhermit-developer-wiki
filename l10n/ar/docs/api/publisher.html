الناشر

سطح الناشر: إدارة مؤسسات الناشرين وأعضائهم، وإنشاء عناوين البرامج وإصداراتها وتحميلها، وإدارة الإنجازات والاستحقاقات وتعريفات لوحة الصدارة لعناوينك.

هل تريد نشر لعبة بدلاً من عنوان الكتالوج؟ لا تحتاج إلى أي من هذا. صاحب أ اللعبة ذات البرنامج النصي أو الواجهة الخلفية للحاوية هي ناشرها وتدير لوحات المتصدرين الخاصة بها الإنجازات تحت /api/v1/me/github-games/{id}/… - يرى البرنامج التعليمي: المتصدرين والإنجازات التي حققتها لعبتك.

عنوان URL الأساسي: https://api.starhermit.com. تتطلب جميع المسارات JWT بالإضافة إلى مطالبات الأذونات المدرجة. الأدوار: PublisherMember, PublisherOwner. يتم تعيين مطالبات الأذونات عبر الأدوار؛ تحمل الرموز المميزة مطالبات الإذن.

الناشرين والأعضاء

بادئة المسار: api/v1/publisher.

طريقة طريق مصادقة وصف
بريد /api/v1/publisher جوت (Permission-publisher.content.manage) إنشاء ناشر؛ يصبح المنشئ عضوًا له دور "Owner" → 201
يحصل /api/v1/publisher جوت (Permission-publisher.content.manage) قائمة الناشرين → Publisher[]
بريد /api/v1/publisher/{publisherId}/members جوت (Permission-publisher.members.manage) + دور Owner إضافة عضو → 204
يمسح /api/v1/publisher/{publisherId}/members/{memberUserId} جوت (Permission-publisher.members.manage) + دور Owner إزالة عضو → 204 (لا يمكن إزالة المالك)
يحصل /api/v1/publisher/{publisherId}/members/{memberUserId} جوت (Permission-publisher.members.manage) + عضوية ذلك الناشر احصل على عضو → PublisherMember

من يجوز له تغيير العضوية

تقول المطالبة بالإذن أنه يمكنك إدارة أعضاء الناشرين في مكان ما؛ لا يقول أيّ الناشر. وبالتالي ينطبق كلا الفحصين:

  • إضافة وإزالة الأعضاء هي Owner-فقط. تحمل العضوية سلطة إدارة المحتوى كل عنوان من عناوين الناشر، لذلك يمكن للعضو العادي الذي يمكنه إضافة أعضاء أن يمنح ذلك سلطة لأحد. يحصل على غير مالك 401.
  • تتطلب قراءة العضوية الانتماء إلى ذلك الناشر. المتصل خارجه يحصل على نفس الشيء 404 باعتبارك مستخدمًا ليس عضوًا، فإن نقطة النهاية لا تكشف شيئًا عن الناشرين الذين لست أنت جزء من.

عناوين البرامج وبنياتها

طريقة طريق مصادقة وصف
بريد /api/v1/publisher/software جوت (Permission-publisher.content.manage) إنشاء/تحديث عنوان البرنامج (النص = بيانات تعريف العنوان؛ فرض العضوية في الناشر الفعلي للعنوان)
بريد /api/v1/publisher/software/upload جوت (Permission-publisher.content.manage + Permission-publisher.binary.publish) احصل على عناوين URL للتحميل للعنوان → UploadUrlInfo[]
بريد /api/v1/publisher/software/build/finalize جوت (Permission-publisher.content.manage + Permission-publisher.binary.publish) وضع اللمسات النهائية على البناء من الأصول التي تم تحميلها → 204
يحصل /api/v1/publisher/analytics/downloads?publisherId= جوت (Permission-publisher.content.manage) عدد التنزيلات لكل عنوان
يحصل /api/v1/publisher/analytics/launches?publisherId= جوت (Permission-publisher.content.manage) عدد مرات الإطلاق لكل عنوان

يحتاج نشر البنية إلى منحة النشر الثنائي

تتطلب نقطتي نهاية البناء publisher.binary.publish على رأس publisher.content.manage وعضوية ناشر العنوان. دون ذلك على حد سواء الإجابة 403, بينما تستمر كل نقطة نهاية أخرى في هذه الصفحة في العمل - يمكنك إنشاء العناوين وتعديلها وتحديدها الإنجازات والمتصدرين، واستحقاقات المنح؛ لا يمكنك إرسال ملف قابل للتنفيذ.

والسبب هو ما هو البناء. يتم تنزيل أصول الإصدار بواسطة عميل سطح المكتب وتشغيلها على جهاز اللاعب بامتيازات اللاعب، خارج أي أدوات تحكم في وضع الحماية Starhermit - على عكس لعبة المتصفح، والتي تعمل في المتصفح. لذلك يتم منح الحق في نشر واحد لكل حساب من قبل أ مسؤول Starhermit ( BinaryPublisher الدور)، لم يتم الحصول عليه عن طريق إنشاء ناشر. لا دور آخر يحمله. اطلب من المسؤول الحصول على المنحة قبل إنشاء تدفق تحميل مقابلها نقاط النهاية هذه; تتم إزالته أيضًا عند تعليق حساب الناشر.

لا تحتاج ألعاب المتصفح إلى أي من هذا: /api/v1/me/github-games عمليات الإرسال وتحميل المجلدات والحزمة يدفع البقاء للخدمة الذاتية لأي حساب تم تسجيل الدخول إليه.

إنشاء أو تحديث عنوان الكتالوج

POST /api/v1/publisher/software يقبل id (حذف للحصول على عنوان جديد)، publisherId, name, description, category, platform, releaseStatus, tags، و priceCents:

{
  "publisherId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "name": "Orbit League",
  "description": "A space racing game.",
  "category": "game",
  "platform": "windows",
  "releaseStatus": "released",
  "tags": ["racing"],
  "priceCents": 0
}

النجاح هو 201 مع العنوان. يتم قبول بيانات تعريف العنوان فقط؛ لا ترسل عضوية الناشر أو كائنات الأصول هنا. يعود إنشاء الناشر 201 بدون كائن الناشر؛ قائمة GET /api/v1/publisher للحصول على هويته

احصل على عناوين URL للتحميل

POST /api/v1/publisher/software/upload

{ "titleId": "<title id>" }

إجابة - UploadUrlInfo[]:

[
  {
    "type": "executable",
    "uploadUrl": "...",
    "fieldKey": "..."
  }
]

type هو واحد من "executable", "data", "metadata".

وضع اللمسات النهائية على البناء

POST /api/v1/publisher/software/build/finalize → 204

{
  "titleId": "<title id>",
  "buildId": "<optional build id>",
  "version": "1.0.0",
  "releaseNotes": "...",
  "assets": [
    { "type": "executable", "checksum": "...", "fieldKey": "..." }
  ]
}

يعد سير عمل إنشاء الكتالوج حاليًا بمثابة معاينة ولا يوفر تسليمًا ثنائيًا للإنتاج أو ضمان التحقق من المحتوى أو فحص البرامج الضارة. لا تتعامل مع بناء أو أصل مقبول الحالة كدليل على أن الملف القابل للتنفيذ آمن. يرى توفر الميزة. يستخدم نشر الألعاب المستضافة API تحميل اللعبة.

التحليلات

تُرجع كلا نقطتي النهاية معرف عنوان تعيين كائن JSON ليتم احتسابه:

{ "<titleId>": 42 }

الإنجازات

طريق api/v1/publisher; تتطلب جميع طرق إدارة الإنجاز Permission-publisher.content.manage.

إدارة نقاط النهاية هذه عنوان الكتالوج الإنجازات فقط. كما أنها تتطلب أن يكون المتصل أ عضو الناشر الذي يملك العنوان، وهم تفشل مغلقة للإنجازات التي تنتمي إليها لعبة موثوقة - تم الإعلان عن تلك بواسطة البرنامج النصي للعبة أو الواجهة الخلفية للحاوية ولم يتم الإعلان عنها يديره الناشر (انظر الإنجازات, مخطوطات اللعبة، و خوادم ألعاب الحاويات).

طريقة طريق مصادقة وصف
بريد /api/v1/publisher/titles/{titleId}/achievements JWT إنشاء إنجاز → AchievementDto
يحصل /api/v1/publisher/titles/{titleId}/achievements JWT قم بإدراج إنجازات العنوان → AchievementDto[]
يحصل /api/v1/publisher/achievements/{id} JWT احصل على إنجاز واحد → AchievementDto
يضع /api/v1/publisher/achievements/{id} JWT تحديث (جميع الحقول فارغة) → AchievementDto
يمسح /api/v1/publisher/achievements/{id} JWT حذف → 204

POST /api/v1/publisher/titles/{titleId}/achievements

{
  "key": "first_win",

  "icon": "...",
  "secret": false,

icon, visibility، و criteria هي اختيارية. على PUT، جميع الحقول فارغة. يرى achievements.md للسطح المواجه للاعب.

الاستحقاقات

طريق api/v1/publisher/entitlements; يتطلب كلا الطريقين Permission-publisher.content.manage.

طريقة طريق مصادقة وصف
بريد /api/v1/publisher/entitlements/grant JWT منح المستخدم عنوان → 204
بريد /api/v1/publisher/entitlements/revoke JWT إبطال عنوان من مستخدم → 204

{

المتصدرين

طريق api/v1/publisher/leaderboards; تتطلب جميع الطرق Permission-publisher.content.manage.

طريقة طريق مصادقة وصف
بريد /api/v1/publisher/leaderboards/ JWT إنشاء تعريف المتصدرين → LeaderboardDefinitionDto
يحصل /api/v1/publisher/leaderboards/{id} JWT احصل على تعريف → LeaderboardDefinitionDto
يضع /api/v1/publisher/leaderboards/{id} JWT تحديث (جميع الحقول فارغة) → LeaderboardDefinitionDto
يمسح /api/v1/publisher/leaderboards/{id} JWT حذف → 204

إنشاء المتصدرين

POST /api/v1/publisher/leaderboards/

{
  "name": "Global Elo",
  "scoreType": "...",
  "sortDirection": "...",
  "resetSchedule": "...",
  "minScore": 0,
  "maxScore": 4000,
  "scope": "...",
  "region": "...",
  "isActive": true,
  "softwareTitleId": "<optional title id>"
}

resetSchedule, minScore, maxScore, region، و softwareTitleId هي اختيارية. على PUT، جميع الحقول فارغة. resetSchedule يكون daily, weekly, monthly أو never; أي شيء آخر هو أ 400 - يرى إعادة تعيين الجداول الزمنية. يرى leaderboards.md للسطح المواجه للاعب.

نشر البناء: التدفق

  1. عقد منحة النشر الثنائي: تتطلب الخطوتين 3 و5 publisher.binary.publish، الذي أ يمنح مسؤول Starhermit لكل حساب. يرى يحتاج نشر البنية إلى منحة النشر الثنائي.
  2. إنشاء ناشر: POST /api/v1/publisher مع { name, description }.
  3. أنشئ العنوان: POST /api/v1/publisher/software مع البيانات الوصفية للعنوان أدناه.
  4. احصل على عناوين URL للتحميل: POST /api/v1/publisher/software/upload مع { titleId }.
  5. تحميل الملفات إلى العائدين uploadUrls.
  6. وضع اللمسات النهائية على البناء: POST /api/v1/publisher/software/build/finalize مع الأصول التي تم تحميلها { type, checksum, fieldKey } إدخالات.
  7. التحقق من توافر التوزيع: لا تضمن معاينة الكتالوج الحالية تنزيلات الإنتاج التي تم التحقق منها أو فحص البرامج الضارة؛ يرى التوفر.
  8. مطالبة المستخدمين وتنزيلها العنوان من خلال الكتالوج - انظر catalog.md.

تختلف أجسام الخطأ؛ يرى اتفاقيات API.
