المصادقة

ستارهيرميت لديه لا مصادقة كلمة المرور. هناك مساران لتسجيل الدخول: مصادقة المفتاح العام (Ed25519، أو ECDSA-P256، أو RSA-PSS، مع تسجيل تم التحقق منه عبر البريد الإلكتروني) وOAuth. جميع طرق المصادقة تعيش تحت api/v1/auth وتكون مجهولة المصدر إلا في حالة الإشارة إليها. تغطي هذه الصفحة أيضًا دورات حياة الرمز المميز، ورموز الإطلاق المميزة على مستوى اللعبة، وتذاكر اتصال WebSocket.

تختلف أجسام الخطأ؛ يرى اتفاقيات API.

بعد تسجيل الدخول: الشروط الحالية

لا يعني تسجيل الدخول الناجح الحصول على إذن لاستخدام واجهات برمجة التطبيقات المحمية. يجب على أصحاب الحسابات اقبل شروط StarHermit الحالية قبل مكالمات REST المحمية أو نجاح ترقيات WebSocket. يمكن لعملاء الحساب التحقق GET /api/v1/me، أحضر GET /api/v1/terms, وتسجيل القبول الصريح مع POST /api/v1/me/terms/accept. كل من OAuth والمفتاح العام تدعم جلسات الحساب هذا التدفق. لا يؤدي تحديث بيانات الاعتماد إلى حل مشكلة القبول المعلقة.

يمكن أن تتلقى لعبة المتصفح المفتوحة مباشرة رمزًا مميزًا قبل قبول الحساب. إذا عادت مكالمة اللعبة 403 مع error: "terms_acceptance_required"، أحضر GET /api/v1/terms, عرض النص الخاص به، وتقديم إجراء قبول صريح. يمكن لرمز إطلاق اللاعب إرسال المعروض التجزئة ل POST /api/v1/me/terms/accept; أعد محاولة الطلب الأصلي بعد القبول. لا تعامل هذا الاستجابة كحلقة تسجيل دخول للرمز المميز منتهية الصلاحية.

تسجيل المفتاح العام

خطوة بخطوة، مع رمز العميل الذي تم اختباره: البرنامج التعليمي: لاعبين على متن الطائرة بمفتاح عام.

keyType keyData (قاعدة 64 القياسية) إمضاء
Ed25519 المفتاح العام الخام 32 بايت توقيع Ed25519 خام بحجم 64 بايت
ECDSA-P256 النقطة العامة، 65 بايت غير مضغوطة أو 33 بايت مضغوطة ECDSA-SHA256، ASN.1 DER (غير خام r‖s)
RSA-PSS SubjectPublicKeyInfo DER، 2048–8192 بت، الأس ≥ 32 بت RSASSA-PSS، SHA-256، MGF1-SHA-256، ملح 32 بايت

POST /api/v1/auth/public-key/register

يبدأ تسجيل المفتاح العام ويرسل بريدًا إلكترونيًا للتحقق. تنتهي صلاحية سجل التسجيل المعلق بعد 4 ساعات. لو userId تم تعيين البريد الإلكتروني، ويجب أن يتطابق مع هذا الحساب. تم التقليص إلى بريد إلكتروني واحد لكل عنوان ولكل IP كل 24 ساعة - عند التخفيض، يكون الرد 429 مع Retry-After header.

متى userId تم تعيين والزوج لا تحقق، والرد 403 برسالة واحدة بغض النظر عن لماذا: حساب غير معروف وعنوان خاطئ الإجابة على نحو مماثل. تأخذ نقطة النهاية هذه لا توجد بيانات اعتماد - لا بد من ذلك، نظرًا لأن هذه هي الطريقة التي يتم بها إرفاق مفتاح جديد - لذا فإن التمييز بينها سيكون أمرًا ممكنًا اجعله أوراكل توجد له معرفات المستخدمين ثم لعناوينهم. المتصل الذي يملك يعرف الحساب بالفعل أيًا من الاثنين أخطأ.

طلب:

{
  "email": "dev@example.com",
  "keyType": "Ed25519",
  "keyData": "<base64-raw-32-byte-public-key>",
  "userId": null
}

الرد — 202:

{
  "registrationId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "email": "dev@example.com",
  "emailSent": true,
  "deferralReason": null,
  "message": "A verification email has been sent. The key will be attached once you confirm."
}

emailSent: false يعني أن البريد الإلكتروني في قائمة الانتظار لإعادة المحاولة (deferralReason يقول لماذا)؛ التسجيل لا يزال مقبولا. البريد الإلكتروني غير صالح أو المواد الرئيسية 400.

GET / POST /api/v1/auth/public-key/verify?token=

فتح الرابط المرسل بالبريد الإلكتروني لا يغير شيئًا. GET يعرض صفحة توضح ما سيفعله التأكيد - إنشاء حساب، أو إضافة مفتاح إلى الحساب الحالي الذي يستخدم العنوان بالفعل - مع زر التأكيد. تقوم ماسحات البريد بإحضار الروابط لمعاينتها، وبالتالي يتم إرسال الرابط عبر البريد الإلكتروني الذي تم التصرف بناءً عليه GET سيتم استبداله بأي شيء تم مسحه ضوئيًا. الأمر نفسه ينطبق على إبطال و رابط الهوية التأكيدات أدناه.

POST إلى نفس عنوان URL يسترده: إرفاق المفتاح وإنشاء المستخدم (اسم المستخدم pk-<hex12>، دور User) ما لم يستخدم الحساب عنوان البريد الإلكتروني هذا بالفعل، وفي هذه الحالة ينضم المفتاح إلى هذا الحساب. تم وضع علامة التحقق على البريد الإلكتروني. الرابط مخصص للاستخدام مرة واحدة وتنتهي صلاحيته بعد 4 ساعات؛ غير معروف، المستخدمة أو الرمز منتهي الصلاحية هو 400، وكذلك الرابط الذي لم يعد عنوانه هو عنوان الحساب - فهذا يثبت التحكم في البريد الوارد الذي تم إرساله إليه، وفقط عندما يظل هذا العنوان ملكًا للحساب.

عندما يضغط اللاعب على تأكيد في الصفحة ومجموعات النشر PublicKeyAuth:VerificationSuccessRedirectUri - موقع starhermit.com موجود على لوحة القيادة - هم كذلك أرسلت هناك مع الرموز الموجودة في القطعة (#access_token=…&refresh_token=…&token_type=Bearer&expires_in=900)، تم تسجيل الدخول إلى لوحة التحكم. أ وبالتالي فإن العميل الأصلي لا يتلقى هذه الرموز المميزة؛ يقوم بتسجيل الدخول باستخدام مفتاحه بمجرد قيام اللاعب بذلك مؤكد. عميل API ذلك POSTعنوان URL نفسه يحصل على JSON:

{
  "userId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "keyId": "9b2f5c74-1d2e-4a6b-8c0d-1e2f3a4b5c6d",
  "accessToken": "eyJhbGciOi...",
  "refreshToken": "dGhpcyBpcyBh..."
}

تسجيل الدخول بالمفتاح العام

POST /api/v1/auth/public-key/challenge

يصدر تحدي تسجيل الدخول، صالح لمدة 5 دقائق وللاستخدام مرة واحدة.

يغطي التوقيع التسلسل الخاص بالخادم لـ payload، وليس JSON الذي تلقيته: مضغوط، أسماء PascalCase بالترتيب ChallengeId, Fingerprint, Issuer, Audience, Expiry, Nonce, ClientTimestamp، تم نسخ القيم تمامًا كما تم تقديمها، وكل + في nonce مكتوبة باسم \u002B (التواريخ تحتفظ بها +). انظر عملت المثال.

طلب:

{
  "keyType": "Ed25519",
  "keyData": "<base64-raw-32-byte-public-key>"
}

إجابة:

{
  "challengeId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "payload": {
    "challengeId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
    "fingerprint": "4d9f3c...",
    "issuer": "starhermit",
    "audience": "starhermit",
    "expiry": "2026-07-22T07:24:44.1234567+00:00",
    "nonce": "NmL+tgMum6HXU/pa3T9xjQ==",
    "clientTimestamp": "2026-07-22T07:19:44.1235521+00:00"
  },
  "expiresIn": 300
}

POST /api/v1/auth/public-key/complete

يتحقق من التوقيع مقابل مفتاح مسجل وغير مُلغى ويعيد زوجًا من الرموز المميزة. الفشل هو 401: "Public key not registered or revoked." (بما في ذلك المفتاح الذي لم يتم إرسال رابطه عبر البريد الإلكتروني لم يفتح بعد) "Invalid signature."، أو "Challenge not found or expired.". التحدي واستكمال مشاركة حد 60 طلبًا في الدقيقة لكل IP (429).

طلب:

{
  "challengeId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "signature": "base64-signature...",
  "keyType": "Ed25519",
  "keyData": "<base64-raw-32-byte-public-key>"
}

إجابة:

{
  "userId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "accessToken": "eyJhbGciOi...",
  "refreshToken": "dGhpcyBpcyBh..."
}

دورة حياة الرمز المميز

POST /api/v1/auth/refresh

التحديث الدوري: يتم إبطال الرمز القديم واستبداله. تؤدي إعادة استخدام رمز التحديث الذي تم إبطاله إلى إبطال عائلة الرمز المميز بالكامل.

طلب:

{ "refreshToken": "dGhpcyBpcyBh..." }

إجابة:

{
  "accessToken": "eyJhbGciOi...",
  "refreshToken": "bmV3IHJlZnJlc2g..."
}

عندما يتوقف التحديث عن العمل

يسجل رمز التحديث حالة الحساب الذي تم إصداره بموجبه، ويتحقق التحديث منه. إجابتين يجب على عميلك التعامل مع ما يلي بدلاً من إعادة المحاولة:

حالة معنى ما يجب على العميل فعله
401 تم إلغاء الجلسة من جانب المنصة — أ "تسجيل الخروج في كل مكان"، أو الرد الوسط. يتم حرق عائلة الرمز المميز بالكامل، بما في ذلك الرمز المميز الذي تم تقديمه للتو. تخلص من كلا الرمزين وابدأ تسجيل دخول جديد.
403 الحساب هو معلق. قف. لن يساعد تسجيل الدخول مرة أخرى؛ نفس الشيء 403 يعود من كل طريق تسجيل دخول حتى يتم رفع التعليق.

ال 403 يختلف عمدا عن 401لأن الاثنين يحتاجان إلى ردود أفعال متضادة: أحدهما يعني "المصادقة مرة أخرى"، والوسيلة الأخرى "المصادقة مرة أخرى لا معنى لها". الحساب الموقوف هو رفض من قبل كل مسار استخراج بيانات الاعتماد - التحديث، وإكمال المفتاح العام، ورد اتصال OAuth، ورموز إطلاق اللعبة - ليس فقط عن طريق التحديث.

POST /api/v1/auth/logout

يلغي رمز التحديث المحدد. يعود 200.

{ "refreshToken": "dGhpcyBpcyBh..." }

OAuth

تشحن المنصة سبعة مقدمي خدمات: google, github, discord, twitch, gitlab, linkedin, bitbucket. فقط موفرو هذا النشر لديهم بيانات اعتماد مباشرة. لا يجب على العميل رمز الثابت القائمة.

GET /api/v1/auth/oauth/providers

مجهول. إرجاع موفري الخدمة المباشرة بالترتيب الذي يجب تقديمهم به:

{
  "providers": [
    {
      "provider": "google",
      "displayName": "Google",
      "authorizeUrl": "/api/v1/auth/oauth/google/authorize",
      "linksExistingAccountsByEmail": true
    }
  ]
}

linksExistingAccountsByEmail هو ما إذا كان تسجيل الدخول لدى هذا المزود يمكنه العثور على حساب الشخص لديه بالفعل (إعداد ثقة المشغل لهذا الموفر). طلب ترخيص اسم ليس كذلك العيش هو 404، وليس إعادة توجيه إلى صفحة الخطأ الخاصة بالموفر.

GET /api/v1/auth/oauth/{provider}/authorize?link=&client=

إرجاع إعادة توجيه 302 إلى الموفر وتعيين oauth_state ملف تعريف الارتباط (HttpOnly، SameSite=Lax، 10 دقائق). link=true يبدأ بربط الهوية بالمستخدم الذي قام بتسجيل الدخول حاليًا؛ يتطلب الربط المصادقة الأخيرة (في غضون 5 دقائق). client يحدد إعادة توجيه العميل المدعومة. ل لعبة مفتوحة مباشرة، استخدم gameId واختياري returnUrl بدلاً من؛ يرى قم بتسجيل الدخول من لعبة متصفح مفتوحة مباشرة.

GET /api/v1/auth/oauth/{provider}/callback?code=&state=

بالنسبة لتسجيل الدخول العادي إلى الحساب، يتم إرجاع إعادة التوجيه 302 إلى عنوان URL للواجهة الأمامية مع الرموز المميزة في ملف جزء (يؤدي تسجيل الدخول إلى اللعبة بدلاً من ذلك إلى إرجاع رمز مميز محدد إلى اللعبة مباشرةً، كما هو موضح أدناه):

#access_token=…&refresh_token=…&token_type=Bearer&expires_in=900

إذا رفض الموفر تبادل الرمز المميز، فسيتم الرد على رد الاتصال 409 تسمية خطأ الموفر شفرة (يبقى الوصف في سجل الخادم).

يؤدي تسجيل الدخول العادي إلى العثور على المستخدم (اسم المستخدم). oauth-{provider}-{guid}، دور User) و سجلات الجلسة الجديدة auth_method=oauth. تسجيل الدخول الذي (provider, providerUserId) غير معروف هو اعتمد على حساب موجود فقط عندما يتم الوثوق بتأكيد الموفر، بالضبط واحد يحتوي الحساب بالفعل على هذا البريد الإلكتروني الذي تم التحقق منه، ولا يحتوي هذا الحساب على هوية من هذا المزود حتى الآن. أي شيء آخر يوفر حساب منفصل. يتم إرسال رسالة اعتماد عبر البريد الإلكتروني إلى الحساب الذي يذكر اسم الموفر.

وهذا مهم لأن جلسة مصادقة OAuth فقط قد يقوم بإجراء تغييرات عالية التأثير على بيانات الاعتماد:

  • إضافة أو إلغاء المفاتيح العامة للحساب؛
  • تغيير البريد الإلكتروني للحساب؛
  • إزالة الهوية المُدارة بواسطة OAuth.

لا يمكن للرموز المميزة على مستوى اللعبة إجراء هذه العمليات أبدًا. يحتفظ رمز التحديث بالأصل طريقة مصادقة الجلسة، لذا فإن تحديث جلسة OAuth لا يؤدي إلى إزالة هذه الإمكانية و تحديث جلسة المفتاح العام لا يضيفها.

متى link=true، لا يقوم رد الاتصال تلقائيًا بترقية الجلسة لمجرد زيارتها موفر OAuth. يتم إرفاق الرابط الذي بدأ من جلسة OAuth على الفور. رابط بدأ من يتم الاحتفاظ بالمفتاح العام أو التحقق من البريد الإلكتروني أو الجلسة القديمة حتى يفتح مالك الحساب الملف تم إرسال التأكيد إلى البريد الإلكتروني الذي تم التحقق منه للحساب؛ تقارير جزء إعادة التوجيه link=pending_email_confirmation. يتم فتح البريد الإلكتروني لمرة واحدة GET /api/v1/auth/oauth/link/confirm?token=…, صفحة تحمل اسم حساب المزود ولا تغير شيئًا؛ زر التأكيد الخاص به POSTإنه نفس عنوان URL، مما يخلق الهوية ({ "provider", "linked": true } إلى عميل API). الرابط الذي عنوانه لم يعد تم رفض الحساب. وهذا يمنع المفتاح العام المسروق من ربط الملف حساب موفر المهاجم وتحويله إلى تسجيل دخول دائم عبر OAuth.

مخازن البيانات التعريفية لهوية GitHub {"login":"…"} - يُستخدم هذا للتحقق من ملكية المستودع ألعاب جيثب.

المفاتيح العامة المسجلة بواسطة OAuth للأتمتة

يمكن لجلسة OAuth الاتصال POST /api/v1/me/public-keys لإرفاق مفتاح الجهاز المسمى على الفور. لاحقًا، توقع CI تحدي المفتاح العام العادي وتستخدم رمز الوصول قصير الأمد الخاص بها لتحميل ملف حزمة اللعبة المملوكة؛ المفتاح الخاص لا يغادر متجر CI السري أبدًا. يرى البرنامج التعليمي لتحميل CI/CD للإعداد، ومساعد التوقيع، و سير عمل إجراءات GitHub.

الرموز

  • رمز الوصول - JWT، عمر 15 دقيقة (expires_in=900). تشمل المطالبات sub (معرف المستخدم) زائد permission ومطالبات الدور. يصبح الإلغاء ساري المفعول على الفور.
  • تحديث الرمز المميز - رمز دوار غير شفاف بعمر 7 أيام. يُصدر كل تحديث رمزًا مميزًا للتحديث جديدًا ويلغي الرمز القديم؛ تؤدي إعادة استخدام الرمز المميز الذي تم إبطاله إلى إلغاء عائلة الرمز المميز بأكملها.

قم بتسجيل الدخول من لعبة متصفح مفتوحة مباشرة

يمكن للعبة المستضافة المفتوحة خارج لوحة المعلومات أن تعرض ملف تسجيل الدخول زر ربط إلى:

https://api.starhermit.com/api/v1/auth/games/{gameId}/sign-in

gameId هو UUID غير القابل للتغيير للعبة (النطاق الفرعي في {gameId}.starhermit.com). ستارهيرميت يعرض موفري تسجيل الدخول الممكّنين. الاستمرار في تسجيل الدخول إلى لاعب موجود أو إنشاء لاعب جديد الحساب باستخدام قواعد مطابقة حساب OAuth العادية، ثم يعيد التوجيه العودة مباشرة إلى لعبة، دون زيارة لوحة القيادة.

الاختياري returnUrl يحتفظ بصفحة لعبة محددة أو سلسلة استعلام أو مسار تجزئة. يجب أن يكون عنوان URL مطلق لـ HTTPS على الأصل المستضاف لتلك اللعبة بالضبط؛ ألعاب أخرى، مضيفين خارجيين، يتم رفض بيانات الاعتماد الموجودة في عنوان URL والمنافذ البديلة 400. احذفها لتعود إلى ملف الإطلاق المنشور. تعود الألعاب غير المعروفة أو المحذوفة أو غير المستضافة أو التي لم يتم نشرها مطلقًا 404. كلاهما يتم دعم عمليات نشر المستودع والألعاب التي تم تحميلها؛ عناوين URL الخارجية/المحلية التعسفية ليست كذلك.

انتقل بالمتصفح إلى أصل واجهة برمجة التطبيقات العامة أعلاه، بدلاً من جلب الصفحة أو البدء من خلال اللعبة /api الوكيل. يجب أن يستخدم ملف تعريف ارتباط حالة OAuth ورد اتصال الموفر نفس الشيء مضيف واجهة برمجة التطبيقات. استخدم هذا التدفق عندما لا تحتوي اللعبة على رمز مميز مقدم من المشغل أو تم الحصول عليه مسبقًا.

مثال على الزر ورمز الإرجاع

<button id="starhermit-sign-in">Sign in</button>
<script type="module">
const api = 'https://api.starhermit.com';
const gameId = 'YOUR_GAME_UID';
const signIn = document.querySelector('#starhermit-sign-in');
let gameToken = null; // Or your existing launcher-provided game token.

// Read this before your game router or third-party scripts consume the fragment.
const auth = new URLSearchParams(location.hash.slice(1));
if (auth.has('access_token')) {
  gameToken = auth.get('access_token');
  const originalHash = auth.get('game_fragment');
  history.replaceState(null, '', location.pathname + location.search +
    (originalHash ? '#' + originalHash : ''));
}
signIn.hidden = Boolean(gameToken);
signIn.addEventListener('click', () => {
  const url = new URL(`/api/v1/auth/games/${gameId}/sign-in`, api);
  url.searchParams.set('returnUrl', location.href);
  location.assign(url.href);
});

// Pass gameToken to your game's API client as Authorization: Bearer <gameToken>.
// This example keeps it in memory; a reload can require sign-in again.
</script>

جزء الإرجاع هو:

#access_token=…&token_type=Bearer&expires_in=3600

access_token هو أ رمز الإطلاق على نطاق اللعبة، وليس رمز وصول على مستوى الحساب. لا يوجد رمز التحديث تم إصداره. expires_in يستخدم عمر رمز الإطلاق المميز للنشر (الافتراضي 3600 ثواني). يتم ترميز جزء عنوان URL الأصلي في الملف الاختياري game_fragment مجال؛ استعادته بعد التقاط الرمز المميز وإزالة بيانات المصادقة من سجل المتصفح. لا تقم بتسجيل أو إعادة توجيه الرمز المميز.

تجديد قبل انتهاء الصلاحية باستخدام POST /api/v1/games/{gameId}/launch-token مع الرمز الحالي كما تفويض حامله، ثم استبداله بالمرتجع token. سقف سلسلة التجديد المعتاد ينطبق (الافتراضي 12 ساعة). إذا انتهت صلاحية الرمز المميز أو تم رفض التجديد، فقم بمسحه وإظهار تسجيل الدخول مرة أخرى. يرى رموز إطلاق اللعبة.

اختيار المزود بنفسك

قد تقرأ الألعاب بدلاً من ذلك GET /api/v1/auth/oauth/providers وانتقل إلى عرض معروض authorizeUrl على أصل API العام، إضافة gameId واختياريا returnUrl. خطوة التفويض التحقق من صحة الهدف وتخزينه في حالة OAuth الحالية التي تبلغ مدتها عشر دقائق؛ معلمات استعلام رد الاتصال لا يمكن تغييره. لا يزال ملف تعريف الارتباط الخاص بالمتصفح البادئ مطلوبًا، ويتم فحص اللعبة مرة أخرى قبل إصدار الرمز المميز. لا يمكن للحسابات المعلقة الحصول على رمز مميز.

لا تجمع بين تسجيل الدخول إلى اللعبة و client أو link (400). A returnUrl بدون gameId هو أيضا 400. يستمر تسجيل الدخول العادي للوحة المعلومات وسطح المكتب في استخدام وجهات الواجهة الأمامية التي تم تكوينها وأزواج الرموز المميزة للحساب العادي.

رموز إطلاق اللعبة

POST /api/v1/games/{slug}/launch-token (JWT) تصوغ JWT على نطاق اللعبة:

{
  "token": "eyJhbGciOi...",
  "expiresInSeconds": 3600
}

يحمل الرمز أ game_scope المطالبة والتخلف عن العمل لمدة 60 دقيقة. تجديد النسخ أ launch_chain وقت البدء إلى الأمام؛ التجديد خلال الـ 12 ساعة الماضية (الافتراضي) هو 403 ويجب أن يذهب الحامل العودة إلى جلسة الحساب الكاملة. التفاصيل الكاملة في ألعاب.

إعادة توصيل المقابس. تم فتح مأخذ توصيل باستخدام رمز الإطلاق (?access_token= على ws/v1/games, ws/v1/realtime, ws/v1/voice) يحمل هذا الرمز المميز في عنوان URL الخاص به، ومصافحة برمز مميز منتهي الصلاحية تم رفضه مع 401 قبل الترقية — يُبلغ المتصفح عن التعليمات البرمجية المغلقة فقط 1006، نفس أ إسقاط الشبكة. تعامل مع عملية إعادة الاتصال الفاشلة على أنها فشل في المصادقة: قبل إعادة الفتح، قم بالتجديد حتى النهاية POST /api/v1/games/{slug}/launch-token (ممكن فقط عندما يكون الرمز المميز الحالي صالحًا و في غضون 12 ساعة من الإطلاق الأصلي) وقم بإنشاء عنوان URL باستخدام الرمز المميز الجديد. بمجرد التجديد رفض، أرسل اللاعب مرة أخرى إلى المشغل، أو من خلاله تسجيل الدخول للعبة إذا كانت هذه هي الطريقة التي تم بها فتح اللعبة. لا يمكن أبدًا استرداد نفس عنوان URL لإعادة المحاولة.

سياج نطاق اللعبة

يمكن للرمز المميز على مستوى اللعبة أن يصل فقط إلى:

  • خاص بها /api/v1/games/{scope} شجرة،
  • /ws/v1/games,
  • غرفة الوقت الحقيقي طرق الراحة و /ws/v1/realtime للعبة الخاصة بها، بما في ذلك تذاكر الاتصال،
  • GET /api/v1/time و GET /api/v1/terms,
  • POST /api/v1/me/terms/accept للحصول على موافقة صريحة من اللاعب المصادق عليه،
  • GET /api/v1/me/friends,
  • GET /api/v1/users/{id}/avatar و GET /api/v1/users/{id}/profile,
  • لوحة المتصدرين للعبة،
  • اللاعب حفظ السحابة للعبة الخاصة (/api/v1/me/cloud-saves/game:<scope> ولها /info) - لا يوجد مفتاح آخر،
  • نقاط نهاية الدردشة/الصوت REST وWebSocket المرتبطة بجلسات اللعبة الخاصة بها،
  • GET /api/v1/github-games/{id}/icon و /cover لأي لعبة (كلاهما عام على أي حال)،
  • POST /api/v1/me/heartbeat، والذي يميز اللاعب عبر الإنترنت فقط،
  • GET /api/v1/github-games/{id}/release-notes للعبة الخاصة بها،
  • تتابع المسارات، للمرحلات المرتبطة بإحدى جلسات أو غرف اللعبة الخاصة بها.

/ws/v1/chat تم حظره لرموز الإطلاق. كل شيء آخر يعود 403.

تدفق تسجيل الدخول النموذجي (الضفيرة)

تسجيل الدخول بالمفتاح العام، بدءًا من التحدي وحتى الاتصال المصادق عليه:

# 1. Request a challenge
curl -s -X POST https://api.starhermit.com/api/v1/auth/public-key/challenge \
  -H "Content-Type: application/json" \
  -d '{"keyType":"Ed25519","keyData":"<base64-raw-32-byte-public-key>"}'
# → { "challengeId": "...", "payload": { ... }, "expiresIn": 300 }

# 2. Sign the serialized payload JSON with your private key, then complete
curl -s -X POST https://api.starhermit.com/api/v1/auth/public-key/complete \
  -H "Content-Type: application/json" \
  -d '{"challengeId":"...","signature":"base64-signature...","keyType":"Ed25519","keyData":"<base64-raw-32-byte-public-key>"}'
# → { "userId": "...", "accessToken": "...", "refreshToken": "..." }

# 3. Call the API with the access token
curl -s https://api.starhermit.com/api/v1/me \
  -H "Authorization: Bearer eyJhbGciOi..."

# 4. When the access token expires (after 15 min), rotate the refresh token
curl -s -X POST https://api.starhermit.com/api/v1/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{"refreshToken":"dGhpcyBpcyBh..."}'

# 5. On logout, revoke the refresh token
curl -s -X POST https://api.starhermit.com/api/v1/auth/logout \
  -H "Content-Type: application/json" \
  -d '{"refreshToken":"dGhpcyBpcyBh..."}'

تسجيل الدخول إلى OAuth يعتمد على المتصفح: قراءة GET /api/v1/auth/oauth/providers، افتح المزود المباشر authorizeUrl، والموافقة الكاملة، ويصل رد الاتصال بالمستخدم إلى الواجهة الأمامية #access_token=…&refresh_token=… في جزء URL.

إلغاء المفتاح عبر البريد الإلكتروني

للمالك الذي لا يستطيع الوصول DELETE /me/public-keys (لا توجد جلسة OAuth، أو تم قفلها بواسطة ملف مسروق المفتاح). POST /api/v1/auth/public-key/revoke-request مع { "email": "…" } يحمل طلبا و رسائل البريد الإلكتروني رابط. فتحه (GET /api/v1/auth/public-key/revoke/confirm?token=…) يظهر صفحة ذلك لا يغير شيئا؛ زر التأكيد الخاص به POSTإنه نفس عنوان URL، الذي يلغي كل المفتاح النشط على ذلك الحساب وينهي الجلسات التي تمت مصادقتها. كلاهما غير مصادق عليه و العدد رقم جلسة. الطلب يجيب دائما 202 بنفس الجسد مهما وجد. طلب واحد لكل الحساب كل 15 دقيقة، وتنتهي صلاحية الرابط بعد 4 ساعات. التأكيد POST إجابات 200 { "revoked": <count>, "sessionsEnded": <count> } إلى عميل API، أو 400 لمجهول أو مستعمل أو رمز منتهي الصلاحية، أو رمز لم يعد عنوانه يخص الحساب.

تذاكر اتصال WebSocket

POST /api/v1/realtime/connection-tickets استبدال الرمز المميز لحامل المتصل بتذكرة لمرة واحدة صالحة حوالي 30 ثانية. تمريرها كما ?ticket= على أي /ws/v1/* مصافحة. يحمل المتصل المطالبات حرفيا (بما في ذلك game_scope و pk)، تم رفضه في REST، ويتم إنفاقه عند الاستخدام الأول. قد يطلب أي متصل مصادق عليه، بما في ذلك رمز الإطلاق المميز على مستوى اللعبة. ?access_token= لا يزال يعمل حتى ينتقل العملاء.

وينتهي المقبس المفتوح عند إبطال بيانات الاعتماد الخاصة به. ينتهي إلغاء المفتاح العام الذي فتحه ذلك على الفور؛ يؤدي التعليق أو تسجيل الخروج في كل مكان إلى إنهاء الأمر في غضون 30 ثانية تقريبًا. انتهاء صلاحية الرمز المميز لا ينتهي بمقبس مفتوح — قم بالتحديث قبل إعادة الاتصال.

إعداد مضمن للألعاب المحلية/ألعاب واجهة المتجر

يمكن للعميل Steam أو Epic أو GOG أو المستقل إنشاء مفتاح على جهاز اللاعب وتقديم الملف يتدفق تسجيل المفتاح العام داخل واجهة المستخدم الخاصة به، مع تجنب OAuth وزيارة StarHermit لوحة القيادة. التسجيل ليس صامتًا: يجب على اللاعب الموافقة وتقديم بريد إلكتروني ومتابعة رابط التحقق لمرة واحدة. لا يمكن لرمز خادم اللعبة إنشاء لاعبين أو انتحالهم. يرى البرنامج التعليمي: لاعبين على متن الطائرة بمفتاح عام، و البرنامج التعليمي للخادم المخصص للعبة التي تشحن خادمًا أيضًا.
