مخطوطات اللعبة

يمكن تعريف لعبة StarHermit الموثوقة من خلال أ ملف جافا سكريبت واحد تم تنفيذها من جانب الخادم في وضع الحماية جينت محرك. النص هو المرجع الوحيد لقواعد تلك اللعبة: فهو يتحقق من صحة أوامر كل لاعب، ويغير الحالة، ويقرر ما قد يراه كل عميل، ويحسب Elo، وينهي الألعاب. العملاء ليس لديهم أي سلطة. توثق هذه الصفحة وقت تشغيل JavaScript؛ الألعاب التي تحتاج إلى لغة أخرى قد تقوم بدلاً من ذلك بتنفيذ خادم لعبة الحاوية بروتوكول. كلاهما يستخدم نفس مواجهة اللاعب واجهة برمجة تطبيقات الألعاب. المثال العملي طوال الوقت هو الشطرنج - التنفيذ المرجعي في HypeDriven/starhermit-الشطرنج.

نموذج التنفيذ

  • ملف JS واحد لكل لعبة، يتم تنفيذه في ملف محرك Jint ذو وضع الحماية الجديد لكل استدعاء. لا شيء يبقى في الذاكرة بين المكالمات - كل الحالة موجودة في المستندات التي تعيدها.
  • لا المحيطة Date أو Math.random. يتم توفير الوقت والعشوائية على النحو التالي: ctx.now (عصر مللي ثانية) و ctx.random (تطفو في [0, 1)).
  • تستدعي المنصة البرنامج النصي عندما يرسل اللاعب أمرًا دائمًا، وعندما يتم إنشاء الجلسة، وبشكل دوري onTick عمليات المسح (انظر واجهة برمجة تطبيقات الألعاب — توقيت وقت التشغيل). في الوقت الحالى {type:"input", realtime:true} الإطارات هي الاستثناء: يتم تخزين أحدث المكاسب مؤقتًا وتسليمها كدفعة إلى العلامة التالية.

نقاط الدخول

فضح المعالجات على globalThis.game. ستة اختيارية ثابت التصريحات تجلس بجانبهم: tickRateHz يسأل النظام الأساسي عن عدد مرات الاستدعاء onTick - أعلن ذلك إذا كانت لعبتك تعتمد على ضع علامة، نظرًا لأن اللعبة التي لا تقول شيئًا يتم تحديدها مرة واحدة كل أربع ثوانٍ (انظر معدل القراد), achievements يسجل إنجازات اللعبة (انظر الإنجازات), replays يطلب من المنصة الاحتفاظ بجلساتك النهائية (انظر الاعادة), persistent توقف مؤقتًا الجلسات بدلاً من إنهائها عندما يغادر الجميع (انظر جلسات مستمرة), linkedAchievements أسماء الألعاب الأخرى التي تتلقى عمليات إلغاء القفل فيها ctx.linkedAchievements (يرى الإنجازات من الألعاب الأخرى)، و queues يعلن تقبل أشكال التوفيق بين التطابقات (انظر الألعاب - التوفيق). لعبة الذي يعلن عدم وجود قوائم انتظار يحتوي على 1v1 ضمني:

globalThis.game = {
  tickRateHz: 0, // turn-based: opt out of periodic ticks
  replays: true, // keep finished sessions as replays
  queues: [{ key: "duos", teams: 2, teamSize: 2 }],
  achievements: [
    { key: "first-win", name: "First Win", description: "Win a match.", points: 10 }
  ],
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

تتم قراءة الإعلانات من خلال تقييم البرنامج النصي الخاص بك عندما يتم نشر اللعبة أو تحديثها, ليس في كل استدعاء — لذلك يجب أن تكون قيمًا ثابتة في ملف game هدف. نشر تحديث لتطبيق التغيير.

  • createSession(ctx) - يتم استدعاؤه عند إنشاء الجلسة (التوفيق، أو قبول الدعوة، أو ممارسة الذكاء الاصطناعي، أو بدء الغرفة في الوقت الفعلي - راجع جلسات مقيدة بالغرفة).
  • onPlayerMessage(ctx) — يُستدعى لأوامر العميل الدائمة التي يتم تلقيها عبر طريقة اللعب WebSocket. تم وضع علامة واضحة على المدخلات realtime:true تجاوز نقطة الدخول هذه.
  • onMembershipChange(ctx) - خياري. يتم استدعاؤه عندما ينضم لاعب إلى جلسة تشغيل أو يغادرها (أ غرفة التقدم، أو دعوة إلى لعبة قيد التقدم). ctx.players يعكس بالفعل التغيير، و ctx.membership يكون { change: "joined" | "left", userId, name, team, slot }. يعود { ok: false } لرفض الانضمام؛ البرنامج النصي الذي لا يحتوي على هذا الخطاف يرفض كل صلة. الإجازة نهائية مهما رجعت. الإنجازات والنتائج قد تتفوق على النتيجة؛ أ sessionState يتم تجاهله.
  • onTick(ctx) - يتم استدعاؤها بواسطة خدمة مؤقت النظام الأساسي بمعدل التجزئة الفعلي؛ أحدث المدخلات في الوقت الحقيقي متوفرة في ctx.inputs. لا تتلقى اللعبة التي تم تحليلها إلى 0 هرتز مكالمات دورية، ولكن يجب أن تظل الوظيفة موجودة للوفاء بعقد البرنامج النصي.

كائن السياق

ctx = {
  now: 1721473200000,              // ms epoch, from the host clock
  random: 0.7231,                  // float in [0, 1), from the host RNG
  sessionId: "0f8fad5b-...",       // current session id
  pausedMs: 0,                     // persistent games only: total ms this session has spent paused
  players: [                       // session participants
    { id: "7c9e6679-...", name: "alice" },
    { id: "00000000-0000-4000-8000-00000000a1a1", name: "The House", ai: true }
  ],
  sessionState: { /* ... */ },     // this script's session document, or null
  playerStates: {                  // per-player documents (elo, history), or null
    "7c9e6679-...": { elo: 1200, wins: 4, losses: 2, draws: 1, /* ... */ }
  },
  message: {                       // onPlayerMessage only
    from: "7c9e6679-...",          // the authenticated user id — trusted
    data: { type: "move", from: "e2", to: "e4" }  // client payload — untrusted (example: a chess move)
  },
  inputs: [                        // onTick only; omitted when none are pending
    { from: "7c9e6679-...",        // authenticated sender id — trusted
      data: { type: "input", seq: 42, mx: 0.7, mz: -0.2 } }
  ]
}
  • يتم وضع علامة على مقعد الذكاء الاصطناعي (إن وجد). ai: true على دخول اللاعب.
  • لعبة تعلن linkedAchievements يحصل أيضا ctx.linkedAchievements: { <playerId>: { <otherSlug>: [unlocked keys] } }، أعد القراءة عند كل استدعاء. يرى الإنجازات من الألعاب الأخرى.
  • تحصل الجلسات المرتبطة بالغرفة (التي تبدأ من غرفة في الوقت الفعلي) على حقلي ctx إضافيين، ctx.room و ctx.presence، على كل الدعوة - ​​انظر جلسات مقيدة بالغرفة.
  • لا تثق بشيء من ctx.message.data أو ctx.inputs[].data. الهوية الموثوقة هي المقابلة from، الذي يرفقه الخادم من الاتصال المصادق عليه - لا يمكن للعميل أبدًا توفيره أو انتحاله.
  • المدخلات تختار التجميع مع {type:"input", realtime:true, ...}. غير مميزة input تظل الأوامر دائمة onPlayerMessage يدعو إلى التوافق مع الإصدارات السابقة. تستخدم مدخلات الوقت الفعلي فتحة واحدة معلقة لكل مرسل: الحركة هي آخر المكاسب، بينما pass, shoot، و tackle يتم دمج حواف الإجراء بحيث لا يمكن لعينة الحركة التالية مسحها قبل العلامة التالية. يجب أن تقوم البرامج النصية بتثبيت كل قيمة والتحقق من صحتها عند استهلاك الدفعة.

معدل القراد

تعمل المنصة onTick عمليات المسح لكل جلسة نشطة بمعدل قابل للتكوين. يطلب البرنامج النصي الخاص بك السعر الذي يريده من خلال إعلان ثابت tickRateHz على كائن اللعبة، بجانب نقاط الدخول:

globalThis.game = {
  tickRateHz: 15,          // ask the platform to tick this game 15x/second
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};
  • تمت قراءة الإعلان عندما يتم نشر لعبتك أو تحديثها، وليس على كل علامة. نشر التحديث بعد تغييره.
  • اللعبة التي لا تعلن عن أي معدل يتم تحديدها عند 0.25 هرتز - مرة كل أربع ثواني. وهذا كثير الحكم على ساعة التحرك أو المهلة لا يكلف المنصة شيئًا تقريبًا، لكنه بطيء جدًا لأي شيء تعتمد عليه طريقة لعبك. لو onTick يقود لعبتك، أعلن عن المعدل الذي تحتاجه.
  • يتم تثبيت الطلبات على الحد الأقصى للمنصة (30 هرتز بشكل افتراضي)، لذلك يمكن أن تطلب اللعبة مبلغًا أقل مما تسمح به المنصة ولكن ليس أكثر من ذلك أبدًا. اطلب 0 لتعطيل القراد بالكامل للعبة يتفاعل فقط مع أوامر اللاعب.
  • قد تكون الأسعار كسور: 0.5 هي علامة كل ثانيتين. أصغر معدل غير الصفر هو 0.01 هرتز - يتم رفع رقم موجب أصغر إليه بدلاً من قراءته كإلغاء الاشتراك، لأن أ الكسر الصغير هو لعبة بطيئة. موقوتة معطلة فقط ل 0 أو معدل سلبي مفقود أو إعلان غير قابل للاستخدام (سلسلة، null, NaN) يأخذ الوضع الافتراضي 0.25 هرتز.
  • يمكن للمشغل تجاوز سعر لعبة معينة، في أي من الاتجاهين.
  • المدخلات في الوقت الفعلي هي أحدث المكاسب بين علامات التجزئة، بينما تظل حواف الإجراء المنفصلة مرتبة. قد يتخطى المستلم البطيء لقطة قديمة ولكن لا يمكنه تأخير المحاكاة أو المستلمين الآخرين.

الاعادة

عند انتهاء الجلسة، يمكن للمنصة الاحتفاظ بجلستها النهائية sessionState كما اعادتها - ال الوثيقة التي يخدمها GET /api/v1/games/{slug}/replays/{sessionId} (يرى واجهة برمجة تطبيقات الألعاب - الإعادة). الإعادة عبارة عن تخزين محفوظ لمدة طويلة مثل سجل المباراة هو، لذلك لعبتك تحصل على واحدة فقط إذا طلبت ذلك:

globalThis.game = {
  replays: true,           // keep finished sessions as replays
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};
  • يجب أن يكون الإعلان حرفيًا true أو false — أي شيء آخر يُقرأ على أنه لا يوجد إعلان، و اللعبة التي لا تعلن شيئًا ليس لها إعادة.
  • تمت قراءته عندما يتم نشر لعبتك أو تحديثها. نشر التحديث بعد تغييره.
  • قد يجيب مشغل المنصة على لعبة معينة في كلتا الحالتين، وبالتالي فإن الإعلان هو طلب بدلا من الضمان. GET /api/v1/games/{slug} تقارير الجواب كما replaysEnabled — قم بتفرع واجهة مستخدم إعادة التشغيل الخاصة بك على ذلك، وليس على ما طلبه البرنامج النصي الخاص بك.
  • لا يتغير أي شيء آخر مع إيقاف عمليات إعادة التشغيل: لا تزال حالة الجلسة الخاصة بك مخزنة ويتم إعادتها إليها كل دعوة كما ctx.sessionState، ولا تزال نقطة استعادة التعطل. يا لها من لعبة بدون عمليات إعادة التشغيل، لا يتم الحصول على نسخة تتجاوز مدة الجلسة، لذلك تجيب نقاط نهاية إعادة التشغيل الخاصة بها 404.
  • تصميم النهائي sessionState تستحق الإعادة — سجل التحركات، أو أي شيء يحتاجه عميلك لإعادة بناء المباراة. يستمر تنفيذ مرجع الشطرنج state.game.moves وخطوات ذلك من خلال نفس وحدة القواعد التي تنفذها المنصة.

جلسات مستمرة

لعبة تعلن persistent: true يحتفظ بجلساته عندما يغادر كل لاعب. حوالي 15 ثواني بعد آخر قطع الاتصال بالجلسة متوقف مؤقتا - لا onTick المكالمات - والأول لاعب لإعادة الاتصال يستأنف ذلك. يؤدي قطع الاتصال أو عدم النشاط إلى إيقاف الجلسة مؤقتًا بدلاً من تركها. نتيجة المباراة يا صاحبي إجراء، أو إجازة صريحة للعضو النهائي، أو انتهاء صلاحية الاحتفاظ المهيأة، أو فشل استرداد المحطة الطرفية لا تزال تنتهي منه. يرى دورة حياة الجلسة.

globalThis.game = {
  persistent: true,        // pause empty sessions instead of ending them
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};
  • يجب أن يكون حرفيا true أو false. تمت قراءته عندما يتم نشر لعبتك أو تحديثها.
  • ctx.now تبقى ساعة الحائط. تحصل أيضًا على جلسات مستمرة ctx.pausedMs، إجمالي الوقت الذي يقضيه توقفت، لذلك ctx.now - ctx.pausedMs هي الساعة التي تقف ساكنة بينما لا أحد هناك.
  • يتم احتساب الجلسات المتوقفة مؤقتًا مقابل الحد الأقصى للجلسة لكل لاعب، لذا أعط اللاعبين أمرًا ينتهي بـ العالم مع أ result.

انظر البرنامج التعليمي للجلسات المستمرة للحصول على مثال عملي وتدفق العميل.

التوفيق بين تخطيط مقعد

تلقي جلسات مطابقة جديدة ctx.matchmaking على كل الاستدعاء (الإنشاء والأمر والعلامة). يحافظ على شكل قائمة الانتظار والمقاعد حتى لو تم إعادة نشر اللعبة لاحقًا:

ctx.matchmaking = {
  queue: "ffa", teams: 4, teamSize: 1,
  seats: [
    { id: "human-uuid", name: "Alice", team: 0, slot: 0, ai: false },
    { id: "synthetic-ai-uuid", name: "AI 2-1", team: 1, slot: 0, ai: true },
    { id: null, name: null, team: 2, slot: 0, ai: false },
    { id: null, name: null, team: 3, slot: 0, ai: false }
  ]
};

ctx.players يحتوي على مقاعد مشغولة فقط، مع team و ai:true للذكاء الاصطناعي. فهارس الفريق/الفتحة هي على أساس الصفر. معرفات الذكاء الاصطناعي مستقرة خلال هذه الجلسة وليست معرفات حساب StarHermit. البشر فقط لديك عضوية جلسة/دردشة ويمكنها الحصول على كتابات حالة اللاعب أو التقييم أو الإنجاز. حافظ على حالة الذكاء الاصطناعي sessionState. انسخ حقول القائمة التي يحتاجها العملاء إلى حالة لعبتك أو البث. يمكن حذف الجلسات الأقدم والجلسات غير المخصصة للتوفيق ctx.matchmaking.

أعلن عن الموعد النهائي للبدء والحد الأقصى لعدد الذكاء الاصطناعي starhermit.txt. مع عدد منظمة العفو الدولية 0، تبقى المقاعد الشاغرة فارغة. يتم تسليم نفس السياق إلى خوادم الحاويات.

جلسات مقيدة بالغرفة

يمكن أن تكون الجلسة منضمة إلى غرفة الوقت الحقيقي: عندما أ غرفة الوقت الحقيقي للعبة مع أ server= يبدأ البرنامج النصي، وتقوم المنصة بإنشاء جلسة N-player واحدة للغرفة بشر المشاركين (مقاعد الذكاء الاصطناعي موجودة فقط في القائمة التي تواجه البرنامج النصي). هذه هي الطريقة التي يتم بها تشغيل ألعاب الوقت الفعلي المعتمدة من الخادم (مثل كرة القدم): توفر الغرف الردهة/التوفيق، ويقوم البرنامج النصي بتشغيل المباراة. يرى غرف الوقت الحقيقي — الجسر لدورة حياة جانب الغرفة.

كل دعوة (createSession, onPlayerMessage, onTick) لجلسة مقيدة بالغرفة تتلقى حقلين ctx إضافيين:

ctx.room = {
  roomId: "0f8fad5b-...",
  metadata: { /* ... */ },        // the room's opaque config.metadata blob
  roster: [                       // frozen match roster, humans AND AI seats,
    { userId: "7c9e6679-...",     //   ordered by team then slot
      name: "alice", team: 0, slot: 0, ai: false },
    { userId: null,               // AI seat — never a session player
      name: "Rafa Vento", team: 0, slot: 1, ai: true }
  ]
};
ctx.presence = {                  // every user who is or was a human participant
  "7c9e6679-...": { online: true, left: false }
};
  • presence.online — لدى المستخدم مقبس مباشر في أي من سجلي الاتصال (غرف الوقت الفعلي أو ws/v1/games).
  • presence.left — لم يعد المستخدم يشغل مقعدًا نشطًا: لقد غادر صراحةً وتم تحويل مقعده إلى مشارك يعمل بالذكاء الاصطناعي. left دائم؛ online قد ترفرف. من المتوقع أن يقود البرنامج النصي منطق الاستيلاء/إعادة الانضمام لمنظمة العفو الدولية من هذه العلامات.
  • تتم إعادة قراءة القائمة عند كل استدعاء، لذلك تظهر تحويلات المقاعد (البشرية → الذكاء الاصطناعي) فور حدوثها.

عندما يعود البرنامج النصي المرتبط بالغرفة result، المنصة تنهي الجلسة، يخزن النتيجة في الغرفة، ويغلق الغرفة - لا توجد نتيجة مقدمة من المضيف.

والعكس غير صحيح: إغلاق الغرفة لا ينهي جلستها. إذا تم إغلاق الغرفة أولاً (على سبيل المثال لأن آخر إنسان غادر الغرفة دون تسجيل قيد التقدم - ليس فقط لأن المضيف أصبح غير متصل بالإنترنت، وهو ما يؤدي فقط إلى نقل دور المضيف عندما تكون الجلسة نشطة)، فستستمر الجلسة في العمل، ctx.room.roster يصبح فارغًا ويظهر كل إنسان left: true. يعود result ثم إذا كانت المباراة يجب أن تنتهي بالغرفة. يرى غرف الوقت الفعلي — قاعدة المضيف لمدة 60 ثانية والجلسات المرتبطة بالغرفة.

عودة الشكل

تقوم كل نقطة إدخال بإرجاع نفس الشكل (جميع الحقول اختيارية باستثناء ok):

return {
  ok: true,                        // false on failure
  error: "Illegal move",           // goes only to the sender (as a WS "error" frame)
  sessionState: { /* ... */ },     // REPLACES the stored session document
  playerStates: {                  // REPLACES stored per-player documents
    "7c9e6679-...": { elo: 1216, /* ... */ }
  },
  broadcast: [                     // only these messages ever reach clients
    { to: "all", data: { type: "moved", /* ... */ } },
    { to: ["9b2f8c1a-..."], data: { type: "state", /* ... */ } }
  ],
  eloUpdates: {                    // published to the game's leaderboard by the host
    "7c9e6679-...": 1216,
    "9b2f8c1a-...": 1184
  },
  achievements: {                  // server-authoritative unlocks, by player id
    "7c9e6679-...": ["first-win", "flawless"]
  },
  scores: {                        // to your game's own leaderboards, by board key
    "high-score": { "7c9e6679-...": 4200 }
  },
  result: { kind: "white-win", reason: "checkmate" }  // ends the session (example: a chess result)
};

القواعد الأساسية:

  • sessionState وكل دخول playerStates يستبدل المستندات المخزنة - قم دائمًا بإرجاع المستندات الكاملة، ولا تختلف أبدًا.
  • الرسائل المدرجة فقط في broadcast يتم تسليمها للعملاء، كل منها موجه إلى معرفات اللاعب الصريحة أو "all". لا شيء آخر يتسرب.
  • eloUpdates هي الطريقة الوحيدة لتغيير التقييمات. القيم هي كل لاعب تصنيف مطلق جديد، يتم تطبيقه كما تم إرساله - النظام الأساسي لا يضع حدًا أقصى للتغيير لكل مباراة، لذا قم بتثبيته بنفسك (انظر إيلو لكل مباراة). يستخدمها المضيف من أجل التوفيق وينشرها على لوحة المتصدرين للعبة؛ لا يمكن للعملاء أبدًا إرسال النتائج مباشرة (انظر المتصدرين). الحفاظ على التصنيف في playerStates[id].elo لذلك المالك إعادة تعيين التصنيف يصل إلى نسختك أيضًا.
  • achievements هي الطريقة الوحيدة لمنح الإنجازات. يتم حل المفاتيح وفقًا لإنجازات اللعبة - التي تم الإعلان عنها أو إنشاؤها بواسطة مالكها - وتستمر بواسطة النظام الأساسي؛ يرى الإنجازات.
  • scores هي الطريقة الوحيدة التي تتغير بها لوحات المتصدرين الخاصة بلعبتك - انظر المتصدرين.
  • إنهاء الألعاب عبر result. ثم ينهي المضيف الجلسة ويلعب مع الاعادة أرشيف النهائي sessionState كما الإعادة (يخدم من قبل GET .../replays/{sessionId} - يرى واجهة برمجة تطبيقات الألعاب).

الإنجازات

البرنامج النصي الخاص بك هو فقط الشيء الذي يمكن أن يفتح إنجازات لعبتك. لا يوجد عميل نقطة النهاية بالنسبة لهم: POST /api/v1/me/achievements/unlock يرفض الإنجازات على نطاق اللعبة بشكل مباشر، وترفض نقاط نهاية CRUD الخاصة بالناشر لمسها. يمكن لصاحب اللعبة إضافة إنجازات بجانبه المعلنة من خلال /me/github-games/{id}/achievements; يفتح البرنامج النصي الخاص بك تلك المفاتيح بنفس الطريقة تمامًا. وهذا يجعل الإنجازات كخادم- موثوقة مثل بقية اللعبة، وهي الآلية أي لعبة مع server= script يجب استخدامه - بما في ذلك الشخص الذي يتم تشغيل طريقة لعبه في مكان آخر (انظر ما هي الألعاب التي يمكنها استخدام هذا؟).

يعلن

ثابت achievements مصفوفة على game هدف. فقط key مطلوب:

globalThis.game = {
  achievements: [
    { key: "first-win", name: "First Win", description: "Win a match.", points: 10 },
    { key: "flawless",  name: "Flawless",  description: "Win without conceding.",
      points: 50, secret: true, icon: "https://cdn.example/flawless.png" }
  ],
  // ...entry points
};
مجال يكتب ملحوظات
key خيط مطلوب. معرف ثابت، ≥ 128 حرفًا، فريد داخل اللعبة. يتم تجاهل التكرارات بعد الأولى.
name خيط الافتراضات ل key.
description خيط الافتراضات ل "".
icon خيط عنوان URL اختياري.
secret منطقية مخفية عن اللاعب حتى هم فتحه. الافتراضات ل false.
points رقم مثبتة إلى 0-10000. الافتراضات ل 0.

يتم تطبيق المصفوفة عند نشر اللعبة أو تحديثها:

  • التعاريف متطابقة key - يؤدي تحرير الاسم أو الرمز أو النقاط أو العلامة السرية إلى تحديث التعريف الحالي، ويحتفظ به كل من حصل عليه بالفعل.
  • يتم حذف المفتاح الذي توقفت عن التصريح عنه فقط بينما لم يفتحه أحد. لا يتم تدمير التاريخ المكتسب أبدًا، لذا يظل الإنجاز المتقاعد مرئيًا للاعبين الذين يحملونه.
  • على الأكثر 100 الإنجازات لكل لعبة؛ يتم إسقاط الإضافات التي تتجاوز ذلك.
  • الإعلان هو أفضل جهد: يتم تخطي الإدخالات المشوهة. قم دائمًا بتأكيد التعريفات المنشورة باستخدام GET /api/v1/games/{slug}/achievements بعد تحديث اللعبة.

فتح

العودة ان achievements خريطة من أي نقطة الدخول — createSession, onPlayerMessage، أو onTick:

onTick(ctx) {
  const state = JSON.parse(JSON.stringify(ctx.sessionState));
  const unlocks = {};
  for (const p of ctx.players) {
    if (!p.ai && state.scores[p.id] >= 10) unlocks[p.id] = ["ten-points"];
  }
  return { ok: true, sessionState: state, achievements: unlocks };
}
  • يفتح عاجز - إعادة التأكيد على المفتاح الذي يحمله اللاعب بالفعل هو أمر محظور، لذلك يمكن للبرنامج النصي أن يمنح بأمان من الشرط الذي يعيد تقييمه في كل علامة بدلاً من التتبع "منحت بالفعل" في حالته الخاصة.
  • يتم تجاهل المفاتيح غير المعروفة (لم يتم الإعلان عنها ولم يتم إنشاؤها من قبل مالك اللعبة)، والمستخدمين الذين ليسوا مشاركين في هذه الجلسة، ومقعد الذكاء الاصطناعي بصمت.
  • على الأكثر 32 يتم قبول المفاتيح لكل لاعب لكل استدعاء؛ يتم إسقاط المزيد من المفاتيح في نفس المصفوفة.
  • تستمر الصفوف مع بقية عمليات الكتابة الخاصة بالاستدعاء، لذا لا يمكن أن ينجو إلغاء القفل من استدعاء فاشل.

توصيل

يتم دفع كل فتح تم منحه حديثًا إلى اللاعب الفائز ws/v1/games كإطار متميز - إنها حقيقة المنصة، وليست واحدة منكم broadcast رسائل:

{ "type": "achievement",
  "data": { "key": "first-win", "name": "First Win", "description": "Win a match.",
            "icon": null, "points": 10, "unlockedAt": "2026-07-25T09:14:02Z" } }

يفتح الممنوحة من createSession يهبطون قبل وجود أي مقبس، لذلك يصلون بدون إطار - يجب على العملاء قراءة GET /api/v1/games/{slug}/achievements عند التحميل وتعامل مع الإطار باعتباره مسار التحديث المباشر سطح كامل في الإنجازات.

المتصدرين

إلى جانب لوحة elo، يمكن أن تشتمل لعبتك على لوحات صدارة ينشئها مالكها POST /api/v1/me/github-games/{id}/leaderboards, كل مع أ key. أرسل لهم عن طريق العودة scores من أي نقطة دخول — مفتاح اللوحة → معرف اللاعب → الرقم:

onPlayerMessage(ctx) {
  var s = ctx.sessionState;
  if (ctx.message.data.type === "finish-run") {
    var scores = { "high-score": {}, "fastest-run": {} };
    scores["high-score"][ctx.message.from] = s.points[ctx.message.from];
    scores["fastest-run"][ctx.message.from] = ctx.now - s.startedAt;   // a time-ms board
    return { ok: true, sessionState: s, scores: scores };
  }
  /* ... */
}
  • يحتفظ كل لاعب به أفضل سجل على كل لوحة، حسب اتجاه نوع اللوحة، لذا قم بالإبلاغ كل نتيجة – يتم تجاهل النتيجة الأسوأ بكل بساطة.
  • يتم احتساب المشاركين في الجلسة فقط. مفاتيح غير معروفة أو غير نشطة، ونتائج خارج قواعد اللوحة، يتم إسقاطها بصمت. على الأكثر 16 لوحة لكل عودة.
  • على عكس eloUpdates، لا يتم نشر أي شيء playerStates - احتفظ بنسختك الخاصة playerStates إذا كانت اللعبة تحتاج إلى قراءة أفضل ما في الأمر شخصيًا.

حيث يتم تشغيل البرنامج النصي الخاص بك

البرنامج النصي الذي يتكرر بلا حدود، أو يستنفد ذاكرته، أو يتجاوز ميزانيته الزمنية، يفشل في استدعاء. لا يتم تطبيق نتائجها الفاشلة. يُبلغ الأمر أو العلامة عن واحد مما يلي:

  • Game script error: the script crashed its runtime (for example, by recursing without limit).
  • Game script error: the script exceeded its memory budget.
  • Game script error: the script exceeded its time budget.

حصة لعبتك من السيرفر

  • وقت البرنامج النصي. تشترك جميع جلسات اللعبة في ميزانية زمنية للبرنامج، تبلغ 2000 مللي ثانية في الثانية الافتراضي، مكلف بما استغرقه كل استدعاء بالفعل. تم رفض اللعبة على حصتها بدلاً من ذلك من قائمة الانتظار: يتم تخطي علامة الاختيار، ويتم الرد على الأمر "هذه اللعبة تستخدم أكثر من حصتها من الخادم الآن؛ حاول مرة أخرى قريبا."، وإنشاء عوائد الجلسة 429.
  • الأوامر. يمكن لكل لاعب إرسال 20 أمرًا دائمًا في الثانية لكل جلسة (مع دفعة قصيرة بدل)؛ أبعد من ذلك يتم الرد على الأمر بـ error إطار، "أوامر كثيرة جدًا؛ ابطئ." لا يتضمن الإطار حالة HTTP. الإدخال في الوقت الفعلي محدود بشكل منفصل.
  • نتائج. قد تكون النتيجة التي تنتهي بها الجلسة 64 كيلو بايت على الأكثر؛ تم رفض واحد أكبر 422.
  • حجم البرنامج النصي. A server= يمكن أن يصل حجم البرنامج النصي إلى 2 ميغابايت على الأكثر؛ تم رفض واحد أكبر 422 من قبل يتم تخزينها أو تحليلها.

يمكن للمشغلين رفع أو خفض كل من هذه العناصر في لعبة فردية.

الميزانيات

تعمل البرامج النصية ضمن ميزانيات الموارد هذه:

  • ~250 مللي ثانية لوحدة المعالجة المركزية لكل استدعاء
  • ذاكرة 32 ميجابايت
  • حد بيان لكل استدعاء
  • ميزانية بايت لكل لاعب — يجب أن تظل جميع مستندات الحالة قابلة للتسلسل وصغيرة الحجم
  • تتداخل القيم على عمق 64 مستوى على الأكثر عندما تصبح نصًا. أي شيء ترجعه نقطة الدخول، كل إعلان, JSON.stringify، و Array.prototype.join/toString/toLocaleString رفض أ قيمة أعمق مع RangeError (واحد تم إرجاعه يفشل في الاحتجاج: "متداخلة أكثر من 64 المستويات عميق"). JSON.parse توقفت بالفعل عند 64، لذا فإن القيمة الأعمق لا يمكن أبدًا أن تكون ذهابًا وإيابًا. flat تتسطح حتى 64 مستوى وترمي إذا كانت المصفوفة متداخلة بشكل أعمق - بما في ذلك المصفوفة التي تحتوي على نفسها.
  • لا يمكن لمكالمة واحدة تخصيص أكثر من ميزانية الذاكرة. repeat, padStart/padEnd, concat و replace/replaceAll يرمي RangeError: Invalid string length عندما يمكن أن تتجاوز النتيجة النصف الميزانية بالأحرف (16 مليونًا في الوضع الافتراضي 32 ميجابايت؛ ويحد استبدال regex كما لو كان كل الموضع المطابق، والذي يؤثر فقط على سلاسل مكونة من حوالي مليون حرف أو أكثر). ArrayBuffer ورمي المصفوفات المكتوبة RangeError تجاوز الميزانية بالبايت، والمصفوفات الماضية تم رفض عناصر الميزانية/8. يتم أيضًا فحص الميزانية بعد إرجاع خطافك، لذلك البيان النهائي الزائد عن الميزانية يفشل في الاستدعاء بدلاً من النجاح.

يبقي النص المرجعي للشطرنج مستنداته صغيرة عن قصد - وكمثال على الالتزام بالميزانية، فإن المستند الخاص بكل لاعب هو

{
  elo: 1200,
  wins: 0, losses: 0, draws: 0,
  lastColorVs: "9b2f8c1a-...",        // for color alternation on rematch
  lastColorOrder: "w",
  recentGames: [ /* up to 30 summaries */ ]
}

الحد الأقصى للجلسة المتزامنة هو 20 لكل لاعب بشكل افتراضي.

النافذة القابلة للقراءة على المنصة

كل شيء في sessionState غير شفاف للمنصة يستثني حقل واحد:

sessionState.summary = {
  turnPlayerId: "7c9e6679-...",
  deadline: 1784642591000,
  status: "active",
  moveCount: 41
};

deadline هو الطابع الزمني يونكس عدد صحيح في ميلي ثانية، أو تم حذفها عندما لا يكون هناك موعد نهائي. لم يتم التعرف على سلسلة تاريخ ISO. turnPlayerId هو UUID لاعب.

GET /api/v1/games/{slug}/sessions/mine يقرأ summary لحساب myTurn و deadline للمتصل. اجعلها دقيقة عند كل تغيير في الحالة؛ احتفظ بكل شيء آخر أينما يريد البرنامج النصي الخاص بك.

مثال عملي: نص الشطرنج

كل شيء في هذا القسم خاص بالتنفيذ المرجعي للشطرنج - شكل الحالة، وترميز اللوحة، ومجموعة الأوامر، وأسباب انتهاء اللعبة، وثابت Elo، والذكاء الاصطناعي، والمهلات أدناه هي اختيارات الشطرنج الخاصة، والمحددة في نصها. لا يعد أي منها سلوكًا على المنصة؛ تحدد لعبتك مرادفاتها الخاصة.

حالة الجلسة:

{
  white: "7c9e6679-...",
  black: "9b2f8c1a-...",
  aiId: "00000000-0000-4000-8000-00000000a1a1",   // present in AI games
  game: {
    board: "RNBQKBNRPPPPPPPP................................pppppppprnbqkbnr", // 64 chars
    turn: "w",
    castling: { K: true, Q: true, k: true, q: true },
    epSquare: null,
    halfmoveClock: 0,
    fullmove: 1,
    moves: [ { from: "e2", to: "e4", promo: null, san: "e4", at: 1721473200000 } ],
    positionCounts: { /* fen-key: count, for threefold repetition */ },
    status: "active"
  },
  createdAt: 1721473200000,
  deadline: 1721559600000,
  result: null,
  drawOfferBy: null,
  summary: { turnPlayerId: "...", deadline: "...", status: "active", moveCount: 1 }
}

ترميز اللوحة: سلسلة مكونة من 64 حرفًا index = rank * 8 + file و a1 هو الفهرس 0. PNBRQK هي قطع بيضاء، pnbrqk أسود، . هو مربع فارغ.

الأوامر التي تم التعامل معها من قبل onPlayerMessage: sync, move, resign, offer-draw, accept-draw, decline-draw (أشكال الأسلاك في واجهة برمجة تطبيقات الألعاب).

انتهت اللعبة reason قيم: checkmate, stalemate, threefold-repetition, fifty-move-rule, insufficient-material, resignation, agreement, timeout, timeout-no-moves.

تفاصيل أخرى في لعبة الشطرنج:

  • إيلو يستخدم K = 32، محسوبة في finishGame عندما تنتهي اللعبة، ويعود عبر eloUpdates.
  • اللعب بالذكاء الاصطناعي: عندما يتحرك مقعد الذكاء الاصطناعي، aiReply مسرحيات "هال" - محرك جشع لالتقاط المواد - داخل نفس الاستدعاء. لا يوجد بوت خارجي.
  • المهلات: onTick يفصل في ساعة الحركة على مدار 24 ساعة — إذا لم يتم لعب أي نقلات، تكون اللعبة عبارة عن timeout-no-moves يرسم؛ وإلا فإن اللاعب الذي يتحرك سيخسر timeout.

النشر

قم بتعريف البرنامج النصي في مستودع اللعبة الخاص بك starhermit.txt يظهر:

server=server.js

يتدفق النشر من خلال تكامل GitHub - راجع ألعاب جيثب. تقوم المنصة بتنفيذ البرنامج النصي ضمن الميزانيات الموثقة. لا تجمع server= مع container.image=; استخدم وقت تشغيل الحاوية بدلاً من ذلك عند شحن صورة.

أفضل الممارسات

  • التحقق من صحة كل أمر. يعامل ctx.message.data باعتبارها معادية: تحقق من الأنواع والنطاقات وترتيب الأدوار وحالة اللعبة قبل لمس الحالة.
  • اجعل الدعوات سريعة وصغيرة الحجم. لديك ما يقرب من 250 مللي ثانية وميزانية بايت لكل مستند لاعب؛ النص المرجعي للشطرنج، على سبيل المثال، قبعات recentGames في 30 إدخالات لهذا السبب.
  • يستخدم ctx.now / ctx.random فقط. لا Date، لا Math.random - يمتلك المضيف الساعة والنرد.
  • تصميم broadcast الرسائل باعتبارها عقد العميل الوحيد. يجب أن يكون العملاء قادرين على عرض اللعبة بأكملها مما يرسله البرنامج النصي؛ أي شيء لا يبث لا وجود له بالنسبة لهم.
  • ملف واحد، سطحين. يمكن مضاعفة الملف نفسه كقواعد من جانب العميل من خلال تصدير منفصل: على سبيل المثال، يتم الكشف عن تنفيذ مرجع الشطرنج globalThis.chessRules للمتصفح (معاينة النقل، وتلميحات التحقق من الصحة) و globalThis.game للمضيف. مصدر واحد للحقيقة، ولا سلطة على العميل.
  • قم دائمًا بإنهاء الألعاب عبر result لذا تقوم المنصة بنشر تحديثات Elo وأرشفة إعادة التشغيل عندما تكون لعبتك متاحة الاعادة.

انظر تجول الشطرنج للقيام بجولة سطرًا تلو الآخر، و مطالبات الذكاء الاصطناعي للمساعدة في إنشاء البرنامج النصي الخاص بك.

مشترك اتفاقيات API وصف تحليل الاستجابة، والطوابع الزمنية، وترقيم الصفحات، وإعادة المحاولة.

يرى التوافق الاعتماد و العقود المقروءة آليا.
