البرنامج التعليمي: الجلسات المستمرة - الألعاب التي تتوقف مؤقتًا عندما يغادر الجميع

عادةً ما تُنهي المنصة المباراة التي لا يلعبها أحد: بمجرد أن ينقطع اتصال كل لاعب ولا أحد عاد في غضون خمس دقائق، وتنتهي الجلسة كما abandoned مع السبب players_left (يرى واجهة برمجة تطبيقات الألعاب - طريقة اللعب WebSocket). هذا صحيح بالنسبة للشطرنج لعبة أو سباق، وخطأ بالنسبة لمزرعة أو باني مدينة أو زنزانة مشتركة أو أي عالم مجموعة يعود اللاعبون إلى أكثر من أيام.

لعبة يمكن أن نسأل عنه جلسات مستمرة بدلاً من. تتوقف الجلسة المستمرة مؤقتًا عندما ينقطع اتصال لاعبيها:

  1. آخر لاعب يغادر.
  2. بعد حوالي 15 ثانية مع عدم اتصال أي شخص بالمنصة توقف مؤقتًا الجلسة. لا شيء يعمل: لعبة السيناريو لا تحصل على أي onTick المكالمات، وتتم إزالة جلسة لعبة الحاوية من ملف حاوية.
  3. تظل الجلسة متوقفة مؤقتًا ضمن سياسة الاحتفاظ بالاسترداد الخاصة بها. يقرأ /sessions/{id}/recovery لأي انتهاء الصلاحية بدلا من افتراض الاحتفاظ بها إلى الأبد.
  4. أول لاعب يتصل ws/v1/games يستأنف ذلك، قبل أمرهم الأول التعامل معها. يستمر اللعب من حيث توقف.

توضح هذه الصفحة كيفية تشغيله، وكيفية منع ساعات لعبتك من القفز عبر التوقف المؤقت، و ما يحتاج عميلك إلى القيام به.

1. الاشتراك

الثبات هو إعلان لكل لعبة، يمكنك قراءته عند نشر لعبتك أو تحديثها - انشر إعلانًا التحديث بعد تغييره. يجب أن يكون حرفيا true أو false; أي شيء آخر يعتبر لا الإعلان، واللعبة التي تعلن عن لا شيء تتصرف كما كانت من قبل.

لعبة السيناريو - ثابت persistent على game كائن (انظر مخطوطات اللعبة):

globalThis.game = {
  persistent: true,
  tickRateHz: 1,
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

لعبة الحاوية — persistent في الخاص بك GET /describe الجواب (انظر خوادم ألعاب الحاويات):

{ "protocol": 1, "tickRateHz": 20, "maxSessions": 48, "persistent": true }

لم يتغير شيء حول كيفية إنشاء الجلسات: التوفيق، والدعوات، ونقطة نهاية الذكاء الاصطناعي، والوقت الفعلي تنتج جميع الغرف جلسات مستمرة للعبة مستمرة.

2. حافظ على ثبات وقت اللعبة أثناء الإيقاف المؤقت

المنصة لا تعيد الكتابة ctx.now - تظل ساعة الحائط الحقيقية، لذلك في أي وقت مطلق إظهار اللاعبين (الموعد النهائي، أ "الحصاد جاهز عند") يبقى يعني ما يقوله. بدلا من ذلك، مثابرة تحصل الجلسات على حقل سياق إضافي واحد:

ctx.pausedMs   // total milliseconds this session has spent paused, so far

إنه ينمو فقط، وفقط في الجلسات المستمرة (الألعاب الأخرى لا ترى المجال أبدًا). اطرحها وأنت لديك ساعة اللعبة الذي يتوقف بينما لا أحد هناك:

function gameTime(ctx) {
  return ctx.now - (ctx.pausedMs || 0);
}

globalThis.game = {
  persistent: true,
  tickRateHz: 1,

  createSession(ctx) {
    return { ok: true, sessionState: { lastTick: gameTime(ctx), crops: [] } };
  },

  onTick(ctx) {
    var state = ctx.sessionState;
    var t = gameTime(ctx);
    var dt = t - state.lastTick;      // never includes the time the world was paused
    state.crops.forEach(function (crop) { crop.growth += dt; });
    state.lastTick = t;
    return { ok: true, sessionState: state };
  },

  onPlayerMessage(ctx) { /* ... */ }
};

قم بتخزين الطوابع الزمنية الخاصة بك في وقت اللعبة (gameTime(ctx))، وليس في ctx.now، ومقارنتها فقط ضد وقت المباراة إذا كنت يريد العالم يمضي قدمًا دون أن يراقبه أحد - محاصيل تنمو بين عشية وضحاها - استخدام ctx.now بدلاً من ذلك ومتابعة العلامة الأولى بعد السيرة الذاتية. وفي كلتا الحالتين هو الخاص بك الاختيار؛ تقوم المنصة بالإبلاغ فقط عما حدث.

تفاصيل التوقيت:

  • خلال الـ 15 ثانية تقريبًا بين مغادرة آخر لاعب والتوقف المؤقت، تظل الجلسة ثابتة تكتك بشكل طبيعي. اللاعب الذي ينقطع اتصاله ويعود مباشرة لا يتسبب في توقفه مؤقتًا.
  • بعد السيرة الذاتية، في اليوم التالي onTick يأتي فاصل زمني واحد في وقت لاحق. لا يتم إعادة تشغيل الوقت المتوقف مؤقتًا كتراكم من القراد الفائتة.

حاوية تستقبل pausedMs في نفس المكان: في POST /sessions الجسم يتم إرساله عندما تتم استعادة الجلسة بعد توقف مؤقت.

3. عميلك

تظل الجلسة المتوقفة مؤقتًا جلسة نشطة، وبالتالي فإن تدفق العميل هو الذي لديك بالفعل:

  • قائمة العوالم للانضمام مرة أخرى مع GET /api/v1/games/{slug}/sessions/mine. كل إدخال لديه pausedAt الطابع الزمني أثناء إيقافه مؤقتًا و null أثناء وجود شخص ما فيه، حتى تتمكن من إظهاره "متوقف مؤقتا منذ…" أو "2 أصدقاء يلعبون الآن" (يرى واجهة برمجة تطبيقات الألعاب - الجلسات).
  • إعادة الانضمام عن طريق الفتح ws/v1/games?sessionId=… تماما كما كان من قبل. السيرة الذاتية تحدث خلال اتصال. لا يوجد خاص "تم استئنافه" إطار لها - يتم تشغيل اللعبة ببساطة عند أول مرة وصول الأمر - لذا اطلب أو انتظر رسالة الحالة الكاملة العادية للعبتك، كما تفعل في السابق أي إعادة الاتصال.
  • التعامل مع السيرة الذاتية الفاشلة. إذا لم يتمكن النظام الأساسي من استئناف الجلسة — على الأرجح حاوية اللعبة التي لا يزال خادمها قيد التشغيل — تتلقى {"type":"error","error":"…"} والمقبس مغلق بالكود 1001. تظل الجلسة متوقفة مؤقتًا ولا يتم فقدان أي شيء. أعد الاتصال بعد فترة قصيرة التراجع (بضع ثوان، المتزايد)، والعرض "بدء العالم…" بدلا من الخطأ.
  • presence تعمل الإطارات كالمعتاد، حتى يرى اللاعبون الآخرون من هو الموجود في العالم الآن.

4. إنهاء الجلسة المستمرة

تنتهي الجلسة المستمرة عندما:

  • تقارير لعبتك أ result (قيمة إرجاع البرنامج النصي أو رسالة التحكم في الحاوية)، أو
  • ينهيها مالك اللعبة (DELETE /api/v1/me/github-games/{id}/sessions/{sessionId}),
  • العضو الأخير يترك صراحة عالمًا بدون غرفة من خلاله /sessions/{id}/leave، أو
  • تنتهي صلاحية بيانات الاسترداد المتوقفة مؤقتًا بموجب سياسة الاحتفاظ بالنشر.

قطع الاتصال يترك العضوية سليمة؛ ترك صراحة يتخلى عن العضوية. يرى دورة حياة الجلسة والانتعاش لكلا التدفقين.

السؤال عن لعبة جديدة يفعل لا قم بإلغاء جلسات اللاعب المتوقفة مؤقتًا، ولا تزال الجلسات المتوقفة مؤقتًا تحتسب مقابل الحد الأقصى للجلسة المتزامنة لكل لاعب (20 افتراضيًا). امنح اللاعبين طريقة لإنهاء أو اترك عالما - ان "التخلي عن العالم" اطلب إجاباتك النصية باستخدام أ result، على سبيل المثال. وإلا فإن اللاعب الذي ملأ الحد الأقصى لا يمكنه أن يبدأ أي شيء جديد.

onPlayerMessage(ctx) {
  var msg = ctx.message.data;
  if (msg.type === "close-world" && ctx.message.from === ctx.sessionState.ownerId) {
    return { ok: true, sessionState: ctx.sessionState, result: { kind: "closed" } };
  }
  /* ... */
}

5. ألعاب الحاويات: مواقف السيارات

بالنسبة للعبة الحاوية، يكون التوقف مؤقتًا حديقة:

  1. تطلب المنصة الحصول على لقطة نهائية (GET /sessions/{id}/snapshot) ويخزنها بشكل دائم.
  2. يمزق الجلسة (DELETE /sessions/{id}). تتوقف الحاوية الخاصة بك عن محاكاتها، وإذا ليس لديه جلسات أخرى يمكن إيقاف النشر بعد فترة الخمول.
  3. في الانضمام التالي، يقوم بإعادة إنشاء الجلسة باستخدام POST /sessions، تحمل المخزنة snapshot والمحدثة pausedMs - نفس طلب استعادة الأعطال - تنبيه النشر المتوقف أولا إذا لزم الأمر.

لذا فإن اللقطة التي تعيدها يجب أن تكون كافية لإعادة بناء العالم بأكمله، وليس فقط لاستئناف البعض منه ثواني من اللعب. إذا فشلت تلك اللقطة النهائية، فسيتم إيقاف الجلسة من آخر دورية لها نقطة تفتيش. على عكس الأعطال، لا يتم احتساب عملية الإيقاف والاستعادة ضمن ميزانية إعادة التشغيل الخاصة بك، و يحصل اللاعبون على لا resumed الإطار: لم يكن هناك أحد لرؤية حالة الترجيع.

قائمة التحقق

  • [ ] persistent: true أعلن (السيناريو) أو عاد من /describe (حاوية)، وتم نشر تحديث.
  • [ ] استخدام توقيت اللعبة ctx.now - ctx.pausedMs، أو استخدامه عمدا ctx.now واللحاق.
  • [ ] قوائم العملاء sessions/mine، يظهر pausedAt، وينضم مجددًا ws/v1/games.
  • [ ] يقوم العميل بإعادة المحاولة مع التراجع بعد فترة error متبوعًا برمز الإغلاق 1001 على الاتصال.
  • [ ] لدى اللاعبين طريقة لإنهاء العالم، لذلك لن يعلقوا أبدًا عند الحد الأقصى للجلسة.
  • [ ] لقطات (الحاوية) تعيد بناء العالم بأكمله.
