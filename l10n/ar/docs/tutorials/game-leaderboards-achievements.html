البرنامج التعليمي: المتصدرين والإنجازات التي حققتها لعبتك

إذا كنت تمتلك لعبة على StarHermit، فأنت ناشرها. يمكنك إعطائها المتصدرين (درجة عالية، أسرع تشغيل، أطول خط) و الإنجازات بدون حساب ناشر أو أي خاص إذن. امتلاك اللعبة هو كل ما يتطلبه الأمر.

هناك قاعدة واحدة وراء كل شيء في هذه الصفحة: أنت تحددهم، يكتب خادم اللعبة الخاص بك لهم. لا يمكن لعميل اللاعب أبدًا نشر نتيجة أو المطالبة بإنجاز لها، ويجب على الخادم الخاص بك التحقق من صحة طريقة اللعب التي تكسبه. رفض عمليات إرسال واجهة برمجة التطبيقات المباشرة وحده لا يمنع العميل المعدل من اختراع أحداث اللعبة. ولهذا السبب تحتاج اللعبة إلى واجهة خلفية موثوقة: أ server= السيناريو أو أ container.image= في starhermit.txt.

يبني هذا البرنامج التعليمي كلا من لعبة أركيد صغيرة، جامع النجوم: ينتهي التشغيل عندما يكون اللاعب تعطل، ولها مجموع النقاط ووقت التشغيل.

قبل أن تبدأ

أنت بحاجة إلى:

  • لعبة ذات واجهة خلفية للخادم التي تمتلكها: التي أضفتها من مستودعك الخاص، وتم تحميلها كمجلد، أو ادعى. لعبة متصفح فقط تجيب 409 لكل مكالمة أدناه، مع رسالة توضح السبب.
  • رمز وصول المستخدم الكامل، وليس رمز إطلاق اللعبة. رموز الإطلاق محاطة بسياج حول اللعبة سطح اللاعب ولا يمكن الوصول إليه /me/....
  • معرف لعبتك (وهو كذلك <id>.starhermit.com عنوان):
ACCESS_TOKEN='your-full-user-access-token'
API=https://api.starhermit.com

curl -s "$API/api/v1/me/github-games" -H "Authorization: Bearer $ACCESS_TOKEN" |
  jq '.[] | {id, displayName, gameSlug}'

GAME_ID='the-id-from-above'

gameSlug هو ما يسميه عميلك اللعبة /api/v1/games/{slug}/.... كل لعبة قمت بإضافتها أو التي تم تحميلها تحتوي على لعبة واحدة مضمنة للمتصفح فقط، لذلك لا تخبرك ما إذا كان هناك خادم: GET /api/v1/games/{slug} يفعل - يجيب 404 حتى تحصل اللعبة على خلفية.

1. قم بإنشاء لوحات الصدارة

يحصل Star Collector على لوحتين: أكبر عدد من النقاط (الأعلى هو الأفضل) وأسرع تشغيل إلى 100 نقطة (أقل هو أفضل).

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/leaderboards" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "high-score", "name": "High score",
        "scoreType": "integer", "sortDirection": "desc",
        "minScore": 0, "maxScore": 1000000 }'

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/leaderboards" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "fastest-100", "name": "Fastest to 100",
        "scoreType": "time-ms", "sortDirection": "asc" }'

تعود كل مكالمة 201 والمجلس، بما في ذلك id و key. يستخدم الخادم الخاص بك مفتاح, لذا اختره بعناية. المفتاح، scoreType و sortDirection لا يمكن تغييرها لاحقا.

scoreType يقبل
integer أعداد كاملة
decimal أي رقم
time-ms ميلي ثانية كاملة وغير سلبية

تعيين minScore/maxScore إلى ما يمكن أن تنتجه لعبتك بالفعل. يتم إسقاط النتيجة خارجهم ، وهو حماية رخيصة ضد الأخطاء في منطق الخادم الخاص بك.

2. إنشاء الإنجازات

يمكنك إعطاء إنجازات اللعبة بطريقتين، ويمكنك استخدام كليهما في وقت واحد:

أعلن في التعليمات البرمجية تم إنشاؤها من خلال API
أين game.achievements في البرنامج النصي الخاص بك، أو /describe في الحاوية الخاصة بك POST /me/github-games/{id}/achievements
تم التغيير بواسطة نشر تحديث استدعاء API، ويصبح ساري المفعول على الفور
جيد ل الإنجازات التي تم بناء التعليمات البرمجية الخاصة بك حولها إضافة أو إعادة صياغة البعض دون إصدار

يتم فتح قفل كلا النوعين بنفس الطريقة، حيث يقوم الخادم الخاص بك بإرجاع المفتاح. هنا نقوم بإنشاء اثنين من خلال واجهة برمجة التطبيقات:

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "century", "name": "Century",
        "description": "Collect 100 stars in one run.", "points": 10 }'

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "untouchable", "name": "Untouchable",
        "description": "Reach 500 points without losing a shield.",
        "points": 50, "secret": true }'

A secret يظل الإنجاز مخفيًا عن اللاعبين حتى يفتحوه.

لرؤية كل ما تحتويه اللعبة، بما في ذلك الإنجازات التي يعلنها الكود الخاص بك، قم بإدراجها:

curl -s "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" | jq '.[] | {key, origin, unlocks}'

origin يكون declared للإنجازات من التعليمات البرمجية الخاصة بك و owner للإنجازات التي قمت بإنشائها هنا. يمكنك التعديل والحذف فقط owner تلك. أ declared سيتم إرجاع أحدهما إلى التالي التحديث، لذلك ترفض واجهة برمجة التطبيقات (409) وقمت بتغييره في الكود بدلاً من ذلك.

3. نشر النتائج وفتح الإنجازات من البرنامج النصي الخاص بك

يُبلغ البرنامج النصي الخاص بك عن كلا النوعين من النتائج في قيمة الإرجاع الخاصة به. يمكنه القيام بذلك من أي خطاف: createSession, onPlayerMessage أو onTick.

  • scores: مفتاح اللوحة → معرف اللاعب → الرقم.
  • achievements: معرف اللاعب → مفاتيح لفتح.
'use strict';

function endRun(ctx, s, playerId) {
  var run = s.runs[playerId];
  var scores = { "high-score": {} };
  scores["high-score"][playerId] = run.points;
  if (run.reached100At) {
    scores["fastest-100"] = {};
    scores["fastest-100"][playerId] = run.reached100At - run.startedAt;
  }

  var unlocked = [];
  if (run.stars >= 100) unlocked.push("century");
  if (run.points >= 500 && !run.lostShield) unlocked.push("untouchable");
  var achievements = {};
  achievements[playerId] = unlocked;

  run.over = true;
  return {
    ok: true,
    sessionState: s,
    scores: scores,
    achievements: achievements,
    broadcast: [{ to: [playerId], data: { type: "run-over", points: run.points } }]
  };
}

globalThis.game = {
  tickRateHz: 10,

  createSession(ctx) {
    var runs = {};
    ctx.players.forEach(function (p) {
      runs[p.id] = { points: 0, stars: 0, lostShield: false, startedAt: ctx.now,
                     reached100At: null, over: false };
    });
    return { ok: true, sessionState: { runs: runs } };
  },

  onPlayerMessage(ctx) {
    var s = ctx.sessionState;
    var from = ctx.message.from;
    var run = s.runs[from];
    var msg = ctx.message.data || {};
    if (!run || run.over) return { ok: false, error: "No run in progress" };

    // The client reports what happened; the script decides what it is worth.
    if (msg.type === "collect") {
      run.stars += 1;
      run.points += 5;
      if (run.points >= 100 && !run.reached100At) run.reached100At = ctx.now;
      return { ok: true, sessionState: s };
    }
    if (msg.type === "shield-lost") {
      run.lostShield = true;
      return { ok: true, sessionState: s };
    }
    if (msg.type === "crash") return endRun(ctx, s, from);
    return { ok: false, error: "Unknown command" };
  },

  onTick(ctx) { return { ok: true }; }
};

الأشياء التي تفعلها لا تحتاج إلى التعامل مع:

  • نتائج أسوأ. يحتفظ كل لاعب بأفضل درجاته على كل لوحة، والتي يتم الحكم عليها من خلال اللوحة sortDirection. قم بالإبلاغ عن كل عملية تشغيل والمنصة تحافظ على الأفضل.
  • كرر عمليات الفتح. إن فتح شيء يمتلكه اللاعب بالفعل لا يؤدي إلى أي شيء، لذا أعد المفتاح كلما استمرت الحالة.
  • معرف أي شخص آخر. يسجل الأهداف ويفتحها للأشخاص غير الموجودين في الجلسة، بما في ذلك الذكاء الاصطناعي مقعد، يتم تجاهلها.

يتم إسقاط المفاتيح غير المعروفة واللوحات غير النشطة والنتائج خارج النطاق بصمت. النص الخاص بك لا يحصل خطأ بالنسبة لهم، لذا تحقق من لوحاتك مرة واحدة، كما هو الحال في القسم 4.

يجب أن تجعل اللعبة الحقيقية الخادم يقوم بتحديد النقاط والأوقات من حالته الرسمية، وليس الثقة collect الرسائل كما هي. يتم الاحتفاظ بهذا المثال قصيرًا لإظهار التقارير. مخطوطات اللعبة لديه عقد كامل على شكل العودة.

3ب. نفس الشيء من الحاوية

ترسل لعبة الحاوية نفس الأمرين إلى WebSocket للتحكم الخاص بها:

{ "type": "scores", "sessionId": "…",
  "scores": { "high-score": { "<userId>": 740 }, "fastest-100": { "<userId>": 41250 } } }

{ "type": "achievements", "sessionId": "…",
  "unlocks": { "<userId>": ["century"] } }

scores يمكن أيضًا تضمينها في أي مظروف استجابة تعود منه الحاوية الخاصة بك /sessions. ال تنطبق نفس القواعد: المشاركون فقط، والحفاظ على أفضل النتائج، وتجاهل المفاتيح غير المعروفة. يرى خوادم ألعاب الحاويات.

4. أظهرهم في لعبتك

يقرأ عميلك كل شيء باستخدام رمز الإطلاق الذي يحمله بالفعل. لا شيء هنا يحتاج إلى رمز المالك.

العثور على المجالس.

const boards = await api(`/api/v1/games/${slug}/leaderboards`);
// [{ id, key: "high-score", name: "High score", sortDirection: "desc", ... }, ...]
const high = boards.find(b => b.key === "high-score");

يتم سرد المجالس النشطة فقط.

قراءة لوحة.

const page = await api(`/api/v1/leaderboards/${high.id}/entries?page=1&pageSize=10`);
// { items: [{ rank, username, score, ... }], total, page, pageSize }
const friends = await api(`/api/v1/leaderboards/${high.id}/entries?friendsOnly=true&pageSize=10`);

ل time-ms اللوحة، قم بتنسيق النتيجة كوقت: 41250 → 0:41.25.

الإنجازات.

  • GET /api/v1/games/{slug}/achievements يسرد كل إنجاز مع اللاعب unlocked ولاية. تبقى الأسرار مخفية حتى يتم اكتسابها.
  • يصل إلغاء القفل نفسه مباشرةً ws/v1/games مثل {"type":"achievement","data":{key,name,description,points,...}}. أظهر نخبًا عندما يحدث ذلك. يقوم استدعاء القائمة عند التحميل بالتقاط أي شيء مفتوح أثناء إغلاق المقبس.

يرى الإنجازات ل الإطار.

5. اعتني بهم

إعادة تسمية لوحة أو تغيير حدودها.

curl -s -X PUT "$API/api/v1/me/github-games/$GAME_ID/leaderboards/$BOARD_ID" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "name": "All-time high score", "maxScore": 2000000 }'

تنطبق الحدود الجديدة على النتائج الجديدة فقط.

تقاعد مجلس الإدارة ولكن احتفظ بنتائجه. يرسل { "isActive": false }. يتوقف المجلس عن القبول يسجل ويختفي من قائمة اللعبة. لا يزال من الممكن قراءة إدخالاته بواسطة المعرف.

إعادة تعيين على جدول زمني. إعطاء لوحة "resetSchedule": "daily", "weekly" أو "monthly" (على إنشاء، أو في وقت لاحق مع PUT) ويبدأ من جديد في تمام الساعة 00:00 بالتوقيت العالمي المنسق لكل فترة — وهو مثالي لـ "هذا أفضل الأسبوع" لوحة بجانب واحدة في كل الأوقات. لا يوجد شيء يجب القيام به في البرنامج النصي الخاص بك: قم بإبلاغ النتائج كالمعتاد، و يتم احتساب النتيجة الأولى لكل لاعب في الفترة الجديدة. يرى إعادة تعيين الجداول الزمنية.

ابدأ موسمًا جديدًا يدويًا. بالنسبة لموسم واحد بدلاً من الجدول الزمني، قم بإنشاء لوحة جديدة (high-score-s2)، وجه البرنامج النصي إليه، وقم بسحب النص القديم.

حذف لوحة. DELETE .../leaderboards/{id} يزيل اللوحة وجميع مداخلها، و لا يمكن التراجع عنه.

تحرير الإنجاز. PUT .../achievements/{achievementId} مع أي من name, description, icon, secret و points. المفتاح لا يتغير أبدا.

حذف إنجاز. يعمل هذا فقط مع الجهاز الذي قمت بإنشائه ولم يفتحه أحد بعد. الإنجازات المكتسبة دائمة.

نقل الإنجاز إلى التعليمات البرمجية. أعلن نفس المفتاح في game.achievements ونشر. ال يتولى الإعلان الإنجاز الحالي، ويحتفظ به اللاعبون الذين يمتلكونه.

إجابة معنى
404 اللعبة ليست ملكك، أو اللوحة أو الإنجاز لا ينتمي إليها
409 "…الخادم الخلفي…" اللعبة لا يوجد بها server= أو container.image=
409 "بالفعل…" يتم أخذ المفتاح بلوحة أو بإنجاز معلن أو مبتكر
409 "المعلنة من قبل خادم اللعبة" قم بتغيير هذا الإنجاز في التعليمات البرمجية الخاصة بك
409 "مقفلة بالفعل" يحتفظ به اللاعبون، لذلك لا يمكن حذفه
400 مفتاح به أحرف أخرى، أو اسم مفقود، أو minScore > maxScore

الحدود: 2048 لوحة صدارة و200 إنجاز تم إنشاؤه لكل لعبة، بالإضافة إلى ما يصل إلى 100 إنجاز معلن.

قائمة التحقق

  • [ ] اللعبة لديها server= البرنامج النصي أو container.image=، و gameSlug تم تعيينه في GET /me/github-games.
  • [ ] كل لوحة لها مفتاح ثابت واليمين scoreType و sortDirection (لا يمكنهم التغيير لاحقًا).
  • [ ] يعود الخادم scores و achievements (البرنامج النصي) أو يرسل رسائل التحكم (الحاوية) الصادرة من الدولة الموثوقة.
  • [ ] يجد العميل لوحات بها GET /games/{slug}/leaderboards، لا تقم مطلقًا بترميز هوياتهم، وتقرأ الإدخالات حسب المعرف.
  • [ ] يتم تحميل العميل GET /games/{slug}/achievements ويظهر نخبًا على achievement إطار.
  • [ ] اللوحات القديمة متقاعدة isActive: false بدلاً من حذفها، إلا إذا كنت تريد حقًا اختفاء النتائج.
