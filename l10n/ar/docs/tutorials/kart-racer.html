البرنامج التعليمي: إنشاء متسابق كارت متعدد اللاعبين

يبني هذا البرنامج التعليمي طبقة متعددة اللاعبين لمتسابق الكارت آركيد - ما يصل إلى ثماني عربات خاصة جماعات الضغط مع الأصدقاء، والانضمام السريع مع الغرباء، وبرامج تشغيل وحدة المعالجة المركزية التي تملأ فتحات الشبكة الفارغة، والعد التنازلي، اللفات والترتيب النهائي والإنجازات - على StarHermit API. ويغطي عقد netcode وتنادي المنصة؛ المحرك الخاص بك وفن المسار ونموذج المناولة هو ملكك.

كل شيء خاص باللعبة هنا - grand-prix قائمة الانتظار، تخطيط الإطار الثنائي، زر العنصر، ثوابت الفيزياء - هي قيمة المثال. فقط نقاط النهاية، ومظاريف الإطار والحدود هي سلوك النظام الأساسي، وكل منها يرتبط بالصفحة المرجعية الخاصة به.

1. اختر الهندسة المعمارية

المتسابق هو أصعب شكل من أشكال اللعبة بالنسبة لميزانية علامة الخادم: تتحرك العربات بسرعة، وتتصادم، و يشعر اللاعبون بـ 50 مللي ثانية من تأخر التوجيه. يمنحك StarHermit طريقتين لتشغيله، كلاهما يبدأ من ملف غرفة الوقت الحقيقي:

أ. توجيه المضيف ب. البرنامج النصي المعتمد للخادم
من يحاكي عميل مضيف الغرفة بأي حال يريده (60 هرتز+) لك server= السيناريو على الأكثر 30 هرتز
ينقل الإطارات الثنائية قيد التشغيل ws/v1/realtime JSON cmd/game إطارات على ws/v1/games
الغش المضيف موثوق به العملاء ليس لديهم أي سلطة
إيلو، إنجازات السيناريو لا (ينشر المضيف نتيجة مثبتة) نعم - eloUpdates, achievements، الإعادة
الأفضل ل سباقات غير رسمية مع الأصدقاء، وفيزياء كاملة الإخلاص سباق مُصنف باستخدام فيزياء الممرات البسيطة

ابدأ بـ A إلا إذا كنت بحاجة إلى اللعب المصنف؛ ويبين القسم 7 ما هي التغييرات ل B. A خادم الحاويات يمكنه أيضًا تشغيل عربة ذات ثمانية عربات مقيدة بالغرفة العرق و محاكاة عند 60 هرتز بشكل رسمي. تستخدم واجهة برمجة تطبيقات الألعاب المباشرة الخاصة بها حاليًا صيغة 1v1 ضمنية قائمة الانتظار، لذا استخدم غرفة حقيقية للشبكة الأكبر. المنصة لا تخطو حلقة الحاوية.

2. البيان

انشر مجلد البناء القابل للتوزيع باستخدام هذا starhermit.txt في جذره (انظر البيان). ال control.* تمنح الخطوط اللاعبين واجهة مستخدم قابلة لإعادة الربط و العميل أ الضوابط API لقراءة الارتباطات من:

name=Turbo Hermits
launch=index.html
cover=art/cover.png
control.accelerate=KeyW+ArrowUp | Accelerate
control.brake=KeyS+ArrowDown | Brake / reverse
control.left=KeyA+ArrowLeft | Steer left
control.right=KeyD+ArrowRight | Steer right
control.drift=ShiftLeft+ShiftRight | Drift
control.item=Space | Use item

المسار أ لديه لا server= خط. إذا كانت اللعبة تشحن برنامجًا نصيًا، فإن بدء الغرفة يؤدي إلى إنشاء جلسة مقيدة والنص فقط هو الذي يمكنه إنهاء المباراة - المضيف POST .../result توقف عن كونه الطريقة التي تنتهي بها السباقات (القسم 7).

3. قم بتسجيل الدخول وقراءة الأساسيات

يتم فتح لعبة مستضافة على النظام الأساسي باستخدام #game_token=<jwt> في عنوان URL - اقرأه مرة واحدة، ثم قم بإزالته history.replaceState، وقم بتحديثه قبل انتهاء صلاحيته لمدة 60 دقيقة (التفاصيل في تجول الشطرنج و مصادقة). سبيكة الخاص بك هو الرمز المميز game_scope المطالبة (أو location.hostname's التسمية الأولى)؛ لا تقم أبدًا بتشفيرها.

عند التحميل، قم بإحضار ما تحتاجه القائمة:

GET /api/v1/games/{slug}/controls     # effective key bindings (manifest defaults + overrides)
GET /api/v1/games/{slug}/settings     # camera, volume, last chosen kart — your own keys
GET /api/v1/realtime/rooms/mine       # 200 → the player is still in a race; rejoin it

حفظ اختيارات القائمة باستخدام PATCH /api/v1/games/{slug}/settings ({"settings":{"kart":"hermit-crab"}}). تتبع الإعدادات اللاعب عبر الأجهزة ولا تحتاج إلى إعلان.

4. اللوبي

سباق الجائزة الكبرى مجاني للجميع، وبالتالي فإن الغرفة بها فريق واحد من ثمانية مقاعد. المسار وعدد اللفات والمحرك الطبقة تذهب في مبهمة metadata:

POST /api/v1/realtime/rooms
Authorization: Bearer <launch token>

{ "teamCount": 1, "seatsPerTeam": 8, "backfillAfterSeconds": 45,
  "aiPlayers": 0, "name": "Friday cup", "isVisible": true,
  "metadata": { "track": "coral-loop", "laps": 3, "cc": 150 } }

مع رمز الإطلاق، تأتي لعبة الغرفة من الرمز المميز، لذا gameSlug يمكن حذفها. الخالق هو المضيف في المقعد (0, 0). من هنا يكون اللوبي تدفقًا عاديًا للغرفة:

  • أصدقاء — POST /rooms/{id}/invites مع {"toUserId": ...}. تقوم المنصة بإخطارهم؛ قبول مقاعد لهم. إظهار الشخصية الستة joinCode حتى يتمكن الأصدقاء أيضًا من كتابتها POST /rooms/join-by-code.
  • الغرباء — المضيف يدعو POST /rooms/{id}/open. اللاعبون الذين ليس لديهم مكالمة للغرفة POST /rooms/quick-join مع {"seats": 1} وعلى 404وإنشاء وفتح خاصة بهم.
  • تتبع التصويت / تغيير رأي المضيف — PATCH /rooms/{id} مع الجديد metadata والغرفة revision مثل expectedRevision.
  • منفردا ضد وحدات المعالجة المركزية - إنشاء مع "aiPlayers": 7، ثم POST /rooms/{id}/start.

تبدأ الغرفة المفتوحة من تلقاء نفسها عندما تمتلئ جميع المقاعد الثمانية أو backfillAfterSeconds يمر؛ المضيف يمكن أيضا POST /rooms/{id}/start. كل مقعد لا يزال فارغًا يصبح مشاركًا في الذكاء الاصطناعي - هذا هو مقعدك برامج تشغيل وحدة المعالجة المركزية.

5. مقبس السباق (توجيه المضيف)

يتصل

يفتح كل مشارك مأخذ التوصيل الفعلي بتذكرة تستخدم لمرة واحدة:

const { ticket } = await api.post("/api/v1/realtime/connection-tickets"); // { ticket, expiresIn }
const ws = new WebSocket(
  `wss://api.starhermit.com/ws/v1/realtime?roomId=${roomId}&ticket=${encodeURIComponent(ticket)}`);
ws.binaryType = "arraybuffer";

إطارات النص هي دفعات JSON وإطارات التحكم؛ الإطارات الثنائية هي طريقة اللعب. ال roster الدفع هو شبكتك: بعد البدء يتم تجميدها، بما في ذلك مقاعد الذكاء الاصطناعي. مع فريق واحد، تكون فتحة شبكة الكارت هي المكان المناسب له المشارك slot.

ws.onmessage = (e) => {
  if (typeof e.data === "string") return onControl(JSON.parse(e.data)); // roster, presence, event, ready, chat, result
  const bytes = new Uint8Array(e.data);
  const sender = guidFromDotNet(bytes.subarray(0, 16)); // server-stamped, trustworthy
  onGameplay(sender, new DataView(e.data, 16));          // your payload starts at byte 16
};

// The server prefixes the sender's participant id in .NET GUID byte order:
// the first three groups are little-endian.
function guidFromDotNet(b) {
  const h = (i) => b[i].toString(16).padStart(2, "0");
  return `${h(3)}${h(2)}${h(1)}${h(0)}-${h(5)}${h(4)}-${h(7)}${h(6)}-` +
         `${h(8)}${h(9)}-${h(10)}${h(11)}${h(12)}${h(13)}${h(14)}${h(15)}`;
}

لا تضع أبدًا معرف اللاعب في حمولتك الخاصة وتثق به، فالبادئة ذات 16 بايت هي الهوية الوحيدة أن يضمن الخادم.

التوجيه والميزانية

تفرض المنصة شكل اللعب الذي يوجهه المضيف:

  • A الضيف تصل الإطارات الثنائية المضيف فقط - هذه هي قناة الإدخال.
  • ال المضيف تصل الإطارات الثنائية كل ضيف - هذه هي قناة اللقطة.
  • كل إطار على الأكثر 8 كيلو بايت; قد يرسل كل اتصال 30 رسالة/ثانية (2 × انفجار لواحد الثانية). تجاوز يغلق المقبس مع PolicyViolation.

لذا فإن المضيف يحاكي بأي معدل يبدو صحيحًا (60 هرتز هو النموذجي) ولكن يرسل لقطات في 20 هرتز، ويرسل الضيوف المدخلات عند 20 هرتز. وهذا يترك مساحة للرأس لإطار التحكم العرضي.

تخطيطات الإطار (مثال)

المدخلات، الضيف → المضيف، 7 بايت:

إزاحة يكتب مجال
0 u8 1 = الإدخال
1 u16 seq - يزيد كل إرسال
3 i8 توجيه، −127…127
4 u8 دواسة الوقود، 0...255
5 u8 القطع: 0 فرامل، 1 انجراف
6 u8 itemPresses - عداد وليس علم

itemPresses هو عدد مستمر من الضغطات على زر العنصر. عند 20 هرتز، سيتم الضغط لمدة أقصر من 50 مللي ثانية وإلا فإنها تقع بين العينات؛ باستخدام العداد، يقوم المضيف بإطلاق عنصر واحد لكل زيادة، ولكن هبطت المطابع.

لقطات، المضيف → الضيوف، 4 + 22 بايت لكل كارت (176 بايت لشبكة كاملة):

إزاحة يكتب مجال
0 u8 2 = لقطة
1 u16 علامة المضيف
3 u8 عدد الكارت
لكل كارت u8, f32 ×4, u8, u16, u8, u8 الفتحة، x، z، العنوان، السرعة، اللفة، نقطة التفتيش، العنصر، الأعلام

يقدم الضيوف عربات أخرى ~100 مللي ثانية في الماضي، الاستيفاء بين اللقطتين ذلك حددوا ذلك الوقت، وتوقعوا الكارت الخاص بهم محليًا من مدخلاتهم، متوجهين نحو المضيف الموقف عندما يختلفون. قم بتضمين الإدخال الأخير seq تقدم المضيف لكل كارت في flags أو حقل إضافي إذا كنت تريد المصالحة الدقيقة.

العد التنازلي، أحداث السباق، النهاية

إطارات التحكم هي JSON، بحد أقصى 4 كيلوبايت، وطوابع الخادم from مع معرف المشارك للمرسل:

  • يرسل الضيوف {"type":"ready"} بمجرد تحميل المسار.
  • ينتظر المضيف أن يكون كل إنسان متصل جاهزًا (أو مهلة)، ثم يرسل {"type":"event","kind":"countdown","goInMs":3000}. يبدأ الضيوف العد التنازلي المحلي الاستلام - لا حاجة لمزامنة الساعة بهذه الدقة.
  • إيقاعات السباق الأخرى موجودة أيضًا event إطارات: {"kind":"lap","slot":3,"lap":2}, {"kind":"finished","slot":3,"place":1,"timeMs":94210}.
  • chat متاح للجميع، ولكن يقتصر عدد الضيوف على 10 إطارات تحكم في الدقيقة - وهو عدد كافٍ ready وعدد قليل "زز"ق، وليس للعب.

عندما يتجاوز آخر إنسان الخط (أو مؤقتًا بعد نفاد الفائز)، يرسل المضيف الرسالة النتيجة التي تغلق الغرفة وتدفع {"type":"result"} للجميع:

POST /api/v1/realtime/rooms/{id}/result

{ "teamScores": [0],
  "metadata": { "track": "coral-loop",
                "order": [ { "slot": 3, "timeMs": 94210 }, { "slot": 0, "timeMs": 95002 } ],
                "bestLapMs": 30112 } }

teamScores يحتاج بالضبط إلى إدخال واحد لكل فريق (مثبت 0-50)، والذي لا يحمل أي شيء مفيد في مجاني للجميع؛ ترتيب التشطيب موجود metadata. سباق الفريق هو نفس الغرفة مع teamCount: 2 ونقاط كل فريق teamScores.

برامج تشغيل وحدة المعالجة المركزية والمغادرين وتغييرات المضيف

  • مقاعد الذكاء الاصطناعي متاحة لك للقيادة. تقوم المنصة بحجز المقعد وتسمية السائق؛ المضيف تقوم المحاكاة بتوجيهها (خط سباق عبر نقاط التفتيش، مع بعض الأربطة المطاطية).
  • الضيف الذي يغادر منتصف السباق (POST /rooms/{id}/leave) يحتفظون بعربتهم على الشبكة: القائمة يظهر الدفع نفس المشارك id الآن isAi: true، وتتولى وحدة المعالجة المركزية الخاصة بالمضيف مسؤولية تلك الكارت.
  • الضيف الذي يسقط لا يزال في الغرفة. احتفظ بسباق الكارت الخاص بهم واسمح لهم بإعادة الاتصال - أحدث المقبس يحل محل القديم.
  • إذا غادر المضيف، ينتقل دور المضيف إلى الإنسان المتبقي الأطول انضمامًا و يُظهر دفع القائمة الجديد isHost. كل ضيف يحمل بالفعل أحدث لقطة كاملة، وبالتالي فإن الجديد يستأنف المضيف المحاكاة منه ويبدأ في إرسال اللقطات؛ يتم الآن توجيه مدخلات الضيف إليهم. ترحيل المضيف هو مهمة الكود الخاص بك - النظام الأساسي ينقل الدور فقط.
  • إذا قام المضيف بقطع الاتصال فقطتغلق الغرفة بعد 60 ثانية بدون مقبس مضيف.

6. حول السباق

  • الصوت والدردشة. يمكن لكل ضيف بالفعل chat على المقبس الحقيقي. للصوت، انظر صوت.
  • مباراة العودة. يتم إغلاق الغرفة بعد النتيجة. اطلب من المضيف إنشاء غرفة جديدة ودعوة بشر القائمة السابقة، أو أرسل الجميع مرة أخرى للانضمام السريع.
  • المتصدرين في وقت اللفة. لوحة المتصدرين الخاصة بالمنصة الخاصة باللعبة هي لوحة elo الخاصة بها، والتي يتم كتابتها بواسطة الخادم فقط وقت التشغيل. يتم قبول لوحة المتصدرين التي يحددها الناشر POST /api/v1/leaderboards/{id}/submitولكن هذا يتم المطالبة بالنتيجة من قبل العميل - وهو أمر جيد بالنسبة للتجربة الودية، وليس لأي شيء به جوائز.

7. البديل ب: السباق الرسمي للخادم

بالنسبة إلى اللعب المصنف، انقل المحاكاة إلى برنامج نصي. اللوبي لم يتغير. إضافة البرنامج النصي و إعدادات التوفيق للبيان:

server=server.js
matchmaking.max_wait_seconds=20
matchmaking.ai_players=7

الآن شيئان يخلقان السباقات: بدء غرفة ينشئ جلسة مقيدة بالغرفة لبشره، و التوفيق (POST /api/v1/games/{slug}/matchmaking?queue=grand-prix) يخلق واحد عندما ثمانية تم العثور على اللاعبين - أو، باستخدام الإعدادات المذكورة أعلاه، بعد 20 ثانية مع وجود وحدات المعالجة المركزية في ما يصل إلى سبعة فارغة مقاعد. يمكن لردهة من الأصدقاء الوقوف في طابور معًا POST /realtime/rooms/{id}/matchmake.

وفي كلتا الحالتين، يأخذ العملاء sessionId (الغرفة gameSessionId، أو التذكرة المطابقة) و انتهى اللعب ws/v1/games?sessionId=…. يتم الاحتفاظ بمقبس الوقت الفعلي، إن وجد، للقائمة فقط.

البرنامج النصي

المحاكاة بأكملها تعمل onTick عند السقف 30 هرتز. كل استدعاء هو بمثابة رمل جديد يحصل sessionState in وإعادتها للخارج، لذا أبقِ تلك الحالة صغيرة - حيث يتم إجراء تسلسل لها في كل علامة.

const TRACK = { laps: 3, radius: 14,
  checkpoints: [[0, 0], [120, 0], [160, 60], [120, 120], [0, 120], [-40, 60]] };

globalThis.game = {
  tickRateHz: 30,
  replays: true,
  queues: [{ key: "grand-prix", teams: 8, teamSize: 1 }],
  achievements: [
    { key: "chequered-flag", name: "Chequered Flag", description: "Win a race.", points: 10 }
  ],

  createSession(ctx) {
    const karts = racers(ctx).map((r, i) => ({
      id: r.id, name: r.name, ai: r.ai, x: -8 * (i % 2), z: -6 * i, heading: 0, speed: 0,
      cp: 1, lap: 0, boost: 0, boosts: 1, input: {}, ack: 0, finishedAt: null
    }));
    return { ok: true, sessionState: { t: ctx.now, goAt: ctx.now + 4000, karts, order: [] } };
  },

  onPlayerMessage(ctx) {                       // durable commands: discrete actions
    const s = copy(ctx.sessionState);
    const k = s.karts.find((k) => k.id === ctx.message.from);
    if (ctx.message.data?.type === "use-item" && k && k.boosts > 0 && ctx.now >= s.goAt) {
      k.boosts--; k.boost = 1.2;
    }
    return { ok: true, sessionState: s };
  },

  onTick(ctx) {
    const s = copy(ctx.sessionState);
    const dt = Math.min(Math.max((ctx.now - s.t) / 1000, 0), 0.1);
    s.t = ctx.now;
    for (const i of ctx.inputs || []) {        // latest realtime input per player since last tick
      const k = s.karts.find((k) => k.id === i.from);
      if (k) { k.input = i.data; k.ack = Math.max(k.ack, Math.floor(+i.data.seq) || 0); }
    }
    if (ctx.now >= s.goAt) {
      for (const k of s.karts) {
        if (k.finishedAt) continue;
        move(k, k.ai ? aiInput(k) : k.input, dt);   // pure motion — shared with the client
        progress(k, s, ctx);                        // checkpoints, laps, finish — server only
      }
    }
    const snap = s.karts.map((k) =>
      [k.id, r2(k.x), r2(k.z), r3(k.heading), r2(k.speed), r2(k.boost), k.lap, k.cp, k.ack]);
    const out = { ok: true, sessionState: s,
      broadcast: [{ to: "all", data: { type: "snap", t: s.t, goAt: s.goAt, karts: snap } }] };
    if (raceOver(s, ctx)) Object.assign(out, finish(s, ctx));
    return out;
  }
};

المساعدون هم رمز اللعبة العادي. الأجزاء التي تهتم بها المنصة:

  • racers(ctx) يقرأ الشبكة من أي بداية كانت للجلسة: ctx.room.roster ل الغرفة (مقاعد الذكاء الاصطناعي بها userId: null، لذا أعطهم معرفات مثل ai-0-5), ctx.matchmaking.seats ل سباق متطابق (تخطي المقاعد مع id: null)، آخر ctx.players.
  • move(k, input, dt) يجب المشبك كل قيمة الإدخال — steer إلى -1…1، throttle إلى 0…1 — لان ctx.inputs[].data هو كل ما أرسله العميل. فقط from موثوق به. اجعلها نقية - لا ctx، لا توجد حالة جلسة - حتى يتمكن العميل من تشغيلها أيضًا (انظر التنبؤ من جانب العميل).
  • العشوائية والوقت تأتي من ctx.random و ctx.now; لا يوجد Date أو Math.random.
  • finish(s, ctx) يعود result (الذي ينهي الجلسة، ويغلقها بالنسبة للغرفة)، achievements للفائز إذا كان الإنسان، و eloUpdates للمتسابقين من البشر - على سبيل المثال الزوجي elo عبر أمر التشطيب، اقرأ منه وأعد كتابته إليه ctx.playerStates. مقاعد الذكاء الاصطناعي لا تستطيع ذلك الحصول على حالة اللاعب أو التقييمات أو الإنجازات.
  • raceOver يجب أيضًا إنهاء السباقات التي لا يمكن لأحد أن ينهيها - كل إنسان ذهب وفقًا لذلك ctx.presence (غرف)، أو حد زمني صعب.
  • الاعادة احتفظ فقط ب أخير sessionState. احتفظ بجدول مدمج لوقت الدورة والتشطيب النظام فيه، وليس سجل موقف لكل علامة.

العميل

أرسل التوجيه كمدخل في الوقت الفعلي لكل علامة وإجراءات منفصلة كأوامر دائمة:

// ~30 Hz: latest-wins, batched into the next onTick
send({ type: "cmd", data: { type: "input", realtime: true, seq: ++seq,
                            steer, throttle, brake, drift } });

// on key press: a durable command, runs onPlayerMessage immediately
send({ type: "cmd", data: { type: "use-item" } });

أغراض يجب تمر بأمر دائم. المدخلات في الوقت الفعلي هي أحدث المكاسب بين القراد، و تحافظ المنصة على الحقول ذات اللقطة الواحدة فقط pass, tackle و shoot عندما عينة أحدث يستبدل زرًا قديمًا - يمكن الكتابة فوق أي زر آخر في الإدخال الفعلي قبل وضع العلامة يرى ذلك.

achievement تصل الإطارات على نفس المقبس؛ يقرأ GET /api/v1/games/{slug}/achievements على تحميل لأي شيء ممنوح قبل فتحه.

التنبؤ من جانب العميل

إن عرض ما يرسله الخادم فقط يجعل الكارت يبدو وكأنه يتم توجيهه عبر الوحل. توجيه يجب أن يصل التغيير إلى الخادم، وينتظر العلامة التالية (حتى 33 مللي ثانية عند 30 هرتز)، ثم يعود بعد ذلك snap — عند 80 مللي ثانية من اختبار الاتصال (ping) أي ما يزيد عن 100 مللي ثانية قبل دوران الكارت. التنبؤ يخفي ذلك: العميل التحركات الكارت الخاص بها على الفور ويعامل كل منهما snap كتصحيح وليس كما في الصورة.

شارك كود الحركة

قم بتقسيم المحاكاة بالطريقة التي يعمل بها البرنامج النصي أعلاه: نقي move(k, input, dt) للتعامل، و الخادم فقط progress لنقاط التفتيش واللفات والتشطيب. فضح رمز الحركة من server.js باعتباره عالميًا ثانيًا - وهو النمط الذي يستخدمه الشطرنج globalThis.chessRules - وقم بتحميل نفس الملف فيه المتصفح:

// server.js — shared by the platform's sandbox and the browser
function move(k, input, dt) { /* clamp input, integrate speed, heading, x, z, boost */ }
globalThis.kartPhysics = { move, TRACK };
globalThis.game = { /* ... as above ... */ };

<script src="server.js"></script>  <!-- defines kartPhysics; the client never calls game.* -->

يتنبأ العميل الحركة فقط. اللفات والمواضع والعناصر وترتيب النهاية تظل ملكًا للخادم اتصل. لا تتوقع نتائج متطابقة بعض الشيء: قد يختلف وضع الحماية والمتصفح في الأجزاء الأخيرة من Math.sin/Math.cos، والمناصب في snap يتم تقريبها. وتمتص المصالحة هذا الانجراف.

خطوة على إيقاع الخادم

لا يقوم الخادم بتشغيل خطوة واحدة لكل إدخال. كل علامة ينطبق عليها أحدث المدخلات التي يحملها ل يستمر هذا الكارت في استخدامه حتى وصول أحدث، ويتكامل في الوقت الفعلي منذ ذلك الحين القراد السابق. لذا قم بعكس هذا الشكل بدلاً من الانتقال إلى معدل إطارات العرض:

const pending = [];                              // inputs the server hasn't acknowledged yet
let seq = 0, predicted, previous;               // { x, z, heading, speed, boost }, seeded from the first snap
let error = { x: 0, z: 0, heading: 0 };          // visual offset, decays in render()

setInterval(() => {                              // 30 Hz, the script's tickRateHz
  if (!predicted || serverNow() < goAt) return;  // the server ignores movement before goAt
  const input = { steer: readSteer(), throttle: readThrottle(), brake: held("brake"), drift: held("drift") };
  const entry = { seq: ++seq, input, dt: 1 / 30 };
  send({ type: "cmd", data: { type: "input", realtime: true, seq: entry.seq, ...input } });
  pending.push(entry);
  previous = { ...predicted };
  kartPhysics.move(predicted, input, entry.dt);  // the kart responds now, not a round trip later
}, 1000 / 30);

يتم إهدار الإرسال بشكل أسرع من معدل التجزئة — يتم استخدام أحدث إدخال فقط لكل علامة — ويتم هدر يسقط النظام الأساسي مدخلات الوقت الفعلي أعلى من الحد الأقصى لكل اتصال.

التوفيق على كل snap

أصداء السيناريو ack، الأعلى seq لقد تم تطبيقه على كل كارت. على كل snap، الترجيع الخاص بك kart إلى حالة الخادم وإعادة تشغيل ما لم يشاهده الخادم بعد:

function onSnap(snap) {
  const [, x, z, heading, speed, boost, lap, cp, ack] = snap.karts.find((k) => k[0] === myId);
  while (pending.length && pending[0].seq <= ack) pending.shift();   // applied or superseded

  const corrected = { x, z, heading, speed, boost };
  for (const p of pending) kartPhysics.move(corrected, p.input, p.dt);

  if (!predicted) { predicted = corrected; previous = { ...corrected }; return; } // first snap
  error.x += predicted.x - corrected.x;          // what the player would see jump
  error.z += predicted.z - corrected.z;
  error.heading += predicted.heading - corrected.heading;
  if (Math.hypot(error.x, error.z) > 3) error = { x: 0, z: 0, heading: 0 }; // wall hit, bump: snap
  predicted = corrected;
  hud.lap = lap; hud.checkpoint = cp;            // progress is never predicted
}

نبذ كل ما يصل إلى ack صحيح على الرغم من أن أحدث المكاسب تتخطى بعض المدخلات: تم تخطيها تم استبدال الإدخال قبل تحديد الخادم، لذلك لم يؤثر أبدًا على بطاقة الخادم أيضًا.

تصحيحات سلسة، يتم عرضها بمعدل الإطارات

يجب أن تكون التصحيحات الصغيرة غير مرئية. ارسم الكارت في الموضع المتوقع بالإضافة إلى الاضمحلال إزاحة الخطأ، والاستيفاء بين آخر خطوتين للتنبؤ بتردد 30 هرتز، بحيث يتم عرض 60 أو 144 هرتز يتحرك بسلاسة:

function render(frameDt) {
  const decay = Math.exp(-frameDt / 0.1);        // ~100 ms to absorb a correction
  error.x *= decay; error.z *= decay; error.heading *= decay;
  const a = sinceLastStep() * 30;                // 0…1 between prediction steps
  drawKart(lerp(previous.x, predicted.x, a) + error.x,
           lerp(previous.z, predicted.z, a) + error.z,
           lerpAngle(previous.heading, predicted.heading, a) + error.heading);
}

قم بضبط عتبة المفاجئة بدلاً من الاضمحلال: التصحيح الأكبر من طول الكارت هو تصحيح حقيقي حدث (صدمة لم تتوقعها) ويُقرأ بشكل أفضل كلقطة سريعة بدلاً من شريحة بطيئة.

تعرف على ما لا يجب التنبؤ به

  • عربات أخرى. تم رسمها ~ 100 مللي ثانية في الماضي (buffer snapالصورة والاستيفاء بين اثنان تلك القوس serverNow() - 100)، فالاصطدام المتوقع ضدهم هو الاصطدام بـ حيث هم كان. توقع الجدران والمسار - فهي لا تتحرك - ودع الخادم يحل المشكلة مطبات الكارت إلى الكارت. يصل التصحيح خلال رحلة ذهابًا وإيابًا. إذا تم تشغيل المخزن المؤقت الجاف، استقراء من السرعة والتوجه لمدة تصل إلى 100 مللي ثانية تقريبًا، ثم استمر في الضغط.
  • أغراض. use-item هو أمر دائم، لذلك يعمل onPlayerMessage بمجرد وصوله - لا علامة الانتظار. قم بتشغيل اللهب والصوت عند الضغط على المفتاح؛ دع السرعة تصل من خلال المصالحة منذ ذلك الحين boost هو في snap. إذا رفض الخادم (لم يتبق أي رسوم)، فإن الخطوة التالية snap يعيدها.
  • حالة السباق. عدد اللفات والموقع والنهاية يأتي من snap وعمليات بث البرنامج النصي الخاص بك فقط.

تقدير ساعة الخادم

snap.t و goAt هي وقت الخادم (ctx.now). احتفظ بإزاحة من أصغر فجوة ملحوظة، والتي تصفية عمليات التسليم البطيئة:

let offset = Infinity;
function noteSnap(snap) { offset = Math.min(offset, performance.now() - snap.t); }
const serverNow = () => performance.now() - offset;

بدء العد التنازلي من goAt، والتنبؤ بالبوابة عليه كما تفعل الحلقة أعلاه. الكارت الذي يتحرك من قبل goAt يتم إعادة ربط النطاقات المطاطية محليًا إلى الشبكة بحلول الأول snap بعد البداية.

لضبط كل هذا، أضف الكمون الاصطناعي في التطوير (تأخير send و onSnap بمقدار 100-200 مللي ثانية) وقم بتسجيل حجم كل تصحيح - تعني التصحيحات الكبيرة الثابتة move وقد انجرفت من نسخة الخادم، أو يتم تثبيت حقل الإدخال بشكل مختلف على كل جانب.
