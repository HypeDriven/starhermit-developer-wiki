انشر خادم ألعاب مخصصًا ولاعبين مدمجين داخل اللعبة

يوضح هذا البرنامج التعليمي كيفية:

  1. انشر أو قم بتحديث حاوية خادم الألعاب المخصصة باستخدام واجهة برمجة تطبيقات تحميل الحزمة الخاصة بـ StarHermit.
  2. احتفظ برمز خادم StarHermit الخاص بالحاوية طويلة الأمد متجددًا.
  3. لاعبين مدمجين من Steam أو Epic أو GOG أو إصدار مستقل دون إرسالهم عبر مزود OAuth أو يطلب منهم زيارة لوحة معلومات StarHermit.
  4. امنح هؤلاء اللاعبين إمكانية الوصول إلى جلسات StarHermit والتوفيق بين اللاعبين ولوحات المتصدرين والإنجازات، دردشة الجلسة والصوت والأصدقاء والحضور والإعادة.

واجهة برمجة التطبيقات التي تواجه اللاعب هي نفسها سواء كان الملف القابل للتنفيذ يأتي من Steam أو Epic أو GOG أو من جهازك الخاص قاذفة، أو https://<slug>.starhermit.com.

حدود مهمة: المضمنة ليست صامتة

StarHermit لا يعرض حاليًا أي امتيازات "إنشاء لاعب تعسفي" نقطة النهاية للعبة الخادم. حاوية STARHERMIT_SERVER_TOKEN ليس لديه هوية لاعب عمدًا ولا يمكنه سك العملة حسابات اللاعبين أو انتحال شخصية اللاعبين.

يتطلب تسجيل المفتاح العام أيضًا بريدًا إلكترونيًا صالحًا ورابطًا للتحقق لمرة واحدة. لذلك:

  • أنت يستطيع استمر في التسجيل داخل واجهة المستخدم الخاصة بلعبتك وتجنب Google/GitHub OAuth و لوحة القيادة ستارهيرميت.
  • أنت لا أستطيع قم بإنشاء حساب StarHermit بصمت من خلال معرف Steam أو معرف حساب Epic أو GOG فقط معرف. يجب على اللاعب الموافقة وتقديم بريد إلكتروني وتأكيده مرة واحدة.
  • قم بإنشاء وتخزين المفتاح الخاص لكل لاعب على أجهزتهم. لا تولد مفتاح كل لاعب في خادمك المخصص، أو قم بتحميل المفاتيح الخاصة، أو احتفظ بقاعدة بيانات مفاتيح الحراسة إلا إذا كنت كذلك تحمل عمدا المسؤولية عن كل تلك الحسابات.

بالنسبة للعبة أصلية، فإن التجربة المدعومة الأكثر سلاسة هي: تقوم لوحة الحساب داخل اللعبة بإنشاء المفتاح، ويطلب البريد الإلكتروني والموافقة، وينتظر حتى يؤكد اللاعب الرابط في صندوق الوارد الخاص به، ثم يسجل الدخول باستخدام المفتاح ويحتفظ برمز التحديث في مخزن بيانات اعتماد نظام التشغيل. لا يحتاج اللاعب إلى ذلك أبدًا تصفح موقع StarHermit. لا يمكن للاعب الذي لا يمكنه تقديم بريد إلكتروني والتحقق منه إكمال هذا التدفق باستخدام واجهة برمجة التطبيقات الحالية.

حدود العمارة والثقة

Steam/Epic/GOG/native client
  ├─ owns the player's private key
  ├─ performs public-key registration/login
  ├─ holds player access + rotating refresh token
  ├─ optionally links the external platform identity
  └─ uses a game-scoped launch token for game/social APIs
                  │
                  │ REST + ws/v1/games
                  ▼
StarHermit API ───────── authenticated command ────────► your container
  ├─ creates sessions and matchmaking                     ├─ owns simulation
  ├─ stamps the trusted StarHermit user id                 ├─ never trusts payload identity
  ├─ persists snapshots/results/elo/achievements           └─ uses narrow server token only
  └─ supplies session chat, voice, friends, and replays

يثبت عميل اللعبة من هو اللاعب. يقوم StarHermit بختم تلك الهوية على حركة المرور المرسلة إلى حاوية. لا تقبل الحاوية مطلقًا معرف Steam أو معرف المستخدم المقدم داخل طريقة اللعب JSON كدليل الهوية.

المتطلبات الأساسية

أنت بحاجة إلى:

  • حساب مطور StarHermit ورمز الوصول الكامل.
  • لعبة مسجلة تملكها، مع gameSlug والخلفية الرسمية. نقطة نهاية الحزمة تحديثات لعبة موجودة؛ لا يقوم بإنشاء سجل لعبة أو حجز سبيكة.
  • تم تمكين استضافة الحاوية لحسابك.
  • Docker أو أي أداة أخرى قادرة على إنتاج ملف متوافق مع Docker docker save أرشيف.
  • تنفيذ حاوية بروتوكول اللعبة v1.

للتسجيل الأولي للخدمة الذاتية، استخدم مستودع GitHub الذي تم التحقق منه starhermit.txt و أ صالح container.image الإعلان كما هو موضح في ألعاب جيثب. مرة واحدة اللعبة موجودة، ويمكن لعمليات دفع الحزمة نشر إصدارات لاحقة من العميل والخادم مباشرةً.

الجزء الأول: تنفيذ عقد الحاوية

يجب أن تستمع عمليتك PORT وتنفيذ:

نقطة النهاية مسؤولية
GET /health يعود 200 فقط عندما يمكن قبول الجلسات
GET /describe أعلن البروتوكول 1، ومعدل/سعة التجزئة المطلوبة، والإنجازات
POST /sessions قم بإنشاء جلسة أو استعادتها من snapshot
GET /sessions/{id}/snapshot قم بإرجاع نقطة استعادة دائمة كاملة
DELETE /sessions/{id} الافراج عن الجلسة
WS /stream تلقي أوامر اللاعب المصادق عليها وإصدار حمولات اللعبة
WS /control ادفع اللقطات والإنجازات والإيلو والنتائج والضغط الخلفي

التحقق من صحة X-Starhermit-Invoke-Key على كل طلب HTTP وترقية WebSocket مقابل STARHERMIT_INVOKE_KEY. يؤدي هذا إلى مصادقة StarHermit على عمليتك.

الحد الأدنى للإعلان هو:

{
  "protocol": 1,
  "tickRateHz": 20,
  "maxSessions": 48,
  "replays": true,
  "achievements": [
    {
      "key": "first-win",
      "name": "First Win",
      "description": "Win a match.",
      "points": 10
    }
  ]
}

replays يطلب من المنصة الاحتفاظ بالحالة الأخيرة لكل جلسة منتهية، وهي ما GET /api/v1/games/{slug}/replays/{sessionId} يخدم. أعلن ذلك فقط إذا كانت لعبتك تريد إعادة العرض؛ بدونها لا يتم الاحتفاظ بأي شيء بمجرد انتهاء المباراة. يرى خوادم ألعاب الحاويات — GET /describe.

تستخدم إطارات دفق اللعب:

[1 byte type][16 byte sessionId][16 byte userId][payload...]

يكتب 1 هو أمر وارد. تم ختم معرف المستخدم الخاص به من مشغل StarHermit المصادق عليه. يكتب 2 هي حمولة JSON صادرة موجهة إلى هذا اللاعب، أو إلى الجميع عندما يكون معرف المستخدم جميع الأصفار.

تستمر التأثيرات الدائمة /control:

{ "type": "snapshot", "sessionId": "...", "state": { "round": 4 } }
{ "type": "achievements", "sessionId": "...", "unlocks": { "<userId>": ["first-win"] } }
{ "type": "elo", "sessionId": "...", "updates": { "<userId>": 1248 } }
{ "type": "result", "sessionId": "...", "result": { "kind": "win", "winner": "<userId>" } }

يقوم StarHermit بتصفية هذه التحديثات للمشاركين في الجلسة ومفاتيح الإنجاز المعلنة. والنتيجة هي محطة. يرى خوادم الألعاب المستضافة بالحاويات للبروتوكول الكامل، عقد اللقطة والعزل والاسترداد.

الجزء الثاني: قم بتسجيل اللعبة مرة واحدة

ضع بيانًا في المستودع الذي تم التحقق منه والمستخدم للتسجيل الأولي:

name=Orbit League
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html
owner=3fa85f64-5717-4562-b3fc-2c963f66afa6  # your user ID from GET /api/v1/me, not username

container.image=ghcr.io/your-github-login/orbit-server@sha256:<64-lowercase-hex>
container.port=8080
container.health=/health
container.memory_mb=1024
container.cpu=1.0

تعيين owner إلى غير القابل للتغيير id عاد بواسطة GET /api/v1/me. لا تستخدم اسم مستخدم الحساب أو لقب؛ هذه هي قيم العرض وقد تتغير.

قم بتسجيله:

API=https://api.starhermit.com
ACCESS_TOKEN='developer-access-token'

curl -sS -X POST "$API/api/v1/me/github-games" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "repoUrl":"https://github.com/your-github-login/orbit-league"
  }'

حفظ عاد id مثل GAME_ID و gameSlug مثل GAME_SLUG، ثم تأكد من وجود الواجهة الخلفية: GET $API/api/v1/games/$GAME_SLUG إجابات 200 بمجرد أن يحدث ذلك. هدية gameSlug وحده لا إثبات ذلك - تحتوي كل لعبة تم التحقق منها على لعبة واحدة متضمنة في المتصفح فقط. التسجيل الذي يعلن أ يتم رفض الحاوية دون إثبات ملكيتك للمستودع 403، والتسجيل الأولي قد تفشل أيضًا عندما تكون استضافة الحاوية غير متاحة أو مقيدة.

الصورة المدعومة بالتسجيل في البيان كافية لنشر الإصدار الأول. القسم التالي يغطي مسار التحميل المباشر، وهو مفيد لـ CI وللإصدارات التي لا تريدها منصة للاستنساخ أو السحب مرة أخرى.

الجزء 3: نشر حزمة العميل والخادم المخصص

بناء الأرشيف

التحميل عبارة عن أرشيف tar واحد مضغوط بصيغة gzip بهذا التخطيط:

client/            optional static web client, including the registered launch file
server/image.tar   optional `docker save` output
starhermit.txt     the manifest

على الأقل client/ أو server/image.tar يجب أن يكون حاضرا.

إذا قمت بالنشر من خلال لوحة معلومات الويب StarHermit أو عميل Windows بدلاً من التجعيد، فإنك لا تفعل ذلك بناء هذا الأرشيف باليد. اختر إما أ مجلد توزيع الخادم (عقد starhermit.txt و image.tar) أو ال image.tar من تلقاء نفسها، ويقوم العميل بحزم التخطيط أعلاه. ال starhermit.txt القيم - اسم العرض و container.* المقابض - هي الحقول الموجودة في مربع الحوار، والتي يتم ملؤها مسبقًا من بيان المجلد عندما يكون هناك واحد، لذا فهي عارية image.tar ينشر كذلك.

rm -rf bundle game-bundle.tar.gz
mkdir -p bundle/client bundle/server

# Optional hosted web client.
cp -R dist/. bundle/client/

# Dedicated server image.
docker build -t orbit-server:release -f Dockerfile.server .
docker save orbit-server:release -o bundle/server/image.tar

# Keeps the artifact self-describing, and is what the dashboard/desktop clients require.
cp starhermit.txt bundle/starhermit.txt

tar -C bundle -czf game-bundle.tar.gz .

يجب أن تعمل الصورة مع نظام ملفات جذر للقراءة فقط، ومستخدم غير جذر قسري، ولا توجد إمكانيات، ولا مجلدات، لا يوجد إنترنت، وفقط صغيرة قابلة للكتابة /tmp. تبعيات البائع في الصورة.

قم بتحميله

POST /api/v1/me/github-games/{id}/bundle يأخذ الأرشيف باعتباره نص الطلب الأولي، وليس كملف شكل متعدد الأجزاء:

curl -sS -X POST "$API/api/v1/me/github-games/$GAME_ID/bundle" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/gzip" \
  --data-binary @game-bundle.tar.gz

لن تتمكن الحزمة التي يزيد حجمها عن 100 ميجابايت من المرور عبر هذا المسار. CDN أمام API يرفض هيئة طلب كبيرة مع أ 413 خاصة بها - واحدة لا تراها المنصة أبدًا، لذا فهي تحملها لا limitBytes ويظهر في أي سجل يمكنك قراءته. أ docker save من صورة الخادم الحقيقية تصل هذا الحجم بسهولة. إذا رأيت أ 413 مع لا limitBytes، هذه هذه وليست لعبتك البدل، وهو غيغابايت.

أرسل نفس الأرشيف ws/v1/game-upload بدلاً من ذلك — إطارات بعد أ ترقية WebSocket ليست نص طلب، لذلك لا يتم تطبيق الحد الأقصى. نفس تخطيط الأرشيف، نفسه البدل، نفس إجابات JSON؛ الإضافة الوحيدة هي أنه يجب عليك إرسال {"type":"complete"} متى لقد انتهى البايت الأخير، لأنه لن يتم نشر أي شيء حتى تقوم بذلك.

مثال للرد:

{
  "clientPublished": true,
  "serverImageLoaded": true,
  "imageDigest": "sha256:4e7d...",
  "bytesReceived": 318767104
}

المنصة:

  • مبادلة ذرية في client/، لذلك لا يرى المستخدمون الإصدار الذي تم تحميله جزئيًا؛
  • الأحمال server/image.tar، ويحسب ملخصه غير القابل للتغيير، ويعيد تثبيت النشر؛
  • وضع الحاوية القديمة في قائمة الانتظار لتحل محلها الصورة التي تم تحميلها؛
  • يستعيد الجلسات النشطة المؤهلة من اللقطات المستمرة.

يمكنك تحميل العميل فقط أو صورة الخادم فقط. استخدام تصحيحات العميل فقط ?mode=merge على نفس نقطة النهاية (انظر تحديثات جزئية); صورة في عملية الدمج لا تزال محملة بالكامل. بدل قرص اللعبة هو 2 جيجابايت على starhermit.com (عامل التشغيل قابل للضبط) ويمكن يتم ضبطها لكل لعبة؛ لأن الدفع يستبدل محتوى اللعبة بدلاً من الإضافة إليه، وهذا هو الأمران معًا أكبر دفعة وأكبر قرص يمكن أن تشغله اللعبة. 413 يشمل limitBytes; غير صالح إرجاع الأرشيف أو الصورة 422; و 507 يعني أن الخادم ليس به مكان في الوقت الحالي — فقد تم فحصه قبل أن تتم قراءة جسدك، لذلك يتم رفض التحميل المحكوم عليه بالفشل بدلاً من الوصول إلى نصفه. لا تضع روابط رمزية، الروابط الصلبة أو اجتياز المسار أو الملفات خارج التخطيط الموثق في الأرشيف.

لا يعني التحميل الناجح أن العملية الجديدة قد اجتازت اختبارات السلامة حتى الآن. استطلاع الموجود GET /api/v1/me/github-games/{id}/deployment عرض واختبار جلسة حقيقية قبل الترويج لل بناء. يؤدي تثبيت التزام المستودع لاحقًا إلى تبديل النشر مرة أخرى إلى محتوى المستودع بشكل صريح.

تبديل لعبة موجودة من server= إلى حاوية

مدعوم، ويحافظ على اللعبة: نفس المعرف، سبيكة، <uid>.starhermit.com عنوان اللاعبين, المتصدرين والإنجازات. لا توجد خطوة تسجيل منفصلة.

  1. يستبدل server=... مع الخاص بك container.* منع في starhermit.txt. الاثنان متبادلان حصريا؛ تم رفض بيان يعلن كلاهما.
  2. دفع حزمة واحدة تحمل client/ (بهذا البيان) و server/image.tar، زيادة ws/v1/game-upload إذا كانت كبيرة.
  3. الصورة التي تقوم بتحميلها هي الصورة التي يتم تشغيلها. أ container.image= السطر في نفس البيان هو من الجيد الاحتفاظ به، لكن الملخص الذي تم تحميله يفوز به.
  4. استطلاع GET /api/v1/me/github-games/{id}/deployment حتى يقرأ running، ثم ابدأ حقيقيًا غرفة أو مباراة.

الجزء 4: تجديد الرمز المميز لمنصة الحاوية

عند بدء التشغيل تتلقى الحاوية:

STARHERMIT_API_BASE
STARHERMIT_GAME_SLUG
STARHERMIT_SERVER_TOKEN
STARHERMIT_SERVER_TOKEN_EXPIRES_IN
STARHERMIT_REFRESH_KEY
STARHERMIT_INVOKE_KEY

STARHERMIT_SERVER_TOKEN ضيقة: فهي تمثل خادم اللعبة، وليس اللاعب. وتنتهي بعد 24 ساعة بشكل افتراضي. تجديد الجدول الزمني في ما يقرب من نصف STARHERMIT_SERVER_TOKEN_EXPIRES_IN:

POST {STARHERMIT_API_BASE}/api/v1/games/{STARHERMIT_GAME_SLUG}/server/token
X-Starhermit-Refresh-Key: {STARHERMIT_REFRESH_KEY}

{ "token": "eyJhbGciOi...", "expiresInSeconds": 86400 }

لا يلزم وجود رمز حامل لنقطة النهاية هذه. وهذا يسمح بالاسترداد حتى لو كان الرمز القديم موجودًا انتهت صلاحيتها بالفعل. استبدل الرمز المميز الموجود في الذاكرة تلقائيًا وقم بجدولة التجديد التالي من الجديد expiresInSeconds.

أبقِ سرّي النشر منفصلين:

  • STARHERMIT_INVOKE_KEY يصادق على طلبات StarHermit إلى الحاوية الخاصة بك.
  • STARHERMIT_REFRESH_KEY يقوم بمصادقة الحاوية الخاصة بك عند تجديد رمز StarHermit الخاص بها.

كلاهما يدور عند كل إعادة تشغيل للحاوية. لا تقم بتسجيلهم أبدًا، قم بإعادتهم /describe، ضعهم في لقطة، أو إرسالها إلى لاعب.

الجزء 5: على متن لاعب غير StarHermit بدون OAuth

قم بتشغيل هذا التدفق في اللعبة الأصلية أو المشغل، وليس في الحاوية المخصصة. الشرح كاملا, مع رمز العميل الذي تم اختباره، هو البرنامج التعليمي: لاعبين على متن الطائرة بمفتاح عام; باختصار:

  1. إنشاء مفتاح لكل تثبيت عند الإطلاق لأول مرة (يوصى باستخدام Ed25519) واحتفظ بالمفتاح الخاص في مخزن بيانات اعتماد نظام التشغيل. لا تقم أبدًا بتحميله، ولا تقم أبدًا بإنشاء مفاتيح اللاعبين على الخادم الخاص بك.
  2. اطلب الموافقة وعنوان البريد الإلكتروني، ثم POST /api/v1/auth/public-key/register مع { email, keyType, keyData } من جهاز اللاعب . يتم اختناقه لتسجيل واحد لكل العنوان ولكل IP كل 24 ساعة (429 مع Retry-After)، لذلك لا تقم أبدًا بتوكيله من خلالك الخادم - سيشارك كل لاعب عنوان IP الخاص به.
  3. انتظر حتى يؤكد اللاعب. يفتح الرابط المرسل بالبريد الإلكتروني صفحة لا تغير شيئًا حتى يضغط اللاعب على تأكيد، مما يؤدي إلى إنشاء الحساب وإرفاق المفتاح؛ على starhermit.com ثم تصل بعد ذلك إلى لوحة معلومات StarHermit، لذلك لا تتلقى لعبتك هذه الرموز. بدلا من ذلك يسجل الدخول بالمفتاح حتى ينجح ذلك: challenge، وقع على StarHermit بايت التحدي الدقيق, complete. حتى يؤكد اللاعب complete إجابات 401 "Public key not registered or revoked.".
  4. احتفظ بالجلسة مع POST /api/v1/auth/refresh، وقم بتسجيل الدخول باستخدام المفتاح مرة أخرى في أي وقت فشل التحديث. قبول الشروط الحالية عندما GET /api/v1/me التقارير termsAcceptanceRequired (يمكن لكل من جلسات الحساب والرموز المميزة لإطلاق اللاعب - انظر قبول الشروط). رمز النشر الخاص بالحاوية الخاصة بك هو معفاة من الشروط؛ لا يمتد هذا الإعفاء إلى لاعبيه.

المزيد من الأجهزة. يقوم كل تثبيت بتسجيل مفتاحه الخاص باستخدام عنوان البريد الإلكتروني نفسه للاعب المفتاح ينضم إلى الحساب الحالي. POST /api/v1/me/public-keys ليس خيارًا لهؤلاء اللاعبين: فهو يتطلب جلسة تم تسجيل دخولها من خلال موفر OAuth.

5. قم بإضافة اسم مواجهة اللاعب وهوية خارجية

يبدأ الحساب الذي تم إنشاؤه بـ pk-... اسم المستخدم. السماح للاعب باختيار لقب:

PATCH /api/v1/me
Authorization: Bearer <access-token>
Content-Type: application/json

{ "nickname": "RookPilot" }

يمكنك ربط الحساب بالنظام الأساسي الذي يعمل عليه الملف القابل للتنفيذ ضمن:

POST /api/v1/me/identities
Authorization: Bearer <access-token>
Content-Type: application/json

{
  "provider": "epic",
  "providerUserId": "epic-account-id",
  "metadata": "{\"displayName\":\"RookPilot\"}"
}

استخدم أ غير محفوظة اسم المزود (epic, gog، أو معرف واجهة المتجر الخاصة بك). يفعل لا يستخدم steam, google, githubأو أي اسم آخر يتعامل معه النظام الأساسي كموفر OAuth - هؤلاء يتم رفضها حتى لو لم يتم تكوين هذا الموفر. احصل على المعرف الخارجي من تلك المنصة جلسة SDK/جلسة مصادق عليها، وليس من مدخلات المشغل القابلة للتحرير. نقطة النهاية هذه تربط الهوية مع حساب StarHermit؛ فهو ليس في حد ذاته دليلاً على ملكية واجهة المتجر ويجب ألا يحل محله التحقق من التذاكر الخاصة بالمنصة لعمليات الشراء أو الحظر.

تعد واجهة برمجة تطبيقات المكتبة الخارجية المنفصلة اختيارية وتستخدم حاليًا المزامنة التجريبية أثناء توفيرها تم الانتهاء من عمليات التكامل؛ ليس مطلوبًا للعب على خادم مخصص.

الجزء السادس: أدخل إلى اللعبة واستخدم خدمات StarHermit

يستبدل {slug} في أمثلة HTTP أدناه مع GAME_SLUG، اللعبة UUID التي حصلت عليها من التسجيل. اسم المستودع orbit-league هو اسم العرض/المصدر، وليس سبيكة API.

صك رمز اللعبة الأقل امتيازًا

استخدم رمز الوصول الكامل مرة واحدة لسك رمز مميز مسور للعبتك:

POST /api/v1/games/{slug}/launch-token
Authorization: Bearer <access-token>

{ "token": "eyJhbGciOi...", "expiresInSeconds": 3600 }

استخدم رمز الإطلاق المميز للعب وواجهات برمجة التطبيقات الاجتماعية للجلسة المسموح بها. قم بتحديثه قبل انتهاء الصلاحية. احتفظ برمز الحساب الكامل بعيدًا عن رمز اللعب حيثما أمكن ذلك.

التوفيق بين

POST /api/v1/games/{slug}/matchmaking
Authorization: Bearer <game-token>

استطلاع GET /api/v1/games/{slug}/matchmaking حتى status يكون matched، ثم قم بالاتصال:

wss://api.starhermit.com/ws/v1/games?sessionId=<sessionId>&access_token=<game-token>

تظل رسائل العميل بتنسيق JSON:

{ "type": "cmd", "data": { "type": "input", "throttle": 0.8 } }

يقوم StarHermit بتحويل الأمر إلى دفق الحاوية ويختم StarHermit المصادق عليه معرف المستخدم. تُرجع الحاوية الخاصة بك حمولات اللعبة الرسمية من خلال إطارات التدفق من النوع 2.

المتصدرين والإنجازات

تحصل كل لعبة موثوقة على لوحة صدارة Elo. ترسل الحاوية الخاصة بك تغييرات Elo وتعلن عنها يفتح الإنجاز أكثر /control; يقرأ العملاء حالة النظام الأساسي الناتجة فقط:

GET /api/v1/games/{slug}/achievements
GET /api/v1/leaderboards/{leaderboardId}/entries

لا يمكن لعميل Steam/Epic/GOG المعدل إرسال نتائج لوحة صدارة اللعبة مباشرة أو المطالبة بـ الإنجاز المملوكة للعبة.

جلسة الدردشة والصوت

GET /api/v1/games/{slug}/sessions/{sessionId} يعود chatConversationId. جلسة تسمح المحادثات للمشاركين بالدردشة واستخدام الصوت حتى عندما لا يكونون أصدقاء.

التدفق الصوتي النموذجي:

  1. GET /api/v1/voice/rooms?conversationId=<chatConversationId>.
  2. إذا لزم الأمر، POST /api/v1/voice/rooms مع معرف المحادثة
  3. POST /api/v1/voice/rooms/{roomId}/join.
  4. يتصل wss://api.starhermit.com/ws/v1/voice?roomId=<roomId>&access_token=<game-token>.

يقوم نفس الحساب أيضًا بتمكين الأصدقاء والتواجد ودعوات اللعبة وعمليات الإعادة وهوية الملف الشخصي جميع بنيات واجهة المتجر. احتفظ بمفتاح/حساب StarHermit واحد لكل إنسان بدلاً من إنشاء حساب جديد لكل مباراة أو كل إطلاق لواجهة المتجر.

قائمة مرجعية الإنتاج

نشر

  • [ ] اللعبة المملوكة الحالية لا تحتوي على قيمة فارغة gameSlug.
  • [ ] ترفض الحاوية مفتاح استدعاء خاطئ أو مفقود.
  • [ ] تتم قراءة مفتاح الاستدعاء ومفتاح التحديث والرمز المميز للخادم من البيئة عند بدء العملية، ولا يتم تخزينها مطلقًا في الصورة أو تخزينها مؤقتًا على القرص (يتم تدوير الثلاثة جميعًا عند كل بداية حاوية).
  • [ ] /health لا يعود 200 قبل أن يتم قبول الدولة.
  • [ ] تستخدم الحزمة الخام application/gzip، وليس ترميز متعدد الأجزاء.
  • [ ] تعمل الصورة للقراءة فقط، وبدون الجذر، وبدون اتصال بالإنترنت، وبدون مجلدات.
  • [ ] يتم اختبار حالة النشر وجلسة التوفيق الحقيقية بعد التحميل.
  • [ ] يتم تشغيل تحديث الرمز المميز للخادم قبل نصف عمره ويتبادل الرموز المميزة تلقائيًا.
  • [ ] لا يتم تسجيل سر النشر أو استمراره في اللقطات.

تأهيل اللاعب

  • [ ] يتم إنشاء زوج المفاتيح على جهاز المشغل ويستخدم المفتاح الخاص مساحة تخزين آمنة.
  • [ ] يتم الإفصاح عن إنشاء الحساب والموافقة عليه.
  • [ ] يتم إكمال التحقق من البريد الإلكتروني مرة واحدة؛ 429 Retry-After محترم.
  • [ ] لا تمر رموز التسجيل واللاعب عبر الخادم المخصص.
  • [ ] يتم تخزين رموز الوصول/التحديث بشكل آمن ويتم إجراء تسلسل لتدوير التحديث.
  • [ ] تأتي المعرفات الخارجية من حالة Steam/Epic/GOG SDK المصادق عليها.
  • [ ] تستخدم طريقة اللعب رمزًا مميزًا على نطاق اللعبة بعد الإعداد الأولي للحساب.
  • [ ] مقابض العميل achievement, resumed، و abandoned إطارات اللعب.
