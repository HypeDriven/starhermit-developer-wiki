البرنامج التعليمي: اللاعبون الموجودون على متن الطائرة باستخدام المفتاح العام

لا يحتاج حساب StarHermit إلى Google أو GitHub أو أي مزود تسجيل دخول آخر. يمكن لأوراق اعتمادها يكون زوج المفاتيح الذي تنشئه لعبتك على جهاز اللاعب، بالإضافة إلى عنوان البريد الإلكتروني للاعب يؤكد مرة واحدة. بعد ذلك، تقوم لعبتك بتسجيل الدخول بصمت عند كل عملية إطلاق من خلال التوقيع على تحدي مع المفتاح. لا يقوم اللاعب أبدًا بكتابة كلمة مرور ولا يتعين عليه مطلقًا زيارة صفحة StarHermit.

يبني هذا البرنامج التعليمي هذا التدفق من البداية إلى النهاية: قم بإنشاء المفتاح، وتسجيله، وانتظر حتى يقوم اللاعب بذلك قم بالتأكيد وتسجيل الدخول والاحتفاظ بالجلسة والتعامل مع الأجهزة الثانية والمفاتيح المفقودة.

استخدم هذا ل ألعاب أصلية ومستقلة، وقاذفات، وإصدارات Steam/Epic/GOG وأدوات سطح المكتب - أي شيء يتم تشغيله على جهاز اللاعب ويمكنه الاحتفاظ بمفتاح خاص هناك.

استخدام شيء آخر ل

  • لعبة متصفح مستضافة على StarHermit، والذي يتلقى بالفعل رمز الإطلاق المميز عند فتحه منه لوحة القيادة، أو يمكن أن تظهر أ زر تسجيل الدخول.
  • خط أنابيب CI، والتي يجب أن تسجل مفتاحًا من جلسة OAuth بدون خطوة البريد الإلكتروني: البرنامج التعليمي: يتم إنشاء التحميل من CI/CD.
  • خادم ألعاب مخصص، الذي له رمز نشر مميز خاص به ولا يمكنه إنشاءه أو التصرف به اللاعبين: البرنامج التعليمي: نشر خادم مخصص.

ما يراه اللاعب

  1. تطلب لعبتك عنوان بريد إلكتروني وموافقتهم على إنشاء حساب StarHermit.
  2. يفتحون رسالة التأكيد الإلكترونية، وينقرون على الرابط، ثم يضغطون يتأكد على الصفحة التي يفتحها.
  3. بالعودة إلى لعبتك، تم تسجيل دخولهم. وفي عمليات الإطلاق اللاحقة، لا يتم طلب أي شيء على الإطلاق.

مطلوب عنوان بريد إلكتروني، ويجب على اللاعب تأكيده مرة واحدة. لا توجد طريقة لإنشاء حساب StarHermit بصمت من هوية Steam أو Epic أو GOG وحدها.

قبل أن تبدأ

الكود الموجود في هذه الصفحة هو JavaScript عادي باستخدام WebCrypto و fetch، لذلك يتم تشغيله في المتصفح، في الإلكترون وفي العقدة 20 أو الأحدث. ال js الكتل أدناه، بالترتيب، تشكل وحدة ES واحدة - احفظهم معا كما starhermit-key-auth.js. أي لغة أخرى تعمل بنفس الطريقة: الخطوة 1 تعطي بالضبط تنسيقات البايت، والخطوة 3 البايتات الدقيقة للتوقيع.

const API = 'https://api.starhermit.com';

const b64 = (bytes) => btoa(String.fromCharCode(...new Uint8Array(bytes)));

1. قم بإنشاء مفتاح الجهاز

يولد زوج مفاتيح واحد لكل عملية تثبيت، في المرة الأولى التي تحتاج فيها لعبتك إلى حساب. الخاص المفتاح لا يغادر الجهاز أبدًا: لا إلى خوادمك، ولا إلى StarHermit.

keyType keyData (قاعدة 64 القياسية) التوقيع (قاعدة 64 القياسية)
Ed25519 - مُستَحسَن المفتاح العمومي الخام 32 بايت التوقيع الخام Ed25519 بحجم 64 بايت
ECDSA-P256 النقطة العامة: 65 بايت غير مضغوطة (04‖X‖Y) أو مضغوطة بحجم 33 بايت ECDSA مع SHA-256، مشفر بـ ASN.1 DER
RSA-PSS SubjectPublicKeyInfo DER، معامل 2048–8192 بت، الأس ≥ 32 بت RSASSA-PSS، SHA-256، MGF1-SHA-256، ملح 32 بايت

keyData هو على الأكثر 2000 حرف. ينتمي مفتاح واحد إلى حساب واحد عبر النظام الأساسي.

يختار إد25519 إلا إذا كان النظام الأساسي الخاص بك لا يستطيع إنتاجه. إذا كنت تستخدم ECDSA، فلاحظ أن WebCrypto، يقوم Windows CNG ومعظم مخازن مفاتيح الأجهزة بإرجاع التوقيع كأول r‖s (64 بايت). ستارهيرميت يتوقع DER، لذا قم بتحويله — الوحدة أدناه تفعل ذلك.

// One key per installation. The private key can sign but is never exported.
export async function createDeviceKey(keyType = 'Ed25519') {
  if (!['Ed25519', 'ECDSA-P256'].includes(keyType)) throw new Error('This helper supports Ed25519 or ECDSA-P256');
  const algorithm = keyType === 'Ed25519'
    ? { name: 'Ed25519' }
    : { name: 'ECDSA', namedCurve: 'P-256' };
  const pair = await crypto.subtle.generateKey(algorithm, false, ['sign', 'verify']);
  return {
    keyType: keyType === 'Ed25519' ? 'Ed25519' : 'ECDSA-P256',
    keyData: b64(await crypto.subtle.exportKey('raw', pair.publicKey)),
    privateKey: pair.privateKey,
  };
}

قم بتخزين المفتاح الخاص حيث يحميه نظام التشغيل. في المتصفح أو العارض الإلكتروني، غير قابلة للاستخراج CryptoKey يمكن الاحتفاظ بها في IndexedDB كما هي. يجب أن تستخدم اللعبة الأصلية ملف مخزن مفاتيح النظام الأساسي — Windows DPAPI أو CNG، وmacOS Keychain، وlibsecret على Linux. محل keyType و keyData بجانبه؛ ترسلهم مع كل طلب.

2. ابدأ التسجيل

اطلب عنوان البريد الإلكتروني للاعب وموافقته، ثم:

async function post(path, body) {
  const res = await fetch(API + path, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  });
  return { status: res.status, body: await res.json().catch(() => ({})) };
}

function fail(step, { status, body }) {
  return Object.assign(new Error(`${step}: ${body.error ?? status}`), { status, body });
}

export async function register(key, email) {
  const res = await post('/api/v1/auth/public-key/register',
    { email, keyType: key.keyType, keyData: key.keyData });
  if (res.status !== 202) throw fail('register', res);
  return res.body; // { registrationId, email, emailSent, deferralReason, message }
}

202 يعني أن StarHermit قبلت التسجيل. لو emailSent يكون false، البريد الإلكتروني في قائمة الانتظار و سوف لا يزال يصل؛ deferralReason يقول لماذا انتظرت. لم يتم ربط أي شيء بأي حساب حتى الآن.

ثلاث قواعد تشكل واجهة المستخدم الخاصة بك:

  • تسجيل واحد لكل عنوان بريد إلكتروني، وتسجيل واحد لكل عنوان IP، كل 24 ساعة. محاولة ثانية هو 429 مع Retry-After. اطلب من اللاعب تأكيد العنوان قبل إرساله، بسبب خطأ مطبعي يكلفهم يوما. أرسل الطلب من جهاز اللاعب، وليس من خلال الخادم الخاص بك أبدًا: كل سيشارك اللاعب عنوان IP الخاص بخادمك وتسجيله اليومي الفردي.
  • تنتهي صلاحية الرابط بعد 4 ساعات. إذا انقضت المدة، يمكن للاعب التسجيل مرة أخرى بعد مرور 24 ساعة متروك.
  • 400 يعني أنه تم رفض عنوان البريد الإلكتروني أو المادة الرئيسية؛ error يقول الذي.

3. قم بتسجيل الدخول بالمفتاح

تسجيل الدخول هو التحدي والاستجابة. POST /api/v1/auth/public-key/challenge العوائد:

{
  "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
  "payload": {
    "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
    "fingerprint": "9c0b7a…",
    "issuer": "starhermit",
    "audience": "starhermit",
    "expiry": "2026-10-09T14:21:41.9264875+00:00",
    "nonce": "NmL+tgMum6HXU/pa3T9xjQ==",
    "clientTimestamp": "2026-10-09T14:16:41.9265739+00:00"
  },
  "expiresIn": 300
}

ما قمت بالتوقيع عليه ليس JSON الذي تلقيته. يقوم StarHermit بالتحقق من التوقيع من تلقاء نفسه تسلسل payload:

  • JSON مضغوط، بدون مسافة بيضاء؛
  • باسكال كيس أسماء الأعضاء بالترتيب بالضبط ChallengeId, Fingerprint, Issuer, Audience, Expiry, Nonce, ClientTimestamp;
  • كل قيمة منسوخة بالضبط كما خدم — لا تقم بتحليل التواريخ وإعادة تنسيقها؛
  • كل + في nonce مكتوبة باسم \u002B. ال + في التواريخ يبقى كما هو.

بالنسبة للتحدي أعلاه، فإن البايتات الموقعة هي ترميز UTF-8 لما يلي:

{"ChallengeId":"4fc4d72b-4c12-41ca-a500-dc13cccc3865","Fingerprint":"9c0b7a…","Issuer":"starhermit","Audience":"starhermit","Expiry":"2026-10-09T14:21:41.9264875+00:00","Nonce":"NmL\u002BtgMum6HXU/pa3T9xjQ==","ClientTimestamp":"2026-10-09T14:16:41.9265739+00:00"}

احصل على أي من هذا الخطأ والجواب هو 401 "Invalid signature."، والتي لن يتم إصلاحها بعد إعادة المحاولة.

const FIELDS = ['challengeId', 'fingerprint', 'issuer', 'audience', 'expiry', 'nonce', 'clientTimestamp'];

export function challengeSigningBytes(payload) {
  const members = FIELDS.map((field) => {
    let value = JSON.stringify(payload[field]);
    if (field === 'nonce') value = value.replaceAll('+', '\\u002B');
    return `"${field[0].toUpperCase()}${field.slice(1)}":${value}`;
  });
  return new TextEncoder().encode(`{${members.join(',')}}`);
}

export async function signChallenge(key, payload) {
  const data = challengeSigningBytes(payload);
  if (key.keyType === 'Ed25519')
    return b64(await crypto.subtle.sign({ name: 'Ed25519' }, key.privateKey, data));
  // WebCrypto returns an ECDSA signature as raw r||s; the server expects ASN.1 DER.
  const rs = new Uint8Array(
    await crypto.subtle.sign({ name: 'ECDSA', hash: 'SHA-256' }, key.privateKey, data));
  return b64(derEcdsaSignature(rs));
}

function derEcdsaSignature(rs) {
  const integer = (bytes) => {
    let i = 0;
    while (i < bytes.length - 1 && bytes[i] === 0) i++;
    const value = [...bytes.slice(i)];
    return value[0] & 0x80 ? [0x02, value.length + 1, 0, ...value] : [0x02, value.length, ...value];
  };
  const body = [...integer(rs.slice(0, 32)), ...integer(rs.slice(32))];
  return new Uint8Array([0x30, body.length, ...body]);
}

// Resolves to { userId, accessToken, refreshToken }, or null while the key is not attached to
// an account yet — the player has not confirmed, the link expired, or the key was revoked.
export async function signIn(key) {
  const { keyType, keyData } = key;
  const challenge = await post('/api/v1/auth/public-key/challenge', { keyType, keyData });
  if (challenge.status !== 200) throw fail('challenge', challenge);
  const signature = await signChallenge(key, challenge.body.payload);
  const done = await post('/api/v1/auth/public-key/complete',
    { challengeId: challenge.body.challengeId, signature, keyType, keyData });
  if (done.status === 200) return done.body;
  if (done.status === 401 && done.body.error === 'Public key not registered or revoked.') return null;
  throw fail('complete', done); // "Invalid signature." will never succeed: fix it, don't retry it
}

يستمر التحدي لمدة خمس دقائق ويتم استخدامه لمرة واحدة، حتى في حالة فشل المحاولة، لذا اطلب تحديًا جديدًا لكل محاولة. تحدي وإكمال المشاركة بحد أقصى 60 طلبًا في الدقيقة لكل عنوان IP.

4. انتظر حتى يؤكد اللاعب

يفتح الرابط المرسل عبر البريد الإلكتروني صفحة StarHermit توضح ما سيفعله التأكيد؛ فتحه يتغير لا شيء، لذلك لا يستطيع ماسح البريد الذي يقوم بمعاينة الرابط التأكيد نيابة عن اللاعب. عندما ضغطات اللاعب يتأكديقوم StarHermit بإنشاء حسابه وإرفاق المفتاح الخاص بك ووضع علامة على العنوان تم التحقق منها. إذا كان الحساب يستخدم هذا العنوان بالفعل، فستشير الصفحة إلى ذلك ويتم إضافة المفتاح إليه بدلاً من ذلك، يحتفظ به اللاعب الذي لديه حساب StarHermit بالفعل. ثم هبطوا على موقع starhermit.com على لوحة معلومات StarHermit، تم تسجيل الدخول بالفعل.

لا تتلقى لعبتك الرموز المميزة من تلك الصفحة أبدًا، ولا يحتاج إليها. يجوز للاعب التأكيد على الهاتف أو في متصفح آخر. بمجرد إرفاق المفتاح، يمكن للعبتك تسجيل الدخول ببساطة معها. لذا أظهر أ "تحقق من البريد الوارد الخاص بك" الشاشة واستمر في المحاولة:

// Poll until the player confirms the emailed link. Two requests per attempt, so every 5 s stays
// well inside the 60-per-minute sign-in limit.
export async function waitUntilConfirmed(key, { intervalMs = 5000, signal } = {}) {
  for (;;) {
    signal?.throwIfAborted();
    const session = await signIn(key);
    if (session) return session;
    await new Promise((resolve) => setTimeout(resolve, intervalMs));
  }
}

تجميع الخطوات من 1 إلى 4 معًا:

import { createDeviceKey, register, signIn, waitUntilConfirmed } from './starhermit-key-auth.js';

const key = await loadStoredKey() ?? await saveKey(await createDeviceKey());
let session = await signIn(key);                // a returning player is signed in here
if (!session) {
  const email = await askForEmailAndConsent();
  await register(key, email);
  showCheckYourInbox(email);
  session = await waitUntilConfirmed(key, { signal: cancelButton.signal });
}

loadStoredKey, saveKey, askForEmailAndConsent و showCheckYourInbox هي لك أن تكتب. عرض أ يلغي يؤدي إلى إحباط الانتظار، وإيقاف الاستقصاء بعد أربع ساعات، عند انتهاء صلاحية الارتباط.

استمر في الاقتراع حتى إذا كانت صفحة التأكيد الخاصة بنظامك الأساسي تعيد التوجيه مرة أخرى إلى موقعك. اللاعب في كثير من الأحيان يفتح البريد الإلكتروني على جهاز مختلف عن الجهاز الذي ينتظره، ومن ثم لا تصل عملية إعادة التوجيه إلى أي مكان بالقرب من شاشة الانتظار الخاصة بك؛ الاستقصاء هو ما يشير إلى دخول جهاز الانتظار. في حالة وصول إعادة التوجيه في علامة التبويب الثانية، قم بتسجيل الدخول باستخدام واحد منهم فقط وقم بإلغاء الجلسة الإضافية، وإلا سينتهي الأمر باللاعب مع اثنين.

5. حافظ على الجلسة

complete تقوم بإرجاع رمز وصول مدته 15 دقيقة ورمز تحديث يستمر لمدة سبعة أيام ويدور. أرسل رمز الوصول كـ Authorization: Bearer …، وقم بالتحديث قبل انتهاء صلاحيته:

// Resolves to the new pair, or null when the session is over — sign in with the key again.
export async function refresh(refreshToken) {
  const res = await post('/api/v1/auth/refresh', { refreshToken });
  return res.status === 200 ? res.body : null; // { accessToken, refreshToken }
}

يستبدل كلاهما الرموز في كل مرة. يؤدي تقديم رمز التحديث المستخدم إلى إنهاء الجلسة بأكملها، لذا قم بذلك تأكد من عدم تحديث خيطين أو عمليتين مرة واحدة. متى refresh يعود null، يتصل signIn — لا يوجد بريد إلكتروني متضمن. المفتاح هو أوراق الاعتماد طويلة الأمد؛ الرموز هي مجرد ذاكرة تخزين مؤقت لها.

6. قم بإنهاء إعداد الحساب

شروط. يجب أن يقبل الحساب الجديد شروط StarHermit الحالية قبل أن يتمكن من استخدام أي شيء آخر. يتصل GET /api/v1/me. لو termsAcceptanceRequired يكون true، أظهر النص من GET /api/v1/termsوعندما يقبلها اللاعب، أرسل التجزئة إلى POST /api/v1/me/terms/accept. تحقق مرة أخرى عند الإطلاقات اللاحقة، لأنه تمت مراجعة الشروط. تفاصيل: قبول الشروط.

اسم. الحساب يبدأ ب pk-… اسم المستخدم. السماح للاعب باختيار لقب:

PATCH /api/v1/me
Authorization: Bearer <access-token>
Content-Type: application/json

{ "nickname": "RookPilot" }

من هنا الحساب مثل أي حساب آخر: الأصدقاء، الدردشة، التوفيق، الحفظ السحابي، الإنجازات.

7. الأجهزة الثانية والمفاتيح المفقودة والحدود

جهاز ثاني يولد المفتاح الخاص به ويسجله نفس عنوان البريد الإلكتروني. عندما بعد تأكيد اللاعب، ينضم المفتاح إلى حسابه الحالي بدلاً من إنشاء حساب جديد. الـ 24 ساعة ينطبق الحد الأقصى لكل عنوان هنا أيضًا.

جهاز مفقود أو مسروق. POST /api/v1/auth/public-key/revoke-request مع { "email": "…" } إرسال رابط إلى صفحة بالبريد الإلكتروني؛ تأكيد هناك يلغي كل المفتاح على الحساب وينهي الجلسات تم تسجيل الدخول إلى هذه المفاتيح. فتح الرابط وحده لا يغير شيئًا. الطلب يجيب دائما 202 مع نفس الرسالة، أم لا العنوان لديه حساب. تنتهي صلاحية الرابط بعد أربع ساعات، ويمكن للحساب أن يطلب مرة واحدة كل 15 دقائق. بعد ذلك، يتم تسجيل كل جهاز متبقي مرة أخرى (الخطوة 2).

ما لا يمكن للحساب الرئيسي فقط فعله تعمل بعض التغييرات على حماية بيانات اعتماد الحساب، لذلك فهي تتطلب جلسة تم تسجيل الدخول إليها من خلال موفر مثل Google أو GitHub:

فعل حساب مفتاح فقط
إضافة مفتاح أو إلغاء الأجهزة الأخرى (POST /me/public-keys, DELETE /me/public-keys/{id} أو /all) 403 — قم بالتسجيل من خلال التسجيل عبر البريد الإلكتروني، أو استخدم جلسة مصادقة OAuth
تغيير عنوان البريد الإلكتروني للحساب 403 oauth_session_required - غير ممكن حتى يتم ربط المزود
