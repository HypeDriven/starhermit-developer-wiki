إصدارات محرك StarHermit

محرك StarHermit — وقت التشغيل الذي يتم تشغيله العاب السيناريو - هو منشورة على هذا الويكي كإصدارات غير قابلة للتغيير ضمن wiki.starhermit.com/engine/. الألعاب دبوس إصدار واحد بالضبط مع engine.version في بهم starhermit.txt; يقوم عميل StarHermit Windows بتثبيت الإصدار أ يتم تثبيت اللعبة وتشغيلها عليها، ويقوم المطورون بتنزيل وقت تشغيل الإصدار من هنا للإنشاء مع.

الإصدارات

الافراج هو X.Y.Z. X هو الإصدار الرئيسي لواجهة برمجة التطبيقات المضيفة، ال engine.api تعلن لعبة، لذلك يتم تشغيل كل إصدار 1.x.x engine.api=1 ألعاب؛ يسجل الإصدار أيضًا الإصدار الثانوي لواجهة برمجة تطبيقات المضيف، الذي ينمو مع إضافة الأعضاء (يمكن أن تتطلب اللعبة عضوًا به engine.minor). بيان منشور لا يتغير أبدًا: الإصلاح هو الإصدار التالي.

يطلق واجهة برمجة تطبيقات المضيف أوقات التشغيل تحميل المطور
1.0.0 1.4 ويندوز (x86-64)؛ لا يوجد وقت تشغيل على شبكة الإنترنت ستارهيرميت-1.0.0-windows-x86_64.zip

versions.json هي القائمة الموثوقة، والأحدث أولاً، والمحرك تسرد الصفحة الخاصة بالمنطقة نفس الشيء.

منطقة المحرك

engine/
  versions.json            every release: host API, date, runtimes, revocation
  X.Y.Z/
    native/windows-x86_64/
      native.json          the Windows runtime's files, each with its size, SHA-256 and chunks
      starhermit-X.Y.Z-windows-x86_64.zip
                           the developer download: the same files as one archive
    manifest.json, starhermit.js, starhermit.wasm, ...
                           the web runtime, in a release that has one
  chunks/ab/<sha256>.z     pieces of the native files, shared by every release
  patches/ab/<sha256>.p    binary patches from earlier releases' files

يتم نشر كل ملف كما هو (لا يوجد اسم ملف يبدأ بـ _ أو .)، وتخدمها صفحات GitHub مع Access-Control-Allow-Origin: *.

versions.json

{
  "format": 2,
  "versions": [
    {
      "api": {"major": 1, "minor": 4},
      "date": "2026-10-20T12:49:23Z",
      "native": {
        "windows-x86_64": {"manifest": "1.0.0/native/windows-x86_64/native.json", "sha256": "<SHA-256 of native.json>"}
      },
      "revoked": false,
      "version": "1.0.0",
      "web": null
    }
  ]
}

web يكون {"manifest": "sha384-…"}، تجزئة SRI لموقع الويب الخاص بالإصدار manifest.json، أو null ل إصدار بدون وقت تشغيل الويب. native دبابيس كل منصة native.json بواسطة SHA-256. أ يقول الافراج عن سحب لأنه غير آمن "revoked": true مع أ "revokedReason"; هذا هو فقط قم بتغيير الإدخال المنشور على الإطلاق.

native.json

native.json يسرد ملفات مجلد المحرك الذي يقوم العميل بتثبيته - starhermit.exe, release.json (إصدار الإصدار، واجهة برمجة التطبيقات المضيفة و launcher البروتوكول يتحدث وقت التشغيل الخاص به) LICENSE-engine وإشعارات الطرف الثالث - لكل منها size, sha256 و chunks. قطعة عبارة عن امتداد لملف تم تخزينه بصيغة zlib المضغوطة chunks/<first two hex digits>/<sha256>.z واسمه بواسطة SHA-256 من وحدات البايت غير المضغوطة؛ حدود القطعة تتبع المحتوى، لذلك لم تتغير يحافظ التمدد على قطعته من إصدار إلى آخر. حيث أنه أصغر، يسرد الملف أيضا patches من نفس ملف الإصدارات السابقة ("from": SHA-256 للملف السابق). downloads يسرد تنزيل المطور مع ملف size و sha256; العملاء لا يقومون بتثبيته أبدًا.

نزاهة

تغطي سلسلة واحدة من التجزئة كل بايت يقوم العميل بتشغيله:

  1. versions.json (أو واجهة برمجة تطبيقات النظام الأساسي أدناه) تعطي SHA-256 للإصدار native.json.
  2. native.json يعطي SHA-256 لكل ملف وكل قطعة.
  3. يقوم العميل بجلب فقط القطع التي لا يحتفظ بها بالفعل، والتحقق من حجم كل منها المخزن، الحجم المضخم وSHA-256، يجمع كل ملف معًا، ويتحقق من SHA-256 الخاص بالملف وبعد ذلك فقط يتحرك الافراج في مكانه. يتم فحص التصحيح مقابل SHA-256 الخاص به، والملف المصحح مقابله الملف؛ أي فشل يعود إلى القطع.

تتم تغطية تنزيل المطور بنفس السلسلة من خلال إدخاله downloads. متصفح تقوم صفحة محمل اللعبة بتثبيت وقت تشغيل الويب starhermit.js و manifest.json مع تجزئات SRI، و يتحقق وقت التشغيل من كل ملف آخر يتم تحميله مقابل البيان.

يقوم المحرك بإصدار API

تخدم المنصة نفس القائمة، مع كل عنوان URL على هذا الويكي، لذلك يسأل العملاء واجهة برمجة التطبيقات عن المحرك لجلب:

GET /api/v1/engine/releases → كل إصدار، الأحدث أولاً:

{"releases": [{
  "version": "1.0.0", "api": {"major": 1, "minor": 4}, "revoked": false, "date": "2026-10-20T12:49:23Z",
  "web": null,
  "native": {"windows-x86_64": {
    "manifestUrl": "https://wiki.starhermit.com/engine/1.0.0/native/windows-x86_64/native.json",
    "manifestSha256": "<SHA-256 of native.json>"}}
}]}

GET /api/v1/engine/releases/{version} → إصدار واحد، أو 404 عندما لا يتم سردها. كلاهما مجهول وقابل للتخزين المؤقت (Cache-Control: public, max-age=60 مع ETag). إطلاق سراح ملغى يحمل revokedReason; web يكون {"base", "manifestIntegrity"} للإصدار مع وقت تشغيل الويب. على الرغم من أن النظام الأساسي لم يقرأ القائمة مطلقًا (تعذر الوصول إلى الويكي منذ بدايته) إلا أنهم يجيبون 503 مع Retry-After.

ألعاب السيناريو على المنصة

عندما جذر اللعبة starhermit.txt يعلن engine.version، تتعامل المنصة معه كبرنامج نصي لعبة:

  • يسجل كل نشر إصدار دبوس الملفات، مثل hosting.engineVersion، ومجموعات hosting.deployWarning (أيضًا في إجابة حزمة الدفع) عندما لا يكون هذا الإصدار مدرجًا أو يكون كذلك تم إبطاله. تحذير لا يتوقف أبدا عن النشر.
  • يتم تقديم كل صفحة من اللعبة المستضافة بسياسة أمان المحتوى التي تقبل البرامج النصية فقط من هذا الويكي (والمحرك الخاص به blob: العمال)، وبالتالي فإن الكود الوحيد الذي يمكن أن تكون عليه صفحة اللعبة النصية run هو المحرك الرسمي:
default-src 'self'; script-src https://wiki.starhermit.com 'wasm-unsafe-eval' blob:; worker-src blob:;
connect-src 'self' https://wiki.starhermit.com; img-src 'self' blob: data:; media-src 'self' blob:;
style-src 'self' 'unsafe-inline'; font-src 'self' https://wiki.starhermit.com;
frame-ancestors https://dashboard.starhermit.com; base-uri 'self'; form-action 'none'

صفحة من لعبة نصية بدون إنشاء متصفح (مثل الصفحة العادية التي يتم تحميلها بواسطة لعبة Windows فقط للمتصفحات) لا يحتاج إلى برنامج نصي ولا يتأثر.

الإلغاءات

يبقى الإصدار المُلغى مُدرجًا حتى يتمكن العملاء من تحديد سبب رفضهم له، وهو ما يفعله عميل StarHermit لا تقم بتثبيته أو تشغيله ويخبر اللاعب أن أوامر التغليف ترفض حزم اللعبة لها عندما يقرؤون versions.json، وتحذر المنصة أصحاب الألعاب من تثبيتها عند قيامهم بذلك نشر. أعد تثبيت الإصدار الذي يحل محله ثم قم بالنشر مرة أخرى (انظر الانتقال إلى محرك أحدث).
