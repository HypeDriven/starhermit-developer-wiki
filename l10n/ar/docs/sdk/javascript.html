JavaScript SDK (ألعاب المتصفح)

starhermit-sdk.js هو عميل ذو ملف واحد وخالي من التبعية لألعاب المتصفح نشرت على ستارهيرميت. فهو يقرأ رمز الإطلاق، ويبقيه متجددًا، ويوفر مساعدين للعامة واجهات برمجة التطبيقات لرموز الإطلاق على نطاق اللعبة: الهوية، وعمليات الحفظ السحابية، والإعدادات وعناصر التحكم لكل لاعب، الدعوات، التوفيق، الجلسات ومقبس اللعب، الإنجازات، المتصدرين، الإعادة، الدردشة، غرف الصوت والوقت الحقيقي.
ملف docs/sdk/starhermit-sdk.js - انسخه في لعبتك دون تغيير
عالمي window.StarHermit (أيضًا module.exports ضمن العقدة، للاختبارات)
التبعيات لا شيء - فهو يستخدم المتصفح الخاص به fetch, WebSocket و (لقراءة الحفظ المضغوط) DecompressionStream
خط الأساس لواجهة برمجة التطبيقات (API). REST v1 وWebSocket v1، سطح رمز الإطلاق فقط

إن SDK هو عميل، وليس تطبيقًا ثانيًا للنظام الأساسي. النتائج والإنجاز يفتح تتم كتابتها فقط بواسطة خادم اللعبة (نتيجة البرنامج النصي أو رسالة التحكم في الحاوية) - العميل لا يمكن أبدًا نشرها، ويقرأها SDK فقط. ويظل كل شيء آخر خاضعًا لسلطة الخادم تماما كما هو موثق في صفحات API.

لا يقوم المساعدون المعتمدون بتقديم أي طلبات لواجهة برمجة التطبيقات (API) بدون رمز إطلاق مميز. يقرأ حل عموما ل null, []أو خريطة فارغة؛ قد يكتب حل null/false والتصديات المرتدة ليس لها أي تأثير فوري قيمة الإرجاع. يبقى المقبس منفصلاً. احتفظ بالتقدم المستقل في الذاكرة إذا اختار اللاعب ذلك اللعب غير المتعقب. يتصل signOut() قبل التبديل من تشغيل الحساب إلى هذا الوضع حتى يتوقف التجديد.

ثَبَّتَ

انسخ الملف الموجود بجوار البرامج النصية الثابتة الأخرى للعبتك — أينما يشحنها الإصدار الخاص بك — وقم بتحميله قبل الكود الخاص بك:

<script src="starhermit-sdk.js"></script>
<script>
  StarHermit.init();          // as early as possible: it reads and strips the token from the URL fragment
</script>

يتصل init() مرة واحدة، قبل أن يلمس أي جهاز توجيه location.hash. خيارات: init({ base, gameId, autoRefresh, launcherUrl }) — base نقاط مكالمات REST من أصل معتمد أثناء التطوير المحلي (تستخدم الألعاب التي تستضيفها المنصة نفس الأصل). gameId، إذا تم توفيره، يجب أن يتطابق UUID المستضاف لتسجيل الدخول؛ الصفحات المحلية/الخارجية ليست أصولًا صالحة لتسجيل الدخول إلى اللعبة. autoRefresh: false يترك التجديد الرمزي للعبة تدير سلسلتها الخاصة، و launcherUrl يتجاوز حيث relaunch() يرسل اللاعب (افتراضي https://dashboard.starhermit.com/).

تسجيل الدخول والهوية

يحتاج يتصل
هل قام اللاعب بتسجيل الدخول؟ StarHermit.signedIn, StarHermit.userId, StarHermit.slug
الرد على تسجيل الدخول / تسجيل الخروج / انتهاء الصلاحية StarHermit.on('auth', ({ signedIn, reason }) => …)
عرض أ تسجيل الدخول زر فقط عندما StarHermit.canSignIn() (صحيح على نطاق فرعي للعبة UUID بدون رمز مميز)؛ عند النقر StarHermit.signIn()
اسم اللاعب/الصورة الرمزية await StarHermit.profile() → { userId, username, nickname, displayName }; StarHermit.avatarUrl()
أصدقاء await StarHermit.friends()

يتعامل SDK مع كلا شكلي الإطلاق — #game_token=<jwt>[&session_id=…] من المكتبة أو دعوة، و #access_token=<jwt> العودة من تسجيل الدخول المباشر - وتجديد الرمز المميز من خلال POST /api/v1/games/{slug}/launch-token قبل انتهاء صلاحيته (انظر إطلاق الرموز). اسم العرض هو الملف الشخصي nickname; /api/v1/me ليس كذلك يمكن الوصول إليها باستخدام رمز الإطلاق.

الحفظ السحابي

فتحة اللعبة هي game:<slug> (الكتالوج: الحفظ من داخل اللعبة); SDK يبني المسار، ويضغط الحمولة، ويتعامل مع ملف /info يفحص.

const remote = await StarHermit.loadJSON();          // null: empty slot, signed out — or a failed read
if (StarHermit.saveLoadFailed()) showSyncError();    // tell those apart when it matters
else if (remote && isNewer(remote, local)) adopt(remote);

StarHermit.saveJSON(state);                          // debounced (2 s) checkpoint upload
addEventListener('pagehide', () => StarHermit.flushSave(true));   // keepalive flush
StarHermit.on('saved', ok => setSyncIndicator(ok));

قم بالتحميل قبل الحفظ. قارن واعتمد النسخة السحابية قبل أي كتابة يمكن أن تصل saveJSON - بما في ذلك الإعدادات أو اللقب أو نقاط التفتيش التي يتم كتابتها عند التمهيد - أو يمكن الحصول على نسخة محلية قديمة الكتابة فوق عملية الحفظ الأحدث التي تم إجراؤها على جهاز آخر. قم بالحفظ المبكر حتى يستقر حمل بدء التشغيل.

يحمي SDK النصف الآخر من هذا السباق: عندما تفشل القراءة (خطأ في الشبكة أو الخادم، كما مقابل فتحة فارغة) فإنه يحدد saveLoadFailed()، ينبعث saveerror، ويرفض يكتب حتى /info يؤكد أن الفتحة فارغة أو أحدث loadSave() ينجح. تم حل مشكلة الكتابة المرفوضة false وتنبعث saved مع false.

يكتب بعد التحميل مشروطة. يتذكر SDK الإصدار (ETag) لحفظه أخيرًا اقرأها أو كتبتها وأرسلها مرة أخرى، لذا فإن الكتابة تتوقف فقط على الحفظ الذي كانت مبنية عليه - أو في فتحة كان ذلك فارغًا، فقط بينما لا يزال كذلك. عندما يتم حفظ جهاز آخر بينهما، يتم رفض الكتابة (412): تنبعث SDK saveconflict، مجموعات saveConflicted()، ويرفض المزيد من الكتابة حتى أ loadSave() يتيح دمج اللعبة أو اعتماد الحفظ الأحدث. لعبة لا يتم تحميلها أبدًا دون قيد أو شرط، كما كان من قبل.

StarHermit.on('saveconflict', async () => {
  const remote = await StarHermit.loadJSON();       // lifts the block
  StarHermit.saveJSON(merge(remote, local));        // conditional on the version just loaded
});

المستوى الأدنى: loadSave() / writeSave(text) للسلاسل الخام، saveInfo() ل { exists, sizeBytes, updatedAt, etag }.

تقارير الأعطال والأخطاء

يمكن للاعبين الإبلاغ عن المشاكل من داخل اللعبة؛ يقوم المالك بفرزهم من خلال تقارير API.

await StarHermit.reportBug('Score did not save', 'Finished level 3, score shows 0', {
  clientVersion: '1.4.2',
  attachments: [{ fileName: 'state.json', contentType: 'application/json', data: JSON.stringify(state) }],
});
StarHermit.captureCrashes({ clientVersion: '1.4.2' });   // opt-in: uncaught errors become crash reports
const mine = await StarHermit.myReports();               // [{ id, kind, status, title, ... }]

report(kind, title, description, opts) هو الشكل العام (reportBug و reportCrash إصلاح النوع). captureCrashes ملفات بحد أقصى تقرير واحد لكل رسالة مميزة وثلاثة لكل تحميل صفحة، لذلك أ لا يمكن أن تستهلك حلقة التعطل البدل اليومي للاعب (20 لكل لعبة بشكل افتراضي). اسأل اللاعب من قبل إرفاق أي شيء شخصي.

الإعدادات والضوابط

يحتاج يتصل
تفضيلات كل لاعب (مستوى الصوت، الرسومات المحددة مسبقًا، اللغة، إمكانية الوصول...) getSettings(), getSetting(key), setSetting(key, value), patchSettings({…}) (a null القيمة تزيل المفتاح)، deleteSetting(key), clearSettings()
تم الإعلان عن ارتباطات لوحة المفاتيح في starhermit.txt مثل control.<action>=… await loadBindings(defaults) → { action: codes[] } مع تطبيق تجاوزات اللاعب
شاشة إعادة الربط getControls(), setControl(action, codes), setControls(bindings), resetControls()

طريق keydown خلال event.code والروابط من loadBindings. يرى أضف عناصر التحكم إلى لعبتك و starhermit.txt يظهر.

للحصول على قائمة الرسومات، graphics-options.js يجلس على رأس مكالمات الإعدادات: فهو يكتشف تلقائيًا إعدادًا مسبقًا للجودة، ويحتفظ باختيار اللاعب localStorage ولكل لعبة الإعدادات، ويشحن لوحة جاهزة. يرى خيارات الرسومات ذات الجودة المكتشفة تلقائيًا.

للحصول على قسم الصوت، راجع خيارات الصوت مع حد الصوت الذي يتم اكتشافه تلقائيًا: مستوى الصوت الموصى به وضوابط الصوت، النقي audio-options.js مساعدين, وغطاء التشغيل الذي يفرضه الخلاط الخاص بك.

للحصول على قسم اللغة، راجع توطين لعبتك وإضافة إعدادات اللغة: حزم ترجمة بعشر لغات، وأعلام SVG، وتخطيطات من اليمين إلى اليسار، و ui.language التفضيل محفوظ مع إعدادات اللعبة. يستخدم api() عندما تحتاج إلى إظهار إعدادات القراءة/الكتابة الفاشلة.

متعددة اللاعبين والدعوات والاجتماعية

تحتاج جلسة اللعب والتوفيق وإنجازات اللعبة ولوحات المتصدرين والإعادة إلى خادم (script أو حاوية). غرف الوقت الحقيقي و الأصدقاء لا. تحتاج جلسة الدردشة والصوت إلى عضوية المحادثة المقابلة.

منطقة المكالمات
الجلسات mySessions(), getSession(id), sessionRecovery(id), leaveSession(id), startAiSession(); StarHermit.launchSessionId بعد إطلاق الدعوة
مقبس اللعب const conn = connect(sessionId, { onGame, onError, onPresence, onAchievement, onResumed, onAbandoned, onOpen, onClose, onAuthLost })، ثم conn.send(data); يعيد الاتصال بالتراجع، ويجدد الرمز المميز أولاً، ويتوقف عند الإغلاق العادي/السياسة/الكبير الحجم (1000/1008/1009)، أو 4403/4404، أو عند رفض التجديد (راجع إعادة الاتصال)
التوفيق بين queues(), joinQueue([keys]), matchStatus(), cancelMatch(), waitForMatch(opts)
يدعو sendInvite(toUserId[, sessionId]) (مع أ sessionId ينضم الصديق إلى جلسة التشغيل تلك)، invites(), acceptInvite(id), declineInvite(id); inviteLink(query) للحصول على رابط المشاركة
أضف جولة إلى المتصدرين الخاصة بك submitScores({ boardKey: number }) → المفاتيح المقبولة (انظر لوحات المتصدرين للاعب واحد)
الإنجازات والمتصدرين (للقراءة فقط) achievements(), linkedAchievements(otherSlug), leaderboards(), leaderboard(key, opts), leaderboardEntries(boardId, opts); فتح الخبز المحمص عبر on('achievement', …)
الاعادة myReplays(limit), getReplay(id)
دردشة الجلسة chatMessages(id), sendChat(id, text), pollChat(id, onMessages, intervalMs) — REST والاستطلاع فقط لرموز الإطلاق
غرف الصوت / الوقت الحقيقي StarHermit.voice.* (REST؛ يتم ترك إشارات WebRTC للعبة)، StarHermit.realtime.* (غرف زائد ws/v1/realtime)

أي شيء غير ملفوف هو مكالمة واحدة بعيدا: StarHermit.api(path, { method, body }) يرسل طلب JSON المصادق عليه (يحل null على 404/204 أو عند تسجيل الخروج، يرفض { status, message } وفي حالات الفشل الأخرى، يتم تجديده مرة واحدة في 401).

لوحات المتصدرين للاعب الفردي

لا يمكن للعميل أبدًا نشر نتيجة - فقط خادم اللعبة يمكنه ذلك - لذا تحتاج لعبة اللاعب الفردي إلى منصة نصية صغيرة لامتلاك لوحاتها. score-script.js هو واحد: نسخه المقبل إلى لعبتك، أعلن عنها starhermit.txt مثل server=score-script.js، و تحرير فقط لها BOARDS كتلة، والتي تسرد كل لوحة باسمك إنشائه:

var BOARDS = {
  "high-score": { "name": "High score", "scoreType": "integer", "sortDirection": "desc", "minScore": 0, "maxScore": 1000000 }
};

عندما تنتهي الجولة، انشرها وأظهر مكان اللاعب:

const accepted = await StarHermit.submitScores({ 'high-score': total });   // [] when signed out or refused
if (accepted.includes('high-score')) {
  const board = await StarHermit.leaderboard('high-score', { pageSize: 100 });
  const me = board.items.find(e => e.userId === StarHermit.userId);
  showRank(me && me.rank);
}

submitScores يفتح جلسة تدريب (POST .../sessions/ai)، يرسل {type:'result', scores} على مقبس اللعب، ويحل مفاتيح اللوحة التي يقبلها البرنامج النصي؛ تنبعث أيضًا scores مع تلك القائمة. يسقط البرنامج النصي نتيجة ليست رقمًا من نوع اللوحة أو تقع خارج نطاقها minScore/maxScore، ينشر الباقي من خلاله scores العودة، وإنهاء الجلسة. العميل لا تزال تقارير النتيجة. يمكن أن تمر نتيجة مخترعة داخل النطاق؛ هذه المجالس مناسبة للمناسبات غير الرسمية لعب. بالنسبة للمنافسة، تحقق من صحة التشغيل في البرنامج النصي أو الحاوية قبل منحها. الإقرار يسرد المفاتيح المقبولة للبرنامج النصي؛ هذا ليس دليلاً على أن كل لوحة كانت نشطة أو أن أفضل شخصية جديدة تم تخزينه. يرى الثقة والتوافر.

إعادة الاتصال والرموز منتهية الصلاحية

يحمل المقبس رمز الإطلاق المميز في عنوان URL الخاص به، ويتم رفض المصافحة برمز منتهي الصلاحية من قبل الترقية - يُبلغ المتصفح عن رمز الإغلاق فقط 1006، تمامًا مثل انخفاض الشبكة. لذلك فشل قد تكون إعادة الاتصال بمثابة فشل في المصادقة، ولا يمكن استرداد محاولة إعادة محاولة نفس عنوان URL أبدًا. التجديد يعمل فقط في حين أن الرمز الحالي صالح وفي غضون 12 ساعة من الإطلاق الأصلي؛ بعد ذلك فقط يستطيع المشغل سك رمزًا مميزًا جديدًا.

connect() يتعامل مع هذا بنفسه: قبل كل عملية إعادة اتصال، يقوم بتجديد الرمز المميز من خلال POST /api/v1/games/{slug}/launch-token (ما لم يتم تجديده منذ فتح المقبس) ويعاد فتحه مع الجديد. خطأ في الشبكة أو الخادم أثناء التجديد يتراجع ويتجدد مرة أخرى - لا يحدث ذلك أبدًا يعيد فتح عنوان URL القديم. عند رفض التجديد أو انتهاء صلاحية الرمز المميز، يقوم SDK بتسجيل الخروج (auth مع reason: 'expired')، يتوقف عن إعادة الاتصال والمكالمات onAuthLost():

const conn = StarHermit.connect(sessionId, {
  onGame, onClose,
  onAuthLost: () => showReconnectPanel(),   // e.g. "Session expired — Back to StarHermit"
});
backButton.onclick = () => StarHermit.relaunch();

relaunch() يرسل اللاعب مرة أخرى للحصول على رمز إطلاق جديد: من خلال تسجيل الدخول عند فتح اللعبة بهذه الطريقة (StarHermit.launchKind === 'sign-in')، وإلا إلى المشغل. داخل قاذفة إطار اللعبة يتنقل في النافذة العلوية، والتي تسمح بها المتصفحات فقط من خلال إيماءة المستخدم، لذلك نسميها من نقرة يعود false عندما تم رفض الملاحة.

يمكن للمتصفح إخفاء الجلسة النهائية أو الشروط أو العضوية أو فشل الإنشاء كما هو موضح 1006. قبل إعادة المحاولة التلقائية، connect() يتحقق من حالة الجلسة من خلال REST ومتى opts.build يتم توفيره، ومقارنتها بمعلومات اللعبة onUnavailable(error) يتلقى فشل REST دائم أو انتهى جلسة؛ onTermsRequired(body) يطلب قبول الشروط الصريحة. إنشاء اتصال جديد بعد حل هذه. onClose(1008) يعني أن الاتصال قد تم إبطاله أو انتهاك السياسة؛ لا تفعل ذلك إعادة فتحه تلقائيًا.

مآخذ توصيل لعبتك تفتح نفسها (realtime.socketUrl(roomId), voice.socketUrl(roomId)) بحاجة إلى نفس القاعدة. قبل إعادة فتح واحدة، اتصل renewForReconnect() والعمل على نتيجته:

async function reopen() {
  const r = await StarHermit.renewForReconnect();
  if (r === 'renewed') ws = new WebSocket(StarHermit.realtime.socketUrl(roomId)); // fresh token in the URL
  else if (r === 'retry') setTimeout(reopen, backoff());                         // renewal itself failed
  else if (r === 'terms-required') showTermsPanel();                              // explicit acceptance
  else showReconnectPanel();                                                     // 'relaunch'
}

التجديدات المتزامنة تشترك في طلب واحد. terms-required يحافظ على رمز اللاعب وينبعث termsrequired; عرض getTerms() واتصل acceptTerms(displayed.hash) فقط على اللاعب قم بقبول الإجراء، ثم أعد المحاولة. تحتاج المقابس التي تديرها لعبتك أيضًا إلى عمليات فحص REST للموارد المنتهية ويجب أن يتوقف عند إغلاق السياسة. يرى استكشاف الأخطاء وإصلاحها.

الأحداث

StarHermit.on(type, fn) إرجاع وظيفة إلغاء الاشتراك؛ off(type, fn) يعمل أيضا.

حدث الحمولة
auth { signedIn, userId } عند تسجيل الدخول؛ { signedIn: false, reason } عند تسجيل الخروج أو انتهاء الصلاحية (reason: 'expired' عند رفض التجديد — العرض relaunch())
saved true / false بعد كل سحابة الكتابة
saveerror { op: 'load' } بعد قراءة فاشلة؛ { op: 'write', blocked: true } لرفض الكتابة
achievement تم فتح القفل على مقبس اللعب
scores مفاتيح اللوحة مقبولة من قبل submitScores ([] عندما لم يتم نشر أي شيء)
saveconflict { etag } عندما يقوم جهاز آخر بتغيير الحفظ؛ إعادة التحميل قبل الدمج/الحفظ
termsrequired خطأ الشروط الذي تم إرجاعه من خلال تجديد رمز الإطلاق؛ الحفاظ على الرمز المميز وطلب الموافقة

الحفاظ على نسختك الحالية

تعامل مع الملف باعتباره بائعًا: انسخه دون تغيير، ولا تقم بتحرير نسختك أبدًا، واستبدله بالجملة عندما يتغير ملف هذه الصفحة. تأكد من أن خطوة البناء أو التغليف الخاصة بك تشحنها جنبًا إلى جنب مع اللعبة ملفات ثابتة أخرى.
