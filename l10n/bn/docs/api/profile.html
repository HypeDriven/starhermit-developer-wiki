প্রোফাইল

প্রোফাইল API প্রমাণীকৃত ব্যবহারকারীর নিজের অ্যাকাউন্টকে কভার করে (/api/v1/me/...), অন্যান্য ব্যবহারকারীদের সর্বজনীন অনুসন্ধান, সর্বজনীন কী, লিঙ্কযুক্ত পরিচয়, গোপনীয়তা সেটিংস, এনটাইটেলমেন্ট এবং উপস্থিতি হার্টবিট। অ্যাকাউন্ট রুট অনুমোদন প্রয়োজন; বর্তমান শর্তাবলী নথি সর্বজনীন.

ত্রুটি সংস্থাগুলি পরিবর্তিত হয়; দেখুন এপিআই কনভেনশন.

শেষবিন্দু

পদ্ধতি পথ প্রমাণ বর্ণনা
পান /api/v1/me JWT (Permission-user.profile.read) আপনার নিজের প্রোফাইল পান
প্যাচ /api/v1/me JWT (Permission-user.profile.update) ব্যবহারকারীর নাম, ইমেল, মেটাডেটা বা ডাকনাম আপডেট করুন
পান /api/v1/terms বেনামী বর্তমান StarHermit শর্তাবলী এবং তাদের হ্যাশ পড়ুন
পোস্ট /api/v1/me/terms/accept অ্যাকাউন্ট JWT বা প্লেয়ার লঞ্চ টোকেন বর্তমান StarHermit শর্তাবলী গ্রহণ করুন
PUT /api/v1/me/avatar JWT (Permission-user.profile.update) আপনার অবতার আপলোড করুন
পান /api/v1/me/avatar JWT (Permission-user.profile.read) আপনার অবতার পান
পান /api/v1/users/{id}/avatar জেডব্লিউটি যেকোনো ব্যবহারকারীর অবতার পান
পান /api/v1/users/{id}/profile জেডব্লিউটি যেকোনো ব্যবহারকারীর পাবলিক প্রোফাইল পান
পান /api/v1/me/public-keys JWT (Permission-user.profile.read) আপনার সর্বজনীন কী তালিকাভুক্ত করুন
পোস্ট /api/v1/me/public-keys OAuth-প্রমাণিত JWT (Permission-user.profile.update) অবিলম্বে একটি সর্বজনীন কী যোগ করুন
মুছুন /api/v1/me/public-keys/{keyId} OAuth-প্রমাণিত JWT (Permission-user.profile.update) একটি কী এবং এর সেশন প্রত্যাহার করুন
মুছুন /api/v1/me/public-keys/all OAuth-প্রমাণিত JWT (Permission-user.profile.update) প্রতিটি সক্রিয় কী এবং এর সেশন প্রত্যাহার করুন
মুছুন /api/v1/me/public-keys/current সর্বজনীন-কী অধিবেশন (Permission-user.profile.update) এই সেশনের সাথে সাইন ইন করা কী এবং এর সেশনগুলি প্রত্যাহার করুন৷ এটি কোন চাবির নাম দেয় না, তাই এটি একটি ভাইবোনের কাছে পৌঁছাতে পারে না; কোন চাবি ছাড়া একটি অধিবেশন 409 no_public_key_session
পান /api/v1/me/identities JWT (Permission-user.profile.read) আপনার লিঙ্কযুক্ত পরিচয় তালিকাভুক্ত করুন
পোস্ট /api/v1/me/identities JWT (Permission-user.profile.update) একটি পরিচয় লিঙ্ক করুন (শুধুমাত্র OAuth প্রদানকারী নয়)
মুছুন /api/v1/me/identities/{identityId} JWT (Permission-user.profile.update) একটি পরিচয় লিঙ্কমুক্ত করুন
পান /api/v1/me/privacy JWT (Permission-user.profile.read) আপনার গোপনীয়তা সেটিংস পান
PUT /api/v1/me/privacy JWT (Permission-user.profile.update) আপনার গোপনীয়তা সেটিংস প্রতিস্থাপন করুন
পান /api/v1/me/entitlements JWT (Permission-user.profile.read) আপনার সফ্টওয়্যার এনটাইটেলমেন্ট তালিকা
পোস্ট /api/v1/me/heartbeat জেডব্লিউটি উপস্থিতি হার্টবিট (থ্রটলড LastSeenAt লিখুন)

PATCH /api/v1/me

সমস্ত ক্ষেত্র ঐচ্ছিক। সীমাবদ্ধতা: username 1-32 অক্ষর; nickname ≤64 অক্ষর (অনেক অ্যাকাউন্ট নেই); metadata ≤4096 অক্ষর। ব্যবহারকারীর নাম এবং ডাকনাম এক ভাগ কেস-সংবেদনশীল নামস্থান: 409 যখন অন্য একটি অ্যাকাউন্ট তার ব্যবহারকারীর নাম বা ডাকনাম হিসাবে নাম ব্যবহার করে, মামলা উপেক্ষা। ডাকনাম হল NFKC-স্বাভাবিক, এবং নিয়ন্ত্রণ বা অদৃশ্য অক্ষর 400. পরিবর্তন হচ্ছে email উপরন্তু একটি প্রয়োজন OAuth-প্রমাণিত সেশন কারণ অ্যাকাউন্ট ইমেল শংসাপত্রের লিঙ্কগুলি অনুমোদন করতে পারে; একটি পাবলিক-কী বা ইমেল-যাচাই সেশন পায় 403 সেই ক্ষেত্রের জন্য কিন্তু এখনও অন্যদের আপডেট করতে পারে। 204 রিটার্ন করে সাফল্য, দ্বন্দ্বে 409 (ব্যবহারকারীর নাম বা ডাকনাম ইতিমধ্যে নেওয়া হয়েছে)।

{
  "username": "newname",
  "email": "new@example.com",
  "metadata": "{}",
  "nickname": "New Nick"
}

শর্তাবলী গ্রহণ

সুরক্ষিত REST এন্ডপয়েন্ট ব্যবহার করার আগে বা WebSockets খোলার আগে, অ্যাকাউন্টটি অবশ্যই গ্রহণ করবে বর্তমান StarHermit শর্তাবলী. এটি অ্যাকাউন্ট টোকেন এবং প্লেয়ার লঞ্চ টোকেনগুলির ক্ষেত্রে প্রযোজ্য, অ্যাকাউন্টগুলি সহ একটি পুরানো সংশোধন গ্রহণ. এটি বেনামী সম্পদ/সাইন-ইন বা একটি কন্টেইনার সার্ভারের ক্ষেত্রে প্রযোজ্য নয় নিজস্ব স্থাপনার টোকেন। GET /api/v1/me এবং গ্রহণযোগ্যতা শেষবিন্দু তাদের স্বাভাবিকের সাথে উপলব্ধ থাকে স্বীকৃতি মুলতুবি থাকাকালীন অ্যাকাউন্ট অনুমতি।

GET /api/v1/me অন্তর্ভুক্ত currentTermsHash এবং termsAcceptanceRequired. সঞ্চিত termsAcceptedHash এবং termsAcceptedAt প্রথম গ্রহণের আগে শূন্য। হ্যাশ দেখানো হয়েছে উপরে প্রোফাইল উদাহরণ সংক্ষিপ্ত করা হয়; সর্বদা API দ্বারা প্রত্যাবর্তিত সম্পূর্ণ হ্যাশ ব্যবহার করুন।

GET /api/v1/terms

বেনামী; এছাড়াও একটি প্লেয়ার লঞ্চ টোকেন সহ পঠনযোগ্য। রিটার্নস 200 সঙ্গে Cache-Control: no-store:

{ "hash": "<current-64-character-lowercase-sha256>", "text": "<complete terms text>" }

রেন্ডার text প্লেইন টেক্সট হিসাবে। hash সঠিক UTF-8 নথি বাইটের SHA-256; ফেরত ব্যবহার করুন রিফরম্যাট করা ডিসপ্লে টেক্সট হ্যাশ করার পরিবর্তে মান।

POST /api/v1/me/terms/accept

ব্যবহারকারী প্রদর্শিত রিভিশনটি পড়ার এবং স্পষ্টভাবে গ্রহণ করার পরে, এর হ্যাশ পাঠান:

POST /api/v1/me/terms/accept
Authorization: Bearer <account-access-token>
Content-Type: application/json

{ "hash": "<hash-returned-with-the-displayed-text>" }

রিটার্নস 200 সঙ্গে { "termsAcceptedHash", "termsAcceptedAt" }. OAuth এবং পাবলিক-কী অ্যাকাউন্ট সেশন এবং প্লেয়ার গেম-স্কোপড লঞ্চ টোকেন গ্রহণ করতে পারে। একটি ধারক সার্ভার টোকেন একটি প্লেয়ার জন্য কাজ করতে পারে না. গ্রহণযোগ্যতা অ্যাকাউন্টে সংরক্ষণ করা হয় এবং এর উপর কার্যকর হয় একই স্থির-বৈধ টোকেন সহ পরবর্তী অনুরোধ; টোকেন রিফ্রেশ করা অপ্রয়োজনীয়।

একটি অনুপস্থিত/ফাঁকা হ্যাশ বা 64 অক্ষরের চেয়ে দীর্ঘ একটি ফিরে আসে 400. একটি হ্যাশ যে ঠিক না বর্তমান রিভিশন রিটার্নের সাথে মেলে 409:

{
  "error": "terms_version_mismatch",
  "termsHash": "<current-hash>",
  "termsUrl": "/api/v1/terms"
}

নতুন নথি আনুন এবং প্রদর্শন করুন এবং আবার গ্রহণের জন্য জিজ্ঞাসা করুন; নীরবে একটি প্রতিস্থাপন গ্রহণ করবেন না পুনর্বিবেচনা মুলতুবি গ্রহণযোগ্যতা রিটার্ন সহ অন্যান্য সুরক্ষিত অনুরোধ 403:

{
  "error": "terms_acceptance_required",
  "message": "Accept the latest terms of service before using the API.",
  "termsHash": "<current-hash>",
  "termsUrl": "/api/v1/terms",
  "acceptUrl": "/api/v1/me/terms/accept"
}

একটি হোস্ট করা গেম শর্তাবলী প্রদর্শন করতে পারে এবং তার প্লেয়ার লঞ্চ টোকেন সহ প্রদর্শিত হ্যাশ জমা দিতে পারে যখন প্লেয়ার Accept চাপে, তারপর আবার চেষ্টা করুন। এটি প্লেয়ারকে তাদের অ্যাকাউন্ট UI এও পাঠাতে পারে। বারবার সাইন-ইন বা টোকেন রিফ্রেশ মুলতুবি গ্রহণযোগ্যতা ঠিক করে না। WebSocket আপগ্রেড HTTP এর সাথে প্রত্যাখ্যান করা হয়েছে 403 খোলার আগে; ব্রাউজার রেসপন্স বডি লুকিয়ে রাখতে পারে, তাই সংযোগ করার আগে REST এর মাধ্যমে গ্রহণযোগ্যতা পরিচালনা করুন।

একটি অ্যাকাউন্ট বা গেম ক্লায়েন্টের উদাহরণ (কল acceptDisplayedTerms শুধুমাত্র ব্যবহারকারীর অ্যাকসেপ্ট অ্যাকশন থেকে):

const api = 'https://api.starhermit.com';
async function loadTerms() {
  const response = await fetch(`${api}/api/v1/terms`);
  if (!response.ok) throw new Error(`Terms fetch failed: ${response.status}`);
  return response.json(); // Display text, retain this document's hash.
}
async function acceptDisplayedTerms(accountToken, displayedTerms) {
  const response = await fetch(`${api}/api/v1/me/terms/accept`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${accountToken}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ hash: displayedTerms.hash })
  });
  if (response.status === 409) {
    throw new Error('Terms changed. Reload and display them for a new acceptance.');
  }
  if (!response.ok) throw new Error(`Acceptance failed: ${response.status}`);
  return response.json();
}

পাবলিক কী

একটি নিবন্ধিত কী একটি API শংসাপত্র: এর ধারক সম্পূর্ণ করতে পারে পাবলিক-কী চ্যালেঞ্জ প্রবাহ এবং একটি সাধারণ অ্যাক্সেস/রিফ্রেশ-টোকেন পান জোড়া এটি একটি পৃথকভাবে লেবেলযুক্ত কী একটি ডেস্কটপ ক্লায়েন্ট বা স্থাপনার পাইপলাইনের জন্য উপযুক্ত করে তোলে।

কী যোগ করা বা অন্যান্য কী প্রত্যাহার করার জন্য একটি OAuth-প্রমাণিত সেশন প্রয়োজন। একটি পাবলিক-কী অধিবেশন শুধুমাত্র এর নিজস্ব কী প্রত্যাহার করতে পারে DELETE /api/v1/me/public-keys/current. এটা পারে না প্রতিস্থাপন তালিকাভুক্ত করুন বা অন্যান্য ডিভাইস প্রত্যাহার করুন। তালিকা যেকোন সম্পূর্ণ অ্যাকাউন্ট সেশনে উপলব্ধ থাকে; গেম লঞ্চ এবং সার্ভার টোকেন অ্যাকাউন্ট কী পরিচালনা করতে পারে না।

POST /api/v1/me/public-keys

একটি OAuth-প্রমাণিত সেশন প্রয়োজন এবং অবিলম্বে কী সংযুক্ত করে; বেনামী থেকে ভিন্ন নিবন্ধন, কোন ইমেল রাউন্ড ট্রিপ প্রয়োজন নেই.

{
  "keyType": "Ed25519",
  "keyData": "<base64-raw-32-byte-public-key>",
  "label": "orbit-league-production"
}

label ঐচ্ছিক (সর্বোচ্চ 128 অক্ষর)। গৃহীত কী ধরনের হয় Ed25519, ECDSA-P256, এবং RSA-PSS; উপাদান অবশ্যই আদর্শ বেস64 হতে হবে: Ed25519 এর জন্য একটি কাঁচা 32-বাইট পাবলিক কী, একটি এনকোড করা P-256 ECDSA-এর জন্য কার্ভ পয়েন্ট বা RSA-এর জন্য একটি পাবলিক SPKI। RSA কী 2048-8192 বিট হতে হবে। প্ল্যাটফর্ম বৈধ উপাদানকে ক্যানোনিকালাইজ করে এবং ডিফল্টরূপে একটি অ্যাকাউন্টকে 20টি সক্রিয় কীগুলিতে সীমাবদ্ধ করে। fingerprint হয় ক্যানোনিকালের ছোট হাতের SHA-256 হেক্স ডাইজেস্ট keyType:keyData স্ট্রিং

রিটার্নস 201 তৈরি কী দিয়ে। অবৈধ উপাদান রিটার্ন 400; একটি ইতিমধ্যে সক্রিয় কী বা একটি সম্পূর্ণ কী তালিকা ফেরত দেয় 409 (পরেরটি অন্তর্ভুক্ত limit) সক্রিয় কী উপাদান অনন্য প্ল্যাটফর্ম-ব্যাপী।

DELETE /api/v1/me/public-keys/{keyId}

একটি OAuth-প্রমাণিত সেশন প্রয়োজন। প্রত্যাহার অদম্য এবং রিফ্রেশ সেশন মিন্টেড শেষ হয় চাবি দ্বারা; অ্যাক্সেস টোকেন নামকরণ তাদের পরবর্তী অনুরোধে প্রত্যাখ্যান করা হয়. রিটার্ন:

{ "revoked": [{ "id": "...", "isRevoked": true }], "sessionsEnded": 1 }

এই অ্যাকাউন্টে একটি অজানা কী ফিরে আসে 404.

DELETE /api/v1/me/public-keys/all

আপস-প্রতিক্রিয়া অপারেশন: প্রতিটি সক্রিয় কী প্রত্যাহার করুন এবং তাদের প্রমাণীকৃত সমস্ত সেশন শেষ করুন। এটি একটি সুস্পষ্ট আছে /all পথ যাতে দুর্ঘটনাক্রমে খালি কী আইডি বাল্ক প্রত্যাহার হতে পারে না। একই রিটার্ন { revoked, sessionsEnded } আকৃতি

DELETE /api/v1/me/public-keys/current

একটি পাবলিক কী দিয়ে প্রমাণীকৃত একটি সম্পূর্ণ অ্যাকাউন্ট সেশন সেই সেশনের জন্য ব্যবহৃত কী প্রত্যাহার করতে পারে, একটি কী আইডি নামকরণ ছাড়া। এই জন্য ব্যবহার করুন এই ডিভাইসটি ভুলে যান. এটা একই রিটার্ন { revoked, sessionsEnded } সেই কী ব্যবহার করে সেশনগুলিকে আকার দেয় এবং অবৈধ করে। সঞ্চিত টোকেন বাতিল করুন এবং সাফল্যের পরে স্থানীয় ব্যক্তিগত কী। কোন পাবলিক কী রিটার্ন ছাড়া একটি অধিবেশন 409 সঙ্গে code: "no_public_key_session"; গেম লঞ্চ টোকেন প্রত্যাখ্যান করা হয়.

একটি সম্পূর্ণ মেশিন-ডিপ্লয়মেন্ট উদাহরণের জন্য, দেখুন একটি OAuth-ভুক্ত পাবলিক কী সহ CI/CD থেকে বিল্ড আপলোড করুন.
