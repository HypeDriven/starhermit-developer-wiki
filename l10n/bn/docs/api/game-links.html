বাহ্যিক লিঙ্ক

একটি StarHermit-ইঞ্জিন গেম (হোস্ট API 1.24) একটি ওয়েব পেজ খুলতে পারে, তবে শুধুমাত্র একটি স্টারহার্মিট স্টাফ আপনার খেলার জন্য অনুমোদিত হয়েছে. আপনার গেম আইডি দ্বারা একটি লিঙ্ক খোলে এবং কখনও একটি URL পাস করে না, তাই এটি যোগ করতে পারে না একজনের কাছে কিছু

আপনার লিঙ্ক ঘোষণা

ইন starhermit.txt:

engine.minor=24
engine.capabilities=platform
engine.link.discord=https://discord.gg/abc
engine.link.store=https://example.com/game
  • আপনি 16টি লিঙ্ক পর্যন্ত ঘোষণা করতে পারেন। প্রতিটি আইডি 1-32 অক্ষরের a-z 0-9 - এবং শুধুমাত্র একবার প্রদর্শিত হতে পারে.
  • যে কোন engine.link.* মূল চাহিদা engine.minor=24, তাই পুরোনো রানটাইম খেলা প্রত্যাখ্যান.
  • একটি উত্পাদন খেলা প্রয়োজন engine.capabilities=platform, কারণ রানটাইম অনুমোদন চেক করে প্লেয়ারের লঞ্চ টোকেন সহ। তা ছাড়া, openLink সমাধান করে "unavailable" বাইরে উন্নয়ন এবং ম্যানিফেস্ট একটি সতর্কতা পায়।

একটি লিঙ্ক খুলুন

openLink(id) থেকে starhermit:engine রিটার্ন Promise<"opened" | "cancelled" | "unapproved" | "unavailable">:

  • "unapproved": লিঙ্কটি মুলতুবি, প্রত্যাখ্যান বা প্রত্যাহার করা হয়েছে, এর ইউআরএল অনুমোদিত থেকে আলাদা, বা আইডি ঘোষণা করা হয় না।
  • "unavailable": কোনো প্ল্যাটফর্ম সেশন নেই, একটি নেটওয়ার্ক ত্রুটি, 401/403/429, বা 10 সেকেন্ডের মধ্যে কোনো উত্তর নেই।

একটি প্রেস (পয়েন্টার, কী বা গেমপ্যাড) পরিচালনা করার সময় এটি কল করুন; প্রতিটি প্রেস সর্বাধিক একটি লিঙ্ক খোলে। একটি কল একটি প্রেসের বাইরে, একটি মুলতুবি থাকা অবস্থায় একটি দ্বিতীয় কল এবং প্লেয়ারের বাতিল হওয়ার 2 সেকেন্ডের মধ্যে একটি কল সব সমাধান "unavailable" এবং একটি সতর্কতা লগ করুন।

রানটাইম লিঙ্কের সম্পূর্ণ হোস্ট এবং URL সহ নিজস্ব নিশ্চিতকরণ দেখায় এবং শুধুমাত্র পৃষ্ঠাটি খোলে যদি প্লেয়ার ওপেন পছন্দ করে। ব্রাউজারগুলিতে একটি গেমপ্যাডের পিছনে বাতিল হয়, কিন্তু নিশ্চিত করার জন্য একটি ক্লিক, আলতো চাপুন, এন্টার বা স্পেস, কারণ একটি ব্রাউজার শুধুমাত্র সেগুলি থেকে একটি উইন্ডো খোলে।

কি একটি লিঙ্ক হতে পারে

একটি লিঙ্ক হতে হবে https, কোন পোর্ট ছাড়া, কোন user@, কোন IP ঠিকানা এবং কোন স্থানীয় নাম (localhost, .local, .internal) এর হোস্ট অবশ্যই ASCII হতে হবে, আন্তর্জাতিক নামগুলি punycode হিসাবে লিখিত, এবং অন্তত দুটি লেবেল আছে. এতে ব্যাকস্ল্যাশ, স্পেস, অক্ষর থাকতে পারে না " < > ` { } | ^, বিকৃত % পালানো, এনকোডেড স্ল্যাশ (%2f, %5c) বা ./.. পথের অংশ। প্ল্যাটফর্মটি ক্যানোনিকাল ফর্ম রাখে: স্কিম এবং হোস্ট ইন ছোট হাতের অক্ষর, এবং / একটি খালি পথের জন্য। অন্য সবকিছু ঠিক যেমন আপনি লিখেছেন ঠিক রাখা আছে.

আপনি প্রকাশ করার সময় একটি নিয়ম ভঙ্গকারী একটি লিঙ্ক সহ একটি প্যাকেজ প্রত্যাখ্যান করা হয়, সঙ্গে 422 invalid_link: engine.link.<id> is not an allowed link (<rule>), কিছু লাইভ হওয়ার আগে।

পর্যালোচনা

প্রতিটি নতুন লিঙ্ক শুরু হয় pending, এবং কর্মীরা এটি অনুমোদন না করা পর্যন্ত রানটাইম কিছুই খোলে না। কিছু লিংক হল স্বয়ংক্রিয়ভাবে প্রত্যাখ্যাত: URL সংক্ষিপ্তকারী এবং পুনঃনির্দেশ পরিষেবা, যার গন্তব্য অন্য কেউ নিয়ন্ত্রণ, এবং প্রোগ্রাম এবং আর্কাইভের সরাসরি ডাউনলোড (.exe, .dmg, .apk, .zip এবং অনুরূপ)। ট্র্যাকিং পরামিতি যেমন utm_* পর্যালোচকদের জন্য পতাকাঙ্কিত করা হয়।

একটি অনুমোদন আপনার গেম এবং সেই সঠিক URL এর অন্তর্গত। একটি পরবর্তী সংস্করণ একই URL তালিকাভুক্ত, অধীনে যে কোন আইডি, রাখে। URL পরিবর্তন একটি নতুন পর্যালোচনা প্রয়োজন. কর্মীরা একটি অনুমোদন প্রত্যাহার করতে পারেন, অথবা একটি ব্লক করতে পারেন পুরো হোস্ট, যে কোনো সময়ে।

আপনার লিঙ্ক এবং তাদের অবস্থা দেখুন GET /api/v1/me/github-games/{id}/links:

[ { "id": "discord", "url": "https://discord.gg/abc", "status": "approved", "autoReason": null, "note": null } ]

রানটাইম চেক করে GET /api/v1/games/{slug}/links/{id} প্রতিটি খোলা, প্লেয়ার এর লঞ্চ সঙ্গে টোকেন উত্তর হল { id, url, status }, কোথায় status হয় approved, pending, rejected বা revoked, বা 404 link_unknown একটি আইডির জন্য আপনার স্থাপন করা ম্যানিফেস্ট ঘোষণা করে না।

যখন আপনি স্থানীয়ভাবে বিকাশ করেন (--dev স্থানীয়ভাবে, বা ব্রাউজারে একটি লুপব্যাক পৃষ্ঠা, কোন লঞ্চ ছাড়াই টোকেন), রানটাইম একটি সতর্কতার পিছনে ঘোষিত লিঙ্কগুলি খোলে যে সেগুলি পর্যালোচনা করা হয়নি।
