খেলা স্ক্রিপ্ট

একটি StarHermit প্রামাণিক খেলা একটি দ্বারা সংজ্ঞায়িত করা যেতে পারে একক জাভাস্ক্রিপ্ট ফাইল একটি স্যান্ডবক্সে সার্ভার-সাইড কার্যকর করা হয়েছে জিন্ত ইঞ্জিন স্ক্রিপ্টটি সেই গেমের নিয়মগুলির একমাত্র কর্তৃত্ব: এটি প্রতিটি প্লেয়ারের আদেশকে বৈধ করে, অবস্থাকে পরিবর্তন করে, প্রতিটি ক্লায়েন্ট কী দেখতে পারে তা সিদ্ধান্ত নেয়, Elo গণনা করে এবং গেমগুলি শেষ করে৷ ক্লায়েন্টদের শূন্য কর্তৃত্ব আছে। এই পৃষ্ঠাটি জাভাস্ক্রিপ্ট রানটাইম নথিভুক্ত করে; যে গেমগুলির জন্য অন্য ভাষা প্রয়োজন তা পরিবর্তে প্রয়োগ করতে পারে কন্টেইনার গেম সার্ভার প্রোটোকল উভয়ই একই প্লেয়ার-ফেসিং ব্যবহার করে গেম API. জুড়ে কাজের উদাহরণ হল দাবা — এখানে রেফারেন্স বাস্তবায়ন হাইপড্রাইভেন/স্টারহার্মিট-দাবা.

মৃত্যুদন্ডের মডেল

  • প্রতি গেমে একটি জেএস ফাইল, একটিতে কার্যকর করা হয়েছে প্রতি আহ্বানের জন্য তাজা স্যান্ডবক্সযুক্ত জিন্ট ইঞ্জিন. কলগুলির মধ্যে মেমরিতে কিছুই স্থির থাকে না — সমস্ত রাজ্য আপনার ফেরত দেওয়া নথিগুলিতে থাকে৷
  • পরিবেষ্টিত নেই Date বা Math.random. সময় এবং এলোমেলোতা হিসাবে সরবরাহ করা হয়: ctx.now (ms epoch) এবং ctx.random (ভেতরে ভেসে আসা [0, 1)).
  • যখন কোনো খেলোয়াড় একটি টেকসই কমান্ড পাঠায়, যখন একটি অধিবেশন তৈরি হয় এবং পর্যায়ক্রমিকভাবে প্ল্যাটফর্মটি স্ক্রিপ্টের আহ্বান জানায় onTick ঝাড়ু দেয় (দেখুন গেম API - রানটাইম টাইমিং) রিয়েলটাইম {type:"input", realtime:true} ফ্রেমগুলি হল ব্যতিক্রম: এগুলিকে বাফার করা হয় সর্বশেষ-জয় এবং পরবর্তী টিককে একটি ব্যাচ হিসাবে বিতরণ করা হয়৷

এন্ট্রি পয়েন্ট

হ্যান্ডলারদের অনাবৃত করুন globalThis.game. ছয়টি ঐচ্ছিক স্থির ঘোষণাগুলি তাদের পাশাপাশি বসে: tickRateHz প্ল্যাটফর্মকে জিজ্ঞাসা করে কত ঘন ঘন আহ্বান করতে হবে onTick - যদি আপনার গেমের উপর নির্ভর করে তবে এটি ঘোষণা করুন টিক দিন, যেহেতু একটি গেম যা বলে যে প্রতি চার সেকেন্ডে একবার টিক দেওয়া হয় না (দেখুন টিক রেট), achievements গেমের কৃতিত্ব নিবন্ধন করে (দেখুন অর্জন), replays প্ল্যাটফর্মকে আপনার সমাপ্ত সেশন রাখতে বলে (দেখুন রিপ্লে), persistent বিরতি যখন সবাই চলে যায় তখন সেশনগুলি শেষ না করে (দেখুন অবিরাম সেশন), linkedAchievements অন্যান্য গেমের নাম দিন যার আনলক আপনি পাবেন ctx.linkedAchievements (দেখুন অন্যান্য গেম থেকে অর্জন), এবং queues ঘোষণা করে ম্যাচ ম্যাচমেকিং এর আকারগুলি গ্রহণ করে (দেখুন গেমস - ম্যাচমেকিং) একটি খেলা যে কোনো সারি ঘোষণা করে না একটি অন্তর্নিহিত 1v1 আছে:

globalThis.game = {
  tickRateHz: 0, // turn-based: opt out of periodic ticks
  replays: true, // keep finished sessions as replays
  queues: [{ key: "duos", teams: 2, teamSize: 2 }],
  achievements: [
    { key: "first-win", name: "First Win", description: "Win a match.", points: 10 }
  ],
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

ঘোষণাপত্র আপনার স্ক্রিপ্ট মূল্যায়ন দ্বারা পড়া হয় যখন গেমটি প্রকাশিত বা আপডেট করা হয়, প্রতিটি আহ্বানে নয় — তাই তাদের অবশ্যই স্ট্যাটিক মান হতে হবে game বস্তু একটি আপডেট প্রকাশ করুন একটি পরিবর্তন প্রয়োগ করতে।

  • createSession(ctx) — যখন একটি সেশন তৈরি করা হয় তখন বলা হয় (ম্যাচমেকিং, আমন্ত্রণ-গ্রহণ, এআই অনুশীলন, বা একটি রিয়েলটাইম রুম শুরু হচ্ছে — দেখুন রুম-বাউন্ড সেশন).
  • onPlayerMessage(ctx) — গেমপ্লে ওয়েবসকেটের মাধ্যমে প্রাপ্ত টেকসই ক্লায়েন্ট কমান্ডের জন্য বলা হয়েছে। ইনপুটগুলি স্পষ্টভাবে চিহ্নিত৷ realtime:true এই এন্ট্রি পয়েন্ট বাইপাস.
  • onMembershipChange(ctx) - ঐচ্ছিক। যখন একজন খেলোয়াড় একটি চলমান অধিবেশনে যোগ দেয় বা ছেড়ে যায় তখন বলা হয় (a জয়েন-ইন-প্রোগ্রেস রুম, অথবা একটি চলমান একটি খেলায় আমন্ত্রণ জানান). ctx.players ইতিমধ্যে পরিবর্তন প্রতিফলিত, এবং ctx.membership হয় { change: "joined" | "left", userId, name, team, slot }. প্রত্যাবর্তন { ok: false } যোগদান প্রত্যাখ্যান করা; এই হুক ছাড়া একটি স্ক্রিপ্ট প্রতিটি যোগদান প্রত্যাখ্যান করে। একটি ছুটি চূড়ান্ত যা আপনি ফিরে যান. অর্জন এবং স্কোর ফলাফল অশ্বারোহণ করতে পারে; ক sessionState উপেক্ষা করা হয়।
  • onTick(ctx) — কার্যকর টিক হারে প্ল্যাটফর্মের টাইমার পরিষেবা দ্বারা ডাকা হয়; সর্বশেষ রিয়েলটাইম ইনপুট পাওয়া যায় ctx.inputs. 0 Hz-এ সমাধান করা একটি গেম পর্যায়ক্রমিক কল গ্রহণ করে না, তবে স্ক্রিপ্ট চুক্তি সন্তুষ্ট করার জন্য ফাংশনটি এখনও উপস্থিত থাকা উচিত।

প্রসঙ্গ বস্তু

ctx = {
  now: 1721473200000,              // ms epoch, from the host clock
  random: 0.7231,                  // float in [0, 1), from the host RNG
  sessionId: "0f8fad5b-...",       // current session id
  pausedMs: 0,                     // persistent games only: total ms this session has spent paused
  players: [                       // session participants
    { id: "7c9e6679-...", name: "alice" },
    { id: "00000000-0000-4000-8000-00000000a1a1", name: "The House", ai: true }
  ],
  sessionState: { /* ... */ },     // this script's session document, or null
  playerStates: {                  // per-player documents (elo, history), or null
    "7c9e6679-...": { elo: 1200, wins: 4, losses: 2, draws: 1, /* ... */ }
  },
  message: {                       // onPlayerMessage only
    from: "7c9e6679-...",          // the authenticated user id — trusted
    data: { type: "move", from: "e2", to: "e4" }  // client payload — untrusted (example: a chess move)
  },
  inputs: [                        // onTick only; omitted when none are pending
    { from: "7c9e6679-...",        // authenticated sender id — trusted
      data: { type: "input", seq: 42, mx: 0.7, mz: -0.2 } }
  ]
}
  • AI আসনটি (যদি উপস্থিত থাকে) সাথে পতাকাযুক্ত ai: true এর প্লেয়ার এন্ট্রিতে।
  • একটি খেলা যে ঘোষণা linkedAchievements এছাড়াও পায় ctx.linkedAchievements: { <playerId>: { <otherSlug>: [unlocked keys] } }, প্রতিটি আহ্বানে পুনরায় পড়ুন। দেখুন অন্যান্য গেম থেকে অর্জন.
  • রুম-বাউন্ড সেশন (একটি রিয়েলটাইম রুম থেকে শুরু) দুটি অতিরিক্ত ctx ক্ষেত্র পান, ctx.room এবং ctx.presence, চালু প্রতিটি আমন্ত্রণ - দেখুন রুম-বাউন্ড সেশন.
  • থেকে কিছুই বিশ্বাস ctx.message.data বা ctx.inputs[].data. বিশ্বস্ত পরিচয়টি সংশ্লিষ্ট from, যা সার্ভার প্রমাণীকৃত সংযোগ থেকে সংযুক্ত করে — ক্লায়েন্ট কখনই এটি সরবরাহ বা ফাঁকি দিতে পারে না।
  • ইনপুট সঙ্গে ব্যাচিং নির্বাচন করুন {type:"input", realtime:true, ...}. অচিহ্নিত input কমান্ড টেকসই থাকে onPlayerMessage পশ্চাদগামী সামঞ্জস্যের জন্য আহ্বান. রিয়েলটাইম ইনপুট প্রতি প্রেরক একটি মুলতুবি স্লট ব্যবহার করে: আন্দোলন সর্বশেষ-জয়, যখন pass, shoot, এবং tackle অ্যাকশন প্রান্তগুলি একত্রিত করা হয়েছে যাতে নিম্নলিখিত আন্দোলনের নমুনা পরবর্তী টিকের আগে তাদের মুছে ফেলতে পারে না। ব্যাচ গ্রহণ করার সময় স্ক্রিপ্টগুলিকে অবশ্যই ক্ল্যাম্প এবং প্রতিটি মান যাচাই করতে হবে।

টিক রেট

প্ল্যাটফর্ম চলছে onTick একটি কনফিগারযোগ্য হারে সক্রিয় সেশন প্রতি sweeps. আপনার স্ক্রিপ্ট এটি চায় হার জন্য জিজ্ঞাসা একটি স্ট্যাটিক ঘোষণা করে tickRateHz গেম অবজেক্টে, এন্ট্রি পয়েন্টের পাশাপাশি:

globalThis.game = {
  tickRateHz: 15,          // ask the platform to tick this game 15x/second
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};
  • ঘোষণাটি পাঠ করা হয় যখন আপনার গেম প্রকাশিত বা আপডেট হয়, প্রতিটি টিক নয়। এটি পরিবর্তন করার পরে একটি আপডেট প্রকাশ করুন।
  • একটি খেলা যা কোনো হার ঘোষণা করে না 0.25 Hz এ টিক দেওয়া হয় - প্রতি চার সেকেন্ডে একবার। যে প্রচুর একটি মুভ ঘড়ি বা সময়সীমার বিচার করুন এবং প্ল্যাটফর্মের প্রায় কিছুই খরচ হয় না, তবে এটি অনেক ধীর যে কোন কিছুর জন্য আপনার গেমপ্লে নির্ভর করে। যদি onTick আপনার গেম চালায়, আপনার প্রয়োজনীয় হার ঘোষণা করুন।
  • অনুরোধ প্ল্যাটফর্মে সর্বোচ্চ ক্ল্যাম্প করা হয় (30 Hz ডিফল্টরূপে), তাই একটি গেম কম চাইতে পারে প্ল্যাটফর্ম অনুমতি দেয় কিন্তু এর বেশি কখনই নয়। চাও 0 একটি খেলার জন্য সম্পূর্ণরূপে টিক নিষ্ক্রিয় করতে যে শুধুমাত্র প্লেয়ার কমান্ড প্রতিক্রিয়া.
  • হার হতে পারে ভগ্নাংশ: 0.5 প্রতি দুই সেকেন্ডে একটি টিক। ক্ষুদ্রতম অ-শূন্য হার হয় 0.01 Hz — একটি অপ্ট-আউট হিসাবে পড়ার পরিবর্তে এটিতে একটি ছোট ধনাত্মক সংখ্যা উত্থাপিত হয়, কারণ a ছোট ভগ্নাংশ একটি ধীর খেলা. শুধুমাত্র জন্য টিক বন্ধ 0 বা একটি নেতিবাচক হার। একটি অনুপস্থিত বা অব্যবহারযোগ্য ঘোষণা (একটি স্ট্রিং, null, NaN) 0.25 Hz ডিফল্ট নেয়।
  • একটি অপারেটর একটি নির্দিষ্ট গেমের জন্য রেট ওভাররাইড করতে পারে, উভয় দিকেই।
  • রিয়েলটাইম ইনপুটগুলি টিকগুলির মধ্যে সর্বশেষ-জয়, যখন বিচ্ছিন্ন অ্যাকশন প্রান্তগুলি ক্রমানুসারে থাকে৷ একটি ধীর প্রাপক একটি অপ্রচলিত স্ন্যাপশট এড়িয়ে যেতে পারে কিন্তু সিমুলেশন বা অন্যান্য প্রাপকদের বিলম্ব করতে পারে না।

রিপ্লে

একটি অধিবেশন শেষ হলে, প্ল্যাটফর্ম তার চূড়ান্ত রাখতে পারে sessionState হিসাবে রিপ্লে — the নথি দ্বারা পরিবেশিত GET /api/v1/games/{slug}/replays/{sessionId} (দেখুন গেম API - রিপ্লে) একটি রিপ্লে ম্যাচের রেকর্ড যতক্ষণ ধরে রাখা হয় হয়, তাই এটি জিজ্ঞাসা করলেই আপনার গেমটি একটি পায়:

globalThis.game = {
  replays: true,           // keep finished sessions as replays
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};
  • ঘোষণা একটি আক্ষরিক হতে হবে true বা false - অন্য কিছু কোন ঘোষণা হিসাবে পড়া হয়, এবং একটি খেলা যে কিছুই ঘোষণা করে না কোন রিপ্লে আছে.
  • এটা পড়া হয় যখন আপনার গেম প্রকাশিত বা আপডেট হয়. এটি পরিবর্তন করার পরে একটি আপডেট প্রকাশ করুন।
  • একটি প্ল্যাটফর্ম অপারেটর একটি নির্দিষ্ট গেমের জন্য উভয় উপায়ে উত্তর দিতে পারে, তাই ঘোষণাটি একটি অনুরোধ গ্যারান্টির পরিবর্তে। GET /api/v1/games/{slug} হিসাবে উত্তর রিপোর্ট replaysEnabled - আপনার রিপ্লে UI এর উপর শাখা করুন, আপনার স্ক্রিপ্ট যা চেয়েছে তার উপর নয়।
  • রিপ্লে বন্ধের সাথে অন্য কিছুই পরিবর্তন হয় না: আপনার সেশনের অবস্থা এখনও সংরক্ষণ করা হয় এবং এখনও হস্তান্তর করা হয় হিসাবে প্রতিটি আহ্বান ctx.sessionState, এবং এটি এখনও ক্র্যাশ পুনরুদ্ধার পয়েন্ট। কি খেলা রিপ্লে ছাড়া পাওয়া যায় না একটি অনুলিপি যা সেশনের বাইরে থাকে, তাই এর রিপ্লে শেষ পয়েন্ট উত্তর দেয় 404.
  • ফাইনাল ডিজাইন করুন sessionState রিপ্লে করার যোগ্য হতে - একটি মুভ লগ, বা আপনার ক্লায়েন্টের যা প্রয়োজন ম্যাচ পুনর্গঠন করতে। দাবা রেফারেন্স বাস্তবায়ন রাখে state.game.moves এবং এটি পদক্ষেপ একই নিয়ম মডিউলের মাধ্যমে প্ল্যাটফর্মটি কার্যকর করে।

অবিরাম সেশন

একটি খেলা যে ঘোষণা persistent: true প্রত্যেক খেলোয়াড় চলে গেলে তার সেশন রাখে। প্রায় 15 শেষ সংযোগ বিচ্ছিন্ন করার সেকেন্ড পরে সেশন হয় বিরতি দেওয়া - না onTick কল - এবং প্রথম পুনরায় সংযোগ করার জন্য প্লেয়ার এটি পুনরায় শুরু করে। সংযোগ বিচ্ছিন্ন করা বা নিষ্ক্রিয়তা অধিবেশনটি পরিত্যাগ করার পরিবর্তে বিরতি দেয়। একটি খেলা ফলাফল, মালিক কর্ম, সুস্পষ্ট চূড়ান্ত-সদস্যদের ছুটি, কনফিগার করা ধরে রাখার মেয়াদ, বা টার্মিনাল পুনরুদ্ধার ব্যর্থতা হতে পারে এখনও এটি শেষ। দেখুন সেশন জীবনচক্র.

globalThis.game = {
  persistent: true,        // pause empty sessions instead of ending them
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};
  • একটি আক্ষরিক হতে হবে true বা false. এটা পড়া হয় যখন আপনার গেম প্রকাশিত বা আপডেট হয়.
  • ctx.now দেয়াল ঘড়ি থাকে। ক্রমাগত সেশনও পান ctx.pausedMs, মোট সময় ব্যয় বিরতি, তাই ctx.now - ctx.pausedMs এমন একটি ঘড়ি যা স্থির থাকে যখন কেউ থাকে না।
  • বিরতি দেওয়া সেশনগুলি প্রতি-প্লেয়ার সেশন ক্যাপের সাথে গণনা করা হয়, তাই খেলোয়াড়দের একটি কমান্ড দিন যা শেষ হয় a একটি সঙ্গে বিশ্বের result.

দেখুন ক্রমাগত সেশন টিউটোরিয়াল একটি কাজের উদাহরণ এবং ক্লায়েন্ট প্রবাহের জন্য।

ম্যাচমেকিং সিট লেআউট

নতুন ম্যাচমেড সেশন গ্রহণ ctx.matchmaking অন প্রতিটি আমন্ত্রণ (তৈরি, আদেশ এবং টিক)। এটি সারির আকার এবং আসন সংরক্ষণ করে এমনকি যদি গেমটি পরে পুনরায় স্থাপন করা হয়:

ctx.matchmaking = {
  queue: "ffa", teams: 4, teamSize: 1,
  seats: [
    { id: "human-uuid", name: "Alice", team: 0, slot: 0, ai: false },
    { id: "synthetic-ai-uuid", name: "AI 2-1", team: 1, slot: 0, ai: true },
    { id: null, name: null, team: 2, slot: 0, ai: false },
    { id: null, name: null, team: 3, slot: 0, ai: false }
  ]
};

ctx.players শুধুমাত্র দখলকৃত আসন রয়েছে, সঙ্গে team এবং ai:true AI এর জন্য। দল/স্লট সূচী হয় শূন্য-ভিত্তিক। এআই আইডি এই সেশনের মধ্যে স্থিতিশীল এবং StarHermit অ্যাকাউন্ট আইডি নয়। শুধু মানুষ অধিবেশন/চ্যাট সদস্যপদ আছে এবং অ্যাকাউন্ট প্লেয়ার-স্টেট, রেটিং বা অর্জনের লেখা পেতে পারে। এআই অবস্থা রাখুন sessionState. আপনার গেমের স্থিতিতে ক্লায়েন্টদের যে রোস্টার ফিল্ডের প্রয়োজন তা কপি করুন বা সম্প্রচার। পুরানো সেশন এবং নন-ম্যাচমেকিং সেশন বাদ দিতে পারে ctx.matchmaking.

একটি শুরুর সময়সীমা ঘোষণা করুন এবং সর্বাধিক AI গণনা করুন৷ starhermit.txt. এআই গণনা সহ 0, খালি আসন খালি থাকে। একই প্রসঙ্গ ধারক সার্ভারে বিতরণ করা হয়।

রুম-বাউন্ড সেশন

একটি অধিবেশন হতে পারে রিয়েলটাইম রুমে আবদ্ধ: যখন ক রিয়েলটাইম রুম একটি খেলার জন্য server= স্ক্রিপ্ট শুরু হয়, প্ল্যাটফর্মটি রুমের জন্য একটি এন-প্লেয়ার সেশন তৈরি করে মানব অংশগ্রহণকারীরা (এআই আসন শুধুমাত্র স্ক্রিপ্ট-মুখী রোস্টারে বিদ্যমান)। এইভাবে সার্ভার-অনুমোদিত রিয়েলটাইম গেম (যেমন ফুটবল) চলে: রুমগুলি লবি/ম্যাচমেকিং প্রদান করে, স্ক্রিপ্ট ম্যাচ চালায়। দেখুন রিয়েলটাইম রুম - সেতু রুমের পাশের জীবনচক্রের জন্য।

প্রতিটি আহ্বান (createSession, onPlayerMessage, onTick) একটি রুম-বাউন্ড সেশনের দুটি অতিরিক্ত ctx ক্ষেত্র পাওয়া যায়:

ctx.room = {
  roomId: "0f8fad5b-...",
  metadata: { /* ... */ },        // the room's opaque config.metadata blob
  roster: [                       // frozen match roster, humans AND AI seats,
    { userId: "7c9e6679-...",     //   ordered by team then slot
      name: "alice", team: 0, slot: 0, ai: false },
    { userId: null,               // AI seat — never a session player
      name: "Rafa Vento", team: 0, slot: 1, ai: true }
  ]
};
ctx.presence = {                  // every user who is or was a human participant
  "7c9e6679-...": { online: true, left: false }
};
  • presence.online — ব্যবহারকারীর উভয় সংযোগ রেজিস্ট্রিতে একটি লাইভ সকেট রয়েছে (রিয়েলটাইম রুম বা ws/v1/games).
  • presence.left — ব্যবহারকারী আর একটি সক্রিয় আসন ধারণ করে না: তারা স্পষ্টভাবে ছেড়ে গেছে এবং তাদের আসনটি এআই অংশগ্রহণকারীতে রূপান্তরিত হয়েছে। left স্থায়ী হয়; online ফ্ল্যাপ হতে পারে। স্ক্রিপ্টটি এই ফ্ল্যাগগুলি থেকে AI টেকওভার / পুনরায় যোগদানের যুক্তি চালাবে বলে আশা করা হচ্ছে।
  • প্রতিটি আহ্বানে রোস্টারটি পুনরায় পড়া হয়, তাই আসন রূপান্তর (মানব → AI) হওয়ার সাথে সাথে দেখা যায়।

যখন একটি রুম-বাউন্ড স্ক্রিপ্ট ফিরে আসে result, প্ল্যাটফর্মটি সেশন শেষ করে, ফলাফলটি ঘরে সঞ্চয় করে এবং ঘরটি বন্ধ করে দেয় - হোস্ট-জমা করা কোনো ফলাফল জড়িত নয়।

বিপরীতটি সত্য নয়: একটি রুম বন্ধ তার অধিবেশন শেষ হয় না. যদি রুমটি প্রথমে বন্ধ হয়ে যায় (উদাহরণস্বরূপ, কারণ তার শেষ মানুষ যোগদান-প্রগতি ছাড়াই একটি রুম ছেড়ে চলে গেছে — কখনোই কেবল হোস্ট অফলাইনে যাওয়ার কারণে নয়, যা শুধুমাত্র সেশন সক্রিয় থাকাকালীন হোস্টের ভূমিকাকে সরিয়ে দেয়), সেশনটি চলতে থাকে, ctx.room.roster খালি হয়ে যায় এবং প্রতিটি মানুষ দেখায় left: true. প্রত্যাবর্তন result তাহলে ম্যাচ শেষ হলেই আসর। দেখুন রিয়েলটাইম রুম — 60-সেকেন্ডের হোস্ট নিয়ম এবং রুম-বাউন্ড সেশন.

প্রত্যাবর্তন আকৃতি

প্রতিটি এন্ট্রি পয়েন্ট একই আকৃতি প্রদান করে (ব্যতীত সমস্ত ক্ষেত্র ঐচ্ছিক ok):

return {
  ok: true,                        // false on failure
  error: "Illegal move",           // goes only to the sender (as a WS "error" frame)
  sessionState: { /* ... */ },     // REPLACES the stored session document
  playerStates: {                  // REPLACES stored per-player documents
    "7c9e6679-...": { elo: 1216, /* ... */ }
  },
  broadcast: [                     // only these messages ever reach clients
    { to: "all", data: { type: "moved", /* ... */ } },
    { to: ["9b2f8c1a-..."], data: { type: "state", /* ... */ } }
  ],
  eloUpdates: {                    // published to the game's leaderboard by the host
    "7c9e6679-...": 1216,
    "9b2f8c1a-...": 1184
  },
  achievements: {                  // server-authoritative unlocks, by player id
    "7c9e6679-...": ["first-win", "flawless"]
  },
  scores: {                        // to your game's own leaderboards, by board key
    "high-score": { "7c9e6679-...": 4200 }
  },
  result: { kind: "white-win", reason: "checkmate" }  // ends the session (example: a chess result)
};

মূল নিয়ম:

  • sessionState এবং প্রতিটি এন্ট্রি playerStates প্রতিস্থাপন সংরক্ষিত নথিগুলি - সর্বদা সম্পূর্ণ নথি ফেরত দিন, কখনও আলাদা হয় না।
  • শুধুমাত্র তালিকাভুক্ত বার্তা broadcast ক্লায়েন্টদের কাছে বিতরণ করা হয়, প্রতিটি স্পষ্ট প্লেয়ার আইডিতে সম্বোধন করা হয় বা "all". অন্য কিছু ফাঁস.
  • eloUpdates রেটিং পরিবর্তনের একমাত্র উপায়। মান প্রতিটি খেলোয়াড়ের হয় নতুন পরম রেটিং, প্রেরিত হিসাবে প্রয়োগ করা হয়েছে — প্ল্যাটফর্মটি প্রতি ম্যাচের পরিবর্তনকে ক্যাপ করে না, তাই এটি নিজেই আটকে দিন (দেখুন ম্যাচ প্রতি এলো) হোস্ট তাদের ম্যাচমেকিং এর জন্য ব্যবহার করে এবং গেমের লিডারবোর্ডে প্রকাশ করে; ক্লায়েন্টরা সরাসরি স্কোর জমা দিতে পারে না (দেখুন লিডারবোর্ড) রেটিং রাখুন playerStates[id].elo তাই একজন মালিকের রেটিং রিসেট আপনার কপিও পৌঁছে যায়।
  • achievements অর্জন মঞ্জুর করা হয় একমাত্র উপায়. কীগুলি গেমের কৃতিত্বের বিরুদ্ধে সমাধান করা হয় — ঘোষিত, বা এর মালিক দ্বারা তৈরি — এবং প্ল্যাটফর্ম দ্বারা স্থির থাকে; দেখুন অর্জন.
  • scores আপনার গেমের নিজস্ব লিডারবোর্ড পরিবর্তন করার একমাত্র উপায় - দেখুন লিডারবোর্ড.
  • এর মাধ্যমে গেমস শেষ করুন result. হোস্ট তারপর সেশন শেষ, এবং সঙ্গে একটি খেলা জন্য রিপ্লে ফাইনাল আর্কাইভ করে sessionState রিপ্লে হিসাবে ( দ্বারা পরিবেশিত GET .../replays/{sessionId} — দেখুন গেম API).

অর্জন

আপনার স্ক্রিপ্ট হল শুধুমাত্র আপনার গেমের কৃতিত্ব আনলক করতে পারে এমন জিনিস। কোনো ক্লায়েন্ট নেই তাদের জন্য শেষ পয়েন্ট: POST /api/v1/me/achievements/unlock গেম-স্কোপড কৃতিত্ব সরাসরি প্রত্যাখ্যান করে, এবং প্রকাশক CRUD এন্ডপয়েন্ট তাদের স্পর্শ করতে অস্বীকার করে। গেমের মালিক পাশে কৃতিত্ব যোগ করতে পারেন মাধ্যমে ঘোষিত বেশী /me/github-games/{id}/achievements; আপনার স্ক্রিপ্ট ঠিক একই ভাবে কী দ্বারা সেগুলি আনলক করে। এটি সার্ভার হিসাবে অর্জন করে তোলে- গেমের বাকি অংশের মতোই প্রামাণিক, এবং এটি প্রক্রিয়া যেকোনো একটি সঙ্গে খেলা server= স্ক্রিপ্ট ব্যবহার করা উচিত — যার গেমপ্লে অন্য কোথাও চলে (দেখুন কোন গেম এই ব্যবহার করতে পারেন).

ঘোষণা করুন

একটি স্থির achievements অ্যারে উপর game বস্তু শুধুমাত্র key প্রয়োজন হয়:

globalThis.game = {
  achievements: [
    { key: "first-win", name: "First Win", description: "Win a match.", points: 10 },
    { key: "flawless",  name: "Flawless",  description: "Win without conceding.",
      points: 50, secret: true, icon: "https://cdn.example/flawless.png" }
  ],
  // ...entry points
};
মাঠ টাইপ নোট
key স্ট্রিং প্রয়োজন। স্থিতিশীল আইডি, ≤ 128 অক্ষর, গেমের মধ্যে অনন্য। প্রথমটির পরে সদৃশগুলি উপেক্ষা করা হয়।
name স্ট্রিং ডিফল্ট থেকে key.
description স্ট্রিং ডিফল্ট থেকে "".
icon স্ট্রিং ঐচ্ছিক URL.
secret বুলিয়ান পর্যন্ত একজন খেলোয়াড় থেকে লুকানো তারা এটা আনলক ডিফল্ট থেকে false.
points সংখ্যা 0-10000 এ আটকানো হয়েছে। ডিফল্ট থেকে 0.

গেমটি প্রকাশিত বা আপডেট হলে অ্যারে প্রয়োগ করা হয়:

  • দ্বারা সংজ্ঞা মিলেছে key — একটি নাম, আইকন, পয়েন্ট, বা গোপন পতাকা সম্পাদনা করা বিদ্যমান সংজ্ঞা আপডেট করে, এবং যারা ইতিমধ্যে এটি অর্জন করেছে প্রত্যেকে এটি রাখে।
  • আপনি ঘোষণা করা বন্ধ করা একটি কী মুছে ফেলা হয়েছে শুধুমাত্র যখন কেউ এটি আনলক করেনি. অর্জিত ইতিহাস কখনই ধ্বংস হয় না, তাই অবসরপ্রাপ্ত অর্জন খেলোয়াড়দের কাছে দৃশ্যমান থাকে যারা এটি ধরে রাখে।
  • সর্বাধিক 100 গেম প্রতি কৃতিত্ব; এর বাইরে অতিরিক্ত বাদ দেওয়া হয়।
  • ঘোষণা হল সেরা প্রচেষ্টা: বিকৃত এন্ট্রি বাদ দেওয়া হয়. সর্বদা এর সাথে প্রকাশিত সংজ্ঞা নিশ্চিত করুন GET /api/v1/games/{slug}/achievements গেম আপডেট করার পর।

আনলক

একটি প্রত্যাবর্তন achievements থেকে মানচিত্র যেকোনো প্রবেশ বিন্দু - createSession, onPlayerMessage, বা onTick:

onTick(ctx) {
  const state = JSON.parse(JSON.stringify(ctx.sessionState));
  const unlocks = {};
  for (const p of ctx.players) {
    if (!p.ai && state.scores[p.id] >= 10) unlocks[p.id] = ["ten-points"];
  }
  return { ok: true, sessionState: state, achievements: unlocks };
}
  • আনলক হয় অক্ষমতা — প্লেয়ারের কাছে ইতিমধ্যেই ধারণ করা একটি কী পুনরায় দাবি করা একটি নো-অপ, তাই একটি স্ক্রিপ্ট নিরাপদে এমন শর্ত থেকে পুরস্কার দিতে পারে যে এটি ট্র্যাকিংয়ের পরিবর্তে প্রতিটি টিককে পুনরায় মূল্যায়ন করে "ইতিমধ্যে পুরস্কৃত" তার নিজের রাজ্যে।
  • অজানা কী (গেমটির মালিকের দ্বারা ঘোষিত বা তৈরি করা হয়নি), ব্যবহারকারী যারা এই সেশনের অংশগ্রহণকারী নন এবং এআই সিট নীরবে উপেক্ষা করা হয়।
  • সর্বাধিক 32 প্রতি আহ্বান প্রতি খেলোয়াড়ের জন্য কীগুলি গ্রহণ করা হয়; একই অ্যারের আরও কী বাদ দেওয়া হয়।
  • সারি বাকি আমন্ত্রণের লেখার সাথে স্থির থাকে, তাই একটি আনলক ব্যর্থ আমন্ত্রণে টিকে থাকতে পারে না।

ডেলিভারি

প্রতিটি নতুন মঞ্জুরি আনলক উপার্জনকারী খেলোয়াড়ের কাছে পুশ করা হয় ws/v1/games একটি স্বতন্ত্র ফ্রেম হিসাবে - এটা প্ল্যাটফর্মের সত্য, আপনার এক নয় broadcast বার্তা:

{ "type": "achievement",
  "data": { "key": "first-win", "name": "First Win", "description": "Win a match.",
            "icon": null, "points": 10, "unlockedAt": "2026-07-25T09:14:02Z" } }

থেকে মঞ্জুর আনলক createSession কোন সকেট বিদ্যমান হওয়ার আগে জমি, তাই তারা কোন ফ্রেম ছাড়াই আসে - ক্লায়েন্টদের পড়তে হবে GET /api/v1/games/{slug}/achievements লোডের উপর এবং ফ্রেমটিকে হিসাবে বিবেচনা করুন লাইভ-আপডেট পথ। মধ্যে সম্পূর্ণ পৃষ্ঠ অর্জন.

লিডারবোর্ড

ইলো বোর্ড ছাড়াও, আপনার গেমে লিডারবোর্ড থাকতে পারে যার মালিক তৈরি করেন POST /api/v1/me/github-games/{id}/leaderboards, প্রতিটি একটি সঙ্গে key. ফিরে তাদের পোস্ট scores যেকোনো এন্ট্রি পয়েন্ট থেকে — বোর্ড কী → প্লেয়ার আইডি → সংখ্যা:

onPlayerMessage(ctx) {
  var s = ctx.sessionState;
  if (ctx.message.data.type === "finish-run") {
    var scores = { "high-score": {}, "fastest-run": {} };
    scores["high-score"][ctx.message.from] = s.points[ctx.message.from];
    scores["fastest-run"][ctx.message.from] = ctx.now - s.startedAt;   // a time-ms board
    return { ok: true, sessionState: s, scores: scores };
  }
  /* ... */
}
  • প্রতিটি খেলোয়াড় তাদের রাখে সেরা বোর্ডের সাজানোর নির্দেশ অনুসারে প্রতিটি বোর্ডে স্কোর করুন, তাই রিপোর্ট করুন প্রতিটি ফলাফল - একটি খারাপ একটি সহজভাবে উপেক্ষা করা হয়.
  • শুধুমাত্র অধিবেশন অংশগ্রহণকারীদের গণনা. অজানা বা নিষ্ক্রিয় কী, এবং বোর্ডের নিয়মের বাইরে স্কোর, নিঃশব্দে ফেলে দেওয়া হয়। রিটার্ন প্রতি সর্বোচ্চ 16টি বোর্ড।
  • অপছন্দ eloUpdates, কিছুই প্রকাশ করা হয় না playerStates - আপনার নিজের কপি রাখুন playerStates যদি খেলায় ব্যক্তিগত সেরা ব্যাক পড়তে হয়।

যেখানে আপনার স্ক্রিপ্ট চলে

একটি স্ক্রিপ্ট যা সীমা ছাড়াই পুনরাবৃত্তি করে, তার মেমরিকে নিঃশেষ করে দেয় বা তার সময় বাজেট অতিক্রম করে তা ব্যর্থ হয় আমন্ত্রণ এর ব্যর্থ ফলাফল প্রয়োগ করা হয় না। কমান্ড বা টিক এর মধ্যে একটি রিপোর্ট করে:

  • Game script error: the script crashed its runtime (for example, by recursing without limit).
  • Game script error: the script exceeded its memory budget.
  • Game script error: the script exceeded its time budget.

আপনার খেলা সার্ভারের ভাগ

  • স্ক্রিপ্ট সময়। একটি গেমের সমস্ত সেশন স্ক্রিপ্ট সময়ের বাজেট ভাগ করে, প্রতি সেকেন্ডে 2000 ms৷ ডিফল্ট, প্রতিটি আমন্ত্রণ আসলে যা নিয়েছিল তার সাথে চার্জ করা হয়। তার ভাগের উপর একটি খেলা বরং প্রত্যাখ্যান করা হয় সারিবদ্ধ চেয়ে: একটি টিক বাদ দেওয়া হয়, একটি কমান্ডের সাথে উত্তর দেওয়া হয় "এই গেমটি তার শেয়ারের চেয়ে বেশি ব্যবহার করছে এই মুহূর্তে সার্ভারের; শীঘ্রই আবার চেষ্টা করুন", এবং একটি সেশন রিটার্ন তৈরি 429.
  • কমান্ড। প্রতিটি খেলোয়াড় প্রতি সেকেন্ডে 20টি টেকসই কমান্ড পাঠাতে পারে (একটি সংক্ষিপ্ত বিস্ফোরণ সহ ভাতা); এর বাইরে একটি কমান্ডের উত্তর একটি দিয়ে দেওয়া হয় error ফ্রেম "অনেক কমান্ড; ধীর নিচে" ফ্রেমে একটি HTTP স্থিতি অন্তর্ভুক্ত নয়। রিয়েলটাইম ইনপুট আলাদাভাবে সীমিত।
  • ফলাফল. একটি সেশন শেষ হওয়ার ফলাফল সর্বাধিক 64 KB হতে পারে; একটি বড় এক সঙ্গে প্রত্যাখ্যান করা হয় 422.
  • স্ক্রিপ্ট আকার. A server= স্ক্রিপ্ট সর্বাধিক 2 MB হতে পারে; একটি বড় এক সঙ্গে প্রত্যাখ্যান করা হয় 422 আগে এটা সংরক্ষিত বা পার্স করা হয়.

অপারেটররা একটি পৃথক গেমের জন্য এগুলির প্রতিটি বাড়াতে বা কমাতে পারে।

বাজেট

এই সম্পদ বাজেটের অধীনে স্ক্রিপ্ট চালানো হয়:

  • প্রতি আহ্বান ~250 ms CPU
  • 32 এমবি মেমরি
  • প্রতি আহ্বানের জন্য একটি বিবৃতি ক্যাপ
  • প্রতি-প্লেয়ার স্টেট বাইট বাজেট — সমস্ত রাষ্ট্রীয় নথি ক্রমিক এবং ছোট থাকতে হবে
  • টেক্সট হয়ে গেলে মানগুলি সর্বাধিক 64 স্তরের গভীরে নেস্ট করে৷ একটি এন্ট্রি পয়েন্ট ফেরত যা কিছু, প্রতি ঘোষণা, JSON.stringify, এবং Array.prototype.join/toString/toLocaleString প্রত্যাখ্যান a একটি সঙ্গে গভীর মান RangeError (একটি ফেরত আসা আমন্ত্রণ ব্যর্থ করে: "64 টিরও বেশি স্তর নেস্ট করেছে গভীর"). JSON.parse ইতিমধ্যেই 64 এ থেমে গেছে, তাই একটি গভীর মান কখনও রাউন্ড-ট্রিপ করতে পারে না। flat 64 লেভেল পর্যন্ত সমতল করে এবং অ্যারে বাসা বাঁধলে আরও গভীরে ছুড়ে দেয় — এমন একটি অ্যারে সহ নিজেই
  • একটি কল মেমরি বাজেটের চেয়ে বেশি বরাদ্দ করতে পারে না। repeat, padStart/padEnd, concat এবং replace/replaceAll নিক্ষেপ RangeError: Invalid string length যখন ফলাফল অর্ধেক অতিক্রম করতে পারে অক্ষরে বাজেট (ডিফল্টে 16M 32 MB; একটি regex প্রতিস্থাপন সীমাবদ্ধ থাকে যেন প্রতিটি অবস্থান মিলেছে, যা শুধুমাত্র এক মিলিয়ন বা তার বেশি অক্ষরের স্ট্রিংকে প্রভাবিত করে)। ArrayBuffer এবং টাইপ করা অ্যারে থ্রো RangeError বাইটে বাজেট অতীত, এবং অ্যারে অতীত বাজেট/8 উপাদান প্রত্যাখ্যান করা হয়. আপনার হুক রিটার্ন করার পরে বাজেটও চেক করা হয়, তাই একটি অতিরিক্ত বাজেটের চূড়ান্ত বিবৃতি সফল হওয়ার পরিবর্তে আহ্বানকে ব্যর্থ করে।

দাবা রেফারেন্স স্ক্রিপ্ট তার নথিগুলিকে উদ্দেশ্যমূলকভাবে ছোট রাখে — বাজেটের মধ্যে থাকার উদাহরণ হিসাবে, এর প্রতি-খেলোয়াড় ডক হল

{
  elo: 1200,
  wins: 0, losses: 0, draws: 0,
  lastColorVs: "9b2f8c1a-...",        // for color alternation on rematch
  lastColorOrder: "w",
  recentGames: [ /* up to 30 summaries */ ]
}

সমবর্তী-সেশন ক্যাপ ডিফল্টরূপে প্রতি খেলোয়াড় 20।

প্ল্যাটফর্ম-পঠনযোগ্য উইন্ডো

মধ্যে সবকিছু sessionState প্ল্যাটফর্মে অস্বচ্ছ ছাড়া একটি ক্ষেত্র:

sessionState.summary = {
  turnPlayerId: "7c9e6679-...",
  deadline: 1784642591000,
  status: "active",
  moveCount: 41
};

deadline একটি পূর্ণসংখ্যা ইউনিক্স টাইমস্ট্যাম্প ইন মিলিসেকেন্ড, অথবা কোনো সময়সীমা না থাকলে বাদ দেওয়া হয়। একটি ISO তারিখ স্ট্রিং স্বীকৃত নয়। turnPlayerId প্লেয়ার UUID.

GET /api/v1/games/{slug}/sessions/mine পড়ে summary গণনা করা myTurn এবং deadline কলারের জন্য। প্রতিটি রাষ্ট্র পরিবর্তনের উপর এটি সঠিক রাখুন; আপনার স্ক্রিপ্ট যেখানে পছন্দ করে সেখানে অন্য সবকিছু রাখুন।

কাজের উদাহরণ: দাবা স্ক্রিপ্ট

এই বিভাগের সবকিছুই দাবা রেফারেন্স বাস্তবায়নের জন্য নির্দিষ্ট — রাষ্ট্রের আকার, বোর্ড এনকোডিং, কমান্ড সেট, গেম-ওভারের কারণ, এলো ধ্রুবক, এআই এবং টাইমআউটগুলি হল দাবার নিজস্ব পছন্দ, যা এর স্ক্রিপ্টে সংজ্ঞায়িত করা হয়েছে। এর কোনোটিই প্ল্যাটফর্মের আচরণ নয়; আপনার খেলা তার নিজস্ব সমতুল্য সংজ্ঞায়িত করে.

বোর্ড এনকোডিং: একটি 64-অক্ষরের স্ট্রিং যেখানে index = rank * 8 + file এবং a1 সূচক 0 হয়। PNBRQK সাদা টুকরা, pnbrqk কালো, . একটি খালি বর্গক্ষেত্র।

অন্যান্য দাবা সুনির্দিষ্ট:

  • এলো K=32 ব্যবহার করে, গণনা করা হয় finishGame যখন একটি খেলা শেষ হয়, এবং এর মাধ্যমে ফিরে আসে eloUpdates.
  • এআই প্লে: যখন এআই সিট সরাতে হবে, aiReply নাটক "hal" — একটি লোভী উপাদান-ক্যাপচার ইঞ্জিন — একই আহ্বানের ভিতরে। কোনো বাহ্যিক বট নেই।
  • সময়সীমা: onTick 24-ঘণ্টার মুভ ঘড়ির বিচার করে — যদি কোনও চাল না খেলা হয় তাহলে গেমটি হল a timeout-no-moves আঁকা অন্যথায় সরানো প্লেয়ার দ্বারা হেরে যায় timeout.

স্থাপনা

আপনার গেমের ভান্ডারে স্ক্রিপ্টটি ঘোষণা করুন starhermit.txt প্রকাশ:

server=server.js

GitHub ইন্টিগ্রেশনের মাধ্যমে প্রকাশনা প্রবাহিত হয় — দেখুন গিটহাব গেমস. প্ল্যাটফর্মটি নথিভুক্ত বাজেটের মধ্যে স্ক্রিপ্টটি কার্যকর করে। একত্রিত করবেন না server= সঙ্গে container.image=; ব্যবহার করুন ধারক রানটাইম পরিবর্তে একটি ছবি শিপিং যখন.

সর্বোত্তম অনুশীলন

  • প্রতিটি আদেশ যাচাই করুন. চিকিৎসা ctx.message.data প্রতিকূল হিসাবে: স্পর্শ করার আগে প্রকার, রেঞ্জ, টার্ন অর্ডার এবং গেমের স্থিতি পরীক্ষা করুন।
  • আমন্ত্রণ দ্রুত রাখুন এবং ছোট করুন। আপনার প্রতি প্লেয়ার ডক ~250 ms এবং একটি বাইট বাজেট আছে; দাবা রেফারেন্স স্ক্রিপ্ট, উদাহরণস্বরূপ, ক্যাপস recentGames এই কারণে 30টি এন্ট্রিতে।
  • ব্যবহার করুন ctx.now / ctx.random শুধুমাত্র না Date, না Math.random — হোস্ট ঘড়ি এবং পাশা মালিক.
  • ডিজাইন broadcast শুধুমাত্র ক্লায়েন্ট চুক্তি হিসাবে বার্তা. স্ক্রিপ্ট যা পাঠায় তা থেকে ক্লায়েন্টদের অবশ্যই পুরো গেমটি রেন্ডার করতে সক্ষম হতে হবে; সম্প্রচার না করা কিছু তাদের জন্য বিদ্যমান নেই.
  • একটি ফাইল, দুটি সারফেস। একই ফাইল একটি পৃথক রপ্তানির মাধ্যমে ক্লায়েন্ট-সাইড নিয়ম হিসাবে দ্বিগুণ হতে পারে: দাবা রেফারেন্স বাস্তবায়ন, উদাহরণস্বরূপ, প্রকাশ করে globalThis.chessRules ব্রাউজারের জন্য (প্রিভিউ সরান, বৈধতা ইঙ্গিত) এবং globalThis.game হোস্টের জন্য। সত্যের একটি উৎস, ক্লায়েন্টের উপর শূন্য কর্তৃত্ব।
  • সর্বদা এর মাধ্যমে গেমস শেষ করুন result তাই প্ল্যাটফর্মটি Elo আপডেট প্রকাশ করে এবং আপনার গেমের রিপ্লে আর্কাইভ করে রিপ্লে.

দেখুন দাবা ওয়াকথ্রু একটি লাইন-বাই-লাইন সফরের জন্য, এবং এআই প্রম্পট আপনার নিজের স্ক্রিপ্ট তৈরি করতে সাহায্যের জন্য।

শেয়ার করা হয়েছে এপিআই কনভেনশন রেসপন্স পার্সিং, টাইমস্ট্যাম্প, পেজিনেশন এবং পুনঃপ্রচেষ্টা বর্ণনা করুন।
