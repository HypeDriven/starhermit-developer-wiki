গিটহাব গেমস

একটি GitHub সংগ্রহস্থল থেকে একটি গেম প্রকাশ করুন স্টার হার্মিট, অথবা ইতিমধ্যেই হোস্ট করা একটি ওয়েব গেম নিবন্ধন করুন৷ সংগ্রহস্থল গেমগুলির জন্য, প্ল্যাটফর্মটি পড়ে starhermit.txt, রেপো ক্লোন করে এবং এটি পরিবেশন করে <slug>.starhermit.com. কারণ /api এবং /ws একটি প্ল্যাটফর্ম-হোস্ট করা গেমের প্রয়োজন সেই সাবডোমেন থেকে প্রক্সি-অরিজিন কোন CORS বা API-বেস কনফিগারেশন নেই. একটি পিন করা কমিট নিয়ন্ত্রণ করে কোন সংগ্রহস্থলের সংস্করণটি লাইভ। দ দাবা রেফারেন্স বাস্তবায়ন এইভাবে প্রকাশিত হয় এবং মডেলের রেফারেন্স উদাহরণ হিসাবে কাজ করে।

ভিত্তি URL: https://api.starhermit.com. সব রুট অধীনে আছে api/v1/... এবং একটি JWT প্রয়োজন যদি না উল্লেখ করা হয়।

হোস্ট করা ক্লায়েন্ট ফাইল ঘোষণা করতে পারেন ফোল্ডার ক্যাশে জীবনকাল এবং অতিরিক্ত CORS উত্স মধ্যে starhermit.txt. সেই নীতিগুলি ক্লায়েন্ট ফাইলগুলির সাথে প্রকাশ করে; একটি ম্যানিফেস্ট-মুক্ত মার্জ ধরে রাখে বিদ্যমান সেটিংস, যখন একটি সরবরাহকৃত ম্যানিফেস্ট তাদের প্রতিস্থাপন করে।

ম্যানিফেস্ট: starhermit.txt

স্থান starhermit.txt রেপো রুটে। বিন্যাস: key=value লাইন, # একটি মন্তব্য শুরু করে।

name=Your Game
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html        # repo-relative HTML entry
cover=art/cover.png      # optional cover art for the library tile; or an https:// URL
description=One-line pitch\nSecond line   # optional; or description.file=DESCRIPTION.md
release_notes.file=CHANGELOG.md          # optional; or release_notes=inline text
owner=<starhermit user id>  # UUID from GET /api/v1/me; do not use username/nickname
# Choose at most one authoritative backend, or omit both for a browser-only game:
server=server.js         # sandboxed JavaScript; see game-scripts.md
# container.image=ghcr.io/owner/game@sha256:<64 lowercase hex>; see container-games.md

control.up=KeyW+ArrowUp | Move forward
control.shoot=Space | Shoot
  • নেই slug কী: প্ল্যাটফর্মটি একটি uid বরাদ্দ করে এবং উভয়ই সাবডোমেন হিসাবে ব্যবহার করে (<uid>.starhermit.com) এবং গেম API নামস্থান (/api/v1/games/<uid>/…).
  • cover (উপানাপগুলি cover_art, coverart) হল গেমের লাইব্রেরি টাইলে দেখানো আর্টওয়ার্ক: লঞ্চ ফাইলের সাথে সম্পর্কিত একটি পথ, বা একটি পরম https:// URL ঐচ্ছিক — একটি ছাড়া টাইল আপনার সাইটের ফেভিকন দেখায়। প্রতিটি স্থাপনায় পুনরায় পড়ুন, তাই লাইন পরিবর্তন করলে কভার পরিবর্তন হয়। দেখুন কভার আর্ট টালি ফসল জন্য.
  • description / release_notes (বা description.file / release_notes.file, কোন নাম a .md/.markdown/.txt ম্যানিফেস্টের সাথে সম্পর্কিত ফাইল) আপনার গেমের জন্য ঐচ্ছিক পাঠ্য। তারা প্রতিটি স্থাপন মত পুনরায় পড়া হয় cover. দেখুন বর্ণনা এবং রিলিজ নোট.
  • server একটি স্যান্ডবক্সযুক্ত জাভাস্ক্রিপ্ট ব্যাকএন্ড ঘোষণা করে; দেখুন game-scripts.md.
  • container.image একটি ধারক ব্যাকএন্ড ঘোষণা করে; দেখুন container-games.md. এটি অবশ্যই ডাইজেস্ট-পিন করা, অনুমোদিত তালিকাভুক্ত রেজিস্ট্রিতে যাচাইকৃত GitHub মালিকের নামস্থানে হোস্ট করা এবং এর সাথে থাকতে পারে container.port, container.health, container.memory_mb, container.cpu, এবং অ গোপন container.env.* মান
  • উভয় ব্যাকএন্ড কী একটি বিশুদ্ধ ব্রাউজার গেমের জন্য ঐচ্ছিক, কিন্তু তারা একে অপরের সাথে পারস্পরিকভাবে একচেটিয়া।

ডিফল্ট নিয়ন্ত্রণ বাঁধাই

একটি গেম শূন্য বা তার বেশি ডেস্কটপ-ব্রাউজার অ্যাকশন ঘোষণা করতে পারে:

control.<action>=<code>[+<code>...][ | <label>]
  • ক্রিয়াগুলি ছোট হাতের অক্ষর [a-z0-9_]{1,32} আইডেন্টিফায়ার এবং ম্যানিফেস্ট অর্ডার বজায় রাখুন।
  • কোডগুলো হল KeyboardEvent.code মান + একটি কর্মের জন্য বিকল্প কী আলাদা করে।
  • ঐচ্ছিক লেবেলটি কন্ট্রোল-রিম্যাপিং UI এবং অ্যাকশন আইডিতে ডিফল্ট দেখানো হয়।
  • একটি ম্যানিফেস্ট 32টি অ্যাকশন এবং 4টি কোড প্রতি অ্যাকশন ঘোষণা করতে পারে। একটি কোড দ্বারা ব্যবহার করা যাবে না দুটি কর্ম। অবৈধ নিয়ন্ত্রণ লাইন উপেক্ষা করা হয়.
  • কোন সঙ্গে গেম control.* ঘোষণার কোনো নিয়ন্ত্রণ নেই API/UI (404 "This game declares no controls.") প্রতিটি প্রকাশিত বিল্ড থেকে ঘোষণাগুলি পুনরায় পড়া হয় — প্রতিটি স্থাপন, ফোল্ডার আপলোড৷ এবং বান্ডিল পুশ প্রতিস্থাপন। ধাপে ধাপে: টিউটোরিয়াল: আপনার গেমে নিয়ন্ত্রণ যোগ করুন.

খেলোয়াড়রা খেলা প্রতি এই ডিফল্টগুলিকে এর মাধ্যমে ওভাররাইড করতে পারে গেম এপিআই নিয়ন্ত্রণ করে.

একটি খেলা নিবন্ধন

POST /api/v1/me/github-games

{
  "repoUrl": "https://github.com/HypeDriven/starhermit-chess",
  "displayName": "StarHermit Chess",
  "launchPath": "index.html"
}

ঐতিহাসিক নাম সত্ত্বেও, repoUrl তিনটি লঞ্চ উত্স গ্রহণ করে:

  1. A github.com/<owner>/<repo> ভান্ডার ব্যাকএন্ড তার ম্যানিফেস্ট পড়ে এবং এটি স্থাপন করতে পারে StarHermit হোস্টিং-এ।
  2. একটি ইতিমধ্যে-হোস্ট করা GitHub পেজ URL যেমন https://owner.github.io/game/. ভান্ডার ইউআরএল থেকে পরিচয় অনুমান করা হয়; URL নিজেই চালু করা হয়েছে, কোন ক্লোন বা ইনস্টল ছাড়াই।
  3. অন্য কোনো পাবলিক http:// বা https:// হোস্ট করা ওয়েব-গেম URL। এটি সরাসরি চালু করা হয় এবং GitHub মালিকানা দাবিতে অংশগ্রহণ করে না।
  • displayName এবং launchPath ঐচ্ছিক ফলব্যাক। তারা একটি তৃতীয় পক্ষের রেপো জন্য দরকারী বিশ্বস্ত ম্যানিফেস্ট মেটাডেটা ছাড়া; একটি সরাসরি হোস্ট করা URL নিজেই লঞ্চ অবস্থান.
  • যাচাইকৃত সংগ্রহস্থলের মালিকদের জন্য প্ল্যাটফর্মটি যাচাই করে starhermit.txt.
  • একটি ঐচ্ছিক server= স্ক্রিপ্ট বা container.image= ব্যাকএন্ড বিধান একটি প্রামাণিক খেলা; দেখুন game-scripts.md এবং container-games.md. starhermit.com-এ যে কোনো সাইন-ইন করা ব্যবহারকারীর জন্য কন্টেইনার হোস্টিং উন্মুক্ত; একটি স্ব-হোস্টেড স্থাপনা এটিকে একটি অপারেটর অনুমোদিত তালিকার মধ্যে সীমাবদ্ধ করতে পারে।
  • একটি ঘোষিত সার্ভার ব্যাকএন্ড একজন প্রমাণিত মালিকের প্রয়োজন৷ একটি রেপো জমা দেওয়া যা ঘোষণা করে server= বা container.image= GitHub-লগইন ছাড়া বা owner= প্রমাণ হল 403 (উভয় প্রমাণের নামকরণ), একটি ব্রাউজার-শুধুমাত্র তালিকা নয় যা একটি ব্যাকএন্ড থাকার ভান করে।
  • সীমা: ব্যবহারকারী প্রতি 100টি গেম (প্রতি অ্যাকাউন্ট অপারেটর-ওভাররিডেবল)। একটি ডুপ্লিকেট রিটার্ন নিবন্ধন 409.

নিবন্ধন/স্থাপনের অবস্থার মধ্যে রয়েছে: InvalidUrl, LimitReached, Duplicate, MissingManualMetadata, MissingStarhermitTxt, InvalidLaunchPath, InvalidServerScriptPath, InvalidContainerImage, ServerProvisionConflict, RemovedByOwner.

ত্রুটিগুলি আদর্শ আকৃতি ব্যবহার করে:

{ "error": "..." }

একটি স্থানীয় ফোল্ডার থেকে একটি খেলা যোগ করুন

POST /api/v1/me/github-games/upload → 201

একটি URL নিবন্ধনের প্রতিপক্ষ: কোন ভান্ডার নেই, এবং কিছুই ক্লোন করা হয় না। ফোল্ডার এক হিসাবে ভ্রমণ .tar.gz অনুরোধের অংশে এবং প্ল্যাটফর্মে যা আছে তা হোস্ট করে। একই সংরক্ষণাগার হিসাবে বিন্যাস একটি বান্ডিল ঠেলাঠেলি, তাই একই প্যাকেজিং উভয়ের জন্য কাজ করে।

তৈরি গেমটিতে একটি রয়েছে gameSlug শুরু থেকে, এটি একটি সার্ভার ঘোষণা করে কি না, তাই একটি ব্রাউজার শুধুমাত্র আপলোড ব্যবহার করতে পারেন নিয়ন্ত্রণ করে, প্রতি-প্লেয়ার সেটিংস, এর ক্লাউড-সেভ স্লট, রিয়েলটাইম রুম এবং অন্য গেমের মতো টোকেন চালু করুন।

client/           the game's files, published as-is
starhermit.txt    name= and launch= instead of the query parameters

ম্যানিফেস্টটি ঐচ্ছিক এই শেষ বিন্দু — ক্যোয়ারী প্যারামিটার একই মান সরবরাহ করতে পারে — এবং StarHermit ক্লায়েন্টরা সবসময় একটি পাঠায়, যা তাদের ম্যানিফেস্ট ফিল্ড থেকে তৈরি করা হয়। ভিতরে ফাইল শিপিং আপনার বিল্ড এখনও করার উপযুক্ত কোন মানগুলির প্রয়োজন তা মনে না রেখে পুনরায় আপলোড করা যেতে পারে। দেখুন দ starhermit.txt প্রকাশ বিন্যাসের জন্য, এবং নোট করুন যে সবকিছু ম্যানিফেস্ট সংলগ্ন আপলোড করা হয় — একটি বিতরণযোগ্য বিল্ড আপলোড করুন, উত্স ট্রি নয়।

বাইট সরাসরি পাঠান — মাল্টিপার্ট ফর্ম ডেটা নয় — সঙ্গে Content-Type: application/gzip:

tar -czf game.tar.gz client/ starhermit.txt

curl -X POST "https://api.starhermit.com/api/v1/me/github-games/upload?displayName=My%20Game" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/gzip" \
  --data-binary @game.tar.gz

{
  "game": { "id": "...", "displayName": "My Game", "launchPath": "index.html", "hosting": { "hostingEnabled": true } },
  "bytesReceived": 4194304
}

মেটাডেটা এই ক্রমে সমাধান করে, তাই বেশিরভাগ ফোল্ডারের জন্য কোনও ক্যোয়ারী প্যারামিটারের প্রয়োজন নেই:

  1. ?displayName= / ?launchPath= অনুরোধে
  2. name= / launch= এ starhermit.txt আর্কাইভ রুটে।
  3. index.html এর মূলে client/ — লঞ্চ পথ হিসাবে ব্যবহৃত হয় যখন অন্য কিছুর নাম থাকে না।

এই রুটের জন্য নির্দিষ্ট নোট:

  • কল রিটার্নের সাথে সাথে গেমটি লাইভ হয়। কোন আলাদা হোস্টিং বা স্থাপনা নেই পদক্ষেপ: deployStatus হয় live এবং deployedCommitSha হয় null, কারণ কোন প্রতিশ্রুতি নেই.
  • ফাইল পুনরায় তৈরি করা যাবে না, তাই প্ল্যাটফর্ম কোথাও থেকে তাদের পুনরায় স্থাপন করে না। একটি খেলা এই ভাবে বহন যোগ contentSource: upload এবং আপনি প্রকাশ না করা পর্যন্ত আপলোড করা বিল্ড ধরে রাখে আরেকটি সঙ্গে একটি নতুন নির্মাণ ধাক্কা বান্ডিল শেষ বিন্দু অথবা ফোল্ডারটি আবার আপলোড করুন।
  • কোন ভান্ডার মানে কোন দাবি নেই। ownerLogin খালি, তাই কোন GitHub লগইন এটির সাথে মেলে না; repoUrl একটি সিন্থেটিক বহন করে upload:<id> একটি URL এর পরিবর্তে মান।
  • A server/image.tar এখানে প্রত্যাখ্যান করা হয় (422) একটি সার্ভার ইমেজ একটি প্রভিশন করা খেলা প্রয়োজন সংযুক্ত করুন, যা গেমটি না হওয়া পর্যন্ত বিদ্যমান নেই — প্রথমে গেমটি তৈরি করুন, তারপর চিত্রটি পুশ করুন থেকে /{id}/bundle.
  • সংরক্ষণাগারে নেই এমন একটি ফাইলের নামকরণের একটি লঞ্চ পথ প্রত্যাখ্যান করা হয়েছে (422) আপলোড করার সময় প্রতিটি খেলোয়াড়ের জন্য 404 হওয়ার পরিবর্তে এখনও মঞ্চে রয়েছে।

সীমা অন্য কোনো ধাক্কা হিসাবে একই: দেখুন আপলোড সীমা.

একটি আপলোড করা ফোল্ডার তার নিজস্ব সার্ভার ব্যাকএন্ড আনতে পারে

যদি সংরক্ষণাগার এর starhermit.txt সার্ভার লজিক, আপলোড ঘোষণা করে এটিকেও প্রভিশন করে — রিপোজিটরি ফ্লো একই জিনিস করে, রিপোজিটরি ছাড়াই। একটা বেছে নিন শৈলী; উভয় ঘোষণা প্রত্যাখ্যান করা হয়.

ঘোষণা কি হয়
server=path/to/server.js একটি স্ক্রিপ্ট ব্যাকএন্ড। ফাইল ঘুরছে আপনার আপলোড করা ফোল্ডারের ভিতরে, তাই এর উৎস সরাসরি আর্কাইভ থেকে পড়া হয় — আনার কিছু নেই। দেখুন game-scripts.md.
container.image=name@sha256:… একটি ধারক ব্যাকএন্ড, বরাবরের মতো ডাইজেস্ট-পিন করা। দেখুন container-games.md. ইমেজ নিজেই পরে ধাক্কা হয় /{id}/bundle.

এখানে প্রত্যাখ্যান পুরো তৈরি করতে ব্যর্থ হয় — কোনো অর্ধ-তৈরি খেলা সারি একটি টিকে থাকে না:

  • server= সংরক্ষণাগার ধারণ করে না এমন একটি ফাইলের নামকরণ।
  • server= ক্লায়েন্ট ফাইলের বাইরে নির্দেশ করা (../).
  • উভয় ঘোষণা server= এবং container.image=.
  • একটি পাত্রের জন্য জিজ্ঞাসা করা যেখানে কন্টেইনারগুলি অক্ষম করা হয়েছে, বা তাদের জন্য অনুমোদিত নয় এমন মালিকের কাছ থেকে।

কভার আর্ট

লাইব্রেরিতে আপনার গেমের টাইলে দেখানো ছবিটি। যেকোন উপায়ে এটি সেট করুন — আপনি যেটিই ব্যবহার করুন না কেন বেনামী GET /api/v1/github-games/{id}/cover যা এটি পরিবেশন করে:

  • আপনার বিল্ডে — a cover= লাইন starhermit.txt, লঞ্চের সাথে সম্পর্কিত একটি চিত্রের নামকরণ ফাইল বা একটি পরম https:// URL প্রতিটি স্থাপনার উপর পুনরায় পড়ুন, তাই আপনার সংগ্রহস্থল সত্যের উৎস থেকে যায়।
  • আপলোড করা হয়েছে — PUT /api/v1/me/github-games/{id}/cover বেস64-এনকোডেড ইমেজ সহ। এই ওয়েব ড্যাশবোর্ড কি পরিচালনা → কভার আর্ট করে, এবং একজন StarHermit অপারেটর আপনার জন্য কি করতে পারে।
PUT /api/v1/me/github-games/{id}/cover
Authorization: Bearer <token>
Content-Type: application/json

{ "imageBase64": "iVBORw0KGgoAAAANSUhEUg..." }

একটি আপলোড ওভাররাইড করে ম্যানিফেস্ট, ইচ্ছাকৃতভাবে: একটি স্থাপনা যা পুনরায় পড়ে starhermit.txt আবশ্যক হাত দ্বারা নির্বাচিত শিল্প কখনও পূর্বাবস্থায় না. DELETE /api/v1/me/github-games/{id}/cover ফেরার পথ- এটি আপলোড এবং ম্যানিফেস্টের ড্রপ করে cover= আবার প্রযোজ্য।

PNG, JPEG, GIF, WEBP, BMP বা SVG, পর্যন্ত 4 এমবি. টাইপ বাইট থেকে sniffed হয়, তাই একটি Content-Type আপনি দাবি করেন না প্রয়োজন বা বিশ্বাস করা হয় না, এবং বাইট যা একটি ডিকোডেবল ইমেজ নয় সঙ্গে প্রত্যাখ্যান করা হয় 400. একজন আত্মীয় cover= পথ শেষ করতে হবে .png, .jpg/.jpeg, .gif, .webp বা .svg (না .., কোন নেতৃস্থানীয় /); একটি অব্যবহারযোগ্য মান ব্যর্থ হওয়ার পরিবর্তে বাদ দেওয়া হয় খেলা

কভার আর্ট পোস্টার আর্ট: উভয় লাইব্রেরি টালি এবং কেন্দ্র-ফসল পূরণ করার জন্য এটি স্কেল করুন যাই হোক না কেন ফিট না টাইলস একই আকৃতি হয় না.

আপনি যখন এটির সংগ্রহস্থল নিয়ন্ত্রণ করেন তখন একটি বিদ্যমান তালিকা গ্রহণ করুন। লিঙ্ক করে মালিকানা প্রমাণ করুন ব্যক্তিগত GitHub লগইন রিপোজিটরি মালিকের সাথে মিলছে, বা প্রতিশ্রুতি দ্বারা owner=<your StarHermit user ID> ভান্ডারের কাছে starhermit.txt. owner হওয়া উচিত অপরিবর্তনীয় UUID হিসাবে ফিরে এসেছে id দ্বারা GET /api/v1/me, না একটি ব্যবহারকারীর নাম বা ডাকনাম। প্রকাশ পদ্ধতিটি সংস্থার মালিকানাধীন সংগ্রহস্থলগুলিকে সমর্থন করে, যা ব্যক্তিগত GitHub org থেকে অনুমান করা হয় না সদস্যপদ

সফল হলে, বিদ্যমান তালিকাটি তার আইডি/ইতিহাস রাখে, দাবিদার দ্বারা পরিচালিত হয়, রিফ্রেশ করে রিপোজিটরি-নিয়ন্ত্রিত মেটাডেটা এবং ব্যাকএন্ড ঘোষণা, এবং সারি হোস্টিং যেখানে উপলব্ধ। দ পূর্ববর্তী জমাকারী মালিক-স্কোপের ব্যবস্থাপনা অ্যাক্সেস হারায়। আপনি ইতিমধ্যেই পরিচালনা করছেন এমন একটি তালিকা দাবি করা একটি দ্বন্দ্ব ফিরিয়ে দেওয়ার পরিবর্তে এটিকে পুনরায় সিঙ্ক্রোনাইজ করে।

GitHub পরিচয় মেটাডেটা স্টোর {"login":"…"}; OAuth প্রবাহের মাধ্যমে আপনার GitHub অ্যাকাউন্ট লিঙ্ক করুন (দেখুন auth.md) সাথে লিঙ্ক স্ট্যাটাস চেক করুন GET /api/v1/me/github → { linked, login }. দেখুন ধাপে ধাপে দাবি করার টিউটোরিয়াল আবিষ্কারের জন্য, উভয় প্রমাণ পদ্ধতি, বৈধতা, টেকওভার, এবং সমস্যা সমাধান।

একটি খেলা বান্ডিল ধাক্কা

POST /api/v1/me/github-games/{id}/bundle StarHermit কে জিজ্ঞাসা না করেই বিল্ট আউটপুট প্রকাশ করে আবার ক্লোন করুন। কলারের অবশ্যই নিবন্ধিত গেমের মালিক হতে হবে। পাঠান .tar.gz বাইট সরাসরি-না মাল্টিপার্ট ফর্ম ডেটা—সহ Content-Type: application/gzip:

client/            optional static client files; must include the registered launch file
server/image.tar   optional output from `docker save`
starhermit.txt     optional manifest copy for bundle portability
remove.txt         merge only: client-relative paths to delete, one per line

অন্তত client/ বা server/image.tar উপস্থিত থাকতে হবে (একটি মার্জ শুধুমাত্র হতে পারে remove.txt) ক্লায়েন্ট ফাইলগুলি পারমাণবিকভাবে অদলবদল করা হয়। ক সার্ভার ইমেজ লোড করা হয়, প্ল্যাটফর্ম দ্বারা ডাইজেস্ট-পিন করা হয় এবং কন্টেইনার স্থাপনাকে সারিবদ্ধ করে সেই ছবিতে পুনরায় আরম্ভ করুন। একটি আপলোড করা ছবি ম্যানিফেস্টের রেজিস্ট্রি রেফারেন্সের উপর প্রাধান্য পায়, এবং একটি উপর server= লাইন একটি ম্যানিফেস্ট উভয় ঘোষণা করে server= এবং container.image= প্রত্যাখ্যান করা হয় কিছু লোড হওয়ার আগে। আর্কাইভের অন্য কিছু উপেক্ষা করা হয়।

একটি ছবি আপলোড নিজেই ঘোষণা. যদি গেমটির এখনও কোনো সার্ভার ব্যাকএন্ড না থাকে — একটি আপলোড করা ফোল্ডার যা কোনোটিই না ঘোষণা করেছে — ঠেলে দিচ্ছে server/image.tar শুধু ডাইজেস্ট থেকে বিধান এক লোড, অধীনে gameSlug খেলা ইতিমধ্যে আছে. আপনি a তে একটি ডাইজেস্ট-পিন করা চিত্রের নাম দিতে হবে না প্রথমে ম্যানিফেস্ট, যা বৃত্তাকার ছিল: সংজ্ঞাটি একটি চিত্র পাওয়ার আগে বিদ্যমান ছিল, এবং ইমেজ ছিল একমাত্র জিনিস যা এটি বর্ণনা করতে পারে।

একটি পুনরায় ধাক্কা প্রযোজ্য ধারক knobs তার প্রকাশ ঘোষণা করে, এবং শুধুমাত্র যারা. অন্তর্ভুক্ত করুন starhermit.txt একটি পরিবর্তন সঙ্গে বান্ডিল মধ্যে container.port, container.health, container.memory_mb বা container.cpu এবং স্থাপনা পুনরায় চালু হলে তা তুলে নেয়; একটি গাঁট আউট ছেড়ে এবং আপনি গতবার সেট করা যাই হোক না কেন এটি রাখে। সম্পূর্ণরূপে ম্যানিফেস্ট বাদ দিন এবং স্থাপনার বিষয়ে কিছুই করবেন না ছবি ছাড়া পরিবর্তন.

StarHermit ক্লায়েন্টরা একটি ফোল্ডার থেকে আপনার জন্য এই বান্ডিলটি তৈরি করে বা একক .tar:

  • ক্লায়েন্ট ফাইল — গেমের ডিস্ট্রিবিউশন ফোল্ডার, অথবা a .tar এর একটি ফোল্ডার অধীনে প্যাক করা হয় client/; a .tarএর এন্ট্রিগুলি সেখানে পুনরায় স্থাপন করা হয়েছে (ইতিমধ্যে একটি সংরক্ষণাগার অধীনে রয়েছে client/ বাকি আছে একা)। শুধুমাত্র ustar — GNU দীর্ঘ-নাম এবং PAX সংরক্ষণাগারগুলি প্রত্যাখ্যান করা হয়েছে, কারণ তাদের পুনরায় হোম করার অর্থ হল নিম্নলিখিত এন্ট্রির নাম দেওয়া মেটাডেটা ব্লকগুলিকে পুনরায় লেখা।
  • ডেডিকেটেড সার্ভার — সার্ভারের বিতরণ ফোল্ডার, বা docker save .tar নিজে থেকে একটি ফোল্ডার থেকে শুধুমাত্র ম্যানিফেস্ট এবং image.tar আপলোড করা হয়েছে: ইমেজ ইতিমধ্যে আপনার রয়েছে সার্ভারের নিজস্ব ফাইল, তাই বাকিগুলি প্যাক করা প্ল্যাটফর্মটিকে বাতিল করার জন্য গিগাবাইট পাঠাবে।

উভয় ক্ষেত্রেই starhermit.txt ডায়ালগে সম্পাদনাযোগ্য। যাই হোক না কেন বাছাই করা বিল্ড ক্ষেত্রগুলিকে প্রিফিল করে, এবং তারা যা কিছু ধরে তা বান্ডেল রুটে লেখা হয় — তাই কোন ম্যানিফেস্ট ছাড়া একটি বিল্ড প্রকাশযোগ্য, এবং একটি যে একটি হিসাবে জাহাজ .tar এখনও এর প্রকাশ থাকতে পারে আপডেট করা হয়েছে

আংশিক আপডেট: ?mode=merge

একটি ধাক্কা একটি প্রতিস্থাপন যদি না আপনি অন্যথায় জিজ্ঞাসা করেন: সংরক্ষণাগার পুরো খেলা, এবং কিছু নেই এটা চলে গেছে ?mode=merge (HTTP এবং আপলোড সকেট একইভাবে) এটি একটি করে প্যাচ লাইভ ক্লায়েন্ট এর ফাইলগুলি — এক-ফাইল ফিক্সের জন্য অপরিবর্তিত সম্পদের গিগাবাইট পুনরায় আপলোড করার উত্তর৷

printf '%s\n' '# one client-relative path per line; a directory removes everything under it' \
    'assets/old-music.ogg' 'levels/cut/' > remove.txt
tar czf patch.tar.gz client/index.html client/js/app.js remove.txt

curl -X POST "https://api.starhermit.com/api/v1/me/github-games/$GAME_ID/bundle?mode=merge" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/gzip" \
  --data-binary @patch.tar.gz

সঙ্গে mode=merge:

  • অধীনে ফাইল client/ যোগ করা বা ওভাররাইট করা হয়
  • একটি রুট মধ্যে পাথ remove.txt (# মন্তব্য একটি ডিরেক্টরি তার পুরো সাবট্রি মুছে ফেলে) মুছে ফেলা হয়
  • প্রতিটি অন্য লাইভ ফাইল ঠিক যেমন আছে

একত্রিত গাছটিকে একটি অনুলিপি হিসাবে মঞ্চস্থ করা হয় এবং পারমাণবিকভাবে অদলবদল করা হয় — খেলোয়াড়রা পুরানো খেলা বা সম্পূর্ণ নতুন, কখনও মিশ্রিত নয়। ফলাফল দ্বারা আবদ্ধ হয় খেলা ভাতা, আপলোড এর না, তাই একটি গেম একবারে একটি ছোট প্যাচের সীমা অতিক্রম করতে পারে না। একটি মার্জ শুধুমাত্র ক্লায়েন্ট ফাইল সম্পর্কে; ক server/image.tar একটি প্রতিস্থাপন হিসাবে ঠিক লোড করা হয়. একটি প্যাচ নং বহন starhermit.txt পাতা কভার শিল্প যেমন ছিল.

একটি মার্জ প্রত্যাখ্যান করা হয়েছে (409/422, কিছুই পরিবর্তন হয় না) যখন গেমটি এখনও প্রকাশিত হয়নি, কখন এটি লঞ্চ ফাইল মুছে ফেলবে, বা কখন remove.txt খেলার বাইরে পয়েন্ট। ক remove.txt এ প্লেইন প্রতিস্থাপনও প্রত্যাখ্যান করা হয় (422), কারণ সেখানে এটি শুধুমাত্র এমন কিছু বোঝাতে পারে যা আপনি করেননি উদ্দেশ্য mode হতে হবে replace (ডিফল্ট) বা merge; অন্য কিছু হয় 400.

একই পরামিতি সকেটে কাজ করে: ws/v1/game-upload?gameId=…&mode=merge. দ ready ফ্রেম এটা হিসাবে প্রতিধ্বনিত "apply":"merge".

শেষ পয়েন্ট একটি বিদ্যমান নিবন্ধিত খেলা আপডেট করে; এটি কখনই গেমের রেকর্ড তৈরি করে না - এর জন্য, দেখুন একটি স্থানীয় ফোল্ডার থেকে একটি গেম যোগ করা. এটা পারে খেলার ব্যবস্থা করুন সার্ভার ব্যাকএন্ড, একটি গেমে একটি সার্ভার ইমেজ লোড করার একটি পার্শ্ব প্রতিক্রিয়া হিসাবে যা কিছুই ছিল না। দেখুন ডেডিকেটেড-সার্ভার প্রকাশনা টিউটোরিয়াল.

CI/CD থেকে আপলোড করুন

একটি রিপোজিটরি গোপনে একটি ইন্টারেক্টিভ OAuth টোকেন রাখবেন না। একবার OAuth এর মাধ্যমে সাইন ইন করুন এবং ব্যবহার করুন একটি পৃথকভাবে লেবেলযুক্ত স্থাপনার কী যোগ করার জন্য সেই সেশন POST /api/v1/me/public-keys. সি.আই চাকরি তখন স্বাক্ষর করতে পারে /auth/public-key/challenge, এটা বিনিময় /auth/public-key/complete, এবং ব্যবহার করুন এই বান্ডেল এন্ডপয়েন্টে 15-মিনিটের অ্যাক্সেস টোকেন ফেরত দেওয়া হয়েছে।

স্থাপনার কী তার মালিকানা হিসাবে কাজ করে, তাই সেই অ্যাকাউন্টটি অবশ্যই লক্ষ্য গেমের মালিক হতে হবে। এটা পারে না অন্য কী যোগ করুন বা অন্য কী প্রত্যাহার করুন। এটা মাধ্যমে নিজেকে প্রত্যাহার করতে পারেন /me/public-keys/current; একটি OAuth-প্রমাণিত সেশন থেকে তালিকাভুক্তি এবং অন্যান্য কীগুলি পরিচালনা করুন। প্রতি একটি কী ব্যবহার করুন পরিবেশ যাতে একটি ওয়ার্কফ্লো অন্যকে না থামিয়ে অক্ষম করা যায়। মোটামুটি উপর আর্কাইভ 100 MB অবশ্যই নীচের WebSocket পরিবহন ব্যবহার করুন৷

দেখুন একটি OAuth-ভুক্ত পাবলিক কী সহ CI/CD থেকে বিল্ড আপলোড করুন মূল প্রজন্মের জন্য, GitHub গোপন সেটআপ, একটি সম্পূর্ণ চ্যালেঞ্জ-সাইনিং/আপলোডার স্ক্রিপ্ট, স্ট্যাটিক এবং কন্টেইনার বান্ডিল লেআউট এবং একটি গিটহাব অ্যাকশন ওয়ার্কফ্লো।

একটি WebSocket উপর আপলোড

GET /ws/v1/game-upload (আপগ্রেড) — প্রায় 100 MB এর বেশি কিছুর জন্য এটি ব্যবহার করুন।

API এর সামনে থাকা CDN মোটামুটিভাবে একটি HTTP অনুরোধ বডি প্রত্যাখ্যান করে 100 MB সঙ্গে a 413 এর নিজস্ব সেই প্রত্যাখ্যান কখনই প্ল্যাটফর্মে পৌঁছায় না, তাই এটি বহন করে না limitBytes এবং কোন লগ আপনি প্রদর্শিত হবে পড়তে পারেন — ক 413 সঙ্গে নেই limitBytes ক্ষেত্র হল CDN, আপনার গেমের ভাতা নয়, যা দুটি বড় আকারের আদেশ. যেকোন বাস্তবসম্মত docker save এটা আঘাত করা হবে.

WebSocket আপগ্রেড করার পরে পাঠানো ফ্রেমগুলি একটি অনুরোধের অংশ নয়, তাই সিলিং প্রযোজ্য নয়৷ শুধু পরিবহন পার্থক্য. বাইনারি ফ্রেমগুলি এইচটিটিপি রুটগুলির ঠিক বাইটগুলিতে সংযুক্ত হয়৷ পড়ুন, একই পাইপলাইনের মধ্য দিয়ে যান, এবং প্রতিটি প্রত্যাখ্যান, ভাতা এবং সাফল্যের মূল অংশ হল HTTP রুট উত্পাদিত হবে - যাতে একটি ক্লায়েন্ট উভয় জুড়ে একটি কোড পাথ ভাগ করতে পারে।

wss://api.starhermit.com/ws/v1/game-upload?gameId=$GAME_ID&access_token=$TOKEN
wss://api.starhermit.com/ws/v1/game-upload?gameId=$GAME_ID&mode=merge&access_token=$TOKEN
wss://api.starhermit.com/ws/v1/game-upload?displayName=My%20Game&launchPath=index.html&access_token=$TOKEN

পাস gameId আপনার মালিকানাধীন একটি খেলায় ঠেলে দিতে ( /{id}/bundle রুট); এটা বাদ দিন এবং পাস করুন displayName/launchPath একটি ফোল্ডার থেকে একটি তৈরি করতে ( /upload রুট)। টোকেন যায় ক্যোয়ারী স্ট্রিং কারণ একটি ব্রাউজার একটি সেট করতে পারে না Authorization একটি WebSocket হ্যান্ডশেকের শিরোনাম; এটা হ্যান্ডশেকের সময় একবার চেক করা হয়েছে, তাই একটি আপলোড যা তার অ্যাক্সেস টোকেনকে ছাড়িয়ে যায় তা এখনও শেষ হয়।

দিকনির্দেশনা ফ্রেম অর্থ
সার্ভার → {"type":"ready","mode":"bundle","apply":"replace","limitBytes":N,"heartbeatSeconds":15} ভাতা নিষ্পত্তি এবং বিনামূল্যে স্থান চেক. পাঠানো শুরু করুন। mode হয় bundle বা create. apply হয় merge যখন আপনি একটি আংশিক আপডেট চেয়েছিলেন।
→ সার্ভার বাইনারি আর্কাইভ বাইট, আপনার পছন্দ অনুযায়ী টুকরো টুকরো করা — সার্ভার কখনই বার্তাগুলিকে পুনরায় একত্রিত করে না, তাই 256 KB–1 MB একটি সূক্ষ্ম ডিফল্ট৷ সমন্বিত, আপনার ফ্রেম অবশ্যই ঠিক হতে হবে .tar.gz.
সার্ভার → {"type":"ack","bytesReceived":N} প্রাপ্তির অগ্রগতি, মোটামুটি প্রতি 8 এমবি। এটি থেকে আপনার অগ্রগতি বার ড্রাইভ করুন.
→ সার্ভার {"type":"complete"} আর্কাইভ সম্পূর্ণ পাঠানো হয়েছে.
→ সার্ভার {"type":"abort"} ছেড়ে দাও। দিয়ে উত্তর দিয়েছেন status: 499; কিছুই প্রকাশিত হয় না।
সার্ভার → {"type":"progress","phase":"publishing","bytesReceived":N} আপলোড ল্যান্ড করার সময় প্রতি 15 সেকেন্ডে হার্টবিট। তাদের উপেক্ষা করুন, কিন্তু তাদের প্রত্যাশা করুন।
সার্ভার → {"type":"result","status":200,...} সফলতা। বাকি অবজেক্ট হল HTTP প্রতিক্রিয়া বডি verbatim (status হয় 201 একটি তৈরির জন্য)।
সার্ভার → {"type":"error","status":413,"error":"...","limitBytes":N} প্রত্যাখ্যান। status এবং শরীরের HTTP রুট উত্তর হবে কি.

পর্যন্ত কিছুই প্রকাশিত হয় না {"type":"complete"} আসে এটি একটি HTTP ছাড়া একটি আচরণ সমতুল্য, এবং এটি ইচ্ছাকৃত: আর্কাইভ-এর শেষ-মার্কার জীবনযাপন করে ভিতরে একটি টার এর বাইট, তাই প্ল্যাটফর্ম সংযোগটি শেষ না হওয়া ছাড়াই একটি সম্পূর্ণ-সুদর্শন সংরক্ষণাগার পড়া শেষ করে। একটি সকেট যেটি শেষ বাইটের পরে বাদ পড়লে তা অন্যথায় শেষের মত প্রকাশ করবে — নিঃশব্দে একটি পরিত্যক্ত ধাক্কা দিয়ে একটি লাইভ গেম প্রতিস্থাপন করা। ফ্রেম আপলোড ছাড়াই সকেট বন্ধ করা হচ্ছে কিছুই না

আপনার শেষ বাইটের পরে প্রকাশে সময় লাগতে পারে, বিশেষ করে একটি সার্ভার চিত্রের জন্য। প্রত্যাশা progress এটি শেষ হওয়ার সময় হৃদস্পন্দন; একটি শান্ত ব্যবধান একটি আপলোড ব্যর্থতা হিসাবে বিবেচনা করবেন না.

হার সীমা

জমা দিন, দাবি করুন, URL পরিবর্তন করুন, হোস্টিং এবং স্থাপনা সবই প্ল্যাটফর্মের একটি টোকেনে GitHub-এ পৌঁছান, তাই একসাথে তারা প্রতি অ্যাকাউন্টে প্রতি মিনিটে 10টি অনুরোধের মধ্যে সীমাবদ্ধ (429, সঙ্গে Retry-After) আ অপারেটর এটি একটি অ্যাকাউন্টের জন্য বাড়াতে পারে।

এটি এমন একটি গেমের জন্য প্রত্যাখ্যান করা হয়েছে যার নাম নেই কোনো সংগ্রহস্থল (একটি আপলোড করা বান্ডিল): একটি প্রতিশ্রুতি পিন করা কি একটি গেমকে তার সংগ্রহস্থলে নিয়ে যায়, এবং একটি বান্ডিল-তৈরি গেমের কিছুই নেই। একটি আপলোড করা গেম পুনরায় স্থাপন করা হচ্ছে৷ github.com আনার পরিবর্তে ভলিউমে থাকা ফাইলগুলি যাচাই করে।

একটি নতুন URL এ একটি গেম সরান৷

PUT /api/v1/me/github-games/{id}/url

{ "repoUrl": "https://github.com/you/new-repo", "displayName": "optional for a hosted URL" }

সারি বেঁচে থাকে — uid, <uid>.starhermit.com, খেলার সময়, রেটিং — এবং থেকে পুনরায় স্থাপন করা হয় গন্তব্য একটি গিথুব গন্তব্য অবশ্যই এমন একটি হতে হবে যা কলকারী প্রমাণ করতে পারে যে তারা নিয়ন্ত্রণ করে (403 অন্যথায়), এবং তার starhermit.txt একটি নাম করা উচিত নয় ভিন্ন owner= (403) একটি স্ক্রিপ্টেড বা ধারক ব্যাকএন্ড অক্ষম করা হয় যদি না গন্তব্য একটি ঘোষণা করে।

লাইভ সেশন (মালিক)

GET /api/v1/me/github-games/{id}/sessions গেমের সার্ভারের সক্রিয় সেশন তালিকাভুক্ত করে। DELETE .../sessions/{sessionId} প্ল্যাটফর্ম পরিত্যক্ত পথের মধ্য দিয়ে শেষ হয় (কোনও বিজয়ী নয়, না elo, কারণ operator_ended) এটি একটি আটকে থাকা সেশনের ধারণক্ষমতার আসন ফিরিয়ে দেয়।

লিডারবোর্ড এবং অর্জন (মালিক)

একটি গেমের মালিক তার প্রকাশক: আপনি তৈরি করতে পারেন লিডারবোর্ড এবং অর্জন এটার জন্য অধীন /me/github-games/{id}/leaderboards এবং /achievements প্রকাশক অ্যাকাউন্ট ছাড়া। শুধুমাত্র আপনার গেমের সার্ভার তাদের লিখছে, তাই গেমটির একটি প্রয়োজন server= স্ক্রিপ্ট বা container.image= ব্যাকএন্ড - একটি ব্রাউজার-শুধুমাত্র গেম পায় 409. দেখুন লিডারবোর্ড, অর্জন এবং টিউটোরিয়াল.

আপনার নিজের খেলা প্রকাশ করুন: ওয়াকথ্রু

দুটি রুট আছে। যদি আপনার গেমটি একটি গিট রিপোজিটরিতে থাকে, তাহলে নিচের নম্বর দেওয়া ধাপগুলি অনুসরণ করুন। যদি এটি আপনার মেশিনে শুধুমাত্র একটি ফোল্ডার হয়, একটি কল এটি সব করে: একটি স্থানীয় ফোল্ডার থেকে একটি গেম যোগ করুন গেমটি নিবন্ধন করে, প্রকাশ করে ফাইলগুলি, এবং এটিকে লাইভ ছেড়ে দেয় - কোনও হোস্টিং টগল এবং কোনও কমিট পিন নেই, কারণ এর কোনও সংগ্রহস্থল নেই ট্র্যাক

  1. একটি উত্স চয়ন করুন: একটি রেপো ধারণকারী ধাক্কা starhermit.txt মূলে (ঐচ্ছিকভাবে ঘোষণা করা হয় a server.js স্ক্রিপ্ট বা কন্টেইনার ইমেজ), অথবা ইতিমধ্যেই হোস্ট করা ব্রাউজার গেমের সর্বজনীন URL প্রস্তুত করুন।
  2. আপনার GitHub পরিচয় লিঙ্ক করুন OAuth প্রবাহের মাধ্যমে (দেখুন auth.md); দিয়ে যাচাই করুন GET /api/v1/me/github.
  3. গেমটি নিবন্ধন করুন: POST /api/v1/me/github-games রিপোজিটরি বা হোস্টেড-গেম URL এর সাথে repoUrl.
  4. শুধুমাত্র রিপোজিটরি গেম - হোস্টিং সক্ষম করুন: PUT /api/v1/me/github-games/{id}/hosting সঙ্গে { "enabled": true }.
  5. শুধুমাত্র রিপোজিটরি গেমস - একটি কমিট পিন করুন: PUT /api/v1/me/github-games/{id}/deployment সঙ্গে { "commit": "<sha>" }. পিন করা কমিট লাইভ সংস্করণ নিয়ন্ত্রণ করে।
  6. খেলোয়াড়রা গেমটি চালু করে: একটি স্থাপন করা সংগ্রহস্থল খেলা পরিবেশিত হয় <slug>.starhermit.com; একটি সরাসরি হোস্ট করা গেম তার জমা দেওয়া URL খোলে। একটি সঙ্গে প্রতিটি খেলা gameSlug — ব্যাকএন্ড বা না — থেকে একটি লঞ্চ টোকেন গ্রহণ করে POST /api/v1/games/<slug>/launch-token URL খণ্ডে (ঐচ্ছিকভাবে এর সাথে &session_id=<guid> গভীর লিঙ্ক আমন্ত্রণের জন্য)।
