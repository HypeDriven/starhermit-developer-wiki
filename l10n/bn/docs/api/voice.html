ভয়েস

StarHermit ভয়েস একটি REST API এর মাধ্যমে প্রতি-কথোপকথনের ভয়েস রুম সরবরাহ করে (api/v1/voice) প্লাস একটি মিশ্র বাইনারি/টেক্সট ওয়েবসকেট (ws/v1/voice) অডিও এবং WebRTC সিগন্যালিংয়ের জন্য। সমস্ত REST এন্ডপয়েন্টের প্রমাণীকরণ প্রয়োজন। ভয়েস প্রাপ্যতা পরিবর্তিত হতে পারে. ত্রুটি সংস্থাগুলি পরিবর্তিত হয়; দেখুন এপিআই কনভেনশন.

কক্ষ নোঙ্গর চ্যাট কথোপকথন; কথোপকথনের সদস্যতা সবকিছুকে গেট করে, তাই চ্যাট বন্ধুত্বের নিয়মগুলি ভয়েসকেও নিয়ন্ত্রণ করে (গেম-সেশন কথোপকথন বন্ধুত্বকে বাইপাস করে)। সীমা: প্রতি কথোপকথনে 3টি সক্রিয় রুম, প্রতি রুমে সর্বাধিক 10 জন অংশগ্রহণকারী, কোডেক "opus".

REST শেষ পয়েন্ট

ভিত্তি: https://api.starhermit.com/api/v1/voice.

পদ্ধতি পথ প্রমাণ বর্ণনা
পোস্ট /rooms জেডব্লিউটি কথোপকথনের জন্য একটি ভয়েস রুম তৈরি করুন
পান /rooms?conversationId= জেডব্লিউটি কথোপকথনের জন্য ঘরের তালিকা করুন
পান /rooms/{roomId} জেডব্লিউটি একটা রুম পান
পোস্ট /rooms/{roomId}/join জেডব্লিউটি একটি রুমে যোগ দিন (WS এর আগে প্রয়োজন)
পোস্ট /rooms/{roomId}/leave জেডব্লিউটি একটা ঘর ছেড়ে দাও
পোস্ট /rooms/{roomId}/mute জেডব্লিউটি আপনার নিজের নিঃশব্দ অবস্থা সেট করুন
পোস্ট /rooms/{roomId}/participants/{userId}/server-mute JWT (স্রষ্টা) হোস্ট নিঃশব্দ অংশগ্রহণকারী তুলতে পারবেন না
পোস্ট /rooms/{roomId}/close জেডব্লিউটি একটি রুম বন্ধ করুন (শুধুমাত্র নির্মাতা)

একটি রুম তৈরি করুন

POST /rooms

{ "conversationId": "<guid>", "maxParticipants": 10 }

ফেরত a VoiceRoomDto.

রুমের আকৃতি

GET /rooms?conversationId=<guid> → VoiceRoomDto[]; GET /rooms/{roomId} → VoiceRoomDto:

  "id": "<guid>",
  "conversationId": "<guid>",
  "creatorUserId": "<guid>",
  "codec": "opus",
  "status": "Active",
  "maxParticipants": 10,
  "createdAt": "2026-07-22T07:00:00Z",
  "participants": [
    {
      "userId": "<guid>",
      "username": "alice",
      "isMuted": false,
      "isConnected": true,
      "joinedAt": "2026-07-22T07:01:00Z"
    }
  ]
}

যোগ দিন, ছেড়ে দিন, নিঃশব্দ, বন্ধ করুন

POST /rooms/{roomId}/join → VoiceRoomDto. এই REST যোগদান হয় প্রয়োজনীয় WebSocket খোলার আগে; এটা ছাড়া সংযোগ ফেরত 403. পুনরায় যোগদান অংশগ্রহণকারীদের সাফ করে নিজস্ব নিঃশব্দ (isMuted); একটি হোস্ট এর isServerMuted বেঁচে যান এবং পুনরায় সংযোগ করুন।

POST /rooms/{roomId}/leave → 204.

POST /rooms/{roomId}/mute সঙ্গে { "muted": true } → 204. এটি অংশগ্রহণকারীর নিজস্ব নিঃশব্দ এবং একটি হোস্ট নিঃশব্দ সাফ করতে পারে না৷

POST /rooms/{roomId}/participants/{userId}/server-mute সঙ্গে { "muted": true } → 204 (শুধুমাত্র স্রষ্টা)। যেকোনো একটি মিউট সেট করা থাকলে অডিও বাদ দেওয়া হয়।

POST /rooms/{roomId}/close → 204 (শুধুমাত্র স্রষ্টা)।

সারিটি যা মনে রাখুক না কেন উত্তরাধিকারী হওয়ার পরিবর্তে সংযোগে আপনার নিঃশব্দটি বলুন।

ওয়েবসকেট: ws/v1/voice

সংযোগ করুন wss://api.starhermit.com/ws/v1/voice?roomId=<guid> মাধ্যমে একটি JWT সঙ্গে Authorization শিরোনাম, ?ticket=, বা ?access_token=. একটি পূর্ববর্তী বিশ্রাম join প্রয়োজন হয়

প্রোটোকল মিশ্রিত হয়:

বাইনারি ফ্রেম — অডিও

বাইনারি ফ্রেম অডিও বহন করে (যেমন ওপাস)। সার্ভার প্রতিটি ফ্রেমকে অন্যান্য অংশগ্রহণকারীদের কাছে রিলে করে:

[16-byte senderUserId][audio…]

সার্ভার উপসর্গ প্রমাণিত প্রেরকের আইডি এবং কখনই ক্লায়েন্ট সরবরাহ করা প্রেরককে বিশ্বাস করে না। নিঃশব্দ ব্যবহারকারীদের থেকে অডিও বাদ দেওয়া হয়েছে। সীমা: ব্যবহারকারী প্রতি 100 প্যাকেট/সেকেন্ড, সর্বোচ্চ ফ্রেম 4000 বাইট।

পাঠ্য ফ্রেম — ক্লায়েন্ট → সার্ভার নিয়ন্ত্রণ

{ "type": "mute", "muted": true }

{ "type": "speaking", "speaking": true }

{ "type": "rtc", "to": "<guid>", "payload": { } }

{ "type": "deafen", "deafened": true }

rtc পেলোডগুলি হল অস্বচ্ছ WebRTC সিগন্যালিং, সম্বোধনকৃত অংশগ্রহণকারীকে ফরোয়ার্ড করা হয়৷ deafen এই সকেটের জন্য ইনকামিং রিলেড বাইনারি অডিও দমন করে; এটি স্বয়ংক্রিয়ভাবে নিঃশব্দ হয় না বহির্গামী অডিও বা একটি পৃথক পিয়ার সংযোগ। প্লেয়ার যখন ডেফেন বেছে নেয় তখন স্থানীয়ভাবে সেগুলি প্রয়োগ করুন।

REST অংশগ্রহণকারী আকৃতি নিজস্ব নিঃশব্দ প্রকাশ করে, হোস্ট মিউট নয়। প্রাথমিক ভয়েস রোস্টার এবং ইভেন্টে যোগদান অন্তর্ভুক্ত serverMuted; কোনো পৃথক হোস্ট-নিঃশব্দ-পরিবর্তিত পুশ ইভেন্ট নেই। যদি আপনার গেম P2P ব্যবহার করে অডিও, এর হোস্ট-মিউট সিগন্যালিং এবং প্রয়োগ অবশ্যই আপনার নিজস্ব মিডিয়া ইন্টিগ্রেশনের অংশ হতে হবে।

শেষ ভয়েস সকেট সংযোগ বিচ্ছিন্ন হলে, ভয়েস-রুম সদস্যতা শেষ হয়। REST কল করুন join আবার আগে অডিও পাঠানোর আগে পুনঃসংযোগ এবং অভিপ্রেত নিঃশব্দ পুনরুদ্ধার করা হচ্ছে।

উদাহরণ ইন্টিগ্রেশন প্যাটার্ন (দাবা রেফারেন্স বাস্তবায়ন থেকে)

ভয়েস গেম সেশন প্রতি অপ্ট-ইন করা হয়. একজন সাধারণ ক্লায়েন্ট enable() প্রবাহ:

  1. GET /api/v1/voice/rooms?conversationId=<chatConversationId> একটি বিদ্যমান রুম খুঁজে পেতে, অন্যথায় POST /api/v1/voice/rooms একটি তৈরি করতে
  2. POST /api/v1/voice/rooms/{roomId}/join.
  3. খোলা ws/v1/voice?roomId=<guid>.

মধ্যে দাবা রেফারেন্স বাস্তবায়ন, নিখুঁত আলোচনার সাথে WebRTC P2P এর উপর অডিও চলে; মাধ্যমে সংকেত বিনিময় করা হয় rtc নিয়ন্ত্রণ বার্তা ({ "sdp": … } / { "ice": … } payloads), ফলব্যাক হিসাবে সার্ভার-রিলেড Opus বাইনারি পাথ সহ।

গেম-স্কোপড লঞ্চ টোকেন হতে পারে তাদের নিজস্ব গেম সেশনের সাথে সংযুক্ত কক্ষগুলির জন্য ভয়েস REST এবং WebSocket ব্যবহার করুন।

এছাড়াও দেখুন

  • অডিও বিকল্প - বেসলাইন ভলিউম, মাইক্রোফোন এবং পুশ-টু-টক কন্ট্রোল, একটি স্বয়ংক্রিয় সনাক্ত প্লেব্যাক ক্যাপ সহ
  • চ্যাট - কথোপকথনের জন্য কক্ষ নোঙ্গর; খেলা সেশন প্রকাশ chatConversationId
  • গেমস — গেম সেশন এবং লঞ্চ টোকেন
  • রিলে — গেম নেটকোডের জন্য বাইট ফ্যান-আউট

দেখুন শংসাপত্রের সামঞ্জস্য এবং মেশিন-পাঠযোগ্য চুক্তি.
