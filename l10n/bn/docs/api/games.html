গেম API

গেমের সাবসিস্টেম হল StarHermit এর মূল: সার্ভার-অনুমোদিত মাল্টিপ্লেয়ার গেম যার নিয়মগুলি হয় একটি স্যান্ডবক্সযুক্ত জাভাস্ক্রিপ্ট ফাইল বা ডেভেলপার দ্বারা সরবরাহকৃত কন্টেইনারে চলে। উভয় রানটাইম এই প্লেয়ার-মুখী REST API (api/v1/games/{slug}) এবং গেমপ্লে ওয়েবসকেট (ws/v1/games) সার্ভার লেখার জন্য, দেখুন খেলা স্ক্রিপ্ট বা কন্টেইনার-হোস্টেড গেম সার্ভার. একটি সম্পূর্ণ স্ক্রিপ্ট-রানটাইম উদাহরণের জন্য, দেখুন দাবা ওয়াকথ্রু এবং হাইপড্রাইভেন/স্টারহার্মিট-দাবা.

ভিত্তি URL: https://api.starhermit.com.

প্লেয়ার এন্ডপয়েন্টের জন্য প্রমাণীকরণের প্রয়োজন হয় এবং সম্পূর্ণ ব্যবহারকারী টোকেন এবং গেম-স্কোপড লঞ্চ উভয়ের সাথে কাজ করে টোকেন দুই /server/... এন্ডপয়েন্টগুলি শুধুমাত্র ধারক: সেশন পুনর্মিলন একটি সংকীর্ণ ব্যবহার করে সার্ভার বহনকারী টোকেন, যখন টোকেন পুনর্নবীকরণ স্থাপনার রিফ্রেশ কী ব্যবহার করে।

কি {slug} হয়

একটি খেলা এর স্লাগ তার uid — তার হিসাবে একই মান <uid>.starhermit.com ঠিকানা, যেমন 83fd04b1-3cbe-4b09-a251-3733ad4b9d94. এটি গেমের অপরিবর্তনীয় আইডি থেকে উদ্ভূত হয়েছে এবং কিছুই না সেট করতে পারেন: না starhermit.txt, রেপো নাম নয়, অপারেটর নয়। একটি নাম একটি বিকাশকারী পারে বেছে নিন এমন কিছু হতে পারে যা দুটি গেমের জন্য লড়াই করতে পারে এবং কাকে সালিশ করার জন্য প্ল্যাটফর্মের প্রয়োজন হবে এটা পেয়েছি; একটি uid সংঘর্ষ বা জিজ্ঞাসা করা যাবে না.

একটি স্লাগ একটি সার্ভার ব্যাকএন্ড নয়। প্রতিটি খেলা একটি স্থানীয় ফোল্ডার থেকে যোগ করা হয়েছে, এবং প্রতিটি সংগ্রহস্থল খেলা একজন যাচাইকৃত মালিক যোগ করেছেন, একটি আছে — সঙ্গে বা ছাড়া server= বা container.image= - কারণ এটা গেমের প্লেয়ার-মুখী পৃষ্ঠের ঠিকানা: টোকেন চালু করুন, নিয়ন্ত্রণ করে, সেটিংস, এর ক্লাউড-সেভ স্লট এবং কক্ষ. ক ব্রাউজার-শুধুমাত্র গেমটি অন্য যেকোনটির মতোই প্রয়োজন। কোন স্লাগ ছাড়া শুধুমাত্র গেম ভান্ডার হয় জমা যার মালিক যাচাই করা হয় না (gameSlug হয় null মধ্যে GET /api/v1/me/github-games).

একটি গেমের সার্ভার সম্পর্কে শেষ পয়েন্টগুলি — গেমের তথ্য, অর্জন, সেশন, ম্যাচমেকিং, আমন্ত্রণ, রিপ্লে - একটি ব্যাকএন্ড প্রয়োজন। GET /api/v1/games/{slug} উত্তর 404 একটি স্লগ এবং না আছে একটি খেলার জন্য ব্যাকএন্ড, যা দুটি আলাদা করার উপায়।

এটা হার্ড কোড না. লঞ্চ টোকেন থেকে এটি পড়ুন game_scope দাবি, বা — একটি জন্য প্ল্যাটফর্ম-হোস্টেড ব্রাউজার গেম — থেকে location.hostname, যেহেতু সাবডোমেন হল uid.

খেলার তথ্য

GET /api/v1/games/{slug}

গেমের সংজ্ঞা এবং সেই গেমের জন্য কলারের পরিসংখ্যান প্রদান করে। 404 যদি এমন কোন খেলা না থাকে, অথবা যদি গেমটি শুধুমাত্র ব্রাউজার হয় (এতে একটি স্লাগ আছে কিন্তু কোনো সার্ভার ব্যাকএন্ড নেই)।

  "name": "Chess",
  "enabled": true,
  "leaderboardId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "maxConcurrentSessionsPerPlayer": 20,
  "replaysEnabled": true,
  "buildId": "s12",
  "me": {

    "elo": 1200,
    "wins": 4,
    "losses": 2,
    "draws": 1,
    "activeSessionCount": 2

}
  • leaderboardId ঐচ্ছিক।
  • me.elo থেকে ডিফল্ট 1200; wins/losses/draws সার্ভার-রানটাইম-মালিকানাধীন প্রতি-প্লেয়ার নথি থেকে পড়া হয়।
  • replaysEnabled এই গেমের সমাপ্ত সেশনগুলি রাখা হয়েছে কিনা তা বলে — অনুমান না করে এটি পড়ুন এবং আপনার রিপ্লে UI লুকান যখন এটি হয় false. দেখুন রিপ্লে.
  • buildId বর্তমানে গেমটি পরিবেশনকারী সার্ভার লজিকের নাম দেয় (s + স্ক্রিপ্ট সংস্করণ, বা c + চিত্র ডাইজেস্ট উপসর্গ)। হিসাবে এটি ফেরত পাঠান ws/v1/games?build=… তাই একটি বাসি ক্লায়েন্ট সঙ্গে প্রত্যাখ্যান করা হয় 409 {"error":"build_mismatch"} এটি সরানো ক্ষেত্রগুলিতে কাজ করার আগে। বাদ দেওয়া build আগের মত সংযোগ করে।

প্রতি-প্লেয়ার গেম সেটিংস

যেখানে আপনার খেলা রাখা তার নিজস্ব বিকল্প একজন প্লেয়ারের জন্য — মাস্টার ভলিউম, গ্রাফিক্সের বিস্তারিত, সাবটাইটেল সাইজ, পছন্দের ক্যামেরা, সর্বশেষ নির্বাচিত লোডআউট — যাতে তারা সাইন ইন করলে যে কোনো মেশিনে সেই প্লেয়ারটিকে অনুসরণ করে থেকে একজন খেলোয়াড় এবং একটি গেমের জন্য একটি কী/মূল্যের দোকান। গ্রাফিক্সের পাশাপাশি একটি ভাষা বিভাগের জন্য, অডিও, এবং কন্ট্রোল, দেখুন আপনার খেলা স্থানীয়করণ এবং ভাষা সেটিংস যোগ করুন.

কিছুই একটি স্কিমা ঘোষণা. প্ল্যাটফর্মটি আপনার কী এবং আপনার মান সংরক্ষণ করে এবং সেগুলি কখনই পড়ে না, তাই আপনি এটি লিখে একটি বিকল্প যোগ করুন: কোনো ম্যানিফেস্ট এন্ট্রি, কোনো পুনঃবিয়োগ, কোনো প্ল্যাটফর্ম প্রকাশ নয়। তাও মানে প্ল্যাটফর্ম আপনার জন্য সেগুলিকে যাচাই করতে পারে না — একটি মূল নামের একটি টাইপো একটি নতুন সেটিং, একটি নয়৷ ত্রুটি

কন্ট্রোল API এর মত, একটি গেম-স্কোপড লঞ্চ টোকেন গৃহীত হয় (এর game_scope মিলতে হবে {slug}), তাই একটি ইন-গেম অপশন স্ক্রিন গেমটি ইতিমধ্যে ধারণ করা টোকেন ছাড়া আর কিছুই দিয়ে কাজ করে। অপছন্দ নিয়ন্ত্রণ করে, কোনো ম্যানিফেস্ট ঘোষণার প্রয়োজন নেই: প্রতিটি গেমের মুহূর্ত থেকে সেটিংস স্টোরেজ রয়েছে কোনো সার্ভার লজিক ছাড়াই শুধুমাত্র ব্রাউজার গেম সহ বিদ্যমান।

সঠিক দোকান চয়ন করুন - মেঘ সংরক্ষণ করে অগ্রগতি ধরে রাখুন (শিরোনাম প্রতি একটি অস্বচ্ছ সংরক্ষণাগার, 10 এমবি, লঞ্চ টোকেনের সাথেও পৌঁছানো যায়), এবং একটি স্ক্রিপ্ট বা কন্টেইনার ব্যাকএন্ডের নিজস্ব প্লেয়ার স্টেট সার্ভার-অনুমোদিত এবং একটি থেকে লেখার যোগ্য নয় ক্লায়েন্ট সেটিংস হল ছোট, ক্লায়েন্টের মালিকানাধীন পছন্দগুলির মধ্যে।

GET /api/v1/games/{slug}/settings

এই গেমের জন্য কলার যা কিছু সংরক্ষণ করেছে। settings এমন একজন খেলোয়াড়ের জন্য খালি যে কখনও সংরক্ষণ করেনি কিছু — যে একটি 200, না a 404. চাবি সাজানো ফিরে আসা.

{
  "slug": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "settings": {
    "audio.master": 0.8,
    "graphics.detail": "ultra",
    "graphics.options": { "shadows": true, "msaa": 4 }
  },
  "count": 3,
  "bytes": 118,
  "updatedAt": "2026-08-07T15:04:11Z",
  "limits": { "maxKeys": 200, "maxKeyLength": 128, "maxTotalBytes": 2097152, "maxAccountBytes": 67108864 }
}

bytes এই প্লেয়ার এর সেটিংস বর্তমানে কি খরচ হয় limits.maxTotalBytes. পড়ুন তাদের হার্ড-কোডিংয়ের পরিবর্তে সীমাবদ্ধ করুন: ভাতা একটি অপারেটর সেটিং, এবং একটি গেম মঞ্জুর করা যেতে পারে তার নিজস্ব maxKeys (ডিফল্টরূপে 200) এছাড়াও গেম প্রতি সেট করা যেতে পারে, এবং maxAccountBytes একটি সীমাবদ্ধ প্রতিটি গেম জুড়ে অ্যাকাউন্টের সেটিংস (ডিফল্টরূপে 64 এমবি)।

GET / PUT / DELETE /api/v1/games/{slug}/settings/{key}

এক সময়ে এক সেটিং। GET রিটার্ন { "key", "value", "updatedAt" }, বা 404 যদি কলকারী থাকে এটা সংরক্ষণ করা হয় না. PUT লাগে { "value": <any JSON> } এবং মান সংরক্ষণ করে শব্দার্থে — সহ একটি সুস্পষ্ট null, যা এখানে অন্য যে কোন মত একটি মান, একটি মুছে ফেলা নয়.   -H "Content-Type: application/json" \

  • সাড়া বহন করে targetSessionId; sessionId থাকে null যতক্ষণ না আমন্ত্রণ গৃহীত হয়।
  • স্বীকার করার সময় সবকিছু আবার চেক করা হয়। যদি খেলাটি প্রত্যাখ্যান করে (পূর্ণ, বন্ধ...) গ্রহণটি হয় a 409 এবং আমন্ত্রণ মুলতুবি থাকে. ম্যাচ শেষ হলে আমন্ত্রণ জানানো হয় বাতিল এবং উত্তর গ্রহণ 410 - এটি কখনই একটি নতুন গেমে পরিণত হয় না।
  • শুধুমাত্র আমন্ত্রিতদের সমবর্তী-সেশন ক্যাপ প্রযোজ্য। আপনি গন্তব্য প্রতি বন্ধু প্রতি একটি মুলতুবি আমন্ত্রণ ধরে রাখতে পারেন, তাই আপনার ম্যাচে একটি আমন্ত্রণ এবং একটি নতুন গেমের আমন্ত্রণ একসাথে থাকতে পারে।

এই বৈশিষ্ট্যটি উপেক্ষা করার আগে থেকে একটি প্ল্যাটফর্ম তৈরি করা হয়েছে৷ sessionId এবং গ্রহণের উপর একটি নতুন অধিবেশন শুরু হয়; targetSessionId উত্তরে আপনি যা পেয়েছেন তা আপনাকে বলে।

আপনি কোন আমন্ত্রণ পাঠাতে হবে? একটি সাধারণ আমন্ত্রণ গ্রহণ করা (নং sessionId) একটি নতুন অধিবেশন তৈরি করে দুই খেলোয়াড়ের জন্য। আমন্ত্রণকারী ইতিমধ্যেই বসে থাকলে ক রিয়েলটাইম রুম (সিট সহ একটি লবি), পরিবর্তে তাদের সেই ঘরে আমন্ত্রণ জানান — POST /api/v1/realtime/rooms/{id}/invites - সুতরাং আপনি যে টেবিলে আছেন সেখানে তাদের আসন গ্রহণ করুন। উভয়ই আমন্ত্রিত ব্যক্তিকে একইভাবে অবহিত করে, তাই উভয়কে কখনই একটি আমন্ত্রণের জন্য পাঠান না: এটি দুবার বিজ্ঞপ্তি দেয়।

লিঙ্ক শেয়ার করুন (URL দ্বারা আমন্ত্রণ)

উপরের আমন্ত্রণ প্রবাহের জন্য দুই খেলোয়াড়কে ইতিমধ্যেই বন্ধু হতে হবে। এমন কাউকে আমন্ত্রণ জানানোর জন্য এখনো প্ল্যাটফর্মে নেই (অথবা এখনও একটি বন্ধু নয়), একটি খেলা হস্তান্তর করতে পারে একটি লিঙ্ক শেয়ার করুন — ওয়েব ড্যাশবোর্ডের একটি URL যা সম্পূর্ণ অনবোর্ডিংকে স্বয়ংক্রিয় করে:

https://dashboard.starhermit.com/game-invite/<userId>/<gameSlug>
  • <userId> — শেয়ারিং প্লেয়ারের ইউজার আইডি। একটি গেম ক্লায়েন্ট ইতিমধ্যে এটি আছে: এটি হয় sub এর লঞ্চ টোকেনের দাবি (দাবা রেফারেন্স বাস্তবায়ন এটিকে প্রকাশ করে Net.userId).
  • <gameSlug> - খেলার স্লাগ (game_scope দাবি)। একটি প্রামাণিক স্ক্রিপ্ট বা কন্টেইনার ব্যাকএন্ড ছাড়া গেমগুলি পরিবর্তে GitHub গেম আইডি (একটি GUID) ব্যবহার করে; ড্যাশবোর্ড হয় গ্রহণ করে।
  • ঐচ্ছিক ক্যোয়ারী স্ট্রিং - আপনার. কিছু পরে ? আপনার খেলা অপরিবর্তিত পাস করা হয়: …/game-invite/<userId>/<gameSlug>?room=K7MP2X&map=arena এ আপনার খেলা খোলে https://<game-id>.starhermit.com/…?room=K7MP2X&map=arena. প্রাপককে সোজা করতে এটি ব্যবহার করুন একটি রুমে, একটি স্তর বা একটি লবিতে। এটি প্রাপকের সাইন-ইন থেকে বেঁচে থাকে এবং এটি আপনার সাথে যুক্ত হয় গেমের URL সেখানে কিছু প্রতিস্থাপন করার পরিবর্তে। লঞ্চ টোকেন এখনও আসে #game_token= টুকরো টুকরো, তাই দুটি কখনই সংঘর্ষে আসে না। আপনি এটিতে যে মানগুলি রেখেছেন তা URL-এনকোড করুন।

প্রাপক লিঙ্কটি খুললে, ড্যাশবোর্ড (গেমটি নয়) স্বয়ংক্রিয় বন্ধু-আমন্ত্রণ অংশটি করে — কোনও নতুন ব্যাকএন্ড এন্ডপয়েন্ট জড়িত নেই, এটি বিদ্যমান APIগুলি রচনা করে:

  1. তাদের সাইন ইন করুন (একটি লাইভ প্রদানকারীর মাধ্যমে OAuth), অথবা তাদের বিদ্যমান সেশন পুনরায় ব্যবহার করুন। সাইন-ইন রাউন্ড ট্রিপে লিঙ্কের অভিপ্রায় টিকে থাকে।
  2. তারপর শেয়ারার এবং গেমের নামকরণ করে একটি সম্মতি ডায়ালগ দেখায় বন্ধু শেয়ারার: এটি শেয়ারারের মুলতুবি বন্ধু অনুরোধ গ্রহণ করে যদি একটি বিদ্যমান থাকে, অন্যথায় এটি একটি পাঠায় (POST /api/v1/me/friend-requests).
  3. তাদের অ্যাকাউন্টে কোনো ডাকনাম না থাকলে ডাকনাম বেছে নিতে অনুরোধ করে (গেমস প্রোফাইল ডাকনাম প্রদর্শন করে — দেখুন প্রোফাইল).
  4. গেমটি চালু করে (প্ল্যাটফর্ম-হোস্টেড https://<game-id>.starhermit.com কপি, একটি লঞ্চ টোকেন সঙ্গে #game_token= যথারীতি খণ্ড)।
  5. পাঠায় ভাগ করে নেওয়ার আমন্ত্রণটি খেলুন সঙ্গে POST /api/v1/games/{slug}/invites — সুতরাং একটি শেয়ারের লিঙ্ক একটি সাধারণ গেম হিসাবে শেষ হয় যা শেয়ারার গ্রহণ করে (ড্যাশবোর্ড টোস্ট, ডেস্কটপ বেলুন, বা গেমের নিজস্ব আমন্ত্রণ তালিকা)। যদি বন্ধুত্বটি এখনও একটি মুলতুবি অনুরোধ থাকে, ড্যাশবোর্ডটি খেলার আমন্ত্রণটিকে সারিবদ্ধ করে এবং শেয়ারার গ্রহণ করার পরে এটি স্বয়ংক্রিয়ভাবে প্রেরণ করে।

আপনার গেম ক্লায়েন্টের জন্য এর অর্থ কী:

  • লিঙ্ক অফার করার জন্য স্ট্রিং বিল্ডিংয়ের এক লাইন খরচ হয় — রাখা a "আমন্ত্রণ লিঙ্ক শেয়ার করুন" আপনার invite-a-friend UI-এর পাশে বোতাম এবং URL টি ক্লিপবোর্ডে অনুলিপি করুন। দেখুন shareInviteLink() মধ্যে দাবা রেফারেন্স বাস্তবায়ন.
  • রিসিভিং সাইডে কোন বিশেষ হ্যান্ডলিং এর প্রয়োজন নেই। প্রাপকের আমন্ত্রণ স্বাভাবিক আমন্ত্রণ প্রবাহের মাধ্যমে আসে: আপনার GET .../invites পোলিং শেয়ারারকে ইনকামিং আমন্ত্রণ দেখায়, এটি গ্রহণ করলে সেশন তৈরি হয় এবং প্রাপক দেখতে পান যে সেশনটি উপস্থিত হবে GET .../sessions/mine (মুলতুবি আউটগোয়িং আমন্ত্রণগুলি দেখান যাতে অপেক্ষা দৃশ্যমান হয় — দাবা ক্লায়েন্টের "আমন্ত্রিত — অপেক্ষা করছে" কার্ড)।
  • ড্যাশবোর্ড নিজেও এই ইউআরএলগুলি ব্যবহার করে: প্রতিটি খেলার যোগ্য হোস্ট করা গেমের বিবরণ ফলকে একটি থাকে৷ আমন্ত্রণ লিঙ্ক কপি করুন বোতাম, এবং উইন্ডোজ ক্লায়েন্ট একটি গেমের প্রসঙ্গ মেনু থেকে একই অফার করে।

  • একটি বিরাম দেওয়া সাথে সংযোগ করা হচ্ছে৷ অবিরাম সেশন আপনার প্রথম কমান্ডের আগে এটি পুনরায় শুরু করে। যদি এটি পুনরায় চালু করা না যায় (সাধারণত একটি ধারক এখনও শুরু হয়), আপনি একটি পাবেন error ফ্রেম এবং সকেট কোড দিয়ে বন্ধ হয় 1001; অধিবেশন থেমে থাকে — ব্যাকঅফের সাথে পুনরায় সংযোগ করুন।

  • membership — কেউ একজন খেলোয়াড় হয়েছিলেন এই সেশনের মাঝামাঝি ম্যাচের (joined) অথবা তাদের আসন ছেড়ে দিয়েছে (left); প্রতিটি সংযুক্ত অংশগ্রহণকারীকে পাঠানো হয়েছে। দেখুন কন্টেইনার গেম সার্ভার - সদস্য.
  • achievement — গেমের স্ক্রিপ্টটি এইমাত্র দেওয়া একটি কৃতিত্ব আপনি, উপার্জনকারী খেলোয়াড়ের কাছে পাঠানো হয়েছে শুধুমাত্র উদ্দেশ্য অনুসারে একটি পৃথক ফ্রেম প্রকার: এটি প্ল্যাটফর্মের সত্য, স্ক্রিপ্ট-রিলেড গেম ডেটা নয়। উভয় রানটাইমের টেকসই আপডেট পাথ থেকে নির্গত। দেখুন অর্জন.
  • resumed — সেশন হাত পরিবর্তন করেছে (কন্টেইনার পুনরুদ্ধার, বা অন্য Api প্রক্রিয়া গ্রহণ করেছে মালিকানা ইজারা)। স্থানীয় ভবিষ্যদ্বাণী বাতিল করুন; lostMs শেষ টেকসই লেখার পর থেকে ব্যবধান। একটি হ্যান্ডঅফ পরে প্রথম সংযুক্তি প্রতি খেলোয়াড় একবার ঘোষণা করা হয়.
  • abandoned — প্ল্যাটফর্মটি বিজয়ী বা ইলো আপডেট ছাড়াই সেশনটি শেষ করেছে। কারণ: players_left, idle_no_players, superseded (খেলোয়াড় এই শিরোনামের একটি নতুন খেলা চেয়েছিল), server_failure, restore_failed, operator_ended (গেমের মালিক এটি শেষ করেছেন), retention_expired (একটি বিরতি দেওয়া বিশ্বের পুনরুদ্ধার ধারণ শেষ)। হিসাবে সংরক্ষিত { "kind": "abandoned", "reason": "…" }. A অবিরাম খেলার সেশন কখনও হয় না শুধুমাত্র সংযোগ বিচ্ছিন্ন বা নিষ্ক্রিয়তার জন্য শেষ হয়েছে - পরিবর্তে তারা বিরতি। শেষ মানুষটি স্পষ্টভাবে চলে যাচ্ছে একটি স্বতন্ত্র বিশ্ব এখনও হিসাবে এটি শেষ করতে পারেন players_left; কনফিগার করা পুনরুদ্ধারের মেয়াদ শেষ হতে পারে retention_expired.

সীমা

প্ল্যাটফর্ম যা প্রয়োগ করে ws/v1/games এবং রেটিং এর উপর। নম্বরগুলি প্ল্যাটফর্মের ডিফল্ট; একজন অপারেটর তাদের টিউন করতে পারে।

বার্তা চালু ws/v1/games

সীমা মান এটা অতীত কি হয়
ফ্রেমের আকার টেক্সট ফ্রেম প্রতি 16 KB সঙ্গে সকেট বন্ধ করা হয় 1009 (বার্তা খুব বড়)।
ফ্রেমের ধরন শুধুমাত্র পাঠ্য একটি বাইনারি ফ্রেম একটি পায় error ফ্রেম; সকেট খোলা থাকে।
সংযোগ প্রতি সেশনে একজন খেলোয়াড় প্রতি একটি নতুন সংযোগ পুরোনোটিকে বন্ধ করে দেয় 1008.
রিয়েলটাইম ইনপুট ({"type":"input","realtime":true,…}) প্রতি সেকেন্ডে 60 প্রতি সংযোগ, 120 পর্যন্ত বিস্ফোরিত হয় অতিরিক্ত ফ্রেম হয় নিঃশব্দে নেমে গেছে - না error ফ্রেম
স্ক্রিপ্টে টেকসই কমান্ড (প্রতিটি cmd) প্রতি সেকেন্ডে 20 প্রতি সেশনে প্রতি খেলোয়াড়, একটি সংক্ষিপ্ত বিস্ফোরণ ভাতা সহ একটি সঙ্গে প্রত্যাখ্যান error ফ্রেম: "Too many commands; slow down."

রিয়েলটাইম ইনপুট নমুনা করা হয়, সারিবদ্ধ নয়: প্ল্যাটফর্ম প্রতিটি খেলোয়াড়ের সর্বশেষ ইনপুট এবং হাত রাখে আপনার স্ক্রিপ্ট এর পরবর্তী ব্যাচ onTick মধ্যে ctx.inputs. আপনার গেমের চেয়ে দ্রুত পাঠানো হচ্ছে টিক রেট কিছুই লাভ করে না, কারণ দুটি টিকের মধ্যে ইনপুট একত্রিত হয় এক আপনার টিক রেট বা ইনপুট পরিবর্তন হলে পাঠান।

স্ক্রিপ্টে টেকসই কমান্ড ক্রমানুসারে প্রক্রিয়া করা হয় এবং রিয়েলটাইম থেকে আলাদাভাবে সীমিত ইনপুট সেগুলি ঘটলে বিযুক্ত কর্ম পাঠান; চিহ্নিত রিয়েলটাইম মাধ্যমে ক্রমাগত আন্দোলন পাঠান ইনপুট পাথ। কমান্ড সীমা গেম দ্বারা পরিবর্তিত হতে পারে. স্ক্রিপ্ট আহ্বানও গেম এর দ্বারা আবদ্ধ হয় বাজেট. WebSocket ত্রুটি ফ্রেম একটি বার্তা বহন করে, একটি HTTP স্থিতি নয়। আপনার স্ক্রিপ্টের এমন আদেশগুলি প্রত্যাখ্যান করা উচিত যেগুলির কোন অর্থ নেই, যেমন পালা থেকে সরে যাওয়া৷

একটি জন্য ধারক গেম, কোন প্ল্যাটফর্ম ছাড়াই কমান্ডগুলি আপনার কন্টেইনারে রিলে করা হয় তাদের উপর হার সীমা। আপনার সার্ভার তার নিজস্ব প্রয়োগ. রিয়েলটাইম-ইনপুট রেট লিমিটিং স্ক্রিপ্টেডের ক্ষেত্রে প্রযোজ্য শুধুমাত্র গেম।

ম্যাচ প্রতি এলো

প্ল্যাটফর্ম করে না এক ম্যাচে রেটিং কতদূর যেতে পারে তা নির্ধারণ করুন। eloUpdates (স্ক্রিপ্ট) এবং elo নিয়ন্ত্রণ বার্তা (ধারক) প্রতিটি খেলোয়াড়ের বহন নতুন পরম রেটিং, একটি পরিবর্তন নয়, এবং প্ল্যাটফর্ম তাদের প্রেরিত হিসাবে প্রয়োগ করে। এটি যা প্রয়োগ করে:

  • সেশনে শুধু খেলোয়াড়রা আপডেট করা হয় অন্য কারও আইডি এবং এআই সিট বাদ দেওয়া হয়েছে।
  • যখনই আপনার সার্ভার তাদের ফেরত দেয় তখনই আপডেটগুলি প্রয়োগ করা হয়। একটি অধিবেশন প্ল্যাটফর্ম শেষ (abandoned: খেলোয়াড় বাম, নিষ্ক্রিয়, স্থানান্তরিত, সার্ভার ব্যর্থতা, মালিক দ্বারা শেষ) প্রকাশ করে৷ না elo পরিবর্তন।
  • রেটিংটি কলাম ম্যাচমেকিং জোড়ায় এবং গেমের ইলো বোর্ডে এক হিসাবে লেখা হয় প্রতি খেলোয়াড় এন্ট্রি (তাদের সর্বশেষ রেটিং)।
  • গেমের মালিক পারেন একজন খেলোয়াড়ের রেটিং রিসেট করুন 1200 পর্যন্ত।

তাই সুইং এর আকার আপনার খেলার সিদ্ধান্ত. আপনার কোডে একটি স্ট্যান্ডার্ড কে-ফ্যাক্টর এবং ক্ল্যাম্প ব্যবহার করুন। দ দাবা রেফারেন্স বাস্তবায়ন K = 32 ব্যবহার করে, তাই একটি খেলা a চলে সর্বাধিক 32 পয়েন্ট দ্বারা রেটিং:

function eloAfter(mine, theirs, score /* 1 win, 0.5 draw, 0 loss */, K = 32) {
  const expected = 1 / (1 + Math.pow(10, (theirs - mine) / 400));
  const next = mine + K * (score - expected);
  return Math.round(Math.max(100, next));      // your floor, if you want one
}

    • আমন্ত্রণ প্রবাহ: থেকে একজন বন্ধু বেছে নিন GET /api/v1/me/friends (দেখুন বন্ধুরা), POST .../invites সঙ্গে { "toUserId": "..." }; আমন্ত্রিত কল POST .../invites/{inviteId}/accept, যা সেশন তৈরি করে। (যদি আপনার গেমটি খেলোয়াড়দেরকে ক রিয়েলটাইম রুম প্রথমে, তাদের পরিবর্তে রুমে আমন্ত্রণ জানান — একই বিজ্ঞপ্তি, কিন্তু গ্রহণ করা হলে আপনি যে টেবিলে আছেন সেই টেবিলে রেখে দিন।)
    • এআই অনুশীলন: POST .../sessions/ai.
  4. সেশন লোড করুন — GET .../sessions/{sessionId}.
  5. WebSocket সংযোগ করুন — ws/v1/games?sessionId={guid} লঞ্চ টোকেন সহ, তারপরে গেমের ব্যাকএন্ড সংজ্ঞায়িত প্রাথমিক-সিঙ্ক কমান্ডটি পাঠান — দাবা রেফারেন্স বাস্তবায়ন, উদাহরণস্বরূপ, পাঠায় {"type":"cmd","data":{"type":"sync"}}.
  6. খেলা - বিনিময় cmd/game ব্যাকএন্ড, পৃষ্ঠ দ্বারা সংজ্ঞায়িত ফ্রেম achievement ফ্রেম, এবং হ্যান্ডেল resumed ভবিষ্যদ্বাণী বাতিল করে এবং একটি পূর্ণ রাষ্ট্রের অনুরোধ করে।
  7. ফলাফল - প্রামাণিক ব্যাকএন্ড গেমটি শেষ করে; প্ল্যাটফর্ম লিডারবোর্ডে ইলো আপডেট প্রকাশ করে এবং এর সাথে একটি গেমের জন্য রিপ্লে, চূড়ান্ত অবস্থা সংরক্ষণাগার.
  8. রিপ্লে — GET .../replays/{sessionId} সম্পূর্ণ চূড়ান্ত অবস্থার জন্য।
