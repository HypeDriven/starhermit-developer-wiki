লোড করুন এবং নিরাপদে অগ্রগতি সংরক্ষণ করুন

সাইন-ইন করা প্লেয়ারের ক্লায়েন্ট-মালিকানাধীন অগ্রগতির জন্য ক্লাউড সেভ ব্যবহার করুন। স্বাক্ষরবিহীন একক প্লেয়ার বিকল্প মেমরিতে অগ্রগতি ধরে রাখে এবং অ্যাকাউন্ট সেভ করে পড়া বা লিখতে পারে না। পছন্দ অন্তর্গত খেলা সেটিংস, অগ্রগতি নথি নয়।

একটি লঞ্চ টোকেন ঠিক অ্যাক্সেস করতে পারে game:<gameId>, কোথায় gameId তার game_scope. প্ল্যাটফর্ম প্রতি স্লটে একটি সংরক্ষণ সহ অস্বচ্ছ বাইট সঞ্চয় করে। আপনার গেমের প্রত্যাশিত বিন্যাস যাচাই করুন। দেখুন ক্লাউড সেভ কোটা এবং শর্তসাপেক্ষ শিরোনামের জন্য।

একটি ছোট সম্পূর্ণ JSON রেসিপি

কপি cloud-save-store.js আপনার বিল্ড মধ্যে. এই উদাহরণ কাঁচা সঞ্চয় UTF-8 JSON বাইট; প্ল্যাটফর্ম তাদের পরিবেশন করে application/zip কিন্তু একটি জিপ বিন্যাস প্রয়োজন হয় না. জিপ সংরক্ষণের জন্য একটি ভিন্ন পাঠক ব্যবহার করুন, সহ ব্রাউজার SDK এর ZIP সংরক্ষণ করে. বিদ্যমান খেলোয়াড়দের জন্য মাইগ্রেশন প্ল্যান ছাড়া ফরম্যাট পরিবর্তন করবেন না।

import { CloudSaveStore } from './cloud-save-store.js';

const store = new CloudSaveStore({
  gameId: StarHermit.slug,
  token: () => StarHermit.token, // Always obtain the current renewed token.
});
const valid = value => value?.version === 1 && Number.isSafeInteger(value.points) && value.points >= 0;
let progress = { version: 1, points: 0 };
let saving = false;

async function startAccountGame() {
  // Keep gameplay/saving disabled until this resolves.
  const remote = await store.load(valid);
  progress = remote ?? { version: 1, points: 0 };
  render(progress);
}

async function saveCheckpoint() {
  if (saving) return; // Coalesce checkpoints; do not issue overlapping writes.
  saving = true;
  showSync('Saving…');
  try {
    await store.save(progress);
    showSync('Saved');
  } catch (error) {
    if (error.status === 412) {
      // Keep local progress in memory. Offer Reload cloud or an explicit merge.
      showConflict(() => startAccountGame());
    } else showSync('Save failed; retry after resolving the error');
  } finally {
    saving = false;
  }
}

render, showSync, এবং showConflict আপনার UI. অপেক্ষা করুন startAccountGame() সক্রিয় করার আগে খেলা বা সংরক্ষণ। লোড ব্যর্থ হলে, প্লেয়ারের বর্তমান স্থানীয় অবস্থা বজায় রাখুন, ব্যর্থতা প্রদর্শন করুন, এবং আপলোড ব্লক রাখুন। ক 404 খালি-স্লট কেস; 401, 403, 5xx, বিকৃত JSON, অথবা একটি অসমর্থিত সংরক্ষণ সংস্করণ খালি স্লট নয়।

রেসিপি শংসাপত্র পুনর্নবীকরণ করে না. ব্রাউজার SDK লঞ্চ টোকেন রিনিউ করে যখন সেগুলি থাকে বৈধ মুলতুবি থাকা শর্তাদি সমাধান করুন বা পুনরায় পড়ার চেষ্টা করার আগে গেমের প্রবেশ প্রবাহের মাধ্যমে পুনরায় প্রমাণীকরণ করুন।

শর্ত এবং দ্বন্দ্ব

কি লোড ছিল পরবর্তী লেখার শিরোনাম অন্য ডিভাইস লিখলে
ETag এর সাথে বিদ্যমান সংরক্ষণ If-Match: <etag> 412 precondition_failed
সংরক্ষণ নেই (404) If-None-Match: * 412 precondition_failed
কিছুই সফলভাবে লোড হয়নি৷ লেখা নেই পড়ার জন্য আবার চেষ্টা করতে থাকুন বা প্লেয়ারকে আনট্র্যাকড প্লেতে থাকতে দিন

থেকে সংস্করণ ব্যবহার করুন আপনার লোড করা ডেটা, পরবর্তী মেটাডেটা চেক নয়। ফিরে আসা নতুন ETag বজায় রাখুন প্রতিটি সফল লেখার মাধ্যমে। ক 412 গেমটি বর্তমান সংস্করণ লোড না হওয়া পর্যন্ত ব্লকগুলি আরও সংরক্ষণ করে খেলোয়াড় এটি গ্রহণ করে বা একত্রিত করে। নিঃশব্দে শর্তটি সরিয়ে অন্য ডিভাইস ওভাররাইট করবেন না। সেই ওভাররাইটকে পূর্বাবস্থায় ফেরাতে API কোনো সংরক্ষণের ইতিহাস অফার করে না।

যদি দুটি ডিভাইসকে স্বাধীনভাবে কাউন্টার বা ইনভেন্টরি আপডেট করতে হয়, একটি একক শেষ-লেখা-জয় নথি খেলার সাথে মানানসই নাও হতে পারে। সার্ভার-অনুমোদিত অবস্থা ব্যবহার করুন এবং পরিবর্তে বৈধ গেম কমান্ড সংজ্ঞায়িত করুন।

বিন্যাস এবং স্থানান্তর সংরক্ষণ করুন

একটি ফর্ম্যাট সংস্করণ অন্তর্ভুক্ত করুন এবং রিমোট গ্রহণ করার আগে প্রকার, পরিসর এবং প্রয়োজনীয় ক্ষেত্রগুলি যাচাই করুন অগ্রগতি সমর্থিত পুরানো সংস্করণগুলির জন্য একটি মাইগ্রেশন লিখুন৷ একটি নতুন অজানা সংস্করণ অক্ষত রাখুন; এটিকে ডিফল্টে রিসেট করবেন না এবং এটিতে আপলোড করবেন না। ক্লাউড ডেটা ক্লায়েন্ট-নিয়ন্ত্রিত, তাই কখনই এটি ব্যবহার করবেন না একটি প্রতিযোগিতামূলক স্কোর বা প্রদত্ত এনটাইটেলমেন্টের প্রমাণ হিসাবে।

ডিফল্ট ডিকোড-সংরক্ষণ সীমা হল 10 MiB। Base64 অনুরোধের অংশে মোটামুটি এক তৃতীয়াংশ যোগ করে। 413 cloud_save_too_large, 409 cloud_save_slots_exhausted, এবং 507 cloud_save_quota_exceeded বিভিন্ন ক্ষমতা ব্যর্থতা হয়; পরিদর্শন code এবং limit. সম্মান Retry-After অন 429.

চেকপয়েন্ট এবং পৃষ্ঠা প্রস্থান

অর্থপূর্ণ চেকপয়েন্টে সংরক্ষণ করুন এবং একটি দৃশ্যমান সংরক্ষণ ক্রিয়া অফার করুন। দ্রুত পরিবর্তন এবং সিরিয়ালাইজ debounce লেখে তাই প্রত্যেকে শেষ স্বীকৃত সংস্করণ ব্যবহার করে। স্বীকার না হওয়া পর্যন্ত একটি নোংরা সূচক রাখুন। একটি ব্যর্থ অনুরোধ একটি নিশ্চিত সংরক্ষণ নয়; একটি অস্পষ্ট লেখার পরে, অন্য লেখার আগে পুনরায় লোড করুন।

একটি পৃষ্ঠা-প্রস্থান আপলোড সেরা প্রচেষ্টা. ব্রাউজার fetch(..., { keepalive: true }) একটি ছোট ইন-ফ্লাইট শেয়ার করে শারীরিক ভাতা, সাধারণত 64 KiB; একটি 10 ​​MiB সংরক্ষণ এটির উপর নির্ভর করতে পারে না। কোনো অনুরোধের আগে একটি ট্যাব বন্ধ হতে পারে শেষ স্থায়িত্বের জন্য সাধারণ ফোরগ্রাউন্ড সেভ ব্যবহার করুন এবং অস্বীকৃত অগ্রগতি হিসাবে লেবেল করবেন না সংরক্ষিত Quickstart প্রতিটি পয়েন্ট সংগ্রহে তার ছোট নথি সংরক্ষণ করে।

আপনার খেলা যাচাই করুন

  1. একটি খালি স্লট দিয়ে শুরু করুন; অগ্রগতি সংগ্রহ করুন, সংরক্ষণ করুন, পুনরায় লোড করুন এবং এটি ফেরত নিশ্চিত করুন।
  2. একটি নেটওয়ার্ক ত্রুটি সহ পড়া প্রত্যাখ্যান, 403, বা অবৈধ তথ্য; কোন আপলোড অনুসরণ নিশ্চিত করুন.
  3. একটি সংস্করণে দুটি ট্যাব খুলুন। A-তে সংরক্ষণ করুন, তারপর B: B-কে অবশ্যই একটি দ্বন্দ্ব দেখা দিতে হবে এবং এর স্থানীয় অবস্থা সংরক্ষণ করতে হবে।
  4. অজানা ডেটা ওভাররাইট না করে একটি পুরানো/নতুন ফর্ম্যাট এবং অনুপস্থিত স্বীকৃতি পরীক্ষা করুন।
  5. আনট্র্যাকড একক-প্লেয়ার মোডে প্রবেশ করুন এবং যাচাই করুন যে খেলাটি ক্লাউড-সংরক্ষণের অনুরোধ করে না।

দেখুন রানেবল কুইকস্টার্ট, এপিআই কনভেনশন, এবং সমস্যা সমাধান.
