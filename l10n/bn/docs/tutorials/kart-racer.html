টিউটোরিয়াল: একটি মাল্টিপ্লেয়ার কার্ট রেসার তৈরি করুন

এই টিউটোরিয়ালটি একটি আর্কেড কার্ট রেসারের মাল্টিপ্লেয়ার স্তর তৈরি করে — আটটি কার্ট পর্যন্ত, ব্যক্তিগত বন্ধুদের সাথে লবি, অপরিচিতদের সাথে দ্রুত যোগদান, সিপিইউ ড্রাইভাররা খালি গ্রিড স্লট পূরণ করছে, একটি গণনা, ল্যাপস, একটি ফিনিশিং অর্ডার এবং অর্জন — StarHermit API-তে। এটি নেটকোড চুক্তি কভার করে এবং প্ল্যাটফর্ম কল; আপনার ইঞ্জিন, ট্র্যাক আর্ট এবং হ্যান্ডলিং মডেল আপনার নিজস্ব।

এখানে খেলা-নির্দিষ্ট সবকিছু — the grand-prix সারি, বাইনারি ফ্রেম বিন্যাস, আইটেম বোতাম, পদার্থবিজ্ঞানের ধ্রুবক - একটি উদাহরণ মান। শুধুমাত্র শেষ পয়েন্ট, ফ্রেম খাম এবং সীমা আছে প্ল্যাটফর্ম আচরণ, এবং প্রতিটি তার রেফারেন্স পৃষ্ঠার সাথে লিঙ্ক করে।

1. একটি স্থাপত্য চয়ন করুন

সার্ভার টিক বাজেটের জন্য একটি রেসার হল খেলার সবচেয়ে কঠিন আকৃতি: কার্ট দ্রুত চলে, সংঘর্ষ হয় এবং খেলোয়াড়রা 50 ms স্টিয়ারিং ল্যাগ অনুভব করে। StarHermit আপনাকে এটি চালানোর দুটি উপায় দেয়, উভয়ই একটি থেকে শুরু করে রিয়েলটাইম রুম:

উ: হোস্ট-রুটেড B. সার্ভার-অনুমোদিত স্ক্রিপ্ট
কে অনুকরণ করে রুম হোস্টের ক্লায়েন্ট, যেকোন হারে এটি পছন্দ করে (60 Hz+) আপনার server= স্ক্রিপ্ট, সর্বাধিক 30 Hz
পরিবহন বাইনারি ফ্রেম চালু ws/v1/realtime JSON cmd/game ফ্রেম চালু ws/v1/games
প্রতারণা হোস্ট বিশ্বস্ত ক্লায়েন্টদের শূন্য কর্তৃত্ব আছে
ইলো, স্ক্রিপ্ট কৃতিত্ব না (হোস্ট একটি ক্ল্যাম্পড ফলাফল পোস্ট করে) হ্যাঁ - eloUpdates, achievements, রিপ্লে
জন্য সেরা বন্ধুদের সাথে নৈমিত্তিক রেস, সম্পূর্ণ বিশ্বস্ত পদার্থবিদ্যা সহজ আর্কেড পদার্থবিদ্যার সাথে র‌্যাঙ্ক করা রেসিং

দিয়ে শুরু করুন A যদি না আপনার র‌্যাঙ্ক করা খেলার প্রয়োজন হয়; অধ্যায় 7 দেখায় কি জন্য পরিবর্তন B. A ধারক সার্ভার একটি আট-কার্টও চালাতে পারে রুমে আবদ্ধ জাতি এবং প্রামাণিকভাবে 60 Hz এ অনুকরণ করুন। এর সরাসরি গেম API ম্যাচমেকিং বর্তমানে একটি অন্তর্নিহিত 1v1 ব্যবহার করে সারি, তাই বড় গ্রিডের জন্য একটি রিয়েলটাইম রুম ব্যবহার করুন। প্ল্যাটফর্ম ধারক এর লুপ ধাপ না.

2. প্রকাশ

এটি দিয়ে বিতরণযোগ্য বিল্ড ফোল্ডারটি প্রকাশ করুন starhermit.txt এর মূলে (দেখুন ম্যানিফেস্ট) দ control.* লাইন প্লেয়ারদের একটি রিবাইন্ডিং UI দেয় এবং আপনার ক্লায়েন্ট a API নিয়ন্ত্রণ করে থেকে বাইন্ডিং পড়তে:

name=Turbo Hermits
launch=index.html
cover=art/cover.png
control.accelerate=KeyW+ArrowUp | Accelerate
control.brake=KeyS+ArrowDown | Brake / reverse
control.left=KeyA+ArrowLeft | Steer left
control.right=KeyD+ArrowRight | Steer right
control.drift=ShiftLeft+ShiftRight | Drift
control.item=Space | Use item

পথ A আছে না server= লাইন যদি একটি গেম একটি স্ক্রিপ্ট পাঠায়, একটি রুম শুরু করা একটি আবদ্ধ সেশন তৈরি করে এবং শুধুমাত্র স্ক্রিপ্ট ম্যাচটি শেষ করতে পারে — হোস্টের POST .../result দৌড় শেষ হওয়ার পথ বন্ধ করে (ধারা 7)।

3. সাইন ইন করুন এবং মূল বিষয়গুলি পড়ুন৷

একটি প্ল্যাটফর্ম-হোস্টেড গেম এর সাথে খোলা হয় #game_token=<jwt> URL-এ - একবার পড়ুন, এটি দিয়ে ফালান history.replaceState, এবং এর 60-মিনিট মেয়াদ শেষ হওয়ার আগে এটি রিফ্রেশ করুন (বিস্তারিত দাবা ওয়াকথ্রু এবং প্রমাণ) আপনার স্লাগ টোকেন এর game_scope দাবি (বা location.hostnameএর প্রথম লেবেল); এটা হার্ড কোড না.

লোড করার সময়, মেনুতে যা প্রয়োজন তা আনুন:

GET /api/v1/games/{slug}/controls     # effective key bindings (manifest defaults + overrides)
GET /api/v1/games/{slug}/settings     # camera, volume, last chosen kart — your own keys
GET /api/v1/realtime/rooms/mine       # 200 → the player is still in a race; rejoin it

সঙ্গে মেনু পছন্দ সংরক্ষণ করুন PATCH /api/v1/games/{slug}/settings ({"settings":{"kart":"hermit-crab"}}) সেটিংস মেশিন জুড়ে প্লেয়ার অনুসরণ করে এবং কোনো ঘোষণার প্রয়োজন নেই।

4. লবি

একটি গ্র্যান্ড প্রিক্স সবার জন্য বিনামূল্যে, তাই রুমে আটটি আসনের একটি দল রয়েছে৷ ট্র্যাক, ল্যাপ কাউন্ট এবং ইঞ্জিন ক্লাস অস্বচ্ছ মধ্যে যান metadata:

POST /api/v1/realtime/rooms
Authorization: Bearer <launch token>

{ "teamCount": 1, "seatsPerTeam": 8, "backfillAfterSeconds": 45,
  "aiPlayers": 0, "name": "Friday cup", "isVisible": true,
  "metadata": { "track": "coral-loop", "laps": 3, "cc": 150 } }

একটি লঞ্চ টোকেন দিয়ে রুম এর খেলা টোকেন থেকে আসে, তাই gameSlug বাদ দেওয়া যেতে পারে। সৃষ্টিকর্তা সিট এ হোস্ট হয় (0, 0). এখান থেকে লবি হল সাধারণ রুম প্রবাহ:

  • বন্ধুরা — POST /rooms/{id}/invites সঙ্গে {"toUserId": ...}. প্ল্যাটফর্ম তাদের অবহিত করে; তাদের আসন গ্রহণ. ছয়-অক্ষর দেখাও joinCode তাই বন্ধুরাও এটি টাইপ করতে পারে POST /rooms/join-by-code.
  • অপরিচিত - হোস্ট কল POST /rooms/{id}/open. কোন রুম কল সঙ্গে খেলোয়াড়দের POST /rooms/quick-join সঙ্গে {"seats": 1} এবং, অন 404, তৈরি এবং তাদের নিজস্ব খুলুন.
  • ট্র্যাক ভোট / হোস্ট মানসিক পরিবর্তন — PATCH /rooms/{id} নতুন সঙ্গে metadata এবং রুম এর revision হিসাবে expectedRevision.
  • সিপিইউ-এর বিরুদ্ধে একক — দিয়ে তৈরি করুন "aiPlayers": 7, তারপর POST /rooms/{id}/start.

একটি খোলা ঘর নিজেই শুরু হয় যখন সমস্ত আটটি আসন পূর্ণ হয় বা backfillAfterSeconds পাস হোস্ট এছাড়াও পারেন POST /rooms/{id}/start. প্রতিটি স্থির-খালি আসন একজন এআই অংশগ্রহণকারী হয়ে ওঠে — সেগুলি আপনার CPU ড্রাইভার।

5. রেস সকেট (হোস্ট-রুটেড)

সংযোগ করুন

প্রত্যেক অংশগ্রহণকারী এক-ব্যবহারের টিকিটের সাথে রিয়েলটাইম সকেট খোলে:

const { ticket } = await api.post("/api/v1/realtime/connection-tickets"); // { ticket, expiresIn }
const ws = new WebSocket(
  `wss://api.starhermit.com/ws/v1/realtime?roomId=${roomId}&ticket=${encodeURIComponent(ticket)}`);
ws.binaryType = "arraybuffer";

পাঠ্য ফ্রেমগুলি হল JSON পুশ এবং নিয়ন্ত্রণ ফ্রেম; বাইনারি ফ্রেম হল গেমপ্লে। দ roster ধাক্কা হয় আপনার গ্রিড: শুরু করার পরে এটি হিমায়িত হয়, এআই আসন অন্তর্ভুক্ত। একটি দলের সঙ্গে, একটি কার্ট এর গ্রিড স্লট তার অংশগ্রহণকারীর slot.

ws.onmessage = (e) => {
  if (typeof e.data === "string") return onControl(JSON.parse(e.data)); // roster, presence, event, ready, chat, result
  const bytes = new Uint8Array(e.data);
  const sender = guidFromDotNet(bytes.subarray(0, 16)); // server-stamped, trustworthy
  onGameplay(sender, new DataView(e.data, 16));          // your payload starts at byte 16
};

// The server prefixes the sender's participant id in .NET GUID byte order:
// the first three groups are little-endian.
function guidFromDotNet(b) {
  const h = (i) => b[i].toString(16).padStart(2, "0");
  return `${h(3)}${h(2)}${h(1)}${h(0)}-${h(5)}${h(4)}-${h(7)}${h(6)}-` +
         `${h(8)}${h(9)}-${h(10)}${h(11)}${h(12)}${h(13)}${h(14)}${h(15)}`;
}

আপনার নিজের পেলোডে কখনও প্লেয়ার আইডি রাখবেন না এবং এটিকে বিশ্বাস করবেন না — 16-বাইট উপসর্গই একমাত্র পরিচয় যে সার্ভার গ্যারান্টি দেয়।

রাউটিং এবং বাজেট

প্ল্যাটফর্মটি হোস্ট-রুটেড খেলার আকার প্রয়োগ করে:

  • A অতিথি এর বাইনারি ফ্রেম পৌঁছায় শুধুমাত্র হোস্ট — সেটা হল ইনপুট চ্যানেল।
  • দ হোস্ট এর বাইনারি ফ্রেম পৌঁছায় প্রত্যেক অতিথি — সেটা হল স্ন্যাপশট চ্যানেল।
  • প্রতিটি ফ্রেম সর্বাধিক 8 KB; প্রতিটি সংযোগ পাঠাতে পারে 30টি বার্তা/সেকেন্ড (একের জন্য 2× বিস্ফোরণ দ্বিতীয়)। ওভার যাওয়া সঙ্গে সকেট বন্ধ PolicyViolation.

তাই হোস্ট যে হারে সঠিক মনে করে তা অনুকরণ করে (60 Hz সাধারণত) কিন্তু পাঠায় এ স্ন্যাপশট 20 Hz, এবং অতিথিরা 20 Hz এ ইনপুট পাঠান। এটি মাঝে মাঝে নিয়ন্ত্রণ ফ্রেমের জন্য হেডরুম ছেড়ে দেয়।

ফ্রেম লেআউট (উদাহরণ)

ইনপুট, অতিথি → হোস্ট, 7 বাইট:

অফসেট টাইপ মাঠ
0 u8 1 = ইনপুট
1 u16 seq - প্রতি পাঠাতে বৃদ্ধি
3 i8 স্টিয়ার, −127…127
4 u8 থ্রোটল, 0…255
5 u8 বিট: 0 ব্রেক, 1 ড্রিফট
6 u8 itemPresses - একটি কাউন্টার, একটি পতাকা নয়

itemPresses আইটেম-বোতাম প্রেসের একটি চলমান গণনা। 20 Hz এ 50 ms এর চেয়ে ছোট একটি প্রেস হবে অন্যথায় নমুনার মধ্যে পড়ে; একটি কাউন্টার সহ হোস্ট প্রতি বৃদ্ধি একটি আইটেম ফায়ার, তবে প্রেস অবতরণ.

স্ন্যাপশট, হোস্ট → অতিথি, কার্ট প্রতি 4 + 22 বাইট (সম্পূর্ণ গ্রিডের জন্য 176 বাইট):

অফসেট টাইপ মাঠ
0 u8 2 = স্ন্যাপশট
1 u16 হোস্ট টিক
3 u8 কার্ট গণনা
কার্ট প্রতি u8, f32 ×4, u8, u16, u8, u8 স্লট, x, z, শিরোনাম, গতি, ল্যাপ, চেকপয়েন্ট, আইটেম, পতাকা

অতিথিরা অন্যান্য কার্ট রেন্ডার করে অতীতে ~100 ms, দুই স্ন্যাপশট মধ্যে interpolating যে সেই সময় বন্ধনী করুন, এবং তাদের ইনপুট থেকে স্থানীয়ভাবে তাদের নিজস্ব কার্ট ভবিষ্যদ্বাণী করুন, হোস্টের দিকে সহজে অবস্থান যখন তারা একমত না। শেষ ইনপুট অন্তর্ভুক্ত করুন seq হোস্ট প্রতি কার্ট ইন প্রয়োগ করা হয় flags অথবা একটি অতিরিক্ত ক্ষেত্র যদি আপনি সঠিক পুনর্মিলন চান।

কাউন্টডাউন, রেস ইভেন্ট, শেষ

কন্ট্রোল ফ্রেমগুলি হল JSON, সর্বাধিক 4 KB, এবং সার্ভার স্ট্যাম্প৷ from প্রেরকের অংশগ্রহণকারী আইডি সহ:

  • অতিথিরা পাঠান {"type":"ready"} একবার ট্র্যাক লোড হয়েছে.
  • হোস্ট প্রতিটি সংযুক্ত মানুষের জন্য প্রস্তুত (বা একটি টাইমআউট) হওয়ার জন্য অপেক্ষা করে, তারপর পাঠায় {"type":"event","kind":"countdown","goInMs":3000}. অতিথিরা তাদের স্থানীয় গণনা শুরু করে রসিদ - এই নির্ভুলতায় কোন ঘড়ি সিঙ্কের প্রয়োজন নেই।
  • অন্যান্য রেস বীট এছাড়াও হয় event ফ্রেম: {"kind":"lap","slot":3,"lap":2}, {"kind":"finished","slot":3,"place":1,"timeMs":94210}.
  • chat প্রত্যেকের জন্য উপলব্ধ, কিন্তু অতিথিরা প্রতি মিনিটে 10টি কন্ট্রোল ফ্রেমের মধ্যে সীমাবদ্ধ - এর জন্য প্রচুর ready এবং কয়েক "gg"s, গেমপ্লের জন্য নয়।

যখন শেষ মানুষ লাইনটি অতিক্রম করে (অথবা বিজয়ী শেষ হওয়ার পরে একটি টাইমার), হোস্ট জমা দেয় ফলাফল, যা রুম বন্ধ করে এবং ধাক্কা দেয় {"type":"result"} সবার কাছে:

POST /api/v1/realtime/rooms/{id}/result

{ "teamScores": [0],
  "metadata": { "track": "coral-loop",
                "order": [ { "slot": 3, "timeMs": 94210 }, { "slot": 0, "timeMs": 95002 } ],
                "bestLapMs": 30112 } }

teamScores প্রতি দলে ঠিক একটি এন্ট্রি প্রয়োজন (ক্ল্যাম্পড 0-50), যা a-তে দরকারী কিছুই বহন করে না সবার জন্য বিনামূল্যে; সমাপ্তি আদেশ বাস metadata. একটি দল রেস সঙ্গে একই ঘর teamCount: 2 এবং প্রতিটি দলের পয়েন্ট teamScores.

সিপিইউ ড্রাইভার, লিভার এবং হোস্ট পরিবর্তন

  • গাড়ি চালানোর জন্য এআই আসনগুলি আপনার। প্ল্যাটফর্মটি আসন সংরক্ষণ করে এবং ড্রাইভারের নাম রাখে; হোস্ট এর সিমুলেশন এটিকে পরিচালনা করে (চেকপয়েন্টগুলির মধ্য দিয়ে একটি রেসিং লাইন, কিছু রাবার-ব্যান্ডিং সহ)।
  • একজন অতিথি যিনি মধ্য-জাতি ছেড়ে চলে যান (POST /rooms/{id}/leave) তাদের কার্টকে গ্রিডে রাখে: রোস্টার push একই অংশগ্রহণকারী দেখায় id এখন isAi: true, এবং হোস্টের CPU সেই কার্ট দখল করে।
  • একজন অতিথি যিনি ড্রপ করেন এখনও রুমে আছে; তাদের কার্ট কোস্টিং রাখুন এবং তাদের পুনরায় সংযোগ করতে দিন - নতুন সকেটটি পুরানোটিকে ছাড়িয়ে যায়।
  • যদি হোস্ট চলে যায়, হোস্ট ভূমিকা দীর্ঘতম যোগদান অবশিষ্ট মানুষের পাস এবং রোস্টার পুশ নতুন দেখায় isHost. প্রত্যেক অতিথি ইতিমধ্যেই সর্বশেষ সম্পূর্ণ স্ন্যাপশট ধারণ করে, তাই নতুন হোস্ট এটি থেকে সিমুলেশন পুনরায় শুরু করে এবং স্ন্যাপশট পাঠাতে শুরু করে; গেস্ট ইনপুট এখন তাদের রুট. হোস্ট মাইগ্রেশন হল আপনার কোডের কাজ — প্ল্যাটফর্মটি শুধুমাত্র ভূমিকা নিয়ে যায়।
  • হোস্ট শুধু সংযোগ বিচ্ছিন্ন হলে, রুমটি হোস্ট সকেট ছাড়াই 60 সেকেন্ড পরে বন্ধ হয়ে যায়।

6. দৌড়ের চারপাশে

  • ভয়েস এবং চ্যাট. প্রত্যেক গেস্ট ইতিমধ্যে করতে পারেন chat রিয়েলটাইম সকেটে; ভয়েসের জন্য, দেখুন ভয়েস.
  • রিম্যাচ। রেজাল্টের পর রুম বন্ধ। হোস্টকে একটি নতুন রুম তৈরি করতে এবং আমন্ত্রণ জানান আগের রোস্টারের মানুষ, অথবা সবাইকে দ্রুত যোগ দিতে পাঠান।
  • ল্যাপ-টাইম লিডারবোর্ড। একটি গেমের প্ল্যাটফর্ম লিডারবোর্ড হল এর ইলো বোর্ড, শুধুমাত্র একটি সার্ভার দ্বারা লেখা রানটাইম একটি প্রকাশক-সংজ্ঞায়িত লিডারবোর্ড গ্রহণ করে POST /api/v1/leaderboards/{id}/submit, কিন্তু যে স্কোর ক্লায়েন্ট দ্বারা দাবি করা হয় — একটি বন্ধুত্বপূর্ণ সময় ট্রায়ালের জন্য জরিমানা, পুরস্কার সহ কিছুর জন্য নয়।

7. ভেরিয়েন্ট বি: সার্ভার-অথরিটেটিভ রেসিং

র‌্যাঙ্ক করা খেলার জন্য, সিমুলেশনটিকে একটি স্ক্রিপ্টে সরান। লবি অপরিবর্তিত; স্ক্রিপ্ট যোগ করুন এবং ম্যানিফেস্টে ম্যাচমেকিং সেটিংস:

server=server.js
matchmaking.max_wait_seconds=20
matchmaking.ai_players=7

এখন দুটি জিনিস রেস তৈরি করে: একটি রুম শুরু এর মানুষের জন্য একটি রুম-বাউন্ড সেশন তৈরি করে, এবং ম্যাচমেকিং (POST /api/v1/games/{slug}/matchmaking?queue=grand-prix) একটি তৈরি করে যখন আট প্লেয়ার পাওয়া যায় - অথবা, উপরের সেটিংস সহ, 20 সেকেন্ড পরে CPU-এর সাথে সাতটি পর্যন্ত খালি আসন বন্ধুদের একটি লবি একসাথে সারিবদ্ধ হতে পারে POST /realtime/rooms/{id}/matchmake.

যেভাবেই হোক, ক্লায়েন্টরা নেয় sessionId (রুমের gameSessionId, অথবা মিলে যাওয়া টিকিটের) এবং খেলা ws/v1/games?sessionId=…. রিয়েলটাইম সকেট, যদি থাকে, শুধুমাত্র রোস্টারের জন্য রাখা হয়।

স্ক্রিপ্ট

পুরো সিমুলেশন সঞ্চালিত হয় onTick 30 Hz সিলিং এ প্রতিটি আহ্বান একটি তাজা স্যান্ডবক্স যে পায় sessionState ভিতরে এবং এটিকে ফিরিয়ে দেয়, তাই সেই অবস্থাটিকে ছোট রাখুন - এটি প্রতিটি টিককে সিরিয়ালাইজ করা হয়।

const TRACK = { laps: 3, radius: 14,
  checkpoints: [[0, 0], [120, 0], [160, 60], [120, 120], [0, 120], [-40, 60]] };

globalThis.game = {
  tickRateHz: 30,
  replays: true,
  queues: [{ key: "grand-prix", teams: 8, teamSize: 1 }],
  achievements: [
    { key: "chequered-flag", name: "Chequered Flag", description: "Win a race.", points: 10 }
  ],

  createSession(ctx) {
    const karts = racers(ctx).map((r, i) => ({
      id: r.id, name: r.name, ai: r.ai, x: -8 * (i % 2), z: -6 * i, heading: 0, speed: 0,
      cp: 1, lap: 0, boost: 0, boosts: 1, input: {}, ack: 0, finishedAt: null
    }));
    return { ok: true, sessionState: { t: ctx.now, goAt: ctx.now + 4000, karts, order: [] } };
  },

  onPlayerMessage(ctx) {                       // durable commands: discrete actions
    const s = copy(ctx.sessionState);
    const k = s.karts.find((k) => k.id === ctx.message.from);
    if (ctx.message.data?.type === "use-item" && k && k.boosts > 0 && ctx.now >= s.goAt) {
      k.boosts--; k.boost = 1.2;
    }
    return { ok: true, sessionState: s };
  },

  onTick(ctx) {
    const s = copy(ctx.sessionState);
    const dt = Math.min(Math.max((ctx.now - s.t) / 1000, 0), 0.1);
    s.t = ctx.now;
    for (const i of ctx.inputs || []) {        // latest realtime input per player since last tick
      const k = s.karts.find((k) => k.id === i.from);
      if (k) { k.input = i.data; k.ack = Math.max(k.ack, Math.floor(+i.data.seq) || 0); }
    }
    if (ctx.now >= s.goAt) {
      for (const k of s.karts) {
        if (k.finishedAt) continue;
        move(k, k.ai ? aiInput(k) : k.input, dt);   // pure motion — shared with the client
        progress(k, s, ctx);                        // checkpoints, laps, finish — server only
      }
    }
    const snap = s.karts.map((k) =>
      [k.id, r2(k.x), r2(k.z), r3(k.heading), r2(k.speed), r2(k.boost), k.lap, k.cp, k.ack]);
    const out = { ok: true, sessionState: s,
      broadcast: [{ to: "all", data: { type: "snap", t: s.t, goAt: s.goAt, karts: snap } }] };
    if (raceOver(s, ctx)) Object.assign(out, finish(s, ctx));
    return out;
  }
};

সাহায্যকারী সাধারণ গেম কোড. প্ল্যাটফর্মটি যে অংশগুলির বিষয়ে যত্নশীল:

  • racers(ctx) অধিবেশন শুরু যেটি থেকে গ্রিড পড়ে: ctx.room.roster একটি জন্য রুম (AI আসন আছে userId: null, তাই তাদের মত আইডি দিন ai-0-5), ctx.matchmaking.seats একটি জন্য ম্যাচমেড রেস (এর সাথে আসনগুলি এড়িয়ে যান id: null), অন্য ctx.players.
  • move(k, input, dt) আবশ্যক প্রতিটি ইনপুট মান ক্ল্যাম্প করুন — steer থেকে −1…1, throttle থেকে 0…1 — কারণ ctx.inputs[].data ক্লায়েন্ট যা পাঠিয়েছে তা। শুধুমাত্র from বিশ্বস্ত হয় এটা বিশুদ্ধ রাখুন - না ctx, কোন সেশন স্টেট নেই — তাই ক্লায়েন্টও এটি চালাতে পারে (দেখুন ক্লায়েন্ট-সাইড পূর্বাভাস).
  • এলোমেলোতা এবং সময় থেকে আসা ctx.random এবং ctx.now; নেই Date বা Math.random.
  • finish(s, ctx) রিটার্ন result (যা সেশন শেষ করে এবং, একটি রুমের জন্য, এটি বন্ধ করে) achievements বিজয়ীর জন্য যদি মানুষ, এবং eloUpdates হিউম্যান রেসারদের জন্য - উদাহরণস্বরূপ পেয়ারওয়াইসে সমাপ্তি ক্রম জুড়ে elo, থেকে পড়া এবং ফিরে লেখা ctx.playerStates. AI আসন যাবে না খেলোয়াড়ের অবস্থা, রেটিং বা কৃতিত্ব পান।
  • raceOver এছাড়াও জাতি শেষ করা উচিত কেউ শেষ করতে পারে না - প্রতিটি মানুষ চলে গেছে অনুযায়ী ctx.presence (রুম), অথবা একটি কঠিন সময়সীমা।
  • রিপ্লে শুধুমাত্র রাখা চূড়ান্ত sessionState. একটি কমপ্যাক্ট ল্যাপ-টাইম টেবিল এবং ফিনিশিং রাখুন এটিতে অর্ডার করুন, প্রতি-টিক অবস্থান লগ নয়।

ক্লায়েন্ট

একটি রিয়েলটাইম ইনপুট হিসাবে স্টিয়ারিং পাঠান প্রতিটি টিক এবং বিচ্ছিন্ন ক্রিয়াগুলি টেকসই কমান্ড হিসাবে:

// ~30 Hz: latest-wins, batched into the next onTick
send({ type: "cmd", data: { type: "input", realtime: true, seq: ++seq,
                            steer, throttle, brake, drift } });

// on key press: a durable command, runs onPlayerMessage immediately
send({ type: "cmd", data: { type: "use-item" } });

আইটেম আবশ্যক একটি টেকসই আদেশ মাধ্যমে যান. রিয়েলটাইম ইনপুট হল সর্বশেষ-টিক্স এবং এর মধ্যে জয় প্ল্যাটফর্ম শুধুমাত্র এক-শট ক্ষেত্র সংরক্ষণ করে pass, tackle এবং shoot যখন একটি নতুন নমুনা একটি পুরানোটিকে প্রতিস্থাপন করে — রিয়েলটাইম ইনপুটে অন্য যেকোন বোতাম টিকের আগে ওভাররাইট করা যেতে পারে এটা দেখে

achievement ফ্রেম একই সকেটে আসে; পড়া GET /api/v1/games/{slug}/achievements অন এটি খোলার আগে মঞ্জুর করা কিছুর জন্য লোড করুন।

ক্লায়েন্ট-সাইড পূর্বাভাস

শুধুমাত্র সার্ভার যা পাঠায় তা রেন্ডার করলে কার্টকে মনে হয় যেন এটি কাদার মধ্য দিয়ে চালিত হয়। একটি স্টিয়ারিং পরিবর্তনের জন্য সার্ভারে পৌঁছাতে হবে, পরবর্তী টিক (30 Hz এ 33 ms পর্যন্ত) অপেক্ষা করতে হবে এবং একটিতে ফিরে আসতে হবে snap — 80 ms ping-এ যা কার্ট ঘুরার আগে 100 ms-এর বেশি। ভবিষ্যদ্বাণী লুকিয়ে রাখে যে: ক্লায়েন্ট চলে তার নিজস্ব কার্ট অবিলম্বে এবং প্রতিটি চিকিত্সা snap একটি সংশোধন হিসাবে, ছবি হিসাবে না.

মোশন কোড শেয়ার করুন

উপরের স্ক্রিপ্টের মতো সিমুলেশনটি বিভক্ত করুন: একটি বিশুদ্ধ move(k, input, dt) পরিচালনার জন্য, এবং শুধুমাত্র সার্ভার progress চেকপয়েন্ট, ল্যাপ এবং সমাপ্তির জন্য। থেকে মোশন কোড প্রকাশ করুন server.js দ্বিতীয় বিশ্ব হিসাবে - প্যাটার্ন দাবা এর জন্য ব্যবহার করে globalThis.chessRules - এবং একই ফাইল লোড করুন ব্রাউজার:

// server.js — shared by the platform's sandbox and the browser
function move(k, input, dt) { /* clamp input, integrate speed, heading, x, z, boost */ }
globalThis.kartPhysics = { move, TRACK };
globalThis.game = { /* ... as above ... */ };

<script src="server.js"></script>  <!-- defines kartPhysics; the client never calls game.* -->

ক্লায়েন্ট ভবিষ্যদ্বাণী করে গতি শুধুমাত্র. ল্যাপস, পজিশন, আইটেম এবং ফিনিশ অর্ডার সার্ভারেরই থাকে কল বিট-অভিন্ন ফলাফল আশা করবেন না: স্যান্ডবক্স এবং ব্রাউজার শেষ বিটগুলিতে অসম্মত হতে পারে Math.sin/Math.cos, এবং অবস্থান snap বৃত্তাকার হয় পুনর্মিলন সেই প্রবাহকে শোষণ করে।

সার্ভারের ছন্দে পা বাড়ান

সার্ভার প্রতি ইনপুট এক ধাপ চালায় না. প্রতিটি টিক এটি প্রযোজ্য সর্বশেষ ইনপুট এটি ধরে রাখে যে কার্ট, একটি নতুন না আসা পর্যন্ত এটি ব্যবহার করতে থাকে, এবং এর পর থেকে বাস্তব সময়ের সাথে একত্রিত হয় আগের টিক। তাই ডিসপ্লে ফ্রেমের হারে না গিয়ে সেই আকৃতিটিকে আয়না করুন:

const pending = [];                              // inputs the server hasn't acknowledged yet
let seq = 0, predicted, previous;               // { x, z, heading, speed, boost }, seeded from the first snap
let error = { x: 0, z: 0, heading: 0 };          // visual offset, decays in render()

setInterval(() => {                              // 30 Hz, the script's tickRateHz
  if (!predicted || serverNow() < goAt) return;  // the server ignores movement before goAt
  const input = { steer: readSteer(), throttle: readThrottle(), brake: held("brake"), drift: held("drift") };
  const entry = { seq: ++seq, input, dt: 1 / 30 };
  send({ type: "cmd", data: { type: "input", realtime: true, seq: entry.seq, ...input } });
  pending.push(entry);
  previous = { ...predicted };
  kartPhysics.move(predicted, input, entry.dt);  // the kart responds now, not a round trip later
}, 1000 / 30);

টিক হারের চেয়ে দ্রুত প্রেরণ করা নষ্ট হয় — প্রতি টিক শুধুমাত্র সর্বশেষ ইনপুট ব্যবহার করা হয় — এবং প্ল্যাটফর্ম তার প্রতি-সংযোগ ক্যাপের উপরে রিয়েলটাইম ইনপুট ড্রপ করে।

প্রতিটি উপর পুনর্মিলন snap

স্ক্রিপ্ট প্রতিধ্বনিত হয় ack, সর্বোচ্চ seq এটি প্রতিটি কার্টের জন্য আবেদন করেছে। প্রতিটির উপর snap, আপনার রিওয়াইন্ড সার্ভারের অবস্থায় কার্ট করুন এবং সার্ভার এখনও যা দেখেনি তা পুনরায় চালান:

function onSnap(snap) {
  const [, x, z, heading, speed, boost, lap, cp, ack] = snap.karts.find((k) => k[0] === myId);
  while (pending.length && pending[0].seq <= ack) pending.shift();   // applied or superseded

  const corrected = { x, z, heading, speed, boost };
  for (const p of pending) kartPhysics.move(corrected, p.input, p.dt);

  if (!predicted) { predicted = corrected; previous = { ...corrected }; return; } // first snap
  error.x += predicted.x - corrected.x;          // what the player would see jump
  error.z += predicted.z - corrected.z;
  error.heading += predicted.heading - corrected.heading;
  if (Math.hypot(error.x, error.z) > 3) error = { x: 0, z: 0, heading: 0 }; // wall hit, bump: snap
  predicted = corrected;
  hud.lap = lap; hud.checkpoint = cp;            // progress is never predicted
}

পর্যন্ত সবকিছু বর্জন করা হচ্ছে ack সর্বশেষ-জয় কিছু ইনপুট এড়িয়ে গেলেও সঠিক: একটি এড়িয়ে যাওয়া সার্ভারে টিক লাগানোর আগে ইনপুট বাতিল করা হয়েছিল, তাই এটি সার্ভারের কার্টকেও প্রভাবিত করেনি।

মসৃণ সংশোধন, ফ্রেম হারে রেন্ডার

ছোট সংশোধন অদৃশ্য হওয়া উচিত. ভবিষ্যদ্বাণীকৃত অবস্থানে কার্টটি আঁকুন প্লাস একটি ক্ষয় ত্রুটি অফসেট, এবং শেষ দুটি 30 Hz ভবিষ্যদ্বাণী পদক্ষেপের মধ্যে ইন্টারপোলেট করুন যাতে একটি 60 বা 144 Hz ডিসপ্লে মসৃণভাবে চলে:

function render(frameDt) {
  const decay = Math.exp(-frameDt / 0.1);        // ~100 ms to absorb a correction
  error.x *= decay; error.z *= decay; error.heading *= decay;
  const a = sinceLastStep() * 30;                // 0…1 between prediction steps
  drawKart(lerp(previous.x, predicted.x, a) + error.x,
           lerp(previous.z, predicted.z, a) + error.z,
           lerpAngle(previous.heading, predicted.heading, a) + error.heading);
}

ক্ষয়ের চেয়ে স্ন্যাপ থ্রেশহোল্ড টিউন করুন: কার্ট দৈর্ঘ্যের চেয়ে বড় একটি সংশোধন একটি বাস্তব ইভেন্ট (একটি বাম্প যা আপনি ভবিষ্যদ্বাণী করেননি) এবং একটি ধীর স্লাইডের চেয়ে দ্রুত স্ন্যাপ হিসাবে ভাল পড়ে।

কী ভবিষ্যদ্বাণী করা উচিত নয় তা জানুন

  • অন্যান্য কার্ট। এগুলি অতীতে ~100 ms আঁকা হয়েছে (বাফার snaps এবং মধ্যে interpolate দুই যে বন্ধনী serverNow() - 100), তাই তাদের বিরুদ্ধে ভবিষ্যদ্বাণী করা একটি সংঘর্ষ হল একটি সংঘর্ষ যেখানে তারা ছিল. দেয়াল এবং ট্র্যাকের পূর্বাভাস দিন - তারা সরে না - এবং সার্ভারকে সমাধান করতে দিন kart-to-kart bumps. সংশোধন একটি রাউন্ড ট্রিপ মধ্যে আসে. বাফার শুষ্ক সঞ্চালিত হলে, extrapolate গতি থেকে এবং ~100 ms পর্যন্ত হেডিং, তারপর ধরে রাখুন।
  • আইটেম use-item একটি টেকসই কমান্ড, তাই এটি চলে onPlayerMessage আসার সাথে সাথে - কোন টিক অপেক্ষা করুন কী টিপে শিখা এবং শব্দ বাজান; গতির মাধ্যমে আসা যাক পুনর্মিলন, যেহেতু boost মধ্যে আছে snap. যদি সার্ভার প্রত্যাখ্যান করে (কোন চার্জ বাকি নেই), পরবর্তী snap এটা রোল ফিরে.
  • জাতি রাষ্ট্র। ল্যাপ কাউন্ট, পজিশন এবং ফিনিস থেকে আসা snap এবং শুধুমাত্র আপনার স্ক্রিপ্টের সম্প্রচার।

সার্ভার ঘড়ি অনুমান

snap.t এবং goAt সার্ভার সময় (ctx.now) ক্ষুদ্রতম পরিলক্ষিত ফাঁক থেকে একটি অফসেট রাখুন, যা ধীর ডেলিভারি ফিল্টার করে:

let offset = Infinity;
function noteSnap(snap) { offset = Math.min(offset, performance.now() - snap.t); }
const serverNow = () => performance.now() - offset;

থেকে কাউন্টডাউন শুরু করুন goAt, এবং উপরের লুপ হিসাবে এটিতে গেট পূর্বাভাস। একটি কার্ট যা নড়াচড়া করে আগে goAt স্থানীয়ভাবে প্রথম দ্বারা গ্রিডে রাবার-ব্যান্ডেড ফিরে আসে snap শুরুর পর।

এই সব টিউন করতে, বিকাশে কৃত্রিম বিলম্ব যোগ করুন (বিলম্ব send এবং onSnap 100-200 ms দ্বারা) এবং প্রতিটি সংশোধনের আকার লগ করুন — স্থির বড় সংশোধন মানে move থেকে সরে গেছে সার্ভারের অনুলিপি, বা একটি ইনপুট ক্ষেত্র প্রতিটি পাশে আলাদাভাবে আটকানো হচ্ছে।
