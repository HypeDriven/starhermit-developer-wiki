ইন্টিগ্রেশন ওয়াকথ্রু: StarHermit-এ একটি গেম তৈরি করা

এই পৃষ্ঠাটি StarHermit-এর সাথে একটি গেমকে একীভূত করার সম্পূর্ণ জীবনচক্রের মধ্য দিয়ে চলে, ধাপে ধাপে — প্রকাশ, লঞ্চ, মেনু, ম্যাচমেকিং, খেলা, চ্যাট, ভয়েস, রেটিং, রিপ্লে। দেখানো সবকিছু প্রযোজ্য যেকোনো গেম: আপনার গেমটি তার নিজস্ব স্লাগ, নিজস্ব কমান্ড এবং নিজস্ব নিয়ম স্ক্রিপ্ট প্রতিস্থাপন করে।

চলমান উদাহরণ হল ওপেন সোর্স দাবা রেফারেন্স বাস্তবায়ন, starhermit-দাবা: ভ্যানিলা HTML/JS/CSS-এ নো-বিল্ড স্ট্যাটিক ব্রাউজার গেম হিসাবে তৈরি একটি চিঠিপত্র-দাবা খেলা (24 ঘন্টা প্রতি মুভ, এলো-রেটেড)। প্রতিটি ধাপের জন্য ওয়াকথ্রু একটি গেম ক্লায়েন্ট যে কলগুলি করে এবং রেফারেন্স রেপোতে যে ফাইলটি করে তা দেখায়। যেখানেই দাবা-নির্দিষ্ট মান প্রদর্শিত হয় — রেফারেন্স গেমের UUID, কমান্ড সরান, বোর্ড এনকোডিং, "hal" AI, 24-ঘন্টা সরানোর সময়সীমা — এগুলি উদাহরণ মান যা আপনার নিজের গেমটি নিজের স্ক্রিপ্টে নিজের জন্য সংজ্ঞায়িত করে।

এটি লিঙ্ক করা API রেফারেন্স পৃষ্ঠাগুলির পাশাপাশি এটি পড়ুন। শেষের চেকলিস্টটি আপনার নিজের গেমের প্রতিলিপি করার জন্য যা প্রয়োজন তার মধ্যে সবকিছুকে ঘনীভূত করে।

1. একটি প্ল্যাটফর্ম-হোস্ট করা গেমের অ্যানাটমি

একটি স্ক্রিপ্টেড প্ল্যাটফর্ম গেম হল একটি প্লেইন স্ট্যাটিক সাইট প্লাস ওয়ান রুলস ফাইল। দাবা রেফারেন্স বাস্তবায়ন, উদাহরণস্বরূপ, কোন বান্ডলার নেই, কোন কাঠামো নেই, কোন বিল্ড স্টেপ নেই:

ফাইল ভূমিকা
index.html পুরো পৃষ্ঠা: বোর্ড, মেনু, চ্যাট এবং ভয়েস UI
app.js অ্যাপ বুটস্ট্র্যাপ, প্রধান মেনু, ম্যাচমেকিং, আমন্ত্রণ, রিপ্লে, প্রোফাইল
net.js HTTP স্তর: স্কোপড গেম পাথ, লঞ্চ টোকেন, টোকেন রিফ্রেশ
game.js ইন-গেম কন্ট্রোলার: গেমপ্লে ওয়েবসকেট, চ্যাট, ভয়েস
ui.js বোর্ড এবং মেনু রেন্ডারিং
style.css শৈলী
server.js নিয়ম - নীচে দেখুন
starhermit.txt ম্যানিফেস্ট প্রকাশ করুন

রেফারেন্স বাস্তবায়নে, server.js বিশেষ মনোযোগ প্রাপ্য। এটা উভয় একযোগে জিনিস:

  • দ সার্ভার-অনুমোদিত স্ক্রিপ্ট প্ল্যাটফর্মটি এক্সিকিউট করে (তার জিন্ট হোস্টের মাধ্যমে) এক্সপোজ করে globalThis.game. প্রতিটি পদক্ষেপ এখানে, সার্ভারে, চুক্তি অনুযায়ী বৈধ করা হয় game-scripts.md.
  • ক্লায়েন্ট এর শেয়ার করা নিয়ম ইঞ্জিন, হিসাবে উদ্ভাসিত globalThis.chessRules, যা ব্রাউজার বোর্ড রেন্ডারিং, মুভ প্রিভিউ এবং প্লেব্যাক রিপ্লে করার জন্য ব্যবহার করে।

একটি ফাইল, সত্যের একটি উৎস, ক্লায়েন্টের উপর শূন্য নিয়মের কর্তৃত্ব. এই প্যাটার্ন অনুসরণকারী একটি গেম ক্লায়েন্ট কখনই সিদ্ধান্ত নেয় না যে একটি পদক্ষেপ বৈধ কিনা - এটি সার্ভার সম্প্রচার করে তা রেন্ডার করে। এটি একটি স্ক্রিপ্টেড প্ল্যাটফর্ম গেমের একক সবচেয়ে গুরুত্বপূর্ণ স্থাপত্য ধারণা এবং রেফারেন্স বাস্তবায়ন এটি প্রদর্শন করে।

2. আপনার গেম প্রকাশ করা হচ্ছে

যেকোন খেলা প্রকাশের মাধ্যমে শুরু হয় starhermit.txt রেপো রুটে প্রকাশিত। এটা খেলা ঘোষণা করে name, launch প্রবেশ বিন্দু, owner, এবং server স্ক্রিপ্ট ঐচ্ছিক cover= লাইব্রেরির টাইলের আর্টওয়ার্ক - দেখুন দ starhermit.txt প্রকাশ. রেফারেন্স বাস্তবায়নের ম্যানিফেস্ট, উদাহরণস্বরূপ:

name=StarHermit Chess
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html
owner=3fa85f64-5717-4562-b3fc-2c963f66afa6  # StarHermit user ID, not username/nickname
server=server.js

অপরিবর্তনীয় ব্যবহার করুন id থেকে GET /api/v1/me জন্য owner; ব্যবহারকারীর নাম এবং ডাকনাম প্রদর্শন করা হয় মান এবং ম্যানিফেস্ট মালিকানা শনাক্তকারী হিসাবে ব্যবহার করা উচিত নয়।

প্ল্যাটফর্মটি রেপো ক্লোন করে, স্ট্যাটিক ফাইলগুলিকে পরিবেশন করে <slug>.starhermit.com — স্লাগ হল সেই uid যা প্ল্যাটফর্ম গেমটি বরাদ্দ করে, কখনোই আপনার পছন্দের নাম নয়; রেফারেন্স গেম এর 83fd04b1-3cbe-4b09-a251-3733ad4b9d94, তাই এটা লাইভ খেলার যোগ্য 83fd04b1-3cbe-4b09-a251-3733ad4b9d94.starhermit.com — এবং প্রক্সি /api এবং /ws ব্যাকএন্ডে একই-উৎস. সেই একটি সিদ্ধান্ত কাজের একটি সম্পূর্ণ বিভাগকে সরিয়ে দেয়: কোনও CORS নেই, কোনও API-বেস কনফিগারেশন নেই, কোনও পরিবেশ সনাক্তকরণ নেই — গেম ক্লায়েন্টরা কেবল আপেক্ষিক পাথ ব্যবহার করে।

সম্পূর্ণ প্রবাহ: github-games.md এবং publisher.md.

3. লঞ্চ এবং প্রমাণীকরণ

দাবা রেফারেন্স ফ্লো প্ল্যাটফর্ম লঞ্চার থেকে শংসাপত্র গ্রহণ করে:

  1. লঞ্চার ডাকে POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/launch-token ব্যবহারকারীর সম্পূর্ণ প্ল্যাটফর্ম JWT-এর সাথে (রেফারেন্স গেমের UUID দিয়ে দেখানো হয়েছে; আপনার নিজের বিকল্প করুন)।
  2. এটি স্বল্প সময়ের জন্য ফিরে আসে, খেলার ব্যাপ্তি টোকেন:
{ "token": "<jwt>", "expiresInSeconds": 3600 }
  1. এটা খেলা খোলে index.html#game_token=<jwt>, ঐচ্ছিকভাবে সঙ্গে &session_id=<guid> আমন্ত্রণ গভীর লিঙ্কের জন্য যুক্ত করা হয়েছে।

রেফারেন্স বাস্তবায়নে, ক্লায়েন্ট হ্যাশ পড়ে একবার, তারপর এটি দিয়ে রেখাচিত্রমালা history.replaceState তাই টোকেন কখনই ইউআরএল বার বা ইতিহাসে থাকে না (app.js, App.init) এটি দুটি দাবির জন্য JWT পেলোড ডিকোড করে:

  • sub - ব্যবহারকারীর আইডি
  • game_scope — খেলা স্লাগ

এই দ্বিতীয় দাবিটি গুরুত্বপূর্ণ: একটি গেম ক্লায়েন্ট কখনই তার স্লাগকে হার্ড-কোড করা উচিত নয়. রেফারেন্স বাস্তবায়ন প্রতিটি API URL হিসাবে তৈরি করে /api/v1/games/<slug> প্লাস একটি প্রত্যয় (net.js, Net.gamePath), তাই একই কোড যেকোনো গেম, যেকোনো স্লাগ, যেকোনো স্থাপনার জন্য কাজ করে।

রিফ্রেশ স্কোপড টোকেন পুনরায় কল করার অনুমতি দেওয়া হয় launch-token নিজের খেলার জন্য, তাই ক্লায়েন্টরা সাধারণত পর্যায়ক্রমে রিফ্রেশ করে — রেফারেন্স বাস্তবায়ন প্রতি 45 মিনিটে রিফ্রেশ করে (net.js, Net.startRefresh, 60 মিনিটের জীবনকালের মধ্যে আরামদায়ক।

একটি খেলা সরাসরি খোলা পরিবর্তে অফার করতে পারেন ব্রাউজার সাইন ইন, যা ফিরে আসে #access_token বরং লঞ্চারের চেয়ে #game_token. উভয় প্রবেশ পথ হ্যান্ডেল যদি আপনি উভয় সমর্থন. ফিরে আসা জীবনকাল ব্যবহার করে পুনর্নবীকরণ করুন এবং ডিফল্ট 12-ঘন্টা পুনর্নবীকরণ-চেইনকে সম্মান করুন সিলিং ক 403 terms_acceptance_required খেলোয়াড়ের প্রয়োজন তাদের অ্যাকাউন্টের মাধ্যমে গ্রহণ করুন; অথবা খেলার শর্তাবলী প্রদর্শন করুন এবং প্লেয়ার লঞ্চ টোকেন সহ গ্রহণ করুন। আবার সাইন ইন করা হয় না রেকর্ড গ্রহণ।

প্রমাণ রেফারেন্স: auth.md, games.md.

4. প্রধান মেনু লোড হচ্ছে

একটি গেমের মেনু সাধারণত তার নিজস্ব স্লাগের বিরুদ্ধে GET-এর একটি ছোট ব্যাচ দিয়ে খোলে। রেফারেন্স বাস্তবায়ন এই হয় refreshMenu মধ্যে app.js:

গেমের তথ্য + আমার পরিসংখ্যান:

GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94

{
  "slug": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "name": "StarHermit Chess",
  "enabled": true,
  "leaderboardId": "<guid>",
  "maxConcurrentSessionsPerPlayer": 20,
  "me": {
    "userId": "<guid>",
    "elo": 1420,
    "wins": 31,
    "losses": 18,
    "draws": 4,
    "activeSessionCount": 3
  }
}

দ me ব্লক হল পুরো প্লেয়ার কার্ড — ইলো, রেকর্ড এবং কতগুলি অনুমোদিত সমসাময়িক সেশন ব্যবহার করা হচ্ছে (দাবা উদাহরণে 20)।

আমার সেশন:

GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/sessions/mine

[
  {
    "sessionId": "<guid>",
    "status": "active",
    "players": [ /* ... */ ],
    "createdAt": "…",
    "finishedAt": null,
    "myTurn": true,
    "deadline": 1784642591000
  }
]

myTurn এবং deadline যা একটি চিঠিপত্র গেমের সেশন তালিকাকে উপযোগী করে তোলে — প্লেয়ার এক নজরে দেখেন কোন গেমগুলি তাদের জন্য অপেক্ষা করছে এবং প্রতিটি পদক্ষেপ কখন শেষ হবে।

বন্ধুদের লিডারবোর্ড:

GET /api/v1/leaderboards/{leaderboardId}/entries?friendsOnly=true&page=1&pageSize=10

ব্যবহার করে leaderboardId গেম-তথ্য প্রতিক্রিয়া থেকে।

সাম্প্রতিক রিপ্লে:

GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/replays/mine?limit=10

মুলতুবি আমন্ত্রণ:

GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/invites

তথ্যসূত্র: games.md, leaderboards.md.

5. খেলোয়াড়দের একটি সেশনে প্রবেশ করানো — তিনটি উপায়

এই ওয়াকথ্রু সেশন তৈরি করতে ম্যাচমেকিং, আমন্ত্রণ গ্রহণ এবং এআই অনুশীলন ব্যবহার করে। একটি লবি প্রয়োজন যে গেম ব্যবহার করতে পারেন রিয়েলটাইম রুম, যার শুরু প্রবাহ একটি আবদ্ধ কর্তৃত্বমূলক অধিবেশন তৈরি করতে পারে।

ক ম্যাচমেকিং

রেফারেন্স বাস্তবায়নে, App.startMatchmaking মধ্যে app.js:

POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/matchmaking

প্রতিক্রিয়া হয় একটি টিকিট:

{ "ticketId": "<guid>", "status": "queued" }

অথবা একটি তাৎক্ষণিক ম্যাচ:

{ "status": "matched", "sessionId": "<guid>" }

সারিবদ্ধ থাকাকালীন, ক্লায়েন্টরা ম্যাচমেকিং এন্ডপয়েন্ট - রেফারেন্স বাস্তবায়ন পোল পোল করে GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/matchmaking প্রতি 3 সেকেন্ড, এবং DELETE /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/matchmaking টিকিট বাতিল করে। রেফারেন্স ক্লায়েন্ট এটাও নিশ্চিত করে যে প্লেয়ার কখনই স্পিনারের দিকে তাকিয়ে আটকে থাকবে না: 30 সেকেন্ডের পর অতুলনীয়, একটি "হালের বিপক্ষে খেলা" বোতাম প্রদর্শিত হয় ("hal" দাবা উদাহরণের অন্তর্নির্মিত AI প্রতিপক্ষ — দেখুন §12), এবং POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/sessions/ai রিটার্ন { "sessionId" }.

খ. বন্ধু আমন্ত্রণ

রেফারেন্স বাস্তবায়নে, App.inviteFriend মধ্যে app.js. প্রথম তালিকার বন্ধু - এই শেষ পয়েন্টটি গেম-স্কোপড টোকেনগুলির জন্য স্পষ্টভাবে অনুমোদিত:

GET /api/v1/me/friends

তারপর আমন্ত্রণ পাঠান:

POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/invites
{ "toUserId": "<guid>" }

প্রাপক তাদের নিজস্ব ক্লায়েন্টের কাছ থেকে গ্রহণ (বা অস্বীকার) করে:

POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/invites/{id}/accept   → { "sessionId": "<guid>" }
POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/invites/{id}/decline  → 204

গ্রহণ করাই সেশন তৈরি করে। দ &session_id= লঞ্চ-হ্যাশ ডিপ-লিংক (§3) আমন্ত্রিত প্লেয়ারকে সরাসরি এটিতে ফেলে দেয়।

বন্ধু আমন্ত্রণ শুধুমাত্র সেই ব্যক্তিদের কাছে পৌঁছায় যারা ইতিমধ্যেই বন্ধু। এমন কাউকে টেনে আনতে যিনি নন (বা একেবারেই প্ল্যাটফর্মে নেই), রেফারেন্স বাস্তবায়নও একটি প্রস্তাব দেয় আমন্ত্রণ লিঙ্ক শেয়ার করুন বোতাম (App.shareInviteLink): স্ট্রিং বিল্ডিংয়ের এক লাইন যা কপি করে

https://dashboard.starhermit.com/game-invite/<Net.userId>/<slug>

ক্লিপবোর্ডে। ওয়েব ড্যাশবোর্ড প্রাপকের প্রয়োজনীয় সমস্ত কিছু পরিচালনা করে — সাইন-ইন, বন্ধুর অনুরোধ, একটি ডাকনাম, গেমটি চালু করা — এবং তারপর শেয়ারারের কাছে খেলার আমন্ত্রণ ফেরত পাঠায়, তাই এটি একই আমন্ত্রণ তালিকায় ল্যান্ড করে৷ দেখুন লিঙ্ক শেয়ার করুন সম্পূর্ণ চুক্তির জন্য।

গ. নিয়ম

ম্যাচমেকিং, আমন্ত্রণ-গ্রহণের মাধ্যমে সেশন তৈরি করা হয়, sessions/ai, অথবা এর সাথে একটি রিয়েলটাইম রুম শুরু করা একটি সার্ভার ব্যাকএন্ড। আসন সহ একটি লবির জন্য, ব্যবহার করুন রিয়েলটাইম রুম API.

6. গেমপ্লে WebSocket উপর খেলা

খেলার লুপ প্রতিটি স্ক্রিপ্ট করা গেমের জন্য একই: সেশন আনুন, সকেট খুলুন, সম্প্রচার রেন্ডার করুন, কমান্ড পাঠান। রেফারেন্স বাস্তবায়নের মধ্যে এটি বাস করে game.js, GameController.

সেশন আনুন:

GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/sessions/{sessionId}

{
  "sessionId": "<guid>",
  "status": "active",
  "players": [ /* ... */ ],
  "createdAt": "…",
  "finishedAt": null,
  "chatConversationId": "<guid>",
  "result": null
}

দ্রষ্টব্য chatConversationId — আপনার চ্যাট (§7) এবং ভয়েস (§8) এর জন্য এটির প্রয়োজন হবে।

গেমপ্লে সকেট সংযোগ করুন:

ws(s)://<host>/ws/v1/games?sessionId=<id>&access_token=<token>

চালু open, ক্লায়েন্ট অবিলম্বে একটি সিঙ্ক কমান্ড পাঠায়:

{ "type": "cmd", "data": { "type": "sync" } }

যেকোনো সংযোগ বিচ্ছিন্ন হলে এটি 1 সেকেন্ড থেকে 30-সেকেন্ডের সিলিং পর্যন্ত সূচকীয় ব্যাকঅফের সাথে পুনরায় সংযোগ করে এবং প্রতিটি খোলাতে সিঙ্ক পুনরায় পাঠায়. সিঙ্ক কমান্ড পুনঃসংযোগকে স্টেটলেস এবং অদম্য করে তোলে: ক্লায়েন্ট যা কিছু মিস করে না কেন, সার্ভার পুনরায় সম্প্রচার করে।

খাম। প্রতিটি ফ্রেম একটি পাতলা JSON খাম:

  • ক্লায়েন্ট → সার্ভার: {"type":"cmd","data":<command>}
  • সার্ভার → ক্লায়েন্ট: {"type":"game","data":…}, {"type":"error","error":…}, {"type":"presence","userId","online"}

গেম কমান্ড আপনার নিজস্ব নিয়ম স্ক্রিপ্ট দ্বারা সংজ্ঞায়িত করা হয়. দাবা উদাহরণের আদেশ, উদাহরণস্বরূপ ( data a এর পেলোড cmd ফ্রেম):

{ "type": "sync" }
{ "type": "move", "from": "e2", "to": "e4", "promo": "q" }
{ "type": "resign" }
{ "type": "offer-draw" }
{ "type": "accept-draw" }
{ "type": "decline-draw" }

দাবা উদাহরণে, promo শুধুমাত্র পদোন্নতির জন্য উপস্থিত।

সম্প্রচার একইভাবে স্ক্রিপ্ট-সংজ্ঞায়িত করা হয়। দাবা উদাহরণের সম্প্রচার ( data a এর পেলোড game ফ্রেম):

  • state - সম্পূর্ণ স্ন্যাপশট:
{
  "type": "state",
  "white": "<userId>",
  "black": "<userId>",
  "ratings": { "white": 1420, "black": 1388 },
  "board": "RNBQKBNRPPPPPPPP................................pppppppprnbqkbnr",
  "turn": "w",
  "moves": [ { "from": "e2", "to": "e4", "promo": null, "san": "e4", "at": "…" } ],
  "status": "active",
  "result": null,
  "deadline": 1784642591000,
  "drawOfferBy": null,
  "ai": false,
  "aiName": null
}

দ board একটি 64-অক্ষরের স্ট্রিং, index = rank * 8 + file সঙ্গে a1 = 0, ব্যবহার করে PNBRQK সাদা জন্য, pnbrqk কালো জন্য, . খালি স্কোয়ারের জন্য - একটি দাবা-নির্দিষ্ট এনকোডিং; আপনার খেলা তার নিজস্ব রাষ্ট্র আকৃতি সংজ্ঞায়িত করে.

  • moved - একটি একক পদক্ষেপ প্রয়োগ করা হয়েছিল।
  • draw-offered / draw-declined.
  • game-over — { "result": { "kind", "reason", "at" }, "view" }, কোথায় reason মান স্ক্রিপ্ট-সংজ্ঞায়িত করা হয়; দাবা উদাহরণ ব্যবহার করে checkmate, stalemate, threefold-repetition, fifty-move-rule, insufficient-material, resignation, agreement, timeout, timeout-no-moves.

পরিচয় কখনোই পেলোড থেকে নেওয়া হয় না। ক্লায়েন্ট কোন ইউজার আইডি ছাড়াই কমান্ড পাঠায় এবং স্ক্রিপ্ট কখনই তারের একটিকে বিশ্বাস করে না — প্ল্যাটফর্মটি প্রমাণীকৃত প্রেরককে স্ক্রিপ্টে পাঠায়। ফাঁকি দেওয়ার কিছু নেই।

দেখুন game-scripts.md এই সব পিছনে স্ক্রিপ্ট চুক্তি জন্য.

7. ইন-গেম চ্যাট

প্রতিটি অধিবেশন একটি বহন করে chatConversationId (§6) যেটি গেম ক্লায়েন্টরা ইন-গেম চ্যাটের জন্য ব্যবহার করতে পারে। রেফারেন্স বাস্তবায়নে, initChat মধ্যে game.js এটি এই মত ব্যবহার করুন:

GET  /api/v1/chat/conversations/{id}/messages?page=1&pageSize=50
POST /api/v1/chat/conversations/{id}/messages
     { "content": "good luck!" }

রিয়েল-টাইম চ্যাট সকেট ws/v1/chat হয় গেম-স্কোপড টোকেনের জন্য অবরুদ্ধ. রেফারেন্স ক্লায়েন্ট এটি একবার চেষ্টা করে, প্রত্যাখ্যান করে, এবং প্রতি 5 সেকেন্ডে REST এন্ডপয়েন্টে পোলিং করতে ফিরে আসে — আপনার নিজের গেমের শুরু থেকেই পোলিং করার পরিকল্পনা করুন।

চ্যাট কাজ করে যদিও দুই খেলোয়াড় বন্ধু নাও হতে পারে: সেশন কথোপকথন (টাইপ "game") উভয় খেলোয়াড়কে অংশগ্রহণকারী হিসাবে তৈরি করা হয়েছে, তাই স্বাভাবিক চ্যাট অনুমতি নিয়ম ইতিমধ্যেই সন্তুষ্ট।

তথ্যসূত্র: chat.md.

8. ভয়েস

ভয়েস অপ্ট-ইন হয়, এবং গেম ক্লায়েন্টরা সাধারণত এটি রাখে ডিফল্টরূপে বন্ধ. রেফারেন্স বাস্তবায়ন এটি পরিচালনা করে game.js, VoiceController. যখন একজন খেলোয়াড় এটি সক্ষম করে:

  1. সেশনের কথোপকথনের সাথে আবদ্ধ রুমটি খুঁজুন বা তৈরি করুন:
GET  /api/v1/voice/rooms?conversationId=<chatConversationId>
POST /api/v1/voice/rooms
     { "conversationId": "<chatConversationId>" }
  1. এতে যোগ দিন:
POST /api/v1/voice/rooms/{roomId}/join
  1. ভয়েস সকেট সংযোগ করুন:
ws(s)://<host>/ws/v1/voice?roomId=<id>&access_token=<token>

মিডিয়া হল নিখুঁত আলোচনার সাথে WebRTC পিয়ার-টু-পিয়ার; সকেট শুধুমাত্র সংকেত এবং নিয়ন্ত্রণ বহন করে:

  • সংকেত: {"type":"rtc","to":<userId>,"payload":{"sdp":…}} বা {"type":"rtc","to":<userId>,"payload":{"ice":…}}
  • নিয়ন্ত্রণ: {"type":"mute","muted":…}, {"type":"speaking","speaking":…}
  • সার্ভার ইভেন্ট: voice.roster, voice.participant_joined, voice.participant_left, voice.mute_changed, voice.speaking, voice.rtc

যদি P2P ব্যর্থ হয়, ফলব্যাক হল সার্ভার-রিলেড অপাস বাইনারি ফ্রেম: একটি 16-বাইট প্রেরক আইডি এবং অডিও পেলোড অনুসরণ করে৷

ভয়েস হল এআই গেমগুলিতে অক্ষম - রেফারেন্স ক্লায়েন্ট চেক করে view.ai রাষ্ট্রীয় সম্প্রচার থেকে এবং কখনই টগল অফার করে না।

তথ্যসূত্র: voice.md.

9. রেটিং এবং লিডারবোর্ড

গেম ক্লায়েন্টরা কখনই একটি স্কোর জমা দেয় না। একটি খেলা শেষ হলে, স্ক্রিপ্ট রিটার্ন eloUpdates এবং প্ল্যাটফর্ম গেমের লিডারবোর্ডে সেগুলি প্রকাশ করে। ক্লায়েন্ট সরাসরি লিডারবোর্ড এন্ট্রি লিখতে পারে না; সার্ভারকে অবশ্যই তার রেটিং আপডেটের পিছনে গেমপ্লে যাচাই করতে হবে।

ক্লায়েন্ট পক্ষ তাই তুচ্ছ: এন্ট্রিগুলি পড়ুন (§4) এবং রেন্ডার করুন, যেমন রেফারেন্স বাস্তবায়ন করে। দেখুন leaderboards.md.

10. রিপ্লে

একটি খেলা যে ঘোষণা replays: true এর স্ক্রিপ্টে প্ল্যাটফর্ম দ্বারা রাখা প্রতিটি সমাপ্ত সেশন রয়েছে; ক্লায়েন্টরা শুধু আনয়ন এবং রেন্ডার করে। চেক করুন replaysEnabled অন GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94 স্ক্রীন অফার করার আগে — একজন অপারেটর যেকোন উপায়ে একটি গেমের জন্য উত্তর দিতে পারে এবং নীচের শেষ পয়েন্টগুলি ফিরে আসে 404 যখন রিপ্লে বন্ধ থাকে। রেফারেন্স বাস্তবায়নে আনা হচ্ছে App.loadReplays / App.openReplay মধ্যে app.js:

GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/replays/mine?limit=10
GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/replays/{sessionId}

একটি রিপ্লে পেলোড (দাবার উদাহরণের ফলাফলের আকারের সাথে দেখানো হয়েছে):

{
  "sessionId": "<guid>",
  "players": [ /* ... */ ],
  "finishedAt": "…",
  "result": {
    "kind": "win",
    "reason": "checkmate",
    "at": "…",
    "white": "<userId>",
    "black": "<userId>",
    "moveCount": 41,
    "eloBefore": { "white": 1420, "black": 1388 },
    "eloAfter": { "white": 1436, "black": 1372 }
  },
  "state": { "game": { "moves": [ /* ... */ ] } }
}

দর্শক পদক্ষেপ state.game.moves ভাগ করা মাধ্যমে chessRules স্থানীয়ভাবে ইঞ্জিন - একই server.js নিয়ম ফাইল, ব্রাউজারে চলছে — তাই রিপ্লেতে সার্ভার রাউন্ড-ট্রিপের প্রয়োজন নেই; নিয়ম পরিবর্তনের সময় সংরক্ষণাগারভুক্ত ম্যাচের জন্য ব্যবহৃত নিয়ম সংস্করণ সংরক্ষণ করুন। এটি §1 থেকে ওয়ান-ফাইল-টু-রোল ডিজাইনের দ্বিতীয় পেঅফ, একটি প্যাটার্ন যে কোনও গেম তার নিজস্ব নিয়ম ফাইলের সাথে গ্রহণ করতে পারে।

11. প্লেয়ার প্রোফাইল

গেম ক্লায়েন্টরা পাবলিক প্রোফাইল এন্ডপয়েন্টের মাধ্যমে অন্যান্য খেলোয়াড়দের সমাধান করে। রেফারেন্স বাস্তবায়নে, App.profileFor মধ্যে app.js:

GET /api/v1/users/{id}/profile  → { "id": "…", "username": "…", "nickname": "…" }
GET /api/v1/users/{id}/avatar   → image/png, or 404

দুটি UI নিয়ম রেফারেন্স ক্লায়েন্ট অনুসরণ করে:

  • রেন্ডার ডাকনাম, কখনোই ব্যবহারকারীর নাম নয়।
  • ফিরে পড়া "Player " + id.slice(0, 8) যখন একটি প্রোফাইল অনুপস্থিত থাকে বা একটি ডাকনাম খালি থাকে।

তথ্যসূত্র: profile.md.

12. এআই অনুশীলন বিরোধীদের

POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/sessions/ai (উদাহরণ স্লাগের সাথে দেখানো হয়েছে) একটি সেশন তৈরি করে যেখানে প্ল্যাটফর্ম একটি আসন পতাকাঙ্কিত করে ai: true মধ্যে createSession. স্ক্রিপ্ট নিজেই সেই আসনটি চালায় — এআই আচরণ এমন কিছু যা আপনার নিজের স্ক্রিপ্ট সংজ্ঞায়িত করে। দাবা উদাহরণে, আসন দ্বারা খেলা হয় "hal", একটি লোভী উপাদান-ক্যাপচার ইঞ্জিন যা উত্তর দেয় একই আহ্বানের মধ্যে যা মানুষের চালকে প্রক্রিয়া করে।

খেলার স্ক্রিপ্ট সিদ্ধান্ত নেয় অনুশীলন মানব খেলোয়াড়ের রেটিং পরিবর্তন করে কিনা। এআই সিট পারে না অ্যাকাউন্ট প্লেয়ার-স্টেট, রেটিং, বা অর্জনের লেখা গ্রহণ করুন। যেকোন এআই পরিসংখ্যান সেশন স্টেটে রাখুন।

13. রেফারেন্স গেম কি ব্যবহার করে না

দাবা রেফারেন্স বাস্তবায়ন এগুলির কোনওটিকেই স্পর্শ করে না, তবে এগুলি সমস্ত গেমগুলির জন্য উপলব্ধ যা তাদের প্রয়োজন:

  • অর্জন — a এর সাথে যেকোনো খেলা server= স্ক্রিপ্ট তাদের ঘোষণা করতে পারে (game.achievements) এবং যেকোন লাইফসাইকেল হুক থেকে তাদের সার্ভার-অনুমোদিতভাবে মঞ্জুর করুন; দাবা সহজভাবে না. ক্যাটালগ শিরোনামগুলির একটি পৃথক ক্লায়েন্ট-দাবী পথ রয়েছে: achievements.md, game-scripts.md.
  • ক্যাটালগ/এনটাইটেলমেন্ট — ক্যাটালগের মাধ্যমে বিতরণ করা এবং বিক্রি করা গেমগুলির জন্য: catalog.md.
  • রিলে — দ্রুতগতির, রিয়েল-টাইম গেমগুলির জন্য উচ্চ-ফ্রিকোয়েন্সি রিলে চ্যানেল যেখানে প্রতি-কমান্ড স্ক্রিপ্ট রাউন্ড-ট্রিপ খুব ধীর: relay.md.
  • বাহ্যিক লাইব্রেরি — স্টিম, এপিক বা GOG গেম লাইব্রেরি লিঙ্ক করা: external-libraries.md.

দাবা উদাহরণ, একটি টার্ন-ভিত্তিক বোর্ড গেম, তাদের কোনটির প্রয়োজন নেই। যদি আপনার গেমটি রিয়েল-টাইম হয়, ক্যাটালগ-বিতরণ করা হয়, বা বাইনারি পেলোডের প্রয়োজন হয়, সেই পৃষ্ঠাগুলি পরবর্তীতে কোথায় দেখতে হবে।

14. ইন্টিগ্রেশন চেকলিস্ট

  • একটি যোগ করুন starhermit.txt প্রকাশ (name, launch, owner, server; ঐচ্ছিক cover= লাইব্রেরি টাইলের জন্য)।
  • পড়ুন #game_token URL হ্যাশ থেকে একবার, তারপর এটি দিয়ে ফালা history.replaceState.
  • এর জন্য JWT ডিকোড করুন sub (ইউজার আইডি) এবং game_scope (স্লাগ) - কখনই আপনার স্লাগকে হার্ড-কোড করবেন না।
  • একই-অরিজিন আপেক্ষিক URL হিসাবে সমস্ত API পাথ তৈরি করুন: /api/v1/games/<slug> + প্রত্যয়।
  • প্রতি 45 মিনিটের মাধ্যমে লঞ্চ টোকেন রিফ্রেশ করুন POST …/launch-token.
  • [ ] ব্যবহার করুন cmd / sync WebSocket প্যাটার্ন: সবকিছু খাম করুন, প্রতিটি খোলাতে সিঙ্ক করুন, 1s→30s ব্যাকঅফের সাথে পুনরায় সংযোগ করুন।
  • আপনার স্ক্রিপ্টের কমান্ড এবং সম্প্রচার ডিজাইন করুন ক্লায়েন্ট চুক্তি হিসাবে — ক্লায়েন্ট ব্রডকাস্ট রেন্ডার করে এবং কমান্ড পাঠায়, আর কিছু নয়।
  • [ ] একটি সারাংশ বস্তু ফেরত দিন { turnPlayerId, deadline, status, moveCount } তাই সেশন লিস্ট দেখাতে পারে কার পালা।
  • [ ] ফিরে এসে গেমস শেষ করুন result — সেই একটি রিটার্ন মান যা রিপ্লে এবং ইলো উভয়কেই শক্তি দেয়।
  • [ ] ঘোষণা replays: true আপনার স্ক্রিপ্টে যদি আপনি শেষ সেশন রাখতে চান এবং রিপ্লে UI চালু করতে চান replaysEnabled.

প্ল্যাটফর্মটি প্রমাণীকরণ, সেশন, ম্যাচমেকিং এবং স্টোরেজ সরবরাহ করে; আপনার স্ক্রিপ্ট সরবরাহ করে খেলার নিয়ম। দিয়ে শুরু করুন ব্রাউজার কুইকস্টার্ট সম্পূর্ণ প্রথম আপলোডের জন্য।
