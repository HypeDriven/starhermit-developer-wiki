একটি খেলা দাবি অন্য কেউ যোগ করা হয়েছে

যদি কেউ ইতিমধ্যেই আপনার সর্বজনীন GitHub গেমটি StarHermit-এ যোগ করে থাকে, তাহলে আপনাকে একটি তৈরি করতে হবে না দ্বিতীয় তালিকা. বিদ্যমান তালিকাটিকে এর যাচাইকৃত মালিক হতে দাবি করুন এবং এর মেটাডেটা পরিচালনা করুন, হোস্টিং, স্থাপনা, সার্ভার ব্যাকএন্ড এবং ভবিষ্যতের স্থানান্তর।

দাবি সংগ্রহস্থল নিয়ন্ত্রণ দ্বারা সুরক্ষিত. গেম আইডি বা সংগ্রহস্থলের URL জানা যথেষ্ট নয়। আপনাকে অবশ্যই দুটি উপায়ের একটিতে নিয়ন্ত্রণ প্রমাণ করতে হবে:

  1. সংগ্রহস্থলের মালিক ব্যক্তিগত GitHub অ্যাকাউন্ট লিঙ্ক করুন; বা
  2. আপনার অপরিবর্তনীয় StarHermit ব্যবহারকারী আইডি হিসাবে প্রতিশ্রুতিবদ্ধ করুন owner= ভান্ডার এর মধ্যে starhermit.txt.

দ্বিতীয় পদ্ধতিটি প্রতিষ্ঠানের মালিকানাধীন সংগ্রহস্থলের জন্য বিশেষভাবে উপযোগী, কারণ বর্তমান GitHub-লগইন চেক ব্যক্তিগত সংগ্রহস্থলের মালিকদের সাথে মেলে এবং সংস্থার সদস্যতা অনুমান করে না।

কি দাবি পরিবর্তন

একটি সফল দাবি:

  • বিদ্যমান গেম/লিস্টিং আইডি এবং এর সঞ্চিত ইতিহাস রাখে;
  • আপনার জন্য তালিকার পরিচালনাকারী StarHermit ব্যবহারকারীকে পরিবর্তন করে;
  • হিসাবে তালিকা চিহ্নিত isVerifiedOwner: true;
  • থেকে বিশ্বস্ত মেটাডেটা এবং নিয়ন্ত্রণ রিফ্রেশ করে starhermit.txt যেখানে প্রযোজ্য;
  • একটি ঘোষিত স্ক্রিপ্ট/কন্টেইনার ব্যাকএন্ড বিধান বা রিফ্রেশ করে;
  • যেখানে উপলব্ধ প্ল্যাটফর্ম হোস্টিং সক্ষম করে এবং হিসাবে সারি স্থাপন করে pending;
  • যে ব্যক্তি মূলত সেই তালিকা জমা দিয়েছেন তার থেকে ব্যবস্থাপনা অ্যাক্সেস সরিয়ে দেয়।

দাবি করা আপনার GitHub অ্যাকাউন্টে পূর্ববর্তী জমাদানকারীকে অ্যাক্সেস দেয় না এবং এটি একত্রিত হয় না StarHermit ব্যবহারকারীর অ্যাকাউন্ট। এটি সেই নির্দিষ্ট তালিকার ব্যবস্থাপনা স্থানান্তর করে।

আপনি শুরু করার আগে

আপনার প্রয়োজন:

  • একটি StarHermit অ্যাকাউন্ট এবং সম্পূর্ণ ব্যবহারকারীর অ্যাক্সেস টোকেন - একটি গেম-স্কোপড লঞ্চ টোকেন নয়।
  • ব্যবহার করলে সংগ্রহস্থলে অ্যাক্সেস লিখুন owner= প্রমাণ পদ্ধতি।
  • বিদ্যমান StarHermit তালিকা আইডি।
  • একটি ক্লোন রিপোজিটরি গেমের জন্য, একটি বৈধ৷ starhermit.txt ভান্ডার রুটে।

শুধুমাত্র github.com/<owner>/<repo> সংগ্রহস্থল এবং তাদের GitHub পেজ সাইট এই দাবিতে অংশগ্রহণ করে প্রবাহ একটি নির্বিচারে হোস্ট করা URL এর প্রমাণ করার জন্য কোন GitHub সংগ্রহস্থলের মালিকানা নেই এবং এটি দাবি করা যাবে না উপায়

নীচের উদাহরণ ব্যবহার:

API=https://api.starhermit.com
ACCESS_TOKEN='your-full-user-access-token'
OWNER='your-github-login'
REPO='your-game-repository'

অ্যাক্সেস টোকেন শেষ 15 মিনিট. মেয়াদ শেষ হয়ে গেলে শুরু করার আগে আপনার রিফ্রেশ করুন।

ধাপ 1: বিদ্যমান তালিকা খুঁজুন

শেয়ার করা গেমের তালিকা করুন:

curl -sS "$API/api/v1/github-games" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

প্রতিটি আইটেম অপরিবর্তনীয় তালিকা অন্তর্ভুক্ত id, স্বাভাবিক করা হয়েছে repoUrl, ownerLogin, repoName, the বর্তমান জমাদানকারী, এবং মালিকানার অবস্থা:

{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "repoUrl": "https://github.com/octocat/orbit-league",
  "ownerLogin": "octocat",
  "repoName": "orbit-league",
  "displayName": "Orbit League",
  "isVerifiedOwner": false,
  "submittedByUserId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "submittedByUsername": "someone-else"
}

দুটোতেই মিল ownerLogin এবং repoName; শুধুমাত্র একটি খেলা নির্বাচন করবেন না কারণ এর প্রদর্শনের নাম অনুরূপ সঙ্গে jq:

GAME_ID=$(
  curl -sS "$API/api/v1/github-games" \
    -H "Authorization: Bearer $ACCESS_TOKEN" |
  jq -r --arg owner "$OWNER" --arg repo "$REPO" \
    '.[] | select((.ownerLogin | ascii_downcase) == ($owner | ascii_downcase)
               and (.repoName | ascii_downcase) == ($repo | ascii_downcase)) | .id' |
  head -n1
)

printf 'Listing ID: %s\n' "$GAME_ID"

ফলাফল খালি হলে থামুন। একটি অসম্পর্কিত তালিকা থেকে অনুলিপি একটি আইডি সঙ্গে দাবি কল করবেন না.

ধাপ 2: কীভাবে মালিকানা প্রমাণ করবেন তা বেছে নিন

বিকল্প A: সংগ্রহস্থলের মালিকের GitHub অ্যাকাউন্ট লিঙ্ক করুন

এটি ব্যবহার করুন যখন সংগ্রহস্থলটি সরাসরি আপনার ব্যক্তিগত GitHub লগইন দ্বারা মালিকানাধীন হয়।

StarHermit এর অ্যাকাউন্ট/সেটিংস ফ্লো থেকে, GitHub OAuth ইন শুরু করুন লিঙ্ক সাইন ইন করার সময় মোড StarHermit অ্যাকাউন্ট যা গেম পরিচালনা করবে। লিঙ্ক করা ঘটনাক্রমে একটি তৈরি করা থেকে ভিন্ন GitHub সাইন-ইন সহ দ্বিতীয় StarHermit অ্যাকাউন্ট।

এপিআই প্রবাহ এখানে শুরু হয়:

GET /api/v1/auth/oauth/github/authorize?link=true

এটি ব্রাউজার-চালিত এবং একটি স্বল্পস্থায়ী রাষ্ট্র কুকি ব্যবহার করে। লিঙ্ক করার জন্য সাম্প্রতিক StarHermit প্রয়োজন প্রমাণীকরণ একই ব্রাউজার সেশনে গিটহাব অনুমোদন সম্পূর্ণ করুন যা এটি শুরু করেছিল।

ফলাফল যাচাই করুন:

curl -sS "$API/api/v1/me/github" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

প্রত্যাশিত:

{ "linked": true, "login": "octocat" }

প্রত্যাবর্তিত লগইন অবশ্যই বিদ্যমান তালিকার সাথে মেলে ownerLogin, কেস-সংবেদনশীলভাবে। একটি ব্যক্তিগত GitHub লগইন কোনো সংস্থার সদস্যপদ প্রমাণ করে না যা সংগ্রহস্থলের মালিক। একটি জন্য প্রতিষ্ঠানের মালিকানাধীন সংগ্রহস্থল, বিকল্প বি ব্যবহার করুন।

বিকল্প B: যোগ করুন owner= থেকে starhermit.txt

এটি নিয়ন্ত্রণ প্রমাণ করে কারণ শুধুমাত্র সংগ্রহস্থলের বিষয়বস্তু প্রকাশ করতে সক্ষম কেউ মান যোগ করতে পারে। সেট owner আপনার অপরিবর্তনীয় StarHermit ইউজার আইডিতে (UUID), না আপনার ব্যবহারকারীর নাম বা ডাকনাম।

আপনার আইডি পান:

STARHERMIT_USER_ID=$(
  curl -sS "$API/api/v1/me" \
    -H "Authorization: Bearer $ACCESS_TOKEN" |
  jq -r '.id'
)

রিপোজিটরি রুটে, তৈরি করুন বা আপডেট করুন starhermit.txt:

name=Orbit League
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html
owner=3fa85f64-5717-4562-b3fc-2c963f66afa6

উদাহরণ মালিকের সাথে প্রতিস্থাপন করুন STARHERMIT_USER_ID. এখানে আপনার ব্যবহারকারীর নাম বা ডাকনাম রাখবেন না; সেগুলি পরিবর্তন করতে পারে, যখন ব্যবহারকারী আইডি স্থিতিশীল মালিকানা সনাক্তকারী।

একটি প্রামাণিক গেমের জন্য, ঠিক একটি ব্যাকএন্ড ঘোষণা বজায় রাখুন:

# JavaScript runtime:
server=server.js

# OR container runtime, never both:
# container.image=ghcr.io/your-org/orbit-server@sha256:<64-lowercase-hex>

রিপোজিটরি/সংস্করণে ম্যানিফেস্টকে কমিট করুন এবং পুশ করুন StarHermit পড়তে পারে:

git add starhermit.txt
git commit -m "Declare StarHermit game ownership"
git push

দাবি করার আগে, ভান্ডারের কাঁচা খুলুন starhermit.txt একটি অননুমোদিত ব্রাউজারে URL এবং নিশ্চিত করুন যে নতুন মান সর্বজনীনভাবে পাঠযোগ্য। দাবি করার সময় রিপোজিটরি রিড করা হয়; একটি অপ্রকাশিত স্থানীয় পরিবর্তন কিছুই প্রমাণ করতে পারে না।

ধাপ 3: ম্যানিফেস্ট যাচাই করুন

একটি সাধারণ ক্লোন রিপোজিটরি গেমের জন্য, দাবি করার প্রয়োজন:

  • starhermit.txt ভান্ডার রুটে;
  • অ-খালি name=;
  • launch= একটি ভান্ডার-আত্মীয়কে নির্দেশ করে .html বা .htm ফাইল
  • একটি বৈধ ঐচ্ছিক server= পথ শেষ .js/.mjs, অথবা একটি বৈধ container.image= ঘোষণা
  • একসাথে উভয় সার্ভার রানটাইম না.

একটি GitHub পেজ তালিকা তার হোস্ট করা URL কে লঞ্চ টার্গেট হিসাবে রাখে এবং একটি ম্যানিফেস্টের প্রয়োজন হয় না যখন ব্যক্তিগত GitHub মালিকানা প্রমাণিত হয়, যদিও একটি বৈধ ম্যানিফেস্ট নাম এখনও আপডেট করতে পারে প্রদর্শনের নাম।

যদি গেমটি একটি ধারক ঘোষণা করে, তবে এর চিত্রটি অবশ্যই রেজিস্ট্রি, মালিকের নামস্থান এবং ডাইজেস্টকে সন্তুষ্ট করতে হবে মধ্যে নিয়ম কন্টেইনার-হোস্টেড গেম সার্ভার. কন্টেইনার হোস্টিংও হতে পারে প্ল্যাটফর্ম অপারেটর দ্বারা সীমাবদ্ধ।

ধাপ 4: তালিকা দাবি করুন

দাবির অনুরোধের কোনো অংশ নেই:

curl -sS -X POST \
  "$API/api/v1/me/github-games/$GAME_ID/claim" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

একটি সফল 200 আপডেট গেম ফেরত দেয়:

{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "repoUrl": "https://github.com/octocat/orbit-league",
  "ownerLogin": "octocat",
  "repoName": "orbit-league",
  "displayName": "Orbit League",
  "launchPath": "index.html",
  "gameSlug": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "isVerifiedOwner": true,
  "metadataSource": "starhermit.txt",
  "hosting": {
    "hostingEnabled": true,
    "deployStatus": "pending"
  }
}

আইডিটি ধাপ 1-এ পাওয়া একই হওয়া উচিত। একটি সফল দাবির পরে একটি নতুন তালিকা তৈরি করবেন না।

আপনি ইতিমধ্যেই পরিচালনা করছেন এমন একটি তালিকা দাবি করা ইচ্ছাকৃতভাবে অনুমোদিত। এটি ম্যানিফেস্টটি পুনরায় পাঠ করে, ব্যাকএন্ডের পুনঃবিধান করে, এবং হোস্টিংকে অনুরোধ করে, তাই একই কল পুনরায় সিঙ্ক্রোনাইজ করতে ব্যবহার করা যেতে পারে সংগ্রহস্থল পরিবর্তনের পরে মালিক-পরিচালিত গেম।

ধাপ 5: টেকওভার এবং স্থাপনা যাচাই করুন

নিশ্চিত করুন যে গেমটি এখন আপনার পরিচালিত তালিকায় প্রদর্শিত হবে:

curl -sS "$API/api/v1/me/github-games" \
  -H "Authorization: Bearer $ACCESS_TOKEN" |
jq --arg id "$GAME_ID" '.[] | select(.id == $id)'

স্থাপনার অবস্থা চেক করুন:

curl -sS \
  "$API/api/v1/me/github-games/$GAME_ID/deployment" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

একটি দাবি সাধারণত একটি স্থাপনার সারিবদ্ধ করে, তাই pending দাবি স্বাভাবিক হওয়ার পরপরই। সঙ্গে পোল ব্যাকঅফ যতক্ষণ না এটি পরিবেশের লাইভ/সফল অবস্থায় পৌঁছায় বা প্রকাশ না করে deployError.

টেকওভারের পরে, আপনার জন্য উপলব্ধ ব্যবস্থাপনার শেষ পয়েন্টগুলির মধ্যে রয়েছে:

PUT    /api/v1/me/github-games/{id}/deployment  pin a commit/branch and redeploy
POST   /api/v1/me/github-games/{id}/bundle      upload built client/container output
PUT    /api/v1/me/github-games/{id}/hosting     requeue hosting where supported
POST   /api/v1/me/github-games/{id}/transfer    transfer management deliberately
DELETE /api/v1/me/github-games/{id}             remove the game

মূল জমাকারী এই তালিকার অধীনে আর দেখতে পায় না GET /api/v1/me/github-games এবং পারে না এটির জন্য এই মালিক-স্কোপড ম্যানেজমেন্ট এন্ডপয়েন্টগুলি ব্যবহার করুন।

সমস্যা সমাধান

403: সংগ্রহস্থলের মালিককে লিঙ্ক করুন বা যোগ করুন owner=

লিঙ্ক করা GitHub লগইন মেলে না ownerLogin, বা ম্যানিফেস্ট owner ঠিক মেলে না আপনার StarHermit ব্যবহারকারী আইডি।

  • চেক করুন GET /api/v1/me/github.
  • সঠিক পরীক্ষা করুন ownerLogin পাবলিক তালিকা দ্বারা ফিরে.
  • প্রতিষ্ঠানের সংগ্রহস্থলের জন্য, ব্যবহার করুন owner=<your StarHermit user ID> রেপোতে
  • নিশ্চিত করুন যে আপনি ম্যানিফেস্টটি পুশ করেছেন এবং এর কাঁচা URL সর্বজনীনভাবে পাঠযোগ্য৷

404: সেই আইডির সাথে কোনো শেয়ার করা খেলা নেই

আইডি ভুল, বা তালিকা মুছে ফেলা হয়েছে. ধাপ 1 পুনরাবৃত্তি করুন। সরানো তালিকা দাবিযোগ্য নয়।

400: অনুপস্থিত বা অবৈধ starhermit.txt

একটি ক্লোন করা সংগ্রহস্থলের জন্য, নিশ্চিত করুন যে রুট ম্যানিফেস্ট বৈধ name এবং এইচটিএমএল launch মান এছাড়াও ঐচ্ছিক স্ক্রিপ্ট/ধারক ঘোষণা যাচাই করুন। দাবিটি মূলত মেটাডেটা বিশ্বাস করে না অ-মালিক দ্বারা প্রবেশ করানো; এটি রিপোজিটরি-নিয়ন্ত্রিত মেটাডেটা দিয়ে প্রতিস্থাপন করে।

স্লাগ/ব্যাকএন্ডের চারপাশে দাবি ব্যর্থ হয়

স্ক্রিপ্টটি অবৈধ হতে পারে বা ধারক হোস্টিং অনুপলব্ধ হতে পারে৷ ফিরে আসা ত্রুটি পরীক্ষা করুন এবং ব্যাকএন্ড ঘোষণা, তারপর আবার দাবি কল. প্ল্যাটফর্মটি গেমের UUID কে তার স্লাগ হিসাবে বরাদ্দ করে; বেছে নেওয়া বা সমাধান করার জন্য কোন প্রকাশ্য স্লাগ নেই।

GitHub লিঙ্ক করা হয়েছিল কিন্তু ভুল StarHermit অ্যাকাউন্ট লিঙ্কটির মালিক

অভিপ্রেত StarHermit অ্যাকাউন্টে সাইন ইন করুন এবং OAuth সম্পূর্ণ করুন লিঙ্ক সেখানে প্রবাহ। দাবি করবেন না একটি অস্থায়ী দ্বিতীয় StarHermit অ্যাকাউন্ট থেকে এবং তারপর অ্যাকাউন্ট মার্জিংয়ের উপর নির্ভর করুন; এপিআই ট্রান্সফার গেম ব্যবস্থাপনা, ব্যবহারকারীর পরিচয় নয়।

নিরাপত্তা নোট

  • সংগ্রহস্থল মালিকানার প্রমাণ হিসাবে একটি দাবি লিঙ্ক বা তালিকা আইডি গ্রহণ করবেন না.
  • GitHub অ্যাক্সেস টোকেন, কন্টেইনার শংসাপত্র বা অন্যান্য গোপনীয়তা রাখবেন না starhermit.txt.
  • সর্বদা অপরিবর্তনীয় StarHermit ব্যবহারকারী আইডি ব্যবহার করুন owner=; ব্যবহারকারীর নাম বা ডাকনাম ব্যবহার করবেন না।
  • দাবি করার আগে বিদ্যমান তালিকা এবং সংগ্রহস্থলের URL পর্যালোচনা করুন; প্রদর্শনের নাম অনন্য নয়।
  • যদি আপনি পরে গেমটি স্থানান্তর করেন, তাহলে প্রাপক ম্যানেজার হয়ে যাবে কিন্তু যাচাইকৃত-মালিকের স্থিতি রিসেট যদি তারা সংগ্রহস্থল নিয়ন্ত্রণ করে তবে তাদের অবশ্যই দাবি প্রবাহ চালাতে হবে।
