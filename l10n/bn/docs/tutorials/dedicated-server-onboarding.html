একটি ডেডিকেটেড গেম সার্ভার এবং অনবোর্ড প্লেয়ার ইন-গেম প্রকাশ করুন

এই টিউটোরিয়ালটি দেখায় কিভাবে:

  1. StarHermit এর বান্ডেল-আপলোড API সহ একটি ডেডিকেটেড গেম-সার্ভার কন্টেইনার প্রকাশ বা আপডেট করুন।
  2. একটি দীর্ঘস্থায়ী কন্টেইনারের StarHermit সার্ভার টোকেন নবায়ন করে রাখুন।
  3. স্টিম, এপিক, জিওজি, বা একটি স্বতন্ত্র বিল্ডের অনবোর্ড প্লেয়ারদের একটি মাধ্যমে না পাঠিয়ে OAuth প্রদানকারী বা তাদের StarHermit ড্যাশবোর্ডে যেতে হবে।
  4. সেই খেলোয়াড়দের StarHermit সেশন, ম্যাচমেকিং, লিডারবোর্ড, কৃতিত্বগুলিতে অ্যাক্সেস দিন সেশন চ্যাট, ভয়েস, বন্ধু, উপস্থিতি, এবং রিপ্লে।

এক্সিকিউটেবল স্টিম, এপিক, জিওজি, আপনার নিজের থেকে এসেছে কিনা প্লেয়ার-ফেসিং API একই লঞ্চার, বা https://<slug>.starhermit.com.

গুরুত্বপূর্ণ সীমানা: এমবেডেড নীরব নয়

StarHermit বর্তমানে কোনো বিশেষ সুবিধাপ্রাপ্তকে প্রকাশ করে না "নির্বিচারে প্লেয়ার তৈরি করুন" একটি খেলার শেষ বিন্দু সার্ভার একটি পাত্রের STARHERMIT_SERVER_TOKEN ইচ্ছাকৃতভাবে কোন খেলোয়াড়ের পরিচয় নেই এবং মিন্ট করতে পারে না প্লেয়ার অ্যাকাউন্ট বা ছদ্মবেশী খেলোয়াড়।

পাবলিক-কী রেজিস্ট্রেশনের জন্য একটি বৈধ ইমেল এবং একটি এক-কালীন যাচাইকরণ লিঙ্কও প্রয়োজন। অতএব:

  • আপনি পারে আপনার গেমের ব্র্যান্ডেড UI এর মধ্যে নিবন্ধন রাখুন এবং Google/GitHub OAuth এবং StarHermit ড্যাশবোর্ড।
  • আপনি পারে না নিঃশব্দে শুধুমাত্র একটি স্টিম আইডি, এপিক অ্যাকাউন্ট আইডি বা GOG থেকে একটি StarHermit অ্যাকাউন্ট তৈরি করুন আইডি খেলোয়াড়কে অবশ্যই সম্মতি দিতে হবে, একটি ইমেল সরবরাহ করতে হবে এবং একবার এটি নিশ্চিত করতে হবে।
  • প্রতিটি প্লেয়ারের ব্যক্তিগত কী তাদের ডিভাইসে তৈরি এবং সংরক্ষণ করুন। প্রতিটি খেলোয়াড়ের কী তৈরি করবেন না আপনার ডেডিকেটেড সার্ভারে, প্রাইভেট কী আপলোড করুন, অথবা একটি কাস্টোডিয়াল কী ডাটাবেস রাখুন যদি না আপনি ইচ্ছাকৃতভাবে যারা অ্যাকাউন্ট সব জন্য দায়িত্ব গ্রহণ.

একটি নেটিভ গেমের জন্য, সবচেয়ে মসৃণ সমর্থিত অভিজ্ঞতা হল: একটি ইন-গেম অ্যাকাউন্ট প্যানেল তৈরি করে কী, ইমেল এবং সম্মতির জন্য জিজ্ঞাসা করে, প্লেয়ার তাদের ইনবক্সে লিঙ্ক নিশ্চিত করার সময় অপেক্ষা করে, তারপর সাইন ইন করে কী দিয়ে এবং OS ক্রেডেনশিয়াল ভল্টে রিফ্রেশ টোকেন রাখে। খেলোয়াড়ের কখনই দরকার নেই StarHermit সাইট নেভিগেট করুন। যে প্লেয়ার একটি ইমেল প্রদান এবং যাচাই করতে পারে না সে বর্তমান API এর সাথে এই প্রবাহটি সম্পূর্ণ করতে পারে না।

স্থাপত্য এবং বিশ্বাসের সীমানা

Steam/Epic/GOG/native client
  ├─ owns the player's private key
  ├─ performs public-key registration/login
  ├─ holds player access + rotating refresh token
  ├─ optionally links the external platform identity
  └─ uses a game-scoped launch token for game/social APIs
                  │
                  │ REST + ws/v1/games
                  ▼
StarHermit API ───────── authenticated command ────────► your container
  ├─ creates sessions and matchmaking                     ├─ owns simulation
  ├─ stamps the trusted StarHermit user id                 ├─ never trusts payload identity
  ├─ persists snapshots/results/elo/achievements           └─ uses narrow server token only
  └─ supplies session chat, voice, friends, and replays

গেম ক্লায়েন্ট প্রমাণ করে যে খেলোয়াড় কে। StarHermit স্ট্যাম্প ট্রাফিকের উপর যে পরিচয় পাঠানো হয়েছে ধারক কনটেইনার কখনোই প্রমাণ হিসেবে গেমপ্লে JSON-এর ভিতরে সরবরাহ করা স্টিম আইডি বা ব্যবহারকারী আইডি গ্রহণ করে না পরিচয়

পূর্বশর্ত

আপনার প্রয়োজন:

  • একটি StarHermit বিকাশকারী অ্যাকাউন্ট এবং সম্পূর্ণ অ্যাক্সেস টোকেন।
  • আপনার মালিকানাধীন একটি নিবন্ধিত খেলা, সঙ্গে a gameSlug এবং প্রামাণিক ব্যাকএন্ড। বান্ডিল শেষ বিন্দু একটি বিদ্যমান গেম আপডেট করে; এটি একটি গেম রেকর্ড তৈরি করে না বা একটি স্লাগ সংরক্ষণ করে না।
  • আপনার অ্যাকাউন্টের জন্য কন্টেইনার হোস্টিং সক্ষম।
  • ডকার বা অন্য একটি টুল যা ডকার-সামঞ্জস্যপূর্ণ উত্পাদন করতে সক্ষম docker save সংরক্ষণাগার
  • একটি ধারক বাস্তবায়ন গেম প্রোটোকল v1.

প্রাথমিক স্ব-পরিষেবা নিবন্ধনের জন্য, এর সাথে একটি যাচাইকৃত GitHub সংগ্রহস্থল ব্যবহার করুন starhermit.txt এবং ক বৈধ container.image ঘোষণা হিসাবে বর্ণনা করা হয়েছে গিটহাব গেমস. একবার গেম বিদ্যমান, বান্ডেল পুশ পরবর্তীতে ক্লায়েন্ট এবং সার্ভার সরাসরি বিল্ড প্রকাশ করতে পারে।

পার্ট 1: কন্টেইনার চুক্তি বাস্তবায়ন

আপনার প্রক্রিয়া শুনতে হবে PORT এবং বাস্তবায়ন:

শেষবিন্দু দায়িত্ব
GET /health প্রত্যাবর্তন 200 শুধুমাত্র যখন সেশন গ্রহণ করা যেতে পারে
GET /describe প্রটোকল ঘোষণা করুন 1, অনুরোধ করা টিক রেট/ক্ষমতা, এবং অর্জন
POST /sessions একটি সেশন তৈরি করুন বা এর থেকে একটি পুনরুদ্ধার করুন৷ snapshot
GET /sessions/{id}/snapshot একটি সম্পূর্ণ টেকসই পুনরুদ্ধার পয়েন্ট ফিরে
DELETE /sessions/{id} অধিবেশন মুক্তি
WS /stream প্রমাণীকৃত প্লেয়ার কমান্ড গ্রহণ করুন এবং গেম পেলোড নির্গত করুন
WS /control পুশ স্ন্যাপশট, কৃতিত্ব, Elo, ফলাফল, এবং ব্যাকপ্রেশার

যাচাই করুন X-Starhermit-Invoke-Key প্রতি HTTP অনুরোধে এবং ওয়েবসকেট আপগ্রেডের বিরুদ্ধে STARHERMIT_INVOKE_KEY. এটি আপনার প্রক্রিয়ায় StarHermit প্রমাণীকরণ করে।

একটি ন্যূনতম ঘোষণা হল:

{
  "protocol": 1,
  "tickRateHz": 20,
  "maxSessions": 48,
  "replays": true,
  "achievements": [
    {
      "key": "first-win",
      "name": "First Win",
      "description": "Win a match.",
      "points": 10
    }
  ]
}

replays প্ল্যাটফর্মকে প্রতিটি সমাপ্ত সেশনের শেষ অবস্থা রাখতে বলে, যা কি GET /api/v1/games/{slug}/replays/{sessionId} পরিবেশন করে আপনার গেম রিপ্লে চায় শুধুমাত্র যদি এটি ঘোষণা; এটি ছাড়া ম্যাচ শেষ হলে কিছুই রাখা হয় না। দেখুন কন্টেইনার গেম সার্ভার - GET /describe.

গেমপ্লে স্ট্রিম ফ্রেম ব্যবহার করে:

[1 byte type][16 byte sessionId][16 byte userId][payload...]

টাইপ 1 একটি অন্তর্মুখী আদেশ; এর ব্যবহারকারী আইডি প্রমাণীকৃত StarHermit প্লেয়ার থেকে স্ট্যাম্প করা হয়েছিল। টাইপ 2 একটি আউটবাউন্ড JSON পেলোড যে প্লেয়ারকে সম্বোধন করা হয়, অথবা ব্যবহারকারীর আইডি থাকাকালীন প্রত্যেকের জন্য সব শূন্য।

টেকসই প্রভাব ওভার যেতে /control:

{ "type": "snapshot", "sessionId": "...", "state": { "round": 4 } }
{ "type": "achievements", "sessionId": "...", "unlocks": { "<userId>": ["first-win"] } }
{ "type": "elo", "sessionId": "...", "updates": { "<userId>": 1248 } }
{ "type": "result", "sessionId": "...", "result": { "kind": "win", "winner": "<userId>" } }

StarHermit এই আপডেটগুলি সেশন অংশগ্রহণকারীদের ফিল্টার করে এবং অ্যাচিভমেন্ট কী ঘোষণা করে। একটি ফলাফল হয় টার্মিনাল দেখুন কন্টেইনার-হোস্টেড গেম সার্ভার সম্পূর্ণ প্রোটোকলের জন্য, স্ন্যাপশট, বিচ্ছিন্নতা, এবং পুনরুদ্ধারের চুক্তি।

পর্ব 2: একবার গেমটি নিবন্ধন করুন

প্রাথমিক নিবন্ধনের জন্য ব্যবহৃত যাচাইকৃত সংগ্রহস্থলে একটি ম্যানিফেস্ট রাখুন:

name=Orbit League
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html
owner=3fa85f64-5717-4562-b3fc-2c963f66afa6  # your user ID from GET /api/v1/me, not username

container.image=ghcr.io/your-github-login/orbit-server@sha256:<64-lowercase-hex>
container.port=8080
container.health=/health
container.memory_mb=1024
container.cpu=1.0

সেট owner অপরিবর্তনীয় id দ্বারা ফিরে GET /api/v1/me. অ্যাকাউন্ট ব্যবহারকারীর নাম ব্যবহার করবেন না বা ডাকনাম; সেগুলি প্রদর্শন মান এবং পরিবর্তন হতে পারে।

এটি নিবন্ধন করুন:

API=https://api.starhermit.com
ACCESS_TOKEN='developer-access-token'

curl -sS -X POST "$API/api/v1/me/github-games" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "repoUrl":"https://github.com/your-github-login/orbit-league"
  }'

ফিরে আসা সংরক্ষণ করুন id হিসাবে GAME_ID এবং gameSlug হিসাবে GAME_SLUG, তারপর নিশ্চিত করুন যে ব্যাকএন্ড বিদ্যমান: GET $API/api/v1/games/$GAME_SLUG উত্তর 200 একবার এটা করে। একটি উপহার gameSlug একা করে না এটি প্রমাণ করুন - প্রতিটি যাচাইকৃত গেমে একটি, শুধুমাত্র ব্রাউজার অন্তর্ভুক্ত রয়েছে। একটি নিবন্ধন যা ঘোষণা করে একটি আপনার সংগ্রহস্থলের মালিক প্রমাণ না করেই ধারকটি প্রত্যাখ্যান করা হয়েছে 403, এবং প্রাথমিক নিবন্ধন কন্টেইনার হোস্টিং অনুপলব্ধ বা সীমাবদ্ধ হলে ব্যর্থ হতে পারে।

ম্যানিফেস্টে থাকা রেজিস্ট্রি-সমর্থিত চিত্রটি প্রথম সংস্করণ স্থাপন করার জন্য যথেষ্ট। পরবর্তী অধ্যায় সরাসরি-আপলোড পাথ কভার করে, CI এর জন্য উপযোগী এবং বিল্ডের জন্য যা আপনি চান না প্ল্যাটফর্ম ক্লোন বা আবার টান.

পার্ট 3: একটি ক্লায়েন্ট এবং ডেডিকেটেড সার্ভার বান্ডেল প্রকাশ করুন

আর্কাইভ তৈরি করুন

আপলোড হল এই লেআউট সহ একটি জিজিপ-সংকুচিত টার সংরক্ষণাগার:

client/            optional static web client, including the registered launch file
server/image.tar   optional `docker save` output
starhermit.txt     the manifest

অন্তত client/ বা server/image.tar উপস্থিত থাকতে হবে।

আপনি যদি কার্ল না করে StarHermit ওয়েব ড্যাশবোর্ড বা Windows ক্লায়েন্টের মাধ্যমে প্রকাশ করেন, আপনি তা করবেন না হাতে এই সংরক্ষণাগার নির্মাণ. একটি বাছাই করুন সার্ভার বিতরণ ফোল্ডার (ধারণ করা starhermit.txt এবং image.tar) বা দ image.tar নিজে থেকে, এবং ক্লায়েন্ট উপরের লেআউট প্যাক করে। দ starhermit.txt মান — প্রদর্শন নাম এবং container.* knobs — হয় ডায়ালগের ক্ষেত্রগুলি, ফোল্ডারের ম্যানিফেস্ট থেকে প্রিফিল করা হয় যখন একটি থাকে, তাই একটি খালি image.tar ঠিক পাশাপাশি প্রকাশ করে।

rm -rf bundle game-bundle.tar.gz
mkdir -p bundle/client bundle/server

# Optional hosted web client.
cp -R dist/. bundle/client/

# Dedicated server image.
docker build -t orbit-server:release -f Dockerfile.server .
docker save orbit-server:release -o bundle/server/image.tar

# Keeps the artifact self-describing, and is what the dashboard/desktop clients require.
cp starhermit.txt bundle/starhermit.txt

tar -C bundle -czf game-bundle.tar.gz .

ইমেজ অবশ্যই একটি পঠনযোগ্য রুট ফাইল সিস্টেমের সাথে কাজ করতে হবে, বাধ্যতামূলক নন-রুট ব্যবহারকারী, কোন ক্ষমতা নেই, না ভলিউম, ইন্টারনেট নেই, এবং শুধুমাত্র একটি ছোট লিখনযোগ্য /tmp. ছবিতে বিক্রেতার নির্ভরতা।

আপলোড করুন

POST /api/v1/me/github-games/{id}/bundle সংরক্ষণাগারটিকে কাঁচা অনুরোধের অংশ হিসাবে নেয়, a হিসাবে নয় মাল্টিপার্ট ফর্ম:

curl -sS -X POST "$API/api/v1/me/github-games/$GAME_ID/bundle" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/gzip" \
  --data-binary @game-bundle.tar.gz

প্রায় 100 MB এর বেশি একটি বান্ডিল এই রুট দিয়ে যাবে না। এপিআই এর সামনে সিডিএন একটি সঙ্গে একটি বড় অনুরোধ শরীরের প্রত্যাখ্যান 413 নিজস্ব - একটি প্ল্যাটফর্ম কখনও দেখে না, তাই এটি বহন করে না limitBytes এবং আপনি পড়তে পারেন এমন কোন লগে প্রদর্শিত হবে না। ক docker save একটি বাস্তব সার্ভার ইমেজ পৌঁছেছে সহজে যে আকার. আপনি যদি একটি দেখতে 413 সঙ্গে নেই limitBytes, এটি এটি এবং আপনার খেলা নয় ভাতা, যা গিগাবাইট।

অভিন্ন সংরক্ষণাগার ওভার পাঠান ws/v1/game-upload পরিবর্তে — ফ্রেম পরে a WebSocket আপগ্রেড একটি অনুরোধের অংশ নয়, তাই ক্যাপ প্রযোজ্য নয়। একই সংরক্ষণাগার বিন্যাস, একই ভাতা, একই JSON উত্তর; একটি সংযোজন হল যে আপনাকে অবশ্যই পাঠাতে হবে {"type":"complete"} যখন শেষ বাইটটি আউট হয়ে গেছে, কারণ আপনি না করা পর্যন্ত কিছুই প্রকাশিত হয় না।

উদাহরণ প্রতিক্রিয়া:

{
  "clientPublished": true,
  "serverImageLoaded": true,
  "imageDigest": "sha256:4e7d...",
  "bytesReceived": 318767104
}

প্ল্যাটফর্ম:

  • পারমাণবিকভাবে অদলবদল করে client/, তাই ব্যবহারকারীরা আংশিক আপলোড করা বিল্ড দেখতে পান না;
  • লোড server/image.tar, এর অপরিবর্তনীয় ডাইজেস্ট গণনা করে, এবং স্থাপনাটিকে পুনরায় পিন করে;
  • আপলোড করা ইমেজ দ্বারা প্রতিস্থাপন করা পুরানো ধারক সারিবদ্ধ;
  • তাদের স্থায়ী স্ন্যাপশট থেকে যোগ্য সক্রিয় সেশন পুনরুদ্ধার করে।

আপনি শুধুমাত্র ক্লায়েন্ট বা শুধুমাত্র সার্ভার ইমেজ আপলোড করতে পারেন. ক্লায়েন্ট-শুধু প্যাচ ব্যবহার ?mode=merge একই শেষ বিন্দুতে (দেখুন আংশিক আপডেট); একটি মার্জ একটি চিত্র এখনও আছে পুরো লোড একটি গেম এর ডিস্ক ভাতা হয় 2 জিবি starhermit.com এ (অপারেটর-টিউনেবল) এবং পারেন খেলা প্রতি সুর করা; কারণ একটি পুশ একটি গেমের সামগ্রীতে যোগ করার পরিবর্তে প্রতিস্থাপন করে, এটি উভয়ই গেমটি সবচেয়ে বড় পুশ এবং সর্বাধিক ডিস্ক দখল করতে পারে। 413 অন্তর্ভুক্ত limitBytes; একটি অবৈধ সংরক্ষণাগার বা ছবি রিটার্ন 422; এবং 507 মানে সার্ভারের এখন কোন জায়গা নেই — এটা চেক করা হয়েছে আপনার শরীর পড়ার আগে, তাই একটি ধ্বংসপ্রাপ্ত আপলোড অর্ধেক ল্যান্ড করার পরিবর্তে প্রত্যাখ্যান করা হয়। সিমলিঙ্ক লাগাবেন না, হার্ড লিঙ্ক, পাথ ট্রাভার্সাল, বা ফাইলগুলি সংরক্ষণাগারে নথিভুক্ত বিন্যাসের বাইরে।

একটি সফল আপলোডের অর্থ এই নয় যে নতুন প্রক্রিয়াটি এখনও স্বাস্থ্য পরীক্ষায় উত্তীর্ণ হয়েছে৷ বিদ্যমান পোল GET /api/v1/me/github-games/{id}/deployment প্রচার করার আগে একটি বাস্তব অধিবেশন দেখুন এবং পরীক্ষা করুন নির্মাণ একটি রিপোজিটরি কমিট পিন করা পরে স্পষ্টভাবে ডিপ্লয়মেন্টকে রিপোজিটরি কন্টেন্টে ফিরিয়ে দেয়।

থেকে একটি বিদ্যমান গেম স্যুইচ করা হচ্ছে server= একটি পাত্রে

সমর্থিত, এবং এটি গেমটিকে রাখে: একই আইডি, স্লাগ, <uid>.starhermit.com ঠিকানা, খেলোয়াড়, লিডারবোর্ড এবং অর্জন। কোন পৃথক নিবন্ধন ধাপ নেই.

  1. প্রতিস্থাপন করুন server=... আপনার সাথে container.* ব্লক ইন starhermit.txt. দুজনে পারস্পরিক একচেটিয়া উভয় ঘোষণা একটি ম্যানিফেস্ট অস্বীকার করা হয়.
  2. একটি বান্ডিল বহন ধাক্কা client/ (সেই প্রকাশ সহ) এবং server/image.tar, ওভার ws/v1/game-upload যদি এটি বড় হয়।
  3. আপনি যে ছবিটি আপলোড করেন সেটিই চলে। ক container.image= একই ম্যানিফেস্টে লাইন হয় রাখা ভাল, কিন্তু আপলোড করা ডাইজেস্ট এর উপর জয়লাভ করে।
  4. পোল GET /api/v1/me/github-games/{id}/deployment এটি পড়া পর্যন্ত running, তারপর একটি বাস্তব শুরু ঘর বা ম্যাচ।

পার্ট 4: কন্টেইনারের প্ল্যাটফর্ম টোকেন পুনর্নবীকরণ করুন

স্টার্টআপে ধারকটি গ্রহণ করে:

STARHERMIT_API_BASE
STARHERMIT_GAME_SLUG
STARHERMIT_SERVER_TOKEN
STARHERMIT_SERVER_TOKEN_EXPIRES_IN
STARHERMIT_REFRESH_KEY
STARHERMIT_INVOKE_KEY

STARHERMIT_SERVER_TOKEN সংকীর্ণ: এটি গেম সার্ভারের প্রতিনিধিত্ব করে, প্লেয়ার নয়। এর পরে মেয়াদ শেষ হয় ডিফল্টরূপে 24 ঘন্টা। প্রায় অর্ধেক সময়সূচী পুনর্নবীকরণ STARHERMIT_SERVER_TOKEN_EXPIRES_IN:

POST {STARHERMIT_API_BASE}/api/v1/games/{STARHERMIT_GAME_SLUG}/server/token
X-Starhermit-Refresh-Key: {STARHERMIT_REFRESH_KEY}

{ "token": "eyJhbGciOi...", "expiresInSeconds": 86400 }

এই এন্ডপয়েন্টের জন্য কোন বেয়ারার টোকেনের প্রয়োজন নেই। পুরানো টোকেন থাকলেও এটি পুনরুদ্ধারের অনুমতি দেয় ইতিমধ্যে মেয়াদ উত্তীর্ণ। ইন-মেমরি টোকেনটি পারমাণবিকভাবে প্রতিস্থাপন করুন এবং নতুন থেকে পরবর্তী পুনর্নবীকরণের সময়সূচী করুন expiresInSeconds.

দুটি স্থাপনার গোপনীয়তা আলাদা রাখুন:

  • STARHERMIT_INVOKE_KEY আপনার কন্টেইনারে StarHermit অনুরোধগুলিকে প্রমাণীকরণ করে।
  • STARHERMIT_REFRESH_KEY StarHermit টোকেন পুনর্নবীকরণ করার সময় আপনার কন্টেইনারকে প্রমাণীকরণ করে।

উভয়ই প্রতিটি কন্টেইনার রিস্টার্টে ঘোরে। তাদের কখনই লগ ইন করবেন না, তাদের ফিরিয়ে দিন /describe, তাদের একটি মধ্যে রাখুন স্ন্যাপশট, বা একটি প্লেয়ার তাদের পাঠান.

পার্ট 5: OAuth ছাড়া একজন নন-স্টারহার্মিট প্লেয়ার অনবোর্ড

এই প্রবাহটি নেটিভ গেম বা লঞ্চারে চালান, ডেডিকেটেড পাত্রে নয়। সম্পূর্ণ ওয়াকথ্রু, পরীক্ষিত ক্লায়েন্ট কোড সহ, হল টিউটোরিয়াল: একটি পাবলিক কী সহ অনবোর্ড প্লেয়ার; সংক্ষেপে:

  1. প্রতি-ইনস্টলেশন কী তৈরি করুন প্রথম লঞ্চে (Ed25519 প্রস্তাবিত) এবং ব্যক্তিগত কী রাখুন OS শংসাপত্রের দোকানে। এটি কখনই আপলোড করবেন না এবং আপনার সার্ভারে খেলোয়াড়দের কী তৈরি করবেন না।
  2. সম্মতি এবং একটি ইমেল ঠিকানার জন্য জিজ্ঞাসা করুন, তারপর POST /api/v1/auth/public-key/register সঙ্গে { email, keyType, keyData } প্লেয়ারের ডিভাইস থেকে। এটি প্রতি এক নিবন্ধন থ্রোটল করা হয় ঠিকানা এবং প্রতি আইপি প্রতি 24 ঘন্টা (429 সঙ্গে Retry-After), তাই এটি আপনার মাধ্যমে প্রক্সি করবেন না সার্ভার - প্রত্যেক প্লেয়ার তার আইপি শেয়ার করবে।
  3. প্লেয়ার নিশ্চিত করার জন্য অপেক্ষা করুন। ইমেল করা লিঙ্কটি এমন একটি পৃষ্ঠা খোলে যা পর্যন্ত কিছুই পরিবর্তন করে না প্লেয়ার কনফার্ম চাপে, যা অ্যাকাউন্ট তৈরি করে এবং কী সংযুক্ত করে; starhermit.com-এ তারা তারপর StarHermit ড্যাশবোর্ডে অবতরণ করে, তাই আপনার গেম সেই টোকেনগুলি গ্রহণ করে না। পরিবর্তে এটি এটি সফল না হওয়া পর্যন্ত কী দিয়ে সাইন ইন করুন: challenge, StarHermit এর স্বাক্ষর করুন সঠিক চ্যালেঞ্জ বাইট, complete. পর্যন্ত খেলোয়াড় নিশ্চিত করে, complete উত্তর 401 "Public key not registered or revoked.".
  4. অধিবেশন রাখুন সঙ্গে POST /api/v1/auth/refresh, এবং যখনই আবার কী দিয়ে সাইন ইন করুন রিফ্রেশ ব্যর্থ হয় বর্তমান শর্তাবলী গ্রহণ করুন যখন GET /api/v1/me রিপোর্ট termsAcceptanceRequired (অ্যাকাউন্ট সেশন এবং প্লেয়ার লঞ্চ টোকেন উভয়ই করতে পারেন — দেখুন শর্তাবলী গ্রহণ) আপনার ধারক এর স্থাপনার টোকেন হয় শর্তাবলী থেকে অব্যাহতি; যে ছাড় তার খেলোয়াড়দের প্রসারিত হয় না.

আরও ডিভাইস। প্রতিটি ইনস্টলেশন প্লেয়ারের একই ইমেল ঠিকানার সাথে নিজস্ব কী নিবন্ধন করে, এবং কী বিদ্যমান অ্যাকাউন্টে যোগদান করে। POST /api/v1/me/public-keys এই খেলোয়াড়দের জন্য একটি বিকল্প নয়: এটির জন্য একটি সেশন প্রয়োজন যা একটি OAuth প্রদানকারীর মাধ্যমে সাইন ইন করা হয়েছে৷

5. একটি প্লেয়ার-মুখী নাম এবং বাহ্যিক পরিচয় যোগ করুন

উৎপন্ন অ্যাকাউন্ট একটি দিয়ে শুরু হয় pk-... ব্যবহারকারীর নাম খেলোয়াড়কে একটি ডাকনাম বেছে নিতে দিন:

PATCH /api/v1/me
Authorization: Bearer <access-token>
Content-Type: application/json

{ "nickname": "RookPilot" }

আপনি যে প্ল্যাটফর্মের অধীনে এক্সিকিউটেবল চলছে তার সাথে অ্যাকাউন্টটি যুক্ত করতে পারেন:

POST /api/v1/me/identities
Authorization: Bearer <access-token>
Content-Type: application/json

{
  "provider": "epic",
  "providerUserId": "epic-account-id",
  "metadata": "{\"displayName\":\"RookPilot\"}"
}

ব্যবহার a অ-সংরক্ষিত প্রদানকারীর নাম (epic, gog, অথবা আপনার নিজের স্টোরফ্রন্ট আইডি)। করবেন না ব্যবহার steam, google, github, বা অন্য কোনো নাম যাকে প্ল্যাটফর্মটি OAuth প্রদানকারী হিসাবে বিবেচনা করে — সেগুলি সেই প্রদানকারী কনফিগার করা না থাকলেও প্রত্যাখ্যান করা হয়। সেই প্ল্যাটফর্ম থেকে বাহ্যিক আইডি পান প্রমাণীকৃত SDK/সেশন, সম্পাদনাযোগ্য প্লেয়ার ইনপুট থেকে নয়। এই শেষবিন্দু একটি পরিচয় সংযুক্ত করে StarHermit অ্যাকাউন্টের সাথে; এটি নিজেই স্টোরফ্রন্ট মালিকানার প্রমাণ নয় এবং প্রতিস্থাপন করা উচিত নয় ক্রয় বা নিষেধাজ্ঞার জন্য প্ল্যাটফর্মের নিজস্ব টিকিট যাচাইকরণ।

আলাদা এক্সটার্নাল-লাইব্রেরি এপিআই ঐচ্ছিক এবং বর্তমানে প্রদানকারী থাকাকালীন ডেমো সিঙ্ক্রোনাইজেশন ব্যবহার করে ইন্টিগ্রেশন চূড়ান্ত করা হয়; এটা ডেডিকেটেড সার্ভার খেলার জন্য প্রয়োজন হয় না.

পার্ট 6: গেমটিতে প্রবেশ করুন এবং StarHermit পরিষেবাগুলি ব্যবহার করুন

প্রতিস্থাপন করুন {slug} নীচের HTTP উদাহরণগুলির সাথে GAME_SLUG, আপনি যে গেমটিতে UUID পেয়েছেন নিবন্ধন ভান্ডারের নাম orbit-league একটি প্রদর্শন/উৎস নাম, API স্লাগ নয়।

মিন্ট একটি ন্যূনতম বিশেষাধিকার গেম টোকেন

আপনার গেমে বেড়া দেওয়া একটি টোকেন মিন্ট করতে একবার সম্পূর্ণ অ্যাক্সেস টোকেন ব্যবহার করুন:

POST /api/v1/games/{slug}/launch-token
Authorization: Bearer <access-token>

{ "token": "eyJhbGciOi...", "expiresInSeconds": 3600 }

গেমপ্লে এবং অনুমোদিত সেশন সামাজিক API-এর জন্য এই লঞ্চ টোকেন ব্যবহার করুন। মেয়াদ শেষ হওয়ার আগে এটি রিফ্রেশ করুন। যেখানে সম্ভব গেমপ্লে কোডের বাইরে সম্পূর্ণ অ্যাকাউন্ট টোকেন রাখুন।

ম্যাচমেকিং

POST /api/v1/games/{slug}/matchmaking
Authorization: Bearer <game-token>

পোল GET /api/v1/games/{slug}/matchmaking পর্যন্ত status হয় matched, তারপর সংযোগ করুন:

wss://api.starhermit.com/ws/v1/games?sessionId=<sessionId>&access_token=<game-token>

ক্লায়েন্ট বার্তা JSON থেকে যায়:

{ "type": "cmd", "data": { "type": "input", "throttle": 0.8 } }

StarHermit কমান্ডটিকে কনটেইনার স্ট্রীমে রূপান্তর করে এবং প্রমাণীকৃত StarHermit স্ট্যাম্প করে ব্যবহারকারী আইডি। আপনার কন্টেইনার টাইপ-2 স্ট্রিম ফ্রেমের মাধ্যমে প্রামাণিক গেম পেলোড ফেরত দেয়।

লিডারবোর্ড এবং অর্জন

প্রতিটি প্রামাণিক গেম একটি Elo লিডারবোর্ড পায়। আপনার ধারক Elo পরিবর্তন এবং ঘোষণা পাঠায় অর্জন উন্মোচিত হয় /control; ক্লায়েন্ট শুধুমাত্র ফলাফল প্ল্যাটফর্ম অবস্থা পড়ে:

GET /api/v1/games/{slug}/achievements
GET /api/v1/leaderboards/{leaderboardId}/entries

একটি পরিবর্তিত স্টিম/এপিক/জিওজি ক্লায়েন্ট সরাসরি গেম লিডারবোর্ড স্কোর জমা দিতে বা দাবি করতে পারে না খেলার মালিকানাধীন কৃতিত্ব।

অধিবেশন চ্যাট এবং ভয়েস

GET /api/v1/games/{slug}/sessions/{sessionId} রিটার্ন chatConversationId. অধিবেশন কথোপকথন অংশগ্রহণকারীদের চ্যাট করতে এবং ভয়েস ব্যবহার করার অনুমতি দেয় এমনকি তারা বন্ধু না হলেও।

সাধারণ ভয়েস প্রবাহ:

  1. GET /api/v1/voice/rooms?conversationId=<chatConversationId>.
  2. প্রয়োজন হলে, POST /api/v1/voice/rooms কথোপকথন আইডি সহ।
  3. POST /api/v1/voice/rooms/{roomId}/join.
  4. সংযোগ করুন wss://api.starhermit.com/ws/v1/voice?roomId=<roomId>&access_token=<game-token>.

একই অ্যাকাউন্ট বন্ধু, উপস্থিতি, গেমের আমন্ত্রণ, রিপ্লে এবং প্রোফাইল পরিচয় জুড়ে সক্ষম করে সমস্ত স্টোরফ্রন্ট বিল্ড। একটি নতুন অ্যাকাউন্ট তৈরি করার পরিবর্তে একজন মানুষ প্রতি একটি StarHermit কী/অ্যাকাউন্ট রাখুন প্রতিটি ম্যাচ বা প্রতিটি স্টোরফ্রন্ট লঞ্চের জন্য।
