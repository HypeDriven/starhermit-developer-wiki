টিউটোরিয়াল: ক্রমাগত সেশন — গেম যেগুলি যখন সবাই চলে যায় তখন বিরতি দেয়

সাধারণত প্ল্যাটফর্ম এমন একটি ম্যাচ শেষ করে যা কেউ খেলছে না: একবার প্রতিটি খেলোয়াড় সংযোগ বিচ্ছিন্ন হয়ে গেলে এবং কেউ না পাঁচ মিনিটের মধ্যে ফিরে এসেছে, সেশন শেষ হয়ে গেছে abandoned কারণ সহ players_left (দেখুন গেম এপিআই - গেমপ্লে ওয়েবসকেট) এটা দাবা খেলার জন্য সঠিক খেলা বা একটি জাতি, এবং একটি খামার, একটি শহর নির্মাতা, একটি ভাগ করা অন্ধকূপ বা যে কোনো বিশ্বের জন্য ভুল খেলোয়াড়রা দিনে ফিরে আসে।

একটি খেলা জন্য জিজ্ঞাসা করতে পারেন অবিরাম সেশন পরিবর্তে একটি ক্রমাগত সেশন বিরতি দেয় যখন এর খেলোয়াড়রা সংযোগ বিচ্ছিন্ন করে:

  1. শেষ খেলোয়াড় চলে যায়।
  2. প্রায় 15 সেকেন্ড পরে, কেউ সংযুক্ত না, প্ল্যাটফর্ম বিরতি অধিবেশন কিছুই চলে না: একটি স্ক্রিপ্ট খেলা না পায় onTick কল, এবং একটি ধারক গেম এর সেশন থেকে সরানো হয় ধারক
  3. সেশনটি তার পুনরুদ্ধার ধরে রাখার নীতির মধ্যে বিরতি দেয়। পড়ুন /sessions/{id}/recovery এটা চিরতরে রাখা হয়েছে অনুমান করার পরিবর্তে যে কোন মেয়াদ শেষ হওয়ার জন্য।
  4. সংযোগকারী প্রথম প্লেয়ার ws/v1/games পুনরায় শুরু এটা, তাদের প্রথম আদেশ আগে পরিচালিত খেলা যেখানে থামে সেখান থেকে চলতে থাকে।

এই পৃষ্ঠাটি দেখায় কীভাবে এটি চালু করতে হয়, কীভাবে আপনার গেমের ঘড়িগুলিকে বিরতি দিয়ে জাম্পিং থেকে বাঁচাতে হয় এবং আপনার ক্লায়েন্টকে কি করতে হবে।

1. নির্বাচন করুন৷

অধ্যবসায় হল একটি প্রতি-গেম ঘোষণা, আপনার গেমটি প্রকাশিত বা আপডেট হলে পড়ুন — একটি প্রকাশ করুন এটি পরিবর্তন করার পরে আপডেট করুন। এটি একটি আক্ষরিক হতে হবে true বা false; অন্য কিছু না হিসাবে গণনা ঘোষণা, এবং একটি খেলা যা ঘোষণা করে না কিছুই আগের মতো আচরণ করে না।

স্ক্রিপ্ট খেলা - একটি স্ট্যাটিক persistent উপর game বস্তু (দেখুন খেলা স্ক্রিপ্ট):

globalThis.game = {
  persistent: true,
  tickRateHz: 1,
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

ধারক খেলা — persistent আপনার মধ্যে GET /describe উত্তর (দেখুন কন্টেইনার গেম সার্ভার):

{ "protocol": 1, "tickRateHz": 20, "maxSessions": 48, "persistent": true }

সেশনগুলি কীভাবে তৈরি করা হয় সে সম্পর্কে কিছুই পরিবর্তন হয় না: ম্যাচমেকিং, আমন্ত্রণ, এআই এন্ডপয়েন্ট এবং রিয়েলটাইম রুম সব একটি অবিরাম খেলা জন্য অবিরাম সেশন উত্পাদন.

2. বিরতির সময় খেলার সময় স্থির রাখুন

প্ল্যাটফর্ম পুনর্লিখন না ctx.now — এটা বাস্তব প্রাচীর ঘড়ি থাকে, তাই যে কোনো পরম সময় আপনি খেলোয়াড় দেখান (একটি সময়সীমা, ক "এ ফসল প্রস্তুত") যা বলে তা মানে রাখে। পরিবর্তে, অবিরাম সেশনগুলি একটি অতিরিক্ত প্রসঙ্গ ক্ষেত্র পায়:

ctx.pausedMs   // total milliseconds this session has spent paused, so far

এটি শুধুমাত্র বৃদ্ধি পায়, এবং শুধুমাত্র ক্রমাগত সেশনে (অন্যান্য গেম কখনই মাঠ দেখতে পায় না)। এটি এবং আপনি বিয়োগ করুন আছে a খেলা ঘড়ি কেউ না থাকার সময় এটি থামে:

function gameTime(ctx) {
  return ctx.now - (ctx.pausedMs || 0);
}

globalThis.game = {
  persistent: true,
  tickRateHz: 1,

  createSession(ctx) {
    return { ok: true, sessionState: { lastTick: gameTime(ctx), crops: [] } };
  },

  onTick(ctx) {
    var state = ctx.sessionState;
    var t = gameTime(ctx);
    var dt = t - state.lastTick;      // never includes the time the world was paused
    state.crops.forEach(function (crop) { crop.growth += dt; });
    state.lastTick = t;
    return { ok: true, sessionState: state };
  },

  onPlayerMessage(ctx) { /* ... */ }
};

খেলার সময় আপনার নিজস্ব টাইমস্ট্যাম্প সংরক্ষণ করুন (gameTime(ctx)), মধ্যে না ctx.now, এবং শুধুমাত্র তাদের তুলনা খেলার সময়ের বিরুদ্ধে। যদি আপনি চাই পৃথিবী এগিয়ে যাওয়ার জন্য যখন কেউ দেখছে না - ফসল যে বেড়েছে রাতারাতি — ব্যবহার ctx.now পরিবর্তে এবং একটি জীবনবৃত্তান্ত পরে প্রথম টিক ধরা. যেভাবেই হোক এটা আপনার পছন্দ; প্ল্যাটফর্ম শুধুমাত্র রিপোর্ট কি ঘটেছে.

সময়ের দুটি বিবরণ:

  • শেষ প্লেয়ারের চলে যাওয়া এবং বিরতির মধ্যে ~15 সেকেন্ডের সময়, সেশনটি স্থির থাকে স্বাভাবিকভাবে টিক দেওয়া। একটি খেলোয়াড় যার সংযোগ ড্রপ এবং সরাসরি ফিরে আসে একটি বিরতি কারণ না.
  • একটি জীবনবৃত্তান্ত পরে, পরের onTick এক টিক ব্যবধান পরে আসে। বিরতি সময় পুনরায় প্লে করা হয় না মিস করা টিকগুলির ব্যাকলগ হিসাবে।

একটি ধারক গ্রহণ pausedMs একই জায়গায়: in the POST /sessions শরীর এটি পাঠানো হয় যখন সেশন একটি বিরতি পরে পুনরুদ্ধার করা হয়.

3. আপনার ক্লায়েন্ট

একটি বিরতি দেওয়া সেশন এখনও একটি সক্রিয় সেশন, তাই ক্লায়েন্ট ফ্লো আপনার ইতিমধ্যেই রয়েছে:

  • পুনরায় যোগদানের জন্য বিশ্বের তালিকা করুন সঙ্গে GET /api/v1/games/{slug}/sessions/mine. প্রতিটি এন্ট্রি আছে একটি pausedAt টাইমস্ট্যাম্প যখন এটি বিরতি দেওয়া হয় এবং null যখন কেউ এটিতে থাকে, যাতে আপনি দেখাতে পারেন "বিরতি দেওয়া যেহেতু…" বা "2 বন্ধু এখন খেলছে" (দেখুন গেম এপিআই — সেশন).
  • পুনরায় যোগদান করুন খোলার মাধ্যমে ws/v1/games?sessionId=… ঠিক আগের মত। জীবনবৃত্তান্তের সময় ঘটে সংযোগ বিশেষ কিছু নেই "পুনরায় শুরু" এটির জন্য ফ্রেম — গেমটি কেবল চলছে যখন আপনার প্রথম কমান্ড আসে - তাই অনুরোধ করুন বা আপনার গেমের স্বাভাবিক পূর্ণ-রাষ্ট্রীয় বার্তার জন্য অপেক্ষা করুন, যেমন আপনি করবেন যে কোনো পুনঃসংযোগ।
  • একটি ব্যর্থ জীবনবৃত্তান্ত হ্যান্ডেল. যদি প্ল্যাটফর্মটি সেশন পুনরায় শুরু করতে না পারে - সম্ভবত একটি ধারক গেম যার সার্ভার এখনও শুরু হচ্ছে - আপনি পাবেন {"type":"error","error":"…"} এবং সকেট কোড দিয়ে বন্ধ করা হয় 1001. অধিবেশন থেমে থাকে এবং কিছুই হারায় না। একটি সংক্ষিপ্ত পরে পুনরায় সংযোগ ব্যাকঅফ (কয়েক সেকেন্ড, ক্রমবর্ধমান), এবং দেখান "বিশ্ব শুরু…" বরং একটি ত্রুটি.
  • presence ফ্রেমগুলি যথারীতি কাজ করে, তাই অন্যান্য খেলোয়াড়রা এই মুহূর্তে বিশ্বে কে আছে তা দেখতে পায়।

4. একটি অবিরাম অধিবেশন শেষ করা

একটি স্থায়ী অধিবেশন শেষ হয় যখন:

  • আপনার খেলা রিপোর্ট একটি result (স্ক্রিপ্ট রিটার্ন মান বা ধারক নিয়ন্ত্রণ বার্তা), বা
  • গেমটির মালিক এটি শেষ করে (DELETE /api/v1/me/github-games/{id}/sessions/{sessionId}),
  • শেষ সদস্য স্পষ্টভাবে একটি ঘর ছাড়া একটি পৃথিবী ছেড়ে যায় /sessions/{id}/leave, বা
  • এর বিরাম দেওয়া পুনরুদ্ধার ডেটা স্থাপনার ধারণ নীতির অধীনে মেয়াদ শেষ হয়ে যায়।

সংযোগ বিচ্ছিন্ন করলে সদস্যপদ অক্ষত থাকে; স্পষ্টভাবে ছেড়ে যাওয়া সদস্যপদ ছেড়ে দেয়। দেখুন সেশন জীবনচক্র এবং পুনরুদ্ধার উভয় প্রবাহের জন্য

একটি নতুন খেলা জন্য জিজ্ঞাসা করে না প্লেয়ারের বিরতি দেওয়াগুলিকে অবসর দেওয়া এবং বিরতি দেওয়া সেশনগুলি এখনও গণনা করা হয়৷ প্লেয়ার প্রতি সমবর্তী-সেশন ক্যাপের বিপরীতে (ডিফল্টরূপে 20)। খেলোয়াড়দের শেষ করার উপায় দিন বা একটি পৃথিবী ছেড়ে — একটি "পৃথিবী ছেড়ে দাও" একটি দিয়ে আপনার স্ক্রিপ্ট উত্তর আদেশ করুন result, উদাহরণস্বরূপ। অন্যথায় একজন খেলোয়াড় যিনি তাদের ক্যাপ পূরণ করেছেন নতুন কিছু শুরু করতে পারবেন না।

onPlayerMessage(ctx) {
  var msg = ctx.message.data;
  if (msg.type === "close-world" && ctx.message.from === ctx.sessionState.ownerId) {
    return { ok: true, sessionState: ctx.sessionState, result: { kind: "closed" } };
  }
  /* ... */
}

5. ধারক গেম: পার্কিং

একটি ধারক খেলার জন্য একটি বিরতি একটি পার্ক:

  1. প্ল্যাটফর্মটি একটি চূড়ান্ত স্ন্যাপশট চেয়েছে (GET /sessions/{id}/snapshot) এবং এটি টেকসইভাবে সংরক্ষণ করে।
  2. এটি অধিবেশন অশ্রুপাত (DELETE /sessions/{id}) আপনার ধারক এটি অনুকরণ বন্ধ করে, এবং যদি এটির অন্য কোন সেশন নেই এটি নিষ্ক্রিয় সময়ের পরে স্থাপনা বন্ধ করা যেতে পারে।
  3. পরবর্তী যোগদানে এটি এর সাথে সেশনটি পুনরায় তৈরি করে POST /sessions, সঞ্চিত বহন snapshot এবং আপডেট করা হয়েছে pausedMs — ক্র্যাশ পুনরুদ্ধারের মতো একই অনুরোধ — একটি বন্ধ স্থাপনাকে জাগিয়ে তোলা প্রয়োজন হলে প্রথমে।

সুতরাং আপনি যে স্ন্যাপশটটি ফেরত দেবেন তা অবশ্যই পুরো বিশ্বকে পুনর্নির্মাণের জন্য যথেষ্ট হবে, শুধুমাত্র কয়েকটি পুনরায় শুরু করার জন্য নয় খেলার সেকেন্ড যদি সেই চূড়ান্ত স্ন্যাপশট ব্যর্থ হয়, সেশনটি তার শেষ পর্যায়ক্রমিক থেকে পার্ক করা হয় চেকপয়েন্ট ক্র্যাশের বিপরীতে, একটি পার্ক-এন্ড-রিস্টোর আপনার রিস্টার্ট বাজেটের সাথে গণনা করা হয় না, এবং খেলোয়াড়রা না পান resumed ফ্রেম: স্টেট রিওয়াইন্ড দেখার জন্য কেউ ছিল না।
