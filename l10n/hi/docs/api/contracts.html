REST और WebSocket अनुबंध

ये डाउनलोड करने योग्य अनुबंध संदर्भ पृष्ठों के पूरक हैं। संचालन का निरीक्षण करने के लिए उनका उपयोग करें, उदाहरण पेलोड को मान्य करें, या ओपनएपीआई-संगत क्लाइंट में REST अनुरोध आयात करें।

फ़ाइल कवरेज
ओपनएपीआई रेस्ट अनुबंध सार्वजनिक REST विधियाँ, पथ, पैरामीटर, JSON अनुरोध मॉडल, सफलता प्रतिक्रियाएँ, और क्रेडेंशियल परिवार; आरक्षित पीढ़ी संचालन अनुपलब्ध के रूप में चिह्नित हैं
वेबसॉकेट JSON स्कीमा प्रोटोकॉल और दिशा द्वारा ज्ञात पाठ फ़्रेम; एप्लिकेशन-स्वामित्व वाला गेमप्ले/सिग्नलिंग डेटा खुला रहता है
बाइनरी लेआउट रीयलटाइम प्रेषक उपसर्ग, ध्वनि उपसर्ग, अनफ़्रेम्ड रिले, कंटेनर स्ट्रीम हेडर, और अपलोड भाग

बाकी अनुबंध

REST फ़ाइल का उपयोग करता है ओपनएपीआई 3.0.3 और सार्वजनिक एपीआई मूल। प्रत्येक ऑपरेशन अपने संदर्भ पृष्ठ से लिंक होता है, जिसमें संपूर्ण प्राधिकरण, सत्यापन, सीमाएं और त्रुटि नियम शामिल हैं। x-credentials स्वीकृत क्रेडेंशियल परिवारों की पहचान करता है; यह स्वामित्व या सदस्यता जाँच को प्रतिस्थापित नहीं करता है। x-required-policies नामित अनुमतियों का वर्णन करता है जहां एपीआई उन्हें लागू करता है।

प्रत्युत्तरों में अतिरिक्त फ़ील्ड शामिल हो सकते हैं. गेम-विशिष्ट JSON, मेटाडेटा, डायग्नोस्टिक्स और अपलोड परिणाम खुले आकार का उपयोग करते हैं जहां गेम या एंडपॉइंट संदर्भ उनकी सामग्री को परिभाषित करता है। सफलता स्कीमा कोई वादा नहीं है कि प्रत्येक कॉल करने वाला अधिकृत है। समापन बिंदु त्रुटियाँ JSON, सादा पाठ, हो सकती हैं खाली प्रतिक्रियाएँ, या सत्यापन समस्या विवरण; उपयोग रक्षात्मक प्रतिक्रिया विश्लेषण.

आरक्षित पीढ़ी के संचालन को एक कार्यशील सेवा के रूप में न मानें। उनके अनुबंध का वर्णन है वर्तमान 503 overloaded प्रतिक्रिया, भविष्य के अनुरोध फ़ील्ड या पीढ़ी व्यवहार नहीं।

वेबसॉकेट अनुबंध

एक विकल्प चुनें $defs आपके सॉकेट के प्रोटोकॉल और दिशा के लिए स्कीमा। उदाहरण के लिए, किसी क्लाइंट को मान्य करें के खिलाफ आंदोलन की रूपरेखा GameRealtimeInput, सामान्य टिकाऊ के बजाय GameCommand:

{ "type": "cmd", "data": { "type": "input", "realtime": true, "seq": 1, "x": 0.5 } }

realtime अंतर्गत आता है अंदर data. इसके बाद के गेमप्ले फ़ील्ड आपके गेम का अनुबंध हैं। का उपयोग करो JSON स्कीमा 2020-12 संपूर्ण स्कीमा दस्तावेज़ के साथ सत्यापनकर्ता ताकि स्थानीय संदर्भ हल हो जाएं। मूल दस्तावेज़ में परिभाषाएँ हैं; किसी फ़्रेम को मान्य करने के लिए परिभाषा का चयन करना आवश्यक है।

शिष्टाचार ग्राहक पाठ परिभाषा सर्वर टेक्स्ट परिभाषा बाइनरी डेटा
खेल GameCommand / GameRealtimeInput GameServerFrame केवल टेक्स्ट गेमप्ले
रीयलटाइम कमरे RealtimeClientControl RealtimeServerFrame होस्ट-रूटेड गेम डेटा, प्राप्त होने पर 16-बाइट प्रेषक प्रतिभागी उपसर्ग
आवाज़ VoiceClientControl VoiceServerEvent ऑडियो, 16-बाइट प्रेषक उपसर्ग प्राप्त पर
बात करना कोई ग्राहक आदेश नहीं; REST का उपयोग करें ChatServerPush कोई नहीं
पीयर रिले कोई JSON फ़्रेमिंग नहीं कोई JSON फ़्रेमिंग नहीं पेलोड अपरिवर्तित; कोई पहचान उपसर्ग नहीं
गेम अपलोड UploadClientControl UploadServerFrame अंश संग्रहित करें
कंटेनर नियंत्रण ContainerControl सर्वर से कोई सामान्य पावती लिफाफा नहीं गेमप्ले अलग कंटेनर का उपयोग करता है /stream

भविष्य के फ़्रेम प्रकार को प्राप्तकर्ता को क्रैश करने के बजाय आपके क्लाइंट के अज्ञात-फ़्रेम हैंडलर तक पहुंचना चाहिए पाश. JSON आकार सत्यापन खेल के नियमों को मान्य नहीं करता, सदस्यता को अधिकृत नहीं करता, या दर लागू नहीं करता सीमाएं. संदर्भ पृष्ठ भूमिका और आकार/दर प्रतिबंधों को परिभाषित करते हैं।

GUID बाइट क्रम

.NET GUID बाइट हेडर में पहले तीन UUID समूह छोटे-छोटे हैं। उदाहरण के लिए:

UUID:  00112233-4455-6677-8899-aabbccddeeff
Bytes: 33 22 11 00 55 44 77 66 88 99 aa bb cc dd ee ff

16-बाइट उपसर्ग के लिए एक ब्राउज़र डिकोडर:

function guidFromDotNet(bytes) {
  if (bytes.length !== 16) throw new Error('Expected a 16-byte GUID');
  const hex = i => bytes[i].toString(16).padStart(2, '0');
  return `${hex(3)}${hex(2)}${hex(1)}${hex(0)}-${hex(5)}${hex(4)}-${hex(7)}${hex(6)}-` +
    `${hex(8)}${hex(9)}-${hex(10)}${hex(11)}${hex(12)}${hex(13)}${hex(14)}${hex(15)}`;
}

रीयलटाइम उपसर्ग पहचानते हैं प्रतिभागियों, जबकि ध्वनि उपसर्ग पहचान करते हैं उपयोगकर्ताओं. एक कंटेनर स्ट्रीम में एक-बाइट प्रकार होता है जिसके बाद सत्र/उपयोगकर्ता यूयूआईडी होता है, इसलिए इसका JSON बाइट से शुरू होता है 33. द रिले कोई उपसर्ग नहीं जोड़ता है। प्रत्येक सॉकेट को एक ही बाइनरी लेआउट के रूप में पढ़ने से पेलोड और पहचान दूषित हो जाती है।

देखना क्रेडेंशियल और पहचानकर्ता, सत्र जीवनचक्र, और वेबसॉकेट समस्या निवारण.
