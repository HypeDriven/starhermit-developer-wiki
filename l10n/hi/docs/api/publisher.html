प्रकाशक

प्रकाशक सतह: प्रकाशक संगठनों और सदस्यों को प्रबंधित करें, सॉफ़्टवेयर शीर्षक और बिल्ड बनाएं और अपलोड करें, और अपने शीर्षकों के लिए उपलब्धियों, पात्रताओं और लीडरबोर्ड परिभाषाओं को प्रबंधित करें।

कैटलॉग शीर्षक के बजाय गेम प्रकाशित करना? आपको इसकी कोई आवश्यकता नहीं है. ए के मालिक एक स्क्रिप्ट या कंटेनर बैकएंड वाला गेम इसका प्रकाशक है और इसके लीडरबोर्ड का प्रबंधन करता है उपलब्धियों के अंतर्गत /api/v1/me/github-games/{id}/… - देखना ट्यूटोरियल: आपके खेल के लिए लीडरबोर्ड और उपलब्धियाँ.

आधार यूआरएल: https://api.starhermit.com. सभी मार्गों के लिए JWT और सूचीबद्ध अनुमति दावों की आवश्यकता होती है। भूमिकाएँ: PublisherMember, PublisherOwner. अनुमति के दावे भूमिकाओं के माध्यम से सौंपे जाते हैं; ढाले गए टोकन अनुमति के दावों को दर्शाते हैं।

प्रकाशक और सदस्य

मार्ग उपसर्ग: api/v1/publisher.

तरीका पथ प्रमाणीकरण विवरण
डाक /api/v1/publisher जेडब्ल्यूटी (Permission-publisher.content.manage) एक प्रकाशक बनाएँ; निर्माता भूमिका के साथ सदस्य बन जाता है "Owner" → 201
पाना /api/v1/publisher जेडब्ल्यूटी (Permission-publisher.content.manage) प्रकाशकों की सूची → Publisher[]
डाक /api/v1/publisher/{publisherId}/members जेडब्ल्यूटी (Permission-publisher.members.manage) + भूमिका Owner एक सदस्य जोड़ें → 204
मिटाना /api/v1/publisher/{publisherId}/members/{memberUserId} जेडब्ल्यूटी (Permission-publisher.members.manage) + भूमिका Owner किसी सदस्य को हटाएँ → 204 (मालिक को हटाया नहीं जा सकता)
पाना /api/v1/publisher/{publisherId}/members/{memberUserId} जेडब्ल्यूटी (Permission-publisher.members.manage) + उस प्रकाशक की सदस्यता एक सदस्य प्राप्त करें → PublisherMember

सदस्यता कौन बदल सकता है

अनुमति का दावा कहता है कि आप प्रकाशक सदस्यों को कहीं प्रबंधित कर सकते हैं; इसमें यह नहीं कहा गया है कौन प्रकाशक. इसलिए दोनों चेक लागू होते हैं:

  • सदस्यों को जोड़ना और हटाना है Owner-केवल। सदस्यता सामग्री-प्रबंधन का अधिकार रखती है प्रकाशक के प्रत्येक शीर्षक, इसलिए एक सादा सदस्य जो सदस्यों को जोड़ सकता है, वह अनुदान दे सकता है किसी को अधिकार. एक गैर मालिक को मिलता है 401.
  • किसी सदस्यता को पढ़ने के लिए उस प्रकाशक से संबंधित होना आवश्यक है। इसके बाहर कॉल करने वाले को भी यही मिलता है 404 एक उपयोगकर्ता के रूप में जो सदस्य नहीं है, इसलिए समापन बिंदु उन प्रकाशकों के बारे में कुछ भी नहीं बताता है जो आप नहीं हैं का हिस्सा.

एक प्रकाशक बनाएं

POST /api/v1/publisher

{

  "description": "..."
}

{ "userId": "<user id>" }

सॉफ़्टवेयर शीर्षक और निर्माण

तरीका पथ प्रमाणीकरण विवरण
डाक /api/v1/publisher/software जेडब्ल्यूटी (Permission-publisher.content.manage) सॉफ़्टवेयर शीर्षक बनाएं/अपडेट करें (बॉडी = शीर्षक मेटाडेटा; शीर्षक के वास्तविक प्रकाशक में सदस्यता लागू)
डाक /api/v1/publisher/software/upload जेडब्ल्यूटी (Permission-publisher.content.manage + Permission-publisher.binary.publish) किसी शीर्षक के लिए अपलोड URL प्राप्त करें → UploadUrlInfo[]
डाक /api/v1/publisher/software/build/finalize जेडब्ल्यूटी (Permission-publisher.content.manage + Permission-publisher.binary.publish) अपलोड की गई संपत्तियों से एक निर्माण को अंतिम रूप दें → 204
पाना /api/v1/publisher/analytics/downloads?publisherId= जेडब्ल्यूटी (Permission-publisher.content.manage) प्रति शीर्षक डाउनलोड संख्या
पाना /api/v1/publisher/analytics/launches?publisherId= जेडब्ल्यूटी (Permission-publisher.content.manage) प्रति शीर्षक लॉन्च संख्या

किसी बिल्ड को प्रकाशित करने के लिए बाइनरी-प्रकाशन अनुदान की आवश्यकता होती है

दो बिल्ड एंडपॉइंट की आवश्यकता है publisher.binary.publish के शीर्ष पर publisher.content.manage और शीर्षक के प्रकाशक की सदस्यता। इसके बिना दोनों उत्तर देते हैं 403, जबकि इस पृष्ठ पर हर दूसरा समापन बिंदु काम करता रहता है - आप शीर्षक बना और संपादित कर सकते हैं, परिभाषित कर सकते हैं उपलब्धियाँ और लीडरबोर्ड, और अनुदान पात्रताएँ; आप किसी निष्पादन योग्य को शिप नहीं कर सकते.

कारण यह है कि एक निर्माण क्या है. किसी बिल्ड की संपत्तियाँ डेस्कटॉप क्लाइंट द्वारा डाउनलोड की जाती हैं और उस पर चलती हैं खिलाड़ी की मशीन, खिलाड़ी के विशेषाधिकारों के साथ, किसी भी सैंडबॉक्स स्टारहर्मिट नियंत्रण के बाहर - एक के विपरीत ब्राउज़र गेम, जो ब्राउज़र में चलता है। इसलिए किसी को प्रकाशित करने का अधिकार प्रति खाते द्वारा दिया जाता है स्टारहर्मिट प्रशासक (द BinaryPublisher भूमिका), प्रकाशक बनाकर हासिल नहीं की गई। नहीं अन्य भूमिका इसे निभाती है। अपलोड प्रवाह बनाने से पहले अनुदान के लिए व्यवस्थापक से पूछें ये समापन बिंदु; किसी प्रकाशक का खाता निलंबित होने पर इसे भी हटा दिया जाता है।

ब्राउज़र गेम्स को इसकी कोई आवश्यकता नहीं है: /api/v1/me/github-games सबमिशन, फ़ोल्डर अपलोड और बंडल किसी भी साइन-इन किए गए खाते के लिए स्व-सेवा को बढ़ावा देता है।

कैटलॉग शीर्षक बनाएं या अपडेट करें

POST /api/v1/publisher/software स्वीकार id (नए शीर्षक के लिए छोड़ें), publisherId, name, description, category, platform, releaseStatus, tags, और priceCents:

{
  "publisherId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "name": "Orbit League",
  "description": "A space racing game.",
  "category": "game",
  "platform": "windows",
  "releaseStatus": "released",
  "tags": ["racing"],
  "priceCents": 0
}

सफलता है 201 शीर्षक के साथ. केवल शीर्षक मेटाडेटा स्वीकार किया जाता है; प्रकाशक सदस्यता न भेजें या यहां संपत्ति वस्तुएं। एक प्रकाशक रिटर्न बनाना 201 प्रकाशक वस्तु के बिना; सूची GET /api/v1/publisher इसकी आईडी प्राप्त करने के लिए.

अपलोड यूआरएल प्राप्त करें

POST /api/v1/publisher/software/upload

{ "titleId": "<title id>" }

प्रतिक्रिया - UploadUrlInfo[]:

[
  {
    "type": "executable",
    "uploadUrl": "...",
    "fieldKey": "..."
  }
]

type में से एक है "executable", "data", "metadata".

किसी निर्माण को अंतिम रूप दें

POST /api/v1/publisher/software/build/finalize → 204

{
  "titleId": "<title id>",
  "buildId": "<optional build id>",
  "version": "1.0.0",
  "releaseNotes": "...",
  "assets": [
    { "type": "executable", "checksum": "...", "fieldKey": "..." }
  ]
}

कैटलॉग बिल्ड वर्कफ़्लो वर्तमान में एक पूर्वावलोकन है और उत्पादन बाइनरी डिलीवरी प्रदान नहीं करता है या सामग्री सत्यापन या मैलवेयर स्कैनिंग की गारंटी। किसी स्वीकृत निर्माण या संपत्ति का इलाज न करें स्थिति प्रमाण के रूप में कि निष्पादन योग्य सुरक्षित है। देखना सुविधा उपलब्धता. होस्ट किया गया गेम प्रकाशन इसका उपयोग करता है गेम अपलोड एपीआई.

एनालिटिक्स

दोनों समापन बिंदु गिनने के लिए एक JSON ऑब्जेक्ट मैपिंग शीर्षक आईडी लौटाते हैं:

{ "<titleId>": 42 }

उपलब्धियों

मार्ग api/v1/publisher; सभी उपलब्धि-प्रबंधन मार्गों की आवश्यकता है Permission-publisher.content.manage.

ये समापनबिंदु प्रबंधन करते हैं कैटलॉग-शीर्षक केवल उपलब्धियाँ. उन्हें कॉल करने वाले का होना भी आवश्यक है प्रकाशक का सदस्य जिसके पास शीर्षक है, और वे उन उपलब्धियों के लिए विफल बंद कर दिया गया है जो संबंधित हैं एक आधिकारिक खेल - वे गेम की स्क्रिप्ट या कंटेनर बैकएंड द्वारा घोषित किए गए हैं और नहीं हैं प्रकाशक-प्रबंधित (देखें) उपलब्धियों, गेम स्क्रिप्ट, और कंटेनर गेम सर्वर).

तरीका पथ प्रमाणीकरण विवरण
डाक /api/v1/publisher/titles/{titleId}/achievements जेडब्ल्यूटी एक उपलब्धि बनाएं → AchievementDto
पाना /api/v1/publisher/titles/{titleId}/achievements जेडब्ल्यूटी शीर्षक की उपलब्धियों की सूची बनाएं → AchievementDto[]
पाना /api/v1/publisher/achievements/{id} जेडब्ल्यूटी एक उपलब्धि प्राप्त करें → AchievementDto
रखना /api/v1/publisher/achievements/{id} जेडब्ल्यूटी अद्यतन करें (सभी फ़ील्ड शून्य करने योग्य) → AchievementDto
मिटाना /api/v1/publisher/achievements/{id} जेडब्ल्यूटी हटाएँ → 204

एक उपलब्धि बनाएं

POST /api/v1/publisher/titles/{titleId}/achievements

{
  "key": "first_win",

icon, visibility, और criteria वैकल्पिक हैं. पर PUT, सभी फ़ील्ड अशक्त हैं। देखना achievements.md खिलाड़ी-सामना वाली सतह के लिए.

पात्रता

मार्ग api/v1/publisher/entitlements; दोनों मार्गों की आवश्यकता है Permission-publisher.content.manage.

तरीका पथ प्रमाणीकरण विवरण
डाक /api/v1/publisher/entitlements/grant जेडब्ल्यूटी किसी उपयोगकर्ता को एक शीर्षक प्रदान करें → 204
डाक /api/v1/publisher/entitlements/revoke जेडब्ल्यूटी किसी उपयोगकर्ता से शीर्षक निरस्त करें → 204

दोनों के लिए शरीर:

{
  "userId": "<user id>",
  "softwareTitleId": "<title id>"
}

लीडरबोर्ड

मार्ग api/v1/publisher/leaderboards; सभी मार्गों की आवश्यकता है Permission-publisher.content.manage.

तरीका पथ प्रमाणीकरण विवरण
डाक /api/v1/publisher/leaderboards/ जेडब्ल्यूटी लीडरबोर्ड परिभाषा बनाएं → LeaderboardDefinitionDto
पाना /api/v1/publisher/leaderboards/{id} जेडब्ल्यूटी एक परिभाषा प्राप्त करें → LeaderboardDefinitionDto
रखना /api/v1/publisher/leaderboards/{id} जेडब्ल्यूटी अद्यतन करें (सभी फ़ील्ड शून्य करने योग्य) → LeaderboardDefinitionDto
मिटाना /api/v1/publisher/leaderboards/{id} जेडब्ल्यूटी हटाएँ → 204

एक लीडरबोर्ड बनाएं

POST /api/v1/publisher/leaderboards/

{
  "name": "Global Elo",
  "scoreType": "...",
  "sortDirection": "...",
  "resetSchedule": "...",
  "minScore": 0,
  "maxScore": 4000,
  "scope": "...",
  "region": "...",
  "isActive": true,
  "softwareTitleId": "<optional title id>"
}

resetSchedule, minScore, maxScore, region, और softwareTitleId वैकल्पिक हैं. पर PUT, सभी फ़ील्ड अशक्त हैं। resetSchedule है daily, weekly, monthly या never; और कुछ भी एक है 400 - देखना शेड्यूल रीसेट करें. देखना leaderboards.md खिलाड़ी-सामना वाली सतह के लिए.

एक बिल्ड प्रकाशित करें: प्रवाह

  1. बाइनरी-प्रकाशन अनुदान को दबाए रखें: चरण 3 और 5 की आवश्यकता है publisher.binary.publish, जो ए स्टारहर्मिट प्रशासक प्रति खाता अनुदान देता है। देखना किसी बिल्ड को प्रकाशित करने के लिए बाइनरी-प्रकाशन अनुदान की आवश्यकता होती है.
  2. एक प्रकाशक बनाएं: POST /api/v1/publisher साथ { name, description }.
  3. शीर्षक बनाएँ: POST /api/v1/publisher/software नीचे शीर्षक मेटाडेटा के साथ।
  4. अपलोड यूआरएल प्राप्त करें: POST /api/v1/publisher/software/upload साथ { titleId }.
  5. फाइलें अपलोड करें लौटे को uploadUrls.
  6. निर्माण को अंतिम रूप दें: POST /api/v1/publisher/software/build/finalize अपलोड की गई संपत्तियों के साथ' { type, checksum, fieldKey } प्रविष्टियाँ।
  7. वितरण उपलब्धता की जाँच करें: वर्तमान कैटलॉग पूर्वावलोकन सत्यापित उत्पादन डाउनलोड या मैलवेयर स्कैनिंग की गारंटी नहीं देता है; देखना उपलब्धता.
  8. उपयोगकर्ता दावा करते हैं और डाउनलोड करते हैं कैटलॉग के माध्यम से शीर्षक - देखें catalog.md.

त्रुटि निकाय अलग-अलग होते हैं; देखना एपीआई कन्वेंशन.

यह भी देखें
