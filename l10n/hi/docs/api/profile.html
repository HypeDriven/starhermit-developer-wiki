प्रोफ़ाइल

प्रोफ़ाइल एपीआई प्रमाणित उपयोगकर्ता के स्वयं के खाते को कवर करता है (/api/v1/me/...), अन्य उपयोगकर्ताओं के सार्वजनिक लुकअप, सार्वजनिक कुंजी, लिंक की गई पहचान, गोपनीयता सेटिंग्स, पात्रताएं, और उपस्थिति दिल की धड़कन। खाता मार्गों के लिए प्राधिकरण की आवश्यकता होती है; वर्तमान शर्तें दस्तावेज़ सार्वजनिक है.

त्रुटि निकाय अलग-अलग होते हैं; देखना एपीआई कन्वेंशन.

अंतिमबिंदुओं

तरीका पथ प्रमाणीकरण विवरण
पाना /api/v1/me जेडब्ल्यूटी (Permission-user.profile.read) अपनी स्वयं की प्रोफ़ाइल प्राप्त करें
पैबंद /api/v1/me जेडब्ल्यूटी (Permission-user.profile.update) उपयोगकर्ता नाम, ईमेल, मेटाडेटा या उपनाम अपडेट करें
पाना /api/v1/terms गुमनाम वर्तमान StarHermit शर्तें और उनके हैश पढ़ें
डाक /api/v1/me/terms/accept खाता JWT या प्लेयर लॉन्च टोकन वर्तमान StarHermit शर्तों को स्वीकार करें
रखना /api/v1/me/avatar जेडब्ल्यूटी (Permission-user.profile.update) अपना अवतार अपलोड करें
पाना /api/v1/me/avatar जेडब्ल्यूटी (Permission-user.profile.read) अपना अवतार प्राप्त करें
पाना /api/v1/users/{id}/avatar जेडब्ल्यूटी किसी भी उपयोगकर्ता का अवतार प्राप्त करें
पाना /api/v1/users/{id}/profile जेडब्ल्यूटी किसी भी उपयोगकर्ता की सार्वजनिक प्रोफ़ाइल प्राप्त करें
पाना /api/v1/me/public-keys जेडब्ल्यूटी (Permission-user.profile.read) अपनी सार्वजनिक कुंजियाँ सूचीबद्ध करें
डाक /api/v1/me/public-keys Oप्रमाणीकृत जेडब्ल्यूटी (Permission-user.profile.update) तुरंत एक सार्वजनिक कुंजी जोड़ें
मिटाना /api/v1/me/public-keys/{keyId} Oप्रमाणीकृत जेडब्ल्यूटी (Permission-user.profile.update) एक कुंजी और उसके सत्र निरस्त करें
मिटाना /api/v1/me/public-keys/all Oप्रमाणीकृत जेडब्ल्यूटी (Permission-user.profile.update) प्रत्येक सक्रिय कुंजी और उसके सत्र को निरस्त करें
मिटाना /api/v1/me/public-keys/current सार्वजनिक-कुंजी सत्र (Permission-user.profile.update) इस सत्र में जिस कुंजी से साइन इन किया गया था, उसे और इसके सत्रों को रद्द करें। इसमें कोई कुंजी नहीं है, इसलिए यह किसी भाई-बहन तक नहीं पहुंच सकता; बिना कुंजी वाला एक सत्र प्राप्त होता है 409 no_public_key_session
पाना /api/v1/me/identities जेडब्ल्यूटी (Permission-user.profile.read) अपनी जुड़ी हुई पहचानों को सूचीबद्ध करें
डाक /api/v1/me/identities जेडब्ल्यूटी (Permission-user.profile.update) एक पहचान लिंक करें (केवल गैर-OAuth प्रदाता)
मिटाना /api/v1/me/identities/{identityId} जेडब्ल्यूटी (Permission-user.profile.update) किसी पहचान को अनलिंक करें
पाना /api/v1/me/privacy जेडब्ल्यूटी (Permission-user.profile.read) अपनी गोपनीयता सेटिंग प्राप्त करें
रखना /api/v1/me/privacy जेडब्ल्यूटी (Permission-user.profile.update) अपनी गोपनीयता सेटिंग बदलें
पाना /api/v1/me/entitlements जेडब्ल्यूटी (Permission-user.profile.read) अपने सॉफ़्टवेयर अधिकारों की सूची बनाएं
डाक /api/v1/me/heartbeat जेडब्ल्यूटी दिल की धड़कन की उपस्थिति (गला घोंट दिया गया)। LastSeenAt लिखना)

PATCH /api/v1/me

सभी फ़ील्ड वैकल्पिक. प्रतिबंध: username 1-32 अक्षर; nickname ≤64 अक्षर (कई) खातों में कोई नहीं है); metadata ≤4096 अक्षर. उपयोगकर्ता नाम और उपनाम एक साझा करते हैं केस-असंवेदनशील नामस्थान: 409 जब कोई अन्य खाता अपने उपयोगकर्ता नाम या उपनाम के रूप में नाम का उपयोग करता है, मामले की अनदेखी उपनाम एनएफकेसी-सामान्यीकृत हैं, और नियंत्रण या अदृश्य वर्ण हैं 400. बदलना email इसके अतिरिक्त एक की आवश्यकता है OAuth-प्रमाणित सत्र क्योंकि खाता ईमेल क्रेडेंशियल लिंक को मंजूरी दे सकता है; एक सार्वजनिक कुंजी या ईमेल-सत्यापन सत्र मिलता है 403 उस फ़ील्ड के लिए लेकिन फिर भी अन्य को अपडेट किया जा सकता है। 204 पर लौटता है सफलता, 409 संघर्ष पर (उपयोगकर्ता नाम या उपनाम पहले ही लिया जा चुका है)।

{
  "username": "newname",
  "email": "new@example.com",
  "metadata": "{}",
  "nickname": "New Nick"
}

शर्तें स्वीकृति

संरक्षित REST एंडपॉइंट का उपयोग करने या WebSockets खोलने से पहले, खाते को स्वीकार करना होगा वर्तमान स्टारहर्मिट शर्तें. यह खाता टोकन और खिलाड़ी लॉन्च टोकन पर लागू होता है, जिसमें खाते भी शामिल हैं पुराने संशोधन को स्वीकार कर लिया। यह अनाम संसाधनों/साइन-इन या कंटेनर सर्वर पर लागू नहीं होता है स्वयं का परिनियोजन टोकन. GET /api/v1/me और स्वीकृति समापन बिंदु उनके सामान्य के साथ उपलब्ध रहता है स्वीकृति लंबित होने पर खाता अनुमतियाँ।

GET /api/v1/me शामिल currentTermsHash और termsAcceptanceRequired. संग्रहित termsAcceptedHash और termsAcceptedAt प्रथम स्वीकृति से पहले शून्य हैं। में दिखाया गया हैश उपरोक्त प्रोफ़ाइल उदाहरण संक्षिप्त है; हमेशा एपीआई द्वारा लौटाए गए पूर्ण हैश का उपयोग करें।

GET /api/v1/terms

गुमनाम; प्लेयर लॉन्च टोकन के साथ भी पढ़ने योग्य। रिटर्न 200 साथ Cache-Control: no-store:

{ "hash": "<current-64-character-lowercase-sha256>", "text": "<complete terms text>" }

प्रदान करना text सादे पाठ के रूप में. hash सटीक UTF-8 दस्तावेज़ बाइट्स का SHA-256 है; लौटाए गए का उपयोग करें हैशिंग के बजाय मान को पुन: स्वरूपित प्रदर्शन पाठ।

POST /api/v1/me/terms/accept

उपयोगकर्ता द्वारा प्रदर्शित संशोधन को पढ़ने और स्पष्ट रूप से स्वीकार करने के बाद, उसका हैश भेजें:

POST /api/v1/me/terms/accept
Authorization: Bearer <account-access-token>
Content-Type: application/json

{ "hash": "<hash-returned-with-the-displayed-text>" }

रिटर्न 200 साथ { "termsAcceptedHash", "termsAcceptedAt" }. OAuth और सार्वजनिक-कुंजी खाता सत्र और प्लेयर गेम-स्कोप्ड लॉन्च टोकन स्वीकार कर सकते हैं. एक कंटेनर सर्वर टोकन किसी खिलाड़ी के लिए कार्य नहीं कर सकता। स्वीकृति खाते में संग्रहीत की जाती है और उस पर प्रभावी होती है उसी स्थिर-मान्य टोकन के साथ अगला अनुरोध; टोकन को ताज़ा करना अनावश्यक है।

एक गुम/रिक्त हैश या 64 वर्णों से अधिक लंबा हैश वापस आ जाता है 400. एक हैश जो बिलकुल नहीं है वर्तमान पुनरीक्षण रिटर्न का मिलान करें 409:

{
  "error": "terms_version_mismatch",
  "termsHash": "<current-hash>",
  "termsUrl": "/api/v1/terms"
}

नया दस्तावेज़ लाएँ और प्रदर्शित करें और पुनः स्वीकृति के लिए पूछें; किसी प्रतिस्थापन को चुपचाप स्वीकार न करें पुनरीक्षण. लंबित स्वीकृति रिटर्न के साथ अन्य संरक्षित अनुरोध 403:

{
  "error": "terms_acceptance_required",
  "message": "Accept the latest terms of service before using the API.",
  "termsHash": "<current-hash>",
  "termsUrl": "/api/v1/terms",
  "acceptUrl": "/api/v1/me/terms/accept"
}

एक होस्ट किया गया गेम शर्तों को प्रदर्शित कर सकता है और अपने प्लेयर लॉन्च टोकन के साथ प्रदर्शित हैश सबमिट कर सकता है जब खिलाड़ी एक्सेप्ट दबाता है, तो पुनः प्रयास करें। यह खिलाड़ी को उनके खाता यूआई पर भी भेज सकता है। बार-बार साइन-इन या टोकन रिफ्रेश लंबित स्वीकृति को ठीक नहीं करता है। HTTP के साथ WebSocket अपग्रेड अस्वीकार कर दिया जाता है 403 खोलने से पहले; ब्राउज़र प्रतिक्रिया निकाय को छुपा सकते हैं, इसलिए कनेक्ट करने से पहले REST के माध्यम से स्वीकृति को संभाल लें।

किसी खाते या गेम क्लाइंट के लिए उदाहरण (कॉल करें)। acceptDisplayedTerms केवल उपयोगकर्ता की स्वीकृति कार्रवाई से):

const api = 'https://api.starhermit.com';
async function loadTerms() {
  const response = await fetch(`${api}/api/v1/terms`);
  if (!response.ok) throw new Error(`Terms fetch failed: ${response.status}`);
  return response.json(); // Display text, retain this document's hash.
}
async function acceptDisplayedTerms(accountToken, displayedTerms) {
  const response = await fetch(`${api}/api/v1/me/terms/accept`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${accountToken}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ hash: displayedTerms.hash })
  });
  if (response.status === 409) {
    throw new Error('Terms changed. Reload and display them for a new acceptance.');
  }
  if (!response.ok) throw new Error(`Acceptance failed: ${response.status}`);
  return response.json();
}

सार्वजनिक कुंजियाँ

एक पंजीकृत कुंजी एक एपीआई क्रेडेंशियल है: इसका धारक इसे पूरा कर सकता है सार्वजनिक-कुंजी चुनौती प्रवाह और एक सामान्य एक्सेस/रीफ्रेश-टोकन प्राप्त करें जोड़ी. यह एक अलग से लेबल की गई कुंजी को डेस्कटॉप क्लाइंट या परिनियोजन पाइपलाइन के लिए उपयुक्त बनाता है।

कुंजियाँ जोड़ने या अन्य कुंजियाँ रद्द करने के लिए OAuth-प्रमाणीकृत सत्र की आवश्यकता होती है। एक सार्वजनिक कुंजी सत्र केवल अपनी ही कुंजी को रद्द कर सकता है DELETE /api/v1/me/public-keys/current. यह नहीं हो सकता प्रतिस्थापनों को नामांकित करें या अन्य उपकरणों को रद्द करें। सूची किसी भी पूर्ण खाता सत्र के लिए उपलब्ध रहती है; गेम लॉन्च और सर्वर टोकन खाता कुंजियाँ प्रबंधित नहीं कर सकते।

GET /api/v1/me/public-keys

सूची में ऑडिट ट्रेल के रूप में निरस्त पंक्तियाँ शामिल हैं:

[
  {
    "id": "9b2f5c74-1d2e-4a6b-8c0d-1e2f3a4b5c6d",
    "keyType": "Ed25519",
    "keyData": "<base64-raw-32-byte-public-key>",
    "label": "orbit-league-production",
    "fingerprint": "4d9f3c...",
    "createdAt": "2026-07-01T12:00:00Z",
    "lastUsedAt": "2026-07-30T09:00:00Z",
    "isRevoked": false,
    "revokedAt": null,
    "metadata": null
  }
]

POST /api/v1/me/public-keys

OAuth-प्रमाणीकृत सत्र की आवश्यकता है और तुरंत कुंजी संलग्न करें; अनाम के विपरीत पंजीकरण, किसी ईमेल राउंड ट्रिप की आवश्यकता नहीं है।

{
  "keyType": "Ed25519",
  "keyData": "<base64-raw-32-byte-public-key>",
  "label": "orbit-league-production"
}

label वैकल्पिक है (अधिकतम 128 अक्षर)। स्वीकृत कुंजी प्रकार हैं Ed25519, ECDSA-P256, और RSA-PSS; सामग्री मानक बेस64 होनी चाहिए: Ed25519 के लिए एक कच्ची 32-बाइट सार्वजनिक कुंजी, एक एन्कोडेड P-256 ईसीडीएसए के लिए वक्र बिंदु, या आरएसए के लिए एक सार्वजनिक एसपीकेआई। RSA कुंजियाँ 2048-8192 बिट होनी चाहिए। मंच वैध सामग्री को प्रामाणिक बनाता है और किसी खाते को डिफ़ॉल्ट रूप से 20 सक्रिय कुंजियों तक सीमित करता है। fingerprint है कैनोनिकल का लोअरकेस SHA-256 हेक्स डाइजेस्ट keyType:keyData डोरी।

रिटर्न 201 निर्मित कुंजी के साथ. अमान्य सामग्री रिटर्न 400; पहले से सक्रिय कुंजी या पूर्ण कुंजी कुंजी सूची वापस आती है 409 (बाद वाला शामिल है limit). सक्रिय कुंजी सामग्री प्लेटफ़ॉर्म-व्यापी अद्वितीय है।

DELETE /api/v1/me/public-keys/{keyId}

OAuth-प्रमाणीकृत सत्र की आवश्यकता है. निरसन निरर्थक है और नवीनीकृत सत्र समाप्त हो जाता है कुंजी द्वारा; इसे नाम देने वाले एक्सेस टोकन को उनके अगले अनुरोध पर अस्वीकार कर दिया जाता है। रिटर्न:

{ "revoked": [{ "id": "...", "isRevoked": true }], "sessionsEnded": 1 }

इस खाते पर एक अज्ञात कुंजी वापस आती है 404.

DELETE /api/v1/me/public-keys/all

समझौता-प्रतिक्रिया ऑपरेशन: प्रत्येक सक्रिय कुंजी को रद्द करें और उनके द्वारा प्रमाणित सभी सत्रों को समाप्त करें। इसमें एक स्पष्टता है /all पथ ताकि गलती से खाली हुई कुंजी आईडी सामूहिक निरस्तीकरण न बन सके। वैसा ही लौटाता है { revoked, sessionsEnded } आकार।

DELETE /api/v1/me/public-keys/current

सार्वजनिक कुंजी से प्रमाणित एक पूर्ण खाता सत्र उस सत्र के लिए उपयोग की गई कुंजी को रद्द कर सकता है, बिना किसी कुंजी आईडी का नाम बताए। इसके लिए इसका प्रयोग करें इस उपकरण को भूल जाओ. यह वैसा ही लौटाता है { revoked, sessionsEnded } उस कुंजी का उपयोग करके सत्रों को आकार देता है और अमान्य करता है। संग्रहित टोकन त्यागें और सफलता के बाद स्थानीय निजी कुंजी। कोई सार्वजनिक कुंजी वाला सत्र रिटर्न नहीं देता 409 साथ code: "no_public_key_session"; गेम लॉन्च टोकन अस्वीकार कर दिए गए हैं.

संपूर्ण मशीन-परिनियोजन उदाहरण के लिए, देखें OAuth-नामांकित सार्वजनिक कुंजी के साथ CI/CD से बिल्ड अपलोड करें.

प्रदाता प्लेटफ़ॉर्म का नाम OAuth के नाम से जानता है (google, github, discord, twitch, gitlab, linkedin, bitbucket, प्लस आरक्षित नाम microsoft, facebook, twitter, x, apple, steam) हैं अस्वीकार कर दिया यहां वह प्रदाता कॉन्फ़िगर किया गया है या नहीं - वे पहचान हैं केवल वास्तविक साइन-इन के माध्यम से लिंक किया जा सकता है। गैर-आरक्षित नाम का प्रयोग करें (epic, gog, एक कस्टम स्टोरफ्रंट आईडी)। देखना प्रमाणीकरण.

DELETE /api/v1/me/identities/{identityId}

OAuth-प्रबंधित पहचान को हटाने के लिए OAuth-प्रमाणीकृत सत्र की आवश्यकता होती है, इसलिए सार्वजनिक कुंजी चोरी हो जाती है खाते में स्वामी का मार्ग वापस नहीं हटाया जा सकता. रिटर्न 204.

{
  "onlineStatus": 1,
  "currentlyPlaying": 1,
  "recentLaunchActivity": 0,
  "hoursPlayed": 0,
  "recentDownloads": 0,
  "achievements": 2,
  "friendDiscoverability": 1,
  "profileVisibility": 2
}

प्रत्येक क्षेत्र एक है PrivacyLevel enum: 0 = निजी, 1 = केवल मित्र, 2 = सार्वजनिक.

गेम-स्कोप्ड लॉन्च टोकन

इस पृष्ठ पर अंतिम बिंदुओं में से, गेम-स्कोप्ड लॉन्च टोकन केवल कॉल कर सकता है:

  • GET /api/v1/users/{id}/avatar
  • GET /api/v1/users/{id}/profile
  • GET /api/v1/me/friends (देखना दोस्त)
  • GET /api/v1/terms
  • POST /api/v1/me/terms/accept
  • POST /api/v1/me/heartbeat

वर्णित गेम-स्कोप फेंसिंग के तहत बाकी सब कुछ 403 लौटाता है प्रमाणीकरण.

प्रदर्शन-नाम सम्मेलन

गेम यूआई आमतौर पर प्रदर्शित होते हैं उपनाम विरोधियों को प्रस्तुत करते समय उपयोगकर्ता नाम के बजाय, कुछ इस तरह वापस आना "Player " + id.slice(0,8) जब कोई उपनाम सेट न हो. शतरंज संदर्भ कार्यान्वयन इस सम्मेलन का अनुसरण करता है; अन्य गेम क्लाइंट को भी ऐसा ही करना चाहिए।
