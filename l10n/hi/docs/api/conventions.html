एपीआई कन्वेंशन

बाकी उपयोग करता है https://api.starhermit.com/api/v1/...; सॉकेट का उपयोग wss://api.starhermit.com/ws/v1/.... होस्ट किए गए गेम कॉल कर सकते हैं /api/v1/... और /ws/v1/... अपने स्वयं के मूल पर. मूल ग्राहक इसका उपयोग करते हैं सार्वजनिक एपीआई मूल. किसी अन्य मूल पर एक विकास पृष्ठ को खेल पर एक अनुमत CORS मूल की आवश्यकता होती है मेज़बान; अकेले एसडीके आधार यूआरएल सेट करने से उस मूल को अधिकृत नहीं किया जा सकता है।

अनुरोध और प्रतिक्रियाएँ

JSON के साथ भेजें Content-Type: application/json, कच्चे gzip बंडल अपलोड को छोड़कर। JSON सदस्य नाम कैमलकेस हैं। REST में वाहक क्रेडेंशियल भेजें Authorization शीर्षक.

प्रतिक्रिया इसे कैसे पढ़ें
200 / 201 JSON प्रलेखित वस्तु या सरणी को पार्स करें; अतिरिक्त फ़ील्ड सहन करें
204 बिना शरीर के सफलता; फ़ोन मत करो response.json()
302 ब्राउज़र साइन-इन/पुष्टि पुनर्निर्देशन; OAuth पेज लाने के बजाय नेविगेट करें
304 सशर्त पढ़ें अपरिवर्तित; आपके पास पहले से मौजूद डेटा को बनाए रखें
छवि, अनुलग्नक, क्लाउड सेव प्रतिक्रिया सामग्री प्रकार और समापन बिंदु अनुबंध का उपयोग करके बाइट्स पढ़ें
गलती पहले स्थिति पढ़ें, फिर रक्षात्मक रूप से शरीर का विश्लेषण करें

सामान्य त्रुटि प्रपत्र है { "error": "...", "code": "..." }, वैकल्पिक फ़ील्ड के आधार पर समापन बिंदु. error प्रायः मानव-पठनीय है; code जहां प्रदान किया गया है वहां एक स्थिर विभेदक है। शर्तें और कुछ अन्य समापन बिंदु एक विवेचक को सीधे अंदर डाल देते हैं error. कुछ समापनबिंदु सादे लौट आते हैं टेक्स्ट, एक खाली बॉडी, या एक सत्यापन समस्या विवरण ऑब्जेक्ट title, status और errors. ग्राहकों को यह नहीं मानना ​​चाहिए कि प्रत्येक असफल प्रतिक्रिया JSON है या उसमें समान फ़ील्ड हैं।

export async function readResponse(response) {
  if (response.status === 204 || response.status === 304) return null;
  const text = await response.text();
  let body;
  try { body = text ? JSON.parse(text) : null; } catch { body = text || null; }
  if (!response.ok) {
    const message = (body && typeof body === 'object' && (body.error || body.message || body.title))
      || (typeof body === 'string' && body) || response.statusText;
    throw Object.assign(new Error(message), {
      status: response.status, code: body?.code, body,
      retryAfter: response.headers.get('Retry-After'),
    });
  }
  return body;
}

समय, आकार और शून्यता

  • createdAt, updatedAt, finishedAt, और समान खाता/संसाधन टाइमस्टैम्प आईएसओ 8601 स्ट्रिंग हैं ऑफसेट के साथ. अनुपस्थित व्यवहार करें या null वैकल्पिक मान अनुपलब्ध हैं।
  • ctx.now, summary.deadline, सत्र-सूची deadline, और /time.serverTime पूर्णांक यूनिक्स हैं मिलीसेकंड. के साथ कनवर्ट करें new Date(value), नहीं Date.parse(value).
  • बाइट्स में सीमा मान बाइट्स हैं, बेस64 वर्ण नहीं। बेस64 JSON अपलोड इससे बड़ा है डिकोड की गई सामग्री। उपलब्ध होने पर समापन बिंदु द्वारा रिपोर्ट की गई प्रभावी सीमा का उपयोग करें।
  • चूक, null, और एक खाली वस्तु सार्वभौमिक रूप से समतुल्य नहीं है। सेटिंग्स PATCH ए हटाता है नामित कुंजी के साथ null; एकल-कुंजी सेटिंग्स PUT भंडार null एक मूल्य के रूप में. संग्रह PUT प्रतिस्थापित करता है पूरा नक्शा. प्रत्येक समापन बिंदु के अद्यतन नियम पढ़ें।
  • एक सेटिंग पैच मर्ज हो जाता है शीर्ष-स्तरीय कुंजियाँ. आपूर्ति किया गया ऑब्जेक्ट मान उस कुंजी के मान को प्रतिस्थापित कर देता है; यह नेस्टेड संपत्तियों को पुनरावर्ती रूप से मर्ज नहीं करता है।

पृष्ठ पर अंक लगाना

पेजिंग एक आधारित है page/pageSize समर्थित हैं. अलग-अलग एपीआई जानबूझकर अलग-अलग हैं प्रतिक्रिया लिफाफे; ऐसे पार्सर का पुन: उपयोग न करें जो एकल गिनती-फ़ील्ड नाम मानता हो।

क्षेत्र संग्रह आकार डिफ़ॉल्ट/अधिकतम पृष्ठ आकार
सॉफ़्टवेयर शीर्षक और निर्माण { items, totalCount, page, pageSize } 20 / 100
चैट संदेश { conversationId, items, totalCount, page, pageSize } 50 / 100
लीडरबोर्ड प्रविष्टियाँ { items, total, page, pageSize } 20 / 100
बाहरी सॉफ्टवेयर { items, total, page, pageSize } 20; एक छोटे सकारात्मक पृष्ठ आकार का अनुरोध करें
रिपोर्ट, कंटेनर क्रैश रिकॉर्ड, मॉडरेशन सूचियाँ { items, total, page, pageSize } 20 / 100
सत्र, मित्र, खेल सूचियाँ, उपलब्धियाँ सरणियों समापन बिंदु-विशिष्ट कैप; कोई सामान्य अगला पृष्ठ कर्सर नहीं
मॉडरेशन निकासी फ़ीड कर्सर आधारित लौटाया गया कर्सर रखें; से उबरना 410 जैसा कि प्रलेखित है

रिस्पॉन्स पेजिंग मेटाडेटा जहां उपलब्ध हो वहां परोसे गए पेज को दर्शाता है। संदर्भ पृष्ठ और मशीन-पठनीय अनुबंध समापन बिंदु-विशिष्ट क्वेरी पैरामीटर का वर्णन करें।

पुनः प्रयास करें और समवर्ती करें

परिस्थिति कार्रवाई
खाता पहुंच टोकन अस्वीकार कर दिया गया 401 एक साझा ताज़ा अनुरोध का उपयोग करके, एक बार ताज़ा करें; यदि मना कर दिया जाए तो साइन इन करें
लॉन्च टोकन की समय सीमा समाप्त हो गई साइन-इन/लॉन्चर के माध्यम से एक नया टोकन प्राप्त करें; समाप्त हो चुके टोकन स्वयं को नवीनीकृत नहीं कर सकते
403 terms_acceptance_required वर्तमान शर्तों को प्रदर्शित करें और स्पष्ट रूप से स्वीकार करें, फिर पुनः प्रयास करें
अन्य 403 दायरा, सदस्यता, अनुमतियाँ, या खाता स्थिति का समाधान करें; एक लूप में ताज़ा न करें
409 डुप्लिकेट/स्थिति/संशोधन विवाद का समाधान करें; संसाधन बदलने से पहले दोबारा पढ़ें
बादल-बचाओ 412 नया संस्करण लोड करें और गेम को मर्ज होने दें या इसे अपनाने दें
429 या अस्थायी 503 सम्मान Retry-After, घबराना जोड़ें, और बाध्य पुनः प्रयास करें
लिखने के दौरान नेटवर्क विफलता परिणाम अज्ञात हो सकता है; कार्रवाई दोहराने से पहले संसाधन स्थिति का निरीक्षण करें

Retry-After सेकंड या HTTP दिनांक हो सकता है। एक निष्क्रिय हेडर का आविष्कार न करें: एपीआई ऐसा नहीं करता है एक सामान्य निष्क्रियता-कुंजी तंत्र का वादा करें। सत्र निर्माण का पुनः प्रयास या आमंत्रण बनाया जा सकता है अन्य संसाधन या पहले के साथ संघर्ष। पढ़ने और स्पष्ट रूप से निष्क्रिय संचालन को प्राथमिकता दें स्वचालित पुनः प्रयास. ताज़ा रोटेशन, पूर्ण अपलोड, शर्तों की सहमति, और टर्मिनल गेम परिणाम प्रत्येक उनके अपने नियम हैं.

तुलना-और-स्वैप लेखन के लिए क्लाउड-सेव ईटैग, रूम का उपयोग करें expectedRevision, या मॉडरेशन संशोधन जहां समर्थन किया गया. एक सफल लेखन आवश्यक रूप से एक पूर्ण कंटेनर परिनियोजन नहीं है; इसकी पुष्टि करें खिलाड़ियों को नए बिल्ड में भेजने से पहले की स्थिति। देखना समस्या निवारण.
