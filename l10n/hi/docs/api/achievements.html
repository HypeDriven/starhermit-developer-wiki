उपलब्धियों

एक उपलब्धि बिल्कुल उसी की है एक मालिक, और मालिक निर्णय लेता है कि इसे अनलॉक करने की अनुमति किसे है:

मालिक द्वारा घोषित किया गया द्वारा अनलॉक किया गया इसके लिए इसका उपयोग करें
एक आधिकारिक खेल game.achievements किसी स्क्रिप्ट में, या achievements एक कंटेनर से /describe — या गेम के मालिक द्वारा के माध्यम से /me/github-games/{id}/achievements केवल गेम का सर्वर रनटाइम — सर्वर-आधिकारिक ए के साथ खेल server= स्क्रिप्ट या container.image= बैकएंड
एक कैटलॉग शीर्षक (SoftwareTitle) एक प्रकाशक, के माध्यम से प्रकाशक एपीआई खिलाड़ी का ग्राहक, के माध्यम से POST /api/v1/me/achievements/unlock (पात्रता आवश्यक) वितरित शीर्षक जिनके ग्राहक ही एकमात्र ऐसी चीज हैं जो जानते हैं कि खिलाड़ी ने कुछ अर्जित किया है

दोनों परस्पर अनन्य हैं और प्लेटफ़ॉर्म विभाजन को लागू करता है:

  • POST /api/v1/me/achievements/unlock गेम-स्कोप वाली उपलब्धियों से इनकार करता है - कोई ग्राहक कभी दावा नहीं कर सकता।
  • प्रकाशक सीआरयूडी एंडपॉइंट्स उन्हें भी मना कर देते हैं। आपके स्वामित्व वाले गेम के लिए आपको किसी प्रकाशक की आवश्यकता नहीं है: जैसे इसके मालिक आप हैं हैं इसका प्रकाशक, और आप इसके माध्यम से इसकी उपलब्धियों का प्रबंधन करते हैं स्वामी समापनबिंदु बजाय।

आधार यूआरएल: https://api.starhermit.com. सभी मार्ग नीचे हैं /api/v1/....

तरीका पथ प्रमाणीकरण विवरण
पाना /api/v1/games/{slug}/achievements ले जानेवाला एक आधिकारिक गेम की उपलब्धियाँ + कॉल करने वाले की अनलॉक स्थिति
पाना /api/v1/me/github-games/{id}/achievements जेडब्ल्यूटी (गेम मालिक) आपके खेल की प्रत्येक उपलब्धि, इसके साथ origin और गिनती अनलॉक करें
डाक /api/v1/me/github-games/{id}/achievements जेडब्ल्यूटी (गेम मालिक) अपने गेम के लिए एक उपलब्धि बनाएं → 201
रखना /api/v1/me/github-games/{id}/achievements/{achievementId} जेडब्ल्यूटी (गेम मालिक) आपके द्वारा बनाए गए को अपडेट करें
मिटाना /api/v1/me/github-games/{id}/achievements/{achievementId} जेडब्ल्यूटी (गेम मालिक) जो आपने बनाया है उसे हटा दें और किसी ने भी अनलॉक नहीं किया है → 204
पाना /api/v1/software/{titleId}/achievements गुमनाम एक कैटलॉग शीर्षक की उपलब्धि परिभाषाएँ
पाना /api/v1/me/achievements?titleId= जेडब्ल्यूटी कॉल करने वाले के अनलॉक (सभी मालिक, या एक शीर्षक)
डाक /api/v1/me/achievements/unlock जेडब्ल्यूटी ग्राहक द्वारा दावा किया गया अनलॉक - केवल कैटलॉग शीर्षक

त्रुटियों को रक्षात्मक रूप से पढ़ें जैसा कि इसमें वर्णित है एपीआई कन्वेंशन. POST /me/achievements/unlock उसे लौटाता है 400 सादे पाठ के रूप में कारण.

सर्वर-आधिकारिक खेल उपलब्धियाँ

यही तंत्र है कोई गेम का उपयोग तब करना चाहिए जब उसके पास स्क्रिप्ट या कंटेनर बैकएंड हो। द सर्वर रनटाइम ही एकमात्र लेखक है। इसे सत्यापित करना होगा कि खिलाड़ी ने प्रत्येक अनलॉक अर्जित किया है; अस्वीकार करना अकेले डायरेक्ट एपीआई सबमिशन संशोधित क्लाइंट द्वारा रिपोर्ट की गई घटनाओं को मान्य नहीं करता है।

1. उन्हें अपनी स्क्रिप्ट में घोषित करें

एक स्थैतिक जोड़ें achievements सरणी को game वस्तु - देखें खेल स्क्रिप्ट - उपलब्धियाँ पूर्ण अनुबंध के लिए:

globalThis.game = {
  achievements: [
    { key: "first-win",  name: "First Win",  description: "Win a match.", points: 10 },
    { key: "flawless",   name: "Flawless",   description: "Win without conceding.",
      points: 50, secret: true, icon: "https://cdn.example/flawless.png" }
  ],
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

घोषणापत्र पढ़ा जाता है जब गेम प्रकाशित या अपडेट किया जाता है इसके भंडार से. परिवर्तन लागू करने के लिए एक अद्यतन प्रकाशित करें।

2. उन्हें किसी भी जीवनचक्र हुक से अनलॉक करें

एक लौटें achievements मानचित्र - उपयोगकर्ता आईडी → कुंजियों की सरणी - से createSession, onPlayerMessage, या onTick:

return {
  ok: true,
  sessionState: state,
  achievements: { [winnerId]: ["first-win", "flawless"] },
  result: { kind: "win", winner: winnerId }
};

अनलॉक हैं निष्क्रिय - खिलाड़ी के पास पहले से मौजूद कुंजी को वापस करना एक नो-ऑप है, इसलिए एक स्क्रिप्ट हो सकती है डुप्लिकेट के बारे में चिंता किए बिना प्रत्येक टिक पर एक उपलब्धि दोबारा दर्ज करें।

3. प्लेयर को गेमप्ले सॉकेट पर सूचित किया जाता है

प्रत्येक नए दिए गए अनलॉक को केवल कमाई करने वाले खिलाड़ी को ही भेजा जाता है ws/v1/games, अपने स्वयं के फ्रेम के रूप में प्रकार (प्लेटफ़ॉर्म सत्य, स्क्रिप्ट-रिले नहीं game संदेश):

{
  "type": "achievement",
  "data": {
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "points": 10,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
}

से अनलॉक दिए गए createSession किसी के पास सॉकेट होने से पहले ही जारी रखा जाता है, इसलिए वे साथ आते हैं कोई फ़्रेम नहीं - उन्हें लोड पर सूची समापन बिंदु से पढ़ें।

कंटेनर बैकएंड

एक कंटेनर समान उपलब्धि फ़ील्ड की घोषणा करता है GET /describe, फिर एक भेजता है achievements इसके नियंत्रण WebSocket पर संदेश। प्लेटफ़ॉर्म एक ही कुंजी लागू करता है, प्रतिभागी, निष्क्रियता, और वितरण नियम। देखना कंटेनर गेम सर्वर.

GET /api/v1/games/{slug}/achievements

कॉल करने वाले की अनलॉक स्थिति के साथ, गेम प्रत्येक उपलब्धि की घोषणा करता है। 404 यदि स्लग के पास नहीं है आधिकारिक गेम परिभाषा (स्क्रिप्ट या कंटेनर बैकएंड के बिना गेम का कोई गेम-स्वामित्व नहीं है उपलब्धियाँ - देखें कौन से गेम इसका उपयोग कर सकते हैं). गुप्त उपलब्धियां तब तक छुपी रहती हैं कॉल करने वाला उन्हें अनलॉक कर देता है। सृजन द्वारा क्रमबद्ध, फिर कुंजी।

[
  {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "secret": false,
    "points": 10,
    "unlocked": true,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
]

पूर्ण उपयोगकर्ता JWT या गेम-स्कोप्ड लॉन्च टोकन के साथ काम करता है।

कौन से गेम इसका उपयोग कर सकते हैं

यह तंत्र उस गेम के लिए उपलब्ध है जो या तो घोषित करता है server= स्क्रिप्ट या ए container.image= बैकएंड में starhermit.txt. द सर्वर रनटाइम अनलॉक को आधिकारिक बनाता है। स्क्रिप्ट-समर्थित उपयोग के मामलों में शामिल हैं:

  • स्क्रिप्टेड प्लेटफ़ॉर्म गेम - से अनलॉक करें onPlayerMessage / onTick जैसे ही मैच खत्म होगा.
  • कमरे में बंद वास्तविक समय के खेल — a वास्तविक समय कक्ष एक के लिए एक के साथ खेल server= स्क्रिप्ट प्रारंभ होने पर एक बाध्य सत्र बनाती है, और उसका प्रत्येक हुक सत्र उपलब्धियाँ प्रदान कर सकता है।
  • एकल-खिलाड़ी और अभ्यास खेल - एआई सीट के खिलाफ एक सत्र (POST /api/v1/games/{slug}/sessions/ai) समान स्क्रिप्ट और समान अनलॉक पथ चलाता है।
  • होस्ट-रूटेड रीयलटाइम गेम - एक गेम जिसका गेमप्ले ऊपर चलता है रीयलटाइम रूम बाइनरी चैनल अभी भी सर्वर स्क्रिप्ट शिप कर सकता है विशुद्ध रूप से इसके उपलब्धि प्राधिकारी के रूप में: रूम स्टार्ट बाउंड सत्र और स्क्रिप्ट बनाता है से पुरस्कार createSession / onTick / टिकाऊ cmd संदेश भेजे गए ws/v1/games जबकि तेज पथ बहता रहता है ws/v1/realtime.

कंटेनर-समर्थित सत्र भी अपने प्रोटोकॉल के माध्यम से उपलब्धियों की घोषणा और अनुदान दे सकते हैं। एक खेल के साथ कोई आधिकारिक बैकएंड नहीं (एक शुद्ध ब्राउज़र गेम, या केवल पर निर्मित सहकर्मी रिले) कोई सर्वर-प्राधिकृत अनलॉक पथ नहीं है। क्लाइंट द्वारा दावा किया गया अनलॉकिंग केवल इनके लिए उपलब्ध है कैटलॉग-वितरित शीर्षक, नीचे।

सीमाएँ और नियम

नियम कीमत
प्रति खेल घोषित उपलब्धियाँ 100 (अतिरिक्त पर ध्यान नहीं दिया गया)
उपलब्धि कुंजी लंबाई 128 अक्षर
अनलॉक कुंजियाँ प्रति खिलाड़ी, प्रति आमंत्रण स्वीकार की जाती हैं 32
points 0-10000 तक सीमित; डिफ़ॉल्ट 0 है
name के लिए डिफ़ॉल्ट key जब छोड़ा गया
  • एक विकृत घोषणा प्रविष्टि है को छोड़ दिया. एक स्क्रिप्ट जो मूल्यांकन करने में विफल रहती है वह खाली हो जाती है सूची; स्वास्थ्य जांच से गुजरने के बाद कंटेनर की घोषणा पढ़ी जाती है। के साथ सत्यापित करें GET /api/v1/games/{slug}/achievements तैनाती के बाद.
  • द्वारा दी गई परिभाषाएँ key. जिस कुंजी को आपका बैकएंड घोषित करना बंद कर देता है उसे हटा दिया जाता है केवल अगर किसी के पास नहीं है इसे अनलॉक किया -अर्जित इतिहास कभी नष्ट नहीं होता। एपीआई के माध्यम से मालिक ने उपलब्धियां हासिल कीं इससे कभी प्रभावित नहीं होते: केवल घोषित लोगों का ही मेल-मिलाप होता है।
  • उन उपयोगकर्ताओं के लिए अनलॉक जो सत्र में भाग नहीं लेते हैं और एआई सीट के लिए अनलॉक को नजरअंदाज कर दिया जाता है।

अन्य खेलों से उपलब्धियां

कोई गेम खिलाड़ी द्वारा अनलॉक की गई चीज़ों के आधार पर सुविधाओं को खोल सकता है एक और खेल: सम्मान की अगली कड़ी मूल, या सौंदर्य प्रसाधन साझा करने वाली श्रृंखला में गेम। इन्हें पढ़ने के दो तरीके हैं.

आपके सर्वर से: ctx.linkedAchievements (विश्वसनीय)

अपनी अन्य घोषणाओं के आगे, अपनी स्क्रिप्ट में अन्य खेलों के नाम बताएं:

globalThis.game = {
  linkedAchievements: ["83fd04b1-3cbe-4b09-a251-3733ad4b9d94"], // other games' slugs (uids)
  // ...
};

एक कंटेनर वही लौटाता है linkedAchievements से सरणी GET /describe. हर स्क्रिप्ट इनवोकेशन का सीटीएक्स उन खेलों में प्रत्येक मानव खिलाड़ी की अनलॉक की गई चाबियों को ले जाता है:

ctx.linkedAchievements = {
  "7c9e6679-...": {                                   // player id
    "83fd04b1-3cbe-4b09-a251-3733ad4b9d94": ["first-win", "checkmate-10"]
  }
};
  • इसे दोबारा पढ़ा जाता है हर आह्वान, इसलिए दूसरे गेम में मध्य-मैच में अर्जित अनलॉक देखा जाता है अगला. एक कंटेनर इसे ctx में प्राप्त करता है POST /sessions, यानी, क्रिएट और एट पर पुनर्स्थापित करें.
  • अधिक से अधिक 8 खेल; ऐसी प्रविष्टियाँ जो गैर-रिक्त स्ट्रिंग्स, डुप्लिकेट और 100 से अधिक स्लग नहीं हैं पात्र हटा दिये गये हैं। अन्य घोषणाओं की तरह इसे तब पढ़ा जाता है जब गेम प्रकाशित होता है या अद्यतन किया गया।
  • एक गेम जो कुछ भी नहीं घोषित करता है उसे 'नहीं' मिलता है linkedAchievements क्षेत्र और कुछ भी भुगतान नहीं करता.
  • प्लेटफ़ॉर्म द्वारा लागू की जाने वाली किसी भी चीज़ के लिए इस मार्ग का उपयोग करें, जैसे कि गेमप्ले को अनलॉक करना या अनुमति देना अपनी खुद की उपलब्धि.

आपके ग्राहक से: GET /api/v1/games/{slug}/linked-achievements/{otherSlug}

कॉल करने वाले का अपना अनलॉक हो जाता है otherSlug. इसे किसी घोषणा की आवश्यकता नहीं है, इसलिए यह केवल ब्राउज़र वाला गेम है सर्वर इसका उपयोग कर सकता है, और यह लॉन्च टोकन के साथ काम करता है {slug}: दूसरे गेम के अपने समापन बिंदु उस टोकन से दूर रहें।

{
  "game": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "hidden": false,
  "unlocked": [
    { "key": "first-win", "unlockedAt": "2026-07-25T09:14:02Z" }
  ]
}

एक ग्राहक इस बारे में झूठ बोल सकता है कि उसे क्या मिला, इसलिए इसे यूआई और सौंदर्य प्रसाधनों के लिए एक संकेत के रूप में लें, सबूत के रूप में नहीं।

क्या खुलासा हुआ है

  • केवल आपके द्वारा नामित गेम की स्थिति को अनलॉक करें: कुंजियाँ और अनलॉक समय, कभी भी नाम, विवरण या नहीं खिलाड़ी द्वारा खेले गए अन्य खेलों की सूची। खिलाड़ी द्वारा अनलॉक की गई एक गुप्त उपलब्धि है शामिल.
  • एक स्लग जो किसी भी गेम से मेल नहीं खाता है, वह उस गेम की तरह उत्तर देता है जिसमें कुछ भी खुला नहीं है।
  • गोपनीयता का सम्मान किया जाता है. एक खिलाड़ी जिसकी उपलब्धियों की गोपनीयता है Private है छिपा हुआ: से अनुपस्थित ctx.linkedAchievements, और "hidden": true समापन बिंदु से एक खाली सूची के साथ। छिपा हुआ के समान नहीं है "कोई नहीं है", इसलिए इसे इस तरह न समझें। FriendsOnly (डिफ़ॉल्ट) का खुलासा किया गया है, क्योंकि पाठक खिलाड़ी के लिए कार्य कर रहा है।

खेल के मालिक द्वारा बनाई गई उपलब्धियाँ

कोड में उपलब्धियों की घोषणा करना आपके गेम को कुछ लाभ देने का एकमात्र तरीका नहीं है। यदि आपके पास एक गेम है server= स्क्रिप्ट या container.image= बैकएंड के माध्यम से आप इसके लिए उपलब्धियां भी बना सकते हैं एपीआई - जिस तरह से एक प्रकाशक किसी कैटलॉग शीर्षक के लिए करता है, जिसमें किसी प्रकाशक खाते या अनुमति की आवश्यकता नहीं होती है। खेल का स्वामित्व ही संपूर्ण अनुदान है। इसका उपयोग तब करें जब कोई डिज़ाइनर जोड़ना या दोबारा लिखना चाहता हो कोड परिवर्तन के बिना उपलब्धियाँ, या जब आपका बैकएंड कुंजी प्रदान करता है तो यह घोषित नहीं होता है।

केवल आपके गेम का सर्वर ही उन्हें अनलॉक कर सकता है, बिल्कुल घोषित लोगों की तरह: आपकी स्क्रिप्ट कुंजी लौटाती है में achievements, या आपका कंटेनर इसे नियंत्रण चैनल पर भेजता है। पर कुछ भी नहीं बदलता अनलॉकिंग पक्ष - कुंजियाँ विरुद्ध हल की जाती हैं सभी खेल की उपलब्धियाँ, घोषित और निर्मित।

{id} आपके गेम की आईडी कहां से है? GET /api/v1/me/github-games.

POST /api/v1/me/github-games/{id}/achievements

  "description": "Finish a level in under a minute.",
  "icon": "https://cdn.example/speedrunner.png",

key, name और description ज़रूरत है। रिटर्न 201:

{
  "id": "…",
  "key": "speedrunner",
  "name": "Speedrunner",
  "description": "Finish a level in under a minute.",
  "icon": "https://cdn.example/speedrunner.png",
  "secret": false,
  "points": 25,
  "origin": "owner",
  "unlocks": 0,
  "createdAt": "…",
  "updatedAt": "…"
}

GET उसी पथ पर खेल की प्रत्येक उपलब्धि को इस आकार में सूचीबद्ध करता है: origin है declared उन लोगों के लिए जिन्हें आपकी स्क्रिप्ट या कंटेनर घोषित करता है और owner यहां बनाए गए लोगों के लिए, और unlocks गिनता है कि प्रत्येक खिलाड़ी के पास कितने खिलाड़ी हैं।

PUT .../achievements/{achievementId} कोई भी लेता है name, description, icon, secret और points; key बदल नहीं सकते। DELETE इसे हटा देता है.

नियम

नियम कीमत
चाबी 1-128 अक्षर: अक्षर, अंक, ., _, -, किसी अक्षर या अंक से प्रारंभ करना
name / description आवश्यक; अधिकतम 200/2000 अक्षर
points 0-10000; डिफ़ॉल्ट 0 है
प्रति गेम स्वामी द्वारा निर्मित उपलब्धियाँ 200 (घोषित 100 तक के अलावा)
  • एक घोषित उपलब्धि आपके कोड की बनी रहती है। एक कुंजी बनाने से गेम में पहले से ही रिटर्न मिलता है 409, और इसी प्रकार संपादन या हटाना भी होता है declared एक - अगला अपडेट इसे आपके कोड के रूप में वापस रख देगा इसकी घोषणा करता है. इसे अपनी स्क्रिप्ट में बदलें या /describe बजाय।
  • यदि आपका कोड बाद में आपके द्वारा यहां बनाई गई कुंजी घोषित करता है, घोषणा उस उपलब्धि को लेती है ओवर (origin बन जाता है declared). जिन खिलाड़ियों ने इसे अर्जित किया वे इसे अपने पास रखते हैं।
  • किसी व्यक्ति द्वारा अनलॉक की गई उपलब्धि को हटाया नहीं जा सकता (409).
  • 404 इसका मतलब है कि गेम आपका नहीं है; 409 इनमें से किसी भी रूट पर सर्वर के बारे में संदेश के साथ बैकएंड का मतलब है कि गेम में कुछ भी नहीं है - केवल ब्राउज़र वाले गेम में ऐसा कुछ भी नहीं है जो किसी को अनलॉक कर सके उपलब्धि.

क्रमशः: ट्यूटोरियल: आपके खेल के लिए लीडरबोर्ड और उपलब्धियाँ.

कैटलॉग शीर्षक उपलब्धियाँ

कैटलॉग के माध्यम से वितरित सॉफ़्टवेयर के लिए, जहां क्लाइंट ही एकमात्र चीज़ है जो अवलोकन करता है अनलॉक स्थिति. परिभाषाएँ गुमनाम रूप से पढ़ी जाती हैं; अनलॉक करने के लिए एक JWT और एक गैर-निरस्त की आवश्यकता होती है उपाधि का अधिकार.
