बात करना

StarHermit चैट में REST API पर सीधे संदेश, समूह कक्ष और गेम-सत्र वार्तालाप शामिल हैं (api/v1/chat) प्लस एक सर्वर-टू-क्लाइंट वेबसॉकेट पुश चैनल (ws/v1/chat). सभी REST समापन बिंदुओं को प्रमाणीकरण की आवश्यकता होती है। त्रुटि निकाय अलग-अलग होते हैं; देखना एपीआई कन्वेंशन.

बाकी समापनबिंदु

आधार: https://api.starhermit.com/api/v1/chat.

तरीका पथ प्रमाणीकरण विवरण
डाक /conversations जेडब्ल्यूटी वार्तालाप बनाएँ (1 मित्र = प्रत्यक्ष, ≥2 = समूह)
पैबंद /conversations/{id} जेडब्ल्यूटी किसी वार्तालाप का नाम बदलें (कोई भी सदस्य)
डाक /conversations/{id}/invites जेडब्ल्यूटी किसी उपयोगकर्ता को समूह में आमंत्रित करें
पाना /invites जेडब्ल्यूटी अपने लंबित चैट आमंत्रणों की सूची बनाएं
डाक /invites/{id}/accept जेडब्ल्यूटी चैट आमंत्रण स्वीकार करें
डाक /invites/{id}/decline जेडब्ल्यूटी चैट आमंत्रण अस्वीकार करें
पाना /rooms/joinable जेडब्ल्यूटी ≥1 मित्र के साथ खुले कमरों की सूची बनाएं
डाक /conversations/{id}/join जेडब्ल्यूटी एक खुले कमरे में शामिल हों (किसी सदस्य से मित्रता होनी चाहिए)
डाक /conversations/{id}/participants जेडब्ल्यूटी प्रतिभागियों को वार्तालाप में जोड़ें
मिटाना /conversations/{id}/participants/{userId} जेडब्ल्यूटी किसी भागीदार को हटाएं (स्वयं: कोई भी सदस्य; अन्य: केवल समूह निर्माता)
डाक /conversations/{id}/leave जेडब्ल्यूटी बातचीत छोड़ें
पाना /conversations जेडब्ल्यूटी प्रत्येक अपठित गिनती सहित बातचीत की सूची बनाएं
पाना /conversations/{id} जेडब्ल्यूटी इसकी अपठित गिनती सहित वार्तालाप प्राप्त करें
पाना /unread जेडब्ल्यूटी कुल अपठित-संदेश संख्या प्राप्त करें
डाक /conversations/{id}/read जेडब्ल्यूटी किसी वार्तालाप को पढ़ा गया चिह्नित करें
पाना /conversations/{id}/messages?page=&pageSize= जेडब्ल्यूटी पृष्ठांकित संदेश इतिहास प्राप्त करें
डाक /conversations/{id}/messages जेडब्ल्यूटी संदेश भेजें (दर-सीमित)
रखना /conversations/{conversationId}/messages/{messageId} जेडब्ल्यूटी एक संदेश संपादित करें
मिटाना /conversations/{conversationId}/messages/{messageId} जेडब्ल्यूटी एक संदेश हटाएं (समाधि का पत्थर)

वार्तालाप बनाएँ

POST /conversations

{
  "participantIds": ["<guid>"],
  "name": "Friday night lobby",
  "friendUserId": "<guid>",
  "joinPolicy": "closed"
}

सभी फ़ील्ड वैकल्पिक हैं. एक मित्र प्रतिभागी बनाता है प्रत्यक्ष बातचीत; दो या दो से अधिक एक बनाते हैं समूह. joinPolicy है "open" या "closed" (गलती करना "closed"). रिटर्न ए ConversationDto.

किसी वार्तालाप का नाम बदलें

PATCH /conversations/{id} साथ { "name": "New name" } → ConversationDto. कोई भी सदस्य नाम बदल सकता है; के साथ एक सिस्टम नोट kind: "system_rename" प्रसारित किया जाता है.

आमंत्रण

POST /conversations/{id}/invites साथ { "toUserId": "<guid>" } → ChatInviteDto. बंद कमरे में निमंत्रण ही एकमात्र रास्ता है।

GET /invites → ChatInviteDto[]:

[
  {
    "id": "<guid>",
    "conversationId": "<guid>",
    "conversationName": "Friday night lobby",
    "fromUserId": "<guid>",
    "fromUsername": "alice",
    "toUserId": "<guid>",
    "status": "pending",
    "createdAt": "2026-07-22T07:00:00Z"
  }
]

POST /invites/{id}/accept और POST /invites/{id}/decline → ChatInviteDto.

जुड़ने वाले कमरे

GET /rooms/joinable → JoinableRoomDto[] - खुले कमरे जिनमें आपका कम से कम एक दोस्त हो:

[
  {
    "id": "<guid>",
    "name": "Friday night lobby",
    "joinPolicy": "open",
    "createdAt": "2026-07-22T07:00:00Z",
    "participants": [{ "userId": "<guid>", "username": "alice" }]
  }
]

POST /conversations/{id}/join → ConversationDto. एक खुले कमरे से जुड़ता है; आपको किसी सदस्य से मित्रता करनी होगी.

प्रतिभागियों

POST /conversations/{id}/participants साथ { "participantIds": ["<guid>"] } → ConversationDto.

DELETE /conversations/{id}/participants/{userId} → 204. कोई भी सदस्य स्वयं को हटा सकता है; दूसरों को हटाने के लिए समूह निर्माता होना आवश्यक है।

POST /conversations/{id}/leave → 204.

बातचीत पढ़ना

GET /conversations → ConversationDto[].

GET /conversations/{id} → ConversationDto:

{
  "id": "<guid>",
  "type": "group",
  "name": "Friday night lobby",
  "createdByUserId": "<guid>",
  "joinPolicy": "closed",
  "createdAt": "2026-07-22T07:00:00Z",
  "participants": [{ "userId": "<guid>", "username": "alice" }],
  "otherParticipant": { "userId": "<guid>", "username": "bob" },
  "unreadCount": 3
}

type में से एक है direct, group, game. name, createdByUserId, और otherParticipant अनुपस्थित हो सकता है. unreadCount कॉल करने वाले के प्रति-वार्तालाप पढ़ने के क्षितिज के बाद अन्य सदस्यों द्वारा भेजे गए अपठित पाठ संदेशों की गणना करता है।

अपठित अवस्था

GET /unread कॉल करने वाले की सभी बातचीतों में अपठित गिनती लौटाता है:

{ "total": 7 }

POST /conversations/{id}/read उस बातचीत के लिए कॉल करने वाले के पढ़ने के क्षितिज को आगे बढ़ाता है। वर्तमान प्रतिलेख प्रदर्शित करने के बाद इसका उपयोग करें। सर्वर उत्सर्जित करता है a conversation_read घटना को कॉल करने वाले से संबंधित सभी सॉकेट, एकाधिक साइन-इन क्लाइंट को अपने बैज साफ़ करने की अनुमति देते हैं। नए और हटाए गए संदेशों का कुल योग बदल सकता है, इसलिए ग्राहकों को WebSocket ईवेंट से अपडेट करना चाहिए समय-समय पर पुनः प्राप्त करें /unread.

संदेशों

GET /conversations/{id}/messages?page=1&pageSize=50 → PagedMessagesDto:

{
  "conversationId": "<guid>",
  "page": 1,
  "pageSize": 50,
  "totalCount": 123,
  "items": []
}

POST /conversations/{id}/messages साथ { "content": "hello" } → MessageDto. दर-प्रति उपयोगकर्ता 10 संदेश/मिनट तक सीमित; इससे अधिक होने पर यह वापस आ जाता है 429.

PUT /conversations/{conversationId}/messages/{messageId} साथ { "content": "edited" } → MessageDto.

DELETE /conversations/{conversationId}/messages/{messageId} → 204. विलोपन एक समाधि है: संदेश साथ रहता है isDeleted: true.

MessageDto:

{
  "id": "<guid>",
  "conversationId": "<guid>",
  "senderId": "<guid>",
  "senderUsername": "alice",
  "content": "hello",
  "kind": "text",
  "metadata": { "key": "value" },
  "sentAt": "2026-07-22T07:00:00Z",
  "editedAt": null,
  "isDeleted": false
}

kind है "text" या "system_rename"; content, metadata (a Dictionary<string,string>), और editedAt अनुपस्थित/शून्य हो सकता है।

वेबसॉकेट: ws/v1/chat

से कनेक्ट wss://api.starhermit.com/ws/v1/chat के माध्यम से एक JWT के साथ Authorization शीर्षलेख, ?ticket=, या ?access_token=.

यह एक है शुद्ध सर्वर→क्लाइंट पुश चैनल: क्लाइंट फ़्रेम को अनदेखा किया जाता है (केवल Close सम्मानित किया गया है)। प्रत्येक फ्रेम एक लिफाफा है:

{ "type": "<event>", "payload": { } }
आयोजन type पेलोड
conversation_created ConversationDto
conversation_renamed ConversationDto
participants_added ConversationDto
participant_removed ConversationDto
chat_invite ChatInviteDto
chat_invite_responded ChatInviteDto
new_message MessageDto
message_updated MessageDto
message_deleted MessageDto
conversation_read साइन-इन किए गए उपयोगकर्ता के लिए रीड-स्टेट परिवर्तन; अपठित गिनती पुनः प्राप्त करें
game_invite { "inviteId", "kind", "gameSlug", "gameName", "roomId", "from": { "userId", "username" }, "createdAt", "acceptPath", "declinePath", "inProgress", "sessionId" } - नीचे देखें

game_invite: दोनों आमंत्रण प्रणालियों के लिए एक इवेंट

किसी को भी दो तरीकों से खेलने के लिए आमंत्रित किया जा सकता है, और इस एकल कार्यक्रम में दोनों शामिल हैं - एक ग्राहक एक टोस्ट लागू करता है, दो नहीं:

kind जारीकर्ता इसे स्वीकार कर रहे हैं
"session" POST /games/{slug}/invites आप दोनों के लिए एक नया गेम सत्र बनाता है
"room" POST /realtime/rooms/{id}/invites उस कमरे में सीट लेता है जिसमें आमंत्रितकर्ता पहले से ही बैठा है; roomId क्या वह कमरा है?

acceptPath और declinePath वे अंतिम बिंदु हैं जो उत्तर देते हैं यह आमंत्रित करें - उनका उपयोग करें और भेद कभी मायने नहीं रखता। अन्य सिस्टम के अंतिम बिंदु पर उत्तर देना एक है 404: दोनों अलग-अलग आमंत्रण आईडी रखते हैं।

inProgress है true स्वीकार करते समय पहले से ही खेले जा रहे खेल में शामिल हो जाता है - एक सत्र आमंत्रण जो चल रहे सत्र का नाम देता है, या एक प्रारंभ किए गए कमरे में एक कमरा आमंत्रण जो प्रगति में शामिल होने की अनुमति देता है - और sessionId वह खेल का सत्र है. कहने के लिए इसका प्रयोग करें "उनके खेल में शामिल हों" के बजाय "खेल".

{
  "type": "game_invite",
  "payload": {
    "inviteId": "e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b",
    "kind": "room",
    "gameSlug": "poker",
    "gameName": "StarHermit Poker",
    "roomId": "b1d2c3e4-5f60-4a71-8b92-c3d4e5f60718",
    "from": { "userId": "9b2f8c1a-1111-4222-8333-444455556666", "username": "alice" },
    "createdAt": "2026-07-26T14:10:00Z",
    "acceptPath": "/api/v1/realtime/rooms/invites/e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b/accept",
    "declinePath": "/api/v1/realtime/rooms/invites/e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b/decline"
  }
}

roomId है null के लिए "session" आमंत्रित करता है. गेम-स्कोप्ड लॉन्च टोकन इस सॉकेट को नहीं खोल सकता है या पूरे खाते को नहीं पढ़ सकता है /me/game-invites इनबॉक्स. गेम क्लाइंट पोल GET /api/v1/games/{slug}/invites सत्र आमंत्रण के लिए और GET /api/v1/realtime/rooms/invites उनके खेल के कमरे के निमंत्रण के लिए। खाता ग्राहक दोनों प्रकार से पढ़ सकते हैं GET /api/v1/me/game-invites.

खेल सत्र के अंदर बातचीत करें

एक गेम-स्कोप्ड लॉन्च टोकन नही सकता खुला ws/v1/chat — यह अवरुद्ध है क्योंकि सॉकेट उपयोगकर्ता की सभी बातचीत को स्ट्रीम करता है। टोकन लॉन्च करें मई अपने स्वयं के गेम सत्रों से जुड़ी बातचीत पर चैट REST API का उपयोग करें: सत्र विवरण एक लौटाता है chatConversationId, बातचीत का प्रकार है "game", इसके प्रतिभागी सत्र के खिलाड़ी हैं, और मैत्री नियमों को दरकिनार कर दिया गया है।

इसलिए गेम क्लाइंट आमतौर पर सॉकेट का उपयोग करने के बजाय इतिहास को REST पर लोड करते हैं और नए संदेशों के लिए पोल करते हैं। उदाहरण के लिए, शतरंज संदर्भ कार्यान्वयन हर 5 सेकंड में मतदान:

GET /api/v1/chat/conversations/{chatConversationId}/messages?page=1&pageSize=50
Authorization: Bearer <launch-token>

POST /api/v1/chat/conversations/{chatConversationId}/messages
Authorization: Bearer <launch-token>
Content-Type: application/json

{ "content": "good game" }

यह भी देखें

  • आवाज़ - वॉयस रूम चैट वार्तालापों के लिए एंकर हैं
  • दोस्त - मैत्री द्वार सीधी चैट और रूम जॉइन
  • खेल — खेल सत्र और उनके chatConversationId

देखना क्रेडेंशियल अनुकूलता और मशीन-पठनीय अनुबंध.
