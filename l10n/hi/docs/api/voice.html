आवाज़

StarHermit वॉयस REST API पर प्रति-बातचीत वॉयस रूम प्रदान करता है (api/v1/voice) प्लस एक मिश्रित बाइनरी/टेक्स्ट वेबसॉकेट (ws/v1/voice) ऑडियो और वेबआरटीसी सिग्नलिंग के लिए। सभी REST समापन बिंदुओं को प्रमाणीकरण की आवश्यकता होती है। आवाज की उपलब्धता भिन्न हो सकती है। त्रुटि निकाय अलग-अलग होते हैं; देखना एपीआई कन्वेंशन.

कमरे एक से लंगर डालते हैं चैट वार्तालाप; बातचीत में सदस्यता हर चीज़ को प्रवेश देती है, इसलिए चैट मैत्री नियम आवाज को भी नियंत्रित करते हैं (गेम-सत्र वार्तालाप मित्रता को दरकिनार कर देते हैं)। सीमाएँ: प्रति वार्तालाप 3 सक्रिय कमरे, प्रति कमरा अधिकतम 10 प्रतिभागी, कोडेक "opus".

बाकी समापनबिंदु

आधार: https://api.starhermit.com/api/v1/voice.

तरीका पथ प्रमाणीकरण विवरण
डाक /rooms जेडब्ल्यूटी बातचीत के लिए एक ध्वनि कक्ष बनाएं
पाना /rooms?conversationId= जेडब्ल्यूटी बातचीत के लिए कमरों की सूची बनाएं
पाना /rooms/{roomId} जेडब्ल्यूटी एक कमरा मिला
डाक /rooms/{roomId}/join जेडब्ल्यूटी एक कमरे में शामिल हों (WS से पहले आवश्यक)
डाक /rooms/{roomId}/leave जेडब्ल्यूटी एक कमरा छोड़ दो
डाक /rooms/{roomId}/mute जेडब्ल्यूटी अपनी स्वयं की मूक स्थिति सेट करें
डाक /rooms/{roomId}/participants/{userId}/server-mute जेडब्ल्यूटी (निर्माता) मेज़बान म्यूट प्रतिभागी नहीं उठा सकता
डाक /rooms/{roomId}/close जेडब्ल्यूटी एक कमरा बंद करें (केवल निर्माता)

एक कमरा बनाएं

POST /rooms

{ "conversationId": "<guid>", "maxParticipants": 10 }

रिटर्न ए VoiceRoomDto.

कमरे का आकार

GET /rooms?conversationId=<guid> → VoiceRoomDto[]; GET /rooms/{roomId} → VoiceRoomDto:

{
  "id": "<guid>",
  "conversationId": "<guid>",
  "creatorUserId": "<guid>",
  "codec": "opus",
  "status": "Active",
  "maxParticipants": 10,
  "createdAt": "2026-07-22T07:00:00Z",
  "participants": [
    {
      "userId": "<guid>",
      "username": "alice",
      "isMuted": false,
      "isConnected": true,
      "joinedAt": "2026-07-22T07:01:00Z"
    }
  ]
}

शामिल हों, छोड़ें, म्यूट करें, बंद करें

POST /rooms/{roomId}/join → VoiceRoomDto. यह REST जॉइन है आवश्यक वेबसॉकेट खोलने से पहले; इसके बिना कनेक्ट करना वापस आ जाता है 403. पुनः शामिल होने से प्रतिभागी का नाम साफ़ हो जाता है अपना आवाज़ बंद करना (isMuted); एक मेज़बान का isServerMuted बचता है छोड़ो और पुनः कनेक्ट करो।

POST /rooms/{roomId}/leave → 204.

POST /rooms/{roomId}/mute साथ { "muted": true } → 204. यह प्रतिभागी का स्वयं का म्यूट है और होस्ट म्यूट को साफ़ नहीं कर सकता।

POST /rooms/{roomId}/participants/{userId}/server-mute साथ { "muted": true } → 204 (केवल निर्माता). यदि म्यूट सेट किया गया है तो ऑडियो हटा दिया जाता है।

POST /rooms/{roomId}/close → 204 (केवल निर्माता).

पंक्ति जो कुछ भी याद रखती है उसे इनहेरिट करने के बजाय कनेक्ट पर अपना म्यूट बताएं।

वेबसॉकेट: ws/v1/voice

से कनेक्ट wss://api.starhermit.com/ws/v1/voice?roomId=<guid> के माध्यम से एक JWT के साथ Authorization शीर्षलेख, ?ticket=, या ?access_token=. एक पूर्व विश्राम join आवश्यक है।

प्रोटोकॉल मिश्रित है:

बाइनरी फ़्रेम - ऑडियो

बाइनरी फ़्रेम ऑडियो ले जाते हैं (जैसे ओपस)। सर्वर प्रत्येक फ़्रेम को अन्य प्रतिभागियों को इस प्रकार रिले करता है:

[16-byte senderUserId][audio…]

सर्वर उपसर्ग लगाता है प्रमाणीकृत प्रेषक आईडी और ग्राहक द्वारा प्रदत्त प्रेषक पर कभी भरोसा नहीं करता। म्यूट किए गए उपयोगकर्ताओं का ऑडियो हटा दिया गया है. सीमाएँ: प्रति उपयोगकर्ता 100 पैकेट/सेकंड, अधिकतम फ्रेम 4000 बाइट्स।

टेक्स्ट फ़्रेम - क्लाइंट → सर्वर नियंत्रण

{ "type": "mute", "muted": true }

{ "type": "speaking", "speaking": true }

{ "type": "rtc", "to": "<guid>", "payload": { } }

{ "type": "deafen", "deafened": true }

rtc पेलोड अपारदर्शी WebRTC सिग्नलिंग हैं, जिन्हें संबोधित प्रतिभागी को भेजा जाता है। deafen इस सॉकेट के लिए आने वाले रिलेड बाइनरी ऑडियो को दबा देता है; यह स्वचालित रूप से म्यूट नहीं होता है आउटगोइंग ऑडियो या एक अलग सहकर्मी कनेक्शन। जब खिलाड़ी डेफेन चुनता है तो उन्हें स्थानीय रूप से लागू करें।

REST प्रतिभागी का आकार स्वयं के म्यूट को उजागर करता है, होस्ट म्यूट को नहीं। प्रारंभिक वॉयस रोस्टर और इवेंट में शामिल हों सम्मिलित करें serverMuted; कोई अलग होस्ट-म्यूट-परिवर्तित पुश इवेंट नहीं है। यदि आपका गेम P2P का उपयोग करता है ऑडियो, इसका होस्ट-म्यूट सिग्नलिंग और प्रवर्तन आपके अपने मीडिया एकीकरण का हिस्सा होना चाहिए।

जब आखिरी वॉयस सॉकेट डिस्कनेक्ट हो जाता है, तो वॉयस-रूम सदस्यता समाप्त हो जाती है। रेस्ट को कॉल करें join फिर से पहले ऑडियो भेजने से पहले इच्छित म्यूट को पुनः कनेक्ट करना और पुनर्स्थापित करना।

उदाहरण एकीकरण पैटर्न (शतरंज संदर्भ कार्यान्वयन से)

वॉयस प्रति गेम सत्र में ऑप्ट-इन है। एक विशिष्ट ग्राहक enable() प्रवाह:

  1. GET /api/v1/voice/rooms?conversationId=<chatConversationId> एक मौजूदा कमरा ढूंढने के लिए, अन्यथा POST /api/v1/voice/rooms एक बनाने के लिए.
  2. POST /api/v1/voice/rooms/{roomId}/join.
  3. खुला ws/v1/voice?roomId=<guid>.

में शतरंज संदर्भ कार्यान्वयन, ऑडियो सही बातचीत के साथ WebRTC P2P पर चलता है; के माध्यम से सिग्नलिंग का आदान-प्रदान किया जाता है rtc संदेशों को नियंत्रित करें ({ "sdp": … } / { "ice": … } पेलोड), फ़ॉलबैक के रूप में सर्वर-रिले ओपस बाइनरी पथ के साथ।

गेम-स्कोप्ड लॉन्च टोकन मई अपने गेम सत्र से जुड़े कमरों के लिए वॉयस REST और WebSocket का उपयोग करें।

यह भी देखें

  • ऑडियो विकल्प - बेसलाइन वॉल्यूम, माइक्रोफ़ोन और पुश-टू-टॉक नियंत्रण, स्वतः-पहचानित प्लेबैक कैप के साथ
  • बात करना - कमरे बातचीत के लिए लंगर डालते हैं; खेल सत्र उजागर chatConversationId
  • खेल - गेम सत्र और लॉन्च टोकन
  • रिले - गेम नेटकोड के लिए बाइट फैन-आउट

देखना क्रेडेंशियल अनुकूलता और मशीन-पठनीय अनुबंध.
