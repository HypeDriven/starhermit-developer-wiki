प्रगति को सुरक्षित रूप से लोड करें और सहेजें

साइन-इन किए गए प्लेयर की क्लाइंट-स्वामित्व वाली प्रगति के लिए क्लाउड सेव का उपयोग करें। अहस्ताक्षरित एकल-खिलाड़ी विकल्प मेमोरी में प्रगति रखता है और अकाउंट सेव को पढ़ता या लिखता नहीं है। प्राथमिकताएं शामिल हैं खेल सेटिंग्स, प्रगति दस्तावेज़ नहीं.

एक लॉन्च टोकन सटीक रूप से पहुंच सकता है game:<gameId>, कहाँ gameId इसका है game_scope. मंच प्रति स्लॉट एक सेव के साथ, अपारदर्शी बाइट्स संग्रहीत करता है। आपके गेम द्वारा अपेक्षित प्रारूप को सत्यापित करें। देखना क्लाउड सेव कोटा और सशर्त शीर्षलेखों के लिए।

एक छोटी संपूर्ण JSON रेसिपी

प्रतिलिपि cloud-save-store.js आपके निर्माण में. यह उदाहरण कच्चा संग्रहीत करता है UTF-8 JSON बाइट्स; मंच उनकी सेवा करता है application/zip लेकिन ज़िप प्रारूप की आवश्यकता नहीं है. ज़िप सेव के लिए एक अलग रीडर का उपयोग करें, जिसमें शामिल है ब्राउज़र SDK का ज़िप सहेजता है. मौजूदा खिलाड़ियों के लिए माइग्रेशन योजना के बिना प्रारूप न बदलें।

import { CloudSaveStore } from './cloud-save-store.js';

const store = new CloudSaveStore({
  gameId: StarHermit.slug,
  token: () => StarHermit.token, // Always obtain the current renewed token.
});
const valid = value => value?.version === 1 && Number.isSafeInteger(value.points) && value.points >= 0;
let progress = { version: 1, points: 0 };
let saving = false;

async function startAccountGame() {
  // Keep gameplay/saving disabled until this resolves.
  const remote = await store.load(valid);
  progress = remote ?? { version: 1, points: 0 };
  render(progress);
}

async function saveCheckpoint() {
  if (saving) return; // Coalesce checkpoints; do not issue overlapping writes.
  saving = true;
  showSync('Saving…');
  try {
    await store.save(progress);
    showSync('Saved');
  } catch (error) {
    if (error.status === 412) {
      // Keep local progress in memory. Offer Reload cloud or an explicit merge.
      showConflict(() => startAccountGame());
    } else showSync('Save failed; retry after resolving the error');
  } finally {
    saving = false;
  }
}

render, showSync, और showConflict आपका यूआई है. का इंतजार startAccountGame() सक्षम करने से पहले खेलें या सहेजें. लोड विफलता पर, खिलाड़ी की वर्तमान स्थानीय स्थिति को बनाए रखें, विफलता प्रदर्शित करें, और अपलोड को अवरुद्ध रखें। ए 404 खाली-स्लॉट मामला है; 401, 403, 5xx, विकृत JSON, या असमर्थित सेव संस्करण खाली स्लॉट नहीं हैं।

नुस्खा क्रेडेंशियल्स को नवीनीकृत नहीं करता है. ब्राउज़र SDK लॉन्च टोकन के बने रहने पर उन्हें नवीनीकृत करता है वैध. पढ़ने का पुनः प्रयास करने से पहले लंबित शर्तों को हल करें या खेल के प्रवेश प्रवाह के माध्यम से पुनः प्रमाणित करें।

स्थितियाँ और संघर्ष

क्या लोड किया गया था अगले लिखने पर हेडर यदि कोई अन्य डिवाइस लिखता है
ETag के साथ मौजूदा बचत If-Match: <etag> 412 precondition_failed
कोई सेव नहीं (404) If-None-Match: * 412 precondition_failed
कुछ भी सफलतापूर्वक लोड नहीं हुआ नहीं लिखना पढ़ने का पुनः प्रयास करते रहें या खिलाड़ी को अनट्रैक प्ले में ही रहने दें

से संस्करण का उपयोग करें आपके द्वारा लोड किया गया डेटा, बाद में मेटाडेटा जाँच नहीं। लौटाए गए नए ईटैग को अपने पास रखें प्रत्येक सफल लेखन द्वारा. ए 412 जब तक गेम वर्तमान संस्करण को लोड नहीं करता तब तक ब्लॉक और सेव हो जाता है खिलाड़ी इसे अपनाता है या विलय करता है। शर्त को चुपचाप हटाकर किसी अन्य डिवाइस पर अधिलेखित न करें। एपीआई उस ओवरराइट को पूर्ववत करने के लिए कोई सेव हिस्ट्री प्रदान नहीं करता है।

यदि दो डिवाइसों को स्वतंत्र रूप से काउंटरों या इन्वेंट्री को अपडेट करना होगा, तो एक अंतिम-लेखन दस्तावेज़ जीतता है खेल में फिट नहीं हो सकता. सर्वर-आधिकारिक स्थिति का उपयोग करें और इसके बजाय मान्य गेम कमांड को परिभाषित करें।

प्रारूप और माइग्रेशन सहेजें

रिमोट अपनाने से पहले एक प्रारूप संस्करण शामिल करें और प्रकार, श्रेणियां और आवश्यक फ़ील्ड मान्य करें प्रगति. समर्थित पुराने संस्करणों के लिए माइग्रेशन लिखें। एक नया अज्ञात संस्करण बरकरार रखें; इसे डिफ़ॉल्ट पर रीसेट न करें और इस पर अपलोड करें। क्लाउड डेटा क्लाइंट-नियंत्रित है, इसलिए इसे कभी भी ट्रीट न करें प्रतिस्पर्धी स्कोर या भुगतान पात्रता के प्रमाण के रूप में।

डिफ़ॉल्ट डिकोडेड-सेव सीमा 10 MiB है। बेस64 अनुरोध निकाय में लगभग एक तिहाई जोड़ता है। 413 cloud_save_too_large, 409 cloud_save_slots_exhausted, और 507 cloud_save_quota_exceeded विभिन्न क्षमता विफलताएँ हैं; निरीक्षण करें code और limit. सम्मान Retry-After पर 429.

चेकप्वाइंट और पेज निकास

सार्थक चौकियों पर बचत करें और दृश्यमान सहेजें कार्रवाई की पेशकश करें। तेजी से बदलावों की निंदा करें और क्रमबद्ध करें लिखता है इसलिए प्रत्येक व्यक्ति अंतिम स्वीकृत संस्करण का उपयोग करता है। स्वीकृत होने तक गंदा संकेतक रखें। एक असफल अनुरोध एक पुष्ट बचत नहीं है; एक अस्पष्ट लेखन के बाद, दूसरे लेखन से पहले पुनः लोड करें।

पेज-एग्जिट अपलोड सर्वोत्तम प्रयास है। ब्राउज़र fetch(..., { keepalive: true }) एक छोटी सी उड़ान साझा करता है शारीरिक भत्ता, सामान्यतः 64 KiB; 10 MiB सेव इस पर भरोसा नहीं कर सकता। किसी अनुरोध से पहले कोई टैब बंद हो सकता है ख़त्म. स्थायित्व के लिए सामान्य अग्रभूमि बचत का उपयोग करें, और अस्वीकृत प्रगति को लेबल न करें बचाया. क्विकस्टार्ट प्रत्येक बिंदु संग्रह पर अपने छोटे दस्तावेज़ को सहेजता है।

अपने गेम में सत्यापित करें

  1. एक खाली स्लॉट से शुरू करें; प्रगति एकत्रित करें, सहेजें, पुनः लोड करें और उसके वापस आने की पुष्टि करें।
  2. नेटवर्क त्रुटि के साथ पढ़ने से इंकार करें, 403, या अमान्य डेटा; पुष्टि करें कि कोई अपलोड नहीं हो रहा है।
  3. एक संस्करण पर दो टैब खोलें. ए में सहेजें, फिर बी: बी को एक संघर्ष सामने लाना होगा और अपनी स्थानीय स्थिति को संरक्षित करना होगा।
  4. अज्ञात डेटा को अधिलेखित किए बिना पुराने/नए प्रारूप और गुम पावती का परीक्षण करें।
  5. अनट्रैक्ड सिंगल-प्लेयर मोड दर्ज करें और सत्यापित करें कि प्ले कोई क्लाउड-सेव अनुरोध नहीं करता है।

देखना चलाने योग्य त्वरित प्रारंभ, एपीआई कन्वेंशन, और समस्या निवारण.
