ट्यूटोरियल: सार्वजनिक कुंजी वाले खिलाड़ियों को ऑनबोर्ड करें

StarHermit खाते को Google, GitHub या किसी अन्य साइन-इन प्रदाता की आवश्यकता नहीं है। इसकी साख हो सकती है एक कुंजी जोड़ी बनें जो आपका गेम खिलाड़ी के डिवाइस पर उत्पन्न करता है, साथ ही खिलाड़ी का एक ईमेल पता भी एक बार पुष्टि करता है. उसके बाद, आपका गेम प्रत्येक लॉन्च पर एक चुनौती पर हस्ताक्षर करके चुपचाप साइन इन करता है कुंजी. खिलाड़ी कभी भी पासवर्ड टाइप नहीं करता है और उसे कभी भी StarHermit पेज पर नहीं जाना पड़ता है।

यह ट्यूटोरियल उस प्रवाह को शुरू से अंत तक बनाता है: कुंजी उत्पन्न करें, इसे पंजीकृत करें, प्लेयर के लिए प्रतीक्षा करें पुष्टि करें, साइन इन करें, सत्र जारी रखें, और दूसरे डिवाइस और खोई हुई कुंजियों को संभालें।

इसके लिए इसका प्रयोग करें देशी और स्टैंडअलोन गेम, लॉन्चर, स्टीम/एपिक/जीओजी बिल्ड और डेस्कटॉप टूल्स - कुछ भी जो खिलाड़ी की मशीन पर चलता है और वहां एक निजी कुंजी रख सकता है।

के लिए कुछ और प्रयोग करें

  • StarHermit पर होस्ट किया गया एक ब्राउज़र गेम, जिसे खोलने पर पहले से ही एक लॉन्च टोकन प्राप्त होता है डैशबोर्ड, या दिखा सकते हैं साइन इन बटन.
  • एक सीआई पाइपलाइन, जिसे बिना किसी ईमेल चरण के OAuth सत्र से एक कुंजी नामांकित करनी चाहिए: ट्यूटोरियल: सीआई/सीडी से बिल्ड अपलोड करें.
  • एक समर्पित गेम सर्वर, जिसका अपना स्वयं का परिनियोजन टोकन है और वह निर्माण या कार्य नहीं कर सकता है खिलाड़ी: ट्यूटोरियल: एक समर्पित सर्वर प्रकाशित करें.

खिलाड़ी क्या देखता है

  1. आपका गेम एक ईमेल पता और एक StarHermit खाता बनाने के लिए उनकी सहमति मांगता है।
  2. वे पुष्टिकरण ईमेल खोलते हैं, लिंक पर क्लिक करते हैं और दबाते हैं पुष्टि करना पेज पर यह खुलता है.
  3. आपके गेम में वापस, वे साइन इन हैं। बाद के लॉन्च पर कुछ भी नहीं पूछा जाता है।

एक ईमेल पता आवश्यक है, और खिलाड़ी को एक बार इसकी पुष्टि करनी होगी। बनाने का कोई तरीका नहीं है अकेले स्टीम, एपिक या जीओजी पहचान से स्टारहर्मिट खाता चुपचाप।

आपके शुरू करने से पहले

इस पृष्ठ पर कोड WebCrypto का उपयोग करके सादा जावास्क्रिप्ट है fetch, तो यह एक ब्राउज़र में चलता है इलेक्ट्रॉन और नोड 20 या बाद में। js नीचे दिए गए ब्लॉक, क्रम में, एक ईएस मॉड्यूल बनाते हैं - उन्हें बचाएं एक साथ जैसे starhermit-key-auth.js. कोई भी अन्य भाषा इसी तरह काम करती है: चरण 1 सटीक जानकारी देता है बाइट प्रारूप, और चरण 3 हस्ताक्षर करने के लिए सटीक बाइट्स।

const API = 'https://api.starhermit.com';

const b64 = (bytes) => btoa(String.fromCharCode(...new Uint8Array(bytes)));

1. डिवाइस कुंजी बनाएं

उत्पन्न प्रति इंस्टालेशन एक कुंजी जोड़ी, पहली बार आपके गेम को एक खाते की आवश्यकता होगी। निजी कुंजी डिवाइस को कभी नहीं छोड़ती: आपके सर्वर पर नहीं, StarHermit पर नहीं।

keyType keyData (मानक बेस64) हस्ताक्षर (मानक बेस64)
Ed25519 - अनुशंसित कच्ची 32-बाइट सार्वजनिक कुंजी कच्चा 64-बाइट Ed25519 हस्ताक्षर
ECDSA-P256 सार्वजनिक बिंदु: 65-बाइट असंपीड़ित (04‖X‖Y) या 33-बाइट संपीड़ित SHA-256 के साथ ECDSA, ASN.1 DER-एन्कोडेड
RSA-PSS SubjectPublicKeyInfo डीईआर, 2048-8192-बिट मापांक, घातांक ≤ 32 बिट्स आरएसएएसएसए-पीएसएस, एसएचए-256, एमजीएफ1-एसएचए-256, 32-बाइट नमक

keyData अधिकतम 2,000 अक्षर हैं. एक कुंजी पूरे प्लेटफ़ॉर्म पर एक खाते की होती है।

चुनना Ed25519 जब तक कि आपका प्लेटफ़ॉर्म इसका उत्पादन न कर सके। यदि आप ECDSA का उपयोग करते हैं, तो ध्यान दें कि WebCrypto, विंडोज़ सीएनजी और अधिकांश हार्डवेयर कीस्टोर हस्ताक्षर को कच्चा बताते हैं r‖s (64 बाइट्स). स्टारहर्मिट डीईआर की अपेक्षा है, इसलिए इसे परिवर्तित करें - नीचे दिया गया मॉड्यूल करता है।

// One key per installation. The private key can sign but is never exported.
export async function createDeviceKey(keyType = 'Ed25519') {
  if (!['Ed25519', 'ECDSA-P256'].includes(keyType)) throw new Error('This helper supports Ed25519 or ECDSA-P256');
  const algorithm = keyType === 'Ed25519'
    ? { name: 'Ed25519' }
    : { name: 'ECDSA', namedCurve: 'P-256' };
  const pair = await crypto.subtle.generateKey(algorithm, false, ['sign', 'verify']);
  return {
    keyType: keyType === 'Ed25519' ? 'Ed25519' : 'ECDSA-P256',
    keyData: b64(await crypto.subtle.exportKey('raw', pair.publicKey)),
    privateKey: pair.privateKey,
  };
}

निजी कुंजी को वहां संग्रहीत करें जहां ऑपरेटिंग सिस्टम उसकी सुरक्षा करता है। किसी ब्राउज़र या इलेक्ट्रॉन रेंडरर में, एक गैर-निकालने योग्य CryptoKey IndexedDB में इसे वैसे ही रखा जा सकता है जैसे यह है। एक देशी खेल का उपयोग करना चाहिए प्लेटफ़ॉर्म कीस्टोर - विंडोज डीपीएपीआई या सीएनजी, मैकओएस किचेन, लिनक्स पर लिबसेक्रेट। इकट्ठा करना keyType और keyData इसके बगल में; आप उन्हें हर अनुरोध के साथ भेजते हैं।

2. पंजीकरण प्रारंभ करें

खिलाड़ी का ईमेल पता और सहमति पूछें, फिर:

async function post(path, body) {
  const res = await fetch(API + path, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  });
  return { status: res.status, body: await res.json().catch(() => ({})) };
}

function fail(step, { status, body }) {
  return Object.assign(new Error(`${step}: ${body.error ?? status}`), { status, body });
}

export async function register(key, email) {
  const res = await post('/api/v1/auth/public-key/register',
    { email, keyType: key.keyType, keyData: key.keyData });
  if (res.status !== 202) throw fail('register', res);
  return res.body; // { registrationId, email, emailSent, deferralReason, message }
}

202 इसका मतलब है कि StarHermit ने पंजीकरण स्वीकार कर लिया है। अगर emailSent है false, ईमेल कतारबद्ध है और अभी भी आएँगे; deferralReason कहता है कि इसका इंतजार क्यों किया गया। अभी तक किसी भी खाते से कुछ भी जुड़ा नहीं है.

तीन नियम आपके यूआई को आकार देते हैं:

  • प्रत्येक 24 घंटे में प्रति ईमेल पते पर एक पंजीकरण और प्रति आईपी पते पर एक पंजीकरण। दूसरा प्रयास है 429 साथ Retry-After. इसे भेजने से पहले खिलाड़ी से पते की पुष्टि करवा लें, क्योंकि इसमें कोई त्रुटि है उनका एक दिन खर्च होता है। खिलाड़ी के डिवाइस से अनुरोध भेजें, अपने सर्वर के माध्यम से कभी नहीं: प्रत्येक प्लेयर आपके सर्वर का आईपी और उसका एकल दैनिक पंजीकरण साझा करेगा।
  • लिंक 4 घंटे के बाद समाप्त हो जाता है. यदि यह समाप्त हो जाता है, तो खिलाड़ी 24 घंटे के भीतर एक बार फिर से पंजीकरण कर सकता है ऊपर हैं.
  • 400 इसका मतलब है कि ईमेल पता या मुख्य सामग्री अस्वीकार कर दी गई थी; error जो कहता है.

3. कुंजी के साथ साइन इन करें

साइन इन करना एक चुनौती और एक प्रतिक्रिया है। POST /api/v1/auth/public-key/challenge रिटर्न:

{
  "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
  "payload": {
    "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
    "fingerprint": "9c0b7a…",
    "issuer": "starhermit",
    "audience": "starhermit",
    "expiry": "2026-10-09T14:21:41.9264875+00:00",
    "nonce": "NmL+tgMum6HXU/pa3T9xjQ==",
    "clientTimestamp": "2026-10-09T14:16:41.9265739+00:00"
  },
  "expiresIn": 300
}

आप जिस पर हस्ताक्षर करते हैं वह आपको प्राप्त JSON नहीं है। StarHermit हस्ताक्षर को स्वयं सत्यापित करता है का क्रमांकन payload:

  • कॉम्पैक्ट JSON, कोई रिक्त स्थान नहीं;
  • पास्कलकेस सदस्यों के नाम, बिल्कुल क्रम में ChallengeId, Fingerprint, Issuer, Audience, Expiry, Nonce, ClientTimestamp;
  • प्रत्येक मान की प्रतिलिपि बनाई गई बिल्कुल वैसा ही जैसा परोसा गया - तारीखों का विश्लेषण और पुन: स्वरूपण न करें;
  • प्रत्येक + नॉन में इस प्रकार लिखा गया है \u002B. + तिथियों में जैसा है वैसा ही रहता है।

उपरोक्त चुनौती के लिए, हस्ताक्षरित बाइट्स UTF-8 एन्कोडिंग हैं:

{"ChallengeId":"4fc4d72b-4c12-41ca-a500-dc13cccc3865","Fingerprint":"9c0b7a…","Issuer":"starhermit","Audience":"starhermit","Expiry":"2026-10-09T14:21:41.9264875+00:00","Nonce":"NmL\u002BtgMum6HXU/pa3T9xjQ==","ClientTimestamp":"2026-10-09T14:16:41.9265739+00:00"}

इनमें से कोई भी गलत समझें और उत्तर है 401 "Invalid signature.", जिसे दोबारा प्रयास करने से ठीक नहीं किया जा सकेगा।

const FIELDS = ['challengeId', 'fingerprint', 'issuer', 'audience', 'expiry', 'nonce', 'clientTimestamp'];

export function challengeSigningBytes(payload) {
  const members = FIELDS.map((field) => {
    let value = JSON.stringify(payload[field]);
    if (field === 'nonce') value = value.replaceAll('+', '\\u002B');
    return `"${field[0].toUpperCase()}${field.slice(1)}":${value}`;
  });
  return new TextEncoder().encode(`{${members.join(',')}}`);
}

export async function signChallenge(key, payload) {
  const data = challengeSigningBytes(payload);
  if (key.keyType === 'Ed25519')
    return b64(await crypto.subtle.sign({ name: 'Ed25519' }, key.privateKey, data));
  // WebCrypto returns an ECDSA signature as raw r||s; the server expects ASN.1 DER.
  const rs = new Uint8Array(
    await crypto.subtle.sign({ name: 'ECDSA', hash: 'SHA-256' }, key.privateKey, data));
  return b64(derEcdsaSignature(rs));
}

function derEcdsaSignature(rs) {
  const integer = (bytes) => {
    let i = 0;
    while (i < bytes.length - 1 && bytes[i] === 0) i++;
    const value = [...bytes.slice(i)];
    return value[0] & 0x80 ? [0x02, value.length + 1, 0, ...value] : [0x02, value.length, ...value];
  };
  const body = [...integer(rs.slice(0, 32)), ...integer(rs.slice(32))];
  return new Uint8Array([0x30, body.length, ...body]);
}

// Resolves to { userId, accessToken, refreshToken }, or null while the key is not attached to
// an account yet — the player has not confirmed, the link expired, or the key was revoked.
export async function signIn(key) {
  const { keyType, keyData } = key;
  const challenge = await post('/api/v1/auth/public-key/challenge', { keyType, keyData });
  if (challenge.status !== 200) throw fail('challenge', challenge);
  const signature = await signChallenge(key, challenge.body.payload);
  const done = await post('/api/v1/auth/public-key/complete',
    { challengeId: challenge.body.challengeId, signature, keyType, keyData });
  if (done.status === 200) return done.body;
  if (done.status === 401 && done.body.error === 'Public key not registered or revoked.') return null;
  throw fail('complete', done); // "Invalid signature." will never succeed: fix it, don't retry it
}

एक चुनौती पाँच मिनट तक चलती है और एकल-उपयोग होती है, भले ही प्रयास विफल हो जाए, इसलिए नए सिरे से अनुरोध करें हर प्रयास के लिए. चुनौती दें और प्रति आईपी पते पर प्रति मिनट 60 अनुरोधों की सीमा साझा करें।

4. खिलाड़ी द्वारा पुष्टि किए जाने तक प्रतीक्षा करें

ईमेल किया गया लिंक एक StarHermit पेज खोलता है जिसमें बताया गया है कि पुष्टि करने से क्या होगा; इसे खोलने पर परिवर्तन हो जाता है कुछ भी नहीं, इसलिए लिंक का पूर्वावलोकन करने वाला मेल स्कैनर खिलाड़ी की ओर से पुष्टि नहीं कर सकता है। जब खिलाड़ी दबाता है पुष्टि करना, StarHermit अपना खाता बनाता है, आपकी कुंजी संलग्न करता है और पता चिह्नित करता है सत्यापित. यदि कोई खाता पहले से ही उस पते का उपयोग करता है, तो पृष्ठ ऐसा कहता है और कुंजी उसमें जोड़ दी जाती है इसके बजाय, जिस खिलाड़ी के पास पहले से ही स्टारहर्मिट खाता है वह इसे रखता है। फिर वे Starhermit.com पर उतरते हैं StarHermit डैशबोर्ड पर, पहले से ही साइन इन है।

आपके गेम को उस पेज से कभी भी टोकन प्राप्त नहीं होंगे, और उनकी जरूरत नहीं है. खिलाड़ी हो सकता है फ़ोन पर या किसी अन्य ब्राउज़र में पुष्टि करें। एक बार कुंजी संलग्न हो जाने पर, आपका गेम आसानी से साइन इन हो सकता है इसके साथ. तो दिखाओ ए "अपने इनबॉक्स की जाँच करें" स्क्रीन करें और प्रयास करते रहें:

// Poll until the player confirms the emailed link. Two requests per attempt, so every 5 s stays
// well inside the 60-per-minute sign-in limit.
export async function waitUntilConfirmed(key, { intervalMs = 5000, signal } = {}) {
  for (;;) {
    signal?.throwIfAborted();
    const session = await signIn(key);
    if (session) return session;
    await new Promise((resolve) => setTimeout(resolve, intervalMs));
  }
}

चरण 1 से 4 को एक साथ रखना:

import { createDeviceKey, register, signIn, waitUntilConfirmed } from './starhermit-key-auth.js';

const key = await loadStoredKey() ?? await saveKey(await createDeviceKey());

if (!session) {
  const email = await askForEmailAndConsent();

  showCheckYourInbox(email);
  session = await waitUntilConfirmed(key, { signal: cancelButton.signal });
}

loadStoredKey, saveKey, askForEmailAndConsent और showCheckYourInbox क्या आप लिखने वाले हैं? प्रस्ताव ए रद्द करना जो प्रतीक्षा को समाप्त कर देता है, और चार घंटे के बाद, जब लिंक समाप्त हो जाता है, मतदान रोक देता है।

भले ही आपके प्लेटफ़ॉर्म का पुष्टिकरण पृष्ठ आपकी साइट पर वापस रीडायरेक्ट हो, तब भी मतदान जारी रखें। खिलाड़ी अक्सर ईमेल को प्रतीक्षारत डिवाइस से भिन्न डिवाइस पर खोलता है, और फिर रीडायरेक्ट कहीं नहीं होता है आपकी प्रतीक्षा स्क्रीन के पास; मतदान वह है जो प्रतीक्षा उपकरण को संकेत देता है। यदि रीडायरेक्ट आता है दूसरे टैब में, उनमें से केवल एक के साथ साइन इन करें और अतिरिक्त सत्र रद्द करें, या खिलाड़ी समाप्त हो जाएगा दो के साथ.

5. सत्र रखें

complete 15 मिनट का एक्सेस टोकन और एक ताज़ा टोकन लौटाता है जो सात दिनों तक चलता है और घूमता है। एक्सेस टोकन को इस रूप में भेजें Authorization: Bearer …, और समाप्त होने से पहले ताज़ा करें:

// Resolves to the new pair, or null when the session is over — sign in with the key again.
export async function refresh(refreshToken) {
  const res = await post('/api/v1/auth/refresh', { refreshToken });
  return res.status === 200 ? res.body : null; // { accessToken, refreshToken }
}

प्रतिस्थापित करें दोनों हर बार टोकन. उपयोग किए गए ताज़ा टोकन को प्रस्तुत करने से पूरा सत्र समाप्त हो जाता है, इसलिए बनाएं सुनिश्चित करें कि दो थ्रेड या प्रक्रियाएँ कभी भी एक साथ ताज़ा नहीं होतीं। कब refresh रिटर्न null, पुकारना signIn — कोई ईमेल शामिल नहीं है. कुंजी लंबे समय तक जीवित रहने वाली साख है; टोकन इसका एक कैश मात्र हैं।

6. खाता सेट करना समाप्त करें

शर्तें। किसी भी अन्य चीज़ का उपयोग करने से पहले एक नए खाते को वर्तमान StarHermit शर्तों को स्वीकार करना होगा। पुकारना GET /api/v1/me. अगर termsAcceptanceRequired है true, से पाठ दिखाएँ GET /api/v1/terms, और जब खिलाड़ी इसे स्वीकार कर ले, तो इसका हैश भेज दें POST /api/v1/me/terms/accept. बाद के लॉन्च पर दोबारा जांच करें, क्योंकि शर्तें संशोधित हैं। विवरण: शर्तें स्वीकृति.

नाम। खाता a से शुरू होता है pk-… उपयोक्तानाम. खिलाड़ी को एक उपनाम चुनने दें:

PATCH /api/v1/me
Authorization: Bearer <access-token>
Content-Type: application/json

{ "nickname": "RookPilot" }

यहां से खाता किसी भी अन्य खाते की तरह है: दोस्त, चैट, मंगनी, क्लाउड सेव, उपलब्धियां।

7. दूसरा उपकरण, खोई हुई चाबियाँ, और सीमाएँ

एक दूसरा उपकरण अपनी स्वयं की कुंजी बनाता है और उसे पंजीकृत करता है वही ईमेल पता. जब खिलाड़ी पुष्टि करता है, कुंजी नया खाता बनाने के बजाय उनके मौजूदा खाते से जुड़ जाती है। 24 घंटे प्रति पते की सीमा यहां भी लागू होती है।

खोया हुआ या चोरी हुआ उपकरण. POST /api/v1/auth/public-key/revoke-request साथ { "email": "…" } किसी पृष्ठ का लिंक ईमेल करता है; वहां पुष्टि करने से निरस्त हो जाता है प्रत्येक खाते पर कुंजी डालें और सत्र समाप्त करें उन कुंजियों में साइन इन किया गया है। केवल लिंक खोलने से कुछ भी नहीं बदलता है। अनुरोध हमेशा उत्तर देता है 202 एक ही संदेश के साथ, चाहे या नहीं पते का एक खाता है. लिंक चार घंटे के बाद समाप्त हो जाता है, और एक खाता हर 15 में एक बार पूछ सकता है मिनट. बाद में, प्रत्येक शेष डिवाइस फिर से पंजीकृत होता है (चरण 2)।

केवल कुंजी वाला खाता क्या नहीं कर सकता. कुछ परिवर्तन खाते की साख की रक्षा करते हैं, इसलिए वे ऐसे सत्र की आवश्यकता है जिसमें Google या GitHub जैसे प्रदाता के माध्यम से साइन इन किया गया हो:

कार्रवाई केवल-कुंजी खाता
एक कुंजी जोड़ें या अन्य डिवाइस निरस्त करें (POST /me/public-keys, DELETE /me/public-keys/{id} या /all) 403 - ईमेल पंजीकरण के माध्यम से नामांकन करें, या OAuth-प्रमाणीकृत सत्र का उपयोग करें
खाते का ईमेल पता बदलें 403 oauth_session_required - जब तक कोई प्रदाता लिंक न हो तब तक संभव नहीं है
इस संस्थापन की अपनी कुंजी को निरस्त करें DELETE /api/v1/me/public-keys/current, अपने पूर्ण सार्वजनिक-कुंजी खाता सत्र का उपयोग करके; सफलता के बाद स्थानीय साख को त्यागें

अन्य क्रेडेंशियल प्रबंधित करने या ईमेल बदलने के लिए, किसी प्रदाता को लिंक करें। जब कोई केवल-कुंजी खाता किसी एक को लिंक करता है, तो लिंक रुका रहता है जब तक खिलाड़ी अपने ईमेल से इसकी पुष्टि नहीं कर देता। उसके बाद, एक प्रदाता साइन-इन उपरोक्त सभी कार्य कर सकता है। देखना authorize?link=true.
