उस गेम का दावा करें जिसे किसी और ने जोड़ा है

यदि किसी ने पहले ही आपके सार्वजनिक GitHub गेम को StarHermit में जोड़ दिया है, तो आपको इसे बनाने की आवश्यकता नहीं है दूसरी सूची. मौजूदा लिस्टिंग का सत्यापित स्वामी बनने का दावा करें और उसके मेटाडेटा का प्रबंधन करें, होस्टिंग, परिनियोजन, सर्वर बैकएंड और भविष्य के स्थानांतरण।

दावा रिपॉजिटरी नियंत्रण द्वारा संरक्षित है। गेम आईडी या रिपॉजिटरी यूआरएल जानना पर्याप्त नहीं है। आपको दो तरीकों में से एक में नियंत्रण साबित करना होगा:

  1. उस व्यक्तिगत GitHub खाते को लिंक करें जो रिपॉजिटरी का स्वामी है; या
  2. अपनी अपरिवर्तनीय StarHermit उपयोगकर्ता आईडी को इस रूप में प्रतिबद्ध करें owner= भंडार में starhermit.txt.

दूसरी विधि संगठन के स्वामित्व वाली रिपॉजिटरी के लिए विशेष रूप से उपयोगी है, क्योंकि वर्तमान GitHub-लॉगिन जांच व्यक्तिगत रिपॉजिटरी मालिकों से मेल खाती है और संगठन की सदस्यता का अनुमान नहीं लगाती है।

क्या दावा करने से बदलाव आता है

एक सफल दावा:

  • मौजूदा गेम/लिस्टिंग आईडी और उसका संचित इतिहास रखता है;
  • लिस्टिंग के प्रबंधित StarHermit उपयोगकर्ता को आपके लिए बदल देता है;
  • सूची को इस रूप में चिह्नित करता है isVerifiedOwner: true;
  • विश्वसनीय मेटाडेटा और नियंत्रणों को ताज़ा करता है starhermit.txt जहां लागू हो;
  • घोषित स्क्रिप्ट/कंटेनर बैकएंड को प्रावधानित या ताज़ा करता है;
  • जहां उपलब्ध हो वहां प्लेटफ़ॉर्म होस्टिंग सक्षम करता है और कतार परिनियोजन को सक्षम बनाता है pending;
  • उस व्यक्ति से प्रबंधन पहुंच हटा देता है जिसने मूल रूप से वह सूची सबमिट की थी।

दावा करने से पिछले सबमिटर को आपके GitHub खाते तक पहुंच नहीं मिलती है, और यह विलय नहीं होता है स्टारहर्मिट उपयोगकर्ता खाते। यह उस विशिष्ट सूची का प्रबंधन स्थानांतरित करता है।

शुरू करने से पहले

आप की जरूरत है:

  • एक StarHermit खाता और पूर्ण उपयोगकर्ता एक्सेस टोकन—गेम-स्कोप्ड लॉन्च टोकन नहीं।
  • यदि का उपयोग कर रहे हैं तो रिपॉजिटरी तक पहुंच लिखें owner= प्रमाण विधि.
  • मौजूदा स्टारहर्मिट लिस्टिंग आईडी।
  • क्लोन रिपॉजिटरी गेम के लिए, एक वैध starhermit.txt रिपोजिटरी रूट पर.

केवल github.com/<owner>/<repo> रिपॉजिटरी और उनकी GitHub पेज साइटें इस दावे में भाग लेती हैं प्रवाह. एक मनमाने ढंग से होस्ट किए गए यूआरएल के पास साबित करने के लिए कोई GitHub रिपॉजिटरी स्वामित्व नहीं है और इस पर दावा नहीं किया जा सकता है रास्ता.

नीचे दिए गए उदाहरण उपयोग करें:

API=https://api.starhermit.com
ACCESS_TOKEN='your-full-user-access-token'
OWNER='your-github-login'
REPO='your-game-repository'

एक्सेस टोकन 15 मिनट तक चलते हैं। यदि समाप्ति तिथि निकट हो तो शुरू करने से पहले उसे ताज़ा कर लें।

चरण 1: मौजूदा सूची ढूंढें

साझा किए गए गेम की सूची बनाएं:

curl -sS "$API/api/v1/github-games" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

प्रत्येक आइटम में अपरिवर्तनीय सूची शामिल है id, सामान्यीकृत repoUrl, ownerLogin, repoName, द वर्तमान जमाकर्ता, और स्वामित्व स्थिति:

{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "repoUrl": "https://github.com/octocat/orbit-league",
  "ownerLogin": "octocat",
  "repoName": "orbit-league",
  "displayName": "Orbit League",
  "isVerifiedOwner": false,
  "submittedByUserId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "submittedByUsername": "someone-else"
}

दोनों पर मिलान ownerLogin और repoName; किसी गेम का चयन केवल इसलिए न करें क्योंकि उसका डिस्प्ले नाम है समान. साथ jq:

GAME_ID=$(
  curl -sS "$API/api/v1/github-games" \
    -H "Authorization: Bearer $ACCESS_TOKEN" |
  jq -r --arg owner "$OWNER" --arg repo "$REPO" \
    '.[] | select((.ownerLogin | ascii_downcase) == ($owner | ascii_downcase)
               and (.repoName | ascii_downcase) == ($repo | ascii_downcase)) | .id' |
  head -n1
)

printf 'Listing ID: %s\n' "$GAME_ID"

यदि परिणाम खाली हो तो रुकें। किसी असंबद्ध सूची से कॉपी की गई आईडी के साथ दावा न करें।

चरण 2: स्वामित्व साबित करने का तरीका चुनें

विकल्प A: रिपॉजिटरी स्वामी के GitHub खाते को लिंक करें

इसका उपयोग तब करें जब रिपॉजिटरी सीधे आपके व्यक्तिगत GitHub लॉगिन के स्वामित्व में हो।

StarHermit के खाते/सेटिंग्स प्रवाह से, GitHub OAuth प्रारंभ करें जोड़ना मोड में साइन इन करते समय StarHermit खाता जिसे गेम का प्रबंधन करना चाहिए। लिंक करना आकस्मिक रूप से बनाने से भिन्न है GitHub साइन-इन के साथ दूसरा StarHermit खाता।

एपीआई प्रवाह यहां से शुरू होता है:

GET /api/v1/auth/oauth/github/authorize?link=true

यह ब्राउज़र-चालित है और अल्पकालिक स्थिति कुकी का उपयोग करता है। लिंक करने के लिए नवीनतम StarHermit की आवश्यकता है प्रमाणीकरण. GitHub प्राधिकरण को उसी ब्राउज़र सत्र में पूरा करें जिससे इसे शुरू किया गया था।

परिणाम सत्यापित करें:

curl -sS "$API/api/v1/me/github" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

अपेक्षित:

{ "linked": true, "login": "octocat" }

लौटाया गया लॉगिन मौजूदा लिस्टिंग से मेल खाना चाहिए ownerLogin, केस-असंवेदनशील रूप से। एक निजी GitHub लॉगिन उस संगठन की सदस्यता साबित नहीं करता है जो रिपॉजिटरी का मालिक है। एक के लिए संगठन के स्वामित्व वाली रिपॉजिटरी, विकल्प बी का उपयोग करें।

विकल्प बी: जोड़ें owner= को starhermit.txt

यह नियंत्रण साबित करता है क्योंकि केवल रिपॉजिटरी सामग्री प्रकाशित करने में सक्षम व्यक्ति ही मूल्य जोड़ सकता है। तय करना owner आपकी अपरिवर्तनीय StarHermit उपयोगकर्ता आईडी (UUID) पर, नहीं आपका उपयोगकर्ता नाम या उपनाम.

अपनी आईडी प्राप्त करें:

STARHERMIT_USER_ID=$(
  curl -sS "$API/api/v1/me" \
    -H "Authorization: Bearer $ACCESS_TOKEN" |
  jq -r '.id'
)

रिपॉजिटरी रूट पर, बनाएं या अपडेट करें starhermit.txt:

name=Orbit League
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html
owner=3fa85f64-5717-4562-b3fc-2c963f66afa6

उदाहरण स्वामी को इसके साथ बदलें STARHERMIT_USER_ID. अपना उपयोगकर्ता नाम या उपनाम यहां न रखें; वे बदल सकते हैं, जबकि उपयोगकर्ता आईडी स्थिर स्वामित्व पहचानकर्ता है।

एक आधिकारिक गेम के लिए, बिल्कुल एक बैकएंड घोषणा बनाए रखें:

# JavaScript runtime:
server=server.js

# OR container runtime, never both:
# container.image=ghcr.io/your-org/orbit-server@sha256:<64-lowercase-hex>

मेनिफेस्ट को रिपॉजिटरी/संस्करण पर प्रतिबद्ध करें और पुश करें StarHermit पढ़ सकता है:

git add starhermit.txt
git commit -m "Declare StarHermit game ownership"
git push

दावा करने से पहले रिपॉजिटरी का कच्चा माल खोलें starhermit.txt एक अप्रमाणित ब्राउज़र में यूआरएल और पुष्टि करें कि नया मान सार्वजनिक रूप से पढ़ने योग्य है। दावा करने वाला अनुरोध समय पर भंडार को पढ़ता है; एक बिना दबाव वाला स्थानीय परिवर्तन कुछ भी सिद्ध नहीं कर सकता।

चरण 3: मेनिफेस्ट को सत्यापित करें

एक सामान्य क्लोन रिपॉजिटरी गेम के लिए, दावा करने के लिए आवश्यक है:

  • starhermit.txt रिपॉजिटरी रूट पर;
  • गैर खाली name=;
  • launch= एक भंडार-सापेक्ष की ओर इशारा करते हुए .html या .htm फ़ाइल;
  • एक वैध वैकल्पिक server= पथ समाप्त हो रहा है .js/.mjs, या एक वैध container.image= घोषणा;
  • कभी भी दोनों सर्वर रनटाइम एक साथ नहीं होते।

GitHub पेज सूची अपने होस्ट किए गए URL को लॉन्च लक्ष्य के रूप में रखती है और इसके लिए मैनिफ़ेस्ट की आवश्यकता नहीं होती है जब व्यक्तिगत GitHub स्वामित्व सिद्ध हो जाता है, हालाँकि एक वैध मैनिफ़ेस्ट नाम अभी भी इसे अपडेट कर सकता है प्रदर्शन नाम.

यदि गेम एक कंटेनर घोषित करता है, तो उसकी छवि को रजिस्ट्री, मालिक नेमस्पेस और डाइजेस्ट को संतुष्ट करना होगा में नियम कंटेनर-होस्टेड गेम सर्वर. कंटेनर होस्टिंग भी हो सकती है प्लेटफ़ॉर्म ऑपरेटर द्वारा प्रतिबंधित।

चरण 4: लिस्टिंग का दावा करें

दावा अनुरोध का कोई निकाय नहीं है:

curl -sS -X POST \
  "$API/api/v1/me/github-games/$GAME_ID/claim" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

एक सफल 200 अद्यतन गेम लौटाता है:

{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "repoUrl": "https://github.com/octocat/orbit-league",
  "ownerLogin": "octocat",
  "repoName": "orbit-league",
  "displayName": "Orbit League",
  "launchPath": "index.html",
  "gameSlug": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "isVerifiedOwner": true,
  "metadataSource": "starhermit.txt",
  "hosting": {
    "hostingEnabled": true,
    "deployStatus": "pending"
  }
}

आईडी वही होनी चाहिए जो चरण 1 में पाई गई थी। सफल दावे के बाद नई सूची न बनाएं।

जिस सूची को आप पहले से प्रबंधित कर रहे हैं उस पर दावा करने की जानबूझकर अनुमति दी गई है। यह मैनिफेस्ट को दोबारा पढ़ता है, बैकएंड को पुन: प्रावधान करता है, और होस्टिंग की आवश्यकता करता है, इसलिए उसी कॉल का उपयोग पुन: सिंक्रनाइज़ करने के लिए किया जा सकता है रिपॉजिटरी परिवर्तन के बाद मालिक द्वारा प्रबंधित गेम।

चरण 5: अधिग्रहण और तैनाती को सत्यापित करें

पुष्टि करें कि गेम अब आपकी प्रबंधित सूची में दिखाई देता है:

curl -sS "$API/api/v1/me/github-games" \
  -H "Authorization: Bearer $ACCESS_TOKEN" |
jq --arg id "$GAME_ID" '.[] | select(.id == $id)'

परिनियोजन स्थिति की जाँच करें:

curl -sS \
  "$API/api/v1/me/github-games/$GAME_ID/deployment" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

एक दावा आम तौर पर एक तैनाती को कतारबद्ध करता है, इसलिए pending दावा सामान्य होने के तुरंत बाद. के साथ मतदान करें जब तक यह पर्यावरण की लाइव/सफलता की स्थिति तक नहीं पहुंच जाता या उजागर नहीं हो जाता, तब तक बैकऑफ़ करें deployError.

अधिग्रहण के बाद, आपके लिए उपलब्ध प्रबंधन समापन बिंदुओं में शामिल हैं:

PUT    /api/v1/me/github-games/{id}/deployment  pin a commit/branch and redeploy
POST   /api/v1/me/github-games/{id}/bundle      upload built client/container output
PUT    /api/v1/me/github-games/{id}/hosting     requeue hosting where supported
POST   /api/v1/me/github-games/{id}/transfer    transfer management deliberately
DELETE /api/v1/me/github-games/{id}             remove the game

मूल प्रस्तुतकर्ता अब इस सूची को नीचे नहीं देखता है GET /api/v1/me/github-games और नहीं कर सकते इसके लिए इन स्वामी-दायरे वाले प्रबंधन समापन बिंदुओं का उपयोग करें।

समस्या निवारण

403: रिपॉजिटरी स्वामी को लिंक करें या जोड़ें owner=

लिंक किया गया GitHub लॉगिन मेल नहीं खाता ownerLogin, या प्रकट owner बिल्कुल मेल नहीं खाता आपकी स्टारहर्मिट उपयोगकर्ता आईडी।

  • जाँच करना GET /api/v1/me/github.
  • सटीक जांचें ownerLogin सार्वजनिक सूची द्वारा लौटाया गया।
  • संगठन भंडार के लिए, उपयोग करें owner=<your StarHermit user ID> रेपो में.
  • पुष्टि करें कि आपने मेनिफेस्ट को आगे बढ़ाया है और इसका कच्चा यूआरएल सार्वजनिक रूप से पढ़ने योग्य है।

404: उस आईडी के साथ कोई साझा गेम नहीं

आईडी ग़लत है, या सूची हटा दी गई है. चरण 1 दोहराएँ। हटाई गई सूचियाँ दावा योग्य नहीं हैं।

400: गुम या अमान्य starhermit.txt

क्लोन रिपॉजिटरी के लिए, सुनिश्चित करें कि रूट मेनिफेस्ट वैध है name और एचटीएमएल launch मूल्य. साथ ही वैकल्पिक स्क्रिप्ट/कंटेनर घोषणाओं को मान्य करें। दावा मूल रूप से मेटाडेटा पर भरोसा नहीं करता है किसी गैर-मालिक द्वारा दर्ज किया गया; यह इसे रिपॉजिटरी-नियंत्रित मेटाडेटा से बदल देता है।

दावा स्लग/बैकएंड के आसपास विफल हो जाता है

स्क्रिप्ट अमान्य हो सकती है या कंटेनर होस्टिंग अनुपलब्ध हो सकती है। लौटाई गई त्रुटि की जाँच करें और बैकएंड घोषणा, फिर दोबारा दावा कॉल करें। प्लेटफ़ॉर्म गेम के UUID को इसके स्लग के रूप में निर्दिष्ट करता है; चुनने या हल करने के लिए कोई स्पष्ट स्लग नहीं है।

GitHub लिंक किया गया था लेकिन गलत StarHermit खाता लिंक का स्वामी है

इच्छित StarHermit खाते में साइन इन करें और OAuth पूरा करें जोड़ना वहाँ बहो. दावा मत करो एक अस्थायी दूसरे StarHermit खाते से और फिर खाते के विलय पर भरोसा करें; एपीआई गेम ट्रांसफर करता है प्रबंधन, उपयोगकर्ता पहचान नहीं।

सुरक्षा नोट

  • रिपॉजिटरी स्वामित्व के प्रमाण के रूप में दावा लिंक या लिस्टिंग आईडी को कभी भी स्वीकार न करें।
  • GitHub एक्सेस टोकन, कंटेनर क्रेडेंशियल या अन्य रहस्य न डालें starhermit.txt.
  • हमेशा अपरिवर्तनीय StarHermit उपयोगकर्ता आईडी का उपयोग करें owner=; उपयोगकर्ता नाम या उपनाम का उपयोग न करें.
  • दावा करने से पहले मौजूदा लिस्टिंग और रिपोजिटरी यूआरएल की समीक्षा करें; प्रदर्शन नाम अद्वितीय नहीं हैं.
  • यदि आप बाद में गेम स्थानांतरित करते हैं, तो प्राप्तकर्ता प्रबंधक बन जाता है लेकिन सत्यापित-स्वामी की स्थिति बन जाती है रीसेट करें. यदि वे भंडार को नियंत्रित करते हैं तो उन्हें दावा प्रवाह स्वयं चलाना होगा।
