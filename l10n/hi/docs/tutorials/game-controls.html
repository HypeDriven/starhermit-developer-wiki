ट्यूटोरियल: अपने गेम में नियंत्रण जोड़ें

स्टारहर्मिट स्टोर कर सकता है कुंजी बाइंडिंग आपके गेम के लिए: आप क्रियाओं और उनकी डिफ़ॉल्ट कुंजियों की घोषणा करते हैं, और प्रत्येक खिलाड़ी उन्हें दोबारा जोड़ सकता है। उनकी पसंद उन्हें किसी भी मशीन पर ले जाती है जिस पर वे साइन इन करते हैं। आपका खेल नियंत्रण एपीआई से प्लेयर की बाइंडिंग पढ़ता है और अपनी पेशकश कर सकता है "कुंजियाँ पुनः बाँधें" स्क्रीन।

यदि आपका गेम नियंत्रण API को कॉल करता है और यह प्राप्त करता है:

404 {"error":"This game declares no controls."}

मंच है कोई घोषित कार्रवाई नहीं निर्माण के लिए यह सेवा दे रहा है। आप एपीआई को कुछ भी नहीं भेज सकते इसे ठीक करें: आपके गेम में नियंत्रण घोषित किए गए हैं starhermit.txt और कब पढ़ें खेल प्रकाशित हो चुकी है।. यह पृष्ठ दिखाता है कि उन्हें कैसे घोषित किया जाए, उन्हें प्रकाशित किया जाए, जाँच की जाए कि वे आ गए हैं, और उन्हें अपने ग्राहक से उपयोग करें।

  1. कार्रवाई की घोषणा करें
  2. उन्हें प्रकाशित करें
  3. जांचें कि वे पहुंचे
  4. अपने खेल में उनका उपयोग करें
  5. समस्या निवारण

1. कार्यों की घोषणा करें

एक जोड़ें control.<action>= प्रति क्रिया पंक्ति starhermit.txt:

name=Space Hopper
launch=index.html

control.left=KeyA+ArrowLeft | Move left
control.right=KeyD+ArrowRight | Move right
control.jump=Space+KeyW | Jump
control.fire=KeyJ | Fire
control.pause=Escape | Pause

प्रत्येक पंक्ति में तीन भाग होते हैं:

control.<action>=<code>[+<code>...][ | <label>]
भाग नियम
<action> कार्रवाई के लिए आपके गेम का नाम: छोटे अक्षरों, अंकों आदि के 1-32 अक्षर _ (move_left, नहीं move-left). अद्वितीय प्रति प्रकट.
<code> A KeyboardEvent.code मान, जैसे KeyA, ArrowLeft, Space, Digit1, ShiftLeft, Enter या Escape. समान क्रिया के लिए 1-4 कोड जोड़ें +.
<label> वैकल्पिक। रीबाइंडिंग स्क्रीन में दिखाया गया; अधिकतम 64 अक्षर. क्रिया नाम पर डिफ़ॉल्ट.

जानने योग्य बातें:

  • उपयोग code, नहीं key. लिखना KeyA, नहीं a, और Space, नहीं " ". कोड भौतिक को नाम देते हैं कुंजी, इसलिए बाइंडिंग किसी भी कीबोर्ड लेआउट पर काम करती है। प्लेटफ़ॉर्म केवल यह जाँचता है कि कोई कोड 1-32 है अक्षर और अंक, तो a या space स्वीकार किया जाता है लेकिन कोई भी कुंजी इसे कभी उत्पन्न नहीं करती है। वर्तनी और मामला बिल्कुल मेल खाना चाहिए.
  • एक कुंजी एक क्रिया से संबंधित होती है. पिछली पंक्ति द्वारा पहले से उपयोग किया गया कोड बाद की पंक्ति बनाता है अमान्य.
  • 32 क्रियाओं तक प्रति खेल. 32 तारीख के बाद की पंक्तियों को नजरअंदाज कर दिया जाता है।
  • आदेश रखा गया है. क्रियाएँ एपीआई से स्पष्ट क्रम में वापस आती हैं, इसलिए उन्हें इस प्रकार सूचीबद्ध करें आपकी सेटिंग्स स्क्रीन को उन्हें दिखाना चाहिए।
  • एक अमान्य पंक्ति चुपचाप छोड़ दी जाती है. गेम अभी भी प्रकाशित होता है. यदि प्रत्येक पंक्ति अमान्य है, गेम में कोई नियंत्रण नहीं है और एपीआई उत्तर देता है 404. प्रकाशन के बाद जांचें.

2. उन्हें प्रकाशित करें

घोषणापत्र पढ़े जाते हैं जब खेल प्रकाशित हो जाता है. संपादन starhermit.txt आपके भंडार में या डिस्क पर तब तक कुछ भी नहीं बदलता जब तक कि आप उस बिल्ड को प्रकाशित नहीं करते जिसमें यह शामिल है:

आपका गेम कैसे प्रकाशित होता है नए नियंत्रणों को क्या जीवंत बनाता है
GitHub रिपोजिटरी से आपकी अगली तैनाती. परिवर्तन को आगे बढ़ाएं, फिर नवीनतम संस्करण तैनात करें (परिनियोजित संस्करण अद्यतन करें डैशबोर्ड में, या PUT /api/v1/me/github-games/{id}/deployment).
अपलोड किया गया फ़ोल्डर या बंडल एक नया बिल्ड अपलोड करें (POST /api/v1/me/github-games/{id}/bundle, या ws/v1/game-upload) किसका starhermit.txt पंक्तियाँ हैं.
एक नया गेम जोड़ा जा रहा है पहला अपलोड या सबमिशन उन्हें तुरंत पढ़ता है।

एक प्रतिस्थापित अपलोड आपके नियंत्रणों को उसके स्वयं के मेनिफ़ेस्ट से पुनर्स्थापित करता है। प्रत्येक को हटा दें control.* लाइन और खेल में कुछ भी नहीं है. ए ?mode=merge उसे पैच करो नंबर वहन करता है starhermit.txt वर्तमान नियंत्रण रखता है.

खिलाड़ियों की अपनी रिबाइंडिंग एक नए निर्माण से बची रहती है। किसी खिलाड़ी की उस कार्रवाई के लिए बाइंडिंग सहेजी गई है जो नहीं है लंबे समय तक मौजूद रहने पर ध्यान नहीं दिया जाता है।

3. जांचें कि वे पहुंचे

नीचे दिया गया प्रत्येक समापन बिंदु पूर्ण उपयोगकर्ता टोकन या आपके गेम के लॉन्च टोकन के साथ काम करता है। {slug} आपका है गेम का स्लग: लॉन्च टोकन game_scope दावा, या gameSlug में GET /api/v1/me/github-games.

curl -s "https://api.starhermit.com/api/v1/games/$SLUG/controls" \
  -H "Authorization: Bearer $TOKEN" | jq

{
  "actions": [
    { "action": "left",  "label": "Move left",  "defaultCodes": ["KeyA", "ArrowLeft"],  "codes": ["KeyA", "ArrowLeft"] },
    { "action": "right", "label": "Move right", "defaultCodes": ["KeyD", "ArrowRight"], "codes": ["KeyD", "ArrowRight"] },
    { "action": "jump",  "label": "Jump",       "defaultCodes": ["Space", "KeyW"],      "codes": ["Space", "KeyW"] },
    { "action": "fire",  "label": "Fire",       "defaultCodes": ["KeyJ"],               "codes": ["KeyJ"] },
    { "action": "pause", "label": "Pause",      "defaultCodes": ["Escape"],             "codes": ["Escape"] }
  ]
}

गुम कार्रवाइयों का मतलब है कि उनकी पंक्तियाँ अमान्य थीं; उपरोक्त नियमों से उनकी तुलना करें। ए 404 इसका मतलब है कि कोई भी जीवित नहीं बचा, या उन्हें घोषित करने वाली रचना अभी तक प्रकाशित नहीं हुई है।

4. अपने खेल में उनका प्रयोग करें

codes खिलाड़ी का प्रभावी बंधन है: यदि वे एक सेट करते हैं तो उनका ओवरराइड, अन्यथा आपका डिफ़ॉल्ट। इससे एक लुकअप बनाएं और मिलान करें event.code:

const auth = { Authorization: `Bearer ${launchToken}` };

// Your built-in defaults, in the same shape the API returns.
const DEFAULT_ACTIONS = [
  { action: "left", label: "Move left", codes: ["KeyA", "ArrowLeft"] },
  { action: "jump", label: "Jump", codes: ["Space", "KeyW"] },
  /* ... */
];

function toControls(actions) {
  const byCode = new Map();
  for (const a of actions) for (const code of a.codes) byCode.set(code, a.action);
  return { actions, byCode };
}

async function loadControls(slug) {
  try {
    const res = await fetch(`/api/v1/games/${slug}/controls`, { headers: auth });
    if (res.ok) return toControls((await res.json()).actions);
  } catch { /* offline: fall through */ }
  return toControls(DEFAULT_ACTIONS);                   // 404, error, or outside StarHermit
}

let controls = await loadControls(gameScope);

window.addEventListener("keydown", (e) => {
  const action = controls.byCode.get(e.code);   // e.code, never e.key
  if (action) { e.preventDefault(); onAction(action, true); }
});
window.addEventListener("keyup", (e) => {
  const action = controls.byCode.get(e.code);
  if (action) onAction(action, false);
});

बिल्ट-इन डिफॉल्ट्स गेम को ऑफ़लाइन, स्टारहर्मिट के बाहर, या यदि नियंत्रण रखते हैं, खेलने योग्य रखते हैं अनुरोध विफल रहता है. उन्हें अपने साथ कदम से कदम मिला कर रखें control.* पंक्तियाँ.

एक रिबाइंडिंग स्क्रीन. सूची actions साथ उनके label. पूरा ओवरराइड मानचित्र रखें, या एक कार्रवाई बदलने से पहले वर्तमान प्रभावी मानचित्र को पढ़ें और संरक्षित करें:

async function saveBinding(slug, action, codes) {
  const current = await fetch(`/api/v1/games/${slug}/controls`, { headers: auth });
  if (!current.ok) throw new Error(`Controls read failed: ${current.status}`);
  const bindings = Object.fromEntries((await current.json()).actions.map(a => [a.action, a.codes]));
  bindings[action] = codes;
  const res = await fetch(`/api/v1/games/${slug}/controls`, {
    method: "PUT",
    headers: { ...auth, "Content-Type": "application/json" },
    body: JSON.stringify({ bindings }),
  });
  if (!res.ok) throw new Error((await res.json()).error);   // e.g. a key already in use
  return res.json();                                         // the new effective map
}

PUT खिलाड़ी के ओवरराइड को आपके द्वारा भेजे गए कार्यों से बदल देता है, इसलिए खिलाड़ी के प्रत्येक कार्य को शामिल करें बदल गया है, केवल नवीनतम नहीं। बाकी आपके डिफ़ॉल्ट पर बने रहेंगे. DELETE उसी रास्ते पर सब कुछ डिफ़ॉल्ट पर रीसेट कर देता है।

अपनी स्क्रीन से परिवर्तनों को क्रमबद्ध करें; दो एक साथ पढ़ने/लिखने पर भी एक-दूसरे को अधिलेखित किया जा सकता है। ब्राउज़र SDK setControl() अपने स्वयं के परिवर्तनों को क्रमबद्ध करता है और वर्तमान प्रभावी मानचित्र को संरक्षित करता है। प्रभावी मानचित्र भेजने से उन मानों को ओवरराइड के रूप में पिन कर दिया जाता है; उपयोग DELETE प्रकट डिफ़ॉल्ट पर लौटने के लिए।

प्लेटफ़ॉर्म ने सेव करने से इंकार कर दिया (400) जो दो कार्यों पर एक कुंजी छोड़ देगा बाद खिलाड़ी का परिवर्तन आपके डिफ़ॉल्ट के साथ विलय कर दिए जाते हैं। उदाहरण के लिए, बाइंडिंग jump को KeyJ जबकि fire अभी भी अपने डिफ़ॉल्ट का उपयोग करता है KeyJ मना कर दिया जाता है. त्रुटि दिखाएं, या विरोधाभासी कार्रवाई को उसी में स्थानांतरित करें सहेजें.

समस्या निवारण

प्रतिक्रिया कारण हल करना
404 "यह गेम कोई नियंत्रण नहीं होने की घोषणा करता है।" कोई मान्य नहीं control.* में लाइन प्रकाशित निर्माण। इसमें पंक्तियाँ जोड़ें starhermit.txt, उनके विरुद्ध जाँच करें नियम, और एक नया निर्माण प्रकाशित करें.
404 "उस स्लग के साथ कोई खेल नहीं।" स्लग ग़लत है, या गेम में कोई स्लग नहीं है। लॉन्च टोकन का उपयोग करें game_scope या gameSlug से GET /me/github-games. स्थानीय फ़ोल्डर से जोड़े गए प्रत्येक गेम और सत्यापित स्वामी द्वारा जोड़े गए प्रत्येक रिपोजिटरी गेम में एक स्लग होता है, चाहे केवल ब्राउज़र हो या नहीं। केवल एक रिपॉजिटरी सबमिशन जिसका मालिक सत्यापित नहीं है, उसके पास कोई नहीं है; इसपर दावा करो एक पाने के लिए.
403 "यह टोकन गेम '...' तक सीमित है।" किसी अन्य गेम के स्लग के साथ उपयोग किया जाने वाला लॉन्च टोकन। टोकन में स्लग के साथ कॉल करें game_scope.
400 "अज्ञात क्रिया '...' - गेम के मेनिफ़ेस्ट में घोषित नहीं की गई है।" PUT एक ऐसी क्रिया का नाम दिया गया है जिसे मेनिफेस्ट घोषित नहीं करता है। उपयोग action से मान GET …/controls.
400 "'...' '...' और '...' दोनों से जुड़ा है।" आपके डिफ़ॉल्ट के साथ विलय के बाद, एक कुंजी दो क्रियाओं को ट्रिगर करेगी। अन्य क्रिया को भी इसी में ले जाएँ PUT, या कोई अन्य कुंजी चुनें।
400 "'...' मान्य कीबोर्डइवेंट.कोड मान नहीं है।" रिक्त स्थान या विराम चिह्न वाला एक कोड. भेजना event.code मूल्य.
400 "क्रिया '...' को 1-4 कोड बाइंड करने होंगे।" एक खाली सूची, या चार से अधिक. 1-4 कोड भेजें; DELETE रीसेट करना।
प्रतिक्रिया से एक क्रिया गायब है इसकी पंक्ति अमान्य थी: एक बड़ा अक्षर या - क्रिया नाम में, , के बजाय +, 4 से अधिक कोड, एक कोड पहले ही उपयोग किया जा चुका है, या 32वीं क्रिया के बाद। लाइन ठीक करें और पुनः प्रकाशित करें।
बंधन कभी नहीं जलता कोड स्वीकार किया जाता है लेकिन कोई कुंजी इसे उत्पन्न नहीं करती है, जैसे a या space. सटीक प्रयोग करें KeyboardEvent.code वर्तनी: KeyA, Space.

यह भी देखें: गेम्स एपीआई - प्रति-खिलाड़ी नियंत्रण बाइंडिंग, starhermit.txt.
