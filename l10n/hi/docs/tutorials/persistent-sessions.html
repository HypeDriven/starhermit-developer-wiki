ट्यूटोरियल: लगातार सत्र - खेल जो सभी के चले जाने पर रुक जाते हैं

आम तौर पर प्लेटफ़ॉर्म उस मैच को समाप्त कर देता है जिसे कोई नहीं खेल रहा है: एक बार प्रत्येक खिलाड़ी डिस्कनेक्ट हो जाता है और कोई भी नहीं खेलता है पाँच मिनट के भीतर वापस आ गया, सत्र समाप्त हो गया abandoned कारण सहित players_left (देखना गेम्स एपीआई - गेमप्ले वेबसॉकेट). यह शतरंज के लिए सही है खेल या दौड़, और एक खेत, एक शहर निर्माता, एक साझा कालकोठरी या किसी भी दुनिया के समूह के लिए गलत खिलाड़ी अधिक दिनों में लौट आते हैं।

एक खेल मांग सकता है लगातार सत्र बजाय। एक सतत सत्र तब रुक जाता है जब उसके खिलाड़ी डिस्कनेक्ट हो जाते हैं:

  1. आखिरी खिलाड़ी चला जाता है.
  2. लगभग 15 सेकंड के बाद जब कोई भी कनेक्ट नहीं हुआ, तो प्लेटफ़ॉर्म रुक जाता है सत्र. कुछ भी नहीं चलता: एक स्क्रिप्ट गेम को नंबर मिलता है onTick कॉल, और एक कंटेनर गेम का सत्र हटा दिया जाता है कंटेनर.
  3. इसकी पुनर्प्राप्ति अवधारण नीति के अंतर्गत सत्र रुका रहता है। पढ़ना /sessions/{id}/recovery किसी भी समाप्ति के लिए यह मानने के बजाय कि इसे हमेशा के लिए रखा जाता है।
  4. जुड़ने वाला पहला खिलाड़ी ws/v1/games बॉयोडाटा यह, उनके पहले आदेश से पहले है संभाला. खेल जहां रुका था वहीं से चलता है।

यह पेज दिखाता है कि इसे कैसे चालू करें, अपने गेम की घड़ियों को रुकने से कैसे बचाएं, और आपके ग्राहक को क्या करने की आवश्यकता है.

1. ऑप्ट इन करें

दृढ़ता एक प्रति-गेम घोषणा है, जब आपका गेम प्रकाशित या अपडेट किया जाता है तो पढ़ें - प्रकाशित करें इसे बदलने के बाद अपडेट करें. यह शाब्दिक होना चाहिए true या false; और कुछ भी नहीं के रूप में गिना जाता है घोषणा, और एक खेल जो कुछ भी घोषित नहीं करता वह पहले की तरह व्यवहार करता है।

स्क्रिप्ट गेम - एक स्थिर persistent पर game वस्तु (देखें गेम स्क्रिप्ट):

globalThis.game = {
  persistent: true,
  tickRateHz: 1,
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

कंटेनर खेल — persistent आपके में GET /describe उत्तर (देखें कंटेनर गेम सर्वर):

{ "protocol": 1, "tickRateHz": 20, "maxSessions": 48, "persistent": true }

सत्र कैसे बनाए जाते हैं, इसके बारे में कुछ भी नहीं बदलता है: मैचमेकिंग, आमंत्रण, एआई समापन बिंदु और वास्तविक समय सभी कमरे लगातार खेल के लिए लगातार सत्र तैयार करते हैं।

2. रुकते समय खेल का समय स्थिर रखें

प्लेटफ़ॉर्म दोबारा नहीं लिखता ctx.now - यह वास्तविक दीवार घड़ी बनी हुई है, इसलिए आप किसी भी पूर्ण समय का उपयोग कर सकते हैं खिलाड़ियों को दिखाएं (एक समय सीमा, ए "फसल तैयार है") जो कहता है उसका अर्थ रखता है। इसके बजाय, लगातार सत्रों को एक अतिरिक्त संदर्भ फ़ील्ड मिलता है:

ctx.pausedMs   // total milliseconds this session has spent paused, so far

यह केवल बढ़ता है, और केवल लगातार सत्रों पर (अन्य गेम कभी मैदान नहीं देखते हैं)। इसे और आप को घटाएं एक है खेल घड़ी वह तब रुकता है जब वहां कोई नहीं होता:

function gameTime(ctx) {
  return ctx.now - (ctx.pausedMs || 0);
}

globalThis.game = {
  persistent: true,
  tickRateHz: 1,

  createSession(ctx) {
    return { ok: true, sessionState: { lastTick: gameTime(ctx), crops: [] } };
  },

  onTick(ctx) {
    var state = ctx.sessionState;
    var t = gameTime(ctx);
    var dt = t - state.lastTick;      // never includes the time the world was paused
    state.crops.forEach(function (crop) { crop.growth += dt; });
    state.lastTick = t;
    return { ok: true, sessionState: state };
  },

  onPlayerMessage(ctx) { /* ... */ }
};

खेल के समय में अपना स्वयं का टाइमस्टैम्प संग्रहित करें (gameTime(ctx)), अंदर नही ctx.now, और केवल उनकी तुलना करें खेल के समय के विरुद्ध. अगर आप चाहना दुनिया में आगे बढ़ना है जबकि कोई नहीं देख रहा है - फसलें जो उगती हैं रात भर - उपयोग करें ctx.now इसके बजाय और बायोडाटा के बाद पहले टिक पर पकड़ बनाएं। किसी भी तरह से यह आपका है पसंद; प्लेटफ़ॉर्म केवल वही रिपोर्ट करता है जो घटित हुआ।

समय के दो विवरण:

  • अंतिम खिलाड़ी के जाने और रुकने के बीच ~15 सेकंड के दौरान, सत्र स्थिर रहता है सामान्य रूप से टिक किया गया। एक खिलाड़ी जिसका कनेक्शन टूट जाता है और सीधे वापस आ जाता है, रुकावट का कारण नहीं बनता है।
  • बायोडाटा के बाद अगला onTick एक टिक अंतराल बाद में आता है। रुका हुआ समय दोबारा नहीं चलाया जाता छूटे हुए टिकों के बैकलॉग के रूप में।

एक कंटेनर प्राप्त करता है pausedMs उसी स्थान पर: में POST /sessions शरीर यह कब भेजा जाता है एक विराम के बाद सत्र बहाल हो जाता है।

3. आपका ग्राहक

रुका हुआ सत्र अभी भी एक सक्रिय सत्र है, इसलिए क्लाइंट प्रवाह वही है जो आपके पास पहले से है:

  • पुनः शामिल होने के लिए दुनियाओं की सूची बनाएं साथ GET /api/v1/games/{slug}/sessions/mine. प्रत्येक प्रविष्टि में एक है pausedAt रुके हुए समय पर टाइमस्टैम्प और null जबकि इसमें कोई है तो आप दिखा सकते हैं "रुका हुआ तब से..." या "2 दोस्त अभी खेल रहे हैं" (देखना गेम्स एपीआई - सत्र).
  • फिर से जोड़ना खोलकर ws/v1/games?sessionId=… बिल्कुल पहले जैसा. बायोडाटा के दौरान होता है कनेक्ट करें. कोई विशेष बात नहीं है "फिर से शुरू" इसके लिए फ़्रेम - गेम बस तब चल रहा है जब आपका पहला आदेश आता है - इसलिए अपने गेम के सामान्य पूर्ण-राज्य संदेश के लिए अनुरोध करें या प्रतीक्षा करें, जैसा कि आप करेंगे कोई भी पुनः कनेक्ट करें.
  • एक असफल बायोडाटा को संभालें। यदि प्लेटफ़ॉर्म सत्र को फिर से शुरू नहीं कर सकता है - तो संभवतः एक कंटेनर गेम जिसका सर्वर अभी भी प्रारंभ हो रहा है - आपको प्राप्त होता है {"type":"error","error":"…"} और सॉकेट कोड के साथ बंद है 1001. सत्र रुका रहता है और कुछ भी नष्ट नहीं होता है। थोड़ी देर बाद पुनः कनेक्ट करें बैकऑफ़ (कुछ सेकंड, बढ़ते हुए), और दिखाएँ "दुनिया की शुरुआत..." एक त्रुटि के बजाय.
  • presence फ़्रेम हमेशा की तरह काम करते हैं, इसलिए अन्य खिलाड़ी देखते हैं कि इस समय दुनिया में कौन है।

4. लगातार सत्र समाप्त करना

एक सतत सत्र तब समाप्त होता है जब:

  • आपके गेम की रिपोर्ट a result (स्क्रिप्ट वापसी मूल्य या कंटेनर नियंत्रण संदेश), या
  • गेम का मालिक इसे समाप्त करता है (DELETE /api/v1/me/github-games/{id}/sessions/{sessionId}),
  • अंतिम सदस्य स्पष्ट रूप से बिना किसी स्थान के एक दुनिया छोड़ देता है /sessions/{id}/leave, या
  • इसका रुका हुआ पुनर्प्राप्ति डेटा परिनियोजन की अवधारण नीति के तहत समाप्त हो जाता है।

डिस्कनेक्ट करने से सदस्यता बरकरार रहती है; स्पष्ट रूप से छोड़ने से सदस्यता समाप्त हो जाती है। देखना सत्र जीवनचक्र और पुनर्प्राप्ति दोनों प्रवाह के लिए.

नए गेम के लिए पूछना ज़रूरी है नहीं खिलाड़ी के रुके हुए सत्रों को रिटायर करें, और रुके हुए सत्र अभी भी गिने जाएंगे प्रति खिलाड़ी समवर्ती-सत्र सीमा के विरुद्ध (डिफ़ॉल्ट रूप से 20)। खिलाड़ियों को समाप्त करने का एक तरीका दें या एक दुनिया छोड़ो - एक "संसार को त्याग दो" अपने स्क्रिप्ट उत्तरों को a के साथ कमांड करें result, उदाहरण के लिए। अन्यथा जो खिलाड़ी अपनी टोपी भर चुका है वह कुछ भी नया शुरू नहीं कर सकता है।

onPlayerMessage(ctx) {
  var msg = ctx.message.data;
  if (msg.type === "close-world" && ctx.message.from === ctx.sessionState.ownerId) {
    return { ok: true, sessionState: ctx.sessionState, result: { kind: "closed" } };
  }
  /* ... */
}

5. कंटेनर गेम: पार्किंग

एक कंटेनर गेम के लिए एक विराम है पार्क:

  1. प्लेटफ़ॉर्म अंतिम स्नैपशॉट मांगता है (GET /sessions/{id}/snapshot) और इसे टिकाऊ रूप से संग्रहीत करता है।
  2. यह सत्र को ख़त्म कर देता है (DELETE /sessions/{id}). आपका कंटेनर इसका अनुकरण करना बंद कर देता है, और यदि इसका कोई अन्य सत्र नहीं है, निष्क्रिय अवधि के बाद परिनियोजन रोका जा सकता है।
  3. अगली बार शामिल होने पर यह सत्र को पुनः बनाता है POST /sessions, संग्रहीत ले जाना snapshot और अद्यतन pausedMs - क्रैश रिस्टोर के समान अनुरोध - रुकी हुई तैनाती को जगाना यदि आवश्यक हो तो पहले.

इसलिए आपके द्वारा लौटाया गया स्नैपशॉट पूरी दुनिया के पुनर्निर्माण के लिए पर्याप्त होना चाहिए, न कि केवल कुछ को फिर से शुरू करने के लिए खेल के सेकंड. यदि वह अंतिम स्नैपशॉट विफल हो जाता है, तो सत्र को उसके अंतिम आवधिक से पार्क कर दिया जाता है चौकी. किसी दुर्घटना के विपरीत, पार्क-और-पुनर्स्थापना को आपके पुनरारंभ बजट में नहीं गिना जाता है, और खिलाड़ियों को नं resumed फ़्रेम: राज्य की स्थिति को देखने वाला कोई नहीं था।

जांच सूची

  • [ ] persistent: true घोषित (स्क्रिप्ट) या से लौटाया गया /describe (कंटेनर), और एक अद्यतन प्रकाशित हुआ।
  • [ ] गेम टाइमर का उपयोग ctx.now - ctx.pausedMs, या जानबूझकर उपयोग करें ctx.now और पकड़ लो.
  • [ ] ग्राहक सूची sessions/mine, दिखाता है pausedAt, और फिर से जुड़ जाता है ws/v1/games.
  • [ ] ग्राहक एक के बाद बैकऑफ़ के साथ पुनः प्रयास करता है error उसके बाद क्लोज़ कोड 1001 कनेक्ट पर.
  • [ ] खिलाड़ियों के पास दुनिया को ख़त्म करने का एक तरीका होता है, इसलिए वे कभी भी सेशन कैप पर अटके नहीं रहते।
  • [ ] (कंटेनर) स्नैपशॉट पूरी दुनिया का पुनर्निर्माण करते हैं।
