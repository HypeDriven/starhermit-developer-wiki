引擎功能：物理、车辆、天空、水和渲染

引擎1.40.0（主机API 1.40）添加了脚本游戏的模拟和渲染功能：刚体 物理、车辆、物理天空和天气、海洋、程序表面和草地、GPU 粒子、 时间抗锯齿和屏幕空间效果、更好的阴影、压缩纹理和新的 动画和细节层次工具。此页面概述了每个区域以及预期内容 从它。每个成员、选项、单位和限制都记录在您的游戏中 .starhermit/starhermit.d.ts (starhermit types 写道）；本页不再重复。

打开它们

此处的每个功能仅适用于声明主机 API 1.40 或更高版本的游戏 starhermit.txt:

engine.api=1
engine.version=1.40.0
engine.minor=40

一场比赛在 engine.minor=39 或更低，逐帧保持 1.39 的行为。无法导入新的 模块（starhermit:physics, starhermit:vehicle, starhermit:sky, starhermit:weather, starhermit:water, starhermit:surfaces, starhermit:particles): 导入会抛出一个 TypeError。新 现有类别的选项对于此类游戏来说仍然是未知的选项。提高 engine.minor 是整体 选择加入；首先在新的运行时上检查您的游戏（请参阅 转向更新的引擎).

一些功能遵循 Three.js r185 并保留其名称和行为。其他的是 发动机 扩展，在声明中标记为这样：它们没有等效的 Three.js，并且代码使用 它们不在 Three.js 上运行。

每台设备上的预期内容

每个视觉特征都有一个后备梯子 （完整→减少→最小→关闭）在每个运行时，本机 和浏览器。当设备或玩家的图形级别无法运行某个层时，引擎会采用 下一个并添加注释 选项 → 图形 这说明了被降低的内容。你的游戏保持 工作；它只是看起来更简单。不过，您不需要自己检测功能 renderer.capabilities 和属性，例如 ocean.tier 告诉你选择了什么。

模拟是确定性的。 物理、车辆、水波场（heightAt, sampleAt, buoyancy），风的 velocityAt，程序表面和 CPU 粒子给出相同的结果 在本机和浏览器中，因此同步多人游戏可以依赖它们。 GPU 粒子和一切 绘制的内容不是确定性的，并且无法通过游戏玩法读取。

本机工作在运行前收费。 召集新当地人负责 燃料 按比例预先完成他们的工作 他们会做多少。每个都有硬边界，因此单个超大调用（一块巨大的草地，一个 全轨搜索（大量水样本）被错误拒绝，而不是停止帧。 数量有上限，例如同时有 64 辆车、16 个高地、16 条跑道和 8 个池塘。

物理： starhermit:physics

PhysicsWorld 是一个 3D 刚体世界（引擎扩展； Three.js 没有物理）：

  • 机构： 动态、静态和运动，具有精确的运动目标。
  • 碰撞器： 球体、盒子、胶囊、圆柱体、圆锥体、凸包、三角形网格、高度场、平面 和三角形。网格和外壳可以直接从 BufferGeometry.
  • 关节： 固定、球、铰链、滑块、距离、绳索、弹簧和锥扭转、带限制、电机 和打破。
  • 查询： 光线投射、形状投射、重叠和触摸事件。
  • 人物： 运动学的 CharacterController 具有滑动、坡度限制、自动步进和捕捉功能 到地面。

单位为米、千克和秒。坐标必须保持在原点 1,000,000 米以内。 迈出世界一步 onFixedUpdate，并放置附加对象 onRender:

import { onFixedUpdate, onRender } from "starhermit:engine";
import { PhysicsWorld } from "starhermit:physics";

const world = new PhysicsWorld();
world.createCollider({ shape: { type: "trimesh", geometry: level.geometry } });
const crate = world.createBody({ position: [0, 5, 0], object: crateMesh });
world.createCollider({ shape: { type: "box", halfExtents: [0.5, 0.5, 0.5] } }, crate);
onFixedUpdate((dt) => world.step(dt));
onRender((alpha) => world.sync(alpha)); // interpolated between steps

车辆： starhermit:vehicle

Vehicle 是由一个 .vehicle 文本或规范对象。它为 Pacejka 轮胎建模， 悬架、传动系统（发动机、离合器、变速箱、差速器、制动器）、空气动力学和 ABS， 牵引力和稳定性控制。汽车在平坦的地面上行驶， Heightfield 或物理世界。 Track, LapTimer, Autopilot 和 formatLapTime 涵盖赛道、圈速和扇区计时以及人工智能驱动程序。步车 来自 onFixedUpdate。阅读他们插值的身体和车轮变换以获得视觉效果。

天空和天气： starhermit:sky, starhermit:weather

  • SkyAtmosphere 是一个基于物理的天空，包含太阳、月相、星星和 银河系，按一天中的时间、一年中的日期和纬度排列。它驱动一个 DirectionalLight （太阳 白天，晚上月亮）并且根据要求， scene.background 和 scene.environment。它是 空中透视 将遥远的陆地和海洋雾化到天空中，没有接缝。雾霾混杂其中 每个渲染通道都有自己的色彩空间，因此当通过后期绘制场景时它保持正确 缓冲区（渲染比例、自适应分辨率、运动矢量）。 CPU 查询（sunDirection, moonDirection, moonPhase）在每个运行时给出相同的数字。它的层数是满的、减少的、 最小（Preetham）并关闭。
  • Three.js r185 的 Preetham Sky 插件也可用，来自 starhermit:scene 和 starhermit:sky.
  • WindField 是风，方向改变，强度增强，阵风猛烈。 velocityAt(x, z, t) 是确定性的并且适合游戏玩法。材料可以读取相机周围的风场 通过一个钩子。 sway 和 swayMesh 用它弯曲草和树。
  • WeatherEffects 添加天气视觉效果。它们是天空层的体积云，雨 远离屋顶、潮湿的表面和水坑以及闪电和雷声。天气来了 来自 Weather （这 .weather 文本，六种内置类型）， WeatherState （天气之间的缓和） 和 WeatherCycle （天气自行改变）。

水： starhermit:water

一个 Ocean 绘制带有反射、折射、泡沫、白浪和浅滩的 FFT 波 海底。它的层级是 "gpu", "cpu", "gerstner" （最低图形级别）和 "off". ocean.tier 和 tierNote 说出哪一个运行。游戏玩法通过读取确定性波场 heightAt, sampleAt 和 buoyancy，无论抽到哪一层。风来自于一个 WindField (setWindField） 或者 setWind. Pond （最多8个）静止的水在风吹起的长方形上泛起涟漪。 WaterMaterial 对于河流和流水，为高度场网格提供相同的阴影。

表面和草地： starhermit:surfaces

  • generateSurface 按名称和种子烘焙 20 个瓷砖表面中的任何一个。它们包括沙子、砾石、 草、岩石、雪、大理石和五种树皮。每个都带有颜色、正常、环境光遮挡、 粗糙度和金属度贴图。
  • createSurfaceMaterial 将烘烤的表面变成一种材料，并带有可选的隐藏挂钩 平铺。
  • createTerrainMaterial 通过共享顶点来混合三个曲面。
  • createGrass 长出草来 .grass 品种（草地、草坪、干燥、高、边缘或您自己的文本）： 叶片、杂草和花朵，准备好随风摇摆 generateLods(…, { thin: true }).

输出在本机和浏览器中是相同的。

颗粒

ParticleEmitter （在 starhermit:scene）收益：

  • 力量： wind, curl, buoyancy, vortex 和 attract.
  • 碰撞： a floor 最多四个 colliders （平面和高度场）弹跳、夹紧、 坚持或杀死。
  • 运动和产卵： sway, sizeSpread, velocityMode "planar"/"radial"， 和 "ring" 和 "disc" 形状。
  • 旋转： rotation, rotationSpread, spin, spinSpread 和 rotationAxis, 对于五彩纸屑, 树叶和碎片。
  • 精灵： lit, soft 和 billboard 精灵（引擎扩展），被太阳照亮， 环境和灯光。

发射器保持确定性。一个 set() 范围检查拒绝现在使设置保持不变。 排队超过 256 个突发会抛出 RangeError，它曾经把它们默默地扔在那里。

GPUParticleEmitter 在 starhermit:particles 是一个引擎扩展。它模拟了大约 GPU 上每个发射器上百万个粒子，在图形级别的预算内，具有力， 碰撞器和场景深度的碰撞。它还加载 Solstice 风格 .particles 效果 （loadParticleEffect）。它不是确定性的，游戏无法读取它。没有浮动渲染 目标是回落到最多 4,096 个粒子的 CPU 发射器。

纹理、动画和细节层次

  • 压缩纹理。 带有 BC1、BC3、BC4、BC5 或 BC7 块的 KTX2 文件通过加载 KTX2Loader 和 TextureLoader。不支持 BC 的设备会将其解压为 RGBA8。拥有 它们是为你写的，设置 engine.textures.compress=bc 和 starhermit package 写入 KTX2 文件 在 PNG 和 WebP 图像旁边。这些图像保留作为后备。不支持基础通用。 Texture.preserveCoverage 防止经过阿尔法测试的树叶在远处稀疏。
  • 变形目标 与在 Three.js r185 中一样工作，包括来自 glTF。
  • AnimationGraph （引擎扩展）提供分层状态机、混合空间、同步 过渡、骨骼蒙版和附加层。
  • SkeletonUtils.retarget, retargetClip 和 clone （三.js 插件）之间携带动画 钻机。
  • compressClip 缩小动画剪辑，以及 setUpdateIntervals 更新远处的字符 较少。
  • 细节层次。 三.js SimplifyModifier，以及发动机的 generateLods，它构建了 一个 LOD 或一个 InstancedMesh通过屏幕上的错误切换的级别。
