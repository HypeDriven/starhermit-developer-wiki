入门

星隐士 是一个游戏和软件分发平台，具有内置社交层，通过 REST 和 WebSocket 公开。此页面为您提供了概况：平台做什么、在哪里监听、身份验证和版本控制如何工作，以及您自己的游戏与其集成的两种方式。

对于您的第一个浏览器游戏， 下载并发布快速入门。 对于另一种架构， 选择集成，然后检查 证书, API约定， 和 功能可用性。使用 故障排除 当呼叫失败时。

星隐者提供什么

  • 用户 & 验证 — 通过此部署拥有凭证的任何提供商进行公钥注册（无密码）和 OAuth 登录；看 验证.
  • 型材 & 在场 — 用户个人资料、头像、隐私设置、权利和存在心跳；看 轮廓.
  • 朋友们 — 好友请求和好友状态；看 朋友们.
  • 文字聊天 ——对话和消息；看 聊天.
  • 实时语音 — 语音室；看 嗓音.
  • 出版商 — 拥有目录条目的出版商帐户；看 出版商.
  • 软件目录 — 具有构建和可下载资产的软件名称；看 目录.
  • 权利 — 目录软件的每用户授权（部分 轮廓).
  • 成就 & 排行榜 — 具有脚本或容器后端的游戏的服务器权威成就，以及目录标题的客户端声明成就；看 成就 和 排行榜.
  • 对等中继 — 比赛绑定的不透明字节扇出，具有名单授权和源自游戏滴答率的速率限制；看 中继.
  • 实时房间 — 大厅、匹配、AI 玩家和回填，以及快节奏游戏的实时传输；还可以桥接到房间绑定的脚本会话，以进行服务器权威的游戏；看 实时房间.
  • 权威游戏 — 平台托管的游戏，其规则作为沙盒 JavaScript 运行 游戏脚本 或一个 容器游戏服务器;客户端使用共享的 游戏API.

基本 URL 和端口

  • 公共 REST API： https://api.starhermit.com， 在下面 api/v1/....
  • 公共 WebSocket： wss://api.starhermit.com/ws/v1/....
  • 平台上发布的游戏的服务地址为 https://<slug>.starhermit.com 和 /api 和 /ws 可用的同源，因此平台托管的游戏应使用相对路径。

版本控制

所有 REST 路由均已版本化： api/v1/...。 WebSocket 路由位于 ws/v1/... 并且与版本无关。

进入托管游戏的推荐方式

建议在 StarHermit 上托管的游戏在其开始屏幕上提供两个清晰的选项：

  1. 使用现有的 StarHermit 帐户登录 — 让玩家使用他们的帐户来保存进度和支持的平台功能，例如成就和排行榜。使用 托管游戏登录流程 当没有有效的启动令牌时；持有有效令牌到达的玩家可以直接继续。
  2. 无需登录即可玩单人游戏 — 提供独立的单人游戏版本，不需要帐户，也不跟踪或保存进度。将当前游戏会话的进度保留在内存中，无需写入云保存、持久本地保存、成就或排行榜分数。

清楚地标记第二个选项，例如 玩单人游戏（不保存进度），以便玩家在开始之前了解会发生什么。此模式应该在没有经过身份验证的 StarHermit API 调用或套接字的情况下运行。

身份验证模型（概述）

  • 访问令牌是具有 15 分钟生命周期的 JWT；刷新令牌轮换并持续 7 天。看 验证 用于令牌格式和刷新/注销端点。
  • 将访问令牌作为 Authorization: Bearer <token> 每个经过身份验证的请求的标头。为了 /ws/** 仅路径，凭证也被接受为 ?ticket= （一张来自 POST /api/v1/realtime/connection-tickets）或作为 ?access_token= （仍然支持）。浏览器无法在 WebSocket 握手上设置标头。
  • 游戏另外使用 游戏范围的启动代币 — 每个游戏铸造的短暂 JWT，将调用者隔离到该游戏的 API 表面。看 验证 和 游戏.

直接在浏览器中打开的托管游戏可以提供 登录按钮。 Starhermit 处理登录或帐户创建，并将游戏范围的令牌直接返回到游戏。

在调用受保护的端点或打开套接字之前，帐户必须 接受当前条款。 使用 GET /api/v1/me 检查 termsAcceptanceRequired，显示文档来自 GET /api/v1/terms，并仅在用户接受后才提交其哈希值。一个 403 和 error: "terms_acceptance_required" 意味着您必须显示当前文档并提供明确的 接受行动。账户会话和玩家启动代币可以提交接受；服务器令牌不能。 刷新令牌并不记录接受。

集成游戏的两种方法

  1. 平台托管的游戏。 您从 GitHub 存储库发布游戏 starhermit.txt 清单 - 或者，如果它不在存储库中， 直接上传文件夹 并完全跳过 git。它可能仅限浏览器，请使用沙盒 server.js，或指向服务器逻辑的摘要固定容器映像。该平台为游戏提供服务 <slug>.starhermit.com 和 /api 和 /ws 代理同源。脚本路径由国际象棋参考实现端到端演示，位于 https://github.com/HypeDriven/starhermit-chess。看 GitHub 游戏, 游戏脚本, 容器游戏服务器，以及 集成演练.
  2. 外部游戏客户端。 您自己的客户端使用 JWT 身份验证以及（如果适用）游戏启动令牌直接调用 REST 和 WebSocket API。下面的 API 参考页记录了表面情况。关于团结， 统一SDK 已经将该表面实现为类型化 C# 客户端，包括令牌刷新、重试和套接字重新连接规则，适用于桌面、移动、WebGL、控制台和无头服务器构建。

进入平台托管游戏的两条路径都经过一个小文件：请参阅 这 starhermit.txt 显现 了解它的格式、它的位置以及为什么 您上传的文件夹应该是您的可分发版本而不是源树。

服务器时钟 — GET /api/v1/time

平台为您提供的截止日期（会议摘要的 deadline，一个脚本的 ctx.now）在 服务器的 时钟，因此客户端根据自己的时钟呈现倒计时将会发生漂移。这个 端点是故意匿名的——同步必须在登录之前工作——并且明确允许 游戏范围内的启动令牌，因此托管游戏可以在隔离到其自己的表面时调用它。

{
  "serverTime": 1785060842000,
  "serverTimeIso": "2026-07-25T09:14:02+00:00",
  "clientTime": 1785060841200,
  "skew": 800
}

clientTime （unix ms，可选）原封不动地回显，以便响应可以与其匹配 请求； skew 是天真的 serverTime - clientTime 对于不想往返的客户 数学。对于真实的估计，请采用 NTP 风格：将往返行程减半并进行计算 offset = serverTime + rtt/2 - now.

跨领域行为

  • 安全标头 对所有响应进行设置。
  • 速率限制 — 每个用户每分钟只能发送 10 条聊天消息；其他端点可能会返回 429，如每页所述。
  • 错误 总是返回为 {"error":"..."} 具有标准状态代码 (400/401/403/404/409/422/429)。各个页面仅记录特定于端点的错误情况。
