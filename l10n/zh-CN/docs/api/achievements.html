成就

一项成就完全属于 一位业主，所有者决定谁可以解锁它：

所有者 声明者 解锁者 用它来
一款权威的游戏 game.achievements 在脚本中，或者 achievements 从容器的 /describe — 或由游戏所有者 通过 /me/github-games/{id}/achievements 仅游戏的服务器运行时 — 服务器权威 游戏与 server= 脚本或 container.image= 后端
目录标题 (SoftwareTitle) 出版商通过 发布者API 玩家的客户端，通过 POST /api/v1/me/achievements/unlock （需要权利） 分布式游戏，其客户端是唯一知道玩家赢得某些东西的人

两者是互斥的，平台强制拆分：

  • POST /api/v1/me/achievements/unlock 拒绝游戏范围内的成就 — 客户永远无法认领。
  • 发布者 CRUD 端点也拒绝它们。您不需要为您拥有的游戏寻找发行商： 它的主人你 是 它的出版商，您可以通过以下方式管理其成就 所有者端点 反而。

基本网址： https://api.starhermit.com。所有路线均在 /api/v1/....

方法 小路 授权 描述
得到 /api/v1/games/{slug}/achievements 承载者 权威游戏成就+调用方解锁状态
得到 /api/v1/me/github-games/{id}/achievements JWT（游戏所有者） 您游戏中的每一项成就，及其 origin 并解锁计数
邮政 /api/v1/me/github-games/{id}/achievements JWT（游戏所有者） 为您的游戏创建成就 → 201
放 /api/v1/me/github-games/{id}/achievements/{achievementId} JWT（游戏所有者） 更新您创建的一个
删除 /api/v1/me/github-games/{id}/achievements/{achievementId} JWT（游戏所有者） 删除您创建的且无人解锁的 → 204
得到 /api/v1/software/{titleId}/achievements 匿名的 目录标题的成就定义
得到 /api/v1/me/achievements?titleId= 智威汤逊 调用者的解锁（所有所有者，或一个头衔）
邮政 /api/v1/me/achievements/unlock 智威汤逊 客户声称解锁—— 仅目录标题

防御性地读取错误，如中所述 API约定. POST /me/achievements/unlock 返回其 400 原因为纯文本。

服务器权威游戏成就

这就是机制 任何 当游戏有脚本或容器后端时应该使用。的 服务器运行时是唯一的编写者。它必须验证玩家是否获得了每个解锁；拒绝 直接 API 提交本身并不能验证修改后的客户端报告的事件。

1. 在脚本中声明它们

添加静态 achievements 数组到 game 对象——参见 游戏脚本——成就 对于完整合同：

globalThis.game = {
  achievements: [
    { key: "first-win",  name: "First Win",  description: "Win a match.", points: 10 },
    { key: "flawless",   name: "Flawless",   description: "Win without conceding.",
      points: 50, secret: true, icon: "https://cdn.example/flawless.png" }
  ],
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

声明已读 游戏发布或更新时 从它的存储库中。发布更新以应用更改。

2.从任何生命周期挂钩中解锁它们

返回一个 achievements 地图 — 用户 ID → 键数组 — 来自 createSession, onPlayerMessage， 或者 onTick:

return {
  ok: true,
  sessionState: state,
  achievements: { [winnerId]: ["first-win", "flawless"] },
  result: { kind: "win", winner: winnerId }
};

解锁有 幂等的 — 返回玩家已持有的密钥是无操作的，因此脚本可以 在每次勾选时重新声明一项成就，而不必担心重复。

3. 通过游戏套接字通知玩家

每个新授予的解锁仅推送给赚钱的玩家， ws/v1/games，作为它自己的框架 类型（平台真相，不是脚本中继 game 信息）：

{
  "type": "achievement",
  "data": {
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "points": 10,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
}

解锁授予自 createSession 在任何人拥有套接字之前就被持久化，因此它们到达时带有 无框架 - 在加载时从列表端点读取它们。

容器后端

容器在中声明相同的成就字段 GET /describe，然后发送一个 achievements 其控件 WebSocket 上的消息。平台应用相同的密钥、参与者、 幂等性和传递规则。看 容器游戏服务器.

GET /api/v1/games/{slug}/achievements

游戏声明的每项成就都带有调用者的解锁状态。 404 如果蛞蝓没有 权威的游戏定义（没有脚本或容器后端的游戏没有游戏拥有的 成就——见 哪些游戏可以用这个）。秘密成就将被隐藏，直到 呼叫者解锁它们。按创建排序，然后按密钥排序。

[
  {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "secret": false,
    "points": 10,
    "unlocked": true,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
]

与完整用户 JWT 或游戏范围的启动令牌配合使用。

哪些游戏可以用这个

该机制可用于声明以下任一者的游戏： server= 脚本或 container.image= 后端在 starhermit.txt。的 服务器运行时使解锁具有权威性。脚本支持的用例包括：

  • 脚本化平台游戏 — 解锁自 onPlayerMessage / onTick 随着比赛的进行。
  • 房间内实时游戏 — a 实时房间 对于一个 游戏与 server= 脚本在启动时创建一个绑定会话，并且该会话的每个钩子 会议可以授予成就。
  • 单人游戏和练习游戏 ——一场针对人工智能席位的会议 （POST /api/v1/games/{slug}/sessions/ai）运行相同的脚本和相同的解锁路径。
  • 主机路由的实时游戏 — 游戏玩法贯穿于 实时房间二进制通道 仍然可以发送服务器脚本 纯粹作为其成就权限：房间开始创建绑定会话，并且脚本 奖项来自 createSession / onTick / 耐用的 cmd 已发送的消息 ws/v1/games 而 快速路径不断流过 ws/v1/realtime.

容器支持的会话还可以通过其协议声明和授予成就。一场比赛 与 无权威后台 （一款纯粹的浏览器游戏，或者仅基于 对等中继） 没有服务器权威的解锁路径。客户声称的解锁仅适用于 目录分发的标题，如下。

限制和规则

规则 价值
每场比赛宣布的成就 100（忽略额外）
成就密钥长度 128 个字符
解锁每个玩家每次调用接受的密钥 32
points 钳位至 0–10000；默认为 0
name 默认为 key 当省略时
  • 格式错误的声明条目是 跳过。无法评估的脚本会产生空值 清单；容器的声明在通过健康检查后被读取。验证与 GET /api/v1/games/{slug}/achievements 部署后。
  • 定义更新插入者 key。您的后端停止声明的密钥已被删除 除非没有人有 解锁它 ——赢得的历史永远不会被摧毁。所有者通过 API 创建的成就 永远不会被这一点所触及：只有声明的才会被协调。
  • 不属于会话参与者的用户以及 AI 席位的解锁将被忽略。

其他游戏的成就

游戏可以根据玩家解锁的内容来打开功能 其他 游戏：续集荣誉 原版或共享化妆品系列中的游戏。有两种阅读它们的方法。

从您的服务器： ctx.linkedAchievements （值得信赖）

在其他声明旁边命名脚本中的其他游戏：

globalThis.game = {
  linkedAchievements: ["83fd04b1-3cbe-4b09-a251-3733ad4b9d94"], // other games' slugs (uids)
  // ...
};

容器返回相同的结果 linkedAchievements 数组来自 GET /describe。每个脚本 然后，调用的 ctx 携带这些游戏中每个人类玩家的解锁密钥：

ctx.linkedAchievements = {
  "7c9e6679-...": {                                   // player id
    "83fd04b1-3cbe-4b09-a251-3733ad4b9d94": ["first-win", "checkmate-10"]
  }
};
  • 已重读 每次调用，因此在另一场比赛中获得的解锁显示在 下一张。容器在 ctx 中接收它 POST /sessions，即在创建时和在 恢复。
  • 最多 8 游戏；非空字符串、重复项和超过 100 条的条目 字符被丢弃。与其他声明一样，它会在游戏发布或发布时读取 已更新。
  • 一款不声明任何内容的游戏将不会获得任何结果 linkedAchievements 领域并且不支付任何费用。
  • 使用此路径执行平台必须强制执行的任何操作，例如解锁游戏玩法或授予 自己的成就。

来自您的客户： GET /api/v1/games/{slug}/linked-achievements/{otherSlug}

调用者自己的解锁 otherSlug。它不需要声明，因此纯浏览器游戏没有 服务器可以使用它，并且它与启动令牌一起使用 {slug}：其他游戏自己的端点 远离该令牌。

{
  "game": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "hidden": false,
  "unlocked": [
    { "key": "first-win", "unlockedAt": "2026-07-25T09:14:02Z" }
  ]
}

客户可能会对收到的内容撒谎，因此请将其视为 UI 和外观的提示，而不是证据。

披露了什么

  • 仅解锁您指定的游戏状态：钥匙和解锁时间，绝不是名称、描述或 玩家玩过的其他游戏的列表。玩家解锁的秘密成就是 包括在内。
  • 与任何游戏答案都不匹配的slug就像没有解锁任何内容的游戏一样。
  • 隐私受到尊重。 成就隐私受到保护的玩家 Private 是 隐: 缺席 来自 ctx.linkedAchievements， 和 "hidden": true 端点的空列表。隐藏 不等于 "没有"，所以不要这样对待它。 FriendsOnly （默认）已披露， 因为读者是在为玩家行事。

游戏所有者创造的成就

在代码中声明成就并不是为游戏提供成就的唯一方法。如果您拥有一款游戏 server= 脚本或 container.image= 后台，您还可以通过以下方式为其创建成就 API — 出版商处理目录标题的方式，无需出版商帐户或权限。 拥有该游戏就是全部赠款。当设计师想要添加或改写时使用此功能 无需更改代码即可取得成就，或者当您的后端授予它未声明的密钥时。

只有您的游戏服务器才能解锁它们，与声明的完全一样：您的脚本返回密钥 在 achievements，或者您的容器在控制通道上发送它。上没有任何变化 解锁方 — 密钥被解析 全部 宣布和创建的游戏成就。

{id} 你的游戏 ID 是来自 GET /api/v1/me/github-games.

POST /api/v1/me/github-games/{id}/achievements

{

  "description": "Finish a level in under a minute.",
  "icon": "https://cdn.example/speedrunner.png",

PUT .../achievements/{achievementId} 采取任何 name, description, icon, secret 和 points;这 key 无法改变。 DELETE 将其删除。

对于通过目录分发的软件，客户端是唯一观察该目录的人 解锁条件。定义是匿名阅读的；解锁需要 JWT 和不可撤销的 获得头衔的权利。
