嗓音

StarHermit 语音通过 REST API 提供每次对话语音室（api/v1/voice）加上混合的二进制/文本 WebSocket（ws/v1/voice）用于音频和 WebRTC 信号传输。所有 REST 端点都需要身份验证。语音可用性可能会有所不同。错误体各不相同；看 API约定.

客房锚定于 聊天对话;对话中的成员资格决定了一切，因此聊天友谊规则也控制语音（游戏会话对话绕过友谊）。限制：每个对话 3 个活动房间，每个房间最多 32 名参与者（省略时的默认值） maxParticipants;您的值被限制在 2–32）。每个房间声明一个 codec 创建者集和客户可以依赖： pcm 默认情况下 - 中继不透明转发的 20 ms/16 kHz/mono/s16 约定 - 或 opus 对于一个房间，其参与者都运行支持 Opus 的客户端。标签被转发，服务器不会应用转换。

REST 端点

根据： https://api.starhermit.com/api/v1/voice.

方法 小路 授权 描述
邮政 /rooms 智威汤逊 创建对话语音室
邮政 /rooms/join-or-create 智威汤逊 返回对话中最旧的活动房间并提供空闲座位，或创建一个 - 以原子方式选择
得到 /rooms?conversationId= 智威汤逊 列出对话房间
得到 /rooms/{roomId} 智威汤逊 获得一个房间
邮政 /rooms/{roomId}/join 智威汤逊 加入房间（WS之前需要）
邮政 /rooms/{roomId}/leave 智威汤逊 留下一个房间
邮政 /rooms/{roomId}/mute 智威汤逊 设置自己的静音状态
邮政 /rooms/{roomId}/participants/{userId}/server-mute 智威汤逊（创建者） 主持人静音参会者无法解除
邮政 /rooms/{roomId}/close 智威汤逊 关闭房间（仅限创建者）

创建一个房间

POST /rooms

{ "conversationId": "<guid>", "maxParticipants": 8, "codec": "opus" }

maxParticipants （可选，限制为 2–32；默认为 32）以及 codec （选修的， pcm 或者 opus;其他任何内容都被读作 pcm) 都在创建时设置一次。返回一个 VoiceRoomDto.

加入或创建房间

POST /rooms/join-or-create 具有相同的主体返回 VoiceRoomDto 对于对话的 仍然有空闲座位的最旧的活动房间，或者在没有人这样做时创建一个 - 在对话的房间锁下自动决定，因此同时打开语音的两个成员会进入一个房间，而不是两个他们无法听到对方声音的房间。 maxParticipants/codec 仅在创建时应用。你还是打电话 /rooms/{roomId}/join 在打开 WebSocket 之前返回的房间。

房间形状

GET /rooms?conversationId=<guid> → VoiceRoomDto[]; GET /rooms/{roomId} → VoiceRoomDto:

{
  "id": "<guid>",
  "conversationId": "<guid>",
  "creatorUserId": "<guid>",
  "codec": "opus",
  "status": "Active",
  "maxParticipants": 8,
  "createdAt": "2026-07-22T07:00:00Z",
  "participants": [
    {
      "userId": "<guid>",
      "username": "alice",
      "isMuted": false,
      "isConnected": true,
      "joinedAt": "2026-07-22T07:01:00Z"
    }
  ]
}

加入、离开、静音、关闭

POST /rooms/{roomId}/join → VoiceRoomDto。这个 REST 连接是 必需的 在打开 WebSocket 之前；连接而不返回 403。重新加入会清除参与者的 自己的 沉默的 （isMuted）；一个主机的 isServerMuted 幸存离开并重新连接。

POST /rooms/{roomId}/leave → 204.

POST /rooms/{roomId}/mute 和 { "muted": true } → 204。这是与会者自己的静音，无法清除主持人的静音。

POST /rooms/{roomId}/participants/{userId}/server-mute 和 { "muted": true } → 204 （仅限创作者）。如果设置了静音，音频就会被丢弃。

POST /rooms/{roomId}/close → 204 （仅限创作者）。

在连接时声明您的静音，而不是继承该行记住的任何内容。

网络套接字： ws/v1/voice

连接到 wss://api.starhermit.com/ws/v1/voice?roomId=<guid> 通过 JWT Authorization 标头， ?ticket=， 或者 ?access_token=。事先休息 join 是必须的。

协议是混合的：

二进制帧——音频

二进制帧携带音频（例如 Opus）。服务器将每个帧转发给其他参与者：

[16-byte senderUserId][audio…]

服务器前缀为 经过验证的 发件人 ID，并且从不信任客户端提供的发件人。来自静音用户的音频将被丢弃。限制：每个用户每秒 100 个数据包，最大帧 4000 字节。

文本框架——客户端→服务器控制

{ "type": "mute", "muted": true }

{ "type": "speaking", "speaking": true }

{ "type": "rtc", "to": "<guid>", "payload": { } }

{ "type": "deafen", "deafened": true }

rtc 有效负载是不透明的 WebRTC 信令，转发给指定的参与者。 deafen 抑制该套接字传入的中继二进制音频；它不会自动静音 传出音频或单独的对等连接。当玩家选择 Deafen 时，在本地应用这些内容。

REST 参与者形状公开自己的静音，而不是主机静音。初始语音名单和加入活动 包括 serverMuted;没有单独的主机静音更改推送事件。如果你的游戏使用P2P 音频、其主机静音信号和执行必须是您自己的媒体集成的一部分。

当最后一个语音套接字断开连接时，语音室成员资格结束。呼叫休息 join 再次之前 在发送音频之前重新连接并恢复预期的静音。

服务器→客户端事件

信封： { "event": "<name>", "data": { } }.

集成模式示例（来自国际象棋参考实现）

每个游戏会话都可以选择加入语音。典型客户 enable() 流动：

  1. POST /api/v1/voice/rooms/join-or-create 和 { "conversationId": "<chatConversationId>" } — 一个呼叫返回其他所有人都打开语音的房间。 （你仍然可以 GET /rooms?conversationId= 然后 POST /rooms 手工，但两个客户同时这样做会产生两个房间。）
  2. POST /api/v1/voice/rooms/{roomId}/join.
  3. 打开 ws/v1/voice?roomId=<guid>.

在 国际象棋参考实现，音频通过WebRTC P2P运行，完美协商；信令是通过交换 rtc 控制消息（{ "sdp": … } / { "ice": … } 有效负载），以服务器中继的 Opus 二进制路径作为后备。

游戏范围内的启动代币 可能 对连接到自己的游戏会话的房间使用语音 REST 和 WebSocket。
