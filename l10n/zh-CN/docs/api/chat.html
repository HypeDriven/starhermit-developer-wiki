聊天

StarHermit 聊天涵盖直接消息、群组房间和游戏会话对话，通过 REST API (api/v1/chat）加上服务器到客户端的 WebSocket 推送通道（ws/v1/chat）。所有 REST 端点都需要身份验证。错误体各不相同；看 API约定.

REST 端点

根据： https://api.starhermit.com/api/v1/chat.

方法 小路 授权 描述
邮政 /conversations 智威汤逊 创建对话（1 个朋友 = 直接，≥2 = 群组）
修补 /conversations/{id} 智威汤逊 重命名对话（任何成员）
邮政 /conversations/{id}/invites 智威汤逊 邀请用户加入群组
得到 /invites 智威汤逊 列出您待处理的聊天邀请
邮政 /invites/{id}/accept 智威汤逊 接受聊天邀请
邮政 /invites/{id}/decline 智威汤逊 拒绝聊天邀请
得到 /rooms/joinable 智威汤逊 列出内部有 ≥1 位好友的开放房间
邮政 /conversations/{id}/join 智威汤逊 加入开放房间（必须是会员的朋友）
邮政 /conversations/{id}/participants 智威汤逊 将参与者添加到对话中
删除 /conversations/{id}/participants/{userId} 智威汤逊 删除参与者（自己：任何成员；其他：仅限群组创建者）
邮政 /conversations/{id}/leave 智威汤逊 留下对话
得到 /conversations 智威汤逊 列出对话，包括每个未读计数
得到 /conversations/{id} 智威汤逊 获取对话，包括其未读计数
得到 /unread 智威汤逊 获取未读消息总数
邮政 /conversations/{id}/read 智威汤逊 将对话标记为已读
得到 /conversations/{id}/messages?page=&pageSize= 智威汤逊 获取分页消息历史记录
邮政 /conversations/{id}/messages 智威汤逊 发送消息（限速）
放 /conversations/{conversationId}/messages/{messageId} 智威汤逊 编辑消息
删除 /conversations/{conversationId}/messages/{messageId} 智威汤逊 删除消息（墓碑）

创建对话

POST /conversations

{
  "participantIds": ["<guid>"],
  "name": "Friday night lobby",
  "friendUserId": "<guid>",
  "joinPolicy": "closed"
}

所有字段都是可选的。一位朋友参与者创建了一个 直接的 对话;两个或多个创建一个 团体. joinPolicy 是 "open" 或者 "closed" （默认 "closed"）。返回一个 ConversationDto.

重命名对话

PATCH /conversations/{id} 和 { "name": "New name" } → ConversationDto。任何会员均可更名；系统注释 kind: "system_rename" 正在广播。

邀请

POST /conversations/{id}/invites 和 { "toUserId": "<guid>" } → ChatInviteDto。邀请是进入封闭房间的唯一途径。

GET /invites → ChatInviteDto[]:

[
  {
    "id": "<guid>",
    "conversationId": "<guid>",
    "conversationName": "Friday night lobby",
    "fromUserId": "<guid>",
    "fromUsername": "alice",
    "toUserId": "<guid>",
    "status": "pending",
    "createdAt": "2026-07-22T07:00:00Z"
  }
]

POST /invites/{id}/accept 和 POST /invites/{id}/decline → ChatInviteDto.

加入房间

GET /rooms/joinable → JoinableRoomDto[] — 打开至少有一位朋友在里面的房间：

[
  {
    "id": "<guid>",
    "name": "Friday night lobby",
    "joinPolicy": "open",
    "createdAt": "2026-07-22T07:00:00Z",
    "participants": [{ "userId": "<guid>", "username": "alice" }]
  }
]

POST /conversations/{id}/join → ConversationDto。加入一个开放的房间；您必须与会员成为朋友。

参加者

POST /conversations/{id}/participants 和 { "participantIds": ["<guid>"] } → ConversationDto.

DELETE /conversations/{id}/participants/{userId} → 204。任何成员都可以自行解职；删除其他人需要成为群组创建者。

POST /conversations/{id}/leave → 204.

阅读对话

GET /conversations → ConversationDto[].

GET /conversations/{id} → ConversationDto:

{
  "id": "<guid>",
  "type": "group",
  "name": "Friday night lobby",
  "createdByUserId": "<guid>",
  "joinPolicy": "closed",
  "createdAt": "2026-07-22T07:00:00Z",
  "participants": [{ "userId": "<guid>", "username": "alice" }],
  "otherParticipant": { "userId": "<guid>", "username": "bob" },
  "unreadCount": 3
}

type 是其中之一 direct, group, game. name, createdByUserId， 和 otherParticipant 可能缺席。 unreadCount 在呼叫者的每次对话阅读范围之后计算其他成员发送的未读短信。

未读状态

GET /unread 返回所有呼叫者对话的未读计数：

{ "total": 7 }

POST /conversations/{id}/read 提高呼叫者对该对话的阅读视野。 显示当前成绩单后使用它。服务器发出一个 conversation_read 事件至 属于调用者的所有套接字，允许多个登录客户端清除其徽章。 新的和删除的消息可能会改变总数，因此客户端应该从 WebSocket 事件或 定期重新获取 /unread.

留言

GET /conversations/{id}/messages?page=1&pageSize=50 → PagedMessagesDto:

{
  "conversationId": "<guid>",
  "page": 1,
  "pageSize": 50,
  "totalCount": 123,
  "items": []
}

POST /conversations/{id}/messages 和 { "content": "hello" } → MessageDto。每个用户的速率限制为 10 条消息/分钟；超过它返回 429.

PUT /conversations/{conversationId}/messages/{messageId} 和 { "content": "edited" } → MessageDto.

DELETE /conversations/{conversationId}/messages/{messageId} → 204。删除是一个墓碑：消息仍然存在 isDeleted: true.

MessageDto:

{
  "id": "<guid>",
  "conversationId": "<guid>",
  "senderId": "<guid>",
  "senderUsername": "alice",
  "content": "hello",
  "kind": "text",
  "metadata": { "key": "value" },
  "sentAt": "2026-07-22T07:00:00Z",
  "editedAt": null,
  "isDeleted": false
}

kind 是 "text" 或者 "system_rename"; content, metadata (a Dictionary<string,string>）， 和 editedAt 可能不存在/为空。

网络套接字： ws/v1/chat

连接到 wss://api.starhermit.com/ws/v1/chat 通过 JWT Authorization 标头， ?ticket=， 或者 ?access_token=.

这是一个 纯服务器→客户端推送通道：忽略客户端框架（仅 Close 很荣幸）。每帧都是一个信封：

{ "type": "<event>", "payload": { } }
事件 type 有效载荷
conversation_created ConversationDto
conversation_renamed ConversationDto
participants_added ConversationDto
participant_removed ConversationDto
chat_invite ChatInviteDto
chat_invite_responded ChatInviteDto
new_message MessageDto
message_updated MessageDto
message_deleted MessageDto
conversation_read 登录用户的读取状态更改；重新获取未读计数
game_invite { "inviteId", "kind", "gameSlug", "gameName", "roomId", "from": { "userId", "username" }, "createdAt", "acceptPath", "declinePath", "inProgress", "sessionId" } - 见下文

game_invite：两个邀请系统的一场活动

任何人都可以通过两种方式被邀请来玩，而这个单一的事件同时包含这两种方式——客户端实现一次祝酒，而不是两次：

kind 由...发出 接受它
"session" POST /games/{slug}/invites 为你们两个创建一个新的游戏会话
"room" POST /realtime/rooms/{id}/invites 在邀请者已经坐过的房间里坐下； roomId 是那个房间吗

acceptPath 和 declinePath 是回答的端点 这 邀请——使用它们，区别并不重要。在其他系统的端点应答是 404：两者保留不同的邀请 ID。

inProgress 是 true 当接受加入已经在玩的游戏时 - 命名正在运行的会话的会话邀请，或允许加入的已启动房间的房间邀请 - 以及 sessionId 是该游戏的会话。用它来表达 "加入他们的游戏" 而不是 "玩".

{
  "type": "game_invite",
  "payload": {
    "inviteId": "e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b",
    "kind": "room",
    "gameSlug": "poker",
    "gameName": "StarHermit Poker",
    "roomId": "b1d2c3e4-5f60-4a71-8b92-c3d4e5f60718",
    "from": { "userId": "9b2f8c1a-1111-4222-8333-444455556666", "username": "alice" },
    "createdAt": "2026-07-26T14:10:00Z",
    "acceptPath": "/api/v1/realtime/rooms/invites/e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b/accept",
    "declinePath": "/api/v1/realtime/rooms/invites/e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b/decline"
  }
}

roomId 是 null 为了 "session" 邀请。游戏范围的启动令牌无法打开此套接字或读取帐户范围的内容 /me/game-invites 收件箱。游戏客户投票 GET /api/v1/games/{slug}/invites 会议邀请和 GET /api/v1/realtime/rooms/invites 获得他们的游戏房间邀请。帐户客户可以通过以下方式阅读这两种类型 GET /api/v1/me/game-invites.

在游戏会话中聊天

游戏范围内的启动令牌 不能 打开 ws/v1/chat — 它被阻止，因为套接字流式传输用户的所有对话。启动代币 可能 在附加到自己的游戏会话的对话上使用聊天 REST API：会话详细信息返回 chatConversationId，对话有类型 "game"，其参与者是会话的玩家，并且绕过了友谊规则。

因此，游戏客户端通常通过 REST 加载历史记录并轮询新消息，而不是使用套接字。例如， 国际象棋参考实现 每 5 秒轮询一次：

GET /api/v1/chat/conversations/{chatConversationId}/messages?page=1&pageSize=50
Authorization: Bearer <launch-token>

POST /api/v1/chat/conversations/{chatConversationId}/messages
Authorization: Bearer <launch-token>
Content-Type: application/json

{ "content": "good game" }
