排行榜

排行榜定义和条目。读取是匿名的；提交分数需要 JWT。

基本网址： https://api.starhermit.com。所有路线均在 /api/v1/....

方法 小路 授权 描述
得到 /api/v1/leaderboards 匿名的 列表定义（查询 scope, region, titleId)
得到 /api/v1/leaderboards/{id} 匿名的 得到一个定义
得到 /api/v1/leaderboards/{id}/entries?scope=&region=&friendsOnly=&page=&pageSize= 匿名的 分页条目； friendsOnly=true 需要授权
邮政 /api/v1/leaderboards/{id}/submit 智威汤逊 提交分数（仅限目录板）
得到 /api/v1/games/{slug}/leaderboards 承载者 您的游戏自己的活动板（接受启动令牌）
获取/发布 /api/v1/me/github-games/{id}/leaderboards JWT（游戏所有者） 列出/创建您的游戏板
放置/删除 /api/v1/me/github-games/{id}/leaderboards/{leaderboardId} JWT（游戏所有者） 更新/删除一个

定义是 LeaderboardDefinitionDto[]:

[
  {
    "id": "…",
    "softwareTitleId": "…",
    "gameDefinitionId": null,
    "key": null,
    "name": "…",
    "scoreType": "…",
    "sortDirection": "…",
    "resetSchedule": "weekly",
    "currentPeriodStartedAt": "2026-10-12T00:00:00+00:00",
    "nextResetAt": "2026-10-19T00:00:00+00:00",
    "minScore": 0,
    "maxScore": 100,
    "scope": "…",
    "region": "…",
    "isActive": true,
    "createdAt": "…",
    "updatedAt": "…"
  }
]

条目回复：

{
  "items": [
    {
      "id": "…",
      "userId": "…",
      "username": "…",
      "score": 1500,
      "rank": 1,
      "region": "…",
      "submittedAt": "…"
    }
  ],
  "total": 1,
  "page": 1,
  "pageSize": 20
}

提交正文：

{
  "score": 1500
}

分数根据定义进行验证 minScore/maxScore 和出版商规则；响应即为录入结果。

权威游戏和Elo

每个权威游戏都有elo排行榜；它的id来自 GET /api/v1/games/{slug} → leaderboardId （看 games.md）。分数仅由平台根据脚本编写 eloUpdates 或者容器控制通道——直接提交被拒绝。游戏客户端通过标准分页端点读取条目；例如，国际象棋参考实现请求：

GET /api/v1/leaderboards/{leaderboardId}/entries?friendsOnly=true&page=1&pageSize=10

游戏范围的启动令牌可以读取自己游戏的排行榜。发行商端排行榜CRUD驻留在 publisher.md.

重置玩家的评分

游戏所有者可以将一名玩家的评分恢复到起始状态 1200 — 对于蓝精灵来说，增强的 帐户或评级已损坏的错误：

DELETE /api/v1/me/github-games/{id}/players/{userId}/elo      → 200 { "userId": "…", "elo": 1200 }

它重置评级匹配对，从 elo 板上删除玩家的行（它返回 与他们的下一个评级匹配），并设置一个顶级数字 elo 在脚本的播放器文档中 到 1200 — 因为您的脚本根据其自己的文档计算下一个评级，仅重置 平台的副本将在下一场比赛时被撤销。文档中的其他所有内容（胜利、历史） 被独自留下。如果您的脚本以任何其他名称保留其评级，则它是 不是 重写：保留 它在 playerStates[id].elo 免费重置。已经进行的比赛可能仍会报告 重置前计算的评级。 404 当游戏不是你的或者玩家没有评分时 它。评级还取决于 埃罗规则.

重置时间表

任何排行榜（游戏自己的排行榜或目录标题的排行榜）都可以按时间表重新开始：

resetSchedule 重新开始
daily 每天 00:00 UTC
weekly 每个星期一 00:00 UTC
monthly 每月 1 日 00:00 UTC
省略， null 或者 "never" 绝不

任何其他值都是 400。定义报告 currentPeriodStartedAt 和 nextResetAt （两个都 null 对于永远不会重置的板），以便客户可以显示 "2天内重置".

当电路板处于复位状态时，会应用复位 读：条目端点仅显示自此以来提交的分数 当前周期开始，并在该周期内计算排名。没有删除任何内容 边界，因此重置会在 UTC 时间 00:00 准确生效。这也意味着日程可以改变 随时 - 它会更改显示的条目，而不是保留的条目。以前的时期没有 通过API可读。

您的游戏自己的排行榜

除了 elo 棋盘之外，还有一款游戏 server= 脚本或 container.image= 后端可以有 自己的排行榜——高分、最快圈速、最多击杀数——由 游戏的所有者。 您不需要发行商帐户：拥有该游戏即可使您成为其发行商。

就像 elo 板一样， 只有您的游戏服务器才会写入它们。 你的脚本返回 scores: { "<key>": { "<userId>": score } } 从任何钩子（参见 游戏脚本——排行榜），或者你的容器发送一个 scores 控制消息. POST /leaderboards/{id}/submit 是 被拒绝，因此修改后的客户端无法发布分数。

创建一个—— POST /api/v1/me/github-games/{id}/leaderboards

{
  "key": "high-score",
  "name": "High score",
  "scoreType": "integer",
  "sortDirection": "desc",
  "minScore": 0,
  "maxScore": 1000000,
  "isActive": true
}

退货 201 与一个 LeaderboardDefinitionDto 谁 gameDefinitionId 和 key 已设置。

场地 意义
key 必需的。 您的服务器提交的名称：1–64 个字母、数字、 ., _, -。每场比赛都是独一无二的。
name 必需的。 显示名称，最多 200 个字符。
scoreType integer （默认）， decimal， 或者 time-ms （非负整数毫秒）
sortDirection desc （默认值 — 越高越好）或 asc （越低越好，例如单圈时间）
minScore / maxScore 可选边界；忽略它们之外的分数
isActive 默认 true。不活跃的棋盘不接受分数，也不会向玩家列出。
resetSchedule 选修的： daily, weekly 或者 monthly - 看 重置时间表。默认值：从不重置。

key, scoreType 和 sortDirection 创建后无法更改：您的服务器通过密钥提交， 已经存储的分数是由另外两个人选择的。需要另一种吗？创建一个新板。 PUT .../leaderboards/{leaderboardId} 接受 name, minScore, maxScore, isActive 和 resetSchedule （发送 "never" 停止重置）； DELETE 拆下电路板 及其条目 - 放 isActive: false 退休它并保留它们。一个游戏最多可能有 2048 板。

分数如何保存

  • 每位玩家一份参赛作品：他们的最佳作品。 "最好的" 遵循董事会的 sortDirection。提交一个 更差的分数不会改变任何事情，因此在每场比赛后报告而不先检查。在板上有 重新设定时间表，这是最好的 这个时期：重置后的第一个分数始终有效， 无论该球员上节课的成绩有多好。
  • 只有在该会话中的玩家才能得分； AI 座位和其他任何人都被忽略。
  • 违反董事会规则的分数（超出范围、分数 integer 板，负 time-ms) 被忽略，就像没有活动板的键一样。不会向您的服务器报告任何内容。

在你的游戏中展示它们

GET /api/v1/games/{slug}/leaderboards 列出游戏的活动板及其 id 和 key, 并与游戏的启动令牌一起使用。使用上面的标准分页端点读取条目 - GET /api/v1/leaderboards/{id}/entries - 启动代币也可能到达这些主板。
