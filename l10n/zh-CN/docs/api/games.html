游戏API

游戏子系统是 StarHermit 的核心：服务器权威的多人游戏，其规则在沙盒 JavaScript 文件或开发人员提供的容器中运行。两个运行时共享这个面向玩家的 REST API（api/v1/games/{slug}）和游戏玩法 WebSocket（ws/v1/games）。对于服务器创作，请参阅 游戏脚本 或者 容器托管的游戏服务器。有关完整的脚本运行时示例，请参阅 国际象棋演练 和 HypeDriven/明星隐士国际象棋.

基本网址： https://api.starhermit.com.

玩家端点需要身份验证并使用完整的用户令牌和游戏范围的启动 代币。两人 /server/... 端点仅是容器：会话协调使用狭窄的 服务器承载令牌，而令牌更新使用部署刷新密钥。

什么 {slug} 是

游戏的主角就是它的 uid — 与它的值相同 <uid>.starhermit.com 地址，例如 83fd04b1-3cbe-4b09-a251-3733ad4b9d94。它源自游戏的不可变 id 和 什么都没有 可以设置一下： 不是 starhermit.txt，不是存储库名称，也不是操作员。开发人员可以使用的名称 选择将是两个游戏可以争夺的东西，并且需要平台来仲裁谁 明白了； uid 既不能冲突也不能被请求。

slug 不是服务器后端。 从本地文件夹添加的每个游戏以及每个存储库游戏 添加了经过验证的所有者，拥有一个 - 有或没有 server= 或者 container.image= ——因为它是 游戏面向玩家的表面的地址： 启动代币, 控制, 设置， 它是 云保存槽 和 房间。一个 纯浏览器游戏和其他游戏一样需要这些。唯一没有slug的游戏是repository 其所有者未经验证的提交内容（gameSlug 是 null 在 GET /api/v1/me/github-games).

有关游戏服务器的端点 - 游戏信息、成就、会话、匹配、邀请、 重播——需要一个后端。 GET /api/v1/games/{slug} 答案 404 对于一个有子弹但没有子弹的游戏 后端，这是区分两者的方法。

不要对其进行硬编码。从启动令牌中读取它 game_scope 索赔，或 - 对于 平台托管的浏览器游戏 — 来自 location.hostname，因为子域是 uid。

游戏信息

GET /api/v1/games/{slug}

返回游戏定义以及该游戏的调用者统计数据。 404 如果不存在这样的游戏， 或者如果游戏仅限浏览器（它有一个 slug 但没有服务器后端）。

{
  "slug": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "name": "Chess",
  "enabled": true,
  "leaderboardId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "maxConcurrentSessionsPerPlayer": 20,
  "replaysEnabled": true,
  "buildId": "s12",
  "me": {
    "userId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
    "elo": 1200,
    "wins": 4,
    "losses": 2,
    "draws": 1,
    "activeSessionCount": 2
  }
}
  • leaderboardId 是可选的。
  • me.elo 默认为 1200; wins/losses/draws 从服务器运行时拥有的每个玩家文档中读取。
  • replaysEnabled 表示是否保留该游戏的已完成会话 - 阅读它而不是假设，并在保留时隐藏您的重播 UI false。看 重播.
  • buildId 命名当前为游戏服务的服务器逻辑（s + 脚本版本，或者 c + 图像摘要前缀）。将其发回为 ws/v1/games?build=… 所以一个过时的客户端被拒绝 409 {"error":"build_mismatch"} 在它作用于移动的字段之前。省略 build 像以前一样连接。

启动代币

POST /api/v1/games/{slug}/launch-token

铸造一个游戏范围的 JWT（默认生命周期 60 分钟）携带 game_scope={slug} 并且没有任何许可声明。范围内的代币可以为自己的游戏重新铸造代币——这是客户端刷新模式——但更新受到以下限制： launch_chain （默认距离原始用户会话 12 小时）。过了那个天花板更新是 403。客户端应在令牌过期前刷新；例如，国际象棋参考客户端每 45 分钟刷新一次。在重新连接套接字之前也进行更新 - 请参阅 游戏玩法 WebSocket.

{
  "token": "eyJhbGciOi...",
  "expiresInSeconds": 3600
}

成就

GET /api/v1/games/{slug}/achievements

游戏的权威后端声明的每项成就以及调用者的解锁状态。秘密 成就将保持隐藏状态，直到调用者将其解锁。接受完整用户 JWT 或游戏范围 启动令牌。 404 当slug没有权威的游戏定义时。

[
  {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "secret": false,
    "points": 10,
    "unlocked": true,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
]

游戏成就有 服务器权威：只有游戏的脚本或容器才能授予它们， 以及客户声称的 POST /api/v1/me/achievements/unlock 端点拒绝它们。实时解锁 到达游戏套接字 {"type":"achievement"} 帧。完整合同已在 成就, 游戏脚本， 和 容器游戏服务器.

GET /api/v1/games/{slug}/linked-achievements/{otherSlug}

调用者自己的解锁 其他 游戏，所以这个游戏可以基于它们开放功能。作品 使用该游戏的启动令牌。看 成就——其他游戏的成就.

每个玩家的控制绑定

游戏可以声明桌面浏览器控件 control.* 条目在 starhermit.txt。控件 API 存储一个 每个用户和游戏的单独覆盖。完整用户 JWT 和游戏范围的启动令牌是 已接受；启动令牌的 game_scope 必须匹配 {slug}.

GET /api/v1/games/{slug}/controls

按清单顺序返回有效绑定。 codes 包含用户的覆盖时 存在一个，否则 defaultCodes。退货 404 "This game declares no controls." 当 实时构建的 starhermit.txt 没有有效的 control.* line — 声明它们并发布构建；看 教程：向游戏添加控件.

{
  "actions": [
    {
      "action": "up",
      "label": "Run forward",
      "defaultCodes": ["KeyW", "ArrowUp"],
      "codes": ["KeyW", "ArrowUp"]
    },
    {
      "action": "shoot",
      "label": "Shoot",
      "defaultCodes": ["Space"],
      "codes": ["KeyJ"]
    }
  ]
}

PUT /api/v1/games/{slug}/controls

替换调用者的覆盖。这 bindings 对象可能包含声明的子集 行动；省略的操作继续使用其默认值。

{
  "bindings": {
    "up": ["KeyW", "ArrowUp"],
    "shoot": ["KeyJ"]
  }
}

每个动作都必须由游戏声明。每个动作必须有 1-4 个有效 KeyboardEvent.code 值，并且不能将代码分配给结果中的两个操作 有效地图。返回无效的操作、代码或冲突 400.

DELETE /api/v1/games/{slug}/controls

删除所有调用者的覆盖并恢复清单默认值。退货 204。 启动令牌写入是有意的，因此托管游戏可能会提供自己的重新绑定屏幕。

每个玩家的游戏设置

你的游戏保存在哪里 有自己的选择 对于播放器 - 主音量、图形细节、字幕 尺寸、首选相机、最后选择的装载 - 因此他们会跟随该玩家到他们登录的任何机器 从。一种键/值存储，适用于一名玩家和一场游戏。对于与图形一起的语言部分， 音频和控件，请参见 本地化您的游戏并添加语言设置.

没有任何东西声明模式。 该平台存储您的密钥和您的值并且从不读取它们， 因此，您可以通过编写来添加一个选项：没有清单条目，没有重新部署，没有平台发布。那也 意味着平台无法为您验证它们 - 键名称中的拼写错误是一个新设置，而不是一个 错误。

与控制 API 一样，接受游戏范围的启动令牌（其 game_scope 必须匹配 {slug}), 因此，游戏内的选项屏幕除了游戏已持有的代币外什么都不起作用。不像 控制，不需要清单声明：每个游戏从一开始就有设置存储 存在，包括完全没有服务器逻辑的纯浏览器游戏。

选择合适的商店—— 云保存 保留进度（每个标题一个不透明的存档，10 MB，也可以使用启动令牌访问）， 并且脚本或容器后端自己的玩家状态是服务器权威的，并且不可从服务器写入 客户。设置是介于两者之间的、客户拥有的小偏好。

GET /api/v1/games/{slug}/settings

调用者为此游戏存储的所有内容。 settings 对于从未保存过的玩家来说是空的 任何东西——那是 200，不是一个 404。钥匙回来已排序。

{
  "slug": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "settings": {
    "audio.master": 0.8,
    "graphics.detail": "ultra",
    "graphics.options": { "shadows": true, "msaa": 4 }
  },
  "count": 3,
  "bytes": 118,
  "updatedAt": "2026-08-07T15:04:11Z",
  "limits": { "maxKeys": 200, "maxKeyLength": 128, "maxTotalBytes": 2097152, "maxAccountBytes": 67108864 }
}

bytes 是该玩家当前设置的成本 limits.maxTotalBytes。阅读 限制而不是硬编码：津贴是运营商设置，并且可以授予游戏 它自己的。 maxKeys （默认200）也可以设置每场比赛，并且 maxAccountBytes 界限一 每个游戏的帐户设置（默认为 64 MB）。

PUT /api/v1/games/{slug}/settings

替换整个地图。 主体省略的键被删除 — 发送所有内容，或使用 PATCH.

{ "settings": { "audio.master": 0.8, "graphics.detail": "ultra" } }

一个空的 settings 对象为调用者清除游戏设置。返回与以下相同的形状 GET.

PATCH /api/v1/games/{slug}/settings

合并到存储的内容中，留下它没有单独提及的密钥。一个 null 价值 删除 它的 关键。这合并了顶级设置键；对象值替换其键处的整个值， 包括它的嵌套属性。这就是一个 选项屏幕应该使用 - 它可以保存未经第一次读取而移动的一个滑块，并且 重写其他一切。

{ "settings": { "audio.music": 0.25, "graphics.options": null } }

GET / PUT / DELETE /api/v1/games/{slug}/settings/{key}

一次一种设置。 GET 回报 { "key", "value", "updatedAt" }， 或者 404 如果呼叫者有 从未存储过它。 PUT 需要 { "value": <any JSON> } 并存储该值 逐字 — 包括 明确的 null，这里是一个与其他值一样的值，而不是删除。 DELETE 回报 204, 和 删除不存在的东西是无操作而不是错误。

curl -X PUT "https://api.starhermit.com/api/v1/games/$SLUG/settings/audio.master" \
  -H "Authorization: Bearer $LAUNCH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"value": 0.35}'

规则

规则 价值
设置名称 1–128 个字符 A-Z a-z 0-9 . _ - : — 自由命名空间 (audio.master, graphics:shadows)
价值观 任何 JSON：数字、字符串、布尔值、数组、对象、 null
每个玩家、每个游戏的设置 200
每个玩家、每个游戏的字节数 默认 2 MB — 运营商可以提高或降低它，并可以为一款游戏授予不同的津贴

单个设置可能会使用整个字节余量；没有单独的较小的每值上限。

地位 意义
400 设置名称错误，或者主体不正确 {"settings": {...}} / {"value": ...}
404 没有游戏回答该弹头，或者（单键 GET）该键下没有存储任何内容
413 超出限额——要么设置太多，要么字节太多。该消息指出了限制

包含一个坏密钥的批次不会写入任何好密钥。设置是针对每个玩家和每个 游戏：两个玩家之间或同一玩家的两个游戏之间不会发生任何泄漏。他们幸存下来 游戏被禁用或除名，因为它们是玩家的数据而不是游戏的数据。

会议

GET /api/v1/games/{slug}/sessions/mine

呼叫者在此游戏中的活动会话。 myTurn 和 deadline 从脚本状态解析 summary 对象（参见 游戏脚本). pausedAt 被设置同时 执着的 会话已暂停且无人参与，并且 null 否则。

包括室内会议。 A 实时房间的绑定会话列出了房间开始时占据座位的每个人，因此在房间开始时它会出现在每个人的此处 active。 AI席位不在 players。离开房间或关闭房间不会将任何人从会话中删除，因此它会保留在此列表中，直到会话本身结束 - 除了在 正在进行中的加入 房间，离开的玩家让出座位并从会话中删除，而新加入的玩家在比赛中途承认会被添加到其中。响应中没有房间 ID：使用 GET /api/v1/realtime/rooms/joined 呼叫者的房间，并匹配他们的 gameSessionId 反对 sessionId.

[
  {
    "sessionId": "0f8fad5b-d9cb-469f-a165-70867728950e",
    "status": "active",
    "players": [
      { "userId": "7c9e6679-7425-40de-944b-e07fc1f90ae7", "username": "alice" },
      { "userId": "9b2f8c1a-1111-4222-8333-444455556666", "username": "bob" }

    "finishedAt": null,
    "myTurn": true,
    "deadline": 1784642591000,
    "pausedAt": null
  }
]

恢复和明确离开

GET /api/v1/games/{slug}/sessions/{sessionId}/recovery 返回有效快照、恢复、 保留和运输价值。参与者和游戏所有者可以阅读它。时间单位及全部 响应字段的描述见 会话生命周期和恢复.

POST /api/v1/games/{slug}/sessions/{sessionId}/leave 放弃持久世界的成员资格 没有实时房间。它不需要身体并返回 204;人类的最后离开结束了世界。 403 表示不是会员， 404 意味着没有会话， 410 意味着结束，并且 409 意味着非持久性 会话或房间限制的会话。对于房间内的会话，请使用房间的 /leave 端点。闭幕式 单独的套接字可以保留成员身份。看 断开连接并离开.

分享链接（通过 URL 邀请）

上面的邀请流程要求两个玩家已经是朋友。邀请某人 还没有上平台 （或者还不是朋友），游戏可以分发 分享链接 — 网络仪表板的 URL，可自动完成整个入职流程：

https://dashboard.starhermit.com/game-invite/<userId>/<gameSlug>
  • <userId> — 共享玩家的用户 ID。游戏客户端已经有了它：它是 sub 声明其启动令牌（国际象棋参考实现将其公开为 Net.userId).
  • <gameSlug> — 游戏的子弹 (game_scope 宣称）。没有权威脚本或容器后端的游戏使用 GitHub 游戏 ID（GUID）；仪表板接受其中之一。
  • 可选的查询字符串——你的。 之后的任何事情 ? 不变地传递到您的游戏： …/game-invite/<userId>/<gameSlug>?room=K7MP2X&map=arena 打开你的游戏 https://<game-id>.starhermit.com/…?room=K7MP2X&map=arena。用它直接丢下收件人 进入房间、楼层或大厅。它在收件人登录后仍然存在，并且会添加到您的 游戏的 URL，而不是替换其中的任何内容。启动令牌仍然到达 #game_token= 碎片，所以两者永远不会碰撞。对您放入其中的值进行 URL 编码。

当收件人打开链接时， 仪表板 （不是游戏）执行自动好友邀请部分——不涉及新的后端端点，它组成了现有的 API：

  1. 让他们登录（通过实时提供商进行 OAuth），或重用他们现有的会话。链接意图在登录往返过程中仍然存在。
  2. 显示一个同意对话框，命名共享者和游戏，然后 朋友分享者：如果存在，则接受共享者待处理的好友请求，否则发送一个（POST /api/v1/me/friend-requests).
  3. 如果他们的帐户没有昵称，则提示他们选择昵称（游戏显示个人资料昵称 - 请参阅 轮廓).
  4. 启动游戏（平台托管 https://<game-id>.starhermit.com 复制，并在其中包含启动令牌 #game_token= 像往常一样片段）。
  5. 发送 向共享者播放邀请 和 POST /api/v1/games/{slug}/invites - 因此，共享链接以共享者接受的普通游戏邀请结束（仪表板吐司、桌面气球或游戏自己的邀请列表）。如果友谊仍然是待处理的请求，仪表板会将游戏邀请排队并在共享者接受后自动发送。

这对您的游戏客户端意味着什么：

  • 提供链接需要一行字符串构建 — 放一个 "分享邀请链接" 按钮，然后将 URL 复制到剪贴板。看 shareInviteLink() 在 国际象棋参考实现.
  • 接收方无需进行特殊处理。 收件人的邀请通过正常的邀请流程到达：您的 GET .../invites 轮询向共享者显示传入的邀请，接受邀请会创建会话，并且接收者会看到会话出现在 GET .../sessions/mine （显示待处理的传出邀请，以便等待可见 - 国际象棋客户端的 "已邀请 — 等待" 牌）。
  • 仪表板本身也使用这些 URL：每个可玩的托管游戏的详细信息窗格都有一个 复制邀请链接 按钮，Windows 客户端从游戏的上下文菜单中提供相同的按钮。

重播

重播是已完成会话的最终状态文档，由平台保存并返回给 身处其中的玩家。 重播是游戏的一项选择加入功能，除非游戏要求，否则关闭 他们，因为重播是存储，只要比赛记录存在，平台就会保留。

在您的服务器代码中询问它们 - replays: true 于 game 对象为一个 脚本, "replays": true 从 /describe 对于一个 容器服务器 - 并发布更新以应用它。一个平台 操作员也可以以任何一种方式回答特定游戏，因此请对待 replaysEnabled 的领域 GET /api/v1/games/{slug} 作为答案，而不是假设您的声明就是最后一句话。

下面的两个端点都返回 404 对于一场重播已关闭的游戏，一切都无法避免 游戏已完成的会话 - 因此提供重播屏幕的客户端应该阅读 replaysEnabled 第一的。

会话模型

  • 会议 status 是 "active" 或者 "finished".
  • 每个会话都会获得一个每个会话的聊天对话（类型 "game"）以便对手可以聊天和语音通话 没有成为朋友 （看 聊天 和 嗓音).
  • 每个玩家的并发会话上限默认为 20.
  • 一款游戏宣告 persistent 保持空会话 暂停 而不是结束它们；连接到一个即可恢复它。暂停的会话会计入上限。请参阅 持久会话教程.
  • 没有人在玩的活动会话是 退休了 （地位 finished，已放弃）：最后一次后 5 分钟 ws/v1/games 套接字在没有人重新加入的情况下关闭，或者在 24 小时后没有玩家操作的情况下关闭。持久会话会暂停。这也适用于室内会议；关闭他们的房间并不能结束他们。
  • 配对票状态： queued | matched | cancelled | expired.
  • 邀请状态： pending | accepted | declined | cancelled.
  • 会话是通过匹配、邀请接受、AI 端点或实时房间启动创建的 （房间内的会议——参见 实时房间) — 没有 "创建大厅" 端点。
  • Elo更新来自权威脚本（eloUpdates）或容器控制频道，设置用于匹配的评分并发布到游戏排行榜（分数类型 elo). 客户端永远无法直接将分数提交到游戏排行榜 （看 排行榜).

游戏玩法 WebSocket

ws/v1/games?sessionId={guid} （版本中立路线）。进行身份验证 Authorization 标头， ?ticket=， 或者 ?access_token=。仅限参与者（403）；当与启动令牌连接时，其 game_scope 必须与会话的游戏相匹配。完成的会话是 410 {"error":"session_not_active"}。选修的 ?build= 是 buildId 从 GET /games/{slug} — 不匹配是 409 {"error":"build_mismatch"}.

  • 仅文本帧，每帧最大 16 KB。
  • 新的连接取代旧的连接：前一个连接被关闭 PolicyViolation.
  • 连接到暂停的 执着的 会话会在您执行第一个命令之前恢复它。如果无法恢复（通常容器仍在启动），您会得到一个 error 框架和插座用代码关闭 1001;会话保持暂停状态 - 通过退避重新连接。
  • 每次重新连接之前更新令牌。 过期的令牌被拒绝 401 升级之前，浏览器仅将其报告为关闭代码 1006 — 与网络丢失无法区分 — 因此重新连接失败可能是身份验证失败，并且重新打开相同的 ?access_token= URL 永远无法恢复。续订通过 POST /api/v1/games/{slug}/launch-token 并重新连接新令牌。续订仅在当前令牌有效且原始启动后 12 小时（默认）内有效；一旦被拒绝（401/403），停止重新连接并将玩家发送回启动器以获取新的启动令牌。

每场比赛 Elo

该平台确实 不是 限制一场比赛中评分的变化幅度。 eloUpdates （脚本）和 elo 控制消息（容器）携带每个玩家的 新的绝对评级，没有改变，并且 平台按发送时应用它们。它执行什么：

  • 仅会话中的玩家 已更新。其他人的 ID 以及 AI 席位都会被丢弃。
  • 每当您的服务器返回更新时，就会应用更新。一个会话 平台 结束 （abandoned：玩家离开、空闲、被取代、服务器故障、由所有者结束）发布 不 改变。
  • 评级将写入配对配对栏，并作为一个写入游戏的 elo 板 每个玩家的条目（他们的最新评级）。
  • 游戏的主人可以 重置一名玩家的评分 至 1200。

所以挥杆的大小是由你的游戏决定的。在代码中使用标准 K 因子和钳位。这 国际象棋参考实现 使用 K = 32，因此一场比赛移动 a 评分最高 32 分：

function eloAfter(mine, theirs, score /* 1 win, 0.5 draw, 0 loss */, K = 32) {
  const expected = 1 / (1 + Math.pow(10, (theirs - mine) / 400));
  const next = mine + K * (score - expected);
  return Math.round(Math.max(100, next));      // your floor, if you want one
}

游戏的生命周期

  1. 铸造启动令牌 — POST /api/v1/games/{slug}/launch-token。客户端应在到期前刷新（国际象棋参考客户端每 45 分钟刷新一次）。
  2. 获取游戏状态 — GET /api/v1/games/{slug} 获取信息+您的统计数据； GET .../sessions/mine 对于正在进行的游戏； GET .../invites 和 GET /api/v1/realtime/rooms/invites 对于待处理的邀请； GET .../replays/mine 对于历史当 replaysEnabled; GET .../achievements 用于成就屏幕。
  3. 寻找对手，以下三种方式之一：
    • 对接会： POST .../matchmaking，然后轮询 GET .../matchmaking 每 3 秒一次，直到 status 是 matched （响应携带 sessionId). DELETE .../matchmaking 取消。
    • 邀请流程： 从中选择一个朋友 GET /api/v1/me/friends （看 朋友们), POST .../invites 和 { "toUserId": "..." };受邀者致电 POST .../invites/{inviteId}/accept，这会创建会话。 （如果您的游戏让玩家坐在 实时房间 首先，邀请他们到房间 - 同样的通知，但接受后会将他们放在您已经所在的桌子上。）
    • 人工智能实践： POST .../sessions/ai.
  4. 加载会话 — GET .../sessions/{sessionId}.
  5. 连接 WebSocket — ws/v1/games?sessionId={guid} 使用启动令牌，然后发送游戏后端定义的任何初始同步命令 - 例如，国际象棋参考实现发送 {"type":"cmd","data":{"type":"sync"}}.
  6. 玩 - 交换 cmd/game 由后端、表面定义的框架 achievement 框架和手柄 resumed 通过放弃预测并请求完整状态。
  7. 结果 ——权威后端结束游戏；该平台将 elo 更新发布到排行榜，并且对于具有 重播，归档最终状态。
  8. 重播 — GET .../replays/{sessionId} 完整的最终状态。
