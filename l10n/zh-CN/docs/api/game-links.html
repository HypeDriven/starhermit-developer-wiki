外部链接

StarHermit引擎游戏（主机API 1.24）可以打开网页，但只能打开StarHermit工作人员的网页 已批准您的游戏。您的游戏通过 id 打开链接，但从不传递 URL，因此无法添加 任何事物对一。

声明您的链接

在 starhermit.txt:

engine.minor=24
engine.link.discord=https://discord.gg/abc
engine.link.store=https://example.com/game
  • 您最多可以声明 16 个链接。每个 id 为 1–32 个字符 a-z 0-9 - 并且可能只出现一次。
  • 任何 engine.link.* 关键需求 engine.minor=24，因此较旧的运行时会拒绝该游戏。
  • 你的脚本调用 openLink("discord")。运行时显示其自己的确认，以及链接的 完整的主机和 URL，并且仅当玩家选择“打开”时才打开页面。

链接可能是什么

必须有一个链接 https，没有端口，没有 user@，没有 IP 地址，也没有本地名称（localhost, .local, .internal）。它的主机必须是 ASCII，国际化名称写为 punycode， 并且至少有两个标签。它不能包含反斜杠、空格、编码斜杠 (%2f, %5c） 或者 ./.. 路径段。该平台保持规范的形式：方案和主机 小写，和 / 为空路径。其他一切都完全按照您编写的方式保留。

发布时，包含违反规则的链接的包会被拒绝， 和 422 invalid_link: engine.link.<id> is not an allowed link (<rule>)，在一切上线之前。

审查

每个新链接都开始 pending，并且运行时不会打开任何内容，直到工作人员批准为止。一些链接是 自动拒绝：URL 缩短程序和重定向服务，其目的地是其他人 控制以及程序和档案的直接下载（.exe, .dmg, .apk, .zip 和 类似）。跟踪参数，例如 utm_* 已标记给审阅者。

批准属于您的游戏和该确切的 URL。更高版本列出了相同的 URL，位于 任何 id，保留它。更改 URL 需要重新审核。工作人员可以撤销批准或阻止 整个主机，随时。

查看您的链接及其状态： GET /api/v1/me/github-games/{id}/links:

[ { "id": "discord", "url": "https://discord.gg/abc", "status": "approved", "autoReason": null, "note": null } ]

运行时检查 GET /api/v1/games/{slug}/links/{id} 每次打开时，随着玩家的启动 令牌。答案是 { id, url, status }， 在哪里 status 是 approved, pending, rejected 或者 revoked， 或者 404 link_unknown 对于您部署的清单未声明的 id。

当您在本地开发时（--dev 本机或浏览器中的环回页面，无需启动 令牌），运行时打开声明的链接，并警告它们未经审查。
