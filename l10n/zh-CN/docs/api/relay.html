中继

中继为游戏网络代码提供不透明字节扇出：REST API（api/v1/relay) 管理 会议，以及 ws/v1/relay 在参与者之间逐字转发二进制帧。每个继电器都是 绑定到恰好一个现有匹配项 - a 游戏环节 或一个 实时房间——并且 使用该比赛的名单进行授权。

所有 REST 端点都需要身份验证 - 完整的用户令牌或用于中继的游戏启动令牌 绑定到该游戏自己的会话和房间：列表仅显示这些以及任何其他中继答案 404 （或者 403 创建一个）。启动令牌的中继需要 它自己的游戏的id为 titleId — 其 uid game_scope 索赔 - 任何其他所有权均被拒绝 403，因为每个标题 会话上限由此计算。错误返回为 {"error":"..."}: 403 当呼叫者是 不在绑定比赛中或接力赛属于另一场比赛， 404 对于未知的继电器， 409 对于一个 拒绝请求的状态（未绑定、已满、关闭、已加入或达到会话上限），以及 503 当继电器关闭时。

REST 端点

根据： https://api.starhermit.com/api/v1/relay.

方法 小路 授权 描述
得到 /?titleId= 智威汤逊 列出该标题的活动中继会话，其绑定匹配项包括呼叫者
邮政 / 智威汤逊 创建绑定到一场比赛的中继
得到 /{sessionId} 智威汤逊 获取中继会话 - 仅对其绑定匹配的成员可见（404 否则）
邮政 /{sessionId}/join 智威汤逊 加入接力；调用者必须在其绑定匹配中
邮政 /{sessionId}/close 智威汤逊 关闭中继（仅限创建者）

匹配绑定

中继会员资格并不是一个独立、开放的游说团体。比赛名单是事实来源：

  • 继电器有一个 gameSessionId 或者 realtimeRoomId，永远不会两者兼而有之，也永远不会两者都不是。
  • 创建者必须属于该游戏会话或在该实时中持有活跃的非左侧席位 房间。
  • 后来的每次加入都会根据同一个名单进行检查。
  • 打开 WebSocket 需要活跃的中继参与者行和当前的成员资格 绑定匹配。因此，离开实时房间可以防止稍后/替换的中继连接。
  • 列表依据 titleId 仅返回绑定到调用者所属匹配的中继；它不是一个 该标题的每场现场比赛的目录。

这是必需的请求形状更改。传统的未绑定中继行无法授权套接字；创造 取而代之的是一个新的绑定中继。

创建会话

POST /api/v1/relay

绑定权威游戏会话：

{
  "titleId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "maxParticipants": 8,
  "gameSessionId": "0f8fad5b-d9cb-469f-a165-70867728950e",
  "realtimeRoomId": null
}

或者绑定到实时房间：

{
  "titleId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "maxParticipants": 8,
  "gameSessionId": null,
  "realtimeRoomId": "b1d2c3e4-5f60-4a71-8b92-c3d4e5f60718"
}

maxParticipants 默认为 8。每个标题最多可以存在五个活动中继会话 默认。如果绑定计数不正好为 1 或者调用者不在集合中，则调用将被拒绝 选定的比赛。

接力不会创建游戏会话或房间。通过以下方式创建/加入匹配 游戏API 或者 实时房间 API 首先，然后将其 ID 传递到此处。

会话形状

{
  "id": "d290f1ee-6c54-4b01-90e6-d701748f0851",
  "titleId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "creatorUserId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "gameSessionId": "0f8fad5b-d9cb-469f-a165-70867728950e",
  "realtimeRoomId": null,
  "isBound": true,
  "maxParticipants": 8,
  "currentParticipantCount": 1,
  "status": "Active",
  "createdAt": "2026-07-28T11:30:00Z",
  "closedAt": null,
  "participants": [
    {
      "id": "e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b",
      "sessionId": "d290f1ee-6c54-4b01-90e6-d701748f0851",
      "userId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
      "connectionId": null,
      "joinedAt": "2026-07-28T11:30:01Z",
      "leftAt": null,
      "status": "Connected"
    }
  ]
}

恰好有一个绑定 ID 为非空且 isBound 因此是 true。会议 status 是 "Active" 或者 "Closed"; closedAt, connectionId， 和 leftAt 可能不存在或为空。

加入并关闭

POST /api/v1/relay/{sessionId}/join 返回更新后的 RelaySession。此 REST 连接是必需的 在打开 WebSocket 之前。一个空闲的中继槽是不够的：呼叫者必须仍然是 绑定的匹配。

POST /api/v1/relay/{sessionId}/close 回报 204 并且仅限创作者使用。

网络套接字： ws/v1/relay

连接到：

wss://api.starhermit.com/ws/v1/relay?sessionId=<relay-id>&titleId=<title-id>

进行身份验证 Authorization: Bearer <token> 标头， ?ticket=， 或者 ?access_token= 查询参数。 握手返回 403 除非用户加入中继并且仍然被其绑定授权 比赛。

该套接字是不透明字节扇出的。每个二进制帧都会原封不动地转发给其他每个二进制帧 连接的参与者。没有 JSON 框架，平台不解释游戏数据。 默认情况下，最大消息大小为 4 KiB。

滴答率感知速率限制

连接断开规则： 如果客户端发送中继命令/帧的速度快于允许的速率， StarHermit 关闭该客户端的中继 WebSocket PolicyViolation。这不是一个队列或 尽力而为丢帧 — 客户端连接终止并且必须重新连接。

每个发送者的最小间隔是根据绑定匹配的速率得出的：

minimum interval ms = (1000 / max(pacingRateHz, 1)) × 0.90

10% 的余量允许普通定时器和网络抖动。汇率绝不会低于以下 1赫兹, 因此，无论游戏速度如何缓慢，限制都不会要求两帧之间的静默时间超过约 900 毫秒 滴答声。示例：

有效率 最小发送间隔
20赫兹 45毫秒
30赫兹 30毫秒
60赫兹 15毫秒
120赫兹 7.5毫秒

对于游戏会话，速率来自其游戏定义。对于实时房间，房间的 gameSlug 被解析为游戏定义。正常有效率优先适用： 运营商覆盖，然后是游戏请求的速率。继电器限位的作用是什么 不是 跟随是一个 比率没有说明玩家彼此交谈的频率：如果没有定义可以 已解决，如果游戏选择退出服务器 0，或者如果它根本不要求任何利率等等 采用平台的缓慢默认值，限制的大小取决于全局速率。游戏从来都不是 每隔几秒就限制为一条消息，因为没有人在其服务器代码中写入数字。价格 以平台天花板为界。

客户端必须将命令调整到此间隔或更慢。发送两个命令/帧靠得更近 超过最小间隔被视为泛洪：StarHermit 会断开该客户端的连接 关闭其中继 WebSocket PolicyViolation。发件人受到独立限制，因此 客户端的违规行为不会断开其他玩家的连接。

推荐客户流程

  1. 创建或加入实际的游戏会话/实时房间。
  2. 让一名比赛成员使用该比赛 ID 创建中继。
  3. 仅通过比赛的经过身份验证的状态或名册消息共享返回的中继 ID。
  4. 对方比赛成员呼叫 POST /api/v1/relay/{relayId}/join.
  5. 各会员开 ws/v1/relay 并调整游戏有效滴答率的框架；发送 更快地断开该客户端的 WebSocket 连接。
  6. 当比赛结束时，创建者关闭接力。

不要使用中继 ID 作为授权秘密。平台对绑定名册进行授权； ID 仅标识资源。

定位

将中继用于需要低开销对等扇出的快节奏游戏。是故意装傻的 传输：绑定确保谁可以参与，但平台仍然不解析或验证 有效负载、选择权威同行或解决作弊问题。

对于服务器强制的规则和状态，请使用 游戏API 使用沙盒脚本或 容器后端。实时房间提供大厅、座位、配对等 主机感知路由；中继现在可以绑定到其中一个房间，而不是复制其名单。

在交付依赖于继电器的功能之前，请确认继电器的可用性。
