验证

星隐者有 没有密码验证。有两种登录流程：公钥身份验证（Ed25519、ECDSA-P256 或 RSA-PSS，通过电子邮件验证注册）和 OAuth。所有身份验证路由都位于 api/v1/auth 除非另有说明，否则均为匿名。此页面还涵盖令牌生命周期、游戏范围的启动令牌和 WebSocket 连接票证。

错误体各不相同；看 API约定.

登录后：当前条款

成功登录并不意味着有权使用受保护的 API。账户持有人必须 接受当前的星隐者条款 在受保护的 REST 调用之前或 WebSocket升级成功。账户客户可以查看 GET /api/v1/me， 拿来 GET /api/v1/terms, 并记录明确接受 POST /api/v1/me/terms/accept。 OAuth 和公钥 帐户会话支持此流程。刷新凭证并不能解决等待接受的问题。

直接打开的浏览器游戏可以在帐户接受之前接收范围令牌。 如果游戏调用返回 403 和 error: "terms_acceptance_required"， 拿来 GET /api/v1/terms, 显示其文本，并提供明确的接受操作。玩家启动令牌可以提交显示的 散列到 POST /api/v1/me/terms/accept;接受后重试原始请求。不要治疗这个 作为过期令牌登录循环的响应。

POST /api/v1/auth/public-key/register

开始公钥注册并发送验证电子邮件。待处理的注册记录将在 4 小时后过期。如果 userId 设置后，电子邮件必须与该帐户匹配。每 24 小时每个地址和每个 IP 限制为 1 封电子邮件 — 限制后，响应为 429，并带有 Retry-After 标头。

什么时候 userId 已设置并且该对未签出，响应为 403 一条消息 不管 为什么：未知帐户和错误地址的答案相同。该端点需要 没有凭证——它必须如此，因为这是附加新密钥的方式——所以区分它们会 使其成为存在用户 ID 和地址的预言机。呼叫者拥有 帐户已经知道他们错了两者中的哪一个。

要求：

{
  "email": "dev@example.com",
  "keyType": "Ed25519",
  "keyData": "<base64-raw-32-byte-public-key>",
  "userId": null
}

响应 — 202：

{
  "registrationId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "email": "dev@example.com",
  "emailSent": true,
  "deferralReason": null,
  "message": "A verification email has been sent. The key will be attached once you confirm."
}

emailSent: false 表示电子邮件已排队等待重试（deferralReason 说出原因）；登记 仍然被接受。电子邮件或密钥材料无效 400.

GET / POST /api/v1/auth/public-key/verify?token=

打开通过电子邮件发送的链接不会改变任何情况。 GET 显示一个页面，说明确认会做什么 - 创建一个帐户，或者 向现有帐户添加密钥 已经使用该地址 - 带有 确认按钮。邮件扫描仪获取链接以预览它们，因此作用于的电子邮件链接 GET 任何扫描它的东西都会被赎回。这同样适用于 撤销 和 身份链接 以下确认。

POST 到相同的 URL 兑换它：附加密钥，创建用户（用户名 pk-<hex12>， 角色 User) 除非帐户已使用该电子邮件地址，在这种情况下，密钥会加入该帐户。 该电子邮件已标记为已验证。该链接是一次性的，4小时后失效；未知的、使用过的或 过期的令牌是 400，地址不再是该帐户的链接也是如此——这证明了 控制其发送到的收件箱，并且仅当该地址仍然是该帐户的地址时。

当玩家按下页面上的“确认”后，部署设置 PublicKeyAuth:VerificationSuccessRedirectUri — starhermit.com 确实如此，在仪表板上 — 他们是 与片段中的令牌一起发送到那里 （#access_token=…&refresh_token=…&token_type=Bearer&expires_in=900)，登录到仪表板。一个 因此本机客户端不会收到这些令牌；一旦玩家登录，它就会用密钥登录 已确认。一个 API 客户端 POSTURL 本身获取 JSON：

{
  "userId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "keyId": "9b2f5c74-1d2e-4a6b-8c0d-1e2f3a4b5c6d",
  "accessToken": "eyJhbGciOi...",
  "refreshToken": "dGhpcyBpcyBh..."
}

POST /api/v1/auth/public-key/challenge

发出登录挑战，有效期为 5 分钟且一次性使用。

签名覆盖了服务器自己的序列化 payload，不是您收到的 JSON： 紧凑、PascalCase 名称的顺序 ChallengeId, Fingerprint, Issuer, Audience, Expiry, Nonce, ClientTimestamp，值完全按照所提供的方式复制，并且每个 + 在随机数中写为 \u002B （日期保留其 +）。请参阅 工作示例.

{

}

{

  "payload": {

    "clientTimestamp": "2026-07-22T07:19:44.1235521+00:00"

POST /api/v1/auth/public-key/complete

根据注册的、未撤销的密钥验证签名并返回令牌对。失败是 401: "Public key not registered or revoked." （包括未通过电子邮件发送链接的密钥 还没开）， "Invalid signature."， 或者 "Challenge not found or expired."。挑战并完成 每个 IP 每分钟共享 60 个请求的限制（429).

要求：

{
  "challengeId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "signature": "base64-signature...",
  "keyType": "Ed25519",
  "keyData": "<base64-raw-32-byte-public-key>"
}

回复：

{
  "userId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "accessToken": "eyJhbGciOi...",
  "refreshToken": "dGhpcyBpcyBh..."
}

代币生命周期

POST /api/v1/auth/refresh

轮换刷新：旧令牌被撤销并替换。重复使用已撤销的刷新令牌会撤销整个令牌系列。

要求：

{ "refreshToken": "dGhpcyBpcyBh..." }

回复：

{
  "accessToken": "eyJhbGciOi...",
  "refreshToken": "bmV3IHJlZnJlc2g..."
}

当刷新停止工作时

刷新令牌记录其发出时的帐户状态，并刷新对其进行检查。两个答案 您的客户端必须处理而不是重试：

地位 意义 客户应该做什么
401 该会话被平台端撤销——a "到处注销"，或妥协的回应。整个代币家族都被烧毁，包括刚刚提交的代币。 丢弃这两个令牌并开始新的登录。
403 该帐户是 暂停. 停止。再次登录也无济于事；相同 403 从每个登录路线返回，直到解除暂停。

这 403 是故意区别于 401，因为两者需要相反的反应：一个意味着 "再次验证",另一种意思是 "再次验证是没有意义的"。被暂停的帐户是 被拒绝 每一个 凭证创建路由 — 刷新、公钥完成、OAuth 回调、 和游戏启动令牌——不仅仅是通过刷新。

POST /api/v1/auth/logout

撤销给定的刷新令牌。返回 200。

开放认证

该平台提供七个提供商： google, github, discord, twitch, gitlab, linkedin, bitbucket. 只有此部署具有凭据的提供商才是活动的。 客户不得 对列表进行硬编码。

GET /api/v1/auth/oauth/providers

匿名的。按应提供的顺序返回实时提供程序：

{
  "providers": [
    {
      "provider": "google",
      "displayName": "Google",
      "authorizeUrl": "/api/v1/auth/oauth/google/authorize",
      "linksExistingAccountsByEmail": true
    }
  ]
}

linksExistingAccountsByEmail 是在该提供商处登录是否可以找到此人的帐户 已经有（运营商对该提供商的信任设置）。请求授权不属于该名称的名称 住的是 404，而不是重定向到提供商自己的错误页面。

GET /api/v1/auth/oauth/{provider}/authorize?link=&client=

返回 302 重定向到提供商并设置 oauth_state cookie（HttpOnly，SameSite=Lax，10 分钟）。 link=true 开始将身份链接到当前登录的用户；链接需要 最近的身份验证（5 分钟内）。 client 选择支持的客户端重定向。对于一个 直接打开游戏，使用 gameId 和可选的 returnUrl 反而;看 从直接打开的浏览器游戏登录.

GET /api/v1/auth/oauth/{provider}/callback?code=&state=

对于普通帐户登录，返回 302 重定向到前端 URL，其中包含令牌 片段（游戏登录直接将范围令牌返回到游戏，如下所述）：

#access_token=…&refresh_token=…&token_type=Bearer&expires_in=900

如果提供商拒绝令牌交换，则回调应答 409 命名提供者的错误 代码 （描述保留在服务器日志中）。

正常登录会查找或创建用户（用户名 oauth-{provider}-{guid}， 角色 User）和 新会话记录 auth_method=oauth。一个登录名 (provider, providerUserId) 未知的是 转入现有账户 仅当提供者的断言可信时，恰好有一个 帐户已持有该经过验证的电子邮件，并且该帐户尚未获得该提供商的身份。 其他任何事情都需要一个单独的帐户。收养通过电子邮件向帐户发送指定提供者的信息。

这很重要，因为只有经过 OAuth 验证的会话 可能会执行影响较大的凭证更改：

  • 添加或撤销账户公钥；
  • 更改帐户电子邮件；
  • 删除 OAuth 管理的身份。

游戏范围的代币永远无法执行这些操作。刷新令牌保留原始令牌 会话的身份验证方法，因此刷新 OAuth 会话不会删除此功能，并且 刷新公钥会话不会添加它。

什么时候 link=true，回调不会仅仅因为访问过而自动提升会话 OAuth 提供商。从 OAuth 会话启动的链接会立即附加。链接始于 公钥、电子邮件验证或旧会话将一直保留，直到帐户所有者打开 确认信息发送至帐户的经过验证的电子邮件；重定向片段报告 link=pending_email_confirmation。一次性电子邮件打开 GET /api/v1/auth/oauth/link/confirm?token=…, 命名提供者帐户的页面不会改变任何内容；它的确认按钮 POST是相同的 URL， 这创建了身份（{ "provider", "linked": true } 到 API 客户端）。一个链接，其地址 不再是该帐户的被拒绝。这可以防止被盗的公钥链接到 攻击者的提供商帐户并将其转变为永久 OAuth 登录。

GitHub 身份元数据存储 {"login":"…"} — 这用于存储库所有权检查 GitHub 游戏.

用于自动化的 OAuth 注册公钥

OAuth 会话可以调用 POST /api/v1/me/public-keys 立即附上贴有标签的机器钥匙。 随后，CI 签署正常的公钥质询并使用其短期访问令牌上传 拥有的游戏捆绑包；私钥永远不会离开 CI 秘密存储。看 CI/CD 构建上传教程 用于设置、签名助手和 GitHub Actions 工作流程。

代币

  • 访问令牌 — JWT，15 分钟生命周期（expires_in=900）。索赔包括 sub （用户 ID）加上 permission 和角色主张。撤销立即生效。
  • 刷新令牌 — 具有 7 天生命周期的不透明旋转代币。每次刷新都会发出一个新的刷新令牌并撤销旧的刷新令牌；重用已撤销的令牌会撤销整个令牌系列。

从直接打开的浏览器游戏登录

在仪表板外部打开的托管游戏可以显示 登入 按钮链接到：

https://api.starhermit.com/api/v1/auth/games/{gameId}/sign-in

gameId 是游戏的不可变 UUID（子域 {gameId}.starhermit.com）。星隐士 显示其启用的登录提供程序。继续签入现有球员或创建新球员 使用普通 OAuth 帐户匹配规则的帐户，然后重定向 直接回到 游戏，无需访问仪表板。

可选的 returnUrl 保留特定的游戏页面、查询字符串或哈希路由。一定是 位于该游戏托管源的绝对 HTTPS URL；其他游戏、外部主机、 URL 和备用端口中的凭据被拒绝 400。省略它返回 发布的启动文件。未知、已删除、未托管或从未发布的游戏回归 404。两者都 支持存储库部署和上传游戏；任意外部/本地 URL 都不是。

将浏览器导航至 公共API来源 上面，而不是获取页面或启动 通过游戏的 /api 代理人。 OAuth 状态 cookie 和提供者回调必须使用相同的 API 主机。当游戏没有有效的启动器提供的或之前获得的令牌时，请使用此流程。

按钮和返回令牌示例

<button id="starhermit-sign-in">Sign in</button>
<script type="module">
const api = 'https://api.starhermit.com';
const gameId = 'YOUR_GAME_UID';
const signIn = document.querySelector('#starhermit-sign-in');
let gameToken = null; // Or your existing launcher-provided game token.

// Read this before your game router or third-party scripts consume the fragment.
const auth = new URLSearchParams(location.hash.slice(1));
if (auth.has('access_token')) {
  gameToken = auth.get('access_token');
  const originalHash = auth.get('game_fragment');
  history.replaceState(null, '', location.pathname + location.search +
    (originalHash ? '#' + originalHash : ''));
}
signIn.hidden = Boolean(gameToken);
signIn.addEventListener('click', () => {
  const url = new URL(`/api/v1/auth/games/${gameId}/sign-in`, api);
  url.searchParams.set('returnUrl', location.href);
  location.assign(url.href);
});

// Pass gameToken to your game's API client as Authorization: Bearer <gameToken>.
// This example keeps it in memory; a reload can require sign-in again.
</script>

返回片段为：

#access_token=…&token_type=Bearer&expires_in=3600

access_token 是一个 游戏范围的启动令牌，不是帐户范围的访问令牌。没有刷新令牌 已发出。 expires_in 使用部署配置的启动令牌生命周期（默认 3600 秒）。原始返回 URL 片段被编码在可选的 game_fragment 场地; 捕获令牌并从浏览器历史记录中删除身份验证数据后恢复它。 不要记录或转发令牌。

到期前续订使用 POST /api/v1/games/{gameId}/launch-token 当前令牌为 承载授权，然后替换为返回的 token。通常的更新链上限 适用（默认 12 小时）。如果令牌过期或续订被拒绝，请将其清除并显示登录 再次。看 游戏启动代币.

自己选择提供商

游戏可以代替阅读 GET /api/v1/auth/oauth/providers 并导航到提供的 authorizeUrl 在公共 API 源上，添加 gameId 以及可选的 returnUrl。授权步骤 验证目标并将其存储在现有的十分钟 OAuth 状态中；回调查询参数 无法改变它。仍然需要发起浏览器的 cookie，并再次检查游戏 在发行令牌之前。暂停的帐户无法接收令牌。

不要将游戏登录与 client 或者 link (400). A returnUrl 没有 gameId 也是 400。正常仪表板和桌面登录继续使用其配置的前端目标 和普通账户代币对。

游戏启动代币

POST /api/v1/games/{slug}/launch-token (JWT) 铸造一个游戏范围的 JWT：

{
  "token": "eyJhbGciOi...",
  "expiresInSeconds": 3600
}

该令牌带有一个 game_scope 声明并默认为 60 分钟的生命周期。续订副本 launch_chain 开始时间向前；过去 12 小时（默认）续订是 403 持有者必须离开 返回到完整的帐户会话。完整详细信息位于 游戏.

重新连接插座。 使用启动令牌打开的套接字（?access_token= 在 ws/v1/games, ws/v1/realtime, ws/v1/voice) 在其 URL 中携带该令牌，并使用过期令牌进行握手 被拒绝 401 升级之前 - 浏览器仅报告关闭代码 1006，与 网络掉线。将失败的重新连接视为可能的身份验证失败：在重新打开之前，通过更新 POST /api/v1/games/{slug}/launch-token （仅当当前令牌仍然有效并且 最初启动后 12 小时内）并使用新令牌构建 URL。一旦续订 拒绝，将玩家送回启动器，或通过 游戏登录 如果这就是游戏的打开方式。 重试相同的 URL 永远无法恢复。

游戏范围击剑

游戏范围的代币只能达到：

  • 它自己的 /api/v1/games/{scope} 树，
  • /ws/v1/games,
  • 实时房间 REST 路线和 /ws/v1/realtime 对于自己的游戏，包括连接门票，
  • GET /api/v1/time 和 GET /api/v1/terms,
  • POST /api/v1/me/terms/accept 经身份验证的玩家明确同意，
  • GET /api/v1/me/friends,
  • GET /api/v1/users/{id}/avatar 和 GET /api/v1/users/{id}/profile,
  • 它的游戏排行榜，
  • 玩家的 云保存 对于自己的游戏（/api/v1/me/cloud-saves/game:<scope> 和它的 /info) — 没有其他键，
  • 附加到其自己的游戏会话的聊天/语音 REST 和 WebSocket 端点，
  • GET /api/v1/github-games/{id}/icon 和 /cover 对于任何游戏（无论如何都是公开的），
  • POST /api/v1/me/heartbeat，仅标记玩家在线，
  • GET /api/v1/github-games/{id}/release-notes 为了自己的游戏，
  • 中继 路线，用于绑定到其自己的游戏会话或房间之一的中继。

/ws/v1/chat 被阻止启动令牌。其他一切都返回 403。

典型登录流程（curl）

公钥登录，从质询到经过身份验证的调用：

# 1. Request a challenge
curl -s -X POST https://api.starhermit.com/api/v1/auth/public-key/challenge \
  -H "Content-Type: application/json" \
  -d '{"keyType":"Ed25519","keyData":"<base64-raw-32-byte-public-key>"}'
# → { "challengeId": "...", "payload": { ... }, "expiresIn": 300 }

# 2. Sign the serialized payload JSON with your private key, then complete
curl -s -X POST https://api.starhermit.com/api/v1/auth/public-key/complete \
  -H "Content-Type: application/json" \
  -d '{"challengeId":"...","signature":"base64-signature...","keyType":"Ed25519","keyData":"<base64-raw-32-byte-public-key>"}'
# → { "userId": "...", "accessToken": "...", "refreshToken": "..." }

# 3. Call the API with the access token
curl -s https://api.starhermit.com/api/v1/me \
  -H "Authorization: Bearer eyJhbGciOi..."

# 4. When the access token expires (after 15 min), rotate the refresh token
curl -s -X POST https://api.starhermit.com/api/v1/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{"refreshToken":"dGhpcyBpcyBh..."}'

# 5. On logout, revoke the refresh token
curl -s -X POST https://api.starhermit.com/api/v1/auth/logout \
  -H "Content-Type: application/json" \
  -d '{"refreshToken":"dGhpcyBpcyBh..."}'

OAuth 登录是浏览器驱动的：阅读 GET /api/v1/auth/oauth/providers, 打开一个实时提供者的 authorizeUrl，完全同意，回调将用户带到前端 #access_token=…&refresh_token=… 在 URL 片段中。

通过电子邮件发送密钥撤销

对于无法到达的业主 DELETE /me/public-keys （没有 OAuth 会话，或者被盗的锁定 键）。 POST /api/v1/auth/public-key/revoke-request 和 { "email": "…" } 持有请求并且 通过电子邮件发送链接。打开它（GET /api/v1/auth/public-key/revoke/confirm?token=…）显示一个页面 没有改变任何东西；它的确认按钮 POST是相同的 URL，这会撤销 每一个 激活键 帐户并结束他们验证的会话。两者均未经身份验证，并且 问题号 会话。请求总会得到答复 202 无论它发现什么，都用同一个身体；每一个请求 每 15 分钟帐户一次，链接在 4 小时后过期。确认的 POST 答案 200 { "revoked": <count>, "sessionsEnded": <count> } 到 API 客户端，或 400 对于未知的、使用过的或 过期的令牌，或其地址不再是该帐户的令牌。

WebSocket 连接票证

POST /api/v1/realtime/connection-tickets 将呼叫者的不记名令牌交换为一次性门票 有效时间约30秒。将其传递为 ?ticket= 在任何 /ws/v1/* 握手。它携带呼叫者的 逐字索赔（包括 game_scope 和 pk)，在 REST 上被拒绝，并在第一次使用时被花费。 任何经过身份验证的调用者都可以询问，包括游戏范围的启动令牌。 ?access_token= 仍然有效 直到客户搬家。

当其凭证被撤销时，打开的套接字就会结束。 撤销打开它的公钥结束 立即；任何地方的暂停或注销都会在大约 30 秒内结束。令牌到期 不结束打开的套接字 - 在重新连接之前刷新。

原生/店面游戏的嵌入式入门

Steam、Epic、GOG 或独立客户端可以在玩家的设备上生成密钥并呈现 公钥注册流程位于其自己的 UI 内，避免了 OAuth 和对 StarHermit 的访问 仪表板。注册并非无声：玩家必须同意、提供电子邮件并遵循 一次性验证链接。游戏服务器令牌无法创建或模拟玩家。看 教程：使用公钥加入玩家，以及 专用服务器教程 对于还附带服务器的游戏。
