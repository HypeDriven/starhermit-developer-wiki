软件目录

该软件目录涵盖浏览和声明标题、列表版本、下载、云保存、愿望清单和评级。读取是匿名的；写入需要 JWT。

基本网址： https://api.starhermit.com。所有路线均在 /api/v1/....

浏览和认领标题

方法 小路 授权 描述
得到 /api/v1/software 匿名的 搜索并分页目录

POST /api/v1/software/{id}/claim 仅适用于免费游戏（priceCents == 0）；它向调用者授予权利并返回 204。对于付费游戏，它返回 402，其中：

{"error": "purchasing is not available yet"}

POST /api/v1/software/{id}/launch 需要一个权利（否则为 403）并返回 LaunchSession:

{
  "launchId": "…",
  "startTime": "…"
}

它记录启动活动，如果用户的隐私设置如此，则该活动将被隐藏（请参阅 profile.md）。结束会话 POST /api/v1/activity/launches/{id}/end - 看 activity.md。用户的权利通过以下方式列出 GET /api/v1/me/entitlements （看 profile.md).

云存档

每场比赛一个槽位，最后写入者获胜。所有路由都需要 JWT——完整的用户令牌，或者游戏的令牌 该游戏自己的插槽的启动令牌（如下）。

10 MB 上限（10,485,760 字节）适用于 解码保存，而不是请求。 PUT 采取 以 JSON 形式保存 base64 编码，因此正文大约比保存的大三分之一 — 大约 14 MB 上限——API 接受这一点。

限额（每个账户） 默认 拒绝
一次保存，解码 10MB 413 cloud_save_too_large
有保存功能的游戏 200 409 cloud_save_slots_exhausted （新游戏的保存）
全部一起保存 1GB 507 cloud_save_quota_exceeded， 和 used
上传 一分钟30个 429， 和 Retry-After

每次拒绝将有效号码命名为 limit。总额是根据账户的 其他 保存，因此插槽总是可以被不更大的东西覆盖。运营商可以更改任何 这些是一个帐户的。

得到 /api/v1/me/cloud-saves/{gameKey} 智威汤逊 application/zip 字节，如果没有则为 404
放 /api/v1/me/cloud-saves/{gameKey} 智威汤逊 上传保存（解码保存≤ 10 MB， gameKey ≤ 300 个字符）

从游戏内部保存（启动令牌）

使用其启动令牌运行的游戏可以读取和写入玩家的保存 那场比赛。 您的游戏无论在何处运行都会自行保存 - 浏览器或运行的 StarHermit 桌面应用程序 也在浏览器中托管游戏 - 因此保存会跟随玩家之间的情况。

关键是 game:<gameId>， 在哪里 <gameId> 是你的游戏的 id — 与它的 slug 值相同，它的 <gameId>.starhermit.com 地址，以及 game_scope 启动令牌的声明：

const key = `game:${gameScope}`;            // e.g. "game:3fa85f64-5717-4562-b3fc-2c963f66afa6"

// Load on startup — 404 means no save yet.
const res = await fetch(`/api/v1/me/cloud-saves/${key}`, { headers: { Authorization: `Bearer ${launchToken}` } });
if (res.status !== 404 && !res.ok) throw new Error(`Save load failed: ${res.status}`);
const save = res.status === 404 ? null : new Uint8Array(await res.arrayBuffer());
const etag = res.headers.get("ETag");
if (save && !etag) throw new Error("Save version unavailable; do not overwrite it.");
// Validate/decode your own save format before adopting it or enabling uploads.

// Save at checkpoints, not every frame.
const written = await fetch(`/api/v1/me/cloud-saves/${key}`, {
  method: "PUT",
  headers: {
    Authorization: `Bearer ${launchToken}`, "Content-Type": "application/json",
    ...(etag ? { "If-Match": etag } : { "If-None-Match": "*" }),
  },
  body: JSON.stringify({ dataBase64: base64(zipBytes) }), // Your ZIP encoder and bytes.
});
if (written.status === 412) throw new Error("Another device saved. Reload before writing again.");
if (!written.ok) throw new Error(`Save write failed: ${written.status}`);
const acknowledgement = await written.json(); // Retain acknowledgement.etag for your next write.
  • 只有那个确切的钥匙。 任何其他键 - 另一个游戏的、商店游戏的或不同的拼写 你的（大写，裸id） - 是 403 作为启动令牌。这包括 github:<gameId>, 当玩家同步游戏的本地保存文件夹时桌面应用程序使用的单独插槽，因此 该同步永远不会覆盖您的游戏写入的保存。
  • 任何格式。 平台从不打开存档；存储您的游戏可以读回的任何内容（它是 担任 application/zip 不管）。最大 10 MB。
  • 无条件写入是最后写入获胜，没有历史记录。使用条件写入来检测 一次保存两个选项卡/设备。启动时加载并在前台检查点保存。页面退出 尽最大努力上传，并有浏览器正文大小限制；看 安全保存秘诀.
  • 每个保存都有一个版本。 它是 ETag 正在下载，在 /info （也如 etag）以及 的 PUT 回复。将其发回为 If-Match 仅当没有人保存时才会进行写入 自从；否则 412 {"error":"precondition_failed","etag":"<current>"} 告诉你版本 负载。 If-Match: * 需要现有的保存； If-None-Match: * 仅当没有时才写入。 没有任何一个标题 PUT 是无条件的——最后写入获胜。一个 GET 和 If-None-Match: <etag> 答案 304 当你已经持有最新的保存时。
  • 没有托管列表的游戏（运营商提供的游戏）没有插槽。

小的、经常变化的偏好属于 每个玩家的设置 反而;它们也可以通过启动令牌访问并支持部分更新。
