内容审核

游戏在向其他人展示之前会检查共享文本、JSON 文档和 PNG/JPEG/WebP 图像 玩家。只有一个电流 allow 授权共享。 review, block、未知、待定、失败、 过期和不兼容的策略结果都会隐藏内容。

目前在公共部署中无法进行审核检查。 之前读过发现 启用共享。支票退回 503 overloaded 和 Retry-After: 300;这不承诺 五分钟后可用。保持内容隐藏，直到您收到当前的允许决定。 一代也 不可用.

下面的合同描述了支持的审核调用及其可用时的行为。仅 通过所有者审查 API 返回可访问、经过筛选的证据。

呼叫者和路线

玩家前缀是 /api/v1/games/{slug}/moderation。 JWT 和启动代币承载着玩家； 启动令牌必须与该游戏匹配。实时容器服务器令牌也必须与游戏匹配。本地人 客户端使用 API 基 URL；浏览器游戏可以使用其游戏来源 /api 代理人。

方法 后缀 呼叫者 结果
得到 （根） 玩家或服务器 可用性、有效限制、支持的内容和当前政策
邮政 /check 玩家或服务器 200 完整批次或 202 待检查
得到 /checks/{checkId} 归属玩家或创建游戏服务器 200 地位; 410 结果保留后
邮政 /decisions/lookup 玩家或服务器 200 已知/未知合格哈希值
邮政 /flags 玩家 201 旗帜收据；服务器无法归档标志
得到 /removed?since=&pageSize= 玩家或服务器 分页取款和下一个光标

玩家不能以其他玩家的身份过牌。服务器通常会发送 sessionId 和 participantUserId; 参与者必须处于该游戏的活跃会话中，并且他们的检查费将被收取。对于一个 持续世界重新检查无人在线，发送 attribution: "game" 并省略这两个字段。 这会消耗单独的服务器速率和游戏预算，不记录任何玩家并允许轮询 仅通过游戏的授权服务器身份。令牌刷新不会更改该逻辑标识。

可用性

GET /api/v1/games/{slug}/moderation 返回：

{
  "checksAvailable": false,
  "contentReportingAvailable": false,
  "disabledReason": "moderation_not_configured",
  "policyVersion": "<current effective version>",
  "supportedKinds": ["text", "image"],
  "supportedContexts": ["chat", "name", "generated-content", "user-content"],
  "limits": { "moderation.check.items": 20, "moderation.decision.allow_ttl_seconds": 3600 },
  "acceptedPreviousPolicyVersion": null,
  "previousPolicyValidUntil": null,
  "deliveredContentGraceSeconds": 0
}

limits 包含有效的审核注册表值，超出了所示的两个值。玩家 值包括该玩家的覆盖；服务器发现揭示了游戏津贴，绝无仅有 玩家的。零游戏项目预算也会禁用检查（game_budget_disabled）。使用返回的策略重叠和宽限值；默认值两者都不提供。

检查具体内容

POST /api/v1/games/{slug}/moderation/check
Authorization: Bearer <launch-token>
Content-Type: application/json

{
  "items": [
    { "id": "story", "kind": "text", "context": "user-content", "text": "abc" }
  ]
}

项目 ID 在批次内是唯一的，最多 128 个字符。文字仅承载 text;图片 携带 contentType 和严格的标准填充 dataBase64，没有空格。声明形象 类型必须与其标头匹配，并且字节和像素是有界的。 WAV、奥格·沃比斯、 不支持 glTF 模型和字体（415 unsupported_kind）；音频支持被推迟。

哈希值是 sha256: 后跟 SHA-256 的 64 个小写十六进制数字，覆盖确切的内容字节：

  • 对于文本，对字符串进行 JSON 解码，并将其 Unicode 标量值编码为不带 BOM 的 UTF-8。 保留空格、行结尾和 Unicode 规范化；拒绝未配对的代理。
  • 作为文本提交的 JSON 文档将被哈希为其确切的文档字符串，而不进行解析， 重新排序或重新序列化它。
  • 对于图像，在调整大小、转码或元数据更改之前对解码的字节进行哈希处理。

三个 ASCII 字节 abc 散列到 sha256:ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad。 添加换行符会更改哈希值。请求信封、项目 ID、上下文、媒体类型和 base64 编码不是哈希输入。平台计算提交的哈希值；接收游戏也必须 对它们实际保存的字节进行散列并比较标识符。

一个完整的项目有 status: "complete", contentHash, decision、类别、修订、 checkedAt 和 decisionPolicyVersion。仅允许携带 validUntil。响应信封 具有当前有效的 policyVersion。如果有任何项目存在，验证将拒绝整批产品 畸形的。接受的项目可能会单独失败， status: "failed"，有代码，没有决定。

同步截止时间默认为两秒。未完成品产生 202 和 checkId, pollAfterSeconds, expiresAt 和 Retry-After。轮询支票；待决事项尚无决定。 后台截止时间默认为 60 秒，然后未完成的项目会失败 timeout 和 它的普通输入被删除。默认情况下，终端结果可读一小时。

对已完成的项目进行轮询会参考实时合格决策、当前政策和保留。 旧支票无法更新已撤回的批准。当前的块/评论照此返回； 陈旧、过期或缺席的决定会产生失败的项目，并且不会更新有效性。

查找和撤回恢复

{
  "hashes": ["sha256:ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad"],
  "kind": "text",
  "context": "user-content"
}

将此发送至 /decisions/lookup。图像查找也命名 contentType。批准资格为 游戏、种类、经过验证的媒体类型和背景。条目有 known 做出决定、修改、 decisionPolicyVersion 并允许有效性，或 unknown 和 not_checked, policy_changed 或者 expired。在政策改变和普通决策保留后，人为封锁仍然有效。

允许有效期默认为一小时，并且可以由操作员降低。到期前重新验证； 没有针对中断启用的宽限期，也没有接受的先前基准版本。改变 游戏政策会立即使之前的批准失效。人类允许仅在复检后幸存 对于相同政策下仍通过当前基线的相同调查结果。

轮询 /removed 在分发共享包之前以及在游戏过程中定期进行。隐藏匹配的哈希值 并在提款时停止分配；删除包括维持旗帜和重新分类 从允许到审查/阻止。 Feed 条目包括限定符、范围、决策、修订、政策、 移除时间和安全原因。光标是不透明的排序标记；使用返回的游标而不是从时间派生游标。

过期游标返回 410 cursor_expired。获取一个新的光标而不 since, 批量查找 所有加载的共享哈希，仅在验证后才恢复。缺席提要绝不意味着批准。 保存的本地副本不授权重新分发。 Feed 默认为 90 天的历史记录； 耐用的人类方块比它更长寿。

旗帜和所有者评论

玩家发送 /flags a reason （最多 64 个字符），可选有界 note和内容， 目标玩家，或两者兼而有之。内容证据使用与支票相同的项目形状。如果 contentHash 也提供了，平台重新计算它并要求相等。裸露的哈希值不是证据； 工作/检查参考未实施。玩家目标标志需要 sessionId 谁的名单 包括报告者和目标。提交举报既不会改变决定，也不会自动改变 阻止任何人。

内容证据在分类以供路由之前被保留并隔离存储。延误了， 失败或不可用的筛选永远不会打开所有者访问权限。当前的业主安全筛查许可证 列表/详细信息/下载/分类。工作人员的调查结果隐藏了旗帜并限制了现有的旗帜和评论 的相同证据。如果没有分类器，内容标志将返回 403 content_reporting_disabled 没有重试建议或保留证据；仅限玩家使用的标志仍然可用。

所有者路线需要完整的 JWT 和游戏所有权，如下 /api/v1/me/github-games/{id}/moderation:

方法 后缀 行为
获取/放置 /policy 读取/设置评级和更严格的类别阈值 expectedVersion
得到 /flags / /flags/{flagId} 分页筛选元数据/一个可访问标志
得到 /flags/{flagId}/evidence 受控下载； 410 证据失效后
修补 /flags/{flagId} action: "uphold" 或者 "dismiss"、可选注释和 expectedRevision
得到 /reviews / /reviews/{reviewId} 分页保留审阅元数据/一篇可访问的审阅
得到 /reviews/{reviewId}/content 受控下载； 410 review_expired 当不可用时
修补 /reviews/{reviewId} action: "allow" 或者 "block"、可选注释和 expectedRevision

清单取 status, page 和 pageSize （默认 20，最大 100）。只有业主更严格的政策 可以允许当前通过平台基线的持有；基线保持需要平台 在游戏所有者 API 之外进行审查。受限证据永远不会为所有者可见。 过时的修订版是 409 revision_conflict。决定进行评论会删除其保留的内容；也到期 阻止下载或批准它。解除一个标志不会撤消另一个块，并且没有所有者 路线解除了人力障碍。

证据是一个 application/octet-stream 附件与 nosniff、沙箱 CSP 和 no-store。 在您的审核 UI 中将注释/原因保留为不受信任的文本。不要将它们呈现为标记或将它们用作 附件 URL。

错误是 { error, code, retryAfterSeconds? }. 400 涵盖格式错误的内容/限定符， 401 缺少身份验证， 403 范围/授权或基线限制， 404 缺席/无法访问 记录， 409 哈希/修订/策略冲突， 410 过期的内容/检查/游标， 413 字节/项/ 像素限制，以及 415 不受支持的种类/类型。 429 涵盖费率/预算/队列/存储 Retry-After。分类器中断是 503 moderation_unavailable;当前未配置的 保留占位符 503 overloaded。任何错误、重试或付款都不能替代允许决定。
