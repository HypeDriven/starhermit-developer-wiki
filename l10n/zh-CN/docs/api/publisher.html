出版商

发布者界面：管理发布者组织和成员，创建和上传软件标题和版本，以及管理标题的成就、权利和排行榜定义。

发布游戏而不是目录标题？ 你不需要这些。业主是一家 具有脚本或容器后端的游戏是其发行商并管理其排行榜和 下的成就 /api/v1/me/github-games/{id}/… - 看 教程：游戏的排行榜和成就.

基本网址： https://api.starhermit.com。所有路由都需要 JWT 以及列出的权限声明。角色： PublisherMember, PublisherOwner。权限声明通过角色分配；铸造的代币带有许可声明。

出版商和会员

路由前缀： api/v1/publisher.

方法 小路 授权 描述
邮政 /api/v1/publisher 智威汤逊（Permission-publisher.content.manage) 创建发布者；创建者成为具有角色的成员 "Owner" → 201
得到 /api/v1/publisher 智威汤逊（Permission-publisher.content.manage) 列出出版商 → Publisher[]
邮政 /api/v1/publisher/{publisherId}/members 智威汤逊（Permission-publisher.members.manage) + 角色 Owner 添加会员 → 204
删除 /api/v1/publisher/{publisherId}/members/{memberUserId} 智威汤逊（Permission-publisher.members.manage) + 角色 Owner 删除成员 → 204 （所有者不能被删除）
得到 /api/v1/publisher/{publisherId}/members/{memberUserId} 智威汤逊（Permission-publisher.members.manage) + 该出版商的会员资格 获取会员 → PublisherMember

谁可以更改会员资格

权限声明表示您可以在某处管理发布者成员；它没有说 哪个 出版商。因此，这两项检查均适用：

  • 添加和删​​除成员是 Owner-仅有的。 会员资格具有内容管理权限 出版商的每一个标题，因此可以添加成员的普通成员可以授予该权利 对任何人的权威。非所有者获得 401.
  • 阅读会员资格需要属于该出版商。 外面的呼叫者得到同样的结果 404 作为非成员的用户，因此端点不会透露任何关于您不是的发布者的信息 的一部分。

软件标题和版本

方法 小路 授权 描述
邮政 /api/v1/publisher/software 智威汤逊（Permission-publisher.content.manage) 创建/更新软件标题（正文 = 标题元数据；强制执行标题实际发布者的成员身份）
邮政 /api/v1/publisher/software/upload 智威汤逊（Permission-publisher.content.manage + Permission-publisher.binary.publish) 获取标题的上传 URL → UploadUrlInfo[]
邮政 /api/v1/publisher/software/build/finalize 智威汤逊（Permission-publisher.content.manage + Permission-publisher.binary.publish) 根据上传的资源完成构建 → 204
得到 /api/v1/publisher/analytics/downloads?publisherId= 智威汤逊（Permission-publisher.content.manage) 每个标题的下载次数
得到 /api/v1/publisher/analytics/launches?publisherId= 智威汤逊（Permission-publisher.content.manage) 每个标题的启动次数

发布构建需要二进制发布授权

两个构建端点需要 publisher.binary.publish 在上面 publisher.content.manage 以及图书出版商的会员资格。没有它两个都会回答 403, 当此页面上的所有其他端点继续工作时 - 您可以创建和编辑标题、定义 成就和排行榜，以及授予的权利；您只是无法发送可执行文件。

原因在于构建是什么。构建的资产由桌面客户端下载并在 具有玩家特权的玩家机器，位于 Starhermit 控制的任何沙箱之外 - 与 浏览器游戏，在浏览器中运行。因此，发布权是由每个帐户授予的 星隐管理员（ BinaryPublisher 角色），不是通过创建发布者获得的。否 其他角色承载它。 在构建上传流程之前，请向管理员请求授权 这些端点;当发布者帐户被暂停时，它也会被删除。

浏览器游戏不需要这些： /api/v1/me/github-games 提交、文件夹上传和捆绑 为任何已登录的帐户推送保持自助服务。

创建或更新目录标题

POST /api/v1/publisher/software 接受 id （省略新标题）， publisherId, name, description, category, platform, releaseStatus, tags， 和 priceCents:

{
  "publisherId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "name": "Orbit League",
  "description": "A space racing game.",
  "category": "game",
  "platform": "windows",
  "releaseStatus": "released",
  "tags": ["racing"],
  "priceCents": 0
}

成功是 201 与标题。仅接受标题元数据；不发送发布商会员资格 或此处的资产对象。创建发布者退货 201 没有发布者对象；列表 GET /api/v1/publisher 获取其 ID。

获取上传网址

POST /api/v1/publisher/software/upload

{ "titleId": "<title id>" }

回复 - UploadUrlInfo[]:

[
  {
    "type": "executable",
    "uploadUrl": "...",
    "fieldKey": "..."
  }
]

type 是其中之一 "executable", "data", "metadata".

完成构建

POST /api/v1/publisher/software/build/finalize → 204

{
  "titleId": "<title id>",
  "buildId": "<optional build id>",
  "version": "1.0.0",
  "releaseNotes": "...",
  "assets": [
    { "type": "executable", "checksum": "...", "fieldKey": "..." }
  ]
}

目录构建工作流程当前是预览版，不提供生产二进制交付 或内容验证或恶意软件扫描的保证。不要对待已接受的构建或资产 状态作为可执行文件安全的证据。看 功能可用性。 托管游戏发布使用 游戏上传API.

分析

两个端点都返回一个 JSON 对象，将标题 id 映射到计数：

{ "<titleId>": 42 }

成就

路线 api/v1/publisher;所有成就管理路线都需要 Permission-publisher.content.manage.

这些端点管理 目录标题 仅成就。他们还要求呼叫者是 拥有该书名的出版商的成员，并且他们 属于以下成就的失败关闭 一个权威的游戏 — 这些是由游戏的脚本或容器后端声明的，而不是 出版商管理（参见 成就, 游戏脚本， 和 容器游戏服务器).

方法 小路 授权 描述
邮政 /api/v1/publisher/titles/{titleId}/achievements 智威汤逊 创造成就 → AchievementDto
得到 /api/v1/publisher/titles/{titleId}/achievements 智威汤逊 列出标题的成就 → AchievementDto[]
得到 /api/v1/publisher/achievements/{id} 智威汤逊 获得一项成就 → AchievementDto
放 /api/v1/publisher/achievements/{id} 智威汤逊 更新（所有字段可为空）→ AchievementDto
删除 /api/v1/publisher/achievements/{id} 智威汤逊 删除 → 204

创造成就

POST /api/v1/publisher/titles/{titleId}/achievements

  "icon": "...",
  "secret": false,

icon, visibility， 和 criteria 是可选的。在 PUT，所有字段都可为空。看 achievements.md 面向玩家的表面。

权利

路线 api/v1/publisher/entitlements;两条路线都需要 Permission-publisher.content.manage.

方法 小路 授权 描述
邮政 /api/v1/publisher/entitlements/grant 智威汤逊 授予用户头衔 → 204
邮政 /api/v1/publisher/entitlements/revoke 智威汤逊 撤销用户的头衔 → 204

两者的身体：

{
  "userId": "<user id>",
  "softwareTitleId": "<title id>"
}

排行榜

路线 api/v1/publisher/leaderboards;所有路线都需要 Permission-publisher.content.manage.

方法 小路 授权 描述
邮政 /api/v1/publisher/leaderboards/ 智威汤逊 创建排行榜定义 → LeaderboardDefinitionDto
得到 /api/v1/publisher/leaderboards/{id} 智威汤逊 获取定义 → LeaderboardDefinitionDto
放 /api/v1/publisher/leaderboards/{id} 智威汤逊 更新（所有字段可为空）→ LeaderboardDefinitionDto
删除 /api/v1/publisher/leaderboards/{id} 智威汤逊 删除 → 204

创建排行榜

POST /api/v1/publisher/leaderboards/

{
  "name": "Global Elo",
  "scoreType": "...",
  "sortDirection": "...",
  "resetSchedule": "...",
  "minScore": 0,
  "maxScore": 4000,
  "scope": "...",
  "region": "...",
  "isActive": true,
  "softwareTitleId": "<optional title id>"
}

resetSchedule, minScore, maxScore, region， 和 softwareTitleId 是可选的。在 PUT，所有字段都可为空。 resetSchedule 是 daily, weekly, monthly 或者 never;其他任何东西都是 400 - 看 重置时间表。看 leaderboards.md 面向玩家的表面。

发布构建：流程

  1. 持有二进制发布授权：步骤 3 和 5 需要 publisher.binary.publish，其中一个 Starhermit 管理员为每个帐户授予权限。看 发布构建需要二进制发布授权.
  2. 创建发布者: POST /api/v1/publisher 和 { name, description }.
  3. 创建标题: POST /api/v1/publisher/software 标题元数据如下。
  4. 获取上传网址: POST /api/v1/publisher/software/upload 和 { titleId }.
  5. 上传文件 给返回的 uploadUrls.
  6. 完成构建: POST /api/v1/publisher/software/build/finalize 与上传的资产' { type, checksum, fieldKey } 条目。
  7. 检查分发可用性：当前目录预览不保证经过验证的生产下载或恶意软件扫描；看 可用性.
  8. 用户认领并下载 目录中的标题 — 请参阅 catalog.md.

错误体各不相同；看 API约定.
