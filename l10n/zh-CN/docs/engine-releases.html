StarHermit 引擎发布

StarHermit 引擎——运行的运行时 脚本游戏 — 是 在此 wiki 上发布为版本控制的、不可变的版本 wiki.starhermit.com/engine/。游戏固定一个版本与 engine.version 在 他们的 starhermit.txt;游戏页面加载版本的网络运行时 在浏览器中，StarHermit Windows 客户端安装该版本的本机运行时并播放 上面的游戏，开发人员可以从这里下载版本的运行时来构建。

版本

一个版本是 X.Y.Z. X 是 主机API的主要版本， 这 engine.api 游戏宣告，所以 每个 1.x.x 版本都会运行 engine.api=1 游戏；该版本还记录了主机 API 的次要版本， 随着成员的增加而增长（游戏可能需要一个 engine.minor）。已发布的版本 永远不会改变：修复是下一个版本。

发行说明

1.6.0

主机 API 1.10。固定到早期版本的游戏可以继续在其上运行；重新固定（与 engine.minor=10 为 新成员）使用这些。

  • 更快的用户界面：未更改的标签保持跨框架的布局，小部件矩形无需访问脚本即可 JSON。大约 800 个小部件的 UI 密集框架在浏览器中从大约 4 毫秒下降到 0.7 毫秒，在浏览器中从大约 3 毫秒下降到 原生时间为 0.75 毫秒，具有像素相同的输出。
  • 更精简的脚本堆：本机解释器的表在垃圾爆发后（8 大部分连续为空集合，其使用量增加了一倍）；在一场大战中，堆的山峰从大约 205 MiB 至 185 MiB 以下。
  • 材料：每种材料的制服最多 16 KiB，并且 textureLoad(tex, coords, 0) 用于精确的纹素读取 （在每个运行时夹入纹理）。
  • 渲染目标和混合：两通道和一通道半浮点目标（RGFormat, RedFormat 和 HalfFloatType）RGBA16F内存的一半或四分之一； CustomBlending 具有混合方程和因子 （反向减法、最小值、最大值）和 SubtractiveBlending; renderer.render 进入目标使用材料，因为他们 正在接听电话。
  • 纹理记忆：DataTexture 的像素一旦上传就可以离开脚本堆（image.data = null, 或 在 onUpdate）；它会继续绘制并在设备或上下文丢失的情况下幸存下来。
  • 场景使用: engine.usage() 和 engine.budgets() 计算节点、对象、实例、实例化网格， 精灵、材质、程序和灯光都超出了它们的极限。

1.5.1

主机 API 1.9，仅修复：从 1.5.0 重新固定，没有其他更改。

  • 临摹作品: clipboard.writeText 将文本本地放置在系统剪贴板上（Windows、X11、 Wayland）和浏览器中；它之前通过了检查，但文本从未到达。
  • 本地粘贴：Ctrl+V、Shift+Insert 或粘贴键粘贴到焦点文本字段中。仅运行时 根据玩家的手势读取剪贴板；游戏将粘贴的文本视为正在打字。
  • frustumCulled = false 从未被淘汰：顶点钩放置的网格即使在钩时也能保持其阴影 让它比它的边界更接近光，NaN、无限或空的边界球体不会剔除任何东西 而不是扔。

1.5.0

主机 API 1.9。固定到早期版本的游戏可以继续在其上运行；重新固定（与 engine.minor=9 对于这些） 使用它们。

  • 玩家选择的文件: files.saveAs(name, data, {type}) 和 files.open({accept}) 打开一个值得信赖的 仅在处理玩家的按下时（或在按下按钮后 5 秒内）时显示对话框：运行时自己的文件选择器 本质上，是浏览器在网络上的下载和文件选择器。游戏看到的是名称和字节，而不是路径； 最多 64 MiB，并且拒绝程序、脚本和页面名称。
  • 捕获: renderer.capture({ui}) 返回游戏自身帧的 PNG（如果需要，则返回其 2D 覆盖层）， 绝不是运行时的菜单；照片模式是 files.saveAs("photo.png", await renderer.capture()).
  • 屏幕阅读器: ui.announce(text, { politeness }) 说出绘制板无法表达的内容（UI 自动化、 AT-SPI，浏览器中的实时区域），最多 500 个字符，每秒几个字符。
  • 邀请链接: platform.launchContext() 为会议提供启动（已接受的邀请、 通知），因此游戏可以打开该桌子而不是大厅。
  • 图像预算: engine.limits.image_mib 将游戏的图像预算从 56 MiB 提高到 512 MiB gpu_mib.
  • 材料和照明：每种自定义材质有 5 个纹理，渲染目标没有深度且带有 mipmap， 在自己的 262,144 个实例预算上实例化网格物体、灯光和雾钩、全屏后通行证 场景的颜色和深度、相机后面开始的雾、阴影的柔和度和等级闪光。
  • 更快的脚本：从重用池中分配解释器，更便宜 for…of 和地图/集合；重物体 游戏代码本身速度大约快 10-20%。在浏览器中，使用短字符串的主机调用大约便宜 3 倍。
  • engine.stats().heapBytes 和 heapLimitBytes 在浏览器中不存在而不是 0。

1.4.1

主机 API 1.8，仅修复：从 1.4.0 重新固定，没有其他更改。

  • 浏览器中的文本字段: 专注的 ui.textField （以及运行时自己的字段）需要输入、粘贴和 浏览器中的输入法组合，没有文本到达；本机输入法仅在 某个领域有焦点，其候选者位于插入符处。
  • 浏览器中的音频剪辑：游戏加载的每个剪辑都会到达混音器，无论它在开始时加载多少 （他们一次排队并按顺序上传一些），而不是大多数都默默地丢失；一个无法做到的剪辑 比赛时进行投掷。
  • 没有云保存，没有控制台错误：运行时在下载之前会询问是否存在保存，因此 尚未保存的玩家不会再在控制台中导致 404 错误。
  • 本地平台 (--dev --local-platform): 被拒绝的命令用平台的错误应答其发送者 框架和服务器脚本获取实时上下文（房间、状态、评级和团队、匹配）。

1.4.0

主机 API 1.8。固定到早期版本的游戏可以继续在其上运行；重新固定以使用这些。

  • 携带 JS SDK 构建的播放器: 云保存引擎没写（一个JS SDK构建的）是没有 更长的错误。 saves.foreign() 给出其 { text, bytes }，保存状态为 "foreign"，并且没有什么是 上传直到游戏迁移它并调用 saves.save(data, { replaceForeign: true })，它取代了 仅显示的版本。 settings.legacyKeys(), legacy(key), removeLegacy(key) 和 onLegacy 读取并删除游戏自己的旧设置键（外部 game.).
  • 压缩: compress 和 decompress ("gzip", "deflate", "deflate-raw"） 在 starhermit:engine, 有界并且在本机和浏览器中具有相同的字节； atob 和 btoa 原生也。
  • 平台托管的远程文件: engine.remote.urls=platform 从 StarHermit 提供游戏的远程文件 根据游戏本身的起源，以及 cargo starhermit publish 仅上传游戏缺少的对象。
  • 渲染目标: WebGLRenderTarget 和 renderer.setRenderTarget 和 render （图标、地面标记）、 自定义材质（软粒子）的场景深度，以及材质挂钩中的更多纹理采样。
  • 用户界面：当在两帧之间按下并释放时，不会丢失点击声（在慢速帧上快速点击）； ui.scrollArea 可以通过脚本滚动读取；每个小部件的文本大小、系列和粗细，以及 普通家庭 serif, monospace 和 cursive.
  • 浏览器: loadClip, loadBuffer, createImageBitmap(path) 和 FontFace.load() 不再使 页面等待未获取的文件， files.fetch 获取包文件并保存，最多获取16次 立即运行（其余队列）。
  • 浏览器中的经典脚本：加载经典脚本的游戏（loadClassic) 现在在浏览器中启动；的 页面的全局变量，例如 fetch, WebSocket 和 location 可以由游戏本身分配。
  • 远程读取: files.readBytes(path, offset, length) 读取包或远程文件的一部分。
  • 脚本: Intl.NumberFormat 和 style: "currency" 本身（符号、会计、CLDR 48），以及 formatToParts。服务器脚本声明 tickRateHz: 0 不需要 onTick 在 authority()，如上 平台。

1.3.0

主机 API 1.7。固定到早期版本的游戏可以继续在其上运行；重新固定以使用这些。

  • 更快、更精简的脚本：本机解释器将值保留在一个机器字中并缓存属性 查找，以及 x | 0, x >>> 0 并按常量移位作为单个指令运行。物体较多的游戏使用 大约一半的堆，并且映射生成的运行速度大约快 1.2–1.3 倍。超过其堆限制的游戏将被收集 桌子在结束前就缩小了； STARHERMIT_HEAP_CENSUS=<seconds> 和 --dev 打印什么 堆持有。
  • 远程文件 （主机API 1.7）： engine.remote.files=, engine.remote.urls= 和 engine.remote.redirects= 标记游戏自己的 HTTPS 主机提供的文件。打包命令将它们排除在外 按大小和 SHA-256 分别上传和固定 starhermit-remote.json (--remote-out DIR 写他们的 哈希对象）。运行时获取、检查并缓存它们； files.fetch(paths, onProgress) 让他们 准备好了， files.status(path) 表示文件在哪里，加载器获取它们加载的内容。
  • 上传限制: --max-upload-mib 和 --max-upload-paths （或者 STARHERMIT_MAX_UPLOAD_MIB / _PATHS） 通过游戏提高的限制，并且 --game-id 该工具读取平台报告的限制。
  • GLTF：Draco 压缩网格（KHR_draco_mesh_compression） 和 KHR_mesh_quantization 加载通过 GLTFLoader.
  • 几何和材料 （主机API 1.7）： BufferAttribute.onUpload 从中删除几何体的数组 一旦到达 GPU，就会堆起来；袖珍的 Int8, Uint8 和 Int16 属性;每个实例四个自定义 vec4 （setCustomAt(i, v, slot)）；预乘和乘法混合；剔除 boundingSphere 和 frustumCulled = false。 0-1 之外的顶点颜色不再默默地丢弃网格。
  • 网络：页面的启动清除不再发出空绘制，因此 WebGPU 停止警告零顶点 计数。

1.2.0

主机 API 1.6。固定到 1.1.0 的游戏继续在 1.1.0 上运行；重新固定以使用这些。

  • 大整型 原生地，就像在浏览器中一样： 1n << 64n 以及 ES2022 BigInt 的其余部分（BigInt.asIntN, asUintN, BigInt64Array, BigUint64Array、DataView 的 BigInt 访问器）。一个 BigInt 最多包含 220 原生位。主机 API 和 JSON.stringify 拒绝 BigInts (TypeError).
  • 浏览器中的模块：导入绑定并再次导出它的模块现在会在以下情况下加载： 两个模块相互导入（失败了 "模块中未定义导出“...”"），就像 export { x } from 和 import() 如此循环。
  • starhermit check 当浏览器获取模块并失败时，使用文件和行链接模块，其中 浏览器无法加载游戏；只有浏览器才有的内置警告；打印游戏的 console 输出 （--quiet 隐藏它）；并且失败了一场游戏，这会带来 "没有回应" 屏幕。
  • 时间预算：模块评估需要 60 秒的燃料（原来是 2 秒）， TypedArray set 和 fill 仅花费他们所写的内容，并且时间错误会指定阶段、运行时间和限制。 分阶段预算如下 教程.
  • 多达 128 个可重新绑定操作 （平台保留账号的前32位，运行时保留 其余部分在播放器的同步设置中），以及 engine.group.<action>=Heading 将它们分组在 控制屏幕。
  • 软件包省略了开发文件 (node_modules/, tsconfig.json, package.json, 锁 文件，源映射，...）以及任何 .starhermitignore 列表。 package --web --out DIR 写 没有它们的上传；就地编写的索引将它们列在下面 "excluded".
  • 页面：打包后更改的文件在错误屏幕上命名，并列出了 实际大小和 SHA-256；加载程序命名游戏的图标（没有 /favicon.ico 要求）;浏览器 没有 WebGPU 或 WebGL 2 会得到明确的信息。
  • 定制材料 （主机 API 1.6）：游戏 WGSL 顶点和曲面挂钩在标准、物理、 兰伯特和基本材料和 ShaderMaterial，由引擎检查和沙箱处理；一个 添加剂表面钩上 MeshBasicMaterial 发光。
  • 场景和工具 （主机 API 1.5）： GLTFLoader 在 starhermit:scene, engine.setBusy(label) 对于无法切片的长时间工作，脚本堆在 engine.stats()和采样分析器 （STARHERMIT_SAMPLE 和 --dev).
  • 更快的脚本：类型化数组循环速度快 25–30% Math 内置内联计算。

1.1.0

Web 运行时：通过该 wiki 的引擎文件在浏览器中玩游戏，由 SRI 固定，并在线 播放、语音以及捆绑的 Liberation 和 DejaVu 字体； starhermit package --web 写入一个文件夹 对于浏览器和客户端。

1.0.0

第一个版本：Windows (x86-64) 运行时，没有 Web 运行时。

发动机区

engine/
  versions.json            every release: host API, date, runtimes, revocation
  X.Y.Z/
    native/windows-x86_64/
      native.json          the Windows runtime's files, each with its size, SHA-256 and chunks
      starhermit-X.Y.Z-windows-x86_64.zip
                           the developer download: the same files as one archive
    manifest.json          the web runtime's files, each with its size and sha384
    starhermit.js          the module a game's loader page loads
    starhermit.wasm, *.js  the runtime, its audio mixer and worklets
    starhermit.d.ts        the host API's declarations
    fonts/, licenses/      the runtime's fonts and every licence notice
                           (all of the web runtime only in a release that has one)
  chunks/ab/<sha256>.z     pieces of the native files, shared by every release
  patches/ab/<sha256>.p    binary patches from earlier releases' files

每个文件均按原样发布（没有文件名以 _ 或者 .），GitHub Pages 为其提供服务 与 Access-Control-Allow-Origin: *.

versions.json

{
  "format": 2,
  "versions": [
    {
      "api": {"major": 1, "minor": 4},
      "date": "2026-10-20T13:55:50Z",
      "native": {
        "windows-x86_64": {"manifest": "1.1.0/native/windows-x86_64/native.json", "sha256": "<SHA-256 of native.json>"}
      },
      "revoked": false,
      "version": "1.1.0",
      "web": {"manifest": "sha384-<SRI hash of manifest.json>"}
    }
  ]
}

web 是 {"manifest": "sha384-…"}, 发布网站的 SRI 哈希值 manifest.json， 或者 null 为了 没有 Web 运行时的版本。 native 固定每个平台的 native.json 通过其 SHA-256。一个 释放已撤回，因为不安全说 "revoked": true 与一个 "revokedReason";那就是 仅更改已发布的条目。

native.json

native.json 列出客户端安装的引擎文件夹的文件 - starhermit.exe, release.json （发布版本、主机 API 和 launcher 其运行时所讲的协议）， LICENSE-engine 和第三方通知——每一个都有其 size, sha256 和 chunks。一大块 是文件的一部分，zlib 压缩存储为 chunks/<first two hex digits>/<sha256>.z 并命名为 通过其未压缩字节的 SHA-256；块边界遵循内容，因此不变 拉伸将其块从一个版本保留到下一个版本。在较小的地方，文件还列出了 patches 来自早期版本的同一文件（"from"：早期文件的 SHA-256）。 downloads 列出了开发人员下载及其 size 和 sha256;客户从不安装它。 在具有 Web 运行时的版本中，本机文件夹还包含 web-manifest.json，发布的网络 清单，因此开发人员可以在没有网络的情况下下载网络游戏包。

网络运行时

版本的 Web 运行时是其旁边的文件 manifest.json，其中列出了每个及其 size 和 sha384 并记录发布版本、主机 API 和构建。游戏的加载页面（index.html, 写于 starhermit package --web) 没有自己的脚本：它会加载 starhermit.js 和 manifest.json 从 https://wiki.starhermit.com/engine/X.Y.Z/ 使用 SRI 哈希值和引擎 获取它需要的所有其他文件（starhermit.wasm、音频工作集、字体）并检查它 反对清单。该页面仅运行引擎 - 输入、运行时的菜单、音频、存储、 平台会话和语音 - 游戏的 TypeScript 在它启动和停止的工作线程中运行。

Web 运行时捆绑了自己的字体 Liberation 2.1.5（SIL 开放字体许可证 1.1）和 DejaVu Sans 2.37（Bitstream Vera 和 Arev 许可证）；他们的通知在 licenses/ 与其他人。

正直

一个哈希链涵盖了客户端运行的每个字节：

  1. versions.json （或下面的平台 API）给出版本的 SHA-256 native.json.
  2. native.json 给出每个文件和每个块的 SHA-256。
  3. 客户端仅获取尚未保存的块，检查每个块的存储大小， 膨胀的大小和 SHA-256，将每个文件放在一起，检查文件的 SHA-256，然后才移动 释放到位。补丁会根据其自己的 SHA-256 进行检查，并且修补后的文件会根据 文件的；任何失败都会归咎于块。

开发者下载通过其入口被同一条链覆盖 downloads。一个浏览器 游戏的加载器页面固定网络运行时的 starhermit.js 和 manifest.json 使用 SRI 哈希值，以及 运行时会根据清单检查它加载的所有其他文件。

引擎发布API

该平台提供相同的列表，包含此 wiki 上的每个 URL，因此客户询问 API 是哪个引擎 获取：

GET /api/v1/engine/releases → 每个版本，最新的在前：

{"releases": [{
  "version": "1.1.0", "api": {"major": 1, "minor": 4}, "revoked": false, "date": "2026-10-20T13:55:50Z",
  "web": {"base": "https://wiki.starhermit.com/engine/1.1.0/", "manifestIntegrity": "sha384-<SRI hash>"},
  "native": {"windows-x86_64": {
    "manifestUrl": "https://wiki.starhermit.com/engine/1.1.0/native/windows-x86_64/native.json",
    "manifestSha256": "<SHA-256 of native.json>"}}
}]}

GET /api/v1/engine/releases/{version} → 一次发布，或 404 当它没有列出时。两者都是 匿名且可缓存（Cache-Control: public, max-age=60 与一个 ETag）。已撤销的发布 携带 revokedReason; web 是 null 对于没有 Web 运行时的版本。 虽然平台从未阅读过该列表（维基百科自启动以来就无法访问），但他们回答 503 和 Retry-After.

平台上的脚本游戏

当游戏的根 starhermit.txt 宣称 engine.version，平台将其视为脚本 游戏：

  • 每次发布都会记录文件 pin 的发布，如 hosting.engineVersion，并设置 hosting.deployWarning （也在捆绑推送的答案中）当该版本未列出或已列出时 撤销。警告永远不会停止发布。
  • 托管游戏的每个页面都提供仅允许脚本的内容安全策略 来自这个维基（以及引擎自己的 blob: 工人），所以脚本游戏页面的唯一代码可以 run 是官方引擎：
default-src 'self'; script-src https://wiki.starhermit.com 'wasm-unsafe-eval' blob:; worker-src blob:;
connect-src 'self' https://wiki.starhermit.com; img-src 'self' blob: data:; media-src 'self' blob:;
style-src 'self' 'unsafe-inline'; font-src 'self' https://wiki.starhermit.com;
frame-ancestors https://dashboard.starhermit.com; base-uri 'self'; form-action 'none'

没有浏览器构建的脚本游戏页面（例如仅限 Windows 的游戏上传的纯页面 对于浏览器）不需要脚本并且不受影响。

撤销

已撤销的版本会保留在列表中，以便客户可以说出拒绝的原因：StarHermit 客户会这样做 不安装或启动它并告诉玩家，打包命令拒绝为其打包游戏 当他们阅读时 versions.json，并且该平台会警告那些将其固定的游戏的所有者 发布。重新固定到替换它的版本并再次发布 （见 转向更新的引擎).
