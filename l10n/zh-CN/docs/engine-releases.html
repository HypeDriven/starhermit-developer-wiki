StarHermit 引擎发布

StarHermit 引擎——运行的运行时 脚本游戏 — 是 在此 wiki 上发布为版本控制的、不可变的版本 wiki.starhermit.com/engine/。游戏固定一个版本与 engine.version 在 他们的 starhermit.txt;游戏页面加载版本的网络运行时 StarHermit Windows 客户端从浏览器中的引擎源安装该版本的本机 运行时并在其上玩游戏，开发人员从此处下载版本的运行时以进行构建。

从engine.starhermit.com加载引擎

游戏的页面应该从以下位置加载其引擎 https://engine.starhermit.com/engine/X.Y.Z/，不是来自 这个维基。 该 wiki 仅包含最新版本：其上限为 1 GB，因此最旧的版本是 随着新的发布而被删除，并且从 wiki 加载其引擎的页面停止工作 当它的版本消失时。 engine.starhermit.com 提供 wiki 列出的每个版本（大约十个） 发布分钟，并保留每个版本以节省空间。那里的文件是逐字节的 wiki 发布的内容，因此相同的 SRI 哈希值会固定它们。

  • 发布列表保留在这里。 versions.json 只读自 https://wiki.starhermit.com/engine/versions.json。它决定存在哪些版本以及哪些版本 被撤销，并且 engine.starhermit.com 故意不服务它。
  • 您自己编写的加载页面 进口 https://engine.starhermit.com/engine/X.Y.Z/starhermit.js 和名字 https://engine.starhermit.com/engine/X.Y.Z/manifest.json 在 #starhermit-config，与 一样 integrity 值作为 wiki URL。
  • 打包游戏： 从开发者工具 1.26.0 开始， starhermit package --web 将此加载程序写入 https://engine.starhermit.com/engine/X.Y.Z/ 默认情况下。它仍然读着 versions.json 和 来自 wiki 的清单。如果存档尚未提供版本的清单（发布后不久） 发布），它会写入 wiki URL 并警告您再次打包。 --loader-base URL （或者 STARHERMIT_WEB_LOADER_BASE) 覆盖默认值，例如保留 wiki URL。包裹来自 旧工具带有 wiki URL，平台将托管游戏的两个引擎 URL 重写为 engine.starhermit.com 当 wiki 删除其版本时。在其他地方托管的游戏没有 重写，因此使用1.26.0或更高版本的工具重新打包它们。
  • 不保留已撤销的版本。 由于不安全而撤回的发布不会从这两个来源提供。 固定一个较新的。

开发者工具

这 独立开发者工具 提供自动化的 macOS（Apple Silicon 和 Intel）上的发布和脚本游戏开发 MCP， Linux 和 Windows。不需要 Rust 安装或私有存储库访问。 工具发布与游戏引脚的游戏运行时无关。

版本

一个版本是 X.Y.Z. X 是 主机API的主要版本， 这 engine.api 游戏宣告，所以 每个 1.x.x 版本都会运行 engine.api=1 游戏；该版本还记录了主机 API 的次要版本， 随着成员的增加而增长（游戏可能需要一个 engine.minor）。已发布的版本 永远不会改变：修复是下一个版本。

发行说明

1.27.0

主机 API 1.29：引脚 engine.version=1.27.0 并添加 engine.minor=29 对于标记的更改（1.29）；游戏宣告 1.28 或以上保持其外观。

  • 后处理为 Three.js r185 (1.29)：移植游戏的 High 级别比 3.js 暗 10 到 15 个级别 构建。后链现在遵循 r185：
    • 盛开 是r185的 UnrealBloomPass，这会使用更宽的内核增加 3 倍的模糊级别强度；的 较旧的通道（r176 及之前）增加了 3 × 强度²，因此相同的强度现在可以提供更多的光线（大约是 2.9 倍） 0.35）。 为 Three.js r176 或更早版本编写的游戏应将其绽放强度平方为 1.29 （使用关于 力量²作为力量）保持绽放。
    • 背景贯穿链条：彩色背景现在通过效果、等级、其 每当任何效果但多重采样打开时，晕影和色调映射，如 r185 的 RenderPass 清除 作曲家的目标。从 1.20 到 1.28 它跳过了它们。
    • 年级 levels 和 overRange：线性 renderer.grade 需要 levels: [scale, offset] 和 overRange: "keep"，对于所携带的等级通行证端口（例如 s = s * 0.98 + 0.015，光线超过 1 时保持 用于色调映射）。
  • Phong、Toon 和 Matcap 材料 (1.29): starhermit:scene 导出 Three.js r185 MeshPhongMaterial, MeshToonMaterial 和 MeshMatcapMaterial，按照 r185 在每个后端绘制它们的方式绘制：Blinn-Phong 亮点 (specular, shininess, specularMap），一个冯 envMap 组合为 combine 和 reflectivity (MultiplyOperation, MixOperation 和 AddOperation 出口），香椿光通过 gradientMap 或r185的 两种色调，以及通过视空间法线查找的 matcap；具有法线贴图和凹凸贴图、平面着色、自发光和 AO 地图、线框和阴影。 lightMap, alphaMap, displacementMap, envMapRotation 并保留折射 但没有画出来。
  • 下载：Windows SHA-256 7d184cf20d49a114608135c8e5b9f0acceb6658f630ac4d38c0e39ad17839d75、Linux f23f7558358bdc32f447cd66b3c0f27e26e9abb71117cfb4ff105fa411609380, macOS x86_64 7bd25ce3029f5869c621a1ac2a58df939290fb560831aaee4f59fa89b179b9cb, macOS aarch64 d3c7205a3ba2e5dc1205e5c75ad66db0481d794ac25f181850d71ad14d01e08f。 macOS 运行时是临时签名的，而不是 经过公证，如 1.26.2 所示。

1.26.2

主机 API 1.28，如 1.26.0：重新固定到 1.26.2 (engine.version=1.26.2）；游戏没有任何变化。

  • macOS 运行时：第一个带有 macOS 原生运行时的版本，基于 Intel (macos-x86_64）和苹果芯片 (macos-aarch64)，对于 StarHermit macOS 客户端；他们需要 macOS 11 或更高版本。开发者下载： starhermit-1.26.2-macos-x86_64.tar.gz （SHA-256 460a39263a749407400cff4b1ecc093034f68fc138b2a8b881ad7bf0b8314c27） 和 starhermit-1.26.2-macos-aarch64.tar.gz （SHA-256 6888857b3ef1608968484ad68f0b256da22273b9cc1b0f7a77233af9bd5cfb0c).
  • 它们是临时签署的 未公证。当客户端安装它们时没问题，但是下载了 tarball 浏览器中带有 Gatekeeper 隔离区并被阻止，直至清除 (xattr -dr com.apple.quarantine starhermit-1.26.2-macos-*).
  • 他们有 尚未在真正的 Apple 硬件或 GPU 上进行测试：构建主机是Intel虚拟机 没有 Metal，因此 x86_64 运行时是无头运行的，而 arm64 运行时仅进行静态检查。

1.26.1

主机 API 1.28，如 1.26.0：重新固定到 1.26.1（engine.version=1.26.1）；游戏没有任何变化。

  • WebAssembly 提前编译：本质上，游戏实例化的 WebAssembly 模块可以运行代码 平台为其编译和签名，在后台获取并缓存；直到它到达，并且对于任何没有到达的事情 经过验证，该模块的解释与以前一样，具有相同的结果、陷阱和燃料。 versions.json 获得一个 aot 撤销清单。 STARHERMIT_WASM_AOT=0 将其关闭；浏览器和检查从不使用它。
  • 使固定：WebAssembly 陷阱不再保留调用深度，这可能会在游戏早期达到调用限制 捕获许多陷阱。

1.26.0

主机 API 1.28：引脚 engine.version=1.26.0 并添加 engine.minor=28 对于标记的更改（1.28）；其他一切 适用于每场比赛。声明 1.27 或更早版本的游戏的行为与以前一样。

  • 彩色地图' colorSpace (1.28): map, emissiveMap, 纹理 scene.background 和纹理 环境遵循纹理 colorSpace 正如 Three.js r185 所做的那样： SRGBColorSpace 被解码，同时 LinearSRGBColorSpace 和 NoColorSpace （默认）按存储方式使用。年龄较大的未成年人保留每个颜色图 sRGB。
  • CSS 样式 (1.28): ui.stylesFromCss 和 starhermit css 转换自定义属性和 var(), 百分比 尺寸， max-width/max-height, font-variant: small-caps 和 flex-wrap.
  • 原生显示：本机游戏以无边框全屏启动，除非玩家另有选择。
  • 网络：登录在 StarHermit 客户端框架内进行；加载器页面不再随滚动条闪烁 当其视口发生变化时；存储的全屏模式等待玩家第一次按下。
  • 工具: package --web 加载程序从引擎存档中获取引擎，该引擎存档保留了每个版本。
  • 使固定：合成的小写大写字母保留其单词空间。

1.25.0

主机 API 1.27：引脚 engine.version=1.25.0 并添加 engine.minor=27 对于标记的更改（1.27）；其他一切 适用于每场比赛。声明 1.26 或更早版本的游戏的行为与以前一样。

  • 工人寿命 (1.27): a starhermit:script 游戏不再引用的工人虽然有 侦听器或消息仍要运行，就像浏览器的 Web Worker 所做的那样，直到 terminate()，它停止，或者游戏 结束。年长的未成年人不断终止收集的工作人员，并在有听众时记录一次性警告。
  • 图形质量：网络的 Auto 现在会在同一 GPU 上选择本机的级别（更稳定的基准， 并且缓慢呈现的帧在浏览器中被视为错过了最后期限）。
  • 速度：每通道剔除达到了 WebGL 2 和 WebGPU，因此从其剔除的通道中遗漏了一批。

1.24.0

主机 API 1.26：引脚 engine.version=1.24.0 并添加 engine.minor=26 对于标记的更改（1.26）；其他一切 适用于每场比赛。声明 1.25 或更早版本的游戏的行为与以前一样。

  • 工人包文件 (1.26): starhermit:script 工作人员通过a读取游戏的包文件 files 全球与 starhermit:engine的读取，本机和浏览器中。
  • 细节层次和阴影级联 (1.26)：三.js r185 LOD;发动机扩展 InstancedMesh.setLevels(...) （每个实例级别，本机）和 directionalLight.shadow.cascades （1-4 地图像 CSM 一样在视图上分割）。
  • 输出色彩空间 (1.26): renderer.outputColorSpace 和 ColorManagement 因为 Three.js r185 有它们； LinearSRGBColorSpace 在每个后端写入线性光。
  • 用户界面布局 (1.26)：将行包裹起来 gap，百分比大小， maxWidth/maxHeight，自定义属性 var()、小型大写字母文本和 ui.lastRect().
  • 材料挂钩 (1.26): pass_kind() 和 is_shadow_pass() 告诉钩子它运行在哪个通道中。
  • 速度：阴影贴图和预通道仅绘制到达它们的内容；蒙皮网格物体的第一个剔除球体已制作完成 原生地；脚本中更快的数组文字、解构和映射/设置查找； WebGL 2 帧不再等待 getError，并且原生 Wayland 在帧回调之前绘制。
  • 修复: o[4294967295] 读取为普通钥匙； Map和Set方法拒绝对方的接收者； package --web 总是包裹 starhermit-remote.json.
  • 发展: --local-container URL 在开发者自己的服务器上运行容器游戏的会话 本地平台主机。

1.23.0

主机 API 1.25：引脚 engine.version=1.23.0 并添加 engine.minor=25 对于标记的更改（1.25）；其他一切 适用于每场比赛。声明 1.24 或更早版本的游戏的行为与以前一样。

  • 骨骼动画 (1.25): Bone, Skeleton 和 SkinnedMesh 正如 Three.js r185 所拥有的那样，它们渗透到每一个 每个后端的材质顶点阶段（包括钩子、阴影和预通道）； GLTFLoader 加载皮肤并 动画剪辑。
  • 网络组装 （1.25）： WebAssembly 本地和全球 starhermit:script 工人，在发动机自己的 沙盒解释器（WebAssembly 2.0 核心和固定宽度 SIMD，无 JIT）；内存受限于 engine.limits.wasm_mib （默认 256 MiB）。整数结果与浏览器逐位匹配。
  • 浮动数据纹理 (1.25): FloatType 和 HalfFloatType DataTextures 到达 ShaderMaterial 并挂钩 WGSL 松开，以半浮子形式存放。

    fonts/, licenses/      the runtime's fonts and every licence notice
                           (all of the web runtime only in a release that has one)
  chunks/ab/<sha256>.z     pieces of the native files, shared by every release
  patches/ab/<sha256>.p    binary patches from earlier releases' files

每个文件均按原样发布（没有文件名以 _ 或者 .），GitHub Pages 为其提供服务 与 Access-Control-Allow-Origin: *.

web 是 {"manifest": "sha384-…"}, 发布网站的 SRI 哈希值 manifest.json， 或者 null 为了 没有 Web 运行时的版本。 native 固定每个平台的 native.json 通过其 SHA-256。一个 释放已撤回，因为不安全说 "revoked": true 与一个 "revokedReason";那就是 只更改已发布的条目，删除除外：将 wiki 保持在 GitHub Pages 的 1 GB 范围内 最旧的版本离开引擎区域，并且它们的条目仍被列为已撤销 "removed": true （2026年10月26日以这种方式删除1.0.0到1.6.0，2026年10月27日从1.7.0到1.15.1，2026年10月28日从1.15.2到1.17.0，1.17.1，1.18.0，1.19.0，1.19.1， 1.19.2、1.19.3、1.20.0、1.20.1 和 1.22.0（2026 年 10 月 29 日）。

aot （从1.26.1开始）是平台提前编译的WebAssembly代码的撤销列表：native 运行时拒绝来自列出的编译器版本或签名密钥的编译代码，并且没有列表读取它们 解释一切。 updated 仅是信息。

native.json

native.json 列出客户端安装的引擎文件夹的文件 - starhermit.exe, release.json （发布版本、主机 API 和 launcher 其运行时所讲的协议）， LICENSE-engine 和第三方通知——每一个都有其 size, sha256 和 chunks。一大块 是文件的一部分，zlib 压缩存储为 chunks/<first two hex digits>/<sha256>.z 并命名为 通过其未压缩字节的 SHA-256；块边界遵循内容，因此不变 拉伸将其块从一个版本保留到下一个版本。在较小的地方，文件还列出了 patches 来自早期版本的同一文件（"from"：早期文件的 SHA-256）。 downloads 列出了开发人员下载及其 size 和 sha256;客户从不安装它。 在具有 Web 运行时的版本中，本机文件夹还包含 web-manifest.json，发布的网络 清单，因此开发人员可以在没有网络的情况下下载网络游戏包。

网络运行时

版本的 Web 运行时是其旁边的文件 manifest.json，其中列出了每个及其 size 和 sha384 并记录发布版本、主机 API 和构建。游戏的加载页面（index.html, 写于 starhermit package --web) 没有自己的脚本：它会加载 starhermit.js 和 manifest.json 从 https://engine.starhermit.com/engine/X.Y.Z/ （或者，从旧工具中， https://wiki.starhermit.com/engine/X.Y.Z/）与 SRI 哈希值和引擎 获取它需要的所有其他文件（starhermit.wasm、音频工作集、字体）并检查它 反对清单。该页面仅运行引擎 - 输入、运行时的菜单、音频、存储、 平台会话和语音 - 游戏的 TypeScript 在它启动和停止的工作线程中运行。

Web 运行时捆绑了自己的字体 Liberation 2.1.5（SIL 开放字体许可证 1.1）和 DejaVu Sans 2.37（Bitstream Vera 和 Arev 许可证）；他们的通知在 licenses/ 与其他人。

正直

一个哈希链涵盖了客户端运行的每个字节：

  1. versions.json （或下面的平台 API）给出版本的 SHA-256 native.json.
  2. native.json 给出每个文件和每个块的 SHA-256。
  3. 客户端仅获取尚未保存的块，检查每个块的存储大小， 膨胀的大小和 SHA-256，将每个文件放在一起，检查文件的 SHA-256，然后才移动 释放到位。补丁会根据其自己的 SHA-256 进行检查，并且修补后的文件会根据 文件的；任何失败都会归咎于块。

开发者下载通过其入口被同一条链覆盖 downloads。一个浏览器 游戏的加载器页面固定网络运行时的 starhermit.js 和 manifest.json 使用 SRI 哈希值，以及 运行时会根据清单检查它加载的所有其他文件。

引擎发布API

该平台提供相同的列表，包含此 wiki 上的每个 URL，因此客户询问 API 是哪个引擎 获取：

GET /api/v1/engine/releases → 每个版本，最新的在前：

{"releases": [{
  "version": "1.1.0", "api": {"major": 1, "minor": 4}, "revoked": false, "date": "2026-10-20T13:55:50Z",
  "web": {"base": "https://wiki.starhermit.com/engine/1.1.0/", "manifestIntegrity": "sha384-<SRI hash>"},
  "native": {"windows-x86_64": {
    "manifestUrl": "https://wiki.starhermit.com/engine/1.1.0/native/windows-x86_64/native.json",
    "manifestSha256": "<SHA-256 of native.json>"}}
}]}

GET /api/v1/engine/releases/{version} → 一次发布，或 404 当它没有列出时。两者都是 匿名且可缓存（Cache-Control: public, max-age=60 与一个 ETag）。已撤销的发布 携带 revokedReason; web 是 null 对于没有 Web 运行时的版本。 虽然平台从未阅读过该列表（维基百科自启动以来就无法访问），但他们回答 503 和 Retry-After.

平台上的脚本游戏

当游戏的根 starhermit.txt 宣称 engine.version，平台将其视为脚本 游戏：

  • 每次发布都会记录文件 pin 的发布，如 hosting.engineVersion，并设置 hosting.deployWarning （也在捆绑推送的答案中）当该版本未列出或已列出时 撤销。警告永远不会停止发布。
  • 托管游戏的每个页面都提供仅允许脚本的内容安全策略 来自两个引擎的起源（以及引擎自己的 blob: 工人），所以只编码一个脚本 游戏页面可以运行的是官方引擎：
default-src 'self'; script-src https://wiki.starhermit.com https://engine.starhermit.com 'wasm-unsafe-eval' blob:; worker-src blob:;
connect-src 'self' https://wiki.starhermit.com https://engine.starhermit.com; img-src 'self' blob: data:; media-src 'self' blob:;
style-src 'self' 'unsafe-inline'; font-src 'self' https://wiki.starhermit.com https://engine.starhermit.com;
frame-ancestors https://dashboard.starhermit.com; base-uri 'self'; form-action 'none'

没有浏览器构建的脚本游戏页面（例如仅限 Windows 的游戏上传的纯页面 对于浏览器）不需要脚本并且不受影响。

撤销

已撤销的版本会保留在列表中，以便客户可以说出拒绝的原因：StarHermit 客户会这样做 不安装或启动它并告诉玩家，打包命令拒绝为其打包游戏 当他们阅读时 versions.json，并且该平台会警告那些将其固定的游戏的所有者 发布。重新固定到替换它的版本并再次发布 （见 转向更新的引擎).
