StarHermit 引擎发布

StarHermit 引擎——运行的运行时 脚本游戏 — 是 在此 wiki 上发布为版本控制的、不可变的版本 wiki.starhermit.com/engine/。游戏固定一个版本与 engine.version 在 他们的 starhermit.txt; StarHermit Windows 客户端安装版本 a 游戏固定并在上面玩游戏，开发人员从这里下载版本的运行时来构建 与.

版本

一个版本是 X.Y.Z. X 是 主机API的主要版本， 这 engine.api 游戏宣告，所以 每个 1.x.x 版本都会运行 engine.api=1 游戏；该版本还记录了主机 API 的次要版本， 随着成员的增加而增长（游戏可能需要一个 engine.minor）。已发布的版本 永远不会改变：修复是下一个版本。

发布 主机API 运行时 开发者下载
1.0.0 1.4 Windows (x86-64)；没有网络运行时 starhermit-1.0.0-windows-x86_64.zip

versions.json 是权威列表，最新优先，引擎 区域自己的页面列出了相同的内容。

发动机区

engine/
  versions.json            every release: host API, date, runtimes, revocation
  X.Y.Z/
    native/windows-x86_64/
      native.json          the Windows runtime's files, each with its size, SHA-256 and chunks
      starhermit-X.Y.Z-windows-x86_64.zip
                           the developer download: the same files as one archive
    manifest.json, starhermit.js, starhermit.wasm, ...
                           the web runtime, in a release that has one
  chunks/ab/<sha256>.z     pieces of the native files, shared by every release
  patches/ab/<sha256>.p    binary patches from earlier releases' files

每个文件均按原样发布（没有文件名以 _ 或者 .），GitHub Pages 为其提供服务 与 Access-Control-Allow-Origin: *.

versions.json

{
  "format": 2,
  "versions": [
    {
      "api": {"major": 1, "minor": 4},
      "date": "2026-10-20T12:49:23Z",
      "native": {
        "windows-x86_64": {"manifest": "1.0.0/native/windows-x86_64/native.json", "sha256": "<SHA-256 of native.json>"}
      },
      "revoked": false,
      "version": "1.0.0",
      "web": null
    }
  ]
}

web 是 {"manifest": "sha384-…"}, 发布网站的 SRI 哈希值 manifest.json， 或者 null 为了 没有 Web 运行时的版本。 native 固定每个平台的 native.json 通过其 SHA-256。一个 释放已撤回，因为不安全说 "revoked": true 与一个 "revokedReason";那就是 仅更改已发布的条目。

native.json

native.json 列出客户端安装的引擎文件夹的文件 - starhermit.exe, release.json （发布版本、主机 API 和 launcher 其运行时所讲的协议）， LICENSE-engine 和第三方通知——每一个都有其 size, sha256 和 chunks。一大块 是文件的一部分，zlib 压缩存储为 chunks/<first two hex digits>/<sha256>.z 并命名为 通过其未压缩字节的 SHA-256；块边界遵循内容，因此不变 拉伸将其块从一个版本保留到下一个版本。在较小的地方，文件还列出了 patches 来自早期版本的同一文件（"from"：早期文件的 SHA-256）。 downloads 列出了开发人员下载及其 size 和 sha256;客户从不安装它。

正直

一个哈希链涵盖了客户端运行的每个字节：

  1. versions.json （或下面的平台 API）给出版本的 SHA-256 native.json.
  2. native.json 给出每个文件和每个块的 SHA-256。
  3. 客户端仅获取尚未保存的块，检查每个块的存储大小， 膨胀的大小和 SHA-256，将每个文件放在一起，检查文件的 SHA-256，然后才移动 释放到位。补丁会根据其自己的 SHA-256 进行检查，并且修补后的文件会根据 文件的；任何失败都会归咎于块。

开发者下载通过其入口被同一条链覆盖 downloads。一个浏览器 游戏的加载器页面固定网络运行时的 starhermit.js 和 manifest.json 使用 SRI 哈希值，以及 运行时会根据清单检查它加载的所有其他文件。

引擎发布API

该平台提供相同的列表，包含此 wiki 上的每个 URL，因此客户询问 API 是哪个引擎 获取：

GET /api/v1/engine/releases → 每个版本，最新的在前：

{"releases": [{
  "version": "1.0.0", "api": {"major": 1, "minor": 4}, "revoked": false, "date": "2026-10-20T12:49:23Z",
  "web": null,
  "native": {"windows-x86_64": {
    "manifestUrl": "https://wiki.starhermit.com/engine/1.0.0/native/windows-x86_64/native.json",
    "manifestSha256": "<SHA-256 of native.json>"}}
}]}

GET /api/v1/engine/releases/{version} → 一次发布，或 404 当它没有列出时。两者都是 匿名且可缓存（Cache-Control: public, max-age=60 与一个 ETag）。已撤销的发布 携带 revokedReason; web 是 {"base", "manifestIntegrity"} 具有 Web 运行时的版本。 虽然平台从未阅读过该列表（维基百科自启动以来就无法访问），但他们回答 503 和 Retry-After.

平台上的脚本游戏

当游戏的根 starhermit.txt 宣称 engine.version，平台将其视为脚本 游戏：

  • 每次发布都会记录文件 pin 的发布，如 hosting.engineVersion，并设置 hosting.deployWarning （也在捆绑推送的答案中）当该版本未列出或已列出时 撤销。警告永远不会停止发布。
  • 托管游戏的每个页面都提供仅允许脚本的内容安全策略 来自这个维基（以及引擎自己的 blob: 工人），所以脚本游戏页面的唯一代码可以 run 是官方引擎：
default-src 'self'; script-src https://wiki.starhermit.com 'wasm-unsafe-eval' blob:; worker-src blob:;
connect-src 'self' https://wiki.starhermit.com; img-src 'self' blob: data:; media-src 'self' blob:;
style-src 'self' 'unsafe-inline'; font-src 'self' https://wiki.starhermit.com;
frame-ancestors https://dashboard.starhermit.com; base-uri 'self'; form-action 'none'

没有浏览器构建的脚本游戏页面（例如仅限 Windows 的游戏上传的纯页面 对于浏览器）不需要脚本并且不受影响。

撤销

已撤销的版本会保留在列表中，以便客户可以说出拒绝的原因：StarHermit 客户会这样做 不安装或启动它并告诉玩家，打包命令拒绝为其打包游戏 当他们阅读时 versions.json，并且该平台会警告那些将其固定的游戏的所有者 发布。重新固定到替换它的版本并再次发布 （见 转向更新的引擎).
