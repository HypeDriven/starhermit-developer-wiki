教程：本地化您的游戏并添加语言设置

给你的游戏一个 语言 设置菜单中的部分，旁边 图形, 声音的， 和 控制。 使其可以从主菜单和游戏过程中使用。使用相同的语言集和基于图像 将选择器标记为 StarHermit 网站和开发人员 wiki。这些是游戏端的推荐； StarHermit 会存储您的偏好，但不会翻译游戏或提供内置语言菜单。

支持的语言和标签

从以下十种语言开始。这与 wiki 的总发言者选择相匹配；这是一个 起始设置，不需要删除游戏支持的其他翻译。仅列出语言 您实际发送的菜单、游戏文本和字体。

显示每种语言的本地名称。旗帜是补充视觉提示：国家和语言 不可互换，并且许多国家都使用多种语言。保留文字标签 可见。使用小本地 SVG 或 PNG 图像，而不是标记表情符号：某些设备将表情符号标记显示为 国家代码。将这些资产复制到您的构建中，而不是在运行时依赖 wiki。

声明每个翻译的实际区域覆盖范围。例如， zh-CN 这里是简体中文 葡萄牙国旗是巴西的标志。一个 pt-BR- 特定包装应相应标识； 分开运送 pt-PT 或繁体中文包（当您支持这些变体时）。

将选择放在设置菜单中

使用 设置 → 语言 → 游戏语言。包括 自动（系统语言） 并显示其 已解决的语言，例如 自动 — 英语。保持当前选择可见 选择器已关闭。该图显示了明确的英语选择。

该部分应提供以下行为：

  • 立即将更改应用于菜单、HUD、教程、工具提示、辅助功能标签和未来 通知。刷新可见文本而不重新开始比赛、放弃进度，或者 重新连接套接字。选择后继续关注语言控制。
  • 使用键盘可访问的下拉菜单或显示菜单，具有可见的焦点、触摸目标和 可滚动列表。还支持游戏的控制器导航。关闭 Escape 和外部 点击次数；即使界面的其余部分发生变化，也能保持母语名称的可读性。
  • 保持 自动的 与明确的选择不同。店铺 auto，不是检测到的语言，所以 另一个设备可以使用自己的系统语言。明确的选择必须战胜检测。
  • 显示有效语言和持久化状态： 已保存至帐户, 已保存在此设备上， 或者 帐户同步不可用。也翻译这些消息；保存时不要报告上传失败。

金属丝 data-language 到您的翻译渲染器和首选项存储。更新摘要图像， 名称、选定状态指示和状态文本一起；关闭披露并返回焦点 它的总结。为按钮提供选定状态指示器和有意义的可访问名称。保留旗帜 图像处于较小的固定尺寸：图表 SVG 的宽泛样式不得放大它们。

翻译包和后备

例如，将面向玩家的文本保留在具有稳定密钥的版本化包中 locales/en.json, locales/ar.json， 和 locales/zh-CN.json。使英语成为完整的源包。 将消息翻译为整个单元，保留命名占位符；避免加入翻译句子 片段或将用户数据插入到翻译源字符串中。

{
  "settings.language": "Language",
  "settings.gameLanguage": "Game language",
  "settings.automatic": "Automatic (system language)",
  "settings.saved": "Saved to account",
  "hud.coins": "{count} coins"
}

最后一个条目说明了稳定的键和占位符；使用复数感知消息格式化程序 实际消息数。语言有不同的复数规则。设置数字、日期、时间和的格式 具有所选语言环境的货币，而不是硬编码的分隔符或字序。保持时间 单位、货币金额和游戏规则不变。

按以下顺序解析语言：

  1. 来自玩家游戏设置的有效显式选择，或他们当前未同步的选择。
  2. 为了 auto，设备语言首选项中第一个支持的匹配。
  3. 不存在支持的匹配时为英语；对于个别丢失的键，也可以回退到英语。

不区分大小写地匹配区域设置标记，在配置之前更喜欢精确支持的区域/脚本 基础语言后备。地图通用 zh 或者 zh-Hans 仅当您需要时才使用简化包 公布的政策；不提供仅简化包作为支持 zh-Hant。不支持或 格式错误的存储选择应该安全地回退。缺少英文源密钥应该会导致验证失败 在发布之前而不是留下空白按钮。

在开发过程中生成翻译并随游戏一起发布包。机器翻译可以 产生初稿；之前先查看术语、说明和面向玩家的重要消息 调用完全支持的语言。将未经审阅的翻译标记为机器生成并提供 英语后备。保留占位符、游戏标题、API 路由、ID、错误代码、保存密钥和协议 价值观完好无损。翻译错误代码显示的解释，而不是您的逻辑使用的代码。

从右到左的文本、字体和游戏玩法

对于阿拉伯语和乌尔都语，请在 UI 根目录上设置界面语言和方向。在浏览器中，例如：

document.documentElement.lang = effectiveLocale;
document.documentElement.dir = ['ar', 'ur'].includes(effectiveLocale) ? 'rtl' : 'ltr';

使用逻辑 CSS 属性，例如 margin-inline-start, padding-inline-end， 和 text-align: start。 镜像适当的界面导航和对齐，同时保留游戏玩法的意义 坐标、方向控制、世界地图和移动指示器。保留技术代币和 代码从左到右显示；隔离玩家名称和混合方向值 <bdi> 或你的 发动机的等价物。不要自动翻译玩家创作的聊天、名称或游戏命令。

提供具有所需中文、梵文、孟加拉文、阿拉伯文和乌尔都语字形和形状支持的字体。 在实际渲染器中检查连接的阿拉伯字母、组合标记、行高和换行。 对于画布或引擎 HUD，使用其支持的整形和双向文本路径；超文本标记语言 dir 独自一人 无法修复将文本视为不相关字形的渲染器。允许更长的标签和字幕换行。 当语言更改时，通过渲染挂钩刷新文本，避免每帧进行完整的 UI 扫描。

通过 StarHermit 保存选择

使用游戏的 每个玩家的设置，不是云保存进度 或帐户范围的个人资料字段。玩家启动令牌可以读取和写入自己游戏的设置； 这不需要游戏服务器或清单语言声明。

建议的游戏拥有密钥是 ui.language，其值例如 { "choice": "fr" } 或者 { "choice": "auto" }。这些名称是您的约定，而不是保留的平台字段。阅读并 写入前验证设置。使用单独的密钥更新，以便图形、音频和控件 偏好被保留。

随着 浏览器SDK， 后 StarHermit.init() 以及正常的登录/条款流程：

const supported = new Set(['en', 'zh-CN', 'hi', 'es', 'ar', 'fr', 'bn', 'pt', 'id', 'ur']);
const validChoice = choice => choice === 'auto' || supported.has(choice);
const settingsPath = `/api/v1/games/${encodeURIComponent(StarHermit.slug)}/settings`;

// Run only when StarHermit.signedIn; unsigned play uses no authenticated requests.
const response = await StarHermit.api(settingsPath);
if (!response || !response.settings || Array.isArray(response.settings) ||
    typeof response.settings !== 'object') {
  throw new Error('Settings could not be loaded'); // Keep account writes blocked.
}
const stored = response.settings['ui.language'];
const choice = validChoice(stored?.choice) ? stored.choice : 'auto';

// Later, on an explicit language change, after a successful settings read:
const nextChoice = 'fr'; // Your selector's validated value.
if (!validChoice(nextChoice)) throw new Error('Unsupported language choice');
const saved = await StarHermit.api(`${settingsPath}/ui.language`, {
  method: 'PUT', body: { value: { choice: nextChoice } },
});
if (!saved) throw new Error('Language preference was not acknowledged');

StarHermit.api 拒绝大多数失败但解决 null 在 404, 204，或已注销的呼叫； 该示例检查是否有丢失的设置和未确认的密钥更新。便利性 getSettings() 和 setSetting() 帮助器将错误软化为后备值，因此在以下情况下使用原始 API： 区分失败的读或写与成功很重要。空成功 settings 地图是一个 新的偏好；失败的请求则不然。

即使帐户同步失败，也可以在本地应用所选语言，保留待定的选择，并提供 成功读取设置后重试。序列化写入，因此快速选择无法保存较旧的 选择最后。当登录的玩家发生变化时，重新初始化并隔离待处理的同步工作。保留任何 本地首选项缓存范围仅限于游戏和玩家，具有单独的访客范围；商店偏好 与进度分开。在非跟踪游戏中，不要调用帐户API，并遵循您的访客模式 本地偏好存储策略。切勿仅仅因为读取失败而上传默认值。

发布前验证

在桌面和窄触摸屏上测试每种支持的语言，包括所有开始屏幕 变体、暂停/设置菜单、动态 HUD 消息、对话框、教程和错误路径。验证 缺乏表情符号标志支持、键盘/控制器选择、显式保存的设备上的 SVG 标志 选择，并在具有不同系统语言的设备上自动。测试阿拉伯语/乌尔都语形状和 混合方向的玩家名称、长标签、复数计数、缺少按键/字体、不可用的存储、 账户读写失败、快速选择、账户切换。语言的改变必须离开 进度、比赛状态和游戏连接完好无损。
