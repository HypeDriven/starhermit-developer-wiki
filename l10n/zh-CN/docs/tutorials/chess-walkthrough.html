集成演练：在 StarHermit 上构建游戏

此页面逐步介绍了将游戏与 StarHermit 集成的完整生命周期 - 发布、启动、菜单、匹配、游戏、聊天、语音、评级、重播。显示的所有内容均适用于 任何 游戏：您的游戏替换它自己的 slug、它自己的命令和它自己的规则脚本。

运行的示例是开源国际象棋参考实现， 明星隐士国际象棋：一款对应国际象棋游戏（每步 24 小时，elo 评级），以普通 HTML/JS/CSS 构建为无构建静态浏览器游戏。对于每个步骤，演练都会显示游戏客户端进行的确切调用以及进行这些调用的参考存储库中的文件。无论国际象棋特定值出现在哪里——参考游戏的 UUID、移动命令、棋盘编码、 "哈尔" AI，24 小时移动截止时间 - 它们是您自己的游戏在自己的脚本中为自己定义的示例值。

请与它链接到的 API 参考页面一起阅读它。最后的清单将所有内容浓缩为您自己的游戏需要复制的内容。

1. 平台托管游戏剖析

脚本化平台游戏是一个普通的静态站点加上一个规则文件。例如，国际象棋参考实现没有捆绑器、没有框架、没有构建步骤：

文件 角色
index.html 整个页面：看板、菜单、聊天和语音 UI
app.js 应用程序引导、主菜单、配对、邀请、重播、个人资料
net.js HTTP 层：范围游戏路径、启动令牌、令牌刷新
game.js 游戏内控制器：游戏 WebSocket、聊天、语音
ui.js 面板和菜单渲染
style.css 风格
server.js 规则——见下文
starhermit.txt 发布清单

在参考实现中， server.js 值得特别关注。这是 两个都 事情同时发生：

  • 这 服务器权威脚本 平台通过公开执行（通过其 Jint 主机） globalThis.game。每个动作都在服务器上根据合同进行验证 game-scripts.md.
  • 客户的 共享规则引擎，暴露为 globalThis.chessRules，浏览器使用它来进行棋盘渲染、移动预览和重放。

一个文件，一个事实来源， 客户端的零规则权限。遵循这种模式的游戏客户端永远不会决定移动是否合法——它会呈现服务器广播的内容。这是脚本平台游戏中最重要的架构思想，参考实现演示了这一点。

2. 发布您的游戏

发布任何游戏都从 starhermit.txt 体现在回购根目录。它宣告了游戏的 name, launch 入口点， owner， 和 server 脚本。选修的 cover= 是图书馆图块上的艺术品 — 请参阅 这 starhermit.txt 显现。参考实现的清单，例如：

name=StarHermit Chess
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html
owner=3fa85f64-5717-4562-b3fc-2c963f66afa6  # StarHermit user ID, not username/nickname
server=server.js

使用不可变的 id 从 GET /api/v1/me 为了 owner;显示用户名和昵称 值，不应用作明显的所有权标识符。

该平台克隆存储库，提供静态文件 <slug>.starhermit.com — slug 是平台分配给游戏的 uid，而不是您选择的名称；参考游戏是 83fd04b1-3cbe-4b09-a251-3733ad4b9d94，所以它可以在现场播放 83fd04b1-3cbe-4b09-a251-3733ad4b9d94.starhermit.com ——和代理 /api 和 /ws 到后端 同源。这一决定消除了一整类工作：没有 CORS、没有基于 API 的配置、没有环境检测——游戏客户端只使用相对路径。

全流程： github-games.md 和 publisher.md.

3. 启动和认证

国际象棋参考流程从平台启动器接收凭据：

  1. 启动器调用 POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/launch-token （与参考游戏的 UUID 一起显示；替换您自己的）与用户的完整平台 JWT。
  2. 它恢复了短暂的， 游戏范围的 令牌：
{ "token": "<jwt>", "expiresInSeconds": 3600 }
  1. 游戏开始于 index.html#game_token=<jwt>，可选地与 &session_id=<guid> 附加邀请深层链接。

在参考实现中，客户端读取哈希值 一次，然后用 history.replaceState 因此令牌永远不会停留在 URL 栏或历史记录中（app.js, App.init）。它对 JWT 有效负载进行解码以获取两个声明：

  • sub — 用户的 ID
  • game_scope — 游戏蛞蝓

第二个主张很重要： 游戏客户端不应该对其 slug 进行硬编码。参考实现将每个 API URL 构建为 /api/v1/games/<slug> 加一个后缀（net.js, Net.gamePath），因此相同的代码适用于任何游戏、任何 slug、任何部署。

刷新。 作用域令牌允许重新调用 launch-token 对于自己的游戏，因此客户端通常会定期刷新 - 参考实现每 45 分钟刷新一次（net.js, Net.startRefresh），在 60 分钟的生命周期内舒适地度过。

直接打开的游戏可以提供 浏览器登录, 返回 #access_token 而不是启动器的 #game_token。处理两个入口路径，如果 你都支持。使用返回的生命周期进行续订并遵循默认的 12 小时续订链 天花板。一个 403 terms_acceptance_required 要求玩家 通过他们的帐户接受; 或在游戏中显示条款并使用玩家启动令牌接受。重新登录也不行 记录验收。

授权参考： auth.md, games.md.

5. 让玩家参与会话——三种方式

本演练使用匹配、邀请接受和 AI 实践来创建会话。需要大厅的游戏可以使用 实时房间，其启动流程还可以创建绑定的权威会话。

一个。对接会

在参考实现中， App.startMatchmaking 在 app.js:

POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/matchmaking

响应是一张票：

{ "ticketId": "<guid>", "status": "queued" }

或立即匹配：

{ "status": "matched", "sessionId": "<guid>" }

在排队时，客户端轮询匹配端点 - 参考实现轮询 GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/matchmaking 每 3 秒一次，并且 DELETE /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/matchmaking 取消机票。参考客户端还确保玩家永远不会盯着旋转器：在 30 秒未匹配的情况下， "对阵哈尔" 按钮出现（"哈尔" 是国际象棋示例的内置 AI 对手 — 请参阅第 12 节），并且 POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/sessions/ai 回报 { "sessionId" }.

b.好友邀请

在参考实现中， App.inviteFriend 在 app.js。首先列出朋友——此端点明确允许用于游戏范围的代币：

GET /api/v1/me/friends

然后发送邀请：

POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/invites
{ "toUserId": "<guid>" }

接收者接受（或拒绝）来自自己客户的：

POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/invites/{id}/accept   → { "sessionId": "<guid>" }
POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/invites/{id}/decline  → 204

接受是创建会话的原因。这 &session_id= launch-hash deep-link (§3) 将受邀请的玩家直接放入其中。

好友邀请仅适用于已经是好友的人。为了吸引不在平台上（或根本不在平台上）的人，参考实现还提供了 分享邀请链接 按钮 （App.shareInviteLink)：复制的一行字符串构建

https://dashboard.starhermit.com/game-invite/<Net.userId>/<slug>

到剪贴板。 Web 仪表板处理接收者所需的一切 - 登录、好友请求、昵称、启动游戏 - 然后将游戏邀请发送回共享者，因此它会出现在同一个邀请列表中。看 分享链接 以获得完整的合同。

c.规则

会话是通过匹配、邀请接受创建的， sessions/ai，或者启动一个实时房间 服务器后端。对于有座位的大堂，请使用 实时房间API.

6. 玩游戏WebSocket

每个脚本游戏的播放循环都是相同的：获取会话、打开套接字、渲染广播、发送命令。在参考实现中，它位于 game.js, GameController.

获取会话：

GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/sessions/{sessionId}

{
  "sessionId": "<guid>",
  "status": "active",
  "players": [ /* ... */ ],
  "createdAt": "…",
  "finishedAt": null,
  "chatConversationId": "<guid>",
  "result": null
}

笔记 chatConversationId — 您将需要它来进行聊天 (§7) 和语音 (§8)。

连接游戏插座：

ws(s)://<host>/ws/v1/games?sessionId=<id>&access_token=<token>

在 open，客户端立即发送同步命令：

{ "type": "cmd", "data": { "type": "sync" } }

在任何断开连接时，它都会以从 1 秒到 30 秒上限的指数退避重新连接，并且 每次打开时重新发送同步。同步命令使重新连接成为无状态和幂等的：无论客户端错过什么，服务器都会重新广播。

信封。 每个帧都是一个薄的 JSON 信封：

  • 客户端→服务器： {"type":"cmd","data":<command>}
  • 服务器→客户端： {"type":"game","data":…}, {"type":"error","error":…}, {"type":"presence","userId","online"}

游戏命令由您自己的规则脚本定义。 例如，国际象棋示例的命令（ data 的有效载荷 cmd 框架）：

{ "type": "sync" }
{ "type": "move", "from": "e2", "to": "e4", "promo": "q" }
{ "type": "resign" }
{ "type": "offer-draw" }
{ "type": "accept-draw" }
{ "type": "decline-draw" }

在国际象棋的例子中， promo 仅出现在促销活动中。

广播同样是由脚本定义的。 国际象棋示例的广播（ data 的有效载荷 game 框架）：

  • state — 完整快照：
{
  "type": "state",
  "white": "<userId>",
  "black": "<userId>",
  "ratings": { "white": 1420, "black": 1388 },
  "board": "RNBQKBNRPPPPPPPP................................pppppppprnbqkbnr",
  "turn": "w",
  "moves": [ { "from": "e2", "to": "e4", "promo": null, "san": "e4", "at": "…" } ],
  "status": "active",
  "result": null,
  "deadline": 1784642591000,
  "drawOfferBy": null,
  "ai": false,
  "aiName": null
}

这 board 是一个 64 个字符的字符串， index = rank * 8 + file 和 a1 = 0， 使用 PNBRQK 对于白色， pnbrqk 对于黑色， . 对于空方块——国际象棋特定的编码；你的游戏定义了它自己的状态形状。

  • moved ——施展了一个动作。
  • draw-offered / draw-declined.
  • game-over — { "result": { "kind", "reason", "at" }, "view" }， 在哪里 reason 值是脚本定义的；国际象棋示例使用 checkmate, stalemate, threefold-repetition, fifty-move-rule, insufficient-material, resignation, agreement, timeout, timeout-no-moves.

身份永远不会从有效负载中获取。 客户端发送没有用户 ID 的命令，并且脚本从不信任来自网络的命令 - 平台将经过身份验证的发送者传递给脚本。没有什么可以欺骗的。

看 game-scripts.md 对于这一切背后的脚本合同。

7. 游戏内聊天

每个会话都带有一个 chatConversationId (§6) 游戏客户端可用于游戏内聊天。在参考实现中， initChat 在 game.js 像这样使用它：

GET  /api/v1/chat/conversations/{id}/messages?page=1&pageSize=50
POST /api/v1/chat/conversations/{id}/messages
     { "content": "good luck!" }

实时聊天套接字 ws/v1/chat 是 阻止游戏范围的代币。参考客户端尝试一次，被拒绝，然后退回到每 5 秒轮询一次 REST 端点 - 计划从一开始就在您自己的游戏中进行轮询。

即使两个玩家可能不是朋友，聊天仍然可以进行：会话对话（类型 "game"）是由两个玩家作为参与者创建的，因此通常的聊天权限规则已经满足。

参考： chat.md.

8. 语音

语音是可选的，游戏客户端通常会保留它 默认关闭。参考实现在中处理它 game.js, VoiceController。当玩家启用它时：

  1. 查找或创建与会话对话绑定的房间：
GET  /api/v1/voice/rooms?conversationId=<chatConversationId>
POST /api/v1/voice/rooms
     { "conversationId": "<chatConversationId>" }
  1. 加入它：
POST /api/v1/voice/rooms/{roomId}/join
  1. 连接语音插座：
ws(s)://<host>/ws/v1/voice?roomId=<id>&access_token=<token>

媒体是 WebRTC 点对点完美协商;套接字仅承载信令和控制：

  • 信令： {"type":"rtc","to":<userId>,"payload":{"sdp":…}} 或者 {"type":"rtc","to":<userId>,"payload":{"ice":…}}
  • 控制： {"type":"mute","muted":…}, {"type":"speaking","speaking":…}
  • 服务器事件： voice.roster, voice.participant_joined, voice.participant_left, voice.mute_changed, voice.speaking, voice.rtc

如果 P2P 失败，后备方案是服务器中继的 opus 二进制帧：一个 16 字节的发送者 ID，后跟音频有效负载。

声音是 在 AI 游戏中禁用 — 参考客户检查 view.ai 来自国家广播并且从不提供切换。

参考： voice.md.

9. 评分和排行榜

游戏客户端从不提交分数。当一场比赛结束时， 脚本 回报 eloUpdates 和 平台 将它们发布到游戏排行榜。客户端永远不能直接写入排行榜条目；服务器还必须验证其评级更新背后的游戏玩法。

因此，客户端很简单：读取条目（§4）并呈现它们，就像参考实现一样。看 leaderboards.md.

10. 重播

一款游戏宣告 replays: true 在其脚本中包含平台保存的每个已完成的会话；客户端只需获取并渲染它。查看 replaysEnabled 在 GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94 在提供屏幕之前 - 操作员可以以任何一种方式回答游戏，并且下面的端点返回 404 当重播关闭时。在参考实现中，获取是 App.loadReplays / App.openReplay 在 app.js:

GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/replays/mine?limit=10
GET /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/replays/{sessionId}

重播有效负载（以国际象棋示例的结果形状显示）：

{
  "sessionId": "<guid>",
  "players": [ /* ... */ ],
  "finishedAt": "…",
  "result": {
    "kind": "win",
    "reason": "checkmate",
    "at": "…",
    "white": "<userId>",
    "black": "<userId>",
    "moveCount": 41,
    "eloBefore": { "white": 1420, "black": 1388 },
    "eloAfter": { "white": 1436, "black": 1372 }
  },
  "state": { "game": { "moves": [ /* ... */ ] } }
}

观看者的脚步 state.game.moves 通过共享的 chessRules 本地引擎 - 相同 server.js 规则文件，在浏览器中运行 - 因此重播不需要服务器往返；当规则更改时，保留用于存档比赛的规则版本。这是第 1 节中单文件双角色设计的第二个成果，任何游戏都可以采用这种模式并拥有自己的规则文件。

11. 球员简介

游戏客户端通过公共配置文件端点解析其他玩家。在参考实现中， App.profileFor 在 app.js:

GET /api/v1/users/{id}/profile  → { "id": "…", "username": "…", "nickname": "…" }
GET /api/v1/users/{id}/avatar   → image/png, or 404

参考客户端遵循两条 UI 规则：

  • 使成为 昵称，绝不是用户名。
  • 回落至 "Player " + id.slice(0, 8) 当个人资料丢失或昵称为空时。

参考： profile.md.

12.AI练习对手

POST /api/v1/games/83fd04b1-3cbe-4b09-a251-3733ad4b9d94/sessions/ai （如示例 slug 所示）创建一个会话，其中平台标记一个席位 ai: true 在 createSession。脚本本身扮演着这个角色——人工智能的行为是你自己的脚本定义的。在国际象棋的例子中，下棋者是 "哈尔"，一个贪婪的材料捕获引擎，它会回复 在同一个调用中 处理人类的动作。

游戏的脚本决定练习是否会改变人类玩家的评分。 AI座椅不能 接收帐户玩家状态、评级或成就写入。将任何 AI 统计数据保留在会话状态。

13. 参考游戏不使用什么

国际象棋参考实现没有触及这些，但它们都可用于需要它们的游戏：

  • 成就 — 任何带有 server= 脚本可以声明它们（game.achievements）并从任何生命周期挂钩授予它们服务器权威；国际象棋根本没有。目录标题有一个单独的客户声明路径： achievements.md, game-scripts.md.
  • 目录/权利 — 对于通过目录分发和销售的游戏： catalog.md.
  • 中继 — 用于快节奏实时游戏的高频中继通道，其中每个命令脚本往返速度太慢： relay.md.
  • 外部库 — 链接 Steam、Epic 或 GOG 游戏库： external-libraries.md.

国际象棋的例子是一种回合制棋盘游戏，不需要它们。如果您的游戏是实时的、目录分布式的或需要二进制有效负载，那么接下来要查看这些页面。
