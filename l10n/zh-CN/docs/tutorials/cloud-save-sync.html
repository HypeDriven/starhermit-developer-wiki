安全地加载和保存进度

使用云保存来保存已登录玩家的客户端拥有的进度。未签名的单人游戏选项 将进度保留在内存中，并且不读取或写入帐户保存。偏好属于 游戏设置，而不是进度文档。

启动令牌可以准确访问 game:<gameId>， 在哪里 gameId 是它的 game_scope。平台 存储不透明字节，每个槽保存一次。验证您的游戏所需的格式。看 云存档 用于配额和条件标头。

一个完整的小 JSON 食谱

复制 cloud-save-store.js 进入你的构建。此示例存储原始数据 UTF-8 JSON 字节；该平台为他们提供服务 application/zip 但不需要 ZIP 格式。 使用不同的阅读器进行 ZIP 保存，包括 浏览器SDK的ZIP保存。 如果没有现有播放器的迁移计划，请勿更改格式。

import { CloudSaveStore } from './cloud-save-store.js';

const store = new CloudSaveStore({
  gameId: StarHermit.slug,
  token: () => StarHermit.token, // Always obtain the current renewed token.
});
const valid = value => value?.version === 1 && Number.isSafeInteger(value.points) && value.points >= 0;
let progress = { version: 1, points: 0 };
let saving = false;

async function startAccountGame() {
  // Keep gameplay/saving disabled until this resolves.
  const remote = await store.load(valid);
  progress = remote ?? { version: 1, points: 0 };
  render(progress);
}

async function saveCheckpoint() {
  if (saving) return; // Coalesce checkpoints; do not issue overlapping writes.
  saving = true;
  showSync('Saving…');
  try {
    await store.save(progress);
    showSync('Saved');
  } catch (error) {
    if (error.status === 412) {
      // Keep local progress in memory. Offer Reload cloud or an explicit merge.
      showConflict(() => startAccountGame());
    } else showSync('Save failed; retry after resolving the error');
  } finally {
    saving = false;
  }
}

render, showSync， 和 showConflict 是你的用户界面。等待 startAccountGame() 启用之前 播放或保存。加载失败时，保留播放器当前的本地状态，显示失败， 并阻止上传。一个 404 是空槽情况； 401, 403, 5xx, 格式错误的 JSON, 或不受支持的保存版本不是空槽。

该配方不会更新凭据。浏览器 SDK 在启动令牌仍然存在时更新它们 有效。解决待决条款或在重试读取之前通过游戏的进入流程重新进行身份验证。

条件和冲突

加载了什么 下次写入时的标头 如果另一个设备写入
使用 ETag 进行现有保存 If-Match: <etag> 412 precondition_failed
没有保存（404) If-None-Match: * 412 precondition_failed
没有加载成功 不写 继续重试读取或让玩家留在未跟踪的游戏中

使用来自的版本 您加载的数据，而不是稍后的元数据检查。保留返回的新ETag 每次成功写入。一个 412 阻止进一步保存，直到游戏加载当前版本并 玩家采用或合并它。不要默默地删除该条件并覆盖另一个设备。 API 不提供保存历史记录来撤消该覆盖。

如果两个设备必须独立更新计数器或库存，则单个最后写入的文档获胜 可能不适合游戏。使用服务器权威状态并定义经过验证的游戏命令。

保存格式和迁移

在采用远程之前，包括格式版本并验证类型、范围和必填字段 进步。为支持的旧版本编写迁移。保持较新的未知版本完好无损； 不要将其重置为默认值并上传。云数据是客户端控制的，所以永远不要对待它 作为竞争分数或付费权利的证明。

默认解码保存限制为 10 MiB。 Base64 向请求正文添加了大约三分之一。 413 cloud_save_too_large, 409 cloud_save_slots_exhausted， 和 507 cloud_save_quota_exceeded 是不同的容量故障；检查 code 和 limit。荣誉 Retry-After 在 429.

检查点和页面退出

在有意义的检查点保存并提供可见的保存操作。反跳快速变化并序列化 写入，以便每个人都使用最后确认的版本。保留脏指示器直至得到确认。 失败的请求并不是确认的保存；在一次不明确的写入之后，在另一次写入之前重新加载。

页面退出上传是最好的努力。浏览器 fetch(..., { keepalive: true }) 在飞行中共享一个小 身体余量，通常为 64 KiB； 10 MiB 的保存不能依赖它。选项卡可能会在任何请求之前关闭 完成。使用普通的前景保存以提高耐用性，并且不要将未确认的进度标记为 已保存。快速入门会在每个点集合中保存其小文档。

在你的游戏中验证

  1. 从一个空槽开始；收集进度、保存、重新加载并确认其返回。
  2. 拒绝读取网络错误， 403，或无效数据；确认没有上传。
  3. 在一个版本上打开两个选项卡。保存在 A 中，然后保存在 B 中：B 必须暴露冲突并保留其本地状态。
  4. 测试较旧/较新的格式和缺失的确认，而不覆盖未知数据。
  5. 进入未跟踪的单人游戏模式并验证游戏是否发出云保存请求。
