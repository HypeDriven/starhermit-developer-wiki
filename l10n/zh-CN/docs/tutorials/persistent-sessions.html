教程：持久会话 - 当所有人离开时暂停的游戏

通常情况下，平台会结束一场没有人参加的比赛：一旦每个玩家都断开连接，就没有人玩了 五分钟内返回，会话结束为 abandoned 合理 players_left （看 游戏 API — 游戏 WebSocket）。这对于国际象棋来说是正确的 游戏或种族，对于农场、城市建设者、共享地下城或任何世界都是错误的 玩家回归多日。

游戏可以要求 持续会话 反而。当玩家断开连接时，持久会话会暂停：

  1. 最后一名玩家离开。
  2. 大约 15 秒后，无人连接，平台 停顿 会议。没有运行： 脚本游戏没有 onTick 调用，并且容器游戏的会话将从 容器。
  3. 会话在其恢复保留策略内保持暂停状态。读 /sessions/{id}/recovery 任何到期而不是假设它永远保留。
  4. 第一个连接的玩家 ws/v1/games 简历 在他们的第一个命令之前 处理。比赛从停止的地方继续进行。

本页展示了如何打开它，如何防止游戏时钟跳过暂停，以及 您的客户需要做什么。

1. 选择加入

持久性是每个游戏的声明，在发布或更新游戏时阅读 - 发布 更改后更新。一定是字面意思 true 或者 false;其他任何事情都算作“不” 声明，并且不声明任何内容的游戏的行为与以前一样。

脚本游戏 — 静态 persistent 于 game 对象（参见 游戏脚本):

globalThis.game = {
  persistent: true,
  tickRateHz: 1,
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

集装箱游戏 — persistent 在你的 GET /describe 答案（参见 容器游戏服务器):

{ "protocol": 1, "tickRateHz": 20, "maxSessions": 48, "persistent": true }

会话的创建方式没有任何变化：匹配、邀请、AI 端点和实时 所有房间都会为持久游戏产生持久会话。

2. 暂停时保持游戏时间静止

平台不重写 ctx.now — 它仍然是真正的挂钟，因此您可以在任何绝对时间 显示玩家（截止日期、 "收获准备在") 保持它所说的意思。而是坚持不懈 会话获得一个额外的上下文字段：

ctx.pausedMs   // total milliseconds this session has spent paused, so far

它只会增长，并且只会在持续的会话中增长（其他游戏永远不会看到这个领域）。减去它和你 有一个 比赛时钟 当没人在那里时就停止了：

function gameTime(ctx) {
  return ctx.now - (ctx.pausedMs || 0);
}

globalThis.game = {
  persistent: true,
  tickRateHz: 1,

  createSession(ctx) {
    return { ok: true, sessionState: { lastTick: gameTime(ctx), crops: [] } };
  },

  onTick(ctx) {
    var state = ctx.sessionState;
    var t = gameTime(ctx);
    var dt = t - state.lastTick;      // never includes the time the world was paused
    state.crops.forEach(function (crop) { crop.growth += dt; });
    state.lastTick = t;
    return { ok: true, sessionState: state };
  },

  onPlayerMessage(ctx) { /* ... */ }
};

在游戏时间中存储您自己的时间戳（gameTime(ctx)），不在 ctx.now，并仅比较它们 针对比赛时间。如果你 想 世界在无人注视的情况下继续前进——农作物正在生长 隔夜 — 使用 ctx.now 相反，要赶上简历后的第一个刻度。不管怎样，它都是你的 选择；该平台仅报告发生的情况。

时间安排的两个细节：

  • 在最后一个玩家离开和暂停之间的约 15 秒内，会话仍然进行 正常勾选。连接断开并立即恢复的玩家不会导致暂停。
  • 简历结束后，接下来 onTick 稍后出现一个刻度间隔。暂停时间不重播 作为错过的报价的积压。

一个容器接收 pausedMs 在同一个地方：在 POST /sessions 正文发送时 会话在暂停后恢复。

3. 你的客户

暂停的会话仍然是活动会话，因此客户端流程是您已有的流程：

  • 列出要重新加入的世界 和 GET /api/v1/games/{slug}/sessions/mine。每个条目都有一个 pausedAt 暂停时的时间戳和 null 当有人在其中时，您可以展示 "暂停 自从…" 或者 "2 位朋友正在玩" （看 游戏 API — 会话).
  • 重新加入 通过打开 ws/v1/games?sessionId=… 和以前一样。简历发生在 连接。没有什么特别的 "恢复" 它的框架——游戏只是在你第一次运行时运行 命令到达 - 因此请求或等待游戏的正常完整状态消息，就像您在 任何重新连接。
  • 处理失败的简历。 如果平台无法恢复会话——很可能是容器 服务器仍在启动的游戏 - 您收到 {"type":"error","error":"…"} 和插座 已用代码关闭 1001。会话保持暂停状态，不会丢失任何内容。短暂后重新连接 退避（几秒钟，不断增长），并显示 "开始世界……" 而不是一个错误。
  • presence 框架照常工作，因此其他玩家可以看到现在世界上有谁。

4. 结束持久会话

持久会话在以下情况下结束：

  • 您的游戏报告了 result （脚本返回值或容器控制消息），或者
  • 游戏的所有者结束了它（DELETE /api/v1/me/github-games/{id}/sessions/{sessionId}),
  • 最后一个成员明确地离开了一个没有空间的世界 /sessions/{id}/leave， 或者
  • 根据部署的保留策略，其暂停的恢复数据将过期。

断开连接后会员资格完好无损；明确退出即表示放弃会员资格。看 会话生命周期和恢复 对于两个流。

要求新游戏确实 不是 退出玩家的暂停会话，暂停的会话仍然有效 限制每个玩家的并发会话上限（默认为 20）。 给玩家一种完成或完成的方法 离开一个世界 - 一个 "放弃世界" 命令你的脚本回答 result， 例如。 否则，已满上限的玩家将无法开始任何新的事情。

onPlayerMessage(ctx) {
  var msg = ctx.message.data;
  if (msg.type === "close-world" && ctx.message.from === ctx.sessionState.ownerId) {
    return { ok: true, sessionState: ctx.sessionState, result: { kind: "closed" } };
  }
  /* ... */
}

5.集装箱游戏：停车

对于容器游戏来说，暂停是 公园:

  1. 该平台要求提供最终快照（GET /sessions/{id}/snapshot）并持久保存。
  2. 它破坏了会话（DELETE /sessions/{id}）。你的容器停止模拟它，如果 它没有其他会话，部署可以在其空闲期后停止。
  3. 在下一次加入时，它会重新创建会话 POST /sessions，携带存储的 snapshot 以及更新后的 pausedMs — 与崩溃恢复相同的请求 — 唤醒停止的部署 如果需要的话首先。

所以你返回的快照必须足以重建整个世界，而不仅仅是恢复几个世界 播放秒数。如果最终快照失败，会话将从其最后一个周期停止 检查站。与崩溃不同，停放并恢复不会计入您的重启预算，并且 玩家得不到 resumed 框架：没有人在那里看到状态倒带。

清单

  • [ ] persistent: true 声明（脚本）或返回自 /describe （容器），并发布更新。
  • [ ] 游戏计时器使用 ctx.now - ctx.pausedMs，或故意使用 ctx.now 并赶上。
  • [ ] 客户列表 sessions/mine，显示 pausedAt，并重新加入 ws/v1/games.
  • [ ] 客户端在一次后通过退避重试 error 接下来是关闭代码 1001 连接上。
  • [ ] 玩家有办法结束世界，因此他们永远不会陷入会话上限。
  • [ ]（容器）快照重建整个世界。
