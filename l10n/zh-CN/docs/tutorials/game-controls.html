教程：向游戏添加控件

星隐者可以存储 键绑定 对于您的游戏：您声明操作及其默认键， 每个玩家都可以重新绑定它们。他们的选择会跟随他们登录的任何机器。你的游戏 从控件 API 读取玩家的绑定并可以提供自己的 "重新绑定按键" 屏幕。

如果您的游戏调用控件 API 并得到以下信息：

404 {"error":"This game declares no controls."}

该平台有 没有宣布的行动 对于它所服务的构建。您发送到 API 的任何内容都不能 解决这个问题：控件在您的游戏中声明 starhermit.txt 并在何时阅读 游戏发布。此页面展示了如何声明它们、发布它们、检查它们是否到达、 并从您的客户那里使用它们。

  1. 宣布行动
  2. 发布它们
  3. 检查他们是否到达
  4. 在你的游戏中使用它们
  5. 故障排除

1. 声明行动

添加一个 control.<action>= 每个动作行 starhermit.txt:

name=Space Hopper
launch=index.html

control.left=KeyA+ArrowLeft | Move left
control.right=KeyD+ArrowRight | Move right
control.jump=Space+KeyW | Jump
control.fire=KeyJ | Fire
control.pause=Escape | Pause

每行由三部分组成：

control.<action>=<code>[+<code>...][ | <label>]
部分 规则
<action> 您的游戏操作名称：1–32 个小写字母、数字和 _ (move_left， 不是 move-left）。每个清单都是唯一的。
<code> A KeyboardEvent.code 值，例如 KeyA, ArrowLeft, Space, Digit1, ShiftLeft, Enter 或者 Escape。将 1-4 个代码连接起来以执行相同的操作 +.
<label> 选修的。显示在重新绑定屏幕中；最多 64 个字符。默认为操作名称。

要知道的事情：

  • 使用 code， 不是 key. 写 KeyA， 不是 a， 和 Space， 不是 " "。代码命名物理 键，因此绑定适用于任何键盘布局。平台仅检查代码是否为1-32 字母和数字，所以 a 或者 space 被接受，但没有密钥产生它。拼写和大小写 必须完全匹配。
  • 一把钥匙属于一个动作。 前一行已使用的代码将生成后一行 无效。
  • 最多 32 个操作 每场比赛。第 32 行之后的行将被忽略。
  • 订单被保留。 操作按清单顺序从 API 返回，因此请按以下方式列出它们 您的设置屏幕应该显示它们。
  • 无效行将被静默跳过。 游戏仍然发布。如果每一行都无效， 游戏没有控件和 API 答案 404. 发布后检查.

2. 发布它们

声明已读 当游戏发布时。编辑 starhermit.txt 在你的存储库中 或者在磁盘上不进行任何更改，直到您发布包含它的构建：

您的游戏如何发布 是什么让新控件生效
来自 GitHub 存储库 您的下一次部署。推送更改，然后部署最新版本（更新部署版本 在仪表板中，或 PUT /api/v1/me/github-games/{id}/deployment).
上传的文件夹或包 上传新版本（POST /api/v1/me/github-games/{id}/bundle， 或者 ws/v1/game-upload) 谁的 starhermit.txt 有线条。
添加新游戏 第一次上传或提交会立即读取它们。

替换上传会根据其自己的清单重申您的控件。删除每个 control.* 线和 游戏没有。一个 ?mode=merge 修补那个 没有携带 starhermit.txt 保持当前的控制。

玩家自己的重新绑定在新构建中仍然存在。 玩家保存的动作绑定 存在时间较长的将被忽略。

3. 检查他们是否到达

下面的每个端点都使用完整的用户令牌或游戏的启动令牌。 {slug} 是你的 游戏的 slug：启动令牌 game_scope 索赔，或 gameSlug 在 GET /api/v1/me/github-games.

curl -s "https://api.starhermit.com/api/v1/games/$SLUG/controls" \
  -H "Authorization: Bearer $TOKEN" | jq

{
  "actions": [
    { "action": "left",  "label": "Move left",  "defaultCodes": ["KeyA", "ArrowLeft"],  "codes": ["KeyA", "ArrowLeft"] },
    { "action": "right", "label": "Move right", "defaultCodes": ["KeyD", "ArrowRight"], "codes": ["KeyD", "ArrowRight"] },
    { "action": "jump",  "label": "Jump",       "defaultCodes": ["Space", "KeyW"],      "codes": ["Space", "KeyW"] },
    { "action": "fire",  "label": "Fire",       "defaultCodes": ["KeyJ"],               "codes": ["KeyJ"] },
    { "action": "pause", "label": "Pause",      "defaultCodes": ["Escape"],             "codes": ["Escape"] }
  ]
}

缺少动作意味着他们的台词无效；将它们与上述规则进行比较。一个 404 意味着没有幸存，或者声明它们的构建尚未发布。

4. 在你的游戏中使用它们

codes 是玩家的有效绑定：如果设置了则覆盖，否则为默认值。 从中构建查找并匹配 event.code:

const auth = { Authorization: `Bearer ${launchToken}` };

// Your built-in defaults, in the same shape the API returns.
const DEFAULT_ACTIONS = [
  { action: "left", label: "Move left", codes: ["KeyA", "ArrowLeft"] },
  { action: "jump", label: "Jump", codes: ["Space", "KeyW"] },
  /* ... */
];

function toControls(actions) {
  const byCode = new Map();
  for (const a of actions) for (const code of a.codes) byCode.set(code, a.action);
  return { actions, byCode };
}

async function loadControls(slug) {
  try {
    const res = await fetch(`/api/v1/games/${slug}/controls`, { headers: auth });
    if (res.ok) return toControls((await res.json()).actions);
  } catch { /* offline: fall through */ }
  return toControls(DEFAULT_ACTIONS);                   // 404, error, or outside StarHermit
}

let controls = await loadControls(gameScope);

window.addEventListener("keydown", (e) => {
  const action = controls.byCode.get(e.code);   // e.code, never e.key
  if (action) { e.preventDefault(); onAction(action, true); }
});
window.addEventListener("keyup", (e) => {
  const action = controls.byCode.get(e.code);
  if (action) onAction(action, false);
});

内置默认设置使游戏可以在 StarHermit 之外离线玩，或者如果控件 请求失败。让他们与您保持同步 control.* 线。

重新绑定屏幕。 列表 actions 与他们的 label。保留完整的覆盖图，或者 在更改一项操作之前读取并保留当前有效地图：

async function saveBinding(slug, action, codes) {
  const current = await fetch(`/api/v1/games/${slug}/controls`, { headers: auth });
  if (!current.ok) throw new Error(`Controls read failed: ${current.status}`);
  const bindings = Object.fromEntries((await current.json()).actions.map(a => [a.action, a.codes]));
  bindings[action] = codes;
  const res = await fetch(`/api/v1/games/${slug}/controls`, {
    method: "PUT",
    headers: { ...auth, "Content-Type": "application/json" },
    body: JSON.stringify({ bindings }),
  });
  if (!res.ok) throw new Error((await res.json()).error);   // e.g. a key already in use
  return res.json();                                         // the new effective map
}

PUT 用您发送的操作替换玩家的覆盖，因此包括玩家的每个操作 已经改变了，而不仅仅是最新的。其余的保留默认值。 DELETE 在同一条路上 将所有内容重置为默认值。

从屏幕上序列化更改；两个同时读/写仍然可以互相覆盖。 浏览器 SDK setControl() 序列化自己的更改并保留当前有效的映射。 发送有效地图将这些值固定为覆盖；使用 DELETE 返回清单默认值。

平台拒绝保存（400）这将在两个操作上留下一个键 后 玩家的 更改将与您的默认值合并。例如，绑定 jump 到 KeyJ 尽管 fire 仍然 使用其默认值 KeyJ 被拒绝。显示错误，或将冲突的操作移至同一操作中 保存。

故障排除

回复 原因 使固定
404 "该游戏声明没有控件。" 无效 control.* 线在 发表 建造。 添加行至 starhermit.txt，检查它们 规则， 和 发布新版本.
404 "与那只蛞蝓没有游戏可言。" slug 错误，或者游戏没有 slug。 使用启动令牌 game_scope 或者 gameSlug 从 GET /me/github-games。从本地文件夹添加的每个游戏以及经过验证的所有者添加的每个存储库游戏都有一个 slug，无论是否仅限浏览器。只有所有者未经验证的存储库提交才没有任何内容； 声称它 得到一个。
403 "该令牌的范围为游戏“...”。" 与另一个游戏的 slug 一起使用的启动令牌。 使用令牌中的 slug 进行调用 game_scope.
400 "未知动作“…”——未在游戏清单中声明。" PUT 命名清单未声明的操作。 使用 action 值来自 GET …/controls.
400 "'...' 绑定到 '...' 和 '...'。" 与默认值合并后，一个键将触发两个操作。 将其他动作移至同一位置 PUT，或选择另一个键。
400 "“…”不是有效的 KeyboardEvent.code 值。" 带有空格或标点符号的代码。 发送 event.code 价值观。
400 "操作“...”必须绑定 1-4 个代码。" 一个空列表，或者超过四个。 发送 1–4 个代码； DELETE 重置。
响应中缺少操作 它的行无效：大写字母或 - 在动作名称中， , 而不是 +、超过 4 个代码、已使用的代码或超过第 32 个操作的代码。 修复线路并再次发布。
绑定永远不会触发 代码被接受，但没有密钥生成它，例如 a 或者 space. 使用精确的 KeyboardEvent.code 拼写： KeyA, Space.

参见： 游戏 API — 每个玩家的控制绑定, starhermit.txt.
