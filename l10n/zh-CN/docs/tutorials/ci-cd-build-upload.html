使用 OAuth 注册的公钥从 CI/CD 上传构建

本教程为部署管道提供了自己的 StarHermit 凭证，而不存储您的 Google 或 CI 中的 GitHub OAuth 令牌。一次性设置是交互式的：

  1. 通过 OAuth 登录并接受当前的 StarHermit 条款。
  2. 将专用公钥添加到您的 StarHermit 帐户。
  3. 仅将该密钥的私有部分放入 CI 秘密存储中。

然后，每个管道运行都会签署一个短暂的 StarHermit 挑战，并收到一个普通的 15 分钟 访问令牌，并上传新版本。管道密钥充当您的帐户，只能更新 帐户拥有的游戏。

为什么要使用单独的部署密钥？

不要在 CI 中保存 OAuth 访问或刷新令牌。 StarHermit 公钥是更好的机器 凭证，因为它可以独立标记、审核和撤销。会话已验证 按那个键 无法添加密钥或撤销其他密钥;这些操作需要 OAuth 验证 会议。它可以通过以下方式撤销自身 /api/v1/me/public-keys/current。如果 CI 机密泄露，请使用 Google 或 GitHub 登录并撤销部署密钥。 撤销还会结束该密钥创建的刷新会话，并使其现有的访问令牌失败 在他们的下一个 API 请求上。

例如，每个存储库/环境使用一个密钥 orbit-league-production，而不是共享 每个工作流程都有一个私钥。

先决条件

  • 通过 Google 或 GitHub OAuth 登录的 StarHermit 帐户。
  • 该帐户拥有的现有游戏。保存其 id 作为 GAME_ID;捆绑端点更新 游戏，但不创建游戏。
  • 可分发的客户端构建和/或 Docker 兼容 docker save 图像。看 GitHub 游戏 用于存档布局。
  • Python 3 用于设置命令和示例工作流程； curl 和 jq 以注册为例。

管道可以成功登录并仍然接收 403 terms_acceptance_required 当它 上传或打开上传套接字。让帐户所有者审核并 接受当前条款 交互地，然后重新运行作业。当条款发生变化时，这种情况可能会再次发生；不自动接受 来自 CI 的术语。

在 StarHermit 客户端中创建密钥

StarHermit 客户端（Windows、macOS、Linux、Android 和 Web 仪表板）可以一次性执行此操作 为您设置：它生成密钥对，将公共部分添加到您的帐户并显示 私人一半一次。使用它代替下面的步骤 1 和 2。

  1. 使用 Google 或 GitHub 登录客户端。使用设备密钥登录的会话无法 添加密钥，以便客户端要求您首先通过提供商登录。

  2. 打开 选项 → 帐户.

  3. 在下面 新钥匙，输入将使用该密钥的名称（例如 orbit-league-ci 或者 publish-agent）并按 创建密钥.

  4. 按 复制。剪贴板包含三行：

    STARHERMIT_KEY_TYPE=Ed25519
STARHERMIT_PUBLIC_KEY=<Base64 raw public key>
STARHERMIT_PRIVATE_KEY=<Base64 32-byte private seed>

  5. 将它们放入您的 CI 秘密存储或代理的环境中（下面的步骤 3），然后按 完毕。 私钥不再显示；如果您丢失了它，请创建另一个密钥并撤销该密钥。

从终端， starhermit-client keys create orbit-league-ci 打印相同的三行。

这 您帐户上的登录密钥 同一页面上的列表显示每个键：添加时， 上次登录的时间、地址和客户端以及是否被撤销。选择一个键 并按 撤销选定的密钥 把它剪掉。撤销也会结束其会话，因此正在运行的作业或 代理在下一个请求时将失去访问权限。 starhermit-client keys 和 starhermit-client keys revoke <id> 从终端执行相同的操作。

让 AI 代理发布您的游戏

构建您的游戏的 AI 编码代理（Claude Code、Codex、Cursor 等）可以发布它 也有自己的密钥：

  1. 如上为agent创建一个key，以agent和项目命名，例如 claude-orbit-league。为每个代理和每个项目提供自己的密钥，以便您可以区分它们 并在不破坏其他项的情况下撤销其中一项。

  2. 给代理三行，再加上 STARHERMIT_GAME_ID （你的游戏 ID），作为环境 变量，来自代理工具的秘密或环境设置，或者 .env 文件是 列于 .gitignore。切勿粘贴私人内容 键入聊天或提交。

  3. 添加 身份验证/上传助手 到项目和 告诉代理如何发布。例如：

    When a build is ready to publish, run
python ci/starhermit_upload.py dist/game.zip
with STARHERMIT_PUBLIC_KEY, STARHERMIT_PRIVATE_KEY and STARHERMIT_GAME_ID from the environment.
Never print, log or commit STARHERMIT_PRIVATE_KEY. If the upload answers
403 terms_acceptance_required, stop and ask me to accept the terms.

代理的密钥充当您的角色，但仅限于您的帐户可以执行的操作：它可以更新您拥有的游戏。 它无法添加密钥、撤销您的其他密钥、更改您的电子邮件或删除登录提供商。查看 选项 → 帐户 时不时地：钥匙的最后一次使用、地址和客户显示代理拥有什么 一直在做。当项目结束或出现任何问题时，撤销密钥。

手动一次性设置

1.本地生成部署密钥

该示例使用 Ed25519。在受信任的工作站上运行此命令，而不是在 CI 作业中：

python -m pip install cryptography
python - <<'PY'
import base64
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
from cryptography.hazmat.primitives.serialization import Encoding, NoEncryption, PrivateFormat, PublicFormat

key = Ed25519PrivateKey.generate()
private = key.private_bytes(Encoding.Raw, PrivateFormat.Raw, NoEncryption())
public = key.public_key().public_bytes(Encoding.Raw, PublicFormat.Raw)
print("STARHERMIT_PRIVATE_KEY=" + base64.b64encode(private).decode())
print("STARHERMIT_PUBLIC_KEY=" + base64.b64encode(public).decode())
PY

私有值是 32 字节种子，并在此受信任的本地终端中显示一次。从不承诺 将其打印在 CI 日志中、将其放入工件中或将其发送给 StarHermit。保持公共价值 下一步和工作流程变量。

2. 使用OAuth登录并添加公钥

在浏览器中打开以下 URL 之一：

https://api.starhermit.com/api/v1/auth/oauth/github/authorize
https://api.starhermit.com/api/v1/auth/oauth/google/authorize

回调后，立即使用返回的 OAuth 验证的访问令牌。把它放在本地 环境变量而不是 shell 历史记录中：

read -rsp 'OAuth access token: ' OAUTH_ACCESS_TOKEN; echo
read -rp  'Public key: ' STARHERMIT_PUBLIC_KEY

curl -sS -X POST https://api.starhermit.com/api/v1/me/public-keys \
  -H "Authorization: Bearer $OAUTH_ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  --data "$(jq -n \
    --arg keyData "$STARHERMIT_PUBLIC_KEY" \
    --arg label 'orbit-league-production' \
    '{keyType:"Ed25519", keyData:$keyData, label:$label}')"

调用返回 201 以及关键记录。一个 403 表示此令牌不是来自 OAuth 会话（电子邮件验证、公钥或游戏启动令牌是不够的）。一个 409 意味着 密钥已处于活动状态或帐户已达到其活动密钥限制。

检查结果 GET /api/v1/me/public-keys。该列表包括标签、指纹、上次使用情况 次，并撤销密钥，因此它也是凭证审计跟踪。

3.配置存储库

在 GitHub 中添加：

  • 行动秘密 STARHERMIT_PRIVATE_KEY：Base64 私人种子。
  • 动作变量 STARHERMIT_PUBLIC_KEY：Base64 原始公钥。
  • 动作变量 STARHERMIT_GAME_ID：所属游戏的ID。

如果需要批准，请使用 GitHub 环境保护生产。等效值可以是 存储在 GitLab 受保护变量、Azure Key Vault 或任何其他 CI 秘密存储中。

添加身份验证/上传帮助程序

提交以下内容作为 ci/starhermit_upload.py。它重建了确切的挑战 JSON StarHermit 进行内部签名，使用 Ed25519 进行身份验证，并为小型档案或大型档案选择 HTTP 上传超过 90 MB 的 WebSocket 档案。 WebSocket 避免了 CDN 的大约 100 MB HTTP 主体 限制。

#!/usr/bin/env python3
import argparse, asyncio, base64, json, os
from pathlib import Path
from urllib.parse import quote, urlparse, urlunparse

import requests
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey


def authenticate(api, public_key, private_key):
    challenge = requests.post(
        f"{api}/api/v1/auth/public-key/challenge",
        json={"keyType": "Ed25519", "keyData": public_key}, timeout=30)
    challenge.raise_for_status()
    body = challenge.json()
    p = body["payload"]

    # Public JSON is camelCase; the server verifies its ChallengePayload serialization, whose
    # property names and order are the PascalCase sequence below.
    payload = {
        "ChallengeId": p["challengeId"],
        "Fingerprint": p["fingerprint"],
        "Issuer": p["issuer"],
        "Audience": p["audience"],
        "Expiry": p["expiry"],
        "Nonce": p["nonce"],
        "ClientTimestamp": p["clientTimestamp"],
    }
    # System.Text.Json escapes '+' in string fields (the Base64 nonce) as \u002B.
    # DateTimeOffset fields keep literal '+' in their offsets: do not replace globally.
    fields = []
    for name, value in payload.items():
        encoded = json.dumps(value)
        if name == "Nonce":
            encoded = encoded.replace("+", r"\u002B")
        fields.append(json.dumps(name) + ":" + encoded)
    signed_payload = ("{" + ",".join(fields) + "}").encode("utf-8")

    seed = base64.b64decode(private_key, validate=True)
    signature = Ed25519PrivateKey.from_private_bytes(seed).sign(signed_payload)
    complete = requests.post(
        f"{api}/api/v1/auth/public-key/complete",
        json={"challengeId": body["challengeId"],
              "signature": base64.b64encode(signature).decode(),
              "keyType": "Ed25519", "keyData": public_key}, timeout=30)
    complete.raise_for_status()
    return complete.json()["accessToken"]


def upload_http(api, game_id, token, archive, mode):
    with archive.open("rb") as stream:
        response = requests.post(
            f"{api}/api/v1/me/github-games/{game_id}/bundle",
            params={"mode": mode} if mode != "replace" else None,
            headers={"Authorization": f"Bearer {token}",
                     "Content-Type": "application/gzip"},
            data=stream, timeout=1800)
    response.raise_for_status()
    print(json.dumps(response.json()))


async def upload_websocket(api, game_id, token, archive, mode):
    import websockets
    parsed = urlparse(api)
    query = f"gameId={quote(game_id)}&access_token={quote(token)}"
    if mode != "replace":
        query += f"&mode={quote(mode)}"
    uri = urlunparse(("wss" if parsed.scheme == "https" else "ws", parsed.netloc,
                      "/ws/v1/game-upload", "", query, ""))
    async with websockets.connect(uri, max_size=None, ping_interval=20) as ws:
        ready = json.loads(await ws.recv())
        if ready.get("type") != "ready":
            raise RuntimeError(ready)
        with archive.open("rb") as stream:
            while chunk := stream.read(512 * 1024):
                await ws.send(chunk)
        await ws.send(json.dumps({"type": "complete"}))
        while True:
            message = json.loads(await ws.recv())
            if message.get("type") == "result":
                print(json.dumps(message))
                return
            if message.get("type") == "error":
                raise RuntimeError(message)


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("archive", type=Path)
    parser.add_argument("--api", default="https://api.starhermit.com")
    parser.add_argument("--mode", choices=("replace", "merge"), default="replace",
                        help="replace the live client files (default) or patch them")
    args = parser.parse_args()
    game_id = os.environ["STARHERMIT_GAME_ID"]
    token = authenticate(args.api.rstrip("/"), os.environ["STARHERMIT_PUBLIC_KEY"],
                         os.environ["STARHERMIT_PRIVATE_KEY"])
    if args.archive.stat().st_size < 90 * 1024 * 1024:
        upload_http(args.api.rstrip("/"), game_id, token, args.archive, args.mode)
    else:
        asyncio.run(upload_websocket(args.api.rstrip("/"), game_id, token, args.archive, args.mode))


if __name__ == "__main__":
    main()

将非零退出视为失败的部署。不要记录访问令牌或完整的请求正文。 访问令牌持续 15 分钟，因此在上传之前立即进行身份验证； WebSocket 在握手期间检查它，并可能在令牌过期后完成。

GitHub 操作示例

此示例发布的内容 dist/ 每次推动 main:

{％ 生的 ％}

name: Deploy to StarHermit
on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'

      - name: Build
        run: |
          npm ci
          npm run build

      - name: Package StarHermit bundle
        run: |
          mkdir -p bundle/client
          cp -R dist/. bundle/client/
          cp starhermit.txt bundle/starhermit.txt
          tar -C bundle -czf game-bundle.tar.gz .

      - name: Install uploader dependencies
        run: python -m pip install 'cryptography>=42,<45' 'requests>=2.31,<3' 'websockets>=12,<13'

      - name: Upload build
        env:
          STARHERMIT_PRIVATE_KEY: ${{ secrets.STARHERMIT_PRIVATE_KEY }}
          STARHERMIT_PUBLIC_KEY: ${{ vars.STARHERMIT_PUBLIC_KEY }}
          STARHERMIT_GAME_ID: ${{ vars.STARHERMIT_GAME_ID }}
        run: python ci/starhermit_upload.py game-bundle.tar.gz

docker build -t my-game-server:${GITHUB_SHA} -f Dockerfile.server .

成功的捆绑包上传意味着 StarHermit 接受并自动发布该捆绑包；确实如此 并不意味着新容器已通过健康检查。轮询 GET /api/v1/me/github-games/{id}/deployment 使用相同的新验证令牌并运行 推广发布前进行冒烟测试。

轮换和事件响应

  1. 通过 OAuth 登录并接受当前的 StarHermit 条款。
  2. 添加新生成的、带有明显标签的密钥（在客户端中： 选项 → 帐户 → 创建密钥).
  3. 替换 CI 密钥和变量，然后运行部署。
  4. 撤销旧密钥（撤销选定的密钥 在客户端中，或者 DELETE /api/v1/me/public-keys/{keyId}).

对于可疑的广泛妥协， DELETE /api/v1/me/public-keys/all 撤销每个活动密钥。 两个删除操作都需要经过 OAuth 身份验证的会话。由自己验证的管道 密钥无法撤销其他密钥、添加替换密钥、更改帐户电子邮件或删除 OAuth 身份。 它可以撤销自身 DELETE /api/v1/me/public-keys/current;之后丢弃其存储的令牌。
