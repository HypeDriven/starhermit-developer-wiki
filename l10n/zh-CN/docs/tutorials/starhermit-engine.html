教程：使用 StarHermit 引擎构建游戏

这 StarHermit 引擎是创建在 StarHermit 上发布的游戏的推荐方法。 您构建游戏一次，相同的包就可以在浏览器和本机中自动播放 跨引擎支持的所有平台。本机游戏提供额外的性能和功能。 可用性取决于引擎版本：1.1.0 及更高版本有 Windows 运行时和 Web 运行时 （1.0.0 仅限 Windows），1.8.1 及更高版本也为开发人员提供 Linux 运行时。本页描述引擎 1.24.0;列出了每个版本的更改内容 下 引擎发布.

StarHermit 引擎运行 脚本游戏：用 TypeScript（或 JavaScript）编写的整个游戏以及 由一个预构建引擎可执行文件（StarHermit 运行时）播放，无需编译任何本机代码。 您根据引擎的内置模块编写游戏逻辑 - 3D 场景、输入、HUD、音频、 存储和 StarHermit 平台 — 剩下的由运行时完成：窗口化、渲染 GPU、声音、选项菜单、登录和在线游戏。玩家在 starhermit.com 上打开游戏 他们的浏览器，其页面加载您的游戏从该 wiki 请求的引擎，或者在本机播放它 在 星隐者 Windows 客户端，安装该引擎。

本教程构建 明星捕手，一个小游戏，你需要驾驶一个篮子来接住掉落的东西 星星，并将其从空文件夹中取出到已发布的游戏中：

1.什么是脚本游戏

脚本游戏是一个文件夹（ 包裹）与一个 starhermit.txt 在其 root、您的 TypeScript 模块和您的资产。三 engine.* 清单中的行使其成为一：

engine.api=1
engine.entry=src/main.ts
engine.version=1.24.0

engine.api 是您的代码所针对的主机 API 的主要版本， engine.entry 的 模块运行时启动，并且 engine.version 游戏构建的确切引擎版本以及 测试过。版本发布在此 wiki 下 引擎发布;的 游戏从不包含引擎本身，因此上传仅包含您自己的文件。

运行时将每个游戏视为不受信任：您的代码仅通过主机 API 到达机器 （它自己的包文件，它自己的存储，它自己的游戏id的平台），从来没有文件，进程， 任意网络连接或玩家的凭据。作为回报，游戏不能使运行时崩溃 或挂起窗口：运行三秒钟的调用会调出运行时自己的窗口 "没有回应" 屏幕上，未捕获的错误会在错误屏幕上结束游戏，玩家可以从中重新启动。

2.获取引擎

对于自动发布和脚本游戏开发 MCP 服务器，请获取 独立开发者工具。他们还包装 macOS 上的网页游戏，无需 Rust 或私有存储库访问权限；游戏测试在 浏览器那里。本机 Windows/Linux 播放使用以下运行时。

玩家 不执行任何操作：在浏览器中，游戏页面加载来自此 wiki 的游戏引脚版本 并根据页面携带的哈希值进行检查；在 StarHermit Windows 客户端中，播放下载 发行版（一次，由固定它的每个游戏共享），根据发行版检查每个文件 发布哈希并启动它。

开发商 从引擎区域下载版本的运行时：

  • starhermit-1.24.0-windows-x86_64.zip （Windows 10 或 11，64 位），11.5 MB。
  • starhermit-1.24.0-linux-x86_64.tar.gz （带有 glibc 2.35 或更高版本的 64 位 Linux：Ubuntu 22.04、Debian 12 或更高版本），11.7 MB。

存档包含一个文件夹， starhermit-1.24.0-windows-x86_64， 和 starhermit.exe， 这 release.json 告诉运行时它是哪个版本，版本的 web-manifest.json, LICENSE-engine 以及第三方通知。它与客户端安装的引擎相同，并且 在没有网络的情况下为发行版的 Web 运行时打包游戏。它的大小和 SHA-256 列在下面 downloads 在发布的 native.json;到 检查 PowerShell 中的副本，进行比较 sha256 和：

Get-FileHash .\starhermit-1.24.0-windows-x86_64.zip -Algorithm SHA256

解压存档并在解压的文件夹中打开终端：

.\starhermit.exe --version

starhermit 1.24.0 (host API 1.26, launcher 1; engine release 1.24.0)

在 Linux 上，解压存档并运行 starhermit 从它的文件夹（它的 native.json 列出存档的 SHA-256 相同 方式；检查一下 sha256sum):

tar -xzf starhermit-1.24.0-linux-x86_64.tar.gz
./starhermit-1.24.0-linux-x86_64/starhermit --version

--version, new, types, check 和 package 不需要更多了。要在窗口中玩游戏 运行时需要带有 Vulkan 或 OpenGL ES 3.0 驱动程序的 Wayland 或 X11，以及用于声音的 ALSA 或 PulseAudio； native.json's requires 列出它使用的每个库。玩家仍然可以在本机上传 StarHermit Windows 客户端； Linux运行时用于编写、检查和打包游戏。

下面的命令写为 starhermit;将它们运行为 .\starhermit.exe （Windows）或 ./starhermit (Linux) 从该文件夹，或将该文件夹添加到您的 PATH.

3. 创建游戏

starhermit new star-catcher --title "Star Catcher"

Created Star Catcher in star-catcher: a script game pinned to engine 1.24.0
Play it: starhermit star-catcher
Check it: starhermit check star-catcher
For a native upload (the StarHermit client plays it): starhermit package --native star-catcher
For the web: starhermit package --web star-catcher --out <upload>

新文件夹包含一个可播放的起点 - 当您按空格键时会跳跃的立方体：

star-catcher/
  starhermit.txt             the manifest, pinned to the runtime's own release (engine.version=1.24.0)
  tsconfig.json              TypeScript settings for checking the game
  src/main.ts                the entry module
  .starhermit/starhermit.d.ts  the host API's declarations, for your editor and the type checker

.starhermit/ 以点开头，因此它永远不是包的一部分。 starhermit types star-catcher 再次写入声明，例如在您移动到较新的版本后 运行时。主机 API 的每个模块、成员、单位、限制和错误都记录在该文件中。

运行时不会进行类型检查：它会在加载每个模块时删除 TypeScript 的类型。检查它们 自己使用 TypeScript 5 或更高版本；安装了 Node.js， npx 无需安装即可运行 游戏文件夹中的任何内容：

cd star-catcher
npx --package typescript tsc -p .

开发文件不包含在包中：点名称（例如 .starhermit/ 和 .git/), node_modules/, tsconfig.json, jsconfig.json, package.json、npm、yarn 和 pnpm 锁定文件， 源映射（*.js.map, *.ts.map 等）和 Thumbs.db/desktop.ini。其他一切都在 该文件夹是包的一部分。要省略更多内容，请添加 .starhermitignore 在游戏的根源 使用 gitignore 风格的规则（* 和 ? 在一个名字中， ** 对于任意数量的文件夹，尾随 / 对于文件夹， ! 保留默认规则遗漏的文件；最后的匹配规则决定）：

notes/
levels/**/draft-*.json
!package.json

读取或导入遗漏文件的游戏失败，并出现命名规则的错误，在开发中为 好吧，所以 starhermit check 在上传之前捕获它。

4. 编写第一个版本

替换生成的 starhermit.txt 与游戏的清单：

name=Star Catcher
description=Catch the falling stars before the time runs out.
launch=index.html
engine.api=1
engine.entry=src/main.ts
engine.version=1.24.0
engine.minor=15
engine.capabilities=platform,storage
control.left=KeyA+ArrowLeft | Move left
control.right=KeyD+ArrowRight | Move right
control.start=Space+Enter | Start a round
engine.gamepad.left=LeftStickLeft+DpadLeft
engine.gamepad.right=LeftStickRight+DpadRight
engine.gamepad.start=South
cache..=0

这 control.* 行使用默认键（平台的 控制 格式）和 engine.gamepad.* 他们的游戏手柄默认值。玩家重新绑定 它们位于运行时的“选项”菜单中，因此游戏会读取 行动，从不钥匙。游戏声明最多 128个动作：平台保留前32个玩家账号，运行时保留 播放器同步设置中其余部分的绑定。 engine.group.<action>=Heading 开始一个小组 例如，控制屏幕在标题下显示该操作（直到下一组） engine.group.left=Movement （主机 API 1.6）。 engine.capabilities 询问游戏除了绘图和输入之外还使用什么： platform 对于已登录玩家和在线玩家 特点， storage 用于保存在玩家设备和帐户上的数据。 launch=index.html 命名 在浏览器中玩游戏的页面，当您 发布.

然后更换 src/main.ts:

// Star Catcher: catch the falling stars in the basket before the time runs out.
import { frame, onFixedUpdate, onRender, onStart, setFixedRate } from "starhermit:engine";
import {
  AmbientLight,
  BoxGeometry,
  Color,
  DirectionalLight,
  Mesh,
  MeshStandardMaterial,
  PerspectiveCamera,
  SphereGeometry,
  renderer,
  scene,
} from "starhermit:scene";
import { onAction, value } from "starhermit:input";
import { storage } from "starhermit:storage";
import { player } from "starhermit:platform";
import * as draw from "starhermit:draw";

// -- The scene ----------------------------------------------------------------
const camera = new PerspectiveCamera(50, 16 / 9, 0.1, 100);
camera.position.set(0, 4, 12);
camera.lookAt(0, 3, 0);
renderer.camera = camera;
scene.background = new Color(0x0b1020);

const sun = new DirectionalLight(0xfff4e0, 1.2);
sun.position.set(3, 8, 5);
scene.add(sun, sun.target, new AmbientLight(0x6070a0, 0.5));

const basket = new Mesh(new BoxGeometry(2, 0.4, 1), new MeshStandardMaterial({ color: 0x4fa3ff, roughness: 0.4 }));
scene.add(basket);

const starGeometry = new SphereGeometry(0.3, 16, 12);
const starMaterial = new MeshStandardMaterial({ color: 0xffd34d, emissive: 0xffb000, emissiveIntensity: 0.6 });
const stars = Array.from({ length: 3 }, () => {
  const mesh = new Mesh(starGeometry, starMaterial);
  scene.add(mesh);
  return { mesh, x: 0, y: 0, previousY: 0, speed: 0 };
});
type Star = (typeof stars)[number];

// -- The rules ----------------------------------------------------------------
const WIDTH = 6; // the basket moves between -WIDTH and WIDTH
const ROUND = 60; // seconds a round lasts
let basketX = 0;
let previousX = 0;
let score = 0;
let timeLeft = 0; // 0 between rounds
const saved = storage.getJson("best");
let best = typeof saved === "number" ? saved : 0;

function drop(star: Star): void {
  star.x = (Math.random() * 2 - 1) * WIDTH;
  star.y = star.previousY = 8 + Math.random() * 4;
  star.speed = 2 + Math.random() * 2 + score * 0.05;
}

onStart(() => {
  setFixedRate(60);
  for (const star of stars) drop(star);
});

onAction((event) => {
  if (event.action === "start" && event.pressed && timeLeft === 0) {
    score = 0;
    timeLeft = ROUND;
    for (const star of stars) drop(star);
  }
});

onFixedUpdate((step) => {
  previousX = basketX;
  for (const star of stars) star.previousY = star.y;
  if (timeLeft === 0) return;
  // An action's value is 0 to 1, so a stick steers gently and a key fully.
  const steer = value("right") - value("left");
  basketX = Math.max(-WIDTH, Math.min(WIDTH, basketX + steer * 9 * step));
  for (const star of stars) {
    star.y -= star.speed * step;
    if (star.y < 0.6 && star.y > 0 && Math.abs(star.x - basketX) < 1.2) {
      score += 1;
      drop(star);
    } else if (star.y < -1) {
      drop(star);
    }
  }
  timeLeft = Math.max(0, timeLeft - step);
  if (timeLeft === 0 && score > best) {
    best = score;
    storage.setJson("best", best);
  }
});

// -- Drawing ------------------------------------------------------------------
onRender((alpha) => {
  // Between two fixed steps: draw where things are at this moment.
  basket.position.set(previousX + (basketX - previousX) * alpha, 0.2, 0);
  for (const star of stars) {
    star.mesh.position.set(star.x, star.previousY + (star.y - star.previousY) * alpha, 0);
  }
  hud();
});

function hud(): void {
  const { width, height, scale } = frame();
  const size = 22 * scale;
  const name = player()?.displayName ?? "Guest";
  draw.text(`${name}   score ${score}   best ${best}`, 16 * scale, 16 * scale, { size, color: "#e8ecf4" });
  if (timeLeft > 0) {
    draw.text(`${Math.ceil(timeLeft)} s`, width - 16 * scale, 16 * scale, { size, color: "#ffd34d", align: "end" });
  } else {
    draw.rect(0, height / 2 - 40 * scale, width, 80 * scale, [0, 0, 0, 0.5]);
    draw.text("Press Space to play", width / 2, height / 2 - 12 * scale, { size, color: "#ffffff", align: "center" });
  }
}

每个部分的作用：

  • 现场。 starhermit:scene 下面是三个.js：相机、灯光、由几何体组成的网格 和一种材料， scene.add。距离为米，角度为弧度，颜色为 sRGB。
  • 规则。 onFixedUpdate 以固定速率运行 setFixedRate(60) 要求，一次 60 次 其次，无论帧速率如何，因此游戏在每台机器上的播放效果都是相同的。 value("right") 是 动作的值从 0 到 1，因此游戏手柄摇杆会轻轻转向，按键会完全转向，并且 onAction 听到每一次按下，这里开始一轮。
  • 绘画。 onRender 每帧运行一次 alpha，最后两个帧之间的距离是多少 固定步骤；之间绘制的位置 previous 并且当前值在任何刷新时都会平滑移动 率。 starhermit:draw 在场景上以窗口像素绘制 HUD； frame().scale 皈依者 高 DPI 显示器的逻辑像素。
  • 最好成绩 保留在玩家的设备上 starhermit:storage，保持分开 每个玩家。

5.本地运行

starhermit check star-catcher

package=Directory files=3 bytes=6378 name="Star Catcher" api=1 entry=src/main.ts capabilities=platform,storage actions=left,right,start
left out: tsconfig.json (default rule tsconfig.json)
web=linked modules=2
runnable=true engine="TypeScript" frames=120 probes=0
PASS package src/main.ts: valid; 120 frames headless

check 验证包（清单、路径、大小）并在没有窗口的情况下播放 120 帧，因此 此处显示语法错误、未知导入或启动时的异常及其文件、行和列。 它打印了游戏的 console 继续输出（[game] log src/main.ts:12:5: text, 最多 1,000 线路； --quiet 隐藏它），失败的游戏会带来 "没有回应" 屏幕和链接 您的模块按照浏览器加载它们的方式进行，因此无法在浏览器中加载的游戏也会在这里失败 （见 本机和浏览器差异）。 然后播放：

starhermit star-catcher

按空格键开始一轮，然后按箭头键（或 A 和 D，或游戏手柄）进行转向。 F1 总是 打开运行时自己的菜单：图形、音频、控件（重新绑定）、帐户和退出。你的 游戏无法绘制或读取该菜单，并且没有游戏可以绑定 F1。

其图形页面提供自动和十个级别，从 quantum （一部电话）通过 atomic, molecular, cellular, terrestrial, planetary, stellar, galactic 和 cosmic 到 infinite （最快的桌面）。自动从 GPU 中选择一个，并首先进行一个简短的基准测试 时间，开始不高于 stellar 并在帧延迟时退出。你的游戏读取关卡 与 frame().level 及其预算 levelSettings() （主机 API 1.14，所以 engine.minor=14); frame().quality 仍然给 low, balanced, high 或者 ultra。设备无法运行的级别 （来自其 GPU 最大纹理大小；手机、平板电脑和 4 GiB 设备停止于 cellular) 显示 因故禁用，并且 frame().levelCeiling 给出最高的可能：一个游戏绘制自己的 图形菜单禁用其上方的级别（ui.select 选项采取 disabled 和 description).

开发时添加 --dev (starhermit star-catcher --dev): 然后运行时打印游戏的 console 以相同的形式输出并指出 TypeScript 行中的错误。

6.同时做很多事情： starhermit:world

原生地，你的游戏的 TypeScript 在引擎自己的脚本解释器中运行，这使得每个游戏 在其时间和内存预算内；在浏览器中，它在浏览器的 JavaScript 引擎中运行 页面可以停止。决策和几十个对象的成本很低，但每个实体的成本却很低 工作——移动数千个粒子、一群人、一群——意味着数千个被解释的步骤 每一帧。为此，发动机具有 starhermit:world:

  • 桌子 将实体数据保存在游戏内存中的类型列（数字和向量）中；
  • 内核 是运行时编译并本机运行的一行的普通函数 表格的每一行，无需输入脚本；
  • 这 日程 每帧运行内核，并且 绑定 将表格绘制为一个整体 InstancedMesh （或驱动场景节点），本地组合每个实例。

你的脚本做出决定；运行时执行每行算术。添加 4,000 的夜空 游戏背后闪烁着光芒 src/sky.ts:

// The night sky behind the game: 4,000 twinkling sparkles. Their data lives
// in a starhermit:world table, a kernel moves every one of them natively each
// frame, and an instance binding draws the table as one InstancedMesh, so the
// game's script runs no per-sparkle code at all.
import { InstancedMesh, MeshBasicMaterial, SphereGeometry, scene } from "starhermit:scene";
import { bind, kernel, schedule, table } from "starhermit:world";

const COUNT = 4_000;

// One row per sparkle: where it hangs, how it twinkles, and what the kernel
// writes each frame (its height and size).
const sky = table("sky", COUNT, {
  base: "vec3",
  phase: "f32",
  rate: "f32",
  y: "f32",
  size: "f32",
});
sky.spawn(COUNT);

// Filled once from script, through typed arrays over the table's memory.
const base = sky.column("base");
const phase = sky.column("phase");
const rate = sky.column("rate");
for (let i = 0; i < COUNT; i++) {
  base[i * 3] = (Math.random() * 2 - 1) * 40;
  base[i * 3 + 1] = Math.random() * 24 - 2;
  base[i * 3 + 2] = -10 - Math.random() * 30;
  phase[i] = Math.random() * Math.PI * 2;
  rate[i] = 0.5 + Math.random() * 2;
}

// An ordinary function of one row. The runtime compiles it and runs it over
// every live row without entering script.
const twinkle = kernel(sky, (r, u: { drift: number }, f) => {
  r.y = r.base.y + Math.sin(f.time * u.drift + r.phase) * 0.3;
  r.size = 0.04 + 0.04 * Math.abs(Math.sin(f.time * r.rate + r.phase));
});

const mesh = new InstancedMesh(new SphereGeometry(1, 6, 4), new MeshBasicMaterial({ color: 0xcfd8ff }), COUNT);
scene.add(mesh);

/** Starts the sky: the kernel runs after every onUpdate, and the binding
 * composes the mesh's instances from the columns after every onRender. */
export function startSky(): void {
  schedule.update(twinkle, { drift: 0.4 });
  bind.instances(mesh, sky, { position: ["base.x", "y", "base.z"], scale: "size" });
}

并从开始 src/main.ts：将其与其他导入一起导入，然后调用它 onStart:

import { startSky } from "./sky.js";

onStart(() => {
  setFixedRate(60);
  startSky();
  for (const star of stars) drop(star);
});

导入名称 ./sky.js，TypeScript 的模块约定写为 sky.ts;运行时 以同样的方式解决它。内核接受语言的子集——数字和布尔值、算术、 Math, if, 有界 for 循环、行的列和您传递的制服 - 以及运行时 拒绝任何其他带有 SyntaxError 在编译内核时，而不是 慢慢地运行它。的声明 starhermit:world 描述事件队列的子集 内核发送到具有平滑固定步运动历史记录的表和节点绑定。

7. 玩家、保存和在线游戏

本机和浏览器差异

本地代码在引擎的解释器中运行，在浏览器的 JavaScript 引擎中运行 （Chrome 和 Edge 中的 V8）。两者都是严格的 ECMAScript 2022，包括 BigInt，并且 starhermit check 本地运行游戏 和 当浏览器获取它们时链接其模块。还有什么不同：

  • 相互导入的模块。 在浏览器中，在其模块运行之前读取的导入是 undefined; check 在模块的顶级代码中进行此类读取失败（在函数内部读取它） 相反）。 export * from 这样一个循环的一个模块失败 check：命名出口。一个 let 从循环的模块再次导出是浏览器中的副本，因此看不到后面的分配 通过它：从它自己的模块导入它。
  • 加载中。 import() 需要一个字符串文字（check 在计算说明符上失败）。
  • 来自字符串的代码。 eval 本机加载失败； new Function(...) 抛出一个 EvalError 上 两者都有。
  • 经典脚本。 一个文件 starhermit:script 作为经典脚本运行（loadClassic, sandbox, authority, worker）没有 "use strict" 指令，在类之外，遵循浏览器中的草率模式 在平台上：分配一个未声明的名称会创建一个全局名称（读取仍然会抛出异常）； this 在一个 没有调用的函数是 globalThis 和一个原始的 this 是盒装的； delete name 答案 true 或者 false;函数可以重复参数名称（不是箭头或方法）； arguments.callee 是 功能；失败的分配将被忽略并被拒绝 delete 是 false。本质上仍然严格：遗留 八进制（010, "\07"） 和 with 加载失败，块中声明的函数仅在该块中可见 块，并且 arguments 不跟随对参数的写入（也不跟随对参数的写入）。此类文件开头为 "use strict" 到处都表现得一样。
  • 只有浏览器内置: Proxy, WeakRef, FinalizationRegistry, Atomics, structuredClone，迭代器助手， Array.fromAsync，新的 Set 方法、工人的 全局变量（self, crypto, atob, URL, WebAssembly，...）和一些 Intl (ListFormat, Segmenter, DisplayNames, Locale). check 每次使用其文件和行时都会发出警告； typeof 测试没问题。
  • 正则表达式。 这 v 旗帜和遗产 RegExp.$1 静态仅适用于浏览器。
  • 日期。 本机本地时间是 UTC (getTimezoneOffset() 是 0);浏览器使用玩家的时间 区。设置挂钟时间的格式 timeZone: "UTC" 在两者上显示相同的内容。
  • 限制。 本质上，一个字符串最多包含 2 个28 − 16 个代码单元，一个数组 226 元素和 BigInt 220 位（浏览器中更多）；堆栈溢出本身会结束游戏而不是 比扔一个可接住的东西 RangeError. Math.random 顺序不同。
  • 音频开始。 在浏览器中，音频等待玩家第一次按下：直到那时 context.state 是 "suspended" 和 currentTime 静止不动，那么就是 "running" 和 statechange 火灾。本来就是 "running" 从一开始。
  • 浏览器默认。 游戏运行时，其页面保留浏览器的右键菜单、文本 选择、复制和粘贴、拖放文件和快捷键，例如 Ctrl+S、Ctrl+F、缩放和菜单 酒吧的 Alt 来自游戏，并且游戏绑定的键也可以通过 Ctrl、Alt 或 Cmd 到达它。 F11、F12、 重新加载，浏览器的 Tab 键仍然有效，并且文本字段保持粘贴状态。
  • 结束。 onQuit 在正在进行的帧之后运行一次（以及之后 onSuspend 如果窗户 或选项卡首先被隐藏）。它写的是什么 storage 和 settings 被保留，并且其 saves.save，帐户的设置副本及其平台调用会随着游戏关闭而消失 （他们的答案无人知晓）。它本身有第二个，并且最多可以上传三个；在 浏览器中，页面消失（关闭选项卡、重新加载、随后出现链接）会等待 0.2 秒，对于具有以下功能的游戏 的 storage 功能或登录玩家，最多发送 16 个请求，大小为 64 KiB 主体全部：较大的保存在下一个会话中上传。 Safari 在页面听到游戏即将消失之前停止游戏，因此 onQuit 不在关闭的选项卡或点击的链接上运行：保留更改时必须最后保存的内容，或者在 onSuspend。浏览器从其后退/前进缓存返回的页面再次加载，并且游戏 从它存储的内容重新开始。
  • 主机 API 值。 没有主机 API 采用 BigInt，并且 JSON.stringify 拒绝一个（TypeError）： 转换为 Number(x) 或者 String(x) 在保存或传递之前。
