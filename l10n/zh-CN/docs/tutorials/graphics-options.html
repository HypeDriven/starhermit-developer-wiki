教程：具有自动检测质量的图形选项

给你的浏览器游戏一个 图形 为玩家的机器选择合理的质量级别的菜单 首次启动时，让他们覆盖它，并通过 StarHermit 跨设备记住他们的选择。

对于相应的音频部分，请参见 具有自动检测声音限制的音频选项。 有关语言部分，请参阅 本地化您的游戏并添加语言设置.

graphics-options.js 是一个单一的 ES 模块，没有依赖关系，即 处理簿记：

  • 汽车 在硬件级别对 GPU 进行评分，从 0（三星 Galaxy S20 或更弱）到 20（三星 Galaxy S20 或更弱） RTX 5090），从该级别、内存、CPU 核心中选择四种预设之一（低、平衡、高、超） 和设备类型，如果帧保持缓慢，则降低会话速度。
  • 玩家可以覆盖每个效果（阴影、环境光遮挡、光晕、抗锯齿或您自己的效果）， 设置 50–200% 渲染比例，选择手动最大 FPS 而不是自动显示刷新 （手机和平板电脑刷新率的一半），并切换自适应分辨率和帧速率读数。
  • 设置保存到 localStorage 所以它们在第一帧之前应用，并应用于玩家的 每个游戏的设置 所以他们会跟随玩家到他们的 其他机器。
  • 它包括一个由相同质量的表格构建的现成选项面板。

它不进口发动机。您的渲染器侦听更改并应用层。该页面将其连接到 三.js。其他引擎使用相同的钩子（参见 其他发动机).

1.添加文件

复制 starhermit-sdk.js 和 graphics-options.js 位于游戏脚本旁边，未更改。称呼 StarHermit.init() 前 您的模块运行，因此启动令牌已被读取 图形存储检查玩家是否已登录：

<script src="starhermit-sdk.js"></script>
<script>StarHermit.init();</script>
<script type="module" src="main.js"></script>

如果没有启动令牌（本地开发、任何其他主机），商店会将所有内容保留在其中 localStorage 并且不提出任何要求。

2. 创建商店和面板

import { createGraphics, mountGraphicsPanel } from './graphics-options.js';

const gfx = createGraphics({ storageKey: 'mygame.graphics' });
mountGraphicsPanel(document.getElementById('graphics-options'), gfx);

mountGraphicsPanel 用控件填充元素。您的设置对话框提供框架、 标题和关闭按钮。每项更改都会立即应用并保存。

如何自动选择预设

游戏运行时，Auto 还会监视帧时间。如果自适应分辨率已经下降到其 对于另外三个 90 帧窗口，地板和帧的平均时间仍超过 26 毫秒，自动降低一个预设 会议剩余时间。选择 汽车 在面板中再次重新检测。预设播放器 手工采摘不会自行改变。

最大帧率

最大帧率 默认为 自动（刷新率）：浏览器安排渲染 与显示器的刷新率。在手机或平板电脑上，默认值为 自动（半刷新率） 相反，它会每秒渲染一次显示刷新（60 Hz 时为 30 FPS，120 Hz 时为 60 FPS）以限制热量 和电池耗尽。浏览器不会报告刷新率，因此商店根据间距来测量刷新率 动画回调；它们到达的频率低于 50 Hz（例如，浏览器在 低功耗模式），每个回调都会渲染。

选择 风俗 并输入一个整数 1 至 1000 FPS 覆盖任一默认值；在电话上， 输入全速率渲染的显示器刷新率。限制立即应用并保存 本地和与其他图形设置相同的云配置文件，并在质量预设中生存 变化。返回 汽车 删除限制。这个选择独立于 汽车 质量预设。

渲染器必须调用 gfx.shouldRender(now) 在其动画循环中，如下所示。极限是一个 上限，不是承诺的帧速率：渲染仍然不能超过浏览器的动画回调 或机器的性能。因此，在 60 Hz 显示器上设置 144 FPS 仍最多渲染 60 FPS。

对于自定义菜单，请使用 gfx.set({ maxFps: 45 }) 和 gfx.set({ maxFps: null }) 恢复自动。 已解决 gfx.settings.maxFps 是 0 对于汽车，以及 gfx.settings.halfRefresh 是 true 当自动为 以刷新率的一半进行调整。无效的保存值将回退为“自动”；正数四舍五入 并固定在 1-1000。

设置所在的位置

店铺 钥匙 为什么
localStorage <storageKey>.gpu.<GPU profile> 同步读取，因此第一帧已经使用该 GPU 的设置
每个玩家的设置 graphics.gpu.<GPU profile> 跟随玩家到另一台报告相同 GPU 的机器

每个 GPU 都有一个独立的配置文件，涵盖每个图形选择，包括最大 FPS。 例如，在 GPU A 上设置 Ultra 和 90 FPS，然后在 GPU B 上启动：B 以硬件检测到的方式启动 除非您之前保存了 B 的选择，否则将使用默认值。返回 A 将恢复 Ultra 和 90 FPS。 两个均检测为“高”的 GPU 仍具有单独的配置文件。检测到的质量发生变化 同一 GPU 上的层不会丢弃其保存的选择。

该配置文件是浏览器报告的 GPU 名称的稳定的 16 个字符的哈希值，针对大小写进行了规范化 和空白。 storageKey 和 cloudKey 提供前缀； gfx.storageKey, gfx.cloudSlot， 和 gfx.gpuProfile 公开活动密钥和配置文件。 GPU 检测在创建存储时发生； 在下一次游戏启动时创建一个新商店以选择另一个 GPU 的配置文件。

如果没有可用的 GPU 名称，则选择适用于没有本地或云持久性的会话。 如果浏览器屏蔽多个具有相同名称的 GPU，它们会共享一个配置文件，因为它无法 区分它们。旧的无范围本地设置和设备级云设置保持不变 且不会被导入，因为它们无法识别选项属于哪个 GPU。

每个值是 { "saved": {…}, "at": <ms timestamp> }。两个副本的核对方式与 云保存:

  • 先读再写。 在启动时（以及当不同的玩家登录时），商店会读取 GET /api/v1/games/{slug}/settings。较新的副本 at 获胜。如果云副本获胜， 商店采用它并触发 change 合理 'cloud'。如果本地副本较新，则商店 推动它。
  • 读取失败会阻止写入。 本地副本继续工作。玩家做出的下一个改变 在写入任何内容之前重试读取，因此过时的设备无法覆盖较新的选择 看不到。
  • 更改是通过 setSetting 800 毫秒后没有进一步的变化。令牌更新（其中 也触发 SDK 的 auth 事件）不会触发另一次读取。

3. 将设置应用到渲染器

四个钩子将商店连接到 Three.js 渲染器：

  • gfx.on('change', fn) 用于阴影和效果切换。
  • 从当前层重建的后处理链。
  • gfx.frame(ms) 和 gfx.pixelRatio() 在渲染循环中，驱动自适应分辨率。
  • gfx.shouldRender(now) 在绘制之前，这会强制执行手动 FPS 限制和半刷新节奏。

创建渲染器 antialias: false。然后 MSAA 来自后期链的渲染目标，因此 每个抗锯齿层都可以切换，而无需重新创建 WebGL 上下文。

import * as THREE from 'three';
import { EffectComposer } from 'three/addons/postprocessing/EffectComposer.js';
import { RenderPass } from 'three/addons/postprocessing/RenderPass.js';
import { GTAOPass } from 'three/addons/postprocessing/GTAOPass.js';
import { UnrealBloomPass } from 'three/addons/postprocessing/UnrealBloomPass.js';
import { OutputPass } from 'three/addons/postprocessing/OutputPass.js';
import { SMAAPass } from 'three/addons/postprocessing/SMAAPass.js';
import { ShaderPass } from 'three/addons/postprocessing/ShaderPass.js';
import { FXAAShader } from 'three/addons/shaders/FXAAShader.js';

// canvas, scene, camera and a shadow-casting DirectionalLight `sun` are your game's own.
const renderer = new THREE.WebGLRenderer({ canvas, antialias: false });
renderer.toneMapping = THREE.ACESFilmicToneMapping;

const SHADOW_MAP = { off: 0, low: 1024, medium: 2048, high: 4096 };
let composer = null;
let size = {};

gfx.on('change', (s) => {
  const mapSize = SHADOW_MAP[s.shadows];
  renderer.shadowMap.enabled = mapSize > 0;
  sun.castShadow = mapSize > 0;
  if (mapSize && sun.shadow.mapSize.x !== mapSize) {
    sun.shadow.mapSize.set(mapSize, mapSize);
    sun.shadow.map?.dispose();
    sun.shadow.map = null;
  }
  scene.traverse((o) => [].concat(o.material || []).forEach((m) => { m.needsUpdate = true; })); // shadow on/off recompiles
  size = {}; // resize and rebuild the post chain on the next frame
});

function buildPost(s, w, h, ratio) {
  composer?.dispose();
  composer = null;
  if (gfx.info.postFailed || (s.ao === 'off' && s.bloom === 'off' && s.antialias === 'off')) return;
  try {
    const pw = Math.round(w * ratio), ph = Math.round(h * ratio);
    const target = new THREE.WebGLRenderTarget(pw, ph, { type: THREE.HalfFloatType, samples: s.antialias === 'msaa' ? 4 : 0 });
    const c = new EffectComposer(renderer, target);
    c.setPixelRatio(ratio);
    c.setSize(w, h);
    c.addPass(new RenderPass(scene, camera));
    if (s.ao !== 'off') {
      const ao = new GTAOPass(scene, camera, pw, ph);
      ao.updateGtaoMaterial({ samples: s.ao === 'high' ? 16 : 8 });
      c.addPass(ao);
    }
    if (s.bloom === 'on') c.addPass(new UnrealBloomPass(new THREE.Vector2(w, h), 0.5, 0.4, 0.9));
    c.addPass(new OutputPass());
    if (s.antialias === 'smaa') c.addPass(new SMAAPass());
    if (s.antialias === 'fxaa') {
      const fxaa = new ShaderPass(FXAAShader);
      fxaa.material.uniforms.resolution.value.set(1 / pw, 1 / ph);
      c.addPass(fxaa);
    }
    composer = c;
  } catch {
    gfx.report({ postFailed: true }); // the panel shows a note; don't console.warn
  }
}

let last = performance.now();
renderer.setAnimationLoop((now) => {
  // Update your simulation here using its own elapsed time or fixed timestep.
  // Keep simulation/input independent of skipped render ticks.
  if (!gfx.shouldRender(now)) return;
  gfx.frame(now - last); // elapsed time between rendered frames, including the FPS limit
  last = now;
  const w = canvas.clientWidth, h = canvas.clientHeight, ratio = gfx.pixelRatio();
  if (w !== size.w || h !== size.h || ratio !== size.ratio) {
    size = { w, h, ratio };
    renderer.setPixelRatio(ratio);
    renderer.setSize(w, h, false);
    camera.aspect = w / h;
    camera.updateProjectionMatrix();
    buildPost(gfx.settings, w, h, ratio);
    gfx.report({ pixels: [Math.round(w * ratio), Math.round(h * ratio)] });
  }
  try {
    if (composer) composer.render();
    else renderer.render(scene, camera);
  } catch {
    composer = null;
    gfx.report({ postFailed: true });
  }
});

笔记：

  • 这 three/addons/ 文件必须来自 相同的 Three.js 版本 作为 three 本身。混合 发布打破了帖子链。上面的代码针对当前版本。对于年纪较大的人来说， SMAAPass 需要 (width, height).
  • 低会关闭所有后处理效果，因此游戏会以一定的速度直接渲染到画布上 设备像素比最多为 1。这使得 Low 与之前的游戏一样便宜。
  • gfx.pixelRatio() 回报 min(devicePixelRatio, preset cap) × preset scale × render scale × adaptive scale，钳位至 0.25–3。上限为 1 表示低，1.5 表示平衡，2 表示高和 超。
  • 自适应分辨率平均为 90 帧。超过 26 毫秒，它将比例降低 0.1（降至 0.6）。下面 14 毫秒，它将比例提高 0.05（最多 1）。超过 1 秒的帧（暂停或背景选项卡） 被忽略，单个慢帧最多算作 250 毫秒的适应时间，因此一个故障无法降低 规模。 FPS 读数使用实际经过的时间。 通过手动限制或半刷新节奏，慢速阈值至少为目标帧的 115% 间隔和快速阈值至少为 85%，因此故意设置 30 FPS 限制本身并不会降低质量。 对于非常低的限制，暂停截止和挂钩截止都至少是两个目标间隔。 喂养 gfx.frame 仅渲染帧；当跳过一个刻度时保留最后渲染的时间戳。

其他发动机

无论绘制您的框架，集成都使用相同的钩子：

称呼 使用
gfx.on('change', (settings, reason) => …) 应用等级。立即运行一次（'init'），然后 'settings', 'cloud' 和 'auto'。返回取消订阅函数。
gfx.settings { preset, auto, scale, dprCap, adaptive, showFps, maxFps, halfRefresh, <category>: <tier> }; maxFps: 0 表示自动显示刷新，当 halfRefresh 是 true.
gfx.level 检测到的硬件级别 0–20，用于调整您自己的预算（粒子计数、绘制距离）。当 Auto 退出时，它不会改变。
gfx.shouldRender(now) 每个动画回调，其时间戳以毫秒为单位。如果返回则跳过绘制 false。保持模拟/输入更新独立。
gfx.frame(ms) 每个渲染帧，以及自上一个渲染帧以来的时间。退货 true 当像素比或自动预设更改时。
gfx.pixelRatio() 渲染比例
gfx.report({ pixels, postFailed }) 告诉面板输出大小，或者效果不可用

对于 2D 画布游戏，请将画布背景尺寸乘以 gfx.pixelRatio()，并映射您自己的 效果（粒子、发光、视差层）按如下所述分类。

4. 使其适合您的游戏

你自己的效果。 通过一个质量表，其中仅列出您的游戏实际绘制的内容。每个预设 row 需要每个类别都有一个层级，另外 scale 和 dprCap:

import { createGraphics, CATEGORIES, TABLE } from './graphics-options.js';

const gfx = createGraphics({
  storageKey: 'mygame.graphics',
  categories: { ...CATEGORIES, particles: ['off', 'low', 'high'] },
  table: {
    low: { ...TABLE.low, particles: 'off' },
    balanced: { ...TABLE.balanced, particles: 'low' },
    high: { ...TABLE.high, particles: 'high' },
    ultra: { ...TABLE.ultra, particles: 'high' },
  },
});

该面板为每个类别构建一个选择，因此会自动出现一个新类别。将其命名为 strings.categories.particles.

您自己的预设。 预设具有其他名称的表也需要 levels：每个预设的最低值 硬件级别。自动选择最高起始级别等于或低于的预设 gfx.level:

const gfx = createGraphics({
  table: { fast: { ...TABLE.low }, standard: { ...TABLE.balanced }, cinematic: { ...TABLE.ultra } },
  levels: { fast: 0, standard: 6, cinematic: 15 },
});

翻译。 面板的英文字符串导出为 STRINGS。用同样的方式传递你自己的 形状。仅替换您提供的密钥：

mountGraphicsPanel(el, gfx, {

造型。 面板使用类 .gfx-panel, .gfx-row, .gfx-summary 和 .gfx-note。其 内置规则包含在 :where()，因此您自己的样式表中的任何规则都会覆盖它们。行是 触摸高度至少为 44 像素。帧速率读数（#gfx-fps）位于左下角， 在安全区域内，并且不捕获点击。

在别处阅读结果。 <html> 携带 data-gfx-preset （活动预设）和 data-gfx-auto (1 或者 0），CSS 和测试可以关闭。

5. 测试一下

  • 无头浏览器使用软件 GPU 进行渲染，因此自动解析为级别 0 (低的）并且测试保持快速。
  • 驱动真正的面板。每个控件都有一个 data-gfx 属性 （preset, renderScale, adaptive, frameRate, maxFps, showFps，或类别名称）：
const preset = () => page.evaluate(() => document.documentElement.dataset.gfxPreset);
await page.locator('select[data-gfx=preset]').selectOption('high');
assert.equal(await preset(), 'high');
await page.reload();
assert.equal(await preset(), 'high'); // persisted
await page.locator('select[data-gfx=frameRate]').selectOption('custom');
await page.locator('input[data-gfx=maxFps]').fill('45');
await page.locator('input[data-gfx=maxFps]').press('Tab');
await page.reload();
assert.equal(await page.locator('input[data-gfx=maxFps]').inputValue(), '45');
await page.locator('select[data-gfx=frameRate]').selectOption('auto');
  • 纯函数 detectLevel(system), presetForLevel(level, levels), detectPreset(system), resolve(saved, detected, { mobile }) 和 withPreset(saved, preset) 在 Node 下运行进行单元测试。 createGraphics({ sdk, storage, system }) 也接受这三者的假货；通过一个 system 与一个 电话的 gpu 和 mobile: true 测试移动默认设置。
