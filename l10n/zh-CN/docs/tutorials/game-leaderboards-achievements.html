教程：游戏的排行榜和成就

如果您在 StarHermit 上拥有一款游戏，那么您就是该游戏的发行商。你可以给它 排行榜 （高分， 跑得最快、连续跑得最长）和 成就 没有发布商帐户或任何特殊 许可。拥有游戏就足够了。

此页面上的所有内容背后都有一条规则： 你定义它们，你的游戏服务器写入 他们。 玩家的客户端永远不能发布分数或声称获得这些成就，并且您的服务器必须验证赢得这些分数的游戏玩法。拒绝直接API提交 仅凭这一点并不能阻止修改后的客户端发明游戏事件。这就是为什么游戏需要一个权威的后端： server= 脚本或 container.image= 在 starhermit.txt.

本教程为小型街机游戏构建， 明星收藏家：当玩家 崩溃，并且有总分和运行时间。

  2. 创建排行榜

开始之前

您需要：

  • 带有服务器后端的游戏 您拥有的：您从自己的存储库添加的、上传的 作为文件夹，或者 声称。仅限浏览器的游戏答案 409 每一个电话 下面有一条消息说明原因。
  • 完整的用户访问令牌，而不是游戏的启动令牌。启动代币被隔离到游戏的 玩家表面且无法到达 /me/....
  • 您的游戏 ID （这也是它的 <id>.starhermit.com 地址）：
ACCESS_TOKEN='your-full-user-access-token'
API=https://api.starhermit.com

curl -s "$API/api/v1/me/github-games" -H "Authorization: Bearer $ACCESS_TOKEN" |
  jq '.[] | {id, displayName, gameSlug}'

GAME_ID='the-id-from-above'

gameSlug 是你的客户对游戏的称呼 /api/v1/games/{slug}/...。您添加的每个游戏 或上传包含一个仅限浏览器的游戏，因此它不会告诉您是否有服务器： GET /api/v1/games/{slug} 确实——它回答了 404 直到游戏有了后端。

1. 创建排行榜

明星收藏家获得两个板：最高分（越高越好）和最快达到 100 分（越低） 更好）。

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/leaderboards" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "high-score", "name": "High score",
        "scoreType": "integer", "sortDirection": "desc",
        "minScore": 0, "maxScore": 1000000 }'

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/leaderboards" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "fastest-100", "name": "Fastest to 100",
        "scoreType": "time-ms", "sortDirection": "asc" }'

每次调用都会返回 201 和董事会，包括其 id 和 key。您的服务器使用 钥匙, 所以要仔细选择。关键， scoreType 和 sortDirection 以后无法更改。

scoreType 接受
integer 整数
decimal 任意数量
time-ms 整数、非负毫秒

放 minScore/maxScore 您的游戏实际可以产生什么。在他们之外的分数被丢弃， 这是针对您自己的服务器逻辑中的错误的廉价防护措施。

2、创造业绩

您可以通过两种方式赋予游戏成就，并且可以同时使用这两种方式：

在代码中声明 通过API创建
在哪里 game.achievements 在你的脚本中，或者 /describe 在你的容器中 POST /me/github-games/{id}/achievements
更改者 发布更新 API调用，立即生效
适合 您的代码所围绕的成就 在没有发布的情况下添加或重写一些内容

两种解锁方式相同，由服务器返回密钥。这里我们创建两个通过 API：

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "century", "name": "Century",
        "description": "Collect 100 stars in one run.", "points": 10 }'

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "untouchable", "name": "Untouchable",
        "description": "Reach 500 points without losing a shield.",
        "points": 50, "secret": true }'

A secret 成就对玩家来说是隐藏的，直到他们解锁为止。

要查看游戏拥有的所有内容，包括代码声明的成就，请列出它们：

curl -s "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" | jq '.[] | {key, origin, unlocks}'

origin 是 declared 从您的代码中取得的成就以及 owner 为了你创造的成就 在这里。您只能编辑和删除 owner 那些。一个 declared 一个会被你的下一个放回去 更新，因此 API 拒绝（409），然后您在代码中更改它。

3. 发布分数并从脚本中解锁成就

您的脚本在其返回值中报告这两种结果。它可以从任何钩子执行此操作： createSession, onPlayerMessage 或者 onTick.

  • scores：棋盘钥匙→玩家ID→号码。
  • achievements：玩家 ID → 解锁钥匙。
'use strict';

function endRun(ctx, s, playerId) {
  var run = s.runs[playerId];
  var scores = { "high-score": {} };
  scores["high-score"][playerId] = run.points;
  if (run.reached100At) {
    scores["fastest-100"] = {};
    scores["fastest-100"][playerId] = run.reached100At - run.startedAt;
  }

  var unlocked = [];
  if (run.stars >= 100) unlocked.push("century");
  if (run.points >= 500 && !run.lostShield) unlocked.push("untouchable");
  var achievements = {};
  achievements[playerId] = unlocked;

  run.over = true;
  return {
    ok: true,
    sessionState: s,
    scores: scores,
    achievements: achievements,
    broadcast: [{ to: [playerId], data: { type: "run-over", points: run.points } }]
  };
}

globalThis.game = {
  tickRateHz: 10,

  createSession(ctx) {
    var runs = {};
    ctx.players.forEach(function (p) {
      runs[p.id] = { points: 0, stars: 0, lostShield: false, startedAt: ctx.now,
                     reached100At: null, over: false };
    });
    return { ok: true, sessionState: { runs: runs } };
  },

  onPlayerMessage(ctx) {
    var s = ctx.sessionState;
    var from = ctx.message.from;
    var run = s.runs[from];
    var msg = ctx.message.data || {};
    if (!run || run.over) return { ok: false, error: "No run in progress" };

    // The client reports what happened; the script decides what it is worth.
    if (msg.type === "collect") {
      run.stars += 1;
      run.points += 5;
      if (run.points >= 100 && !run.reached100At) run.reached100At = ctx.now;
      return { ok: true, sessionState: s };
    }
    if (msg.type === "shield-lost") {
      run.lostShield = true;
      return { ok: true, sessionState: s };
    }
    if (msg.type === "crash") return endRun(ctx, s, from);
    return { ok: false, error: "Unknown command" };
  },

  onTick(ctx) { return { ok: true }; }
};

你做的事情 不是 需要处理：

  • 成绩更差。 每个玩家都在每个棋盘上保留自己的最佳成绩，并根据棋盘的得分来判断 sortDirection。报告每次跑步，平台保持最佳成绩。
  • 重复解锁。 解锁玩家已经拥有的东西没有任何作用，所以归还钥匙 每当条件成立时。
  • 别人的id。 为不在会话中的人（包括人工智能）评分和解锁 座位，被忽略。

未知的按键、不活动的棋盘和超出范围的分数都会被悄悄丢弃。你的脚本没有得到 他们的错误，所以检查你的董事会一次，如 第4节.

真正的游戏应该让服务器根据自己的权威状态计算出分数和时间，而不是 信任 collect 消息原样。该示例保持简短以显示报告。 游戏脚本 具有完整的回报形状合同。

3b.与容器相同

容器游戏在其控件 WebSocket 上发送相同的两个内容：

{ "type": "scores", "sessionId": "…",
  "scores": { "high-score": { "<userId>": 740 }, "fastest-100": { "<userId>": 41250 } } }

{ "type": "achievements", "sessionId": "…",
  "unlocks": { "<userId>": ["century"] } }

scores 也可以包含在您的容器返回的任何响应信封中 /sessions。的 相同的规则适用：仅限参与者，保留最佳成绩，忽略未知键。看 容器游戏服务器.

4. 在你的游戏中展示它们

您的客户端使用其已持有的启动令牌读取所有内容。这里没有什么需要 所有者的令牌。

找到木板。

const boards = await api(`/api/v1/games/${slug}/leaderboards`);
// [{ id, key: "high-score", name: "High score", sortDirection: "desc", ... }, ...]
const high = boards.find(b => b.key === "high-score");

仅列出活动板。

读一块板子。

const page = await api(`/api/v1/leaderboards/${high.id}/entries?page=1&pageSize=10`);
// { items: [{ rank, username, score, ... }], total, page, pageSize }
const friends = await api(`/api/v1/leaderboards/${high.id}/entries?friendsOnly=true&pageSize=10`);

对于一个 time-ms board，将分数格式化为时间： 41250 → 0:41.25.

成就。

  • GET /api/v1/games/{slug}/achievements 列出玩家的每项成就 unlocked 状态。秘密会被隐藏起来，直到它们被获得为止。
  • 解锁本身已上线 ws/v1/games 作为 {"type":"achievement","data":{key,name,description,points,...}}。当它出现时，请举杯。 加载时的列表调用捕获套接字关闭时未锁定的任何内容。

看 成就 为了 框架。

5. 照顾他们

重命名板或更改其边界。

curl -s -X PUT "$API/api/v1/me/github-games/$GAME_ID/leaderboards/$BOARD_ID" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "name": "All-time high score", "maxScore": 2000000 }'

新界限仅适用于新分数。

退出董事会但保留其分数。 发送 { "isActive": false }。董事会停止受理 得分并从游戏列表中消失。它的条目仍然可以通过 id 读取。

按计划重置。 给个板子 "resetSchedule": "daily", "weekly" 或者 "monthly" （在 创建，或稍后使用 PUT）并且每个周期在 00:00 UTC 开始 — 非常适合 "这个 本周最佳" 董事会旁边是历史上最伟大的董事会。在您的脚本中无需执行任何操作：照常报告分数，并且 每个玩家在新时期的第一个得分都算在内。看 重置时间表.

手工开启新的季节。 对于一次性赛季而不是时间表，创建一个新董事会 （high-score-s2），将你的脚本指向它，然后淘汰旧的脚本。

删除一块板子。 DELETE .../leaderboards/{id} 删除棋盘及其所有条目，并且 无法撤消。

编辑成就。 PUT .../achievements/{achievementId} 与任何一个 name, description, icon, secret 和 points。钥匙永远不会改变。

删除成就。 这仅适用于您创建的尚未解锁的人。 获得的成就是永久的。

将成就转移到代码中。 声明相同的键 game.achievements 并发布。的 声明接管现有成就，拥有该成就的玩家保留该成就。

回复 意义
404 该游戏不是您的，或者棋盘或成就不属于它
409 "...服务器后端..." 游戏没有 server= 或者 container.image=
409 "已经有……" 关键是由董事会或已宣布或创造的成就获得
409 "由游戏服务器声明" 更改代码中的成就
409 "已经解锁" 玩家持有它，因此无法删除
400 带有其他字符的键、缺少名称或 minScore > maxScore

限制：每场比赛有 2048 个排行榜和 200 个创建的成就，加上最多 100 个已声明的成就。

清单

  • [ ] 游戏中有一个 server= 脚本或 container.image=， 和 gameSlug 设置于 GET /me/github-games.
  • [ ] 每块板都有一个稳定的密钥和正确的 scoreType 和 sortDirection （以后不能更改）。
  • [ ] 服务器返回 scores 和 achievements （脚本）或发送控制消息（容器），由权威状态制定。
  • [ ] 客户端找到带有以下内容的板 GET /games/{slug}/leaderboards，从不硬编码它们的 id，并通过 id 读取条目。
  • [ ] 客户端加载 GET /games/{slug}/achievements 并在上面祝酒 achievement 框架。
  • [ ] 旧板已退役 isActive: false 而不是删除，除非你真的希望分数消失。
