JavaScript SDK（浏览器游戏）

starhermit-sdk.js 是一个单文件、无依赖的浏览器游戏客户端 发表在《星隐者》上。它读取启动令牌，保持更新，并为常见问题提供帮助。 游戏范围的启动令牌 API：身份、云保存、每个玩家的设置和控制， 邀请、配对、会话和游戏套接字、成就、排行榜、重播、聊天、 语音和实时房间。
文件 docs/sdk/starhermit-sdk.js — 将其原封不动地复制到您的游戏中
全球的 window.StarHermit （还 module.exports 在 Node 下，用于测试）
依赖关系 无 — 它使用浏览器自己的 fetch, WebSocket 和（读取压缩保存） DecompressionStream
API基线 REST v1 和 WebSocket v1，仅启动令牌表面

SDK 是一个客户端，而不是平台的第二个实现。分数和成就解锁 仅由游戏服务器写入（脚本结果或容器控制消息）-客户端 永远不能发布它们，并且 SDK 只能读取它们。其他一切都保持服务器权威 完全按照记录 API页面.

如果没有启动令牌，经过身份验证的助手不会发出 API 请求。 阅读一般可以解决 到 null, []，或一张空地图；写入可能会解决 null/false 并且去抖动保存不会立即生效 返回值。套接字保持断开状态。如果玩家选择，则在内存中保留独立进度 未跟踪的播放。称呼 signOut() 在从帐户游戏切换到该模式之前，更新会停止。

安装

将文件复制到游戏的其他静态脚本旁边（无论您的构建将其运送到何处）并加载 它位于您自己的代码之前：

<script src="starhermit-sdk.js"></script>
<script>
  StarHermit.init();          // as early as possible: it reads and strips the token from the URL fragment
</script>

称呼 init() 在任何路由器接触之前一次 location.hash。选项： init({ base, gameId, autoRefresh, launcherUrl }) — base 将 REST 调用指向授权来源 在本地开发期间（平台托管的游戏使用同源）。 gameId，如果提供，必须匹配 用于登录的托管 UUID；本地/外部页面不是有效的游戏登录返回源。 autoRefresh: false 将代币更新留给游戏 经营自己的连锁店，并且 launcherUrl 覆盖哪里 relaunch() 发送玩家（默认 https://dashboard.starhermit.com/).

云存档

游戏的槽位是 game:<slug> (目录：从游戏内部保存）；软件开发工具包 构建路径，压缩有效负载并处理 /info 查看。

const remote = await StarHermit.loadJSON();          // null: empty slot, signed out — or a failed read
if (StarHermit.saveLoadFailed()) showSyncError();    // tell those apart when it matters
else if (remote && isNewer(remote, local)) adopt(remote);

StarHermit.saveJSON(state);                          // debounced (2 s) checkpoint upload
addEventListener('pagehide', () => StarHermit.flushSave(true));   // keepalive flush
StarHermit.on('saved', ok => setSyncIndicator(ok));

保存之前加载。 在任何可能到达的写入之前比较并采用云副本 saveJSON — 包括设置、昵称或启动时写入的检查点 — 或者过时的本地副本可以 覆盖在另一台设备上进行的较新的保存。保留早期保存，直到启动负载稳定。

SDK 保护了比赛的另一半：当读取失败时（网络或服务器错误，如 与空槽相反）它设置 saveLoadFailed()，发出 saveerror，并拒绝写入，直到 /info 确认插槽为空或稍后 loadSave() 成功了。拒绝写入解决 false 并发出 saved 和 false.

加载后的写入是有条件的。 SDK 会记住版本（ETag）最后保存 读取或写入并将其发送回，因此写入仅落在其所基于的保存上 - 或者，对于插槽 那是空的，只是在它仍然存在的时候。当中间保存另一个设备时，写入被拒绝 （412): SDK 发出 saveconflict， 套 saveConflicted()，并拒绝进一步写入，直到 loadSave() 让游戏合并或采用更新的保存。一个永远不会加载写入的游戏 无条件地，像以前一样。

StarHermit.on('saveconflict', async () => {
  const remote = await StarHermit.loadJSON();       // lifts the block
  StarHermit.saveJSON(merge(remote, local));        // conditional on the version just loaded
});

较低级别： loadSave() / writeSave(text) 对于原始字符串， saveInfo() 为了 { exists, sizeBytes, updatedAt, etag }.

崩溃和错误报告

玩家可以在游戏内反馈问题；业主通过以下方式对他们进行分类 报告API.

await StarHermit.reportBug('Score did not save', 'Finished level 3, score shows 0', {
  clientVersion: '1.4.2',
  attachments: [{ fileName: 'state.json', contentType: 'application/json', data: JSON.stringify(state) }],
});
StarHermit.captureCrashes({ clientVersion: '1.4.2' });   // opt-in: uncaught errors become crash reports
const mine = await StarHermit.myReports();               // [{ id, kind, status, title, ... }]

report(kind, title, description, opts) 是一般形式（reportBug 和 reportCrash 修复 种）。 captureCrashes 每个不同的消息最多文件一个报告，每个页面加载最多三个文件，因此 崩溃循环不能用完玩家的每日津贴（默认每场游戏 20 个）。之前询问玩家 附加任何个人的东西。

单人排行榜

客户端永远无法发布分数——只有游戏的服务器可以——所以单人游戏需要一个 拥有其主板的小平台脚本。 score-script.js 是一：复制下一个 在你的游戏中声明它 starhermit.txt 作为 server=score-script.js, 和 仅编辑其 BOARDS 块，其中列出了您所选择的每个板 创建它:

var BOARDS = {
  "high-score": { "name": "High score", "scoreType": "integer", "sortDirection": "desc", "minScore": 0, "maxScore": 1000000 }
};

当跑步结束时，将其发布并显示玩家的位置：

const accepted = await StarHermit.submitScores({ 'high-score': total });   // [] when signed out or refused
if (accepted.includes('high-score')) {
  const board = await StarHermit.leaderboard('high-score', { pageSize: 100 });
  const me = board.items.find(e => e.userId === StarHermit.userId);
  showRank(me && me.rank);
}

submitScores 打开练习课（POST .../sessions/ai), 发送 {type:'result', scores} 上 游戏套接字，并解析脚本接受的棋盘键；它还发出 scores 与 那个清单。脚本丢弃的分数不是棋盘类型的数字或超出其范围 minScore/maxScore，通过其发布其余部分 scores 返回，并结束会话。客户 仍然报告结果。范围内的发明分数可以通过；这些板适合休闲 玩。对于竞赛，请在授予奖项之前验证脚本或容器中的运行。致谢 列出脚本接受的键；这并不能证明每个板块都处于活跃状态，也不能证明新的个人最佳成绩 被存储。看 信任和可用性.

重新连接和过期令牌

套接字在其 URL 中携带启动令牌，并且之前使用过期令牌的握手会被拒绝 升级 - 浏览器仅报告关闭代码 1006，就像网络丢弃一样。所以失败了 重新连接可能会导致身份验证失败，并且重试相同的 URL 永远无法恢复。仅更新工程 当前令牌有效且在最初发布后 12 小时内；之后只有 启动器可以铸造一个新的代币。

connect() 自己处理这个问题：在每次重新连接之前，它都会通过以下方式更新令牌 POST /api/v1/games/{slug}/launch-token （除非套接字打开后已更新）并重新打开 与新的。续订时出现网络或服务器错误会退出并再次续订 - 永远不会 重新打开旧网址。当续订被拒绝或令牌已过期时，SDK 会注销（auth 和 reason: 'expired'），停止重新连接并调用 onAuthLost():

const conn = StarHermit.connect(sessionId, {
  onGame, onClose,
  onAuthLost: () => showReconnectPanel(),   // e.g. "Session expired — Back to StarHermit"
});
backButton.onclick = () => StarHermit.relaunch();

relaunch() 将玩家送回以获取新的启动令牌：在游戏打开时通过登录 那样（StarHermit.launchKind === 'sign-in')，否则发送给启动器。在启动器内 它导航顶部窗口的游戏框架，浏览器仅允许通过用户手势进行操作，因此将其称为 通过点击；它返回 false 当导航被拒绝时。

浏览器可以隐藏已完成的会话、术语、成员身份或构建失败，例如 1006。之前 自动重试， connect() 通过 REST 检查会话状态，当 opts.build 供应， 将其与游戏信息进行比较。 onUnavailable(error) 收到永久 REST 失败或结束 会议； onTermsRequired(body) 要求接受明确的条款。之后创建新连接 解决这些。 onClose(1008) 表示连接已被取代或违反政策；不 自动重新打开它。

您的游戏会自行打开套接字（realtime.socketUrl(roomId), voice.socketUrl(roomId)）需要 同样的规则。在重新开放之前，请致电 renewForReconnect() 并对其结果采取行动：

async function reopen() {
  const r = await StarHermit.renewForReconnect();
  if (r === 'renewed') ws = new WebSocket(StarHermit.realtime.socketUrl(roomId)); // fresh token in the URL
  else if (r === 'retry') setTimeout(reopen, backoff());                         // renewal itself failed
  else if (r === 'terms-required') showTermsPanel();                              // explicit acceptance
  else showReconnectPanel();                                                     // 'relaunch'
}

并发续订共享一个请求。 terms-required 保留玩家令牌并发出 termsrequired;展示 getTerms() 并打电话 acceptTerms(displayed.hash) 仅在玩家的 接受操作，然后重试。您的游戏管理的套接字还需要对已结束的资源进行 REST 检查 并且必须在保单关闭时停止。看 故障排除.
