统一SDK

这 星隐者Unity SDK (HypeDriven/starhermit-unity-sdk） 是一个 Unity 包管理器包，带有适用于该平台的类型化、异步 C# 客户端。它处理 HTTP 请求、JSON 解析、令牌刷新和 WebSocket 重新连接。
包裹 com.starhermit.sdk，版本0.1.0
命名空间 Starhermit
API基线 REST v1 和 WebSocket v1
较新的 REST 功能 使用 client.Raw 和型号 RawJson 当此 SDK 版本没有类型成员时
WebSocket 协议 总共 6 个，每个连接类别一个
执照 麻省理工学院

SDK 是一个客户端，而不是平台的第二个实现。授权、友谊、 权利、房间会员资格、分数验证、游戏结果和存储预算保留 服务器权威性与以下页面中记录的完全相同 - SDK 显示服务器的答案 及其发布的限制，而不是决定或缓存自己的限制。

此页面是集成指南。完整的包文档位于以下存储库中 Packages/com.starhermit.sdk/Documentation~.

要求

  • Unity 2021.3 LTS 或更高版本，API 兼容性级别 .NET 标准 2.1, C# 9.
  • Mono 和 IL2CPP，可从“禁用”到“禁用”进行托管剥离 高的 （包裹自带 Runtime/link.xml).
  • 没有反射，没有动态代码生成，没有强制性的本机插件。

每个模块都会针对每个构建目标进行编译。如果目标确实缺乏能力——不 无头服务器上的麦克风，浏览器中没有握手标头 - 调用会引发 StarhermitFeatureUnavailableException 具有稳定的 Reason，而不是构建失败或 禁用不相关的功能。

安装

包管理器 → 从 git URL 添加包，或中的一个条目 Packages/manifest.json。套餐 位于存储库的子文件夹中，因此 URL 需要 path=:

{
  "dependencies": {
    "com.starhermit.sdk": "https://github.com/HypeDriven/starhermit-unity-sdk.git?path=/Packages/com.starhermit.sdk"
  }
}

通过附加固定版本 #<tag-or-commit>:

https://github.com/HypeDriven/starhermit-unity-sdk.git?path=/Packages/com.starhermit.sdk#v0.1.0

Unity炮轰 git，因此只有编辑者的 git 可以验证时私有存储库才会解析 非交互方式 — SSH 密钥（git@github.com:HypeDriven/starhermit-unity-sdk.git?path=/Packages/com.starhermit.sdk）或一个 配置的凭证助手。本地路径或作用域注册表的工作方式相同。导入修改无 项目设置并且不执行网络访问。

创建一个客户端

using Starhermit;

var client = StarhermitClient.Create(new StarhermitOptions
{
    ApiBaseUri = new Uri("https://api.starhermit.com/api/v1/"),
    GameSlug   = "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
    TokenStore = myPlatformSecureStore,
    LogLevel   = StarhermitLogLevel.Warning
});

await client.InitializeAsync();               // loads a stored session, refreshes it if expired
var me = await client.Me.GetProfileAsync();

Create 不执行任何 I/O。在您初始化、调用服务或打开一个服务之前，没有任何东西会触及网络。 连接。 WebSocket 基础源自 ApiBaseUri (wss://<host>/ws/v1/）除非你设置 WebSocketBaseUri 你自己。

StarhermitClient 是 IDisposable：处理取消正在进行的请求，关闭每个连接 发出，停止心跳并释放音频。包中没有静态可变状态，因此 两个客户端可以在不同的环境下并行运行，并且一个客户端可以承受场景负载。

平台上发布的游戏 服务于 https://<slug>.starhermit.com 和 /api 和 /ws 代理同源（参见 GitHub 游戏）。 WebGL 版本发布了 way 应该指向它自己的原点，以便浏览器进行同源调用：

ApiBaseUri = new Uri("https://83fd04b1-3cbe-4b09-a251-3733ad4b9d94.starhermit.com/api/v1/") // your game's uid

对于本地后端， AllowInsecureTransport = true 许可 http/ws。客户施工拒绝 没有它的非 HTTPS 地址，并且编辑器的构建验证会导致非开发播放器构建失败 仍然有它设置。它永远不会禁用证书验证。

登录

中描述的三种凭证类型 验证 是单独的类型 存储在SDK中；没有人可以替代另一个人。

开放认证 — SDK 通过注入的方式打开授权 URL IStarhermitOAuthBrowser 并完成 交换：

var session = await client.Auth.SignInWithOAuthAsync("google");

使用 BuildAuthorizeUri(provider) 加 CompleteOAuthAsync(...) 相反，当您的平台将 通过其自己的深层链接或嵌入式浏览器管道重定向回来。

公钥 — 嵌入式、控制台和专用服务器播放器的无密码流程 （见 专用服务器+嵌入式播放器入门）。 支持的密钥类型有 Ed25519, ECDSA-P256 和 RSA-PSS; SDK从不生成或存储 私钥，它调用注入 IStarhermitSigner:

var session = await client.Auth.SignInWithPublicKeyAsync(signer);   // or (), using Options.Signer

值得了解的合同细节。 部署根据自己的挑战签名验证挑战签名 挑战的 PascalCase 序列化，而您收到的 JSON 是驼峰命名法 — 重新序列化 响应永远不会得到验证。 StarhermitChallenge.CanonicalPayload 将精确的字节复制到 签名，因此手卷签名也必须这样做。

游戏启动令牌 — 每场比赛铸造并围入该游戏的表面：

var chess = client.Games.ForSlug("83fd04b1-3cbe-4b09-a251-3733ad4b9d94");
await chess.AcquireLaunchTokenAsync();
var fenced = chess.WithLaunchToken();     // subsequent calls authorise with the launch token

铸造启动令牌永远不会取代帐户会话。请求携带哪个凭证 由请求管道决定，而不是由您调用的服务决定。

协调访问令牌刷新： 401 最多购买一次刷新和一次重播，并且并发 调用者等待相同的刷新，而不是启动多个刷新 - 使用旋转刷新令牌，第二次 交换将撤销该家庭并注销该球员。明确拒绝提出 SessionExpired 一次;传输失败会使会话保持完整。

接受当前条款

在开始心跳、游戏请求或套接字之前检查接受情况。 0.1.0版本有 AcceptTermsAsync，但较新的配置文件字段和术语发现使用其原始 JSON 支持：

var profile = await client.Me.GetProfileAsync(ct);
var needsAcceptance = profile.RawJson["termsAcceptanceRequired"].AsBooleanOrDefault();
var terms = await client.Raw.SendForJsonAsync(new StarhermitRequest("GET", "terms"), ct);
var textToDisplay = terms["text"].AsStringOrNull();
var displayedHash = terms["hash"].AsStringOrNull();
// Display textToDisplay. Retain displayedHash for this displayed revision.
// Only in the user's Accept handler, using an account session:
// await client.Me.AcceptTermsAsync(displayedHash, ct);

不要使用示例修订标签，例如 terms-2026-08：只有来自 API 的当前哈希值是 接受了。在 409，获取并显示新文本以供再次接受。在 403 terms_acceptance_required，在重试之前解决接受问题；玩家启动代币也可以在明确同意后通过 API 提交接受。看 轮廓 以获得完整的流程。

一个会话从头到尾

生命周期从 集成演练，在 C# 中：

var chess = client.Games.ForSlug("83fd04b1-3cbe-4b09-a251-3733ad4b9d94");
await chess.AcquireLaunchTokenAsync();

var ticket = await chess.EnqueueMatchmakingAsync();
while (!ticket.IsMatched)
{
    await Task.Delay(TimeSpan.FromSeconds(2), ct);
    ticket = await chess.GetMatchmakingAsync(ct) ?? ticket;
}

using var game = client.CreateGameConnection(ticket.SessionId!.Value, "83fd04b1-3cbe-4b09-a251-3733ad4b9d94", useLaunchToken: true);
game.FrameReceived       += frame => ApplyServerState(frame);
game.AchievementUnlocked += unlock => ShowToast(unlock);
game.PresenceChanged     += (userId, online) => UpdateOpponentDot(userId, online);
game.ErrorReceived       += message => ShowError(message);

await game.ConnectAsync(ct);
await game.SendCommandAsync(writer =>
{
    writer.Write("type", "move");
    writer.Write("from", "e2");
    writer.Write("to",   "e4");
}, ct);

SendCommandAsync 将有效负载包装为 {"type":"cmd","data":…}; SendRealtimeInputAsync 是 连续输入的速率限制路径。连接不勾选游戏逻辑，预测权威 状态、捏造结果或在不明确的命令之后重新发送可能的非幂等命令 断开连接——服务器仍然是所发生事件的唯一权威。

每个连接共享一个状态机： Disconnected, Connecting, Connected, Reconnecting, Closing, Faulted， 和 StateChanged, Closed 和 Faulted 事件，有界出站队列 显式背压和有序发送。重新连接使用抖动退避，重新获取电流 每次尝试之前的令牌，以及 授权或保单关闭时永久停止 而不是 敲打一扇门，将平台关上。它从不假设成员资格在间隙中幸存下来：每个协议 重新连接时重新获取或重新加入。

凭证乘坐 Authorization 平台允许的标头以及 ?access_token= 在 /ws/** 否则，因为浏览器无法设置握手标头。查询令牌是从 每一条日志。

异步、线程和 Unity

每个 I/O 操作都会返回 Task 并采取尾随 CancellationToken。没有 async void 方法，并且没有公共方法会阻塞调用线程。

事件和进度回调被发布到创建客户端的同步上下文 - 所以 如果你在 Unity 的主线程上创建它，处理程序可能会触及 GameObject直接。无头服务器 可以跳过跳跃 options.CallbackDispatcher = ImmediateCallbackDispatcher.Instance。回调是 每个连接都排序，并且抛出的处理程序会报告给诊断程序，而无需停止 接收循环。

StarhermitLifecycle.Attach(client) 桥接 Unity 的应用程序事件：存在心跳暂停 挂起时并在恢复时立即发送，并且客户端在退出时被处理而无需同步 网络工作。

模型从未参考 GameObject, MonoBehaviour 或一个场景。 StarhermitTextures 转换头像和 将封面艺术字节转换为 Texture2D 在主线程上 - 调用者拥有结果并且必须销毁它。

错误、重试和分页

地位 例外
400 / 422 StarhermitBadRequestException, StarhermitValidationException （由线路名称键入的字段错误）
401 StarhermitAuthenticationException
402 StarhermitEntitlementException
403 StarhermitAuthorizationException
404 StarhermitNotFoundException
409 StarhermitConflictException
429 StarhermitRateLimitException （携带 RetryAfter)
5xx StarhermitServerException

每个都携带状态，服务器的 {"error":"..."} 消息、任何机器可读的代码、请求 身份证号， Retry-After、经过编辑的标头和经过大小限制的经过编辑的正文。从未到达的请求 API上涨 StarhermitTransportException 或者 StarhermitTimeoutException — 运输故障永远不会发生 打扮成 API 响应。取消总是表现为 OperationCanceledException.

重试是有限的、抖动的、荣誉的 Retry-After 达到上限，并限制每秒失败一次 尝试可以生存：连接错误、超时、 408, 429 和瞬态 5xx. 403, 404, 409 并且验证失败永远不会重试，并且仅当选择使用 POST 时才会重试 AsIdempotent。整个流程的重试预算可以防止多个客户端将一次中断变成一场风暴。

列出端点返回 StarhermitPage<T> 携带服务器自己的分页元数据，加上lazy 仅在消耗页面时获取页面的枚举：

await foreach (var title in client.Software.EnumerateTitlesAsync(query, cancellationToken: ct)) { … }

下载流至 IStarhermitFileStore 通过临时文件，验证提供的 SHA-256 并 以原子方式提升； OpenDownloadAsync 报告 IsResumed 只为真正的 206，因为 将整个文件附加到部分文件会损坏它，同时仍然通过长度检查。

存储凭证

套餐 没有任何声称安全的商店。 默认是内存中的；选择加入 EncryptedFileTokenStore （AES-CBC 与 HMAC-SHA256 通过您的应用程序提供的密钥）已记录 作为静态混淆，而不是钥匙串。金属丝 IStarhermitTokenStore 平台自身安全 storage — Keychain、Keystore、控制台 SDK 的用户存储。 PlayerPrefs 从未呈现为 安全。

令牌、刷新令牌、私钥、客户端机密和调用密钥永远不会序列化为 ScriptableObject，一个场景， Resources、日志、异常消息、遥测事件或构建 神器。 StarhermitSettings 仅保存非秘密项目默认值：地址、slug、日志级别、 超时和开发标志。

密文是结构化的——通过标题、查询参数和 JSON 成员名称，在每个深度——所以 此 SDK 版本从未听说过的凭据仍然从日志、异常和遥测中剥离。 URL 片段被完全丢弃。默认不收集遥测数据；注入的接收器接收 事件名称、操作 ID、持续时间、状态系列、重试次数、请求 ID 和结果、从不 URL、 主体或播放器内容。

当平台推出新产品时

模型是不可变的，并保留从中解析它们的 JSON，因此在部署之后添加了一个字段 此 SDK 版本仍然可读，并且此版本未键入的端点仍可调用 与键入的调用相同的凭据、重试和编辑：

var value = profile.RawJson["shippedAfterThisSdk"].AsStringOrNull();

var json  = await client.Raw.SendForJsonAsync(
    new StarhermitRequest("GET", "some/new/route").WithQuery("page", 1), ct);

套接字帧在其类型鉴别器上分派，并带有未知帧回退，该回退保留了 有效负载，未知的枚举字符串保留为字符串而不是强制的，以及未知的隐私级别 读作 最多 私人解释。 Optional<T> 区分省略、显式 null 和 value，这是 PATCH 主体所需要的。

client.GetDiagnostics() 返回连接状态、队列深度、重新连接计数、令牌过期、时钟 新鲜度、正在进行的请求、重试次数和最后编辑的错误 - 附加到的快照 错误报告。

验证状态

SDK自己的套件（144项密封测试） dotnet test，以 Unity EditMode 运行的相同文件 测试）以及生成的覆盖清单，当 API 操作没有 SDK 映射时，该清单会导致构建失败 抓住每一个变化；另外五个测试在指向其中一个时会读取实时部署，并被跳过 否则。编辑器矩阵和 IL2CPP 适用于 Linux、Android 和 WebGL 的播放器构建是在 CI 中定义的，但需要获得许可的构建农场，因此 上面的平台表说明了预期的支持——只有在构建目标后才将目标视为合格的目标 你自己吧。
