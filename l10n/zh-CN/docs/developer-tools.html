StarHermit开发者工具

创建可发布的脚本游戏包，将其上传到 StarHermit，然后 为您的编码助手提供本地 MCP 连接。这些工具不需要 Rust 安装或引擎源检查。游戏可能有自己的 构建依赖项，例如 Node.js。

从下表下载适用于您计算机的存档，或从 https://engine.starhermit.com/engine/tools/latest.json（它列出了每个 存档的地址、大小和 SHA-256），并将其 SHA-256 与 旁边的校验和（<archive>.sha256）。解压它并将其目录放在 PATH 中，或者 在下面的命令中使用可执行文件的完整路径。 macOS 下载的是 单独提供 Apple Silicon (macos-aarch64）和英特尔 (macos-x86_64）。它们未经 Apple 公证，且无需下载 验证码或开发者 ID 签名。 Apple Silicon 的构建是 交叉编译；报告问题。

检查并打包游戏

starhermit-tools --version
starhermit-tools check my-game
starhermit-tools package --web my-game --out upload --remote-out remote-objects

游戏目录包含 starhermit.txt 以及游戏所需的文件。 engine.version 固定已发布的引擎版本；该工具读取其 来自engine.starhermit.com 的清单并写入哈希固定加载程序和文件 索引。 --engine-version X.Y.Z 明确选择兼容版本。 声明的文件 engine.remote.files 写给 remote-objects; 什么时候 engine.remote.urls=platform，发布首先上传它们。

check 验证清单、包路径和文件结构。确实如此 不执行脚本。之前在浏览器中测试打包好的网页游戏 出版。开发者还可以另外下载匹配的原生 来自引擎版本的运行时（Windows、Linux 和引擎 1.26.2 Intel 和 Apple Silicon 上的 macOS 11 或更高版本）并使用 starhermit check my-game 用于无头执行检查。苹果系统 运行时是临时签名且未经公证的，并且尚未经过公证 在真实的 Apple 硬件上进行了测试。在浏览器中下载的 tarball 是 隔离：运行 xattr -d com.apple.quarantine starhermit 或允许 在系统设置中。

发布

按照公钥加入流程，使用您自己注册的部署密钥 以及开发人员 wiki 中的 CI/CD 指南。放 STARHERMIT_PUBLIC_KEY 和 STARHERMIT_PRIVATE_KEY 在你的 shell 或 CI 秘密存储中。或者， 设置 STARHERMIT_ACCESS_TOKEN 到帐户访问令牌。不要把这些 游戏中的值、提交它们或将它们添加到 MCP 配置中。

starhermit-tools publish --game-id YOUR-GAME-ID --upload upload --remote-out remote-objects

这会替换游戏的部署文件。 --mode merge 修补现有的 改为上传。要创建新游戏，请替换 --game-id YOUR-GAME-ID 和 --new. --socket 选择上传WebSocket；大上传选择它 自动。 --display-name 和 --description 覆盖上传的 清单的名称和描述。发布者报告托管 URL 并在上传旁边写一份发布报告。

该帐户必须拥有该游戏。凭证错误或拒绝限制是 错误；不要用别人的凭据来解决这个问题。远程 游戏中已有的物体被重复使用；对象上传中断 简历。可能会在后续对象上传失败之前创建新游戏； 使用其报告的游戏 ID 进行重试，而不是创建另一个游戏。

STARHERMIT_API_BASE 选择另一个 HTTPS 部署。 STARHERMIT_CA_FILE 选择 PEM 信任包，例如开发 加州； TLS 验证始终启用。正常使用不需要这两个变量。

将编码助手与 MCP 连接

使用绝对路径将 stdio MCP 服务器添加到助手的配置中 适合您计算机的路径：

{
  "mcpServers": {
    "starhermit": {
      "command": "/absolute/path/to/starhermit-tools",
      "args": ["mcp", "--package", "/absolute/path/to/my-game"]
    }
  }
}

服务器提供 check_package, package_web， 和 package_native。 如果游戏有 Node.js 构建脚本，请附加 --build-script 和它的 MCP 参数的绝对路径以公开 build 工具。这运行 配置的脚本；它不接受来自 MCP 的任意命令。 package_web 采取可选的 outDir, remoteOut， 和 engineVersion; 相对输出路径是相对于游戏目录的。默认情况下它 写 starhermit-build/upload 和 starhermit-build/remote 旁边的 游戏目录。 package_native 写入游戏的本机文件索引 由受支持的 StarHermit 客户端安装，该客户端安装引擎 玩家平台的运行时（包括 macOS，从引擎 1.26.2 开始）。这两个工具都没有发布任何内容。

安装本机运行时后，附加 --runtime 和它的 要启用的 MCP 参数的绝对可执行路径 run_checks。 该工具在配置的运行时执行游戏的代码。出版 只能作为显式 CLI 命令使用，并且绝不是 MCP 工具。
