گپ شپ

StarHermit چیٹ ایک REST API (api/v1/chat) نیز سرور سے کلائنٹ ویب ساکٹ پش چینل (ws/v1/chat)۔ تمام REST اینڈ پوائنٹس کو توثیق کی ضرورت ہوتی ہے۔ خرابی کی لاشیں مختلف ہوتی ہیں؛ دیکھیں API کنونشنز.

ریسٹ اینڈ پوائنٹس

بنیاد: https://api.starhermit.com/api/v1/chat.

طریقہ راستہ تصنیف تفصیل
پوسٹ /conversations جے ڈبلیو ٹی ایک گفتگو بنائیں (1 دوست = براہ راست، ≥2 = گروپ)
پیچ /conversations/{id} جے ڈبلیو ٹی گفتگو کا نام تبدیل کریں (کوئی رکن)
پوسٹ /conversations/{id}/invites جے ڈبلیو ٹی کسی صارف کو گروپ میں مدعو کریں۔
حاصل کریں۔ /invites جے ڈبلیو ٹی اپنے زیر التواء چیٹ کے دعوت ناموں کی فہرست بنائیں
پوسٹ /invites/{id}/accept جے ڈبلیو ٹی چیٹ کی دعوت قبول کریں۔
پوسٹ /invites/{id}/decline جے ڈبلیو ٹی چیٹ کی دعوت کو مسترد کریں۔
حاصل کریں۔ /rooms/joinable جے ڈبلیو ٹی اندر ≥1 دوست کے ساتھ کھلے کمروں کی فہرست بنائیں
پوسٹ /conversations/{id}/join جے ڈبلیو ٹی ایک کھلے کمرے میں شامل ہوں (ایک ممبر کے ساتھ دوست ہونا ضروری ہے)
پوسٹ /conversations/{id}/participants جے ڈبلیو ٹی شرکاء کو گفتگو میں شامل کریں۔
حذف کریں۔ /conversations/{id}/participants/{userId} جے ڈبلیو ٹی کسی شریک کو ہٹا دیں (خود: کوئی بھی رکن؛ دیگر: صرف گروپ تخلیق کار)
پوسٹ /conversations/{id}/leave جے ڈبلیو ٹی ایک گفتگو چھوڑیں۔
حاصل کریں۔ /conversations جے ڈبلیو ٹی گفتگو کی فہرست بنائیں، بشمول ہر ایک بغیر پڑھے ہوئے شمار
حاصل کریں۔ /conversations/{id} جے ڈبلیو ٹی گفتگو حاصل کریں، بشمول اس کی پڑھی ہوئی تعداد
حاصل کریں۔ /unread جے ڈبلیو ٹی بغیر پڑھے ہوئے پیغامات کی کل تعداد حاصل کریں۔
پوسٹ /conversations/{id}/read جے ڈبلیو ٹی پڑھی ہوئی گفتگو کو نشان زد کریں۔
حاصل کریں۔ /conversations/{id}/messages?page=&pageSize= جے ڈبلیو ٹی صفحہ شدہ پیغام کی تاریخ حاصل کریں۔
پوسٹ /conversations/{id}/messages جے ڈبلیو ٹی پیغام بھیجیں (شرح محدود)
ڈالو /conversations/{conversationId}/messages/{messageId} جے ڈبلیو ٹی ایک پیغام میں ترمیم کریں۔
حذف کریں۔ /conversations/{conversationId}/messages/{messageId} جے ڈبلیو ٹی ایک پیغام کو حذف کریں (قبر کا پتھر)

ایک مکالمہ بنائیں

POST /conversations

{
  "participantIds": ["<guid>"],
  "name": "Friday night lobby",
  "friendUserId": "<guid>",
  "joinPolicy": "closed"
}

تمام فیلڈز اختیاری ہیں۔ ایک دوست شریک تخلیق کرتا ہے۔ براہ راست بات چیت؛ دو یا زیادہ تخلیق کریں a گروپ. joinPolicy ہے "open" یا "closed" (پہلے سے طے شدہ "closed")۔ واپسی a ConversationDto.

گفتگو کا نام تبدیل کریں۔

PATCH /conversations/{id} کے ساتھ { "name": "New name" } → ConversationDto. کوئی بھی رکن نام بدل سکتا ہے۔ کے ساتھ ایک سسٹم نوٹ kind: "system_rename" نشر کیا جاتا ہے.

دعوت دیتا ہے۔

POST /conversations/{id}/invites کے ساتھ { "toUserId": "<guid>" } → ChatInviteDto. بند کمرے میں دعوتیں ہی واحد راستہ ہیں۔

GET /invites → ChatInviteDto[]:

[
  {
    "id": "<guid>",
    "conversationId": "<guid>",
    "conversationName": "Friday night lobby",
    "fromUserId": "<guid>",
    "fromUsername": "alice",
    "toUserId": "<guid>",
    "status": "pending",
    "createdAt": "2026-07-22T07:00:00Z"
  }
]

POST /invites/{id}/accept اور POST /invites/{id}/decline → ChatInviteDto.

کمروں میں شامل ہونا

GET /rooms/joinable → JoinableRoomDto[] - کھلے کمرے جن کے اندر آپ کا کم از کم ایک دوست ہے:

[
  {
    "id": "<guid>",
    "name": "Friday night lobby",
    "joinPolicy": "open",
    "createdAt": "2026-07-22T07:00:00Z",
    "participants": [{ "userId": "<guid>", "username": "alice" }]
  }
]

POST /conversations/{id}/join → ConversationDto. ایک کھلے کمرے میں شامل ہوتا ہے؛ آپ کو ایک رکن کے ساتھ دوست ہونا ضروری ہے.

شرکاء

POST /conversations/{id}/participants کے ساتھ { "participantIds": ["<guid>"] } → ConversationDto.

DELETE /conversations/{id}/participants/{userId} → 204. کوئی بھی رکن خود کو ہٹا سکتا ہے۔ دوسروں کو ہٹانے کے لیے گروپ کا تخلیق کار ہونا ضروری ہے۔

POST /conversations/{id}/leave → 204.

گفتگو پڑھنا

GET /conversations → ConversationDto[].

GET /conversations/{id} → ConversationDto:

{
  "id": "<guid>",
  "type": "group",
  "name": "Friday night lobby",
  "createdByUserId": "<guid>",
  "joinPolicy": "closed",
  "createdAt": "2026-07-22T07:00:00Z",
  "participants": [{ "userId": "<guid>", "username": "alice" }],
  "otherParticipant": { "userId": "<guid>", "username": "bob" },
  "unreadCount": 3
}

type میں سے ایک ہے direct, group, game. name, createdByUserId، اور otherParticipant غیر حاضر ہو سکتا ہے. unreadCount کال کرنے والے کی فی گفتگو پڑھنے کے افق کے بعد دوسرے اراکین کے بھیجے گئے بغیر پڑھے ہوئے ٹیکسٹ پیغامات کو شمار کرتا ہے۔

بغیر پڑھی ہوئی حالت

GET /unread کال کرنے والے کی تمام بات چیت میں بغیر پڑھے ہوئے شمار کو لوٹاتا ہے:

{ "total": 7 }

POST /conversations/{id}/read اس گفتگو کے لیے کالر کے پڑھنے کے افق کو آگے بڑھاتا ہے۔ موجودہ نقل کو ظاہر کرنے کے بعد اسے استعمال کریں۔ سرور خارج کرتا ہے a conversation_read واقعہ کو کال کرنے والے سے تعلق رکھنے والے تمام ساکٹ، متعدد سائن ان کلائنٹس کو اپنے بیجز کو صاف کرنے کی اجازت دیتے ہیں۔ نئے اور حذف شدہ پیغامات کل تبدیل کر سکتے ہیں، لہذا کلائنٹس کو WebSocket ایونٹس سے اپ ڈیٹ کرنا چاہیے یا وقتاً فوقتاً دوبارہ حاصل کریں۔ /unread.

پیغامات

GET /conversations/{id}/messages?page=1&pageSize=50 → PagedMessagesDto:

{
  "conversationId": "<guid>",
  "page": 1,
  "pageSize": 50,
  "totalCount": 123,
  "items": []
}

POST /conversations/{id}/messages کے ساتھ { "content": "hello" } → MessageDto. فی صارف 10 پیغامات/منٹ تک شرح محدود؛ اس سے تجاوز کرنا واپس آتا ہے۔ 429.

PUT /conversations/{conversationId}/messages/{messageId} کے ساتھ { "content": "edited" } → MessageDto.

DELETE /conversations/{conversationId}/messages/{messageId} → 204. حذف کرنا ایک قبر کا پتھر ہے: پیغام ساتھ رہتا ہے۔ isDeleted: true.

MessageDto:

{
  "id": "<guid>",
  "conversationId": "<guid>",
  "senderId": "<guid>",
  "senderUsername": "alice",
  "content": "hello",
  "kind": "text",
  "metadata": { "key": "value" },
  "sentAt": "2026-07-22T07:00:00Z",
  "editedAt": null,
  "isDeleted": false
}

kind ہے "text" یا "system_rename"; content, metadata (a Dictionary<string,string>)، اور editedAt غیر حاضر / کالعدم ہو سکتا ہے۔

ویب ساکٹ: ws/v1/chat

سے جڑیں۔ wss://api.starhermit.com/ws/v1/chat کے ذریعے JWT کے ساتھ Authorization ہیڈر ?ticket=، یا ?access_token=.

یہ ایک ہے خالص سرور → کلائنٹ پش چینل: کلائنٹ کے فریموں کو نظر انداز کر دیا گیا ہے (صرف Close عزت دی جاتی ہے)۔ ہر فریم ایک لفافہ ہے:

{ "type": "<event>", "payload": { } }
واقعہ type پے لوڈ
conversation_created ConversationDto
conversation_renamed ConversationDto
participants_added ConversationDto
participant_removed ConversationDto
chat_invite ChatInviteDto
chat_invite_responded ChatInviteDto
new_message MessageDto
message_updated MessageDto
message_deleted MessageDto
conversation_read سائن ان کردہ صارف کے لیے پڑھنے کی حالت میں تبدیلی؛ بغیر پڑھے ہوئے شماروں کو دوبارہ حاصل کریں۔
game_invite { "inviteId", "kind", "gameSlug", "gameName", "roomId", "from": { "userId", "username" }, "createdAt", "acceptPath", "declinePath", "inProgress", "sessionId" } - نیچے دیکھیں

game_invite: دونوں دعوتی نظاموں کے لیے ایک ایونٹ

کسی کو بھی دو طریقوں سے کھیلنے کے لیے مدعو کیا جا سکتا ہے، اور اس ایک ایونٹ میں دونوں ہوتے ہیں — ایک کلائنٹ ایک ٹوسٹ لگاتا ہے، دو نہیں:

kind کی طرف سے جاری اسے قبول کرنا
"session" POST /games/{slug}/invites آپ دونوں کے لیے ایک نیا گیم سیشن بناتا ہے۔
"room" POST /realtime/rooms/{id}/invites ایک کمرے میں بیٹھتا ہے جس میں مدعو پہلے سے بیٹھا ہوتا ہے۔ roomId وہ کمرہ ہے؟

acceptPath اور declinePath آخر پوائنٹس ہیں جو جواب دیتے ہیں۔ یہ invite — ان کا استعمال کریں اور امتیاز کبھی اہمیت نہیں رکھتا۔ دوسرے نظام کے اختتامی نقطہ پر جواب دینا a ہے۔ 404: دونوں الگ الگ دعوت نامے رکھتے ہیں۔

inProgress ہے true جب قبول کرنا کسی ایسے گیم میں شامل ہوتا ہے جو پہلے سے کھیلا جا رہا ہے — ایک سیشن انوائٹ جس میں ایک چلتے ہوئے سیشن کا نام ہوتا ہے، یا ایک ایسے کمرے کا دعوت نامہ جو شروع ہونے والے کمرے میں شامل ہوتا ہے — اور sessionId یہ گیم کا سیشن ہے؟ کہنے کے لیے استعمال کریں۔ "ان کے کھیل میں شامل ہوں" کے بجائے "کھیلیں".

{
  "type": "game_invite",
  "payload": {
    "inviteId": "e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b",
    "kind": "room",
    "gameSlug": "poker",
    "gameName": "StarHermit Poker",
    "roomId": "b1d2c3e4-5f60-4a71-8b92-c3d4e5f60718",
    "from": { "userId": "9b2f8c1a-1111-4222-8333-444455556666", "username": "alice" },
    "createdAt": "2026-07-26T14:10:00Z",
    "acceptPath": "/api/v1/realtime/rooms/invites/e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b/accept",
    "declinePath": "/api/v1/realtime/rooms/invites/e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b/decline"
  }
}

roomId ہے null کے لیے "session" دعوت دیتا ہے گیم اسکوپڈ لانچ ٹوکن اس ساکٹ کو نہیں کھول سکتا اور نہ ہی پورے اکاؤنٹ کو پڑھ سکتا ہے۔ /me/game-invites ان باکس گیم کلائنٹس پول GET /api/v1/games/{slug}/invites سیشن کی دعوتوں کے لیے اور GET /api/v1/realtime/rooms/invites ان کے گیم روم کے دعوت نامے کے لیے۔ اکاؤنٹ کلائنٹس دونوں قسم کے ذریعے پڑھ سکتے ہیں۔ GET /api/v1/me/game-invites.

گیم سیشن کے اندر چیٹ کریں۔

ایک گیم اسکوپڈ لانچ ٹوکن نہیں کر سکتے کھلا ws/v1/chat - یہ مسدود ہے کیونکہ ساکٹ صارف کی تمام گفتگو کو سٹریم کرتا ہے۔ ٹوکنز لانچ کریں۔ ہو سکتا ہے چیٹ REST API کو ان کے اپنے گیم سیشنز سے منسلک گفتگو پر استعمال کریں: سیشن کی تفصیل واپس آتی ہے۔ chatConversationId، گفتگو کی قسم ہے۔ "game"، اس کے شرکاء سیشن کے کھلاڑی ہیں، اور دوستی کے اصولوں کو نظرانداز کیا جاتا ہے۔

گیم کلائنٹس اس لیے عام طور پر ساکٹ استعمال کرنے کے بجائے REST پر تاریخ لوڈ کرتے ہیں اور نئے پیغامات کے لیے پول کرتے ہیں۔ مثال کے طور پر، the شطرنج کے حوالہ کا نفاذ ہر 5 سیکنڈ میں پولز:

GET /api/v1/chat/conversations/{chatConversationId}/messages?page=1&pageSize=50
Authorization: Bearer <launch-token>

POST /api/v1/chat/conversations/{chatConversationId}/messages
Authorization: Bearer <launch-token>
Content-Type: application/json

{ "content": "good game" }

یہ بھی دیکھیں

  • آواز - چیٹ گفتگو کے لیے وائس رومز اینکر
  • دوستو - دوستی کے دروازے براہ راست چیٹس اور کمرے میں شامل ہوتے ہیں۔
  • گیمز - گیم سیشن اور ان کے chatConversationId

دیکھیں اسناد کی مطابقت اور مشین پڑھنے کے قابل معاہدے.
