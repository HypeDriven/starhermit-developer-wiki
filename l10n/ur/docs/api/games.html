گیمز API

گیمز سب سسٹم StarHermit کا بنیادی حصہ ہے: سرور سے مستند ملٹی پلیئر گیمز جن کے قواعد یا تو سینڈ باکسڈ JavaScript فائل یا ڈویلپر کے فراہم کردہ کنٹینر میں چلتے ہیں۔ دونوں رن ٹائم اس پلیئر کا سامنا کرنے والے REST API کا اشتراک کرتے ہیں (api/v1/games/{slug}) اور گیم پلے WebSocket (ws/v1/games)۔ سرور تصنیف کے لیے، دیکھیں کھیل ہی کھیل میں سکرپٹ یا کنٹینر کی میزبانی والے گیم سرورز. مکمل اسکرپٹ رن ٹائم مثال کے لیے، دیکھیں شطرنج واک تھرو اور HypeDriven/starhermit-chess.

بنیادی URL: https://api.starhermit.com.

پلیئر اینڈ پوائنٹس کے لیے تصدیق کی ضرورت ہوتی ہے اور مکمل صارف ٹوکن اور گیم اسکوپڈ لانچ دونوں کے ساتھ کام کرتے ہیں۔ ٹوکن دو /server/... اختتامی نکات صرف کنٹینر ہیں: سیشن کی مفاہمت ایک تنگ استعمال کرتی ہے۔ سرور بیئرر ٹوکن، جبکہ ٹوکن کی تجدید تعیناتی ریفریش کلید کا استعمال کرتی ہے۔

کیا {slug} ہے

ایک کھیل کا سلگ اس کا ہے۔ uid - ایک ہی قدر جو اس کی ہے۔ <uid>.starhermit.com پتہ، جیسے 83fd04b1-3cbe-4b09-a251-3733ad4b9d94. یہ گیم کی ناقابل تغیر آئی ڈی اور سے ماخوذ ہے۔ کچھ نہیں اسے مقرر کر سکتے ہیں: نہیں starhermit.txt، ریپو نام نہیں، آپریٹر نہیں۔ ایک نام جو ایک ڈویلپر کرسکتا ہے۔ ایک ایسی چیز کا انتخاب کریں گے جس کے لیے دو گیمز لڑ سکتے ہیں، اور اسے ثالثی کرنے کے لیے پلیٹ فارم کی ضرورت ہوگی۔ مل گیا یو آئی ڈی نہ تو ٹکرا سکتی ہے اور نہ ہی مانگی جا سکتی ہے۔

سلگ سرور کا بیک اینڈ نہیں ہے۔ مقامی فولڈر سے شامل ہر گیم، اور ہر ریپوزٹری گیم ایک تصدیق شدہ مالک نے شامل کیا، ایک ہے — کے ساتھ یا بغیر server= یا container.image= - کیونکہ یہ ہے گیم کے کھلاڑی کے سامنے کی سطح کا پتہ: ٹوکن لانچ کریں, کنٹرول کرتا ہے, ترتیباتاس کا کلاؤڈ سیو سلاٹ اور کمرے. اے صرف براؤزر گیم کو ان کی اتنی ہی ضرورت ہوتی ہے جتنی کسی اور کی ہوتی ہے۔ واحد کھیل جس میں کوئی سلگ نہیں ہے وہ ذخیرہ ہیں۔ گذارشات جن کے مالک کی تصدیق نہیں ہوئی ہے (gameSlug ہے null میں GET /api/v1/me/github-games).

گیم کے سرور کے بارے میں اختتامی نکات — گیم کی معلومات، کامیابیاں، سیشنز، میچ میکنگ، دعوتیں، ری پلے - ایک بیک اینڈ کی ضرورت ہے۔ GET /api/v1/games/{slug} جوابات 404 اس کھیل کے لیے جس میں سلگ اور نہیں ہے۔ پسدید، جو دونوں کو الگ بتانے کا طریقہ ہے۔

اسے ہارڈ کوڈ نہ کریں۔ اسے لانچ ٹوکن سے پڑھیں game_scope دعوی، یا — ایک کے لیے پلیٹ فارم کی میزبانی کردہ براؤزر گیم — سے location.hostname، چونکہ ذیلی ڈومین uid ہے۔

گیم کی معلومات

GET /api/v1/games/{slug}

گیم کی تعریف اور اس گیم کے لیے کال کرنے والے کے اعدادوشمار لوٹاتا ہے۔ 404 اگر ایسا کوئی کھیل موجود نہیں ہے، یا اگر گیم صرف براؤزر ہے (اس میں سلگ ہے لیکن کوئی سرور بیک اینڈ نہیں)۔

{
  "slug": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "name": "Chess",
  "enabled": true,
  "leaderboardId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "maxConcurrentSessionsPerPlayer": 20,
  "replaysEnabled": true,
  "buildId": "s12",
  "me": {
    "userId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
    "elo": 1200,
    "wins": 4,
    "losses": 2,
    "draws": 1,
    "activeSessionCount": 2
  }
}
  • leaderboardId اختیاری ہے.
  • me.elo پہلے سے طے شدہ 1200; wins/losses/draws سرور رن ٹائم کی ملکیت فی کھلاڑی دستاویز سے پڑھا جاتا ہے۔
  • replaysEnabled کہتا ہے کہ آیا اس گیم کے ختم ہونے والے سیشن رکھے گئے ہیں — فرض کرنے کے بجائے اسے پڑھیں، اور اپنے ری پلے UI کو چھپائیں جب یہ ہو false. دیکھیں ری پلے کرتا ہے۔.
  • buildId اس وقت گیم پیش کرنے والے سرور کی منطق کا نام دیتا ہے (s + اسکرپٹ ورژن، یا c + امیج ڈائجسٹ کا سابقہ)۔ بطور واپس بھیجیں۔ ws/v1/games?build=… تو ایک باسی کلائنٹ کے ساتھ انکار کر دیا جاتا ہے 409 {"error":"build_mismatch"} اس سے پہلے کہ یہ منتقل شدہ فیلڈز پر کام کرے۔ چھوڑنا build پہلے کی طرح جوڑتا ہے۔

ٹوکنز لانچ کریں۔

POST /api/v1/games/{slug}/launch-token

ایک گیم اسکوپڈ JWT (پہلے سے طے شدہ لائف ٹائم 60 منٹ) لے جانے والا منٹ game_scope={slug} اور اجازت کا کوئی دعویٰ نہیں۔ اسکوپڈ ٹوکن اپنے گیم کے لیے ٹوکن کو دوبارہ ٹکسال کر سکتا ہے - یہ کلائنٹ ریفریش پیٹرن ہے - لیکن تجدید اس کی پابند ہے launch_chain (اصل صارف سیشن سے پہلے سے طے شدہ 12 گھنٹے)۔ اس حد کی تجدید گزر چکی ہے۔ 403. کلائنٹس کو ٹوکن کی میعاد ختم ہونے سے پہلے ریفریش کرنا چاہیے۔ شطرنج کا حوالہ دینے والا کلائنٹ، مثال کے طور پر، ہر 45 منٹ میں تازہ دم ہوتا ہے۔ ساکٹ کو دوبارہ جوڑنے سے پہلے بھی تجدید کریں — دیکھیں گیم پلے ویب ساکٹ.

کامیابیاں

GET /api/v1/games/{slug}/achievements

کال کرنے والے کی غیر مقفل حالت کے ساتھ، گیم کا مستند بیک اینڈ اعلان کردہ ہر کامیابی۔ خفیہ کامیابیاں اس وقت تک پوشیدہ رہتی ہیں جب تک کہ کالر ان کو کھول نہیں دیتا۔ ایک مکمل صارف JWT یا گیم اسکوپڈ کو قبول کرتا ہے۔ لانچ ٹوکن. 404 جب سلگ کی کوئی مستند گیم تعریف نہیں ہوتی ہے۔

[
  {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "secret": false,
    "points": 10,
    "unlocked": true,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
]

کھیل کی کامیابیاں ہیں۔ سرور مستند: صرف گیم کا اسکرپٹ یا کنٹینر ہی انہیں دیتا ہے، اور کلائنٹ کا دعویٰ POST /api/v1/me/achievements/unlock اختتامی نقطہ ان سے انکار کرتا ہے۔ لائیو ان لاک کے طور پر گیم پلے ساکٹ پر پہنچیں۔ {"type":"achievement"} فریم مکمل معاہدے موجود ہیں۔ کامیابیاں, کھیل ہی کھیل میں سکرپٹ، اور کنٹینر گیم سرورز.

GET /api/v1/games/{slug}/linked-achievements/{otherSlug}

کال کرنے والے کا اپنا ان لاک ہو جاتا ہے۔ ایک اور کھیل، لہذا یہ گیم ان کی بنیاد پر خصوصیات کھول سکتا ہے۔ کام کرتا ہے۔ اس گیم کے لانچ ٹوکن کے ساتھ۔ دیکھیں کامیابیاں - دوسرے کھیلوں سے کامیابیاں.

فی کھلاڑی کنٹرول بائنڈنگز

گیمز ڈیسک ٹاپ براؤزر کنٹرولز کا اعلان کر سکتے ہیں۔ control.* اندراجات starhermit.txt. کنٹرول API اسٹورز a ہر صارف اور گیم کے لیے علیحدہ اوور رائیڈ۔ مکمل صارف JWTs اور گیم اسکوپڈ لانچ ٹوکنز ہیں۔ قبول ایک لانچ ٹوکن game_scope ملنا چاہئے {slug}.

GET /api/v1/games/{slug}/controls

مینی فیسٹ آرڈر میں موثر پابندیاں لوٹاتا ہے۔ codes صارف کے اوور رائڈ پر مشتمل ہے جب ایک موجود ہے، دوسری صورت میں defaultCodes. واپسی 404 "This game declares no controls." جب لائیو تعمیر starhermit.txt کوئی درست نہیں ہے control.* لائن - ان کا اعلان کریں اور ایک تعمیر شائع کریں؛ دیکھیں ٹیوٹوریل: اپنے گیم میں کنٹرولز شامل کریں۔.

ریئل ٹائم ان پٹس نمونے لیے جاتے ہیں، قطار میں نہیں: پلیٹ فارم ہر کھلاڑی کا تازہ ترین ان پٹ اور ہاتھ رکھتا ہے۔ آپ کے اسکرپٹ کے اگلے حصے کا بیچ onTick میں ctx.inputs. آپ کے گیم سے زیادہ تیزی سے بھیجنا ٹک کی شرح کچھ حاصل نہیں ہوتا، کیونکہ دو ٹک کے درمیان ان پٹ ضم ہو جاتے ہیں۔ ایک اپنے ٹک ریٹ پر بھیجیں، یا ان پٹ تبدیل ہونے پر۔

اسکرپٹ کو پائیدار کمانڈز ترتیب سے عملدرآمد کیا جاتا ہے اور ریئل ٹائم سے الگ محدود ہوتا ہے۔ ان پٹ مجرد اعمال بھیجیں جب وہ واقع ہوں؛ نشان زد ریئل ٹائم کے ذریعے مسلسل تحریک بھیجیں۔ ان پٹ کا راستہ کمانڈ کی حد گیم کے لحاظ سے مختلف ہو سکتی ہے۔ اسکرپٹ کی درخواستیں بھی گیم کے پابند ہیں۔ بجٹ. WebSocket ایرر فریم میں ایک پیغام ہوتا ہے، HTTP کی حیثیت نہیں۔ آپ کے اسکرپٹ کو ان کمانڈوں کو مسترد کرنا چاہئے جن کا کوئی مطلب نہیں ہے، جیسے موڑ آف ٹرن۔

کے لیے کنٹینر گیم، کمانڈز آپ کے کنٹینر پر پہنچتے ہی پہنچ جاتے ہیں، بغیر کسی پلیٹ فارم کے ان پر شرح کی حد آپ کا سرور خود کو نافذ کرتا ہے۔ ریئل ٹائم ان پٹ ریٹ محدود کرنا اسکرپٹ پر لاگو ہوتا ہے۔ صرف کھیل.

ایلو فی میچ

پلیٹ فارم کرتا ہے۔ نہیں ایک میچ میں درجہ بندی کتنی آگے بڑھ سکتی ہے eloUpdates (اسکرپٹ) اور elo کنٹرول پیغام (کنٹینر) ہر کھلاڑی کے ساتھ لے جاتا ہے۔ نئی مطلق درجہ بندی، تبدیلی نہیں، اور پلیٹ فارم انہیں بھیجے گئے لاگو کرتا ہے۔ یہ کیا نافذ کرتا ہے:

  • سیشن میں صرف کھلاڑی اپ ڈیٹ کر رہے ہیں. کسی اور کی آئی ڈی، اور AI سیٹ، گرا دی جاتی ہے۔
  • اپ ڈیٹس کا اطلاق ہوتا ہے جب بھی آپ کا سرور انہیں واپس کرتا ہے۔ ایک سیشن پلیٹ فارم ختم (abandoned: کھلاڑی رہ گئے، بیکار، سپرسیڈ، سرور کی ناکامی، مالک کے ذریعہ ختم) شائع کرتا ہے۔ نہیں elo تبدیلی.
  • درجہ بندی کالم میچ میکنگ جوڑوں پر اور گیم کے ایلو بورڈ پر ایک کے طور پر لکھی جاتی ہے۔ اندراج فی کھلاڑی (ان کی تازہ ترین درجہ بندی)۔
  • گیم کا مالک کر سکتا ہے۔ ایک کھلاڑی کی درجہ بندی کو دوبارہ ترتیب دیں۔ 1200 تک.

تو جھولے کا سائز آپ کے کھیل کا فیصلہ ہے۔ اپنے کوڈ میں معیاری K-فیکٹر اور کلیمپ استعمال کریں۔ دی شطرنج کے حوالہ کا نفاذ K = 32 استعمال کرتا ہے، لہذا ایک گیم حرکت کرتی ہے a زیادہ سے زیادہ 32 پوائنٹس کی درجہ بندی:

function eloAfter(mine, theirs, score /* 1 win, 0.5 draw, 0 loss */, K = 32) {
  const expected = 1 / (1 + Math.pow(10, (theirs - mine) / 400));
  const next = mine + K * (score - expected);
  return Math.round(Math.max(100, next));      // your floor, if you want one
}

GET /api/v1/games/{slug}/diagnostics

لائیو سیشنز کا ایک سنیپ شاٹ (فعال، ختم، لائیو کنکشن)، سی پی یو کے خلاف اسکرپٹ میٹرنگ / میموری / اسٹیٹمنٹ بجٹ، میچ میکنگ قطار (سب سے طویل انتظار اور یہ کتنا وسیع ہوا ہے) اور ویب ہک اینڈ پوائنٹ کی صحت۔

ویب ہکس

GET/POST/DELETE /api/v1/games/{slug}/webhooks اور POST .../{id}/resume. فی 5 اینڈ پوائنٹس تک کھیل واقعات: session.created, session.finished (چھوڑ دینا events دونوں کو سبسکرائب کرنے کے لیے)۔ دی دستخط کرنے کا راز واپس آ گیا ہے۔ ایک بار، تخلیق پر۔

پلیٹ فارم JSON کو اس کے ساتھ پوسٹ کرتا ہے:

  • X-Starhermit-Signature: t=<unix>,v1=<hmac-sha256> ختم "<t>.<body>"
  • X-Starhermit-Event-Id - واقعہ (آئیڈیمپوٹینسی کلید؛ دوبارہ کوششوں میں دہرایا جاتا ہے)
  • X-Starhermit-Delivery - یہ کوشش

یو آر ایل https ہونا چاہیے اور اسے کسی نجی / لوپ بیک / CGNAT رینج میں حل نہیں کرنا چاہیے (پر چیک کیا گیا ہے۔ ہر بھیجنے سے پہلے رجسٹریشن اور دوبارہ)۔ ری ڈائریکٹس کی پیروی نہیں کی جاتی ہے۔ ناکام اختتامی پوائنٹس واپس آ گئے۔ اور لگاتار ناکامیوں کے بعد معذور ہو جاتے ہیں۔ resume توڑنے والے کو صاف کرتا ہے۔

رن ٹائم ٹائمنگ

JavaScript گیمز کے لیے، پلیٹ فارم چلتا ہے۔ onTick کے ذریعے درخواست کردہ کلیمپڈ ریٹ پر جھاڑو دیتا ہے۔ game.tickRateHz; 0 ٹِکس کو غیر فعال کر دیتا ہے، اور ایک گیم جس میں کچھ بھی نہیں کہا جاتا ہے اس پر ٹک نہیں لگایا جاتا ہے۔ 0.25 ہرٹج - اگر آپ کا گیم پلے ٹک پر منحصر ہے تو شرح کا اعلان کریں۔ ایک کنٹینر اپنا سمولیشن لوپ چلاتا ہے اور کے ذریعے اپنی مطلوبہ شرح کا اعلان کرتا ہے۔ /describe; پلیٹ فارم اس شرح کو شیڈولنگ کے لیے استعمال کرتا ہے۔ اسنیپ شاٹ پالیسی، گیم کو آگے بڑھانے کے لیے نہیں۔ دیکھیں گیم اسکرپٹس - ٹک ریٹ اور کنٹینر گیم سرورز.

کھیل کا لائف سائیکل

  1. ایک لانچ ٹوکن ٹکسال کریں۔ — POST /api/v1/games/{slug}/launch-token. کلائنٹس کو اسے ختم ہونے سے پہلے ریفریش کرنا چاہیے (شطرنج کا حوالہ کلائنٹ ہر 45 منٹ بعد تازہ کرتا ہے)۔
  2. کھیل کی حالت حاصل کریں۔ — GET /api/v1/games/{slug} معلومات کے لیے + آپ کے اعدادوشمار؛ GET .../sessions/mine جاری کھیلوں کے لیے؛ GET .../invites اور GET /api/v1/realtime/rooms/invites زیر التواء دعوتوں کے لیے؛ GET .../replays/mine تاریخ کے لئے جب replaysEnabled; GET .../achievements کامیابی کی سکرین کے لیے۔
  3. ایک مخالف تلاش کریں۔، تین طریقوں میں سے ایک:
    • میچ میکنگ: POST .../matchmaking، پھر رائے شماری GET .../matchmaking ہر 3 سیکنڈ تک status ہے matched (جواب لے جاتا ہے sessionId). DELETE .../matchmaking منسوخ کرنے کے لئے.
    • دعوت کا بہاؤ: سے ایک دوست منتخب کریں GET /api/v1/me/friends (دیکھیں۔ دوستو), POST .../invites کے ساتھ { "toUserId": "..." }; مدعو کرنے والا کال کرتا ہے۔ POST .../invites/{inviteId}/accept، جو سیشن تخلیق کرتا ہے۔ (اگر آپ کا گیم کھلاڑیوں کو a ریئل ٹائم کمرہ سب سے پہلے، اس کے بجائے انہیں کمرے میں مدعو کریں — وہی اطلاع، لیکن قبول کرنے سے وہ میز پر آپ پہلے سے موجود ہیں۔)
    • AI مشق: POST .../sessions/ai.
  4. سیشن لوڈ کریں۔ — GET .../sessions/{sessionId}.
  5. ویب ساکٹ کو مربوط کریں۔ — ws/v1/games?sessionId={guid} لانچ ٹوکن کے ساتھ، پھر جو بھی ابتدائی-sync کمانڈ گیم کے بیک اینڈ کی وضاحت کرتا ہے بھیجیں - مثال کے طور پر شطرنج کے حوالہ کا نفاذ، بھیجتا ہے {"type":"cmd","data":{"type":"sync"}}.
  6. کھیلیں - تبادلہ cmd/game پسدید، سطح کے ذریعے بیان کردہ فریم achievement فریم، اور ہینڈل resumed پیشن گوئی کو مسترد کرکے اور مکمل ریاست کی درخواست کرکے۔
  7. نتیجہ - مستند پسدید کھیل کو ختم کرتا ہے؛ پلیٹ فارم لیڈر بورڈ پر ایلو اپ ڈیٹس شائع کرتا ہے اور، اس کے ساتھ گیم کے لیے ری پلے، حتمی حالت کو محفوظ کرتا ہے۔
  8. ری پلے — GET .../replays/{sessionId} مکمل حتمی حالت کے لیے۔
