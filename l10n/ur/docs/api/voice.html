آواز

StarHermit آواز ایک REST API (api/v1/voice) کے علاوہ ایک مخلوط بائنری/ٹیکسٹ ویب ساکٹ (ws/v1/voice) آڈیو اور WebRTC سگنلنگ کے لیے۔ تمام REST اینڈ پوائنٹس کو توثیق کی ضرورت ہوتی ہے۔ آواز کی دستیابی مختلف ہو سکتی ہے۔ خرابی کی لاشیں مختلف ہوتی ہیں؛ دیکھیں API کنونشنز.

کمروں کا لنگر a بات چیت بات چیت; گفتگو میں رکنیت ہر چیز کو روکتی ہے، اس لیے چیٹ دوستی کے قوانین آواز پر بھی حکومت کرتے ہیں (گیم سیشن کی گفتگو دوستی کو نظرانداز کرتی ہے)۔ حدود: 3 فعال کمرے فی گفتگو، فی کمرہ 32 شرکاء تک (پہلے سے طے شدہ جب آپ چھوڑ دیتے ہیں maxParticipants; آپ کی قیمت 2–32 تک بند ہے)۔ ہر کمرہ اعلان کرتا ہے a codec تخلیق کار سیٹ اور کلائنٹس پر بھروسہ کر سکتے ہیں: pcm بطور ڈیفالٹ — 20 ms/16 kHz/mono/s16 کنونشن ریلے کو مبہم طور پر آگے بڑھاتا ہے — یا opus ایک ایسے کمرے کے لیے جس کے تمام شرکاء Opus کے قابل کلائنٹ چلاتے ہیں۔ لیبل کو آگے بھیج دیا جاتا ہے، سرور کا اطلاق کبھی نہیں ہوتا ہے۔

ریسٹ اینڈ پوائنٹس

بنیاد: https://api.starhermit.com/api/v1/voice.

طریقہ راستہ تصنیف تفصیل
پوسٹ /rooms جے ڈبلیو ٹی بات چیت کے لیے آواز کا کمرہ بنائیں
پوسٹ /rooms/join-or-create جے ڈبلیو ٹی بات چیت کے سب سے پرانے فعال کمرے کو مفت نشست کے ساتھ واپس کریں، یا ایک بنائیں — جوہری طور پر منتخب کیا گیا ہے۔
حاصل کریں۔ /rooms?conversationId= جے ڈبلیو ٹی گفتگو کے لیے کمروں کی فہرست بنائیں
حاصل کریں۔ /rooms/{roomId} جے ڈبلیو ٹی ایک کمرہ لے لو
پوسٹ /rooms/{roomId}/join جے ڈبلیو ٹی ایک کمرے میں شامل ہوں (WS سے پہلے ضروری ہے)
پوسٹ /rooms/{roomId}/leave جے ڈبلیو ٹی ایک کمرہ چھوڑ دو
پوسٹ /rooms/{roomId}/mute جے ڈبلیو ٹی اپنی خاموش حالت خود سیٹ کریں۔
پوسٹ /rooms/{roomId}/participants/{userId}/server-mute JWT (تخلیق کار) میزبان کو خاموش کر دیں شرکت کنندہ اٹھا نہیں سکتا
پوسٹ /rooms/{roomId}/close جے ڈبلیو ٹی کمرہ بند کریں (صرف تخلیق کار)

ایک کمرہ بنائیں

POST /rooms

{ "conversationId": "<guid>", "maxParticipants": 8, "codec": "opus" }

maxParticipants (اختیاری، 2–32 پر کلیمپڈ؛ ڈیفالٹس 32 تک) اور codec (اختیاری، pcm یا opus; کچھ اور پڑھا جاتا ہے۔ pcm) دونوں تخلیق کے وقت ایک بار سیٹ ہوتے ہیں۔ واپسی a VoiceRoomDto.

شامل ہوں یا کمرہ بنائیں

POST /rooms/join-or-create اسی جسم کے ساتھ واپسی a VoiceRoomDto بات چیت کے لیے سب سے قدیم فعال کمرہ جس میں اب بھی مفت نشست ہے۔, یا ایک تخلیق کرتا ہے جب کوئی نہیں کرتا — جوہری طور پر بات چیت کے کمرے کے تالے کے نیچے فیصلہ کیا جاتا ہے، لہذا دو ممبران جو ایک ہی کمرے میں دو کے بجائے ایک ہی فوری زمین پر آواز آن کرتے ہیں وہ ایک دوسرے کو سن نہیں سکتے۔ maxParticipants/codec صرف اس وقت لاگو کریں جب یہ تخلیق کرتا ہے۔ تم پھر بھی کال کرو /rooms/{roomId}/join WebSocket کھولنے سے پہلے واپس آنے والے کمرے پر۔

کمرے کی شکل

GET /rooms?conversationId=<guid> → VoiceRoomDto[]; GET /rooms/{roomId} → VoiceRoomDto:

{
  "id": "<guid>",
  "conversationId": "<guid>",
  "creatorUserId": "<guid>",
  "codec": "opus",
  "status": "Active",
  "maxParticipants": 8,
  "createdAt": "2026-07-22T07:00:00Z",
  "participants": [
    {
      "userId": "<guid>",
      "username": "alice",
      "isMuted": false,
      "isConnected": true,
      "joinedAt": "2026-07-22T07:01:00Z"
    }
  ]
}

شامل ہونا، چھوڑنا، خاموش کرنا، بند کرنا

POST /rooms/{roomId}/join → VoiceRoomDto. یہ REST جوائن ہے۔ مطلوبہ WebSocket کھولنے سے پہلے؛ اس کے بغیر جڑنا واپس آتا ہے۔ 403. دوبارہ شامل ہونے سے شرکت کنندہ کو صاف ہو جاتا ہے۔ اپنے خاموش (isMuted); ایک میزبان کا isServerMuted چھوڑ کر دوبارہ جڑنے سے بچ جاتا ہے۔

POST /rooms/{roomId}/leave → 204.

POST /rooms/{roomId}/mute کے ساتھ { "muted": true } → 204. یہ شرکت کنندہ کا اپنا خاموش ہے اور میزبان خاموش کو صاف نہیں کر سکتا۔

POST /rooms/{roomId}/participants/{userId}/server-mute کے ساتھ { "muted": true } → 204 (صرف تخلیق کار)۔ اگر دونوں میں سے ایک خاموش سیٹ ہو تو آڈیو چھوڑ دیا جاتا ہے۔

POST /rooms/{roomId}/close → 204 (صرف تخلیق کار)۔

قطار کو جو کچھ بھی یاد ہے اسے وراثت میں لینے کے بجائے کنیکٹ پر اپنے خاموش کو بیان کریں۔

ویب ساکٹ: ws/v1/voice

سے جڑیں۔ wss://api.starhermit.com/ws/v1/voice?roomId=<guid> کے ذریعے JWT کے ساتھ Authorization ہیڈر ?ticket=، یا ?access_token=. ایک پیشگی آرام join کی ضرورت ہے.

پروٹوکول ملا ہوا ہے:

بائنری فریم - آڈیو

بائنری فریم آڈیو لے جاتے ہیں (جیسے Opus)۔ سرور ہر فریم کو دوسرے شرکاء کو اس طرح ریلے کرتا ہے:

[16-byte senderUserId][audio…]

سرور کا سابقہ ​​ہے۔ تصدیق شدہ بھیجنے والے کی شناخت اور کبھی بھی کلائنٹ کے فراہم کردہ بھیجنے والے پر بھروسہ نہیں کرتا ہے۔ خاموش صارفین کی آڈیو کو چھوڑ دیا گیا ہے۔ حدود: 100 پیکٹ/سیکنڈ فی صارف، زیادہ سے زیادہ فریم 4000 بائٹس۔

ٹیکسٹ فریمز — کلائنٹ → سرور کنٹرول

{ "type": "mute", "muted": true }

{ "type": "speaking", "speaking": true }

{ "type": "rtc", "to": "<guid>", "payload": { } }

{ "type": "deafen", "deafened": true }

rtc پے لوڈز مبہم WebRTC سگنلنگ ہیں، جو مخاطب شریک کو بھیجے جاتے ہیں۔ deafen اس ساکٹ کے لیے آنے والی ریلے بائنری آڈیو کو دباتا ہے۔ یہ خود بخود خاموش نہیں ہوتا ہے۔ آؤٹ گوئنگ آڈیو یا علیحدہ ہم مرتبہ کنکشن۔ جب کھلاڑی ڈیفین کا انتخاب کرتا ہے تو انہیں مقامی طور پر لگائیں۔

REST شرکت کنندہ کی شکل اپنے گونگا کو ظاہر کرتی ہے، میزبان خاموش نہیں۔ ابتدائی صوتی فہرست اور ایونٹس میں شمولیت شامل serverMuted; کوئی الگ میزبان-خاموش تبدیل شدہ پش ایونٹ نہیں ہے۔ اگر آپ کا گیم P2P استعمال کرتا ہے۔ آڈیو، اس کی میزبان خاموش سگنلنگ اور نفاذ آپ کے اپنے میڈیا انضمام کا حصہ ہونا چاہیے۔

جب آخری صوتی ساکٹ منقطع ہو جاتا ہے، تو وائس روم کی رکنیت ختم ہو جاتی ہے۔ REST کو کال کریں۔ join دوبارہ پہلے آڈیو بھیجنے سے پہلے مطلوبہ خاموش کو دوبارہ جوڑنا اور بحال کرنا۔

سرور → کلائنٹ کے واقعات

لفافہ: { "event": "<name>", "data": { } }.

واقعہ data
voice.roster { "roomId", "participants": [{ "userId", "muted", "serverMuted" }] } - نئے آنے والے کو بھیجا گیا۔
voice.participant_joined { "roomId", "userId", "muted", "serverMuted" }
voice.participant_left { "roomId", "userId" }
voice.mute_changed { "roomId", "userId", "muted" }
voice.deafened `{ "کمرے کی شناخت", "صارف کی شناخت", "بہرا" }
voice.speaking { "roomId", "userId", "speaking" }
voice.rtc { "roomId", "from", "payload" }

مثال کے انضمام کا نمونہ (شطرنج کے حوالہ کے نفاذ سے)

آواز فی گیم سیشن آپٹ ان ہے۔ ایک عام کلائنٹ enable() بہاؤ:

  1. POST /api/v1/voice/rooms/join-or-create کے ساتھ { "conversationId": "<chatConversationId>" } - ایک کال جو کمرے کو لوٹاتا ہے باقی ہر ایک کی آواز کو آن کرنے میں بدل جاتا ہے۔ (آپ اب بھی کر سکتے ہیں۔ GET /rooms?conversationId= پھر POST /rooms ہاتھ سے، لیکن ایسا کرنے والے دو کلائنٹ ایک ساتھ دو کمرے بناتے ہیں۔)
  2. POST /api/v1/voice/rooms/{roomId}/join.
  3. کھولیں۔ ws/v1/voice?roomId=<guid>.

میں شطرنج کے حوالہ کا نفاذ، آڈیو کامل گفت و شنید کے ساتھ WebRTC P2P پر چلتا ہے۔ کے ذریعے سگنلنگ کا تبادلہ کیا جاتا ہے۔ rtc کنٹرول پیغامات ({ "sdp": … } / { "ice": … } payloads)، فال بیک کے طور پر سرور سے چلنے والے Opus بائنری پاتھ کے ساتھ۔

گیم اسکوپڈ لانچ ٹوکنز ہو سکتا ہے ان کے اپنے گیم سیشنز سے منسلک کمروں کے لیے وائس REST اور WebSocket استعمال کریں۔

یہ بھی دیکھیں

  • آڈیو کے اختیارات - بیس لائن والیوم، مائیکروفون اور پش ٹو ٹاک کنٹرولز، خود کار طریقے سے پتہ چلنے والی پلے بیک کیپ کے ساتھ
  • گپ شپ - کمرے بات چیت کے لیے اینکر؛ گیم سیشن بے نقاب chatConversationId
  • گیمز - گیم سیشنز اور لانچ ٹوکنز
  • ریلے - گیم نیٹ کوڈ کے لیے بائٹ فین آؤٹ

دیکھیں اسناد کی مطابقت اور مشین پڑھنے کے قابل معاہدے.
