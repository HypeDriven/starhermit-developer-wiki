کنٹینر کی میزبانی والے گیم سرورز

ایک StarHermit گیم اپنی مستند سرور منطق کو a کی بجائے کنٹینر امیج کے طور پر بھیج سکتا ہے۔ سینڈ باکس شدہ جاوا اسکرپٹ فائل۔ یہ سرور کو Rust، Go، C++، یا کوئی دوسرا رن ٹائم استعمال کرنے دیتا ہے جو کر سکتا ہے۔ HTTP اور WebSockets کی خدمت کریں۔ براؤزر کا سامنا گیمز API وہی رہتا ہے: کلائنٹ اب بھی گیم اسکوپڈ لانچ ٹوکنز، REST سیشنز، اور استعمال کریں۔ ws/v1/games JSON فریمز۔

starhermit.com پر کسی بھی سائن ان صارف کے لیے کنٹینر ہوسٹنگ کھلا ہے۔ ایک خود میزبان تعیناتی کر سکتے ہیں اسے آپریٹر کی اجازت کی فہرست تک محدود رکھیں؛ ایک غیر ترتیب شدہ اجازت کی فہرست وہاں ہر ایک کے بجائے کسی کو قبول نہیں کرتی ہے۔ یہ رجسٹری کی تصویر اور اپ لوڈ کردہ پر یکساں طور پر لاگو ہوتا ہے۔ server/image.tar، تو کوئی بھی راستہ نہیں ہے۔ خاموشی سے دوسرے سے زیادہ اجازت دینے والا۔

ابتدائی گیم رجسٹریشن کے بعد، ڈویلپرز بھی بلٹ کو آگے بڑھا سکتے ہیں۔ .tar.gz پر مشتمل server/image.tar (docker save آؤٹ پٹ) کے ذریعے POST /api/v1/me/github-games/{id}/bundle. پلیٹ فارم تصویر اور قطاروں کو لوڈ اور ڈائجسٹ پن کرتا ہے۔ ایک تعیناتی دوبارہ شروع. دیکھیں GitHub گیمز - ایک گیم بنڈل پش کریں۔ اور سرشار سرور ٹیوٹوریل.

اس دھکا کے بارے میں یہ تفصیلات جاننے کے قابل ہیں اس سے پہلے کہ آپ اس کے ارد گرد ریلیز پائپ لائن بنائیں:

  • ایک بڑا docker save CDN کی ~100 MB ریکویسٹ باڈی کیپ سے تجاوز کر سکتا ہے۔، جو a کے ساتھ جواب دیتا ہے۔ 413 پلیٹ فارم کبھی نہیں دیکھتا ہے۔ limitBytesکسی بھی لاگ میں کچھ بھی نہیں جسے آپ پڑھ سکتے ہیں۔ آرکائیو کو اوپر دبائیں۔ ws/v1/game-upload اس کے بجائے ایک ہی محفوظ شدہ دستاویزات، وہی الاؤنس، ایک جیسے جوابات۔
  • آپ جو تصویر اپ لوڈ کرتے ہیں وہ خود اعلان ہے۔ ایک گیم جس کا ابھی تک کوئی بیک اینڈ نہیں ہے۔ اپ لوڈ کردہ فولڈر جس نے کسی کو بھی قرار نہیں دیا - اس کے کنٹینر کی تعریف ڈائجسٹ سے فراہم کی جاتی ہے۔ ابھی بھری ہوئی. آپ کو ایک کی ضرورت نہیں ہے۔ container.image= پہلے ظاہر میں۔
  • دوبارہ دھکا ان نوبس کو لاگو کرتا ہے جو اس کا مینی فیسٹ اعلان کرتا ہے اور ان کو برقرار رکھتا ہے جنہیں وہ چھوڑ دیتا ہے۔ بدل رہا ہے۔ container.port اور دوبارہ اپ لوڈ کرنا اب تعیناتی کو اس بندرگاہ پر منتقل کرتا ہے۔ ظاہر کو چھوڑنا بنڈل کی تصویر کے علاوہ کچھ نہیں بدلتا۔
  • ایک اپ لوڈ کردہ تصویر مینی فیسٹ پر جیت جاتی ہے۔، بشمول ایک سے زیادہ server= لائن، اور ایک ظاہر دونوں کا اعلان server= اور container.image= کسی بھی چیز کو لوڈ کرنے سے پہلے انکار کر دیا جاتا ہے.
  • آپ کا مقامی تصویری ٹیگ تعینات شدہ ورژن کو منتخب نہیں کرتا ہے۔ اپ لوڈ کردہ تصویر کو اس کے ذریعے پن کیا گیا ہے۔ مواد ڈائجسٹ. آپ اسے مقامی طور پر ٹیگ کر سکتے ہیں جسے آپ چاہیں؛ اپ لوڈ کردہ ڈائجسٹ اور تعیناتی کی تصدیق کریں۔ اشاعت کے بعد کی حیثیت
  • ?mode=merge صرف کلائنٹ فائلوں کو پیچ کرتا ہے۔ A server/image.tar انضمام میں بالکل اسی طرح بھری ہوئی ہے۔ تبدیل کرنے پر — ایک تصویر کو آدھی اپ ڈیٹ نہیں کیا جا سکتا۔ دیکھیں جزوی اپ ڈیٹس.

ظاہر کرنا

مخزن میں تصویر کا اعلان کریں۔ starhermit.txt:

name=Void Marshals
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html

container.image=ghcr.io/octocat/vm-server@sha256:9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08
container.port=8080
container.health=/health
container.memory_mb=1024
container.cpu=1.0
container.env.LOG_LEVEL=info

صرف container.image کی ضرورت ہے. بندرگاہ اور صحت کا راستہ پہلے سے طے شدہ ہے۔ 8080 اور /health. میموری اور سی پی یو درخواستیں ہیں، گارنٹی نہیں۔ پلیٹ فارم ان کو آپریٹر کی حدود میں بند کر دیتا ہے۔

آپ کی تصویر کی ایک سائز کی حد ہے: 2 GiB غیر کمپریسڈ ہے جب تک کہ آپریٹر نے آپ کے گیم کو دوسرا سیٹ نہ کیا ہو، اور رجسٹری پل میں پانچ منٹ ہوتے ہیں۔ ایک پل جو چھت سے آگے بڑھتا ہے اسے جزوی طور پر چھوڑ دیا جاتا ہے، ایک اپ لوڈ کیا جاتا ہے۔ image.tar اس کے ساتھ انکار کیا جاتا ہے 413, اور ایک تصویر جو غیر کمپریس ہونے کے بعد بڑی ہو جاتی ہے۔ دوبارہ ہٹا دیا. container.env.* صرف غیر خفیہ ترتیب کے لیے ہے۔

جمع کرانے کو مسترد کر دیا جاتا ہے جب تک:

  • تصویر کو ڈائجسٹ کے طور پر پن کیا گیا ہے۔ name@sha256:<64 lowercase hex>. تغیر پذیر ٹیگز قبول نہیں ہیں۔
  • رجسٹری کی اجازت دی گئی ہے اور تصویر تصدیق شدہ ذخیرہ کے مالک کے نام کی جگہ کے تحت ہے۔ فی الحال اس کا مطلب ہے ghcr.io/<github-owner>/....
  • مینی فیسٹ بالکل ایک سرور رن ٹائم کا اعلان کرتا ہے۔ server= اور container.image= باہمی طور پر ہیں خصوصی
  • ماحولیات کے نام درست ہیں اور محفوظ سے شروع نہیں ہوتے ہیں۔ STARHERMIT_ سابقہ

کبھی بھی اسناد داخل نہ کریں۔ starhermit.txt; یہ ایک عوامی ذخیرہ فائل ہے۔

پروٹوکول v1

کنٹینر HTTP/1.1 آن کی خدمت کرتا ہے۔ container.port. ہر پلیٹ فارم HTTP درخواست اور WebSocket اپ گریڈ میں شامل ہے۔ X-Starhermit-Invoke-Key، جس کی قیمت انجیکشن سے میل کھاتا ہے۔ STARHERMIT_INVOKE_KEY; جب کوئی درخواست غیر حاضر یا غلط ہو تو اسے مسترد کر دیں۔

اختتامی نقطہ مقصد
GET <container.health> واپسی 200 جب سرور تیار ہے۔
GET /describe پروٹوکول ورژن، ٹک ریٹ، صلاحیت، اور کامیابیوں کا اعلان کریں۔
POST /sessions ایک سیشن شروع کریں، یا جب اسے بحال کریں۔ snapshot موجود ہے
GET /sessions/{sessionId}/snapshot موجودہ پائیدار حالت کو لوٹائیں۔
DELETE /sessions/{sessionId} ایک سیشن کو پھاڑ دیں۔
POST /sessions/{sessionId}/members اختیاری: ایک کھلاڑی رننگ سیشن میں شامل ہو رہا ہے یا چھوڑ رہا ہے۔
WS /control تعیناتی وسیع آؤٹ باؤنڈ کنٹرول چینل
WS /stream دونوں سمتوں میں گیم پلے فریم

ایک کنٹینر ایک گیم کے لیے تمام لائیو سیشنز کی میزبانی کرتا ہے۔ سیشن کی حالت کو کلید کے ذریعے رکھیں sessionId اور کرو یہ نہ سمجھیں کہ یہ عمل میچ کی زندگی تک زندہ رہے گا۔

GET /describe

{
  "protocol": 1,
  "tickRateHz": 20,
  "maxSessions": 48,
  "replays": true,
  "persistent": false,
  "achievements": [
    { "key": "first-blood", "name": "First Blood", "description": "Score first.", "points": 10 }
  ]
}

protocol ہونا ضروری ہے 1. tickRateHz اور maxSessions درخواستیں ہیں اور اسے بند کیا جا سکتا ہے۔ پلیٹ فارم کبھی بھی کنٹینر کے لوپ کو قدم نہیں اٹھاتے ہیں، لہذا tickRateHz یہ بتاتا ہے کہ آپ کا کھیل کتنا تیز ہے۔ چالیں بجائے کہ کس طرح اسے چلانے کے لیے تیز: یہ وہی چیز ہے جو پلیٹ فارم کو آپ کے گیم سے زیادہ تیزی سے سنیپ شاٹس مانگنے سے روکتا ہے۔ نئی ریاست. اس شرح کا اعلان کریں جس پر آپ کا لوپ دراصل چلتا ہے۔ جزوی شرحیں قبول کی جاتی ہیں (0.5 ایک ہے ہر دو سیکنڈ پر نشان لگائیں) اور ایک شرح جو اسنیپ شاٹ کی درخواستوں کے درمیان وقفہ کو بڑھاتی ہے — جس میں کریش کھیلنے کی قیمت کتنی ہے۔ ایک کنٹینر جو کچھ بھی نہیں بتاتا ہے چیک پوائنٹ کو چھوڑ دیتا ہے۔ صرف سنیپ شاٹ کی قیمت۔ کامیابی کے اندراجات میں وہی فیلڈز اور حدود استعمال ہوتی ہیں۔ اسکرپٹ سے اعلان کردہ کامیابیاں. اعلان کردہ اور مالک کی تخلیق کردہ چابیاں بعد میں دی جا سکتی ہیں۔

replays پلیٹ فارم سے کہتا ہے کہ وہ ہر مکمل سیشن کی آخری حالت کو a کے طور پر رکھے دوبارہ چلائیںکی طرف سے خدمت کی GET /api/v1/games/{slug}/replays/{sessionId} (دیکھیں۔ گیمز API - ری پلے)۔ یہ ضروری ہے ایک لفظی ہو true یا false; ایک کھیل جو اعلان کرتا ہے کہ کچھ بھی نہیں ہے کوئی ری پلے نہیں ہے، اور اس کے ری پلے اینڈ پوائنٹس جواب 404. ٹک ریٹ کی طرح یہ بھی ایک درخواست ہے - ایک آپریٹر کسی خاص گیم کا جواب دے سکتا ہے۔ کسی بھی طرح - لہذا اپنے کلائنٹ کو برانچ کریں۔ replaysEnabled سے GET /api/v1/games/{slug} کے بجائے جو آپ نے اعلان کیا. سنیپ شاٹس کسی بھی طرح سے متاثر نہیں ہوتے ہیں: ایک لائیو سیشن کو بحالی پوائنٹ کی ضرورت ہے چاہے یا اس کا آخری نہیں رکھا گیا ہے۔

persistent (لفظی true/false) سیشن کے لئے پوچھتا ہے کہ ختم کرنے کے بجائے روک دیں جب ہر کھلاڑی چلا گیا. ایک وقفہ سیشن کو کھڑا کرتا ہے: پلیٹ فارم ایک حتمی سنیپ شاٹ لیتا ہے، اسے اسٹور کرتا ہے، اور کالز DELETE /sessions/{id}; شامل ہونے والا اگلا کھلاڑی اسے واپس لاتا ہے۔ POST /sessions کے ساتھ کہ snapshot، بالکل کریش ریسٹور کی طرح لیکن ری اسٹارٹ بجٹ یا بھیجے بغیر resumed. بحال مسلسل سیشن بھی لے pausedMs، توقف میں گزارا گیا کل وقت۔ دیکھیں مسلسل سیشن ٹیوٹوریل.

linkedAchievements (8 تک دیگر گیمز کے سلگس کی ایک صف) کھلاڑیوں کے ان لاک کو ان میں رکھتا ہے کے ctx میں گیمز POST /sessionsبنائیں اور بحال کریں۔ دیکھیں دوسرے کھیلوں سے کامیابیاں.

کرنٹ /describe ریڈر درآمد نہیں کرتا a queues جائیداد کنٹینر گیمز اس لیے استعمال کریں۔ مضمر default 1v1 میچ میکنگ قطار؛ یہاں شکلیں شامل کرنے سے بڑی مماثلتیں فعال نہیں ہوتی ہیں۔ چیک کریں۔ GET /api/v1/games/{slug}/queues مؤثر شکل کے لئے. مینی فیسٹ کی آخری تاریخ شروع ہوتی ہے اور AI-سیٹ حدود اب بھی اس شکل کے اندر لاگو ہوتے ہیں؛ دیکھیں میچ میکنگ.

POST /sessions

درخواست وہی سیاق و سباق کی شکل ہے جو جاوا اسکرپٹ گیم کو موصول ہوتی ہے:

{
  "now": 1769500000000,
  "random": 0.418,
  "sessionId": "0f8fad5b-d9cb-469f-a165-70867728950e",
  "players": [
    { "id": "7c9e6679-7425-40de-944b-e07fc1f90ae7", "name": "alice", "elo": 1312 }
  ],
  "sessionState": null,
  "playerStates": {
    "7c9e6679-7425-40de-944b-e07fc1f90ae7": null
  }
}

فیلڈ سیمنٹکس سے میل کھاتا ہے۔ سکرپٹ سیاق و سباقسمیت میچ میکنگ سیٹیں، AI جھنڈے اور خالی سیٹیں۔ کھیلوں کے لیے جو شروع کی آخری تاریخ کو ترتیب دیتا ہے۔ starhermit.txt، اور ہر کھلاڑی کا کرنٹ elo (1200 تک درجہ بندی)۔ کیونکہ ایک کنٹینر گیم صرف اسکرپٹ کو نہیں پڑھ سکتا playerStates، وہ فہرست elo کس طرح ہے یہ 1200 سے ہر میچ شروع کرنے کے بجائے میچوں کے درمیان ریٹنگ آگے بڑھاتا ہے۔ ایک درجہ بندی تبدیل کریں صرف بھیج کر eloUpdates. معیاری نتیجہ کے لفافے کے ساتھ جواب دیں، مثال کے طور پر:

{ "ok": true, "sessionState": { "round": 1 } }

وصولی پر درخواست بھی شامل ہے snapshotپلیٹ فارم کے ذریعہ آخری حالت کو برقرار رکھنا، اور restoredFrom، یونکس ملی سیکنڈ ٹائم اسٹیمپ۔ سنیپ شاٹ سے کھیلنے کے قابل سیشن کی تشکیل نو کریں۔ مستقل گیمز کو اسی طرح بحال کیا جاتا ہے جب کوئی کھلاڑی رکے ہوئے سیشن میں دوبارہ شامل ہوتا ہے۔ pausedMs جسم میں

GET /sessions/{sessionId}/snapshot

معیاری لفافہ مکمل کے ساتھ واپس کریں۔ sessionState بحالی نقطہ:

{ "ok": true, "sessionState": { "round": 3, "scores": [2, 1] } }

پلیٹ فارم چیک پوائنٹس وقتا فوقتا فعال سیشن کرتا ہے۔ اسنیپ شاٹ کے جواب میں بھی شامل ہو سکتا ہے۔ playerStates, eloUpdates, achievements, scores، یا result; وہ ایک ہی توثیق سے گزرتے ہیں اور اسکرپٹ کے نتیجے کے طور پر استقامت کے اصول۔ کے ساتھ کھیل کے لیے ری پلے، آخری حالت a تکمیل شدہ سیشن وہی ہے جسے پلیٹ فارم اپنے ری پلے کے طور پر رکھتا ہے - لہذا اس حالت کو بنائیں دوبارہ قابل تعمیر، نہ صرف دوبارہ شروع کرنے کے قابل۔

POST /sessions/{sessionId}/members

اختیاری کھلاڑی کر سکتے ہیں۔ جاری سیشن میں شامل ہوں۔، ایک کے ذریعے ریئل ٹائم کمرہ یہ اجازت دیتا ہے اسے یا کسی دوست کو قبول کرکے سیشن میں مدعو کریں جو وہ کھیل رہے ہیں۔, اور کمرے ایک کھلاڑی کو بغیر AI کے اپنی سیٹ چھوڑنے دیتے ہیں۔ پلیٹ فارم آپ کے کنٹینر سے پوچھتا ہے۔ تبدیلی حتمی ہونے سے پہلے جسم عام ctx ہے، کے ساتھ players پہلے سے ہی کی عکاسی کر رہا ہے تبدیلی، پلس membership:

{
  "now": 1769500000000,
  "sessionId": "0f8fad5b-d9cb-469f-a165-70867728950e",
  "players": [
    { "id": "7c9e6679-7425-40de-944b-e07fc1f90ae7", "name": "alice" },
    { "id": "9b2f8c1a-1111-4222-8333-444455556666", "name": "carol" }
  ],
  "membership": { "change": "joined", "userId": "9b2f8c1a-1111-4222-8333-444455556666", "name": "carol", "team": 0, "slot": 1 }
}

change ہے joined یا left. معیاری لفافے کے ساتھ جواب دیں:

  • شمولیت سے انکار کیا جا سکتا ہے۔ {"ok": false, "error": "This world is full."} کھلاڑی کو دور کر دیتا ہے، سیٹ واپس دی جاتی ہے اور کچھ بھی ریکارڈ نہیں کیا جاتا ہے۔ ایک دعوت قبول جوابات 409 اور دعوت باقی ہے زیر التواء اگر آپ اختتامی نقطہ کو نافذ نہیں کرتے ہیں تو، ہر شمولیت سے انکار کر دیا جائے گا: 404, 405 اور 501 مطلب "یہ کھیل کھلاڑیوں کو مڈ میچ میں نہیں لیتا ہے۔"، لہذا ایک مقررہ فہرست کے لئے لکھی گئی گیم میں کبھی بھی a نہیں ہوتا ہے۔ اجنبی اس میں گرا.
  • چھٹی حتمی ہے۔ آپ جو بھی جواب دیں
  • جواب لے جا سکتا ہے۔ achievements اور scores. A sessionState نظر انداز کیا جاتا ہے: بھیجیں a snapshot ختم /control اگر تبدیلی چیک پوائنٹ کے قابل ہے۔

شمولیت کے بعد، نئے کھلاڑی کے احکامات آنا شروع ہو جاتے ہیں۔ /stream اور وہ اندر ہیں players ہر ایک پر بعد میں بحال کریں. چھٹی کے بعد، ان کے فریم رک جاتے ہیں اور ان کا ساکٹ بند ہوجاتا ہے۔ ہر منسلک کلائنٹ حاصل کرتا ہے a membership فریم کسی بھی طرح سے، اور سیشن چیٹ میں فائدہ یا نقصان ہوتا ہے۔ رکن

A مسلسل سیشن روک دیا نہیں پوچھا جاتا، کیونکہ یہ نہیں چل رہا ہے۔ اس کی بحالی دوبارہ شروع کرتا ہے یہ کرنٹ لے جاتا ہے۔ players، تو ایسے کھلاڑی کے ساتھ برتاؤ کریں جیسا کہ آپ نے پہلے بحالی میں نہیں دیکھا ہوگا۔ شمولیت اختیار کی

گیم پلے کا سلسلہ

WS /stream دونوں سمتوں میں بائنری پیغامات کا استعمال کرتا ہے:

[1 byte type][16 byte sessionId][16 byte userId][payload...]

GUIDs اپنی 16 بائٹ .NET تار کی نمائندگی کا استعمال کرتے ہیں۔

  • قسم 1، پلیٹ فارم → کنٹینر: پلیئر کمانڈ. پلیٹ فارم تصدیق شدہ صارف کی شناخت پر مہر لگاتا ہے۔ پے لوڈ کلائنٹ کی طرف سے JSON قدر ہے۔ cmd.data.
  • قسم 2، کنٹینر → پلیٹ فارم: کھیل پے لوڈ. ایک شرکت کنندہ کو ان کی صارف آئی ڈی کے ساتھ ایڈریس کریں، یا استعمال کریں۔ براڈکاسٹ کرنے کے لیے ایک تمام صفر صارف کی شناخت۔ پے لوڈ درست JSON ہونا چاہیے؛ کلائنٹ اسے اندر سے وصول کرتے ہیں۔ {"type":"game","data":...}.

ترتیب کو محفوظ رکھنے کے لیے سیشنز کو سٹریم کنکشن پر پن کیا جاتا ہے۔ کبھی بھی کھلاڑی کو قبول یا اخذ نہ کریں۔ کمانڈ JSON سے شناخت — توثیق شدہ ہیڈر مستند ہے۔

کنٹرول چینل

JSON ٹیکسٹ پیغامات بھیجیں۔ WS /control پائیدار اثرات کے لیے:

{ "type": "snapshot",     "sessionId": "...", "state": { "round": 3 } }
{ "type": "achievements", "sessionId": "...", "unlocks": { "<userId>": ["first-blood"] } }
{ "type": "elo",          "sessionId": "...", "updates": { "<userId>": 1312 } }   // absolute ratings, not deltas — see games.md#elo-per-match
{ "type": "scores",       "sessionId": "...", "scores": { "<boardKey>": { "<userId>": 4200 } } }
{ "type": "result",       "sessionId": "...", "result": { "kind": "win", "winner": "..." } }
{ "type": "backpressure", "load": 0.75 }

پلیٹ فارم صرف اس تعیناتی کے لیے بھیجے گئے سیشنز کے لیے اثرات قبول کرتا ہے، وصول کنندگان کو فلٹر کرتا ہے۔ سیشن کے شرکاء، کامیابی کی کلیدوں کو گیم کی کامیابیوں تک محدود کرتے ہیں (اعلان کردہ، یا تخلیق کردہ اس کا مالک)، حدود scores کھیل کے اپنے مالک کے بنائے ہوئے لیڈر بورڈز - ہر کھلاڑی اپنا رکھتا ہے۔ بہترین - اور ریاستی بجٹ کا اطلاق ہوتا ہے۔ result سیشن ختم ہوتا ہے؛ اس سیشن کے بعد کے اثرات کو نظر انداز کر دیا جاتا ہے۔ backpressure.load ہے سے جکڑ لیا 0..1 اور موجودہ تعیناتی بوجھ کے لیے پلیٹ فارم اکاؤنٹ میں مدد کرتا ہے۔

لفظی طور پر اہم واقعات کے بعد اسنیپ شاٹ کو دبائیں، جیسے کہ گول یا گول منتقلی، بلکہ صرف متواتر چوکیوں پر انحصار کرنے کے بجائے۔

کنٹینر ماحول اور سرور API

متغیر مطلب
STARHERMIT_PROTOCOL پروٹوکول ورژن (1)
STARHERMIT_GAME_SLUG اس گیم کی سلگ
STARHERMIT_INVOKE_KEY میں خفیہ متوقع X-Starhermit-Invoke-Key; پلیٹ فارم کو آپ کے کنٹینر سے تصدیق کرتا ہے۔
STARHERMIT_REFRESH_KEY الگ راز صرف سرور ٹوکن کی تجدید کے لیے استعمال کیا جاتا ہے۔
STARHERMIT_API_BASE الگ تھلگ نیٹ ورک سے پلیٹ فارم API کا بنیادی URL قابل رسائی ہے۔
STARHERMIT_SERVER_TOKEN تنگ سرور سے سرور API کے لیے بیئرر ٹوکن کی میعاد ختم ہو رہی ہے۔
STARHERMIT_SERVER_TOKEN_EXPIRES_IN انجیکشن سرور ٹوکن کا لائف ٹائم، سیکنڈوں میں
PORT پورٹ جس پر کنٹینر ضرور سنے۔

سرور ٹوکن میں کھلاڑی کی کوئی شناخت نہیں ہوتی ہے اور وہ اکاؤنٹ یا پلیئر کی کارروائیوں کا استعمال نہیں کر سکتا۔ یہ پڑھ سکتا ہے۔ GET /api/v1/time، اس کے اپنے سیشنوں کو ملاپ کریں، اور سرور سے تعاون یافتہ کو کال کریں۔ اعتدال کے راستے اپنے کھیل کے لیے۔ نسل کے راستے ہیں۔ محفوظ اور دستیاب نہیں۔.

سرور ٹوکن کی تجدید کریں۔

انجیکشن سرور ٹوکن کی میعاد ختم ہو جاتی ہے (بطور ڈیفالٹ 24 گھنٹے)۔ اس سے پہلے اسے اچھی طرح سے تازہ کریں۔ STARHERMIT_SERVER_TOKEN_EXPIRES_IN گزر جاتا ہے:

POST /api/v1/games/{slug}/server/token
X-Starhermit-Refresh-Key: <STARHERMIT_REFRESH_KEY>

{ "token": "eyJhbGciOi...", "expiresInSeconds": 86400 }

یہ اختتامی نقطہ جان بوجھ کر ختم شدہ بیئرر ٹوکن کے بغیر کہا جاتا ہے۔ سرشار ریفریش کلید لائیو تعیناتی سے موازنہ کیا جاتا ہے اور پرانے ٹوکن کی میعاد ختم ہونے کے بعد بھی کام کرتا ہے۔ یہ الگ ہے۔ سے STARHERMIT_INVOKE_KEY: invoke کلید پلیٹ فارم کالز کو آپ کے عمل کی تصدیق کرتی ہے، جبکہ ریفریش کلید پلیٹ فارم پر آپ کے عمل کی تصدیق کرتی ہے۔ جب بھی کنٹینر شروع ہوتا ہے تو دونوں گھومتے ہیں۔ تجدید کا شیڈول لائف ٹائم کے تقریباً نصف پر بنائیں اور ٹوکن کو ایٹمی طور پر تبدیل کریں۔

"جب بھی کنٹینر شروع ہوتا ہے۔" ایک تعیناتی سے زیادہ شامل ہے۔ ایک کے بعد ایک بیکار تعیناتی روک دی جاتی ہے۔ بغیر سیشن کے خاموش اسپیل (بطور ڈیفالٹ 15 منٹ) اور اگلے کھلاڑی کے ذریعہ دوبارہ شروع کیا گیا۔ کریش ہونے والا کنٹینر ہے۔ دوبارہ شروع ہر آغاز ایک نیا کنٹینر ہوتا ہے جس میں نئی چابیاں اور ایک نیا ٹوکن ہوتا ہے، لہذا سے تینوں کو پڑھیں چلانے کے عمل کا ماحول. انہیں کبھی بھی تصویر، کنفگ فائل یا اسنیپ شاٹ میں نہ بنائیں۔

اگر کوئی آغاز ناکام ہو جاتا ہے۔ The game container returned 401 for GET /describe، پلیٹ فارم کی کلید اور آپ کے عمل کی کلید متفق نہیں ہے۔ پڑھیں STARHERMIT_INVOKE_KEY آغاز پر اور اس کا غیر ترمیم شدہ موازنہ کریں۔ اگر توثیق اب بھی ناکام ہو جاتی ہے، گیم آئی ڈی اور سینیٹائزڈ اسٹارٹ اپ لاگز کی اطلاع دیں؛ چیک کو ڈھیلا نہ کرو.

ایک سیشن میں صلح کریں۔

GET /api/v1/games/{slug}/server/sessions/{sessionId} کے ساتھ Authorization: Bearer <STARHERMIT_SERVER_TOKEN> پلیٹ فارم کے موجودہ سیشن کا منظر واپس کرتا ہے:

{
  "sessionId": "0f8fad5b-d9cb-469f-a165-70867728950e",
  "status": "active",
  "players": [
    { "userId": "7c9e6679-7425-40de-944b-e07fc1f90ae7", "username": "alice" }
  ],
  "createdAt": "2026-07-27T16:00:00Z",
  "finishedAt": null,
  "chatConversationId": "d290f1ee-6c54-4b01-90e6-d701748f0851",
  "result": null
}

اسے بحالی کے بعد استعمال کریں جب کنٹینر کو اس بات کی تصدیق کرنے کی ضرورت ہو کہ آیا پلیٹ فارم ابھی بھی غور کرتا ہے۔ ایک فعال سیشن۔ کسی دوسرے گیم کے لیے ٹوکن، یا پلیئر لانچ ٹوکن، منع ہے۔

chatConversationId ہو سکتا ہے null ایک مکمل سیشن پر اگرچہ اس میں ایک وقت لائیو تھا: جب a میچ ختم ہوتا ہے اور کسی نے چیٹ میسج نہیں بھیجا، پلیٹ فارم گیم کی خالی گفتگو کو چھوڑ دیتا ہے۔ سیشن قطار کی زندگی کے لئے رکھنے کے بجائے، اور فیلڈ پڑھتا ہے null بعد میں اسے حاضر سمجھیں۔ صرف اس وقت جب سیشن ہو۔ active.

علیحدگی

گیم کنٹینر میں انٹرنیٹ تک رسائی نہیں ہے۔ یہ صرف StarHermit API تک پہنچ سکتا ہے۔ STARHERMIT_API_BASE; یہ دوسرے گیمز، پلیٹ فارم سروسز، یا میزبان تک نہیں پہنچ سکتا۔ سب وینڈر تصویر میں رن ٹائم انحصار۔

روٹ فائل سسٹم صرف پڑھنے کے لیے ہے، سوائے ایک چھوٹے کے /tmp; عمل جبری غیر جڑ کے طور پر چلتا ہے۔ وہ صارف جس میں لینکس کی کوئی صلاحیت نہیں، کوئی حجم نہیں، اور CPU، میموری، اور عمل کی حدود۔ انسٹال نہ کریں۔ شروع ہونے پر پیکجوں کی حالت صرف مقامی ڈسک سے ملتی ہے۔

ناکامی اور بحالی

اگر عمل ختم ہوجاتا ہے، تو پلیٹ فارم تعیناتی کو دوبارہ شروع کرتا ہے اور اپنے لائیو سیشنز کو ان سے دوبارہ بناتا ہے۔ آخری سنیپ شاٹس منسلک کھلاڑیوں کو ایک پلیٹ فارم فریم ملتا ہے:

{ "type": "resumed", "sessionId": "...", "lostMs": 750 }

کلائنٹس کو مقامی پیشن گوئی کو مسترد کرنا چاہئے اور گیم کے عام فل اسٹیٹ پے لوڈ کا انتظار کرنا چاہئے۔ ایک سیشن جب کوئی قابل استعمال سنیپ شاٹ موجود نہ ہو، یہ بہت پرانا ہے، یا سیشن میں اکثر دوبارہ شروع. پلیٹ فارم اسے فاتح یا ایلو تبدیلی کے بغیر ختم کرتا ہے اور بھیجتا ہے:

{ "type": "abandoned", "sessionId": "...", "reason": "server_failure" }

reason ہے server_failure جب بحالی غیر محفوظ ہو یا متبادل کبھی شروع نہیں ہوتا ہے، اور restore_failed جب سیشن کو دوبارہ بنانا ناکام ہوجاتا ہے۔ نئی تصویر شائع کرنے سے لائیو سیشنز بحال ہو جاتے ہیں۔ متبادل میں (یا ان کو چھوڑ دیتا ہے جو بہت باسی ہیں)۔ ایک ایسا آغاز جو ناکام ہو جاتا ہے — پل کا وقت ختم ہو گیا، کنٹینر سے باہر نکلا، یا اس نے کبھی بھی اپنی صحت کی جانچ کا وقت پر جواب نہیں دیا - بیک آف کے ساتھ دوبارہ کوشش کی جاتی ہے، جیسے کہ حادثہ دس منٹ کے اندر تین ناکام کوششیں (آپریٹر ٹیون ایبل) تعیناتی کو غیر فعال کر دیتی ہیں (failed) اور یہ ہے نہیں کھلاڑیوں کی مانگ سے بیدار ہوا۔ کھیل کے ناکامی الاؤنس کو خرچ کیے بغیر عارضی ہوسٹنگ رکاوٹوں کو دوبارہ آزمایا جا سکتا ہے۔

بغیر کسی لائیو سیشن کے تعیناتی کو 15 منٹ کے بیکار رہنے کے بعد روک دیا جاتا ہے (آپریٹر آپ کے گیم کو ایک مختلف ونڈو سیٹ کر سکتا ہے)۔ روک دیا گیا مسلسل سیشنز کنٹینر سے باہر کھڑے ہیں اور اسے برقرار نہیں رکھتے ہیں۔ ایک کے خلاف اگلے سیشن کی درخواست stopped تعیناتی اسے بیدار کرتی ہے (pending → صحت کا دروازہ → running); اس دوڑ کو کھونا ہے 503 کہتے ہیں کہ کھیل شروع ہو رہا ہے۔ صرف stopped یہ بیدار ہے راستہ - کبھی نہیں failed.

ڈیزائن POST /sessions بحالی اور اسنیپ شاٹ کیڈینس گیم پروٹوکول کے حصے کے طور پر، نہ کہ بطور اختیاری اصلاح

گیم کا مالک پھنسے ہوئے سیشنوں کی فہرست بنا اور ختم کر سکتا ہے: GET/DELETE /api/v1/me/github-games/{id}/sessions[/{sessionId}].

آپ کے سرور کی آؤٹ پٹ اور کریش رپورٹس

گیم کے مالک کے طور پر آپ پڑھ سکتے ہیں کہ آپ کے سرور نے کیا پرنٹ کیا، اور جب یہ نیچے چلا گیا تو کیا ہوا:

طریقہ راستہ تفصیل
حاصل کریں۔ /api/v1/me/github-games/{id}/container/logs?tail=N حالیہ پیداوار: { source, deploymentStatus, capturedAt, truncated, logs }
حاصل کریں۔ /api/v1/me/github-games/{id}/container/crashes?page=&pageSize= کریش ریکارڈز، سب سے نئے پہلے
حاصل کریں۔ /api/v1/me/github-games/{id}/container/crashes/{crashId} ایک کریش ریکارڈ، آؤٹ پٹ کیپچر کے ساتھ
  • نوشتہ جات چلتے ہوئے سرور سے براہ راست آئیں (source: "live")، تازہ ترین رکھی گئی، 500 لائنوں تک اور 256 KiB بطور ڈیفالٹ۔ جب کچھ بھی نہیں چل رہا ہے تو آپ کو آخری حادثے پر آؤٹ پٹ حاصل ہوتا ہے۔ (source: "last_crash")۔ ایک گیم جس کا بیک اینڈ ایک اسکرپٹ ہے، یا جس میں کوئی نہیں ہے، ملتا ہے۔ 409.
  • حادثے کا ریکارڈ لکھا جاتا ہے جب بھی آپ کا سرور کریش ہوتا ہے، جواب دینا بند کر دیتا ہے، وقت ختم ہو جاتا ہے۔ سٹارٹ اپ یا شروع ہونے میں ناکام ہو جاتا ہے — کنٹینر کو ہٹانے سے پہلے۔ اس میں قسم کا، ایگزٹ کوڈ ہوتا ہے، امیج ڈائجسٹ، دوبارہ شروع کی گنتی، متاثرہ سیشنز، اور آپ کے سرور کا آخری 64 KiB آؤٹ پٹ۔ دی 50 تازہ ترین 30 دنوں کے لیے رکھے گئے ہیں۔
  • رازوں سے پردہ اٹھایا جاتا ہے۔ آپ کے سرور کی انووک کلید، ریفریش کی اور کوئی بھی سرور ٹوکن بطور ظاہر ہوتا ہے۔ [redacted]. آپ کا اپنا container.env.* اقدار پرنٹ کے طور پر ظاہر ہوتی ہیں - لاگ ان نہ کریں جو آپ نہیں کریں گے۔ ذخیرہ کرنا چاہتے ہیں؟

آپریٹرز ان حدود میں سے ہر ایک کو، فی گیم تبدیل کر سکتے ہیں۔

  • کامیابیاں - کھلاڑی کا سامنا کامیابی کو پڑھتا ہے اور اطلاعات

مشترکہ API کنونشنز جوابی تجزیہ، ٹائم اسٹیمپ، صفحہ بندی، اور دوبارہ کوششوں کی وضاحت کریں۔
