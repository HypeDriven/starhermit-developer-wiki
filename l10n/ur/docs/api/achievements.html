کامیابیاں

ایک کارنامہ بالکل اسی سے تعلق رکھتا ہے۔ ایک مالک، اور مالک فیصلہ کرتا ہے کہ اسے غیر مقفل کرنے کی اجازت کسے ہے:

مالک کی طرف سے اعلان کیا کی طرف سے کھلا کے لیے استعمال کریں۔
ایک مستند کھیل game.achievements اسکرپٹ میں، یا achievements ایک کنٹینر سے /describe — یا گیم کے مالک کی طرف سے کے ذریعے /me/github-games/{id}/achievements صرف گیم کا سرور رن ٹائم - سرور مستند a کے ساتھ کھیل server= سکرپٹ یا container.image= پسدید
ایک کیٹلاگ کا عنوان (SoftwareTitle) ایک پبلشر، کے ذریعے پبلشر API کھلاڑی کا کلائنٹ، بذریعہ POST /api/v1/me/achievements/unlock (استحقاق درکار ہے) تقسیم شدہ عنوانات جن کا کلائنٹ واحد چیز ہے جو جانتا ہے کہ کھلاڑی نے کچھ کمایا ہے۔

دونوں باہمی طور پر خصوصی ہیں اور پلیٹ فارم تقسیم کو نافذ کرتا ہے:

  • POST /api/v1/me/achievements/unlock کھیل کے دائرہ کار میں کامیابیوں سے انکار کرتا ہے۔ - ایک کلائنٹ کبھی بھی دعوی نہیں کرسکتا۔
  • پبلشر CRUD اینڈ پوائنٹس ان سے بھی انکار کرتے ہیں۔ آپ کو اپنے اپنے کھیل کے لیے پبلشر کی ضرورت نہیں ہے: جیسے اس کے مالک آپ ہیں اس کے ناشر، اور آپ اس کے ذریعے اس کی کامیابیوں کا نظم کرتے ہیں۔ مالک کے اختتامی نکات اس کے بجائے

بنیادی URL: https://api.starhermit.com. تمام راستے نیچے ہیں۔ /api/v1/....

طریقہ راستہ تصنیف تفصیل
حاصل کریں۔ /api/v1/games/{slug}/achievements اٹھانے والا ایک مستند گیم کی کامیابیاں + کال کرنے والے کی غیر مقفل حالت
حاصل کریں۔ /api/v1/me/github-games/{id}/achievements JWT (کھیل کا مالک) آپ کے کھیل کی ہر کامیابی، اس کے ساتھ origin اور گنتی کو غیر مقفل کریں۔
پوسٹ /api/v1/me/github-games/{id}/achievements JWT (کھیل کا مالک) اپنے گیم کے لیے ایک کارنامہ تخلیق کریں → 201
ڈالو /api/v1/me/github-games/{id}/achievements/{achievementId} JWT (کھیل کا مالک) آپ کے بنائے ہوئے ایک کو اپ ڈیٹ کریں۔
حذف کریں۔ /api/v1/me/github-games/{id}/achievements/{achievementId} JWT (کھیل کا مالک) جسے آپ نے بنایا ہے اسے حذف کریں اور کسی نے ان لاک نہیں کیا → 204
حاصل کریں۔ /api/v1/software/{titleId}/achievements گمنام کیٹلاگ کے عنوان کی کامیابی کی تعریف
حاصل کریں۔ /api/v1/me/achievements?titleId= جے ڈبلیو ٹی کال کرنے والے کے ان لاک (تمام مالکان، یا ایک عنوان)
پوسٹ /api/v1/me/achievements/unlock جے ڈبلیو ٹی کلائنٹ کا دعوی کردہ غیر مقفل — صرف کیٹلاگ کے عنوانات

غلطیوں کو دفاعی طور پر پڑھیں جیسا کہ میں بیان کیا گیا ہے۔ API کنونشنز. POST /me/achievements/unlock اس کی واپسی 400 سادہ متن کے طور پر وجہ.

سرور سے مستند گیم کی کامیابیاں

یہ طریقہ کار ہے۔ کوئی بھی گیم کو اس وقت استعمال کرنا چاہئے جب اس میں اسکرپٹ یا کنٹینر بیک اینڈ ہو۔ دی سرور رن ٹائم واحد مصنف ہے۔ اس کی توثیق ہونی چاہیے کہ کھلاڑی نے ہر ایک انلاک حاصل کیا ہے۔ مسترد کرنا اکیلے براہ راست API گذارشات ترمیم شدہ کلائنٹ کے ذریعہ رپورٹ کردہ واقعات کی توثیق نہیں کرتی ہیں۔

1. اپنی اسکرپٹ میں ان کا اعلان کریں۔

ایک جامد شامل کریں۔ achievements کے لئے صف game اعتراض - دیکھیں گیم اسکرپٹس - کامیابیاں مکمل معاہدے کے لیے:

globalThis.game = {
  achievements: [
    { key: "first-win",  name: "First Win",  description: "Win a match.", points: 10 },
    { key: "flawless",   name: "Flawless",   description: "Win without conceding.",
      points: 50, secret: true, icon: "https://cdn.example/flawless.png" }
  ],
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

اعلامیہ پڑھا جاتا ہے۔ جب گیم شائع یا اپ ڈیٹ کیا جاتا ہے۔ اس کے ذخیرے سے۔ تبدیلی کو لاگو کرنے کے لیے ایک اپ ڈیٹ شائع کریں۔

2. انہیں کسی بھی لائف سائیکل ہک سے غیر مقفل کریں۔

واپسی ایک achievements نقشہ — صارف کی شناخت → کلیدوں کی صف — سے createSession, onPlayerMessage, یا onTick:

return {
  ok: true,
  sessionState: state,
  achievements: { [winnerId]: ["first-win", "flawless"] },
  result: { kind: "win", winner: winnerId }
};

انلاک ہیں۔ کمزور - پلیئر کے پاس پہلے سے موجود کلید کو واپس کرنا ایک نہیں ہے، لہذا اسکرپٹ ہو سکتا ہے۔ نقل کے بارے میں فکر کیے بغیر ہر ٹک پر کامیابی کا دوبارہ دعوی کریں۔

3. کھلاڑی کو گیم پلے ساکٹ پر مطلع کیا جاتا ہے۔

ہر نیا عطا کردہ انلاک صرف کمانے والے کھلاڑی کو دیا جاتا ہے۔ ws/v1/games، اس کے اپنے فریم کے طور پر قسم (پلیٹ فارم کی سچائی، اسکرپٹ سے متعلق نہیں۔ game پیغام):

{
  "type": "achievement",
  "data": {
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "points": 10,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
}

سے دیے گئے انلاک createSession کسی کے پاس ساکٹ ہونے سے پہلے ہی برقرار رہتے ہیں، لہذا وہ ساتھ پہنچ جاتے ہیں۔ کوئی فریم نہیں — انہیں لوڈ پر لسٹ اینڈ پوائنٹ سے پڑھیں۔

کنٹینر بیک اینڈز

ایک کنٹینر اسی کامیابی کے شعبوں کا اعلان کرتا ہے۔ GET /describe، پھر ایک بھیجتا ہے۔ achievements اس کے کنٹرول WebSocket پر پیغام۔ پلیٹ فارم ایک ہی کلید کا اطلاق کرتا ہے، شریک، کمزوری، اور ترسیل کے قواعد۔ دیکھیں کنٹینر گیم سرورز.

GET /api/v1/games/{slug}/achievements

کال کرنے والے کی غیر مقفل حالت کے ساتھ، گیم اعلان کردہ ہر کامیابی۔ 404 اگر سلگ نہیں ہے مستند گیم کی تعریف (اسکرپٹ یا کنٹینر بیک اینڈ کے بغیر ایک گیم کی کوئی گیم ملکیت نہیں ہے۔ کامیابیاں - دیکھیں کون سے گیمز اسے استعمال کر سکتے ہیں۔)۔ اس وقت تک خفیہ کامیابیاں پوشیدہ رہتی ہیں۔ کالر ان کو کھولتا ہے۔ تخلیق کی طرف سے حکم دیا، پھر کلید.

[
  {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "secret": false,
    "points": 10,
    "unlocked": true,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
]

مکمل صارف JWT یا گیم اسکوپڈ لانچ ٹوکن کے ساتھ کام کرتا ہے۔

کون سے گیمز اسے استعمال کر سکتے ہیں۔

میکانزم ایک گیم کے لیے دستیاب ہے جو یا تو a کا اعلان کرتا ہے۔ server= سکرپٹ یا a container.image= میں پسدید starhermit.txt. دی سرور رن ٹائم انلاک کو مستند بناتا ہے۔ اسکرپٹ کی حمایت یافتہ استعمال کے معاملات میں شامل ہیں:

  • اسکرپٹڈ پلیٹ فارم گیمز - سے انلاک onPlayerMessage / onTick جیسا کہ میچ ختم ہوتا ہے۔
  • کمرے سے منسلک ریئل ٹائم گیمز — a ریئل ٹائم کمرہ a کے لیے a کے ساتھ کھیل server= اسکرپٹ جب شروع ہوتا ہے تو ایک پابند سیشن بناتا ہے، اور اس کا ہر ہک سیشن کامیابیاں دے سکتا ہے۔
  • سنگل پلیئر اور پریکٹس گیمز - AI سیٹ کے خلاف ایک سیشن (POST /api/v1/games/{slug}/sessions/ai) ایک ہی اسکرپٹ اور وہی انلاک پاتھ چلاتا ہے۔
  • ریئل ٹائم گیمز کی میزبانی کریں۔ - ایک کھیل جس کا گیم پلے اوپر چلتا ہے۔ ریئل ٹائم روم بائنری چینل اب بھی سرور اسکرپٹ بھیج سکتا ہے۔ مکمل طور پر اس کی کامیابی کے اختیار کے طور پر: روم اسٹارٹ باؤنڈ سیشن اور اسکرپٹ تخلیق کرتا ہے۔ سے ایوارڈز createSession / onTick / پائیدار cmd پیغامات بھیجے گئے ws/v1/games جبکہ تیز راستہ بہہ رہا ہے۔ ws/v1/realtime.

کنٹینر کی حمایت یافتہ سیشن اپنے پروٹوکول کے ذریعے کامیابیوں کا اعلان اور عطا بھی کر سکتے ہیں۔ ایک کھیل کے ساتھ کوئی مستند پس منظر (ایک خالص براؤزر گیم، یا صرف پر بنایا گیا ہے۔ ہم مرتبہ ریلے) کوئی سرور سے مستند غیر مقفل راستہ نہیں ہے۔ کلائنٹ کا دعوی کردہ انلاکنگ صرف اس کے لیے دستیاب ہے۔ ذیل میں کیٹلاگ سے تقسیم شدہ عنوانات۔

حدود اور قواعد

قاعدہ قدر
فی گیم کامیابیوں کا اعلان کیا۔ 100 (اضافی نظر انداز)
کامیابی کی کلید کی لمبائی 128 حروف
انلاک کیز فی پلیئر، فی دعوت قبول کی جاتی ہیں۔ 32
points 0-10000 تک بند; پہلے سے طے شدہ 0
name کے لیے ڈیفالٹس key جب چھوڑ دیا جاتا ہے
  • ایک خراب ڈیکلریشن اندراج ہے۔ چھوڑ دیا. ایک اسکرپٹ جو اندازہ کرنے میں ناکام ہوتا ہے وہ خالی نکلتا ہے۔ فہرست کنٹینر کا اعلامیہ صحت کی جانچ سے گزرنے کے بعد پڑھا جاتا ہے۔ کے ساتھ تصدیق کریں۔ GET /api/v1/games/{slug}/achievements تعیناتی کے بعد.
  • کی طرف سے تعریفیں upsert key. ایک کلید جو آپ کے بیک اینڈ کا اعلان کرنا بند کر دیتی ہے حذف ہو جاتی ہے۔ صرف اس صورت میں جب کسی کے پاس نہ ہو۔ اسے کھول دیا - کمائی ہوئی تاریخ کبھی تباہ نہیں ہوتی۔ API کے ذریعے مالک کی تخلیق کردہ کامیابیاں اس سے کبھی چھوا نہیں جاتا ہے: صرف اعلان کردہ افراد ہی صلح کر رہے ہیں۔
  • سیشن کے شریک نہ ہونے والے صارفین اور AI سیٹ کے لیے ان لاک کو نظر انداز کر دیا جاتا ہے۔

دوسرے کھیلوں سے کامیابیاں

ایک گیم اس کی بنیاد پر خصوصیات کھول سکتی ہے کہ کھلاڑی نے کیا ان لاک کیا ہے۔ ایک اور کھیل: ایک سیکوئل اعزاز کاسمیٹکس کا اشتراک کرنے والی سیریز میں اصل، یا گیمز۔ ان کو پڑھنے کے دو طریقے ہیں۔

آپ کے سرور سے: ctx.linkedAchievements (قابل اعتماد)

اپنے اسکرپٹ میں اپنے دوسرے اعلانات کے آگے دیگر گیمز کے نام رکھیں:

globalThis.game = {
  linkedAchievements: ["83fd04b1-3cbe-4b09-a251-3733ad4b9d94"], // other games' slugs (uids)
  // ...
};

ایک کنٹینر وہی واپس کرتا ہے۔ linkedAchievements سے صف GET /describe. ہر اسکرپٹ invocation's ctx پھر ان گیمز میں ہر انسانی کھلاڑی کی غیر مقفل کیز اپنے ساتھ رکھتا ہے:

ctx.linkedAchievements = {
  "7c9e6679-...": {                                   // player id
    "83fd04b1-3cbe-4b09-a251-3733ad4b9d94": ["first-win", "checkmate-10"]
  }
};
  • اسے دوبارہ پڑھا جاتا ہے۔ ہر دعا، تو دوسرے گیم کے وسط میچ میں حاصل کردہ ایک انلاک آن دیکھا جاتا ہے۔ اگلا ایک کنٹینر اسے کے ctx میں وصول کرتا ہے۔ POST /sessions، یعنی تخلیق اور پر بحال
  • زیادہ سے زیادہ 8 کھیل وہ اندراجات جو غیر خالی سٹرنگز، ڈپلیکیٹس، اور سلگس 100 سے زیادہ نہیں ہیں حروف کو چھوڑ دیا جاتا ہے. دوسرے اعلانات کی طرح یہ بھی پڑھا جاتا ہے جب کھیل شائع ہوتا ہے یا اپ ڈیٹ
  • ایک کھیل جو اعلان کرتا ہے کہ کچھ نہیں ملتا ہے۔ linkedAchievements فیلڈ اور کچھ بھی ادا نہیں کرتا ہے۔
  • اس راستے کو کسی بھی چیز کے لیے استعمال کریں جو پلیٹ فارم کو نافذ کرنا چاہیے، جیسے گیم پلے کو غیر مقفل کرنا یا گرانٹ دینا آپ کی اپنی کامیابی.

آپ کے کلائنٹ سے: GET /api/v1/games/{slug}/linked-achievements/{otherSlug}

کال کرنے والے کا اپنا ان لاک ہو جاتا ہے۔ otherSlug. اسے کسی اعلان کی ضرورت نہیں ہے، لہذا صرف براؤزر والا گیم جس میں کوئی نہیں۔ سرور اسے استعمال کرسکتا ہے، اور یہ لانچ ٹوکن کے ساتھ کام کرتا ہے۔ {slug}: دوسرے گیم کے اپنے اختتامی نکات اس ٹوکن سے دور رہیں۔

{
  "game": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "hidden": false,
  "unlocked": [
    { "key": "first-win", "unlockedAt": "2026-07-25T09:14:02Z" }
  ]
}

ایک کلائنٹ اس کے بارے میں جھوٹ بول سکتا ہے جو اسے موصول ہوا ہے، لہذا اسے UI اور کاسمیٹکس کے اشارے کے طور پر سمجھیں، ثبوت کے طور پر نہیں۔

جو انکشاف ہوا ہے۔

  • صرف اس گیم کی حالت کو غیر مقفل کریں جس کا آپ نے نام لیا ہے۔: چابیاں اور انلاک اوقات، کبھی نام، تفصیل یا دوسرے گیمز کی فہرست جو کھلاڑی نے کھیلی ہے۔ ایک خفیہ کارنامہ جو کھلاڑی نے کھولا ہے۔ شامل
  • ایک سلگ جو کسی گیم کے جوابات سے مماثل نہیں ہے جیسا کہ کوئی بھی چیز کھلا نہیں ہے۔
  • رازداری کا احترام کیا جاتا ہے۔ ایک کھلاڑی جس کی کامیابیوں کی رازداری ہے۔ Private ہے چھپا ہوا: غیر حاضر سے ctx.linkedAchievements، اور "hidden": true اختتامی نقطہ سے خالی فہرست کے ساتھ۔ پوشیدہ جیسا نہیں ہے "کوئی نہیں ہے"، تو اس کے ساتھ ایسا سلوک نہ کریں۔ FriendsOnly (پہلے سے طے شدہ) انکشاف کیا جاتا ہے، کیونکہ قاری کھلاڑی کے لیے کام کر رہا ہے۔

گیم کے مالک کی تخلیق کردہ کامیابیاں

کوڈ میں کامیابیوں کا اعلان کرنا اپنے گیم کو کچھ دینے کا واحد طریقہ نہیں ہے۔ اگر آپ a کے ساتھ ایک گیم کے مالک ہیں۔ server= سکرپٹ یا container.image= پسدید، آپ اس کے ذریعے کامیابیاں بھی بنا سکتے ہیں۔ API — جس طرح سے ایک پبلشر کیٹلاگ کے عنوان کے لیے کرتا ہے، بغیر کسی ناشر کے اکاؤنٹ یا اجازت کی ضرورت ہے۔ کھیل کا مالک ہونا گرانٹ کا پورا حصہ ہے۔ اسے استعمال کریں جب کوئی ڈیزائنر شامل کرنا یا دوبارہ لفظ کرنا چاہتا ہے۔ کوڈ میں تبدیلی کے بغیر کامیابیاں، یا جب آپ کا پسدید کلید دیتا ہے تو یہ اعلان نہیں کرتا۔

صرف آپ کے گیم کا سرور ہی انہیں غیر مقفل کر سکتا ہے۔، بالکل اعلان کردہ کی طرح: آپ کا اسکرپٹ کلید واپس کرتا ہے۔ میں achievements، یا آپ کا کنٹینر اسے کنٹرول چینل پر بھیجتا ہے۔ پر کچھ بھی نہیں بدلتا غیر مقفل کرنے کی طرف - چابیاں اس کے خلاف حل ہوجاتی ہیں۔ تمام گیم کی کامیابیوں کا، اعلان اور تخلیق کیا گیا۔

  • ایک اعلان کردہ کامیابی آپ کے کوڈ پر قائم رہتی ہے۔ ایک کلید بنانا گیم میں پہلے ہی واپسی ہے۔ 409, اور اسی طرح ترمیم کرنا یا حذف کرنا declared ایک - اگلی اپ ڈیٹ اسے آپ کے کوڈ کے طور پر واپس کر دے گی۔ اس کا اعلان کرتا ہے. اسے اپنی اسکرپٹ میں تبدیل کریں یا /describe اس کے بجائے
  • اگر آپ کا کوڈ بعد میں ایک کلید کا اعلان کرتا ہے جسے آپ نے یہاں بنایا ہے۔، اعلامیہ اس کامیابی کو لیتا ہے۔ زیادہ (origin بن جاتا ہے declared)۔ جن کھلاڑیوں نے اسے کمایا وہ اسے برقرار رکھتے ہیں۔
  • ایک کامیابی جسے کسی نے غیر مقفل کیا ہے اسے حذف نہیں کیا جا سکتا (409).
  • 404 اس کا مطلب ہے کہ کھیل آپ کا نہیں ہے۔ 409 سرور کے بارے میں پیغام کے ساتھ ان راستوں میں سے کسی پر بیک اینڈ کا مطلب ہے کہ گیم میں کوئی نہیں ہے — صرف براؤزر والے گیم میں کچھ بھی نہیں ہے جو اسے کھول سکتا ہے۔ کامیابی
