گٹ ہب گیمز

گٹ ہب ریپوزٹری سے ایک گیم شائع کریں۔ StarHermit، یا پہلے سے میزبان ویب گیم کو رجسٹر کریں۔ ریپوزٹری گیمز کے لیے، پلیٹ فارم پڑھتا ہے۔ starhermit.txt، ریپو کو کلون کرتا ہے، اور اس پر کام کرتا ہے۔ <slug>.starhermit.com. کیونکہ /api اور /ws اس ذیلی ڈومین سے پراکسیڈ ایک جیسے ہیں، پلیٹ فارم کی میزبانی والے گیم کی ضرورت ہے۔ کوئی CORS یا API بیس کنفیگریشن نہیں ہے۔. ایک پِنڈ کمٹ کنٹرول کرتا ہے کہ کون سا ریپوزٹری ورژن لائیو ہے۔ دی شطرنج کے حوالہ کا نفاذ اس طرح شائع کیا جاتا ہے اور ماڈل کی حوالہ مثال کے طور پر کام کرتا ہے۔

بنیادی URL: https://api.starhermit.com. تمام راستے نیچے ہیں۔ api/v1/... اور JWT کی ضرورت ہے جب تک کہ نوٹ نہ کیا جائے۔

میزبان کلائنٹ کی فائلیں اعلان کر سکتی ہیں۔ فولڈر کیشے کی زندگی بھر اور اضافی CORS ماخذ میں starhermit.txt. وہ پالیسیاں کلائنٹ فائلوں کے ساتھ شائع ہوتی ہیں۔ ایک مینی فیسٹ فری انضمام برقرار رہتا ہے۔ موجودہ ترتیبات، جبکہ ایک فراہم کردہ مینی فیسٹ ان کی جگہ لے لیتا ہے۔

منشور: starhermit.txt

جگہ starhermit.txt ریپو روٹ پر۔ فارمیٹ: key=value لائنیں # ایک تبصرہ شروع کرتا ہے.

name=Your Game
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html        # repo-relative HTML entry
cover=art/cover.png      # optional cover art for the library tile; or an https:// URL
description=One-line pitch\nSecond line   # optional; or description.file=DESCRIPTION.md
release_notes.file=CHANGELOG.md          # optional; or release_notes=inline text
owner=<starhermit user id>  # UUID from GET /api/v1/me; do not use username/nickname
# Choose at most one authoritative backend, or omit both for a browser-only game:
server=server.js         # sandboxed JavaScript; see game-scripts.md
# container.image=ghcr.io/owner/game@sha256:<64 lowercase hex>; see container-games.md

control.up=KeyW+ArrowUp | Move forward
control.shoot=Space | Shoot
  • نہیں ہے slug کلید: پلیٹ فارم ایک uid تفویض کرتا ہے اور اسے دونوں ذیلی ڈومین کے طور پر استعمال کرتا ہے (<uid>.starhermit.com) اور گیم API نام کی جگہ (/api/v1/games/<uid>/…).
  • cover (عرف cover_art, coverart) گیم کی لائبریری ٹائل پر دکھایا گیا آرٹ ورک ہے: لانچ فائل سے متعلق ایک راستہ، یا مطلق https:// URL اختیاری - ایک کے بغیر ٹائل آپ کی سائٹ کا فیویکن دکھاتا ہے۔ ہر تعیناتی پر دوبارہ پڑھیں، لہذا لائن کو تبدیل کرنے سے کور بدل جاتا ہے۔ دیکھیں کور آرٹ ٹائل فصلوں کے لئے.
  • description / release_notes (یا description.file / release_notes.file، کون سا نام a .md/.markdown/.txt مینی فیسٹ سے متعلق فائل) آپ کے گیم کے لیے اختیاری متن ہیں۔ وہ ہر تعیناتی پر دوبارہ پڑھے جاتے ہیں۔ cover. دیکھیں تفصیل اور ریلیز نوٹس.
  • server ایک سینڈ باکس شدہ جاوا اسکرپٹ پسدید کا اعلان کرتا ہے۔ دیکھیں game-scripts.md.
  • container.image کنٹینر پسدید کا اعلان کرتا ہے؛ دیکھیں container-games.md. اس کا ڈائجسٹ پن ہونا ضروری ہے، تصدیق شدہ GitHub کے مالک کے نام کی جگہ پر اجازت یافتہ رجسٹری پر میزبانی کی گئی ہے، اور اس کے ساتھ ہو سکتا ہے container.port, container.health, container.memory_mb, container.cpu، اور غیر خفیہ container.env.* اقدار
  • دونوں بیک اینڈ کیز خالص براؤزر گیم کے لیے اختیاری ہیں، لیکن وہ ایک دوسرے کے ساتھ باہمی طور پر خصوصی ہیں۔

ڈیفالٹ کنٹرول بائنڈنگز

ایک گیم صفر یا اس سے زیادہ ڈیسک ٹاپ براؤزر کی کارروائیوں کا اعلان کر سکتا ہے:

control.<action>=<code>[+<code>...][ | <label>]
  • اعمال چھوٹے حروف میں ہیں۔ [a-z0-9_]{1,32} شناخت کنندگان اور مینی فیسٹ آرڈر کو برقرار رکھیں۔
  • کوڈز ہیں۔ KeyboardEvent.code اقدار + ایک عمل کے لیے متبادل چابیاں الگ کرتا ہے۔
  • اختیاری لیبل کو کنٹرول ری میپنگ UIs میں دکھایا گیا ہے اور ایکشن آئی ڈی پر ڈیفالٹ ہے۔
  • ایک مینی فیسٹ 32 ایکشنز اور فی ایکشن 4 کوڈز تک کا اعلان کر سکتا ہے۔ ایک کوڈ کی طرف سے استعمال نہیں کیا جا سکتا دو اعمال. غلط کنٹرول لائنوں کو نظر انداز کر دیا گیا ہے۔
  • نمبر کے ساتھ گیمز control.* اعلانات کا کوئی کنٹرول API/UI نہیں ہے (404 "This game declares no controls.")۔ اعلانات ہر شائع شدہ تعمیر سے دوبارہ پڑھے جاتے ہیں - ہر ایک تعیناتی، فولڈر اپ لوڈ اور بنڈل پش کو تبدیل کرنا۔ مرحلہ وار: ٹیوٹوریل: اپنے گیم میں کنٹرولز شامل کریں۔.

کھلاڑی ان ڈیفالٹس کو فی گیم کے ذریعے اوور رائیڈ کر سکتے ہیں۔ گیمز API کو کنٹرول کرتا ہے۔.

ایک گیم رجسٹر کریں۔

POST /api/v1/me/github-games

{
  "repoUrl": "https://github.com/HypeDriven/starhermit-chess",
  "displayName": "StarHermit Chess",
  "launchPath": "index.html"
}

اپنے تاریخی نام کے باوجود، repoUrl تین لانچ ذرائع کو قبول کرتا ہے:

  1. A github.com/<owner>/<repo> ذخیرہ پسدید اس کا مینی فیسٹ پڑھتا ہے اور اسے تعینات کر سکتا ہے۔ StarHermit ہوسٹنگ کے لیے۔
  2. پہلے سے میزبان GitHub صفحات کا URL جیسے https://owner.github.io/game/. مخزن شناخت کا اندازہ URL سے لگایا گیا ہے۔ URL بذات خود لانچ کیا گیا ہے، بغیر کسی کلون یا انسٹال کے۔
  3. کوئی اور عوام http:// یا https:// میزبان ویب گیم یو آر ایل۔ یہ براہ راست شروع کیا جاتا ہے اور GitHub ملکیت کے دعوی میں حصہ نہیں لیتا ہے۔
  • displayName اور launchPath اختیاری فال بیکس ہیں۔ وہ تھرڈ پارٹی ریپو کے لیے مفید ہیں۔ قابل اعتماد مینی فیسٹ میٹا ڈیٹا کے بغیر؛ ایک براہ راست میزبانی شدہ URL بذات خود لانچ کا مقام ہے۔
  • تصدیق شدہ ذخیرہ کے مالکان کے لیے پلیٹ فارم کی توثیق ہوتی ہے۔ starhermit.txt.
  • ایک اختیاری۔ server= سکرپٹ یا container.image= پسدید دفعات ایک مستند کھیل؛ دیکھیں game-scripts.md اور container-games.md. starhermit.com پر کسی بھی سائن ان صارف کے لیے کنٹینر ہوسٹنگ کھلا ہے۔ ایک خود میزبان تعیناتی اسے آپریٹر کی اجازت کی فہرست تک محدود کر سکتی ہے۔
  • ایک اعلان کردہ سرور پسدید کو ایک ثابت شدہ مالک کی ضرورت ہے۔ ایک ریپو جمع کرانا جو اعلان کرتا ہے۔ server= یا container.image= GitHub-login کے بغیر یا owner= ثبوت ہے 403 (دونوں ثبوتوں کا نام دینا)، صرف براؤزر کی فہرست نہیں ہے جو بیک اینڈ ہونے کا بہانہ کرتی ہے۔
  • حدود: فی صارف 100 گیمز (آپریٹر کے لیے اوور رائیڈ ایبل فی اکاؤنٹ)۔ ڈپلیکیٹ ریٹرن رجسٹر کرنا 409.

رجسٹریشن/تعیناتی کے حالات میں شامل ہیں: InvalidUrl, LimitReached, Duplicate, MissingManualMetadata, MissingStarhermitTxt, InvalidLaunchPath, InvalidServerScriptPath, InvalidContainerImage, ServerProvisionConflict, RemovedByOwner.

غلطیاں معیاری شکل کا استعمال کرتی ہیں:

مقامی فولڈر سے ایک گیم شامل کریں۔

POST /api/v1/me/github-games/upload → 201

یو آر ایل کو رجسٹر کرنے کا ہم منصب: کوئی ذخیرہ نہیں ہے، اور کچھ بھی کلون نہیں ہے۔ فولڈر ایک کے طور پر سفر کرتا ہے .tar.gz درخواست کے باڈی پر اور پلیٹ فارم میزبانی کرتا ہے کہ اس میں کیا ہے۔ وہی آرکائیو فارمیٹ کے طور پر ایک بنڈل کو آگے بڑھانا، لہذا ایک ہی پیکیجنگ دونوں کے لئے کام کرتی ہے۔

تخلیق کردہ گیم میں ایک ہے۔ gameSlug شروع سے، چاہے یہ سرور کا اعلان کرے یا نہ کرے، تو a براؤزر صرف اپ لوڈ استعمال کر سکتے ہیں۔ کنٹرول کرتا ہے, فی کھلاڑی کی ترتیباتاس کا کلاؤڈ سیو سلاٹ, حقیقی وقت کے کمرے اور کسی دوسرے گیم کی طرح ٹوکن لانچ کریں۔

  • آرکائیو پر مشتمل فائل کا نام دینے والے لانچ پاتھ سے انکار کر دیا گیا ہے (422) جبکہ اپ لوڈ ہے۔ ہر کھلاڑی کے لیے 404 بننے کے بجائے اب بھی اسٹیجنگ میں ہے۔

اگر محفوظ شدہ دستاویزات کی starhermit.txt سرور لاجک، اپ لوڈ کا اعلان کرتا ہے۔ اسے بھی فراہم کرتا ہے — وہی چیز جو ریپوزٹری فلو کرتا ہے، بغیر کسی ریپوزٹری کے۔ ایک چنو انداز دونوں کا اعلان کرنے سے انکار کر دیا گیا ہے۔

اعلامیہ کیا ہوتا ہے
server=path/to/server.js ایک اسکرپٹ پسدید۔ فائل سفر کرتی ہے۔ اس فولڈر کے اندر جو آپ اپ لوڈ کرتے ہیں۔، لہذا اس کا ماخذ محفوظ شدہ دستاویزات سے سیدھا پڑھا جاتا ہے — لانے کے لئے کچھ نہیں ہے۔ دیکھیں game-scripts.md.
container.image=name@sha256:… ایک کنٹینر پسدید، ہمیشہ کی طرح ڈائجسٹ-پِن۔ دیکھیں container-games.md. تصویر کو خود بعد میں دھکیل دیا جاتا ہے۔ /{id}/bundle.

یہاں انکار پوری تخلیق کو ناکام بناتا ہے - کوئی بھی آدھی بنی گیم قطار زندہ نہیں رہتی ہے:

  • server= کسی فائل کا نام دینا جو آرکائیو پر مشتمل نہیں ہے۔
  • server= کلائنٹ فائلوں کے باہر اشارہ کرنا (../).
  • دونوں کا اعلان server= اور container.image=.
  • ایسے کنٹینر کا مطالبہ کرنا جہاں کنٹینرز غیر فعال ہیں، یا کسی مالک سے ان کے لیے منظور شدہ نہیں۔

POST /api/v1/me/github-games/{id}/bundle StarHermit سے پوچھے بغیر بلٹ آؤٹ پٹ شائع کرتا ہے۔ اسے دوبارہ کلون کریں. کال کرنے والے کو رجسٹرڈ گیم کا مالک ہونا چاہیے۔ بھیجیں۔ .tar.gz بائٹس براہ راست - نہیں ملٹی پارٹ فارم ڈیٹا — کے ساتھ Content-Type: application/gzip:

client/            optional static client files; must include the registered launch file
server/image.tar   optional output from `docker save`
starhermit.txt     optional manifest copy for bundle portability
remove.txt         merge only: client-relative paths to delete, one per line

کم از کم client/ یا server/image.tar موجود ہونا ضروری ہے (ایک انضمام صرف ہو سکتا ہے remove.txt)۔ کلائنٹ فائلوں کو جوہری طور پر تبدیل کیا جاتا ہے۔ اے سرور امیج کو لوڈ کیا جاتا ہے، پلیٹ فارم کے ذریعے ڈائجسٹ پن کیا جاتا ہے، اور کنٹینر کی تعیناتی کو قطار میں کھڑا کیا جاتا ہے۔ اس تصویر پر دوبارہ شروع کریں. اپ لوڈ کردہ تصویر مینی فیسٹ کے رجسٹری ریفرنس پر فوقیت رکھتی ہے، اور ایک سے زیادہ server= لائن دونوں کا اعلان کرنے والا ایک منشور server= اور container.image= انکار کر دیا ہے کسی بھی چیز کو لوڈ کرنے سے پہلے. آرکائیو میں موجود کسی بھی چیز کو نظر انداز کر دیا گیا ہے۔

تصویر اپ لوڈ کرنا بذات خود اعلان ہے۔ اگر گیم کا ابھی تک کوئی سرور بیک اینڈ نہیں ہے - ایک اپ لوڈ کردہ فولڈر جس نے اعلان کیا کہ کوئی نہیں — آگے بڑھا رہا ہے۔ server/image.tar صرف ڈائجسٹ سے ایک کی فراہمی بھری ہوئی، کے تحت gameSlug کھیل پہلے سے ہی ہے. آپ کو a میں ڈائجسٹ پن والی تصویر کا نام دینے کی ضرورت نہیں ہے۔ سب سے پہلے مینی فیسٹ، جو سرکلر تھا: اس سے پہلے کہ وہ تصویر حاصل کر سکے، تعریف کا موجود ہونا ضروری ہے، اور تصویر ہی واحد چیز تھی جو اسے بیان کر سکتی تھی۔

ایک دوبارہ دھکا لاگو ہوتا ہے کنٹینر knobs اس کے مینی فیسٹ کا اعلان کرتا ہے، اور صرف وہی۔ شامل کریں۔ starhermit.txt ایک تبدیل کے ساتھ بنڈل میں container.port, container.health, container.memory_mb یا container.cpu اور تعیناتی اسے دوبارہ شروع کرنے پر اٹھا لیتی ہے۔ ایک دستک چھوڑ دو اور یہ جو کچھ بھی آپ نے آخری بار سیٹ کیا اسے رکھتا ہے۔ مینی فیسٹ کو مکمل طور پر چھوڑ دیں اور تعیناتی کے بارے میں کچھ بھی نہیں۔ تصویر کے علاوہ تبدیلیاں۔

StarHermit کلائنٹس آپ کے لیے ایک فولڈر سے یہ بنڈل بناتے ہیں۔ یا ایک .tar:

  • کلائنٹ کی فائلیں۔ - گیم کا ڈسٹری بیوشن فولڈر، یا a .tar اس کا ایک فولڈر کے نیچے پیک کیا گیا ہے۔ client/; a .tarکے اندراجات کو دوبارہ وہاں رکھا گیا ہے (ایک محفوظ شدہ دستاویزات پہلے سے ہی نیچے ہے۔ client/ رہ گیا ہے تنہا)۔ صرف ustar — GNU طویل نام اور PAX آرکائیوز سے انکار کر دیا گیا ہے، کیونکہ ان کو دوبارہ گھر کرنے کا مطلب ہے مندرجہ ذیل اندراج کو نام دینے والے میٹا ڈیٹا بلاکس کو دوبارہ لکھنا۔
  • سرشار سرور - سرور کا ڈسٹری بیوشن فولڈر، یا docker save .tar اپنے طور پر ایک فولڈر سے صرف مینی فیسٹ اور image.tar اپ لوڈ کیے گئے ہیں: تصویر میں پہلے سے ہی آپ کی سرور کی اپنی فائلیں ہیں، لہذا باقی پیک کرنے سے پلیٹ فارم کو ضائع کرنے کے لیے گیگا بائٹس بھیجے جائیں گے۔

دونوں صورتوں میں starhermit.txt ڈائیلاگ میں قابل تدوین ہے۔ جو بھی ہو۔ picked build کھیتوں کو پہلے سے بھرتا ہے، اور جو کچھ بھی ان کے پاس ہوتا ہے وہ بنڈل روٹ پر لکھا جاتا ہے۔ بغیر کسی مینی فیسٹ کے ایک تعمیر قابل اشاعت ہے، اور ایک جو بطور a کے طور پر بھیجی جاتی ہے۔ .tar اب بھی اس کا اظہار ہو سکتا ہے اپ ڈیٹ

جزوی اپ ڈیٹس: ?mode=merge

ایک دھکا ہے a تبدیل کریں جب تک کہ آپ دوسری صورت میں نہ پوچھیں: آرکائیو سارا کھیل ہے، اور کچھ بھی نہیں ہے۔ یہ چلا گیا ہے. ?mode=merge (HTTP اور اپ لوڈ ساکٹ یکساں) اسے بناتا ہے۔ پیچ لائیو کلائنٹ کے فائلیں - ایک فائل فکس کے لیے غیر تبدیل شدہ اثاثوں کے گیگا بائٹس کو دوبارہ اپ لوڈ کرنے کا جواب۔

printf '%s\n' '# one client-relative path per line; a directory removes everything under it' \
    'assets/old-music.ogg' 'levels/cut/' > remove.txt
tar czf patch.tar.gz client/index.html client/js/app.js remove.txt

  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/gzip" \
  --data-binary @patch.tar.gz

کے ساتھ mode=merge:

  • کے تحت فائلیں client/ شامل یا اوور رائٹ کیا جاتا ہے۔
  • ایک جڑ میں راستے remove.txt (# تبصرے ایک ڈائریکٹری اپنے پورے ذیلی درخت کو ہٹا دیتی ہے) کو حذف کر دیا جاتا ہے۔
  • ہر دوسری لائیو فائل بالکل ویسے ہی رہتی ہے۔

ضم شدہ درخت کو ایک کاپی کے طور پر اسٹیج کیا جاتا ہے اور جوہری طور پر تبدیل کیا جاتا ہے - کھلاڑی پرانا کھیل یا بالکل نیا، کبھی مکس نہیں۔ نتیجہ کی طرف سے پابند ہے کھیل کی الاؤنس، اپ لوڈ کا نہیں، تو ایک کھیل ایک وقت میں ایک چھوٹے سے پیچ کی حد سے آگے نہیں بڑھ سکتا۔ انضمام صرف کلائنٹ فائلوں کے بارے میں ہے۔ a server/image.tar بالکل اسی طرح بھری ہوئی ہے جیسے بدلنے پر۔ ایک پیچ جس میں نمبر ہے۔ starhermit.txt پتے کور آرٹ جیسا تھا.

انضمام سے انکار کر دیا گیا ہے (409/422، کچھ بھی نہیں بدلتا ہے) جب گیم میں ابھی تک کچھ بھی شائع نہیں ہوا ہے، جب یہ لانچ فائل کو ہٹا دے گا، یا کب remove.txt کھیل سے باہر پوائنٹس۔ اے remove.txt ایک میں سادہ بدلنے سے بھی انکار کر دیا گیا ہے (422) کیونکہ وہاں اس کا مطلب صرف وہی ہو سکتا ہے جو آپ نے نہیں کیا۔ ارادہ mode ہونا ضروری ہے replace (پہلے سے طے شدہ) یا merge; کچھ اور ہے 400.

ایک ہی پیرامیٹر ساکٹ پر کام کرتا ہے: ws/v1/game-upload?gameId=…&mode=merge. دی ready فریم کے طور پر اس کی بازگشت "apply":"merge".

اینڈ پوائنٹ ایک موجودہ رجسٹرڈ گیم کو اپ ڈیٹ کرتا ہے۔ یہ کبھی بھی گیم ریکارڈ نہیں بناتا - اس کے لیے دیکھیں مقامی فولڈر سے گیم شامل کرنا. یہ کر سکتے ہیں کھیل کی فراہمی سرور پسدید، سرور کی تصویر کو کسی گیم میں لوڈ کرنے کے ضمنی اثر کے طور پر جس میں کوئی نہیں تھا۔ دیکھیں سرشار سرور پبلشنگ ٹیوٹوریل.

CI/CD سے اپ لوڈ کریں۔

ایک انٹرایکٹو OAuth ٹوکن کو مخزن خفیہ میں نہ رکھیں۔ OAuth کے ذریعے ایک بار سائن ان کریں اور استعمال کریں۔ اس سیشن میں ایک علیحدہ لیبل والی تعیناتی کلید شامل کرنا ہے۔ POST /api/v1/me/public-keys. سی آئی نوکری پھر دستخط کر سکتے ہیں /auth/public-key/challengeپر اس کا تبادلہ کریں۔ /auth/public-key/complete، اور استعمال کریں۔ اس بنڈل کے اختتامی نقطہ پر 15 منٹ تک رسائی کا ٹوکن واپس آیا۔

تعیناتی کلید اپنے اکاؤنٹ کے طور پر کام کرتی ہے، اس لیے اس اکاؤنٹ کو ٹارگٹ گیم کا مالک ہونا چاہیے۔ یہ نہیں کر سکتا ایک اور کلید شامل کریں یا دوسری چابیاں منسوخ کریں۔ یہ خود کو منسوخ کر سکتا ہے۔ /me/public-keys/current; OAuth سے تصدیق شدہ سیشن سے اندراج اور دیگر کلیدوں کا نظم کریں۔ فی ایک کلید استعمال کریں۔ ماحول تاکہ ایک ورک فلو دوسرے کو روکے بغیر غیر فعال کیا جا سکے۔ آرکائیوز تقریبا 100 MB کے لیے نیچے دی گئی ویب ساکٹ ٹرانسپورٹ کا استعمال کرنا چاہیے۔

دیکھیں OAuth کے اندراج شدہ عوامی کلید کے ساتھ CI/CD سے تعمیرات اپ لوڈ کریں۔ کلیدی نسل کے لیے، GitHub خفیہ سیٹ اپ، ایک مکمل چیلنج سائننگ/اپ لوڈر اسکرپٹ، جامد اور کنٹینر بنڈل لے آؤٹ، اور ایک GitHub ایکشن ورک فلو۔

ویب ساکٹ پر اپ لوڈ کریں۔

GET /ws/v1/game-upload (اپ گریڈ) - اسے تقریباً 100 MB سے زیادہ کے لیے استعمال کریں۔

API کے سامنے موجود CDN تقریباً ایک HTTP درخواست کی باڈی سے انکار کرتا ہے۔ 100 MB a کے ساتھ 413 اس کا اپنے وہ انکار کبھی بھی پلیٹ فارم تک نہیں پہنچتا، اس لیے اس میں نہیں ہوتا limitBytes اور آپ کو نو لاگ ان میں ظاہر ہوتا ہے۔ پڑھ سکتے ہیں - a 413 نہیں کے ساتھ limitBytes فیلڈ CDN ہے، آپ کے گیم کا الاؤنس نہیں، جو کہ دو ہے۔ بڑے پیمانے کے احکامات. کوئی بھی حقیقت پسندانہ docker save اسے مارے گا.

WebSocket اپ گریڈ کرنے کے بعد بھیجے گئے فریم درخواست کی باڈی نہیں ہیں، اس لیے زیادہ سے زیادہ حد لاگو نہیں ہوتی۔ صرف نقل و حمل میں فرق ہے۔ بائنری فریم HTTP روٹس کے بالکل بائٹس میں جڑ جاتے ہیں۔ پڑھیں، اسی پائپ لائن سے گزریں، اور ہر انکار، الاؤنس اور کامیابی کا باڈی HTTP ہے۔ روٹ تیار ہوتا - لہذا ایک کلائنٹ دونوں میں ایک کوڈ کا راستہ بانٹ سکتا ہے۔

wss://api.starhermit.com/ws/v1/game-upload?gameId=$GAME_ID&access_token=$TOKEN
wss://api.starhermit.com/ws/v1/game-upload?gameId=$GAME_ID&mode=merge&access_token=$TOKEN

پاس gameId اپنی ملکیت والے کھیل کو آگے بڑھانے کے لیے ( /{id}/bundle راستہ)؛ اسے چھوڑ دو اور پاس کرو displayName/launchPath فولڈر سے ایک بنانے کے لیے ( /upload راستہ)۔ ٹوکن میں جاتا ہے استفسار سٹرنگ کیونکہ براؤزر سیٹ نہیں کر سکتا Authorization ویب ساکٹ ہینڈ شیک پر ہیڈر؛ یہ ہے مصافحہ کے وقت ایک بار چیک کیا گیا، تو ایک اپ لوڈ جو اس کے رسائی ٹوکن سے باہر رہتا ہے اب بھی ختم ہوجاتا ہے۔
