پبلشر

پبلشر کی سطح: پبلشر تنظیموں اور اراکین کا نظم کریں، سافٹ ویئر کے عنوانات بنائیں اور اپ لوڈ کریں اور اپنے عنوانات کے لیے کامیابیوں، حقداروں، اور لیڈر بورڈ کی تعریفوں کا نظم کریں۔

کیٹلاگ کے عنوان کے بجائے گیم شائع کرنا؟ آپ کو اس میں سے کسی کی ضرورت نہیں ہے۔ کا مالک a اسکرپٹ یا کنٹینر بیک اینڈ کے ساتھ گیم اس کا ناشر ہے اور اس کے لیڈر بورڈز کا انتظام کرتا ہے اور کے تحت کامیابیاں /api/v1/me/github-games/{id}/… - دیکھیں ٹیوٹوریل: لیڈر بورڈز اور آپ کے گیم کے لیے کامیابیاں.

بنیادی URL: https://api.starhermit.com. تمام راستوں کے لیے JWT کے علاوہ درج اجازت کے دعووں کی ضرورت ہوتی ہے۔ کردار: PublisherMember, PublisherOwner. اجازت کے دعوے کرداروں کے ذریعے تفویض کیے جاتے ہیں۔ minted ٹوکن اجازت کے دعوے لے.

پبلشرز اور ممبران

راستے کا سابقہ: api/v1/publisher.

طریقہ راستہ تصنیف تفصیل
پوسٹ /api/v1/publisher جے ڈبلیو ٹی (Permission-publisher.content.manage) ایک پبلشر بنائیں؛ تخلیق کار کردار کے ساتھ ایک رکن بن جاتا ہے۔ "Owner" → 201
حاصل کریں۔ /api/v1/publisher جے ڈبلیو ٹی (Permission-publisher.content.manage) پبلشرز کی فہرست → Publisher[]
پوسٹ /api/v1/publisher/{publisherId}/members جے ڈبلیو ٹی (Permission-publisher.members.manage) + کردار Owner ممبر شامل کریں → 204
حذف کریں۔ /api/v1/publisher/{publisherId}/members/{memberUserId} جے ڈبلیو ٹی (Permission-publisher.members.manage) + کردار Owner ایک رکن کو ہٹا دیں → 204 (مالک کو ہٹایا نہیں جا سکتا)
حاصل کریں۔ /api/v1/publisher/{publisherId}/members/{memberUserId} جے ڈبلیو ٹی (Permission-publisher.members.manage) + اس ناشر کی رکنیت ممبر حاصل کریں → PublisherMember

جو رکنیت تبدیل کر سکتے ہیں۔

اجازت کا دعویٰ کہتا ہے کہ آپ کہیں پبلشر کے اراکین کا انتظام کر سکتے ہیں۔ یہ نہیں کہتا جو پبلشر لہذا دونوں چیک لاگو ہوتے ہیں:

  • اراکین کو شامل کرنا اور ہٹانا ہے۔ Owner-صرف رکنیت میں مواد کا انتظام کرنے کا اختیار ہوتا ہے۔ پبلشر کے عنوانات میں سے ہر ایک، لہذا ایک سادہ ممبر جو ممبروں کو شامل کرسکتا ہے وہ اسے دے سکتا ہے۔ کسی کو اختیار. ایک غیر مالک کو ملتا ہے۔ 401.
  • رکنیت کو پڑھنے کے لیے اس ناشر کا ہونا ضروری ہے۔ اس کے باہر ایک کال کرنے والا وہی ملتا ہے۔ 404 ایک صارف کے طور پر جو رکن نہیں ہے، لہذا اختتامی نقطہ ان پبلشرز کے بارے میں کچھ بھی ظاہر نہیں کرتا جو آپ نہیں ہیں۔ کا حصہ

ایک پبلشر بنائیں

POST /api/v1/publisher

{
  "name": "HypeDriven",
  "description": "..."
}

تخلیق کار کردار کے ساتھ رکن بنتا ہے۔ "Owner".

ایک ممبر شامل کریں۔

POST /api/v1/publisher/{publisherId}/members

{ "userId": "<user id>" }

سافٹ ویئر کے عنوانات اور تعمیرات

طریقہ راستہ تصنیف تفصیل
پوسٹ /api/v1/publisher/software جے ڈبلیو ٹی (Permission-publisher.content.manage) سافٹ ویئر ٹائٹل بنائیں/اپ ڈیٹ کریں (باڈی = ٹائٹل میٹا ڈیٹا؛ ٹائٹل کے اصل ناشر میں ممبرشپ نافذ)
پوسٹ /api/v1/publisher/software/upload جے ڈبلیو ٹی (Permission-publisher.content.manage + Permission-publisher.binary.publish) عنوان کے لیے اپ لوڈ URLs حاصل کریں → UploadUrlInfo[]
پوسٹ /api/v1/publisher/software/build/finalize جے ڈبلیو ٹی (Permission-publisher.content.manage + Permission-publisher.binary.publish) اپ لوڈ کردہ اثاثوں سے ایک تعمیر کو حتمی شکل دیں → 204
حاصل کریں۔ /api/v1/publisher/analytics/downloads?publisherId= جے ڈبلیو ٹی (Permission-publisher.content.manage) ڈاؤن لوڈ کی تعداد فی عنوان
حاصل کریں۔ /api/v1/publisher/analytics/launches?publisherId= جے ڈبلیو ٹی (Permission-publisher.content.manage) فی عنوان لانچ کی گنتی

کسی تعمیر کو شائع کرنے کے لیے بائنری پبلش گرانٹ کی ضرورت ہوتی ہے۔

دو تعمیراتی اختتامی نقطوں کی ضرورت ہے۔ publisher.binary.publish کے اوپر publisher.content.manage اور عنوان کے ناشر کی رکنیت۔ اس کے بغیر دونوں جواب دیتے ہیں۔ 403, جب کہ اس صفحہ پر ہر دوسرا اختتامی نقطہ کام کرتا رہتا ہے — آپ عنوانات تخلیق اور ترمیم کر سکتے ہیں، وضاحت کر سکتے ہیں۔ کامیابیاں اور لیڈر بورڈز، اور حقدار فراہم کرنا؛ آپ صرف ایک قابل عمل جہاز نہیں بھیج سکتے۔

وجہ یہ ہے کہ تعمیر کیا ہے۔ ایک بلڈ کے اثاثے ڈیسک ٹاپ کلائنٹ کے ذریعہ ڈاؤن لوڈ کیے جاتے ہیں اور اس پر چلتے ہیں۔ کھلاڑی کے مراعات کے ساتھ پلیئر کی مشین، کسی بھی سینڈ باکس سٹارہرمیٹ کنٹرول کے باہر — ایک کے برعکس براؤزر گیم، جو براؤزر میں چلتا ہے۔ لہذا ایک کو شائع کرنے کا حق فی اکاؤنٹ کے ذریعہ دیا گیا ہے۔ سٹارہرمیٹ ایڈمنسٹریٹر (دی BinaryPublisher کردار)، پبلشر بنا کر حاصل نہیں کیا گیا۔ نہیں دوسرا کردار اسے لے جاتا ہے. کے خلاف اپ لوڈ فلو بنانے سے پہلے گرانٹ کے لیے ایڈمنسٹریٹر سے پوچھیں۔ یہ اختتامی نکات; اسے بھی ہٹا دیا جاتا ہے جب ایک ناشر کا اکاؤنٹ معطل کیا جاتا ہے۔

براؤزر گیمز کو اس میں سے کسی کی ضرورت نہیں ہے: /api/v1/me/github-games گذارشات، فولڈر اپ لوڈز اور بنڈل pushes کسی بھی سائن ان کردہ اکاؤنٹ کے لیے سیلف سروس رہیں۔

کیٹلاگ کا عنوان بنائیں یا اپ ڈیٹ کریں۔

POST /api/v1/publisher/software قبول کرتا ہے id (نئے عنوان کے لیے چھوڑ دیں) publisherId, name, description, category, platform, releaseStatus, tags، اور priceCents:

{
  "publisherId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "name": "Orbit League",
  "description": "A space racing game.",
  "category": "game",
  "platform": "windows",
  "releaseStatus": "released",
  "tags": ["racing"],
  "priceCents": 0
}

کامیابی ہے۔ 201 عنوان کے ساتھ. صرف ٹائٹل میٹا ڈیٹا قبول کیا جاتا ہے۔ پبلشر کی رکنیت نہ بھیجیں۔ یا اثاثہ اشیاء یہاں. پبلشر بنانے سے واپسی ہوتی ہے۔ 201 پبلشر آبجیکٹ کے بغیر؛ فہرست GET /api/v1/publisher اس کی شناخت حاصل کرنے کے لیے۔

اپ لوڈ URLs حاصل کریں۔

POST /api/v1/publisher/software/upload

{ "titleId": "<title id>" }

جواب - UploadUrlInfo[]:

[
  {
    "type": "executable",
    "uploadUrl": "...",
    "fieldKey": "..."
  }
]

type میں سے ایک ہے "executable", "data", "metadata".

ایک تعمیر کو حتمی شکل دیں۔

POST /api/v1/publisher/software/build/finalize → 204

{
  "titleId": "<title id>",
  "buildId": "<optional build id>",
  "version": "1.0.0",
  "releaseNotes": "...",
  "assets": [
    { "type": "executable", "checksum": "...", "fieldKey": "..." }
  ]
}

کیٹلاگ بلڈ ورک فلو فی الحال ایک پیش نظارہ ہے اور پروڈکشن بائنری ڈیلیوری فراہم نہیں کرتا ہے۔ یا مواد کی تصدیق یا میلویئر سکیننگ کی ضمانت۔ کسی منظور شدہ تعمیر یا اثاثے کا علاج نہ کریں۔ اس بات کے ثبوت کے طور پر حیثیت کہ قابل عمل محفوظ ہے۔ دیکھیں خصوصیت کی دستیابی. میزبان گیم پبلشنگ کا استعمال کرتا ہے۔ گیم اپ لوڈ API.

تجزیات

دونوں اختتامی پوائنٹس شمار کرنے کے لیے JSON آبجیکٹ میپنگ ٹائٹل آئی ڈی واپس کرتے ہیں:

{ "<titleId>": 42 }

کامیابیاں

راستہ api/v1/publisher; کامیابی کے انتظام کے تمام راستوں کی ضرورت ہوتی ہے۔ Permission-publisher.content.manage.

یہ اختتامی نکات کا انتظام کرتے ہیں۔ catalog-title صرف کامیابیاں وہ یہ بھی مطالبہ کرتے ہیں کہ کال کرنے والا ایک ہو۔ پبلشر کے ممبر جو ٹائٹل کے مالک ہیں، اور وہ ان کامیابیوں کے لیے بند ہو جانا جن کا تعلق ہے۔ ایک مستند کھیل - ان کا اعلان گیم کے اسکرپٹ یا کنٹینر بیک اینڈ کے ذریعہ کیا گیا ہے اور نہیں ہے۔ ناشر کے زیر انتظام (دیکھیں۔ کامیابیاں, کھیل ہی کھیل میں سکرپٹ, اور کنٹینر گیم سرورز).

طریقہ راستہ تصنیف تفصیل
پوسٹ /api/v1/publisher/titles/{titleId}/achievements جے ڈبلیو ٹی ایک کارنامہ تخلیق کریں → AchievementDto
حاصل کریں۔ /api/v1/publisher/titles/{titleId}/achievements جے ڈبلیو ٹی عنوان کی کامیابیوں کی فہرست بنائیں → AchievementDto[]
حاصل کریں۔ /api/v1/publisher/achievements/{id} جے ڈبلیو ٹی ایک کامیابی حاصل کریں → AchievementDto
ڈالو /api/v1/publisher/achievements/{id} جے ڈبلیو ٹی اپ ڈیٹ کریں (تمام فیلڈز کالعدم) → AchievementDto
حذف کریں۔ /api/v1/publisher/achievements/{id} جے ڈبلیو ٹی حذف کریں → 204

ایک کارنامہ بنائیں

POST /api/v1/publisher/titles/{titleId}/achievements

{
  "key": "first_win",
  "name": "First Win",
  "description": "Win your first game.",
  "icon": "...",
  "secret": false,
  "points": 10,
  "visibility": "...",
  "criteria": "..."
}

icon, visibility، اور criteria اختیاری ہیں. پر PUTتمام فیلڈز کالعدم ہیں۔ دیکھیں achievements.md کھلاڑی کا سامنا کرنے والی سطح کے لیے۔

استحقاق

راستہ api/v1/publisher/entitlements; دونوں راستوں کی ضرورت ہے۔ Permission-publisher.content.manage.

طریقہ راستہ تصنیف تفصیل
پوسٹ /api/v1/publisher/entitlements/grant جے ڈبلیو ٹی صارف کو ایک عنوان دیں → 204
پوسٹ /api/v1/publisher/entitlements/revoke جے ڈبلیو ٹی صارف سے عنوان منسوخ کریں → 204

دونوں کے لیے جسم:

{
  "userId": "<user id>",
  "softwareTitleId": "<title id>"
}

لیڈر بورڈز

راستہ api/v1/publisher/leaderboards; تمام راستوں کی ضرورت ہے۔ Permission-publisher.content.manage.

طریقہ راستہ تصنیف تفصیل
پوسٹ /api/v1/publisher/leaderboards/ جے ڈبلیو ٹی لیڈر بورڈ کی تعریف بنائیں → LeaderboardDefinitionDto
حاصل کریں۔ /api/v1/publisher/leaderboards/{id} جے ڈبلیو ٹی ایک تعریف حاصل کریں → LeaderboardDefinitionDto
ڈالو /api/v1/publisher/leaderboards/{id} جے ڈبلیو ٹی اپ ڈیٹ کریں (تمام فیلڈز کالعدم) → LeaderboardDefinitionDto
حذف کریں۔ /api/v1/publisher/leaderboards/{id} جے ڈبلیو ٹی حذف کریں → 204

لیڈر بورڈ بنائیں

POST /api/v1/publisher/leaderboards/

{
  "name": "Global Elo",
  "scoreType": "...",
  "sortDirection": "...",
  "resetSchedule": "...",
  "minScore": 0,
  "maxScore": 4000,
  "scope": "...",
  "region": "...",
  "isActive": true,
  "softwareTitleId": "<optional title id>"
}

resetSchedule, minScore, maxScore, region، اور softwareTitleId اختیاری ہیں. پر PUTتمام فیلڈز کالعدم ہیں۔ resetSchedule ہے daily, weekly, monthly یا never; کچھ اور ہے a 400 - دیکھیں نظام الاوقات کو دوبارہ ترتیب دیں۔. دیکھیں leaderboards.md کھلاڑی کا سامنا کرنے والی سطح کے لیے۔

ایک تعمیر شائع کریں: بہاؤ

  1. بائنری پبلش گرانٹ کو پکڑو: مرحلہ 3 اور 5 درکار ہے۔ publisher.binary.publish، جو ایک Starhermit منتظم فی اکاؤنٹ گرانٹ کرتا ہے۔ دیکھیں کسی تعمیر کو شائع کرنے کے لیے بائنری پبلش گرانٹ کی ضرورت ہوتی ہے۔.
  2. ایک پبلشر بنائیں: POST /api/v1/publisher کے ساتھ { name, description }.
  3. عنوان بنائیں: POST /api/v1/publisher/software ذیل میں عنوان میٹا ڈیٹا کے ساتھ۔
  4. اپ لوڈ URLs حاصل کریں۔: POST /api/v1/publisher/software/upload کے ساتھ { titleId }.
  5. فائلیں اپ لوڈ کریں۔ واپس آنے والے کو uploadUrls.
  6. تعمیر کو حتمی شکل دیں۔: POST /api/v1/publisher/software/build/finalize اپ لوڈ کردہ اثاثوں کے ساتھ { type, checksum, fieldKey } اندراجات
  7. تقسیم کی دستیابی کو چیک کریں۔: موجودہ کیٹلاگ کا پیش نظارہ تصدیق شدہ پروڈکشن ڈاؤن لوڈز یا میلویئر اسکیننگ کی ضمانت نہیں دیتا ہے۔ دیکھیں دستیابی.
  8. صارفین دعوی کرتے ہیں اور ڈاؤن لوڈ کرتے ہیں۔ کیٹلاگ کے ذریعے عنوان - دیکھیں catalog.md.

خرابی کی لاشیں مختلف ہوتی ہیں؛ دیکھیں API کنونشنز.

یہ بھی دیکھیں

  • catalog.md — کھلاڑی کس طرح ٹائٹلز کو براؤز کرتے ہیں، دعویٰ کرتے ہیں اور ڈاؤن لوڈ کرتے ہیں۔
  • achievements.md - کھلاڑی کے سامنے کامیابیاں
  • leaderboards.md - کھلاڑی کا سامنا کرنے والے لیڈر بورڈز
  • auth.md - JWT، کردار، اور اجازت کے دعوے

دیکھیں اسناد کی مطابقت اور مشین پڑھنے کے قابل معاہدے.
