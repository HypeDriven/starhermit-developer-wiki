ٹیوٹوریل: عوامی کلید کے ساتھ آن بورڈ پلیئرز

ایک StarHermit اکاؤنٹ کو Google، GitHub یا کسی دوسرے سائن ان فراہم کنندہ کی ضرورت نہیں ہے۔ اس کی سند ہو سکتی ہے۔ ایک کلیدی جوڑا بنیں جو آپ کا گیم کھلاڑی کے آلے پر تیار کرتا ہے، نیز کھلاڑی کا ای میل پتہ ایک بار تصدیق کرتا ہے. اس کے بعد، آپ کا گیم ہر لانچ پر خاموشی سے ایک چیلنج پر دستخط کر کے سائن ان کرتا ہے۔ چابی کھلاڑی کبھی بھی پاس ورڈ ٹائپ نہیں کرتا ہے اور نہ ہی کبھی StarHermit پیج پر جانا پڑتا ہے۔

یہ ٹیوٹوریل اس بہاؤ کو آخر سے آخر تک بناتا ہے: کلید بنائیں، اسے رجسٹر کریں، کھلاڑی کا انتظار کریں تصدیق کریں، سائن ان کریں، سیشن رکھیں، اور دوسری ڈیوائسز اور کھوئی ہوئی چابیاں ہینڈل کریں۔

اس کے لیے استعمال کریں۔ مقامی اور اسٹینڈ اسٹون گیمز، لانچرز، Steam/Epic/GOG تعمیرات اور ڈیسک ٹاپ ٹولز — کوئی بھی چیز جو کھلاڑی کی مشین پر چلتی ہے اور وہاں پرائیویٹ کلید رکھ سکتی ہے۔

کے لیے کچھ اور استعمال کریں۔

  • StarHermit پر میزبان ایک براؤزر گیم، جو پہلے سے ہی ایک لانچ ٹوکن وصول کرتا ہے جب سے کھولا جاتا ہے۔ ڈیش بورڈ، یا دکھا سکتا ہے۔ سائن ان بٹن.
  • ایک CI پائپ لائن، جس کو بغیر ای میل قدم کے OAuth سیشن سے ایک کلید کا اندراج کرنا چاہئے: ٹیوٹوریل: CI/CD سے تعمیرات اپ لوڈ کریں۔.
  • ایک سرشار گیم سرور، جس کا اپنا تعیناتی ٹوکن ہے اور وہ بنا یا کام نہیں کر سکتا کھلاڑی: سبق: ایک سرشار سرور شائع کریں۔.

جو کھلاڑی دیکھتا ہے۔

  1. آپ کا گیم StarHermit اکاؤنٹ بنانے کے لیے ای میل ایڈریس اور ان کی رضامندی طلب کرتا ہے۔
  2. وہ تصدیقی ای میل کھولتے ہیں، لنک پر کلک کرتے ہیں، اور دبائیں۔ تصدیق کریں۔ جس صفحے پر یہ کھلتا ہے۔
  3. آپ کے گیم میں واپس، وہ سائن ان ہو گئے ہیں۔ بعد میں لانچ ہونے پر کچھ بھی نہیں پوچھا جاتا ہے۔

ایک ای میل پتہ درکار ہے، اور کھلاڑی کو ایک بار اس کی تصدیق کرنی ہوگی۔ ایک بنانے کا کوئی طریقہ نہیں ہے۔ StarHermit اکاؤنٹ خاموشی سے Steam، Epic یا GOG شناخت سے۔

اس سے پہلے کہ آپ شروع کریں۔

اس صفحہ پر کوڈ سادہ جاوا اسکرپٹ ہے WebCrypto استعمال کرتے ہوئے اور fetch، تو یہ براؤزر میں چلتا ہے۔ الیکٹران اور نوڈ 20 یا بعد میں۔ دی js نیچے بلاکس، ترتیب میں، ایک ES ماڈیول بنائیں - ان کو بچائیں۔ ایک ساتھ کے طور پر starhermit-key-auth.js. کوئی بھی دوسری زبان اسی طرح کام کرتی ہے: مرحلہ 1 بالکل درست بتاتا ہے۔ بائٹ فارمیٹس، اور مرحلہ 3 سائن کرنے کے لیے عین بائٹس۔

const API = 'https://api.starhermit.com';

const b64 = (bytes) => btoa(String.fromCharCode(...new Uint8Array(bytes)));

1. آلہ کی کلید بنائیں

پیدا کریں۔ ایک کلیدی جوڑی فی تنصیب، پہلی بار جب آپ کے گیم کو اکاؤنٹ کی ضرورت ہوتی ہے۔ نجی کلید کبھی بھی ڈیوائس کو نہیں چھوڑتی: آپ کے سرورز پر نہیں، StarHermit کو نہیں۔

keyType keyData (معیاری بیس 64) دستخط (معیاری بیس 64)
Ed25519 - تجویز کردہ خام 32 بائٹ عوامی کلید خام 64 بائٹ Ed25519 دستخط
ECDSA-P256 عوامی نقطہ: 65 بائٹ غیر کمپریسڈ (04‖X‖Y) یا 33 بائٹ کمپریسڈ SHA-256 کے ساتھ ECDSA، ASN.1 DER-encoded
RSA-PSS SubjectPublicKeyInfo DER، 2048–8192-bit ماڈیولس، exponent ≤ 32 بٹس RSASSA-PSS, SHA-256, MGF1-SHA-256, 32-بائٹ نمک

keyData زیادہ سے زیادہ 2,000 حروف ہیں۔ ایک کلید پورے پلیٹ فارم میں ایک اکاؤنٹ سے تعلق رکھتی ہے۔

چنو ایڈ 25519 جب تک کہ آپ کا پلیٹ فارم اسے تیار نہیں کرسکتا۔ اگر آپ ECDSA استعمال کرتے ہیں، تو نوٹ کریں کہ WebCrypto، ونڈوز سی این جی اور زیادہ تر ہارڈویئر کی اسٹورز دستخط کو خام کے طور پر واپس کرتے ہیں۔ r‖s (64 بائٹس)۔ StarHermit DER کی توقع ہے، لہذا اسے تبدیل کریں - ذیل کا ماڈیول کرتا ہے۔

// One key per installation. The private key can sign but is never exported.
export async function createDeviceKey(keyType = 'Ed25519') {
  if (!['Ed25519', 'ECDSA-P256'].includes(keyType)) throw new Error('This helper supports Ed25519 or ECDSA-P256');
  const algorithm = keyType === 'Ed25519'
    ? { name: 'Ed25519' }
    : { name: 'ECDSA', namedCurve: 'P-256' };
  const pair = await crypto.subtle.generateKey(algorithm, false, ['sign', 'verify']);
  return {
    keyType: keyType === 'Ed25519' ? 'Ed25519' : 'ECDSA-P256',
    keyData: b64(await crypto.subtle.exportKey('raw', pair.publicKey)),
    privateKey: pair.privateKey,
  };
}

نجی کلید کو ذخیرہ کریں جہاں آپریٹنگ سسٹم اس کی حفاظت کرتا ہے۔ براؤزر یا الیکٹران رینڈرر میں، ایک غیر نکالنے کے قابل CryptoKey IndexedDB میں رکھا جا سکتا ہے جیسا کہ یہ ہے۔ ایک مقامی کھیل کو استعمال کرنا چاہئے۔ پلیٹ فارم کی اسٹور - ونڈوز ڈی پی اے پی آئی یا سی این جی، میکوس کیچین، لینکس پر libsecret۔ اسٹور keyType اور keyData اس کے قریب؛ آپ انہیں ہر درخواست کے ساتھ بھیجتے ہیں۔

2. رجسٹریشن شروع کریں۔

کھلاڑی کا ای میل پتہ اور رضامندی طلب کریں، پھر:

async function post(path, body) {
  const res = await fetch(API + path, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  });
  return { status: res.status, body: await res.json().catch(() => ({})) };
}

function fail(step, { status, body }) {
  return Object.assign(new Error(`${step}: ${body.error ?? status}`), { status, body });
}

export async function register(key, email) {
  const res = await post('/api/v1/auth/public-key/register',
    { email, keyType: key.keyType, keyData: key.keyData });
  if (res.status !== 202) throw fail('register', res);
  return res.body; // { registrationId, email, emailSent, deferralReason, message }
}

202 یعنی StarHermit نے رجسٹریشن قبول کر لی۔ اگر emailSent ہے false، ای میل قطار میں ہے اور اب بھی پہنچیں گے؛ deferralReason کہتا ہے کہ انتظار کیوں کیا؟ ابھی تک کسی بھی اکاؤنٹ سے کچھ بھی منسلک نہیں ہے۔

تین اصول آپ کے UI کو تشکیل دیتے ہیں:

  • ایک رجسٹریشن فی ای میل ایڈریس، اور ایک فی IP ایڈریس، ہر 24 گھنٹے۔ دوسری کوشش ہے 429 کے ساتھ Retry-After. پلیئر کو ایڈریس بھیجنے سے پہلے اس کی تصدیق کروائیں، کیونکہ ٹائپنگ کی غلطی ہے۔ ان کا ایک دن خرچ ہوتا ہے. پلیئر کے آلے سے درخواست بھیجیں، کبھی بھی اپنے سرور کے ذریعے: ہر پلیئر آپ کے سرور کا آئی پی اور اس کی روزانہ کی رجسٹریشن کا اشتراک کرے گا۔
  • لنک 4 گھنٹے بعد ختم ہو جاتا ہے۔ اگر یہ ختم ہوجاتا ہے، تو کھلاڑی 24 گھنٹوں میں ایک بار دوبارہ رجسٹر ہوسکتا ہے۔ اوپر ہیں
  • 400 مطلب ای میل ایڈریس یا کلیدی مواد کو مسترد کر دیا گیا تھا۔ error جو کہتا ہے.

3. کلید کے ساتھ سائن ان کریں۔

سائن ان کرنا ایک چیلنج اور جواب ہے۔ POST /api/v1/auth/public-key/challenge واپسی:

{
  "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
  "payload": {
    "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
    "fingerprint": "9c0b7a…",
    "issuer": "starhermit",
    "audience": "starhermit",
    "expiry": "2026-10-09T14:21:41.9264875+00:00",
    "nonce": "NmL+tgMum6HXU/pa3T9xjQ==",
    "clientTimestamp": "2026-10-09T14:16:41.9265739+00:00"
  },
  "expiresIn": 300
}

آپ جس پر دستخط کرتے ہیں وہ JSON نہیں ہے جو آپ کو موصول ہوا ہے۔ StarHermit اپنے دستخط کی تصدیق کرتا ہے۔ کی سیریلائزیشن payload:

  • کمپیکٹ JSON، کوئی خالی جگہ نہیں؛
  • پاسکل کیس اراکین کے نام، بالکل اسی ترتیب میں ChallengeId, Fingerprint, Issuer, Audience, Expiry, Nonce, ClientTimestamp;
  • ہر قدر کاپی بالکل جیسا کہ پیش کیا گیا ہے۔ - تاریخوں کو پارس اور ریفارمیٹ نہ کریں؛
  • ہر + غیر میں کے طور پر لکھا ہے \u002B. دی + تاریخوں میں وہی رہتا ہے جیسا کہ یہ ہے۔

مندرجہ بالا چیلنج کے لیے، دستخط شدہ بائٹس UTF-8 کی انکوڈنگ ہیں:

{"ChallengeId":"4fc4d72b-4c12-41ca-a500-dc13cccc3865","Fingerprint":"9c0b7a…","Issuer":"starhermit","Audience":"starhermit","Expiry":"2026-10-09T14:21:41.9264875+00:00","Nonce":"NmL\u002BtgMum6HXU/pa3T9xjQ==","ClientTimestamp":"2026-10-09T14:16:41.9265739+00:00"}

اس میں سے کوئی بھی غلط حاصل کریں اور جواب ہے۔ 401 "Invalid signature."، جسے دوبارہ کوشش کرنے سے ٹھیک نہیں ہوگا۔

const FIELDS = ['challengeId', 'fingerprint', 'issuer', 'audience', 'expiry', 'nonce', 'clientTimestamp'];

export function challengeSigningBytes(payload) {
  const members = FIELDS.map((field) => {
    let value = JSON.stringify(payload[field]);
    if (field === 'nonce') value = value.replaceAll('+', '\\u002B');
    return `"${field[0].toUpperCase()}${field.slice(1)}":${value}`;
  });
  return new TextEncoder().encode(`{${members.join(',')}}`);
}

export async function signChallenge(key, payload) {
  const data = challengeSigningBytes(payload);
  if (key.keyType === 'Ed25519')
    return b64(await crypto.subtle.sign({ name: 'Ed25519' }, key.privateKey, data));
  // WebCrypto returns an ECDSA signature as raw r||s; the server expects ASN.1 DER.
  const rs = new Uint8Array(
    await crypto.subtle.sign({ name: 'ECDSA', hash: 'SHA-256' }, key.privateKey, data));
  return b64(derEcdsaSignature(rs));
}

function derEcdsaSignature(rs) {
  const integer = (bytes) => {
    let i = 0;
    while (i < bytes.length - 1 && bytes[i] === 0) i++;
    const value = [...bytes.slice(i)];
    return value[0] & 0x80 ? [0x02, value.length + 1, 0, ...value] : [0x02, value.length, ...value];
  };
  const body = [...integer(rs.slice(0, 32)), ...integer(rs.slice(32))];
  return new Uint8Array([0x30, body.length, ...body]);
}

// Resolves to { userId, accessToken, refreshToken }, or null while the key is not attached to
// an account yet — the player has not confirmed, the link expired, or the key was revoked.
export async function signIn(key) {
  const { keyType, keyData } = key;
  const challenge = await post('/api/v1/auth/public-key/challenge', { keyType, keyData });
  if (challenge.status !== 200) throw fail('challenge', challenge);
  const signature = await signChallenge(key, challenge.body.payload);
  const done = await post('/api/v1/auth/public-key/complete',
    { challengeId: challenge.body.challengeId, signature, keyType, keyData });
  if (done.status === 200) return done.body;
  if (done.status === 401 && done.body.error === 'Public key not registered or revoked.') return null;
  throw fail('complete', done); // "Invalid signature." will never succeed: fix it, don't retry it
}

ایک چیلنج پانچ منٹ تک جاری رہتا ہے اور یہ واحد استعمال ہوتا ہے، یہاں تک کہ جب کوشش ناکام ہو جائے، اس لیے ایک نئے کی درخواست کریں۔ ہر کوشش کے لیے۔ چیلنج کریں اور فی آئی پی ایڈریس ایک منٹ میں 60 درخواستوں کی حد کو مکمل کریں۔

4. کھلاڑی کی تصدیق کا انتظار کریں۔

ای میل شدہ لنک ایک StarHermit صفحہ کھولتا ہے جس میں کہا جاتا ہے کہ تصدیق کرنے سے کیا ہوگا؛ اسے کھولنے سے بدل جاتا ہے۔ کچھ بھی نہیں، لہذا لنک کا پیش نظارہ کرنے والا میل اسکینر کھلاڑی کی جانب سے تصدیق نہیں کرسکتا۔ جب پلیئر پریس تصدیق کریں۔, StarHermit ان کا اکاؤنٹ بناتا ہے، آپ کی کلید منسلک کرتا ہے اور پتہ کو نشان زد کرتا ہے۔ تصدیق شدہ اگر کوئی اکاؤنٹ پہلے سے ہی اس ایڈریس کو استعمال کرتا ہے، تو صفحہ ایسا کہتا ہے اور اس میں کلید شامل کردی جاتی ہے۔ اس کے بجائے، لہذا ایک کھلاڑی جس کے پاس پہلے سے ہی StarHermit اکاؤنٹ ہے اسے رکھتا ہے۔ starhermit.com پر وہ پھر اترتے ہیں۔ StarHermit ڈیش بورڈ پر، پہلے سے سائن ان ہے۔

آپ کا گیم کبھی بھی اس صفحہ سے ٹوکن وصول نہیں کرتا ہے۔، اور ان کی ضرورت نہیں ہے۔ کھلاڑی ہو سکتا ہے۔ فون پر یا دوسرے براؤزر میں تصدیق کریں۔ کلید منسلک ہونے کے بعد، آپ کا گیم آسانی سے سائن ان کر سکتا ہے۔ اس کے ساتھ تو دکھائیں a "اپنا ان باکس چیک کریں۔" اسکرین کریں اور کوشش کرتے رہیں:

// Poll until the player confirms the emailed link. Two requests per attempt, so every 5 s stays
// well inside the 60-per-minute sign-in limit.
export async function waitUntilConfirmed(key, { intervalMs = 5000, signal } = {}) {
  for (;;) {
    signal?.throwIfAborted();
    const session = await signIn(key);
    if (session) return session;
    await new Promise((resolve) => setTimeout(resolve, intervalMs));
  }
}

اقدامات 1 سے 4 کو ایک ساتھ رکھنا:

import { createDeviceKey, register, signIn, waitUntilConfirmed } from './starhermit-key-auth.js';

const key = await loadStoredKey() ?? await saveKey(await createDeviceKey());
let session = await signIn(key);                // a returning player is signed in here
if (!session) {
  const email = await askForEmailAndConsent();
  await register(key, email);
  showCheckYourInbox(email);
  session = await waitUntilConfirmed(key, { signal: cancelButton.signal });
}

loadStoredKey, saveKey, askForEmailAndConsent اور showCheckYourInbox آپ کو لکھنا ہے پیشکش a منسوخ کریں۔ جو انتظار کو ختم کر دیتا ہے، اور لنک کی میعاد ختم ہونے پر چار گھنٹے بعد پولنگ روک دیتا ہے۔

پولنگ جاری رکھیں چاہے آپ کے پلیٹ فارم کا تصدیقی صفحہ آپ کی سائٹ پر واپس بھیج دے۔ کھلاڑی اکثر ای میل کو انتظار کرنے والے سے مختلف ڈیوائس پر کھولتا ہے، اور پھر ری ڈائریکٹ کہیں نہیں پہنچتا آپ کی ویٹنگ اسکرین کے قریب؛ پولنگ وہ ہے جو ویٹنگ ڈیوائس کو سائن ان کرتی ہے۔ اگر ری ڈائریکٹ آتا ہے۔ دوسرے ٹیب میں، ان میں سے صرف ایک کے ساتھ سائن ان کریں اور اضافی سیشن کو منسوخ کریں، یا کھلاڑی ختم ہو جائے گا۔ دو کے ساتھ.

5. سیشن رکھیں

complete 15 منٹ تک رسائی کا ٹوکن اور ریفریش ٹوکن جو سات دنوں تک چلتا ہے اور گھومتا ہے۔ رسائی ٹوکن بطور بھیجیں۔ Authorization: Bearer …، اور اس کی میعاد ختم ہونے سے پہلے ریفریش کریں:

// Resolves to the new pair, or null when the session is over — sign in with the key again.
export async function refresh(refreshToken) {
  const res = await post('/api/v1/auth/refresh', { refreshToken });
  return res.status === 200 ? res.body : null; // { accessToken, refreshToken }
}

بدل دیں۔ دونوں ہر بار ٹوکن. استعمال شدہ ریفریش ٹوکن پیش کرنے سے پورا سیشن ختم ہو جاتا ہے، لہذا بنائیں یقینی طور پر دو دھاگے یا عمل کبھی بھی ایک ساتھ تازہ نہیں ہوتے ہیں۔ جب refresh واپسی null، کال کریں۔ signIn - کوئی ای میل شامل نہیں ہے. کلید طویل المدت سند ہے۔ ٹوکن اس کا صرف ایک ذخیرہ ہیں۔

6. اکاؤنٹ سیٹ اپ مکمل کریں۔

شرائط نئے اکاؤنٹ کو اسٹار ہرمٹ کی موجودہ شرائط کو قبول کرنا ضروری ہے اس سے پہلے کہ وہ کوئی اور چیز استعمال کر سکے۔ کال کریں۔ GET /api/v1/me. اگر termsAcceptanceRequired ہے true، سے متن دکھائیں۔ GET /api/v1/terms، اور جب کھلاڑی اسے قبول کرتا ہے تو اس کی ہیش کو بھیجیں۔ POST /api/v1/me/terms/accept. بعد میں لانچوں پر دوبارہ چیک کریں، کیونکہ شرائط پر نظر ثانی کی گئی ہے۔ تفصیلات: شرائط کی قبولیت.

نام اکاؤنٹ ایک سے شروع ہوتا ہے۔ pk-… صارف نام کھلاڑی کو ایک عرفی نام منتخب کرنے دیں:

PATCH /api/v1/me
Authorization: Bearer <access-token>
Content-Type: application/json

{ "nickname": "RookPilot" }

یہاں سے اکاؤنٹ کسی دوسرے کی طرح ہے: دوست، چیٹ، میچ میکنگ، کلاؤڈ سیو، کامیابیاں۔

7. دوسری ڈیوائسز، کھوئی ہوئی چابیاں، اور حدود

دوسرا آلہ اپنی کلید تیار کرتا ہے اور اسے رجسٹر کرتا ہے۔ ایک ہی ای میل ایڈریس. جب پلیئر تصدیق کرتا ہے، کلید نیا بنانے کے بجائے ان کے موجودہ اکاؤنٹ میں شامل ہو جاتی ہے۔ 24 گھنٹے فی ایڈریس کی حد یہاں بھی لاگو ہوتی ہے۔

گم شدہ یا چوری شدہ آلہ۔ POST /api/v1/auth/public-key/revoke-request کے ساتھ { "email": "…" } کسی صفحے کا لنک ای میل کرتا ہے۔ وہاں کی تصدیق منسوخ ہو جاتی ہے۔ ہر اکاؤنٹ پر کلید اور سیشن ختم کرتا ہے۔ وہ چابیاں سائن ان ہیں۔ اکیلے لنک کھولنے سے کچھ نہیں بدلتا۔ درخواست ہمیشہ جواب دیتی ہے۔ 202 اسی پیغام کے ساتھ، چاہے یا نہیں ایڈریس کا اکاؤنٹ ہے۔ لنک چار گھنٹے بعد ختم ہو جاتا ہے، اور اکاؤنٹ ہر 15 میں ایک بار پوچھ سکتا ہے۔ منٹ اس کے بعد، ہر بقیہ آلہ دوبارہ رجسٹر ہو جاتا ہے (مرحلہ 2)۔

جو صرف کلیدی اکاؤنٹ نہیں کر سکتا۔ چند تبدیلیاں اکاؤنٹ کی اسناد کی حفاظت کرتی ہیں، اس لیے وہ ایک سیشن کی ضرورت ہے جو گوگل یا GitHub جیسے فراہم کنندہ کے ذریعے سائن ان ہو:

ایکشن صرف کلیدی اکاؤنٹ
ایک کلید شامل کریں یا دوسرے آلات کو منسوخ کریں (POST /me/public-keys, DELETE /me/public-keys/{id} یا /all) 403 - ای میل شدہ رجسٹریشن کے ذریعے اندراج کریں، یا OAuth سے تصدیق شدہ سیشن استعمال کریں۔
اکاؤنٹ کا ای میل پتہ تبدیل کریں۔ 403 oauth_session_required - اس وقت تک ممکن نہیں جب تک کہ فراہم کنندہ منسلک نہ ہو۔
اس انسٹالیشن کی اپنی کلید کو منسوخ کریں۔ DELETE /api/v1/me/public-keys/current, اس کے مکمل عوامی کلید اکاؤنٹ سیشن کا استعمال کرتے ہوئے؛ کامیابی کے بعد مقامی اسناد کو رد کر دیں۔

دیگر اسناد کا نظم کرنے یا ای میل تبدیل کرنے کے لیے، فراہم کنندہ کو لنک کریں۔ جب صرف کلیدی اکاؤنٹ ایک کو جوڑتا ہے، تو لنک کو روک دیا جاتا ہے۔ جب تک کہ کھلاڑی اپنے ای میل سے اس کی تصدیق نہ کرے۔ اس کے بعد، ایک فراہم کنندہ سائن ان اوپر سب کچھ کر سکتا ہے۔ دیکھیں authorize?link=true.
