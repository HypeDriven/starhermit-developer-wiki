ٹیوٹوریل: مستقل سیشنز - وہ گیمز جو سب کے جانے پر رک جاتے ہیں۔

عام طور پر پلیٹ فارم ایک میچ ختم کرتا ہے جو کوئی نہیں کھیل رہا ہے: ایک بار جب ہر کھلاڑی کا رابطہ منقطع ہو جاتا ہے اور کوئی نہیں ہوتا ہے۔ پانچ منٹ کے اندر واپس آ گیا ہے، سیشن اس طرح ختم ہو جاتا ہے۔ abandoned وجہ کے ساتھ players_left (دیکھیں۔ گیمز API — گیم پلے ویب ساکٹ)۔ یہ شطرنج کے لیے صحیح ہے۔ کھیل یا ریس، اور فارم، شہر بنانے والے، مشترکہ تہھانے یا کسی بھی دنیا کے ایک گروپ کے لیے غلط کھلاڑیوں کی زیادہ دنوں میں واپسی.

ایک کھیل کے لئے پوچھ سکتے ہیں مسلسل سیشن اس کے بجائے ایک مستقل سیشن اس وقت رک جاتا ہے جب اس کے کھلاڑی منقطع ہو جاتے ہیں:

  1. آخری کھلاڑی چلا جاتا ہے۔
  2. تقریباً 15 سیکنڈ کے بعد جس میں کوئی بھی نہیں جڑا، پلیٹ فارم روکتا ہے سیشن کچھ نہیں چلتا: اسکرپٹ گیم کو نمبر ملتا ہے۔ onTick کالز، اور کنٹینر گیم کے سیشن کو سے ہٹا دیا جاتا ہے۔ کنٹینر
  3. سیشن اس کی ریکوری برقرار رکھنے کی پالیسی کے اندر موقوف رہتا ہے۔ پڑھیں /sessions/{id}/recovery کسی بھی میعاد ختم ہونے کے بجائے یہ فرض کرنے کے کہ اسے ہمیشہ کے لیے رکھا گیا ہے۔
  4. جڑنے والا پہلا کھلاڑی ws/v1/games دوبارہ شروع اس سے پہلے کہ ان کا پہلا حکم ہے۔ سنبھالا کھیل وہیں سے چلتا ہے جہاں سے یہ رکا تھا۔

یہ صفحہ دکھاتا ہے کہ اسے کیسے آن کیا جائے، اپنے گیم کی گھڑیوں کو وقفے وقفے سے کودنے سے کیسے روکا جائے، اور آپ کے کلائنٹ کو کیا کرنے کی ضرورت ہے۔

1. آپٹ ان کریں۔

استقامت ایک فی گیم ڈیکلریشن ہے، جب آپ کا گیم شائع یا اپ ڈیٹ ہوتا ہے تو اسے پڑھیں — شائع کریں۔ اسے تبدیل کرنے کے بعد اپ ڈیٹ کریں۔ یہ لفظی ہونا چاہیے۔ true یا false; کچھ بھی نہیں کے طور پر شمار کرتا ہے اعلان، اور ایک کھیل جو اعلان کرتا ہے کہ کچھ بھی پہلے جیسا برتاؤ نہیں کرتا ہے۔

اسکرپٹ گیم - ایک جامد persistent پر game اعتراض (دیکھیں۔ کھیل ہی کھیل میں سکرپٹ):

globalThis.game = {
  persistent: true,
  tickRateHz: 1,
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

کنٹینر گیم — persistent آپ میں GET /describe جواب (دیکھیں۔ کنٹینر گیم سرورز):

{ "protocol": 1, "tickRateHz": 20, "maxSessions": 48, "persistent": true }

سیشنز کیسے بنائے جاتے ہیں اس کے بارے میں کچھ بھی تبدیل نہیں ہوتا ہے: میچ میکنگ، دعوتیں، AI اینڈ پوائنٹ اور ریئل ٹائم تمام کمرے ایک مستقل کھیل کے لیے مستقل سیشن تیار کرتے ہیں۔

2. وقفے کے دوران کھیل کا وقت ساکن رکھیں

پلیٹ فارم دوبارہ نہیں لکھتا ہے۔ ctx.now - یہ حقیقی دیوار کی گھڑی رہتی ہے، لہذا کسی بھی وقت آپ کھلاڑیوں کو دکھائیں (ایک آخری تاریخ، a "پر فصل تیار") معنی رکھتا ہے جو یہ کہتا ہے۔ اس کے بجائے، مسلسل سیشنز کو ایک اضافی سیاق و سباق کا میدان ملتا ہے:

ctx.pausedMs   // total milliseconds this session has spent paused, so far

یہ صرف بڑھتا ہے، اور صرف مسلسل سیشنوں پر (دوسرے کھیل کبھی بھی میدان نہیں دیکھتے)۔ اسے اور آپ کو منہا کریں۔ ایک ہے کھیل کی گھڑی وہ رک جاتا ہے جب کہ وہاں کوئی نہیں ہوتا:

function gameTime(ctx) {
  return ctx.now - (ctx.pausedMs || 0);
}

globalThis.game = {
  persistent: true,
  tickRateHz: 1,

  createSession(ctx) {
    return { ok: true, sessionState: { lastTick: gameTime(ctx), crops: [] } };
  },

  onTick(ctx) {
    var state = ctx.sessionState;
    var t = gameTime(ctx);
    var dt = t - state.lastTick;      // never includes the time the world was paused
    state.crops.forEach(function (crop) { crop.growth += dt; });
    state.lastTick = t;
    return { ok: true, sessionState: state };
  },

  onPlayerMessage(ctx) { /* ... */ }
};

گیم ٹائم میں اپنے ٹائم اسٹیمپ اسٹور کریں (gameTime(ctx)) میں نہیں۔ ctx.now، اور صرف ان کا موازنہ کریں۔ کھیل کے وقت کے خلاف. اگر آپ چاہتے ہیں دنیا کو آگے بڑھنا ہے جب کہ کوئی نہیں دیکھ رہا ہے - فصلیں جو اگتی ہیں۔ راتوں رات - استعمال کریں۔ ctx.now اس کے بجائے اور دوبارہ شروع کرنے کے بعد پہلی ٹک کو پکڑیں۔ کسی بھی طرح سے یہ آپ کا ہے۔ انتخاب؛ پلیٹ فارم صرف رپورٹ کرتا ہے کہ کیا ہوا ہے۔

وقت کی دو تفصیلات:

  • آخری کھلاڑی کے جانے اور توقف کے درمیان ~15 سیکنڈ کے دوران، سیشن ابھی باقی ہے۔ عام طور پر ٹک. ایک کھلاڑی جس کا کنکشن گر جاتا ہے اور سیدھا واپس آتا ہے توقف کا سبب نہیں بنتا ہے۔
  • دوبارہ شروع کرنے کے بعد، اگلا onTick ایک ٹک وقفہ بعد میں آتا ہے۔ روکا ہوا وقت دوبارہ نہیں چلایا جاتا ہے۔ گم شدہ ٹِکس کے بیک لاگ کے طور پر۔

ایک کنٹینر وصول کرتا ہے۔ pausedMs اسی جگہ: میں POST /sessions جسم جب بھیجا جاتا ہے۔ سیشن ایک وقفے کے بعد بحال کیا جاتا ہے.

3. آپ کا کلائنٹ

ایک موقوف سیشن اب بھی ایک فعال سیشن ہے، لہذا کلائنٹ کا بہاؤ وہی ہے جو آپ کے پاس پہلے سے موجود ہے:

  • دوبارہ شامل ہونے کے لیے دنیا کی فہرست بنائیں کے ساتھ GET /api/v1/games/{slug}/sessions/mine. ہر اندراج میں ایک ہے۔ pausedAt ٹائم اسٹیمپ جب یہ موقوف ہے اور null جب کہ کوئی اس میں ہے، تاکہ آپ دکھا سکیں "روک دیا جب سے…" یا "2 دوست اب کھیل رہے ہیں۔" (دیکھیں۔ گیمز API — سیشنز).
  • دوبارہ شامل ہوں۔ کھول کر ws/v1/games?sessionId=… بالکل پہلے کی طرح. ریزیومے کے دوران ہوتا ہے۔ جڑیں کوئی خاص نہیں ہے۔ "دوبارہ شروع" اس کے لیے فریم — گیم صرف اس وقت چل رہا ہے جب آپ پہلی بار کمانڈ آجاتی ہے - لہذا درخواست کریں یا اپنے گیم کے عام مکمل ریاستی پیغام کا انتظار کریں، جیسا کہ آپ جاری رکھیں گے۔ کوئی بھی دوبارہ جڑیں۔
  • ناکام ریزیومے کو ہینڈل کریں۔ اگر پلیٹ فارم سیشن کو دوبارہ شروع نہیں کرسکتا ہے - زیادہ تر امکان ہے کہ ایک کنٹینر گیم جس کا سرور ابھی شروع ہو رہا ہے — آپ وصول کرتے ہیں۔ {"type":"error","error":"…"} اور ساکٹ کوڈ کے ساتھ بند ہے۔ 1001. سیشن رکا رہتا ہے اور کچھ بھی ضائع نہیں ہوتا ہے۔ تھوڑی دیر بعد دوبارہ جڑیں۔ بیک آف (چند سیکنڈ، بڑھتا ہوا)، اور شو "دنیا کی شروعات…" غلطی کے بجائے.
  • presence فریم معمول کے مطابق کام کرتے ہیں، لہذا دوسرے کھلاڑی دیکھتے ہیں کہ اس وقت دنیا میں کون ہے۔

4. ایک مستقل سیشن ختم کرنا

ایک مستقل سیشن ختم ہوتا ہے جب:

  • آپ کے گیم کی رپورٹس a result (اسکرپٹ کی واپسی کی قیمت یا کنٹینر کنٹرول پیغام)، یا
  • گیم کا مالک اسے ختم کرتا ہے (DELETE /api/v1/me/github-games/{id}/sessions/{sessionId}),
  • آخری رکن واضح طور پر بغیر کسی کمرے کے دنیا سے نکل جاتا ہے۔ /sessions/{id}/leave، یا
  • تعیناتی کی برقرار رکھنے کی پالیسی کے تحت اس کا موقوف شدہ ریکوری ڈیٹا ختم ہو جاتا ہے۔

منقطع ہونے سے رکنیت برقرار رہتی ہے۔ واضح طور پر چھوڑنے سے رکنیت ختم ہوجاتی ہے۔ دیکھیں سیشن لائف سائیکل اور ریکوری دونوں بہاؤ کے لیے۔

ایک نیا گیم طلب کرنا ہوتا ہے۔ نہیں کھلاڑی کے روکے ہوئے سیشنز کو ریٹائر کریں، اور موقوف سیشنز اب بھی شمار ہوتے ہیں۔ فی کھلاڑی کنکرنٹ سیشن کیپ کے خلاف (20 بذریعہ ڈیفالٹ)۔ کھلاڑیوں کو ختم کرنے کا راستہ دیں یا ایک دنیا چھوڑ دو - ایک "دنیا کو چھوڑ دو" اپنے اسکرپٹ کے جوابات کو a کے ساتھ کمانڈ کریں۔ resultمثال کے طور پر. ورنہ جس کھلاڑی نے اپنی ٹوپی بھر لی ہے وہ کوئی نئی شروعات نہیں کر سکتا۔

onPlayerMessage(ctx) {
  var msg = ctx.message.data;
  if (msg.type === "close-world" && ctx.message.from === ctx.sessionState.ownerId) {
    return { ok: true, sessionState: ctx.sessionState, result: { kind: "closed" } };
  }
  /* ... */
}

5. کنٹینر گیمز: پارکنگ

کنٹینر گیم کے لیے ایک وقفہ ہے a پارک:

  1. پلیٹ فارم ایک حتمی سنیپ شاٹ مانگتا ہے (GET /sessions/{id}/snapshot) اور اسے پائیدار طریقے سے ذخیرہ کرتا ہے۔
  2. یہ سیشن کو پھاڑ دیتا ہے (DELETE /sessions/{id})۔ آپ کا کنٹینر اس کی نقل کرنا بند کر دیتا ہے، اور اگر اس میں کوئی اور سیشن نہیں ہے اس کی بیکار مدت کے بعد تعیناتی کو روکا جا سکتا ہے۔
  3. اگلی شمولیت پر یہ اس کے ساتھ سیشن کو دوبارہ بناتا ہے۔ POST /sessions, ذخیرہ لے کر snapshot اور اپ ڈیٹ pausedMs - کریش ریسٹور کے طور پر ایک ہی درخواست - روکی ہوئی تعیناتی کو جگانا سب سے پہلے اگر ضرورت ہو.

اس لیے آپ جو سنیپ شاٹ واپس کریں گے وہ پوری دنیا کو دوبارہ بنانے کے لیے کافی ہونا چاہیے، نہ کہ صرف چند کو دوبارہ شروع کرنے کے لیے کھیل کے سیکنڈ. اگر وہ حتمی سنیپ شاٹ ناکام ہو جاتا ہے، تو سیشن اپنے آخری متواتر سے کھڑا ہو جاتا ہے۔ چوکی کریش کے برعکس، پارک اور ریسٹور کو آپ کے دوبارہ شروع کرنے والے بجٹ میں شمار نہیں کیا جاتا ہے، اور کھلاڑیوں کو نمبر ملتا ہے۔ resumed فریم: ریاست کو ریوائنڈ دیکھنے کے لیے کوئی نہیں تھا۔

چیک لسٹ

  • [ ] persistent: true اعلان کیا گیا (اسکرپٹ) یا واپس آیا /describe (کنٹینر)، اور ایک اپ ڈیٹ شائع ہوا۔
  • گیم ٹائمر استعمال کرتے ہیں۔ ctx.now - ctx.pausedMs، یا جان بوجھ کر استعمال کریں۔ ctx.now اور پکڑو.
  • کلائنٹ کی فہرست sessions/mine، دکھاتا ہے۔ pausedAt، اور دوبارہ شامل ہوتا ہے۔ ws/v1/games.
  • کلائنٹ ایک کے بعد بیک آف کے ساتھ دوبارہ کوشش کرتا ہے۔ error قریبی کوڈ کے بعد 1001 کنیکٹ پر
  • کھلاڑیوں کے پاس دنیا کو ختم کرنے کا ایک طریقہ ہوتا ہے، اس لیے وہ سیشن کیپ میں کبھی نہیں پھنستے۔
