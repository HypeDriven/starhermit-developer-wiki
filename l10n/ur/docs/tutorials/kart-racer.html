ٹیوٹوریل: ملٹی پلیئر کارٹ ریسر بنائیں

یہ ٹیوٹوریل آرکیڈ کارٹ ریسر کی ملٹی پلیئر پرت بناتا ہے — آٹھ کارٹس تک، نجی دوستوں کے ساتھ لابیاں، اجنبیوں کے ساتھ جلدی شامل ہونا، خالی گرڈ سلاٹ بھرنے والے CPU ڈرائیور، الٹی گنتی، لیپس، ایک فنشنگ آرڈر اور کامیابیاں — StarHermit API پر۔ یہ نیٹ کوڈ معاہدے کا احاطہ کرتا ہے۔ اور پلیٹ فارم کالز؛ آپ کا انجن، ٹریک آرٹ اور ہینڈلنگ ماڈل آپ کے اپنے ہیں۔

یہاں کھیل سے متعلق ہر چیز — the grand-prix قطار، بائنری فریم لے آؤٹ، آئٹم بٹن، طبیعیات کے مستقل - ایک مثالی قدر ہے۔ صرف اختتامی نقطے، فریم لفافے اور حدود ہیں۔ پلیٹ فارم کا رویہ، اور ہر ایک اس کے حوالہ کے صفحے سے لنک کرتا ہے۔

1. ایک فن تعمیر کا انتخاب کریں۔

سرور ٹک بجٹ کے لیے ریسر کھیل کی سب سے مشکل شکل ہے: کارٹس تیزی سے حرکت کرتے ہیں، ٹکراتے ہیں اور کھلاڑی 50 ایم ایس سٹیئرنگ وقفہ محسوس کرتے ہیں۔ StarHermit آپ کو اسے چلانے کے دو طریقے فراہم کرتا ہے، دونوں ایک سے شروع ہوتے ہیں۔ ریئل ٹائم کمرہ:

A. میزبان کی طرف جانے والا B. سرور مستند اسکرپٹ
جو نقل کرتا ہے۔ کمرے کے میزبان کا کلائنٹ، کسی بھی قیمت پر اسے پسند ہو (60 Hz+) آپ کا server= سکرپٹ، زیادہ سے زیادہ 30 ہرٹج
ٹرانسپورٹ بائنری فریم آن ws/v1/realtime JSON cmd/game فریم آن ws/v1/games
دھوکہ دہی میزبان قابل اعتماد ہے۔ کلائنٹس کے پاس کوئی اختیار نہیں ہے۔
ایلو، اسکرپٹ کی کامیابیاں نہیں (میزبان ایک بند نتیجہ پوسٹ کرتا ہے) ہاں - eloUpdates, achievements, ری پلے
کے لیے بہترین دوستوں کے ساتھ آرام دہ دوڑ، مکمل مخلص طبیعیات سادہ آرکیڈ فزکس کے ساتھ رینکڈ ریسنگ

سے شروع کریں۔ A جب تک کہ آپ کو درجہ بندی کے کھیل کی ضرورت نہ ہو۔ سیکشن 7 ظاہر کرتا ہے کہ کن تبدیلیوں کے لیے B. A کنٹینر سرور آٹھ کارٹ بھی چلا سکتے ہیں۔ کمرے سے منسلک نسل اور 60 ہرٹج پر مستند طریقے سے نقل کریں۔ اس کا براہ راست گیمز API میچ میکنگ فی الحال ایک مضمر 1v1 استعمال کرتا ہے۔ قطار، لہذا بڑے گرڈ کے لیے ایک حقیقی وقت کا کمرہ استعمال کریں۔ پلیٹ فارم کنٹینر کے لوپ کو آگے نہیں بڑھاتا ہے۔

2. ظاہر کرنا

اس کے ساتھ قابل تقسیم فولڈر شائع کریں۔ starhermit.txt اس کی جڑ میں (دیکھیں۔ ظاہر)۔ دی control.* لائنز کھلاڑیوں کو ایک ریبائنڈنگ UI دیتی ہیں اور آپ کا کلائنٹ a API کو کنٹرول کرتا ہے۔ بائنڈنگز پڑھنے کے لیے یہاں سے:

name=Turbo Hermits
launch=index.html
cover=art/cover.png
control.accelerate=KeyW+ArrowUp | Accelerate
control.brake=KeyS+ArrowDown | Brake / reverse
control.left=KeyA+ArrowLeft | Steer left
control.right=KeyD+ArrowRight | Steer right
control.drift=ShiftLeft+ShiftRight | Drift
control.item=Space | Use item

راستہ A کے پاس ہے۔ نہیں server= لائن اگر کوئی گیم اسکرپٹ بھیجتا ہے، تو کمرہ شروع کرنے سے ایک پابند سیشن بنتا ہے۔ اور صرف اسکرپٹ میچ کو ختم کر سکتا ہے — میزبان کا POST .../result ریس ختم ہونے کا راستہ روکتا ہے۔ (سیکشن 7)۔

3. سائن ان کریں اور بنیادی باتیں پڑھیں

پلیٹ فارم کی میزبانی والا گیم اس کے ساتھ کھولا جاتا ہے۔ #game_token=<jwt> یو آر ایل میں - اسے ایک بار پڑھیں، اس کے ساتھ پٹی کریں۔ history.replaceState، اور اس کی 60 منٹ کی میعاد ختم ہونے سے پہلے اسے تازہ کریں (تفصیلات شطرنج واک تھرو اور تصنیف)۔ آپ کی سلگ ٹوکن کی ہے۔ game_scope دعوی (یا location.hostnameکی پہلا لیبل؛ اسے کبھی ہارڈ کوڈ نہ کریں۔

لوڈ ہونے پر، مینو کی ضرورت کو حاصل کریں:

GET /api/v1/games/{slug}/controls     # effective key bindings (manifest defaults + overrides)
GET /api/v1/games/{slug}/settings     # camera, volume, last chosen kart — your own keys
GET /api/v1/realtime/rooms/mine       # 200 → the player is still in a race; rejoin it

کے ساتھ مینو کے انتخاب کو محفوظ کریں۔ PATCH /api/v1/games/{slug}/settings ({"settings":{"kart":"hermit-crab"}})۔ ترتیبات پوری مشینوں میں پلیئر کی پیروی کرتی ہیں اور کسی اعلان کی ضرورت نہیں ہے۔

4. لابی

ایک گراں پری سب کے لیے مفت ہے، اس لیے کمرے میں آٹھ نشستوں کی ایک ٹیم ہے۔ ٹریک، لیپ کاؤنٹ اور انجن کلاس مبہم میں جانا metadata:

POST /api/v1/realtime/rooms
Authorization: Bearer <launch token>

{ "teamCount": 1, "seatsPerTeam": 8, "backfillAfterSeconds": 45,
  "aiPlayers": 0, "name": "Friday cup", "isVisible": true,
  "metadata": { "track": "coral-loop", "laps": 3, "cc": 150 } }

لانچ ٹوکن کے ساتھ کمرے کا کھیل ٹوکن سے آتا ہے، تو gameSlug چھوڑ دیا جا سکتا ہے. خالق سیٹ پر میزبان ہے (0, 0). یہاں سے لابی عام کمرے کا بہاؤ ہے:

  • دوستو — POST /rooms/{id}/invites کے ساتھ {"toUserId": ...}. پلیٹ فارم انہیں مطلع کرتا ہے۔ انہیں نشستیں قبول کرنا۔ چھ کردار دکھائیں۔ joinCode تو دوست بھی اسے ٹائپ کر سکتے ہیں۔ POST /rooms/join-by-code.
  • اجنبی - میزبان کال کرتا ہے۔ POST /rooms/{id}/open. بغیر روم کال کے کھلاڑی POST /rooms/quick-join کے ساتھ {"seats": 1} اور، پر 404، خود بنائیں اور کھولیں۔
  • ووٹ / میزبان کی سوچ کی تبدیلی کو ٹریک کریں۔ — PATCH /rooms/{id} نئے کے ساتھ metadata اور کمرے کی revision کے طور پر expectedRevision.
  • CPUs کے خلاف سولو - کے ساتھ بنائیں "aiPlayers": 7، پھر POST /rooms/{id}/start.

ایک کھلا کمرہ اپنے طور پر شروع ہوتا ہے جب تمام آٹھ نشستیں بھر جاتی ہیں یا backfillAfterSeconds گزرتا ہے میزبان بھی کر سکتے ہیں POST /rooms/{id}/start. ہر خالی نشست AI شرکت کنندہ بن جاتی ہے - وہ آپ کی ہیں۔ سی پی یو ڈرائیورز۔

5. ریس ساکٹ (میزبان کے راستے)

جڑیں۔

ہر شریک ایک استعمال شدہ ٹکٹ کے ساتھ ریئل ٹائم ساکٹ کھولتا ہے:

const { ticket } = await api.post("/api/v1/realtime/connection-tickets"); // { ticket, expiresIn }
const ws = new WebSocket(
  `wss://api.starhermit.com/ws/v1/realtime?roomId=${roomId}&ticket=${encodeURIComponent(ticket)}`);
ws.binaryType = "arraybuffer";

ٹیکسٹ فریم JSON pushes اور کنٹرول فریم ہیں۔ بائنری فریم گیم پلے ہیں۔ دی roster دھکا ہے آپ کا گرڈ: شروع ہونے کے بعد یہ منجمد ہو جاتا ہے، AI سیٹیں شامل ہوتی ہیں۔ ایک ٹیم کے ساتھ، ایک کارٹ کا گرڈ سلاٹ اس کا ہے۔ شریک کی slot.

ws.onmessage = (e) => {
  if (typeof e.data === "string") return onControl(JSON.parse(e.data)); // roster, presence, event, ready, chat, result
  const bytes = new Uint8Array(e.data);
  const sender = guidFromDotNet(bytes.subarray(0, 16)); // server-stamped, trustworthy
  onGameplay(sender, new DataView(e.data, 16));          // your payload starts at byte 16
};

// The server prefixes the sender's participant id in .NET GUID byte order:
// the first three groups are little-endian.
function guidFromDotNet(b) {
  const h = (i) => b[i].toString(16).padStart(2, "0");
  return `${h(3)}${h(2)}${h(1)}${h(0)}-${h(5)}${h(4)}-${h(7)}${h(6)}-` +
         `${h(8)}${h(9)}-${h(10)}${h(11)}${h(12)}${h(13)}${h(14)}${h(15)}`;
}

اپنے پے لوڈ میں کبھی بھی پلیئر آئی ڈی نہ لگائیں اور اس پر بھروسہ کریں - 16 بائٹ کا سابقہ واحد شناخت ہے جس کی سرور ضمانت دیتا ہے۔

روٹنگ اور بجٹ

پلیٹ فارم میزبان کے ذریعے چلنے والے کھیل کی شکل کو نافذ کرتا ہے:

  • A مہمان کی بائنری فریم تک پہنچ جاتے ہیں صرف میزبان - یہ ان پٹ چینل ہے۔
  • دی میزبان کی بائنری فریم تک پہنچ جاتے ہیں ہر مہمان - یہ سنیپ شاٹ چینل ہے۔
  • ہر فریم زیادہ سے زیادہ ہے۔ 8 KB; ہر کنکشن بھیج سکتا ہے۔ 30 پیغامات/سیکنڈ (2× ایک کے لیے پھٹنا دوسرا)۔ اوپر جانے سے ساکٹ بند ہو جاتا ہے۔ PolicyViolation.

لہذا میزبان جو بھی شرح صحیح محسوس کرتا ہے اس پر نقل کرتا ہے (60 ہرٹج عام ہے) لیکن بھیجتا ہے پر سنیپ شاٹس 20 Hz، اور مہمان 20 Hz پر ان پٹ بھیجتے ہیں۔ یہ کبھی کبھار کنٹرول فریم کے لیے ہیڈ روم چھوڑ دیتا ہے۔

فریم لے آؤٹ (مثال)

ان پٹ، مہمان → میزبان، 7 بائٹس:

آفسیٹ قسم میدان
0 u8 1 = ان پٹ
1 u16 seq - ہر بھیجنے میں اضافہ
3 i8 اسٹیئر، −127…127
4 u8 تھروٹل، 0…255
5 u8 بٹس: 0 بریک، 1 ڈرفٹ
6 u8 itemPresses - ایک کاؤنٹر، پرچم نہیں

itemPresses آئٹم بٹن دبانے کی ایک چلتی گنتی ہے۔ 20 ہرٹز پر 50 ایم ایس سے چھوٹا پریس ہوگا۔ دوسری صورت میں نمونوں کے درمیان گر; کاؤنٹر کے ساتھ میزبان فی انکریمنٹ ایک آئٹم فائر کرتا ہے، تاہم پریس اترا.

سنیپ شاٹس، میزبان → مہمان، 4 + 22 بائٹس فی کارٹ (مکمل گرڈ کے لیے 176 بائٹس):

آفسیٹ قسم میدان
0 u8 2 = سنیپ شاٹ
1 u16 میزبان ٹک
3 u8 کارٹ شمار
فی کارٹ u8, f32 ×4, u8, u16, u8, u8 سلاٹ، ایکس، زیڈ، سرخی، رفتار، گود، چوکی، آئٹم، جھنڈے

مہمان دوسرے کارٹس پیش کرتے ہیں۔ ماضی میں ~100 ms, دو سنیپ شاٹس کے درمیان interpolating کہ اس وقت کو بریکٹ کریں، اور میزبان کی طرف آسانی پیدا کرتے ہوئے، ان کے ان پٹس سے مقامی طور پر ان کے اپنے کارٹ کی پیش گوئی کریں جب وہ متفق نہ ہوں تو پوزیشن۔ آخری ان پٹ شامل کریں۔ seq میزبان نے فی کارٹ میں لاگو کیا۔ flags یا ایک اضافی فیلڈ اگر آپ درست مفاہمت چاہتے ہیں۔

الٹی گنتی، ریس کے واقعات، ختم

کنٹرول فریم JSON ہیں، زیادہ سے زیادہ 4 KB، اور سرور سٹیمپ from بھیجنے والے کے شریک کی شناخت کے ساتھ:

  • مہمان بھیجتے ہیں۔ {"type":"ready"} ٹریک لوڈ ہونے کے بعد۔
  • میزبان ہر منسلک انسان کے تیار ہونے کا انتظار کرتا ہے (یا ٹائم آؤٹ)، پھر بھیجتا ہے۔ {"type":"event","kind":"countdown","goInMs":3000}. مہمان اپنی مقامی الٹی گنتی شروع کرتے ہیں۔ رسید - اس درستگی پر گھڑی کی مطابقت پذیری کی ضرورت نہیں ہے۔
  • دوسری ریس کی دھڑکنیں بھی ہیں۔ event فریم: {"kind":"lap","slot":3,"lap":2}, {"kind":"finished","slot":3,"place":1,"timeMs":94210}.
  • chat ہر کسی کے لیے دستیاب ہے، لیکن مہمان 10 کنٹرول فریم فی منٹ تک محدود ہیں۔ ready اور چند "gg"s، گیم پلے کے لیے نہیں۔

جب آخری انسان لائن کو عبور کرتا ہے (یا فاتح کے ختم ہونے کے بعد ٹائمر)، میزبان جمع کر دیتا ہے۔ نتیجہ، جو کمرے کو بند کرتا ہے اور دھکیلتا ہے۔ {"type":"result"} سب کو:

POST /api/v1/realtime/rooms/{id}/result

{ "teamScores": [0],
  "metadata": { "track": "coral-loop",
                "order": [ { "slot": 3, "timeMs": 94210 }, { "slot": 0, "timeMs": 95002 } ],
                "bestLapMs": 30112 } }

teamScores فی ٹیم بالکل ایک اندراج کی ضرورت ہے (کلیمپڈ 0–50)، جس میں a سب کے لیے مفت؛ حتمی ترتیب میں رہتا ہے metadata. ایک ٹیم کی دوڑ کے ساتھ ایک ہی کمرہ ہے teamCount: 2 اور ہر ٹیم کے پوائنٹس teamScores.

سی پی یو ڈرائیورز، لیورز اور میزبان تبدیلیاں

  • گاڑی چلانے کے لیے AI سیٹیں آپ کی ہیں۔ پلیٹ فارم سیٹ محفوظ رکھتا ہے اور ڈرائیور کا نام رکھتا ہے۔ میزبان کی تخروپن اسے چلاتا ہے (چیک پوائنٹس کے ذریعے ایک ریسنگ لائن، کچھ ربڑ بینڈنگ کے ساتھ)۔
  • ایک مہمان جو درمیانی دوڑ سے نکل جاتا ہے۔ (POST /rooms/{id}/leave) اپنے کارٹ کو گرڈ پر رکھتا ہے: روسٹر push ایک ہی شریک کو دکھاتا ہے۔ id اب isAi: true، اور میزبان کا CPU اس کارٹ کو سنبھال لیتا ہے۔
  • ایک مہمان جو گرتا ہے۔ ابھی بھی کمرے میں ہے؛ ان کے کارٹ کوسٹنگ رکھیں اور انہیں دوبارہ جڑنے دیں - تازہ ترین ساکٹ پرانے کی جگہ لے لیتا ہے۔
  • اگر میزبان چلا جائے۔، میزبان کا کردار سب سے طویل عرصے تک شامل ہونے والے بقیہ انسان کو جاتا ہے۔ روسٹر پش نیا دکھاتا ہے۔ isHost. ہر مہمان کے پاس پہلے سے ہی تازہ ترین مکمل سنیپ شاٹ ہوتا ہے، لہذا نیا میزبان اس سے نقل دوبارہ شروع کرتا ہے اور اسنیپ شاٹس بھیجنا شروع کرتا ہے۔ مہمانوں کے ان پٹ اب ان کی طرف جاتے ہیں۔ میزبان منتقلی آپ کے کوڈ کا کام ہے — پلیٹ فارم صرف کردار کو منتقل کرتا ہے۔
  • اگر میزبان صرف منقطع ہوجاتا ہے۔، کمرہ 60 سیکنڈ کے بعد میزبان ساکٹ کے بغیر بند ہوجاتا ہے۔

6. دوڑ کے ارد گرد

  • آواز اور بات چیت۔ ہر مہمان پہلے ہی کر سکتا ہے۔ chat ریئل ٹائم ساکٹ پر؛ آواز کے لیے، دیکھیں آواز.
  • دوبارہ میچ۔ رزلٹ آنے کے بعد کمرہ بند ہے۔ میزبان کو ایک نیا کمرہ بنانے اور مدعو کرنے کو کہیں۔ پچھلے روسٹر کے انسان، یا سب کو فوری شمولیت کے لیے واپس بھیجیں۔
  • لیپ ٹائم لیڈر بورڈز۔ گیم کا پلیٹ فارم لیڈر بورڈ اس کا ایلو بورڈ ہوتا ہے، جو صرف سرور کے ذریعے لکھا جاتا ہے۔ رن ٹائم پبلشر کی طرف سے بیان کردہ لیڈر بورڈ قبول کرتا ہے۔ POST /api/v1/leaderboards/{id}/submit، لیکن وہ کلائنٹ کے ذریعہ اسکور کا دعویٰ کیا جاتا ہے — دوستانہ ٹائم ٹرائل کے لیے جرمانہ، انعامات والی کسی چیز کے لیے نہیں۔

7. متغیر B: سرور سے مستند ریسنگ

درجہ بندی کے کھیل کے لیے، تخروپن کو اسکرپٹ میں منتقل کریں۔ لابی غیر تبدیل شدہ ہے؛ سکرپٹ شامل کریں اور مینی فیسٹ سے میچ میکنگ سیٹنگز:

server=server.js
matchmaking.max_wait_seconds=20
matchmaking.ai_players=7

اب دو چیزیں ریس بناتی ہیں: ایک کمرہ شروع کرنا اپنے انسانوں کے لیے ایک کمرہ بند سیشن بناتا ہے، اور میچ میکنگ (POST /api/v1/games/{slug}/matchmaking?queue=grand-prix) ایک تخلیق کرتا ہے جب آٹھ کھلاڑی مل جاتے ہیں — یا، اوپر کی ترتیبات کے ساتھ، 20 سیکنڈ کے بعد CPUs کے ساتھ سات تک خالی نشستیں دوستوں کی ایک لابی ایک ساتھ قطار میں لگ سکتی ہے۔ POST /realtime/rooms/{id}/matchmake.

کسی بھی طرح، کلائنٹ لے sessionId (کمرے کا gameSessionId، یا مماثل ٹکٹ) اور کھیلو ws/v1/games?sessionId=…. ریئل ٹائم ساکٹ، اگر کوئی ہے، صرف روسٹر کے لیے رکھا گیا ہے۔

سکرپٹ

پورا تخروپن چلتا ہے۔ onTick 30 ہرٹج کی چھت پر۔ ہر درخواست ایک تازہ سینڈ باکس ہے جو ملتا ہے sessionState میں اور اسے باہر واپس کرتا ہے، لہذا اس حالت کو چھوٹا رکھیں - یہ ہر ٹک کو سیریلائز کیا جاتا ہے۔

const TRACK = { laps: 3, radius: 14,
  checkpoints: [[0, 0], [120, 0], [160, 60], [120, 120], [0, 120], [-40, 60]] };

globalThis.game = {
  tickRateHz: 30,
  replays: true,
  queues: [{ key: "grand-prix", teams: 8, teamSize: 1 }],
  achievements: [
    { key: "chequered-flag", name: "Chequered Flag", description: "Win a race.", points: 10 }
  ],

  createSession(ctx) {
    const karts = racers(ctx).map((r, i) => ({
      id: r.id, name: r.name, ai: r.ai, x: -8 * (i % 2), z: -6 * i, heading: 0, speed: 0,
      cp: 1, lap: 0, boost: 0, boosts: 1, input: {}, ack: 0, finishedAt: null
    }));
    return { ok: true, sessionState: { t: ctx.now, goAt: ctx.now + 4000, karts, order: [] } };
  },

  onPlayerMessage(ctx) {                       // durable commands: discrete actions
    const s = copy(ctx.sessionState);
    const k = s.karts.find((k) => k.id === ctx.message.from);
    if (ctx.message.data?.type === "use-item" && k && k.boosts > 0 && ctx.now >= s.goAt) {
      k.boosts--; k.boost = 1.2;
    }
    return { ok: true, sessionState: s };
  },

  onTick(ctx) {
    const s = copy(ctx.sessionState);
    const dt = Math.min(Math.max((ctx.now - s.t) / 1000, 0), 0.1);
    s.t = ctx.now;
    for (const i of ctx.inputs || []) {        // latest realtime input per player since last tick
      const k = s.karts.find((k) => k.id === i.from);
      if (k) { k.input = i.data; k.ack = Math.max(k.ack, Math.floor(+i.data.seq) || 0); }
    }
    if (ctx.now >= s.goAt) {
      for (const k of s.karts) {
        if (k.finishedAt) continue;
        move(k, k.ai ? aiInput(k) : k.input, dt);   // pure motion — shared with the client
        progress(k, s, ctx);                        // checkpoints, laps, finish — server only
      }
    }
    const snap = s.karts.map((k) =>
      [k.id, r2(k.x), r2(k.z), r3(k.heading), r2(k.speed), r2(k.boost), k.lap, k.cp, k.ack]);
    const out = { ok: true, sessionState: s,
      broadcast: [{ to: "all", data: { type: "snap", t: s.t, goAt: s.goAt, karts: snap } }] };
    if (raceOver(s, ctx)) Object.assign(out, finish(s, ctx));
    return out;
  }
};

مددگار عام گیم کوڈ ہیں۔ پلیٹ فارم کو جن حصوں کی پرواہ ہے:

  • racers(ctx) گرڈ کو پڑھتا ہے جس سے بھی سیشن شروع ہوا تھا: ctx.room.roster a کے لیے کمرہ (AI سیٹیں ہیں۔ userId: null، تو انہیں آئی ڈی جیسے دیں۔ ai-0-5), ctx.matchmaking.seats a کے لیے میچ میڈ ریس (اس کے ساتھ سیٹیں چھوڑ دیں۔ id: null)، اور ctx.players.
  • move(k, input, dt) ضروری ہے ہر ان پٹ ویلیو کو بند کریں۔ — steer سے −1…1، throttle 0…1 سے کیونکہ ctx.inputs[].data جو کچھ بھی کلائنٹ نے بھیجا ہے۔ صرف from قابل اعتماد ہے. اسے پاک رکھیں- نہیں ctx، سیشن کی کوئی حالت نہیں - لہذا کلائنٹ اسے بھی چلا سکتا ہے (دیکھیں۔ کلائنٹ کی طرف کی پیشن گوئی).
  • بے ترتیبی اور وقت سے آئے ctx.random اور ctx.now; نہیں ہے Date یا Math.random.
  • finish(s, ctx) واپسی result (جس سے سیشن ختم ہوتا ہے اور، ایک کمرے کے لیے، اسے بند کر دیتا ہے) achievements فاتح کے لیے اگر انسان، اور eloUpdates انسانی ریسرز کے لیے - مثال کے طور پر جوڑے کے لحاظ سے مکمل ترتیب میں elo، سے پڑھیں اور واپس لکھیں۔ ctx.playerStates. AI نشستیں نہیں ہوسکتی ہیں۔ کھلاڑی کی حالت، درجہ بندی یا کامیابیاں حاصل کریں۔
  • raceOver ریسوں کو بھی ختم کرنا چاہئے کوئی بھی ختم نہیں کرسکتا - ہر انسان اس کے مطابق چلا گیا۔ ctx.presence (کمرے)، یا مشکل وقت کی حد۔
  • ری پلے کرتا ہے۔ صرف رکھیں حتمی sessionState. ایک کمپیکٹ لیپ ٹائم ٹیبل اور فنشنگ رکھیں اس میں آرڈر کریں، فی ٹک پوزیشن لاگ نہیں۔

کلائنٹ

اسٹیئرنگ کو ریئل ٹائم ان پٹ کے طور پر ہر ٹک اور مجرد اعمال کو پائیدار کمانڈز کے طور پر بھیجیں:

// ~30 Hz: latest-wins, batched into the next onTick
send({ type: "cmd", data: { type: "input", realtime: true, seq: ++seq,
                            steer, throttle, brake, drift } });

// on key press: a durable command, runs onPlayerMessage immediately
send({ type: "cmd", data: { type: "use-item" } });

اشیاء ضروری ہے ایک پائیدار کمانڈ کے ذریعے جانا. ریئل ٹائم ان پٹ ٹک، اور کے درمیان تازہ ترین جیت ہیں۔ پلیٹ فارم صرف ایک شاٹ فیلڈز کو محفوظ رکھتا ہے۔ pass, tackle اور shoot جب ایک نیا نمونہ ایک پرانے کی جگہ لے لیتا ہے — ریئل ٹائم ان پٹ میں کوئی دوسرا بٹن ٹک سے پہلے اوور رائٹ کیا جا سکتا ہے۔ اسے دیکھتا ہے.

achievement فریم ایک ہی ساکٹ پر آتے ہیں۔ پڑھیں GET /api/v1/games/{slug}/achievements پر کھلنے سے پہلے دی گئی کسی بھی چیز کے لیے لوڈ کریں۔

کلائنٹ کی طرف کی پیشن گوئی

صرف وہی پیش کرنے سے جو سرور بھیجتا ہے کارٹ کو ایسا محسوس ہوتا ہے جیسے یہ کیچڑ سے چل رہا ہے۔ ایک اسٹیئرنگ تبدیلی کو سرور تک پہنچنا ہے، اگلی ٹک کا انتظار کریں (30 ہرٹج پر 33 ایم ایس تک)، اور ایک میں واپس آنا ہے۔ snap - 80 ایم ایس پنگ پر جو کارٹ کے موڑنے سے پہلے 100 ایم ایس سے زیادہ ہے۔ پیشن گوئی اس کو چھپاتی ہے: کلائنٹ چالیں اس کا اپنا کارٹ فوری طور پر اور ہر ایک کا علاج کرتا ہے snap اصلاح کے طور پر، تصویر کے طور پر نہیں۔

موشن کوڈ کا اشتراک کریں۔

تخروپن کو اس طرح تقسیم کریں جس طرح اوپر اسکرپٹ کرتا ہے: ایک خالص move(k, input, dt) ہینڈلنگ کے لئے، اور صرف سرور progress چوکیوں، گودوں اور تکمیل کے لیے۔ سے موشن کوڈ کو بے نقاب کریں۔ server.js ایک دوسرے عالمی کے طور پر - پیٹرن شطرنج کے لئے استعمال کرتا ہے globalThis.chessRules - اور اسی فائل کو لوڈ کریں۔ براؤزر:

// server.js — shared by the platform's sandbox and the browser
function move(k, input, dt) { /* clamp input, integrate speed, heading, x, z, boost */ }
globalThis.kartPhysics = { move, TRACK };
globalThis.game = { /* ... as above ... */ };

<script src="server.js"></script>  <!-- defines kartPhysics; the client never calls game.* -->

کلائنٹ کی پیشن گوئی صرف تحریک. لیپس، پوزیشنز، آئٹمز اور فنش آرڈر سرور کا ہی رہتا ہے۔ کال تھوڑا سا ایک جیسے نتائج کی توقع نہ کریں: سینڈ باکس اور براؤزر کے آخری بٹس میں اختلاف ہو سکتا ہے Math.sin/Math.cos، اور پوزیشنیں snap گول ہیں. مفاہمت اس بہاؤ کو جذب کرتی ہے۔

سرور کی تال پر قدم رکھیں

سرور فی ان پٹ ایک قدم نہیں چلاتا ہے۔ ہر ٹک اس کا اطلاق ہوتا ہے۔ تازہ ترین ان پٹ اس کے لیے رکھتا ہے۔ وہ کارٹ، اس وقت تک استعمال کرتا رہتا ہے جب تک کہ کوئی نیا نہیں آتا، اور اس کے بعد سے حقیقی وقت میں ضم ہوجاتا ہے۔ پچھلے ٹک. لہذا ڈسپلے فریم کی شرح پر قدم رکھنے کے بجائے اس شکل کو آئینہ دیں:

const pending = [];                              // inputs the server hasn't acknowledged yet
let seq = 0, predicted, previous;               // { x, z, heading, speed, boost }, seeded from the first snap
let error = { x: 0, z: 0, heading: 0 };          // visual offset, decays in render()

setInterval(() => {                              // 30 Hz, the script's tickRateHz
  if (!predicted || serverNow() < goAt) return;  // the server ignores movement before goAt
  const input = { steer: readSteer(), throttle: readThrottle(), brake: held("brake"), drift: held("drift") };
  const entry = { seq: ++seq, input, dt: 1 / 30 };
  send({ type: "cmd", data: { type: "input", realtime: true, seq: entry.seq, ...input } });
  pending.push(entry);
  previous = { ...predicted };
  kartPhysics.move(predicted, input, entry.dt);  // the kart responds now, not a round trip later
}, 1000 / 30);

ٹک کی شرح سے زیادہ تیزی سے بھیجنا ضائع ہوتا ہے — فی ٹک صرف تازہ ترین ان پٹ استعمال کیا جاتا ہے — اور پلیٹ فارم ریئل ٹائم ان پٹ کو اپنے فی کنکشن کیپ سے اوپر گراتا ہے۔

ہر ایک پر صلح کریں۔ snap

اسکرپٹ کی بازگشت سنائی دیتی ہے۔ ack، سب سے زیادہ seq اس نے ہر کارٹ کے لیے درخواست دی ہے۔ ہر ایک پر snap، اپنے کو ریوائنڈ کریں۔ kart کو سرور کی حالت پر رکھیں اور اسے دوبارہ چلائیں جو سرور نے ابھی تک نہیں دیکھا:

function onSnap(snap) {
  const [, x, z, heading, speed, boost, lap, cp, ack] = snap.karts.find((k) => k[0] === myId);
  while (pending.length && pending[0].seq <= ack) pending.shift();   // applied or superseded

  const corrected = { x, z, heading, speed, boost };
  for (const p of pending) kartPhysics.move(corrected, p.input, p.dt);

  if (!predicted) { predicted = corrected; previous = { ...corrected }; return; } // first snap
  error.x += predicted.x - corrected.x;          // what the player would see jump
  error.z += predicted.z - corrected.z;
  error.heading += predicted.heading - corrected.heading;
  if (Math.hypot(error.x, error.z) > 3) error = { x: 0, z: 0, heading: 0 }; // wall hit, bump: snap
  predicted = corrected;
  hud.lap = lap; hud.checkpoint = cp;            // progress is never predicted
}

تک ہر چیز کو ترک کرنا ack درست ہے حالانکہ تازہ ترین جیت کچھ ان پٹ کو چھوڑ دیتی ہے: ایک چھوڑ دیا گیا۔ سرور پر ٹک لگنے سے پہلے ان پٹ کو ختم کر دیا گیا تھا، لہذا اس نے سرور کے کارٹ کو بھی کبھی متاثر نہیں کیا۔

ہموار اصلاحات، فریم ریٹ پر پیش کریں۔

چھوٹی اصلاحات پوشیدہ ہونی چاہئیں۔ کارٹ کو پیش گوئی کی گئی پوزیشن کے علاوہ ایک بوسیدہ ہونے پر کھینچیں۔ غلطی کو آفسیٹ کریں، اور آخری دو 30 ہرٹز پیشین گوئی کے مراحل کے درمیان انٹرپولیٹ کریں تاکہ 60 یا 144 ہرٹز ڈسپلے آسانی سے چلتا ہے:

function render(frameDt) {
  const decay = Math.exp(-frameDt / 0.1);        // ~100 ms to absorb a correction
  error.x *= decay; error.z *= decay; error.heading *= decay;
  const a = sinceLastStep() * 30;                // 0…1 between prediction steps
  drawKart(lerp(previous.x, predicted.x, a) + error.x,
           lerp(previous.z, predicted.z, a) + error.z,
           lerpAngle(previous.heading, predicted.heading, a) + error.heading);
}

کٹائی کی بجائے سنیپ تھریشولڈ کو ٹیون کریں: کارٹ کی لمبائی سے بڑی اصلاح حقیقی ہے۔ ایونٹ (ایک ٹکرانا جس کی آپ نے پیش گوئی نہیں کی تھی) اور ایک سست سلائیڈ کے مقابلے میں ایک فوری سنیپ کے طور پر بہتر پڑھتا ہے۔

جانیں کہ کیا پیشن گوئی نہیں کرنی ہے۔

  • دیگر کارٹس۔ وہ ماضی میں ~100 ms بنائے گئے ہیں (بفر snaps اور کے درمیان interpolate دو وہ بریکٹ serverNow() - 100)، تو ان کے خلاف پیش گوئی کی گئی تصادم کے ساتھ تصادم ہے۔ جہاں وہ تھے. دیواروں اور ٹریک کی پیش گوئی کریں - وہ حرکت نہیں کرتے ہیں - اور سرور کو حل کرنے دیں۔ kart-to-kart bumps. تصحیح راؤنڈ ٹرپ کے اندر پہنچ جاتی ہے۔ اگر بفر خشک ہو جائے تو ایکسٹرپولیٹ کریں۔ رفتار سے اور ~100 ms تک کی طرف بڑھیں، پھر پکڑیں۔
  • اشیاء. use-item ایک پائیدار کمانڈ ہے، لہذا یہ اندر چلتی ہے۔ onPlayerMessage جیسے ہی یہ آتا ہے - کوئی ٹک انتظار نہیں. کلید دبانے پر شعلہ اور آواز بجائیں۔ رفتار کے ذریعے پہنچنے دو مفاہمت، کے بعد سے boost میں ہے snap. اگر سرور انکار کرتا ہے (کوئی چارجز باقی نہیں ہیں)، اگلا snap اسے واپس رول کرتا ہے.
  • ریس ریاست۔ گود کی گنتی، پوزیشن اور ختم سے آتے ہیں snap اور صرف آپ کے اسکرپٹ کی نشریات۔

سرور کی گھڑی کا اندازہ لگائیں۔

snap.t اور goAt سرور کا وقت ہے (ctx.now)۔ سب سے چھوٹے مشاہدہ شدہ فرق سے ایک آفسیٹ رکھیں، جو سست ترسیل کو فلٹر کرتا ہے:

let offset = Infinity;
function noteSnap(snap) { offset = Math.min(offset, performance.now() - snap.t); }

سے الٹی گنتی شروع کریں۔ goAt، اور اس پر گیٹ کی پیشن گوئی جیسا کہ اوپر کا لوپ کرتا ہے۔ ایک کارٹ جو حرکت کرتا ہے۔ پہلے goAt مقامی طور پر سب سے پہلے ربڑ کی پٹی گرڈ پر واپس آجاتی ہے۔ snap آغاز کے بعد.
