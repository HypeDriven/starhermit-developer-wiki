ایک گیم کا دعوی کریں کسی اور نے شامل کیا

اگر کسی نے پہلے ہی آپ کے عوامی GitHub گیم کو StarHermit میں شامل کیا ہے، تو آپ کو ایک بنانے کی ضرورت نہیں ہے۔ دوسری فہرست. موجودہ فہرست کا تصدیق شدہ مالک بننے کا دعوی کریں اور اس کے میٹا ڈیٹا کا نظم کریں، ہوسٹنگ، تعیناتی، سرور پسدید، اور مستقبل کی منتقلی۔

ریپوزٹری کنٹرول کے ذریعے دعویٰ محفوظ ہے۔ گیم آئی ڈی یا ریپوزٹری یو آر ایل جاننا کافی نہیں ہے۔ آپ کو دو طریقوں میں سے کسی ایک میں کنٹرول ثابت کرنا ہوگا:

  1. ذاتی GitHub اکاؤنٹ کو لنک کریں جو ذخیرہ کا مالک ہے؛ یا
  2. اپنی ناقابل تغیر StarHermit صارف ID بطور عہد کریں۔ owner= ذخیرہ میں starhermit.txt.

دوسرا طریقہ خاص طور پر تنظیم کی ملکیت والے ذخیروں کے لیے مفید ہے، کیونکہ موجودہ GitHub لاگ ان چیک ذاتی ذخیرے کے مالکان سے میل کھاتا ہے اور تنظیم کی رکنیت کا اندازہ نہیں لگاتا۔

کیا دعویٰ بدلتا ہے۔

ایک کامیاب دعویٰ:

  • موجودہ گیم/ لسٹنگ ID اور اس کی جمع شدہ تاریخ کو برقرار رکھتا ہے۔
  • آپ کے لیے فہرست کے مینیجنگ StarHermit صارف کو تبدیل کرتا ہے۔
  • فہرست کو بطور نشان زد کرتا ہے۔ isVerifiedOwner: true;
  • سے قابل اعتماد میٹا ڈیٹا اور کنٹرولز کو تازہ کرتا ہے۔ starhermit.txt جہاں قابل اطلاق ہو؛
  • ایک اعلان کردہ اسکرپٹ/کنٹینر پسدید کی فراہمی یا تازہ کاری کرتا ہے۔
  • پلیٹ فارم ہوسٹنگ کو قابل بناتا ہے جہاں دستیاب ہو اور قطار میں تعیناتی کو بطور pending;
  • اس شخص سے انتظامی رسائی کو ہٹاتا ہے جس نے اصل میں وہ فہرست جمع کرائی تھی۔

دعوی کرنے سے پچھلے جمع کنندہ کو آپ کے GitHub اکاؤنٹ تک رسائی نہیں ملتی ہے، اور یہ ضم نہیں ہوتا ہے۔ StarHermit صارف اکاؤنٹس۔ یہ اس مخصوص فہرست کے انتظام کو منتقل کرتا ہے۔

اس سے پہلے کہ آپ شروع کریں۔

آپ کو ضرورت ہے:

  • ایک StarHermit اکاؤنٹ اور مکمل صارف تک رسائی کا ٹوکن — گیم اسکوپڈ لانچ ٹوکن نہیں۔
  • اگر استعمال کر رہے ہیں تو ذخیرہ تک رسائی لکھیں۔ owner= ثبوت کا طریقہ.
  • موجودہ StarHermit لسٹنگ ID۔
  • کلون شدہ ریپوزٹری گیم کے لیے، ایک درست starhermit.txt ذخیرہ کی جڑ میں.

صرف github.com/<owner>/<repo> ریپوزٹریز اور ان کی GitHub صفحات کی سائٹیں اس دعوے میں حصہ لیتی ہیں۔ بہاؤ ایک صوابدیدی میزبانی شدہ URL میں ثابت کرنے کے لیے GitHub ذخیرہ کی ملکیت نہیں ہے اور اس کا دعویٰ نہیں کیا جا سکتا راستہ

ذیل میں استعمال کی مثالیں:

API=https://api.starhermit.com
ACCESS_TOKEN='your-full-user-access-token'
OWNER='your-github-login'
REPO='your-game-repository'

آخری 15 منٹ تک ٹوکن تک رسائی حاصل کریں۔ اگر اس کی میعاد ختم ہونے کے قریب ہے تو اسے شروع کرنے سے پہلے ریفریش کریں۔

مرحلہ 1: موجودہ فہرست تلاش کریں۔

مشترکہ کھیلوں کی فہرست:

curl -sS "$API/api/v1/github-games" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

ہر آئٹم میں ناقابل تغیر فہرست شامل ہے۔ id، عام repoUrl, ownerLogin, repoName, the موجودہ جمع کنندہ، اور ملکیت کی حیثیت:

{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "repoUrl": "https://github.com/octocat/orbit-league",
  "ownerLogin": "octocat",
  "repoName": "orbit-league",
  "displayName": "Orbit League",
  "isVerifiedOwner": false,
  "submittedByUserId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "submittedByUsername": "someone-else"
}

دونوں پر میچ ownerLogin اور repoName; کسی گیم کو صرف اس لیے منتخب نہ کریں کہ اس کا ڈسپلے نام ہے۔ اسی طرح کے ساتھ jq:

GAME_ID=$(
  curl -sS "$API/api/v1/github-games" \
    -H "Authorization: Bearer $ACCESS_TOKEN" |
  jq -r --arg owner "$OWNER" --arg repo "$REPO" \
    '.[] | select((.ownerLogin | ascii_downcase) == ($owner | ascii_downcase)
               and (.repoName | ascii_downcase) == ($repo | ascii_downcase)) | .id' |
  head -n1
)

printf 'Listing ID: %s\n' "$GAME_ID"

اگر نتیجہ خالی ہو تو روک دیں۔ غیر متعلقہ فہرست سے کاپی کی گئی ID کے ساتھ کلیم کال نہ کریں۔

مرحلہ 2: ملکیت ثابت کرنے کا طریقہ منتخب کریں۔

آپشن A: ریپوزٹری کے مالک کے GitHub اکاؤنٹ کو لنک کریں۔

اسے اس وقت استعمال کریں جب ریپوزٹری براہ راست آپ کے ذاتی GitHub لاگ ان کی ملکیت ہو۔

StarHermit کے اکاؤنٹ/ترتیبات کے بہاؤ سے، GitHub OAuth in شروع کریں۔ لنک موڈ میں سائن ان ہونے کے دوران StarHermit اکاؤنٹ جو گیم کا انتظام کرے۔ جوڑنا اتفاقی طور پر تخلیق کرنے سے مختلف ہے۔ GitHub سائن ان کے ساتھ دوسرا StarHermit اکاؤنٹ۔

API کا بہاؤ یہاں سے شروع ہوتا ہے:

GET /api/v1/auth/oauth/github/authorize?link=true

یہ براؤزر سے چلنے والا ہے اور قلیل المدت ریاستی کوکی استعمال کرتا ہے۔ لنک کرنے کے لیے حالیہ StarHermit کی ضرورت ہے۔ تصدیق اسی براؤزر سیشن میں GitHub کی اجازت مکمل کریں جس نے اسے شروع کیا۔

نتیجہ کی تصدیق کریں:

curl -sS "$API/api/v1/me/github" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

متوقع:

{ "linked": true, "login": "octocat" }

لوٹا ہوا لاگ ان موجودہ لسٹنگ سے مماثل ہونا چاہیے۔ ownerLogin، کیس غیر حساس۔ ایک ذاتی GitHub لاگ ان کسی ایسی تنظیم کی رکنیت کو ثابت نہیں کرتا جو مخزن کی مالک ہو۔ ایک کے لیے تنظیم کے زیر ملکیت ذخیرہ، اختیار B استعمال کریں۔

اختیار B: شامل کریں۔ owner= کو starhermit.txt

اس سے کنٹرول ثابت ہوتا ہے کیونکہ صرف وہی شخص جو ذخیرہ مواد کو شائع کرنے کے قابل ہوتا ہے وہ قدر میں اضافہ کر سکتا ہے۔ سیٹ owner آپ کے ناقابل تبدیل StarHermit صارف ID (UUID) پر، نہیں آپ کا صارف نام یا عرفی نام۔

اپنی شناخت حاصل کریں:

STARHERMIT_USER_ID=$(
  curl -sS "$API/api/v1/me" \
    -H "Authorization: Bearer $ACCESS_TOKEN" |
  jq -r '.id'
)

ریپوزٹری روٹ پر، بنائیں یا اپ ڈیٹ کریں۔ starhermit.txt:

name=Orbit League
# (There is no slug key: the platform assigns your game a uid and uses it as the
# slug — the same value as its <uid>.starhermit.com address. Nothing can choose
# it, so two games can never contend for a name. Your client reads its own slug
# from the launch token's game_scope claim.)
launch=index.html
owner=3fa85f64-5717-4562-b3fc-2c963f66afa6

مثال کے مالک کو اس سے بدل دیں۔ STARHERMIT_USER_ID. اپنا صارف نام یا عرفی نام یہاں مت ڈالیں؛ وہ تبدیل ہو سکتے ہیں، جبکہ صارف ID مستحکم ملکیت کا شناخت کنندہ ہے۔

ایک مستند گیم کے لیے، بالکل ایک بیک اینڈ ڈیکلریشن برقرار رکھیں:

# JavaScript runtime:
server=server.js

# OR container runtime, never both:
# container.image=ghcr.io/your-org/orbit-server@sha256:<64-lowercase-hex>

ریپوزٹری/ورژن پر مینی فیسٹ کو کمٹ اور پش کریں StarHermit پڑھ سکتا ہے:

git add starhermit.txt
git commit -m "Declare StarHermit game ownership"
git push

دعوی کرنے سے پہلے، ذخیرہ کا خام کھولیں starhermit.txt ایک غیر تصدیق شدہ براؤزر میں URL اور تصدیق کریں کہ نئی قدر عوامی طور پر پڑھنے کے قابل ہے۔ دعویٰ درخواست کے وقت ذخیرہ کو پڑھتا ہے۔ ایک بلدیاتی تبدیلی کچھ ثابت نہیں کر سکتی۔

مرحلہ 3: مینی فیسٹ کی توثیق کریں۔

عام کلون شدہ ریپوزٹری گیم کے لیے، دعوی کرنے کی ضرورت ہے:

  • starhermit.txt ذخیرہ کی جڑ میں؛
  • غیر خالی name=;
  • launch= ایک مخزن رشتہ دار کی طرف اشارہ کرنا .html یا .htm فائل
  • ایک درست اختیاری server= راستہ ختم ہوتا ہے۔ .js/.mjs، یا ایک درست container.image= اعلان؛
  • کبھی بھی دونوں سرور رن ٹائم ایک ساتھ نہیں۔

ایک GitHub صفحات کی فہرست اپنے میزبان یو آر ایل کو لانچ کے ہدف کے طور پر رکھتی ہے اور اسے مینی فیسٹ کی ضرورت نہیں ہوتی ہے۔ جب ذاتی GitHub کی ملکیت ثابت ہو جائے، حالانکہ ایک درست مینی فیسٹ نام اب بھی اس کو اپ ڈیٹ کر سکتا ہے ڈسپلے نام.

اگر گیم کنٹینر کا اعلان کرتا ہے، تو اس کی تصویر کو رجسٹری، مالک کے نام کی جگہ، اور ڈائجسٹ کو پورا کرنا چاہیے۔ میں قوانین کنٹینر کی میزبانی والے گیم سرورز. کنٹینر ہوسٹنگ بھی ہو سکتی ہے۔ پلیٹ فارم آپریٹر کے ذریعہ محدود۔

مرحلہ 4: فہرست کا دعوی کریں۔

دعوے کی درخواست کا کوئی باڈی نہیں ہے:

curl -sS -X POST \
  "$API/api/v1/me/github-games/$GAME_ID/claim" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

ایک کامیاب 200 اپ ڈیٹ شدہ گیم واپس کرتا ہے:

{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "repoUrl": "https://github.com/octocat/orbit-league",
  "ownerLogin": "octocat",
  "repoName": "orbit-league",
  "displayName": "Orbit League",
  "launchPath": "index.html",
  "gameSlug": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "isVerifiedOwner": true,
  "metadataSource": "starhermit.txt",
  "hosting": {
    "hostingEnabled": true,
    "deployStatus": "pending"
  }
}

ID وہی ہونی چاہئے جو مرحلہ 1 میں پائی گئی ہے۔ کامیاب دعوے کے بعد نئی فہرست نہ بنائیں۔

ایسی فہرست کا دعوی کرنے کی اجازت ہے جس کا آپ پہلے سے انتظام کرتے ہیں۔ یہ منشور کو دوبارہ پڑھتا ہے، بیک اینڈ کو دوبارہ فراہم کرتا ہے، اور ہوسٹنگ کی درخواست کرتا ہے، لہذا اسی کال کو دوبارہ ہم آہنگ کرنے کے لیے استعمال کیا جا سکتا ہے۔ ذخیرہ کی تبدیلیوں کے بعد مالک کے زیر انتظام کھیل۔

مرحلہ 5: ٹیک اوور اور تعیناتی کی تصدیق کریں۔

تصدیق کریں کہ گیم اب آپ کی زیر انتظام فہرست میں ظاہر ہوتا ہے:

curl -sS "$API/api/v1/me/github-games" \
  -H "Authorization: Bearer $ACCESS_TOKEN" |
jq --arg id "$GAME_ID" '.[] | select(.id == $id)'

تعیناتی کی حالت چیک کریں:

curl -sS \
  "$API/api/v1/me/github-games/$GAME_ID/deployment" \
  -H "Authorization: Bearer $ACCESS_TOKEN"

ایک دعوی عام طور پر تعیناتی کی قطار لگاتا ہے، لہذا pending فوری طور پر دعوی عام ہونے کے بعد. کے ساتھ پول بیک آف جب تک کہ یہ ماحول کی رواں/کامیابی کی حالت تک نہ پہنچ جائے یا بے نقاب ہو جائے۔ deployError.

ٹیک اوور کے بعد، آپ کے لیے دستیاب مینجمنٹ اینڈ پوائنٹ میں شامل ہیں:

PUT    /api/v1/me/github-games/{id}/deployment  pin a commit/branch and redeploy
POST   /api/v1/me/github-games/{id}/bundle      upload built client/container output
PUT    /api/v1/me/github-games/{id}/hosting     requeue hosting where supported
POST   /api/v1/me/github-games/{id}/transfer    transfer management deliberately
DELETE /api/v1/me/github-games/{id}             remove the game

اصل جمع کنندہ اس فہرست کو مزید نہیں دیکھتا ہے۔ GET /api/v1/me/github-games اور نہیں کر سکتے اس کے لیے مالک کے دائرہ کار کے انتظام کے اختتامی نکات کا استعمال کریں۔

خرابی کا سراغ لگانا

403: ذخیرہ کے مالک کو لنک کریں یا شامل کریں۔ owner=

منسلک GitHub لاگ ان مماثل نہیں ہے۔ ownerLogin، یا ظاہر owner بالکل مماثل نہیں ہے آپ کا StarHermit صارف ID۔

  • چیک کریں۔ GET /api/v1/me/github.
  • عین مطابق چیک کریں۔ ownerLogin عوامی فہرست کے ذریعہ واپس کیا گیا۔
  • تنظیم کے ذخیروں کے لیے، استعمال کریں۔ owner=<your StarHermit user ID> ریپو میں.
  • تصدیق کریں کہ آپ نے مینی فیسٹ کو آگے بڑھایا ہے اور اس کا خام URL عوامی طور پر پڑھنے کے قابل ہے۔

404: اس ID کے ساتھ کوئی مشترکہ گیم نہیں۔

ID غلط ہے، یا فہرست کو ہٹا دیا گیا تھا۔ مرحلہ 1 کو دہرائیں۔ ہٹائی گئی فہرستیں قابل دعوی نہیں ہیں۔

400: غائب یا غلط starhermit.txt

کلون شدہ ذخیرہ کے لیے، یقینی بنائیں کہ روٹ مینی فیسٹ درست ہے۔ name اور HTML launch اقدار بھی اختیاری اسکرپٹ/کنٹینر کے اعلانات کی توثیق کریں۔ دعوی اصل میں میٹا ڈیٹا پر بھروسہ نہیں کرتا ہے۔ غیر مالک کی طرف سے داخل؛ یہ اسے ریپوزٹری کے زیر کنٹرول میٹا ڈیٹا سے بدل دیتا ہے۔

slug/backend کے ارد گرد دعوی ناکام ہو جاتا ہے۔

سکرپٹ غلط ہو سکتا ہے یا کنٹینر ہوسٹنگ دستیاب نہیں ہو سکتی ہے۔ واپس آنے والی غلطی کو چیک کریں اور پسدید اعلامیہ، پھر دوبارہ دعوی کو کال کریں۔ پلیٹ فارم گیم کے UUID کو اس کے سلگ کے طور پر تفویض کرتا ہے۔ منتخب کرنے یا حل کرنے کے لیے کوئی واضح سلگ نہیں ہے۔

GitHub کو لنک کیا گیا تھا لیکن غلط StarHermit اکاؤنٹ لنک کا مالک ہے۔

مطلوبہ StarHermit اکاؤنٹ میں سائن ان کریں اور OAuth کو مکمل کریں۔ لنک وہاں بہاؤ. دعویٰ نہ کریں۔ ایک عارضی دوسرے StarHermit اکاؤنٹ سے اور پھر اکاؤنٹ کے انضمام پر انحصار کریں؛ API ٹرانسفر گیم انتظامیہ، صارف کی شناخت نہیں۔

سیکیورٹی نوٹ

  • ریپوزٹری کی ملکیت کے ثبوت کے طور پر دعوی کے لنک یا لسٹنگ ID کو کبھی بھی قبول نہ کریں۔
  • GitHub تک رسائی کے ٹوکن، کنٹینر کی اسناد، یا دیگر راز اس میں نہ ڈالیں۔ starhermit.txt.
  • میں ہمیشہ ناقابل تبدیل StarHermit صارف ID استعمال کریں۔ owner=; صارف نام یا عرفی نام استعمال نہ کریں۔
  • دعوی کرنے سے پہلے موجودہ لسٹنگ اور ریپوزٹری URL کا جائزہ لیں؛ ڈسپلے نام منفرد نہیں ہیں۔
  • اگر آپ بعد میں گیم کو منتقل کرتے ہیں، تو وصول کنندہ مینیجر بن جاتا ہے لیکن تصدیق شدہ مالک کا درجہ ہوتا ہے۔ دوبارہ ترتیب دیں اگر وہ ریپوزٹری کو کنٹرول کرتے ہیں تو انہیں کلیم فلو خود چلانا چاہیے۔
