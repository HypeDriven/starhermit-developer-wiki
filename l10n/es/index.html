Wiki para desarrolladores StarHermit

Documentación para la API pública de estrellaermitaño - un juego/software distribución + plataforma social: usuarios & Autenticación OAuth, amigos, chat de texto, voz en tiempo real, editores, un catálogo de software con compilaciones/activos, derechos, logros, tablas de clasificación, un relevo entre pares, y juegos multijugador autorizados por el servidor cuyas reglas se ejecutan ya sea en un archivo JavaScript en espacio aislado o un contenedor proporcionado por el desarrollador. Esta wiki es una integración general. guía para cualquier juego dirigido a la plataforma.

El ejemplo de referencia utilizado en esta wiki es HypeDriven/ajedrez ermitaño estrella - un juego de ajedrez por correspondencia (sitio estático sin compilación + un archivo de reglas JS del lado del servidor) que utiliza tokens de lanzamiento, emparejamiento elo, invitaciones de amigos, WebSocket de juego, chat en el juego, voz, tablas de clasificación y repeticiones, jugables en vivo en 83fd04b1-3cbe-4b09-a251-3733ad4b9d94.starhermit.com (La dirección de un juego es el uid asignado a la plataforma, no su nombre). Es una implementación concreta de los patrones descritos aquí, no es el tema de los documentos.

Por donde empezar

  • Inicio rápido del navegador — descargue un juego completo con inicio de sesión de cuenta, aceptación de términos explícitos, guardado seguro en la nube y juego para un jugador sin seguimiento.

  • Elige una integración — compare juegos exclusivos de navegador, salas enrutadas por host, scripts, contenedores y títulos de catálogos.

  • Credenciales e identificadores – qué tokens pueden llamar a qué API y en qué se diferencian los ID de juego, usuario, sesión, sala y participante.

  • Convenciones API — análisis de respuesta/error, unidades de marca de tiempo, paginación, semántica de actualización y reintentos.

  • Solución de problemas — diagnosticar inicio de sesión, alcance, guardar conflictos, sockets, cargas e inicio de contenedores.

  • Ciclo de vida y recuperación de la sesión. — pausar/reanudar, desconectar versus salir, límites de instantáneas y vencimiento de la recuperación.

  • Disponibilidad y confianza — API disponibles, opcionales, de vista previa y reservadas; lo que hace que una puntuación sea confiable.

  • Contratos REST y WebSocket — OpenAPI descargable, esquemas de marco JSON y diseños binarios.

  • Sincronización segura guardada en la nube — un completo asistente de carga/validación/escritura condicional con manejo de conflictos.

  • El starhermit.txt manifiesto - el único archivo de cada juego publicado necesita, dónde debe ubicarse en la carpeta que carga y por qué esa carpeta debería ser su compilación distribuible: todo lo que está al lado del manifiesto se carga y se entrega a los jugadores. También cubre la vida útil de la caché de activos y orígenes CORS adicionales.

  • Empezando — URL base, control de versiones, modelo de autenticación y el formas de integrar (un juego de plataforma publicado desde GitHub o subido como una carpeta, con un script opcional o servidor de contenedor, o un cliente externo que llama directamente a la API REST/WS).

  • Tutorial: tutorial de integración de un extremo a otro (usando el ejemplo de referencia de ajedrez) — el ciclo de vida completo desde el token de lanzamiento hasta el visor de repetición, con las llamadas exactas de un cliente de juego hace, ilustrado por la implementación de referencia del ajedrez.

  • Tutorial: usa IA para conectar StarHermit a tu juego — indicaciones que se pueden copiar y pegar para un asistente de codificación de IA, una por función más una en conjunto mega-rápido.

  • Tutorial: publicar un servidor dedicado y jugadores integrados en el juego — envíe un paquete de contenedores, renueve su token de servidor y use el registro de clave pública para incorporarlo Steam/Epic/GOG/jugadores nativos sin OAuth o una visita al panel de StarHermit.

  • Tutorial: jugadores incorporados con clave pública - crear e inicie sesión en una cuenta de StarHermit con una clave que el juego genera en el dispositivo del jugador y una confirmación enviada por correo electrónico: formatos de clave, los bytes exactos para firmar, espera de confirmación, sesiones, segundos dispositivos y claves perdidas, y lo que una cuenta de solo clave no puede hacer.

  • Tutorial: cargar compilaciones desde CI/CD — inscribir a un dedicado implementar la clave pública desde una sesión de OAuth, autenticar de forma no interactiva y publicar el cliente o compilaciones de contenedores a partir de GitHub Actions (incluidas cargas grandes a través de WebSockets).

  • Tutorial: construye un corredor de karts multijugador - un ocho karts corredor en salas en tiempo real: vestíbulos, acceso rápido, controladores de CPU, código de red binario enrutado por el host dentro del límites de velocidad de socket, migración de host y una variante de script de 30 Hz autorizada por el servidor para juego clasificado, con predicción y conciliación del lado del cliente.

  • Tutorial: sesiones persistentes: juegos que se detienen cuando todos se van — optar por un script o juego contenedor en sesiones que se detengan en lugar de finalizar, mantener los relojes del juego quietos con ctx.pausedMsy volver a unirse a mundos en pausa desde el cliente.

  • Tutorial: tablas de clasificación y logros para tu juego — como propietario de un juego, eres su editor: crea tableros y logros de puntuación alta y tiempo a través de la API, publique puntuaciones y desbloquee logros desde su script o contenedor, y muestre ellos en su cliente.

  • Tutorial: opciones de gráficos con calidad autodetectada — entrar graphics-options.js: ajustes preestablecidos de calidad seleccionados entre 0 y 20 nivel de hardware (Galaxy S20 a RTX 5090), anulaciones por efecto, resolución adaptativa, ritmo de media actualización activado teléfonos, una opción manual de FPS máximo, un panel de opciones y configuraciones que seguir al jugador por GPU a través de StarHermit; conectado a un renderizador three.js.

  • Tutorial: opciones de audio con límite de sonido detectado automáticamente — controles básicos de volumen y chat de voz, una recomendación de simultaneidad automática compatible con el dispositivo y la CPU y un límite política de reproducción; incluye el libre de dependencia audio-options.js ayudante.

  • Tutorial: localiza tu juego y agrega configuraciones de idioma — los mismos diez idiomas que la wiki, etiquetas nativas y banderas SVG, una sección de Idioma junto Gráficos/Audio/Controles, texto de derecha a izquierda, paquetes de traducción y sincronización de preferencias por jugador.

  • Tutorial: añade controles a tu juego — declarar reencuadernable acciones del teclado en starhermit.txt, publicarlos, leer los enlaces del jugador con el token de lanzamiento, construir una pantalla de reenlace y arreglar "This game declares no controls.".

  • Tutorial: reclama un juego que otra persona agregó — demostrar el control del repositorio, hacerse cargo del listado existente y gestionar su alojamiento e implementaciones.

SDK de cliente

Si está construyendo sobre un motor con un SDK mantenido, comience allí en lugar de hacerlo con HTTP sin formato: el misma API, con las reglas de actualización, reintento, reconexión y redacción de tokens ya implementadas.

Referencia API

Convenciones compartidas por todos los puntos finales: REST bajo api/v1/... en https://api.starhermit.com, WebSockets bajo ws/v1/..., autenticación de portador JWT (?access_token= permitido en /ws/**), camelCase JSON; convenciones de respuesta y error.

Validar cambios

El sitio no tiene ninguna compilación de aplicación. Para documentación y verificaciones de ejemplo, use Node.js 22 o posterior, Python 3 y npm ci, entonces npm test. npm run test:browser además necesita Chrome/Chromium (CHROME_PATH puede seleccionar su ejecutable).

Después de editar un asistente de inicio rápido, ejecute python3 scripts/build-quickstart.py para actualizar el ejemplo y Código postal. Para actualizar el índice de operación REST desde un pago de origen coincidente, ejecute python3 scripts/build-contracts.py /path/to/platform-checkout, revise la diferencia del contrato y vuelva a ejecutar las pruebas. Las anulaciones de respuesta se mantienen en scripts/rest-contract-overrides.json.
