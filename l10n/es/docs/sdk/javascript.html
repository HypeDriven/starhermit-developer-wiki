SDK de JavaScript (juegos de navegador)

starhermit-sdk.js es un cliente de archivo único y libre de dependencias para juegos de navegador publicado en StarHermit. Lee el token de lanzamiento, lo mantiene actualizado y proporciona ayuda para el común API de token de lanzamiento con ámbito de juego: identidad, guardado en la nube, configuración y controles por jugador, invitaciones, emparejamiento, sesiones y juego, logros, tablas de clasificación, repeticiones, chat, Salas de voz y tiempo real.
Archivo docs/sdk/starhermit-sdk.js — cópialo en tu juego sin cambios
Global window.StarHermit (también module.exports en Nodo, para pruebas)
Dependencias none: utiliza el propio navegador fetch, WebSocket y (para leer guardados comprimidos) DecompressionStream
Línea base de API REST v1 y WebSocket v1, solo superficie de token de lanzamiento

El SDK es un cliente, no una segunda implementación de la plataforma. Desbloqueos de puntuaciones y logros son escritos únicamente por el servidor del juego (un resultado de script o un mensaje de control de contenedor): un cliente nunca puede publicarlos y el SDK solo los lee. Todo lo demás sigue teniendo autoridad del servidor exactamente como está documentado en el páginas API.

Los ayudantes autenticados no realizan solicitudes de API sin un token de lanzamiento. Las lecturas generalmente se resuelven a null, [], o un mapa vacío; escribe puede resolver null/false y las salvadas rebotadas no tienen efecto inmediato. valor de retorno. Un enchufe permanece desconectado. Mantener el progreso independiente en la memoria si el jugador así lo desea. reproducción sin seguimiento. Llamar signOut() antes de cambiar del juego con cuenta a ese modo para que se detenga la renovación.

Instalar

Copie el archivo junto a los otros scripts estáticos de su juego (dondequiera que los envíe su compilación) y cárguelo. antes de tu propio código:

<script src="starhermit-sdk.js"></script>
<script>
  StarHermit.init();          // as early as possible: it reads and strips the token from the URL fragment
</script>

Llamar init() una vez, antes de que cualquier enrutador toque location.hash. Opciones: init({ base, gameId, autoRefresh, launcherUrl }) — base puntos llamadas REST en un origen autorizado durante el desarrollo local (los juegos alojados en plataformas utilizan el mismo origen). gameId, si se suministra, debe coincidir el UUID alojado para iniciar sesión; Las páginas locales/externas no son orígenes válidos de devolución de inicio de sesión del juego. autoRefresh: false deja la renovación de fichas a un juego que dirige su propia cadena y launcherUrl anula donde relaunch() envía el reproductor (predeterminado https://dashboard.starhermit.com/).

Guardados en la nube

La ranura del juego es game:<slug> (catálogo: guardar desde dentro de un juego); el SDK construye el camino, comprime la carga útil y maneja el /info controlar.

const remote = await StarHermit.loadJSON();          // null: empty slot, signed out — or a failed read
if (StarHermit.saveLoadFailed()) showSyncError();    // tell those apart when it matters
else if (remote && isNewer(remote, local)) adopt(remote);

StarHermit.saveJSON(state);                          // debounced (2 s) checkpoint upload
addEventListener('pagehide', () => StarHermit.flushSave(true));   // keepalive flush
StarHermit.on('saved', ok => setSyncIndicator(ok));

Cargar antes de guardar. Compare y adopte la copia en la nube antes de cualquier escritura que pueda llegar saveJSON (incluidas configuraciones, apodos o escrituras de puntos de control en el arranque) o una copia local obsoleta puede sobrescribir un guardado más reciente realizado en otro dispositivo. Mantenga los guardados anticipados hasta que se estabilice la carga inicial.

El SDK protege la otra mitad de esa carrera: cuando falla una lectura (error de red o de servidor, como opuesto a una ranura vacía) establece saveLoadFailed(), emite saveerror, y se niega a escribir hasta /info confirma que la ranura está vacía o más tarde loadSave() tiene éxito. Una escritura rechazada resuelve false y emite saved con false.

Las escrituras después de una carga son condicionales. El SDK recuerda la versión (ETag) de guardarlo al final leído o escrito y lo envía de vuelta, por lo que una escritura llega solo al guardado en el que se basó o, para un espacio que estuvo vacío, sólo mientras todavía lo está. Cuando se guarda otro dispositivo en el medio, se rechaza la escritura. (412): el SDK emite saveconflict, conjuntos saveConflicted(), y se niega a escribir más hasta que un loadSave() permite que el juego se fusione o adopte el guardado más reciente. Un juego que nunca carga escribe. incondicionalmente, como antes.

StarHermit.on('saveconflict', async () => {
  const remote = await StarHermit.loadJSON();       // lifts the block
  StarHermit.saveJSON(merge(remote, local));        // conditional on the version just loaded
});

Nivel inferior: loadSave() / writeSave(text) para cuerdas crudas, saveInfo() para { exists, sizeBytes, updatedAt, etag }.

Informes de fallos y errores

Los jugadores pueden informar problemas desde dentro del juego; el propietario los clasifica a través del API de informes.

await StarHermit.reportBug('Score did not save', 'Finished level 3, score shows 0', {
  clientVersion: '1.4.2',
  attachments: [{ fileName: 'state.json', contentType: 'application/json', data: JSON.stringify(state) }],
});
StarHermit.captureCrashes({ clientVersion: '1.4.2' });   // opt-in: uncaught errors become crash reports
const mine = await StarHermit.myReports();               // [{ id, kind, status, title, ... }]

report(kind, title, description, opts) es la forma general (reportBug y reportCrash arreglar el tipo). captureCrashes archiva como máximo un informe por mensaje distinto y tres por carga de página, por lo que un Crash Loop no puede consumir la asignación diaria del jugador (20 por juego de forma predeterminada). Pregúntale al jugador antes adjuntar cualquier cosa personal.

Tablas de clasificación para un jugador

Un cliente nunca puede publicar una puntuación (sólo el servidor del juego puede hacerlo), por lo que un juego para un solo jugador necesita una Pequeño script de plataforma para poseer sus tableros. score-script.js es uno: cópielo a continuación a tu juego, declaralo en starhermit.txt como server=score-script.js, y editar solo su BOARDS bloque, que enumera cada tablero como usted crearlo:

var BOARDS = {
  "high-score": { "name": "High score", "scoreType": "integer", "sortDirection": "desc", "minScore": 0, "maxScore": 1000000 }
};

Cuando termine una carrera, publícala y muestra el lugar del jugador:

const accepted = await StarHermit.submitScores({ 'high-score': total });   // [] when signed out or refused
if (accepted.includes('high-score')) {
  const board = await StarHermit.leaderboard('high-score', { pageSize: 100 });
  const me = board.items.find(e => e.userId === StarHermit.userId);
  showRank(me && me.rank);
}

submitScores abre una sesión de práctica (POST .../sessions/ai), envía {type:'result', scores} en el zócalo del juego y resuelve las claves del tablero que el script aceptó; también emite scores con esa lista. El guión arroja una puntuación que no es un número del tipo del tablero o queda fuera de su minScore/maxScore, publica el resto a través de su scores regresa y finaliza la sesión. el cliente todavía informa el resultado. Una puntuación inventada dentro del rango puede pasar; Estas tablas son adecuadas para uso informal. jugar. Para competición validar la carrera en el script o contenedor antes de adjudicarla. el reconocimiento enumera las claves aceptadas por secuencias de comandos; no es prueba de que todos los tableros estuvieran activos o de que se haya logrado una nueva marca personal fue almacenado. Ver confianza y disponibilidad.

Reconexión y tokens caducados

Un socket lleva el token de inicio en su URL y un protocolo de enlace con un token caducado se rechaza antes. la actualización: el navegador solo informa el código de cierre 1006, exactamente como una caída de la red. Entonces un fracaso La reconexión puede ser un error de autenticación y volver a intentar la misma URL nunca podrá recuperarse. Sólo obras de renovación. mientras el token actual sea válido y dentro de las 12 horas posteriores al lanzamiento original; después de eso sólo el El lanzador puede acuñar un nuevo token.

connect() maneja esto por sí mismo: antes de cada reconexión, renueva el token a través de POST /api/v1/games/{slug}/launch-token (a menos que se renovó desde que se abrió el socket) y se vuelve a abrir con el nuevo. Un error de red o servidor durante la renovación retrocede y renueva nuevamente; nunca Vuelve a abrir la URL anterior. Cuando se rechaza la renovación o el token ha caducado, el SDK cierra sesión (auth con reason: 'expired'), deja de reconectarse y llama onAuthLost():

const conn = StarHermit.connect(sessionId, {
  onGame, onClose,
  onAuthLost: () => showReconnectPanel(),   // e.g. "Session expired — Back to StarHermit"
});
backButton.onclick = () => StarHermit.relaunch();

relaunch() envía al jugador de regreso para obtener un nuevo token de inicio: a través del inicio de sesión cuando se abrió el juego de esa manera (StarHermit.launchKind === 'sign-in'), de lo contrario al lanzador. Dentro del lanzador marco del juego, navega por la ventana superior, lo que los navegadores permiten solo mediante un gesto del usuario, así que llámalo desde un clic; regresa false cuando se denegó la navegación.

Un navegador puede ocultar la sesión finalizada, los términos, la membresía o las fallas de compilación como 1006. ante un reintento automático, connect() comprueba el estado de la sesión a través de REST y, cuando opts.build se suministra, lo compara con la información del juego. onUnavailable(error) recibe un fallo REST permanente o finaliza sesión; onTermsRequired(body) solicita la aceptación de los términos explícitos. Crear una nueva conexión después resolviendo estos. onClose(1008) significa que la conexión fue reemplazada o violó la política; no volver a abrirlo automáticamente.

Sockets tu juego se abre solo (realtime.socketUrl(roomId), voice.socketUrl(roomId)) necesita el misma regla. Antes de reabrir uno, llame renewForReconnect() y actuar sobre su resultado:

async function reopen() {
  const r = await StarHermit.renewForReconnect();
  if (r === 'renewed') ws = new WebSocket(StarHermit.realtime.socketUrl(roomId)); // fresh token in the URL
  else if (r === 'retry') setTimeout(reopen, backoff());                         // renewal itself failed
  else if (r === 'terms-required') showTermsPanel();                              // explicit acceptance
  else showReconnectPanel();                                                     // 'relaunch'
}

Las renovaciones simultáneas comparten una solicitud. terms-required conserva el token del jugador y emite termsrequired; mostrar getTerms() y llamar acceptTerms(displayed.hash) sólo en el jugador Acepte la acción y vuelva a intentarlo. Los sockets que administra tu juego también necesitan comprobaciones REST para detectar recursos finalizados. y debe detenerse cuando se cierre la política. Ver solución de problemas.

Eventos

StarHermit.on(type, fn) devuelve una función para cancelar la suscripción; off(type, fn) también funciona.

Evento Carga útil
auth { signedIn, userId } al iniciar sesión; { signedIn: false, reason } al cerrar sesión o al vencimiento (reason: 'expired' cuando se rechaza la renovación - oferta relaunch())
saved true / false después de cada nube escribe
saveerror { op: 'load' } después de una lectura fallida; { op: 'write', blocked: true } por una escritura rechazada
achievement un desbloqueo presionado en el zócalo del juego
scores las claves del tablero aceptadas por submitScores ([] cuando no se publicó nada)
saveconflict { etag } cuando otro dispositivo cambió el guardado; recargar antes de fusionar/guardar
termsrequired El error de términos devuelto por una renovación del token de lanzamiento; conservar el token y solicitar el consentimiento
