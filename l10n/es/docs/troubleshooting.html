Solucionar problemas de una integración

Comience con el estado HTTP, el punto final y la familia de credenciales. Reproduzca la solicitud más pequeña usando el mismo ID de juego y credencial, luego verifique el estado actual del recurso. Mantener fichas y jugador. guarde datos de registros e informes de soporte.

WebSockets

La actualización fallida de un navegador suele aparecer como código de cierre 1006, ocultando la respuesta HTTP. Antes de volver a intentarlo, realice una llamada REST al mismo juego/sesión/sala para distinguir la autenticación, términos, membresía, sesión finalizada y fallas temporales de inicio del servidor. Verifique la compatibilidad de compilación a través de la información del juego cuando suministras ?build=. Obtenga un boleto de conexión nuevo para cada actualización.

Cerrar/resultado Significado Acción
1000 Cierre normal Detener a menos que el reproductor inicie explícitamente otra conexión
1001 más error de reanudación El mundo no pudo reanudarse aún Vuelva a conectarse con el retroceso después de verificar el estado de la sesión
1006 Pérdida de red o actualización rechazada Verifique el estado REST y las credenciales actuales; reintentos enlazados
1008 Violación de política o conexión reemplazada Detener la reconexión automática; ofrecer una reconexión deliberada después de solucionar la causa
1009 Mensaje demasiado grande Reduzca el tamaño del marco antes de volver a conectarse
HTTP 409 build_mismatch La compilación del cliente/servidor no coincide Vuelva a cargar una compilación compatible; no inventes un valor de construcción coincidente
HTTP 410 session_not_active Sesión terminada Regresar al lobby o reproducir; dejar de reconectar
error: "Too many commands; slow down." Asignación de comando duradero de script Comandos discretos de ritmo; poner entradas continuas dentro data con type: "input", realtime: true

Solicitar un estado de juego completo después de volver a conectarse; No repitas ciegamente movimientos u otros movimientos no idempotentes. comandos. resumed significa descartar la predicción y resincronizar. abandoned es terminal. Ver Contratos WebSocket.

Publicación y puesta en marcha de contenedores.

Síntoma Controlar Siguiente acción
Subir 413 con limitBytes Asignación efectiva de carga/alojamiento Reducir el paquete o el árbol fusionado resultante
Carga HTTP grande 413 sin campos de error de plataforma Límite de cuerpo de solicitud antes de la API Usar ws/v1/game-upload; enviar complete después de todos los bytes
Subir 422 Diseño de archivo, archivo de inicio, seguridad de ruta, manifiesto Corrija el error nombrado; la API espera raw .tar.gz, no multiparte
La carga se realizó correctamente pero el servidor no está disponible Preparación para la implementación Despliegue de encuestas; los bytes aceptados no significan que el contenedor esté listo
El inicio de la sala de contenedores regresa temporalmente 503 El servidor puede estar despertando Mantenga el lobby y vuelva a intentarlo con retroceso; no recurrir a una simulación de cliente
Las solicitudes de contenedor fallan en la validación de la clave de invocación Entorno de inicio y comparación exacta de encabezados Leer la clave de invocación inyectada actual; informar fallas persistentes con la identificación del juego y los registros desinfectados
Error de implementación persistente Estado de implementación y registros/fallos visibles para el propietario Corrija la compilación o configuración y publique una nueva versión funcional

Para obtener un informe de soporte útil, incluya ID del juego, versión del cliente/compilación, punto final y método, estado/código, hora UTC aproximada, pasos de reproducción y registros desinfectados relevantes. Los ID de sesión/sala ayudan a localizar el recurso. No adjunte credenciales, claves privadas ni la partida guardada completa de un jugador sin su consentimiento.
