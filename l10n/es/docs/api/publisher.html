Editor

La superficie del editor: administre organizaciones y miembros de editores, cree y cargue títulos y compilaciones de software, y administre logros, derechos y definiciones de tablas de clasificación para sus títulos.

¿Publicar un juego en lugar de un título de catálogo? No necesitas nada de esto. El dueño de un El juego con un script o contenedor backend es su editor y administra sus tablas de clasificación y logros bajo /api/v1/me/github-games/{id}/… - ver Tutorial: tablas de clasificación y logros para tu juego.

URL básica: https://api.starhermit.com. Todas las rutas requieren un JWT más los permisos enumerados. Funciones: PublisherMember, PublisherOwner. Las solicitudes de permiso se asignan mediante roles; Los tokens acuñados llevan los reclamos de permiso.

Editores y miembros

Prefijo de ruta: api/v1/publisher.

Método Camino autenticación Descripción
CORREO /api/v1/publisher JWT (Permission-publisher.content.manage) Crear un editor; el creador se convierte en miembro con rol "Owner" → 201
CONSEGUIR /api/v1/publisher JWT (Permission-publisher.content.manage) Lista de editores → Publisher[]
CORREO /api/v1/publisher/{publisherId}/members JWT (Permission-publisher.members.manage) + role Owner Agregar un miembro → 204
BORRAR /api/v1/publisher/{publisherId}/members/{memberUserId} JWT (Permission-publisher.members.manage) + role Owner Eliminar un miembro → 204 (el propietario no se puede eliminar)
CONSEGUIR /api/v1/publisher/{publisherId}/members/{memberUserId} JWT (Permission-publisher.members.manage) + membresía de ese editor Consigue un miembro → PublisherMember

¿Quién puede cambiar de membresía?

El reclamo de permiso dice que puedes administrar miembros editores en algún lugar; no dice cual editor. Por tanto, se aplican ambos controles:

  • Agregar y eliminar miembros es Owner-solo. La membresía conlleva autoridad para administrar el contenido cada uno de los títulos del editor, por lo que un miembro simple que pudiera agregar miembros podría otorgar eso autoridad a nadie. Un no propietario obtiene 401.
  • Leer una membresía requiere pertenecer a esa editorial. Una persona que llama afuera recibe lo mismo. 404 como usuario que no es miembro, por lo que el punto final no revela nada sobre los editores que usted no es parte de.

Títulos y compilaciones de software.

Método Camino autenticación Descripción
CORREO /api/v1/publisher/software JWT (Permission-publisher.content.manage) Crear/actualizar un título de software (cuerpo = metadatos del título; se aplica la membresía en el editor real del título)
CORREO /api/v1/publisher/software/upload JWT (Permission-publisher.content.manage + Permission-publisher.binary.publish) Obtenga URL de carga para un título → UploadUrlInfo[]
CORREO /api/v1/publisher/software/build/finalize JWT (Permission-publisher.content.manage + Permission-publisher.binary.publish) Finalizar una compilación a partir de recursos cargados → 204
CONSEGUIR /api/v1/publisher/analytics/downloads?publisherId= JWT (Permission-publisher.content.manage) Descargar recuentos por título
CONSEGUIR /api/v1/publisher/analytics/launches?publisherId= JWT (Permission-publisher.content.manage) Recuento de lanzamientos por título

La publicación de una compilación necesita la concesión de publicación binaria

Los dos puntos finales de compilación requieren publisher.binary.publish encima de publisher.content.manage y membresía del editor del título. Sin ella ambos responden 403, mientras todos los demás puntos finales de esta página siguen funcionando: puede crear y editar títulos, definir logros y tablas de clasificación, y derechos de subvenciones; simplemente no puedes enviar un ejecutable.

La razón es lo que es una construcción. El cliente de escritorio descarga los activos de una compilación y los ejecuta en el máquina del jugador con los privilegios del jugador, fuera de cualquier control sandbox de Starhermit, a diferencia de un juego de navegador, que se ejecuta en el navegador. Entonces, el derecho a publicar uno se otorga por cuenta mediante un Administrador de Starhermit (el BinaryPublisher rol), no adquirido mediante la creación de un editor. No otro papel lo lleva. Solicite la concesión a un administrador antes de crear un flujo de carga en contra estos puntos finales; también se elimina cuando se suspende una cuenta de editor.

Los juegos de navegador no necesitan nada de esto: /api/v1/me/github-games envíos, cargas de carpetas y paquetes impulsa el autoservicio para cualquier cuenta que haya iniciado sesión.

Crear o actualizar un título de catálogo

POST /api/v1/publisher/software acepta id (omitir para un título nuevo), publisherId, name, description, category, platform, releaseStatus, tags, y priceCents:

{
  "publisherId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "name": "Orbit League",
  "description": "A space racing game.",
  "category": "game",
  "platform": "windows",
  "releaseStatus": "released",
  "tags": ["racing"],
  "priceCents": 0
}

El éxito es 201 con el título. Sólo se aceptan metadatos de títulos; no enviar membresía de editor u objetos de activos aquí. Crear devoluciones de un editor 201 sin objeto de editor; lista GET /api/v1/publisher para obtener su DNI.

Obtener URL de carga

POST /api/v1/publisher/software/upload

{ "titleId": "<title id>" }

Respuesta - UploadUrlInfo[]:

[
  {
    "type": "executable",
    "uploadUrl": "...",
    "fieldKey": "..."
  }
]

type es uno de "executable", "data", "metadata".

Finalizar una construcción

POST /api/v1/publisher/software/build/finalize → 204

{
  "titleId": "<title id>",
  "buildId": "<optional build id>",
  "version": "1.0.0",
  "releaseNotes": "...",
  "assets": [
    { "type": "executable", "checksum": "...", "fieldKey": "..." }
  ]
}

El flujo de trabajo de creación del catálogo es actualmente una vista previa y no proporciona entrega binaria de producción. o una garantía de verificación de contenido o escaneo de malware. No trate una construcción o activo aceptado estado como prueba de que un ejecutable es seguro. Ver disponibilidad de funciones. La publicación de juegos alojados utiliza el API de carga de juegos.

Analítica

Ambos puntos finales devuelven una identificación del título de asignación de objetos JSON para contar:

Logros

Ruta api/v1/publisher; todas las rutas de gestión de logros requieren Permission-publisher.content.manage.

Estos puntos finales gestionan título-catálogo logros solamente. También requieren que la persona que llama sea un miembro del editor propietario del título, y falla cerrada por logros que pertenecen a un juego autorizado — Son declarados por el script del juego o por el contenedor backend y no son administrado por el editor (ver Logros, Guiones de juego, y Servidores de juegos en contenedores).

Método Camino autenticación Descripción
CORREO /api/v1/publisher/titles/{titleId}/achievements JWT Crear un logro → AchievementDto
CONSEGUIR /api/v1/publisher/titles/{titleId}/achievements JWT Listar los logros de un título → AchievementDto[]
CONSEGUIR /api/v1/publisher/achievements/{id} JWT Consigue un logro → AchievementDto
PONER /api/v1/publisher/achievements/{id} JWT Actualizar (todos los campos anulables) → AchievementDto
BORRAR /api/v1/publisher/achievements/{id} JWT Eliminar → 204

Crear una tabla de clasificación

POST /api/v1/publisher/leaderboards/

{
  "name": "Global Elo",
  "scoreType": "...",
  "sortDirection": "...",
  "resetSchedule": "...",
  "minScore": 0,
  "maxScore": 4000,
  "scope": "...",
  "region": "...",
  "isActive": true,
  "softwareTitleId": "<optional title id>"
}

resetSchedule, minScore, maxScore, region, y softwareTitleId son opcionales. En PUT, todos los campos admiten valores NULL. resetSchedule es daily, weekly, monthly o never; cualquier otra cosa es un 400 - ver Restablecer horarios. Ver leaderboards.md para la superficie de cara al jugador.

Publicar una compilación: flujo

  1. Mantener la subvención de publicación binaria: los pasos 3 y 5 requieren publisher.binary.publish, que un Subvenciones de administrador de Starhermit por cuenta. Ver La publicación de una compilación necesita la concesión de publicación binaria.
  2. Crear un editor: POST /api/v1/publisher con { name, description }.
  3. Crea el título: POST /api/v1/publisher/software con los metadatos del título a continuación.
  4. Obtener URL de carga: POST /api/v1/publisher/software/upload con { titleId }.
  5. Subir archivos a los regresados uploadUrls.
  6. Finalizar la construcción: POST /api/v1/publisher/software/build/finalize con los activos cargados' { type, checksum, fieldKey } entradas.
  7. Consultar disponibilidad de distribución: la vista previa del catálogo actual no garantiza descargas de producción verificadas ni análisis de malware; ver disponibilidad.
  8. Los usuarios reclaman y descargan el título a través del catálogo - ver catalog.md.

Los cuerpos de error varían; ver Convenciones API.
