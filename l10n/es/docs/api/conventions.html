Convenciones API

Usos del DESCANSO https://api.starhermit.com/api/v1/...; uso de enchufes wss://api.starhermit.com/ws/v1/.... Los juegos alojados pueden llamar /api/v1/... y /ws/v1/... sobre su propio origen. Los clientes nativos utilizan el Origen de API pública. Una página de desarrollo en otro origen necesita un origen CORS permitido en el juego anfitrión; establecer una URL base del SDK por sí solo no autoriza ese origen.

Solicitudes y respuestas

Enviar JSON con Content-Type: application/json, excepto cargas de paquetes gzip sin formato. Nombres de miembros JSON son camelCase. Enviar credenciales de portador en el REST Authorization encabezamiento.

Respuesta como leerlo
200 / 201 JSON Analizar el objeto o matriz documentado; tolerar campos adicionales
204 Éxito sin cuerpo; no llames response.json()
302 Inicio de sesión en el navegador/redireccionamiento de confirmación; navegar en lugar de buscar páginas OAuth
304 Lectura condicional sin cambios; conservar los datos que ya posee
Imagen, archivo adjunto, guardado en la nube Leer bytes, utilizando el tipo de contenido de respuesta y el contrato de punto final
Error Primero lea el estado y luego analice el cuerpo a la defensiva.

La forma de error común es { "error": "...", "code": "..." }, con campos opcionales dependiendo de el punto final. error suele ser legible por humanos; code es un discriminador estable cuando se proporciona. Los términos y algunos otros puntos finales ponen a un discriminador directamente en error. Algunos puntos finales regresan sin formato texto, un cuerpo vacío o un objeto de detalles del problema de validación con title, status y errors. Los clientes no deben asumir que todas las respuestas fallidas son JSON o tienen los mismos campos.

export async function readResponse(response) {
  if (response.status === 204 || response.status === 304) return null;
  const text = await response.text();
  let body;
  try { body = text ? JSON.parse(text) : null; } catch { body = text || null; }
  if (!response.ok) {
    const message = (body && typeof body === 'object' && (body.error || body.message || body.title))
      || (typeof body === 'string' && body) || response.statusText;
    throw Object.assign(new Error(message), {
      status: response.status, code: body?.code, body,
      retryAfter: response.headers.get('Retry-After'),
    });
  }
  return body;
}

Tiempo, tamaños y nulos

  • createdAt, updatedAt, finishedAty marcas de tiempo similares de cuenta/recurso son cadenas ISO 8601 con un desplazamiento. Tratar ausente o null valores opcionales como no disponibles.
  • ctx.now, summary.deadline, lista de sesiones deadline, y /time.serverTime son enteros Unix milisegundos. Convertir con new Date(value), no Date.parse(value).
  • Los valores límite en bytes son bytes, no caracteres Base64. Una carga JSON Base64 es más grande que su contenidos decodificados. Utilice el límite efectivo informado por un punto final cuando esté disponible.
  • Omisión, nully un objeto vacío no son universalmente equivalentes. Ajustes PATCH elimina un clave nombrada con null; configuraciones de una sola tecla PUT víveres null como valor. Recopilación PUT reemplaza todo el mapa. Lea las reglas de actualización de cada punto final.
  • Se fusiona un parche de configuración claves de nivel superior. Un valor de objeto proporcionado reemplaza el valor de esa clave; no fusiona recursivamente propiedades anidadas.

Paginación

La paginación es basada en uno donde page/pageSize son compatibles. Diferentes API tienen deliberadamente diferentes sobres de respuesta; no reutilice un analizador que asuma un único nombre de campo de recuento.

Área Forma de colección Tamaño de página predeterminado/máximo
Títulos y compilaciones de software. { items, totalCount, page, pageSize } 20 / 100
mensajes de chat { conversationId, items, totalCount, page, pageSize } 50 / 100
Entradas en la tabla de clasificación { items, total, page, pageSize } 20 / 100
software externo { items, total, page, pageSize } 20; solicitar un tamaño de página pequeño y positivo
Informes, registros de accidentes de contenedores, listas de moderación { items, total, page, pageSize } 20 / 100
Sesiones, amigos, listados de juegos, logros. matrices Límites específicos de endpoints; sin cursor genérico de página siguiente
Feed de retiro de moderación Basado en cursor Mantener el cursor devuelto; recuperarse de 410 como está documentado

Los metadatos de paginación de respuesta reflejan la página servida cuando esté disponible. Páginas de referencia y contratos legibles por máquina describir parámetros de consulta específicos del punto final.

Reintento y concurrencia

Situación Acción
Token de acceso a la cuenta rechazado con 401 Actualizar una vez, utilizando una solicitud de actualización compartida; luego inicie sesión si es rechazado
El token de lanzamiento expiró Obtenga un nuevo token a través del inicio de sesión/lanzador; los tokens caducados no pueden renovarse solos
403 terms_acceptance_required Mostrar y aceptar explícitamente los términos actuales, luego volver a intentarlo
Otro 403 Resolver el alcance, la membresía, los permisos o el estado de la cuenta; no actualizar en un bucle
409 Resolver conflictos de duplicados/estados/revisiones; volver a leer antes de cambiar un recurso
guardar en la nube 412 Carga la versión más nueva y deja que el juego la fusione o la adopte.
429 o temporal 503 Honor Retry-After, agregar jitter y reintentos enlazados
Fallo de red durante una escritura Es posible que se desconozca el resultado; inspeccionar el estado del recurso antes de repetir la acción

Retry-After pueden ser segundos o una fecha HTTP. No inventes un encabezado de idempotencia: la API no prometen un mecanismo general de clave de idempotencia. Un reintento de creación de sesión o una invitación pueden crear otro recurso o conflicto con el primero. Prefiere lecturas y operaciones explícitamente idempotentes para reintentos automáticos. Actualizar la rotación, completar las cargas, los términos de consentimiento y los resultados del juego terminal cada uno tienen sus propias reglas.

Para escrituras de comparación e intercambio, utilice ETags guardados en la nube, room expectedRevision, o revisiones de moderación donde sea compatible. Una escritura exitosa no es necesariamente una implementación de contenedor completa; verificar su estado antes de enviar jugadores a una nueva construcción. Ver solución de problemas.
