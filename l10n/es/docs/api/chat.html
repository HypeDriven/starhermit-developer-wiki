Charlar

El chat de StarHermit cubre mensajes directos, salas de grupo y conversaciones de sesiones de juegos, a través de una API REST (api/v1/chat) más un canal push WebSocket de servidor a cliente (ws/v1/chat). Todos los puntos finales REST requieren autenticación. Los cuerpos de error varían; ver Convenciones API.

Puntos finales de descanso

Base: https://api.starhermit.com/api/v1/chat.

Método Camino autenticación Descripción
CORREO /conversations JWT Crear una conversación (1 amigo = directo, ≥2 = grupo)
PARCHE /conversations/{id} JWT Cambiar el nombre de una conversación (cualquier miembro)
CORREO /conversations/{id}/invites JWT Invitar a un usuario a un grupo
CONSEGUIR /invites JWT Enumere sus invitaciones de chat pendientes
CORREO /invites/{id}/accept JWT Aceptar una invitación de chat
CORREO /invites/{id}/decline JWT Rechazar una invitación de chat
CONSEGUIR /rooms/joinable JWT Listar habitaciones abiertas con ≥1 amigo dentro
CORREO /conversations/{id}/join JWT Únase a una sala abierta (debe ser amigo de un miembro)
CORREO /conversations/{id}/participants JWT Agregar participantes a una conversación
BORRAR /conversations/{id}/participants/{userId} JWT Eliminar un participante (yo: cualquier miembro; otros: solo el creador del grupo)
CORREO /conversations/{id}/leave JWT dejar una conversación
CONSEGUIR /conversations JWT Enumerar conversaciones, incluido cada recuento no leído
CONSEGUIR /conversations/{id} JWT Obtener una conversación, incluido el recuento de no leídos
CONSEGUIR /unread JWT Obtenga el recuento total de mensajes no leídos
CORREO /conversations/{id}/read JWT Marcar una conversación como leída
CONSEGUIR /conversations/{id}/messages?page=&pageSize= JWT Obtener historial de mensajes paginados
CORREO /conversations/{id}/messages JWT Enviar un mensaje (tarifa limitada)
PONER /conversations/{conversationId}/messages/{messageId} JWT Editar un mensaje
BORRAR /conversations/{conversationId}/messages/{messageId} JWT Eliminar un mensaje (lápida sepulcral)

Crear una conversación

POST /conversations

{
  "participantIds": ["<guid>"],
  "name": "Friday night lobby",
  "friendUserId": "<guid>",
  "joinPolicy": "closed"
}

Todos los campos son opcionales. Un amigo participante crea un directo conversación; dos o más crean un grupo. joinPolicy es "open" o "closed" (por defecto "closed"). Devuelve un ConversationDto.

Cambiar el nombre de una conversación

PATCH /conversations/{id} con { "name": "New name" } → ConversationDto. Cualquier miembro puede cambiar de nombre; una nota del sistema con kind: "system_rename" se transmite.

invita

POST /conversations/{id}/invites con { "toUserId": "<guid>" } → ChatInviteDto. Las invitaciones son la única forma de acceder a una sala cerrada.

GET /invites → ChatInviteDto[]:

[
  {
    "id": "<guid>",
    "conversationId": "<guid>",
    "conversationName": "Friday night lobby",
    "fromUserId": "<guid>",
    "fromUsername": "alice",
    "toUserId": "<guid>",
    "status": "pending",
    "createdAt": "2026-07-22T07:00:00Z"
  }
]

POST /invites/{id}/accept y POST /invites/{id}/decline → ChatInviteDto.

Unir salas

GET /rooms/joinable → JoinableRoomDto[] — salas abiertas que tienen al menos uno de tus amigos dentro:

[
  {
    "id": "<guid>",
    "name": "Friday night lobby",
    "joinPolicy": "open",
    "createdAt": "2026-07-22T07:00:00Z",
    "participants": [{ "userId": "<guid>", "username": "alice" }]
  }
]

POST /conversations/{id}/join → ConversationDto. Se une a una sala abierta; debes ser amigo de un miembro.

Participantes

POST /conversations/{id}/participants con { "participantIds": ["<guid>"] } → ConversationDto.

DELETE /conversations/{id}/participants/{userId} → 204. Cualquier miembro podrá darse de baja; Para eliminar a otros es necesario ser el creador del grupo.

POST /conversations/{id}/leave → 204.

Leer conversaciones

GET /conversations → ConversationDto[].

GET /conversations/{id} → ConversationDto:

{
  "id": "<guid>",
  "type": "group",
  "name": "Friday night lobby",
  "createdByUserId": "<guid>",
  "joinPolicy": "closed",
  "createdAt": "2026-07-22T07:00:00Z",
  "participants": [{ "userId": "<guid>", "username": "alice" }],
  "otherParticipant": { "userId": "<guid>", "username": "bob" },
  "unreadCount": 3
}

type es uno de direct, group, game. name, createdByUserId, y otherParticipant puede estar ausente. unreadCount cuenta los mensajes de texto no leídos enviados por otros miembros después del horizonte de lectura por conversación de la persona que llama.

Estado no leído

GET /unread devuelve el recuento de no leídos en todas las conversaciones de la persona que llama:

{ "total": 7 }

POST /conversations/{id}/read avanza el horizonte de lectura de la persona que llama para esa conversación. Úselo después de mostrar la transcripción actual. El servidor emite un conversation_read evento a todos los sockets que pertenecen a la persona que llama, lo que permite que varios clientes que hayan iniciado sesión borre sus credenciales. Los mensajes nuevos y eliminados pueden cambiar el total, por lo que los clientes deben actualizar desde eventos WebSocket o recuperar periódicamente /unread.

Mensajes

GET /conversations/{id}/messages?page=1&pageSize=50 → PagedMessagesDto:

{
  "conversationId": "<guid>",
  "page": 1,
  "pageSize": 50,
  "totalCount": 123,
  "items": []
}

POST /conversations/{id}/messages con { "content": "hello" } → MessageDto. Velocidad limitada a 10 mensajes/minuto por usuario; superandolo regresa 429.

PUT /conversations/{conversationId}/messages/{messageId} con { "content": "edited" } → MessageDto.

DELETE /conversations/{conversationId}/messages/{messageId} → 204. La eliminación es una lápida: el mensaje permanece isDeleted: true.

MessageDto:

{
  "id": "<guid>",
  "conversationId": "<guid>",
  "senderId": "<guid>",
  "senderUsername": "alice",
  "content": "hello",
  "kind": "text",
  "metadata": { "key": "value" },
  "sentAt": "2026-07-22T07:00:00Z",
  "editedAt": null,
  "isDeleted": false
}

kind es "text" o "system_rename"; content, metadata (a Dictionary<string,string>), y editedAt puede estar ausente/nulo.

WebSocket: ws/v1/chat

Conéctate a wss://api.starhermit.com/ws/v1/chat con un JWT a través del Authorization encabezamiento, ?ticket=, o ?access_token=.

Este es un servidor puro → canal push de cliente: las tramas del cliente se ignoran (sólo Close es honrado). Cada cuadro es un sobre:

{ "type": "<event>", "payload": { } }
Evento type Carga útil
conversation_created ConversationDto
conversation_renamed ConversationDto
participants_added ConversationDto
participant_removed ConversationDto
chat_invite ChatInviteDto
chat_invite_responded ChatInviteDto
new_message MessageDto
message_updated MessageDto
message_deleted MessageDto
conversation_read Cambio de estado de lectura para el usuario que inició sesión; recuperar recuentos no leídos
game_invite { "inviteId", "kind", "gameSlug", "gameName", "roomId", "from": { "userId", "username" }, "createdAt", "acceptPath", "declinePath", "inProgress", "sessionId" } - vea abajo

game_invite: un evento para ambos sistemas de invitación

Cualquiera puede ser invitado a jugar de dos maneras, y este único evento incluye ambas: un cliente implementa un brindis, no dos:

kind Expedido por aceptándolo
"session" POST /games/{slug}/invites Crea una nueva sesión de juego para ustedes dos.
"room" POST /realtime/rooms/{id}/invites Toma asiento en una habitación en la que ya está sentado el que invita; roomId es esa habitación

acceptPath y declinePath son los puntos finales que responden este Invita: úsalos y la distinción nunca importará. Responder en el punto final del otro sistema es una 404: los dos mantienen identificadores de invitación separados.

inProgress es true al aceptar, se une a un juego que ya se está jugando (una invitación a una sesión que nombra una sesión en ejecución o una invitación a una sala iniciada que permite unirse en progreso) y sessionId es la sesión de ese juego. Úselo para decir "únete a su juego" en lugar de "jugar".

{
  "type": "game_invite",
  "payload": {
    "inviteId": "e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b",
    "kind": "room",
    "gameSlug": "poker",
    "gameName": "StarHermit Poker",
    "roomId": "b1d2c3e4-5f60-4a71-8b92-c3d4e5f60718",
    "from": { "userId": "9b2f8c1a-1111-4222-8333-444455556666", "username": "alice" },
    "createdAt": "2026-07-26T14:10:00Z",
    "acceptPath": "/api/v1/realtime/rooms/invites/e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b/accept",
    "declinePath": "/api/v1/realtime/rooms/invites/e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b/decline"
  }
}

roomId es null para "session" invita. Un token de lanzamiento con ámbito de juego no puede abrir este socket ni leer la información de toda la cuenta. /me/game-invites bandeja de entrada. Encuesta de clientes del juego GET /api/v1/games/{slug}/invites para invitaciones a sesiones y GET /api/v1/realtime/rooms/invites para invitaciones a la sala de juegos. Los clientes de cuentas pueden leer ambos tipos a través de GET /api/v1/me/game-invites.

Chat dentro de una sesión de juego

Un token de lanzamiento con ámbito de juego no puedo abierto ws/v1/chat — está bloqueado porque el socket transmite todas las conversaciones de un usuario. Fichas de lanzamiento puede utilizar la API REST de chat en conversaciones adjuntas a sus propias sesiones de juego: el detalle de la sesión devuelve un chatConversationId, la conversación tiene tipo "game", sus participantes son los jugadores de la sesión y se saltan las reglas de amistad.

Por lo tanto, los clientes de juegos suelen cargar el historial a través de REST y buscar nuevos mensajes en lugar de utilizar el socket. Por ejemplo, el implementación de referencia de ajedrez encuestas cada 5 segundos:

GET /api/v1/chat/conversations/{chatConversationId}/messages?page=1&pageSize=50
Authorization: Bearer <launch-token>

POST /api/v1/chat/conversations/{chatConversationId}/messages
Authorization: Bearer <launch-token>
Content-Type: application/json

{ "content": "good game" }
