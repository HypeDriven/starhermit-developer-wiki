Logros

Un logro pertenece exactamente a un dueño, y el propietario decide quién puede desbloquearlo:

Dueño Declarado por Desbloqueado por Úselo para
Un juego autorizado game.achievements en un guión, o achievements de un contenedor /describe — o por el dueño del juego a través de /me/github-games/{id}/achievements Solo el tiempo de ejecución del servidor del juego. - servidor autorizado Juegos con un server= guión o container.image= backend
Un título de catálogo (SoftwareTitle) Un editor, a través de API del editor El cliente del jugador, a través de POST /api/v1/me/achievements/unlock (derecho requerido) Títulos distribuidos cuyo cliente es el único que sabe que el jugador ganó algo.

Los dos son mutuamente excluyentes y la plataforma impone la división:

  • POST /api/v1/me/achievements/unlock rechaza logros relacionados con el juego – un cliente nunca puede reclamar uno.
  • Los puntos finales CRUD del editor también los rechazan. No necesitas un editor para un juego de tu propiedad: como su dueño tu son su editor, y usted gestiona sus logros a través de los puntos finales del propietario en cambio.

URL básica: https://api.starhermit.com. Todas las rutas están bajo /api/v1/....

Método Camino autenticación Descripción
CONSEGUIR /api/v1/games/{slug}/achievements Portador Los logros de un juego autorizado + el estado de desbloqueo de la persona que llama
CONSEGUIR /api/v1/me/github-games/{id}/achievements JWT (propietario del juego) Cada logro de tu juego, con su origin y desbloquear cuenta
CORREO /api/v1/me/github-games/{id}/achievements JWT (propietario del juego) Crea un logro para tu juego → 201
PONER /api/v1/me/github-games/{id}/achievements/{achievementId} JWT (propietario del juego) Actualiza uno que creaste
BORRAR /api/v1/me/github-games/{id}/achievements/{achievementId} JWT (propietario del juego) Elimina uno que creaste y nadie lo ha desbloqueado → 204
CONSEGUIR /api/v1/software/{titleId}/achievements Anónimo Definiciones de logros de un título de catálogo
CONSEGUIR /api/v1/me/achievements?titleId= JWT Desbloqueos de la persona que llama (todos los propietarios o un título)
CORREO /api/v1/me/achievements/unlock JWT Desbloqueo reclamado por el cliente: solo títulos de catálogo

Lea los errores a la defensiva como se describe en Convenciones API. POST /me/achievements/unlock devuelve su 400 razón como texto plano.

Logros de juegos autorizados por el servidor

Este es el mecanismo cualquier El juego debe usarse cuando tiene un backend de secuencia de comandos o contenedor. el El tiempo de ejecución del servidor es el único escritor. Debe validar que el jugador obtuvo cada desbloqueo; rechazando Los envíos directos de API por sí solos no validan los eventos informados por un cliente modificado.

1. Declaralos en tu script

Agregar una estática achievements matriz a la game objeto - ver Guiones del juego: logros para el contrato completo:

globalThis.game = {
  achievements: [
    { key: "first-win",  name: "First Win",  description: "Win a match.", points: 10 },
    { key: "flawless",   name: "Flawless",   description: "Win without conceding.",
      points: 50, secret: true, icon: "https://cdn.example/flawless.png" }
  ],
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

Se lee la declaración cuando el juego se publica o actualiza desde su repositorio. Publique una actualización para aplicar un cambio.

2. Desbloquéalos de cualquier gancho del ciclo de vida.

Devolver un achievements mapa - identificación de usuario → conjunto de claves - desde createSession, onPlayerMessage, o onTick:

return {
  ok: true,
  sessionState: state,
  achievements: { [winnerId]: ["first-win", "flawless"] },
  result: { kind: "win", winner: winnerId }
};

Los desbloqueos son idempotente — Devolver una clave que el jugador ya tiene no es una operación, por lo que un script puede Vuelva a afirmar un logro en cada tick sin preocuparse por los duplicados.

3. El jugador recibe una notificación a través del conector del juego.

Cada desbloqueo recién otorgado se envía únicamente al jugador que lo obtuvo, el ws/v1/games, como su propio marco tipo (verdad de plataforma, no un script transmitido game mensaje):

{
  "type": "achievement",
  "data": {
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "points": 10,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
}

Desbloqueos otorgados desde createSession persisten antes de que alguien tenga un socket, por lo que llegan con sin marco: léalos desde el punto final de la lista al cargar.

Backends de contenedores

Un contenedor declara los mismos campos de logros en GET /describe, luego envía un achievements mensaje en su control WebSocket. La plataforma aplica la misma clave, participante, idempotencia y reglas de entrega. Ver Servidores de juegos en contenedores.

GET /api/v1/games/{slug}/achievements

Cada logro que declara el juego, con el estado de desbloqueo de la persona que llama. 404 si la babosa no tiene definición autorizada del juego (un juego sin script o contenedor backend no tiene propiedad del juego). logros - ver ¿Qué juegos pueden usar esto?). ¿Qué juegos pueden usar esto?

El mecanismo está disponible para un juego que declara una server= guión o un container.image= backend en starhermit.txt. el El tiempo de ejecución del servidor hace que el desbloqueo sea autorizado. Los casos de uso respaldados por scripts incluyen:

  • Juegos de plataformas con guión — desbloquear desde onPlayerMessage / onTick mientras se desarrolla el partido.
  • Juegos en tiempo real en salas — a sala en tiempo real por un juego con un server= El script crea una sesión vinculada cuando se inicia, y cada enlace de esa La sesión puede otorgar logros.
  • Juegos para un jugador y de práctica. — una sesión contra el asiento de AI (POST /api/v1/games/{slug}/sessions/ai) ejecuta el mismo script y la misma ruta de desbloqueo.
  • Juegos en tiempo real enrutados por host - un juego cuya jugabilidad transcurre sobre el canal binario de sala en tiempo real todavía puede enviar un script de servidor puramente como su autoridad de logro: el inicio de la sala crea la sesión vinculada y el guión premios de createSession / onTick / duradero cmd mensajes enviados ws/v1/games mientras que el El camino rápido sigue fluyendo. ws/v1/realtime.

Las sesiones respaldadas por contenedores también pueden declarar y otorgar logros a través de su protocolo. un juego con sin backend autorizado (un juego de navegador puro, o uno construido sólo en el relevo entre pares) no tiene una ruta de desbloqueo autorizada por el servidor. El desbloqueo reclamado por el cliente está disponible sólo para títulos distribuidos por catálogo, a continuación.

Logros de otros juegos.

Un juego puede abrir funciones basadas en lo que el jugador desbloqueó otro juego: una secuela en honor el original, o juegos de una serie que comparten cosméticos. Hay dos formas de leerlos.

Desde su servidor: ctx.linkedAchievements (confiable)

Nombra los otros juegos en tu guión, junto a tus otras declaraciones:

globalThis.game = {
  linkedAchievements: ["83fd04b1-3cbe-4b09-a251-3733ad4b9d94"], // other games' slugs (uids)
  // ...
};

Un contenedor devuelve lo mismo linkedAchievements matriz de GET /describe. Cada guión El ctx de invocación luego lleva las claves desbloqueadas de cada jugador humano en esos juegos:

ctx.linkedAchievements = {
  "7c9e6679-...": {                                   // player id
    "83fd04b1-3cbe-4b09-a251-3733ad4b9d94": ["first-win", "checkmate-10"]
  }
};
  • Se vuelve a leer en cada invocación, por lo que un desbloqueo obtenido en el otro juego a mitad del partido se ve en el siguiente. Un contenedor lo recibe en el ctx de POST /sessions, es decir, en crear y en restaurar.
  • A lo sumo 8 juegos; entradas que no sean cadenas no vacías, duplicados y slugs superiores a 100 los personajes se eliminan. Al igual que las demás declaraciones, se lee cuando se publica el juego o actualizado.
  • Un juego que declara que nada obtiene no. linkedAchievements campo y no paga nada.
  • Utilice esta ruta para cualquier cosa que la plataforma deba exigir, como desbloquear el juego u otorgar una logro propio.

De su cliente: GET /api/v1/games/{slug}/linked-achievements/{otherSlug}

El propio autor de la llamada se desbloquea en otherSlug. No necesita declaración, por lo que un juego sólo para navegador sin El servidor puede usarlo y funciona con el token de inicio para {slug}: los propios puntos finales del otro juego manténgase alejado de esa ficha.

{
  "game": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "hidden": false,
  "unlocked": [
    { "key": "first-win", "unlockedAt": "2026-07-25T09:14:02Z" }
  ]
}

Un cliente puede mentir sobre lo que recibió, así que trate esto como una pista para la interfaz de usuario y los cosméticos, no como una prueba.

Logros creados por el propietario del juego.

Declarar logros en el código no es la única forma de darle algunos a tu juego. Si tienes un juego con un server= guión o container.image= backend, también puedes crear logros para él a través del API: como lo hace un editor con el título de un catálogo, sin necesidad de cuenta de editor ni permiso. Ser propietario del juego es la totalidad de la subvención. Úselo cuando un diseñador quiera agregar o reformular logros sin un cambio de código, o cuando su backend otorga claves que no declara.

Sólo el servidor de tu juego puede desbloquearlos., exactamente como los declarados: su script devuelve la clave en achievements, o su contenedor lo envía por el canal de control. Nada cambia en el lado de desbloqueo: las claves se resuelven contra todo de los logros del juego, declarados y creados.

{id} es la identificación de tu juego de GET /api/v1/me/github-games.

POST /api/v1/me/github-games/{id}/achievements

{

  "description": "Finish a level in under a minute.",
  "icon": "https://cdn.example/speedrunner.png",
  "secret": false,
  "points": 25
}

key, name y description son requeridos. Devoluciones 201:

{

GET En el mismo camino se enumeran todos los logros del juego de esta forma: origin es declared para los que su script o contenedor declara y owner para los creados aquí, y unlocks cuenta cuántos jugadores tienen cada uno.

PUT .../achievements/{achievementId} toma cualquiera de name, description, icon, secret y points; el key no puede cambiar. DELETE lo elimina.

Logros del título del catálogo

Para software distribuido a través del catálogo, donde el cliente es lo único que observa las condición de desbloqueo. Las definiciones se leen de forma anónima; el desbloqueo requiere un JWT y un no revocado derecho al título.

GET /api/v1/software/{titleId}/achievements

AchievementDto[]. Los logros secretos están ocultos a menos que la persona que llama los desbloquee (y sus criteria se retiene hasta entonces). Los logros relacionados con el juego nunca aparecen aquí.

[
  {
    "id": "…",
    "key": "…",
    "name": "…",
    "description": "…",
    "icon": "…",
    "secret": false,
    "points": 10,
    "visibility": "…",
    "criteria": "…"
  }
]

POST /api/v1/me/achievements/unlock

{ "achievementDefinitionId": "…" }

Devoluciones 204. Devoluciones 400 cuando el logro no existe, cuando la persona que llama no tiene derecho al título (ver catalog.md), o cuando el logro es ámbito del juego - esos son otorgado únicamente por el script autorizado o el backend del contenedor. Volver a desbloquear algo que ya se tiene regresa 204.

La gestión por parte del editor (definir, actualizar y eliminar logros de títulos) reside en publisher.md.

GET /api/v1/me/achievements

La persona que llama se desbloquea como UserAchievementDto[]. sin titleId esto devuelve cada desbloqueo retenciones del usuario, tanto en el ámbito del juego como en el del título; aprobar ?titleId= para limitarlo a un título de catálogo.

    "name": "…",
    "description": "…",
    "icon": "…",
    "points": 10,
    "unlockedAt": "…"

Para la pantalla de logros propia de un juego, prefiera GET /api/v1/games/{slug}/achievements, que también devuelve las definiciones que tiene el jugador no aún desbloqueado.
