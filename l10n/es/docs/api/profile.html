Perfil

La API de perfil cubre la propia cuenta del usuario autenticado (/api/v1/me/...), búsquedas públicas de otros usuarios, claves públicas, identidades vinculadas, configuraciones de privacidad, derechos y latidos de presencia. Las rutas de cuentas requieren autorización; El documento de términos actuales es público.

Los cuerpos de error varían; ver Convenciones API.

Todos los campos son opcionales. Restricciones: username 1 a 32 caracteres; nickname ≤64 caracteres (muchos las cuentas no tienen ninguno); metadata ≤4096 caracteres. Los nombres de usuario y los apodos comparten uno. espacio de nombres que no distingue entre mayúsculas y minúsculas: 409 cuando otra cuenta utiliza el nombre como nombre de usuario o apodo, ignorando el caso. Los apodos están normalizados por NFKC y los caracteres de control o invisibles están normalizados. 400. Cambio email requiere adicionalmente un Sesión autenticada por OAuth porque el correo electrónico de la cuenta puede aprobar enlaces de credenciales; una clave pública o sesión de verificación de correo electrónico obtiene 403 para ese campo pero aún puede actualizar los demás. Devuelve 204 en éxito, 409 en conflicto (nombre de usuario o apodo ya tomado).

Aceptación de términos

Antes de utilizar puntos finales REST protegidos o abrir WebSockets, la cuenta debe aceptar la actual Términos de StarHermit. Esto se aplica a los tokens de cuenta y a los tokens de lanzamiento de jugadores, incluidas las cuentas que Aceptó una revisión anterior. No se aplica a recursos/inicios de sesión anónimos ni a un servidor de contenedor. propio token de implementación. GET /api/v1/me y el punto final de aceptación permanecen disponibles con su habitual permisos de la cuenta mientras la aceptación está pendiente.

GET /api/v1/me incluye currentTermsHash y termsAcceptanceRequired. el almacenado termsAcceptedHash y termsAcceptedAt son nulos antes de la primera aceptación. El hash que se muestra en el el ejemplo de perfil anterior está abreviado; Utilice siempre el hash completo devuelto por la API.

GET /api/v1/terms

Anónimo; también legible con un token de inicio de jugador. Devoluciones 200 con Cache-Control: no-store:

{ "hash": "<current-64-character-lowercase-sha256>", "text": "<complete terms text>" }

Prestar text como texto plano. hash es SHA-256 de los bytes exactos del documento UTF-8; usar el devuelto valor en lugar de aplicar hash al texto de visualización reformateado.

POST /api/v1/me/terms/accept

Después de que el usuario lea y acepte explícitamente la revisión mostrada, envíe su hash:

POST /api/v1/me/terms/accept
Authorization: Bearer <account-access-token>
Content-Type: application/json

{ "hash": "<hash-returned-with-the-displayed-text>" }

Devoluciones 200 con { "termsAcceptedHash", "termsAcceptedAt" }. OAuth y sesiones de cuentas de clave pública y tokens de lanzamiento con alcance de juego del jugador puede aceptar. Un token de servidor contenedor no puede actuar para un jugador. La aceptación se almacena en la cuenta y entra en vigor en el siguiente solicitud con el mismo token aún válido; Actualizar el token no es necesario.

Se devuelve un hash faltante/en blanco o uno de más de 64 caracteres 400. Un hash que no exactamente coincidir con las devoluciones de la revisión actual 409:

{
  "error": "terms_version_mismatch",
  "termsHash": "<current-hash>",
  "termsUrl": "/api/v1/terms"
}

Obtener y mostrar el nuevo documento y solicitar nuevamente su aceptación; no aceptes silenciosamente un reemplazo revisión. Otras solicitudes protegidas con devolución pendiente de aceptación 403:

{
  "error": "terms_acceptance_required",
  "message": "Accept the latest terms of service before using the API.",
  "termsHash": "<current-hash>",
  "termsUrl": "/api/v1/terms",
  "acceptUrl": "/api/v1/me/terms/accept"
}

Un juego alojado puede mostrar los términos y enviar el hash mostrado con su token de inicio de jugador. cuando el jugador presiona Aceptar, luego vuelve a intentarlo. También puede enviar al jugador a la interfaz de usuario de su cuenta. El inicio de sesión repetido o la actualización del token no solucionan la aceptación pendiente. Las actualizaciones de WebSocket se rechazan con HTTP 403 antes de abrir; los navegadores pueden ocultar el cuerpo de la respuesta, así que maneje la aceptación a través de REST antes de conectarse.

Ejemplo para una cuenta o cliente de juego (llame acceptDisplayedTerms sólo desde la acción Aceptar del usuario):

const api = 'https://api.starhermit.com';
async function loadTerms() {
  const response = await fetch(`${api}/api/v1/terms`);
  if (!response.ok) throw new Error(`Terms fetch failed: ${response.status}`);
  return response.json(); // Display text, retain this document's hash.
}
async function acceptDisplayedTerms(accountToken, displayedTerms) {
  const response = await fetch(`${api}/api/v1/me/terms/accept`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${accountToken}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ hash: displayedTerms.hash })
  });
  if (response.status === 409) {
    throw new Error('Terms changed. Reload and display them for a new acceptance.');
  }
  if (!response.ok) throw new Error(`Acceptance failed: ${response.status}`);
  return response.json();
}

Claves públicas

Una clave registrada es una credencial API: su titular puede completar el flujo de desafío de clave pública y recibir un token de acceso/actualización ordinario par. Esto hace que una clave etiquetada por separado sea adecuada para un cliente de escritorio o una canalización de implementación.

Agregar claves o revocar otras claves requiere una sesión autenticada por OAuth. Una clave pública La sesión puede revocar sólo su propia clave a través de DELETE /api/v1/me/public-keys/current. no puede inscribir reemplazos o revocar otros dispositivos. El listado permanece disponible para cualquier sesión completa de la cuenta; Los tokens de inicio del juego y del servidor no pueden administrar las claves de cuenta.

GET /api/v1/me/public-keys

La lista incluye filas revocadas como pista de auditoría:

[
  {
    "id": "9b2f5c74-1d2e-4a6b-8c0d-1e2f3a4b5c6d",
    "keyType": "Ed25519",
    "keyData": "<base64-raw-32-byte-public-key>",
    "label": "orbit-league-production",
    "fingerprint": "4d9f3c...",
    "createdAt": "2026-07-01T12:00:00Z",
    "lastUsedAt": "2026-07-30T09:00:00Z",
    "isRevoked": false,
    "revokedAt": null,
    "metadata": null
  }
]

POST /api/v1/me/public-keys

Requiere una sesión autenticada por OAuth y adjunta la clave inmediatamente; a diferencia del anónimo registrarse, no es necesario enviar un correo electrónico de ida y vuelta.

{
  "keyType": "Ed25519",
  "keyData": "<base64-raw-32-byte-public-key>",
  "label": "orbit-league-production"
}

label es opcional (128 caracteres como máximo). Los tipos de claves aceptados son Ed25519, ECDSA-P256, y RSA-PSS; El material debe ser Base64 estándar: una clave pública sin formato de 32 bytes para Ed25519, un P-256 codificado. punto de curva para ECDSA, o un SPKI público para RSA. Las claves RSA deben tener entre 2048 y 8192 bits. la plataforma canonicaliza el material válido y limita una cuenta a 20 claves activas de forma predeterminada. fingerprint es el resumen hexadecimal SHA-256 en minúsculas del canónico keyType:keyData cadena.

Devoluciones 201 con la clave creada. Devoluciones de material no válido 400; una clave ya activa o una completa devuelve la lista de claves 409 (este último incluye limit). El material clave activo es único en toda la plataforma.

DELETE /api/v1/me/public-keys/{keyId}

Requiere una sesión autenticada por OAuth. La revocación es idempotente y finaliza las sesiones de actualización acuñadas. por la llave; los tokens de acceso que lo nombran se rechazan en su siguiente solicitud. Devoluciones:

{ "revoked": [{ "id": "...", "isRevoked": true }], "sessionsEnded": 1 }

Devuelve una clave desconocida en esta cuenta. 404.

DELETE /api/v1/me/public-keys/all

La operación de compromiso-respuesta: revocar todas las claves activas y finalizar todas las sesiones que hayan autenticado. Tiene un explícito /all ruta para que una ID de clave vacía accidentalmente no pueda convertirse en una revocación masiva. Devuelve lo mismo { revoked, sessionsEnded } forma.

DELETE /api/v1/me/public-keys/current

Una sesión de cuenta completa autenticada con una clave pública puede revocar la clave utilizada para esa sesión, sin nombrar una ID de clave. Usa esto para Olvídate de este dispositivo. me devuelve lo mismo { revoked, sessionsEnded } forma e invalida las sesiones usando esa clave. Descartar tokens almacenados y la clave privada local después del éxito. Una sesión sin retornos de clave pública 409 con code: "no_public_key_session"; Se rechazan los tokens de inicio del juego.

Para ver un ejemplo completo de implementación de la máquina, consulte Cargue compilaciones desde CI/CD con una clave pública inscrita en OAuth.

Configuración de privacidad

GET /api/v1/me/privacy te devuelve tu PrivacySettings; PUT /api/v1/me/privacy los reemplaza (devuelve 204):

{
  "onlineStatus": 1,
  "currentlyPlaying": 1,
  "recentLaunchActivity": 0,
  "hoursPlayed": 0,
  "recentDownloads": 0,
  "achievements": 2,

Cada campo es un PrivacyLevel enumeración: 0 = Privado, 1 = Sólo amigos, 2 = Público.

presencia de latidos del corazón

POST /api/v1/me/heartbeat

Devuelve 204. Escribe LastSeenAt del lado del servidor, acelerado: esta es la señal de presencia utilizada por los amigos y el chat.

Tokens de lanzamiento relacionados con el juego

De los puntos finales de esta página, un token de inicio con ámbito de juego solo puede llamar a:

  • GET /api/v1/users/{id}/avatar
  • GET /api/v1/users/{id}/profile
  • GET /api/v1/me/friends (ver Amigos)
  • GET /api/v1/terms
  • POST /api/v1/me/terms/accept
  • POST /api/v1/me/heartbeat

Todo lo demás devuelve 403 bajo la valla del alcance del juego descrita en Autenticación.

Convención de nombre para mostrar

Las interfaces de usuario de los juegos suelen mostrar apodos en lugar de nombres de usuario al representar oponentes, recurriendo a algo como "Player " + id.slice(0,8) cuando no se establece ningún apodo. La implementación de referencia de ajedrez sigue esta convención; Otros clientes del juego deberían hacer lo mismo.
