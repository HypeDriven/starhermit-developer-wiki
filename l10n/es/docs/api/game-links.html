Enlaces externos

Un juego con motor StarHermit (host API 1.24) puede abrir una página web, pero solo una que el personal de StarHermit has aprobado para tu juego. Tu juego abre un enlace por identificación y nunca pasa una URL, por lo que no puede agregar cualquier cosa a uno.

Declara tus enlaces

En starhermit.txt:

engine.minor=24
engine.link.discord=https://discord.gg/abc
engine.link.store=https://example.com/game
  • Puedes declarar hasta 16 enlaces. Cada identificación tiene entre 1 y 32 caracteres de a-z 0-9 - y podrá aparecer sólo una vez.
  • Cualquier engine.link.* necesidades clave engine.minor=24, por lo que los tiempos de ejecución más antiguos rechazan el juego.
  • Tus guiones llaman openLink("discord"). El tiempo de ejecución muestra su propia confirmación, con el enlace host completo y URL, y abre la página sólo si el jugador elige Abrir.

¿Qué vínculo puede ser?

Un enlace debe ser https, sin puerto, no user@, sin dirección IP ni nombre local (localhost, .local, .internal). Su host debe ser ASCII, con nombres internacionalizados escritos como punycode, y tener al menos dos etiquetas. No puede contener barras invertidas, espacios, barras diagonales codificadas (%2f, %5c) o ./.. segmentos de camino. La plataforma mantiene la forma canónica: el esquema y el host en minúscula, y / por un camino vacío. Todo lo demás se mantiene exactamente como lo escribiste.

Un paquete con un enlace que infringe una regla se rechaza cuando se publica, con 422 invalid_link: engine.link.<id> is not an allowed link (<rule>), antes de que algo se publique.

Revisar

Cada nuevo enlace comienza pendingy el tiempo de ejecución no abre nada hasta que el personal lo apruebe. Algunos enlaces son rechazados automáticamente: acortadores de URL y servicios de redireccionamiento, cuyo destino es otra persona controles y descargas directas de programas y archivos (.exe, .dmg, .apk, .zip y similares). Parámetros de seguimiento como utm_* están marcados para el revisor.

Una aprobación pertenece a tu juego y a esa URL exacta. Una versión posterior que enumera la misma URL, en cualquier identificación, la conserva. Cambiar la URL necesita una nueva revisión. El personal puede revocar una aprobación o bloquear una anfitrión completo, en cualquier momento.

Vea sus enlaces y su estado en GET /api/v1/me/github-games/{id}/links:

[ { "id": "discord", "url": "https://discord.gg/abc", "status": "approved", "autoReason": null, "note": null } ]

Las comprobaciones en tiempo de ejecución GET /api/v1/games/{slug}/links/{id} en cada apertura, con el lanzamiento del jugador ficha. La respuesta es { id, url, status }, dónde status es approved, pending, rejected o revoked, o 404 link_unknown para una identificación que su manifiesto implementado no declara.

Mientras desarrollas localmente (--dev de forma nativa, o una página de bucle invertido en el navegador, sin inicio token), el tiempo de ejecución abre enlaces declarados detrás de una advertencia de que no están revisados.
