Voz

StarHermit Voice proporciona salas de voz por conversación a través de una API REST (api/v1/voice) más un WebSocket mixto binario/texto (ws/v1/voice) para señalización de audio y WebRTC. Todos los puntos finales REST requieren autenticación. La disponibilidad de voz puede variar. Los cuerpos de error varían; ver Convenciones API.

Las habitaciones están ancladas a un conversación de chat; la membresía en la conversación controla todo, por lo que las reglas de amistad del chat también gobiernan la voz (las conversaciones de sesiones de juego pasan por alto la amistad). Límites: 3 salas activas por conversación, hasta 32 participantes por sala (el valor predeterminado cuando omites maxParticipants; su valor está fijado entre 2 y 32). Cada habitación declara un codec los conjuntos de creadores y los clientes pueden confiar en: pcm de forma predeterminada, la convención de 20 ms/16 kHz/mono/s16, el relé reenvía de forma opaca, o opus para una sala cuyos participantes ejecutan un cliente compatible con Opus. La etiqueta se reenvía, nunca se aplica una transformación del servidor.

Puntos finales de descanso

Base: https://api.starhermit.com/api/v1/voice.

Método Camino autenticación Descripción
CORREO /rooms JWT Crear una sala de voz para una conversación
CORREO /rooms/join-or-create JWT Devuelva la sala activa más antigua de la conversación con un asiento libre o cree una, elegida atómicamente
CONSEGUIR /rooms?conversationId= JWT Listar salas para una conversación
CONSEGUIR /rooms/{roomId} JWT consigue una habitacion
CORREO /rooms/{roomId}/join JWT Unirse a una sala (requerido antes del WS)
CORREO /rooms/{roomId}/leave JWT dejar una habitación
CORREO /rooms/{roomId}/mute JWT Establece tu propio estado de silencio
CORREO /rooms/{roomId}/participants/{userId}/server-mute JWT (creador) El anfitrión silencia que el participante no puede levantar
CORREO /rooms/{roomId}/close JWT Cerrar una sala (solo creador)

crear una habitación

POST /rooms

{ "conversationId": "<guid>", "maxParticipants": 8, "codec": "opus" }

maxParticipants (opcional, fijado en 2–32; por defecto en 32) y codec (opcional, pcm o opus; cualquier otra cosa se lee como pcm) se configuran una vez en el momento de la creación. Devuelve un VoiceRoomDto.

Unirse o crear una sala

POST /rooms/join-or-create con el mismo cuerpo devuelve un VoiceRoomDto para la conversación sala activa más antigua que todavía tiene un asiento libre, o crea uno cuando ninguno lo hace, decidido atómicamente bajo el bloqueo de la sala de conversación, por lo que dos miembros que activan la voz en el mismo instante aterrizan en una habitación en lugar de dos en los que no pueden escucharse entre sí. maxParticipants/codec aplicar sólo cuando se crea. aun llamas /rooms/{roomId}/join en la habitación devuelta antes de abrir el WebSocket.

Forma de la habitación

GET /rooms?conversationId=<guid> → VoiceRoomDto[]; GET /rooms/{roomId} → VoiceRoomDto:

{
  "id": "<guid>",
  "conversationId": "<guid>",
  "creatorUserId": "<guid>",
  "codec": "opus",
  "status": "Active",
  "maxParticipants": 8,
  "createdAt": "2026-07-22T07:00:00Z",
  "participants": [
    {
      "userId": "<guid>",
      "username": "alice",
      "isMuted": false,
      "isConnected": true,
      "joinedAt": "2026-07-22T07:01:00Z"
    }
  ]
}

Unirse, salir, silenciar, cerrar

POST /rooms/{roomId}/join → VoiceRoomDto. Esta unión REST es requerido antes de abrir el WebSocket; conectando sin que regrese 403. Al volver a unirse se borra el permiso del participante. propio silenciar (isMuted); un anfitrión isServerMuted sobrevive a la salida y se vuelve a conectar.

POST /rooms/{roomId}/leave → 204.

POST /rooms/{roomId}/mute con { "muted": true } → 204. Este es el silencio del participante y no puede borrar el silencio de un anfitrión.

POST /rooms/{roomId}/participants/{userId}/server-mute con { "muted": true } → 204 (solo creador). El audio se interrumpe si se establece el silencio.

POST /rooms/{roomId}/close → 204 (solo creador).

Indique su silencio al conectarse en lugar de heredar lo que recuerde la fila.

WebSocket: ws/v1/voice

Conéctate a wss://api.starhermit.com/ws/v1/voice?roomId=<guid> con un JWT a través del Authorization encabezamiento, ?ticket=, o ?access_token=. Un DESCANSO previo join se requiere.

El protocolo es mixto:

Marcos binarios: audio

Los fotogramas binarios transportan audio (por ejemplo, Opus). El servidor transmite cada cuadro a los demás participantes como:

[16-byte senderUserId][audio…]

El servidor antepone el autenticado ID del remitente y nunca confía en un remitente proporcionado por el cliente. Se elimina el audio de los usuarios silenciados. Límites: 100 paquetes/segundo por usuario, trama máxima de 4000 bytes.

Marcos de texto: cliente → control de servidor

{ "type": "mute", "muted": true }

{ "type": "speaking", "speaking": true }

{ "type": "rtc", "to": "<guid>", "payload": { } }

{ "type": "deafen", "deafened": true }

rtc Las cargas útiles son señales WebRTC opacas, reenviadas al participante direccionado. deafen suprime el audio binario retransmitido entrante para este conector; no se silencia automáticamente audio saliente o una conexión de pares separada. Aplícalos localmente cuando el jugador elija Deafen.

La forma del participante REST expone el silencio propio, no el silencio del host. La lista de voces inicial y los eventos para unirse. incluir serverMuted; no hay ningún evento push separado de cambio de silenciamiento del host. Si tu juego usa P2P El audio, su señalización de silenciamiento del host y su aplicación deben ser parte de su propia integración de medios.

Cuando se desconecta el último enchufe de voz, finaliza la membresía de la sala de voz. Llamar DESCANSO join otra vez antes reconectar y restaurar el silencio deseado antes de enviar audio.

Patrón de integración de ejemplo (de la implementación de referencia de ajedrez)

La voz se activa por sesión de juego. Un cliente típico enable() fluir:

  1. POST /api/v1/voice/rooms/join-or-create con { "conversationId": "<chatConversationId>" } – una llamada que regresa a la habitación en la que convergen todos los demás que activan la voz. (aún puedes GET /rooms?conversationId= entonces POST /rooms a mano, pero dos clientes que hacen eso a la vez forman dos habitaciones.)
  2. POST /api/v1/voice/rooms/{roomId}/join.
  3. Abierto ws/v1/voice?roomId=<guid>.

En el implementación de referencia de ajedrez, el audio se ejecuta a través de WebRTC P2P con negociación perfecta; La señalización se intercambia a través del rtc mensajes de control ({ "sdp": … } / { "ice": … } payloads), con la ruta binaria Opus transmitida por el servidor como alternativa.

Tokens de lanzamiento relacionados con el juego puede utilice la voz REST y WebSocket para salas adjuntas a sus propias sesiones de juego.
