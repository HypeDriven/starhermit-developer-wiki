Elige una integración

Comience por dónde se ejecuta su juego y quién valida el juego. Un juego de navegador alojado no necesita una backend del servidor para usar inicio de sesión, guardados en la nube, configuraciones, controles o salas en tiempo real.

Tres puntos de partida comunes

Un juego de navegador para un jugador: seguir el inicio rápido del navegador. Oferta Iniciar sesión con StarHermit para el progreso de la cuenta y Juega para un solo jugador (el progreso no es guardado) para jugar inmediatamente. Comience sin backend; agregue uno cuando necesite competitivo validado resultados. La configuración y los guardados en la nube no requieren una server= línea.

Multijugador casual con amigos: usar salas en tiempo real. El anfitrión ejecuta el simulación, los invitados envían aportaciones y el anfitrión transmite instantáneas. Tu juego implementa IA y host migración. La plataforma proporciona asientos, identidad y rutas. La confianza en el anfitrión es parte de este modelo.

Multijugador clasificado o persistente: usar un guión o un contenedor, con habitaciones si necesitas un vestíbulo. Validar el juego antes premiar cualquier cosa. Los scripts solicitan una frecuencia de ticks dentro del límite admitido (30 Hz de forma predeterminada); Los contenedores ejecutan su propio ciclo de simulación. El emparejamiento directo de contenedores actualmente tiene un implícito Cola 1 contra 1, pero una sala puede crear una sesión de contenedor de N jugadores.

El UUID de un juego alojado es su subdominio y slug API. Los nombres para mostrar y los nombres de repositorio no son API identificadores. Ver credenciales e identificadores antes de las solicitudes de cableado.
