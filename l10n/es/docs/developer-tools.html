Herramientas para desarrolladores de StarHermit

Cree paquetes de juegos de script publicables, cárguelos en StarHermit y Proporcione a su asistente de codificación una conexión MCP local. Estas herramientas no requieren Instalación de óxido o verificación de la fuente del motor. El juego puede tener el suyo. construir dependencias, como Node.js.

Descargue el archivo para su computadora desde la siguiente tabla o desde https://engine.starhermit.com/engine/tools/latest.json (enumera cada uno dirección, tamaño y SHA-256 del archivo) y compare su SHA-256 con el suma de comprobación al lado (<archive>.sha256). Descomprímalo y coloque su directorio en PATH, o utilice la ruta completa del ejecutable en los siguientes comandos. Las descargas de macOS son proporcionado por separado para Apple Silicon (macos-aarch64) e Intel (macos-x86_64). No están notariados por Apple y no se requiere ninguna descarga. Código de autenticación o ID de desarrollador firmado. La construcción de Apple Silicon es compilado cruzado; reportar problemas.

Comprobar y empaquetar un juego

starhermit-tools --version
starhermit-tools check my-game
starhermit-tools package --web my-game --out upload --remote-out remote-objects

El directorio del juego contiene starhermit.txt y los archivos que necesita el juego. engine.version fija una versión de motor publicada; la herramienta lee su manifiesta desde Engine.starhermit.com y escribe un cargador y un archivo con hash índice. --engine-version X.Y.Z selecciona una versión compatible explícitamente. Archivos declarados por engine.remote.files están escritos para remote-objects; cuando engine.remote.urls=platform, la publicación los carga primero.

check valida el manifiesto, las rutas de los paquetes y la estructura del archivo. lo hace no ejecutar scripts. Pruebe el juego web empaquetado en un navegador antes publicación. Los desarrolladores también pueden descargar el nativo correspondiente. tiempo de ejecución desde una versión del motor (Windows, Linux y desde el motor 1.26.2 macOS 11 o posterior en Intel y Apple Silicon) y uso starhermit check my-game para una verificación de ejecución sin cabeza. los macos Los tiempos de ejecución están firmados ad hoc y no están notariados, y aún no han sido Probado en hardware Apple real. Un tarball descargado en un navegador es en cuarentena: correr xattr -d com.apple.quarantine starhermit o permitirlo en Configuración del sistema.

Publicar

Utilice su propia clave de implementación registrada, siguiendo la incorporación de clave pública y guías de CI/CD en la wiki para desarrolladores. Colocar STARHERMIT_PUBLIC_KEY y STARHERMIT_PRIVATE_KEY en su shell o en su almacén secreto de CI. Alternativamente, conjunto STARHERMIT_ACCESS_TOKEN a un token de acceso a la cuenta. No pongas estos valores en el juego, confirmarlos o agregarlos a la configuración de MCP.

starhermit-tools publish --game-id YOUR-GAME-ID --upload upload --remote-out remote-objects

Esto reemplaza los archivos implementados del juego. --mode merge parchea un existente subir en su lugar. Para crear un nuevo juego, reemplace --game-id YOUR-GAME-ID con --new. --socket selecciona el WebSocket de carga; cargas grandes selecciónelo automáticamente. --display-name y --description anular lo subido nombre y descripción del manifiesto. El editor informa la URL alojada. y escribe un informe de publicación al lado de la carga.

La cuenta debe ser propietaria del juego. Un error de credencial o un límite denegado es un error; no lo solucione con las credenciales de otra persona. Remoto los objetos que ya están en el juego se reutilizan; cargas de objetos interrumpidas currículum. Se puede crear un nuevo juego antes de que falle la carga de un objeto posterior; use su ID de juego reportado para volver a intentarlo en lugar de crear otro.

STARHERMIT_API_BASE selecciona otra implementación HTTPS. STARHERMIT_CA_FILE selecciona un paquete de confianza PEM, por ejemplo un desarrollo CA; La verificación TLS siempre está habilitada. El uso normal no necesita ninguna variable.

Conecte un asistente de codificación con MCP

Agregue un servidor stdio MCP a la configuración de su asistente, usando absoluta rutas apropiadas para su computadora:

{
  "mcpServers": {
    "starhermit": {
      "command": "/absolute/path/to/starhermit-tools",
      "args": ["mcp", "--package", "/absolute/path/to/my-game"]
    }
  }
}

El servidor ofrece check_package, package_web, y package_native. Si el juego tiene un script de compilación de Node.js, agrega --build-script y su camino absoluto a los argumentos de MCP para exponer un build herramienta. esto corre ese script configurado; no acepta comandos arbitrarios de MCP. package_web toma opcional outDir, remoteOut, y engineVersion; Las rutas de salida relativas son relativas al directorio del juego. Por defecto escribe starhermit-build/upload y starhermit-build/remote al lado del directorio del juego. package_native escribe el índice de archivos nativo del juego para instalación por parte de un cliente StarHermit compatible, que instala el motor tiempo de ejecución para la plataforma del reproductor (incluido macOS, desde el motor 1.26.2). Ninguna herramienta publica nada.

Con un tiempo de ejecución nativo instalado, agregue --runtime y su ruta ejecutable absoluta a los argumentos de MCP para habilitar run_checks. Esa herramienta ejecuta el código del juego en el tiempo de ejecución configurado. Publicación está disponible solo como un comando CLI explícito y nunca es una herramienta MCP.
