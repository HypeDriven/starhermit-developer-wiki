Juego de ejemplo: cómo el fútbol utiliza el motor StarHermit

Fútbol StarHermit es un publico, completo juego de guión. Es fútbol en 3D en tiempo real para 1 a 22 jugadores, con compañeros de equipo AI, un foco iluminado estadio, vestíbulos en línea, chat de voz y texto, repeticiones, tabla de clasificación, logros y nueve idiomas. Esta página lo desmonta paso a paso para mostrar cómo un juego real utiliza el motor. cada uno El paso nombra los módulos del motor involucrados y enlaza a la fuente del juego, donde puedes leer el código completo.

Este tutorial está escrito para el motor. 1.40.0, la última versión. Cada llamada mostrada está listada en el referencia de API del motor. Lea el tutorial del motor primero si aún no has creado un juego de script.

Los enlaces de origen apuntan al compromiso 33bd9bd. En ese compromiso, el juego fija el motor 1.39.0 con engine.minor=39. No utiliza nada más nuevo, por lo que se ejecuta sin cambios en 1.40.0; moverlo es un cambio de una línea a engine.version (ver paso 12).

La forma del juego.

Camino Role
starhermit.txt El manifiesto: nombre, pin del motor, script del servidor, controles, capacidades
server.js La simulación de un partido: ejecutada por la plataforma como servidor autorizado y cargada por el cliente para practicar y predecir fuera de línea.
engine/src/main.ts El módulo de entrada: devoluciones de llamada del ciclo de vida y la máquina de estado de las pantallas
engine/src/match.ts, logic/ Flujo de coincidencias, código de red, interpolación y predicción.
engine/src/world/ El estadio, los futbolistas, el balón y el público en el escenario 3D
engine/src/screens/, hud.ts Menús (starhermit:ui) y el HUD del partido (starhermit:draw)
engine/src/net.ts, platform.ts, chat.ts, voice.ts Todo lo que habla de la plataforma StarHermit
engine/src/audio.ts, i18n.ts, quality.ts Niveles de sonido, idiomas y gráficos.
assets/, sfx/ Imágenes, tablas de cuerdas y clips de sonido.

1. El manifiesto

starhermit.txt convierte la carpeta en un juego de script y también declara el script del servidor y los controles:

name=Football
launch=index.html
server=server.js
control.up=KeyW+ArrowUp | Run forward
control.shoot=Space+KeyJ | Shoot (hold) / tap to pass
control.tackle=KeyK | Slide tackle / pressure
engine.api=1
engine.entry=engine/src/main.ts
engine.version=1.39.0
engine.minor=39
engine.capabilities=platform,voice,clipboard,storage
engine.gamepad.shoot=West+RightTrigger
engine.gamepad.pass=South
  • launch=index.html es la página del cargador que starhermit package --web escribe. juega el juego en los navegadores en el tiempo de ejecución web de la versión anclada.
  • server=server.js es el script de coincidencia autorizado de la plataforma (paso 6).
  • control.* y engine.gamepad.* las líneas definen comportamiento. El tiempo de ejecución les vincula claves y pads, y los jugadores los vuelven a vincular en el menú de Opciones del tiempo de ejecución. El juego nunca menciona una clave para el juego.
  • engine.capabilities solicita la plataforma (salas, enchufes, tablas de clasificación, repeticiones, chat), voz, el portapapeles (enlaces de invitación) y el almacenamiento (configuraciones). El tiempo de ejecución rechaza llamadas fuera de ellos.

La lista completa de claves está en el starhermit.txt manifiesto.

2. El módulo de entrada y el bucle del marco.

engine/src/main.ts configura el renderizador en el alcance del módulo, luego registra las cuatro devoluciones de llamadas del ciclo de vida de starhermit:engine:

import { frame, onFixedUpdate, onRender, onStart, onUpdate, setFixedRate } from "starhermit:engine";
import { ACESFilmicToneMapping, PCFSoftShadowMap, PerspectiveCamera, renderer, scene } from "starhermit:scene";

const camera = new PerspectiveCamera(55, 16 / 9, 0.1, 800);
renderer.camera = camera;
renderer.shadowMap.enabled = true;
renderer.shadowMap.type = PCFSoftShadowMap;
renderer.toneMapping = ACESFilmicToneMapping;

onStart(() => {
  setFixedRate(60);
  loadLanguages(); // string tables (step 10)
  sim();           // evaluate server.js once (step 6)
  menuScene.start(); // an AI-vs-AI match behind the menu
  // … platform listeners, settings listeners, invite polling
});

onFixedUpdate((step) => {
  if (match) match.fixedStep(step);
  else if (!replay) menuScene.fixedStep(step);
});

onUpdate((delta) => {
  pollQuality();
  if (match) match.update(Math.min(delta, 0.1));
  // … replay viewer or menu backdrop
});

onRender(() => {
  const fr = frame();
  if (Math.abs(camera.aspect - fr.width / fr.height) > 1e-6) {
    camera.aspect = fr.width / fr.height;
    camera.updateProjectionMatrix();
  }
  hud.draw();
  // … chat, in-match menu or the menu screens
});

El patrón a copiar:

  • La simulación se ejecuta onFixedUpdate, a 60 Hz fijos.
  • La lógica por cuadro se ejecuta onUpdate, con delta tapado para que un marco estancado no haga los jugadores saltan.
  • El dibujo se ejecuta onRender. Sólo hay una de cada devolución de llamada, por lo que main.ts abanicos hacia el pantalla actual: menú, lobby, partido, repetición o resultado.

3. El mundo 3D: starhermit:scene

El estadio, los futbolistas, el balón y los árbitros son objetos ordinarios de estilo three.js de starhermit:scene: Mesh, Group, MeshStandardMaterial, CylinderGeometry, Sprite, CanvasTexture etcétera. El código portado desde three.js funciona principalmente sin cambios. Algunos detalles que vale la pena leer:

  • world/stadium.ts construye el campo, las gradas, los focos y la niebla. Establece los efectos posteriores (renderer.bloom, renderer.grade, renderer.antialias) y sombras para cada nivel de gráficos.
  • world/environment.ts hace un mapa del entorno con PMREMGenerator de un DataTexture.
  • world/crest.ts y world/nametags.ts dibujar escudos de equipo y apodos flotantes en un starhermit:canvas OffscreenCanvas, luego úselos como CanvasTexturearena Sprites.

4. Miles de piezas móviles: starhermit:world

Animar a 22 futbolistas porro, además de miles de espectadores, sería demasiado lento ya que script por objeto en el intérprete nativo. Movimientos de fútbol que funcionan starhermit:world mesas (filas de columnas escritas) y granos (funciona el tiempo de ejecución se ejecuta en cada fila de forma nativa):

import { kernel, schedule, table } from "starhermit:world";

const crowd = table("crowd", CROWD_ROWS, {
  bx: "f32", by: "f32", bz: "f32", ph: "f32", fr: "f32", av: "f32",
  q: "quat", s: "f32", sy: "f32", x: "f32", y: "f32", z: "f32",
});
const sway = kernel(crowd, (r, u: { t: number; amp: number; spd: number; sway: number; shake: number }) => {
  const j = Math.sin(u.t * u.spd * r.fr + r.ph);
  r.y = r.by + (j > 0 ? j * j : 0) * u.amp * r.av;
  // …
});
// An eighth of the crowd each frame: the work is sliced across frames.
const swayRun = schedule.update(sway, { t: 0, amp: 0, spd: 0, sway: 0, shake: 0 }, { slices: 8 });

El futbolista se infiltra world/rig.ts utilizar el mismo enfoque. A rigs La tabla contiene el estado de animación de cada futbolista. A joints mesa, con un ref:rigs columna, admite 15 uniones por equipo y fijaciones expulse los nodos de escena de él. Dos núcleos programados después onUpdate calcula las poses y el tiempo de ejecución escribe el nodo se transforma. El trabajo de guión por futbolista asciende a una docena de números por fotograma.

5. Entrada: acciones, toques y gamepads

engine/src/input.ts lee las acciones del manifiesto a través de starhermit:input:

  • value(action) devuelve hasta qué punto se mantiene una acción (el movimiento es value("up") - value("down")). onAction Ofrece bordes de presión y liberación.
  • Usos de la apariencia del mouse requestPointerLock, onPointerDelta y onPointerLockChange. la cámara El joystick derecho proviene de gamepads(), y vibrate da un tic háptico corto.
  • En pantallas táctiles (primaryPointer() es grueso), setTouchControls muestra un joystick y Botones DISPARAR/PASAR/ENTRAR dibujados por el tiempo de ejecución. Los botones están vinculados a las mismas acciones:
setTouchControls([
  { kind: "stick", up: "up", down: "down", left: "left", right: "right", anchor: "bottom-left", offset: [90, 90], radius: 66 },
  { kind: "button", action: "shoot", label: T("SHOOT").slice(0, 16), anchor: "bottom-right", offset: [66, 66], radius: 46 },
  // … PASS and TACKLE
]);

screens/controls.ts enumera la corriente bindings() y llamadas requestRebind. Luego, el tiempo de ejecución captura la nueva clave o botón.

6. Una simulación para cliente y servidor: starhermit:script

server.js es un script clásico simple sin importaciones, Date o Math.random, como sandbox de la plataforma requiere. Define dos globales:

  • globalThis.game sostiene los puntos de entrada a la plataforma (createSession, onPlayerMessage, onTick) y declaraciones estáticas leídas en el momento de la publicación:

    globalThis.game = {
  tickRateHz: 30,
  replays: true,
  achievements: [
    { key: 'debut', name: 'Debut', description: 'Finish your first match.', points: 10 },
    { key: 'hat-trick', name: 'Hat-Trick', description: 'Score three goals in one match.', points: 50 },
    // …
  ],
  createSession: function (ctx) { /* seats, AI, seed from ctx.random */ },
  // …
};

  • globalThis.FootballSim tiene la misma simulación (createMatch, stepMatch, la IA) para el cliente.

El cliente carga el mismo archivo en su propio dominio con loadClassic de starhermit:script (engine/src/sim.ts):

import { loadClassic } from "starhermit:script";

loadClassic("server.js");
const S = (globalThis as unknown as { FootballSim?: FootballSimApi }).FootballSim;

Pasos de práctica sin conexión FootballSim localmente a 60 Hz con IA en cada dos asientos. En línea, el carreras de plataforma server.js autoritariamente a 30 Hz. El juego nunca mantiene dos copias de su reglas.

7. Partidos online: salas y enchufes de juego

Los lobbys utilizan las salas de la plataforma a través de starhermit:platform (screens/lobby.ts):

import * as P from "starhermit:platform";

// Quick play: join any open room, or open one.
let room = await P.rooms.quickJoin();
if (!room) {
  room = await P.rooms.create({ teamCount: 2, seatsPerTeam: teamSize, backfillAfterSeconds: 30, metadata: { game: "football" } });
  room = await P.rooms.open(room.id);
}

// Ranked solo vs AI: every other seat is an AI player, so starting begins the match at once.
room = await P.rooms.create({ teamCount: 2, seatsPerTeam: teamSize, backfillAfterSeconds: 30, aiPlayers: 2 * teamSize - 1, metadata: { game: "football" } });
room = await P.rooms.start(room.id);

Amigos, invitaciones y cambios de asiento pasan P.friends.list, P.rooms.invite, P.rooms.acceptInvite y P.rooms.seat. P.rooms.mine permite que un jugador se reincorpore a una partida que abandonó.

Una vez que comience el partido, engine/src/net.ts abre la ranura del juego con P.connectGame(sessionId):

  • Envía entradas a 30 Hz con sendInput.
  • Solicita una instantánea completa con sendCommand({ type: "sync" }) en cada apertura y en resumed.
  • escucha por game (instantáneas y eventos), achievement y stopped. stopped informa por qué el socket se detuvo: se cerró sesión, se actualizaron los términos o la coincidencia desapareció.

El tiempo de ejecución conserva las credenciales del jugador y se vuelve a conectar por sí solo, por lo que el juego no maneja tokens. y no tiene bucle de reintento.

logic/interp.ts suaviza las instantáneas del servidor con interpolación adaptativa. logic/predict.ts predice el movimiento del futbolista local y lo corrige hacia cada instantánea. La predicción afecta sólo lo que se dibuja; el servidor sigue teniendo autoridad.

8. El resto de la plataforma

Característica llamadas Fuente
Jugador registrado, inicio de sesión, fin de sesión P.player(), P.onPlayerChange, P.requestSignIn, P.onSessionEnded platform.ts, main.ts
Tabla de clasificación P.leaderboards.list, P.leaderboards.entries (junta declarada en leaderboards.json) screens/leaderboard.ts
Logros Declarado en server.js, otorgado a tiempo completo, cotizado con P.achievements.list screens/achievements.ts
Repeticiones game.replays: true en server.js; P.replays.list, P.replays.get screens/replays.ts, replayView.ts
Chat de texto P.sessions.get (la conversación del partido), P.chat.messages, P.chat.subscribe, P.chat.post chat.ts
chat de voz P.voice.join, P.voice.setVolume y P.voice.setPan por la distancia entre futbolistas, P.voice.setMuted voice.ts
Enlaces de invitación P.inviteLink y clipboard de starhermit:engine platform.ts
Informes de errores P.reportBug screens/settings.ts

Cada llamada puede rechazar con un PlatformError. El fútbol trata las funciones online como el mejor esfuerzo: el fracaso muestra "en línea no disponible" o vuelve a quedarse en silencio y nunca termina el juego. Cerrado sesión, el juego todavía ofrece práctica sin conexión.

9. Menús y HUD: starhermit:ui, starhermit:draw, starhermit:canvas

  • Menús (screens/*.ts, el menú del partido y los cuadros de diálogo en main.ts) usar starhermit:ui, la interfaz de usuario en modo inmediato del motor. Los widgets se llaman cada marco de onRender, y ui.setTheme les da los colores del juego. Las opciones propias del tiempo de ejecución El menú se abre con openMenu.
  • El HUD ( hud.ts) Dibuja el marcador, el reloj y los marcadores con starhermit:draw: draw.roundRect, draw.text y draw.image (un lienzo de cresta), en orden de llamada sobre la escena.
  • Imágenes están cargados con createImageBitmap de starhermit:canvas, por ejemplo, el arte clave del menú.

10. Configuraciones e idiomas: starhermit:storage, cuerdas

  • Las configuraciones por jugador (silencio, voz, idioma, anulaciones de gráficos) se encuentran en settings de starhermit:storage. Se guardan en el dispositivo y en la cuenta. settings.onChange aplica un cambio realizado en otro dispositivo.
  • i18n.ts cargas assets/strings.json en el motor strings mesas (strings.load, strings.t, strings.setLanguage). Elige el idioma de la elección guardada, luego el del jugador. idioma StarHermit, luego el dispositivo (preferences). l10n/font.ts carga fuentes script con FontFace para idiomas que los necesitan.

11. Niveles de sonido y gráficos.

  • audio.ts construye un gráfico de audio web con starhermit:audio:
    • Los clips creados se enumeran en sfx/manifest.json (leer con files.readJson).
    • Un sintetizador cubre cualquier evento sin clip, además de la reverberación del público y del estadio.
    • Los nodos de corta duración se liberan tan pronto como finalizan, porque el gráfico del host está limitado.
  • quality.ts sigue el nivel de gráficos del jugador (frame().level, levelSettings). Sombras, florecer y el suavizado sigue ese nivel. El contenido propio del juego (detalles del campo, densidad de público, partículas) tiene anulaciones por jugador en la parte superior.

12. Empaquetar, probar y publicar

  • Verificación de tipo con tsc -p engine. engine/tsconfig.json incluye el lanzamiento starhermit.d.ts y conjuntos "lib": ["ES2022"], "types": [] y "allowImportingTsExtensions": true.
  • Prueba. npm test corre server.js pruebas de regresión. engine/tests/run.sh ejecuta la lógica pruebas (interpolación, predicción, pose, lobby) en Node. starhermit <folder> --check valida el paquete y reproduce 120 fotogramas sin cabeza.
  • Paquete. starhermit package --web . reescribe index.html y starhermit-files.json, que se comprometen con cada cambio.
  • Publicar. El juego se agrega a StarHermit desde la URL de su repositorio. La plataforma lee starhermit.txt, corre server.js como guión del partido y crea la tabla de clasificación a partir de leaderboards.json.

Para mover Football, o tu propio juego, al motor 1.40.0:

  1. Descargue el tiempo de ejecución 1.40.0.
  2. Colocar engine.version=1.40.0.
  3. Ejecute las comprobaciones y empaquete nuevamente.

Aumentar engine.minor a 40 solo cuando desea alojar API 1.40 nuevas características.
