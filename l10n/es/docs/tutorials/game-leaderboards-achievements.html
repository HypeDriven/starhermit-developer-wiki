Tutorial: tablas de clasificación y logros para tu juego

Si tienes un juego en StarHermit, eres su editor. puedes darle tablas de clasificación (puntuación alta, carrera más rápida, racha más larga) y logros sin una cuenta de editor ni ningún tipo de especial permiso. Ser dueño del juego es todo lo que necesitas.

Hay una regla detrás de todo en esta página: tú los defines, el servidor de tu juego escribe ellos. El cliente de un jugador nunca puede publicar una puntuación ni reclamar un logro por estos, y su servidor debe validar el juego que los otorga. Rechazar envíos directos de API por sí solo no impide que un cliente modificado invente eventos de juego. Es por eso que el juego necesita un backend autorizado: un server= guión o un container.image= en starhermit.txt.

Este tutorial construye tanto para un pequeño juego arcade, Coleccionista de estrellas: una carrera termina cuando el jugador se bloquea y tiene un total de puntos y un tiempo de ejecución.

Antes de empezar

Necesitas:

  • Un juego con un servidor backend. que posee: uno que agregó desde su propio repositorio, subido como una carpeta, o reclamado. Un juego solo para navegador responde 409 a cada llamada a continuación, con un mensaje que dice por qué.
  • Un token de acceso de usuario completo, no el token de inicio de un juego. Las fichas de lanzamiento están cercadas al juego. superficie del jugador y no puede alcanzar /me/....
  • La identificación de tu juego. (también es su <id>.starhermit.com DIRECCIÓN):
ACCESS_TOKEN='your-full-user-access-token'
API=https://api.starhermit.com

curl -s "$API/api/v1/me/github-games" -H "Authorization: Bearer $ACCESS_TOKEN" |
  jq '.[] | {id, displayName, gameSlug}'

GAME_ID='the-id-from-above'

gameSlug es como tu cliente llama el juego /api/v1/games/{slug}/.... Cada juego que agregaste o subido tiene uno, juegos solo para navegador incluidos, por lo que no te dice si hay un servidor: GET /api/v1/games/{slug} lo hace - responde 404 hasta que el juego tenga un backend.

1. Crea las tablas de clasificación

Star Collector obtiene dos tableros: la mayor cantidad de puntos (cuanto más alto, mejor) y la carrera más rápida hasta los 100 puntos (más bajo). es mejor).

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/leaderboards" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "high-score", "name": "High score",
        "scoreType": "integer", "sortDirection": "desc",
        "minScore": 0, "maxScore": 1000000 }'

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/leaderboards" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "fastest-100", "name": "Fastest to 100",
        "scoreType": "time-ms", "sortDirection": "asc" }'

Cada llamada regresa 201 y la junta directiva, incluidos sus id y key. Su servidor utiliza el llave, así que elígelo con cuidado. La clave, scoreType y sortDirection no se puede cambiar más tarde.

scoreType Acepta
integer numeros enteros
decimal cualquier numero
time-ms milisegundos enteros no negativos

Colocar minScore/maxScore a lo que tu juego realmente puede producir. Se cae una puntuación fuera de ellos, que es una protección barata contra un error en la lógica de su propio servidor.

2. Crea los logros

Puedes otorgar logros a un juego de dos maneras y puedes usar ambas a la vez:

Declarado en código Creado a través de la API
Dónde game.achievements en su guión, o /describe en tu contenedor POST /me/github-games/{id}/achievements
Cambiado por publicando una actualización una llamada API, que entra en vigor inmediatamente
Bueno para los logros en torno a los cuales se construye su código agregar o reformular algunos sin autorización

Ambos tipos se desbloquean de la misma manera: su servidor devuelve la clave. Aquí creamos dos a través la API:

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "century", "name": "Century",
        "description": "Collect 100 stars in one run.", "points": 10 }'

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "untouchable", "name": "Untouchable",
        "description": "Reach 500 points without losing a shield.",
        "points": 50, "secret": true }'

A secret El logro permanece oculto para los jugadores hasta que lo hayan desbloqueado.

Para ver todo lo que tiene el juego, incluidos los logros que declara tu código, enuméralos:

curl -s "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" | jq '.[] | {key, origin, unlocks}'

origin es declared para los logros de su código y owner por los logros que creaste aquí. Sólo puedes editar y eliminar owner unos. A declared uno sería devuelto por el próximo actualizar, por lo que la API se niega (409) y en su lugar lo cambias en el código.

3. Publica puntuaciones y desbloquea logros desde tu guión.

Su secuencia de comandos informa ambos tipos de resultados en su valor de retorno. Puede hacer esto desde cualquier gancho: createSession, onPlayerMessage o onTick.

  • scores: clave del tablero → identificación del jugador → número.
  • achievements: ID del jugador → claves para desbloquear.
'use strict';

function endRun(ctx, s, playerId) {
  var run = s.runs[playerId];
  var scores = { "high-score": {} };
  scores["high-score"][playerId] = run.points;
  if (run.reached100At) {
    scores["fastest-100"] = {};
    scores["fastest-100"][playerId] = run.reached100At - run.startedAt;
  }

  var unlocked = [];
  if (run.stars >= 100) unlocked.push("century");
  if (run.points >= 500 && !run.lostShield) unlocked.push("untouchable");
  var achievements = {};
  achievements[playerId] = unlocked;

  run.over = true;
  return {
    ok: true,
    sessionState: s,
    scores: scores,
    achievements: achievements,
    broadcast: [{ to: [playerId], data: { type: "run-over", points: run.points } }]
  };
}

globalThis.game = {
  tickRateHz: 10,

  createSession(ctx) {
    var runs = {};
    ctx.players.forEach(function (p) {
      runs[p.id] = { points: 0, stars: 0, lostShield: false, startedAt: ctx.now,
                     reached100At: null, over: false };
    });
    return { ok: true, sessionState: { runs: runs } };
  },

  onPlayerMessage(ctx) {
    var s = ctx.sessionState;
    var from = ctx.message.from;
    var run = s.runs[from];
    var msg = ctx.message.data || {};
    if (!run || run.over) return { ok: false, error: "No run in progress" };

    // The client reports what happened; the script decides what it is worth.
    if (msg.type === "collect") {
      run.stars += 1;
      run.points += 5;
      if (run.points >= 100 && !run.reached100At) run.reached100At = ctx.now;
      return { ok: true, sessionState: s };
    }
    if (msg.type === "shield-lost") {
      run.lostShield = true;
      return { ok: true, sessionState: s };
    }
    if (msg.type === "crash") return endRun(ctx, s, from);
    return { ok: false, error: "Unknown command" };
  },

  onTick(ctx) { return { ok: true }; }
};

Cosas que haces no necesidad de manejar:

  • Peores puntuaciones. Cada jugador mantiene su mejor puntuación en cada tablero, juzgada por la puntuación del tablero. sortDirection. Informe cada ejecución y la plataforma se quedará con lo mejor.
  • Repetir desbloqueos. Desbloquear algo que un jugador ya tiene no hace nada, así que devuelve la clave. siempre que se cumpla la condición.
  • La identificación de cualquier otra persona. Puntuaciones y desbloqueos para personas que no están en la sesión, incluida la IA asiento, son ignorados.

Las claves desconocidas, los tableros inactivos y las puntuaciones fuera de rango se eliminan silenciosamente. Tu guión no recibe error para ellos, así que revise sus tableros una vez, como en sección 4.

En un juego real, el servidor debería calcular los puntos y tiempos desde su propio estado autoritativo, no confianza collect mensajes tal como son. Este ejemplo es breve para mostrar los informes. Guiones de juego tiene el contrato completo en forma de retorno.

3b. Lo mismo de un contenedor.

Un juego contenedor envía las mismas dos cosas en su WebSocket de control:

{ "type": "scores", "sessionId": "…",
  "scores": { "high-score": { "<userId>": 740 }, "fastest-100": { "<userId>": 41250 } } }

{ "type": "achievements", "sessionId": "…",
  "unlocks": { "<userId>": ["century"] } }

scores También se puede incluir en cualquier sobre de respuesta que su contenedor devuelva. /sessions. el Se aplican las mismas reglas: solo participantes, se mantiene la mejor puntuación, se ignoran las claves desconocidas. Ver Servidores de juegos en contenedores.

4. Muéstralos en tu juego

Su cliente lee todo con el token de lanzamiento que ya posee. Nada aquí necesita el ficha del propietario.

Encuentra las tablas.

const boards = await api(`/api/v1/games/${slug}/leaderboards`);
// [{ id, key: "high-score", name: "High score", sortDirection: "desc", ... }, ...]
const high = boards.find(b => b.key === "high-score");

Sólo se enumeran los tableros activos.

Leer un tablero.

const page = await api(`/api/v1/leaderboards/${high.id}/entries?page=1&pageSize=10`);
// { items: [{ rank, username, score, ... }], total, page, pageSize }
const friends = await api(`/api/v1/leaderboards/${high.id}/entries?friendsOnly=true&pageSize=10`);

por un time-ms tablero, formatee la partitura como un tiempo: 41250 → 0:41.25.

Logros.

  • GET /api/v1/games/{slug}/achievements enumera cada logro con el del jugador unlocked estado. Los secretos permanecen ocultos hasta que se obtienen.
  • El desbloqueo llega en vivo ws/v1/games como {"type":"achievement","data":{key,name,description,points,...}}. Muestre un brindis cuando lo haga. La llamada de lista al cargar detecta cualquier cosa desbloqueada mientras el socket estaba cerrado.

Ver Logros para el marco.

5. Cuídalos

Cambie el nombre de un tablero o cambie sus límites.

curl -s -X PUT "$API/api/v1/me/github-games/$GAME_ID/leaderboards/$BOARD_ID" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "name": "All-time high score", "maxScore": 2000000 }'

Los nuevos límites se aplican únicamente a las nuevas puntuaciones.

Retire un tablero pero mantenga sus puntuaciones. Enviar { "isActive": false }. La junta deja de aceptar anota y desaparece de la lista del juego. Sus entradas aún se pueden leer por id.

Reiniciar según un cronograma. dar una tabla "resetSchedule": "daily", "weekly" o "monthly" (en crear, o más tarde con PUT) y comienza de nuevo a las 00:00 UTC en cada período, perfecto para un "esto lo mejor de la semana" tablero al lado de uno de todos los tiempos. No hay nada que hacer en tu guión: informa las puntuaciones como de costumbre y Cuenta la primera puntuación de cada jugador en un nuevo período. Ver Restablecer horarios.

Comienza una nueva temporada a mano. Para una temporada única en lugar de un calendario, cree un nuevo tablero (high-score-s2), apunte su script hacia él y retire el anterior.

Eliminar un tablero. DELETE .../leaderboards/{id} elimina el tablero y todas sus entradas, y no se puede deshacer.

Editar un logro. PUT .../achievements/{achievementId} con cualquiera de name, description, icon, secret y points. La clave nunca cambia.

Eliminar un logro. Esto funciona solo para uno que creaste y que nadie ha desbloqueado todavía. Los logros obtenidos son permanentes.

Mueve un logro al código. Declarar la misma clave en game.achievements y publicar. el La declaración se hace cargo del logro existente y los jugadores que lo tienen lo conservan.

Respuesta Significado
404 El juego no es tuyo, o el tablero o logro no le pertenece
409 "…servidor backend…" El juego no tiene server= o container.image=
409 "ya tiene…" La clave se toma, por un tablero o por un logro declarado o creado.
409 "declarado por el servidor del juego" Cambia ese logro en tu código
409 "ya desbloqueado" Los jugadores lo conservan, por lo que no se puede eliminar.
400 Una clave con otros caracteres, un nombre faltante o minScore > maxScore

Límites: 2048 tablas de clasificación y 200 logros creados por juego, más hasta 100 declarados.

Lista de verificación

  • [ ] El juego tiene un server= guión o container.image=, y gameSlug está ambientado en GET /me/github-games.
  • [ ] Cada tablero tiene una llave estable y el derecho scoreType y sortDirection (No pueden cambiar más tarde).
  • [ ] El servidor regresa scores y achievements (script) o envía los mensajes de control (contenedor), elaborados desde el estado autoritativo.
  • [ ] El cliente encuentra tableros con GET /games/{slug}/leaderboards, nunca codifica sus identificaciones y lee las entradas por identificación.
  • [ ] El cliente carga GET /games/{slug}/achievements y muestra un brindis en el achievement marco.
  • [ ] Los tableros viejos se retiran con isActive: false en lugar de eliminarlas, a menos que realmente quieras que desaparezcan las puntuaciones.
