Cargue y guarde el progreso de forma segura

Utilice los guardados en la nube para el progreso propiedad del cliente de un jugador que haya iniciado sesión. La opción para un jugador sin firmar mantiene el progreso en la memoria y no lee ni escribe los guardados de la cuenta. Las preferencias pertenecen a configuración del juego, no el documento de progreso.

Un token de lanzamiento puede acceder exactamente game:<gameId>, dónde gameId es su game_scope. la plataforma almacena bytes opacos, con un guardado por ranura. Valida el formato que espera tu juego. Ver Guardados en la nube para cuotas y encabezados condicionales.

Una pequeña receta JSON completa

Copiar cloud-save-store.js en tu construcción. Este ejemplo almacena raw UTF-8 bytes JSON; la plataforma les sirve con application/zip pero no requiere un formato ZIP. Utilice un lector diferente para guardar archivos ZIP, incluido el El ZIP del SDK del navegador guarda. No cambie formatos sin un plan de migración para los reproductores existentes.

import { CloudSaveStore } from './cloud-save-store.js';

const store = new CloudSaveStore({
  gameId: StarHermit.slug,
  token: () => StarHermit.token, // Always obtain the current renewed token.
});
const valid = value => value?.version === 1 && Number.isSafeInteger(value.points) && value.points >= 0;
let progress = { version: 1, points: 0 };
let saving = false;

async function startAccountGame() {
  // Keep gameplay/saving disabled until this resolves.
  const remote = await store.load(valid);
  progress = remote ?? { version: 1, points: 0 };
  render(progress);
}

async function saveCheckpoint() {
  if (saving) return; // Coalesce checkpoints; do not issue overlapping writes.
  saving = true;
  showSync('Saving…');
  try {
    await store.save(progress);
    showSync('Saved');
  } catch (error) {
    if (error.status === 412) {
      // Keep local progress in memory. Offer Reload cloud or an explicit merge.
      showConflict(() => startAccountGame());
    } else showSync('Save failed; retry after resolving the error');
  } finally {
    saving = false;
  }
}

render, showSync, y showConflict son su interfaz de usuario. Esperar startAccountGame() antes de habilitar jugar o guardar. En caso de falla de carga, conserva el estado local actual del reproductor, muestra la falla, y mantener las cargas bloqueadas. A 404 es el caso de la ranura vacía; 401, 403, 5xx, JSON con formato incorrecto, o una versión guardada no compatible no son espacios vacíos.

La receta no renueva las credenciales. El SDK del navegador renueva los tokens de lanzamiento mientras permanecen válido. Resuelva los términos pendientes o vuelva a autenticarse a través del flujo de entrada del juego antes de volver a intentar una lectura.

Condiciones y conflictos

que fue cargado Encabezado en la siguiente escritura Si otro dispositivo escribe
Guardar existente con ETag If-Match: <etag> 412 precondition_failed
Sin guardar (404) If-None-Match: * 412 precondition_failed
Nada se cargó correctamente no escribir Sigue reintentando la lectura o deja que el reproductor permanezca en reproducción sin seguimiento

Utilice la versión del datos que cargaste, no una verificación posterior de metadatos. Conservar la nueva ETag devuelta por cada escritura exitosa. A 412 bloquea más guardados hasta que el juego carga la versión actual y el jugador lo adopta o lo fusiona. No elimine silenciosamente la condición y sobrescriba otro dispositivo. La API no ofrece un historial de guardado para deshacer esa sobrescritura.

Si dos dispositivos deben actualizar contadores o inventario de forma independiente, un único documento que se escribe en último lugar gana Puede que no se ajuste al juego. Utilice el estado autorizado del servidor y defina en su lugar comandos de juego validados.

Guardar formato y migración

Incluya una versión de formato y valide tipos, rangos y campos obligatorios antes de adoptar control remoto. progreso. Escriba una migración para versiones anteriores compatibles. Mantenga intacta una versión desconocida más nueva; no lo restablezca a los valores predeterminados ni lo cargue sobre él. Los datos de la nube están controlados por el cliente, así que nunca los trate como prueba de una puntuación competitiva o de un derecho remunerado.

El límite predeterminado para guardar archivos decodificados es 10 MiB. Base64 agrega aproximadamente un tercio al cuerpo de la solicitud. 413 cloud_save_too_large, 409 cloud_save_slots_exhausted, y 507 cloud_save_quota_exceeded son diferentes fallas de capacidad; inspeccionar code y limit. Honor Retry-After en 429.

Puntos de control y salida de página.

Guarde en puntos de control significativos y ofrezca una acción de guardar visible. Antirrebote de cambios rápidos y serialización escribe para que cada uno use la última versión reconocida. Mantenga un indicador sucio hasta que se reconozca. Una solicitud fallida no es un guardado confirmado; después de una escritura ambigua, recarga antes de otra escritura.

Una carga al salir de la página es el mejor esfuerzo. Navegador fetch(..., { keepalive: true }) comparte un pequeño vuelo asignación corporal, comúnmente 64 KiB; un ahorro de 10 MiB no puede depender de ello. Una pestaña puede cerrarse antes de cualquier solicitud. acabados. Utilice guardados de primer plano normales para mayor durabilidad y no etiquete el progreso no reconocido como salvado. El inicio rápido guarda su pequeño documento en cada punto de colección.

Verifica en tu juego

  1. Comience con una ranura vacía; recopile el progreso, guarde, vuelva a cargar y confirme que regresa.
  2. Rechazar lecturas con un error de red, 403, o datos no válidos; Confirme que no se realiza ninguna carga.
  3. Abra dos pestañas en una versión. Salvo en A, luego B: B debe sacar a la luz un conflicto y preservar su estado local.
  4. Pruebe un formato más antiguo o más nuevo y una confirmación faltante sin sobrescribir datos desconocidos.
  5. Ingrese al modo para un jugador sin seguimiento y verifique que el juego no realice solicitudes de guardado en la nube.
