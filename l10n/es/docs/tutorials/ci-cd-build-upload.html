Cargue compilaciones desde CI/CD con una clave pública inscrita en OAuth

Este tutorial proporciona a un canal de implementación su propia credencial StarHermit sin almacenar su Google o tokens GitHub OAuth en CI. La configuración única es interactiva:

  1. Inicie sesión a través de OAuth y acepte los términos actuales de StarHermit.
  2. Agregue una clave pública dedicada a su cuenta StarHermit.
  3. Coloque solo la mitad privada de esa clave en el almacén secreto de CI.

Luego, cada recorrido del oleoducto firma un desafío StarHermit de corta duración, recibe un tiempo normal de 15 minutos. token de acceso y carga la nueva compilación. La clave de canalización actúa como su cuenta y solo puede actualizarse juegos que posee la cuenta.

¿Por qué utilizar una clave de implementación independiente?

No guarde un token de actualización o acceso de OAuth en CI. Una clave pública de StarHermit es una máquina mejor credencial porque puede etiquetarse, auditarse y revocarse de forma independiente. Una sesión autenticada por esa llave No se pueden agregar claves ni revocar otras claves.; esas operaciones requieren una autenticación OAuth sesión. Puede revocarse mediante /api/v1/me/public-keys/current. Si se filtra el secreto de CI, inicie sesión con Google o GitHub y revoque la clave de implementación. La revocación también finaliza las sesiones de actualización creadas por esa clave y hace que sus tokens de acceso existentes fallen. en su próxima solicitud de API.

Utilice una clave por repositorio/entorno, por ejemplo orbit-league-production, en lugar de compartir una clave privada entre cada flujo de trabajo.

Requisitos previos

  • Una cuenta de StarHermit iniciada a través de Google o GitHub OAuth.
  • Un juego existente propiedad de esa cuenta. guardar su id como GAME_ID; el punto final del paquete actualiza un juego pero no crea uno.
  • Una compilación de cliente distribuible y/o compatible con Docker docker save imagen. Ver Juegos de GitHub para el diseño del archivo.
  • Python 3 para los comandos de configuración y el flujo de trabajo de ejemplo; curl y jq para el ejemplo de inscripción.

Una canalización puede iniciar sesión correctamente y seguir recibiendo 403 terms_acceptance_required cuando carga o abre un socket de carga. Haga que el propietario de la cuenta revise y aceptar los términos actuales interactivamente y luego vuelva a ejecutar el trabajo. Esto puede repetirse cuando cambian los términos; no aceptar automáticamente términos de CI.

Configuración única

1. Genere una clave de implementación localmente

El ejemplo utiliza Ed25519. Ejecute esto en una estación de trabajo confiable, no en el trabajo de CI:

python -m pip install cryptography
python - <<'PY'
import base64
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
from cryptography.hazmat.primitives.serialization import Encoding, NoEncryption, PrivateFormat, PublicFormat

key = Ed25519PrivateKey.generate()
private = key.private_bytes(Encoding.Raw, PrivateFormat.Raw, NoEncryption())
public = key.public_key().public_bytes(Encoding.Raw, PublicFormat.Raw)
print("STARHERMIT_PRIVATE_KEY=" + base64.b64encode(private).decode())
print("STARHERMIT_PUBLIC_KEY=" + base64.b64encode(public).decode())
PY

El valor privado es la semilla de 32 bytes y se muestra una vez en esta terminal local confiable. nunca te comprometas imprimirlo, imprimirlo en registros de CI, colocarlo en un artefacto o enviarlo a StarHermit. Mantener el valor público para el siguiente paso y para la variable de flujo de trabajo.

2. Inicie sesión con OAuth y agregue la clave pública.

Abra una de estas URL en un navegador:

https://api.starhermit.com/api/v1/auth/oauth/github/authorize
https://api.starhermit.com/api/v1/auth/oauth/google/authorize

Después de la devolución de llamada, utilice inmediatamente el token de acceso autenticado por OAuth devuelto. ponlo en un local variable de entorno en lugar de en el historial del shell:

read -rsp 'OAuth access token: ' OAUTH_ACCESS_TOKEN; echo
read -rp  'Public key: ' STARHERMIT_PUBLIC_KEY

curl -sS -X POST https://api.starhermit.com/api/v1/me/public-keys \
  -H "Authorization: Bearer $OAUTH_ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  --data "$(jq -n \
    --arg keyData "$STARHERMIT_PUBLIC_KEY" \
    --arg label 'orbit-league-production' \
    '{keyType:"Ed25519", keyData:$keyData, label:$label}')"

La llamada regresa 201 y el registro clave. A 403 significa que este token no proviene de OAuth sesión (una verificación por correo electrónico, una clave pública o un token de inicio de juego no es suficiente). A 409 significa el La clave ya está activa o la cuenta ha alcanzado su límite de claves activas.

Comprueba el resultado con GET /api/v1/me/public-keys. La lista incluye etiquetas, huellas dactilares, último uso. veces y claves revocadas, por lo que también es el registro de auditoría de credenciales.

3. Configurar el repositorio

En GitHub, agregue:

  • Acciones secretas STARHERMIT_PRIVATE_KEY: la semilla privada Base64.
  • Variables de acciones STARHERMIT_PUBLIC_KEY: la clave pública sin formato Base64.
  • Variables de acciones STARHERMIT_GAME_ID: ID del juego de propiedad.

Proteja la producción con un entorno GitHub si se requiere aprobación. Los valores equivalentes pueden ser almacenado en variables protegidas de GitLab, Azure Key Vault o cualquier otro almacén secreto de CI.

Agregar el asistente de autenticación/carga

cometa lo siguiente como ci/starhermit_upload.py. Reconstruye el desafío JSON exacto que StarHermit firma internamente, se autentica con Ed25519 y elige HTTP para archivos pequeños o el suba WebSocket para archivos de más de 90 MB. WebSocket evita el cuerpo HTTP de aproximadamente 100 MB de la CDN límite.

#!/usr/bin/env python3
import argparse, asyncio, base64, json, os
from pathlib import Path
from urllib.parse import quote, urlparse, urlunparse

import requests
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey


def authenticate(api, public_key, private_key):
    challenge = requests.post(
        f"{api}/api/v1/auth/public-key/challenge",
        json={"keyType": "Ed25519", "keyData": public_key}, timeout=30)
    challenge.raise_for_status()
    body = challenge.json()
    p = body["payload"]

    # Public JSON is camelCase; the server verifies its ChallengePayload serialization, whose
    # property names and order are the PascalCase sequence below.
    payload = {
        "ChallengeId": p["challengeId"],
        "Fingerprint": p["fingerprint"],
        "Issuer": p["issuer"],
        "Audience": p["audience"],
        "Expiry": p["expiry"],
        "Nonce": p["nonce"],
        "ClientTimestamp": p["clientTimestamp"],
    }
    # System.Text.Json escapes '+' in string fields (the Base64 nonce) as \u002B.
    # DateTimeOffset fields keep literal '+' in their offsets: do not replace globally.
    fields = []
    for name, value in payload.items():
        encoded = json.dumps(value)
        if name == "Nonce":
            encoded = encoded.replace("+", r"\u002B")
        fields.append(json.dumps(name) + ":" + encoded)
    signed_payload = ("{" + ",".join(fields) + "}").encode("utf-8")

    seed = base64.b64decode(private_key, validate=True)
    signature = Ed25519PrivateKey.from_private_bytes(seed).sign(signed_payload)
    complete = requests.post(
        f"{api}/api/v1/auth/public-key/complete",
        json={"challengeId": body["challengeId"],
              "signature": base64.b64encode(signature).decode(),
              "keyType": "Ed25519", "keyData": public_key}, timeout=30)
    complete.raise_for_status()
    return complete.json()["accessToken"]


def upload_http(api, game_id, token, archive, mode):
    with archive.open("rb") as stream:
        response = requests.post(
            f"{api}/api/v1/me/github-games/{game_id}/bundle",
            params={"mode": mode} if mode != "replace" else None,
            headers={"Authorization": f"Bearer {token}",
                     "Content-Type": "application/gzip"},
            data=stream, timeout=1800)
    response.raise_for_status()
    print(json.dumps(response.json()))


async def upload_websocket(api, game_id, token, archive, mode):
    import websockets
    parsed = urlparse(api)
    query = f"gameId={quote(game_id)}&access_token={quote(token)}"
    if mode != "replace":
        query += f"&mode={quote(mode)}"
    uri = urlunparse(("wss" if parsed.scheme == "https" else "ws", parsed.netloc,
                      "/ws/v1/game-upload", "", query, ""))
    async with websockets.connect(uri, max_size=None, ping_interval=20) as ws:
        ready = json.loads(await ws.recv())
        if ready.get("type") != "ready":
            raise RuntimeError(ready)
        with archive.open("rb") as stream:
            while chunk := stream.read(512 * 1024):
                await ws.send(chunk)
        await ws.send(json.dumps({"type": "complete"}))
        while True:
            message = json.loads(await ws.recv())
            if message.get("type") == "result":
                print(json.dumps(message))
                return
            if message.get("type") == "error":
                raise RuntimeError(message)


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("archive", type=Path)
    parser.add_argument("--api", default="https://api.starhermit.com")
    parser.add_argument("--mode", choices=("replace", "merge"), default="replace",
                        help="replace the live client files (default) or patch them")
    args = parser.parse_args()
    game_id = os.environ["STARHERMIT_GAME_ID"]
    token = authenticate(args.api.rstrip("/"), os.environ["STARHERMIT_PUBLIC_KEY"],
                         os.environ["STARHERMIT_PRIVATE_KEY"])
    if args.archive.stat().st_size < 90 * 1024 * 1024:
        upload_http(args.api.rstrip("/"), game_id, token, args.archive, args.mode)
    else:
        asyncio.run(upload_websocket(args.api.rstrip("/"), game_id, token, args.archive, args.mode))


if __name__ == "__main__":
    main()

Trate una salida distinta de cero como una implementación fallida. No registre el token de acceso ni el cuerpo completo de la solicitud. El token de acceso dura 15 minutos, así que autentíquese inmediatamente antes de cargarlo; el WebSocket lo verifica durante el protocolo de enlace y puede finalizar después de que caduque el token.

Ejemplo de acciones de GitHub

Este ejemplo publica el contenido de dist/ en cada empujón hacia main:

{% crudo %}

name: Deploy to StarHermit
on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'

      - name: Build
        run: |
          npm ci
          npm run build

      - name: Package StarHermit bundle
        run: |
          mkdir -p bundle/client
          cp -R dist/. bundle/client/
          cp starhermit.txt bundle/starhermit.txt
          tar -C bundle -czf game-bundle.tar.gz .

      - name: Install uploader dependencies
        run: python -m pip install 'cryptography>=42,<45' 'requests>=2.31,<3' 'websockets>=12,<13'

      - name: Upload build
        env:
          STARHERMIT_PRIVATE_KEY: ${{ secrets.STARHERMIT_PRIVATE_KEY }}
          STARHERMIT_PUBLIC_KEY: ${{ vars.STARHERMIT_PUBLIC_KEY }}
          STARHERMIT_GAME_ID: ${{ vars.STARHERMIT_GAME_ID }}
        run: python ci/starhermit_upload.py game-bundle.tar.gz

Para un servidor dedicado, agregue docker build, guarde la imagen en bundle/server/image.tary retener starhermit.txt en la raíz del paquete:

docker build -t my-game-server:${GITHUB_SHA} -f Dockerfile.server .
mkdir -p bundle/server
docker save my-game-server:${GITHUB_SHA} -o bundle/server/image.tar
tar -C bundle -czf game-bundle.tar.gz .

Una carga exitosa del paquete significa que StarHermit aceptó y publicó atómicamente el paquete; lo hace no significa que un nuevo contenedor haya pasado los controles sanitarios. Encuesta GET /api/v1/me/github-games/{id}/deployment con el mismo token recién autenticado y ejecute un prueba de humo antes de promover el lanzamiento.

Rotación y respuesta a incidentes.

  1. Inicie sesión a través de OAuth y acepte los términos actuales de StarHermit.
  2. Agregue una clave recién generada y claramente etiquetada.
  3. Reemplace la variable y el secreto de CI y luego ejecute una implementación.
  4. Revocar la antigua clave con DELETE /api/v1/me/public-keys/{keyId}.

Para un supuesto compromiso amplio, DELETE /api/v1/me/public-keys/all revoca cada clave activa. Ambas operaciones de eliminación requieren una sesión autenticada por OAuth. Un oleoducto autenticado por su propia La clave no puede revocar otras claves, agregar una de reemplazo, cambiar el correo electrónico de la cuenta ni eliminar una identidad de OAuth. Puede revocarse con DELETE /api/v1/me/public-keys/current; descarta sus tokens almacenados después.
