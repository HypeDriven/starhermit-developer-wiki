Tutorial: jugadores incorporados con una clave pública

Una cuenta de StarHermit no necesita Google, GitHub ni ningún otro proveedor de inicio de sesión. Su credencial puede ser un par de claves que su juego genera en el dispositivo del jugador, más una dirección de correo electrónico que el jugador confirma una vez. Después de eso, tu juego inicia sesión silenciosamente en cada lanzamiento al firmar un desafío con la clave. El jugador nunca escribe una contraseña y nunca tiene que visitar una página de StarHermit.

Este tutorial construye ese flujo de principio a fin: genera la clave, regístrala, espera a que el reproductor confirmar, iniciar sesión, mantener la sesión y gestionar segundos dispositivos y llaves perdidas.

Usa esto para Juegos nativos e independientes, lanzadores, compilaciones Steam/Epic/GOG y herramientas de escritorio. cualquier cosa que se ejecute en la máquina del jugador y pueda mantener una clave privada allí.

Usa algo más para

  • Un juego de navegador alojado en StarHermit, que ya recibe un token de lanzamiento cuando se abre desde el tablero, o puede mostrar un Botón de inicio de sesión.
  • Un canal de CI, que debería registrar una clave de una sesión de OAuth sin ningún paso de correo electrónico: Tutorial: cargar compilaciones desde CI/CD.
  • Un servidor de juegos dedicado, que tiene su propio token de implementación y no puede crear ni actuar como jugadores: Tutorial: publicar un servidor dedicado.

Lo que ve el jugador

  1. Su juego solicita una dirección de correo electrónico y su consentimiento para crear una cuenta StarHermit.
  2. Abren el correo electrónico de confirmación, hacen clic en el enlace y presionan Confirmar en la página que se abre.
  3. De vuelta en el juego, han iniciado sesión. En lanzamientos posteriores no se pregunta nada en absoluto.

Se requiere una dirección de correo electrónico y el jugador debe confirmarla una vez. No hay manera de crear un Cuenta StarHermit de forma silenciosa desde una identidad Steam, Epic o GOG únicamente.

1. Crea la clave del dispositivo

Generar un par de claves por instalación, la primera vez que tu juego necesita una cuenta. el privado La clave nunca sale del dispositivo: ni a sus servidores, ni a StarHermit.

keyType keyData (Base64 estándar) Firma (estándar Base64)
Ed25519 - recomendado La clave pública sin formato de 32 bytes La firma Ed25519 sin formato de 64 bytes
ECDSA-P256 El punto público: 65 bytes sin comprimir (04‖X‖Y) o comprimido de 33 bytes ECDSA con SHA-256, ASN.1 codificado en DER
RSA-PSS SubjectPublicKeyInfo DER, módulo de 2048 a 8192 bits, exponente ≤ 32 bits RSASSA-PSS, SHA-256, MGF1-SHA-256, sal de 32 bytes

keyData tiene como máximo 2.000 caracteres. Una clave pertenece a una cuenta en toda la plataforma.

Elegir Ed25519 a menos que su plataforma no pueda producirlo. Si utiliza ECDSA, tenga en cuenta que WebCrypto, Windows CNG y la mayoría de los almacenes de claves de hardware devuelven la firma sin formato r‖s (64 bytes). estrellaermitaño espera DER, así que conviértalo; el módulo siguiente lo hace.

// One key per installation. The private key can sign but is never exported.
export async function createDeviceKey(keyType = 'Ed25519') {
  if (!['Ed25519', 'ECDSA-P256'].includes(keyType)) throw new Error('This helper supports Ed25519 or ECDSA-P256');
  const algorithm = keyType === 'Ed25519'
    ? { name: 'Ed25519' }
    : { name: 'ECDSA', namedCurve: 'P-256' };
  const pair = await crypto.subtle.generateKey(algorithm, false, ['sign', 'verify']);
  return {
    keyType: keyType === 'Ed25519' ? 'Ed25519' : 'ECDSA-P256',
    keyData: b64(await crypto.subtle.exportKey('raw', pair.publicKey)),
    privateKey: pair.privateKey,
  };
}

Almacene la clave privada donde la proteja el sistema operativo. En un navegador o renderizador Electron, un no extraíble CryptoKey se puede mantener en IndexedDB tal como está. Un juego nativo debería usar el Almacén de claves de plataforma: Windows DPAPI o CNG, macOS Keychain, libsecret en Linux. Almacenar keyType y keyData al lado; los envías con cada solicitud.

2. Iniciar el registro

Solicite la dirección de correo electrónico y el consentimiento del jugador, luego:

async function post(path, body) {
  const res = await fetch(API + path, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  });
  return { status: res.status, body: await res.json().catch(() => ({})) };
}

function fail(step, { status, body }) {
  return Object.assign(new Error(`${step}: ${body.error ?? status}`), { status, body });
}

export async function register(key, email) {
  const res = await post('/api/v1/auth/public-key/register',
    { email, keyType: key.keyType, keyData: key.keyData });
  if (res.status !== 202) throw fail('register', res);
  return res.body; // { registrationId, email, emailSent, deferralReason, message }
}

202 significa que StarHermit aceptó el registro. Si emailSent es false, el correo electrónico está en cola y todavía llegará; deferralReason dice por qué esperó. No hay nada adjunto a ninguna cuenta todavía.

Tres reglas dan forma a tu interfaz de usuario:

  • Un registro por dirección de correo electrónico y uno por dirección IP, cada 24 horas. Un segundo intento es 429 con Retry-After. Haga que el jugador confirme la dirección antes de enviarla, ya que se puede producir un error tipográfico. les cuesta un día. Envía la solicitud desde el dispositivo del jugador, nunca a través de tu propio servidor: cada El jugador compartiría la IP de su servidor y su único registro diario.
  • El enlace caduca después de 4 horas. Si transcurre, el jugador podrá registrarse nuevamente una vez transcurridas las 24 horas. están arriba.
  • 400 significa que la dirección de correo electrónico o el material clave fueron rechazados; error dice cual.

3. Inicia sesión con la clave

Registrarse es un desafío y una respuesta. POST /api/v1/auth/public-key/challenge devuelve:

{
  "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
  "payload": {
    "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
    "fingerprint": "9c0b7a…",
    "issuer": "starhermit",
    "audience": "starhermit",
    "expiry": "2026-10-09T14:21:41.9264875+00:00",
    "nonce": "NmL+tgMum6HXU/pa3T9xjQ==",
    "clientTimestamp": "2026-10-09T14:16:41.9265739+00:00"
  },
  "expiresIn": 300
}

Lo que firma no es el JSON que recibió. StarHermit verifica la firma sobre la suya propia serialización de payload:

  • JSON compacto, sin espacios en blanco;
  • PascalCaso nombres de los miembros, exactamente en el orden ChallengeId, Fingerprint, Issuer, Audience, Expiry, Nonce, ClientTimestamp;
  • cada valor copiado exactamente como se sirve — no analizar ni reformatear las fechas;
  • cada + en el nonce escrito como \u002B. El + en las fechas se queda como está.

Para el desafío anterior, los bytes firmados son la codificación UTF-8 de:

{"ChallengeId":"4fc4d72b-4c12-41ca-a500-dc13cccc3865","Fingerprint":"9c0b7a…","Issuer":"starhermit","Audience":"starhermit","Expiry":"2026-10-09T14:21:41.9264875+00:00","Nonce":"NmL\u002BtgMum6HXU/pa3T9xjQ==","ClientTimestamp":"2026-10-09T14:16:41.9265739+00:00"}

Si se equivoca en algo de eso, la respuesta es 401 "Invalid signature.", que ningún reintento solucionará.

const FIELDS = ['challengeId', 'fingerprint', 'issuer', 'audience', 'expiry', 'nonce', 'clientTimestamp'];

export function challengeSigningBytes(payload) {
  const members = FIELDS.map((field) => {
    let value = JSON.stringify(payload[field]);
    if (field === 'nonce') value = value.replaceAll('+', '\\u002B');
    return `"${field[0].toUpperCase()}${field.slice(1)}":${value}`;
  });
  return new TextEncoder().encode(`{${members.join(',')}}`);
}

export async function signChallenge(key, payload) {
  const data = challengeSigningBytes(payload);
  if (key.keyType === 'Ed25519')
    return b64(await crypto.subtle.sign({ name: 'Ed25519' }, key.privateKey, data));
  // WebCrypto returns an ECDSA signature as raw r||s; the server expects ASN.1 DER.
  const rs = new Uint8Array(
    await crypto.subtle.sign({ name: 'ECDSA', hash: 'SHA-256' }, key.privateKey, data));
  return b64(derEcdsaSignature(rs));
}

function derEcdsaSignature(rs) {
  const integer = (bytes) => {
    let i = 0;
    while (i < bytes.length - 1 && bytes[i] === 0) i++;
    const value = [...bytes.slice(i)];
    return value[0] & 0x80 ? [0x02, value.length + 1, 0, ...value] : [0x02, value.length, ...value];
  };
  const body = [...integer(rs.slice(0, 32)), ...integer(rs.slice(32))];
  return new Uint8Array([0x30, body.length, ...body]);
}

// Resolves to { userId, accessToken, refreshToken }, or null while the key is not attached to
// an account yet — the player has not confirmed, the link expired, or the key was revoked.
export async function signIn(key) {
  const { keyType, keyData } = key;
  const challenge = await post('/api/v1/auth/public-key/challenge', { keyType, keyData });
  if (challenge.status !== 200) throw fail('challenge', challenge);
  const signature = await signChallenge(key, challenge.body.payload);
  const done = await post('/api/v1/auth/public-key/complete',
    { challengeId: challenge.body.challengeId, signature, keyType, keyData });
  if (done.status === 200) return done.body;
  if (done.status === 401 && done.body.error === 'Public key not registered or revoked.') return null;
  throw fail('complete', done); // "Invalid signature." will never succeed: fix it, don't retry it
}

Un desafío dura cinco minutos y es de un solo uso, incluso cuando el intento falla, así que solicita uno nuevo. por cada intento. Desafía y completa comparte un límite de 60 solicitudes por minuto por dirección IP.

4. Espere a que el jugador confirme.

El enlace enviado por correo electrónico abre una página de StarHermit que dice lo que hará la confirmación; al abrirlo cambia nada, por lo que un escáner de correo que obtenga una vista previa del enlace no puede confirmarlo en nombre del jugador. cuando el prensas del jugador Confirmar, StarHermit crea su cuenta, adjunta su clave y marca la dirección verificado. Si una cuenta ya usa esa dirección, la página lo dice y se le agrega la clave. en cambio, un jugador que ya tiene una cuenta StarHermit la mantiene. Luego aterrizan en starhermit.com en el panel de StarHermit, ya iniciado sesión.

Tu juego nunca recibe los tokens de esa página., y no los necesita. El jugador puede confirmar en un teléfono o en otro navegador. Una vez adjunta la clave, tu juego puede simplemente iniciar sesión con eso. Así que muestra un "revisa tu bandeja de entrada" pantalla y sigue intentando:

// Poll until the player confirms the emailed link. Two requests per attempt, so every 5 s stays
// well inside the 60-per-minute sign-in limit.
export async function waitUntilConfirmed(key, { intervalMs = 5000, signal } = {}) {
  for (;;) {
    signal?.throwIfAborted();
    const session = await signIn(key);
    if (session) return session;
    await new Promise((resolve) => setTimeout(resolve, intervalMs));
  }
}

Juntando los pasos 1 a 4:

import { createDeviceKey, register, signIn, waitUntilConfirmed } from './starhermit-key-auth.js';

const key = await loadStoredKey() ?? await saveKey(await createDeviceKey());
let session = await signIn(key);                // a returning player is signed in here
if (!session) {
  const email = await askForEmailAndConsent();
  await register(key, email);
  showCheckYourInbox(email);
  session = await waitUntilConfirmed(key, { signal: cancelButton.signal });
}

loadStoredKey, saveKey, askForEmailAndConsent y showCheckYourInbox son tuyos para escribir. Ofrecer un Cancelar eso aborta la espera y deja de sondear después de cuatro horas, cuando el enlace caduca.

Continúe encuestando incluso si la página de confirmación de su plataforma redirige a su sitio. El jugador a menudo abre el correo electrónico en un dispositivo diferente al que está esperando y luego la redirección no llega a ninguna parte cerca de tu pantalla de espera; el sondeo es lo que inicia la sesión del dispositivo en espera. Si la redirección llega en una segunda pestaña, inicia sesión solo con uno de ellos y revoca la sesión extra, o el jugador terminará con dos.

5. Mantenga la sesión

complete devuelve un token de acceso de 15 minutos y un token de actualización que dura siete días y rota. Envía el token de acceso como Authorization: Bearer …y actualice antes de que caduque:

// Resolves to the new pair, or null when the session is over — sign in with the key again.
export async function refresh(refreshToken) {
  const res = await post('/api/v1/auth/refresh', { refreshToken });
  return res.status === 200 ? res.body : null; // { accessToken, refreshToken }
}

Reemplazar ambos fichas cada vez. La presentación de un token de actualización usado finaliza toda la sesión, así que asegúrese de Asegúrese de que dos subprocesos o procesos nunca se actualicen a la vez. Cuando refresh regresa null, llamar signIn — no hay ningún correo electrónico involucrado. La clave es la credencial de larga duración; los tokens son solo un caché.

6. Termina de configurar la cuenta.

Términos. Una cuenta nueva debe aceptar los términos actuales de StarHermit antes de poder utilizar cualquier otra cosa. Llamar GET /api/v1/me. Si termsAcceptanceRequired es true, muestra el texto de GET /api/v1/terms, y cuando el jugador lo acepte, envía su hash a POST /api/v1/me/terms/accept. Vuelva a consultar en lanzamientos posteriores, porque los términos están revisados. Detalles: Aceptación de términos.

Nombre. La cuenta comienza con un pk-… nombre de usuario. Deja que el jugador elija un apodo:

PATCH /api/v1/me
Authorization: Bearer <access-token>
Content-Type: application/json

{ "nickname": "RookPilot" }

A partir de aquí la cuenta es como cualquier otra: amigos, chat, emparejamiento, guardado en la nube, logros.

7. Segundos dispositivos, llaves perdidas y límites

Un segundo dispositivo genera su propia clave y la registra con la misma dirección de correo electrónico. cuando el El jugador confirma, la clave se une a su cuenta existente en lugar de crear una nueva. las 24 horas El límite por dirección también se aplica aquí.

Un dispositivo perdido o robado. POST /api/v1/auth/public-key/revoke-request con { "email": "…" } envía por correo electrónico un enlace a una página; confirmando hay revocaciones cada clave en la cuenta y finaliza las sesiones esas claves iniciaron sesión. Abrir el enlace por sí solo no cambia nada. La solicitud siempre responde. 202 con el mismo mensaje, ya sea que el La dirección tiene una cuenta. El enlace caduca después de cuatro horas y una cuenta puede solicitarlo una vez cada 15 minutos. Luego, cada dispositivo restante se registra nuevamente (paso 2).

Lo que una cuenta de sólo clave no puede hacer. Algunos cambios protegen las credenciales de la cuenta, por lo que Requiere una sesión que haya iniciado sesión a través de un proveedor como Google o GitHub:

Acción Cuenta de solo clave
Agregue una clave o revoque otros dispositivos (POST /me/public-keys, DELETE /me/public-keys/{id} o /all) 403 — inscribirse mediante el registro enviado por correo electrónico o utilizar una sesión autenticada por OAuth
Cambiar la dirección de correo electrónico de la cuenta 403 oauth_session_required — no es posible hasta que un proveedor esté vinculado
Revocar la clave propia de esta instalación DELETE /api/v1/me/public-keys/current, utilizando su sesión completa de cuenta de clave pública; descartar las credenciales locales después del éxito

Para administrar otras credenciales o cambiar el correo electrónico, vincule un proveedor. Cuando una cuenta de solo clave vincula una, el vínculo se mantiene hasta que el jugador lo confirme desde su correo electrónico. Después de eso, un inicio de sesión de proveedor puede hacer todo lo anterior. Ver authorize?link=true.
