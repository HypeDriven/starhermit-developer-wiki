Desempenho nativo para jogos de script

Um jogo com motor StarHermit executa o mesmo pacote em navegadores e nativamente. Os dois executam seu código muito de forma diferente, então escolha onde fica o trabalho pesado antes de transferi-lo ou escrevê-lo. Esta página cobre o script velocidade, WebAssembly, cenas vinculadas a GPU, trabalhadores e medição. Os números são medições do motor de Outubro de 2026, a partir do motor 1.26.1.

Como seu código é executado

Em navegadores Nativamente
JavaScript do jogo O navegador V8, velocidade máxima O próprio intérprete do mecanismo, sem JIT (por design, por segurança)
WebAssembly, domínio principal O WebAssembly do navegador Código nativo compilado pela plataforma do mecanismo 1.26.1 (detalhes); caso contrário, o interpretador do mecanismo (API host 1.25 e posterior)
WebAssembly em starhermit:script trabalhadores O intérprete do mecanismo, para resultados exatos em bits Código nativo compilado pela plataforma, como no domínio principal
  • Nativamente, o JavaScript do jogo real trata 15–25× mais lento que V8. Micro-benchmarks podem sugerir cerca de 8×. Não confie neles.
  • O WebAssembly nativo que a plataforma compilou é executado em aproximadamente velocidade V8: cerca de 7× mais rápido do que o intérprete no benchmark de simulação do motor, cerca de 1,4× o tempo do V8. Interpretado O WebAssembly é cerca de 8–18× mais lento que o V8.
  • starhermit check executa JavaScript exatamente como um jogo em janela. Referência com um --release apenas construção do motor.

WebAssembly compilado

A partir do motor 1.26.1, quando você publica um jogo contendo .wasm módulos, a plataforma compila cada módulo antecipadamente em uma construção em sandbox e assina o resultado. O tempo de execução nativo faz o download, verifica a assinatura, armazena-a em cache e executa-a como código nativo. Você não precisa mudar o jogo; basta publicá-lo.

  • Onde: Windows x86-64, Linux x86-64 e Intel macOS, em CPUs x86-64-v2 ou mais recentes (SSE4.2 e POPCNT). Apple Silicon Macs e CPUs mais antigas ainda interpretam, assim como módulos que usar SIMD.
  • Quando: uma instância criada antes do download do código compilado continua sendo interpretada. Mais tarde as instâncias são executadas compiladas, incluindo a próxima inicialização, que as carrega do cache do disco.
  • Mesmos resultados: o código compilado corresponde ao interpretador bit por bit, incluindo combustível e armadilhas.
  • Verifique e desative: com --dev, o log mostra para cada módulo se ele executou compilado ou interpretado e por quê. STARHERMIT_WASM_AOT=0 desativa a compilação.
  • Os navegadores permanecem inalterados: o domínio principal usa o WebAssembly do navegador e os trabalhadores usam o intérprete do motor.

Trabalho pesado por quadro

Simulação, geração de malha, localização de caminhos e construção de entidades são os pontos críticos usuais.

  1. Escreva o código quente em Rust ou outra linguagem WASM e executá-lo como WebAssembly, de preferência em um starhermit:script trabalhador. Depois que o jogo é publicado ele roda nativamente próximo à velocidade V8 enquanto o JavaScript simples permanece cerca de 15–25× mais lento.
  2. Escolha um caminho com runtime() de starhermit:engine (host API 1.26). "web" significa V8, então JavaScript está bem aí. "native" significa que você deve preferir o caminho WASM. Os trabalhadores sempre levam o caminho nativo e não é possível importar starhermit:engine.
  3. Mantenha JavaScript simples para lógica de jogo, UI e orquestração. Espalhe trabalhos pesados ​​raros entre quadros.
  4. Não compile JavaScript ou TypeScript para WebAssembly para obter velocidade. O resultado ainda precisa de um Modelo de objeto JavaScript, portanto não ganha nada.

Para muitas entidades semelhantes, starhermit:world grãos execute nativamente também.

Cenas vinculadas à GPU

Nativamente, a GPU geralmente se torna o limite somente depois que o tempo do script está sob controle.

  • Usar InstancedMesh.setLevels([...]) com níveis low-poly e uma distância de desenho, e três LOD (host API 1.26).
  • Vez castShadow desligado para adereços pequenos ou distantes.
  • Limite as cascatas de sombras com shadow.cascades = { count, maxDistance }, uma extensão do motor.
  • Definir STARHERMIT_GPU_PASS_TIMES=1 para imprimir o tempo da GPU para cada passagem.

Trabalhadores

  • Antes do host API 1.27, mantenha uma referência para cada trabalhador que você usa, porque a coleta de lixo termina. A partir de 1.27, um trabalhador com ouvintes vive até terminate().
  • Os trabalhadores podem ler arquivos de pacote (files) da API do host 1.26.
  • Os trabalhadores podem enviar mensagens binárias e transferíveis do host API 1.25.

Medindo

  • Compare nativo e web usando a mesma construção.
  • As estatísticas de quadro do mecanismo relatam o tempo do script separadamente do tempo do quadro. Os números do banco de scripts são adequado para citar.
