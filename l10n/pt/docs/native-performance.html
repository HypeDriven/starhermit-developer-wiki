Desempenho nativo para jogos de script

Um jogo com motor StarHermit executa o mesmo pacote em navegadores e nativamente. Os dois executam seu código muito de forma diferente, então escolha onde fica o trabalho pesado antes de transferi-lo ou escrevê-lo. Esta página cobre o script velocidade, WebAssembly, cenas vinculadas a GPU, trabalhadores e medição. Os números são medições do motor de Outubro de 2026.

Como seu código é executado

Em navegadores Nativamente
JavaScript do jogo O navegador V8, velocidade máxima O próprio intérprete do mecanismo, sem JIT (por design, por segurança)
WebAssembly, domínio principal O WebAssembly do navegador O intérprete do mecanismo (API host 1.25 e posterior)
WebAssembly em starhermit:script trabalhadores O intérprete do mecanismo, para resultados exatos em bits O intérprete do motor
  • Nativamente, o JavaScript do jogo real trata 15–25× mais lento que V8. Micro-benchmarks podem sugerir cerca de 8×. Não confie neles.
  • WebAssembly nativo é sobre 8–17× mais lento que V8 hoje. A plataforma planeja compilar WASM com antecedência para assinar o código nativo no momento da publicação, o que deve aproximá-lo da velocidade V8.
  • starhermit check executa JavaScript exatamente como um jogo em janela. Referência com um --release apenas construção do motor.

Trabalho pesado por quadro

Simulação, geração de malha, localização de caminhos e construção de entidades são os pontos críticos usuais.

  1. Escreva o código quente em Rust ou outra linguagem WASM e executá-lo como WebAssembly, de preferência em um starhermit:script trabalhador. O código escrito dessa maneira obtém a aceleração planejada antecipadamente, sem mudanças.
  2. Escolha um caminho com runtime() de starhermit:engine (host API 1.26). "web" significa V8, então JavaScript está bem aí. "native" significa que você deve preferir o caminho WASM. Os trabalhadores sempre levam o caminho nativo e não é possível importar starhermit:engine.
  3. Mantenha JavaScript simples para lógica de jogo, UI e orquestração. Espalhe trabalhos pesados ​​raros entre quadros.
  4. Não compile JavaScript ou TypeScript para WebAssembly para obter velocidade. O resultado ainda precisa de um Modelo de objeto JavaScript, portanto não ganha nada.

Para muitas entidades semelhantes, starhermit:world grãos execute nativamente também.

Cenas vinculadas à GPU

Nativamente, a GPU geralmente se torna o limite somente depois que o tempo do script está sob controle.

  • Usar InstancedMesh.setLevels([...]) com níveis low-poly e uma distância de desenho, e três LOD (host API 1.26).
  • Vez castShadow desligado para adereços pequenos ou distantes.
  • Limite as cascatas de sombras com shadow.cascades = { count, maxDistance }, uma extensão do motor.
  • Definir STARHERMIT_GPU_PASS_TIMES=1 para imprimir o tempo da GPU para cada passagem.

Trabalhadores

  • Antes do host API 1.27, mantenha uma referência para cada trabalhador que você usa, porque a coleta de lixo termina. A partir de 1.27, um trabalhador com ouvintes vive até terminate().
  • Os trabalhadores podem ler arquivos de pacote (files) da API do host 1.26.
  • Os trabalhadores podem enviar mensagens binárias e transferíveis do host API 1.25.

Medindo

  • Compare nativo e web usando a mesma construção.
  • As estatísticas de quadro do mecanismo relatam o tempo do script separadamente do tempo do quadro. Os números do banco de scripts são adequado para citar.
