Lançamentos do motor StarHermit

O mecanismo StarHermit — o tempo de execução que reproduz jogos de roteiro - é publicados nesta wiki como lançamentos versionados e imutáveis sob wiki.starhermit.com/engine/. Os jogos fixam um lançamento exatamente com engine.version em seu starhermit.txt; a página de um jogo carrega o tempo de execução da web do lançamento de aqui no navegador, o cliente StarHermit Windows instala o tempo de execução nativo da versão e reproduz o jogo nele, e os desenvolvedores baixam o tempo de execução de uma versão aqui para construir.

Versões

Um lançamento é X.Y.Z. X é o versão principal da API host, o engine.api um jogo declara, então cada versão 1.x.x é executada engine.api=1 jogos; o lançamento também registra a versão secundária da API do host, que cresce à medida que os membros são adicionados (um jogo pode exigir um com engine.minor). Um lançamento publicado nunca muda: uma correção é a próxima versão.

A documentação sempre descreve a versão mais recente. As páginas aqui podem ser armazenadas em cache por até dez minutos após a publicação de um comunicado; versions.json diz qual é o lançamento mais novo.

Notas de lançamento

1.5.1

Host API 1.9, apenas correções: fixe novamente a partir de 1.5.0 sem nenhuma outra alteração.

  • Copiar funciona: clipboard.writeText coloca o texto na área de transferência do sistema nativamente (Windows, X11, Wayland) e em navegadores; ele passou nas verificações antes, mas o texto nunca chegou.
  • Colando nativamente: Ctrl+V, Shift+Insert ou a tecla Colar cola em um campo de texto em foco. Apenas o tempo de execução lê a prancheta, por gesto do jogador; o jogo vê o texto colado como digitação.
  • frustumCulled = false nunca é abatido: uma malha que um gancho de vértice coloca mantém sua sombra mesmo quando o gancho coloca-o mais próximo da luz do que seus limites, digamos, e um NaN, esfera delimitadora infinita ou vazia não seleciona nada em vez de jogar.

1.5.0

API de host 1.9. Os jogos fixados em uma versão anterior continuam rodando nele; fixar novamente (com engine.minor=9 para estes) para usá-los.

  • Arquivos que o jogador escolhe: files.saveAs(name, data, {type}) e files.open({accept}) abra um confiável caixa de diálogo apenas durante o pressionamento do player (ou dentro de 5 segundos): o próprio seletor de arquivos do tempo de execução nativamente, o seletor de downloads e arquivos do navegador na web. O jogo vê nomes e bytes, nunca caminhos; no máximo 64 MiB, e nomes de programas, scripts e páginas são recusados.
  • Capturas: renderer.capture({ui}) retorna um PNG do próprio quadro do jogo (com sua sobreposição 2D, se solicitado), nunca os menus do tempo de execução; um modo de foto é files.saveAs("photo.png", await renderer.capture()).
  • Leitores de tela: ui.announce(text, { politeness }) fala o que um quadro desenhado não pode (UI Automation, AT-SPI, uma região ativa em navegadores), no máximo 500 caracteres e alguns por segundo.
  • Links de convite: platform.launchContext() dá à sessão um lançamento (um convite aceito, um notificação), para que o jogo possa abrir essa mesa em vez de seu lobby.
  • Orçamento de imagem: engine.limits.image_mib aumenta o orçamento de imagem de um jogo de 56 MiB para 512 MiB, dentro gpu_mib.
  • Materiais e iluminação: 5 texturas por material personalizado, renderiza alvos sem profundidade e com mipmaps, malhas instanciadas em seu próprio orçamento de 262.144 instâncias, ganchos de luz e neblina, uma passagem de postagem em tela cheia com o cor e profundidade da cena, neblina que começa atrás da câmera, suavidade das sombras e flash graduado.
  • Scripts mais rápidos: alocação de intérpretes de pools reutilizados, mais barato for…of e Mapa/Conjunto; pesado em objetos código do jogo cerca de 10–20% mais rápido nativamente. Nos navegadores, as chamadas de host com strings curtas são cerca de 3x mais baratas.
  • engine.stats().heapBytes e heapLimitBytes estão ausentes nos navegadores em vez de 0.

1.4.1

Host API 1.8, apenas correções: fixe novamente a partir de 1.4.0 sem nenhuma outra alteração.

  • Campos de texto em navegadores: um foco ui.textField (e os próprios campos do tempo de execução) exige digitar, colar e composições de métodos de entrada em navegadores, onde nenhum texto chegava; nativamente, o método de entrada está ativado apenas enquanto um campo tem foco, com seus candidatos no cursor.
  • Clipes de áudio em navegadores: cada clipe que um jogo carrega chega ao mixer, não importa quantos clipes ele carregue no início (eles fazem fila e carregam alguns de cada vez em ordem) em vez de a maioria ser perdida silenciosamente; um clipe que não poderia ser feito arremessos quando jogado.
  • Nenhum erro de console sem salvar na nuvem: o tempo de execução pergunta se existe um save antes de baixá-lo, então um jogador sem salvar ainda não causa mais um 404 no console.
  • Plataforma local (--dev --local-platform): um comando recusado responde ao seu remetente com o erro da plataforma frame e scripts de servidor obtêm o contexto ao vivo (sala, presença, classificações e equipes, matchmaking).

1.4.0

API de host 1.8. Os jogos fixados em uma versão anterior continuam rodando nele; fixe novamente para usá-los.

  • Leve os jogadores de uma compilação JS SDK: um salvamento na nuvem que o mecanismo não escreveu (uma compilação do JS SDK) não é não é mais um erro. saves.foreign() dá o seu { text, bytes }, o estado de salvamento é "foreign", e nada é carregado até que o jogo o migre e chame saves.save(data, { replaceForeign: true }), que substitui apenas a versão que foi mostrada. settings.legacyKeys(), legacy(key), removeLegacy(key) e onLegacy leia e remova as chaves de configurações mais antigas do jogo (fora game.).
  • Compressão: compress e decompress ("gzip", "deflate", "deflate-raw") em starhermit:engine, delimitado e com os mesmos bytes nativamente e em navegadores; atob e btoa nativamente também.
  • Arquivos remotos hospedados na plataforma: engine.remote.urls=platform serve arquivos remotos de um jogo do StarHermit sob a própria origem do jogo, e cargo starhermit publish carrega apenas os objetos que faltam no jogo.
  • Destinos de renderização: WebGLRenderTarget com renderer.setRenderTarget e render (ícones, marcas de fundo), a profundidade da cena para materiais personalizados (partículas suaves) e mais amostragem de textura em ganchos de materiais.
  • IU: não há cliques perdidos quando pressionar e soltar fica entre dois quadros (um toque rápido em um quadro lento); ui.scrollArea pode ser rolado e lido pelo script; tamanho, família e peso do texto por widget, e o famílias genéricas serif, monospace e cursive.
  • Navegadores: loadClip, loadBuffer, createImageBitmap(path) e FontFace.load() não faça mais o página espera por um arquivo não buscado, files.fetch busca arquivos de pacotes e os mantém, e no máximo 16 buscas executado de uma só vez (a fila restante).
  • Scripts clássicos em navegadores: jogos que carregam scripts clássicos (loadClassic) agora inicia nos navegadores; o globais da página, como fetch, WebSocket e location pode ser atribuído por um jogo como nativamente.
  • Leituras à distância: files.readBytes(path, offset, length) lê parte de um pacote ou arquivo remoto.
  • Roteiros: Intl.NumberFormat com style: "currency" nativamente (símbolos, contabilidade, CLDR 48) e formatToParts. Um script de servidor declarando tickRateHz: 0 não precisa onTick em authority(), como no plataforma.

1.3.0

API de host 1.7. Os jogos fixados em uma versão anterior continuam rodando nele; fixe novamente para usá-los.

  • Scripts mais rápidos e enxutos: o intérprete nativo mantém valores em uma palavra de máquina e armazena propriedades em cache pesquisas e x | 0, x >>> 0 e mudanças por constantes são executadas como instruções únicas. Uso de jogos com muitos objetos cerca de metade do heap e a geração do mapa é cerca de 1,2–1,3× mais rápida. Um jogo que ultrapassou seu limite de heap é coletado e as suas mesas encolheram antes que acabasse; STARHERMIT_HEAP_CENSUS=<seconds> com --dev imprime o que pilha se mantém.
  • Arquivos remotos (host API 1.7): engine.remote.files=, engine.remote.urls= e engine.remote.redirects= marque os arquivos que os próprios hosts HTTPS do jogo servem. Os comandos de empacotamento os deixam de fora do upload e fixe cada um por tamanho e SHA-256 em starhermit-remote.json (--remote-out DIR escreve seu objetos por hash). O tempo de execução os busca, verifica e armazena em cache; files.fetch(paths, onProgress) faz com que eles pronto, files.status(path) diz onde está um arquivo e os carregadores buscam o que carregam.
  • Limites de upload: --max-upload-mib e --max-upload-paths (ou STARHERMIT_MAX_UPLOAD_MIB / _PATHS) ultrapassar os limites elevados de um jogo e com --game-id as ferramentas leem os limites que a plataforma informa.
  • glTF: Malhas Draco-comprimidas (KHR_draco_mesh_compression) e KHR_mesh_quantization carregar através GLTFLoader.
  • Geometria e materiais (host API 1.7): BufferAttribute.onUpload elimina as matrizes de uma geometria do amontoar quando chegarem à GPU; compactar Int8, Uint8 e Int16 atributos; quatro vec4s personalizados por instância (setCustomAt(i, v, slot)); mistura pré-multiplicada e multiplicada; selecionando por boundingSphere e frustumCulled = false. As cores de vértice fora de 0–1 não descartam mais uma malha silenciosamente.
  • Rede: a limpeza de inicialização da página não emite mais um desenho vazio, então o WebGPU para de avisar sobre um vértice zero contar.

1.2.0

API de host 1.6. Os jogos fixados em 1.1.0 continuam rodando em 1.1.0; fixe novamente para usá-los.

  • BigInt nativamente, como nos navegadores: 1n << 64n e o restante do ES2022 BigInt (BigInt.asIntN, asUintN, BigInt64Array, BigUint64Array, acessadores BigInt do DataView). Um BigInt contém no máximo 220 bits nativamente. Hospedar APIs e JSON.stringify recusar BigInts (TypeError).
  • Módulos em navegadores: um módulo que importa uma ligação e a exporta novamente agora é carregado quando o dois módulos importam um ao outro (falhou com "A exportação '…' não está definida no módulo"), assim como export { x } from e import() em tal ciclo.
  • starhermit check vincula os módulos conforme os navegadores os obtêm e falha, com arquivo e linha, onde um o navegador não carregava o jogo; avisa sobre recursos integrados que apenas os navegadores possuem; imprime o jogo console saída (--quiet esconde); e falha em um jogo que traria à tona o "não respondendo" tela.
  • Orçamentos de tempo: avaliação do módulo tem 60 s de combustível (eram 2 s), TypedArray set e fill custam apenas o que escrevem, e um erro de tempo nomeia a fase, o tempo de execução e o limite. Os orçamentos por fase estão na tutorial.
  • Até 128 ações revinculáveis (a plataforma mantém os primeiros 32 com a conta, o tempo de execução mantém o resto nas configurações sincronizadas do player) e engine.group.<action>=Heading agrupa-os no tela de controles.
  • Pacotes omitem arquivos de desenvolvimento (node_modules/, tsconfig.json, package.json, bloqueio arquivos, mapas de origem, …) e qualquer que seja .starhermitignore listas. package --web --out DIR escreve um upload sem eles; um índice escrito no local os lista em "excluded".
  • A página: um arquivo alterado após o empacotamento ser nomeado na tela de erro com seus nomes listados e tamanho real e SHA-256; o carregador nomeia o ícone do jogo (não /favicon.ico solicitar); um navegador sem WebGPU ou WebGL 2 recebe uma mensagem clara.
  • Materiais personalizados (host API 1.6): vértice WGSL do jogo e ganchos de superfície no padrão, físico, Lambert e materiais básicos e um ShaderMaterial, verificado e colocado em sandbox pelo mecanismo; um gancho de superfície aditivo MeshBasicMaterial dá brilho.
  • Cenas e ferramentas (host API 1.5): GLTFLoader em starhermit:scene, engine.setBusy(label) para trabalhos longos que não podem ser fatiados, o script é empilhado engine.stats()e um perfilador de amostragem (STARHERMIT_SAMPLE com --dev).
  • Scripts mais rápidos: loops de array digitado 25–30% mais rápido e Math embutidos computados em linha.

1.1.0

O tempo de execução da web: os jogos são reproduzidos em navegadores a partir dos arquivos do mecanismo deste wiki, fixados pelo SRI, com recursos on-line reprodução, voz e fontes Liberation e DejaVu incluídas; starhermit package --web escreve uma pasta para navegadores e para o cliente.

1.0.0

A primeira versão: o tempo de execução do Windows (x86-64), sem tempo de execução da web.

A área do motor

engine/
  versions.json            every release: host API, date, runtimes, revocation
  X.Y.Z/
    native/windows-x86_64/
      native.json          the Windows runtime's files, each with its size, SHA-256 and chunks
      starhermit-X.Y.Z-windows-x86_64.zip
                           the developer download: the same files as one archive
    manifest.json          the web runtime's files, each with its size and sha384
    starhermit.js          the module a game's loader page loads
    starhermit.wasm, *.js  the runtime, its audio mixer and worklets
    starhermit.d.ts        the host API's declarations
    fonts/, licenses/      the runtime's fonts and every licence notice
                           (all of the web runtime only in a release that has one)
  chunks/ab/<sha256>.z     pieces of the native files, shared by every release
  patches/ab/<sha256>.p    binary patches from earlier releases' files

Cada arquivo é publicado como está (nenhum nome de arquivo começa com _ ou .) e o GitHub Pages serve isso com Access-Control-Allow-Origin: *.

versions.json

{
  "format": 2,
  "versions": [
    {
      "api": {"major": 1, "minor": 4},
      "date": "2026-10-20T13:55:50Z",
      "native": {
        "windows-x86_64": {"manifest": "1.1.0/native/windows-x86_64/native.json", "sha256": "<SHA-256 of native.json>"}
      },
      "revoked": false,
      "version": "1.1.0",
      "web": {"manifest": "sha384-<SRI hash of manifest.json>"}
    }
  ]
}

web é {"manifest": "sha384-…"}, o hash SRI da web do lançamento manifest.json, ou null para uma versão sem tempo de execução da web. native fixa cada plataforma native.json pelo seu SHA-256. Um liberação retirada porque não é seguro, diz "revoked": true com um "revokedReason"; esse é o apenas a alteração que uma entrada publicada é necessária.

native.json

native.json lista os arquivos da pasta do mecanismo que um cliente instala — starhermit.exe, release.json (a versão do lançamento, a API do host e o launcher protocolo que seu tempo de execução fala), LICENSE-engine e os avisos de terceiros - cada um com seu size, sha256 e chunks. Um pedaço é um trecho de um arquivo, armazenado compactado em zlib como chunks/<first two hex digits>/<sha256>.z e nomeado pelo SHA-256 de seus bytes não compactados; os limites dos pedaços seguem o conteúdo, portanto, um valor inalterado stretch mantém seu pedaço de um lançamento para o outro. Onde for menor, um arquivo também lista patches do mesmo arquivo de versões anteriores ("from": o SHA-256 do arquivo anterior). downloads lista o download do desenvolvedor com seu size e sha256; os clientes nunca o instalam. Em uma versão com tempo de execução da Web, a pasta nativa também contém web-manifest.json, a web do lançamento manifesto, para que o desenvolvedor baixe pacotes de jogos para a web sem rede.

O tempo de execução da web

O tempo de execução da web de uma versão são os arquivos ao lado de seu manifest.json, que lista cada um com seu size e sha384 e registra a versão do lançamento, API do host e compilação. A página de carregamento de um jogo (index.html, escrito por starhermit package --web) não possui script próprio: ele carrega starhermit.js e manifest.json de https://wiki.starhermit.com/engine/X.Y.Z/ com hashes SRI e o mecanismo busca todos os outros arquivos necessários (starhermit.wasm, os worklets de áudio, as fontes) e verifica contra o manifesto. A página executa apenas o mecanismo - entrada, menus de tempo de execução, áudio, armazenamento, sessão e voz da plataforma - e o TypeScript do jogo é executado em um trabalhador que ele inicia e pode parar.

O tempo de execução da web agrupa suas próprias fontes, Liberation 2.1.5 (SIL Open Font License 1.1) e DejaVu Sans 2.37 (licenças Bitstream Vera e Arev); seus avisos estão em licenses/ com os outros.

Integridade

Uma cadeia de hashes cobre cada byte que um cliente executa:

  1. versions.json (ou a API da plataforma abaixo) fornece o SHA-256 de uma versão native.json.
  2. native.json fornece o SHA-256 de cada arquivo e cada pedaço.
  3. O cliente busca apenas os pedaços que ainda não contém, verifica o tamanho armazenado de cada um, tamanho inflado e SHA-256, junta cada arquivo, verifica o SHA-256 do arquivo e só então move a liberação no lugar. Um patch é verificado em relação ao seu próprio SHA-256 e o arquivo corrigido em relação ao o arquivo; qualquer falha recai sobre os pedaços.

O download do desenvolvedor é coberto pela mesma cadeia através de sua entrada em downloads. Um navegador a página de carregamento do jogo fixa o tempo de execução da web starhermit.js e manifest.json com hashes SRI e o tempo de execução verifica todos os outros arquivos carregados no manifesto.

O mecanismo libera API

A plataforma serve a mesma lista, com todos os URLs deste wiki, então os clientes perguntam à API qual mecanismo para buscar:

GET /api/v1/engine/releases → cada lançamento, o mais recente primeiro:

{"releases": [{
  "version": "1.1.0", "api": {"major": 1, "minor": 4}, "revoked": false, "date": "2026-10-20T13:55:50Z",
  "web": {"base": "https://wiki.starhermit.com/engine/1.1.0/", "manifestIntegrity": "sha384-<SRI hash>"},
  "native": {"windows-x86_64": {
    "manifestUrl": "https://wiki.starhermit.com/engine/1.1.0/native/windows-x86_64/native.json",
    "manifestSha256": "<SHA-256 of native.json>"}}
}]}

GET /api/v1/engine/releases/{version} → uma liberação, ou 404 quando não está listado. Ambos são anônimo e armazenável em cache (Cache-Control: public, max-age=60 com um ETag). Uma versão revogada carrega revokedReason; web é null para uma versão sem tempo de execução da web. Embora a plataforma nunca tenha lido a lista (o wiki está inacessível desde que começou), eles respondem 503 com Retry-After.

Jogos de script na plataforma

Quando a raiz de um jogo starhermit.txt declara engine.version, a plataforma trata isso como um script jogo:

  • cada publicação registra a liberação do pin dos arquivos, conforme hosting.engineVersione conjuntos hosting.deployWarning (também na resposta de um pacote push) quando esse lançamento não está listado ou é revogado. Um aviso nunca interrompe uma publicação.
  • cada página do jogo hospedado é servida com uma Política de Segurança de Conteúdo que admite apenas scripts deste wiki (e do próprio mecanismo blob: trabalhadores), então o único código que a página de um jogo de script pode run é o motor oficial:
default-src 'self'; script-src https://wiki.starhermit.com 'wasm-unsafe-eval' blob:; worker-src blob:;
connect-src 'self' https://wiki.starhermit.com; img-src 'self' blob: data:; media-src 'self' blob:;
style-src 'self' 'unsafe-inline'; font-src 'self' https://wiki.starhermit.com;
frame-ancestors https://dashboard.starhermit.com; base-uri 'self'; form-action 'none'

Uma página de um jogo de script sem construção de navegador (como a página simples que um jogo somente para Windows carrega para navegadores) não precisa de script e não é afetado.

Revogações

Uma versão revogada permanece listada para que os clientes possam dizer por que a recusam: o cliente StarHermit não não instale ou inicie e diga ao jogador que os comandos de empacotamento se recusam a empacotar um jogo para ele quando eles lerem versions.json, e a plataforma avisa os proprietários dos jogos que a fixam quando publicar. Fixe novamente na versão que o substitui e publique novamente (veja Mude para um mecanismo mais novo).
