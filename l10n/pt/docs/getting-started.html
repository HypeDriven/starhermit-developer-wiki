Começando

Eremita Estelar é uma plataforma de distribuição de jogos e software com uma camada social integrada, exposta por REST e WebSockets. Esta página fornece uma visão geral: o que a plataforma faz, onde ela escuta, como funcionam a autenticação e o controle de versão e as duas maneiras pelas quais seu próprio jogo pode se integrar a ela.

Para o seu primeiro jogo de navegador, baixe e publique o início rápido. Para outra arquitetura, escolha uma integração, então verifique credenciais, Convenções de API, e disponibilidade de recursos. Usar solução de problemas quando uma chamada falha.

O que StarHermit oferece

  • Usuários & autenticação — registro de chave pública (sem senhas) e login OAuth por meio de quaisquer provedores para os quais esta implantação tenha credenciais; ver Autenticação.
  • Perfis & presença — perfis de usuário, avatares, configurações de privacidade, direitos e pulsações de presença; ver Perfil.
  • Amigos — pedidos de amizade e estado de amizade; ver Amigos.
  • Bate-papo de texto — conversas e mensagens; ver Bater papo.
  • Voz em tempo real — salas de voz; ver Voz.
  • Editores — contas de editores que possuem entradas de catálogo; ver Editor.
  • Catálogo de software — títulos de software com compilações e recursos para download; ver Catálogo.
  • Direitos — concessões por usuário de software de catálogo (parte de Perfil).
  • Conquistas & tabelas de classificação — conquistas autorizadas pelo servidor para jogos com script ou back-end de contêiner, além de conquistas reivindicadas pelo cliente para títulos de catálogo; ver Conquistas e Tabelas de classificação.
  • Retransmissão de pares — distribuição de bytes opacos vinculados à partida com autorização de escalação e limites de taxa derivados da taxa de ticks do jogo; ver Relé.
  • Salas em tempo real — lobbies, matchmaking, jogadores e preenchimento de IA e transporte em tempo real para jogos em ritmo acelerado; também pode fazer a ponte para uma sessão com script vinculada à sala para reprodução autorizada pelo servidor; ver Salas em tempo real.
  • Jogos oficiais — jogos hospedados em plataforma cujas regras são executadas como um JavaScript em sandbox Roteiro do jogo ou um Servidor de jogos de contêiner; os clientes usam o compartilhamento API de jogos.

URLs e portas base

  • API REST pública: https://api.starhermit.com, sob api/v1/....
  • WebSockets públicos: wss://api.starhermit.com/ws/v1/....
  • Os jogos publicados na plataforma são veiculados em https://<slug>.starhermit.com com /api e /ws disponíveis na mesma origem, portanto, os jogos hospedados na plataforma devem usar caminhos relativos.

Versionamento

Todas as rotas REST são versionadas: api/v1/.... As rotas WebSocket residem em ws/v1/... e são neutros em termos de versão.

Maneiras recomendadas de entrar em um jogo hospedado

Recomenda-se que os jogos hospedados no StarHermit ofereçam duas opções claras na tela inicial:

  1. Faça login com uma conta StarHermit existente — permita que os jogadores usem suas contas para salvar o progresso e os recursos da plataforma compatíveis, como conquistas e placares de líderes. Use o fluxo de login do jogo hospedado quando não há token de lançamento válido; os jogadores que chegam com um token válido podem continuar diretamente.
  2. Jogue no modo single player sem fazer login – oferece uma versão autônoma para um jogador que não requer conta e não rastreia ou salva o progresso. Mantenha o progresso na memória da sessão de jogo atual, sem gravar salvamentos na nuvem, salvamentos locais persistentes, conquistas ou pontuações na tabela de classificação.

Rotule a segunda opção claramente, por exemplo Jogue no modo single player (o progresso não é salvo), para que os jogadores entendam o que esperar antes de começar. Este modo deve ser executado sem chamadas ou soquetes autenticados da API StarHermit.

Modelo de autenticação (visão geral)

  • Os tokens de acesso são JWTs com vida útil de 15 minutos; os tokens de atualização giram e duram 7 dias. Ver Autenticação para o formato do token e os pontos de extremidade de atualização/logout.
  • Envie o token de acesso como um Authorization: Bearer <token> cabeçalho em cada solicitação autenticada. Para /ws/** apenas caminhos, a credencial também é aceita como ?ticket= (um ticket de conexão único de POST /api/v1/realtime/connection-tickets) ou como ?access_token= (ainda suportado). Os navegadores não podem definir cabeçalhos em handshakes WebSocket.
  • Os jogos também usam tokens de lançamento no escopo do jogo - JWTs de curta duração criados por jogo que isolam o chamador da superfície da API do jogo. Ver Autenticação e Jogos.

Um jogo hospedado aberto diretamente no navegador pode oferecer uma Botão de login. Starhermit cuida do login ou da criação de conta e retorna um token do escopo do jogo diretamente para o jogo.

Antes de chamar endpoints protegidos ou abrir soquetes, uma conta deve aceitar os termos atuais. Usar GET /api/v1/me verificar termsAcceptanceRequired, exiba o documento de GET /api/v1/termse envie seu hash somente depois que o usuário aceitar. UM 403 com error: "terms_acceptance_required" significa que você deve exibir o documento atual e oferecer uma explicação explícita Aceite a ação. Sessões de conta e tokens de lançamento de jogadores podem enviar aceitação; tokens de servidor não podem. Atualizar um token não registra aceitação.

Duas maneiras de integrar seu jogo

  1. Jogo hospedado na plataforma. Você publica um jogo de um repositório GitHub com um starhermit.txt manifesto — ou, se não estiver em um repositório, carregue a pasta diretamente e pule o git completamente. Pode ser apenas para navegador, use um sandbox server.jsou aponte para uma imagem de contêiner fixada por resumo para lógica do servidor. A plataforma serve o jogo em <slug>.starhermit.com com /api e /ws proxy de mesma origem. O caminho do script é demonstrado de ponta a ponta pela implementação de referência de xadrez em https://github.com/HypeDriven/starhermit-chess. Ver Jogos GitHub, Scripts de jogos, Servidores de jogos em contêiner, e o Passo a passo de integração.
  2. Cliente de jogo externo. Seu próprio cliente chama a API REST e WebSocket diretamente, usando autenticação JWT e, quando apropriado, tokens de inicialização do jogo. As páginas de referência da API abaixo documentam a superfície. Na Unidade, o Unidade SDK já implementa essa superfície como clientes C# digitados — incluindo as regras de atualização de token, nova tentativa e reconexão de soquete — para compilações de desktop, dispositivos móveis, WebGL, console e servidores headless.

Ambas as rotas para um jogo hospedado na plataforma passam por um pequeno arquivo: consulte O starhermit.txt manifesto pelo seu formato, onde deve ficar e por que o a pasta que você carrega deve ser sua compilação distribuível e não sua árvore de origem.

Relógio do servidor — GET /api/v1/time

Prazos que a plataforma lhe entrega (um resumo da sessão deadline, um roteiro ctx.now) estão no do servidor clock, então um cliente que renderiza uma contagem regressiva em relação ao seu próprio relógio irá desviar. Isto O endpoint é anônimo propositalmente — a sincronização precisa funcionar antes do login — e é explicitamente permitido para tokens de lançamento com escopo de jogo, para que um jogo hospedado possa chamá-lo enquanto estiver cercado em sua própria superfície.

{
  "serverTime": 1785060842000,
  "serverTimeIso": "2026-07-25T09:14:02+00:00",
  "clientTime": 1785060841200,
  "skew": 800
}

clientTime (unix ms, opcional) é ecoado de volta intacto para que uma resposta possa ser correspondida ao seu solicitação; skew é o ingênuo serverTime - clientTime para clientes que não querem a viagem de ida e volta matemática. Para uma estimativa real, faça no estilo NTP: reduza pela metade a viagem de ida e volta e calcule offset = serverTime + rtt/2 - now.

Comportamento transversal

  • Cabeçalhos de segurança são definidos em todas as respostas.
  • Limitação de taxa — mensagens de chat são limitadas a 10 por minuto por usuário; outros endpoints podem retornar 429 conforme documentado por página.
  • Erros são sempre retornados como {"error":"..."} com códigos de status padrão (400/401/403/404/409/422/429). As páginas individuais registram apenas casos de erro específicos do endpoint.
