Escolha uma integração

Comece com onde seu jogo é executado e quem valida a jogabilidade. Um jogo de navegador hospedado não precisa de um back-end do servidor para usar login, salvamentos na nuvem, configurações, controles ou salas em tempo real.

Três pontos de partida comuns

Um jogo de navegador para um jogador: seguir o início rápido do navegador. Oferecer Faça login com StarHermit para o progresso da conta e Jogue no modo single player (o progresso não é salvo) para jogo imediato. Comece sem back-end; adicione um quando precisar de concorrência validada resultados. As configurações e os salvamentos na nuvem não exigem um server= linha.

Multijogador casual com amigos: usar salas em tempo real. O host executa o simulação, os convidados enviam entradas e o host transmite instantâneos. Seu jogo implementa IA e host migração. A plataforma fornece assentos, identidade e roteamento. A confiança no anfitrião faz parte deste modelo.

Multijogador classificado ou persistente: usar um roteiro ou um recipiente, com quartos se você precisar de um lobby. Valide a jogabilidade antes premiando qualquer coisa. Os scripts solicitam uma taxa de tick dentro do limite máximo suportado (30 Hz por padrão); contêineres executam seu próprio loop de simulação. Atualmente, a combinação direta de contêineres tem um implícito Fila 1v1, mas uma sala pode criar uma sessão de contêiner para N jogadores.

Hospedagem e publicação

Sua construção Publicar através Leia a seguir
Pasta distribuível Carregamento de pasta; versões subsequentes usam uploads de pacotes Manifesto, carregar API
Repositório GitHub público Registre o repositório, comprove a propriedade, implante uma versão selecionada Jogos GitHub
Imagem do contêiner Registre/faça upload de um jogo e, em seguida, declare uma imagem de registro fixada ou envie por push server/image.tar Protocolo de contêiner, Carregamentos de CI
Cliente de jogo externo/nativo Chame a API pública diretamente; usar credenciais de jogador Integração de chave pública, Unidade SDK
Executável de catálogo Fluxo de trabalho de título/construção do editor; a publicação binária requer uma concessão Editor, disponibilidade atual

O UUID de um jogo hospedado é seu slug e subdomínio de API. Nomes de exibição e nomes de repositório não são API identificadores. Ver credenciais e identificadores antes das solicitações de fiação.

Escolha onde armazenar o estado

Dados Loja Escritor
Corrida single-player não rastreada Estado do jogo na memória Jogo local
Progresso de login de propriedade do cliente game:<gameId> slot para salvar na nuvem Cliente de jogo do jogador
Volume, gráficos, acessibilidade, preferências Configurações de jogo por jogador Cliente de jogo do jogador
Substituições de teclado API de controles, após declarações de manifesto Cliente de jogo do jogador
Partida validada/estado mundial e estatísticas do jogador Retorno de script ou instantâneo/resultado do contêiner Back-end de jogo confiável

Os salvamentos na nuvem contêm um documento opaco por slot, não um histórico de correspondências. As repetições contêm estado de sessão concluída que seu back-end escolheu reter, não um vídeo ou entrada gravado automaticamente fluxo. Ver economizando com segurança e ciclo de vida da sessão.
