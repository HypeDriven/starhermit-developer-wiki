Catálogo de software

O catálogo de software cobre navegação e reivindicação de títulos, listagem de compilações, download, salvamentos na nuvem, lista de desejos e classificações. As leituras são anônimas; as gravações exigem um JWT.

URL base: https://api.starhermit.com. Todas as rotas estão sob /api/v1/....

Navegando e reivindicando títulos

Método Caminho Autenticação Descrição
PEGAR /api/v1/software Anônimo Pesquisar e paginar o catálogo
PEGAR /api/v1/software/{id} Anônimo Obtenha um título ou 404
PEGAR /api/v1/software/{id}/builds?page=&pageSize= Anônimo Lista paginada de compilações para um título
PUBLICAR /api/v1/software/{id}/claim JWT Auto-reivindicar um título gratuito, concedendo um direito
PUBLICAR /api/v1/software/{id}/launch JWT Iniciar uma sessão de lançamento (requer autorização)

GET /api/v1/software aceita parâmetros de consulta q (texto completo), category, tag, publisherId, platform, releaseStatus, sort, page, e pageSize. Válido sort valores: name, name_desc, created, created_desc, updated, updated_desc. Ele retorna um PagedResult:

{
  "items": [
    {
      "id": "…",
      "name": "…",
      "description": "…",
      "publisherId": "…",
      "category": "…",
      "platform": "…",
      "releaseStatus": "…",
      "tags": ["…"],
      "priceCents": 0,
      "createdAt": "…",
      "updatedAt": "…"
    }
  ],
  "totalCount": 1,
  "page": 1,
  "pageSize": 20
}

GET /api/v1/software/{id}/builds retorna um PagedResult de SoftwareBuild:

{
  "items": [
    {
      "id": "…",
      "titleId": "…",
      "version": "…",
      "releaseDate": "…",
      "releaseNotes": "…",
      "metadata": "…",
      "createdAt": "…",
      "updatedAt": "…"
    }
  ],
  "totalCount": 1,
  "page": 1,
  "pageSize": 20
}

POST /api/v1/software/{id}/claim funciona apenas para títulos gratuitos (priceCents == 0); concede ao chamador um direito e retorna 204. Para títulos pagos, retorna 402 com:

{"error": "purchasing is not available yet"}

POST /api/v1/software/{id}/launch requer um direito (403 caso contrário) e retorna um LaunchSession:

{
  "launchId": "…",
  "startTime": "…"
}

Ele registra uma atividade de lançamento, que fica oculta se as configurações de privacidade do usuário assim o indicarem (consulte profile.md). Termine a sessão com POST /api/v1/activity/launches/{id}/end - ver activity.md. Os direitos de um usuário são listados por meio GET /api/v1/me/entitlements (ver profile.md).

Transferências

Método Caminho Autenticação Descrição
PUBLICAR /api/v1/software/{id}/download JWT Obtenha um URL de download assinado (requer autorização)

Requer um direito (403 caso contrário). Retorna:

{
  "downloadUrl": "…"
}

O URL tem como alvo o primeiro ativo para download da versão mais recente. A chamada registra uma atividade de download. A distribuição binária do catálogo é atualmente uma prévia; URLs retornados não têm produção garantida downloads. Ver disponibilidade de recursos antes de confiar neste fluxo de publicação.

Salvamentos na nuvem

Um slot por jogo, a última gravação vence. Todas as rotas requerem um JWT – um token de usuário completo ou um token de jogo token de lançamento para o slot do próprio jogo (abaixo).

O limite de 10 MB (10.485.760 bytes) se aplica ao salvamento decodificado, não o pedido. PUT leva o salve codificado em base64 em JSON, então o corpo é cerca de um terço maior que o salvo - aproximadamente 14 MB em o limite – e a API aceita isso.

Limite (por conta) Padrão Recusa
Um salvamento, decodificado 10MB 413 cloud_save_too_large
Jogos com salvamento 200 409 cloud_save_slots_exhausted (um salvamento para um novo jogo)
Todos salvam juntos 1GB 507 cloud_save_quota_exceeded, com used
Envios 30 por minuto 429, com Retry-After

Cada recusa nomeia o número em vigor como limit. O total é medido sobre o valor da conta outro salva, então um slot sempre pode ser substituído por algo não maior. Os operadores podem alterar qualquer um dos estes para uma conta.

Método Caminho Autenticação Descrição
PEGAR /api/v1/me/cloud-saves/{gameKey}/info JWT Salvar metadados: { exists, sizeBytes, updatedAt? }
PEGAR /api/v1/me/cloud-saves/{gameKey} JWT application/zip bytes, 404 se nenhum
COLOCAR /api/v1/me/cloud-saves/{gameKey} JWT Carregar um save (salvamento decodificado ≤ 10 MB, gameKey ≤ 300 caracteres)
EXCLUIR /api/v1/me/cloud-saves/{gameKey} JWT (token de usuário completo) Exclua o slot, 204 (idempotente)

O DELETE é do proprietário da conta — apenas um token de usuário completo. O token de lançamento de um jogo pode ler e escreva seu próprio slot, mas não pode exclua-o (403), então um jogo nunca pode apagar um save do jogador espera manter.

COLOCAR corpo:

{
  "dataBase64": "…"
}

Resposta COLOCAR:

{
  "gameKey": "…",
  "sizeBytes": 0,
  "updatedAt": "…"
}

Salvando de dentro de um jogo (token de lançamento)

Um jogo rodando com seu token de lançamento pode ler e gravar o salvamento do jogador para aquele jogo. Seu jogo se salva onde quer que seja executado – um navegador ou o aplicativo de desktop StarHermit, que é executado jogos hospedados em um navegador também – então o salvamento segue o jogador entre eles.

A chave é game:<gameId>, onde <gameId> é o ID do seu jogo - o mesmo valor do seu slug, seu <gameId>.starhermit.com endereço e o game_scope reivindicação do token de lançamento:

const key = `game:${gameScope}`;            // e.g. "game:3fa85f64-5717-4562-b3fc-2c963f66afa6"

// Load on startup — 404 means no save yet.
const res = await fetch(`/api/v1/me/cloud-saves/${key}`, { headers: { Authorization: `Bearer ${launchToken}` } });
if (res.status !== 404 && !res.ok) throw new Error(`Save load failed: ${res.status}`);
const save = res.status === 404 ? null : new Uint8Array(await res.arrayBuffer());
const etag = res.headers.get("ETag");
if (save && !etag) throw new Error("Save version unavailable; do not overwrite it.");
// Validate/decode your own save format before adopting it or enabling uploads.

// Save at checkpoints, not every frame.
const written = await fetch(`/api/v1/me/cloud-saves/${key}`, {
  method: "PUT",
  headers: {
    Authorization: `Bearer ${launchToken}`, "Content-Type": "application/json",
    ...(etag ? { "If-Match": etag } : { "If-None-Match": "*" }),
  },
  body: JSON.stringify({ dataBase64: base64(zipBytes) }), // Your ZIP encoder and bytes.
});
if (written.status === 412) throw new Error("Another device saved. Reload before writing again.");
if (!written.ok) throw new Error(`Save write failed: ${written.status}`);
const acknowledgement = await written.json(); // Retain acknowledgement.etag for your next write.
  • Apenas essa chave exata. Qualquer outra chave – de outro jogo, de um jogo de loja ou com uma grafia diferente seu (maiúsculas, o id simples) - é 403 para um token de lançamento. Isso inclui github:<gameId>, o slot separado que o aplicativo de desktop usa quando um jogador sincroniza uma pasta salva local para o seu jogo, então essa sincronização nunca pode substituir as gravações salvas do jogo.
  • Qualquer formato. A plataforma nunca abre o save; armazene tudo o que seu jogo pode ler (é serviu como application/zip sem considerar). Até 10 MB.
  • Gravações incondicionais são vitórias de última gravação, sem histórico. Use gravações condicionais para detectar duas guias/dispositivos salvando ao mesmo tempo. Carregue no início e salve nos pontos de verificação em primeiro plano. Saída da página os uploads são de melhor esforço e têm limites de tamanho do corpo do navegador; ver a receita de poupança segura.
  • Cada save tem uma versão. Isso é ETag está no download, em /info (também como etag) e em o PUT resposta. Envie de volta como If-Match e a gravação só acontece se ninguém salvou desde então; de outra forma 412 {"error":"precondition_failed","etag":"<current>"} informa a versão para carga. If-Match: * requer um salvamento existente; If-None-Match: * escreve apenas quando não há nenhum. Sem nenhum cabeçalho PUT é incondicional – a última gravação vence. UM GET com If-None-Match: <etag> respostas 304 quando você já possui o save mais recente.
  • Um jogo sem listagem hospedada (um jogo fornecido pelo operador) não possui slot.

Preferências pequenas e que mudam frequentemente pertencem a configurações por jogador em vez de; eles também podem ser acessados ​​com o token de lançamento e suportam atualizações parciais.

Lista de desejos

Todas as rotas requerem um JWT.

Método Caminho Autenticação Descrição
PEGAR /api/v1/me/wishlist JWT { titleIds: guid[] }
COLOCAR /api/v1/me/wishlist/{titleId} JWT Adicionar à lista de desejos, 204 (idempotente)
EXCLUIR /api/v1/me/wishlist/{titleId} JWT Remover da lista de desejos, 204

Avaliações

Todas as rotas requerem um JWT. A chave uniforme do jogo é um guia de catálogo ou "provider:externalId" para jogos externos (veja external-libraries.md).

Método Caminho Autenticação Descrição
COLOCAR /api/v1/me/ratings JWT Aumentar minha classificação para um jogo
PUBLICAR /api/v1/ratings/query JWT Resumos de classificação de busca em lote
PEGAR /api/v1/ratings/reviews?key=&top= JWT Críticas de um jogo (top padrão 10)

COLOCAR corpo:

{
  "gameKey": "…",
  "stars": 4,
  "review": "…"
}

stars é 0–5; review é opcional. A resposta é uma RatingSummaryDto:

{
  "gameKey": "…",
  "average": 4.5,
  "count": 12,
  "myStars": 4
}

POST /api/v1/ratings/query corpo e resposta:

{
  "keys": ["…", "…"]
}

retorna RatingSummaryDto[]. GET /api/v1/ratings/reviews retorna GameReviewDto[]:

[
  {
    "userId": "…",
    "username": "…",
    "stars": 4,
    "review": "…",
    "timestamp": "…"
  }
]
