Bater papo

O bate-papo do StarHermit abrange mensagens diretas, salas de grupo e conversas em sessões de jogo por meio de uma API REST (api/v1/chat) além de um canal push WebSocket servidor para cliente (ws/v1/chat). Todos os endpoints REST requerem autenticação. Os corpos de erro variam; ver Convenções de API.

Pontos de extremidade REST

Base: https://api.starhermit.com/api/v1/chat.

Método Caminho Autenticação Descrição
PUBLICAR /conversations JWT Crie uma conversa (1 amigo = direto, ≥2 = grupo)
CORREÇÃO /conversations/{id} JWT Renomear uma conversa (qualquer membro)
PUBLICAR /conversations/{id}/invites JWT Convidar um usuário para um grupo
PEGAR /invites JWT Liste seus convites de bate-papo pendentes
PUBLICAR /invites/{id}/accept JWT Aceitar um convite de bate-papo
PUBLICAR /invites/{id}/decline JWT Recusar um convite para bate-papo
PEGAR /rooms/joinable JWT Listar salas abertas com ≥1 amigo dentro
PUBLICAR /conversations/{id}/join JWT Participe de uma sala aberta (deve ser amigo de um membro)
PUBLICAR /conversations/{id}/participants JWT Adicionar participantes a uma conversa
EXCLUIR /conversations/{id}/participants/{userId} JWT Remover um participante (próprio: qualquer membro; outros: somente criador do grupo)
PUBLICAR /conversations/{id}/leave JWT Sair de uma conversa
PEGAR /conversations JWT Liste conversas, incluindo cada contagem não lida
PEGAR /conversations/{id} JWT Receba uma conversa, incluindo a contagem de mensagens não lidas
PEGAR /unread JWT Obtenha a contagem total de mensagens não lidas
PUBLICAR /conversations/{id}/read JWT Marcar uma conversa como lida
PEGAR /conversations/{id}/messages?page=&pageSize= JWT Obter histórico de mensagens paginadas
PUBLICAR /conversations/{id}/messages JWT Envie uma mensagem (taxa limitada)
COLOCAR /conversations/{conversationId}/messages/{messageId} JWT Editar uma mensagem
EXCLUIR /conversations/{conversationId}/messages/{messageId} JWT Excluir uma mensagem (lápide)

Crie uma conversa

POST /conversations

{
  "participantIds": ["<guid>"],
  "name": "Friday night lobby",
  "friendUserId": "<guid>",
  "joinPolicy": "closed"
}

Todos os campos são opcionais. Um amigo participante cria um direto conversa; dois ou mais criam um grupo. joinPolicy é "open" ou "closed" (padrão "closed"). Retorna um ConversationDto.

Renomear uma conversa

PATCH /conversations/{id} com { "name": "New name" } → ConversationDto. Qualquer membro pode renomear; uma nota do sistema com kind: "system_rename" é transmitido.

Convites

POST /conversations/{id}/invites com { "toUserId": "<guid>" } → ChatInviteDto. Os convites são a única forma de entrar em uma sala fechada.

GET /invites → ChatInviteDto[]:

[
  {
    "id": "<guid>",
    "conversationId": "<guid>",
    "conversationName": "Friday night lobby",
    "fromUserId": "<guid>",
    "fromUsername": "alice",
    "toUserId": "<guid>",
    "status": "pending",
    "createdAt": "2026-07-22T07:00:00Z"
  }
]

POST /invites/{id}/accept e POST /invites/{id}/decline → ChatInviteDto.

Ingressando em salas

GET /rooms/joinable → JoinableRoomDto[] — salas abertas que tenham pelo menos um de seus amigos dentro:

[
  {
    "id": "<guid>",
    "name": "Friday night lobby",
    "joinPolicy": "open",
    "createdAt": "2026-07-22T07:00:00Z",
    "participants": [{ "userId": "<guid>", "username": "alice" }]
  }
]

POST /conversations/{id}/join → ConversationDto. Entra em uma sala aberta; você deve ser amigo de um membro.

Participantes

POST /conversations/{id}/participants com { "participantIds": ["<guid>"] } → ConversationDto.

DELETE /conversations/{id}/participants/{userId} → 204. Qualquer membro pode retirar-se; remover outros exige ser o criador do grupo.

POST /conversations/{id}/leave → 204.

Lendo conversas

GET /conversations → ConversationDto[].

GET /conversations/{id} → ConversationDto:

{
  "id": "<guid>",
  "type": "group",
  "name": "Friday night lobby",
  "createdByUserId": "<guid>",
  "joinPolicy": "closed",
  "createdAt": "2026-07-22T07:00:00Z",
  "participants": [{ "userId": "<guid>", "username": "alice" }],
  "otherParticipant": { "userId": "<guid>", "username": "bob" },
  "unreadCount": 3
}

type é um dos direct, group, game. name, createdByUserId, e otherParticipant pode estar ausente. unreadCount conta mensagens de texto não lidas enviadas por outros membros após o horizonte de leitura por conversa do chamador.

Estado não lido

GET /unread retorna a contagem de não lidas em todas as conversas do chamador:

{ "total": 7 }

POST /conversations/{id}/read avança o horizonte de leitura do chamador para essa conversa. Use-o depois de exibir a transcrição atual. O servidor emite um conversation_read evento para todos os soquetes pertencentes ao chamador, permitindo que vários clientes conectados limpem seus crachás. Mensagens novas e excluídas podem alterar o total, portanto os clientes devem atualizar a partir de eventos WebSocket ou buscar periodicamente /unread.

Mensagens

GET /conversations/{id}/messages?page=1&pageSize=50 → PagedMessagesDto:

{
  "conversationId": "<guid>",
  "page": 1,
  "pageSize": 50,
  "totalCount": 123,
  "items": []
}

POST /conversations/{id}/messages com { "content": "hello" } → MessageDto. Taxa limitada a 10 mensagens/minuto por usuário; excedê-lo retorna 429.

PUT /conversations/{conversationId}/messages/{messageId} com { "content": "edited" } → MessageDto.

DELETE /conversations/{conversationId}/messages/{messageId} → 204. A exclusão é uma lápide: a mensagem permanece com isDeleted: true.

MessageDto:

{
  "id": "<guid>",
  "conversationId": "<guid>",
  "senderId": "<guid>",
  "senderUsername": "alice",
  "content": "hello",
  "kind": "text",
  "metadata": { "key": "value" },
  "sentAt": "2026-07-22T07:00:00Z",
  "editedAt": null,
  "isDeleted": false
}

kind é "text" ou "system_rename"; content, metadata (a Dictionary<string,string>), e editedAt pode estar ausente/nulo.

WebSocket: ws/v1/chat

Conecte-se a wss://api.starhermit.com/ws/v1/chat com um JWT por meio do Authorization cabeçalho, ?ticket=, ou ?access_token=.

Este é um canal push servidor→cliente puro: os frames do cliente são ignorados (somente Close é homenageado). Cada quadro é um envelope:

{ "type": "<event>", "payload": { } }
Evento type Carga útil
conversation_created ConversationDto
conversation_renamed ConversationDto
participants_added ConversationDto
participant_removed ConversationDto
chat_invite ChatInviteDto
chat_invite_responded ChatInviteDto
new_message MessageDto
message_updated MessageDto
message_deleted MessageDto
conversation_read Mudança de estado de leitura para o usuário conectado; recuperar contagens não lidas
game_invite { "inviteId", "kind", "gameSlug", "gameName", "roomId", "from": { "userId", "username" }, "createdAt", "acceptPath", "declinePath", "inProgress", "sessionId" } - Veja abaixo

game_invite: um evento para ambos os sistemas de convite

Qualquer pessoa pode ser convidada para jogar de duas maneiras, e este único evento traz ambas — um cliente implementa um brinde, não dois:

kind Emitida pela Aceitando
"session" POST /games/{slug}/invites Cria uma nova sessão de jogo para vocês dois
"room" POST /realtime/rooms/{id}/invites Senta-se em uma sala onde o convidante já está sentado; roomId é aquele quarto

acceptPath e declinePath são os pontos finais que respondem esse convide - use-os e a distinção nunca importa. Responder no ponto final do outro sistema é uma 404: os dois mantêm IDs de convite separados.

inProgress é true ao aceitar entrar em um jogo que já está sendo jogado — um convite de sessão que nomeia uma sessão em andamento ou um convite de sala para uma sala iniciada que permite entrar em andamento — e sessionId é a sessão desse jogo. Use-o para dizer "junte-se ao jogo deles" em vez de "jogar".

{
  "type": "game_invite",
  "payload": {
    "inviteId": "e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b",
    "kind": "room",
    "gameSlug": "poker",
    "gameName": "StarHermit Poker",
    "roomId": "b1d2c3e4-5f60-4a71-8b92-c3d4e5f60718",
    "from": { "userId": "9b2f8c1a-1111-4222-8333-444455556666", "username": "alice" },
    "createdAt": "2026-07-26T14:10:00Z",
    "acceptPath": "/api/v1/realtime/rooms/invites/e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b/accept",
    "declinePath": "/api/v1/realtime/rooms/invites/e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b/decline"
  }
}

roomId é null para "session" convida. Um token de inicialização no escopo do jogo não pode abrir este soquete ou ler o token de toda a conta /me/game-invites caixa de entrada. Enquete de clientes de jogos GET /api/v1/games/{slug}/invites para convites de sessão e GET /api/v1/realtime/rooms/invites para os convites da sala de jogos. Os clientes da conta podem ler ambos os tipos GET /api/v1/me/game-invites.

Converse dentro de uma sessão de jogo

Um token de lançamento no escopo do jogo não pode abrir ws/v1/chat — está bloqueado porque o soquete transmite todas as conversas de um usuário. Tokens de lançamento poderia usam a API REST de bate-papo em conversas anexadas às suas próprias sessões de jogo: o detalhe da sessão retorna um chatConversationId, a conversa tem tipo "game", seus participantes são os jogadores da sessão e as regras de amizade são ignoradas.

Os clientes do jogo, portanto, normalmente carregam o histórico em REST e pesquisam novas mensagens em vez de usar o soquete. Por exemplo, o implementação de referência de xadrez enquetes a cada 5 segundos:

GET /api/v1/chat/conversations/{chatConversationId}/messages?page=1&pageSize=50
Authorization: Bearer <launch-token>

POST /api/v1/chat/conversations/{chatConversationId}/messages
Authorization: Bearer <launch-token>
Content-Type: application/json

{ "content": "good game" }
