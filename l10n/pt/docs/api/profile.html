Perfil

A API de perfil cobre a própria conta do usuário autenticado (/api/v1/me/...), pesquisas públicas de outros usuários, chaves públicas, identidades vinculadas, configurações de privacidade, direitos e pulsação de presença. As rotas de conta requerem autorização; o documento dos termos atuais é público.

Os corpos de erro variam; ver Convenções de API.

Pontos finais

Método Caminho Autenticação Descrição
PEGAR /api/v1/me JWT (Permission-user.profile.read) Obtenha seu próprio perfil
CORREÇÃO /api/v1/me JWT (Permission-user.profile.update) Atualizar nome de usuário, e-mail, metadados ou apelido
PEGAR /api/v1/terms Anônimo Leia os termos atuais do StarHermit e seu hash
PUBLICAR /api/v1/me/terms/accept JWT da conta ou token de lançamento do jogador Aceite os termos atuais do StarHermit
COLOCAR /api/v1/me/avatar JWT (Permission-user.profile.update) Carregue seu avatar
PEGAR /api/v1/me/avatar JWT (Permission-user.profile.read) Obtenha seu avatar
PEGAR /api/v1/users/{id}/avatar JWT Obtenha o avatar de qualquer usuário
PEGAR /api/v1/users/{id}/profile JWT Obtenha o perfil público de qualquer usuário
PEGAR /api/v1/me/public-keys JWT (Permission-user.profile.read) Liste suas chaves públicas
PUBLICAR /api/v1/me/public-keys Autenticado por OAuth JWT (Permission-user.profile.update) Adicione uma chave pública imediatamente
EXCLUIR /api/v1/me/public-keys/{keyId} Autenticado por OAuth JWT (Permission-user.profile.update) Revogar uma chave e suas sessões
EXCLUIR /api/v1/me/public-keys/all Autenticado por OAuth JWT (Permission-user.profile.update) Revogar todas as chaves ativas e suas sessões
EXCLUIR /api/v1/me/public-keys/current Sessão de chave pública (Permission-user.profile.update) Revogar a chave com a qual esta sessão entrou e suas sessões. Não nomeia nenhuma chave, portanto não pode alcançar um irmão; uma sessão sem chave obtém 409 no_public_key_session
PEGAR /api/v1/me/identities JWT (Permission-user.profile.read) Liste suas identidades vinculadas
PUBLICAR /api/v1/me/identities JWT (Permission-user.profile.update) Vincular uma identidade (somente provedores não OAuth)
EXCLUIR /api/v1/me/identities/{identityId} JWT (Permission-user.profile.update) Desvincular uma identidade
PEGAR /api/v1/me/privacy JWT (Permission-user.profile.read) Obtenha suas configurações de privacidade
COLOCAR /api/v1/me/privacy JWT (Permission-user.profile.update) Substitua suas configurações de privacidade
PEGAR /api/v1/me/entitlements JWT (Permission-user.profile.read) Liste seus direitos de software
PUBLICAR /api/v1/me/heartbeat JWT Batimento cardíaco de presença (estrangulado LastSeenAt escrever)

PATCH /api/v1/me

Todos os campos são opcionais. Restrições: username 1–32 caracteres; nickname ≤64 caracteres (muitos as contas não têm nenhuma); metadata ≤4096 caracteres. Nomes de usuário e apelidos compartilham um namespace que não diferencia maiúsculas de minúsculas: 409 quando outra conta usa o nome como nome de usuário ou apelido, ignorando o caso. Os apelidos são normalizados por NFKC e os caracteres de controle ou invisíveis são 400. Mudando email requer adicionalmente uma Sessão autenticada pelo OAuth porque o e-mail da conta pode aprovar links de credenciais; uma chave pública ou sessão de verificação de e-mail obtém 403 para esse campo, mas ainda pode atualizar os outros. Retorna 204 em sucesso, 409 em conflito (nome de usuário ou apelido já utilizado).

{
  "username": "newname",
  "email": "new@example.com",
  "metadata": "{}",
  "nickname": "New Nick"
}

Aceitação dos termos

Antes de usar endpoints REST protegidos ou abrir WebSockets, a conta deve aceitar o atual Termos do StarHermit. Isto se aplica a tokens de conta e tokens de lançamento de jogadores, incluindo contas que aceitou uma revisão mais antiga. Não se aplica a recursos/login anônimos ou a um servidor de contêiner próprio token de implantação. GET /api/v1/me e o endpoint de aceitação permanecem disponíveis com seus valores habituais permissões de conta enquanto a aceitação estiver pendente.

GET /api/v1/me inclui currentTermsHash e termsAcceptanceRequired. O armazenado termsAcceptedHash e termsAcceptedAt são nulos antes da primeira aceitação. O hash mostrado no o exemplo de perfil acima é abreviado; sempre use o hash completo retornado pela API.

GET /api/v1/terms

Anônimo; também legível com um token de lançamento do jogador. Devoluções 200 com Cache-Control: no-store:

{ "hash": "<current-64-character-lowercase-sha256>", "text": "<complete terms text>" }

Renderizar text como texto simples. hash é SHA-256 dos bytes exatos do documento UTF-8; use o retornado valor em vez de hash do texto de exibição reformatado.

POST /api/v1/me/terms/accept

Após o usuário ler e aceitar explicitamente a revisão exibida, envie seu hash:

POST /api/v1/me/terms/accept
Authorization: Bearer <account-access-token>
Content-Type: application/json

{ "hash": "<hash-returned-with-the-displayed-text>" }

Devoluções 200 com { "termsAcceptedHash", "termsAcceptedAt" }. Sessões OAuth e de conta de chave pública e tokens de lançamento no escopo do jogo do jogador pode aceitar. Um token de servidor de contêiner não pode atuar em nome de um jogador. A aceitação é armazenada na conta e entra em vigor no próxima solicitação com o mesmo token ainda válido; atualizar o token é desnecessário.

Um hash ausente/em branco ou com mais de 64 caracteres retorna 400. Um hash que não exatamente corresponder aos retornos da revisão atual 409:

{
  "error": "terms_version_mismatch",
  "termsHash": "<current-hash>",
  "termsUrl": "/api/v1/terms"
}

Buscar e exibir o novo documento e solicitar novamente o aceite; não aceite silenciosamente uma substituição revisão. Outras solicitações protegidas com retorno de aceitação pendente 403:

{
  "error": "terms_acceptance_required",
  "message": "Accept the latest terms of service before using the API.",
  "termsHash": "<current-hash>",
  "termsUrl": "/api/v1/terms",
  "acceptUrl": "/api/v1/me/terms/accept"
}

Um jogo hospedado pode exibir os termos e enviar o hash exibido com seu token de inicialização do jogador quando o jogador pressionar Aceitar e tente novamente. Também pode enviar o jogador para a interface de usuário de sua conta. O login repetido ou a atualização do token não corrigem a aceitação pendente. As atualizações do WebSocket são recusadas com HTTP 403 antes de abrir; os navegadores podem ocultar o corpo da resposta, portanto, lide com a aceitação por meio do REST antes de conectar.

Exemplo para uma conta ou cliente de jogo (chame acceptDisplayedTerms somente a partir da ação Aceitar do usuário):

const api = 'https://api.starhermit.com';
async function loadTerms() {
  const response = await fetch(`${api}/api/v1/terms`);
  if (!response.ok) throw new Error(`Terms fetch failed: ${response.status}`);
  return response.json(); // Display text, retain this document's hash.
}
async function acceptDisplayedTerms(accountToken, displayedTerms) {
  const response = await fetch(`${api}/api/v1/me/terms/accept`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${accountToken}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ hash: displayedTerms.hash })
  });
  if (response.status === 409) {
    throw new Error('Terms changed. Reload and display them for a new acceptance.');
  }
  if (!response.ok) throw new Error(`Acceptance failed: ${response.status}`);
  return response.json();
}

Avatares

PUT /api/v1/me/avatar aceita uma imagem PNG, quadrada, ≤512×512 pixels, ≤1 MB:

{ "imageBase64": "iVBORw0KGgoAAAANSUhEUg..." }

Retorna 204. GET /api/v1/me/avatar retorna seu avatar como image/png bytes.

Outros usuários

  • GET /api/v1/users/{id}/avatar — Avatar PNG para qualquer usuário.
  • GET /api/v1/users/{id}/profile:

  "nickname": "Al"
}

Chaves públicas

Uma chave registrada é uma credencial de API: seu titular pode completar o fluxo de desafio de chave pública e receba um token de acesso/atualização comum par. Isso torna uma chave rotulada separadamente adequada para um cliente de desktop ou pipeline de implantação.

Adicionar chaves ou revogar outras chaves requer uma sessão autenticada por OAuth. Uma chave pública sessão pode revogar apenas sua própria chave através DELETE /api/v1/me/public-keys/current. Não pode inscrever substituições ou revogar outros dispositivos. A listagem permanece disponível para qualquer sessão completa da conta; o lançamento do jogo e os tokens do servidor não podem gerenciar as chaves da conta.

GET /api/v1/me/public-keys

A lista inclui linhas revogadas como trilha de auditoria:

[
  {
    "id": "9b2f5c74-1d2e-4a6b-8c0d-1e2f3a4b5c6d",
    "keyType": "Ed25519",
    "keyData": "<base64-raw-32-byte-public-key>",
    "label": "orbit-league-production",
    "fingerprint": "4d9f3c...",
    "createdAt": "2026-07-01T12:00:00Z",
    "lastUsedAt": "2026-07-30T09:00:00Z",
    "isRevoked": false,
    "revokedAt": null,
    "metadata": null
  }
]

POST /api/v1/me/public-keys

Requer uma sessão autenticada por OAuth e anexa a chave imediatamente; ao contrário do anônimo registro, nenhuma viagem de ida e volta por e-mail é necessária.

{
  "keyType": "Ed25519",
  "keyData": "<base64-raw-32-byte-public-key>",
  "label": "orbit-league-production"
}

label é opcional (máximo de 128 caracteres). Os tipos de chave aceitos são Ed25519, ECDSA-P256, e RSA-PSS; o material deve ser Base64 padrão: uma chave pública bruta de 32 bytes para Ed25519, um P-256 codificado ponto de curva para ECDSA, ou um SPKI público para RSA. As chaves RSA devem ter 2.048 a 8.192 bits. A plataforma canoniza material válido e limita uma conta a 20 chaves ativas por padrão. fingerprint é o resumo hexadecimal SHA-256 minúsculo do canônico keyType:keyData corda.

Devoluções 201 com a chave criada. Devoluções de material inválidas 400; uma chave já ativa ou uma chave completa lista de chaves retorna 409 (este último inclui limit). O material da chave ativa é exclusivo em toda a plataforma.

DELETE /api/v1/me/public-keys/{keyId}

Requer uma sessão autenticada por OAuth. A revogação é idempotente e encerra as sessões de atualização criadas pela chave; os tokens de acesso que o nomeiam são recusados ​​na próxima solicitação. Retorna:

{ "revoked": [{ "id": "...", "isRevoked": true }], "sessionsEnded": 1 }

Uma chave desconhecida nesta conta retorna 404.

DELETE /api/v1/me/public-keys/all

A operação de compromisso-resposta: revogar todas as chaves ativas e encerrar todas as sessões autenticadas. Tem uma explícita /all path para que um ID de chave acidentalmente vazio não possa se tornar uma revogação em massa. Retorna o mesmo { revoked, sessionsEnded } forma.

DELETE /api/v1/me/public-keys/current

Uma sessão de conta completa autenticada com uma chave pública pode revogar a chave usada para essa sessão, sem nomear um ID de chave. Use isso para Esqueça este dispositivo. Ele retorna o mesmo { revoked, sessionsEnded } forma e invalida sessões usando essa chave. Descartar tokens armazenados e a chave privada local após sucesso. Uma sessão sem retorno de chave pública 409 com code: "no_public_key_session"; os tokens de lançamento do jogo são recusados.

Para obter um exemplo completo de implantação de máquina, consulte Fazer upload de builds de CI/CD com uma chave pública registrada em OAuth.

    "providerUserId": "12345678",

    "metadata": "{\"login\":\"octocat\"}"
  }
]

POST /api/v1/me/identities

{
  "provider": "epic",
  "providerUserId": "your-epic-account-id",
  "metadata": null
}

O provedor nomeia a plataforma como OAuth (google, github, discord, twitch, gitlab, linkedin, bitbucket, mais nomes reservados microsoft, facebook, twitter, x, apple, steam) são rejeitado aqui, independentemente de esse provedor estar configurado ou não - essas identidades são vinculável apenas por meio de um login real. Use um nome não reservado (epic, gog, um ID de vitrine personalizado). Ver Autenticação.

DELETE /api/v1/me/identities/{identityId}

A remoção de uma identidade gerenciada pelo OAuth requer uma sessão autenticada pelo OAuth, portanto, uma chave pública roubada não é possível remover a rota do proprietário de volta à conta. Retorna 204.

Batimento cardíaco de presença

POST /api/v1/me/heartbeat

Retorna 204. Escreve LastSeenAt lado do servidor, limitado – este é o sinal de presença usado por amigos e bate-papo.

Tokens de lançamento no escopo do jogo

Dos endpoints desta página, um token de inicialização no escopo do jogo só pode chamar:

  • GET /api/v1/users/{id}/avatar
  • GET /api/v1/users/{id}/profile
  • GET /api/v1/me/friends (ver Amigos)
  • GET /api/v1/terms
  • POST /api/v1/me/terms/accept
  • POST /api/v1/me/heartbeat

Todo o resto retorna 403 sob a cerca do escopo do jogo descrita em Autenticação.

Convenção de nome de exibição

As interfaces de jogo normalmente exibem apelidos em vez de nomes de usuário ao renderizar oponentes, recorrendo a algo como "Player " + id.slice(0,8) quando nenhum apelido está definido. A implementação de referência do xadrez segue esta convenção; outros clientes de jogos devem fazer o mesmo.

Ver compatibilidade de credenciais e contratos legíveis por máquina.
