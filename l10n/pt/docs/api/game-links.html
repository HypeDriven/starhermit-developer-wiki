Links externos

Um jogo com mecanismo StarHermit (host API 1.24) pode abrir uma página da web, mas apenas uma que a equipe do StarHermit aprovou para o seu jogo. Seu jogo abre um link por id e nunca passa uma URL, então não pode adicionar qualquer coisa para um.

Declare seus links

Em starhermit.txt:

engine.minor=24
engine.capabilities=platform
engine.link.discord=https://discord.gg/abc
engine.link.store=https://example.com/game
  • Você pode declarar até 16 links. Cada ID tem de 1 a 32 caracteres de a-z 0-9 - e pode aparecer apenas uma vez.
  • Qualquer engine.link.* principais necessidades engine.minor=24, então tempos de execução mais antigos recusam o jogo.
  • Um jogo de produção também precisa engine.capabilities=platform, porque o tempo de execução verifica a aprovação com o token de lançamento do jogador. Sem isso, openLink resolve "unavailable" fora desenvolvimento e o manifesto recebe um aviso.

Abra um link

openLink(id) de starhermit:engine retorna Promise<"opened" | "cancelled" | "unapproved" | "unavailable">:

  • "unapproved": o link está pendente, rejeitado ou revogado, seu URL é diferente do aprovado ou o id não é declarado.
  • "unavailable": nenhuma sessão de plataforma, erro de rede, 401/403/429 ou nenhuma resposta em 10 s.

Chame-o enquanto pressiona (ponteiro, tecla ou gamepad); cada toque abre no máximo um link. Uma chamada fora de um pressionamento, uma segunda chamada enquanto uma está pendente e uma chamada dentro de 2 s após o cancelamento do jogador todos resolvem "unavailable" e registre um aviso.

O tempo de execução mostra sua própria confirmação, com o host completo e URL do link, e abre apenas a página se o jogador escolher Abrir. Nos navegadores, o Voltar do gamepad é cancelado, mas a confirmação precisa de um clique, toque, Enter ou Espaço, porque um navegador abre uma janela apenas a partir deles.

O que pode ser um link

Um link deve ser https, sem porta, não user@, sem endereço IP e sem nome local (localhost, .local, .internal). Seu host deve ser ASCII, com nomes internacionalizados escritos como punycode, e ter pelo menos dois rótulos. Não pode conter barras invertidas, espaços, os caracteres " < > ` { } | ^, malformado % escapes, barras codificadas (%2f, %5c) ou ./.. segmentos de caminho. A plataforma mantém a forma canônica: o esquema e o host em minúsculas e / para um caminho vazio. Todo o resto é mantido exatamente como você escreveu.

Um pacote com um link que quebra uma regra é recusado quando você publica, com 422 invalid_link: engine.link.<id> is not an allowed link (<rule>), antes de qualquer coisa ir ao ar.

Análise

Cada novo link inicia pending, e o tempo de execução não abre nada até que a equipe o aprove. Alguns links são rejeitados automaticamente: encurtadores de URL e serviços de redirecionamento, cujo destino outra pessoa controles e downloads diretos de programas e arquivos (.exe, .dmg, .apk, .zip e semelhante). Parâmetros de rastreamento como utm_* são sinalizados para o revisor.

Uma aprovação pertence ao seu jogo e ao URL exato. Uma versão posterior listando o mesmo URL, em qualquer id, mantém. A alteração do URL precisa de uma nova revisão. A equipe pode revogar uma aprovação ou bloquear uma anfitrião inteiro, a qualquer momento.

Veja seus links e seus status em GET /api/v1/me/github-games/{id}/links:

[ { "id": "discord", "url": "https://discord.gg/abc", "status": "approved", "autoReason": null, "note": null } ]

As verificações de tempo de execução GET /api/v1/games/{slug}/links/{id} a cada abertura, com o lançamento do jogador ficha. A resposta é { id, url, status }, onde status é approved, pending, rejected ou revoked, ou 404 link_unknown para um ID que seu manifesto implantado não declara.

Enquanto você desenvolve localmente (--dev nativamente ou uma página de loopback no navegador, sem inicialização token), o tempo de execução abre links declarados atrás de um aviso de que eles não foram revisados.
