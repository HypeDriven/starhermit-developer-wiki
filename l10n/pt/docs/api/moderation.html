Moderação de conteúdo

Os jogos verificam textos compartilhados, documentos JSON e imagens PNG/JPEG/WebP antes de mostrá-los a outros jogadores. Apenas uma corrente allow autoriza o compartilhamento. review, block, desconhecido, pendente, com falha, resultados de políticas expiradas e incompatíveis mantêm o conteúdo oculto.

As verificações de moderação estão atualmente indisponíveis na implantação pública. Leia a descoberta antes permitindo o compartilhamento. Devolução de cheques 503 overloaded com Retry-After: 300; isso não promete disponibilidade após cinco minutos. Mantenha o conteúdo oculto até receber uma decisão de permissão atual. A geração também é indisponível.

O contrato abaixo descreve as chamadas de moderação suportadas e seu comportamento quando disponíveis. Somente evidências acessíveis e selecionadas são retornadas por meio das APIs de revisão do proprietário.

Chamadores e rotas

O prefixo do jogador é /api/v1/games/{slug}/moderation. JWTs e tokens de lançamento carregam o jogador; um token de lançamento deve corresponder a este jogo. Um token de servidor de contêiner ativo também deve corresponder ao jogo. Nativo os clientes usam o URL base da API; jogos de navegador podem usar a origem do jogo /api procuração.

Método Sufixo Chamador Resultado
PEGAR (raiz) Jogador ou servidor Disponibilidade, limites efetivos, conteúdo suportado e política atual
PUBLICAR /check Jogador ou servidor 200 lote completo ou 202 cheque pendente
PEGAR /checks/{checkId} Jogador atribuído ou criação de servidor de jogo 200 status; 410 após retenção do resultado
PUBLICAR /decisions/lookup Jogador ou servidor 200 hashes qualificados conhecidos/desconhecidos
PUBLICAR /flags Jogador 201 recibo de bandeira; servidores não podem arquivar sinalizadores
PEGAR /removed?since=&pageSize= Jogador ou servidor Retiradas paginadas e próximo cursor

Os jogadores não podem verificar como outro jogador. Um servidor normalmente envia sessionId e participantUserId; o participante deve estar em uma sessão ativa deste jogo, e sua taxa de cheque é cobrada. Por um verificação persistente do mundo sem ninguém online, envie attribution: "game" e omitir ambos os campos. Isso consome uma taxa de servidor separada e o orçamento do jogo, não registra nenhum jogador e permite pesquisas apenas pela identidade do servidor autorizado do jogo. A atualização do token não altera essa identidade lógica.

Disponibilidade

GET /api/v1/games/{slug}/moderation retorna:

{
  "checksAvailable": false,
  "contentReportingAvailable": false,
  "disabledReason": "moderation_not_configured",
  "policyVersion": "<current effective version>",
  "supportedKinds": ["text", "image"],
  "supportedContexts": ["chat", "name", "generated-content", "user-content"],
  "limits": { "moderation.check.items": 20, "moderation.decision.allow_ttl_seconds": 3600 },
  "acceptedPreviousPolicyVersion": null,
  "previousPolicyValidUntil": null,
  "deliveredContentGraceSeconds": 0
}

limits contém os valores efetivos do registro de moderação, além dos dois ilustrados. Jogador os valores incluem as substituições desse jogador; descoberta de servidor revela permissões de jogo, nunca outra do jogador. Um orçamento zero para itens de jogo também desativa a verificação (game_budget_disabled). Use os valores retornados de sobreposição de política e tolerância; os padrões não fornecem nenhum dos dois.

Verifique o conteúdo exato

POST /api/v1/games/{slug}/moderation/check
Authorization: Bearer <launch-token>
Content-Type: application/json

{
  "items": [
    { "id": "story", "kind": "text", "context": "user-content", "text": "abc" }
  ]
}

Os IDs dos itens são exclusivos em um lote e têm no máximo 128 caracteres. O texto carrega apenas text; imagens carregar contentType e padrão rigoroso acolchoado dataBase64, sem espaços em branco. Imagem declarada os tipos devem corresponder aos seus cabeçalhos e os bytes e pixels são limitados. WAV, Ogg Vorbis, Modelos e fontes glTF não são suportados (415 unsupported_kind); o suporte de áudio é adiado.

O hash é sha256: seguido por 64 dígitos hexadecimais minúsculos de SHA-256 sobre os bytes de conteúdo exatos:

  • Para texto, decodifique a string em JSON e codifique seus valores escalares Unicode como UTF-8 sem uma lista técnica. Preservar espaços em branco, finais de linha e normalização Unicode; rejeitar substitutos não pareados.
  • Um documento JSON enviado como texto é hash como sua string de documento exata, sem análise, reordená-lo ou reserializá-lo.
  • Para uma imagem, faça hash dos bytes decodificados antes de redimensionar, transcodificar ou alterar metadados.

Os três bytes ASCII abc hash para sha256:ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad. Adicionar uma nova linha altera o hash. O envelope de solicitação, ID do item, contexto, tipo de mídia e base64 codificação não é entrada hash. A plataforma calcula os hashes enviados; receber jogos também deve hash os bytes que eles realmente contêm e compare o identificador.

Um item completo tem status: "complete", contentHash, decision, categorias, revisão, checkedAt e decisionPolicyVersion. Somente uma permissão carrega validUntil. O envelope de resposta tem a corrente efetiva policyVersion. A validação recusa todo o lote se algum item for malformado. Um item aceito pode falhar separadamente, com status: "failed", um código e nenhuma decisão.

O prazo síncrono é padronizado como dois segundos. Itens inacabados são produzidos 202 com checkId, pollAfterSeconds, expiresAt e Retry-After. Pesquise o cheque; itens pendentes não têm decisão. O prazo padrão em segundo plano é 60 segundos, então um item inacabado falha com timeout e sua entrada normal é apagada. Os resultados do terminal permanecem legíveis por uma hora por padrão.

A pesquisa de um item concluído consulta a decisão qualificada em tempo real, a política atual e a retenção. Um cheque antigo não pode renovar uma aprovação retirada. Os bloqueios/revisões atuais são retornados como tal; decisões obsoletas, expiradas ou ausentes geram um item com falha sem validade renovada.

Recuperação de pesquisa e retirada

{
  "hashes": ["sha256:ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad"],
  "kind": "text",
  "context": "user-content"
}

Envie isto para /decisions/lookup. Pesquisas de imagens também nomeiam contentType. A aprovação é qualificada por jogo, tipo, tipo de mídia validado e contexto. As entradas são known com uma decisão, revisão, decisionPolicyVersion e permitir validade, ou unknown com not_checked, policy_changed ou expired. Os bloqueios humanos permanecem eficazes após mudanças políticas e retenção normal de decisões.

A validade padrão é de uma hora e pode ser reduzida pela operadora. Revalidar antes do vencimento; não há período de carência habilitado para uma interrupção e nenhuma versão de linha de base anterior aceita. Mudando uma política de jogo invalida imediatamente aprovações anteriores. Uma permissão humana sobrevive apenas a uma nova verificação para resultados idênticos que ainda ultrapassam a linha de base atual sob a mesma política.

Enquete /removed antes de distribuir um pacote compartilhado e regularmente durante o jogo. Ocultar hashes correspondentes e interromper a distribuição em caso de retirada; as remoções incluem sinalizações mantidas e reclassificação de permitir para revisar/bloquear. As entradas do feed incluem qualificadores, escopo, decisão, revisão, política, tempo de remoção e um motivo seguro. Os cursores são marcadores de ordenação opacos; use o cursor retornado em vez de derivar um de cada vez.

Um cursor expirado retorna 410 cursor_expired. Busque um novo cursor sem since, pesquisa em lote todos os hashes compartilhados carregados e retomados somente quando validados. Ausência no feed nunca é aprovação. Uma cópia local salva não autoriza a redistribuição. O feed tem como padrão 90 dias de histórico; blocos humanos duráveis ​​sobrevivem a isso.

Sinalizadores e avaliação do proprietário

Um jogador envia /flags a reason (no máximo 64 caracteres), opcionalmente limitado notee conteúdo, um jogador alvo, ou ambos. A evidência de conteúdo usa o mesmo formato de item de um cheque. Se contentHash também é fornecido, a plataforma o recalcula e exige igualdade. Um hash simples não é evidência; referências de trabalho/verificação não são implementadas. Uma bandeira jogador-alvo requer um sessionId cuja lista inclui repórter e alvo. Apresentar uma sinalização não altera uma decisão nem automaticamente bloqueia qualquer um.

A evidência de conteúdo é reservada e armazenada em quarentena antes da classificação para roteamento. Atrasado, a triagem com falha ou indisponível nunca abre o acesso do proprietário. Uma triagem atual segura para o proprietário permite listagem/detalhe/download/triagem. As descobertas da equipe ocultam o sinalizador e restringem sinalizadores e revisões existentes da mesma prova. Sem um classificador, os sinalizadores de conteúdo retornam 403 content_reporting_disabled sem aconselhamento de nova tentativa ou provas retidas; sinalizadores somente para jogadores permanecem utilizáveis.

As rotas do proprietário exigem JWT completo e propriedade do jogo, de acordo com /api/v1/me/github-games/{id}/moderation:

Método Sufixo Comportamento
OBTER / COLOCAR /policy Ler/definir classificação e limites de categoria mais rígidos com expectedVersion
PEGAR /flags / /flags/{flagId} Metadados filtrados paginados/um sinalizador acessível
PEGAR /flags/{flagId}/evidence Download controlado; 410 após expiração da evidência
CORREÇÃO /flags/{flagId} action: "uphold" ou "dismiss", nota opcional e expectedRevision
PEGAR /reviews / /reviews/{reviewId} Metadados de revisão retida paginados/uma revisão acessível
PEGAR /reviews/{reviewId}/content Download controlado; 410 review_expired quando indisponível
CORREÇÃO /reviews/{reviewId} action: "allow" ou "block", nota opcional e expectedRevision

As listas levam status, page e pageSize (padrão 20, máximo 100). Apenas uma política mais rigorosa do proprietário a retenção que atualmente ultrapassa a linha de base da plataforma pode ser permitida; retenções de linha de base exigem plataforma revisão fora da API do proprietário do jogo. A evidência restrita nunca é visível ao proprietário. Uma revisão obsoleta é 409 revision_conflict. Decidir uma revisão apaga seu conteúdo retido; expiração também impede o download ou a aprovação. Dispensar um sinalizador não desfaz outro bloco e nenhum proprietário rota levanta um bloqueio humano.

A evidência é um application/octet-stream apego com nosniff, sandbox CSP e no-store. Mantenha notas/motivos como texto não confiável em sua IU de revisão. Não os renderize como marcação nem os use como URLs de anexo.

Limites e erros padrão

Os operadores podem ajustar os limites do jogo; as taxas dos jogadores também suportam substituições por usuário. Leia a descoberta para os valores reais em vigor.

Limite Padrão
Itens/hashes de pesquisa por solicitação 20 / 100
Texto/imagem/total de bytes de conteúdo 64 KiB/5 MiB/10 MiB
Pixels de imagem 20 milhões
Verificações de jogadores/verificações de servidores atribuídas ao jogo por minuto 30 / 30
O chamador lê por minuto 60
Itens verificados ou selecionados por jogo por dia 10,000
Bandeiras por jogador, por jogo, por dia / bandeiras abertas por jogo 20 / 1,000
Sinalizar bytes de nota 4 KiB
Evidência de bandeira pendente/retida por jogo 64 MiB/256 MiB
Evidência de sinalização pendente/retida em toda a plataforma 1 GiB / 4 GiB
Chamadas simultâneas do classificador em toda a plataforma 8
Verifique a entrega/permita validade 1 hora / 1 hora
Suspensão de revisão normal/retenção de sinalização 7 dias / 30 dias

O esgotamento da fila/armazenamento recusa novas evidências em vez de despejar casos ativos. Respeite o acessibilidade e expiração relatadas por cada parâmetro de evidência/revisão.

Erros são { error, code, retryAfterSeconds? }. 400 cobre conteúdo/qualificadores malformados, 401 falta de autenticação, 403 escopo/delegação ou restrições básicas, 404 ausente/inacessível registros, 409 conflitos de hash/revisão/política, 410 conteúdo/verificações/cursores expirados, 413 byte/item/ limites de pixels e 415 tipos/tipos não suportados. 429 cobre tarifas/orçamentos/filas/armazenamento com Retry-After. As interrupções do classificador são 503 moderation_unavailable; o atual não configurado espaço reservado permanece 503 overloaded. Nenhum erro, nova tentativa ou pagamento substitui uma decisão de permissão.

Compartilhado Convenções de API descreve a análise de resposta, carimbos de data/hora, paginação e novas tentativas.
