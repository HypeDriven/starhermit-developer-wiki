Conquistas

Uma conquista pertence exatamente um proprietário, e o proprietário decide quem tem permissão para desbloqueá-lo:

Proprietário Declarado por Desbloqueado por Use-o para
Um jogo autoritário game.achievements em um roteiro ou achievements de um contêiner /describe — ou pelo dono do jogo através /me/github-games/{id}/achievements Apenas o tempo de execução do servidor do jogo - autoridade do servidor Jogos com um server= roteiro ou container.image= back-end
Um título de catálogo (SoftwareTitle) Uma editora, através do API do editor O cliente do jogador, via POST /api/v1/me/achievements/unlock (é necessário ter direito) Títulos distribuídos cujo cliente é a única pessoa que sabe que o jogador ganhou alguma coisa

Os dois são mutuamente exclusivos e a plataforma impõe a divisão:

  • POST /api/v1/me/achievements/unlock recusa conquistas no escopo do jogo - um cliente nunca pode reivindicar um.
  • Os endpoints CRUD do editor também os recusam. Você não precisa de um editor para um jogo que possui: como seu dono você são seu editor, e você gerencia suas conquistas por meio os endpoints do proprietário em vez de.

URL base: https://api.starhermit.com. Todas as rotas estão sob /api/v1/....

Método Caminho Autenticação Descrição
PEGAR /api/v1/games/{slug}/achievements Portador As conquistas de um jogo oficial + o estado de desbloqueio do chamador
PEGAR /api/v1/me/github-games/{id}/achievements JWT (proprietário do jogo) Cada conquista do seu jogo, com seu origin e desbloquear contagem
PUBLICAR /api/v1/me/github-games/{id}/achievements JWT (proprietário do jogo) Crie uma conquista para o seu jogo → 201
COLOCAR /api/v1/me/github-games/{id}/achievements/{achievementId} JWT (proprietário do jogo) Atualize um que você criou
EXCLUIR /api/v1/me/github-games/{id}/achievements/{achievementId} JWT (proprietário do jogo) Exclua um que você criou e ninguém desbloqueou → 204
PEGAR /api/v1/software/{titleId}/achievements Anônimo As definições de conquistas de um título de catálogo
PEGAR /api/v1/me/achievements?titleId= JWT Os desbloqueios do chamador (todos os proprietários ou um título)
PUBLICAR /api/v1/me/achievements/unlock JWT Desbloqueio reivindicado pelo cliente — apenas títulos de catálogo

Leia os erros defensivamente, conforme descrito em Convenções de API. POST /me/achievements/unlock retorna seu 400 razão como texto simples.

Conquistas de jogos com autoridade de servidor

Este é o mecanismo qualquer o jogo deve ser usado quando tiver um back-end de script ou contêiner. O o tempo de execução do servidor é o único gravador. Deve validar que o jogador ganhou cada desbloqueio; rejeitando os envios diretos da API por si só não validam eventos relatados por um cliente modificado.

1. Declare-os em seu script

Adicione uma estática achievements matriz para o game objeto - veja Scripts de jogo – Conquistas para o contrato completo:

globalThis.game = {
  achievements: [
    { key: "first-win",  name: "First Win",  description: "Win a match.", points: 10 },
    { key: "flawless",   name: "Flawless",   description: "Win without conceding.",
      points: 50, secret: true, icon: "https://cdn.example/flawless.png" }
  ],
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

A declaração é lida quando o jogo é publicado ou atualizado de seu repositório. Publique uma atualização para aplicar uma alteração.

2. Desbloqueie-os de qualquer gancho de ciclo de vida

Retornar um achievements map — id do usuário → array de chaves — de createSession, onPlayerMessage, ou onTick:

return {
  ok: true,
  sessionState: state,
  achievements: { [winnerId]: ["first-win", "flawless"] },
  result: { kind: "win", winner: winnerId }
};

Os desbloqueios são idempotente - retornar uma chave que o jogador já possui não é operacional, então um script pode reafirme uma conquista a cada tick sem se preocupar com duplicatas.

3. O jogador é notificado pelo soquete de jogo

Cada desbloqueio recém-concedido é enviado apenas ao jogador ganhador, em ws/v1/games, como seu próprio quadro tipo (verdade da plataforma, não retransmitida por script game mensagem):

{
  "type": "achievement",
  "data": {
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "points": 10,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
}

Desbloqueios concedidos de createSession são persistidos antes que alguém tenha um soquete, então eles chegam com sem quadro – leia-os no terminal da lista durante o carregamento.

Back-ends de contêiner

Um contêiner declara os mesmos campos de conquista em GET /describe, em seguida, envia um achievements mensagem em seu controle WebSocket. A plataforma aplica a mesma chave, participante, idempotência e regras de entrega. Ver Servidores de jogos em contêiner.

GET /api/v1/games/{slug}/achievements

Cada conquista declarada pelo jogo, com o estado de desbloqueio do chamador. 404 se a lesma não tiver definição de jogo oficial (um jogo sem script ou back-end de contêiner não tem propriedade do jogo conquistas - veja Quais jogos podem usar isso). Conquistas secretas ficam escondidas até o chamador os desbloqueia. Ordenado por criação e depois por chave.

[
  {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "key": "first-win",
    "name": "First Win",
    "description": "Win a match.",
    "icon": null,
    "secret": false,
    "points": 10,
    "unlocked": true,
    "unlockedAt": "2026-07-25T09:14:02Z"
  }
]

Funciona com um JWT de usuário completo ou um token de inicialização no escopo do jogo.

Quais jogos podem usar isso

O mecanismo está disponível para um jogo que declara um server= roteiro ou um container.image= back-end em starhermit.txt. O o tempo de execução do servidor torna o desbloqueio autoritativo. Os casos de uso apoiados por script incluem:

  • Jogos de plataforma com script - desbloquear de onPlayerMessage / onTick conforme a partida se desenrola.
  • Jogos em tempo real vinculados à sala — a sala em tempo real por um jogo com um server= script cria uma sessão vinculada quando é iniciado, e cada gancho desse sessão pode conceder conquistas.
  • Jogos individuais e de treino — uma sessão contra o assento AI (POST /api/v1/games/{slug}/sessions/ai) executa o mesmo script e o mesmo caminho de desbloqueio.
  • Jogos em tempo real roteados por host - um jogo cuja jogabilidade percorre o canal binário de sala em tempo real ainda pode enviar um script de servidor puramente como sua autoridade de conquista: o início da sala cria a sessão vinculada e o script prêmios de createSession / onTick / durável cmd mensagens enviadas ws/v1/games enquanto o o caminho rápido continua fluindo ws/v1/realtime.

As sessões apoiadas por contêineres também podem declarar e conceder conquistas por meio de seu protocolo. Um jogo com nenhum back-end oficial (um jogo de navegador puro ou construído apenas no retransmissão de pares) não tem caminho de desbloqueio autorizado pelo servidor. O desbloqueio solicitado pelo cliente está disponível apenas para títulos distribuídos por catálogo, abaixo.

Limites e regras

Regra Valor
Conquistas declaradas por jogo 100 (extras ignorados)
Comprimento da chave de conquista 128 caracteres
Chaves de desbloqueio aceitas por jogador, por invocação 32
points fixado em 0–10000; o padrão é 0
name o padrão é o key quando omitido
  • Uma entrada de declaração malformada é ignorado. Um script que não avalia gera um vazio lista; a declaração de um contêiner é lida depois de passar nas verificações de integridade. Verifique com GET /api/v1/games/{slug}/achievements após a implantação.
  • Definições atualizadas por key. Uma chave que seu back-end para de declarar é excluída só se ninguém tiver desbloqueou - a história conquistada nunca é destruída. Conquistas que o proprietário criou por meio da API nunca são tocados por isso: apenas os declarados são reconciliados.
  • Os desbloqueios para usuários que não são participantes da sessão e para a licença AI são ignorados.

Conquistas de outros jogos

Um jogo pode abrir recursos com base no que o jogador desbloqueou outro jogo: uma sequência em homenagem o original, ou jogos de uma série que compartilham cosméticos. Existem duas maneiras de lê-los.

Do seu servidor: ctx.linkedAchievements (confiável)

Nomeie os outros jogos em seu script, ao lado de suas outras declarações:

globalThis.game = {
  linkedAchievements: ["83fd04b1-3cbe-4b09-a251-3733ad4b9d94"], // other games' slugs (uids)
  // ...
};

Um contêiner retorna o mesmo linkedAchievements matriz de GET /describe. Cada roteiro o ctx da invocação carrega as chaves desbloqueadas de cada jogador humano nesses jogos:

ctx.linkedAchievements = {
  "7c9e6679-...": {                                   // player id
    "83fd04b1-3cbe-4b09-a251-3733ad4b9d94": ["first-win", "checkmate-10"]
  }
};
  • É relido cada invocação, então um desbloqueio obtido no outro jogo no meio da partida é visto em o próximo. Um contêiner o recebe no ctx de POST /sessions, isto é, em criar e em restaurar.
  • No máximo 8 jogos; entradas que não são strings não vazias, duplicatas e slugs acima de 100 caracteres são descartados. Como as outras declarações, ela é lida quando o jogo é publicado ou atualizado.
  • Um jogo que declara nada não recebe nenhum linkedAchievements campo e não paga nada.
  • Use esta rota para qualquer coisa que a plataforma deva impor, como desbloquear jogabilidade ou conceder um realização própria.

Do seu cliente: GET /api/v1/games/{slug}/linked-achievements/{otherSlug}

Os próprios desbloqueios do chamador em otherSlug. Não precisa de declaração, portanto, um jogo somente para navegador, sem servidor pode usá-lo e funciona com o token de inicialização para {slug}: os próprios endpoints do outro jogo fique isolado desse token.

{
  "game": "83fd04b1-3cbe-4b09-a251-3733ad4b9d94",
  "hidden": false,
  "unlocked": [
    { "key": "first-win", "unlockedAt": "2026-07-25T09:14:02Z" }
  ]
}

Um cliente pode mentir sobre o que recebeu, então trate isso como uma dica para interface de usuário e cosméticos, não como prova.

O que é divulgado

  • Desbloqueie apenas o estado do jogo que você nomeou: chaves e horários de desbloqueio, nunca nomes, descrições ou a lista de outros jogos que o jogador jogou. Uma conquista secreta que o jogador desbloqueou é incluído.
  • Um slug que não corresponde a nenhum jogo responde como um jogo sem nada desbloqueado.
  • A privacidade é respeitada. Um jogador cuja privacidade de conquistas é Private é escondido: ausente de ctx.linkedAchievements, e "hidden": true com uma lista vazia do endpoint. Oculto não é o mesmo que "não tem nenhum", então não o trate como tal. FriendsOnly (o padrão) é divulgado, porque o leitor está agindo pelo jogador.

Conquistas criadas pelo dono do jogo

Declarar conquistas em código não é a única maneira de dar alguma vantagem ao seu jogo. Se você possui um jogo com um server= roteiro ou container.image= back-end, você também pode criar conquistas para ele por meio do API — da mesma forma que um editor faz para um título de catálogo, sem necessidade de conta ou permissão do editor. Possuir o jogo é a totalidade da concessão. Use isto quando um designer quiser adicionar ou reformular conquistas sem alteração de código ou quando seu back-end concede chaves que ele não declara.

Somente o servidor do seu jogo pode desbloqueá-los, exatamente como os declarados: seu script retorna a chave em achievements, ou seu contêiner o envia no canal de controle. Nada muda no lado de desbloqueio – as chaves são resolvidas contra todos das conquistas do jogo, declaradas e criadas.

{id} é o ID do seu jogo de GET /api/v1/me/github-games.

POST /api/v1/me/github-games/{id}/achievements

{
  "key": "speedrunner",
  "name": "Speedrunner",
  "description": "Finish a level in under a minute.",
  "icon": "https://cdn.example/speedrunner.png",
  "secret": false,
  "points": 25
}

key, name e description são necessários. Devoluções 201:

{
  "id": "…",
  "key": "speedrunner",
  "name": "Speedrunner",
  "description": "Finish a level in under a minute.",
  "icon": "https://cdn.example/speedrunner.png",
  "secret": false,
  "points": 25,
  "origin": "owner",
  "unlocks": 0,
  "createdAt": "…",
  "updatedAt": "…"
}

GET no mesmo caminho lista todas as conquistas do jogo neste formato: origin é declared para aqueles que seu script ou contêiner declara e owner para aqueles criados aqui, e unlocks conta quantos jogadores seguram cada um.

PUT .../achievements/{achievementId} leva qualquer um name, description, icon, secret e points; o key não pode mudar. DELETE remove-o.

Regras

Regra Valor
Chave 1–128 caracteres: letras, dígitos, ., _, -, começando com uma letra ou dígito
name / description obrigatório; no máximo 200/2000 caracteres
points 0–10.000; o padrão é 0
Conquistas criadas pelo proprietário por jogo 200 (além dos até 100 declarados)
  • Uma conquista declarada permanece no seu código. Criar uma chave que o jogo já possui retorna 409, e o mesmo acontece com a edição ou exclusão de um declared um – a próxima atualização o colocaria de volta como seu código declara isso. Altere-o em seu script ou /describe em vez de.
  • Se o seu código declarar posteriormente uma chave que você criou aqui, a declaração leva essa conquista acabou (origin torna-se declared). Os jogadores que o ganharam mantêm-no.
  • Uma conquista que alguém desbloqueou não pode ser excluída (409).
  • 404 significa que o jogo não é seu; 409 em qualquer uma dessas rotas com uma mensagem sobre um servidor back-end significa que o jogo não tem nenhum - um jogo somente para navegador não tem nada que possa desbloquear um conquista.

Conquistas do título do catálogo

Para software distribuído através do catálogo, onde o cliente é a única coisa que observa o condição de desbloqueio. As definições são lidas anonimamente; o desbloqueio requer um JWT e um não revogado direito ao título.

GET /api/v1/software/{titleId}/achievements

AchievementDto[]. As conquistas secretas ficam ocultas, a menos que sejam desbloqueadas pelo chamador (e seu criteria é retido até então). As conquistas do jogo nunca aparecem aqui.

[
  {
    "id": "…",
    "key": "…",
    "name": "…",
    "description": "…",
    "icon": "…",
    "secret": false,
    "points": 10,
    "visibility": "…",
    "criteria": "…"
  }
]

POST /api/v1/me/achievements/unlock

{ "achievementDefinitionId": "…" }

Devoluções 204. Devoluções 400 quando a conquista não existe, quando o chamador não tem direito ao título (ver catalog.md), ou quando a conquista é escopo do jogo - esses são concedido apenas pelo script oficial do jogo ou pelo back-end do contêiner. Desbloquear novamente algo já mantido retorna 204.

O gerenciamento do lado do editor – definindo, atualizando e excluindo conquistas de títulos – reside em publisher.md.

GET /api/v1/me/achievements

O chamador é desbloqueado como UserAchievementDto[]. Sem titleId isso retorna a cada desbloqueio do retenções do usuário, tanto no escopo do jogo quanto no escopo do título; passar ?titleId= para restringi-lo a um título de catálogo.

[
  {
    "id": "…",
    "achievementDefinitionId": "…",
    "key": "…",
    "name": "…",
    "description": "…",
    "icon": "…",
    "points": 10,
    "unlockedAt": "…"
  }
]

Para a tela de conquistas do próprio jogo, prefira GET /api/v1/games/{slug}/achievements, que também retorna as definições que o jogador possui não ainda desbloqueado.
