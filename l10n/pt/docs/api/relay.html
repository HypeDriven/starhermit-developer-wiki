Relé

O relé fornece distribuição de bytes opacos para o netcode do jogo: uma API REST (api/v1/relay) gerencia sessões, e ws/v1/relay encaminha quadros binários literalmente entre os participantes. Cada relé é vinculado a exatamente uma correspondência existente - um sessão de jogo ou um sala em tempo real—e usa a escalação dessa partida para autorização.

Todos os endpoints REST exigem autenticação – um token de usuário completo ou um token de lançamento de jogo para retransmissões vinculado às próprias sessões e salas do jogo: a listagem mostra apenas essas e quaisquer outras respostas de retransmissão 404 (ou 403 para criar um). A retransmissão de um token de lançamento leva o id do seu próprio jogo como titleId - o uid em seu game_scope reivindicação - e qualquer outro título é recusado 403, porque o título por título o limite de sessão é contado por ele. Os erros são retornados como {"error":"..."}: 403 quando o chamador é não está na partida vinculada ou o revezamento pertence a outro jogo, 404 para um relé desconhecido, 409 por um estado que recusa a solicitação (não consolidado, completo, fechado, já ingressado ou no limite da sessão), e 503 quando o relé está desligado.

Pontos de extremidade REST

Base: https://api.starhermit.com/api/v1/relay.

Método Caminho Autenticação Descrição
PEGAR /?titleId= JWT Listar sessões de retransmissão ativas para este título cuja correspondência vinculada inclui o chamador
PUBLICAR / JWT Crie um relé vinculado a uma partida
PEGAR /{sessionId} JWT Obtenha uma sessão de retransmissão — visível apenas para membros de sua correspondência vinculada (404 de outra forma)
PUBLICAR /{sessionId}/join JWT Junte-se ao revezamento; o chamador deve estar em sua correspondência vinculada
PUBLICAR /{sessionId}/close JWT Fechar um relé (somente criador)

Vinculação de correspondência

A associação ao Relay não é um lobby independente e aberto. A escalação da partida é a fonte da verdade:

  • Um relé tem gameSessionId ou realtimeRoomId, nunca os dois e nunca nenhum dos dois.
  • O criador deve pertencer a essa sessão de jogo ou ocupar um lugar ativo e não-esquerdo naquela sessão em tempo real quarto.
  • Cada junção posterior é verificada na mesma lista.
  • Abrir o WebSocket requer uma linha de participante de retransmissão ativa e uma associação atual no partida vinculada. Sair de uma sala em tempo real evita, portanto, uma conexão de relé posterior/de substituição.
  • Listando por titleId retorna apenas relés vinculados às correspondências às quais o chamador pertence; não é um diretório de todas as partidas ao vivo desse título.

Esta é uma alteração obrigatória no formato da solicitação. As linhas de retransmissão não vinculadas herdadas não podem autorizar um soquete; criar em vez disso, um novo relé vinculado.

Crie uma sessão

POST /api/v1/relay

Vincule-se a uma sessão de jogo oficial:

{
  "titleId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "maxParticipants": 8,
  "gameSessionId": "0f8fad5b-d9cb-469f-a165-70867728950e",
  "realtimeRoomId": null
}

Ou vincule-se a uma sala em tempo real:

{
  "titleId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "maxParticipants": 8,
  "gameSessionId": null,
  "realtimeRoomId": "b1d2c3e4-5f60-4a71-8b92-c3d4e5f60718"
}

maxParticipants o padrão é 8. Podem existir no máximo cinco sessões de revezamento ativas por título, padrão. A chamada será rejeitada se a contagem de ligações não for exatamente uma ou se o chamador não estiver no partida selecionada.

O revezamento não cria a sessão ou sala de jogo. Crie/participe dessa partida através do API de jogos ou API de salas em tempo real primeiro, depois passe seu ID aqui.

Formato da sessão

{
  "id": "d290f1ee-6c54-4b01-90e6-d701748f0851",
  "titleId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "creatorUserId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "gameSessionId": "0f8fad5b-d9cb-469f-a165-70867728950e",
  "realtimeRoomId": null,
  "isBound": true,
  "maxParticipants": 8,
  "currentParticipantCount": 1,
  "status": "Active",
  "createdAt": "2026-07-28T11:30:00Z",
  "closedAt": null,
  "participants": [
    {
      "id": "e7f1a2b3-4c5d-4e6f-8a9b-0c1d2e3f4a5b",
      "sessionId": "d290f1ee-6c54-4b01-90e6-d701748f0851",
      "userId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
      "connectionId": null,
      "joinedAt": "2026-07-28T11:30:01Z",
      "leftAt": null,
      "status": "Connected"
    }
  ]
}

Exatamente um ID de ligação não é nulo e isBound é portanto true. Sessão status é "Active" ou "Closed"; closedAt, connectionId, e leftAt pode estar ausente ou nulo.

Junte-se e feche

POST /api/v1/relay/{sessionId}/join retorna o atualizado RelaySession. Esta junção REST é obrigatória antes de abrir o WebSocket. Um slot de retransmissão livre não é suficiente: o chamador ainda deve ser membro do a partida vinculada.

POST /api/v1/relay/{sessionId}/close retorna 204 e é apenas para criadores.

WebSocket: ws/v1/relay

Conecte-se a:

wss://api.starhermit.com/ws/v1/relay?sessionId=<relay-id>&titleId=<title-id>

Autenticar com um Authorization: Bearer <token> cabeçalho, ?ticket=, ou ?access_token= parâmetro de consulta. O aperto de mão retorna 403 a menos que o usuário tenha ingressado no relé e ainda esteja autorizado por seu limite combinar.

O soquete é um fan-out de bytes opaco. Cada quadro binário é encaminhado inalterado para todos os outros participante conectado. Não há enquadramento JSON e a plataforma não interpreta os dados do jogo. O tamanho máximo da mensagem é 4 KiB por padrão.

Limite de taxa com reconhecimento de taxa de tick

Regra de queda de conexão: se um cliente enviar comandos/quadros de retransmissão mais rápido que a taxa permitida, StarHermit fecha o WebSocket de retransmissão desse cliente com PolicyViolation. Isto não é uma fila ou um queda de quadro de melhor esforço – a conexão do cliente é encerrada e deve ser reconectada.

O intervalo mínimo de cada remetente é derivado da taxa de ritmo da correspondência vinculada:

minimum interval ms = (1000 / max(pacingRateHz, 1)) × 0.90

O headroom de 10% permite temporizador comum e instabilidade de rede. A taxa nunca é tomada abaixo 1 hertz, então o limite nunca pede mais de ~900 ms de silêncio entre dois frames, por mais lento que seja o jogo carrapatos. Exemplos:

Taxa efetiva Intervalo mínimo do remetente
20Hz 45ms
30Hz 30ms
60Hz 15ms
120Hz 7,5ms

Para uma sessão de jogo, a taxa vem da definição do jogo. Para uma sala em tempo real, a sala gameSlug é resolvido para uma definição de jogo. A precedência da taxa efetiva normal se aplica: substituição do operador e, em seguida, a taxa solicitada pelo jogo. O que o limite do relé faz não seguir é um taxa que não diz nada sobre a frequência com que os jogadores conversam entre si: se nenhuma definição puder ser resolvido, se o jogo optou por não receber ticks do servidor com 0, ou se não solicitou nenhuma taxa e assim assume o padrão lento da plataforma, o limite é dimensionado a partir da taxa global. Um jogo nunca é limitado a uma mensagem a cada poucos segundos porque ninguém escreveu um número no código do servidor. Tarifas são limitados pelo teto da plataforma.

Um cliente deve acompanhar os comandos nesse intervalo ou mais lentamente. Enviando dois comandos/frames mais próximos do que o intervalo mínimo é tratado como inundação: StarHermit interrompe a conexão desse cliente fechando seu relé WebSocket com PolicyViolation. Os remetentes são limitados de forma independente, então um a violação do cliente não desconecta os outros jogadores.

Fluxo de cliente recomendado

  1. Crie ou participe da sessão de jogo/sala em tempo real.
  2. Faça com que um membro da correspondência crie uma retransmissão com esse ID de correspondência.
  3. Compartilhe o ID de retransmissão retornado somente por meio do estado autenticado ou das mensagens de escalação da partida.
  4. Cada outro membro da partida chama POST /api/v1/relay/{relayId}/join.
  5. Cada membro abre ws/v1/relay e acompanha os frames de acordo com a taxa efetiva de ticks do jogo; enviando descarta mais rapidamente a conexão WebSocket desse cliente.
  6. O criador fecha o revezamento quando a partida termina.

Não use IDs de retransmissão como segredos de autorização. A plataforma autoriza a lista vinculada; os IDs identificam apenas recursos.

Posicionamento

Use o relé para jogos de ritmo acelerado que precisam de distribuição entre pares com baixa sobrecarga. É deliberadamente estúpido transporte: a ligação garante quem pode participar, mas a plataforma ainda não analisa ou valida cargas úteis, eleger um par com autoridade ou resolver trapaças.

Para regras e estado impostos pelo servidor, use o API de jogos com um script em sandbox ou back-end do contêiner. As salas em tempo real oferecem lobbies, assentos, matchmaking e roteamento com reconhecimento de host; o relé agora pode se vincular a uma dessas salas em vez de duplicar sua lista.

Confirme a disponibilidade do relé antes de enviar um recurso que dependa dele.
