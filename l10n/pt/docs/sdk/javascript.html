JavaScript SDK (jogos de navegador)

starhermit-sdk.js é um cliente de arquivo único e livre de dependências para jogos de navegador publicado no StarHermit. Ele lê o token de lançamento, mantém-no renovado e fornece ajudantes para o comum APIs de token de lançamento no escopo do jogo: identidade, salvamentos na nuvem, configurações e controles por jogador, convites, matchmaking, sessões e soquete de jogo, conquistas, tabelas de classificação, replays, bate-papo, salas de voz e em tempo real.
Arquivo docs/sdk/starhermit-sdk.js — copie-o para o seu jogo inalterado
Global window.StarHermit (também module.exports em Node, para testes)
Dependências nenhum — ele usa o próprio navegador fetch, WebSocket e (para ler salvamentos compactados) DecompressionStream
Linha de base da API REST v1 e WebSocket v1, apenas superfície de token de inicialização

O SDK é um cliente, não uma segunda implementação da plataforma. Pontuações e desbloqueios de conquistas são escritos apenas pelo servidor do jogo (um resultado de script ou uma mensagem de controle de contêiner) — um cliente nunca pode publicá-los e o SDK apenas os lê. Todo o resto permanece autoritativo do servidor exatamente como documentado no Páginas de API.

Auxiliares autenticados não fazem solicitações de API sem um token de inicialização. As leituras geralmente resolvem para null, [], ou um mapa vazio; escreve pode resolver null/false e salvamentos debounced não têm imediato valor de retorno. Uma tomada permanece desconectada. Mantenha o progresso independente na memória se o jogador escolher jogo não rastreado. Chamar signOut() antes de mudar do jogo por conta para esse modo, para que a renovação seja interrompida.

Instalar

Copie o arquivo próximo aos outros scripts estáticos do seu jogo – onde quer que sua versão os envie – e carregue antes do seu próprio código:

<script src="starhermit-sdk.js"></script>
<script>
  StarHermit.init();          // as early as possible: it reads and strips the token from the URL fragment
</script>

Chamar init() uma vez, antes que qualquer roteador toque location.hash. Opções: init({ base, gameId, autoRefresh, launcherUrl }) — base aponta chamadas REST para uma origem autorizada durante o desenvolvimento local (jogos hospedados na plataforma usam a mesma origem). gameId, se fornecido, deve corresponder o UUID hospedado para login; páginas locais/externas não são origens válidas de retorno de login no jogo. autoRefresh: false deixa a renovação do token para um jogo que administra sua própria cadeia e launcherUrl substitui onde relaunch() envia o jogador (padrão https://dashboard.starhermit.com/).

Login e identidade

Precisar Chamar
Um jogador está conectado? StarHermit.signedIn, StarHermit.userId, StarHermit.slug
Reaja ao login/saída/expiração StarHermit.on('auth', ({ signedIn, reason }) => …)
Mostrar um Entrar botão somente quando StarHermit.canSignIn() (verdadeiro em um subdomínio UUID de jogo sem token); ao clicar StarHermit.signIn()
Nome do jogador/avatar await StarHermit.profile() → { userId, username, nickname, displayName }; StarHermit.avatarUrl()

O SDK lida com ambas as formas de lançamento — #game_token=<jwt>[&session_id=…] da biblioteca ou de um convidar, e #access_token=<jwt> retornando do login direto — e renova o token por meio POST /api/v1/games/{slug}/launch-token antes de expirar (ver tokens de lançamento). O nome de exibição é o perfil nickname; /api/v1/me não é acessível com um token de lançamento.

Salvamentos na nuvem

O slot do jogo é game:<slug> (catálogo: salvando de dentro de um jogo); o SDK constrói o caminho, compacta a carga útil e lida com o /info verificar.

const remote = await StarHermit.loadJSON();          // null: empty slot, signed out — or a failed read
if (StarHermit.saveLoadFailed()) showSyncError();    // tell those apart when it matters
else if (remote && isNewer(remote, local)) adopt(remote);

StarHermit.saveJSON(state);                          // debounced (2 s) checkpoint upload
addEventListener('pagehide', () => StarHermit.flushSave(true));   // keepalive flush
StarHermit.on('saved', ok => setSyncIndicator(ok));

Carregue antes de salvar. Compare e adote a cópia na nuvem antes de qualquer gravação que possa atingir saveJSON — incluindo configurações, apelidos ou gravações de pontos de verificação na inicialização — ou uma cópia local obsoleta pode substituir um salvamento mais recente feito em outro dispositivo. Mantenha os salvamentos antecipados até que a carga inicial seja estabilizada.

O SDK protege a outra metade dessa corrida: quando uma leitura falha (erro de rede ou servidor, como oposto a um slot vazio) ele define saveLoadFailed(), emite saveerror, e recusa gravações até /info confirma que o slot está vazio ou posterior loadSave() consegue. Uma gravação recusada resolve false e emite saved com false.

As gravações após um carregamento são condicionais. O SDK lembra a versão (ETag) do salve por último lê ou escreve e envia de volta, então uma gravação chega apenas ao salvamento em que foi baseada - ou, para um slot que estava vazio, apenas enquanto ainda está. Quando outro dispositivo é salvo no meio, a gravação é recusada (412): o SDK emite saveconflict, conjuntos saveConflicted(), e recusa novas gravações até que um loadSave() permite que o jogo se funda ou adote o salvamento mais recente. Um jogo que nunca carrega, escreve incondicionalmente, como antes.

StarHermit.on('saveconflict', async () => {
  const remote = await StarHermit.loadJSON();       // lifts the block
  StarHermit.saveJSON(merge(remote, local));        // conditional on the version just loaded
});

Nível inferior: loadSave() / writeSave(text) para cordas brutas, saveInfo() para { exists, sizeBytes, updatedAt, etag }.

Relatórios de falhas e bugs

Os jogadores podem relatar problemas dentro do jogo; o proprietário os faz a triagem através do API de relatórios.

await StarHermit.reportBug('Score did not save', 'Finished level 3, score shows 0', {
  clientVersion: '1.4.2',
  attachments: [{ fileName: 'state.json', contentType: 'application/json', data: JSON.stringify(state) }],
});
StarHermit.captureCrashes({ clientVersion: '1.4.2' });   // opt-in: uncaught errors become crash reports
const mine = await StarHermit.myReports();               // [{ id, kind, status, title, ... }]

report(kind, title, description, opts) é a forma geral (reportBug e reportCrash consertar o tipo). captureCrashes arquiva no máximo um relatório por mensagem distinta e três por carregamento de página, portanto, um O crash loop não pode esgotar a cota diária do jogador (20 por jogo por padrão). Pergunte ao jogador antes anexar qualquer coisa pessoal.

Multijogador, convites e redes sociais

A jogabilidade da sessão, a organização de partidas, as conquistas do jogo, as tabelas de classificação e os replays precisam de um servidor (roteiro ou recipiente). Salas em tempo real e amigos não. O bate-papo e a voz da sessão precisam da associação de conversação correspondente.

Área Chamadas
Sessões mySessions(), getSession(id), sessionRecovery(id), leaveSession(id), startAiSession(); StarHermit.launchSessionId após o lançamento de um convite
Soquete de jogo const conn = connect(sessionId, { onGame, onError, onPresence, onAchievement, onResumed, onAbandoned, onOpen, onClose, onAuthLost }), então conn.send(data); reconecta com back-off, renovando o token primeiro, e para em fechamentos normais/de política/de tamanho excessivo (1000/1008/1009), 4403/4404, ou quando a renovação é recusada (consulte reconectando)
Organização de partidas queues(), joinQueue([keys]), matchStatus(), cancelMatch(), waitForMatch(opts)
Convites sendInvite(toUserId[, sessionId]) (com um sessionId o amigo entra nessa sessão de corrida), invites(), acceptInvite(id), declineInvite(id); inviteLink(query) para um link de compartilhamento
Publique uma corrida em suas tabelas de classificação submitScores({ boardKey: number }) → chaves aceitas (ver tabelas de classificação para um jogador)
Conquistas e tabelas de classificação (somente leitura) achievements(), linkedAchievements(otherSlug), leaderboards(), leaderboard(key, opts), leaderboardEntries(boardId, opts); desbloquear brindes via on('achievement', …)
Repetições myReplays(limit), getReplay(id)
Bate-papo da sessão chatMessages(id), sendChat(id, text), pollChat(id, onMessages, intervalMs) — REST e polling apenas para tokens de lançamento

Qualquer coisa que não esteja embrulhada está a uma chamada de distância: StarHermit.api(path, { method, body }) envia um solicitação JSON autenticada (resolve null em 404/204 ou quando desconectado, rejeita { status, message } em outras falhas, renova uma vez em 401).

Tabelas de classificação para um jogador

Um cliente nunca pode postar uma pontuação - apenas o servidor do jogo pode - então um jogo para um jogador precisa de um script de plataforma pequena para possuir seus painéis. score-script.js é um: copie-o a seguir ao seu jogo, declare-o em starhermit.txt como server=score-script.jse edite apenas o seu BOARDS bloco, que lista cada quadro conforme você crie-o:

var BOARDS = {
  "high-score": { "name": "High score", "scoreType": "integer", "sortDirection": "desc", "minScore": 0, "maxScore": 1000000 }
};

Quando uma corrida terminar, publique-a e mostre a posição do jogador:

const accepted = await StarHermit.submitScores({ 'high-score': total });   // [] when signed out or refused
if (accepted.includes('high-score')) {
  const board = await StarHermit.leaderboard('high-score', { pageSize: 100 });
  const me = board.items.find(e => e.userId === StarHermit.userId);
  showRank(me && me.rank);
}

submitScores abre uma sessão prática (POST .../sessions/ai), envia {type:'result', scores} ligado o soquete do jogo e resolve as chaves do tabuleiro que o script aceitou; também emite scores com essa lista. O script descarta uma pontuação que não é um número do tipo do tabuleiro ou está fora de seu minScore/maxScore, posta o resto através de seu scores retornar e encerrar a sessão. O cliente ainda relata o resultado. Uma pontuação inventada dentro do intervalo pode ser aprovada; essas pranchas são adequadas para uso casual jogar. Para competição, valide a corrida no script ou container antes de premiá-la. O reconhecimento lista chaves aceitas por script; não é prova de que todos os conselhos estavam ativos ou que um novo recorde pessoal foi armazenado. Ver confiança e disponibilidade.

Reconectando e tokens expirados

Um soquete carrega o token de inicialização em sua URL e um handshake com um token expirado é recusado antes a atualização – o navegador reporta apenas código fechado 1006, exatamente como uma queda de rede. Então, um fracasso reconectar pode ser uma falha de autenticação e tentar novamente o mesmo URL nunca poderá ser recuperado. A renovação funciona apenas enquanto o token atual for válido e dentro de 12 horas após o lançamento original; depois disso só o lançador pode cunhar um novo token.

connect() cuida disso sozinho: antes de cada reconexão, ele renova o token por meio POST /api/v1/games/{slug}/launch-token (a menos que tenha sido renovado desde a abertura do soquete) e reabre com o novo. Um erro de rede ou servidor durante a renovação recua e renova novamente - nunca reabre o URL antigo. Quando a renovação é recusada ou o token expira, o SDK sai (auth com reason: 'expired'), para de reconectar e liga onAuthLost():

const conn = StarHermit.connect(sessionId, {
  onGame, onClose,
  onAuthLost: () => showReconnectPanel(),   // e.g. "Session expired — Back to StarHermit"
});
backButton.onclick = () => StarHermit.relaunch();

relaunch() envia o jogador de volta para obter um novo token de lançamento: através do login quando o jogo foi aberto desse jeito (StarHermit.launchKind === 'sign-in'), caso contrário, para o inicializador. Dentro do lançador frame do jogo ele navega pela janela superior, que os navegadores permitem apenas a partir de um gesto do usuário, então chame-o a partir de um clique; ele retorna false quando a navegação foi recusada.

Um navegador pode ocultar sessões concluídas, termos, associação ou falhas de compilação conforme 1006. Antes de um nova tentativa automática, connect() verifica o estado da sessão através de REST e, quando opts.build é fornecido, compara com informações do jogo. onUnavailable(error) recebe uma falha REST permanente ou é encerrado sessão; onTermsRequired(body) solicita aceitação de termos explícitos. Crie uma nova conexão depois resolvendo isso. onClose(1008) significa que a conexão foi substituída ou violou a política; não reabri-lo automaticamente.

Sockets que seu jogo abre sozinho (realtime.socketUrl(roomId), voice.socketUrl(roomId)) precisa do mesma regra. Antes de reabrir um, ligue renewForReconnect() e agir de acordo com seu resultado:

async function reopen() {
  const r = await StarHermit.renewForReconnect();
  if (r === 'renewed') ws = new WebSocket(StarHermit.realtime.socketUrl(roomId)); // fresh token in the URL
  else if (r === 'retry') setTimeout(reopen, backoff());                         // renewal itself failed
  else if (r === 'terms-required') showTermsPanel();                              // explicit acceptance
  else showReconnectPanel();                                                     // 'relaunch'
}

As renovações simultâneas compartilham uma solicitação. terms-required preserva o token do jogador e emite termsrequired; mostrar getTerms() e ligue acceptTerms(displayed.hash) apenas no jogador Aceite a ação e tente novamente. Os soquetes gerenciados pelo seu jogo também precisam de verificações REST para recursos finalizados e deve parar nos fechamentos da política. Ver solução de problemas.

Eventos

StarHermit.on(type, fn) retorna uma função de cancelamento de assinatura; off(type, fn) também funciona.

Evento Carga útil
auth { signedIn, userId } no login; { signedIn: false, reason } ao sair ou expirar (reason: 'expired' quando a renovação é recusada – oferta relaunch())
saved true / false depois de cada gravação na nuvem
saveerror { op: 'load' } depois de uma leitura falhada; { op: 'write', blocked: true } por uma gravação recusada
achievement um desbloqueio pressionado no soquete de jogo
scores as chaves do tabuleiro aceitas por submitScores ([] quando nada foi postado)
saveconflict { etag } quando outro dispositivo alterou o salvamento; recarregar antes de mesclar/salvar
termsrequired O erro de termos retornado por uma renovação do token de lançamento; preservar o token e solicitar consentimento

Mantendo sua cópia atualizada

Trate o arquivo como vendido: copie-o inalterado, nunca edite sua cópia e substitua-o no atacado quando o arquivo desta página muda. Certifique-se de que sua etapa de construção ou embalagem o envie junto com o jogo outros arquivos estáticos.
