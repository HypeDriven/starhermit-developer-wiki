Ferramentas de desenvolvedor StarHermit

Crie pacotes de jogos de script publicáveis, carregue-os no StarHermit e forneça ao seu assistente de codificação uma conexão MCP local. Estas ferramentas não requerem Instalação de ferrugem ou verificação da fonte do motor. O jogo pode ter seu próprio construir dependências, como Node.js.

Baixe o arquivo para o seu computador na tabela abaixo ou em https://engine.starhermit.com/engine/tools/latest.json (lista cada endereço, tamanho e SHA-256 do arquivo) e compare seu SHA-256 com o soma de verificação ao lado dele (<archive>.sha256). Descompacte-o e coloque seu diretório em PATH, ou use o caminho completo do executável nos comandos abaixo. Os downloads do macOS são fornecido separadamente para Apple Silicon (macos-aarch64) e Intel (macos-x86_64). Eles não são autenticados pela Apple e nenhum download é Authenticode ou ID do desenvolvedor assinado. A construção do Apple Silicon é compilado cruzado; relatar problemas.

Verifique e empacote um jogo

starhermit-tools --version
starhermit-tools check my-game
starhermit-tools package --web my-game --out upload --remote-out remote-objects

O diretório do jogo contém starhermit.txt e os arquivos que o jogo precisa. engine.version fixa uma versão publicada do mecanismo; a ferramenta lê seu manifesta de engine.starhermit.com e grava um carregador e um arquivo fixados em hash índice. --engine-version X.Y.Z seleciona explicitamente uma versão compatível. Arquivos declarados por engine.remote.files são escritos para remote-objects; quando engine.remote.urls=platform, a publicação os carrega primeiro.

check valida o manifesto, os caminhos do pacote e a estrutura do arquivo. Isso acontece não execute scripts. Teste o jogo da web empacotado em um navegador antes publicação. Os desenvolvedores também podem baixar o nativo correspondente tempo de execução de uma versão do mecanismo (Windows, Linux e do mecanismo 1.26.2 macOS 11 ou posterior em Intel e Apple Silicon) e use starhermit check my-game para uma verificação de execução sem cabeça. O macOS os tempos de execução são assinados ad-hoc e não autenticados, e ainda não foram testado em hardware Apple real. Um tarball baixado em um navegador é em quarentena: correr xattr -d com.apple.quarantine starhermit ou permitir em Configurações do sistema.

Publicar

Use sua própria chave de implantação registrada, seguindo a integração da chave pública e guias de CI/CD no wiki do desenvolvedor. Definir STARHERMIT_PUBLIC_KEY e STARHERMIT_PRIVATE_KEY em seu shell ou em seu armazenamento secreto de CI. Alternativamente, definir STARHERMIT_ACCESS_TOKEN para um token de acesso à conta. Não coloque estes valores no jogo, confirme-os ou adicione-os à configuração do MCP.

starhermit-tools publish --game-id YOUR-GAME-ID --upload upload --remote-out remote-objects

Isso substitui os arquivos implantados do jogo. --mode merge corrige um existente carregue em vez disso. Para criar um novo jogo, substitua --game-id YOUR-GAME-ID com --new. --socket seleciona o WebSocket de upload; uploads grandes selecione-o automaticamente. --display-name e --description substituir o enviado nome e descrição do manifesto. O editor informa o URL hospedado e escreve um relatório de publicação ao lado do upload.

A conta deve possuir o jogo. Um erro de credencial ou limite negado é um erro; não contorne isso com as credenciais de outra pessoa. Remoto objetos já mantidos pelo jogo são reaproveitados; uploads de objetos interrompidos currículo. Um novo jogo pode ser criado antes que o upload de um objeto subsequente falhe; use o ID do jogo relatado para tentar novamente em vez de criar outro.

STARHERMIT_API_BASE seleciona outra implantação HTTPS. STARHERMIT_CA_FILE seleciona um pacote confiável PEM, por exemplo, um desenvolvimento AC; A verificação TLS está sempre habilitada. O uso normal não precisa de nenhuma variável.

Conecte um assistente de codificação ao MCP

Adicione um servidor stdio MCP à configuração do seu assistente, usando absoluto caminhos apropriados ao seu computador:

{
  "mcpServers": {
    "starhermit": {
      "command": "/absolute/path/to/starhermit-tools",
      "args": ["mcp", "--package", "/absolute/path/to/my-game"]
    }
  }
}

O servidor oferece check_package, package_web, e package_native. Se o jogo tiver um script de construção Node.js, anexe --build-script e seu caminho absoluto para os argumentos MCP para expor um build ferramenta. Isso funciona aquele script configurado; não aceita comandos arbitrários do MCP. package_web leva opcional outDir, remoteOut, e engineVersion; os caminhos de saída relativos são relativos ao diretório do jogo. Por padrão escreve starhermit-build/upload e starhermit-build/remote ao lado do diretório do jogo. package_native escreve o índice de arquivo nativo do jogo para instalação por um cliente StarHermit compatível, que instala o mecanismo tempo de execução para a plataforma do player (macOS incluído, a partir do motor 1.26.2). Nenhuma das ferramentas publica nada.

Com um tempo de execução nativo instalado, anexe --runtime e seu caminho executável absoluto para os argumentos do MCP para ativar run_checks. Essa ferramenta executa o código do jogo no tempo de execução configurado. Publicação está disponível apenas como um comando CLI explícito e nunca é uma ferramenta MCP.
