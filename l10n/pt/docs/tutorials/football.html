Jogo de exemplo: como o futebol usa o motor StarHermit

Futebol StarHermit é um público, completo jogo de roteiro. É futebol 3D em tempo real para 1 a 22 jogadores, com companheiros de equipe de IA, um ambiente iluminado estádio, lobbies online, chat de voz e texto, replays, tabela de classificação, conquistas e nove línguas. Esta página desmonta passo a passo para mostrar como um jogo real usa o mecanismo. Cada passo nomeia os módulos do motor envolvidos e links para a fonte do jogo, onde você pode ler o código completo.

Este passo a passo foi escrito para o mecanismo 1.40.0, o lançamento mais recente. Cada chamada mostrada é listada no referência da API do mecanismo. Leia o tutorial do motor primeiro, se você ainda não construiu um jogo de script.

Links de origem apontam para commit 33bd9bd. Nesse momento, comprometa o mecanismo de pinos do jogo 1.39.0 com engine.minor=39. Ele não usa nada mais recente, então funciona inalterado em 1.40.0; movê-lo é uma mudança de uma linha para engine.version (ver passo 12).

A forma do jogo

Caminho Papel
starhermit.txt O manifesto: nome, PIN do mecanismo, script do servidor, controles, recursos
server.js A simulação de uma partida: executada pela plataforma como servidor oficial e carregada pelo cliente para prática e previsão offline
engine/src/main.ts O módulo de entrada: retornos de chamada do ciclo de vida e a máquina de estado das telas
engine/src/match.ts, logic/ Fluxo de correspondência, netcode, interpolação e previsão
engine/src/world/ O estádio, os jogadores de futebol, a bola e a multidão na cena 3D
engine/src/screens/, hud.ts Menus (starhermit:ui) e o HUD da partida (starhermit:draw)
engine/src/net.ts, platform.ts, chat.ts, voice.ts Tudo o que conversa com a plataforma StarHermit
engine/src/audio.ts, i18n.ts, quality.ts Níveis de som, idiomas e gráficos
assets/, sfx/ Imagens, tabelas de cordas e clipes de som

1. O manifesto

starhermit.txt transforma a pasta em um jogo de script e também declara o script do servidor e os controles:

name=Football
launch=index.html
server=server.js
control.up=KeyW+ArrowUp | Run forward
control.shoot=Space+KeyJ | Shoot (hold) / tap to pass
control.tackle=KeyK | Slide tackle / pressure
engine.api=1
engine.entry=engine/src/main.ts
engine.version=1.39.0
engine.minor=39
engine.capabilities=platform,voice,clipboard,storage
engine.gamepad.shoot=West+RightTrigger
engine.gamepad.pass=South
  • launch=index.html é a página do carregador que starhermit package --web escreve. Ele joga o jogo em navegadores no tempo de execução da web da versão fixada.
  • server=server.js é o script de correspondência oficial da plataforma (etapa 6).
  • control.* e engine.gamepad.* linhas definem ações. O tempo de execução vincula teclas e pads a eles, e os jogadores os religam no menu Opções do tempo de execução. O jogo nunca nomeia uma chave para o jogo.
  • engine.capabilities pede a plataforma (salas, soquetes, tabelas de classificação, replays, chat), voz, a área de transferência (links de convite) e armazenamento (configurações). O tempo de execução recusa chamadas fora deles.

A lista completa de chaves está em o starhermit.txt manifesto.

2. O módulo de entrada e o loop de quadro

engine/src/main.ts configura o renderizador no escopo do módulo e registra os quatro retornos de chamada do ciclo de vida de starhermit:engine:

import { frame, onFixedUpdate, onRender, onStart, onUpdate, setFixedRate } from "starhermit:engine";
import { ACESFilmicToneMapping, PCFSoftShadowMap, PerspectiveCamera, renderer, scene } from "starhermit:scene";

const camera = new PerspectiveCamera(55, 16 / 9, 0.1, 800);
renderer.camera = camera;
renderer.shadowMap.enabled = true;
renderer.shadowMap.type = PCFSoftShadowMap;
renderer.toneMapping = ACESFilmicToneMapping;

onStart(() => {
  setFixedRate(60);
  loadLanguages(); // string tables (step 10)
  sim();           // evaluate server.js once (step 6)
  menuScene.start(); // an AI-vs-AI match behind the menu
  // … platform listeners, settings listeners, invite polling
});

onFixedUpdate((step) => {
  if (match) match.fixedStep(step);
  else if (!replay) menuScene.fixedStep(step);
});

onUpdate((delta) => {
  pollQuality();
  if (match) match.update(Math.min(delta, 0.1));
  // … replay viewer or menu backdrop
});

onRender(() => {
  const fr = frame();
  if (Math.abs(camera.aspect - fr.width / fr.height) > 1e-6) {
    camera.aspect = fr.width / fr.height;
    camera.updateProjectionMatrix();
  }
  hud.draw();
  // … chat, in-match menu or the menu screens
});

O padrão a ser copiado:

  • A simulação é executada em onFixedUpdate, em 60 Hz fixos.
  • A lógica por quadro é executada em onUpdate, com delta tampado para que um quadro travado não faça os jogadores saltam.
  • O desenho é executado em onRender. Há apenas um de cada retorno de chamada, então main.ts fãs para o tela atual: menu, lobby, partida, replay ou resultado.

3. O mundo 3D: starhermit:scene

O estádio, os jogadores de futebol, a bola e os árbitros são objetos comuns no estilo three.js de starhermit:scene: Mesh, Group, MeshStandardMaterial, CylinderGeometry, Sprite, CanvasTexture e assim por diante. Código portado de three.js funciona principalmente inalterado. Alguns detalhes que valem a pena ler:

  • world/stadium.ts constrói o campo, arquibancadas, holofotes e neblina. Ele define os pós-efeitos (renderer.bloom, renderer.grade, renderer.antialias) e sombras para cada nível gráfico.
  • world/environment.ts faz um mapa ambiental com PMREMGenerator de um DataTexture.
  • world/crest.ts e world/nametags.ts desenhe escudos de times e apelidos flutuantes em um starhermit:canvas OffscreenCanvas, então use-os como CanvasTextureareia Sprites.

4. Milhares de peças móveis: starhermit:world

Animar 22 jogadores de futebol juntos, além de milhares de torcedores, seria muito lento, pois script por objeto no intérprete nativo. Movimentos de futebol que funcionam em starhermit:world tabelas (linhas de colunas digitadas) e grãos (funciona o tempo de execução em cada linha nativamente):

import { kernel, schedule, table } from "starhermit:world";

const crowd = table("crowd", CROWD_ROWS, {
  bx: "f32", by: "f32", bz: "f32", ph: "f32", fr: "f32", av: "f32",
  q: "quat", s: "f32", sy: "f32", x: "f32", y: "f32", z: "f32",
});
const sway = kernel(crowd, (r, u: { t: number; amp: number; spd: number; sway: number; shake: number }) => {
  const j = Math.sin(u.t * u.spd * r.fr + r.ph);
  r.y = r.by + (j > 0 ? j * j : 0) * u.amp * r.av;
  // …
});
// An eighth of the crowd each frame: the work is sliced across frames.
const swayRun = schedule.update(sway, { t: 0, amp: 0, spd: 0, sway: 0, shake: 0 }, { slices: 8 });

O jogador de futebol se prepara world/rig.ts use a mesma abordagem. UM rigs table contém o estado de animação de cada jogador de futebol. UM joints mesa, com um ref:rigs coluna, comporta 15 juntas por plataforma e ligações dirija os nós da cena dele. Dois kernels agendados após onUpdate calcula as poses e o tempo de execução grava o nó se transforma. O trabalho de roteiro por jogador de futebol chega a cerca de uma dúzia de números por quadro.

5. Entrada: ações, toque e gamepads

engine/src/input.ts lê as ações do manifesto através starhermit:input:

  • value(action) retorna até que ponto uma ação é realizada (o movimento é value("up") - value("down")). onAction fornece bordas de pressão e liberação.
  • A aparência do mouse usa requestPointerLock, onPointerDelta e onPointerLockChange. A câmera stick direito vem de gamepads(), e vibrate dá um breve tique tátil.
  • Em telas sensíveis ao toque (primaryPointer() é grosseiro), setTouchControls mostra um joystick e Botões SHOOT/PASS/TACKLE desenhados pelo tempo de execução. Os botões estão vinculados às mesmas ações:
setTouchControls([
  { kind: "stick", up: "up", down: "down", left: "left", right: "right", anchor: "bottom-left", offset: [90, 90], radius: 66 },
  { kind: "button", action: "shoot", label: T("SHOOT").slice(0, 16), anchor: "bottom-right", offset: [66, 66], radius: 46 },
  // … PASS and TACKLE
]);

screens/controls.ts lista o atual bindings() e chamadas requestRebind. O tempo de execução então captura a nova chave ou botão.

6. Uma simulação para cliente e servidor: starhermit:script

server.js é um script clássico simples, sem importações, Date ou Math.random, como sandbox da plataforma requer. Ele define dois globais:

  • globalThis.game contém os pontos de entrada da plataforma (createSession, onPlayerMessage, onTick) e declarações estáticas lidas no momento da publicação:

    globalThis.game = {
  tickRateHz: 30,
  replays: true,
  achievements: [
    { key: 'debut', name: 'Debut', description: 'Finish your first match.', points: 10 },
    { key: 'hat-trick', name: 'Hat-Trick', description: 'Score three goals in one match.', points: 50 },
    // …
  ],
  createSession: function (ctx) { /* seats, AI, seed from ctx.random */ },
  // …
};

  • globalThis.FootballSim mantém a mesma simulação (createMatch, stepMatch, a IA) para o cliente.

O cliente carrega o mesmo arquivo em seu próprio domínio com loadClassic de starhermit:script (engine/src/sim.ts):

import { loadClassic } from "starhermit:script";

loadClassic("server.js");
const S = (globalThis as unknown as { FootballSim?: FootballSimApi }).FootballSim;

Etapas de prática off-line FootballSim localmente a 60 Hz com IA em todos os assentos. On-line, o corridas de plataforma server.js com autoridade em 30 Hz. O jogo nunca mantém duas cópias de seu regras.

7. Partidas online: salas e tomadas de jogo

Os lobbies utilizam as salas da plataforma através starhermit:platform (screens/lobby.ts):

import * as P from "starhermit:platform";

// Quick play: join any open room, or open one.
let room = await P.rooms.quickJoin();
if (!room) {
  room = await P.rooms.create({ teamCount: 2, seatsPerTeam: teamSize, backfillAfterSeconds: 30, metadata: { game: "football" } });
  room = await P.rooms.open(room.id);
}

// Ranked solo vs AI: every other seat is an AI player, so starting begins the match at once.
room = await P.rooms.create({ teamCount: 2, seatsPerTeam: teamSize, backfillAfterSeconds: 30, aiPlayers: 2 * teamSize - 1, metadata: { game: "football" } });
room = await P.rooms.start(room.id);

Amigos, convites e mudanças de assento passam P.friends.list, P.rooms.invite, P.rooms.acceptInvite e P.rooms.seat. P.rooms.mine permite que um jogador volte a uma partida da qual saiu.

Assim que a partida começar, engine/src/net.ts abre o soquete do jogo com P.connectGame(sessionId):

  • Ele envia entradas em 30 Hz com sendInput.
  • Ele pede um instantâneo completo com sendCommand({ type: "sync" }) em cada aberto e em resumed.
  • Ele escuta game (instantâneos e eventos), achievement e stopped. stopped relata por que o soquete parou: desconectado, termos atualizados ou partida perdida.

O tempo de execução mantém as credenciais do jogador e se reconecta sozinho, para que o jogo não lide com tokens e não tem loop de nova tentativa.

logic/interp.ts suaviza os instantâneos do servidor com interpolação adaptativa. logic/predict.ts prevê o movimento do jogador de futebol local e o corrige a cada instantâneo. A previsão afeta apenas o que está desenhado; o servidor permanece autoritativo.

8. O resto da plataforma

Recurso Chamadas Fonte
Jogador conectado, login, fim da sessão P.player(), P.onPlayerChange, P.requestSignIn, P.onSessionEnded platform.ts, main.ts
Tabela de classificação P.leaderboards.list, P.leaderboards.entries (placa declarada em leaderboards.json) screens/leaderboard.ts
Conquistas Declarado em server.js, premiado em tempo integral, listado com P.achievements.list screens/achievements.ts
Repetições game.replays: true em server.js; P.replays.list, P.replays.get screens/replays.ts, replayView.ts
Bate-papo de texto P.sessions.get (a conversa da partida), P.chat.messages, P.chat.subscribe, P.chat.post chat.ts
Bate-papo por voz P.voice.join, P.voice.setVolume e P.voice.setPan pela distância entre jogadores de futebol, P.voice.setMuted voice.ts
Links de convite P.inviteLink e clipboard de starhermit:engine platform.ts
Relatórios de bugs P.reportBug screens/settings.ts

Cada chamada pode ser rejeitada com um PlatformError. O futebol trata os recursos online como o melhor esforço: um mostra falha "on-line indisponível" ou volta ao silêncio e nunca termina o jogo. Desconectado, o jogo ainda oferece prática offline.

9. Menus e HUD: starhermit:ui, starhermit:draw, starhermit:canvas

  • Cardápios (screens/*.ts, o menu da partida e as caixas de diálogo em main.ts) usar starhermit:ui, a IU de modo imediato do mecanismo. Widgets são chamados todos quadro de onRender, e ui.setTheme dá-lhes as cores do jogo. As próprias opções do tempo de execução menu abre com openMenu.
  • O HUD ( hud.ts) desenha o placar, o relógio e os marcadores com starhermit:draw: draw.roundRect, draw.text e draw.image (uma tela de crista), em ordem de chamada na cena.
  • Imagens estão carregados com createImageBitmap de starhermit:canvas, por exemplo, a arte principal do menu.

10. Configurações e idiomas: starhermit:storage, cordas

  • As configurações por jogador (mudo, voz, idioma, substituições gráficas) ficam disponíveis settings de starhermit:storage. Eles são mantidos no dispositivo e na conta. settings.onChange aplica uma alteração feita em outro dispositivo.
  • i18n.ts cargas assets/strings.json no motor strings tabelas (strings.load, strings.t, strings.setLanguage). Ele escolhe o idioma da escolha salva e, em seguida, o idioma do jogador Idioma StarHermit e, em seguida, o do dispositivo (preferences). l10n/font.ts carrega fontes de script com FontFace para idiomas que precisam deles.

11. Níveis de som e gráficos

  • audio.ts constrói um gráfico de áudio da Web com starhermit:audio:
    • Os clipes de autoria estão listados em sfx/manifest.json (leia com files.readJson).
    • Um sintetizador cobre qualquer evento sem clipe, além da reverberação da multidão e do estádio.
    • Nós de curta duração são liberados assim que terminam, porque o gráfico host é limitado.
  • quality.ts segue o nível gráfico do jogador (frame().level, levelSettings). Sombras, flores e o anti-aliasing segue esse nível. O próprio conteúdo do jogo (detalhes do campo, densidade da multidão, partículas) tem substituições por jogador na parte superior.

12. Empacotar, testar e publicar

  • Verificação de tipo com tsc -p engine. engine/tsconfig.json inclui o lançamento starhermit.d.ts e conjuntos "lib": ["ES2022"], "types": [] e "allowImportingTsExtensions": true.
  • Teste. npm test corre server.js testes de regressão. engine/tests/run.sh executa a lógica testes (interpolação, previsão, pose, lobby) no Node. starhermit <folder> --check valida o pacote e reproduz 120 quadros sem cabeça.
  • Pacote. starhermit package --web . reescreve index.html e starhermit-files.json, que estão comprometidos com cada mudança.
  • Publicar. O jogo é adicionado ao StarHermit a partir do URL do repositório. A plataforma lê starhermit.txt, corre server.js como o script da partida e cria a tabela de classificação a partir leaderboards.json.

Para mover o Futebol, ou seu próprio jogo, para o motor 1.40.0:

  1. Baixe o tempo de execução 1.40.0.
  2. Definir engine.version=1.40.0.
  3. Execute as verificações e empacote novamente.

Elevação engine.minor para 40 somente quando você deseja hospedar API 1.40 novos recursos.
