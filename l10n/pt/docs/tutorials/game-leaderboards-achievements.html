Tutorial: tabelas de classificação e conquistas para o seu jogo

Se você possui um jogo no StarHermit, você é o editor dele. Você pode dar tabelas de classificação (pontuação alta, corrida mais rápida, sequência mais longa) e conquistas sem uma conta de editor ou qualquer permissão. Possuir o jogo é tudo o que você precisa.

Existe uma regra por trás de tudo nesta página: você os define, o servidor do seu jogo escreve eles. O cliente de um jogador nunca pode postar uma pontuação ou reivindicar uma conquista por isso, e seu servidor deve validar a jogabilidade que os rendeu. Recusando envios diretos de API por si só não impede um cliente modificado de inventar eventos de jogo. É por isso que o jogo precisa de um back-end confiável: um server= roteiro ou um container.image= em starhermit.txt.

Este tutorial foi desenvolvido para um pequeno jogo de arcade, Colecionador de estrelas: uma corrida termina quando o jogador trava e tem um total de pontos e um tempo de execução.

Antes de começar

Você precisa de:

  • Um jogo com back-end de servidor que você possui: aquele que você adicionou do seu próprio repositório, carregou como uma pasta ou reivindicado. Um jogo somente para navegador responde 409 para cada chamada abaixo, com uma mensagem dizendo o porquê.
  • Um token de acesso de usuário completo, não o token de lançamento de um jogo. Os tokens de lançamento são limitados ao jogo superfície do jogador e não consegue alcançar /me/....
  • ID do seu jogo (também é seu <id>.starhermit.com endereço):
ACCESS_TOKEN='your-full-user-access-token'
API=https://api.starhermit.com

curl -s "$API/api/v1/me/github-games" -H "Authorization: Bearer $ACCESS_TOKEN" |
  jq '.[] | {id, displayName, gameSlug}'

GAME_ID='the-id-from-above'

gameSlug é como seu cliente chama o jogo /api/v1/games/{slug}/.... Cada jogo que você adicionou ou carregado tem um jogo somente para navegador incluído, portanto, não informa se existe um servidor: GET /api/v1/games/{slug} faz - ele responde 404 até que o jogo tenha um back-end.

1. Crie as tabelas de classificação

Star Collector ganha dois tabuleiros: mais pontos (quanto maior, melhor) e corrida mais rápida até 100 pontos (menor é melhor).

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/leaderboards" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "high-score", "name": "High score",
        "scoreType": "integer", "sortDirection": "desc",
        "minScore": 0, "maxScore": 1000000 }'

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/leaderboards" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "fastest-100", "name": "Fastest to 100",
        "scoreType": "time-ms", "sortDirection": "asc" }'

Cada chamada retorna 201 e o conselho, incluindo seus id e key. Seu servidor usa o chave, então escolha-o com cuidado. A chave, scoreType e sortDirection não pode ser alterado posteriormente.

scoreType Aceita
integer números inteiros
decimal qualquer número
time-ms milissegundos inteiros e não negativos

Definir minScore/maxScore ao que seu jogo pode realmente produzir. Uma pontuação fora deles é descartada, que é uma proteção barata contra um bug na lógica do seu próprio servidor.

2. Crie as conquistas

Você pode conceder conquistas ao jogo de duas maneiras e pode usar as duas ao mesmo tempo:

Declarado em código Criado por meio da API
Onde game.achievements em seu roteiro ou /describe em seu contêiner POST /me/github-games/{id}/achievements
Alterado por publicando uma atualização uma chamada de API, com efeito imediato
Bom para as conquistas em torno do seu código é construído adicionando ou reformulando alguns sem autorização

Ambos os tipos são desbloqueados da mesma maneira, com o retorno da chave pelo servidor. Aqui criamos dois através a API:

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "century", "name": "Century",
        "description": "Collect 100 stars in one run.", "points": 10 }'

curl -s -X POST "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "key": "untouchable", "name": "Untouchable",
        "description": "Reach 500 points without losing a shield.",
        "points": 50, "secret": true }'

A secret a conquista permanece oculta dos jogadores até que eles a desbloqueiem.

Para ver tudo o que o jogo tem, incluindo as conquistas declaradas pelo seu código, liste-as:

curl -s "$API/api/v1/me/github-games/$GAME_ID/achievements" \
  -H "Authorization: Bearer $ACCESS_TOKEN" | jq '.[] | {key, origin, unlocks}'

origin é declared para conquistas do seu código e owner pelas conquistas que você criou aqui. Você só pode editar e excluir owner uns. UM declared um seria devolvido pelo seu próximo atualização, então a API recusa (409) e você o altera no código.

3. Publique pontuações e desbloqueie conquistas do seu script

Seu script relata os dois tipos de resultado em seu valor de retorno. Isso pode ser feito de qualquer gancho: createSession, onPlayerMessage ou onTick.

  • scores: tecla do tabuleiro → ID do jogador → número.
  • achievements: ID do jogador → chaves para desbloquear.
'use strict';

function endRun(ctx, s, playerId) {
  var run = s.runs[playerId];
  var scores = { "high-score": {} };
  scores["high-score"][playerId] = run.points;
  if (run.reached100At) {
    scores["fastest-100"] = {};
    scores["fastest-100"][playerId] = run.reached100At - run.startedAt;
  }

  var unlocked = [];
  if (run.stars >= 100) unlocked.push("century");
  if (run.points >= 500 && !run.lostShield) unlocked.push("untouchable");
  var achievements = {};
  achievements[playerId] = unlocked;

  run.over = true;
  return {
    ok: true,
    sessionState: s,
    scores: scores,
    achievements: achievements,
    broadcast: [{ to: [playerId], data: { type: "run-over", points: run.points } }]
  };
}

globalThis.game = {
  tickRateHz: 10,

  createSession(ctx) {
    var runs = {};
    ctx.players.forEach(function (p) {
      runs[p.id] = { points: 0, stars: 0, lostShield: false, startedAt: ctx.now,
                     reached100At: null, over: false };
    });
    return { ok: true, sessionState: { runs: runs } };
  },

  onPlayerMessage(ctx) {
    var s = ctx.sessionState;
    var from = ctx.message.from;
    var run = s.runs[from];
    var msg = ctx.message.data || {};
    if (!run || run.over) return { ok: false, error: "No run in progress" };

    // The client reports what happened; the script decides what it is worth.
    if (msg.type === "collect") {
      run.stars += 1;
      run.points += 5;
      if (run.points >= 100 && !run.reached100At) run.reached100At = ctx.now;
      return { ok: true, sessionState: s };
    }
    if (msg.type === "shield-lost") {
      run.lostShield = true;
      return { ok: true, sessionState: s };
    }
    if (msg.type === "crash") return endRun(ctx, s, from);
    return { ok: false, error: "Unknown command" };
  },

  onTick(ctx) { return { ok: true }; }
};

Coisas que você faz não precisa lidar com:

  • Piores pontuações. Cada jogador mantém sua melhor pontuação em cada tabuleiro, julgada pela pontuação do tabuleiro. sortDirection. Relate cada corrida e a plataforma mantém o melhor.
  • Repetir desbloqueios. Desbloquear algo que um jogador já possui não adianta nada, então devolva a chave sempre que a condição for válida.
  • A identificação de qualquer outra pessoa. Pontuações e desbloqueios para pessoas que não estão na sessão, incluindo a IA assento, são ignorados.

Chaves desconhecidas, quadros inativos e pontuações fora do intervalo são eliminados silenciosamente. Seu script não recebe erro para eles, então verifique suas placas uma vez, como em seção 4.

Um jogo real deveria ter o servidor calculando pontos e tempos a partir de seu próprio estado autoritativo, não confiança collect mensagens como elas são. Este exemplo é curto para mostrar o relatório. Scripts de jogos tem o contrato de forma de retorno completo.

3b. O mesmo de um contêiner

Um jogo contêiner envia as mesmas duas coisas em seu WebSocket de controle:

{ "type": "scores", "sessionId": "…",
  "scores": { "high-score": { "<userId>": 740 }, "fastest-100": { "<userId>": 41250 } } }

{ "type": "achievements", "sessionId": "…",
  "unlocks": { "<userId>": ["century"] } }

scores também pode ser incluído em qualquer envelope de resposta do qual seu contêiner retorna /sessions. O aplicam-se as mesmas regras: apenas participantes, melhor pontuação mantida, chaves desconhecidas ignoradas. Ver Servidores de jogos em contêiner.

4. Mostre-os em seu jogo

Seu cliente lê tudo com o token de lançamento que já possui. Nada aqui precisa do token do proprietário.

Encontre as placas.

const boards = await api(`/api/v1/games/${slug}/leaderboards`);
// [{ id, key: "high-score", name: "High score", sortDirection: "desc", ... }, ...]
const high = boards.find(b => b.key === "high-score");

Somente placas ativas são listadas.

Leia um quadro.

const page = await api(`/api/v1/leaderboards/${high.id}/entries?page=1&pageSize=10`);
// { items: [{ rank, username, score, ... }], total, page, pageSize }
const friends = await api(`/api/v1/leaderboards/${high.id}/entries?friendsOnly=true&pageSize=10`);

Por um time-ms tabuleiro, formate a pontuação como um tempo: 41250 → 0:41.25.

Conquistas.

  • GET /api/v1/games/{slug}/achievements lista todas as conquistas com o jogador unlocked estado. Os segredos permanecem ocultos até serem conquistados.
  • O desbloqueio em si chega ao vivo ws/v1/games como {"type":"achievement","data":{key,name,description,points,...}}. Mostre um brinde quando isso acontecer. A chamada list no carregamento captura qualquer coisa desbloqueada enquanto o soquete estava fechado.

Ver Conquistas para o quadro.

5. Cuide deles

Renomeie um tabuleiro ou altere seus limites.

curl -s -X PUT "$API/api/v1/me/github-games/$GAME_ID/leaderboards/$BOARD_ID" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H "Content-Type: application/json" \
  -d '{ "name": "All-time high score", "maxScore": 2000000 }'

Novos limites aplicam-se apenas a novas pontuações.

Aposente um tabuleiro, mas mantenha suas pontuações. Enviar { "isActive": false }. A diretoria deixa de aceitar pontua e desaparece da lista do jogo. Suas entradas ainda podem ser lidas por id.

Redefinir de acordo com uma programação. Dê um quadro "resetSchedule": "daily", "weekly" ou "monthly" (em criar, ou mais tarde com PUT) e recomeça às 00:00 UTC de cada período — perfeito para um "isso melhor da semana" placa ao lado de uma de todos os tempos. Nada a fazer em seu roteiro: relate as pontuações normalmente e a primeira pontuação de cada jogador em um novo período conta. Ver Redefinir programações.

Comece uma nova temporada manualmente. Para uma temporada única, em vez de um cronograma, crie um novo quadro (high-score-s2), aponte seu script para ele e retire o antigo.

Exclua um quadro. DELETE .../leaderboards/{id} remove o quadro e todas as suas entradas, e não pode ser desfeito.

Edite uma conquista. PUT .../achievements/{achievementId} com qualquer um name, description, icon, secret e points. A chave nunca muda.

Exclua uma conquista. Isso funciona apenas para aquele que você criou e que ninguém desbloqueou ainda. As conquistas conquistadas são permanentes.

Mova uma conquista para o código. Declare a mesma chave em game.achievements e publicar. O declaração assume a conquista existente e os jogadores que a possuem a mantêm.

Resposta Significado
404 O jogo não é seu, ou o tabuleiro ou conquista não pertence a ele
409 "… back-end do servidor…" O jogo não tem server= ou container.image=
409 "já tem…" A chave é tomada, por um conselho ou por uma conquista declarada ou criada
409 "declarado pelo servidor do jogo" Altere essa conquista em seu código
409 "já desbloqueado" Os jogadores o seguram, então não pode ser excluído
400 Uma chave com outros caracteres, um nome ausente ou minScore > maxScore

Limites: 2.048 tabelas de classificação e 200 conquistas criadas por jogo, além de até 100 declaradas.

Lista de verificação

  • [ ] O jogo tem um server= roteiro ou container.image=, e gameSlug está definido em GET /me/github-games.
  • [] Cada placa possui uma chave estável e o direito scoreType e sortDirection (eles não podem mudar mais tarde).
  • [] O servidor retorna scores e achievements (script) ou envia as mensagens de controle (contêiner), elaboradas a partir do estado autoritativo.
  • [ ] O cliente encontra pranchas com GET /games/{slug}/leaderboards, nunca codifica seus IDs e lê entradas por ID.
  • [] O cliente carrega GET /games/{slug}/achievements e faz um brinde no achievement quadro.
  • [ ] Placas antigas são retiradas com isActive: false em vez de excluído, a menos que você realmente queira que as pontuações desapareçam.
