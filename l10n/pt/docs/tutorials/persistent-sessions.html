Tutorial: sessões persistentes — jogos que pausam quando todos saem

Normalmente a plataforma termina uma partida que ninguém está jogando: uma vez que todos os jogadores se desconectaram e ninguém voltou em cinco minutos, a sessão termina como abandoned com razão players_left (ver API de jogos – WebSocket de jogabilidade). Isso é certo para um xadrez jogo ou corrida, e errado para uma fazenda, um construtor de cidade, uma masmorra compartilhada ou qualquer mundo, um grupo de os jogadores retornam ao longo de dias.

Um jogo pode pedir sessões persistentes em vez de. Uma sessão persistente é pausada quando seus jogadores se desconectam:

  1. O último jogador sai.
  2. Após cerca de 15 segundos sem ninguém conectado, a plataforma pausas a sessão. Nada funciona: um jogo de script não ganha onTick chamadas e a sessão de um jogo contêiner é removida do recipiente.
  3. A sessão permanece pausada dentro da sua política de retenção de recuperação. Ler /sessions/{id}/recovery para qualquer expiração, em vez de presumir que será mantido para sempre.
  4. O primeiro jogador a se conectar ws/v1/games currículos isso, antes que seu primeiro comando seja manipulado. O jogo continua de onde parou.

Esta página mostra como ativá-lo, como evitar que os relógios do jogo entrem em pausa e o que seu cliente precisa fazer.

1. Ative

Persistência é uma declaração por jogo, lida quando seu jogo é publicado ou atualizado — publique uma atualizar depois de alterá-lo. Deve ser literal true ou false; qualquer outra coisa conta como não declaração, e um jogo que não declara nada se comporta como antes.

Jogo de roteiro - uma estática persistent no game objeto (ver Scripts de jogos):

globalThis.game = {
  persistent: true,
  tickRateHz: 1,
  createSession(ctx) { /* ... */ },
  onPlayerMessage(ctx) { /* ... */ },
  onTick(ctx) { /* ... */ }
};

Jogo de contêiner — persistent em seu GET /describe resposta (veja Servidores de jogos em contêiner):

{ "protocol": 1, "tickRateHz": 20, "maxSessions": 48, "persistent": true }

Nada muda na forma como as sessões são criadas: matchmaking, convites, endpoint de IA e tempo real todas as salas produzem sessões persistentes para um jogo persistente.

2. Mantenha o tempo do jogo parado durante a pausa

A plataforma não reescreve ctx.now - ele continua sendo o verdadeiro relógio de parede, então a qualquer hora que você mostrar aos jogadores (um prazo, um "colheita pronta em") continua significando o que diz. Em vez disso, persistente sessões recebem um campo de contexto extra:

ctx.pausedMs   // total milliseconds this session has spent paused, so far

Ele só cresce, e apenas em sessões persistentes (outros jogos nunca entram em campo). Subtraia e você tenha um relógio de jogo que para enquanto ninguém está lá:

function gameTime(ctx) {
  return ctx.now - (ctx.pausedMs || 0);
}

globalThis.game = {
  persistent: true,
  tickRateHz: 1,

  createSession(ctx) {
    return { ok: true, sessionState: { lastTick: gameTime(ctx), crops: [] } };
  },

  onTick(ctx) {
    var state = ctx.sessionState;
    var t = gameTime(ctx);
    var dt = t - state.lastTick;      // never includes the time the world was paused
    state.crops.forEach(function (crop) { crop.growth += dt; });
    state.lastTick = t;
    return { ok: true, sessionState: state };
  },

  onPlayerMessage(ctx) { /* ... */ }
};

Armazene seus próprios carimbos de data/hora no tempo do jogo (gameTime(ctx)), não em ctx.now, e compare-os apenas contra o tempo de jogo. Se você querer o mundo siga em frente enquanto ninguém está olhando - colheitas que crescem durante a noite - use ctx.now em vez disso, acompanhe o primeiro tick após um currículo. De qualquer forma, é seu escolha; a plataforma apenas informa o que aconteceu.

Dois detalhes do momento:

  • Durante os aproximadamente 15 segundos entre a saída do último jogador e a pausa, a sessão ainda está marcou normalmente. Um jogador cuja conexão cai e volta direto não causa pausa.
  • Depois de um currículo, o próximo onTick vem um intervalo de tick depois. O tempo pausado não é reproduzido como um acúmulo de ticks perdidos.

Um contêiner recebe pausedMs no mesmo lugar: no POST /sessions corpo ele é enviado quando a sessão é restaurada após uma pausa.

3. Seu cliente

Uma sessão pausada ainda é uma sessão ativa, portanto o fluxo do cliente é aquele que você já possui:

  • Listar mundos para voltar com GET /api/v1/games/{slug}/sessions/mine. Cada entrada tem um pausedAt carimbo de data/hora enquanto está pausado e null enquanto alguém está nele, para que você possa mostrar "pausado desde…" ou "2 amigos jogando agora" (ver API de jogos – Sessões).
  • Junte-se novamente abrindo ws/v1/games?sessionId=… exatamente como antes. O currículo acontece durante o conectar. Não há nenhum especial "retomado" quadro para isso - o jogo simplesmente está rodando quando seu primeiro chega o comando - então solicite ou aguarde a mensagem normal de estado completo do seu jogo, como faria em qualquer reconectar.
  • Lidar com um currículo com falha. Se a plataforma não puder retomar a sessão — provavelmente um contêiner jogo cujo servidor ainda está iniciando — você recebe {"type":"error","error":"…"} e a tomada está fechado com código 1001. A sessão permanece pausada e nada é perdido. Reconecte após um breve espera (alguns segundos, crescente) e mostrar "começando o mundo…" em vez de um erro.
  • presence os frames funcionam normalmente, para que os outros jogadores vejam quem está no mundo agora.

4. Encerrando uma sessão persistente

Uma sessão persistente termina quando:

  • seu jogo relata um result (valor de retorno do script ou mensagem de controle do contêiner), ou
  • o dono do jogo termina (DELETE /api/v1/me/github-games/{id}/sessions/{sessionId}),
  • o último membro deixa explicitamente um mundo sem espaço através /sessions/{id}/leave, ou
  • seus dados de recuperação pausados ​​expiram de acordo com a política de retenção da implantação.

A desconexão deixa a associação intacta; sair explicitamente desiste de ser membro. Ver Ciclo de vida e recuperação da sessão para ambos os fluxos.

Pedir um novo jogo faz não retirar as pausadas do jogador, e as sessões pausadas ainda contam contra o limite de sessões simultâneas por jogador (20 por padrão). Dê aos jogadores uma maneira de terminar ou deixe um mundo - um "abandonar o mundo" comande suas respostas de script com um result, por exemplo. Caso contrário, um jogador que tenha preenchido o seu limite não poderá começar nada novo.

onPlayerMessage(ctx) {
  var msg = ctx.message.data;
  if (msg.type === "close-world" && ctx.message.from === ctx.sessionState.ownerId) {
    return { ok: true, sessionState: ctx.sessionState, result: { kind: "closed" } };
  }
  /* ... */
}

5. Jogos de contêineres: estacionamento

Para um jogo de contêiner, uma pausa é um parque:

  1. A plataforma pede um instantâneo final (GET /sessions/{id}/snapshot) e armazena-o de forma durável.
  2. Isso destrói a sessão (DELETE /sessions/{id}). Seu contêiner para de simulá-lo e se se não tiver outras sessões, a implantação poderá ser interrompida após o período ocioso.
  3. Na próxima junção, ele recria a sessão com POST /sessions, carregando o armazenado snapshot e o atualizado pausedMs — a mesma solicitação de uma restauração de falha — ativando uma implantação interrompida primeiro, se necessário.

Portanto, o instantâneo que você retorna deve ser suficiente para reconstruir o mundo inteiro, não apenas para retomar alguns segundos de jogo. Se esse snapshot final falhar, a sessão será estacionada desde seu último snapshot periódico. ponto de verificação. Ao contrário de uma falha, um estacionamento e restauração não é contabilizado no seu orçamento de reinicialização e os jogadores não recebem resumed frame: ninguém estava lá para ver o estado retroceder.

Lista de verificação

  • [ ] persistent: true declarado (script) ou retornado de /describe (contêiner) e uma atualização publicada.
  • [] Uso de cronômetros de jogo ctx.now - ctx.pausedMs, ou usar deliberadamente ctx.now e recuperar o atraso.
  • [ ] As listas de clientes sessions/mine, mostra pausedAt, e se junta novamente ws/v1/games.
  • [] O cliente tenta novamente com espera após um error seguido pelo código de fechamento 1001 ao conectar.
  • [] Os jogadores têm uma maneira de acabar com um mundo, para que nunca fiquem presos no limite da sessão.
  • [ ] (Container) snapshots reconstroem o mundo inteiro.
