Tutorial: jogadores integrados com chave pública

Uma conta StarHermit não precisa do Google, GitHub ou qualquer outro provedor de login. Sua credencial pode será um par de chaves que seu jogo gera no dispositivo do jogador, além de um endereço de e-mail que o jogador confirma uma vez. Depois disso, seu jogo entra silenciosamente em cada lançamento, assinando um desafio com a chave. O jogador nunca digita uma senha e nunca precisa visitar uma página do StarHermit.

Este tutorial constrói esse fluxo de ponta a ponta: gere a chave, registre-a, espere o jogador confirme, faça login, mantenha a sessão e administre segundos dispositivos e chaves perdidas.

Use isso para jogos nativos e independentes, inicializadores, compilações Steam/Epic/GOG e ferramentas de desktop — qualquer coisa que rode na máquina do jogador e possa manter uma chave privada lá.

Use outra coisa para

  • Um jogo de navegador hospedado no StarHermit, que já recebe um token de lançamento quando aberto em no painel ou pode mostrar um Botão de login.
  • Um pipeline de CI, que deve registrar uma chave de uma sessão OAuth sem etapa de email: Tutorial: fazer upload de compilações de CI/CD.
  • Um servidor de jogo dedicado, que tem seu próprio token de implantação e não pode criar ou atuar como jogadores: Tutorial: publicar um servidor dedicado.

O que o jogador vê

  1. Seu jogo pede um endereço de e-mail e consentimento para criar uma conta StarHermit.
  2. Eles abrem o e-mail de confirmação, clicam no link e pressionam Confirmar na página que ele abre.
  3. De volta ao jogo, eles estão logados. Em lançamentos posteriores, nada é solicitado.

É necessário um endereço de e-mail e o jogador deve confirmá-lo uma vez. Não há como criar um Conta StarHermit silenciosamente apenas com uma identidade Steam, Epic ou GOG.

Antes de começar

O código nesta página é JavaScript simples usando WebCrypto e fetch, então ele roda em um navegador, em Electron e no Nó 20 ou posterior. O js blocos abaixo, em ordem, formam um módulo ES - salve-os juntos como starhermit-key-auth.js. Qualquer outra linguagem funciona da mesma maneira: o passo 1 fornece a exata formatos de bytes e etapa 3 os bytes exatos a serem assinados.

const API = 'https://api.starhermit.com';

const b64 = (bytes) => btoa(String.fromCharCode(...new Uint8Array(bytes)));

1. Crie a chave do dispositivo

Gerar um par de chaves por instalação, na primeira vez que seu jogo precisar de uma conta. O privado A chave nunca sai do dispositivo: nem para seus servidores, nem para o StarHermit.

keyType keyData (Base64 padrão) Assinatura (base64 padrão)
Ed25519 - recomendado A chave pública bruta de 32 bytes A assinatura Ed25519 bruta de 64 bytes
ECDSA-P256 O ponto público: 65 bytes não compactados (04‖X‖Y) ou compactado de 33 bytes ECDSA com SHA-256, ASN.1 codificado por DER
RSA-PSS SubjectPublicKeyInfo DER, módulo de 2048–8192 bits, expoente ≤ 32 bits RSASSA-PSS, SHA-256, MGF1-SHA-256, sal de 32 bytes

keyData tem no máximo 2.000 caracteres. Uma chave pertence a uma conta na plataforma.

Escolha Ed25519 a menos que sua plataforma não possa produzi-lo. Se você usa ECDSA, observe que WebCrypto, O Windows CNG e a maioria dos armazenamentos de chaves de hardware retornam a assinatura como bruta r‖s (64bytes). Eremita Estelar espera DER, então converta-o - o módulo abaixo o faz.

// One key per installation. The private key can sign but is never exported.
export async function createDeviceKey(keyType = 'Ed25519') {
  if (!['Ed25519', 'ECDSA-P256'].includes(keyType)) throw new Error('This helper supports Ed25519 or ECDSA-P256');
  const algorithm = keyType === 'Ed25519'
    ? { name: 'Ed25519' }
    : { name: 'ECDSA', namedCurve: 'P-256' };
  const pair = await crypto.subtle.generateKey(algorithm, false, ['sign', 'verify']);
  return {
    keyType: keyType === 'Ed25519' ? 'Ed25519' : 'ECDSA-P256',
    keyData: b64(await crypto.subtle.exportKey('raw', pair.publicKey)),
    privateKey: pair.privateKey,
  };
}

Armazene a chave privada onde o sistema operacional a protege. Em um navegador ou renderizador Electron, um não extraível CryptoKey pode ser mantido no IndexedDB como está. Um jogo nativo deve usar o keystore da plataforma — Windows DPAPI ou CNG, macOS Keychain, libsecret no Linux. Loja keyType e keyData próximo a ele; você os envia com cada solicitação.

2. Inicie o registro

Peça o endereço de e-mail e consentimento do jogador e então:

async function post(path, body) {
  const res = await fetch(API + path, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  });
  return { status: res.status, body: await res.json().catch(() => ({})) };
}

function fail(step, { status, body }) {
  return Object.assign(new Error(`${step}: ${body.error ?? status}`), { status, body });
}

export async function register(key, email) {
  const res = await post('/api/v1/auth/public-key/register',
    { email, keyType: key.keyType, keyData: key.keyData });
  if (res.status !== 202) throw fail('register', res);
  return res.body; // { registrationId, email, emailSent, deferralReason, message }
}

202 significa que StarHermit aceitou o registro. Se emailSent é false, o e-mail será colocado na fila e ainda chegará; deferralReason diz por que esperou. Nada está vinculado a nenhuma conta ainda.

Três regras moldam sua IU:

  • Um registro por endereço de e-mail e um por endereço IP, a cada 24 horas. Uma segunda tentativa é 429 com Retry-After. Peça ao jogador que confirme o endereço antes de enviá-lo, pois houve um erro de digitação custa-lhes um dia. Envie a solicitação do dispositivo do jogador, nunca através do seu próprio servidor: cada player compartilharia o IP do seu servidor e seu registro único diário.
  • O link expira após 4 horas. Se caducar, o jogador poderá se cadastrar novamente uma vez decorridas 24 horas estão acordados.
  • 400 significa que o endereço de e-mail ou material chave foi rejeitado; error diz qual.

3. Faça login com a chave

Entrar é um desafio e uma resposta. POST /api/v1/auth/public-key/challenge retorna:

{
  "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
  "payload": {
    "challengeId": "4fc4d72b-4c12-41ca-a500-dc13cccc3865",
    "fingerprint": "9c0b7a…",
    "issuer": "starhermit",
    "audience": "starhermit",
    "expiry": "2026-10-09T14:21:41.9264875+00:00",
    "nonce": "NmL+tgMum6HXU/pa3T9xjQ==",
    "clientTimestamp": "2026-10-09T14:16:41.9265739+00:00"
  },
  "expiresIn": 300
}

O que você assina não é o JSON que você recebeu. StarHermit verifica a assinatura por conta própria serialização de payload:

  • JSON compacto, sem espaços em branco;
  • Caso Pascal nomes dos membros, exatamente na ordem ChallengeId, Fingerprint, Issuer, Audience, Expiry, Nonce, ClientTimestamp;
  • cada valor copiado exatamente como servido — não analise e reformate as datas;
  • todo + no nonce escrito como \u002B. O + nas datas permanece como está.

Para o desafio acima, os bytes assinados são a codificação UTF-8 de:

{"ChallengeId":"4fc4d72b-4c12-41ca-a500-dc13cccc3865","Fingerprint":"9c0b7a…","Issuer":"starhermit","Audience":"starhermit","Expiry":"2026-10-09T14:21:41.9264875+00:00","Nonce":"NmL\u002BtgMum6HXU/pa3T9xjQ==","ClientTimestamp":"2026-10-09T14:16:41.9265739+00:00"}

Entenda tudo errado e a resposta é 401 "Invalid signature.", que nenhuma nova tentativa corrigirá.

const FIELDS = ['challengeId', 'fingerprint', 'issuer', 'audience', 'expiry', 'nonce', 'clientTimestamp'];

export function challengeSigningBytes(payload) {
  const members = FIELDS.map((field) => {
    let value = JSON.stringify(payload[field]);
    if (field === 'nonce') value = value.replaceAll('+', '\\u002B');
    return `"${field[0].toUpperCase()}${field.slice(1)}":${value}`;
  });
  return new TextEncoder().encode(`{${members.join(',')}}`);
}

export async function signChallenge(key, payload) {
  const data = challengeSigningBytes(payload);
  if (key.keyType === 'Ed25519')
    return b64(await crypto.subtle.sign({ name: 'Ed25519' }, key.privateKey, data));
  // WebCrypto returns an ECDSA signature as raw r||s; the server expects ASN.1 DER.
  const rs = new Uint8Array(
    await crypto.subtle.sign({ name: 'ECDSA', hash: 'SHA-256' }, key.privateKey, data));
  return b64(derEcdsaSignature(rs));
}

function derEcdsaSignature(rs) {
  const integer = (bytes) => {
    let i = 0;
    while (i < bytes.length - 1 && bytes[i] === 0) i++;
    const value = [...bytes.slice(i)];
    return value[0] & 0x80 ? [0x02, value.length + 1, 0, ...value] : [0x02, value.length, ...value];
  };
  const body = [...integer(rs.slice(0, 32)), ...integer(rs.slice(32))];
  return new Uint8Array([0x30, body.length, ...body]);
}

// Resolves to { userId, accessToken, refreshToken }, or null while the key is not attached to
// an account yet — the player has not confirmed, the link expired, or the key was revoked.
export async function signIn(key) {
  const { keyType, keyData } = key;
  const challenge = await post('/api/v1/auth/public-key/challenge', { keyType, keyData });
  if (challenge.status !== 200) throw fail('challenge', challenge);
  const signature = await signChallenge(key, challenge.body.payload);
  const done = await post('/api/v1/auth/public-key/complete',
    { challengeId: challenge.body.challengeId, signature, keyType, keyData });
  if (done.status === 200) return done.body;
  if (done.status === 401 && done.body.error === 'Public key not registered or revoked.') return null;
  throw fail('complete', done); // "Invalid signature." will never succeed: fix it, don't retry it
}

Um desafio dura cinco minutos e é descartável, mesmo quando a tentativa falha, então solicite um novo para cada tentativa. Desafie e conclua o compartilhamento de um limite de 60 solicitações por minuto por endereço IP.

4. Aguarde a confirmação do jogador

O link enviado por e-mail abre uma página do StarHermit dizendo o que a confirmação fará; abri-lo muda nada, então um scanner de e-mail que visualiza o link não pode confirmar em nome do jogador. Quando o jogador pressiona Confirmar, StarHermit cria sua conta, anexa sua chave e marca o endereço verificado. Se uma conta já usa esse endereço, a página informa isso e a chave é adicionada a ela em vez disso, um jogador que já possui uma conta StarHermit a mantém. Em starhermit.com eles pousam no painel do StarHermit, já conectado.

Seu jogo nunca recebe os tokens dessa página, e não precisa deles. O jogador pode confirme em um telefone ou em outro navegador. Assim que a chave for anexada, seu jogo pode simplesmente fazer login com isso. Então mostre um "verifique sua caixa de entrada" tela e continue tentando:

// Poll until the player confirms the emailed link. Two requests per attempt, so every 5 s stays
// well inside the 60-per-minute sign-in limit.
export async function waitUntilConfirmed(key, { intervalMs = 5000, signal } = {}) {
  for (;;) {
    signal?.throwIfAborted();
    const session = await signIn(key);
    if (session) return session;
    await new Promise((resolve) => setTimeout(resolve, intervalMs));
  }
}

Juntando as etapas 1 a 4:

import { createDeviceKey, register, signIn, waitUntilConfirmed } from './starhermit-key-auth.js';

const key = await loadStoredKey() ?? await saveKey(await createDeviceKey());
let session = await signIn(key);                // a returning player is signed in here
if (!session) {
  const email = await askForEmailAndConsent();
  await register(key, email);
  showCheckYourInbox(email);
  session = await waitUntilConfirmed(key, { signal: cancelButton.signal });
}

loadStoredKey, saveKey, askForEmailAndConsent e showCheckYourInbox é seu para escrever. Ofereça um Cancelar que aborta a espera e interrompe a pesquisa após quatro horas, quando o link expira.

Continue pesquisando mesmo que a página de confirmação da sua plataforma redirecione de volta para o seu site. O jogador muitas vezes abre o e-mail em um dispositivo diferente daquele que está aguardando e o redirecionamento não chega a lugar nenhum perto da tela de espera; polling é o que conecta o dispositivo em espera. Se o redirecionamento chegar em uma segunda aba, faça login com apenas uma delas e revogue a sessão extra, ou o jogador acaba com dois.

5. Mantenha a sessão

complete retorna um token de acesso de 15 minutos e um token de atualização que dura sete dias e é rotativo. Envie o token de acesso como Authorization: Bearer …e atualize antes que expire:

// Resolves to the new pair, or null when the session is over — sign in with the key again.
export async function refresh(refreshToken) {
  const res = await post('/api/v1/auth/refresh', { refreshToken });
  return res.status === 200 ? res.body : null; // { accessToken, refreshToken }
}

Substituir ambos fichas todas as vezes. Apresentar um token de atualização usado encerra toda a sessão, então faça certifique-se de que dois threads ou processos nunca sejam atualizados ao mesmo tempo. Quando refresh retorna null, chamar signIn - nenhum e-mail está envolvido. A chave é a credencial de longa duração; tokens são apenas um cache disso.

6. Conclua a configuração da conta

Termos. Uma nova conta deve aceitar os termos atuais do StarHermit antes de poder usar qualquer outra coisa. Chamar GET /api/v1/me. Se termsAcceptanceRequired é true, mostre o texto de GET /api/v1/terms, e quando o jogador aceitar, envie seu hash para POST /api/v1/me/terms/accept. Verifique novamente em lançamentos posteriores, pois os termos foram revisados. Detalhes: Aceitação dos termos.

Nome. A conta começa com um pk-… nome de usuário. Deixe o jogador escolher um apelido:

PATCH /api/v1/me
Authorization: Bearer <access-token>
Content-Type: application/json

{ "nickname": "RookPilot" }

A partir daqui a conta é como qualquer outra: amigos, chat, matchmaking, salvamentos na nuvem, conquistas.

7. Segundos dispositivos, chaves perdidas e limites

Um segundo dispositivo gera sua própria chave e a registra com o mesmo endereço de e-mail. Quando o jogador confirma, a chave se junta à sua conta existente em vez de criar uma nova. As 24 horas o limite por endereço também se aplica aqui.

Um dispositivo perdido ou roubado. POST /api/v1/auth/public-key/revoke-request com { "email": "…" } envia por e-mail um link para uma página; confirmando há revoga todo chave na conta e encerra as sessões essas chaves conectadas. Abrir o link por si só não muda nada. O pedido sempre responde 202 com a mesma mensagem, quer o endereço tem uma conta. O link expira após quatro horas e uma conta pode solicitar uma vez a cada 15 horas. minutos. Depois, cada dispositivo restante é registrado novamente (etapa 2).

O que uma conta somente chave não pode fazer. Algumas alterações protegem as credenciais da conta, então elas exigem uma sessão conectada por meio de um provedor como Google ou GitHub:

Ação Conta somente chave
Adicione uma chave ou revogue outros dispositivos (POST /me/public-keys, DELETE /me/public-keys/{id} ou /all) 403 — inscreva-se por meio de registro por e-mail ou use uma sessão autenticada por OAuth
Alterar o endereço de e-mail da conta 403 oauth_session_required — não é possível até que um provedor esteja vinculado
Revogar a própria chave desta instalação DELETE /api/v1/me/public-keys/current, usando sua sessão completa da conta de chave pública; descartar credenciais locais após sucesso

Para gerenciar outras credenciais ou alterar o e-mail, vincule um provedor. Quando uma conta somente chave vincula uma, a vinculação é mantida até que o jogador confirme em seu e-mail. Depois disso, o login do provedor pode fazer tudo acima. Ver authorize?link=true.
