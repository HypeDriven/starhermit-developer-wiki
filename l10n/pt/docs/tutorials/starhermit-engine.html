Tutorial: construir um jogo com o motor StarHermit

O O mecanismo StarHermit é a forma recomendada de criar jogos para publicação no StarHermit. Você cria o jogo uma vez e o mesmo pacote pode ser reproduzido automaticamente em um navegador e nativamente em todas as plataformas suportadas pelo mecanismo. O jogo nativo oferece desempenho e recursos adicionais. A disponibilidade depende da versão do mecanismo: 1.1.0 e posteriores possuem um tempo de execução do Windows e um tempo de execução da Web (1.0.0 era apenas para Windows). Esta página descreve o motor 1.6.0; o que cada versão mudou está listado sob Versões do motor.

O motor StarHermit funciona jogos de roteiro: um jogo inteiro escrito em TypeScript (ou JavaScript) e executado por um executável de mecanismo pré-construído, o tempo de execução StarHermit, sem compilar nenhum código nativo. Você escreve a lógica do jogo nos módulos integrados do mecanismo - uma cena 3D, entrada, HUD, áudio, armazenamento e a plataforma StarHermit - e o tempo de execução faz o resto: janelas, renderização no GPU, som, menu de opções, login e jogo online. Os jogadores abrem o jogo em starhermit.com em seu navegador, onde sua página carrega o mecanismo que seu jogo solicita neste wiki, ou jogue-o nativamente no Cliente StarHermit Windows, que instala esse mecanismo.

1. O que é um jogo de script

Um jogo de script é uma pasta (um pacote) com um starhermit.txt em seu root, seus módulos TypeScript e seus ativos. Três engine.* linhas no manifesto tornam-no um:

engine.api=1
engine.entry=src/main.ts
engine.version=1.6.0

engine.api é a versão principal da API do host na qual seu código foi escrito, engine.entry o módulo o tempo de execução é iniciado e engine.version a versão exata do motor em que o jogo foi construído e testado para. Os lançamentos são publicados neste wiki em Versões do motor; o o jogo nunca contém o mecanismo em si, portanto, um upload contém apenas seus próprios arquivos.

O tempo de execução trata todos os jogos como não confiáveis: seu código chega à máquina apenas por meio da API do host (seus próprios arquivos de pacote, seu próprio armazenamento, a plataforma para seu próprio ID de jogo), nunca arquivos, processos, conexões de rede arbitrárias ou as credenciais do jogador. Em troca, um jogo não pode travar o tempo de execução ou desligue a janela: uma chamada que dura três segundos traz à tona o próprio tempo de execução "não respondendo" tela, e um erro não detectado encerra o jogo em uma tela de erro a partir da qual o jogador pode reiniciar.

2. Pegue o motor

Jogadores não faça nada: em um navegador, a página do jogo carrega os pins do jogo desta wiki e verifica os hashes que a página carrega; no cliente StarHermit Windows, faça downloads do Play o lançamento (uma vez, compartilhado por cada jogo que o fixa), verifica todos os arquivos em relação ao lançamento hashes publicados e inicia-o.

Desenvolvedores baixe o tempo de execução de uma versão da área do motor:

  • starhermit-1.6.0-windows-x86_64.zip (Windows 10 ou 11, 64 bits), 6,7 MB.

O arquivo contém uma pasta, starhermit-1.6.0-windows-x86_64, com starhermit.exe, o release.json que informa ao tempo de execução qual versão é, a versão web-manifest.json, LICENSE-engine e os avisos de terceiros. É o mesmo mecanismo que o cliente instala e empacota jogos para o tempo de execução da web do lançamento sem rede. Seu tamanho e SHA-256 estão listados em downloads no lançamento native.json; para verifique sua cópia no PowerShell, compare isso sha256 com:

Get-FileHash .\starhermit-1.6.0-windows-x86_64.zip -Algorithm SHA256

Descompacte o arquivo e abra um terminal na pasta descompactada:

.\starhermit.exe --version

starhermit 0.1.0 (host API 1.10, launcher 1; engine release 1.6.0)

Os comandos abaixo são escritos como starhermit; executá-los como .\starhermit.exe dessa pasta ou adicione a pasta ao seu PATH.

3. Crie o jogo

starhermit new star-catcher --title "Star Catcher"

Created Star Catcher in star-catcher: a script game pinned to engine 1.6.0
Play it: starhermit star-catcher
Check it: starhermit check star-catcher
For a native upload (the StarHermit client plays it): starhermit package --native star-catcher
For the web: starhermit package --web star-catcher --out <upload>

A nova pasta contém um ponto de partida jogável – um cubo que salta quando você pressiona Espaço:

star-catcher/
  starhermit.txt             the manifest, pinned to the runtime's own release (engine.version=1.6.0)
  tsconfig.json              TypeScript settings for checking the game
  src/main.ts                the entry module
  .starhermit/starhermit.d.ts  the host API's declarations, for your editor and the type checker

.starhermit/ começa com um ponto, portanto nunca faz parte do pacote. starhermit types star-catcher escreve as declarações novamente, por exemplo, depois de mudar para uma versão mais recente tempo de execução. Cada módulo, membro, unidade, limite e erro da API do host está documentado nesse arquivo.

O tempo de execução não verifica o tipo: ele remove os tipos do TypeScript à medida que carrega cada módulo. Verifique-os você mesmo com TypeScript 5 ou mais recente; com o Node.js instalado, npx executa sem instalar qualquer coisa na pasta do jogo:

cd star-catcher
npx --package typescript tsc -p .

Os arquivos de desenvolvimento ficam fora do pacote: nomes de pontos (como .starhermit/ e .git/), node_modules/, tsconfig.json, jsconfig.json, package.json, arquivos de bloqueio npm, yarn e pnpm, mapas de origem (*.js.map, *.ts.map e similares) e Thumbs.db/desktop.ini. Todo o resto em a pasta faz parte do pacote. Para deixar de fora mais, adicione um .starhermitignore na raiz do jogo com regras no estilo gitignore (* e ? dentro de um nome, ** para qualquer número de pastas, um final / para uma pasta, ! para manter um arquivo, uma regra padrão omite; a última regra de correspondência decide):

notes/
levels/**/draft-*.json
!package.json

Um jogo que lê ou importa um arquivo deixado de fora falha com um erro ao nomear a regra, no desenvolvimento como bem, então starhermit check pega antes de fazer o upload.

4. Escreva a primeira versão

Substitua o gerado starhermit.txt com o manifesto do jogo:

name=Star Catcher
description=Catch the falling stars before the time runs out.
launch=index.html
engine.api=1
engine.entry=src/main.ts
engine.version=1.6.0
engine.capabilities=platform,storage
control.left=KeyA+ArrowLeft | Move left
control.right=KeyD+ArrowRight | Move right
control.start=Space+Enter | Start a round
engine.gamepad.left=LeftStickLeft+DpadLeft
engine.gamepad.right=LeftStickRight+DpadRight
engine.gamepad.start=South
cache..=0

O control.* linhas declaram as ações do jogo com suas teclas padrão (a plataforma controles formato) e engine.gamepad.* seus padrões de gamepad. Jogadores religados no menu Opções do tempo de execução, para que o jogo leia ações, nunca chaves. Um jogo declara até 128 ações: a plataforma mantém as 32 primeiras com a conta do jogador, e o runtime mantém as ligações do resto nas configurações sincronizadas do player. engine.group.<action>=Heading inicia um grupo naquela ação (até o próximo grupo), que a tela de controles mostra sob o título, por exemplo engine.group.left=Movement (host API 1.6). engine.capabilities pergunta o que o jogo usa além do desenho e da entrada: platform para o jogador conectado e online recursos, storage para dados mantidos no dispositivo e na conta do jogador. launch=index.html nomeia o página que joga o jogo em navegadores, que o mecanismo escreve quando você publicar.

Então substitua src/main.ts:

// Star Catcher: catch the falling stars in the basket before the time runs out.
import { frame, onFixedUpdate, onRender, onStart, setFixedRate } from "starhermit:engine";
import {
  AmbientLight,
  BoxGeometry,
  Color,
  DirectionalLight,
  Mesh,
  MeshStandardMaterial,
  PerspectiveCamera,
  SphereGeometry,
  renderer,
  scene,
} from "starhermit:scene";
import { onAction, value } from "starhermit:input";
import { storage } from "starhermit:storage";
import { player } from "starhermit:platform";
import * as draw from "starhermit:draw";

// -- The scene ----------------------------------------------------------------
const camera = new PerspectiveCamera(50, 16 / 9, 0.1, 100);
camera.position.set(0, 4, 12);
camera.lookAt(0, 3, 0);
renderer.camera = camera;
scene.background = new Color(0x0b1020);

const sun = new DirectionalLight(0xfff4e0, 1.2);
sun.position.set(3, 8, 5);
scene.add(sun, sun.target, new AmbientLight(0x6070a0, 0.5));

const basket = new Mesh(new BoxGeometry(2, 0.4, 1), new MeshStandardMaterial({ color: 0x4fa3ff, roughness: 0.4 }));
scene.add(basket);

const starGeometry = new SphereGeometry(0.3, 16, 12);
const starMaterial = new MeshStandardMaterial({ color: 0xffd34d, emissive: 0xffb000, emissiveIntensity: 0.6 });
const stars = Array.from({ length: 3 }, () => {
  const mesh = new Mesh(starGeometry, starMaterial);
  scene.add(mesh);
  return { mesh, x: 0, y: 0, previousY: 0, speed: 0 };
});
type Star = (typeof stars)[number];

// -- The rules ----------------------------------------------------------------
const WIDTH = 6; // the basket moves between -WIDTH and WIDTH
const ROUND = 60; // seconds a round lasts
let basketX = 0;
let previousX = 0;
let score = 0;
let timeLeft = 0; // 0 between rounds
const saved = storage.getJson("best");
let best = typeof saved === "number" ? saved : 0;

function drop(star: Star): void {
  star.x = (Math.random() * 2 - 1) * WIDTH;
  star.y = star.previousY = 8 + Math.random() * 4;
  star.speed = 2 + Math.random() * 2 + score * 0.05;
}

onStart(() => {
  setFixedRate(60);
  for (const star of stars) drop(star);
});

onAction((event) => {
  if (event.action === "start" && event.pressed && timeLeft === 0) {
    score = 0;
    timeLeft = ROUND;
    for (const star of stars) drop(star);
  }
});

onFixedUpdate((step) => {
  previousX = basketX;
  for (const star of stars) star.previousY = star.y;
  if (timeLeft === 0) return;
  // An action's value is 0 to 1, so a stick steers gently and a key fully.
  const steer = value("right") - value("left");
  basketX = Math.max(-WIDTH, Math.min(WIDTH, basketX + steer * 9 * step));
  for (const star of stars) {
    star.y -= star.speed * step;
    if (star.y < 0.6 && star.y > 0 && Math.abs(star.x - basketX) < 1.2) {
      score += 1;
      drop(star);
    } else if (star.y < -1) {
      drop(star);
    }
  }
  timeLeft = Math.max(0, timeLeft - step);
  if (timeLeft === 0 && score > best) {
    best = score;
    storage.setJson("best", best);
  }
});

// -- Drawing ------------------------------------------------------------------
onRender((alpha) => {
  // Between two fixed steps: draw where things are at this moment.
  basket.position.set(previousX + (basketX - previousX) * alpha, 0.2, 0);
  for (const star of stars) {
    star.mesh.position.set(star.x, star.previousY + (star.y - star.previousY) * alpha, 0);
  }
  hud();
});

function hud(): void {
  const { width, height, scale } = frame();
  const size = 22 * scale;
  const name = player()?.displayName ?? "Guest";
  draw.text(`${name}   score ${score}   best ${best}`, 16 * scale, 16 * scale, { size, color: "#e8ecf4" });
  if (timeLeft > 0) {
    draw.text(`${Math.ceil(timeLeft)} s`, width - 16 * scale, 16 * scale, { size, color: "#ffd34d", align: "end" });
  } else {
    draw.rect(0, height / 2 - 40 * scale, width, 80 * scale, [0, 0, 0, 0.5]);
    draw.text("Press Space to play", width / 2, height / 2 - 12 * scale, { size, color: "#ffffff", align: "center" });
  }
}

O que cada parte faz:

  • A cena. starhermit:scene segue three.js: uma câmera, luzes, malhas feitas de uma geometria e um material, scene.add. As distâncias são metros, ângulos radianos e cores sRGB.
  • As regras. onFixedUpdate funciona com taxa fixa setFixedRate(60) pede, 60 vezes por em segundo lugar, qualquer que seja a taxa de quadros, para que o jogo seja reproduzido da mesma forma em todas as máquinas. value("right") é o valor da ação de 0 a 1, de modo que um joystick de gamepad seja direcionado suavemente e uma tecla seja totalmente direcionada, e onAction ouve cada pressão, aqui para iniciar uma rodada.
  • Desenho. onRender é executado uma vez por quadro com alpha, a que distância o quadro está entre os dois últimos etapas fixas; posições traçadas entre previous e os valores atuais movem-se suavemente em qualquer atualização taxa. starhermit:draw desenha o HUD sobre a cena em pixels da janela; frame().scale converte pixels lógicos para telas de alto DPI.
  • A melhor pontuação permanece no dispositivo do jogador através starhermit:storage, mantido separado por cada jogador.

5. Execute-o nativamente

starhermit check star-catcher

package=Directory files=3 bytes=6378 name="Star Catcher" api=1 entry=src/main.ts capabilities=platform,storage actions=left,right,start
left out: tsconfig.json (default rule tsconfig.json)
web=linked modules=2
runnable=true engine="TypeScript" frames=120 probes=0
PASS package src/main.ts: valid; 120 frames headless

check valida o pacote (manifesto, caminhos, tamanhos) e reproduz 120 frames sem janela, então um erro de sintaxe, uma importação desconhecida ou uma exceção na inicialização é exibida aqui com seu arquivo, linha e coluna. Ele imprime o jogo console saída conforme avança ([game] log src/main.ts:12:5: text, no máximo 1.000 linhas; --quiet esconde), falha em um jogo que traria à tona o "não respondendo" tela e links seus módulos da maneira como os navegadores os carregam, então um jogo que não carrega em um navegador falha aqui também (veja Diferenças nativas e de navegador). Então jogue:

starhermit star-catcher

Pressione Espaço para iniciar uma rodada e as teclas de seta (ou A e D, ou um gamepad) para dirigir. F1 sempre abre o menu próprio do runtime: gráficos, áudio, controles (religação), conta e encerramento. Seu o jogo não pode desenhar ou ler esse menu, e nenhum jogo pode vincular F1.

Durante o desenvolvimento, adicione --dev (starhermit star-catcher --dev): o tempo de execução imprime o jogo console saída no mesmo formato e aponta erros em suas linhas TypeScript.

6. Muitas coisas ao mesmo tempo: starhermit:world

Nativamente, o TypeScript do seu jogo é executado no próprio interpretador de script do mecanismo, que mantém cada jogo dentro dos seus orçamentos de tempo e memória; nos navegadores, ele é executado no mecanismo JavaScript do navegador, em um trabalhador a página pode parar. As decisões e algumas dezenas de objetos custam pouco lá, mas por entidade trabalho – mover milhares de partículas, uma multidão, um rebanho – significaria milhares de passos interpretados cada quadro. Para isso o motor possui starhermit:world:

  • tabelas manter os dados da entidade em colunas digitadas (números e vetores) na memória do jogo;
  • grãos são funções comuns de uma linha que o tempo de execução compila e executa nativamente cada linha de uma tabela, sem entrar em script;
  • o agendar executa kernels em cada quadro e ligações desenhe uma mesa como uma só InstancedMesh (ou nós de cena de unidade), compondo cada instância nativamente.

Seu script toma as decisões; o tempo de execução faz a aritmética por linha. Adicione um céu noturno de 4.000 brilhos cintilantes por trás do jogo como src/sky.ts:

// The night sky behind the game: 4,000 twinkling sparkles. Their data lives
// in a starhermit:world table, a kernel moves every one of them natively each
// frame, and an instance binding draws the table as one InstancedMesh, so the
// game's script runs no per-sparkle code at all.
import { InstancedMesh, MeshBasicMaterial, SphereGeometry, scene } from "starhermit:scene";
import { bind, kernel, schedule, table } from "starhermit:world";

const COUNT = 4_000;

// One row per sparkle: where it hangs, how it twinkles, and what the kernel
// writes each frame (its height and size).
const sky = table("sky", COUNT, {
  base: "vec3",
  phase: "f32",
  rate: "f32",
  y: "f32",
  size: "f32",
});
sky.spawn(COUNT);

// Filled once from script, through typed arrays over the table's memory.
const base = sky.column("base");
const phase = sky.column("phase");
const rate = sky.column("rate");
for (let i = 0; i < COUNT; i++) {
  base[i * 3] = (Math.random() * 2 - 1) * 40;
  base[i * 3 + 1] = Math.random() * 24 - 2;
  base[i * 3 + 2] = -10 - Math.random() * 30;
  phase[i] = Math.random() * Math.PI * 2;
  rate[i] = 0.5 + Math.random() * 2;
}

// An ordinary function of one row. The runtime compiles it and runs it over
// every live row without entering script.
const twinkle = kernel(sky, (r, u: { drift: number }, f) => {
  r.y = r.base.y + Math.sin(f.time * u.drift + r.phase) * 0.3;
  r.size = 0.04 + 0.04 * Math.abs(Math.sin(f.time * r.rate + r.phase));
});

const mesh = new InstancedMesh(new SphereGeometry(1, 6, 4), new MeshBasicMaterial({ color: 0xcfd8ff }), COUNT);
scene.add(mesh);

/** Starts the sky: the kernel runs after every onUpdate, and the binding
 * composes the mesh's instances from the columns after every onRender. */
export function startSky(): void {
  schedule.update(twinkle, { drift: 0.4 });
  bind.instances(mesh, sky, { position: ["base.x", "y", "base.z"], scale: "size" });
}

e comece a partir de src/main.ts: importe-o com as outras importações e chame-o onStart:

import { startSky } from "./sky.js";

onStart(() => {
  setFixedRate(60);
  startSky();
  for (const star of stars) drop(star);
});

Os nomes de importação ./sky.js, convenção do TypeScript para um módulo escrito como sky.ts; o tempo de execução resolve da mesma forma. Os kernels aceitam um subconjunto da linguagem — números e booleanos, aritmética, Math, if, limitado for loops, as colunas da linha e os uniformes que você passa - e o tempo de execução rejeita qualquer outra coisa com um SyntaxError na linha do kernel quando ele o compila, em vez de executando-o lentamente. As declarações de starhermit:world descrever o subconjunto, filas de eventos que kernels emitem, tabelas com histórico para movimento suave de etapas fixas e ligações de nós.

7. Jogadores, defesas e jogo online

O jogador. player() de starhermit:platform é o jogador conectado ou null por um convidado; Star Catcher mostra seu nome em seu HUD. Quando o cliente StarHermit Windows inicia o jogo, o jogador está logado desde o primeiro frame, com a conta do cliente: o cliente entrega o runtime um token de lançamento para o seu jogo em um canal privado, renova-o enquanto o jogo é executado e o o jogo nunca o vê (nenhuma chamada de host retorna um token, chave ou cookie). Os jogadores nunca fazem login dentro de um jogo; a entrada e a saída acontecem no cliente.

Em navegadores a plataforma abre a página do jogo com um token de lançamento do seu jogo, que o o mecanismo retira o endereço da página antes que seu código seja executado e renova dentro do prazo de 12 horas da plataforma limite; seu jogo vê apenas player(), exatamente como nativamente. Um convidado que escolhe Entrar no A caixa de diálogo Conta do tempo de execução vai para a própria página de login do StarHermit e volta conectada. O Voice usa o microfone do navegador após a solicitação de permissão do próprio navegador.

O desenvolvimento é executado. Iniciado a partir de um terminal, um pacote não pode reivindicar uma identidade de plataforma por si só, então starhermit star-catcher joga como convidado. Depois que seu jogo for publicado, um lançamento de desenvolvimento nomeia:

starhermit star-catcher --game <your game's id>

e você faz login através F1 → Conta…, a caixa de diálogo do próprio tempo de execução (uma chave neste computador e uma confirmação enviada por e-mail, como em integração de chave pública). Armazenamento, configurações, salva e joga online e depois segue esse jogo e conta.

Salva e configurações. starhermit:storage tem três lojas, todas privadas para o seu jogo: storage (dados de chave/valor no dispositivo, como o Star Catcher usa), settings (as opções do jogo, mantidas com o conta do jogador na plataforma configurações por jogador), e saves (o save do jogo, no dispositivo e no jogador slot para salvar na nuvem com conflito manuseio).

Jogo on-line. Tudo o que a plataforma oferece em um jogo está em starhermit:platform para o seu jogo id próprio: amigos e presença, convites, salas em tempo real, matchmaking, o tomada de jogo (connectGame), tabelas de classificação, conquistas, replays, bate-papo e voz. Para multijogador com autoridade de servidor, declare um roteiro do jogo:

server=server.js

A plataforma o administra como autoridade para as sessões do seu jogo; starhermit:script's authority("server.js", …) executa o mesmo arquivo em um trabalhador local para prática offline, exatamente como a plataforma faz isso, então o jogo offline e online compartilham um caminho de código. Pontuações da tabela de classificação, conquistas e os resultados das partidas são escritos apenas pelo script do servidor, nunca pelo jogo em si; criar as placas conforme descrito em tabelas de classificação e conquistas.

Vindo de uma versão JavaScript SDK

Um jogo que já roda no StarHermit como um navegador construído usando o JavaScript SDK mantém seus jogadores progresso quando ele passa para o mecanismo (host API 1.8, então adicione engine.minor=8). O motor mostra uma nuvem salvá-lo não escreveu como estrangeiro: saves.state() é "foreign", saves.foreign() dá o slots bytes exatamente como armazenado (e seu text quando é texto) e nada é carregado até que o o jogo converte e salva com replaceForeign, que substitui apenas a versão mostrada. O teclas de configurações mais antigas do jogo (fora game.) são lidos settings.legacyKeys() e settings.legacy(key)e removido com settings.removeLegacy(key) uma vez migrado. decompress e compress (gzip, zlib ou raw DEFLATE) fornecem os mesmos bytes nativamente e nos navegadores:

import { saves, settings } from "starhermit:storage";
import { decompress } from "starhermit:engine";

saves.onStatus((_, state) => {
  if (state !== "foreign") return;
  const old = saves.foreign()!;
  // For example, a save written as gzip-compressed JSON:
  const text = new TextDecoder().decode(decompress(old.bytes, "gzip"));
  saves.save(convert(JSON.parse(text)), { schema: 1, replaceForeign: true });
});
settings.onLegacy(() => {
  for (const key of settings.legacyKeys() ?? []) importOldSetting(key, settings.legacy(key));
});

Se a construção do navegador registrou um service worker que atende primeiro a partir de seu cache, retornando os jogadores continuam obtendo a versão antiga em cache até que o trabalhador desapareça. Envie um substituto no mesmo caminho (por exemplo sw.js) no upload do mecanismo. Ele assume o controle imediatamente, limpa os caches antigos, cancela o registro e recarrega suas páginas no carregador do mecanismo. navigate() só funciona depois clients.claim():

self.addEventListener("install", () => self.skipWaiting());
self.addEventListener("activate", (event) => event.waitUntil((async () => {
  await self.clients.claim();
  for (const key of await caches.keys()) await caches.delete(key);
  await self.registration.unregister();
  for (const client of await self.clients.matchAll({ type: "window" })) client.navigate(client.url);
})()));

8. Publique

Um jogo de script publicado é um jogo StarHermit comum cujos arquivos são o seu pacote. Os jogadores encontram em starhermit.com e em sua biblioteca: a página reproduz no navegador e o StarHermit O cliente Windows o instala com o mecanismo que ele fixa e o reproduz nativamente.

Embale-o. Um comando, executado após cada alteração como última etapa antes do upload, grava o carregue em uma pasta própria: os arquivos do pacote (sem os arquivos de desenvolvimento deixados acima) mais os dois arquivos que a plataforma e o cliente precisam:

starhermit package --web star-catcher --out upload

Web package: upload (5 files, 8620 bytes to upload; the platform takes at most 50 MiB)
Left out (not part of the package): tsconfig.json (default rule tsconfig.json)
Engine 1.6.0 from https://wiki.starhermit.com/engine (manifest sha384-NKRlD4xQw7FJPj8LgLFOoPrTNoYXCBjfIwxk8g4Tibr1rOoXT9VbPgJZxBx3mmXa)
Not checked against versions.json (read offline): https://wiki.starhermit.com/engine/versions.json says whether 1.6.0 is still current
  • index.html, o página do carregador launch=index.html nomes: apenas marcação, sem script próprio. Isso carrega o lançamento starhermit.js e manifest.json deste wiki fixado por seus hashes SRI, e o mecanismo verifica todos os outros arquivos carregados nesse manifesto, para que a página possa ser executada apenas esse lançamento exato. Empacote novamente em vez de editá-lo.
  • starhermit-files.json, o índice de arquivo: cada arquivo com seu tamanho e SHA-256. O navegador o motor lê o pacote por meio dele e o cliente instala e atualiza o jogo por meio dele.

Ele verifica o pacote em relação às regras de upload da plataforma (sem api/ ou ws/ pastas, no máximo 9.998 caminhos e 50 MiB) e os pins de lançamento do seu jogo, que devem ser publicados com um tempo de execução da web e não revogado. O tempo de execução verifica seu próprio lançamento offline; --engine-version X.Y.Z --manifest <a copy of that release> pacotes para outro. Um jogo não deve ter o seu próprio index.html; o comando se recusa a substitua-o. Sem --out, package --web grava os dois arquivos na própria pasta do jogo. starhermit package --native star-catcher grava o mesmo índice de arquivo na pasta do jogo sem o carregador, para um jogo que é jogado apenas no cliente (com qualquer página simples nomeada por launch=). Um índice escrito na pasta do jogo lista os arquivos de desenvolvimento que a pasta contém "excluded", e o cliente StarHermit os deixa fora do upload (cliente 0.2.7 ou posterior).

Faça upload. O upload pasta é o upload, exatamente como é: o mecanismo do navegador e o cliente verifique cada arquivo em relação ao índice, então carregue seus arquivos inalterados, com o mesmo starhermit.txt tanto dentro da pasta quanto na raiz do pacote (a plataforma publica a cópia raiz no arquivo da pasta lugar). Como em Adicione um jogo de uma pasta local:

mkdir -p bundle/client
cp -R upload/. bundle/client/
cp upload/starhermit.txt bundle/starhermit.txt
tar -C bundle -czf star-catcher.tar.gz .

curl --fail-with-body -X POST https://api.starhermit.com/api/v1/me/github-games/upload \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H 'Content-Type: application/gzip' \
  --data-binary @star-catcher.tar.gz

ACCESS_TOKEN é o token de acesso da sua conta (veja fazer upload de compilações de CI/CD para fazer login sem um navegador). A resposta é game.id é o ID do seu jogo, e o jogo é lançado imediatamente https://<id>.starhermit.com/. Para cada versão posterior, empacote novamente e envie o mesmo tipo de pacote para o jogo com POST /api/v1/me/github-games/{id}/bundle; os clientes dos jogadores baixam apenas os arquivos cujos hashes foram alterados. Se um arquivo for alterado após embalagem, o mecanismo do navegador se recusa a iniciar e sua tela de erro nomeia o arquivo com o tamanho e SHA-256 as listas de índices e os encontrados: empacote novamente e carregue o que o comando escreveu. starhermit check avisa quando o índice de uma pasta está desatualizado. UM server= roteiro no pasta obtém o back-end do jogo conforme o upload é publicado.

De um repositório. Um jogo publicado no GitHub funciona da mesma maneira: commitar a pasta empacotada (starhermit.txt com seu engine.* linhas, index.html e starhermit-files.json) na raiz do repositório. O cliente instala e atualiza um jogo de repositório com o git, buscando apenas o que cada commit adiciona.

O bloqueio da página. A plataforma atende todas as páginas de um jogo cujo starhermit.txt declara engine.version com uma Política de Segurança de Conteúdo que admite scripts apenas deste wiki, então o único código que a página de um jogo de script pode executar é o mecanismo oficial (veja Versões do motor). Seu TypeScript é executado em um trabalhador, o motor dá partida; a página em si executa apenas o mecanismo: entrada, menus de tempo de execução, áudio, armazenamento e a sessão da plataforma.

9. Mude para um motor mais novo

Um jogo é executado exatamente no lançamento que ele fixa: nada o atualiza pelas suas costas, e um jogo publicado a liberação nunca muda. Para migrar para um mais recente, baixe seu tempo de execução, execute seu jogo e suas verificações nele e, em seguida, fixe novamente alterando engine.version em starhermit.txt, empacote novamente e publique. Os clientes dos jogadores baixam o novo mecanismo uma vez (apenas o que mudou nas versões que eles já hold) e os arquivos alterados do seu jogo.

A versão principal do lançamento é a API do host: engine.api=1 os jogos se movem livremente dentro de 1.x.x. Um jogo que precisa de membros da API do host adicionados em uma versão secundária pode dizer isso com engine.minor=N; um mais velho o tempo de execução recusa com uma mensagem em vez de falhar mais tarde.

Uma versão considerada insegura é revogado: versions.json marca-o com o razão, o cliente se recusa a instalá-lo ou iniciá-lo (e diz ao jogador o porquê), e a embalagem os comandos recusam sempre que leem versões.json. Uma versão revogada é sempre seguida por uma versão fixa; fixe novamente nele e publique.

10. Limites e licença

O tempo de execução mantém todos os jogos dentro dos orçamentos, que um pacote pode diminuir com engine.limits.* mas nunca aumente, exceto seu orçamento de imagem: engine.limits.image_mib (host API 1.9) aumenta o padrão de 56 MiB para 512 MiB, dentro gpu_mib. O tempo do script é medido nativamente nas instruções de uma máquina de referência (combustível); os navegadores não têm combustível, mas o mesmo "não respondendo" limites:

Fase Combustível "Não respondendo" depois
Avaliação do módulo (código do escopo do módulo da entrada e suas importações) 60s ao todo; não pode pausar 9s, junto com onStart
onStart e seus empregos promissores 256 ms por fatia (8 × fuel_ms) 9 s, juntamente com avaliação do módulo
Um quadro: eventos, temporizadores, onFixedUpdate, onUpdate, onRender, prometer empregos 32 ms por chamada (fuel_ms) 3 s para todo o quadro
onSuspend, onResume 32ms 3 s

Uma chamada que esgota seu combustível é pausada, não finalizada: ela continua nos próximos frames enquanto o jogo não desenha nada de novo. Quando uma fase ultrapassa seu limite, o tempo de execução "não respondendo" tela permite que o jogador espere ou pare o jogo (60 s enquanto o jogo termina engine.setBusy). Um erro para nomes de horas a fase, o tempo de execução e o limite, por exemplo module evaluation of src/main.ts ran past its time budget (it ran 61234 ms; the limit is 60000 ms of the reference machine's instructions). Fatia longo trabalho entre quadros (fuelLeft() diz o que resta do combustível desta chamada), ou anunciá-lo com setBusy.

Os outros limites: um heap de script de 256 MiB e 1.024 frames de chamada, 64 MiB de armazenamento, telas de no máximo 4.096 pixels por lado e 8.388.608 pixels (4096 × 2048), 128 ações, BigInts de no máximo 220 pedaços, no máximo 512 MiB e 65.536 arquivos em um pacote e, para uploads, os 50 MiB e 9.998 caminhos da plataforma (um jogo a plataforma permite mais passes --max-upload-mib e --max-upload-paths para a embalagem comandos, ou --game-id ler seus limites). Ativos grandes podem ficar fora do upload, pois arquivos remotos: engine.remote.files= e engine.remote.urls= em starhermit.txt nomeie arquivos que seus próprios hosts HTTPS servem (ou engine.remote.urls=platform: StarHermit os serve, e cargo starhermit publish carrega-os), os comandos de empacotamento fixam cada um por tamanho e SHA-256, e o tempo de execução os busca e verifica (files.fetch em starhermit:engine; veja as declarações da API do host). Ultrapassar um limite onde uma operação pode falhar (uma alocação, uma chamada de host) lança um RangeError; ficar sem heap ou profundidade de chamada encerra o jogo na tela de erro. As declarações da API do host liste todos os limites.

Diferenças nativas e de navegador

Nativamente seu código roda no interpretador do motor, nos navegadores no motor JavaScript do navegador (V8 no Chrome e Edge). Ambos são ECMAScript 2022 estritos, incluindo BigInt, e starhermit check roda o jogo nativamente e vincula seus módulos à medida que os navegadores os obtêm. O que ainda difere:

  • Módulos que se importam. Nos navegadores, uma importação lida antes de seu módulo ser executado é undefined; check falha nessa leitura no código de nível superior de um módulo (leia-o dentro de uma função em vez disso). export * from um módulo de tal ciclo falha check: nomeie as exportações. UM let exportado novamente de um módulo de um ciclo é uma cópia nos navegadores, portanto as atribuições posteriores não são vistas através dele: importe-o de seu próprio módulo.
  • Carregando. import() precisa de uma string literal (check falha em um especificador computado).
  • Código de strings. eval falha no carregamento nativamente; new Function(...) lança um EvalError ligado ambos.
  • Somente navegadores integrados possuem: Proxy, WeakRef, FinalizationRegistry, Atomics, structuredClone, os ajudantes do iterador, Array.fromAsync, o novo Set métodos, o trabalhador globais (self, crypto, atob, URL, WebAssembly, …) e alguns dos Intl (ListFormat, Segmenter, DisplayNames, Locale). check avisa sobre todo uso com seu arquivo e linha; typeof os testes estão bem.
  • Expressões regulares. O v bandeira e o legado RegExp.$1 estática é somente para navegador.
  • Datas. A hora local nativa é UTC (getTimezoneOffset() é 0); navegadores usam o tempo do jogador zona. Formate os horários do relógio de parede com timeZone: "UTC" para mostrar o mesmo em ambos.
  • Limites. Nativamente, uma string contém no máximo 228 − 16 unidades de código, uma matriz 226 elementos e um BigInt 220 bits (mais em navegadores); um estouro de pilha encerra o jogo nativamente do que lançar um capturável RangeError. Math.random sequências diferem.
  • Valores da API do host. Nenhuma API de host usa um BigInt e JSON.stringify recusa um (TypeError): converter com Number(x) ou String(x) antes de salvá-lo ou passá-lo.
