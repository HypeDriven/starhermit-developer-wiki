Carregar compilações de CI/CD com uma chave pública registrada em OAuth

Este tutorial fornece a um pipeline de implantação sua própria credencial StarHermit sem armazenar seu Google ou tokens GitHub OAuth em CI. A configuração única é interativa:

  1. Faça login através do OAuth e aceite os termos atuais do StarHermit.
  2. Adicione uma chave pública dedicada à sua conta StarHermit.
  3. Coloque apenas a metade privada dessa chave no armazenamento secreto do CI.

Cada pipeline executado então assina um desafio StarHermit de curta duração, recebe um desafio normal de 15 minutos token de acesso e carrega a nova compilação. A chave do pipeline atua como sua conta e só pode ser atualizada jogos que a conta possui.

Por que usar uma chave de implantação separada?

Não salve um acesso OAuth ou um token de atualização no CI. Uma chave pública StarHermit é uma máquina melhor credencial porque pode ser rotulada, auditada e revogada de forma independente. Uma sessão autenticada por essa chave não é possível adicionar chaves ou revogar outras chaves; essas operações exigem um sistema autenticado por OAuth sessão. Pode revogar-se através /api/v1/me/public-keys/current. Se o segredo do CI vazar, faça login no Google ou GitHub e revogue a chave de implantação. A revogação também encerra sessões de atualização criadas por essa chave e faz com que seus tokens de acesso existentes falhem na próxima solicitação de API.

Use uma chave por repositório/ambiente, por exemplo orbit-league-production, em vez de compartilhar uma chave privada entre cada fluxo de trabalho.

Pré-requisitos

  • Uma conta StarHermit conectada através do Google ou GitHub OAuth.
  • Um jogo existente pertencente a essa conta. Salve seu id como GAME_ID; o endpoint do pacote atualiza um jogo, mas não cria um.
  • Uma versão de cliente distribuível e/ou compatível com Docker docker save imagem. Ver Jogos GitHub para o layout do arquivo.
  • Python 3 para os comandos de configuração e exemplo de fluxo de trabalho; curl e jq para o exemplo de inscrição.

Um pipeline pode fazer login com êxito e ainda receber 403 terms_acceptance_required quando carrega ou abre um soquete de upload. Peça ao proprietário da conta que analise e aceitar os termos atuais interativamente e, em seguida, execute novamente o trabalho. Isto pode ocorrer quando os termos mudam; não aceite automaticamente termos do CI.

Configuração única

1. Gere uma chave de implantação localmente

O exemplo usa Ed25519. Execute isto em uma estação de trabalho confiável, não no trabalho de CI:

python -m pip install cryptography
python - <<'PY'
import base64
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
from cryptography.hazmat.primitives.serialization import Encoding, NoEncryption, PrivateFormat, PublicFormat

key = Ed25519PrivateKey.generate()
private = key.private_bytes(Encoding.Raw, PrivateFormat.Raw, NoEncryption())
public = key.public_key().public_bytes(Encoding.Raw, PublicFormat.Raw)
print("STARHERMIT_PRIVATE_KEY=" + base64.b64encode(private).decode())
print("STARHERMIT_PUBLIC_KEY=" + base64.b64encode(public).decode())
PY

O valor privado é a semente de 32 bytes e é mostrado uma vez neste terminal local confiável. Nunca se comprometa imprima-o em logs de CI, coloque-o em um artefato ou envie-o para o StarHermit. Mantenha o valor público para a próxima etapa e para a variável de fluxo de trabalho.

2. Faça login com OAuth e adicione a chave pública

Abra um destes URLs em um navegador:

https://api.starhermit.com/api/v1/auth/oauth/github/authorize
https://api.starhermit.com/api/v1/auth/oauth/google/authorize

Após o retorno de chamada, use imediatamente o token de acesso autenticado pelo OAuth retornado. Coloque-o em um local variável de ambiente em vez de no histórico do shell:

read -rsp 'OAuth access token: ' OAUTH_ACCESS_TOKEN; echo
read -rp  'Public key: ' STARHERMIT_PUBLIC_KEY

curl -sS -X POST https://api.starhermit.com/api/v1/me/public-keys \
  -H "Authorization: Bearer $OAUTH_ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  --data "$(jq -n \
    --arg keyData "$STARHERMIT_PUBLIC_KEY" \
    --arg label 'orbit-league-production' \
    '{keyType:"Ed25519", keyData:$keyData, label:$label}')"

A chamada retorna 201 e o registro chave. UM 403 significa que este token não veio de um OAuth sessão (uma verificação de e-mail, chave pública ou token de lançamento de jogo não é suficiente). UM 409 significa o a chave já está ativa ou a conta atingiu seu limite de chave ativa.

Confira o resultado com GET /api/v1/me/public-keys. A lista inclui rótulos, impressões digitais, dados de última utilização vezes e chaves revogadas, portanto também é a trilha de auditoria de credenciais.

3. Configure o repositório

No GitHub, adicione:

  • Segredo de ações STARHERMIT_PRIVATE_KEY: a semente privada Base64.
  • Variável de ações STARHERMIT_PUBLIC_KEY: a chave pública bruta Base64.
  • Variável de ações STARHERMIT_GAME_ID: o ID do jogo de propriedade.

Proteja a produção com um ambiente GitHub se for necessária aprovação. Os valores equivalentes podem ser armazenado em variáveis protegidas do GitLab, Azure Key Vault ou qualquer outro armazenamento secreto de CI.

Adicione o auxiliar de autenticação/upload

Comprometa o seguinte como ci/starhermit_upload.py. Ele reconstrói o desafio JSON exato que StarHermit assina internamente, autentica com Ed25519 e escolhe HTTP para arquivos pequenos ou carregue o WebSocket para arquivos com mais de 90 MB. O WebSocket evita o corpo HTTP de aproximadamente 100 MB do CDN limite.

#!/usr/bin/env python3
import argparse, asyncio, base64, json, os
from pathlib import Path
from urllib.parse import quote, urlparse, urlunparse

import requests
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey


def authenticate(api, public_key, private_key):
    challenge = requests.post(
        f"{api}/api/v1/auth/public-key/challenge",
        json={"keyType": "Ed25519", "keyData": public_key}, timeout=30)
    challenge.raise_for_status()
    body = challenge.json()
    p = body["payload"]

    # Public JSON is camelCase; the server verifies its ChallengePayload serialization, whose
    # property names and order are the PascalCase sequence below.
    payload = {
        "ChallengeId": p["challengeId"],
        "Fingerprint": p["fingerprint"],
        "Issuer": p["issuer"],
        "Audience": p["audience"],
        "Expiry": p["expiry"],
        "Nonce": p["nonce"],
        "ClientTimestamp": p["clientTimestamp"],
    }
    # System.Text.Json escapes '+' in string fields (the Base64 nonce) as \u002B.
    # DateTimeOffset fields keep literal '+' in their offsets: do not replace globally.
    fields = []
    for name, value in payload.items():
        encoded = json.dumps(value)
        if name == "Nonce":
            encoded = encoded.replace("+", r"\u002B")
        fields.append(json.dumps(name) + ":" + encoded)
    signed_payload = ("{" + ",".join(fields) + "}").encode("utf-8")

    seed = base64.b64decode(private_key, validate=True)
    signature = Ed25519PrivateKey.from_private_bytes(seed).sign(signed_payload)
    complete = requests.post(
        f"{api}/api/v1/auth/public-key/complete",
        json={"challengeId": body["challengeId"],
              "signature": base64.b64encode(signature).decode(),
              "keyType": "Ed25519", "keyData": public_key}, timeout=30)
    complete.raise_for_status()
    return complete.json()["accessToken"]


def upload_http(api, game_id, token, archive, mode):
    with archive.open("rb") as stream:
        response = requests.post(
            f"{api}/api/v1/me/github-games/{game_id}/bundle",
            params={"mode": mode} if mode != "replace" else None,
            headers={"Authorization": f"Bearer {token}",
                     "Content-Type": "application/gzip"},
            data=stream, timeout=1800)
    response.raise_for_status()
    print(json.dumps(response.json()))


async def upload_websocket(api, game_id, token, archive, mode):
    import websockets
    parsed = urlparse(api)
    query = f"gameId={quote(game_id)}&access_token={quote(token)}"
    if mode != "replace":
        query += f"&mode={quote(mode)}"
    uri = urlunparse(("wss" if parsed.scheme == "https" else "ws", parsed.netloc,
                      "/ws/v1/game-upload", "", query, ""))
    async with websockets.connect(uri, max_size=None, ping_interval=20) as ws:
        ready = json.loads(await ws.recv())
        if ready.get("type") != "ready":
            raise RuntimeError(ready)
        with archive.open("rb") as stream:
            while chunk := stream.read(512 * 1024):
                await ws.send(chunk)
        await ws.send(json.dumps({"type": "complete"}))
        while True:
            message = json.loads(await ws.recv())
            if message.get("type") == "result":
                print(json.dumps(message))
                return
            if message.get("type") == "error":
                raise RuntimeError(message)


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("archive", type=Path)
    parser.add_argument("--api", default="https://api.starhermit.com")
    parser.add_argument("--mode", choices=("replace", "merge"), default="replace",
                        help="replace the live client files (default) or patch them")
    args = parser.parse_args()
    game_id = os.environ["STARHERMIT_GAME_ID"]
    token = authenticate(args.api.rstrip("/"), os.environ["STARHERMIT_PUBLIC_KEY"],
                         os.environ["STARHERMIT_PRIVATE_KEY"])
    if args.archive.stat().st_size < 90 * 1024 * 1024:
        upload_http(args.api.rstrip("/"), game_id, token, args.archive, args.mode)
    else:
        asyncio.run(upload_websocket(args.api.rstrip("/"), game_id, token, args.archive, args.mode))


if __name__ == "__main__":
    main()

Trate uma saída diferente de zero como uma implantação com falha. Não registre o token de acesso nem complete o corpo da solicitação. O token de acesso dura 15 minutos, portanto autentique imediatamente antes de fazer o upload; o WebSocket verifica durante o handshake e pode terminar após o token expirar.

Exemplo de ações do GitHub

Este exemplo publica o conteúdo de dist/ em cada impulso para main:

{% cru %}

name: Deploy to StarHermit
on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'

      - name: Build
        run: |
          npm ci
          npm run build

      - name: Package StarHermit bundle
        run: |
          mkdir -p bundle/client
          cp -R dist/. bundle/client/
          cp starhermit.txt bundle/starhermit.txt
          tar -C bundle -czf game-bundle.tar.gz .

      - name: Install uploader dependencies
        run: python -m pip install 'cryptography>=42,<45' 'requests>=2.31,<3' 'websockets>=12,<13'

      - name: Upload build
        env:
          STARHERMIT_PRIVATE_KEY: ${{ secrets.STARHERMIT_PRIVATE_KEY }}
          STARHERMIT_PUBLIC_KEY: ${{ vars.STARHERMIT_PUBLIC_KEY }}
          STARHERMIT_GAME_ID: ${{ vars.STARHERMIT_GAME_ID }}
        run: python ci/starhermit_upload.py game-bundle.tar.gz

Para um servidor dedicado, adicione docker build, salve a imagem em bundle/server/image.tar, e reter starhermit.txt na raiz do pacote:

docker build -t my-game-server:${GITHUB_SHA} -f Dockerfile.server .
mkdir -p bundle/server
docker save my-game-server:${GITHUB_SHA} -o bundle/server/image.tar
tar -C bundle -czf game-bundle.tar.gz .

Um upload de pacote bem-sucedido significa que o StarHermit aceitou e publicou atomicamente o pacote; isso acontece não significa que um novo contêiner tenha passado nas verificações de integridade. Enquete GET /api/v1/me/github-games/{id}/deployment com o mesmo token recém-autenticado e execute um teste de fumaça antes de promover o lançamento.

Rotação e resposta a incidentes

  1. Faça login através do OAuth e aceite os termos atuais do StarHermit.
  2. Adicione uma chave recém-gerada e rotulada distintamente.
  3. Substitua o segredo e a variável do CI e execute uma implantação.
  4. Revogue a chave antiga com DELETE /api/v1/me/public-keys/{keyId}.

Para um suposto compromisso amplo, DELETE /api/v1/me/public-keys/all revoga todas as chaves ativas. Ambas as operações de exclusão requerem uma sessão autenticada por OAuth. Um pipeline autenticado por conta própria key não pode revogar outras chaves, adicionar uma substituição, alterar o e-mail da conta ou remover uma identidade OAuth. Pode revogar-se com DELETE /api/v1/me/public-keys/current; descarte seus tokens armazenados depois.
