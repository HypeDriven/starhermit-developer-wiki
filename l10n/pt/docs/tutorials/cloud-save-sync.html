Carregue e salve o progresso com segurança

Use salvamentos na nuvem para o progresso de propriedade do cliente de um jogador conectado. A opção single-player não assinada mantém o progresso na memória e não lê ou grava salvamentos de contas. As preferências pertencem a configurações do jogo, não o documento de progresso.

Um token de lançamento pode acessar exatamente game:<gameId>, onde gameId é o seu game_scope. A plataforma armazena bytes opacos, com um salvamento por slot. Valide o formato que seu jogo espera. Ver Salvamentos na nuvem para cotas e cabeçalhos condicionais.

Uma pequena receita JSON completa

Cópia cloud-save-store.js em sua construção. Este exemplo armazena dados brutos Bytes JSON UTF-8; a plataforma os atende com application/zip mas não requer um formato ZIP. Use um leitor diferente para salvar ZIP, incluindo o ZIP do SDK do navegador salva. Não altere os formatos sem um plano de migração para os players existentes.

import { CloudSaveStore } from './cloud-save-store.js';

const store = new CloudSaveStore({
  gameId: StarHermit.slug,
  token: () => StarHermit.token, // Always obtain the current renewed token.
});
const valid = value => value?.version === 1 && Number.isSafeInteger(value.points) && value.points >= 0;
let progress = { version: 1, points: 0 };
let saving = false;

async function startAccountGame() {
  // Keep gameplay/saving disabled until this resolves.
  const remote = await store.load(valid);
  progress = remote ?? { version: 1, points: 0 };
  render(progress);
}

async function saveCheckpoint() {
  if (saving) return; // Coalesce checkpoints; do not issue overlapping writes.
  saving = true;
  showSync('Saving…');
  try {
    await store.save(progress);
    showSync('Saved');
  } catch (error) {
    if (error.status === 412) {
      // Keep local progress in memory. Offer Reload cloud or an explicit merge.
      showConflict(() => startAccountGame());
    } else showSync('Save failed; retry after resolving the error');
  } finally {
    saving = false;
  }
}

render, showSync, e showConflict são sua IU. Aguarde startAccountGame() antes de ativar jogar ou salvar. Em caso de falha de carregamento, retém o estado local atual do player, exibe a falha, e mantenha os uploads bloqueados. UM 404 é o caso do slot vazio; 401, 403, 5xx, JSON malformado, ou uma versão salva não suportada não são slots vazios.

A receita não renova credenciais. O SDK do navegador renova os tokens de inicialização enquanto eles permanecem válido. Resolva os termos pendentes ou reautentique-se através do fluxo de entrada do jogo antes de tentar novamente uma leitura.

Condições e conflitos

O que foi carregado Cabeçalho na próxima gravação Se outro dispositivo gravar
Salvar existente com ETag If-Match: <etag> 412 precondition_failed
Não salvar (404) If-None-Match: * 412 precondition_failed
Nada carregado com sucesso Não escrever Continue tentando a leitura novamente ou deixe o player permanecer em reprodução não rastreada

Use a versão do dados que você carregou, não uma verificação posterior de metadados. Reter a nova ETag retornada por cada gravação bem-sucedida. UM 412 bloqueia salvamentos adicionais até que o jogo carregue a versão atual e o jogador o adota ou funde. Não remova silenciosamente a condição e substitua outro dispositivo. A API não oferece histórico de salvamento para desfazer essa substituição.

Se dois dispositivos precisarem atualizar contadores ou inventário de forma independente, um único documento de última gravação vence pode não caber no jogo. Use o estado autoritativo do servidor e defina comandos de jogo validados.

Salvar formato e migração

Inclua uma versão de formato e valide tipos, intervalos e campos obrigatórios antes de adotar progresso. Escreva uma migração para versões mais antigas suportadas. Mantenha intacta uma versão desconhecida mais recente; não redefina-o para os padrões e faça upload sobre ele. Os dados na nuvem são controlados pelo cliente, portanto, nunca os trate como prova de pontuação competitiva ou direito pago.

O limite padrão de salvamento decodificado é 10 MiB. Base64 adiciona cerca de um terço ao corpo da solicitação. 413 cloud_save_too_large, 409 cloud_save_slots_exhausted, e 507 cloud_save_quota_exceeded são diferentes falhas de capacidade; inspecionar code e limit. Honra Retry-After sobre 429.

Pontos de verificação e saída de página

Salve em pontos de verificação significativos e ofereça uma ação de Salvar visível. Debounce mudanças rápidas e serializar escreve para que cada um use a última versão reconhecida. Mantenha um indicador sujo até ser reconhecido. Uma solicitação com falha não é um salvamento confirmado; após uma gravação ambígua, recarregue antes de outra gravação.

Um upload de saída de página é o melhor esforço. Navegador fetch(..., { keepalive: true }) compartilha um pequeno voo subsídio corporal, geralmente 64 KiB; um salvamento de 10 MiB não pode contar com isso. Uma guia pode fechar antes de qualquer solicitação termina. Use salvamentos comuns em primeiro plano para maior durabilidade e não rotule o progresso não reconhecido como salvo. O início rápido salva seu pequeno documento em cada coleta de ponto.

Verifique no seu jogo

  1. Comece com um slot vazio; colete o progresso, salve, recarregue e confirme que ele retorna.
  2. Recusar leituras com erro de rede, 403ou dados inválidos; confirme que nenhum upload segue.
  3. Abra duas guias em uma versão. Salvo em A, então B: B deve trazer à tona um conflito e preservar seu estado local.
  4. Teste um formato mais antigo/mais recente e uma confirmação ausente sem substituir dados desconhecidos.
  5. Entre no modo single-player não rastreado e verifique se o jogo não faz solicitações de salvamento na nuvem.
