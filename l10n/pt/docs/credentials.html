Credenciais e identificadores

Use a credencial com menos privilégios que pode executar a ação. Estar conectado não substitui verificações de recursos: os chamadores ainda precisam de amizade, direitos, associação ou propriedade relevantes.

APIs de geração são reservado e indisponível. Um token não os torna utilizáveis. As regras específicas do endpoint nas páginas de referência têm precedência sobre esta visão geral; Contratos REST identificar as famílias de credenciais por operação.

Vida útil do token

Credencial Vida útil padrão Renovação
Token de acesso à conta 15 minutos Troque o token de atualização rotativo; substitua os dois tokens retornados
Token de atualização da conta 7 dias Rotação de uso único; atualizações simultâneas devem compartilhar uma solicitação
Token de lançamento do jogo do jogador 60 minutos Renovar enquanto for válido, dentro da cadeia de lançamento padrão de 12 horas
Token do servidor de contêiner 24 horas Chave de atualização de implantação dedicada; leia o tempo de vida relatado
Tíquete de conexão WebSocket Cerca de 30 segundos Apenas uma atualização; obtenha um novo ticket para cada tentativa

Leia as vidas retornadas. Um token de lançamento de jogador não é um token de conta e não possui token de atualização. Ele não pode se recuperar após expirar. Ofereça login no jogo ou retorno ao inicializador. Um soquete aberto pode sobreviver à expiração do token, mas a reconexão requer uma credencial atual.

O lançador fornece #game_token=<jwt>; retornos diretos de login no jogo hospedado #access_token=<jwt>. Leia e remova-os antes que roteadores ou outros scripts consumam o fragmento. Decodifique declarações apenas para criar URLs e exibir identidade; a API valida a credencial.

Usar Authorization: Bearer <token> para REST. Os soquetes do navegador usam um novo ?ticket= de POST /api/v1/realtime/connection-tickets, ou suportado ?access_token=. Os ingressos herdam o escopo do chamador e não concede acesso a outros recursos. Nunca coloque credenciais de conta em seu public build ou passá-los para o URL de um jogo. Ver autenticação.

O método de autenticação é importante

Uma sessão de conta autenticada pelo OAuth pode registrar chaves, revogar outras chaves, alterar o e-mail da conta, e remover identidades de provedores. Uma sessão de conta de chave pública pode usar APIs de conta comuns e revogar seu ter chave através /me/public-keys/current, mas não pode gerenciar outras credenciais. Um token de inicialização não pode gerenciar chaves de conta, mesmo quando foi criado a partir de uma sessão de chave pública.

Aceitação dos termos atuais é uma ação do jogador suportada pela conta e lançar tokens. Exiba o documento e envie seu hash somente mediante aceitação explícita.
